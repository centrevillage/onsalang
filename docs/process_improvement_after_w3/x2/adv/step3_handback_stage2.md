## 2. 割れた点（利用者の判断に委ねるもの）

### (A) 頭の欄: TOML（`+++`）か、決まった名前の箇条（`- 状態: 決定`）か

確かめた事実（Python 3.14.5 の `tomllib`）: `status = "DECIDED"`、`spec = ["§3.1", "§2.5"]`、`decided = 2026-10-15`、`severity = "低〜中"` は読める。`status = DECIDED`（引用符なし）、同じキーの重複、日本語のキー（`状態 = "決定"`）は誤りになる。文字列の中の `\`（`"\|"`）も誤りになる。`tomllib` を使う道具は 4 つ（`builtin_names.py`・`fuzz.py`・`pending.py`・`test_gate.py`）で親の記述のとおり。

| | TOML（親） | 箇条（第 1 段） |
|---|---|---|
| 読む道具 | 標準ライブラリ。型（日付、配列、整数）が付く | 正規表現 1 本（約 30 行）。値は文字列で、配列は `、` で分ける |
| 誤りの出方 | 文法の誤りは読めずに確実に落ちる（引用符の抜け、重複） | 文法の誤りは無い。値の揺れは閉じた値の確かめだけで捕まえる |
| 見た目 | 日本語の文書の頭に英語のキーと大文字の値。本文（日本語の箇条）と二つの文法 | 一つの文法。今の R・K・票の `- 内容:` と同じ形 |
| 書く摩擦 | 引用符と配列の括弧。`\` を含む値は書けない（規則が要る） | 無し。値は行末まで |
| 既存のデータとの揃い | `pending.toml`・`allowed.toml`・`builtin_names.toml` と同じ | 文書の側の形と同じ |
| 利用者が vim で書くとき | 頭の数行を飛ばして読む。`+++` で境が明瞭 | 欄と本文が続いて見える。境は最初の空行か本文のラベル |

- 選ぶと変わること: TOML なら、手順 4 の道具は `tomllib` と `+++` の切り出しだけで、欄の値に型がある（日付の比べ、整数の `aspect`）。箇条なら、道具が自前で切るが本文と同じ規則で読め、担当が頭の欄を書くときの誤りが減る。
- 親の DF-10 の「値が文の中に紛れて揺れやすい」は、欄を頭に限り閉じた値を gate で確かめれば、箇条でも同じ程度に抑えられる（今の R の行が揺れているのは、欄が無く一行に三つの値を `・` で並べているため）。
- 私の見立て: どちらでも手順 4 以降は成り立ち、差は「読む道具の 30 行」と「英語の頭の見た目と `\` の規則」。確信は低く、どちらでも反対しない。TOML を選ぶなら README に「値に `\` を書かない、キーは重ねない、`+++` の中にコメントを書かない」を足す。
