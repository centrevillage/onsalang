## 0. 考え方

- **読むのは頭の欄と見出しと裸の ID だけ**（DF-8）。本文の文の意味は読まない。
- **ID の一覧を持たない**: 求めのたびにファイルを読んで作る（DS-6。索引のファイルもキャッシュも作らない）。対象は約 1,000 ファイル（S 551、R 235、W 105、D・K・Q・A 68、仕様の章 21 など）・数 MB。

- **書き換えは頭の欄と、本文の末尾への箇条の追記だけ**。本文の途中は Edit ツールで人と担当が直す。
- **道具が直せる形の確かめは gate で落とさない**（DF-8 の行の長さと同じ考え）。

## DT-1 ID と経路と欄の定義

- `tools/repo.py` に ID の種類の表を一つ置く: 種類（S・D・K・Q・A・R・RF・X・W）ごとに、ID の形（正規表現）、ディレクトリ、下書きの有無。`path_of("S-537")` → `decisions/S/S-537.md`、`§6.1` → `spec/06-*.md`。
- **欄の定義は各ディレクトリの README の表から読む**（DF-7 で README を欄の定義の正本にした）。
  - README の表の形: `| キー | 形 | 値 | 要る | 意味 |`。形は `文字列`・`閉じた値`・`ID の並び（S、W …）`・`節の並び`・`日付`・`整数` のどれか。閉じた値の区切りは ` / `。
  - 道具は README の決まった見出しの下の表だけを読み、形ごとに確かめる。欄を足すのは README の表に一行を足すこと（文書のコミット）。
  - **README の表の崩れは一件で出す**: `check` は先に README の表の形（列の数、知られた形の名前、閉じた値の書き方）を確かめ、崩れていればそのディレクトリについて「README の表の形」の一件だけを出し、そのディレクトリのファイルの確かめを飛ばす（全てのファイルの失敗として出さない）。
  - 関係の規則（`amends` と `amended_by` の対称、担う作業が DONE なら決定は OPEN でない、`fix`、`doing`、`depends`）は、キー名ごとに道具のコードに書く（README の表にできるのはキー・形・閉じた値まで）。
- 代替（advisor が推す）: 欄の表を `repo.py` に持ち、README の表は人のための写しにし、`check` が README と道具の表の一致を確かめる。
  どちらも README の表を読むコードが要り、作る量は同じ。違いは、欄を足すときに README だけを直すか（親）、README と道具の二か所を直すか（代替）。
  代替は欄の変更が文書と道具の両方に掛かり、「規則と道具は別のコミット」で分けると、間のコミットで一致の確かめが落ちる。親は README を読む方を推す（判断を頼む項目の DT-B）。

## DT-2 参照（利用者の例 1）

- `docs.py path <ID か §>…`: 経路（Read ツールと vim に渡す）。`§6.1` は章のファイル。
- `docs.py refs <ID か経路>`: そのファイルが指す ID の一覧。一行に「ID、状態、経路、題」。利用者の例 1。
- `docs.py back <ID>`: その ID を指すファイルと行（逆引き）。頭の欄のキーからの参照と本文の言及を分けて出す。履歴は `--history` のときだけ。今の「複数の文書をまとめた grep」の置き換え。
- `docs.py show <ID>`: 頭の欄と、道具が出す逆向きの関係と、本文。
  - 作業: 実現する決定（決定の `tasks`）、直す R（R の `fix`）、この作業に依存する作業（`depends`）、決定待ち（担う決定が OPEN か、`before` がこの作業の S）。それぞれ ID、状態、題、仕様の節。
  - 決定: 担う作業と状態、`amends` / `amended_by` の題、この決定を指す R（R の `decisions`）、実装待ちの一覧の項目（`tests/pending.toml` の `reasons`）。
  - R: `fix` と `decisions` の先の題と状態。
  - `--relations` で頭の欄と関係だけを出す（本文を読まずに関係だけ知りたいとき。親が票を書くときの既定）。
- README と規則で「ID のファイルは `show` で読む」とする（DF-10 の「関係を一方にだけ書くリスク」への手当て）。
- 計算量: 頭の欄の読みはファイル数に線形、本文の言及は総字数に線形。1 回の走査で止まる（固定点も再帰も無い）。

## DT-3 状態の管理（利用者の例 2）

- `docs.py list <種類> [--status S] [--stage W4] [--group 33] [--before W4-02] [--no-fix] [--waiting] [--count]`: 一行に「ID、状態、主な欄、題」。題の無い S は「空白」の頭の 40 字。
  - 例: `list S --status OPEN --before W4-02`（W4-02 の前に決める空白。今の記憶の「空白の後の段」の置き換え）、`list R --status OPEN --no-fix`（宛先の無い R）、`list W --stage W4 --waiting`（決定待ちの作業）、`list W --count`（段ごとの状態の数。DF-6 の「作業の数の欄は道具が出す」）。
- `docs.py set <ID> <キー>=<値>…`: 頭の欄を書き換える（`set W4-02 status=DOING doing=U1/t,U1/i`、`doing=` で欄を消す）。
  値は README の形で、書いた後の状態は `check` の関係の規則で確かめ、落ちるなら書かずに理由を出す（`pending.py add` と同じ流儀）。
- `docs.py note <ID> <ラベル> <文>`: 本文の末尾に `- <ラベル>（<今日の日付>、親）: <文>` を足す（R の `判断`、W の `保留`、S の `補い`）。`--by` で書き手を変える。
  対象は記録の文書（`decisions/`・`issues/`・`tasks/`）だけ（DF-1 で発言者と日付を書けるのはそこだけ）。
- `docs.py new <種類> [--title 題] [<キー>=<値>…]`: 次の番号（その種類の、下書きを含む最大 + 1）でファイルを作り、経路を出す。本文はその種類のラベルの空の箇条。
  番号を振るのは親だけ（担当は今と同じく `NEW` と書く）。作業ツリーで呼ばれたら拒む（`repo.tree_kind`。主のツリーの番号を見ないため）。
- `docs.py draft <S の ID>… --group 33`: 空白の下書き `S-xxx.draft.md` の雛形（DF-4 のラベル）。
- `docs.py amend <後の ID> <前の ID>`: 後に `amends`、前に `amended_by` を一度に書く（DF-B）。二つのファイルのスワップファイルと値を全て確かめてから両方を書く（片方だけ書かない）。
- **書き換えの安全**:
  - 書く前に、そのファイルの vim のスワップファイル（`.<名前>.sw?`）を見て、あれば書かずに止める（利用者が vim で開いているとき。`docs/agent-rules.md` 5 章）。道具の中で確かめて結果を読んで止まるので、`docs/leader-rules.md` 7.1 の意図に合う。
  - 頭の欄は正規形で書き直す（キーの順は README の表の順、文字列は `"…"`、配列は一行）。DF-1 で頭の欄にコメントを書かない約束をしたので、書き直しで失うものが無い。手で書いた順は `set` のときに揃う（README に一行書く）。
  - 頭の欄の終わりは「最初の `+++` だけの行」。本文に `+++` だけの行を書かない約束を README に書く。
  - 本文はバイト単位で保つ。一時ファイルに書いて rename する。
- 計算量: `set`・`note`・`amend` は 1〜2 ファイルの読み書きと、確かめのための頭の欄の一読（ファイル数に線形）。`new` は種類のディレクトリの一覧。

## DT-10 リスクと、もっと単純な代替

- **README の表を道具が読むこと**: README の表を崩すと、そのディレクトリの確かめが止まる。崩れは一件の失敗として出す（DT-1）。README を直す文書のコミットだけで gate の挙動が変わるが、変わるのはキー・形・閉じた値だけで、関係の規則はコードにある。
- **毎回全てを読むこと**: ファイルが増えて遅くなったら、そのときにキャッシュを考える（今は作らない。線形で、数倍に増えても 1 秒程度）。
- **`set` と人の編集がぶつかる**: スワップファイルがあれば止めるので、vim で開いている文書は書き換えない。Edit ツールの編集とは、同じファイルを同時に触らない限りぶつからない（親が担当の成果を写すのはパッチ）。
- **頭の欄の正規形による差分**: 手で書いた直後の `set` で差分が広がる（一回限り）。
- **存在の判定を消し忘れる**: 移行の最後の段に「判定と今の配置の作り物を消す」を入れる。消した後に `layout` が今の配置を読まないことを自己テストで確かめる。
- **もっと単純な代替: `show`・`refs`・`back` を作らず、`grep` と Read で読む**: 関係を一方にだけ書いた形（手順 3 の 0.）は逆引きの道具が前提なので、逆向きを読む手段が無くなる。採らない。
- **もっと単純な代替: `set`・`note`・`new`・`amend` を作らず、Edit ツールで直す**: 頭の欄の書き間違いは gate が落とすので成り立つ。代わりに、改めの両側や新しい番号を人が揃えることになり、gate の往復が増える。状態の更新は利用者の例 2 にあるので、作る方を推す。
