# Onsa ツールの仕様（0.3）

言語の仕様（[`onsa-lang-spec-0.3.md`](../onsa-lang-spec-0.3.md)、以下「基本仕様」）§18 のコマンドのうち、人が見る表示の約束を書く。

基本仕様との分け方（2026-10-04、S-66）:

- **基本仕様**: 言語の規則と、利用者・CI・修復のループが依存する出力。診断と修正候補、終了コード、`onsa fmt` の正規形、`onsa interface` の内容と大きさなど。
- **この文書**: 人が見る表示の約束。グラフの形・色・枠、`onsa play` の UI、`onsa probe` の表示など。変えても、書いたコードの受理や自動の処理の結果は変わらない。

分けるかどうかは記述量ではなく内容で決める。基本仕様は `onsa primer` で LLM のコンテキストにも入るので、表示の細部を入れない。

## 1. `onsa graph`

flow の信号グラフを DOT で出す（`--svg` で SVG。Graphviz の `dot` を使う）。

### 1.1 ノード

| ノード | 形 | ラベル |
|---|---|---|
| 入力 | 楕円 | `名前: 型 @レート` |
| `let` | 箱 | `名前 = 式の種類: 型 @レート`。ノード名は `let` の名前（基本仕様 §18.2） |
| 名前の無い状態のノード（式の中に直接書いたインスタンス、`prev~` / `delay~` / `vdelay~`） | 角の丸い箱 | 名前は基本仕様 §11.6 の生成する名前（`saw_0`、`prev_0`） |
| 出力 | 二重八角形 | `out: 型 @レート` |

レートで色を分ける: `Init` と定数は灰色、`Ctl` は青、`Sig` は黒。

### 1.2 辺

- 値を読む向きに引く（読まれる側 → 読む側）。
- 帰還（`^名前`）と、`prev` / `delay` / `vdelay` の look-back の辺は破線にする。それ以外は実線。
- **実線の辺だけでは閉路を作らない。** flow には遅延を通らない閉路が書けない（基本仕様 §11.2）ので、グラフがそれと矛盾する絵を出さないことを保証する。`tests/spec` の全ての flow について、性質テストで検査する。

### 1.3 `par`

- 複製を枠（Graphviz のクラスタ）で囲む。見出しは `par i in 0..N（×N）`。
- 複製の添字は、枠の中に `Init` の入力として描く（楕円、灰色）。ノード名は `par` の名前で修飾する（`saws.i`）。入れ子でも重ならない。
- 本体の結果から、`par` の結果のノードへ辺を引く。
- 入れ子の `par` は、入れ子の枠にする。

```dot
subgraph cluster_saws {
  label="par i in 0..4（×4）"
  "saws.i" [label="i: U32 @Init" shape=ellipse color="gray40"]
  "saw_0"  [label="saw_0 = saw~: F32 @Sig" style=rounded]
}
"f0" -> "saw_0"; "detune" -> "saw_0"; "saws.i" -> "saw_0"
"saw_0" -> "saws"; "saws" -> "out"
```

枠にするのは、`par` が N 個の構造の宣言（基本仕様 §11.5）で、「同じ構造が N 個ある」ことと、添字が各複製の中の値であることを見せるためである。
