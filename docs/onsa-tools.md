# Onsa ツールの仕様（0.3）

言語の仕様（[`onsa-lang-spec-0.3.md`](../onsa-lang-spec-0.3.md)、以下「基本仕様」）§18 のコマンドのうち、人が見る表示の約束を書く。

基本仕様との分け方（2026-10-04、S-66）:

- **基本仕様**: 言語の規則と、利用者・CI・修復のループが依存する出力。診断と修正候補、終了コード、`onsa fmt` の正規形、`onsa interface` の内容と大きさなど。
- **この文書**: 人が見る表示の約束。グラフの形・色・枠、`onsa play` の UI、`onsa probe` の表示など。変えても、書いたコードの受理や自動の処理の結果は変わらない。

分けるかどうかは記述量ではなく内容で決める。基本仕様は `onsa primer` で LLM のコンテキストにも入るので、表示の細部を入れない。

## 1. `onsa graph`

flow の信号グラフを DOT で出す（`--svg` で SVG。Graphviz の `dot` を使う）。

### 1.1 ノード

| ノード | 形 | ラベル |
|---|---|---|
| 入力 | 楕円 | `名前: 型 at クロック`（ソースの宣言と同じ形、基本仕様 §11.3） |
| `let` | 箱 | `名前 = 式の種類: 型 at クロック`。ノード名は `let` の名前（基本仕様 §18.2） |
| 名前の無い状態のノード（式の中に直接書いたインスタンス、`prev~` / `delay~` / `vdelay~`） | 角の丸い箱 | 名前は基本仕様 §11.6 の生成する名前（`a.prev_0`、`saws.saw_0`）。ラベルは修飾を除いた `saw_0 = saw~: 型 at クロック` |
| 出力 | 二重八角形 | `out: 型 at クロック` |

クロックで色を分ける: `init` と定数は灰色、`block` は青、`sample` は黒。

### 1.2 辺

- 値を読む向きに引く（読まれる側 → 読む側）。
- 帰還（`^名前`）と、`prev` / `delay` / `vdelay` の look-back の辺は破線にする。それ以外は実線。
- **実線の辺だけでは閉路を作らない。** flow には遅延を通らない閉路が書けない（基本仕様 §11.2）ので、グラフがそれと矛盾する絵を出さないことを保証する。`tests/spec` の全ての flow について、性質テストで検査する。

### 1.3 `par`

- 複製を枠（Graphviz のクラスタ）で囲む。見出しは `par i in 0..N（×N）`。
- 複製の添字は、枠の中に `init` のクロックの入力として描く（楕円、灰色）。ノード名は `par` の名前で修飾する（`saws.i`）。入れ子でも重ならない。
- 本体の結果から、`par` の結果のノードへ辺を引く。
- 入れ子の `par` は、入れ子の枠にする。

```dot
subgraph cluster_saws {
  label="par i in 0..4（×4）"
  "saws.i" [label="i: U32 at init" shape=ellipse color="gray40"]
  "saws.saw_0" [label="saw_0 = saw~: F32 at sample" style=rounded]
}
"f0" -> "saws.saw_0"; "detune" -> "saws.saw_0"; "saws.i" -> "saws.saw_0"
"saws.saw_0" -> "saws"; "saws" -> "out"
```

枠にするのは、`par` が N 個の構造の宣言（基本仕様 §11.5）で、「同じ構造が N 個ある」ことと、添字が各複製の中の値であることを見せるためである。

## 2. ホットリロードとプローブの照合

基本仕様 §18.3 の flow の計画を使い、再コンパイルの前後の状態のノードを対応付ける（2026-10-05、R-98）。生成する名前（基本仕様 §11.6）は表示のためのもので、照合には使わない。

- **鍵**: `let` の名前と flow の入力の名前を鍵にする（React の `key` と同じ役割）。名前を変えた `let` は別のものとして扱う。
- **位置**: 同じ鍵の中では、式の木の中の経路（どの呼び出しの何番目の引数か）と種類で対応付ける。ノードを別の呼び出しで包むと経路が変わり、そのノードは初期化される。
- **差分**: 経路だけでは対応が付かない挿入や並べ替えは、旧新の式の木の差分で補ってよい（Glicol は LCS でノードを対応付ける）。
- **型**: 対応付けたノードでも、型（`onsa interface` の表記、組込みの flow の状態は疑似型）が違えば状態を引き継がない。サブインスタンスは、その flow の計画の中まで同じ規則で辿る。
- **定数の変更**: 上流の定数を変えても、下流のノードの対応は変わらない（構造の同値でノードを見分ける方式は、上流の変更で下流の状態を全て失うので採らない）。
- **照合できなかった部分**: `init` で始める。音の途切れを避けるため、旧と新の出力を短くクロスフェードしてよい（FaustLive、SuperCollider の JITLib と同じ）。
- **プローブ**: 付けていたノードを同じ照合で新しい計画に移す。対応が付かなければ外し、利用者に知らせる。
