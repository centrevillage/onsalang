# Onsa Draft 0.2 → Draft 0.3 の変更点

- 対象: [`onsa-lang-spec-0.3.md`](../onsa-lang-spec-0.3.md)（0.2 は [`onsa-lang-spec-0.2.md`](../onsa-lang-spec-0.2.md)）
- 根拠: [`review-draft-0.2.md`](review-draft-0.2.md) の `C-01`〜`C-11` と、その決定（同文書 §7）
- 日付: 2026-10-01

0.3 は 0.2 のレビューで「矛盾・誤り」に分類した 11 件と、「空白」の 8 件と「設計提案」の 5 件を解決した版である。「実装上の懸念」の 6 件も決定し、レビューの指摘は全て反映済みである（§4）。

## 1. 意味に関わる変更

|---|---|---|---|

| G-04 | flow の細部（`init` のレート、`Ctl` を `prev` に渡したとき、`vdelay` の補間、`reset`、`render`、多チャンネルの引数、`Out`、本体の式、名前空間、in-place、フィードバック）が未定義 | `init` は `Init` 以下（E0814）。`prev` 系の第 1 引数は `Sig` 必須で `Ctl` はエラー（E0813。注釈で昇格できる）。遅延の状態と演算順を固定し、`vdelay` は FAUST と同じ 2 乗算の補間、長さ `MAX + 1`。`reset` は `Init` の値を保つ。`render` は 1 ブロックで、`Sig` 入力があれば `frames` を取らない。多チャンネルは planar で `[Span[T]; N]` を引数の型としてだけ許す。`Out` は `process` の出力と同じ形。本体では `match` も点ごと（`assert` は不可）。flow は同名の名前空間を作り、同名の宣言は E0305。`process_inplace` を生成する。サンプルループは入力を全て読んでから出力を書く | §5.3, §11.2, §11.4, §11.5, §11.6, §14.2, §17.3 |
| G-03 | タプル、配列リテラル、パターン、関連定数、列挙子の関数値、`?` の対象、`_`、前置と後置の結合、整数の意味、浮動小数の `%`、無名関数の引数モード、効果の操作の効果行が未定義 | 借用元（主に Rust）と意味が一致する構文で定義した。詳細は §2.2, §2.4, §3.1, §3.4, §4.1, §4.4, §6.1, §6.6, §7, §8.1, §9.1 | 同左 |
| G-03 (d) | — | struct 形の列挙子は採らない（名前付きのフィールドを持つものは struct 一種類、規則 1）。struct リテラルとパターンの省略形も無い | §4.4, §7 |
| G-03 (f) | `prop` がキーワードにあるが書き方が無い | `prop` を外した。性質の検査は `std.test.check`（ライブラリ）と `onsa test --flows`（`@param` の範囲での自動検査） | §2.2, §8.5, §11.8, §18.2 |
| G-01 | ジェネリックな `T` の破棄が要する効果が未定義 | `T: Copy` の制約が無い限り `Alloc` を要する。`rt fn` で `T` を破棄できるのは `T: Copy` のときだけ。標準ライブラリは「借用で受け取り、複製して返す、移動する」様式で書き、捨てる操作だけが `Alloc` を持つ | §6.3, §12.2 |
| G-08 | `for s in xs` の `s` が所有束縛で、読むだけの反復にも `Alloc` が要った | 借用束縛。`for s in xs` と借用引数から派生した `let` は借用で破棄を起こさない。`for s in move xs` は消費する反復。借用した Dup 値は `move` 引数へ複製して渡せる。組込みの集合の借用の反復はコンパイラが直接扱う | §5.2, §5.4, §7, §12.2 |

C-01 の規則 (2)、(3) を足した理由: 0.2 の規則（結果が Copy）だけでは、外側の `var` への代入・`inout`、および外側の効果の handler が引数を複製して保存する経路で、arena のメモリが外へ漏れた。(3) は「緩い版」（`Alloc` 以外の効果を持つ呼び出しの引数をヒープを持たない型に限る）も検討したが、arena の用途は初期化時の純粋な計算なので、まず厳しい版にした。

C-02 で (b)「`rt fn` の効果行は空に限る」を採らなかった理由: リングバッファに書く `Log` や、PRNG の `Random` は rt で使いたい。

C-03 で (A)「`spawn` だけを例外にしてクロージャの環境をタスクへコピーする」を採らなかった理由: クロージャは Affine を捕捉できないので、`voice.State` や `Buf` をタスクへ渡す経路が別に要り、書き方が二つになる。(B) なら引数モードの意味がそのままタスクへの受け渡しの意味になり、C の `pthread_create(fn, arg)` や JS の Worker と一対一で変換できる。

## 5. 0.3 の見直し（2026-10-02）: 並行性と、用途の無い機能

言語の目的（プラグイン、マイコン、worklet、CLI）に照らして棚卸しをした。実装への影響は無い（第 1 期に並行性は無い）。

| 対象 | 決定 | 仕様 |
|---|---|---|
| 並行性（§16） | **削除して書き直し。** Onsa はスレッドを作らない。実行の文脈（オーディオコールバック、メインループ、割り込み、worklet）はターゲットが `target` 宣言で与え、登録は「状態を `move`、同期型を `inout`、捕捉の無い関数を値で渡す、戻らない呼び出し」（`device.run`）。`task.scope` / `spawn` / `Task` / `join` / `Scope`、効果 `Spawn` / `Sync`、`Chan` / `Mutex`、E0615 を外した。同期型（`Spsc` / `Atomic` / `Swap`）は要素を Copy に限った Affine の固定サイズの値になり、生成に `Alloc` が要らず、`main` のフレームや struct のフィールドに置ける。これにより §19 の「同期型を静的領域に置く方法」と §13.5 の「JavaScript でのタスク」が解消。参照カウントは原子的でなくてよい（Shared 値は文脈の間を渡らない）。C-03 の決定（捕捉の無い関数 + `move` の引数）は登録の形として残る | §0.4, §8.2, §12.6, §12.8, §13.5, §16, §19 |
| `Sleep` 効果 | 削除（待機の用途が無い） | §8.2, §8.5, §19.2 |
| `Net` 効果 | 延期（用途が出てから） | §8.2, §19.1 |
| `Stdin` | 残す（CLI） | §8.2 |
| `Str` の API | 最低限（リテラル、補間、`==`、`len`、`is_empty`、`as_bytes`、`from_utf8`）から始め、必要になったら足す。`substr` / `find` / `chars` / `is_char_boundary` を外した。`Char` 型とリテラルは残す | §4.2, §19.2 |
| `Map` / `Set` / `Hash` | 残す（基本的な構造） | — |
| ユーザ定義型の反復（`IntoIter` の実装） | 延期 | §6.3, §7, §19.1 |
| `Array` の `map` / `filter` | `std` の最初の版には置かない。効果行変数は言語の仕組みとして残す | §8.1, §19.1 |
| `@deprecated` | 必要になったら定義する | §6.5, §19.1 |
| `onsa.policy` | 延期（第 2 期の末尾以降） | §15.4, §19.1 |

§19 を「未決定事項」と「実装しない機能（理由付き）」の二つに分けた。
