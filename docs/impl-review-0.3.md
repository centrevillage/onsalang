- 対象: コミット `6a9e4c3`（M4 完了）までの `crates/`、`std/`、`tests/`、`runtime/`
- 仕様: [`onsa-lang-spec-0.3.md`](../onsa-lang-spec-0.3.md)（S-01〜S-28 反映済み）、決定の経緯は [`onsa-0.3-changes.md`](onsa-0.3-changes.md) §4〜§5

実装の進め方は「大きな単位をワーカー 1 つに任せ、親はテスト・golden・適合性・CLI の実行で検証する」だった。親はコードを読んでいない。したがって細則は各ワーカーの報告から拾ったもので、設計の筋はこのレビューで初めて見ることになる。

## 2. 実装で決めた細則

各行は「ワーカーが決めたこと」と「親の推奨」。推奨は **仕様へ**（仕様に書き足す）、**妥当**（実装の都合で仕様に書かなくてよい）、**要判断**（利用者の判断が要る）、**直す**（仕様に合わせて実装を変える）。

### 2.1 字句・構文（`onsa_syntax`）

| # | 細則 | 推奨 |
|---|---|---|
| P-1 | 式の中の `a.b.c` は `Path` 1 要素 + `Field` の連鎖として解析し、名前解決がモジュールのパスに読み替える。複数要素の `Path` は型・`use`・パターン・属性・struct リテラルにだけ現れる | 妥当 |
| P-2 | 項目の無い末尾の `///` は黙って捨てる（§2.1 の例がコメントだけのファイル） | 仕様へ（「ドキュメントコメントは直後の宣言に付く。無ければ無視」） |
| P-3 | エラー回復: 波括弧の深さ 0 で、行頭の項目キーワードまで読み飛ばす。失敗した項目は AST に入れないが P-01 の単位にはなる | 妥当 |
| P-4 | パターンの `-1` は `PatKind::Neg` | 妥当 |
| P-5 | `()` は空のタプル | 妥当 |
| P-6 | `move` の被演算子は後置式（場所）。`let y = move x + 1` は `+` で構文エラー | 仕様へ（§5.2 の `move x` の形） |
| P-7 | ブロックの末尾の式は外側の位置を継ぐ。`let y = if c { a } else { b }` で Affine の `a` / `b` は `move a` / `move b` が要る。関数の末尾と `return` は暗黙 | 要判断（読みやすさ。Rust は暗黙）→ 決定（2026-10-05）: 置かれた位置を継ぐ。返り値の位置の `move` は fmt が取り除く（S-100、[`review-impl-phase1.md`](review-impl-phase1.md) §8） |
| P-8 | struct リテラルは、最後の要素が UpperCamel でフィールドの連鎖から再構成する（S-08 の制限付き） | 妥当 |
| P-9 | E0020 の対象: `;` `::` `<T>` `&mut x` `&x` `let mut` `loop {` 小文字の組込み型名 `#[...]` `proc` `mut self` `.5` `1.` 型接尾辞 `..=`（修正候補なし） `/* */` | 仕様へ（§18.1 に一覧） |
| P-10 | E0003 のスパンは `}` の後の改行で、修正候補は行の結合 | 妥当 |

| # | 細則 | 推奨 |
