# K-23 W3-07 を三つの作業に分ける

- 論点: W3-07（式と演算子）は、作業を切った後に決まった項目（S-186、S-191、S-225 / S-253、S-227、S-249、S-278、S-317、S-319、S-320、S-322）が同じ行に追記され、K-21 と K-22 で二度分けた後も規模 M を超えていた。実装待ちの一覧の until W3-07 は 65 件で全作業で最多。主題は三つで、互いの依存は「ガードの候補（`lo <= k && k < hi`）が群の部分順序を要する」一つだけ（K-15 の教訓）。
- 決定（2026-10-09、利用者が了承。親の案と Fable の独立の判断（伏せて分けた後に突き合わせ）を合わせた形）: W3-07 を「演算子の群」に絞り、新しい作業 W3-20「呼び出しと式の形」と W3-21「パターンのガードの候補」を足す。作業は 102 個になる。
  - W3-07: §3.1 の群の部分順序を一つの表に置き、二項演算子の連鎖を強弱の木として一度だけ作る（今の AST の平らな連鎖を全ての読み手が左から畳む形を改める。D-15。作業の最大の塊）。E0010 の候補（S-60、R-72）、同じビット演算子の連鎖（S-61）、`as` の連鎖、S-320。実装待ちの 42 件は until W3-07 のまま。依存に W3-18 を足す（同じ `parse_expr_inner`・`ast.rs`・`lower.rs` を触る）。
  - W3-20: `.(` と呼び先の形（S-191）、R-42、R-43（式・型・パターンの `(e)`。型の `(T)` とパターンの `(p)` を一つのテストが確かめる）、S-100 の構文、S-322（`is_place` は `(t.0)(x)` の候補の形も決める）、R-196。実装待ちの 14 件の until を W3-20 に。
  - W3-21: 穴の抽象を `@`・補間を含む文字列・`-LIMIT`・範囲に広げ、選択の規則（S-317、S-319）、構造体のパターンの `..`、R-156、S-278（パターンと見出しの片側の範囲。見出しの範囲の記号の直後の `{` の S-338 と同じ回に）。実装待ちの 9 件の until を W3-21 に。
    依存は W3-07（ガードの候補の比較と `&&` の混在は群の部分順序まで E0010）と W3-18。W3-20 には依存しないが、`parse_pattern_alt` が重なるので W3-20 の後が無難。
  - 他の行: `at` の連鎖の E0011（S-118 の `at`）は `at` の構文を持つ W3-09 へ。S-45 の fmt（強い群の冗長な括弧を外す）は W3-12 が担い、依存に W3-07 を足す。W3-13 の依存に W3-18〜W3-21。W4-12 の依存の W3-07 を W3-20 に。W5-09 の `-LIMIT` は W3-21。W4-13・W5-02・W8-09 も `.(` を待つが、段の順（W4 以後は W3 の全て）で満たされるので行は改めない。
  - 順: W3-07 と W3-20 は並行できる（作業ツリーで実装し、後にコミットする側が `git merge dev`。衝突は規則の表の並びと `tests/pending.toml` の追記で機械的。重いと判断すれば直列、利用者）。W3-07 を先にコミットし、W3-21 はその後。
