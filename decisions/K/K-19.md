# K-19 W3-15 を W3-03 の後にする

- 論点: W3-15 は構文の段の E0020 で項目を失敗させる（R-87 (4)）。今の実装は失敗した項目を AST から消すので、全ての E0020 を致命にすると、その項目を使う別の項目に偽の E0302 が出る（W3-15/i の設計メモの再現。R-71 の形）。失敗した項目を名前と読めた署名で残すこと、impl と trait のメンバの単位、項目の後の `;` の単位（S-254）は W3-03（診断の単位と回復）の範囲で、W3-15 が抱えると規模が L になる。
- 決定（2026-10-08、親）: 構文解析器を触る順を W3-14 → W3-03 → W3-15 にし、W3-15 の依存に W3-03 を足す。W3-17 も W3-03 の後にする（W3-17 の設計メモ。単位の表を W3-03 が `reduce` に作り、W3-17 の器はそれを読む。W3-03 の前は構文の診断が一つの項目から複数出て「唯一の誤り」の判定が外れる）。
  順は W3-14 → W3-03 → W3-17 → W3-15・W3-06 で、W3-15 は自分の行の `fix-contract` の項目を外して終える。W3-15 は行を致命にするだけにする。W3-15/i の設計メモへの他の決定（表の形、字句の外来の形を非 trivia のトークンにする、後の作業の行も今置いて表を閉じる）は、W3-15 の作業票に入れる。
