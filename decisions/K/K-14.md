# K-14 poison の期待値を書く形

- 論点: 仕様 §9.2 の poison の表、§14.2 の状態の値、§15.3 の `panic` の設定を、export の境界で呼び出しの手順ごとに確かめる形が実行器に無い。
  今は `crates/onsa_tests/tests/poison.rs` が C の driver を Rust の文字列に持ち（D-05 の「Rust に事例の表を持たない」に反する）、`tests/spec/flow_semantics/poison_boundary.onsa` は手順の表をコメントに置いている。
- 案と推奨: [`spec-gaps-w1.md`](spec-gaps-w1.md) の K-14。
- 決定: 形は (f1)、断片の `[test]` を広げた `[[test.host]]` の配列（計画 D-05 の改定）。置き場所は (p1)、新しい作業 W1-11（2026-10-07）。作業は 87 個になる。W2-08、W10-02、W10-03 は W1-11 に依存し、W10-02 / W10-03 は driver を作る部分だけを新しい API に合わせる。
  利用者の基準は「一貫性があり、保守しやすいこと」で、全ての事例が同じ断片の形になること、C の API が変わっても直すのは driver を作る部分だけであること、M6 の WASM で同じ手順のデータを使い回せることで満たす。
