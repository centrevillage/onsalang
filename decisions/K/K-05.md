# K-05 型の位置の定数の評価

- 論点: 仕様 §4.5 は「初期化式で計算した定数は、配列の長さなどに名前で使える」とし、§6.6 は初期化式に関数の呼び出しを許す。型を比べるには、型の段で値が要る。一方、R-89 (2) は定数の評価を Core の一つの段にした。Q-14 の表（点検 §4.3）でも、署名の段の評価をこの段に寄せるかは保留である。今は、計算で決まる定数を長さに使うと E0200 になる。
- 案:
  - (a) 評価器は Core の一つだけにする。型の段は、長さに使う定数を依存の順に、要るときに評価させる（その定数の初期化式と呼ぶ関数を型付けし、降下して評価する）。値は一度だけ記録し、Core の定数の評価の段は記録を読む。循環は E0312。
  - (b) 型の位置で名前で使える定数を、初期化式が §4.5 の定数式であるものに限る（仕様の変更）。型の段は、定数式だけを評価する小さな評価器を持つ。
- 推奨: (a)。(b) は、DSP でよく書く `const MAX_DELAY: U32 = (MAX_SR * 0.05).trunc_u32()`（最大のサンプルレートから遅延線の長さを決める）を、遅延線の長さに使えなくする（浮動小数とメソッドの呼び出しは §4.5 の定数式に無い）。また、溢れと E0419 の意味を二つの評価器で揃え続けることになり、D-15 に反する。
  (a) の作り方は W9-03 の設計メモで詰める。W9 までは今の E0200 のまま（仕様にあって未実装なので Q-09 に合う）。
- 決定: (a)（2026-10-07）。W5-08 は小さな評価器を作らず、今の「リテラルとリテラルの定数だけ」のまま、それ以外は E0200 にする。W9-03 の設計メモに、項目の単位の依存の順と crate の依存の向きを含める（要るときに sema → Core → 評価器を項目の単位で回すので、今のモジュール全体を段ごとに処理する driver では書けない）。
  関数を経由する定数の閉路は仕様の空白なので S-173 に登録し、W9-03 と同じ回に決める。計画 §3.6 の「定数の評価」の行を改めた。
