# K-03 後の段で作り直すコードの直し

- 論点: 下書きの 2「根に触れない直し」には、後の段で作り直すコードの直しが混ざっている。
- 案:
  - R-43、R-44、R-124 は W3 へ移す。構文解析器は W3 で CST を出す形に改め、E0020 の検出は W3-02 の規則の表に集める（R-87 (4)）からである。
  - R-03 のうち `par` の look-back は W7-04 へ移す。flow の解析は W7 で作り直す。それまで、落ちる入力はファズの実装待ちの一覧に置く。
  - R-08 は、W2 で `from_fn` の無名関数の中の `?` と `return` を両方 E0200 にし、W8-09 の Core の関数値で正式に作る。R-08 の決定は「難しければ両方を E0200」を許しており、今作ると W8 で作り直すことになる。
  - R-92 (1)（インタプリタは型の合わない値を内部エラーにする）は、検証器をすり抜けたときの備えで Core の作り直しと独立なので、W2 に置く（決定では R-81 と同じ回）。
  - S-53 のうち `runtime/c/onsa.h` を公開と内部に分ける部分は、W2-09 へ前倒しする。S-54 の `#error` を内部のランタイムに置く決定なので、分けずに入れると公開ヘッダに入り、GNU モードの gcc でホストのビルドが落ちる。
  - R-12（poisoned の `process` の出力）と R-22（平面の長さ）は W2 で直す。R-12 は実行時の振る舞いで E0200 で止める形が無く、止めるなら poison と平面の入出力を広く拒むことになり、W1-09 のテストが W7・W10 まで塞がる（K-09 の例外）。
  - R-13、R-14、R-17 は、下書きどおり W7 に置く。それまでの間、黙って誤る形は K-08 で E0200 にする。
- 推奨: 上のとおり。
- 決定: 推奨のとおり（2026-10-07）。R-12 / R-22 の理由は K-09 で改めた。
