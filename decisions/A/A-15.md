# A-15 Onsa のコードから属性の値を読むリフレクションの API

- 候補: flow の名前空間に、属性（`@param`・`@host`・`@latency`）の値を読む生成する関数を置く（仮に `voice.meta()`）。属性の有無によらず在り、属性が無ければ空を返す（キーごとの `Option` など）。形の案は第 50 組の下書き（`decisions/S/S-632.draft.md` の案 (v) の論点 a・b）。
- 決定: 保留（2026-10-24、利用者「Onsa内でのリフレクションは必要になるまで実装しない、で良いと思います」。60 回目、S-632 の B1）。実例が出たら開く。
- 理由: 無いと煩雑になる実例は、flow を使う側の fn が、C の API やラッパーと同じく `@param` の範囲で入力を確かめる形。
  無い場合の書き方: 同じパッケージの flow なら、範囲を `const` にして `@param` の値と確かめる fn の両方から指す（`@param` の値に `const` を書けるのは W9-03 の後）。他のパッケージの flow で、その `const` が公開されていなければ書けず、`@param` と公開する `const` の一致はコンパイラが確かめない。
  足すときは、§6.5 の「この版の Onsa のコードには、属性の値を読む手段が無い」の文と、§11.6 の生成する名前の閉じた一覧を改める（名前空間に利用者の項目は入らないので、既存のプログラムを壊さない）。借用元の近いもの: Java の `@Retention(RUNTIME)` とリフレクション（`getAnnotation` は無ければ `null`）、Cmajor の注釈（「allows the runtime to access them」）。
