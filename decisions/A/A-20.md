# A-20 総称の境界による多重定義（特殊化）か、型パラメータの破棄に依る条件付きの効果（`[T; N].fill!`・`swap[T]` を、Copy の型では `rt` のまま、Shared の型でも書けるように）

- 候補: 二つの形のどちらか。(i) 総称の境界による多重定義（特殊化）: `impl[T: Copy, const N: U32] [T; N] { pub rt fn fill … }` と `impl[T, const N: U32] [T; N] { pub fn fill … uses {Alloc} }` を並べて書け、呼ぶ所の型で、より狭い境界の版を選ぶ。(ii) 型パラメータの破棄に依る条件付きの効果: 一つの宣言のまま、「`T` が Copy なら `Alloc` が要らない」を呼ぶ所で数える（効果行が型パラメータに依る）。目的は、`[T; N].fill!`・利用者の `swap[T]`・`put[T]` の類を、Copy の型では `rt` のまま、Shared の型でも書けるようにすること。
- 決定: 将来の実装の候補として登録（2026-11-13、利用者が S-1040 の決定と一緒に了承。146 回目）。時期は決めていない。
- 理由: S-1040 で `fill!` を Copy の要素に絞った（上書きの破棄（S-1038）が `rt` の本体に書けないため）。利用者は、総称の多重定義が入れば解決すると見た。開くときに決めること: (i) は §6.1（多重定義は無い）と §6.3（実装は重ならない、特殊化は無い）の原則を改める判断で、どれが呼ばれるかが境界で決まる（名前の解決、`interface` の出力、C の名前の付け方、境界が重なりどちらも狭くない組の扱い）。(i) は具体の型の呼び出しを解決するが、`T` が決まっていない総称の呼び出し側（`fn g[T, const N: U32](inout xs: [T; N], v: T) { xs.fill!(v) }`）は一般の版を選ぶので `uses {Alloc}` か `T: Copy` が残る。(ii) は総称の呼び出し側まで解決し名前の解決を変えないが、効果行が型パラメータに依り、第 2 期の効果行変数に近い仕組みが要る。今の (1) は絞る向きなので、どちらを後で入れても通るプログラムは壊れない。第 101 組（S-1039・S-1040）と第 100 組の独立のレビューの段 1 が挙げた。関係: S-1040、S-1038、S-853、A-19
