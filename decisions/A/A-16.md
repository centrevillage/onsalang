# A-16 `map_err` を `rt` の関数から呼べる形（`rt` の多相: `f` が `rt` なら呼び出しを `rt` と数える）

- 候補: `Result` の `map_err` の呼び出しを、渡した `f` が `rt fn` なら `rt` と数える。形は設計していない。見えている形は三つ: (i) rt の検査が `map_err` の呼び出しに限って引数の型を読む（約 +15〜30 行、§10 の規則 4 に特定の関数の例外）。
  (ii) 効果行変数と同じ形の「`rt` の変数」（仮に `map_err[F, r](move self, f: r fn(move E) -> F)`。本体は `r` を `rt` と仮定して検査し、呼ぶ所で `r` を具体化する。利用者の高階関数にも使える一般の仕組みで、構文・型の規則・診断が増える）。
  (iii) `rt` でないことを効果として扱い、効果の多相に乗せる（§10 の作りを大きく変える）。
  どの形も、`rt` の関数の中で `map_err` に渡す無名関数を `rt` の規則で検査する規則が要る（§8.1 の 35 行と同じ向き）。
- 決定: 保留（2026-11-04、利用者「ひとまず(c)で。rt関数で困ることが増えたらrtの多相化の仕組みを考えます」。110 回目、第 80 組の S-873）。`rt` の関数でエラーの型の変換を `match` で書く実例が、事例か利用者のコードで繰り返し出たら開く。
- 理由: 無いと煩雑になる実例は、`rt` の関数（flow から呼ぶイベントの解釈など）でエラーの型を変換する形。無い場合の書き方は `match move r { Ok(v) => Ok(v), Err(e) => Err(High.Wrapped(e)) }`（4 行ほど）。flow の本体は関数値を書けない（E0806）ので、どの形でも当たらない。
  借用元の近いもの: Clang の `-Wfunction-effects`（テンプレートの具体化ごとに効果を推論し、`std::expected::transform_error` に `nonblocking` の関数を渡すと警告しない）、Rust の条件付きの `const`（`~const Fn`、安定版に無い）。
  S-873 の (c) から後で足しても、通っていたプログラムは止まらない（緩める向き）。第 1 期の std で同じ形が当たるのは `map_err` だけである（§19.1 の `Array` の `map` は確保するので `rt` にならない）。
