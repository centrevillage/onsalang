# Q-09 仕様に無いものは拒否する（閉世界の原則）

- 案:
  - 仕様の空白に出会ったら、受理する側に倒さず、拒否する（E0200「この版では未対応」、または構文エラー）。
  - 例外は、受理しないと仕様の例が書けない場合だけにする。その場合は Q-10 で記録する。
- 狙い: 今回の「黙って受理」の多くは、この原則で防げた。後で受理を広げるのは互換性を壊さないが、受理を狭めるのは壊す。
- 費用: 低。ワーカーへの指示に一文を足す。
- 推奨: 採る。
- 決定: 採る（明文化）。仕様にあって未実装のものは E0200、仕様に無いもの（空白）は最も保守的な拒否にして Q-10 で報告する。既に R-81、S-96、S-99、S-103、S-105 で実践していた
- 決定（API への適用、2026-10-03）: 組込みの API も閉じた一覧にする大方針は採る。ただし単に拒否するのではなく、本当に不要かを議論する。事前に設計した API が十分とは限らず、実装の中で必要と分かる場合があるからである。コーパスの重力に引かれただけのものは省く。候補は `decisions/A/` に記録して議論する（R-96 の議論から）
