# D-08 第 1 期の効果の扱い: `Alloc` だけを認識し、`test` ブロックの中でだけ使える

- 案: 効果行は構文解析と名前解決まで通す。第 1 期で意味を持つのは `Alloc` だけで、他の効果名は E0200。`Alloc` を要する操作（`Buf.zeroed`、`render`、`impulse`）は、`uses {Alloc}` を持つ関数と `test` の本体でだけ呼べる（§8.5 の「テストランナーが `Alloc` を提供する」の部分だけを実装する）。
  `Buf[T]` はインタプリタの内蔵型で、C / WASM / JS バックエンドは `Buf` を含む関数を出力しない（E0200）。
- 理由: M3 の受け入れ（`resonator decays`）が `impulse(48000) -> Buf[F32] uses {Alloc}` と `o.out: Buf[F32]` を使う。効果の仕組み全体（handler、証拠渡し）を入れずに、この経路だけを通す。
- 代替: `render` を `[F32; N]` を返す形にして `Buf` を避ける。`N` が実行時の値なので無理。
- 追記（2026-10-03、レビュー R-27）: 効果行の変数（`[e]` と `uses {e}`）も第 1 期では宣言の時点で E0200 にする。効果の多相は、第 2 期に handler と一緒に入れる。
- 追記（2026-10-04、レビュー R-129、S-74）: 効果行の名前は、他の名前と同じく解決する（見つからなければ E0302）。第 1 期は、効果の宣言を std の中でだけ受け付け（名前と操作のシグネチャを集める）、利用者の `effect` 宣言は E0200 のまま。
  std は `pub effect Alloc {}` を宣言して prelude に入れ、コンパイラは lang item として知る。`Random` も std に宣言し（モジュールの名前は仮。第 2 期の std の設計で確定する）、`std/test.onsa` は `use` で取り込む。`Alloc` 以外の効果を効果行に書くと、名前が解決できた上で E0200。
- 追記（2026-10-05、レビュー R-125、S-97）: 効果行に無い効果の使用（E0601）は、`Alloc` だけでなく std が宣言する全ての効果について検査する。`test` の本体では、ランナーが `Alloc` と `Random` を与えるので例外のまま。
  `Alloc` 以外の効果は効果行に書けない（E0200）ので、E0601 の修正候補（効果行への追加）を出さず、「この版では `Random` はテストの本体でだけ与えられる」と note で示す。テスト用の補助（`check` など）を `test` の本体に限る規則は作らない（効果の規則が事実上そうする）。
