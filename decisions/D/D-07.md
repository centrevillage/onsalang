# D-07 `std` は Onsa のソースで書き、プリミティブは `target fn` で宣言する。ソースはバイナリに埋め込む

- 案: `std/math.onsa` は次のように書く。

```onsa
pub target rt fn exp[T: Float](x: T) -> T
pub target rt fn sqrt[T: Float](x: T) -> T
```

  各バックエンド（インタプリタ、C、WASM、JS）が `std.math` の `target` 宣言の実装を持つ。`std` のソースは `include_str!` でコンパイラに埋め込み、`wasm32` でもファイル I/O なしで使える。利用者のパッケージの `target` 宣言は、第 1 期では `bind` が無いので E0200。

- 理由: §15.2 の `target` は「実装をビルドターゲットが与える宣言」で、プリミティブの意味そのもの。`extern "C"` にすると核が C 系以外へ出せなくなる（§13.2 の E1010）。
- 代替: コンパイラ組込みの名前。ソースが無いので `onsa primer --std` と `interface` に出すものを別に持つことになる。
- 追記（2026-10-04、レビュー R-79、S-69）: 組込み型のメソッド・関連関数・関連定数も、std の `impl` に Onsa で宣言する（`impl F32 { pub target rt fn to_bits(self) -> U32 }`、`impl[T] Buf[T] { pub target fn zeroed(n: U32) -> Buf[T] uses {Alloc} }`）。
  他の操作で書けるものは本体ごと std に書き、プリミティブだけを `target` にする。`[T; N]` と `Buf[T]` の受け手は `Span[T]` のメソッドを引く（§5.3）。rt・効果・引数のモード・doc は通常の規則で扱い、`rt.rs` / `effects.rs` の名前による特別扱いを無くす。
  Rust に残す表は、std の `target` 宣言の修飾名 → `Prim`（std の宣言と 1 対 1 であることをテストで確かめる）、組込み型の trait（§6.3。第 1 期の暫定で、第 2 期に std の `impl` へ移す。S-72）、`as` の可否（§3.3）、Option / Result の lang item（S-71）、`array.from_fn` の展開だけ。
  理由: 第 2 期に足す API（`Str`、`Map`、`Set`、`Array`、`Bytes`）の大半は組込み型のメソッドで、表に持つと全てがプリミティブになり、各バックエンドで実装し直すことになる。API の追加が std の差分として見え、仕様の一覧と照らしやすい。
- 追記（2026-10-04、レビュー R-79、S-71）: Option / Result も std の enum として宣言する（§4.1）。コンパイラが知るのは lang item の表（std の経路 → 役割）の 2 行だけで、使い道は prelude と `?` に限る。sema は `?` ごとに早期に返る列挙子の番号を決めて Core に渡す。
  std の `target` 宣言の引数と返り値には Option / Result を使わない（スカラ、配列、タプル、`Span` だけ）。Option を返すメソッド（`get`、`narrow_*`、`checked_*`）は std に Onsa で書き、範囲の比較などの後で、std の中だけで見える（`pub` の無い）プリミティブを使う。
  バックエンドは Option / Result の配置を知らずに済み、一般の enum に対応すれば動く。
- 追記（2026-10-04、レビュー R-80）: std のモジュールの一覧は、build.rs で `std/` のファイルから生成する（モジュールの経路はファイルの経路から決める。§15.1 と同じ規則）。driver とテストに手書きの表を持たない。std のファイルを足すだけで済む。
- 追記（2026-10-04）: `array.from_fn` の特別な展開（無名関数をその場に展開する）は、Core が関数値を扱えない第 1 期の回避策である。M5 で `std.test.check` のために関数値を降下するときに、普通のプリミティブへ寄せる（R-08 補足）。
- 改め（2026-10-25、親）: S-670・S-661（2026-10-25）: 利用者の `target` 宣言の E0200 を §15.2 と診断の表に書いた（形によらず名前の段）。追記の「関連定数」は std の `impl` に値で書く（`target const` は無い）。`impl` の `target fn` は構文の段がどのパッケージでも読み、std の外は E0200
