# 実装の判断（D）

実装の作り方の判断（字句解析と構文解析の作り、AST と Core IR の形、診断の登録簿、テストの基盤など）。
判断を受けた実装の共通の形は `design/` にある。

## 本文のラベル

`docs.py new D` は、この節のラベルを新しい D の雛形にする。

- `案`: 採るやり方。
- `理由`: そのやり方を採る理由。
- `代替`: 採らなかったやり方と、採らない理由。

決めた後の改めや追記は、`docs.py note <ID> 改定 <文> --by <誰>` などで、日付の付いた箇条として足す。

## 計画から移した D

D-01〜D-16 は、計画 §1 の見出しの節から、本文を一字も変えずに移した。
`decided` は計画 §1 の頭の文「全て 2026-10-01 に案の通り決定。」から取った（D-16 は本文の決定の日付の 2026-10-06）。
本文には、後から足した `改定（<日付>、…）`・`追記（<日付>）`・`実装（<日付>、…）` の箇条がある。
