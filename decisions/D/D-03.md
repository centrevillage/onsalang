# D-03 Core IR は構造化ツリー。flow は `init` / `reset` / `ctl` / `tick` / `process` の 5 関数に落とす

- 案: Core は CFG / SSA ではなく、**構造化された文と式のツリー** にする（`if` / `while` / `for` の範囲、`match` は enum のタグの `switch`）。全てのバックエンドがソース（C / JS）か構造化バイトコード（WASM）なので、CFG に落とすと構造を復元する作業が各バックエンドに要る。
- flow は次の 5 つの Core 関数に落とす（計画 §2.2 の `process` を 2 つに分けたもの）。

| 関数 | 内容 | 呼ばれる場所 |
|---|---|---|
| `f.init(cfg, sr) -> State` | `init` のクロックのノード（`let` と巻き上げた部分式）を評価して状態を構築する。段の順で読む前に必ず書かれるフィールドは設定しない（R-92） | 利用者、親の `init` |
| `f.reset(inout s)` | 遅延の状態を `init` 値へ、`w = 0`、サブインスタンスを `reset`、`poisoned = false` | 利用者、親の `reset` |
| `f.ctl(inout s, params: Params)` | `block` のクロックのノード（`let` と巻き上げた部分式、S-33）を順に評価し、`sample` から読まれるものを状態へ書く。サブインスタンスの `ctl` を呼ぶ | `f.process` の先頭、親の `ctl` |
| `f.tick(inout s, <sample の入力の値>...) -> <出力の値>` | `sample` のクロックのノードを順に評価する 1 サンプル分。遅延の保存は、全ての遅延の出力を読み、保存する値を全て評価した後にまとめて行う（R-13）。サブインスタンスの `tick` を呼ぶ | `f.process` のループ、親の `tick` |
| `f.process(inout s, params, input, output)` | `ctl` を 1 回呼び、`for i in 0..<frames` で入力を全て読み、`tick`、出力を全て書く（§11.6 の不変条件。引数の名前は S-30） | 利用者、export の wrapper |

（2026-10-06、点検 C-66: 表を S-102 のクロック、S-33 の巻き上げ、S-30、R-13、R-92 に合わせた。export の境界の `initialized` は S-27。）

- `process_inplace` は `process` に同じ `Span` を渡すだけの関数。`render` は `Buf` を確保して `process` を 1 回呼ぶ（インタプリタと `Alloc` のあるターゲットだけ）。
- 理由: 親 flow が子を点ごとに呼ぶには、子のブロックレートの計算（`ctl`）とサンプルの計算（`tick`）が分かれていなければならない。FAUST の `compute` を `control` と `loop` に分けた形と同じ。`tick` が関数呼び出しになるのは C コンパイラがインライン化するので問題ない。
- 代替: 子の `process` をブロック単位で呼び、中間バッファを置く。状態の大きさにブロック長が入り、§12.4 の「コンパイル時に決まる」が崩れる。
- 追記（2026-10-04、レビュー R-80）: 降下はターゲットによらない形にし、その後に **ターゲットの pass** を置く。この pass が、bulk の分割（R-90 (i)）、配置（大きさ・アラインメント・オフセット）と溢れの検査を行い、結果を Module に記録する。
  C、`onsa interface`（S-65 の `--target`）、`onsa audit`、E0820、WASM / JS は記録を読むだけで、計算し直さない。sema の `layout.rs` は消す（言語の意味として大きさを使う所は S-32 で無くなった）。
  到達解析は Core に一つ（`reach(module, roots)`）で、C の生成の範囲、`--backends all` の超越関数の判定（§13.4）、`onsa audit --panics` が使い、走査（`walk`）も Core のものだけにする。
  NRVO は Core の一か所で §12.7 どおり（全ての経路で返すローカルが一つ）に判定して記録し、C と監査はそれを読む（R-81 で結果の置き場所を明示するときに行う）。
- 追記（2026-10-04、レビュー R-81）: 降下の最後に正規化の段を置き、次の形にする。R1: 書き込みを持つ式（`inout` を渡す呼び出し、代入）と、文を含む式（`Block`、`IfExpr`、`Switch`）は、文の位置にだけ置く。R2: 文の位置の式の木に含まれる、効果を持つ演算（panic しうる演算、効果を持つ呼び出し）は、木全体で一つまで。
  残りは純粋な演算（panic も書き込みも無い）にする。R3: 文の位置へ出すものは評価順（§3.5）どおりに並べ、書き込みを持つ式を出すときは、それより先に評価される部分のうち、その書き込みが届きうる場所を読むものを先に出す。R4: 条件付きで評価される部分（`&&` / `||` の右辺、`if` / `match` の腕）から出すものは、その条件の内側に出す。
  木の中に書き込みが無く、観測できる演算が一つだけなので、バックエンドは木をどの順で評価してもよく、文を順に出し、条件付きの評価（C / JS の `&&` と `?:`、WASM の `if`）を保つだけでよい。演算の分類（純粋・panic しうる・書き込みを持つ）は Core の一か所で決め、プリミティブの分類は R-79 の `Prim` の表に欄として持たせる。
  検証器（R-82）が R1・R2 を検査し、R3・R4 は評価順の再現の期待値付きテストと、インタプリタと C の差分テストで押さえる。移動とコピーを区別して表す。破棄は `Drop(place)` の文として、sema が経路を見て列挙した破棄の点（R-32）から写す。
  型ごとの破棄の種類（何もしない／ヒープの解放・参照カウント／利用者の `Drop`）は Core で一度だけ決め、各バックエンドは破棄の種類を `_` 無しで網羅し、実装していない種類は生成の前に E0200 にする。
  検証器は「所有する値は全ての経路でちょうど一度、移動か破棄される。移動・破棄の後は使わない」を検査し、インタプリタは破棄・移動した後の値を読むと内部エラーにする（テストでは常に有効）。結果の置き場所は Core に明示する（集成体を作る式に宛先の場所を持たせ、sret の関数には返り値の置き場所のローカルを置き、NRVO はそれへの割り当てとして記録する）。
  宛先が構築に使う値から読まれうる場合は、一時変数に作ってからコピーする（§12.7、S-76）。重なりの判定の関数は一つにし、sema の E0702 と共有する（場所の経路を表す小さな型を共有する）。進め方は R-06 と同じ: 設計メモを先に書かせて親が読み、最も能力の高いモデルに推論を深くして実装させ、別のエージェントが仕様だけから期待値付きのテストを書いて壊しにいく。
- 追記（2026-10-05、レビュー R-89、D-15）: Core の段を「降下 → 正規化 → 定数の評価 → ターゲットの pass → export の計画」とする。定数の評価は、関数を呼ぶ `const` の初期化式を評価してリテラルに置き換える段で、ターゲットによらない（超越関数を含む定数の評価に何を使うかは R-108）。
  今は driver のビルドの経路にだけあり（`inline_consts`）、テストの `emit_c` は通っていない。
  export の計画は、パッケージとターゲットごとに一度だけ作る記録で、flow ごとにシンボル（`prefix` + 名前、重なりは E1011）、生成する API（`init` / `reset` / `process` / `render` と入出力の形、S-30）、状態とパラメータの配置への参照、パラメータの情報（`@param`）、panic の扱い（§9.2）と、そのために状態が持つフィールドを持ち、関数ごとにシンボル、FFI の型のシグネチャ、panic の通知を持つ。
  降下が作る状態のフィールド（`poisoned`、`initialized`、bulk のポインタ）は、作った時点で役割の印を付けて記録し、名前の文字列で探さない。入出力の役割は `FlowMeta` の明示の一覧から取り、引数の位置（`skip(2)`）で決めない。C・WASM・JS のバックエンド、`play`、ブラウザの IDE のパラメータの UI は、この計画を読むだけにする。
  計画の中身のうち、C の API の名前空間・ABI の版・関数の panic の通知（R-121）と、パラメータの ID（§11.7）は、それぞれの決定で埋める。テストは、ビルドと同じ入口（D-05 の改定、R-80 (5)）を通り、定数の評価と export の計画の段まで含める。
