# 決定

仕様の空白（S）、設計の決定（D）、反映の作業の決定（K）、プロセスの決定（Q）、組込み API の候補（A）を、ID ごとに一つのファイルで持つ。
一つの決定の本文はそのファイルだけに書き、仕様・規則・作業のファイルからは ID で指す。

- 置き場所は `decisions/<種類>/<ID>.md`（`S-537` は `decisions/S/S-537.md`）。種類ごとの本文のラベルは、各ディレクトリの `README.md` にある。
- 一覧と逆引きはコミットせず、道具が出す。`python3 -B tools/docs.py list S --status OPEN`、`show <ID>`（担う作業、この決定を指す R、実装待ちの項目）、`back <ID>`（ID を挙げる本文）。
- 書くのは親で、利用者の決定を記録するとき（新しい決定の登録、決定、補い）。手順は `rules/process.md` にある。担当は報告で親に返す。
- 頭の欄は TOML で、`+++` の行で囲む。値に `\` を書かない、キーを重ねない、頭の欄の中にコメントを書かない。状態と欄は `docs.py set`、本文の補いは `docs.py note`、新しい決定の番号は `docs.py new`（主のツリーだけ）で書く。

## 頭の欄

| キー | 形 | 値 | 要る | 意味 |
|---|---|---|---|---|
| `status` | 閉じた値 | `OPEN` / `DECIDED` / `DROPPED` | はい | 状態 |
| `spec` | 節の並び | — | いいえ | 仕様の節 |
| `tasks` | ID の並び（W、T、PH2） | — | いいえ | 担う作業 |
| `amends` | ID の並び（S、D、K、Q、A） | — | いいえ | 改めた前の決定 |
| `amended_by` | ID の並び（S、D、K、Q、A） | — | いいえ | 改めた後の決定 |
| `found_by` | 文字列 | — | いいえ | 見つけた票 |
| `before` | ID（W、段、PH2） | — | いいえ | 期限の作業か段（`PH2` は第 2 期） |
| `group` | 整数 | — | いいえ | 空白の組 |
| `decided` | 日付 | — | いいえ | 決めた日 |

- `status`: `OPEN` は未決、`DECIDED` は決めた、`DROPPED` は不要になったか取り下げた。後の決定に改められても `DECIDED` のままで、改めた範囲は本文に書く。
- 実装済みかは欄にしない。`tasks` の作業が全て済めば済みで、`show` が出す。
- `before` は `OPEN` のときだけ書く。要る作業が分かれば作業の ID（`W4-02`）を、まだ分からなければ段（`W4`）を書く。段は段の終わりを期限として比べる（`list --before`・`--stage`）。
- `amends`・`amended_by` は、表から移した決定には書いていない（改めの注は本文にある）。書き方は見直している（`docs/carryovers.md` の「決定の関係の表し方」）。
