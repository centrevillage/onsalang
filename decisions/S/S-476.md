# S-476

- 空白: C++ の桁の区切り `1'000'000`（C++14）。今は数の後の `'000'` を一字でない文字リテラルの E0001 と読み、note は「文字列は `"…"`」で、書き手の意図と違う（`1'000` は閉じない `'000` の E0001）。Onsa の数は `_` で区切れる（§2.4）ので、`'` を `_` にする候補の読みが一つ。
  数に接する `'` は S-466 と別に決められる。第 27 組の下書きの付録で見つけ、Fable も別の S にするのに同意した（2026-10-13）
- 提案: 後の段（急ぎは低）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1、Y）数のトークンの数字の間の `'`（C++14 の `1'000'000`、16 進の `0xFF'FF`、`1'000.5`）は数の一部として読み、E0020 の行 `digit_separator`（字句の段）で、候補は全ての `'` を `_` にした一つ。数字に挟まれない `'` は今のまま文字リテラルの始まり。 §2.4 の数のトークンの定義に「数字に挟まれた `'` も含む」、区切りの文に「16 進では 16 進の数字の間」を添える（Y）。
  - 仕様の節: §2.4（数値リテラルの綴りの項に一文）。
  - 今通るプログラム: 変わらない（数の直後に空白なしで `'` が続く形は今どれも誤り）。
  - 実装の見当: `literal.rs` の `number()` で数字と `'` と数字を同じトークンに含め、`Foreign` に一つ、`foreign/literals.rs` の `spellings` に一つ（30〜50 行）。
  - ぶつかる事例: なし。
