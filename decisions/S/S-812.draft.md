# S-812 値の関数を `!(` で呼ぶ形（`f!(x)`、`f` はローカルの関数値）

- 決定済みで戻さないもの: 関数値の `!` が E0714 であること（S-791、§5.2）。値の `x(...)` の E0020 と候補 `.(`（S-191。定数の候補を残すかは R-301 の判断の残りで範囲の外）。flow の本体の値の `!(` は S-125 の E0806（S-811 の (a) の 1）。
  第 76 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/93/g76/draft.md`）。
- 論点: §15.1（76 行）は値を `x(...)` の形で呼ぶと型によらず E0020（候補 `x.(...)`）、§5.2（82 行、S-791）は `inout self` のメソッドでない呼び出し（関数、関数値、構築子を含む）の `!` を E0714 で「修正候補は一意」とし、S-791 はその候補を「`!` を消す」と書いた。
  関数値の `f!(x)` の `!` を消すと `f(x)` になり、W4-12 の U1 が入れる名前の段の E0020 が当たる。§18.1 の約束（当てた後に同じ段か前の段の誤りを残さない）と S-791 の候補の形が食い違う。関数でない値（定数 `K`、const パラメータ `N`）の `!(` は、どの文も書いていない。
- 今の実装: fn の本体の `h!(x)`（引数の関数値）と `f!(x)`（ローカル）は型の段の E0714「`!` marks `inout self` method calls only (§5.2)」と候補「remove `!`」（`m/fn.out` の w006・w011）。当てると今は誤りなし（`x/loop.out`）。
  定数の `K!(x)` は名前の段の E0020「a value is called as `f.(x)`」と、呼び先の後に `.` を挿入する候補（w022）で、当てた `K.!(x)` は構文の段の E0002「expected a field name or tuple index after `.`, found `!`」（`x/k_bang_after.onsa`）。
  const パラメータの `N!(1)` は型の段の E0401「`U32` is not a function and cannot be called」（w015）。`test`・`const`・無名関数の本体も同じ（`m/ctx.out`）。
- 案: どの案も、`f(x)` で呼ぶ項目と構築子の `!` の E0714 と「`!` を消す」候補（S-791）は変えない。
  - (a) E0714 のまま、候補を呼び先の種類の印にする: 関数型の値は `!` を `.` に置き換える候補（`h.(x)`）。関数でない値（定数、const パラメータ）は型の段の E0401（呼べない値。今の `N!(1)` と同じ）で候補なし。E0714 は候補が必須（登録簿）で、`.(` にしても E0401 が残るので、その形は E0714 にしない。名前の段の値の E0020 は `!(` に当てない。
  - (b) 名前の段の E0020: 値の `x!(...)` を値の `x(...)` と同じ E0020 にし、候補は `!` を `.` に置き換える（`h.(x)`、`K.(x)`）。S-791 の「関数値」を E0714 の並びから外す。
  - (c) E0714 で候補なし（関数値も定数も）。§5.2 の「修正候補は一意」に値の例外を書き、登録簿の E0714 の必須の印（`codes.rs` の 369 行）と必須の一覧のテスト（476 行）を直す（直さないと `Code::without_fixes` が候補の無い E0714 を E0002 に変える）。
  - 形ごとの出力: `h!(x)` は、(a) が E0714 と候補 `h.(x)`、(b) が E0020 と候補 `h.(x)`、(c) が E0714 だけ。`K!(x)` は、(a) が E0401 で候補なし、(b) が E0020 と候補 `K.(x)`（当てると E0401）、(c) が E0714 だけ。
  - 書き手から見て（修復のループの回数）: `h!(x)` は、(a)・(b) が一回、(c) が二回。`!` を書く書き手は、関数がレシーバか引数を変える（Julia の `sort!` の命名、`inout` の引数のつもり）と読んでいるか、印を取り違えている。
    `h` の型が `fn(inout F32)` なら、(a)・(b) の候補の後の `h.(x)` は modes の段の「`inout` を書く」誤り（後の段、その候補で直る）で、当て続けて二回で止まる。(c) はその前に書き手が `.(` を自分で書く。
    `K!(x)` は値を呼ぶ誤解で、(b) の候補の後も E0401 が残る（`K` は関数でない）。(a)・(c) は候補なしで、note で値は `.(` で呼ぶことを示す。
  - 修正候補: (a) の候補は呼び先の型が関数のときだけで、当てた後は名前の段と型の段を通る（`m/fn.out` の w010 の `h.(x)` は誤りなし）。当て続けて止まる。(b) の `h.(x)` も同じ。(b) の `K.(x)` は型の段の E0401 が残るが、E0020 は名前の段なので約束の内。
    (c) は候補なしで止まる。どの案も今の `K.!(x)` を作る候補（構文の誤り）は消える。
  - 通るプログラム: どの案も変えない。
  - 規則と例外: (a) は S-811 の (a) の 2 から決まり、§5.2 の 82 行の候補の文を「`!` を呼び先の種類の印に置き換える（関数値は `.`、他は消す）」と改める。S-791 の決定の「`!` を消す候補」は、関数・構築子にはそのまま、関数値には置き換えに読み替える（候補の形は §18.1 で例で約束でない。候補の数の「一意」は保つ）。
    (b) は §15.1 の 76 行を「`x(...)`・`x!(...)` の形」に広げ、§5.2 の 82 行と S-791 から関数値を外す。`~` の値（S-590 の E0812）と順が逆になる。(c) は §5.2 に例外の一句と、登録簿の E0714 を必須から外す改め（必須の印の規則に例外を足す）。
  - 実装の量（W4-12 の U1）: (a) は、名前の段の値の E0020（`kinds.rs::value_called` を呼ぶ所）を `CallKind::Bang` で呼ばない約 1〜2 行と、型の段の E0714（`body/calls.rs` の 96・137 行の辺り）の候補を、呼び先の型が関数なら `!` の 1 字を `.` に置き換える形にし、関数でなければ今の E0401 を先に出す約 +4 行。
    (b) は、名前の段の値の E0020 を `CallKind::Bang` にも当て、候補を `!` の置き換えにする約 +5 行（`foreign` の行 `value_call` の候補の形も分ける）。型の段の E0714 の関数値の枝は名前の段が先に止めるので届かない。(c) は約 +3 行（候補を外す）に、`codes.rs` の E0714 の必須の印と一覧のテスト（約 ±3 行）と §5.2 の文。
  - 後の作業への手当て: (a) は、W5-02 の関数型のフィールドの `s.f!(x)` が同じ型の段の判定に入り、手当ては要らない。(b) は W5-02 の `s.f!(x)` を型の段の E0020（行 `field_call`）にする分岐が要る。(c) は無い。
- 他言語: S-811 の「他言語」のとおり。rustc はクロージャに `f!(2)` を書くと「cannot find macro `f`」で候補なし（`probe/other/r1.rs`）。Julia の `f!` は名前の一部で、検査されない。どれも Onsa の `!` と意味が違う。
