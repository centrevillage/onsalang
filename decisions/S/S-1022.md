# S-1022 形の E0200 の `impl Tr for Ty` と、宣言が E0200 の利用者の trait の `impl` の後の、対象の型の使う所の診断（`Q.hash(q)` の E0302、`T: Hash` の E0416、`p == q` の E0401）

- 空白: §18.1 は、`Default` の他の trait の `impl Tr for P` を形の E0200 とし、メンバを読まない（99〜100 行）。同じ節は「読めなかった部分は誤りの型として扱い、それを使う側には診断を出さない」（103 行）とし、宣言が E0200 の `trait` のメンバを読めなかった部分とする。S-774 は、derive の一覧のこの版で E0200 の trait を「書いた trait として満たす」とした。形の E0200 の `impl` が対象の型に与えるはずだったメンバと trait を、使う所でどう扱うかは書いていない。
  今（`2a416e35`）は、その `impl` が何も与えないものとして使う所に診断を出す。`impl Hash for Q { fn hash(self) -> U64 }` の後の `Q.hash(q)` は E0302、`T: Hash` に `Q` を渡すと E0416（`hash_form`、`bound_form`）。`impl PartialEq for P` の後の `p == q` は E0401（`form_operator`）、`impl Add for V` の後の `p + q` は E0401・`p.add(q)` は E0413（`form_add`）、`impl Show for P` の後の `"{p}"` は E0416（`form_show`）。`impl Default[I32] for P` の後の `P.default()` は E0302（`default_args`）。
  `trait Tr { fn m(self) -> I32 }`（E0200）と `impl Tr for P`（E0200）の後は、`p.m()` が E0413、`P.m(p)` が E0302 で、一つの未対応から 5 件になる（`user_trait_decl`）。境界 `T: Tr` は E0200 で、`k(p)` は黙る（`user_trait_bound`）。
  見出しの誤りを直すと形の E0200 になる `impl` では、直した後に使う所の診断が増える（`impl Hsah for P` を `Hash` に直す `hash_typo` → `hash_typo_fixed`。`impl std.core.Hash for P` の E0302 の候補 `add use std` を当てると 1 件が 2 件、`form_path_use_fix_before` → `form_path_use_fix_after`）。
  読みは (1) 今のまま（この版ではその `impl` は何も与えず、使う所の診断は本物。`impl` を消しても残る） (2) 書いた trait だけ満たすとみなす（S-774 と同じ道。メンバは読まないので、`.` の後の名前と値のメソッドは今のまま） (3) その型のメンバと満たす trait を読めなかった部分とし、使う所に診断を出さない（S-850 と同じ道。その型の本物の綴りの誤りも `impl` を消すまで隠れる） (4) メンバの名前と署名を読んで数え、書いた trait を満たすとみなす（99 行の「メンバは読まない」を改める）。どの読みでも通るプログラムは変わらない。S-1019 の対象の側だけの誤りの形（`impl Hash for Al`）は、どの読みに決まってもこの決定に従う。
