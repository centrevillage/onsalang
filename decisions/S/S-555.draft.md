# S-555 インスタンスの修飾子の構文

- 決定済みで戻さないもの: S-371（`.` の直後の予約語は名前として読む）。§19.1 の「インスタンスを指す名前（ハンドル）と、止める命令は持たない」。S-110（`if` / `match` の枝の E0811 と `if~` / `match~`）。S-170 の節の形（`when c` / `reset_if r`）は X-7 で見直す対象なので、案 (a) に並べる。
- 論点: §19.1「インスタンスの呼び出しに、`when c`（`c` が真の刻みだけ動く）と `reset_if r`（`r` が真の刻みで状態を初期値に戻してから動く）の節を付ける方向とする（`seq~(tick) when running reset_if start`。キーワードは予約済み、§2.2）」。
  X-7 は、修飾子を連鎖の形（`saw~(f0).when(active).reset_if(on_start) + sin~(f0)`）で付け、新しい flow を合成する方向を示した。
  - (1) 後置の節か連鎖か。(2) 連鎖なら、修飾子の名前に印を付けるか。§2.6 は `~` を「状態を持つものを作り、進める」印とし、`!` と並べて「名前の直後の印 + `(`」で呼び出しの種類を表すとする。
    印が無いと、`saw~(f0).when(active)` は出力の値のメソッド呼び出しと同じ見た目になる。値のメソッドと読むと「`saw` は動き続け、出力だけを保持する」意味になり、インスタンスを止める意味と違う（§0.3 の 4）。
  - (3) `let s1 = saw~(f0)` の後の `s1.when(active)` を認めるか。認めるなら、インスタンスの数と、`s1` と修飾した名前の両方を使ったときの意味。§11.5 は「呼び出し位置ごとに独立した状態を持つインスタンスを作る」とする。
  - (4) 関数の形（`when~(saw~(f0), active)`）。flow の引数には出力の値が渡る（§11.5）ので、flow そのものを受ける形と見分けが要る（X-7 の事前検討のとおり P3）。(5) §19.1 と §2.2 の文。
- 今の実装: 後置の節は E0200（p01、p11）。印の無い連鎖は E0413「`F32` has no method `when`」（p02〜p04、p15）。`~` を付けた連鎖は構文の段を通り、名前の段の E0812（p06、b/p18、b/p20、b/p21）。
  関数の形は頭の `when` で E0200（p05、p08）。`$` は E0001（p07）。`(式) with os2` は E0002（p14）。
- 案:
  - (a) 後置の節（S-170 のまま）。`(saw~(f0) when active reset_if on_start) + sin~(f0)`。結合は `as` / `at` と同じにし、二項の被演算子では括弧が要る（E0011 と同じ規則）。
    実装: 構文に節を一つ足し、修飾子ごとにキーワードが要る。費用の要因: 括弧の規則が `as` / `at` の外にもう一つ増える。後の修飾子ごとに予約語が増え、`default` は std の `Default` のメソッド名なので予約語にできない（§2.2「フィールドとメソッドの名前にはキーワードを宣言できない」）。
  - (b) 連鎖で、修飾子の名前に `~` を付ける。`saw~(f0).when~(active).reset_if~(on_start) + sin~(f0)`。後置の連鎖なので外側の括弧は要らない。
    実装: 構文は今のまま読める（p06）。名前の段で、`a.名前~(…)` の頭がモジュールなら今の flow の呼び出し、頭が flow の呼び出しか修飾子の連鎖なら修飾子と分ける。費用の要因: `filters.resonator~(x)` と同じ見た目の形に二つ目の意味ができ、頭の種類で分かれる。
  - (c) 連鎖で印を付けない（X-7 の一行の形）。`saw~(f0).when(active)`。実装: 名前の段で、flow の呼び出しの受け手と予約語の名前の組を修飾子と読む。費用の要因: 値のメソッドと型に現れない約束で分かれる。予約語でない修飾子（`default`）は `T.default()` と同じ名前になる。
  - (d) 新しい印。`when~~(…)`（印を重ねる）、`when$(…)`（新しい記号）。実装: 字句と構文に新しいトークン。費用の要因: `$` は他の言語で別の意味（シェルと PHP の変数、JavaScript の名前の字）を持つ。`~~` は既にある印に印を重ねる。
  - (e) 他の区別の考え（利用者の問いへの答えとして並べる）: 呼び出しの括弧の中に置く `saw~(f0; when: active)`（Onsa に名前付きの引数は無く、Swift と Python の名前付きの引数に見える）。
    ブロックで囲む `when active { saw~(f0) }`（中の全てのインスタンスを止める。flow に分けて呼び出しに修飾子を付ける形と同じことを二通りに書ける）。
    パイプ `saw~(f0) |> when(active)`（F# と Elixir では値を渡す記号で、インスタンスを渡す意味と違う）。
  - (3) の案: (3a) 認めない。受け手は flow の呼び出しか修飾子の連鎖そのものに限る。(3b) 修飾子ごとに別のインスタンスを作る（X-7 の形）。(3c) `s1` の名前がインスタンスを指し、後の行の修飾子が `s1` のインスタンスにかかる。
  - (4) の案: (4a) 認めない。(4b) 関数の形も認め、印で見分ける（(d) の印）。

- 他言語: 連鎖の読みは言語の中でも分かれる。rustc 1.94.1 で、組み立ての型の同じ設定を二度呼ぶ `Command::new("pwd").current_dir("/").current_dir("/usr")` は後の値が勝ち（`/usr`）、反復子の `filter` を二度呼ぶ形は積（`[0, 6, 12]`）になった（`probe/lang/chain.rs`）。
  Node v26.11.1 の `URLSearchParams.set` の二度は後の値（`?q=b`）、配列の `filter` の二度は積（`probe/lang/chain.js`）。SwiftUI の修飾子は元のビューを包む新しいビューを返し、順で結果が変わる（未確認）。
  Lustre V6 はインスタンスを止める印を引数の側に付ける（`current(STABLE((set,delay) when ck))`、参照の手引き v6.112.1 §1.2.4）。faust-rs は包む形 `ondemand(C)`（README）。
- 推奨と理由: (1)(2) は (b)、(3) は (3a)、(4) は (4a)。確度: (1)(2) 中、(3) 高、(4) 高。
  - 連鎖は、キーワードを修飾子ごとに増やさず、後置なので二項の中でも括弧が要らない。(a) は修飾子を足すたびに予約語が要り、`default` のように予約できない名前がある。
  - 印は要る。印の無い (c) は、値のメソッドと同じ見た目で「出力だけを保持する」と読め、止める意味と食い違う（偽の友人）。今は `F32` に `when` が無いので誤りになるが、型に現れない約束で見分けることになる。
  - 印は新しく作らず `~` を使う。`~` は既に「状態を持つものを作り、進める」印で（§2.6）、修飾子は受け手の状態を止める・戻す・保持の状態を足すので意味が合う。`.when~(` は `.push!(` と同じ「名前の直後の印 + `(`」の形である。
    (d) の `~~` は印に印を重ね、`$` は他の言語の意味とぶつかる。(e) の考えは、名前付きの引数に見えるか、同じことを二通りに書けるか、値を渡す記号と読めるかのどれかに当たる。
  - X-7 の「`~` の数だけインスタンスができる」は、厳密には「`~` の数だけ状態を作るか進める印がある」になる。`.when~` は保持する出力の状態を作り、`.reset_if~` は受け手の状態を戻す。インスタンスの数（呼び出しの位置）は `saw~` の一つのままである。
  - (3a): (3b) は呼び出しの位置に無いインスタンスが増え、`s1` を他で使うかでインスタンスの数が変わる（後で probe や別の式に `s1` を足すと意味が変わる）。(3c) は後の行が前の `let` の意味を変える。
    (3a) は「インスタンスは呼び出しの位置で作られる」（§19.1）をそのまま保ち、修飾子は呼び出しの一部になる。後で緩める向きの変更は壊さない。
  - (4a): 関数の形は、flow の呼び出しの引数に値が渡る規則と同じ見た目で、flow そのものを渡す。印で見分ける (4b) は、連鎖と同じことを二通りに書けることにもなる。
  - あわせて決めること（誤りの形）: `saw~(f0).when(active)`（`~` が無い）は E0811 にして `~` を足す候補を出す（今の E0413 を改める。`when` は予約語で値のメソッドになりえない）。
    受け手が flow の呼び出しでない形（`s1.when~(c)` の `s1` が値、`(a + b).when~(c)`、`par`）は E0812 にし、note で「修飾子は flow の呼び出しに付ける」と示す。`s1` を他で使わないときだけ、`let s1 = saw~(f0).when~(c)` へ移す候補を出す。
  - あわせて決めること（後置の節）: `saw~(f0) when active` は構文の段の誤りにし、note で連鎖の形を示す（旧版の形は対象にしない方針なので、新しい行は立てない）。
