# S-755 `const` の値の位置に失敗した名前を書いたとき（`pub const C: Str = "{KK}"`、`KK` は失敗した `use`）、宣言の型の誤り（この版の Shared を含む型の E0200、`Map`・Affine を含む型の E0407）を出すか（関数の見出しの型の段の E0303 は、本体に失敗した名前があっても出る）

- 決定済みで戻さないもの: 値の位置で単位の以後を止めること（S-692。値の後ろの本物の誤りが次の検査に回ることは受け入れた）。型の位置の失敗した名前の後も値を検査すること（S-689）。
  `const` の型の分類（S-610）と、E0312 の定数の単位（S-734）。署名の段で判定する `const` の型の E0710・E0416（R-37、R-135。整形性の段は値に頼らない）。
  第 73 組の下書きの「S-755 の仕組みの出所」と「S-755 の形の表」の節（写しは `target/notes/81/g73/draft.md`）。
- 論点: §18.1（101 行）は、値の位置の失敗した名前の後、その単位の以後を検査しないとする。§6.6（199〜201 行）の `const` の型の誤り（E0407、この版の Shared を含む型の E0200）は、型の構造だけで決まり値に頼らない。
  値の位置の失敗した名前が、同じ単位の宣言の型の判定を止めるかは書いていない。S-724 は「以後」を検査の順の後と読み、どこまで検査するかを約束しないとしたが、`const` の型の判定を値の前と後のどちらに置くかは決めていない。
- 今の実装: 形の表のとおり。値に失敗した名前があると、`const` の型の E0407 は出ない。値が正しければ値の位置に E0407 が出る。値の型の誤り（`const C15: Buf[F32] = 1`）があっても、型の E0407 は出ない（値を先に検査する）。
  関数では、見出しの型の段の E0303 は本体の失敗した名前があっても出る（`f2`、`g3`）。
- 案: どの案も、値の位置の失敗した名前の後の値の検査（止める、S-692）と、署名の段の E0710・E0416 は変えない。通るプログラムは変えない。
  - (a) 出さない: `const` の型の判定は値の検査の後に置く（E0407 の段は今の登録簿どおり「`const` の評価」）。値に失敗した名前があれば、型の E0200・E0407 は名前を直した次の検査で出る。仕様の §6.6 か §18.1 に一句書く。
  - (b) 出す: `const` の型の判定は値に頼らない判定として、値の検査より先に行う（関数の見出しの型の段と同じ）。値に失敗した名前があっても型の E0200・E0407 を出し、値の検査はしない（単位の最初の誤り）。
    置き場所は、`check_const` の頭（値の検査の前）か、署名の段（U4a の整形性の段）。仕様の §6.6 に一句書く。
  - (c) 約束しない: S-724 と同じく、どこまで検査するかは実装の順で決まり、仕様に書かない（今の実装の順なら (a) と同じ出力）。
  - 形ごとの出力: `C1`〜`C5`・`C8`〜`C10`・`M1` は、(a) が何も出ない、(b) が E0200（Shared）か E0407（`Map`・Affine）、(c) が実装の順による。`C6`（Copy）はどの案も何も出ない。
    `const C15: Buf[F32] = 1` は、(a) が値の E0401、(b) が型の E0407（同じ型の段で位置が先。`check_const` の頭に置いても署名の段に置いても同じ）。`impl[T] W[T] { const Z: T = 1 }` は、(a) が値の E0401（計画の E0200 と違う）、(b) が型の E0200（計画どおり）。
  - 書き手から見て（修復のループの回数）: `use` の綴りを誤った `const C1: Str = "{KK}"` は、(a) が三回（`use` を直す → この版で Shared の `const` は書けない E0200 → `const` を関数などに改める）、(b) が二回（一回目で `use` の E0302 と `C1` の E0200 の両方を見る）。
    E0200 の直し方は値を直すことと関係が無く（値によらず `Str` の `const` はこの版で書けない）、(a) では名前を直す作業が無駄になりうる。`const C15: Buf[F32] = 1` は、(a) が値を直した後に型の E0407 を見る順、(b) が根の誤り（型）を先に見る順になる。
  - 修正候補: どの案も、当たる診断（E0200、E0407、失敗した `use` の E0302）は候補を持たず、当て続けても止まる。
  - 規則と例外: (a) は、`const` の型の判定を値の後に置く一句で、関数の見出し（型の段の誤りは本体の失敗した名前に止められない）と順が逆になる。同じ `const` の型でも、署名の段の E0710・E0416 は出て、E0200・E0407 は出ない違いが残る。
    (b) は、`const` の宣言の型を関数の見出しと同じく値に頼らない判定とする一句で、E0407 の段を「型」に改める。署名の段の E0710・E0416 と同じ扱いになる。(c) は規則を足さず、出力の違い（(a) と同じ）が実装の順に任される。
  - 実装の量（W4-05 の U4b。どの案も U4b は `check_const` の分類を書き換える）: (a) は書き換えた判定を値の後に置いたまま、0 行。
    (b) は、`check_const` の頭に置くなら判定の塊を `check_expr` の前に移すだけで約 +0〜4 行（位置を型にするなら、AST の `const` の型の span を引く分。誤りで `self.failed` が立ち、今の道で評価が止まる）。値を検査しない単位の `read_held` の記録が要るかは確かめていない。
    署名の段に置くなら、見積もり直しのとおり約 +3〜5 行（評価を止める印）。(c) は (a) と同じ 0 行。
  - 後の作業への手当て: (a)・(c) は無い。(b) を `check_const` の頭に置くなら、W9-03（関数を経由する定数の評価）でも評価は `self.failed` の今の道で止まり、手当ては要らない見込み。署名の段に置くなら、評価を止める印を W9-03 の評価器も読む。
    第 2 期で Shared の `const` を書けるようにするとき（S-610 の E0200 を外す）は、どの案も分類の行を変えるだけである。
- 他言語: 
  - rustc 1.94.1（`probe/other/r4.rs`〜`r6.rs`）: `const C: str = undefined_name;` は E0425「cannot find value」と E0277「the size for values of type `str` cannot be known」の両方を出す。`static S: Cell<u8> = undefined_name2;` も E0425 と E0277（`Sync` でない）の両方を出す。
  - g++ 15.2・clang 21（`probe/other/c1.cpp`、C++20）: `constexpr NL x = undefined_name;`（`NL` はリテラル型でない）は、「`undefined_name` was not declared」と「the type … of constexpr variable is not literal」の両方を出す（順は処理系で違う）。
  - どれも、名前の誤りと宣言の型の誤りを同じ検査で出す。Onsa の「単位ごとに一つ」とは報告の数の規則が違い、参考にとどまる。
- 推奨と理由: (b)。確度: 中。
  - `const` の型の誤りは型の構造だけで決まり（§6.6）、値の失敗した名前を直しても残る。偽の連鎖エラーでなく、名前を直しても残る誤りを報告する S-753・S-754 と同じ見方が当たる。
    §18.1 が値の位置で止める理由（後の段が分からない値を扱う必要）は、値に頼らない型の判定には当たらない。
  - 関数の見出しの型の段の誤り（E0303）と、U4a が署名の段で出す `const` の型の E0710・E0416 と同じ扱いになり、同じ `const` の型の誤りが種類によって出たり出なかったりする違いが無くなる。
  - 修復のループが一回短く、直し方が値と無関係な E0200（この版の Shared の `const`）を先に見られる。`const C15: Buf[F32] = 1` のように、値と型の両方が誤りのときも根の誤り（型）を先に示す。
  - 実装は、U4b がどの案でも書き換える `check_const` の判定を値の検査の前に置く形なら、足す行がほぼ無く、評価を止める仕組みも今のものを使う。W4-05 の計画の `const Z: T` の E0200 もこの順を前提にしている。
  - (a)・(c) は実装が 0 行だが、上の違いが残る。(c) は S-724 と同じ扱いで、規則は増えないが、利用者に見える出力が実装の順に任される。
  - あわせて決めること: 型の判定の位置は宣言の型（`Str`）にする（今の値の位置から移す。型を直す誤りなので）。置き場所は約束しない（`check_const` の頭でも署名の段でも出力は同じ）。
    `tasks/diag-codes.md` の E0407 の段を「型」に改め、E0200（Shared を含む型の `const`）も同じ段とする。値の型の誤り（`const C15: Buf[F32] = 1`）も型の誤りが先になる。
  - 別の S にしてよい論点: 無い。
