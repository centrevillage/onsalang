# S-711 境界の `?` を `Dup` 以外に付けた形（`?Show`・`?Copy`・`?Add`）の診断（今は `?Show`・`?Copy` を黙って受理し、`?Add` は E0200）

- 空白: §4.5 は「Affine 型も受け付けるには `[T: ?Dup]` と書いて、この制約を外す」とだけ書き、`?` を `Dup` 以外（種の制約の `Copy`、標準 trait の `Show`、演算子 trait の `Add`）に付けた形を書いていない。
  §4.6 も、種の制約を書けるのは境界（`[T: Copy]`、`[T: ?Dup]`）と trait の要求だけとし、「Affine も受けるのは `?Dup`」と書く（読み (1) の根拠になりうる。73 回目の文書の点検）。
  今の実装は `fn f[T: ?Show](x: T)` と `fn f[T: ?Copy](x: T)` を診断なしで受理して `?` を無視し、`?Add` は E0200（U5b の前と後で同じ。再現は `target/notes/72/w403/u5b/b/rx.onsa`）。仕様に無い形を黙って受理するのは閉世界（`rules/process.md` 8.2 の 2）に反する。
  読みは (1) `?Dup` 以外は誤り（構文か名前か、どのコードか）と、(2) 種の制約は外せて trait は外せない、で割れる。
- 決定: 決定（2026-10-28、利用者。79 回目、第 71 組。細部は ID を挙げて了承）: (b)。
  境界の `?` は暗黙の `Dup` を外す印で、`Dup` にだけ付けられる。`?` を `Dup` 以外（種の制約の `?Copy`、prelude の trait の `?Show`、この版で境界にできない `?Add`）に付けると E0416（境界の誤り）。名前を引いた後に判定し、未知の名前の E0302 と種類の違う名前の E0308 は今のまま先に出す。
  候補は出さない（`?Copy` の意図は `?Dup` とも境界を外すとも読め、一つに決まらない）。note で規則（`?` は暗黙の `Dup` だけを外す。Affine も受けるには `?Dup`）を示す。誤りにする方が厳しく、後で意味を与えて緩めても既存のプログラムは壊れない。
  細部（確認だけ）: 位置は境界の名前。同じ並びに二つあれば位置の順で最初の一つ（§18.1）。この版の境界の trait の E0200 より先に出す。型の段で出す（E0416 の段。`lower_derives` と同じ）。
  仕様は §4.5 の 140 行に書いた。`tasks/diag-codes.md` の E0416 の行に足した。
  実装は W4-05 の U4（`sig.rs::lower_generics` の境界の `match` で、`Dup` の腕の後、trait・種の制約の腕の前に `b.relaxed` の腕。約 +6〜10 行）。事例は `?Copy`・`?Show`・`?Add` を一つずつの単位に。今通る形が誤りになるが、`tests/`・std・`examples/` に当たる形は無い。関係: S-746（`?Sized`）、S-747（重なる境界と矛盾する組）は別の S。
- 経緯: 72 回目（2026-10-26）、W4-03 U5b の壊す側（onsa-break）が仕様の空白として報告し、親が確かめた（前からの挙動）。重大度は低。境界の意味を入れる W5-05 の前に決める。関係: S-107、S-511。
