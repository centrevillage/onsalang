  - 論点 1 入れるか。
    - (i) 型の修飾 `static T`（利用者の書き方）。`T` は §6.6 の静的に配置できる型で、値の中のヒープのオブジェクトが全て静的なオブジェクトであることを表す。
      仕様: §2.2（キーワード）、§4.1・§4.6（Copy の行）・§4.7（リテラルと変換）・§6.6・§11.3・§12.1・§12.8・§13.5・§14.2、§18.1 の他の言語の語（S-459）、fmt。
      実装: 字句・構文・fmt（約 30〜40 行）、型の検査（論点 2〜6 で約 250〜400 行）、事例約 40 件。降下は第 2 期の `Str` と同じ表し方で、破棄の種類を「無し」にするだけ（約 20〜30 行）。
      費用の要因: キーワードを足す（後で足すと `static` を名前に使ったプログラムが壊れるので、入れる見込みがあれば今予約が要る）。前置きの修飾は型の書き方の新しい種類である（今の型は名前、`[T; N]`、タプル、関数型だけ）。
      一覧の言語では `static` は記憶域や型のメンバの印で（C・C++ の記憶域とリンク、Java・C#・JS・TS・Swift の型のメンバ、Rust の `static` の項目と `'static` の寿命）、型の修飾として使う言語は無い。Onsa の中でもマニフェストの `main_frame = "static"`（§12.5）が別の意味で使う。
    - (ii) Shared の型ごとの別の組込み型（`StaticStr`、`StaticBytes`。S-613 の (e) を型ごとに）。Copy の組込み型で、`Param` の代わりに `pub struct SParam { name: StaticStr, value: F32 }` を書くと構造から Copy になる。
      仕様: §4.1・§4.2・§4.6・§4.7・§6.3 の組込み型の trait の表・§12.8・§13.5・§15.1（組込み型の名前）。実装: 型と種と表示（約 40〜60 行）、リテラル（約 30 行）、変換（約 30〜40 行）、メソッドの表（W5-02 の `Prim`、約 30 行）、事例約 25 件。
      費用の要因: 組込み型の名前は隠せないので、後で足すと同じ名前の利用者の型が E0304 になる（予約が要る）。型ごとに別の名前で、`Str` の API を足すたびに静的な版にも置くかを決める。`[StaticStr; 2]` から `[Str; 2]` への変換は別の規則が要る。
    - (iii) std の総称の型 `Static[T]`（lang item。名前は `use` で取り込む。中身は `Str` の取っ手なので、Copy にするには §4.6 の「Shared を含む型は Shared」に、§4.1 の `Ptr[T]` と同じ組込みの扱いの例外が要る。親の直し、段 1・段 2）。`Static[Str]`、`[Static[Str]; 2]`。`T` は Shared の葉（`Str`・`Bytes`。`Array[T]` は論点 6）に限るか、静的に配置できる型の全てにするか（論点 2）。
      仕様: std の型の一覧、§4.7・§6.6・§12.8・§13.5、§4.2 か新しい節。実装: (i) から字句・構文を除いた量（約 250〜400 行）と lang item の表（約 10 行）、事例約 40 件。
      費用の要因: std の型なので、`use` で取り込む形なら後で足しても名前はぶつからない（prelude に置くなら予約が要る）。std の他の型と違い、コンパイラが作り方・変換・（葉に限らないなら）フィールドの射影を特別に扱う。包む型の見た目なので、書き手が `.get()` などの取り出しを探しうる。
    - (iv) 入れない。束縛ごとの静的な値（S-610・S-613）、L5 の `FixedStr`（S-614）、第 2 期の L1〜L3 の形 C、Copy の ID と `const` の表で書く。仕様と実装は変えない。
      費用の要因: 「静的なものだけを指す」を関数の境界（引数、返り値、フィールド）の型で約束できない。長さの決まらない UTF-8 の名前を、容量なしで状態の struct に持てない（`FixedStr` は容量 `N` と ASCII）。第 1 期は例 1・3 の呼ぶ側が書けない（第 2 期の L1・L2 まで）。
  - 論点 2 書き方と書ける位置（(i)〜(iii)）。
    - (w1) 葉の形: 静的な型は `Str`・`Bytes`（と論点 6 で入れるなら `Array[T]`）にだけ付け、集成体は要素に付ける（`[static Str; 2]`、`(static Str, F32)`、`Option[static Str]`、`pub struct Preset { name: static Str, gain: F32 }`）。

    - (w2) 深い形: どの型にも付けられ（`static Param`、`static [Str; 2]`）、フィールドと要素の射影が静的な型を返す（`p.name: static Str`）。名前的な struct に「静的な版」を作り、型の同一性（`static [Str; 2]` と `[static Str; 2]`）の正規化が要る（約 100〜150 行増える）。
      利用者の例（`[static Str; 2]`、`name: static Str`）は (w1) で書ける。`Param` を書き換えずに静的な版を使いたいときだけ (w2) が要る。

  - 論点 3 値の作り方と、リテラルの型（(i)〜(iii)）。
    - 作れる値: 静的な値（S-610 の定め。補間の無いリテラル、`const`、静的な値だけの集成体）、静的な型の場所の射影（フィールド、添字、タプルの添字、`match` の腕の束縛）、静的な型を返す関数の結果。
      作れない値: 実行時の `Str`（補間、`Str` の引数、`Str` を返す呼び出し）は E0401 で、note で「リテラルか `const` から作る」と示す。逆向きの変換は無い。
    - (l1) 期待の型で選ぶ（S-614 の (l1) と同じ）。`let s: static Str = "abc"`、`const NAMES: [static Str; 2] = ["warm", "bright"]`（`const` は型を書くので期待の型がある）。期待の型が無い `let s = "abc"` は今のまま `Str`（§5.4 の静的な値で借用）。費用の要因: 期待の型の無い所では `Str` になるので、静的な型が要る `var` には型を書く。
    - (l2) 文字列リテラルを数のリテラルと同じ制約付きの型変数にし、関数の終わりに `Str` を既定にする（`var mode = "a"; mode = NAMES[i]` で `mode` が静的な型になる）。§4.7 の既定の規則が一つ増え、`FixedStr` の (l1) とも組み合わせを決め直す（約 40〜60 行増える）。

  - 論点 5 変換と、推論・総称・関数型（(i)〜(iii)）。
    - (c1) 暗黙: 静的な型の値は、期待の型が普通の型の位置（借用と `move` の引数、注釈のある `let`、返り値、フィールド、代入の右辺）でそのまま使える（表し方が同じなので値は変わらない）。
      `inout` の引数は型が一致するときだけ（呼ばれた側が実行時の `Str` を書き込みうる）。§5.3 で `[T; N]` を `Span[T]` の引数に渡せるのと同じく、位置で決まる変換である。§3.3 の「暗黙の変換は無い」（数に限らない一般の文。親の直し、段 2）に一文を足す。費用の要因: 型の一致を求めない位置が一つ増え、一致を求める `inout` と関数型の互換と書き分ける。
      深さは、値の一番外だけ（`[static Str; 2]` は `[Str; 2]` の引数に渡せない）か、要素の中まで（Shared の値は不変なので、中まで変えても安全）かを決める（中までは約 20〜30 行増える）。
    - (c2) 明示: `s.to_str()`（(ii)・(iii) はメソッド、(i) は組込みの操作）。§3.3 の `as` は数の変換だけなので使わない。費用の要因: 例 4 の全ての呼び出しに書く。
    - 推論（§4.7）: 型は文の順に一方向で決まる。`if c { NAMES[0] } else { s }`（`s` は `Str`）の腕の型が違うときに、(j1) 普通の型に揃える（約 20 行）か、(j2) 期待の型が無ければ E0401 にする（費用の要因: 腕の型が違うたびに期待の型を書く）。
    - 総称: 静的な型は Copy なので `[T: Copy]` に渡せる（例 `pick(c, NAMES[0], "b")` の `T` は静的な型）。効果行は変わらない。関数型の互換（§8.1 の 1）は型の一致のままで、`fn(Str)` を `fn(static Str)` の位置に置くと E0401（後で緩められる）。
  - 論点 6 使える操作と、書き込み時コピーの型（(i)〜(iii)）。
    - (m1) `Str`・`Bytes` のメソッド、等値、順序、`Hash`、`Show`、補間の穴は、普通の型へ変換して使う（論点 5 の (c1)。結果の型は普通の型のシグネチャのまま、`s.as_bytes()` は `Bytes`）。費用の要因: 静的と分かる性質がメソッドの結果に残らない。
      (m2) 結果も静的な型になるメソッド（`as_bytes() -> static Bytes`）を、メソッドごとに定める。費用の要因: 第 2 期の `Str`・`Array` の API を足すたびに静的な版の結果を決める。

      `[static Str; 2]` のような値の配列の要素の代入（`t[0] = "z"`）はどちらでも書ける（Copy の要素の代入）。
  - 論点 7 S-610・S-613 との関係: (i)〜(iii) のどれも、決定済みの規則を変えずに足せる。静的な値はそのまま束縛ごとに決まり、期待の型が静的な型のときに、その値になれるものの定めとして使う。期待の型の無い `let s = "abc"`・`let p = ("gain", v)` は今のまま（借用の行）。置き換える案は決定を戻すので並べない。
