# S-376

- 空白: 見出しの「括弧の外」の `{`（S-338）が、丸括弧でない囲みの中にあるとき。入れ子の `match` の腕の本体（`if match n { _ => { true } } { 1 } else { 2 }`）と添字の `[ ]`（`if xs[{ 0 }] == 1 {`）は E0002、配列リテラルの `[{ 0 }]` と呼び出しの引数の `id({ 1 })` は通る。
  struct リテラルの既存の判定も同じ分かれ方。§4.4 は「括弧の外」の範囲を書かない。E0002 の文面「a `{` at the start of an expression in a header starts the body」は、これらの `{` に当たらない。W3-21/b で見つけた（2026-10-09）
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R7、B3）見出しの式で本体の始まりと読む `{` は、閉じていない括弧（`(`・`[`・`{`。キーワードに続く `{` を含む）の外（深さ 0）にあるものだけである。括弧の内側の `{` はブロック式か struct リテラルとして読む。
  - 仕様の節: §4.4 の見出しの段落に二文。`spec/tools.md` §3.3 の「見出しの struct リテラルとブロック式」に「括弧の外（§4.4）の」を足す。
  - 今通るプログラムが変わるか: 増える。`if xs[{ i }] == 1 {`、`if match n { _ => { true } } {`、`while xs[{ i }] == 0 {`、`for i in 0 ..< xs[{ 1 }] {`、`match xs[{ 0 }] {`、`if xs[S { a: 0 }.a] == 1 {`、`if match n { _ => S { a: 1 }.a == 1 } {` が通る（今は E0002）。深さ 0 の `if { n } == 1 {`・`if S { a: n }.a == 1 {` は今のまま E0002。
  - 実装の見当: `onsa_syntax/src/parser/expressions.rs` で、後置の添字の `[`、`match` の腕の並びの `{`、式の中の型引数の `[` の中で `no_struct_lit` を `false` にする（`(` と配列リテラルの `[` と同じ形。3〜4 か所、約 10〜15 行）。E0002 の note の「outside parentheses」は意味が合う。fmt の冗長な括弧の除去は第 2 期（W3-12）なので今は実装が無い。
  - ぶつかる既存の事例: なし（`tests/spec/negative/header_block_expression.onsa` と `crates/onsa_cli/tests/cli/pattern_guard_candidates.rs`からの事例は全て深さ 0）。
