# S-719 宣言がこの版の E0200 の利用者の trait と効果の名前（`trait Tr`・`effect Ef`）を、型の位置・値の位置・経路の頭に書いたとき（今は黙る）と、境界・効果行に書いたとき（今は E0200）の扱い

- 空白: 利用者の `trait` と `effect` の宣言はこの版の E0200（第 2 期。`tasks/phase2.md` の trait の定義）で、§18.1 は「誤りのある宣言も、名前まで読めれば名前解決に見せる」とする。
  その名前を型の位置（`x: Tr`）・値の位置（`let a = Tr`）・経路の頭（`Tr.y`）に書くと今は黙り、境界（`T: Tr`）と効果行（`uses {Ef}`）に書くと E0200 になる。宣言のキーワードから種類（trait、効果）は分かる。
  読み: (1) 種類が分かるので、S-713 の族の規則で要る種類でない位置は E0308（型の位置の `Tr` など）、要る種類の位置は今の E0200。(2) 宣言が E0200 の名前は失敗した名前と同じく全ての位置で黙る（境界と効果行も）。(3) 今のまま（第 2 期に宣言を入れるときに揃う）。
  再現は 75 回目の scratchpad の `g65/probe/out_all.txt` の `utrait`・`ueffect` の列（区切りで `target/notes/75/g65/probe/` へ写す）。
- 決定: 決定（2026-10-27、利用者が ID を挙げて了承。76 回目、第 66 組。A2 は確認だけ）: (1)・(p1)。宣言の形がこの版で E0200 の `trait`・`effect` も、名前と宣言のキーワードの種類まで読めるので、その種類の名前として見せ、S-713 の規則を当てる（`x: Tr`・`T: Ef`・`uses {Tr}` は E0308、`T: Tr`・`uses {Ef}` は E0200、`Tr.y()` は名前空間でない名前の後の `.` の E0308）。
  宣言のメンバ（trait のメソッド、効果の操作）は読めなかった部分で、使う所は黙る（値の位置では、§18.1 の失敗した名前と同じく単位の以後を検査しない）。
  prelude と同じ名前の宣言（`pub trait Show`）の後の使う所は、どちらの `Show` も引かず黙る（(p1)、S-675 の E0304 になった名前の扱い。今の実装で既に動いている）。§18.1 の E0304 の段落に、報告が同じ単位の先の誤り（宣言の E0200）に隠れても扱いは同じ、と一句足した。
  仕様は §18.1 の誤りのある宣言の段落と E0304 の段落、`tasks/diag-codes.md` の E0308 の行に書いた。実装は W4-04 の U8（コードの割り当て）。宣言が E0200 の handler の名前と extern のメンバの名前は S-721（後の組）。
- 経緯: 75 回目（2026-10-27）、第 65 組（S-713）の下書きが「別の S にしてよい論点」に置き、独立のレビューの段 1・段 2 が別の S を勧めた。利用者が A12 で了承した。期限は W4-04 のコードの割り当ての単位（U8）の前。
  関係: S-713、S-712、S-462。
