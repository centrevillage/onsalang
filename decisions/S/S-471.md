# S-471

- 空白: 定数の型引数・`as` の型・属性の引数の位置の数の形（`S[017]`）。今は「expected a type, found number literal」の一般の E0002 で、式の位置の `017` の E0020（候補 `17`・`15`）と揃わない。W3-05/b の単位 1 が見つけた（2026-10-13。`w305b1/repro/r7_const_arg_leading_zero.onsa`、G-2）。親が単位 2 のバイナリで確かめた
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R4、既決 S-281、X、Y）数のトークンの形の誤りと候補は、数を書ける位置（式、パターン、定数の型引数、配列型の長さ、属性の引数）によらず同じ。`S[017]` は E0020（候補 `17`・`15`）、`S[0o17]`・`S[1u32]`・`S::[017] {…}` も式と同じ行。数を書けない位置（`as` の型、項目の位置）は S-281 のとおり同じ範囲の置き場所の E0002 が先。 S-281 を改める理由は無い（X）。タプルの添字（`t.017`）は §2.4 の添字の規則で、数を書ける位置に数えない（候補は `t.17` の一つ、Y）。
  - 仕様の節: §2.4（数のトークンの項。タプルの添字の括弧書き）。
  - 今通るプログラム: 変わらない（`S[17]` は今も通る）。
  - 実装の見当: 型引数の並びの構文で `ForeignLit` を定数の型引数として読み、字句の行を報告させる（`foreign/literals.rs` の `misplaced_if` の条件と、型の構文の入口。10〜25 行）。
  - ぶつかる事例: なし。
