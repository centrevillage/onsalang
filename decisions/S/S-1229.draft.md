# S-1229 イベントの入力を持つ部品を塊（`x.up~(M).down~(N)`）の中で動かす形の、塊の走りより後の位置のイベントの見え方

- 決定済みで戻さないもの: S-560〜S-564、S-567 の K・P・E、S-578、S-1207・S-1214（塊の読み）、S-1209（塊の内の条件は走りの時点）、S-1228。下書きの全文（出所、前の議論との整合の表、族の形の表、他言語）は `target/notes/183/g118/draft.md`、伏せた版は `blind.md`、段 1 の報告は `stage1_report.md`、値の模型は `model/`（下書き）と `adv/`（段 1）。
- 論点: 塊（`x.up~(M).down~(N)`）は境界の刻み c で、窓の N 個の位置に当たる走りを先に全て走る。(i) 頭の `at event` の入力に位置 c+1 に来たイベントを処理する位置と、見える走り。(ii) 塊の内に書いたイベントの条件の `reset_if~` の時点。(iii) 塊の内の部品のイベントの出力の位置。
- 今の実装: `at event` は E0302 で書けない。`block` の値を代わりにした 20 件と `reset_if~` の 4 件を今のバイナリで確かめた（親も再現した）。どの案でも今通るプログラムは変わらない。
- 案: (1) 来た位置で処理し、次の境界の走りから見える（足す規則なし）。(2a) 境界で集めて N サンプル遅らせる（イベントの輪）。(2c) 段は来た位置、走りが読む値だけ位置ごとに集める。(3) 塊の中のイベントの入力を誤りにする。出力は (o1) 走りが動く境界の刻みの位置、(o2) その走りの音声の出力が出る位置。
- 値（`x.up~(2).down~(2)`、`x` は音声をそのまま遅れて出す部品、イベントは位置 17）: (1) 17 で処理し境界 18 の走り 0 から見える（その走りが読む音声は位置 16、差 −1）。(2a) 18 の走り 1 の前に処理する（音声と差 0、出るのは 19）。一段の `x.down~(4)` は、(1) でも (2a) でも 17 のイベントが 20 の走りから見える（今の決定のまま）。
  名前の flow で包んだ `w2~(m, v).down~(2)` は、(1) では連鎖と同じ値、(2a) では違う。
- 音符の時点の誤差（(1)）: イベントから出力までが 0〜N − 1 サンプルで揺れ、音声は N 一定。2 倍のシンセの典型 `fir_down2~(voice~(m, p).up~(2))` は塊でなく、どの案でも差 0。揃えるときは、呼び出し側でイベントの値か脈を `sample` の入力へ渡して集める。
- 前の議論との整合（要点）: (1) は S-567 の P8（全ての位置のイベントで動く）・560 行（利用者「イベントはいつも受け手のレートの次の格子で反映すればよく、他の変換は無い」）・S-578（その位置で処理する）・S-1209（イベントの値は走りの時点）・S-1217・§12.4 と合う。
  改めるのは §11.9 の「中の部品の入出力を境界で集めて配る」の「入出力」に「周期の刻みのクロックの」を足す一句（元の S-566 の A10・A3 は `sample * M` のポートに限る字）。(2a) は P8・S-578・S-1209 と矛盾し、同じ位置のイベントの数に上限が無いので輪の大きさが決まらない（§12.4）。
- 推奨と理由: 下書きは (1) と (o1)（確度 高）。字と既決が (1) に揃い、`.up~`・`.down~` のどちらの修飾子もイベントを変えない、の一文で一段・塊・二重の塊が出る。(o1) は「出した刻みの直後に並ぶ」のまま。
