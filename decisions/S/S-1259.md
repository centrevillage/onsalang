# S-1259 細部: 名前の段の E0811（`~` 無しの flow の呼び出し）の `~` の候補を、当てると E0801 が残る形（`prev~(lp(^w))`、`match~ ^w { b => lp(b) }`）でも出すか（§2.6 の「必ず示す」と §18.1 の候補の約束がぶつかる。仮は出す、R-521）

- 空白: §2.6 は「名前の段の E0811（`~` 無しの flow の呼び出し）は、`~` を足す修正候補を必ず示す」とし、§18.1 は「この約束（当てた後に同じ所に誤りを残さない）を満たす候補を作れなければ、候補を出さない」とする。
  引数が `^` か過去の束縛を読む形（`prev~(lp(^w))`、`match~ ^w { b => lp(b) }`）では、`~` を足すと `^` を flow の引数に書いた E0801 が残る（R-521）。S-1245 の「この E0801 に行き着く候補は出さない」は §11.5 の `match` の候補に限る。
  読み: (1) §2.6 が先に立ち、今のまま候補を出す（約束は破れる）。(2) §18.1 が先に立ち、この形では候補を出さない（§2.6 に例外の一文と、登録簿 `crates/onsa_diag/src/codes.rs` の `FixRule::Names` の改めが要る。試した形は診断の約束の検査が内部エラーにした）。(3) 約束を満たす別の候補（`let` に出す形など。一つに決まらず 30 行を超える見込み）。
  仮の扱い: (1)（今の実装。`SPEC-GAP(R-521)` の印は `crates/onsa_sema/src/names/body/flow.rs` と `modifiers.rs` の E0811 の腕）。通るプログラムは変わらない。規則どうしの食い違いなので、W7 の区切りで利用者に示す。
