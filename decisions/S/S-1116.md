# S-1116 ビューの位置（`Span`・平面の引数、生成型のフィールド）に置いた `if`・`match` の末尾の種類が違う形（`take(if c { x } else { y.slice(0, 2) })`）を、末尾ごとにビューへ変換して通すか、腕の型を先に合わせて E0401 にするか

- 空白: §4.7 は期待型を式の中へ下向きに伝えるとし（呼び出し先の引数の型）、同じ段落で「`if` の後の枝と `match` の二つ目以降の腕には前の枝の型」とする。ビューの位置（`Span`・平面の引数、生成型のフィールド）に置いた `if` の末尾の種類が違うとき、どちらが期待型になるかで結果が分かれる。
  今は全て E0401（`take(if c { x } else { y.slice(0, 2) })`、配列と `Buf`、長さ違い、`Span` と `Buf`）。直に書けばどれも渡せる。S-1113 の (A)（末尾の平面のリテラル）の後は、`two_pl(if c { [x, y] } else { ps }, …)` も E0401 になる見込み（今は `check` が通り降下が E0200）。
  読み: (i) 末尾ごとに引数の型（ビュー）へ変換して通す（§5.2「位置を継ぐ」と §5.3 の「要素ごとに `Span` へ変換」。末尾の平面のリテラルを平面と読んだのと同じ理屈。降下の値の全体の写しが要らなくなる）。(ii) 腕の型を先に合わせる（§4.7 の「前の枝の型」。今のまま E0401）。
  (i) の「降下の値の全体の写しが要らなくなる」は、腕の中で宣言した Copy の束縛の末尾では成り立たない（その記憶域は R-481 の仕組みで外へ写すか生かす。161 回目の決定の文の監査）。
  型の段の記録（末尾ごとの変換）の形は、どちらでも同じ（(ii) なら腕の型を合わせる検査が残る）。(ii) から (i) へ緩めても通っていたものは止まらない。
  再現は `target/notes/161/w712/u2c/audit/advisor/`（`in/p7.txt` の `mixed_tail_*`）と `target/notes/161/w712/u2c/memo/forms.txt` の `view_tail`。
  急ぎ: 後の段（今の挙動 (ii) のまま W7-12 を進められる）。
- 決定（2026-11-27、利用者。191 回目、第 122 組）: (i)。ビューの位置（`Span` と `Span` の配列の引数、平面の配列リテラルの要素、flow の生成型 `In`・`Out` のリテラルのフィールド。`process`・`render` の入力、関数値の呼び出しの引数、利用者のメソッドの引数を含む）に置いた `if`・`match`・ブロック式は、発散しない末尾ごとに、そこへ直に書いた値と同じに検査して変換する。末尾の種類と長さは揃っていなくてよく、前の枝の型は末尾に渡さない（§5.3、§4.7 の除外の句）。他の腕の型を借りて型が決まっていた末尾（`take(if c { x } else { mk() })`、`array.from_fn` の末尾、`FixedStr` と並べた文字列リテラル）は、直に書いたときと同じ E0420・E0406・E0401 になる（今は通る。リポジトリの中には見つからなかった）。当たらない位置: `slice`・添字の基、受け手、`for` の反復元、`let` の注釈。
  利用者は、今通る三つの形が誤りになることと、他の腕の型が全て同じときだけ借りる案 (i+)・今のまま (ii) との比べの説明の後に「(i)で」。実装は型の段（`calls.rs::view_arg`・`expressions.rs::check_viewed`、約 30〜50 行の見込み、`SPEC-GAP(S-1116)` を外す）で、置く作業は W8-01 の設計メモ部 2 の割り当てで決める。事例 `tests/spec/negative/view_tail_planar_kinds.onsa` の 4 件の E0401 が通る形に移る。本文の「(i) なら降下の値の全体の写しが要らなくなる」は、W7-12 U2c2b の後は (i) と (ii) の差でない（同じ型の末尾も写しが無い、第 122 組の C の読み）。
