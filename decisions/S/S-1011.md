# S-1011 比較の一方がリテラルを含む複合式（`o == Some("ab")`、`x == ["a"; 2]`、タプル）のとき、他方の型をその中の文字列リテラルの期待の型にするか

- 空白: §4.2 は「比較の他方の型（`t == "warm"`）も期待の型になる」、§4.7（S-614 の補い C2）は「比較の一方が補間の無い文字列リテラルなら、他方の型が期待型になる」とし、直接のリテラル（S-1009 で括弧で囲んだものも）だけを指す。一方がリテラルを含む複合式（`o == Some("ab")`、`x == ["a"; 2]`、`p == ("ab", 1)`）のときを書かない。
  W5-12 U2 の後は直接のリテラルだけで、`let o: Option[FixedStr[4]] = Some("ab")` の後の `o == Some("ab")` は E0401「expected `Option[FixedStr[4]]`, found `Option[Str]`」（同じ式を `let` の注釈の下に置くと通る）。
  割れる読み: (1) 直接のリテラルだけ（今の実装、仕様の字） (2) 比較の他方の型を、一方の式の全体の期待の型にする（`Some("ab")` の中のリテラルまで届く）。(2) は今通るプログラムを変えず、誤りだった形を通す向き。
  仮の扱い: (1)。
- 決定: 決定（2026-11-12、利用者「文字列リテラル型の保留は二期に回し、S-1011 は (1) で」。140 回目）: (1)。比較の他方の型を期待型にするのは、一方が補間の無い文字列リテラルそのもの（括弧で囲んでも同じ）のときだけで、リテラルを中に含む式（`o == Some("ab")`、`x == ["a"; 2]`、`p == ("ab", 1)`）には届かない（E0401。`let` の注釈を付けた束縛か `match` で書く）。根は文字列リテラルの型をその場で決めること（S-1010 と同じ）で、利用者が指摘した。数のリテラルのように保留する形は第 2 期へ回した（`tasks/phase2.md` の `FixedStr` の項。onsa-advisor の見積もりは型の段で約 200〜300 行、仕様の決め方 8〜9 件、設計メモと二つの単位、`target/notes/140/s1005-advisor/onsa-advisor-a551def1b7cac7c14-002.md`）。保留が入るとこの形は通り、比較の特別扱いは要らなくなる。(2) の比較だけの規則（約 15 行）を今入れると、保留のときに捨てになるので採らない。§4.7 の比較の文に、リテラルを中に含む式には届かないことを足した。
