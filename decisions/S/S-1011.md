# S-1011 比較の一方がリテラルを含む複合式（`o == Some("ab")`、`x == ["a"; 2]`、タプル）のとき、他方の型をその中の文字列リテラルの期待の型にするか

- 空白: §4.2 は「比較の他方の型（`t == "warm"`）も期待の型になる」、§4.7（S-614 の補い C2）は「比較の一方が補間の無い文字列リテラルなら、他方の型が期待型になる」とし、直接のリテラル（S-1009 で括弧で囲んだものも）だけを指す。一方がリテラルを含む複合式（`o == Some("ab")`、`x == ["a"; 2]`、`p == ("ab", 1)`）のときを書かない。
  W5-12 U2 の後は直接のリテラルだけで、`let o: Option[FixedStr[4]] = Some("ab")` の後の `o == Some("ab")` は E0401「expected `Option[FixedStr[4]]`, found `Option[Str]`」（同じ式を `let` の注釈の下に置くと通る）。
  割れる読み: (1) 直接のリテラルだけ（今の実装、仕様の字） (2) 比較の他方の型を、一方の式の全体の期待の型にする（`Some("ab")` の中のリテラルまで届く）。(2) は今通るプログラムを変えず、誤りだった形を通す向き。
  仮の扱い: (1)。
