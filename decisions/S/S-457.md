# S-457 直後に `(` が接する数の形の誤り

- 空白: 直後に `(` が接する数の形の誤り（`017(2)`、`0o17(2)`、`1u8(2)`）。W3-20 が入れた `literal_call`（候補を出さない。`017(2)` の候補 `17(2)` を当てると同じ位置に呼び先の E0020 が残り、S-236 のファズの近似に当たる）を残すか、S-350 の決定の向きで候補を出し、残る呼び先の E0020 を二つ目の誤りとするか。
  W3-05/i の設計メモ（残す）と W3-05/t の期待値（出す）が割れた（2026-10-13） 補い（2026-10-13、第 26 組の下書き）: W3-05/i の設計メモの「`017(2)`・`0o17(2)` は E0020（候補なし）」は、候補の無い構文の段の行が E0002 になる（§18.1）ので、今は E0002（W3-05 の単位 1 のバイナリで確かめた）。
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (b) を了承。下書きと Fable が一致、第 26 組）: 直後に `(` が接する数の形の誤りにも数の候補を出し、規則の表は同じ失敗の所で呼び先の E0020（範囲は数から `(` まで、候補は `(` の前に `.`）も報告する。
  並べ方（S-281）で範囲の短い数の行が先に選ばれ、呼び先の誤りは二つ目の誤りとして残る（`017(2)` → `17(2)` → `17.(2)` → 型の段）。S-236 のファズの近似は `held_before` に当たり違反にならない（Fable が類似の形で確かめた）。`literal_call` で候補を消す分かれを外し、`SPEC-GAP(S-457)` を外す。仕様は変えない。
  W3-05/t の保留の事例 `fixes/e0020_numeric_callee_overlap.onsa` を期待値のまま戻す。実装は W3-05（直しの往復）
