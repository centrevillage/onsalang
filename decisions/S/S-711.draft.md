# S-711 境界の `?` を `Dup` 以外に付けた形（`?Show`・`?Copy`・`?Add`）の診断（今は `?Show`・`?Copy` を黙って受理し、`?Add` は E0200）

- 決定済みで戻さないもの: `Copy`・`Dup` が種の制約であること（S-140）、境界の名前の種類の誤り（S-713 (c)、S-719、S-689）。`? Dup` の空白（S-511、未決の別の S）。
  第 71 組の下書きの「S-711 の仕組みの出所」と「S-711 の形の表」の節（写しは `target/notes/79/g71/draft.md`）。
- 論点: §4.5（140 行）は `[T: ?Dup]` で暗黙の `Dup` を外すとだけ書き、`?` を他の名前に付けた形を書いていない。§4.6 は「Affine も受けるのは `?Dup`」とする。
  `?` を `Dup` 以外に付けた形を誤りにするか、どの段のどのコードか、候補を出すかが決まっていない。今の実装は `?` を捨てるので、`?Copy` を書くと書き手の意図と逆に `Copy` を要求する。
- 今の実装: 形の表のとおり。`?Copy`・`?Show` は黙って通り、`?` の無い境界として要求する。`?Add` は境界の trait のこの版の E0200 で、`?` を見ない。
- 案: 
  - (a) 構文の段の E0002。`?` の後に書けるのは名前 `Dup` だけ（`?Copy`・`?Show`・`?Sized` は名前を引かずに E0002、note で規則）。
  - (b) 名前の段で境界の名前を引いた後、`?` が種の制約 `Dup` 以外（`Copy`、prelude の trait）に付いていれば E0416（境界の誤り）。候補は無く、note で規則（`?` は暗黙の `Dup` だけを外す。Affine も受けるのは `?Dup`、Shared は書かなくても受ける）を示す。
    未知の名前（E0302）と種類の違う名前（E0308）は今のまま先に出し、この版で境界にできない trait（`?Add`）は E0200 より先にこの E0416 を出す。
  - (c) (b) と同じ位置で E0020（書き手の誤解を示す形）と、`?X` を `+` と一緒に外す削除の候補。
  - (d) 種の制約には `?` を付けられ（`?Copy` は何もしない、または `?Dup` と同じ意味）、trait に付けると誤り（S-711 の読み (2)）。
  - (e) 今のまま（`?` を捨てて普通の境界として読む）。
  - 形ごとの出力: `?Copy` は、(a) が E0002、(b) が E0416、(c) が E0020 と候補、(d) が通る、(e) が通って `Copy` を要求。`?Sized`（Rust の書き方）は、(a) が E0002、(b)〜(e) が E0302「cannot find `Sized`」。`?Add` は、(a)〜(c) が今の E0200 の代わりに各案のコード、(d) が誤り、(e) が E0200。
  - 書き手から見て: `?Copy` は、Swift の `~Copyable`（複製できない型も受ける）からの写しなら `?Dup` が意図で、既定を Copy だけと思った書き手なら境界を外すのが意図である。意図は一つに決まらない。`?Show` は `Show` を要求したいのか、何も要らないのかが決まらない。
    (a)〜(c) は一回の検査で規則を示し、書き手が選ぶ。(d) は `?Copy` を正しい形と見せ、§4.6 の「Affine も受けるのは `?Dup`」と食い違う。(e) は意図と逆の要求を黙って足し、呼び出し側の E0416 で初めて気付く。
  - 修正候補: (a)・(b) は候補が無く、当て続けても `no-candidate` で止まる。(c) の削除の候補は当てた後に誤りが残らず収束するが、`?Copy` の書き手が Affine を受けたかった場合は、呼び出し側の E0416 で次の回に `?Dup` を書く。意図は決まらないので、候補は情報を失う削除になる。
  - 通るプログラム: (a)〜(c) は今通る `?Copy`・`?Show` などを誤りにする（`tests/` と std に当たる形は無い）。(d) は `?Copy` を通し続け、(e) は変わらない。
  - 規則と例外: (a) は構文の規則に名前 `Dup` を一つ入れる（構文の段が prelude の名前を知る）。(b) は §4.5 に一文で、既にある E0416（境界）の範囲に入る。(c) は E0020 の行を一つ足し、候補の形を決める。(d) は同じ意味の書き方を二つにするか、何もしない書き方を一つ足す。
  - 実装の量: (a) は `onsa_syntax/src/lower/items.rs` の `generics` か構文解析で約 +6〜10 行。(b) は `sig.rs::lower_generics` の境界の `match` の頭に一つの腕（`b.relaxed` で `Dup` でない）と note で約 +6〜10 行（W4-05 の U4、今の計画の仮と同じ所）。
    (c) は (b) に、`+` を含む削除の範囲の計算と候補で約 +15〜25 行。(d) は約 +3〜5 行。(e) は 0 行。どの案も、境界の意味を入れる W5-05 に手当ては続かない（(b) と (c) は E0200 より先に判定するので、W5-05 で `Add` を境界にできるようになっても変わらない）。
- 他言語: 
  - rustc 1.94.1（`probe/other/s711.rs`）: `fn f<T: ?Clone>(x: T)` は「bound modifier `?` can only be applied to `Sized`」（コードの無い誤り）。`?Sized + ?Sized` は E0203「duplicate relaxed `Sized` bounds」。`T: Clone + Clone` と `T: Sized + ?Sized` は診断なしで通る（`probe/other/s711b.rs`）。
  - swiftc 6.3.1（`probe/other/s711.swift`）: `T: ~Copyable` は通り、`T: ~Hashable`・`T: ~Equatable` は「conformance to 'Hashable' cannot be suppressed」の誤り。
- 推奨と理由: (b)。確度: 中。
  - `?` は暗黙の制約を外す印で、暗黙の制約は `Dup` だけなので、他の名前に付けた形は意味を持たない。黙って受理すると、書き手の意図と逆の要求になる。誤りにする方が厳しく、後で意味を与えて緩めても既存のプログラムを壊さない。
  - (b) は名前を引いた後に判定するので、構文の段に prelude の名前を持ち込まず、未知の名前と種類の違う名前は既にある規則のまま先に出る。コードは境界の誤りの E0416 の範囲に入り、規則は §4.5 の一文で足りる。
  - (a) は構文の規則に一つの名前を入れる特別な規則になる。(c) の削除の候補は、意図が一つに決まらない形で情報を失い、実装も多い。(d) は書き方を増やし、§4.6 と食い違う。
  - あわせて決めること: 位置は `?` から名前までの境界の要素（細部は約束しない）。同じ並びに二つあれば、§18.1 の位置の順で最初の一つ。この版の境界の trait の E0200 より先に出す（版によらない規則のコードを先にする、§18.1 の E0200 の段落）。
  - 別の S にしてよい論点（新しい S の候補）: 下の NEW-1（`T: ?Sized`）と NEW-2（同じ境界の重なりと矛盾する組）。`? Dup` の空白は S-511。
