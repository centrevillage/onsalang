# S-702 §8.2 の組込みの `Block`（extern の主張の効果）を、§15.1 の prelude の閉じた一覧に置くか、std の宣言にするか（S-74 の名前の解決の後の `uses {Block}`）

- 空白: §8.2 の 46 行は「組込みの `Block` は操作を持たない `blocking` の効果で、extern 関数がブロックすることを主張するのに使う（§14.1）」とする。§15.1 の prelude の閉じた一覧（`Option Result Some None Ok Err panic Alloc`、trait、種の制約、組込み型）に `Block` は無い。
  S-74 で効果行の名前を解決すると、`uses {Block}` は名前が見つからない E0302 になる（今は綴りの比較で E0200、`target/notes/70/g63/probe/e7_block.onsa`）。prelude にコンパイラの名前として足すか、std の宣言（S-659 の (B) のモジュール）にするかが決まっていない。
- 決定: 決定（2026-10-26、利用者。71 回目、第 63 組、(B)）: (1)。`Block` は `std.core` の `pub blocking effect Block {}` で、prelude にある。§15.1 の prelude の一覧に足し、§8.1 の「`Alloc` だけは prelude にある」を「`Alloc` と `Block`」に改める。
  理由: 組込みではペリフェラルの応答を待つ busy wait が一般的で頻出し（利用者）、extern の HAL の関数が主張した `Block` は効果行で呼ぶ側の全てに伝わるので、`use` を求めるとその手間が繰り返し出る。利用者の型や関数の名前 `Block` が E0304 になる代償は、宣言の一か所の改名で済む。
  親は初め (3)（prelude に入れず `use std.ffi.{Block}`）を推したが、`Block` を書く所を extern の宣言だけと誤って見積もっていた。利用者の異議を受けて改めた。`Block` を効果で表すこと自体は S-704、`Block` の handler に `unsafe` が要ることは S-705。
  実装は W4-03 の U5（`tests/spec/fmt/lists_decl_bodies.onsa` の `pub struct Block` の改名、`tests/spec/negative/flow_clock_names.onsa:92` の `at Block` が変わらないことの確かめ）。
- 経緯: 70 回目（2026-10-26）、第 63 組（S-659）の下書き（onsa-gap、`target/notes/70/g63/draft.md`）が新しい S の候補として挙げ、親が仕様の文を確かめた。S-659 の (A) で std が標準の効果を宣言するなら、U5 の前に決める。
