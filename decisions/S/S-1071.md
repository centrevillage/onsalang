# S-1071 細部: `?Escape` の `T` が未決の引数に書いた配列リテラル（`g([a, b])`、`g(inout [a, b])`、`g([b2, b3])`）の E0710・E0415・E0711 に、型引数を書いて先に決める（S-1070、§4.7）と導く note を付けるか

- 空白: S-1070 の決定 (1) では、`?Escape` の `T` が未決の引数に書いた配列リテラルは普通の配列リテラルで、要素が第二級なら E0710、`inout` なら E0415（場所でない）、`Buf` の要素なら E0711 と候補「`move` を足す」になる。どれも文面が型引数で先に決める道へ導かない（`c::[Span[F32], 2]([a, b])` なら通る）。通るプログラムは変わらない（note の有無だけ）。

  読み: (1) note を付けない（今） (2) 直接の引数の配列リテラルが平面と記録されず、引数の宣言の型の要素が `?Escape` の型パラメータのとき、型引数で先に決める旨の note を足す（置き場の見当は `modes/walk.rs::argument`。候補は外さない）。
  仮の扱い: (1)（今の実装）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
