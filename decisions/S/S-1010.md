# S-1010 細部: 容量 `N` か型変数 `T` が未決の位置で、`FixedStr` の文字列リテラルと別の値が並ぶとき、左から決まる（`pair("ab", t)` は E0401、`pick(["a", "bcd"])` は E0408、`same("ab", t8)` は E0401）か、全てを見てから決めるか

- 空白: §4.2 は「`N` が決まっていなければリテラルの長さを `N` にする」とし、§4.7 は推論を文の順に一方向で進める。一つの呼び出しの引数や配列の要素に、容量 `N` か型変数 `T` を共有するリテラルと別の値が並ぶときの決め方を書かない（比較だけは「左右どちらに書いても同じ」と書く）。
  W5-12 U2 の後（dev `28f1b0a6`）は左から決まる: `fn same[const N: U32](a: FixedStr[N], b: FixedStr[N])` の `same(t8, "ab")` は通り、`same("ab", t8)` は E0401、`same("ab", "abc")` は E0408。`fn pair[T](x: T, y: T)` の `pair(t, "ab")` は通り、`pair("ab", t)` は E0401（未決の `T` は期待の型でないのでリテラルは `Str`）。`fn pick[const N: U32](a: [FixedStr[N]; 2])` の `pick(["bcd", "a"])` は通り、`pick(["a", "bcd"])` は E0408。配列のリテラルの長さ（`[U8; N]`）も同じく左から決まる（前から）。
  同じ族（140 回目、W5-12 U3a の壊す側）: 型が決まっていない対象に文字列リテラルのパターンを書くと、そのパターンで `Str` に決まる（`var o = None` の `match o { Some("a") => … }` の後の `o = Some(t)`（`t: FixedStr[4]`）は E0401「expected `Str`, found `FixedStr[4]`」。再現は `P/w512a/b/c13.txt` の `unresolved_then_fs`）。
  仮の扱い: 今の実装のまま（`rules/leader.md` 5.11。今通るプログラムは変えず、後で全てを見て決める形に緩められる）。
- 決定: 決定（2026-11-12、利用者。140 回目、W5 の区切りの確認だけ。「全て現状のまま」で了承）: 仮の扱いのとおり。容量 `N` か型変数 `T` が未決の位置で `FixedStr` の文字列リテラルと別の値が並ぶとき、一つの呼び出しの引数と配列の要素では左から順に決まる（`same(t8, "ab")` は通り、`same("ab", t8)` は E0401、`same("ab", "abc")` と `pick(["a", "bcd"])` は E0408。`pair("ab", t)` は、未決の `T` が期待の型でないので `"ab"` が `Str` に決まり E0401）。型が決まっていない対象の `match` のパターンの文字列リテラルも `Str` に決まる。呼び出しの全体の型が外から決まっていれば（返り値の位置、`let` の注釈）、それが先に入る。後で全てを見て決める形（`N` は長さ以上の制約）に緩めても、今通るプログラムは変わらない。§4.2 のリテラルの行に足した。利用者は、型検査が文字列リテラルの型をその場で決め、数のリテラルのような保留が無いという理由を聞いて了承した。
