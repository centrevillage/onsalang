# S-645 パッケージの中のファイルを渡して絞った `check` で、そのファイルの経路のディレクトリの名前の E0320 が、ディレクトリの最初のファイルを渡したときだけ出る

- 空白: §2.3 はディレクトリの名前の E0320 を「一つのディレクトリに一つ、位置はそのディレクトリの下の `.onsa` ファイルのうち診断の並べ方（§18.1）で最初のものの先頭」とし、§15.1 は「`check` と LSP は、そのファイルの診断だけを出す」とする。
  `Bad-Dir/a.onsa` と `Bad-Dir/b.onsa` があるパッケージで `onsa check Bad-Dir/b.onsa` は、位置が `a.onsa` なので E0320 を出さず 0、`onsa check Bad-Dir/a.onsa` は 1 になる（W4-14 U2/i の作業ツリー、`P61/w414u2/i/try.py` の `trees/pkg`）。
  読みは (1) 最初のファイルのときだけ出る（今の実装）、(2) 渡したファイルの経路のディレクトリの違反は、そのファイルの先頭にも出す、に割れる。仮の扱いは (1)（`SPEC-GAP(S-645)`）。
- 決定:
- 経緯: 61 回目（2026-10-24）、W4-14 U2/i（onsa-impl）の空白の報告から。族「絞った check の診断の範囲」（S-636 と同じ、族の規則は S-647）。
- 補い（2026-10-25、親）: 同じ形（66 回目、W4-03 U3a1 の壊す側）: 依存の名前と重なるルート直下のディレクトリの E0304（S-246）は、下の `.onsa` のうち最初のファイルの先頭に一つ出るので、別のファイルを渡した `check std/z.onsa` は終了コード 0 で何も出さない（`P66/w403/u3a/b/cases3.py` の `narrow_std_dir`）。
