# S-1123 細部: Copy でない入力（値型の E0810）を使う側の連鎖（生成する `Params`・`Config` を誤りの型にするか。S-1068 を値型の E0810 に広げるか）

- 空白: Copy でない入力（`flow child(s: Str at block, …)`）は E0810 だが、その flow の生成する `Params` を使う所（`p: child.Params at block`）に二つ目の E0810（`child.Params` is Shared）、`struct H { ps: Buf[child.Params] }` に E0416 が出る。E0416 の入力（S-1068）では入力を誤りの型にして使う側に出さない。S-372 は関数型の入力の E0810 で同じく誤りの型にすると決めた（細部）。
  読みは (1) Copy の E0810 も入力を誤りの型にし、使う側の連鎖を出さない（S-1068・S-372 と揃える）、(2) 今のまま使う側にも出す。違いは報告の数だけで、通るプログラムは変わらない。再現は `target/notes/163/g109/advisor/probe/a6.txt` の `s01`・`s02`（親が `s01` の二つの E0810 を確かめた）。
  仮の扱い: (1)（形ごとに挙動を揃える）。W7-13 U3（入力の型の E0810）で入れる。W7 の区切りで確認だけ。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認だけ。「(A)と(B1)はS-1148以外OKです」）: 仮の扱いのとおり。値型の E0810 の入力も誤りの型にし、生成する `Params`・`Config` を使う側に出さない。
  突き合わせ: 助言の担当が固定のバイナリ `onsa-d02ddee` で再現し、仮の扱いが今の挙動と合い、既決とぶつからないことを確かめた（`target/notes/189/reports/onsa-advisor-a5d87f2cf05f2cfce-001.md`）。
- 経緯: 163 回目（2026-11-17）、S-372 の段 1（onsa-advisor）が細部の候補に挙げ、親が登録した。
- 補い（2026-11-17、親）: （2026-11-17、163 回目、文書の点検から）§18.1 の「境界の誤り（E0416）で誤りの型にするのは … flow の入力」は E0416 だけを言い、S-372 の細部（関数型を含む入力の E0810）とこの細部の仮の (1)（Copy でない入力の E0810）を書いていない。W7 の区切りで確認するときに、§18.1 の文に「E0810 の入力も」と足す案と、S-372 の `spec` に §18.1 を足す案を一緒に出す。
