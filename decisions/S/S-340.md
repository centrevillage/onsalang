# S-340 見出しの範囲の端の `as` / `at`

- 空白: 範囲の端の `as` / `at`（`for _ in 0..<m as U32`、`m as U32..<9`）に、二項演算子の被演算子と同じく E0011 の括弧を求めるか。
  今は通る（範囲の記号は二項演算子でない）。`as` の強さは終わりの端で言語により割れる（Swift は `0..<x as Int` を `(0..<x) as Int` と読み、Rust は `0..(x as u32)` と読む）。始まりの端（`x as Int8..<9`）は Swift も始まりの変換と読む（第 13 組の下書きで確かめた）。
  第 12 組の下書きで見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 13 組）: 範囲の両端の裸の `as` / `at` は E0011（候補は括弧で囲む一つ）。規則は「`as` / `at` の式を、それより弱い記号（二項演算子と範囲の記号）の被演算子にするときは括弧で囲む」の一つ。
  fmt はこの括弧を外さない（S-339 の基準の「外すと構文の段の誤りになる括弧」、S-336）。一つの見出しに裸の `as` が二つある形の数え方は S-348 に合わせる。`par` の端は括弧を足すと次に E0417（後の段）。仕様 §3.3、§11.3、`spec/tools.md` §3.3。
  実装は W3-21（`groups.rs` の後段の E0011 の検査に範囲の端の腕を足す。`tests/spec/control/range_half_open.onsa` の `widened` を `0..<(n as I64)` にし試験の名前を改める、E0011 の否定例は `tests/spec/negative/cast_operands.onsa` に `for` の見出しの両端の関数を足す、`tests/spec/fixes/e0020_range_dots.onsa` の `conversion_in_the_end` は元を `0..(n as I64)` に直し `.fix1`・`.fix2` を作り直す、`crates/onsa_cli/tests/range_syntax.rs` の読める形の一覧の `"0..<n as U32"` を括弧の形にし裸の形は E0011 の確かめへ）
- 時期: W3
