# S-1061 `else if` の連鎖や合流の枝の中に入れ子にした `if`・`match` の枝に書いた無名関数は、前の枝の効果行を受けるか（S-1032 の (ii-3) の当たる範囲）

- 空白: §4.7 は「期待型の無い `if`・`match`・配列のリテラル」の「合流の枝に書いた無名関数は、前の枝の型から引数の型と返り値の型だけを受け、効果行と `rt` は受けない」とする。S-1032 の決定は「当たるのは一番外の枝そのもので、枝の中のタプルの要素や `Some(…)` の引数は S-1031 のとおり期待型として全てを受ける」とする。`else if` の連鎖（構文では後の枝の中の `if`）と、後の枝に入れ子にした `if`・`match` の枝に書いた無名関数が、どちらに当たるかを書かない。
  例: `pub fn k(a: Bool, b: Bool) -> U32 uses {Alloc} { let f = if a { mk } else if b { mk } else { fn(x: U32) -> U32 { mk(x) } }; f.(1) }`（`mk` は `uses {Alloc}`）。二枝の形 `if a { mk } else { fn(x: U32) -> U32 { mk(x) } }` は (ii-3) で無名関数の行が空になり、本体の `mk(x)` が E0601（W6-03 U5 の後）。
  読み: (1) 連鎖の三つ目の枝も、入れ子の合流の枝も「合流の枝」で、効果行を受けない（二枝の形と同じく E0601。今は通るプログラムが誤りになる） (2) 入れ子の `if`・`match` は一番外の枝の中の式なので、期待型（前の枝の型、効果行を含む）を全て受ける（誤りなし。二枝の形と書き方で結果が変わる）。
  再現: `target/notes/151/w603/u5/probe/gap1.onsa` の `chain`。W6-03 U5 の前のバイナリでは誤りなし（無名関数の使用を外側が数える）。
  仮の扱い: W6-03 U5 の実装の自然な帰結（`check_closure` の `self.joining`。特別な扱いを足さない、コードに `SPEC-GAP(S-1061)` の印）。U5 の後の形は親が確かめて補いに書く。事例は書いていない（U5/t）。
  急ぎ: W6 の区切りまで（今通るプログラムが誤りになるかが変わるので、確認だけでなく利用者の判断）。
