# S-1135 細部: `vdelay~` の `T: Float` の E0416（R-493）は型の段か flow の検査の段か

- 空白: §11.4 は `vdelay~` の `T: Float`（でなければ E0416、R-493）とし、§18.1 は型引数の要求の E0416 を型の段に数える。`vdelay~` の要素の型の E0416 が型の段か flow の検査の段かで、同じ flow の前の位置の flow の段の誤りとの順が変わる（`let s = "text"` の後に `vdelay~(i, 1, 8)` は、型の段なら E0416、flow の段なら位置の順で E0810）。
  読み: (1) 型の段。(2) flow の検査の段（今の検査の場所。§11.4 か §18.1 に一句）。
  仮の扱い: (2)（165 回目、利用者の離席中。実装の簡単な方、助言の担当は字は (1) 寄りで細部とした。暫定）。どちらも通るプログラムは変わらない。
- 決定（2026-11-18、利用者が了承、165 回目。利用者の基準「既決と整合性が取れている範囲で、管理がしやすくシンプルなもの」を親が当てた結果を、ID ごとに了承）: 読みの (1) 型の段（仮の扱いの (2) を改めた）。
  §4.5 の型パラメータの要求の E0416 と同じく、`vdelay~` の呼び出しの位置の型の段の E0416 で、同じ flow の前の位置の flow の段の誤りより先に報告する（`let b = prev~(p)` の後の `I32` の `vdelay~` は E0416）。
  W7-14 が実装する（`flow/check.rs` の `check_delay` で総称の fn の境界と同じ後回しの要求にし、登録簿の E0416 の段を型の段だけに戻す）。それまでは W7-02 U3 の flow の検査の段のまま。
  理由: §11.4 は `T: Float` を型パラメータの要求の形で書き、§4.5 は呼び出しが生む要求を型の段の E0416 とする。(2) は §11.4 か §18.1 の一句、登録簿の二つの段、`tasks/diag-codes.md` の注の三つの例外が要り、(1) は例外が無い。実装の量はほぼ同じ。
- 経緯: 165 回目、2026-11-18、W7-02 U3 の読みの助言の段 1（onsa-advisor）が空白として挙げ、親が登録した。
