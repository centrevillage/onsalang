# S-687 S-673 の「ルート直下の読みを先にする」で、ルート直下の読みが循環を閉じるとき、自分の名前の読みに移るか（`dsp/util.onsa` の `util.g()`）

- 空白: S-673 は「頭がルート直下のモジュールの名前で自分の名前でもあるときは、ルート直下の読みを先にする」とし、§15.1 は「通らなければ外す読み」とする（67 回目の文書の点検の取り込み）。ルート直下の読みが経路としては解決するが、足す `use` が循環を閉じるときに、自分の名前の読みに移るかを書いていない。
  読みは (1) 「通らない」は経路が解決しないことだけ（循環で出さないなら候補なし）、(2) 循環を閉じることも含む（自分の名前の読みに移る）、に割れる。
  今（`c77f3f3`）は (2): `util.onsa` が `use dsp.util.{f}` で、`dsp/util.onsa` の本体 `util.g()` に候補「take off `util.`」（`util.onsa` と `dsp/util.onsa` が共に `g` を持つ。`target/notes/67/w403/u3a2/t2/h9`）。W4-03 U3a2/t2 の `use_model.rs` は、どちらの答えでも通す（`SPEC-GAP(S-687)`）。
- 決定: 決定（2026-10-25、利用者。67 回目、第 60 組。(B) として例と案の比べを示して）: (1)。ルート直下の読みは、その経路が名前の段で最後まで解決しなければ外す読みに移る。解決するが足す `use` が循環を閉じるときは候補を出さず、S-682 の note で `use util` と循環のモジュールを示す。
  note に `g()` も並べる案 (3) は採らない（A3）。仕様は §15.1 の括弧書き。実装は W4-03 の U3b2（約 +5〜10 行、S-682 の note と共有）。
- 経緯: 67 回目（2026-10-25）、W4-03 U3a2/t2（onsa-test）が NEW-4 として挙げた。関係: S-673、R-268、S-682。
