# S-1146 flow の本体の `match` の腕の束縛を E0309 に数えるか

- 決定済みで戻さないもの: E0309 の段と、他の誤りとの順（S-726）、E0320 との順（S-716）、候補 `_` と選択のパターンの全ての位置の書き換え（S-129）、全て `_` の分解（S-727）、辿れない `let` の E0309（S-129）。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/166/g111/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版（親の直し `parent_edits.md`）・入力は `advisor/`、下書きと段 1 の報告は `onsa-gap-a1c71ded76168b5c9-001.md`・`-002.md`・`onsa-advisor-a3feadd0f744eff07-001.md`。
- 論点: §5.1（25 行）は E0309 の対象に `match` の腕を挙げた後、flow の本体については「出力と `let _` から辿れない `let`」を使われない束縛とする。
  後の文が flow の本体の対象を `let` の到達だけに置き換えるのか、参照の数の判定に `let` の到達を足すのかが、字で決まらない。腕の束縛（`m01`）と、分解した `let` の名前の一部（`m10`）がこの読みで分かれる。
- 今の実装: 形の表のとおり。flow の本体の E0309 がまだ無いので、全て通る。fn の同じ形は E0309。
- 案:
  - (1) 数える（足す読み）: flow の本体でも、§5.1 の対象（`let` の名前、`match` の腕の束縛）を fn と同じく参照の数で数え、さらに出力と `let _` から辿れない `let` も使われない束縛とする。§5.1 の flow の文を「さらに」の形に書き直す。
  - (2) 数えない（置き換える読み）: flow の本体の使われない束縛は、辿れない `let` だけである。腕の束縛と、辿れる `let` の分解の一部の名前は対象外。§5.1 の flow の文に「だけ」を書き、対象外を列挙する。
  - 形ごとの出力: 形の表のとおり。違うのは、読まない腕の束縛（`m01`・`m04`・`m06`・`m11`、版の制限が外れた後の `m08`）と、辿れる分解の一部の名前（`m10`）である。
  - 書き手から見て: 読まない腕の束縛は、fn と同じく「束縛したのに使い忘れた」誤り（`Some(v) => 1.0` で `v` を返すつもりだった）か、`_` の書き忘れである。(1) は fn と同じ診断と候補を一回で出す。(2) は flow でだけ黙って通し、fn から写した書き手は同じ形の扱いが世界で違うことを知らない。
    修復のループは、(1) が候補を当てて 1 回（`_v` は S-716 の順で 2 回）、(2) が 0 回である。
  - 修正候補: (1) は fn と同じ `_` で、当てて `clean` に止まる（選択のパターンは全ての位置を一度に書き換える）。(2) は候補が無い。
  - 通るプログラム: (1) は今通る flow の読まない腕の束縛と分解の一部の名前を誤りにする。`tests/`・`std/`・`examples/` の当たりは、期待の無い項目で 0 か所（推定）。(2) は変えない。
    どちらも、今の flow の E0309 は未実装で、W7-14 で入れる時点の変化である。
  - 規則と例外: (1) は fn と flow で同じ対象と同じ数え方で、flow には到達の判定を一つ足すだけである（例外を足さない）。
    (2) は flow の本体にだけ、腕の束縛と分解の一部を対象外にする例外を置く。§5.1 の目的（名前を付けて黙って捨てる値を残さない）は世界によらないので、例外の理由を別に書く必要がある。
  - 実装の量（W7-14、flow の E0309）: (1) は flow の本体の記録にも fn と同じ `counted`（`MatchBind` を含む）を当て、到達で辿れない `let` を足す。読みは名前の段が既に数えているので、約 +3〜8 行（`walk_bodies` の `!flow` を外す所）。
    (2) は flow の本体の記録から `let` の名前以外を除き、分解の一部の名前も `let` 単位にまとめる約 +5〜10 行で、fn と flow で `counted` を分ける。
  - 後の作業への手当て: (1) は、束縛の場所が増えるとき（`match~` の版の制限を外す作業、§19.1 の `ser~`）に fn と同じ数え方がそのまま当たる。(2) は flow に束縛の場所が増えるたびに、対象に入れるかを決め直す。
- 他言語: rustc 1.94.1 と swiftc 6.3.3 は、関数の本体の読まない `match` の腕・`case` の束縛に未使用の警告を出す（Rust の `unused_variables`、Swift の never used）が、手元で確かめたのは S-393 の `for` の形だけで、腕の形は未確認。flow の本体に当たる世界の分かれ目を持つ言語は 7.32 の一覧に無い。
- 推奨と理由: (1)。確度: 高。
  - §5.1 の対象の列挙は世界を限らず、flow の文は参照の数では見えない形（`^` だけで読み合う組）を足すために置かれた。足す読みなら規則は一つで、fn と flow で同じ形が同じ診断と候補になる。
  - (2) は flow にだけ例外を置き、使い忘れた束縛を黙って通す。名前を付けて黙って捨てる値を残さないという目的に、flow で外す理由が無い。
  - 今の事例への当たりは推定 0 で、実装は名前の段の数えた読みをそのまま使う。
  - あわせて決めること: 辿れる分解した `let` の一部の名前（`m10`）も同じ読みで数え、位置はその名前（fn の `g04` と同じ）。`match~` の腕の束縛も同じに数える（取られない腕で既定値になることは読みに関わらない）。
    同じ単位に辿れない `let` とその中の読まない腕の束縛があれば、位置の順で `let` の名前が先である（§18.1）。ガードだけで読む束縛は読んだ束縛である。
  - S-393 との関係: (1) なら §5.1 の対象の列挙が flow の本体にもそのまま当たるので、S-393 は「列挙に `par~` の添字を入れるか」の一つの問いになり、同じ文（列挙の一句）で決まる。(2) なら、S-393 の (b)・(c) は flow の対象に二つ目の種類を足す別の文が要る。
