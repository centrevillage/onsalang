# S-1274 入れ子の添字 `grid[i][j]` で、基 `grid[i]` の範囲の検査と後の添字 `j` の式の評価のどちらが先か

- 位置付け: 第 123 組。族の規則 S-1275 から決まる（表と案と値の帰結は S-1275 の下書き）。
- 論点: §3.5 の例「`xs[i][j]` で両方が範囲外なら `i`」はどちらの読みとも合う。`grid[i][1 / z]`（`i` が範囲外、`z` が 0）で、基の評価が `i` の範囲の検査を含むなら範囲外（(A)）、添字の式を全て評価してから検査するなら 0 で割る（(B)）。後の添字が抜ける形（`grid[i][pf(z)?]`、`break`）では、(B) は範囲外を報告せずに `Err` や値を返し、値が変わる。
- 今の実装: 場所の基は解釈器が全ての位置で (B)（`grid[i][pf(z)?]` は `Err(9)`）、C は読む位置で (B)、代入先の位置は C の規格で決まらない順に頼る。場所でない基、分けた形 `let row = grid[i]`、引数は (A)。
- 案: (A)（S-1275 の F4・F1′ のどちらでも）。(B) は族の案として立たない（S-1275 の「並べなかった案」）。
- 推奨と理由: (A)（下書きは確度 中、段 1 は高）。`g[i][j]` を `(g[i])[j]` と読むだけの規則で、分けた形・引数・場所でない基の今の挙動と揃い、早い出口で範囲外を隠さない。生成コードは、後の添字が panic しうる・書く・抜けうるときだけ検査した添字を一時に取り、検査と割り算の数は変わらない。
- 独立のレビュー: 段 1・段 2 とも一致。
