# S-855 `add_from!` の要素の型の要求（今は `[Bool; 2]`・`[[F32; 2]; 2]` の `add_from!` が検査を通り、`onsa test` で内部エラー）

- 決定済みで戻さないもの: 無し（論点の節に決定済みの箇条が無い）。
  第 78 組の下書きの「仕組みの出所」と「族の形の表」・「形の表」の節（写しは `target/notes/105/g78/draft.md`）。
- 論点: §5.3（103 行）は `add_from!(other)` を挙げるが、要素の型に何を求めるかを書いていない。§6.3 は `+` の被演算子にその演算子の trait（`Add`）を求め、配列・`Bool`・`Str`・`Buf` には `Add` が無い（§6.3 の組込み型の表）。
  S-853 の族の規則（`add_from!` は `Span[T]` を受けるので Copy）だけでは、要素が Copy で `+` の無い型（`[Bool; 2]`、`[[F32; 2]; 3]`）が残る。
- 今の実装: `[Bool; 2]`・`[[F32; 2]; 3]`・`[Str; 2]`・`[Buf[F32]; 2]`・平面の配列の `add_from!` は全て検査を通る（c04・c05・s05・a13・x17）。
  `onsa test` では、`[Bool; 2]` が内部エラー「arithmetic on Bool」、`[[F32; 2]; 2]` が内部エラー「an integer expected, found an array」（どちらも終了コード 101、`crates/onsa_interp/src/numeric.rs`。`addfrom/r1`・`r2`）。
  `[U8; 2]` の溢れは panic になる（`addfrom/r3`、`250 + 10` の溢れ）。
- 案: 
  - (a) 要素に `AnyNum` を求める（符号なしを含む数）。満たさなければ呼び出しの位置の E0416。std は `impl[T: AnyNum] Span[T] { … add_from! … }` と、境界の違う `impl` に分けて書ける（§6.2）。
  - (b) 要素に `Add` を求める（演算子の trait）。第 2 期に `Add` だけを実装した利用者の型（ベクトルの型など）も受ける。宣言は (a) と同じ形。
  - (c) 要素に `Num` を求める（数の境界の既定、§6.3）。符号なし整数の配列（`[U8; N]`）の `add_from!` が誤りになる。
  - 書き手から見て: どの案も `[Bool; 2]` などは検査の誤り一回で、内部エラーにならない。候補は出さない（`+` を何に直すかが決まらない）。第 1 期では利用者の型に trait を実装できない（E0200）ので、(a) と (b) の違いは第 2 期まで現れない。
  - 通るプログラム: 今通って内部エラーになる形が誤りになるだけで、`tests/`・`examples/` に当たる事例は無い（`add_from!` の受け手は全て `F32` などの数の要素）。
  - 規則と例外: どの案も §5.3 の一句。(a) から (b) へは後で緩めても壊れない。実装は W5-02 の宣言の境界だけで、約 +2〜5 行。
- 他言語: 調べていない（未確認）。
- 推奨と理由: (a)。確度: 中。
  - `add_from!` は数の列を混ぜる操作で（§17 の 257 行の `out.add_from!(scratch)`）、`+` の意味（溢れの panic、§3.4）が数の trait で揃う。符号なしの配列も足し合わせに使うので、`Num` に狭める理由が無い。
  - 第 1 期は (a) と (b) で同じ結果になり、(a) から (b) へは必要が分かってから緩められる。
  - 別の S にしてよい論点: 長さの違う `other` の扱い（`copy_from!` は panic、S-614 の下書きの `b5_badcopy`。`add_from!` は確かめていない）は、§5.3 か §9.2 に一句を足す候補で、この S では決めない。
