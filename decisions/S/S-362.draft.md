# S-362 `for` の見出しの `move` と範囲

- 決定済みで戻さないもの: 範囲の `move` を誤りにすること、始まりが後置式の範囲の E0703（15 行、S-103）、範囲の両端の書き方（S-257）。
- 論点: §7「範囲には消費する値が無いので、`move` は付けない（`for i in move 0..<n` は E0703）」と S-103（「`for … in move` の範囲は E0703」）は、範囲の形によらず E0703 と読める。
  §5.2「`move` と `inout` の被演算子は後置式…で、二項演算子の被演算子にはならない（`move y + 1` と `take(move y + 1)` は E0002）」は、`move lo + 1..<hi - 1` の `move` の被演算子を `lo` と読めば `+` の E0002 になる。始まりの端が後置式でない範囲（表の 16 行）でどちらの文が先に当たるかが割れる。
  `tests/spec/negative/range_move.onsa` の 28 行目（`move lo + 1..<hi - 1`）は E0703 を期待し、R-42 の前に書かれた。
- 今の実装: 15 行は型の段の E0401「`move` applies to collections, not ranges (§7)」（E0703 は W4-09）。
  16 行は構文の段の E0002 で、`+`（`move lo + 1..<hi - 1`、`move lo + 1..=hi`）、前置の `-`（`move -1..<hi`）、`as`（`move lo as I32..<hi`）が同じ形で、候補は無い（`check --json` の `fixes` が空）。
  木は `For { moved: true, iter: Range }`（`SPEC-GAP(S-362)`、`crates/onsa_syntax/src/parser/statements.rs`）。`range_move.onsa` は `tests/pending.toml` で until W4-09。

  - 略記: 「借用の行」は §5.4 の表の借用の行（起点か派生した借用束縛の名前・フィールド・添字・分解と、静的な値）、「所有の行」は同じ表の所有の行。
- 案: (a) 見出しの `move` は範囲の全体に付く印で、始まりの端の形によらず modes の E0703（候補は `move` を消す形）。構文は、見出しの `move` の後を見出しの式として読み、範囲でなく後置式でもなければ E0002 にする。
  実装: 見出しの読み方を変える（約 10 行）、事例は今の `range_move.onsa` のまま。費用の要因: 族の規則（`move` の被演算子は後置式）に、`for` の見出しの範囲だけの例外が一つ増える。
  (b) 族の規則のとおり、見出しの `move` の被演算子も後置式。始まりの端が後置式なら範囲の E0703、そうでなければ構文の段の E0002（今の実装）。実装: 0 行。`range_move.onsa` の 28 行目の期待値を E0002 に改める。
  費用の要因: 同じ誤り（範囲に `move`）が始まりの形で E0002 と E0703 に分かれる。E0002 には候補が無く、修復のループは `no-candidate` で止まる。書き手が始まりを括弧で囲むと E0703 になり、二回目で直る。
  (c) (b) の E0002 に、`for` の見出しで範囲が続くときだけ `move` を消す候補を付ける。範囲には `move` を書かないので、書き手の意図は一つに決まり、一回で収束する。実装: 構文の段の候補（約 5 行）と事例 2 件。費用の要因: 文脈で決まる候補の規則が一つ増える。
  (d) 範囲の `move` を全て構文の段の E0002 にする（範囲は字面で分かる）。実装: 構文の段の誤り（約 5 行）と、modes の E0703 の範囲の判定を消す。費用の要因: 決定済みの S-103 の E0703 と §7 の例の文を改める（親が見出しを足した）。
- 他言語: Swift 6.3.1（手元、`s3.swift`）: `for i in consume 0..<n` は `consume` を関数の名前と読んで「cannot find 'consume' in scope」と「expected '{' to start the body of for-each loop」。
  Rust 1.94.1（手元）: 印は無く、`for i in r` は範囲 `r` を動かす（`Range` は Copy でなく、二度目の `for i in r` は E0382）。
- 推奨と理由: (b)。確度: 低。
  - 族の規則（`move` の被演算子は後置式）をそのまま当て、例外を足さない。§7 の文の例（`move 0..<n`）は始まりが後置式の形で、(b) でもそのまま E0703 になる。§5.2 の後置式の規則は先に構文の段で当たるので、二つの文は段の順で読める。
  - 当たるのは始まりが二項演算子・前置の `-`・`as` の範囲に `move` を付けた形だけで、`move` を範囲に付けること自体がまれである。(a) と (c) の利益（一回で直る）は小さく、修正の量の割に薄い。
  - (b) の E0002 の文面は `+` を指し、範囲に `move` を付けないことは示さない。(c) はこれを候補で補うので、修復のループの収束を重く見るなら (c) を採る。(a) は見出しの読み方を変え、例外の規則が残る。
  - 後で緩められるか: どの案も誤りのコードの違いだけで、(b) から (a) か (c) へ移しても通っていたプログラムは壊れない。
