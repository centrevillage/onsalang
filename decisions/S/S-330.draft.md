# S-330

- 決定済みで戻さないもの: S-333（`,` を含む並び）、`&` の行、S-191・S-239（名前の経路の `[…]` の呼び出しは名前の段）、S-732（種類の合わない要素の E0308）。下書きの全文（各 S の「仕組みの出所」と「形の表」）は `target/notes/132/g95/draft.md`、入力は同じ所の `probe/`。
- 論点: §4.5（141 行）は出す段を「読みが一つに決まる最初の段」とし、例に「名前の経路に付けた `[…]` は名前の段」を挙げる。中身が型にしか読めない形（関数型、配列型、タプル型）を、形で構文の段が決めるか、名前の段に任せるかを書いていない。
  配列型 `[F32; 4]`・タプル型 `(I32, F32)`・`()` は式としても読める（配列の繰り返しのリテラル、タプル）ので構文の段を通るが、関数型 `fn(I32) -> I32` は式として読めず、今は構文の段の一般の E0002 で止まる。
  - 決定済み（論点から外す）: `,` を含む並び（S-333）。参照の `&`（`&` の行の E0020、候補は除く形）。名前の経路の `[…]` の呼び出しが名前の段で、項目なら候補 `::`（§6.1、S-191・S-239）。種類の合わない要素の E0308（S-732）。
    候補を当てた後に同じ段か前の段の誤りが残る中身（`f[i](x)`、`f[[1; 4]](x)`、種類の合わない定数式）には候補を出さないこと（§18.1 の約束）。
- 今の実装: 形の表のとおり。W5-10 の前なので、名前の段の E0020 は無い。式として読める中身は中の名前の E0308 か型の段の誤り、関数型は構文の段の E0002「expected `{`, found `]`」で、note も候補も無い。
- 案: 
  - (a) 今の段の規則のまま: 式として読める中身（型の名前、型引数のある型、配列型、タプル型、`()`）は名前の段の E0020（`type_args_square`）で、候補 `::` は中身が型の並びとして読め、名前の種類が合うときだけ。式として読めない関数型と `rt fn` は、構文の段の一般の E0002 のまま（行を立てない）。
  - (b) 形で構文の段: 中身が添字にならない形（タプル、配列のリテラル、`()`、本体の無い `fn(…)`）は、構文の段の E0020（新しい行、候補 `::`）。型の名前と定数式は (a) のまま名前の段。
    `xs[(i, j)]` のように値の組で添字を書く読み（`a[(i, j)]` を `a[i, j]` と読む Python の書き方）とも割れるので、S-333 と同じく添字の形 `xs[i][j]` の候補も並べるかを決める。
  - (c) (a) と関数型の行: 名前の経路の直後の `[` の中身が `fn`（か `rt fn`）で始まり、閉じる `]` までに `{` を含まないとき、構文の段の E0020（新しい行、候補 `::` は中身が型として読めるとき）。他は (a)。
  - (d) 全て名前の段: 構文の段は、名前の経路の直後の `[…]` の中の本体の無い関数型を型の節として木に置き、名前の段が `type_args_square` の E0020 を出す。
  - 形ごとの出力: 型の名前・型引数のある型・const 引数は、どの案も名前の段の E0020。配列型・タプル型・`()` は、(a)・(c)・(d) が名前の段、(b) が構文の段。関数型は、(a) が構文の段の E0002（候補なし）、(b)・(c) が構文の段の E0020（候補 `::`）、(d) が名前の段の E0020。
    `f[(a, b)](x)`（値の組）は、(b) では構文の段の E0020 と候補で、当てた後に名前の段の E0308 が残る（後の段なので約束は満たす）。(a)・(c)・(d) は名前の段の E0020 で候補なし。
  - 書き手から見て（修復のループの回数）: 配列型・タプル型は、どの案も候補を一回当てて通る。関数型は、(a) が E0002「expected `{`」で、書き手が無名関数の本体を足す方向へ誤りうる（型引数の書き方は自分で見つける）。(b)〜(d) は候補一回で通る。
    `&I32` は、どの案も `&` を除く候補の後に名前の段の候補で、二回。
  - 修正候補を当て続けて止まるか: どの案も `::` の挿入は一度で、当てた後は型の段の誤り（`T` に合わない引数、E0412）か誤りの無いコードで止まる。(b) の値の組の候補は、当てた後に名前の段の誤りで `no-candidate` になる。
  - 通るプログラム: どの案も変わらない。変わるのは誤りのある形の段とコードと候補である。
  - 規則と例外: (a) は規則を足さない（今の段の文のまま）。(b) は §4.5 の段の文に「添字にならない形は構文の段」の一文と、`foreign-forms.toml` の行（読みが割れれば二つの候補）を足し、同じ `[…]` の形が中身で段を変える。
    (c) は関数型の行を一つ足し、`type_args_square` の形が中身で二つの段に分かれる（関数型だけ構文の段）。(d) は §4.5 に「名前の経路の後の `[…]` の中の関数型は型として読む」の一文を足し、式の構文に例外の節ができる。
  - 実装の量: (a) は W5-10 の `type_args_square` の候補の条件だけで、新しい行は無い（中身の読める判定は `parser::reads_as_type_list` を使う。条件は約 10〜20 行で、どの案でも要る）。
    (b) は構文の段に中身の形の分類と行と事例で約 40〜70 行。(c) は `foreign/` に関数型の行で約 20〜40 行（`fn` の後の `]` までの `{` の有無を数え、`reads_as_type` で候補を確かめる）。(d) は構文と木と名前の段で約 60〜100 行。
  - 後の作業への手当て: (a) は、関数型の E0002 の文面が無名関数の本体を求めて書き手を誤らせうるので、その形が書き手に多いと分かれば後で行を足す見直しが残る（足しても通るプログラムは変わらない）。(b)・(c) は、型の構文が増えるとき（第 2 期の新しい型の形）に、行の判定に形を足すかを見る。(d) は木の節を読む全ての歩き手（fmt、CST の比べ）に手当てが要る。
- 他言語: 
  - Scala 3（一覧の外、参考）: `f[Int => Int](x)` は関数型の型引数を角括弧で書く正しい形（Scala 3 の言語の参照、Function Types）。手元に処理系が無く未確認。
  - rustc 1.94.1（`probe/gap/other/r330.rs`）: `f::<fn(i32) -> i32>(dbl)`、`f::<[f32; 4]>([0.0; 4])`、`f::<(i32, f32)>((1, 2.0))` を受理し、`6 4 1` を出す。角括弧で型引数を書く形は無い。
  - C++・C#・Java・TypeScript・Swift は `< >` で型引数を書き、角括弧の形は無い。
- 推奨と理由: (a)。確度: 中。
  - 式として読める中身は、構文の段では添字か型引数かが決まらない（`xs[(i, j)]` を添字の組と読む書き方もある）。読みが一つに決まるのは呼び先の種類が分かる名前の段で、今の段の文と §6.1 がそのまま当たる。新しい規則も行も要らない。
  - 関数型を型引数にする形は、明示の型引数の中でも稀である（関数を受ける総称の関数は、引数から型が決まる）。(c) は稀な形のために、一つの行を二つの段に分ける。(d) は式の構文に例外を作る。
  - 関数型の E0002 の文面は無名関数の本体を求め、書き手を誤らせうる。ここは (c) が勝る点で、実際の書き手に多いと分かれば、行を足す変更は通るプログラムを変えない。
  - あわせて決めること: 名前の段の `type_args_square` の候補 `::` は、中身が型の並びとして読め、要素の名前の種類が呼び先の宣言の位置と合う（宣言の数を超えた要素は読まない、S-762）ときだけ出す。§4.5（137 行）の「呼び先の宣言を読まない」は構文の編集の形の説明で、名前の段の候補の条件は §18.1 の約束が決める、と §4.5 に一句足す。
    `f[i](x)`（`f` は項目、`i` はローカル）は名前の段の E0020 で候補なし、note で `::[…]` の書き方と、添字なら関数値でないことを示す。
  - 別の S にしてよい論点: 上の候補の条件の一句は、S-330 と別に「名前の段の `type_args_square` の候補の条件」として決めてもよい（新しい S の候補）。
