# S-891 §7 の発散の形の範囲: 入れ子で終わるブロック、`while true` で終わるブロック、括弧の条件の `while (true)`、腕の無い `match`

- 空白: §7 の「それで終わるブロック」の「それ」が、発散するものそのものだけか、発散する形と文の全てかを書いていない（`{ { return 1 } }`、`{ if c { return 1 } else { return 2 } }`、`{ while true {} }`）。
  「条件がリテラルの `true`」は括弧で囲んだ `while (true)` を含むかを書いていない。「全ての枝が発散する」は腕の無い `match e {}`（空の enum、今は通る）に当たるかを書いていない
- 決定: 決定（2026-11-04、利用者。113 回目、第 84 組）:
  (a1)・(b1) は設計メモと独立のレビューが一致した (A) の確認だけ（利用者「(A): OK」）。発散の形は再帰で数え（`{ { return 1 } }`、`{ if c { return 1 } else { return 2 } }`、`{ while true {} }`）、`while (true)` も発散する（`fmt` が括弧を外すので、外す前後で合否を変えない。§18.2）。
  腕の無い `match`: 下書きの (c1)・(c2) を、利用者の案で改めた: 値の無い型を言語から外す。列挙子の無い `enum E {}` は E0002（§4.4 の要素の無い `Circle()` と同じ。総称の `enum E[T] {}` も。候補なし）。腕の無い `match` は全ての型で E0501 で、新しい規則は要らない（構文は禁じない）。対象が誤りの型の `match e {}` は E0501 を出さず（S-692）、発散に数えない。
  理由: 空の enum が固有に担うのは起こらないことを型で示す形（`Result[T, Never]`）だけで、失敗しない関数は `T` を返せ、タグと名前空間は `struct`、FFI は `type` で書ける。今通る空の enum の宣言は誤りになるが、`tests/`・`std/` に無く、後で許すのは通るプログラムが増えるだけである。
  作業は W5-08。仕様 §7、§4.4。
