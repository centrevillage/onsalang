# S-1192 細部: 状態を持つものの無い `if~`（E0812）の式のクロックは誤りのクロックか、普通のクロックか（`let a = (if~ c { x } else { 0.0 }) at block` を `at sample` の flow に置く）

- 空白: §18.1 は「読めなかった部分は誤りで、それを使う側には診断を出さない」と書き、E0812 の `if~` が読めなかった部分かを書いていない。
  読み: (1) 誤りのクロックで、外の `at block` の E0815 を黙らせる（E0812 だけ）、(2) 普通のクロック（枝と条件の結び）で、E0812 と E0815 が並び、§18.1 の順で位置の先のものを報告する。
  前例: 状態の無い `par~` の E0812 は (2)（`687a9117` のバイナリで `let a = (par~ i in 0 ..< 2 { x }) at block` は E0815 を報告する。`~` の向きだけの誤りで、式の意味は読める）。
  仮の扱い: (2)（`par~` の E0812 と揃える。`SPEC-GAP(S-1192)`）。通るプログラムは変わらない。急ぎ: W7 の区切りで確認だけ。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認だけ。「(A)と(B1)はS-1148以外OKです」）: 仮の扱いのとおり。E0812 の `if~`・`match~`・`par~` は式として読め、クロックの検査は普通に行う。
  突き合わせ: 助言の担当が固定のバイナリ `onsa-d02ddee` で再現し、仮の扱いが今の挙動と合い、既決とぶつからないことを確かめた（`target/notes/189/reports/onsa-advisor-a4f41d23ad112f9fe-001.md`）。
- 経緯: 171 回目（2026-11-20）、W7-06 U2/t（onsa-test）が挙げ、親が `par~` の前例を確かめて登録した。
