# S-693 他のモジュールの本体の経路の最後の要素が、E0200 の `pub use` の取り込む名前のとき（`use main.inner` の後の `inner.g()`、`g` は `main/inner.onsa` の `pub use util.{g}`）

- 論点:

    E0200 の取り込む名前は失敗した名前（S-462: 偽の連鎖を出さないため、使う所に診断を出さない）で、他のモジュールの `use main.{g}` も黙る。経路の途中に通す `use main.inner.{g}` は、途中を定義だけから引くので E0302（R-250 の規則）とした（§18.1）。
  - §18.1 は他のモジュールの `use` の形だけを書き、本体の経路（`use main.inner` の後の `inner.g()`）の要素がその名前のときを書かない。S-611 の「他のモジュールの経路は定義だけを引く」を当てれば E0302、S-596 の `use` の最後の要素と同じに読めば黙る。
  - 当たる形は表の 5〜10 行。この版では、どの形も使う側を直す以外に通る書き方が無い（`pub` を外すと `use` の束縛になり、他のモジュールからは S-611 の E0302）。

- 案:
  - (a) 本体の経路は位置によらず E0302。E0200 の `pub use` の名前を、本体の経路では名前空間に無い名前として扱う。
  - (b) 本体の経路の最後の要素なら失敗した名前で黙り、後ろに要素が続けば E0302。S-596 の `use` の規則（最後は黙り、途中は E0302）を、`use` と本体の経路に一つの規則として当てる。5〜7 行は黙り、8〜10 行は E0302。
  - (c) 本体の経路では位置によらず失敗した名前で黙る（経路はそこで失敗する）。5〜10 行は全て黙り、`use` の途中（4 行）だけが E0302。
  - 一回の検査で出る誤り: (a) は E0200 と、使う単位ごとの E0302。(b)・(c) は 5〜7 行で E0200 だけ。どの診断にも候補は無く（E0200 は note で定義の経路の `use` を示す）、偽の連鎖は無い（この版では使う所も必ず直す所である）。
    E0200 だけのとき、書き手が note のとおり使う側を直せば一回で終わり、`pub` を外して直すと次の検査で使う所の E0302 が出て二回になる。(a) は一回目に両方を示す。
  - 書き方で結果が分かれる組（3 行と比べる）: (a) は `use main.inner.{g}` と `g()`（黙る）と `inner.g()`（E0302）。(b) は `use main.inner.{Mode}` と `Mode.A`（黙る）と `inner.Mode.A`（E0302）。

  - 通るプログラム: どの案も変えない（全ての形が誤りのまま）。第 2 期に再公開を入れるときに、どの案も決め直す。
  - 実装（本体の経路の歩き手は W4-04 の U4 が作る）: (a) は 0 行（R-254 の直しで 5 行も E0302 になる）。
