# S-616 flow の本体の `let` の値型が Copy でなければならないことを、E0810 の文面が指す §11.3 に書くか

- 空白: 今の実装は flow の本体の `let n = "gain"` を E0810「the value type of a signal must be Copy; `Str` is Shared (§11.3)」にし（`tests/spec/negative/flow.onsa` の 41 行が期待値）、文面は §11.3 を指す。
  §11.3 の文は「flow の入出力の値型 `T` は Copy でなければならない（E0810）」で、本体の `let` を書いていない。本体の `let` の値型が Copy であることは、§12.4 の括弧（「値型は Copy、ヒープを使わない」）からしか読めない。規則は仕様と実装で食い違っておらず、書いた場所だけが抜けている。
- 決定: 決定（2026-10-24、利用者が了承「付録 2 はその文で問題ないと思います」。58 回目、第 47 組）: §11.3 の文を「flow の入出力と本体の `let` の値型（信号の値型）`T` は Copy でなければならない（E0810）」に改める。実装と事例（`tests/spec/negative/flow.onsa` の 41 行）は既にこの規則なので、担う作業は無い。
  S-614（容量付きの Copy の文字列）・S-615（静的な Shared 型）で Copy の型が入れば、この規則のまま flow の状態に置ける。仕様 §11.3
- 経緯:
  58 回目（2026-10-24）、S-613 の範囲の外のまとめ（onsa-gap、`target/notes/58/alloc58/draft.md` の付録 2）が見つけ、親が利用者に文の案を出して了承を得た。助言の担当には回していない（文の置き場所だけの直しで、規則は変わらないため）。
