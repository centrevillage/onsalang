# S-853 族: §5.3 の要素が Dup でない列のメソッド

- 空白: 族の S（S-794 の `get`、S-847 の `fill!`・`slice`・`add_from!`・`copy_from!`）は、要素が Dup でない（Affine の）`[T; N]` を受け手にしたとき、どのメソッドを持ち、値を複製するか取り出すメソッドをどう扱うかを、仕様が書いていないことから出た。
  §5.3 は `[T; N]` に `Span[T]` と同じメソッドを与え、§4.5 が要素の型を `T: Copy` に限るのは `Buf[T]` と `Span[T]` だけである。
  族の一般の規則（要素の種ごとに、列のメソッドのどれを持つか）を一つ決め、個々の形はそこから決める。関係: R-349（`fill!` が Affine の値を複製したまま通る）
- 決定: 決定（2026-11-03、利用者が ID を挙げて了承。105 回目、第 78 組。下書きと独立のレビュー（段 1）が一致）: (C)。`[T; N]` は `len()` を要素によらず持ち、`get`・`fill!` は要素が Dup のとき、`slice`・`copy_from!`・`add_from!` は要素が Copy のとき持つ（`Buf[T]`・`Span[T]` は要素が Copy なので全てを持つ）。
  満たさなければ呼び出しの位置の E0416 で、note で要素の種と代わりの形（添字で借りる、`for x in move xs`、代入の `for`、`array.from_fn`、要素ごとの `copy_from!`）を示し、修正候補は出さない。要素が第二級（平面の配列）なら §4.5 の規則で E0710。
  理由: 各メソッドの条件が、そのメソッドのすることと既にある規則（§2.4 の `[e; N]` の Dup、§5.4 の `xs[i]`、§4.5 の `Span` の要素の Copy）から決まり、族のための新しい概念を足さない。Affine の値の複製（R-349、S-794）を全て閉じ、Shared の `get`・`fill!` と全ての配列の `len`（§4.2 の約束、平面の配列のチャンネルの数）を残す。第 2 期の `Array[T]` の `get` と条件が揃う。
  D-07 の追記を「`[T; N]` と `Buf[T]` の受け手は、自分の `impl` に無いメソッドを `Span[T]` から引く」に改めた。std にどう書くか（std だけに許す配列の `impl` か、組込みの表の行か）は W5-02 の設計メモで決める（言語の規則はどちらでも同じ）。
  仕様 §5.3、`tasks/diag-codes.md` の E0410〜E0416 の行、D-07。族の規則から決まる S: S-794、S-847。
- 経緯: 105 回目（2026-11-03）、族の未決の S が S-794・S-847 の 2 件なので登録した（`rules/process.md` 8.6 の仕様の空白の流れの 2）
