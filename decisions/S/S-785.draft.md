# S-785 `Option`・`Result` の `unwrap` の受け手のモード（借用か `move self` か）

- 決定済みで戻さないもの: 族の規則 S-786 の「決定済み」と同じ。利用者の型の `unwrap` という名のメソッド（利用者の宣言のモードに従う）。関数の形 `Option.unwrap(o)` の E0308（§6.2・§15.1）。
  第 75 組の下書きの「S-785 の仕組みの出所」と「S-785 の形の表」の節（族は「S-786 の族の形の表」。写しは `target/notes/86/g75/draft.md`）。
- 論点: §9.1（18・19 行）は `unwrap` を挙げるが、`map_err` と違って受け手のモードを書かない。中身が Affine のとき、所有の場所の `r.unwrap()` が `r` を移すか、借用・`inout` の場所から取り出せるかが決まらない。
  今は借用の引数からも、同じ `r` から二度も通る（`u02`・`p19`・`p19b`）。
- 今の実装: 族の形の表の `unwrap` の列と、上の表のとおり。
- 案: どの案も、場所でない値の受け手（`mk().unwrap()`）は一時の値を消費し、Copy・Shared の中身は写す。`None`・`Err` の panic は変えない。
  - (1) `move self`: `pub fn unwrap(move self) -> T`。受け手の扱いは §5.2 の `move self` の受け手のまま（所有の局所の全体は移す、フィールドの経路は根の全体を消費、添字の経路と借用・`inout` の Affine の場所は候補なしの E0711、Dup の場所は複製）。印は書かない。
  - (2) 借用の `self`: 受け手を借用し、中身を写す。中身の型 `T` が Dup でない場所は、所有でも借用でも候補なしの E0711（`match move r { Some(v) => move v, None => panic("…") }` の形を note）。
    場所でない受け手の一時の値を消費する所は、借用の宣言の規則の外の扱いになる。
  - (3) 中身の種で分ける: `T` が Dup なら (2)、Dup でない（Affine か `T: ?Dup`）なら (1)。`Option` では `Option[T]` の種と `T` の種が同じなので (1) と同じで、違うのは `Result[<Dup>, <Affine>]` の受け手だけである。
  - (4) `match` と同じに読む: `r.unwrap()` を `match r { Some(v) => v, None => panic("…") }` と同じに検査し、場所の受け手からの `let b = r.unwrap()` は借用束縛、消費する位置（`take(r.unwrap())`）では候補なしの E0711。
  - 形ごとの出力（所有の `r` を「所有」と書く）:

    | 二度（`p19b`・`u18`）、ループ（`u10`） | 二度目に E0704 | E0711 | (1) と同じ | 通る |

  - 書き手から見て（修復のループの回数）: 所有の `let b = r.unwrap()` で `r` を後で使わないとき、(1)・(3)・(4) は 0 回、(2) は 1 回で候補が無く、`match move` に書き直す。
    借用の `r` から読むだけのときは、(4) が 0 回、(1)〜(3) が 1 回で、借用の `match r` に書き直すか引数を `move` にする（候補なし）。
  - 修正候補: どの案も足す候補は無い。今の E0703・E0711 の候補（S-605・S-609）は変わらず、当て続けて止まる。
  - 通るプログラム: 今は全て通る。(1) は借用・`inout`・二度・ループ・添字・取り出した後の使用を誤りにする。(2) は中身が Dup でない場所の全てを誤りにする。(3) は (1) から `Result[<Dup>, <Affine>]` の形を除く。
    (4) は消費する位置の Affine だけを誤りにする。今のリポジトリで当たる形は、どの案も 0 件。
  - 規則と例外: (1) は `unwrap` の宣言に `move self` と書くだけで、受け手の規則は §5.2 のまま。`map_err` と同じ形になる。(2) は中身の種による E0711 の制限を一つ足し、場所でない受け手の一時の値を消費する扱いが借用の宣言の例外になる。
    (3) は種で受け手のモードを変える規則を一つ足す。特殊化が無い（§6.2）ので、std の一つの宣言では書けない。(4) は `match` への読み替えと、§5.4 の表の 105 行（`let y = f(...)` は所有）への例外を足す。
  - 実装の量（W4-07 の U2、設計メモの 2.5）: (1) は、`builtin.rs` の `Method` に受け手のモード（`bang` を借用・`inout`・`move` の三つに改めるか、欄を一つ足す）を持たせて `unwrap` の二行に `move` を書き、2.5 の `BuiltinMethod` の行で `move` の受け手を利用者の `move self` と同じ道に通す。約 +5〜10 行、単体テスト 4〜6 件。
    (2) は 2.5 を変えず、`unwrap` の受け手が場所で `T` が Dup でないときの E0711 を足して約 +6〜10 行。(3) は (1) に `T` の種の判定を足して約 +8〜14 行。(4) は W4-16 の束縛の状態に `unwrap` の呼び出しを借用の見出しとして足し、約 +30〜60 行（確かめていない）。
  - 降下と後端: どの案も `call.rs` の `unwrap` の降下は変えない。(1)・(3) は移した `r` が `MovedLocals` に入り、W6-02 の破棄点も他の移動と同じに扱う。(4) は `b` が借用束縛で破棄されない。
  - 後の作業への手当て: (1) は、W5-02・W5-03 で `impl[T: ?Dup] Option[T] { pub fn unwrap(move self) -> T }` と普通の宣言で書け、組込みの表の受け手のモードは宣言へ移る。
    (2)・(3)・(4) は、std の宣言の規則で書けない（(2) は借用の `self` から Affine の `T` を返す、(3) は種で二つの宣言、(4) は呼び出しの結果を借用束縛にする）ので、W5-03 の後も sema に `unwrap` の特別扱いが残る。
- 他言語: 
  - rustc 1.94.1（`other/r5.rs`）: `Option::unwrap(self)` は受け手を移す。`&Option<Vec<f32>>` の `r.unwrap()` は E0507「cannot move out of `*r`」（note「`Option::<T>::unwrap` takes ownership of the receiver `self`」）、所有の `r` に二度は E0382、`Option<u32>` は二度書ける。
  - swiftc 6.3.1（`other/s3.swift`、`-emit-sil`）: `borrowing B?`（`B: ~Copyable`）の `r!` は「'r' is borrowed and cannot be consumed」。
  - Apple clang 21（`other/c1.cpp`・`c2.cpp`、`-std=c++20`）: `std::optional<std::unique_ptr<int>>&` の `o.value()` は参照を返し、`auto b = o.value()` は写すので「call to implicitly-deleted copy constructor」。
    `std::move(o).value()` は移し、二度書いても通る（移した後の使用を検査しない）。
  - Kotlin の `!!`、TypeScript の `!`、Java の `Optional.get()` は所有の規則を持たない（手元に Kotlin・Java は無く未確認。TypeScript の `!` は型だけの印）。
- 推奨と理由: S-786 の規則から (1)。確度: 中。
  - `unwrap` は中身を所有して外へ出す形で、同じ節の `map_err` が `move self` と書かれている。(1) は宣言に `move self` と書くだけで、受け手の規則は §5.2 のまま足さず、`?`（S-784 の (a)）と同じ答えになる。
  - W5-02・W5-03 で std の普通の宣言に書け、組込みの特別扱いを取り除く作業の向きと合う。(2)〜(4) は宣言の規則で書けず、特別扱いが残る。
  - (3) は `Result[<Dup>, <Affine>]` の借用から取り出せる利点があるが、借用の `match r { Ok(v) => v, Err(_) => panic("…") }` で同じことが書け、種で受け手のモードを変える規則を足すほどの用途が見えない。
  - あわせて決めること: 借用・`inout` の E0711 は候補なしで、借用の `match r` で読む形と引数を `move` にする形を note で示す（利用者の `move self` の受け手の E0711 と同じ文面、`q16`）。
    組込みの表の受け手のモードは、W4-07 の U2 で表に持たせ、W5-02 で宣言へ移す。
