# S-271

- 空白: 引数の並びの中の `g(f<A, B>(x))` は、二つの比較の引数と一つの総称の呼び出し（C# の仕様の 6.2.5 節）に読みが割れ、値だけで書けば今は通る。誤りにするなら `<` の後の並びと `>(` の先読みの構文の規則を足す（S-256 と同じ機構で拾える）。第 5 組の下書きで見つけた（2026-10-08）
- 提案: 急がない。W3-07 の作業票で、S-256 の先読みがこの形も拾えるかだけを記録する
- 時期: W3
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目。親の確認だけの読み）: `<` を前の名前に、`(` を `>` に、空白を空けずに続けた `f<T>(x)` は型引数の形（E0020、§4.5）で、引数の並びの中（`g(f<A, B>(x))`）も `,` で二つの比較に分けない。空白を空けた `g(a < b, c > (d))` は二つの比較として読む。
  W3-19/b の後の実装（`onsa_syntax` の `type_list_ahead`）のとおりで、仕様 §4.5 に書いた。引数の並びの中の形の事例は W5-11
- 経緯: 55 回目（2026-10-23）、W4 の前の S の確認（X-8）。dev `8427cf2` のバイナリで、`g(pair<U8, F32>(1, 2.0))` と `g2(a<b, c>(d))` は E0020（候補 `::[…]`）、`g2(a < b, c > (d))` と `g2(a<b, c> (d))` は通る、`g(pair < U8, F32 > (1, 2.0))` は二つの比較として読んで E0412 を確かめた。重複: S-331。
