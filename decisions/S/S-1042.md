# S-1042 `break` を含む `while true` の後の状態に、条件が偽で抜ける道を数えるか（今は数え、`while true` の中で移して `break` した値の破棄と、入れ直した値の E0704 が出る）

- 空白: §7 は「条件がリテラルの `true`（括弧で囲んだ形を含む）で、そのループを抜ける `break` を含まない `while true { ... }` も発散する」とし、E0503 の判定は「文の構造だけで行い、条件の値は見ない」とする。`break` を含む `while true` の後の状態（移した値、破棄）に、条件が偽で抜ける道を数えるかは書かない。
  今（`ba5e764e`）: modes の `flow.rs::iterate` は、条件を歩いた後の状態を、`while true` でもループの出口へ合わせる。そのため次の二つが出る。
  `rt fn s1(move a: Buf[F32]) -> Option[Buf[F32]] { while true { let w = pass(move a)` / `break }` / `None }` の `a` に E0901（W6-02 U2a から。ループの中で移したのに、本体を一度も歩かない道で生きているとする）。
  `var b = move a` / `let x = pass(move b)` / `while true { b = Buf.zeroed(1)` / `break }` / `b` の最後の `b` に E0704（U2a の前から。`break` の道では入れ直している）。
  再現は `target/notes/147/w602/u2a/f1/m1.onsa`（`s1`・`s3`）と `revive.onsa`（`revive_in_loop`、`while c` の対照）。
  読み: (1) `while true` を抜けるのは `break` だけで、条件が偽の道は無い（後の状態は `break` の状態の和）。(2) 構造だけで読み、条件が偽の道が残る（今の挙動）。
  親の読み: (1)。§7 は `break` を含まない `while true` を発散するとしており、これは条件が偽の道が無いと読むことである（(2) なら `while true {}` にも条件が偽の出口があり、発散しない）。`break` を含むかで条件が偽の道の有無が変わる読みは無い。(1) は今の誤りを消す向きだけで、通るプログラムを誤りにしない。判定は E0503 の `while true` と同じ構造の判定（リテラルの `true`、括弧を含む。定数と式の条件は対象外）を一か所で使う。
  急ぎ: W6-02 の中（U2a から破棄の誤りに効く。直すのは `iterate`）
- 決定: 決定（2026-11-13、利用者。147 回目、確認だけ）: (1)。`break` を含む `while true`（条件がリテラルの `true`、括弧を含む。定数と式の条件は対象外）を抜けるのは `break` だけで、条件が偽で抜ける道は無い。ループの後の値の状態（移した値、破棄）は `break` の時点の状態の和である。判定は E0503 の `while true` と同じ構造の判定を一か所で使う。今の誤りを消す向きだけで、通るプログラムを誤りにしない。作業は W6-02 の U3（`flow.rs::iterate` とループの出口を触る単位）。仕様 §7（`while true` の段落）
- 経緯: 147 回目（2026-11-13）、W6-02 U2a の壊す側（onsa-break）が、経路を数える模型との突き合わせで見つけた（約 5 万関数のうち `while true` と `break` を含む形の 93 件だけが食い違い、模型に「`break` を含む `while true` に条件が偽の出口は無い」を足すと 0 件）。親が固定のバイナリ `onsa-u1d`・`onsa-u2a` で再現し、E0704 の形が U2a の前からあることを確かめた。関係: R-32、S-873、S-128
- 補い（2026-11-13、親）: 利用者が、定数（`while ALWAYS`）と式（`while 1 == 1`）の条件は対象外のままでよいと確かめた（147 回目）。§7 の発散の規則（S-40）と同じ線で、条件が偽の道を残す。無限ループは `while true` と書く。
