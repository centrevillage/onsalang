# S-303

- 空白: 総称の関数を型引数なしで値にしたとき（`let g = id`）の具体化の時点。今の実装は参照の位置で型変数を一度作り、最初の使用で決める（`g(250)` の後の `g(1.5)` が E0401）。仕様（§4.7、§5.3）は書かず、決まらないまま終われば E0406 かも書かない。S-239 の `id::[U8]` と並べて書く。第 9 組の下書き（S-239）で見つけた（2026-10-08）
- 提案: W4-13 の前に決める。空白の流れで下書きに回す
- 時期: W4
- 経緯（2026-10-23、親）: X-8: W4-13 を W5-10 へ移したので、期限を W5-10 にした。
- 決定: 決定（2026-11-10、利用者。132 回目、第 95 組。材料は `target/notes/132/g95/`）: (a)。型引数を書かずに値に置いた総称の関数（関連関数と列挙子の構築を含む）は、その位置で型パラメータを型変数にし、期待型と後の文で決める（§4.7 の単一化変数のまま）。一つの値は一つの具体化を指す（`let g = id` の後の `g.(250)` と `g.(1.5)` は二度目が E0401）。関数の終わりに残れば参照の位置に E0406（浮動小数のリテラルだけなら E0405）、要求は決まった文で検査して参照の位置に E0416、第二級の型は E0710。今の実装のとおりで、通るプログラムは変わらない。
  仕様: §6.1 に一文、§4.7 の E0406 の一覧と §4.5 の E0416・E0710 の一覧に値に置いた総称の関数を足し、§4.5 の「具体化済み」を「一つの具体化を指し」と言い直した。
  W5-10: E0406 の note に `名前::[…]` の書き方（型に現れない型パラメータと const パラメータは注釈で直せない。`fn sz[T]() -> U32` の `let s = sz`）と、通る形と誤りの形の事例。二度目の使用の E0401 に型の決まった位置の note を付けるかは、`let o = None` と同じ一般の論点で、この決定に含めない。下書き（onsa-gap）と独立のレビュー（onsa-advisor の段 1）が一致した。
