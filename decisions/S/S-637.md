# S-637 渡した経路が、名前が `.onsa` でないリンクで `.onsa` のファイルか `onsa.toml` を指すとき

- 空白: §15.1 は「パッケージを読むコマンドに `.onsa` でも `onsa.toml` でもないファイルを渡すのも、使い方の誤り（終了コード 2）」「渡した経路にリンクがあれば（途中のディレクトリのリンクも）、リンクを解いた場所から探す。…見つからず単一のファイルのパッケージになるときのモジュール名と表示の経路は、渡した経路のまま」とし、S-272 は名前が `.onsa` のリンク（`outfile.onsa -> base/sub/b.onsa` は `base` の `sub.b`）、S-622 は経路で渡した `onsa.toml` のリンク（置き場所のディレクトリ）を決めた。
  渡した経路の名前が `.onsa` でも `onsa.toml` でもないリンクで、`.onsa` のファイルを指すとき（`cut -> base/sub/b.onsa`）は書いていない。
  読みは (1) 種類は渡した名前で決める（S-622 と同じ向き。`cut` は 2）、(2) リンクを解いた先の名前で決める（`cut` は `base` の `sub.b`。見つからなければモジュール名をどうするか、`foo -> x/onsa.toml` をどのディレクトリとして扱うかも決める）、に割れる。
- 決定:
- 経緯: 60 回目（2026-10-24）、W4-14 U1 の実装（onsa-impl）の空白の報告から。テストの票は (2) で期待値を書き（`crates/onsa_cli/tests/package_links.rs` の `a_link_in_the_given_path_is_resolved_to_find_the_root` の 4 つ目の形）、実装は (1) を仮の扱いにした。W4-14 ではこの形を事例から外し、`SPEC-GAP(S-637)` を付ける。
