# S-993 `onsa diff --ast` が一つの場所の属性の順（`@export @fp(relaxed)` と `@fp(relaxed) @export`）を違いとして報告する: 属性も集合として読む並びに数えるか

- 空白: §4.5 は「集合として読む他の並び（derive の一覧 §6.4、一つの場所の属性 §6.5、効果行 §8.1）」と、一つの場所の属性も集合として読む並びに数える（同じ属性の重なりは E0005）。`spec/tools.md` §3.5 は、`onsa diff --ast` が順を報告しない並びを「集合として読む並び（境界、derive の一覧、効果行）」と三つだけ挙げ、S-750 の決定も同じ三つを挙げる。属性の順をどちらに数えるかを書かない。
  今の実装は、属性の順だけが違う二つのファイル（`@export @fp(relaxed) pub fn h` と `@fp(relaxed) @export pub fn h`）を `~ fn h` と報告し、終了コードは 1（W5-24 U3b の前も後も同じ。dev `82f097a2`）。属性は一つの場所にそれぞれ一度だけ付けられるので、順は意味を変えない。fmt は書き手の順を保つ。
  読みは (1) 属性の順も報告しない（§3.5 の一覧に「一つの場所の属性」を足し、`diff.rs::in_one_order` が属性も名前の順に並べ替える。見当は数行） (2) 今のまま報告する（§3.5 と S-750 の三つの並びのとおり） に割れる。通るプログラムは変わらない。違いは `onsa diff --ast` の報告だけである。
  仮の扱い: 今の実装のまま（(2)）。
- 決定: 決定（2026-11-10、利用者。135 回目、確認だけ。条件は「修正量と、後々まで手当が必要かに問題が無ければ」）: (1)。`onsa diff --ast` は、一つの場所の属性の順も報告しない。集合として読む並び（境界、derive の一覧、一つの場所の属性、効果行）の順は報告しない、という一つの規則にする。fmt は書き手の順を保つ。
  条件の確かめ（親）: 直すのは `onsa_syntax` の `diff.rs::in_one_order` の一か所で、属性の並びを名前の順に並べ替える行を三つの置き場所（項目の `Item.attrs`、入力と引数の `Param.attrs`、`let` の属性）に足す。見当は +10〜15 行と、CLI のテスト `diff_ast_sets.rs` の組 2 つ。属性の種類が後から増えても（W10-08 の `@host`・`@latency`）同じ並びに入るので、直す所は無い。属性を書ける構文の場所が増えたときだけ一行を足す（境界と効果行の新しい位置と同じ。足し忘れても、順が報告されるだけで、違いを隠す向きには壊れない）。
  仕様: `spec/tools.md` §3.5 の並びの一覧に「一つの場所の属性」を足す。実装は W5-24 U8（fmt と CLI の単位）。それまで実装は属性の順を報告する。
- 経緯: 135 回目（2026-11-10）、W5-24 U3b の壊す側（onsa-break）が、§4.5 と `spec/tools.md` §3.5 の並びの一覧の食い違いとして報告した。再現の入力は 135 回目の scratchpad の `w524/u3b/b/dd/a1.onsa`・`a2.onsa`（属性の順だけが違う二つのファイル）。関係: S-750、S-490、S-965 の R9。
