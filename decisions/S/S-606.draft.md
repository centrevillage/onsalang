# S-606 族: タプルの添字で終わる名前の経路の呼び出し

- 決定済みで戻さないもの: 関数値（引数、ローカルの束縛、フィールド、要素、呼び出しの結果）は `.(` で呼び、項目は `f(x)` で呼ぶ（S-191、§6.1）。`s.f(x)` は常にメソッドの呼び出しで型の段（§6.2）。
  呼び先が名前の経路でない呼び出し（`(s.f)(x)`、`mk2().0(x)`、`ts[0].0(x)`）は構文の段の E0020（`callee_expression` の行、W3-20/b）。flow は値でない（§11.6）。flow の本体に関数値は書けない（E0806、S-195）。
  flow の外の `~` は E0821（S-101）。`!` は `inout self` のメソッドの名前の直後（§2.6、§5.2）。式の中の `::[…]` とその候補は S-239・S-256（W5-10）で、ここでは論点にしない。
- 論点: §6.1「呼び先が名前の経路でも、名前の経路に `[…]` を付けた形でもない呼び出し（`(s.f)(x)`、`pick(true)(5)`）は項目でありえないので構文の段で決まる」「名前の経路の呼び出しは名前の解決で決まる（`f(x)` の `f` がローカルの束縛か引数なら修正候補は `f.(x)`…）」。
  §2.4 の定義ではタプルの添字で終わる `t.0` も名前の経路なので、字面のまま読むと `t.0(x)` は名前の段になる。一方、`t.0` は項目でありえない（添字は名前でない）ので、§6.1 の構文の段の理由にも当たる。
  §2.6「`~` は名前の直後に空白を空けずに書き」「`!` も名前…の直後に」。添字 `0` は名前でないので、`t.0~(x)`・`t.0!(x)` が「名前の直後」に当たるかが書かれていない。
  今の構文解析器は、`(` では名前の鎖の後の添字だけを名前の段へ渡し（`Callee::by_name`）、印では前によらず添字を受ける（`Link::takes_a_mark`、W3-19）。
  そのため表の 14・21 行は、後の段の候補を当てると前の段（構文の段）の E0020 が残り、§18.1 の約束を満たさない。

- 案:
  - (a) 構文の段で決める。タプルの添字は名前でなく、項目・メソッド・flow の名前になりえないので、タプルの添字で終わる呼び先は、前が名前の経路でもそうでなくても値である。
    `(` は E0020 で候補は `.` の挿入（表の 7 行を 8 行と同じにする）。`!(`・`~(` は印を書けない位置なので、名前の経路でない値の後（15・22 行）と同じ構文の段の E0002 で、候補なし（13・14・20・21 行）。note で、印は項目・メソッド・flow の名前の直後に書くことを示す。
    実装: `callee.rs` の `by_name` の `TupleIndex` を偽に、印を受ける判定から `TupleIndex` を外す（`::[` を受ける `names_a_path` は W5-10 まで変えない。5〜10 行と注釈）。名前の段（W4-12）にタプルの添字の枝は要らない。
    事例: `e0020_callee_tuple_index.onsa` の `fine` を否定例に移し（3 件）、印の E0002 の否定例 3 件以上。§6.1 に一句（「タプルの添字で終わる経路も項目でありえない」）。
    費用の要因: §6.1 の「名前の経路の呼び出しは名前の解決で決まる」と S-191 の「名前の経路は名前の段」に、タプルの添字で終わるものを除く一句が要る。
    頭が解けない形（9 行の `nosuch.0(1)`）は、E0020 の候補を当てた後に E0302 が出るので、往復が一つ増える。印の E0002 には候補が無い。
  - (b) 名前の段で決める（§6.1 の文のまま）。名前の経路のタプルの添字（7・13・20 行）は名前の段で、頭が値なら `(` は E0020（候補 `.(`）、頭が解けなければ E0302、頭が型・モジュール・項目なら W4-04 の経路の誤り。
    印は、`~(` を E0812（候補なし、C3）、`!(` を名前の段の E0714（候補なし）にする。名前の経路でない添字（14・21 行）は構文の段の E0002（15・22 行と同じ）。
    実装: 構文の段は印を受ける判定を名前の鎖の添字だけにする（3〜5 行）。名前の段（W4-12）に、名前の鎖の添字の呼び先の枝と候補と、E0714 を名前の段で出す枝（15〜30 行）。`onsa_diag::codes` の E0714 の候補の必須の印を外す（候補の無い必須のコードは E0002 に落ちる、`Code::without_fixes`）。
    事例: 名前の段の否定例を各コード 3 件以上。費用の要因: 同じ形（添字で終わる呼び先）が頭によって構文の段と名前の段に分かれる。名前の段は `t.0` と `mk2().0` を見分けるために、構文の段の鎖の読みを AST から読み直すか、W4-12 の関門の結果の印を要る。
  - (c) 型の段で決める（`s.f(x)` と同じ）。`t.0(x)` は、`t.0` の型が関数型なら E0020（候補 `.(`）、でなければ E0401。印は (b) と同じ（`~` の E0812 は S-267 で名前の段なので型の段には移せない）。名前の経路でない添字の印は構文の段の E0002。
    実装: 名前の段は名前の鎖の添字を素通しにし、型の段に枝と候補（10〜20 行）。費用の要因: `t.0(x)` と `mk2().0(x)` が、候補は同じなのに段が違う。印の扱いが名前の段と型の段に分かれる。関数でない要素（p09）は往復が一つ減る。
  - (d) `t.0(x)` を今のまま関数値の呼び出しとして通す。印は (b) の名前の経路でない形だけを構文の段の E0002 にして、§18.1 の約束の外れを直す。
    実装: 3〜5 行。費用の要因: S-191 と §6.1 の「要素の関数値は `.(` で呼ぶ」と食い違い、タプルの要素の関数値に二つの呼び方（`t.0(x)` と `t.0.(x)`）ができる。`t.0(x)` が通り `mk2().0(x)` が E0020 になる。

- 推奨と理由: (a)。確度: 中〜高。
  - タプルの添字は名前でないので、`t.0` は前が何であっても項目・メソッド・flow を指せない。だから `t.0(x)` の直し方は常に `.(` で、`t` が何かに依らない。
    §6.1 が名前の経路を名前の段にした理由は「修正候補が呼び先の種類で分かれる」ことで、`t.0` には当たらない。読みが一つに決まる最初の段は構文の段である。S-191 の「名前の経路は名前の段」は、この理由のとおりに、タプルの添字で終わるものを除くと改める。
  - 書き手には「タプルの要素は値で、`.(` で呼ぶ」という一つの規則に見える。`t.0(x)` と `mk2().0(x)` が同じ段の同じ診断になり、(b)・(c) のように頭で段が分かれることも、(d) のように一方だけが通ることもない。
  - 印は「名前の直後」（§2.6）なので、添字の後に書けないのは名前の経路でない値の後（15・22 行）と同じ扱いで、新しい規則が要らない。
    今の 14・21 行の、候補を当てると前の段の誤りが残る形も無くなる。`t.0!(x)`・`t.0~(x)` は意図が一つに決まらない（関数値を呼びたいのか、メソッドの名前を書き落としたのか）ので、候補を出さないのは今の 15・22 行と同じである。
  - 実装は `callee.rs` の二つの述語から添字を外すだけで、(b) より名前の段の枝が少ない。
    W4-12 の持ち越しの「関門の結果を AST に持たせるか」は、名前の段が受け取る呼び出しの呼び先が名前・フィールド・`::[…]`・名前の経路に付けた `[…]` の形だけになり、添字の鎖を見分ける必要が無くなる。印を持たせるかは W4-12 の設計メモのままでよい（(b) では、印が無いと名前の段が構文の段の鎖の読みを繰り返す）。
  - 後で緩められるか: (a)・(b)・(c) はどれも誤りにするので、後で段を移しても通っていたプログラムは壊れない。(d) から他の案へ移ると、通っていた `t.0(x)` が壊れる。
  - 第 2 期と JS / WASM: 構文の規則なので型やバックエンドに依らない。`.(` は間接の呼び出しを見た目で示す印（§6.1）で、JS の生成でも間接の呼び出しの位置が同じに分かる。
  - 規則から決まる S:
    - S-342: 表の 7 行（`t.0(1)`、`s.t.0(1)`、`u.0.0(1)`）は構文の段の E0020（`callee_expression` の行）で、候補は `.` の挿入。9 行の頭の誤りは、候補を当てた後の名前の段の E0302・E0413・E0401（後の段なので §18.1 の約束の内）。
    - S-591: 表の 13・14・20・21 行（`t.0!(1)`、`mk2().0!(1)`、`t.0~(x)`、`mk2(x).0~(x)` など）は構文の段の E0002 で、候補なし。flow の外の形（23 行）も同じ E0002 で、E0821 には届かない。
  - あわせて決めること: 印の E0002 の note は、`!`・`~` は項目・メソッド・flow の名前の直後に書くことを示す（今の `~` の文面「written without spaces」は空白の誤りと読める。文面は約束しないので W4-12 で改める）。
