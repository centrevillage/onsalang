# S-1275 族: 添字の基の評価

- 位置付け: 第 123 組の族の規則。S-1273（添字の中で基を変更する形）と S-1274（入れ子の添字の範囲の検査と後の添字の式の順）はこの規則から決まる。W8-03 の正規化の単位（U7a）の前に決める。
  下書きの全文（族の 41 形の表、他言語、前の決定との照らし合わせ、五つの組み合わせの比べ）は `target/notes/194/g123/draft.md`、入力は同じ所の `probe/`。独立のレビューの段 1・段 2 は `advisor/`（伏せた版 `blind.md`・`blind2.md`、報告 `onsa-advisor-af70759dc17dcbfd5-001.md`〜`003.md`、入力 `advisor/probe/`）。
- 決定済みで戻さないもの: §3.5 の左から右の順と例「`xs[i][j]` で両方が範囲外なら `i`」（S-75）、代入は右辺が先（S-1264）、呼び出しの引数の窓の E0702（S-193・S-799）、兄弟の要素は値として書いた順に取る（S-806。`xs[0] + reset(inout xs)` は前の値）、借用束縛の経路の添字（S-803 の補い E1）、flow の本体では変更を書けない（§11.2）。
- 論点: §3.5 は「添字 `xs[i]` は、`xs` の後に `i` を評価する」とするが、基 `xs` が場所（局所変数、`inout` の引数、フィールドと添字の経路）のとき、「`xs` の評価」が場所を決めるだけか（P）、基の値を読むか（V）、基の中の添字の範囲の検査を含むか（K）を書いていない。
  P か V かで、添字の式が基を書く形（S-1273、`xs[reset(inout xs)]` は 8 か 2）の値が割れる。K を含むかで、入れ子の添字の後の式が panic するか抜ける形（S-1274、`grid[i][1 / z]`）の報告と値が割れる。
- 今の実装（`target/base/0049175/onsa`）: 添字の中で基を変更する形は、場所の経路の基なら解釈器も C も P の値（8）で揃う。場所でない基（`if`・ブロックの末尾、`slice`）は割れるか、移した・破棄した `Buf` を読む（R-531・R-532）。範囲の検査は、場所の基では後の添字の式の後（`grid[i][1 / z]` は 0 で割る、`grid[i][pf(z)?]` は `Err(9)` を返して範囲外を報告しない）、場所でない基・分けた形（`let row = grid[i]`）・引数では先（範囲外）。C の代入先の位置の順は C の規格で決まらない順に頼る。
- 案（族の案ごとの表は全文の「族の案ごとの比べ」。段 2 の指摘で、並べる案を二つに絞った）:
  - **F4** = (3)+(A): 添字の式の評価の間に、基と重なる場所を変更すると E0702（場所でない基も、末尾の場所・部分ビューの元・`move` を同じに数える）。基の評価は中の添字の範囲の検査を含む。
    字（§3.5 の添字の箇条に足す）: 「`xs` の評価は、中の添字の範囲の検査を含む。」、panic の箇条の例に「`xs[i][1 / z]` で `i` が範囲外、`z` が 0 なら `i`」。§5.2 の E0702 の段落に「添字 `xs[i]` の `i` の評価の間も同じで、`i` の中で `xs` と重なる場所を変更すると E0702 である（`xs[reset(inout xs)]`、`s.xs[f(inout s)]`、`xs.slice(0, 2)[f(inout xs)]`）。`xs` の場所は借用の引数と同じに数える。」
    費用: 今通って読みも割れない形が誤りになる（下の表の一つ目。`self.voices[self.alloc!()].note_on!(n)` は `let i = self.alloc!()` を前に出す書き方に直す。同じ書き換えは `self.voices.get(self.alloc!())` が今も E0702 で求めている）。sema の値の段に窓を一つ足す（`walk.rs` の二か所、見込み 40〜80 行）。
  - **F1′** = (1′)+(A): 場所の経路そのままの基（括弧を含む）は添字の中で変更でき、要素は添字の後に読み書きする。それ以外の基（末尾の場所、部分ビュー）は E0702。検査は (A) で、長さが値で決まる基（`Buf`）の中の検査は、後の添字が純でなければ触れる前にもう一度行う。
    字: §3.5 に「`xs` の評価は、中の添字の範囲の検査を含む。場所の経路の `xs` は、要素を読み書きするのが `i` の後である。長さの変わりうる `xs` は、`i` の後に検査し直す。」と F4 と同じ panic の例、§5.2 に F4 の一文を「場所の経路でない `xs`」に限って足す。
    費用: 規則が二つと `Buf` の検査の例外。表面が割れる（`xs[reset(inout xs)]` は 8、`({ xs })[…]`・`xs.slice(0, 3)[…]`・`xs.get(…)` は誤り）。全ての後端（C・JS・WASM）で場所の経路の値（変更の後）を保つ事例が要る。後で F4 へ締めると、リリースの後は通るプログラムを壊す。
  - 並べなかった案: F2 = (1)+(B)（検査を添字の式を全て評価した後に）は、R-531 の穴を残し、早い出口で範囲外を隠し、基の種類で報告が割れるので、そのままでは立たない（段 2）。V を採る F3 は、基の全体の写し（`[F32; 4096]` なら 16 KiB）と、ビュー・Affine の要素の例外が要る。

- 他言語: 値の型の配列を持つ Rust（組込みの配列）・C・C++・Swift は、場所の経路の基を添字の中で書き換える形を通し、変更の後を読む（F1′ の値）。Rust は `Vec`（`Index` の呼び出し）とスライスの基では借用の誤り（E0502）で、F4 に近い。範囲の検査を後の添字の式より先にするのは Rust・C++ の `at`・Java・Python（(A)）、後にするのは Swift。
- 生成コードの性能: (A) は、後の添字が panic しうる・書く・抜けうるときだけ、検査した添字を一時に取る文を分ける（`uint32_t c = onsa_idx(i, 3, …);`）。検査と割り算の数は今と同じで、増えるのはスカラの一時一つ。純な添字（`grid[i][j]`）は一つの式のまま。F4・F1′ とも基の写しは無い。
- 推奨と理由: F4（下書き、確度 中）。(3) の分は中、(A) の分は高。場所を持つ間の変更を誤りにする規則（引数の E0702、`for` とガードの E0715）を添字にも当てる一様さ、R-531 の穴を同じ判定で塞ぐこと、(A) に `Buf` の検査のやり直しの例外が要らないこと、後で F1′ へ緩めても通るプログラムを壊さないこと。
- 独立のレビュー: 段 1 は伏せた版から独立に F4 を選んだ（S-1274 の (A) は高）。段 2 は三件とも一致。確度は中のまま（理由は同じ基準から出ていて、独立の裏付けにはならない。残るのは、一つ目の表の形を誤りにする重みで、利用者の判断）。段 2 は F1′ を対等に並べるべきとし、下書きの F2 の費用の書き方（「例外も無い」）、S-1274 の「値は変わらない」、「書き手の出身の言語で読みが割れる」を理由にする所を誤りか弱いと指摘した（上の案と表は直した後の字）。
- 影響: 仕様は §3.5 の添字の箇条と panic の箇条の例、F4 は §5.2 の E0702 の段落に一文、F1′ は同じ一文を限って足す。作業は W8-03（sema の窓は U7a の前の単位、正規化の検査した添字の一時は U7a、解釈器は U3 の場所の順の直しに続けて）、R-531〜R-534 を同じ作業で閉じる。事例は F4 なら一つ目・二つ目の表を負の事例、F1′ なら一つ目の表の値を全ての後端で保つ事例。
