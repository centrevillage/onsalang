# S-997 細部: 括弧の中に doc コメントのあるタプル形の struct（`struct P(` 改行 `/// x` 改行 `F32)`）の E0020 に、名前付きのフィールドの struct への候補を出すか

- 空白: §4.4 はタプル形の struct を E0020（修正候補は名前付きのフィールドの struct）とし、§2.1（S-433）はタプル形の struct の要素の doc を付く先でないとし、位置が前の E0020 を先に報告するとする。括弧の中に doc コメント（やコメント）のある形（`struct P(` 改行 `/// x` 改行 `F32)`）の E0020 に候補を出すか、出すならコメントを候補の struct のどこに置くかを書かない。
  今（dev `c63b9c0f`）は、改行した形が R-414 の「expected `{`, found `(`」の E0002（1 行 9 桁）で候補なし。R-414 は W5-24 U7b で直す。
  仮の扱い: W5-24 U7b の実装の出す診断のまま（`rules/leader.md` 5.11）。事例 `tests/spec/lex/tuple_struct_doc_struct.onsa` は `fixes` を書かず、コードと行だけを見る。
  U7b の後は、どの形も候補のある E0020 で、候補は括弧の中の doc を名前付きのフィールドの struct のフィールドの前に残し（`pub struct Hz {` 改行 `/// the value` 改行 `priv value: F32,` 改行 `}`）、要素の後ろの付く先の無い doc（`///`・`//!`）は `//` にする。
- 決定: 決定（2026-11-12、利用者。140 回目、W5 の区切りの確認だけ。「全て現状のまま」で了承）: 仮の扱いのとおり。括弧の中に doc コメントのあるタプル形の struct も候補のある E0020 にする。候補は括弧の中の doc を名前付きのフィールドの struct のフィールドの前に残し、要素の後ろの付く先の無い doc（`///`・`//!`）は `//` にする。§4.4 の候補の字のままで、仕様は変えない。
- 経緯: 138 回目（2026-11-11）、W5-24 U7 のテストの担当（onsa-test）が NEW-C として報告した。親が dev のバイナリで今の出力を確かめた。通るプログラムを変えない細部。
