# S-464 宣言のキーワードの並びの誤り

- 空白: 宣言のキーワードの並びの誤り（Rust の `const fn h`・`extern "C" fn h`、`extern fn h`、旧版の `export "C" fn h`、Onsa の修飾の重なりと順 `pub pub fn h`・`rt pub fn h`）。
  今は「expected constant name, found `fn`」などの E0002 で、項目が消えて使う所に E0302 が出る。
  S-459 の引き金（キーワードの前の名前）に当たらない。`const fn` は外す候補の読みが一つ（§6.6）、`extern "C" fn` と `export "C" fn` は C の ABI に出す意味でマニフェスト（§14.2）なので候補を作れない。第 26 組の下書きの付録で見つけた（2026-10-13）
- 提案: 決定（2026-10-13、利用者が親の組み合わせの案 (e) を選び、Fable も推した。下書きは (b)、Fable は (c) で割れた。第 27 組）: 一般の規則と表の行の二層。
  構文解析器は、`const`・`extern` の見出しの失敗に同じ行の項目のキーワードが続く形と、S-459 の並びの後ろの文字列の形で、一つの E0002（一般の note）にして読み続ける（`Failed::Unit`）。表の行 `const_fn`（E0020、`const` を外す）・`extern_fn`・`export_c`（E0002 と note）は、失敗した所で先に当たる。
  行はデータのファイルと実装待ちに登録し、W3-08 に余裕が無ければ次の E0020 の回に実装する。修飾の重なりと順は一つの E0002 と並べ直す候補。仕様 §18.1 に書いた。実装は W3-08。改め（2026-10-13、利用者）: `export_c` は旧版の行なので RF-11 で整理する（`export "C" fn h` は一般の規則の E0002 で読み続ける）
