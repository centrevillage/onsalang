# S-497 括弧の中の要素の中の書き手の改行

- 空白: 括弧の中の要素の中の書き手の改行（腕の `0 =>` 改行 `1,`、struct リテラルのフィールドの値の前、`g(x` 改行 `as F64)`）を fmt が保つか（R-201 の残り）。§3.2 は「書き手の改行（並びやメソッドの連鎖をどこで折るか）は保ち」、§2.5 は括弧の中の改行を空白とする。
  今の fmt は要素の中の改行を除き、そこにある行末のコメントを遠くへ移す（R-201）。あわせて、正規形が改行を除く位置（1 行の形と継続形の閉じ括弧の前、`@mem(bulk)` と `let` の間）にある行末のコメントの置き場所。W3-11/i の設計メモの G2（2026-10-13）
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (2)＋(β) を了承。下書きと Fable が一致、第 28 組。設計メモの (1) とは割れた）: 要素の中の改行は継続の位置（§2.5）だけに残し、他の位置は空白一つに継ぐ。行末のコメントの後の改行はどの位置でも除かず、閉じ括弧と `let` をコメントの前へ寄せない。
  理由: 括弧の中でも記号の置き場所は外と同じ（S-370・S-374・S-380）で、(2) から (1) へは後で緩めても正規形を書き換えない。`spec/tools.md` §3.2・§3.4。実装は W3-11 の U3・U4。
  補い（2026-10-14、第 31 組）: 第 28 組の推奨の「あわせて決めること（`,` を寄せる形）」（`two(a // c1` 改行 `, // c2` 改行 `b)` は `,` を前へ移し、`// c2` はコメントだけの行に残る）も、この決定に含む（S-529）
