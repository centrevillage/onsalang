# S-333

- 空白: 名前の後の `,` を含む `[…]`（`a[i, j]`、`a[0, 1]`）を、型引数の試み（E0020、候補は `::` の挿入）とするか、添字の誤り（候補なしの E0002 と note）とするか。中身が型として読めない形（リテラル、`&&`）は W3-19 で候補を出さないが、名前だけの `a[i, j]` は型として読めるので候補が残る。
  W3-19/b で見つけた（2026-10-09） W3-19 の最後の形: 要素は型として読めなければ式として読むので、`a["s", 2]`・`a[1.5, 2]`・`a[x && y, 2]` にも候補 `a::[…]` が出る（当てた後は後の段の誤りだけで、S-236 の約束は満たす）
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: B6、X、Y）名前の後の `,` を含む `[…]`（`xs[i, j]`、`pair[U8, F32](1, 2.0)`）は構文の段の E0020（`type_args_square_comma`）で、候補は `xs::[i, j]` と `xs[i][j]` の二つ。要素の全てが型か §4.5 の定数式（整数のリテラル、定数の名前と経路、`+ - * / %` と前置 `-`、括弧）の形で読めれば二つ（`Rg[F32, 4].CAP` も二つ。B6 の「型に読めなければ」は型引数の並びの読みのこと、X）。型引数として読めない並び（文字列・浮動小数のリテラル、比較・論理の演算子、呼び出しを含む。`xs["s", 2]`、`xs[a && b, 2]`）は `xs["s"][2]` の形の一つ。末尾の `,` は添字の形では落とす（`xs[i, j,]` の添字の形は `xs[i][j]`、Y）。§4.5 の段の文の「メソッドに付けた `[…]`」は「`,` の無い」に狭める（Y）。
  - 仕様の節: §4.5 の他言語の型引数の項に一文、段の文の言い方を直す。`forms.toml` の `type_args_square_comma` の注記・origin・rule と例の fixed、例二つ。
  - 今通るプログラムが変わるか: 変わらない。報告と候補だけ（今は全ての並びで `::` の一つ）。
  - 実装の見当: `onsa_syntax/src/foreign/calls.rs` の `type_args_square_comma` の候補の作り手に、`]` と `,` を `][` にする候補を足し、要素の読みで `::` の候補を出すかを決める。約 20〜40 行。
  - ぶつかる既存の事例: `spec/foreign-forms.toml` の `type_args_square_comma` の三つの例の `fixed`（二つ目の候補が足される。forms.toml の「直す例」）。`UPDATE_GOLDEN=1` で書き直す。
