# S-1070 `?Escape` の型パラメータの配列 `xs: [T; N]` の引数に、平面の配列リテラル `[a, b]`（`a`・`b` は `Span`）を書けるか（`T` が先の引数や型引数で `Span` に決まる形）

- 空白: §5.3 の表の「`Span` の配列」の行は、平面の配列リテラル `[a, b]` を「引数の型として `xs: [Span[T]; N]`」の引数の位置に書けるとする。§4.5 は `?Escape` の `T` の値を `Span` と同じに扱い、`?Escape` の無い `T` の `xs: [T; N]` に平面の配列を渡す形を E0710 とする。`?Escape` の `T` の `xs: [T; N]` に `[a, b]`（`Span`）を書けるかを書かない。
  今（dev `edf7b772`）: 型の段（`body/calls.rs` の `coerce`）は、その時点で `T` が `Span` に決まっていれば `[T; N]` を平面として扱い、modes は呼ばれる側の宣言の型を呼ぶ側の総称で読んで別に判じていた（二か所の判定が食い違い、呼ぶ側が総称かで結果が変わった）。W6-04 U4 は modes を型の段の記録だけを読む形にしたので、型の段の読みがそのまま出る。U4 の後、`c[T: ?Escape, const N: U32](x: T, xs: [T; N])` の `c(a, [a, b])` と明示の型引数 `c::[Span[F32], 2]([a, b])` は誤りなし、引数の順を入れ替えた `c([a, b], a)` と `g([a, b])`（`g(xs: [T; N])`）は E0710（引数の順で結果が変わる）。U4 の前は、総称でない呼ぶ側ではどれも E0710。
  再現: `target/notes/154/w604/s1070/cases.txt`（`compare.py probe`、前 `onsa-edf7b77`・後 U4）。U4 の壊す側の報告 `target/notes/154/w604/onsa-break-a7ec36e0454acb012-001.md` の指摘 1 と「仕様の空白」に形の表がある。
  読み: (1) `T` が先に `Span` に決まれば平面の配列として書ける（U4 の後の今。引数の順と型引数の書き方で結果が変わる） (2) 平面の配列リテラルを書けるのは、宣言の引数の型が `[Span[T]; N]` の形のときだけで、`[T; N]` には `T` の境界に依らず E0710（表の字のとおり。U4 の前の総称でない呼ぶ側と同じ） (3) `T` が `Span` に決まれば、引数の順に依らず書ける（`g([a, b])` も通す。型の決まり方を待って判じる）。
  通るプログラム: (1) と (3) は U4 の前に E0710 だった形を通し、(2) は U4 の前の総称でない呼ぶ側の結果を保つ（呼ぶ側が `?Escape` の総称のときに誤りなしだった形は、どの読みでも誤った読み方の結果で、(2) では E0710）。
  仮の扱い: (1)（U4 の後の今）。決まるまで U4 を写すかは親が利用者と決める。
  急ぎ: W6-04 の U4 の前（U4 の出力の変化と W7-03 の struct リテラルの枝の置き場に関わる）。
