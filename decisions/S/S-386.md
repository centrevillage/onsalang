# S-386

- 空白: S-370 の「前の行の末尾へ移す」候補を作れない行頭の記号: 前の腕に `,` の無い行頭の `|` と `-`（`0 => 2` 改行 `| 1 => 1,`、`0 => { 1 }` 改行 `-1 => 2,`。OCaml と F# の腕の区切りの `|`、Rust のブロックの腕の `,` の省略と負のリテラルのパターン）。
  移すと `=>` が残り、候補の約束（S-236）に反する。今は `=>` の位置の E0002（候補なし）。候補を作れないときのコード（E0002 で `,` の挿入一つか、E0020 のまま候補一つか）を決める。第 18 組の下書きの付録が `|` の形を見つけ、Fable が `-1` の形を足して急ぎを上げた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて Fable の案を了承。第 18 組の Fable のレビューの補足 6）: 前の行の末尾へ移すと `=>` の前で終わって二項の読みが成り立たない行頭の記号は、読みが割れないので、一般の `,` の抜け（S-384）と同じ E0002 で、修正候補は `,` の挿入一つ（主の位置は行頭の記号）。
  S-370 の E0020 と移す候補は出さない。記号が被演算子に接していない `- b` は、`,` を入れても前置の空白の E0020 が残るので候補なし。`|` の形は、`,` を当てた後に S-383 の E0020 が出る二段で直る。
  判定は一度の読みの中で行う（腕のパターンの後の `=>` で失敗したとき、その腕の本体の行頭の `-` / `|` を二項として読んだことを覚えておく。次の要素を試しに読まない）。仕様 §2.5。実装は W3-06
