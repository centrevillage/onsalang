# S-1073 細部: 単位の最初の誤りの後にある、報告しなかった誤りのフィールド（`struct RA { x: Buf[Str], b: Buf[RB] }` の `b`）を、外の使う側が読めた部分として読むか

- 空白: §18.1 は、型の段の検査を単位ごとに最初の誤りで止め、読めなかった部分（フィールドなど）を誤りの型として使う側に見せる。単位の最初の誤りの後にあり、判定しなかったので報告もしなかった誤りのフィールドを、外の使う側が誤りの型として読むか、読めた部分として読むかを書かない。誤りのあるプログラムだけの形で、通るプログラムは変わらない。
  今（W6-04 U15 の後。U16 で変わらない見込み）: `RA { x: Buf[Str], b: Buf[RB] }`・`RB { a: Buf[RA] }`・`struct OC[T: Copy]`・`RU { u: OC[RA] }`・`RV { u: OC[RB] }` で、`RA.x` の E0416 の他に、`RU` に E0416（`RA.b` の `Buf` で `RA` が Affine）。`RV` は黙る（`RB.a` は報告して誤りの型）。宣言の順によらない。
  再現: `target/notes/155/s1066/advisor/cases_more.txt` の `w05_ring_first_error_other_field_users` と `_rev`。
  読み: (1) 報告しなかった誤りのフィールドも誤りの型（単位の最初の誤りの後も残りのフィールドを判定し続ける手当てが要る） (2) 報告したフィールドだけ誤りの型で、他は読めた部分（今）。
  仮の扱い: (2)（今の実装。`RU` の E0416 は `RA.x` を直しても残る誤りで、連鎖でない）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-16、利用者。156 回目、W6 の区切りの確認だけ。「既決と矛盾が無ければ、仮の扱いのままでも良いです」。親が既決との突き合わせを確かめた）: 仮の扱いのとおり (2)。単位の最初の誤りの後にある、判定しなかったフィールドは読めた部分で、外の使う側はそれで判定する（`RU` の E0416）。
  突き合わせ: §18.1 の「読めなかった部分」（判定に失敗して報告したもの）と、S-1067 の「読めた部分だけで決まる判定を行う」と同じ向き。
