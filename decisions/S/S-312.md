# S-312 複数の経路を渡したとき（一回の実行は一つのパッケージ）

- 空白: `onsa test` に複数のファイルを渡す形の残り（S-286 が決めたのはマニフェストの無いファイルを複数渡すと 2 だけ）。
  同じパッケージの中のファイルを複数渡したとき（それらのモジュールのテストを合わせて選ぶか）、パッケージの中と外のファイルを混ぜたとき、`check`・`build`・`interface` にマニフェストの無いファイルを複数渡したとき（「一回の実行は一つのパッケージ」を全てのコマンドの規則にするか。今の読み込みはどのコマンドでも複数のファイルを一つのパッケージにまとめる）。
  S-286 の反映で見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者。第 11 組の Fable の案 (b)。下書きの推奨は (a)）: パッケージを読むコマンド（`check`、`test`、`build`、`interface`、`graph`、`audit`、`play`、`probe`）の経路の引数は一つ（ファイル、ディレクトリ、`onsa.toml`）で、二つ以上は使い方の誤り（2）。`fmt` と `diff --ast` は対象外（S-261）。
  理由（利用者）: (a) は S-286 の「一回の実行は一つのパッケージ」と複数のファイルを一旦禁止にした決定と矛盾する。後で (a) へ緩めても既存の実行は壊れない。S-286 の「マニフェストの無いファイルを複数渡すと 2」はこの帰結になる。仕様 §15.1、§18.2（第 11 組の他の項目と同じ回に反映）。
  実装は W4-02（`read_input` が一つの経路からルートを探す。`sig.rs` の `build_module_tree` の上書きは内部エラーに。`check_json_document.rs` の 3 件を書き換える）。
  あわせて（2026-10-09、利用者が了承）: ディレクトリの引数はパッケージのルートを指し、`onsa.toml` を持たないディレクトリ（`onsa test pkg/dsp`）を渡すのは使い方の誤り（2）（S-286 の下書きのあわせて決めること。仕様 §15.1）。作業ディレクトリの外から走らせる `--dir`（利用者の提案）は足さず、位置の引数の形は S-323 で決める
