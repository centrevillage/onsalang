# S-1095 二項の木の中の、イベントの値だけの部分式のクロック（`(a.x + b.y) + z`、`z` は周期の刻みのクロック）

- 決定済みで戻さないもの: S-560（別の入力のイベントのクロックどうしは比べられない）、S-567 の K4・K5、S-1158、S-1196、S-1210。下書きの全文（出所、前の議論との整合の表、族の形の表、他言語）は `target/notes/183/g118/draft.md`、伏せた版は `blind.md`、段 1 の報告は `stage1_report.md`、値の模型は `model/`（下書き）と `adv/`（段 1）。
- 論点: §11.3 の「式のクロックは三つで決まる…最大が無ければ E0815」を、部分式ごとに当てるか、一番外の式に当てるか。`a`・`b` は別のイベントの入力、`z` は周期の刻みの値。S-567 の K4 の [確 13] の例 `(a.x + z) + b.y` はどの読みでも通る。割れるのは `(a.x + b.y) + z`（`a.x + b.y + z` も同じ木）。
- 今の実装: `at event` は E0302。周期の値の似た形 `(lf4~(p) + lf2~(p)) + z` は今も部分式の E0815。
- 案: (A) 各部分式が自分の直の被演算子で決まる（内側の `a.x + b.y` は E0815）。(B) 一番外の式に周期の被演算子があれば内側もその刻みで読む（`let` に分けると E0815）。(C) イベントの源の集まりを持つクロックにし、読む所の刻みで評価する（`let` に分けても通る）。(D) 別のイベントどうしの合わせを本体の `sample` とする。
- 比べ（要点）: (A) は足す文 0・例外 0、`let` に分けても分けなくても同じ（どちらも E0815）。代わりに `a.x + b.y + z` は誤り、`z + a.x + b.y` は通る（並びで変わる）。(B) は `let` に分けると通らなくなる。(C) は `let` の段が読む所で決まり、`Clock` の形が変わる（sema +200〜350 の見当）。
  (D) は四つの所（遅延の第 1 引数、帰還、`reset_if~` の条件、イベントの出力）でイベントごとの処理を黙って `sample` ごとに変え、S-560 を改める。
  典型: 二つの入力を合わせる `note_hz(m) * depth(tr)` は、(A) では `(note_hz(m) at sample) * depth(tr)` と書き直す（1 回）。
- 推奨と理由: 下書きは (A)（確度 中〜高）。§11.3 の「部分式も含めて」と「`let` は名前を付けるだけ」（K5 の理由）に揃い、後で (B)・(C) に開ける（今の誤りが通るだけ）。診断は E0815、note は「各イベントの値に `at` を付ける」（`(a.x + b.y) at sample` は直しにならないと分かる文）。修正候補は出さない。
