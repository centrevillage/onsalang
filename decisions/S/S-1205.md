# S-1205 細部: 変換の flow（導くクロックの入出力を持つ flow）の生成する API の項目と `onsa interface` の表示

- 空白: §11.6 は `process`・`process_inplace`・`render`・`In`・`Rendered` を `sample` の入出力から作る形を書き、§11.9 は一番外の flow の `sample / N`・`sample * N` を E0810（W10-01 まで E0200、使う所と `@export` の印）とするが、変換の flow の生成する API の項目に導くクロックの入出力を入れるかを書いていない（§19.1 の「後で `sample * N` を境界に開くときの生成する API（S-574）」）。今の実装（W7-09 U4a）は入力の側を「ホストの入力」（`ClockRef::host`）だけにし、出力の側は常に項目を作るので、`onsa interface` は `decim(x: F32 at sample) -> F32 at (sample / 2)` に `process(…, input, inout output: Span[F32])` と `process_inplace` を、`allslow(lf: F32 at (sample / 4)) -> F32 at (sample / 4)` に `process(inout s, inout output: Span[F32])` と `render(frames, sample_rate)` を出す。
  読み: (1) 導くクロックの入出力は項目に入れない（入出力の両方で揃える）、(2) 入れる、(3) 変換の flow には `process` などを作らない（使えば E0200・E0810 なので）。使う所は E0200 で止まるので、通るプログラムは変わらない（`interface` の表示と、使えない項目の名前の有無だけ）。
  仮の扱い: 今の出力のまま（W7-09 U4a）。急ぎ: W10-01 の境界の E0810 の前（`rules/leader.md` 5.11 の確認だけ）。
- 補い（2026-11-21、親）: 173 回目、W7-09 U4a/i2: 導くクロックの入力は生成する API の引数にならないので、入力が E0810 の変換の flow の `render` は `(frames, sample_rate)` の見出しで型を検査し、`badty.render([1.0, 2.0], 8.0)` は E0401 になる（`sample` の struct の入力の flow は `members_unknown` で黙る）。この S で項目の形を決めるときの材料。
