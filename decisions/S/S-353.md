# S-353 括弧の中のメンバの `.` の後の改行

- 空白: 括弧の中で、メンバの `.` の後に改行を置く形（`two(s.` 改行 `f, 1)`、`s.f.` 改行 `(1)`）を受けるか。§2.5 は「メンバの `.` の前後に、行の中で空白を空けない」「次の行の頭に置く `.` は継続」とし、括弧の中の改行は空白として扱う。今は括弧の中の `.` の後の改行が黙って通り（W3-20 の前から）、`.(` の形も届く。括弧の中の `s .` 改行 `f` は候補なしの E0002。W3-20/b で見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 15 組）: メンバの `.` の後の改行は、括弧の中でも外でも構文の段の E0020（データのファイルに新しい行）。候補は `.` を次の行の頭（名前、タプルの添字、`.(` の `(` の直前）へ移す形で、間のコメントと空行は残す。
  改行の後が名前・整数・`(` でない形は E0002（今の文面）。`s .` 改行 `f` は一つの置き場所の誤りで、候補は `.` を移す形一つ（`space_around_dot` の行は今どおり後が改行の形を外す）。継続の一覧と §18.1 は変えない。
  退けた案: 括弧の中だけ受ける (c)（同じ字面を場所で受けたり拒んだりする。R-62 の「規則を一つに」）、継続に足す (d)（名前を書き落とした `let a = s.` が次の行の文と黙ってつながる）。仕様 §2.5。
  実装は W3-06（否定例と `tests/spec/fixes/` にタプルの添字の形を一件、第 15 組の補足 2）（読みの補い、2026-10-10、親: 改行の後がキーワードなら、名前の字句ではないので候補を作らず E0002（`let c = s.` 改行 `let d = 1`。§2.2 の「`.` の後のキーワードは名前として読む」はモジュールの経路の規則）。パターン・型・`use`・`impl` の経路の `.` も「修飾」として同じ規則（S-203 の空白も同じ）。W3-06/b（単位 1b）が見つけた）
