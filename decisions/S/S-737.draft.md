# S-737 同じ enum の列挙子と、その型の `impl` の関連定数が同じ名前のとき（`pub enum E { A(I32) }` と `impl E { pub const A: I32 = 1 }` の `E.A` が両方を指す）、E0304 か

- 決定済みで戻さないもの: 列挙子どうしと `impl` のメンバどうしの E0304（§4.4、§6.2）、関連関数の名前の形（E0320）、prelude の列挙子を型から引かないこと（S-607）、重なる名前への改名の候補なし（S-652）。
  第 70 組の下書きの「S-737 の仕組みの出所」と「S-737 の形の表」の節（写しは `target/notes/79/g70/draft.md`）。
- 論点: §4.4 は列挙子名の重複を、§6.2 はメソッドと関連定数の名前の重なりを E0304 とするが、型の名前の後の `.` で引く名前（列挙子と、`impl` の関連定数・関連関数）が一つの空間かを書いていない。同じ空間でなければ、`E.A` がどちらを指すかも書いていない。
  関連関数と列挙子は形が違い（§2.3）、重なりうるのは両方の形に合う名前（`A`、`MAX`）の関連定数だけである。
- 今の実装: 表のとおり。重なっても通り、`E.A` は全ての位置で列挙子に解決され、関連定数に届く書き方が無い。関連定数 `a` の改名の候補 `A` は、当てると `clean` になり、`E.A` の値が黙って変わる。
- 案: 
  - (1) 型の名前の後の `.` で引く名前（列挙子、関連定数、関連関数）は一つの空間で、重なると E0304。付ける宣言は次の二つ。
    (p1) 書いた順によらず `impl` のメンバ（関連定数）に付け、列挙子を note で示す（型の宣言に `impl` が足す側。§15.1 の項目と `use` の付け方と同じ形）。(p2) ソースの順で後の宣言に付ける（項目どうしの E0304 と同じ）。
  - (2) 重なってよく、`E.A` は列挙子を先に引く（今の実装）。§6.2 に「列挙子を先に引く」の一文を足す。関連定数は `E.A` で届かない。
  - 形ごとの出力: (1) は表の列挙子と関連定数が重なる宣言（タプル形、単位形、`Self`、別名、パターン、`impl` を先に書く形、総称）が全て E0304 になり（(p1) は関連定数に、(p2) は後に書いた宣言に付く）、使う所（`E.A(1)`、`E.A`、`Self.A`、`F.A`、`E.A =>`）は誤りの名前として黙る（§18.1 の 89 行）。(2) は今のまま。
    改名の行: (1) では S-652 の範囲に列挙子が入り、候補 `A` は出ず note になる。(2) では E0304 にならないので S-652 は候補を止めず、当てると値が変わる（止めるには候補の規則に例外を足す）。
  - 書き手から見て: 関連定数を書いた書き手は `E.A` で読むつもりで、(2) では列挙子が返り、E0401（型が違うとき）か、黙って違う値（型が同じとき、`const A: E = E.B`）になる。(1) は宣言の所で一つの誤りを示す。
    重なる名前を書くのは、C の列挙の値を同じ名前の定数で持たせたいとき（`enum Color { RED, GREEN }` と `const RED: U32 = 0xFF0000`）など、少ない。
  - 修正候補: (1) の E0304 に候補は無い（どちらを改名するかは書き手が決める）。当て続けても `no-candidate` で止まる。(2) の改名の候補は、今の S-652 の判定のままでは値を変えるのに `clean` で止まる。
  - 通るプログラム: (1) は、列挙子と同じ名前の関連定数を持つプログラムを誤りにする（今の事例と std に、その形は見つけていない）。(2) は変わらない。
  - 規則と例外: (1) は §6.2 の重なりの文に「列挙子と」を足す（空間を一つにするので例外は無い）。(p1) は付け先の句を一つ、(p2) は今の項目の規則のまま。
    (2) は「列挙子を先に引く」の一文と、改名の候補が値を変えないための S-652 の例外（列挙子に隠れる名前も重なりとみなす）を一つ足す。
  - 実装の量: (1) は `assoc` の表に入れる所（W4-05 で S-725 の前段に移る所）で、enum の型の `impl` のメンバの名前を列挙子の並びと比べて E0304 を出す（約 +10〜15 行）。
    `rename.rs::clashes` で、関連定数の改名に持ち主の enum の列挙子を、列挙子の改名に `assoc` の表を足す（約 +5〜10 行）。(2) は改名の判定の同じ足し（約 +5〜10 行）と仕様の一文。
    第 2 期に利用者の trait の関連定数（`impl Tr for E { const A }`）が型の名前で引けるようになると、(1) は同じ空間に入れるだけで、(2) は引く順をもう一つ決める。
- 他言語: 
  - rustc 1.94.1（`probe/other/s737.rs`）: `enum E { A, B }` と `impl E { const A: E = E::B; }` は通り、`E::A`・別名の `F::A`・`Self::A` は全て列挙子 `A` を返す。
    警告は dead_code の「associated constant `A` is never used」で、note に「it is impossible to refer to the associated constant `A` because it is shadowed by this enum variant with the same name」と出る。
  - swiftc 6.3.1（`probe/other/s737.swift`）: `enum E { case a, b; static let a: E = .b }` は「invalid redeclaration of 'a'」の誤り。
  - TypeScript（tsc がこの機械に無い）は未確認。
- 推奨と理由: (1)・(p1)。確度: 中〜高。
  - 型の名前の後の `.` は一つの引き方で、そこで二つのものが同じ名前を持つと、一つの名前が一つのものを指す §5.1 の約束が破れる。(2) では関連定数に届く書き方が無く、宣言しても使えない。
  - (2) は、今の S-652 のままでは改名の候補が値を黙って変え、修復のループが `clean` で止まる（表の改名の行、確かめた）。止めるには S-652 に例外が要る。(1) は空間を一つにするだけで、S-652 がそのまま止める。
  - 実装はどちらも約 +10〜25 行で、W4-05 のメンバの同名の所に入る。誤りにする形は、現実に少ない。
  - (p1) は、列挙子が型の宣言の一部で、関連定数は `impl` が足す側なので、書いた順によらず足す側に付ける。直すのも多くは関連定数の改名である（列挙子は `match` の腕などで多く使う）。(p2) は `impl` を先に書くと列挙子に付く。
  - あわせて決めること: §6.2 の 83 行の「メソッドや関連定数の名前が重なると E0304」を「メソッド、関連定数と、列挙子の名前が重なると E0304（関連定数に付け、列挙子を note で示す）」とし、§4.4 の 95 行から指す。
