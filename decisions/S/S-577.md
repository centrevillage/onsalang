# S-577 std の制御のレートの変換の flow: 方式と、比の名前

- 空白: §19.1（S-565・S-566・S-567）は、制御のレートを `.down~(N)` の部品で書き、音声の信号を遅いクロックへ下げるのは変換の flow（速い側を配列で受ける flow）だけ、遅い値を `at sample` で読むと保持、とした。std の変換の flow（S-568）の下書きはオーバーサンプリング（2 倍のハーフバンド）だけを扱い、制御のレートの変換を扱っていなかった。決めること:
  1. std に置く制御のレートの変換の一覧と方式（下げる: ブロックの平均、最後の値、ピークなど。上げる: 線形の補間、一次の平滑など）。線形位相の FIR を使わない理由（ステップの前から動く、遅れ）。
  2. 比の表し方。flow は比を引数に取れないので、比ごとの名前になる（S-568 の名前の形 `fir_up2` に合わせるか）。置く比の一覧（16、32、64 など）。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51 回目）: `std.dsp` に `cut_down16`・`cut_down32`・`cut_down64`（塊の最後の値）、`avg_down16`・`avg_down32`・`avg_down64`（塊の平均）、`lin_up16`・`lin_up32`・`lin_up64`（2 乗算の形の線形の補間。既定値 0 から上がる）を置く（型は `F32` だけ）。
  std の flow が中で `.down~(N)` を使い、呼び出しに修飾子は要らない。線形位相の FIR とピークは置かず、比を持たない平滑は S-579。名前と最初の刻みは回答のとおり。仕様 §19.1
- 経緯: 第 35 組（X-7）の S-568 の B-2 の確かめ（2026-10-22、51 回目）で、利用者が「Onsaではコントロールレートをダウンサンプリングで扱うと決めているので…コントロール信号の変換にFIRは適切ではない」とし、親が範囲を確かめて、利用者が「std に制御のレートの変換の flow も要る」の読みを了承した。関係: S-565、S-566、S-567、S-568。
