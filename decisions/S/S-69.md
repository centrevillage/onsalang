# S-69

- 空白: 降下が std の `target fn` を、`std.math` と `array.from_fn` 以外は名前の文字列のまま `Prim::Std` にする。`check` を通ったプログラムが、インタプリタでは実行時に、C ではビルドで落ちる。組込み型のメソッドの知識が、sema の `builtin.rs`、降下、`rt.rs` / `effects.rs`、各バックエンドに名前の文字列で散っている（レビュー R-79）
- 提案: (1) 組込み型のメソッド・関連関数・関連定数を std の `impl` に宣言する（D-07 の追記）。(2) sema は名前ではなく表の ID を Core へ渡し、降下は名前を読み直さない。(3) 各バックエンドは `Prim` を `_` 無しで網羅し、与えないものを明示する。
  降下の後、走らせる・生成する前に Core の全体を照らして E0200（機能名と変換先）を出す（インタプリタも同じ。「Core の全体」は S-242 で、その実行やビルドの入口から届く範囲に改めた）。M5 までの `std.test` の `check` / `gen` は、表に未対応の印を付ける。
  (4) std の `target` 宣言は `bind` で差し替えられない（コードは `bind` の実装と一緒に決める）。`tests/review-phase1/parent/r79/` の期待値は `m.onsa` の各項目の上のコメント（2026-10-04 決定。実装は第 4 段。組込みのメソッドの一覧は先に R-126 で閉じる）
- 時期: M2
