# S-750 derive の一覧と効果行の同じ要素の重なり（`struct P: PartialEq + PartialEq`、`uses {Alloc, Alloc}`）の診断（今はどちらも黙って通る）

- 空白: §6.4 の derive の一覧と §8.1 の効果行は、同じ要素を二度書く形を書いていない。`pub struct P: PartialEq + PartialEq { … }` と `fn n(x: I32) -> I32 uses {Alloc, Alloc}` は今どちらも診断なしで通る（再現は 80 回目の第 72 組の下書きの `probe/s747/b12`・`b13`）。
  読み: 並びの同じ要素の重なりを誤りにする（同じ名前の二度の `use`、型パラメータ、struct リテラルのフィールド、`@latency` の項は誤りで、候補なし）、意味を変えない余分として受理して fmt が除く（§0.5.1）、そのまま通す。境界の並びの重なり（S-747）と、属性の重なり（S-490、族「§6.5 の同じ属性の重なり」）と揃えるかも決める。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R9、B2、既存 tools.md §3.5、X）derive の一覧の同じ trait の重なり（`struct P: PartialEq + PartialEq`）は E0416、効果行の同じ効果の重なり（`uses {Alloc, Alloc}`。効果行変数も同じ）は新しいコード E0602 で、どちらも境界の重なり（§4.5）と同じ形（二つ目に付け、一つ目を note、候補なし）。上位の trait を並べる形（`Ord + PartialEq`）は誤りでない。並びの順（S-750 の補い）は揃えない。`onsa diff --ast` は集合として読む並び（境界、derive の一覧、効果行）を集合として比べて順の違いを出さず、fmt は書き手の順を保つ（`spec/tools.md` §3.5 の「項目の順は報告しない」の先例、X）。
  - 仕様の節: §6.4 に一文、§8.1 の効果行は集合の項に一文、§4.5 に R9 の文、`spec/tools.md` §3.5 に一文。
  - 今通るプログラムが変わるか: 誤りになる（`PartialEq + PartialEq`、`uses {Alloc, Alloc}` は今は通る）。`onsa diff --ast` は順だけの違い（`~ struct P`、`~ fn f`）を出さなくなる。
  - 実装の見当: derive は `onsa_sema` の derive の一覧を読む所（`def.rs` の `derives` の作り手）で `sig/bound_list.rs` の重なりの判定（84 行）と同じ形、約 10〜20 行。効果行は `onsa_sema` の効果行の名前を解決する所で同じ効果の重なり、`onsa_diag` に `Code::E0602` と `explain/E0602.md`、約 20〜40 行。
  - ぶつかる既存の事例: なし（`tests/spec/types/bounds_overlap.onsa` は境界の事例で、今のまま）。
  - E0602 の意味の一行（登録簿と `tasks/diag-codes.md` は親が揃える）: 「E0602 | 効果行に同じ効果（効果行変数を含む）を二度書いた（S-750）。重なる最初の要素に付け、前の要素を note で示し、候補なし | 名前解決 | M3」。
- 経緯: 80 回目（2026-10-28）、第 72 組の下書き（onsa-gap）が新しい S の候補（NEW-1）として挙げた。関係: S-747、S-490。
