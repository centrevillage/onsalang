# S-810 既定のモードの関数型の引数を借用の `match` の見出しに置く形（`match f { g => g }`、`match f { _ => 1 }`）

- 空白: §5.4 の 139 行は、既定のモードの関数型の引数を「`let` に束縛できず」とし、§5.3 の 92 行は「借用と `Span` … だけは、§5.4 の規則で `let` と `for` と `match` の腕に束縛できる」とする。借用の `match` の見出しに既定のモードの関数型の引数を置く形は、どの列挙にも無い。
  `match f { g => g }` は腕の束縛 `g` を通して値を返せる。`match f { _ => 1 }` は値を持ち出さない。
  読み: (a) 見出しに置くと腕によらず E0710。(b) 名前を束縛する腕があるときだけ E0710（`_` だけなら通る）。
  dev（`6de1620d`）はどちらの形も通す。再現は `target/notes/92/w411/i/probe/forms.onsa` の g3 と `forms2.onsa` の h1。
- 決定: 決定（2026-10-31、利用者。92 回目）: (a)。既定のモードの関数型の引数を借用の `match` の見出しに置くと、腕のパターンによらず見出しの式の位置で E0710（`let _ = f` と同じ数え方）。`Span` の `match xs { _ => 1 }` が通るのは、`Span` が `match` の腕に束縛できる（§5.3 の 92 行）からで、関数値には無い。仕様 §5.2 の 87 行に足した。実装は W4-11。
- 経緯: 92 回目（2026-10-31）、W4-11 の設計メモ（onsa-impl）が NEW-2 として挙げた。親が dev のバイナリで再現した。
- 経緯（2026-10-31、親）: S-809 と同じ要約で段 1 にかけ、段 1 は (a) を選んだ（親の読みと一致、段 2 は省いた）。利用者が (a) を選んだ
