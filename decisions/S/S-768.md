# S-768 境界の並びに見つからない名前がある型パラメータ（`struct M[T: Gone]`、E0302）を使う側（`M[Buf[F32]]`）で、暗黙の `Dup` を含む要求を判定するか（未知の境界として何も判定しないか、見つからない名前だけを除いて暗黙の `Dup` は判定するか）

- 空白: §18.1 の誤りのある宣言の段落は、読めなかった部分を誤りの型とし、それを使う側に診断を出さないとし、総称の境界の失敗した名前は未知の境界（その型引数に頼る判定には診断を出さない）として読むとする（S-689）。`struct M[T: Gone]`（`Gone` は見つからない、E0302）の後の `fn f(x: M[Buf[F32]])` で、`M` の `T` の暗黙の `Dup`（§4.5 の 143 行）を判定するかは書いていない。
  `Gone` を何に直しても（`?` の無い境界は暗黙の `Dup` を外さない）`M[Buf[F32]]` の `Dup` の誤りは残る、とも読める。一方、境界の並びの誤りを使う側で未知の境界として読む既決の形（S-711 の `?Copy`、S-747 の矛盾の並び。どちらも書き手が `?Dup` のつもりでありうる）は、暗黙の `Dup` を含めて判定しない。
  W4-05 U4a のテストの票は `tests/spec/types/wellformed_type_args_unknown_bound.onsa`（26・39 行の `M[Buf[F32]]`）を (1) で書き、実装の担当が `sig.rs::lower_generics` の E0302・E0308 の枝で `unknown = true` にして通した（範囲の外の変更として報告。HEAD `4561708` の前のコードは (2) の E0416 を出していた）。
  読み: (1) 未知の境界として、暗黙の `Dup` を含めて使う側で判定しない（S-711・S-747 の誤りの並びと一つの規則。偽の連鎖を出さない向き）。(2) 見つからない名前だけを除き、暗黙の `Dup` は判定する（`M[Buf[F32]]` は E0416）。
- 決定:
- 経緯: 82 回目（2026-10-29）、W4-05 U4a/i（onsa-impl）が仕様の空白（NEW）として報告した。親の読みは (1)（境界の並びの誤りは、見つからない名前も S-711・S-747 と同じく使う側で未知の境界）で、確認だけにする。期限は W4-05 U4a（実装と事例は (1) の形）。関係: S-689、S-711、S-747、S-756。
