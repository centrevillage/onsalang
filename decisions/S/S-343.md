# S-343

- 空白: 消費しない位置（文の位置の `if c { move a } else { move b }`、条件、`match` の対象）に置いたブロックの末尾の `move` を、構文の段の E0002 にするか、構文は通して modes の段の誤りにするか。
  S-100 は「消費する位置に置いたブロックの末尾の式に `move` を書ける」とし、§5.2 は消費する位置を列挙するが、それ以外の位置の末尾の `move` のコードと段を書かない。
  W3-20/t で見つけた（2026-10-09）。`for` の反復元に置いたブロックの末尾の `move`（`for x in if c { move xs } else { move ys } {`）も同じ問い（§5.2 は `for` の反復元を消費する位置に挙げるが、反復元は `move` の無いときは借用。今は E0200 `MoveOnUnconsumedTail`。W3-20/b で見つけた）
- 提案: W3-20 は構文を通して modes の段に回す仮の扱い（`SPEC-GAP(S-343)`）。W4-09 の前に決める
- 時期: W4
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。57 回目、第 42 組）: 族の規則 S-605 から決まる。
  消費しない位置（文、条件、二項演算子の被演算子、添字、範囲の端、借用と `inout` の引数）に置いたブロックの末尾の `move` は modes の E0703 で、候補はその `move` を消す形。`for x in if c { move xs } else { move ys } {` と `match` の見出しの末尾の `move` は受理し、消費する反復と所有の腕になる。`MoveOnUnconsumedTail`（E0200）は消す。
  仕様 §5.2
- 経緯: 57 回目、第 42 組（族 S-605、下書き `S-343.draft.md`、助言の担当の二段。全て一致）。
