# S-1215 細部: 導くクロックのポートを持つ flow（`process`・`process_inplace`・`render` を作らない）の `onsa interface` に、それらの関数を載せるか

- 空白: W7-16 U5b2 は、導くクロックのポート（`sample / N`・`sample * N`）を持つ flow の `process`・`process_inplace`・`render` を Core に作らない（使う所は検査の E0200、W10-01 から E0810。§11.9「誤りの位置は、その flow の `process`・`process_inplace`・`render` を使う所と `@export` の印で、`init`・`reset`・`State` は使える」）。`onsa interface` は今もその flow に `g.process`・`g.render` の署名を載せる。§11.6 のインターフェースの節は生成する関数の一覧を述べ、出す flow を区別しない。
  読み: (1) interface は宣言の一覧なので今のまま載せる、(2) 使えない関数は載せない（か、使えない印を付ける）。どちらも通るプログラムは変わらない。
  再現: `target/notes/176/w716/u5b2/pk/`（`pub flow g(p: U32 at block) -> U32 at (sample / 4)` を置いたパッケージ。`onsa interface` に `g.process`・`g.render` が載り、`dump --core` に `g.process` は無い）。
  仮の扱い: (1)（今の出力のまま）。急ぎ: W10-01 で E0810 にするときに、確認だけ（`rules/leader.md` 5.11）。
- 補い（2026-11-23、178 回目、W7-16 U7 の設計メモ）: (1)（載せる）を採ると署名の形が決まらない。§11.6 の `process` の数の規則は `sample` の入出力だけを数え、今の interface は導くクロックの入力を落とし（`g2.process(inout s: g2.State, inout output: Span[F32])`）、`sample * N` の出力を `Span[T]` で書き、`h(y: F32 at (sample * 4), z: F32 at sample) -> F32 at (sample * 2)` にも `process_inplace` を作る（再現 `target/notes/178/w716/u7/memo/p3.onsa` を `onsa interface`）。使う所は E0200（W10-01 まで）なので通るプログラムは変わらない。急ぎは変わらない（W7 の区切りで確認だけ）。
