# S-1067 細部: 誤りのフィールドを持つ型の種（Copy か）が、他のフィールドで決まるとき（`S1[T0: Copy] { f0: (T0, Str), f2: <誤り> }` の `S1[S1[I32]]`）、使う側の境界の E0416 を出すか

- 空白: §18.1 は、読めなかった部分を使う側には診断を出さず、総称の境界では「その型引数が trait を満たすかに頼る判定には診断を出さない」とする。
  誤りのフィールドを持つ型の種（Copy か）が、誤りでない他のフィールドで既に決まるとき（`S1[T0: Copy] { f0: (T0, Str), f2: <誤りの型> }` の `S1[I32]` は `Str` のフィールドで Copy でない）、その型を Copy の境界に渡す使う側（`fn p0_0(move x: S1[S1[I32]])`）に E0416 を出すかを書かない。
  誤りのあるプログラムだけの形で、通るプログラムは変わらない（違うのはどの診断を出すかだけ）。
  今（W6-04 U5 の後。前も同じ）: 種の合わせ方（`summary.rs::greatest`）が Shared と答えの無い部分（誤りの型）を合わせると「答え無し」にするので、E0416 は出ず、その引数の破棄の E0601 が出る。宣言の順によらない（U5 の後）。
  再現: `target/notes/121/w523/u1b/m4.onsa`（`p0_0` の 4:21 の E0601）。
  読み: (1) 誤りの部分を含む型の種は「答え無し」とし、それに頼る判定は全て出さない（今の実装） (2) 他のフィールドで決まる種は決まったと読み、使う側の境界の E0416 を出す（種の事実に「少なくともこれ」を持たせる。kinds と破棄を読む modes などにも及ぶ。見当 +20〜40）。
  仮の扱い: (1)（今の実装。親が U5 の担当に伝えた読みは (2) の向きだったが、実装の担当が範囲の外と判断して直さなかった）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-16、利用者。155 回目、W6 の区切り。二つを一緒にした独立のレビューの段 1 が (2)・(2) を選び親の読みと一致、段 2 は省いた。材料 `target/notes/155/s1066/`。「上記の通りで進めてください」）: (2) と D-c。
  誤りの型の部分を持つ型の種・破棄・`const` の置き場は、読めた部分だけで決まる判定を行い（Copy でない部分があれば `Copy` を求める判定を報告する、置けない部分があれば E0407、Shared の部分があればこの版の E0200）、誤りの部分に頼る判定だけ黙る。仕様 §18.1 の「誤りの型の部分を持つ型の種（§4.6）、破棄（§12.2）、`const` の置き場（§6.6）は、」の文に書いた。
  理由: 今も Affine の部分があれば `Dup`・`Copy`・移動を判定し、破棄の `Alloc` も要る部分があれば報告する。黙るのは「Shared の部分がある型に `Copy` を求める」ときだけで、種の表し方（`Option<Kind>` が「Shared 以上」を表せない）の都合だった。誤りのフィールドを直しても他の部分は残るので、出る診断は連鎖でない（直しの往復が一回減る）。
  §18.1 の `match` の網羅性（誤りの部分は何にでも一致し、他の部分の欠けは報告する）と同じ向き。D-c: `const` の置き場（`kind.rs::Place`）も同じ規則に含める（例外を作らない）。
