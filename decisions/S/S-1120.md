# S-1120 細部: `onsa interface` が示す `@param` の値を、書いた式の字（`max: FB_MAX`）で出すか、評価した値をリテラルの形（`max: 0.95`）で出すか

- 空白: §18.2 の `interface` の行は属性の `@param` を「書いたとおりの形で」出すとし、同じ行は struct のフィールドの既定値を値で出す。§11.7 は「`onsa interface` も、書かれていないキーを出さない」。「書いたとおりの形」の出所は S-588 の A10（`@latency(samples: 32, seconds: 0.005)` を計算した遅れでなく項のまま出す）で、属性の形を言う文である。値の字か評価した値かは決めていない。
  読みは (1) 書いた式の字（`max: FB_MAX`、`label: "Gain {CH}"`）、(2) 評価した値をリテラルの形で（`max: 0.95`）に割れる。(1) では公開でない名前が出て、シグネチャだけでは値が分からない。`const` の項目は今も評価した値で出る。
  今の実装（`aea4ce78`）: 数値のキーは浮動小数の形で出る（整数の入力の `min: -1` が `min: -1.0`）。W7-13 U4 は W9-03 まで値をリテラル・括弧・前置の `-` の形に限るので、W9-03 までの (1) と (2) の差は字面の正規化（`-(60.0)` と `-60.0`）だけ。
  仮の扱い: (2)（W7-13 U4b の `interface` の表示）。改めるなら直す所は `interface.rs` の一か所。W9-03（名前を書ける）と W10-08（`@latency` の項）の前に確認だけ。
