# S-124

- 空白: 継続の間のコメント行と空行、行頭の二項演算子、`with` の位置、宣言の本体と `{…}` の並びの改行が決まっていない（点検 C-12）
- 提案: 継続はトークンで判定し、コメントだけの行と空行は読み飛ばす（空行は fmt が除く）。二項にしか使わない演算子で始まる行は E0020（前の行の末尾へ移す候補）。`with` は `}` と同じ行（E0003）。
  宣言の本体と `{…}` の並びの改行は空白（2026-10-06 決定。実装は構文の段で、E0020 の検出は R-87 の一つのモジュール）（読みの補い、2026-10-10、親: 前の行が `for`・`while` の文や項目の本体を閉じる `}` で終わるとき（`for … { }` 改行 `* 2`）と、`let`・`var`・代入・`return`・`assert` の文で終わるとき（`x = 2` 改行 `= 0`）は、行頭の記号を前の行へ移す・つなぐ候補を作らない。移すと文の後の演算子になり、二項の読みが成り立たず構文の誤りが残る（S-236、S-386 と同じ考え）。`leading_operator` は当たらず、`+` は前置の `+`（S-405）、それ以外は一般の E0002。`if` 式・`match`・ブロックの `}` の後と、`const`・`type` の後は今どおり移す候補を出す。判定は構文解析器が文を閉じたときの記録による。W3-06/i の単位 2 の設計メモと gate のファズが見つけた）（読みの補い、2026-10-10、親: 行頭の記号の直後に、被演算子を始めない記号が空白なしで続く形（`+=`、`-=`、`*=`、`**`、`===`、`!==`、`<>`）は、最初の一字だけを移すと残りの字が誤りになるので、移す候補を作らない（S-236。一般の E0002）。字句がこれらを一つのトークンにするかは W3-04 で決める。行頭の `&` は、前の行が被演算子で終わり次のトークンが被演算子を始めるとき行頭の二項演算子の規則が先（`&mut`・`&*`・`&=` は参照の行のまま）。W3-06/b（単位 2）が見つけた）
- 時期: M1
