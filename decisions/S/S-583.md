# S-583 プラグインの状態と構成: 状態の保存と読み込み、サンプルレートとブロックの長さ、バス、尾

- 空白: プラグインのホストは、プロジェクトとプリセットの保存と読み込み、サンプルレートと最大のブロックの長さの通知（CLAP の `activate` など）、入出力のバスの構成、遅れと尾の長さの報告、バイパスを求める。§14.2 の C の API には `init`（サンプルレート）、`reset`、`_new`・`_free`、`@param` の表があるが、これらの全ては揃っていない。決めること:
  1. 状態の保存と読み込み（パラメータの値を文字列の ID で保存するか、パラメータでない状態を含めるか、版の違いの扱い）。
  2. `activate` と `init` の対応（サンプルレートの変更、最大のブロックの長さとイベントの出力の容量（S-571））と、`reset` を呼ぶ所（トランスポートの停止など）。
  3. `sample` の入出力とホストのバス（モノ、ステレオ、サイドチェイン、`In`・`Out` のフィールドの名前）の対応。
  4. 尾の長さとバイパス。遅れは S-576。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51・52 回目）: 状態はパラメータの値だけを文字列の ID と値の組で保存する文字の形で、`Config` を持つ flow はプラグインにできない（E0200）。ラッパーは起動のときに `_init`、ホストが求めたときだけ `_reset` を呼び、`_process` が 1 を返したら次の呼び出しの前に `_reset` を呼んでホストのログに一度知らせる（回答の (pz2)）。
  ラッパーは自分が起こす初期化の直後に短いフェードインを掛け、C の API と `render` はフェードを持たない（回答）。バスは `sample` の入力ごとに一つのポートで、型は `F32`、チャンネルは 1 か 2（他は E0200）。尾は無限として報告し、バイパスのパラメータは持たない。仕様 §19.1
- 経緯: 第 36 組（プラグインの出力）の一つ。第 35 組（境界、S-570〜S-574）の決定の見込みの上に立ち、C の API がラッパーの要求を満たすかを W10 の前に確かめる。利用者が「VST/CLAP/AU用の出力は主要な機能の一つなので、今考えておきたい」「避けられる手戻りは前もって避けた方が良い」とし、出力の形まで決める範囲（(β)）を選んだ（2026-10-22、51 回目）。関係: S-570、S-571、S-576、§11.6、§14.2、§16。
