# S-864 `target fn` の `else` の次の行に `{` を書いた形（`target fn open() -> I32 else` の次の行の `{ 1 }`）の診断のコード

- 空白: §15.2 の 103 行は `else` の置き場所（見出しの最後のトークンと同じ行）だけを言い、`else` の後の `{` を言わない。S-629 は「次の行の `{` は今のまま」とする（`else` の無い見出しの次の行の `{` のこと）。
  読み: (1) §2.5 の 164 行の一般則「`{` は、それが属する形の最後のトークンと同じ行に書く」で E0003（主の位置は `{`、候補は `else` の行の末尾へ移す）。(2) 別の診断。
  親の読みは (1)（`else` の後の `{` は `else` の形に属し、一般則で決まる）。再現は 106 回目の scratchpad の `w502/u2t/probe/gap2_else_brace_line.onsa`（今は `else` が E0002）
- 決定: 決定（2026-11-03、利用者が確認だけで了承。106 回目）: (1)。§2.5 の 164 行の一般則（`{` は、それが属する形の最後のトークンと同じ行）で、`else` の次の行の `{` は E0003（主の位置は `{`、候補は `else` の行の末尾へ移す）。仕様 §15.2 の 103 行に括弧書きで添えた。実装は W5-02 の U2
- 経緯: 106 回目（2026-11-03）、W5-02 U2 のテストの担当（onsa-test）が NEW として挙げ、事例に書かなかった。親が §2.5 の 164 行から (1) に読めるので確認だけで出す
