# S-760 モジュールをまたぐ flow のインスタンスの循環（`a.fa` が `b.fb` を、`b.fb` が `a.fa` をインスタンスにする）に、E0310 に加えて E0817 を出すか（§18.1 はモジュールをまたぐ型と定数の循環を E0310 だけとする）

- 空白: §18.1 は、宣言をまたぐ循環（`use` の E0310、型の E0311、定数の E0312、flow のインスタンスの E0817）を集まりごとに一つ報告し、「モジュールをまたぐ宣言（型と定数）の循環は、必ず `use` の循環の中にあるので E0310 だけを報告する（他のモジュールの項目は `use` でだけ引け、`use` は依存に数える、§15.1）」とする。括弧は型と定数だけを挙げ、flow のインスタンスの循環は挙げていない。
  形: `a.onsa` の `use b.{fb}` と `pub flow fa … { fb~(x) }`、`b.onsa` の `use a.{fa}` と `pub flow fb … { fa~(x) }`。
  今（`0eb4575`）: `a.onsa:1:1` の E0310「the modules `a`, `b` import each other」だけ（E0817 は W4-05 U5 で入る）。
  読み: (1) 括弧の文のとおり、E0310 に加えて E0817 も出す。(2) 同じ理由（他のモジュールの flow も `use` でだけ引ける）で E0310 だけを出し、括弧に flow を足す。
  どちらも誤りのあるプログラムの報告だけが変わる。(2) は型と定数の守り（成分のモジュールが全て一つの E0310 の成分に入るときは出さない）を flow にも当て、足す行は 0。(1) は flow だけ守りを外す分岐。再現は `target/notes/81/u5/pkg_flow/`。
- 決定: 決定（2026-10-29、利用者。81 回目。第 73 組の独立のレビューの答えと親の案が一致）: (2)。
  モジュールをまたぐ flow のインスタンスの循環は、型と定数と同じく E0310 だけを報告する（他のモジュールの flow も `use` でだけ引け、`use` は依存に数えるので、必ず `use` の循環の中にある）。成分のモジュールが全て一つの E0310 の成分に入るときは E0817 を出さない守りを、型と定数と共有する。
  E0310 を直して flow を一つのモジュールにまとめた後に E0817 が出る二回目の検査は、型と定数で受け入れた形と同じ（S-734）。仕様は §18.1 の括弧に flow のインスタンスを足した。実装は W4-05 U5（`names/body/cycles.rs` の `across_one_cycle`、足す行は 0）。
- 経緯: 81 回目（2026-10-29）、W4-05 U5/i の見積もり直し（onsa-impl）が仕様の空白の候補（NEW 1）として挙げ、親が `P80/bin/onsa-w405u3b2` で再現した。担当の仮の扱いは (2)。利用者が外出中なので、第 73 組の助言のレビューに加える。期限は W4-05 U5。関係: S-734、S-742。
