# S-762 型の位置で、宣言の型パラメータの数を超える型引数（`P[Nope]`・`Ring[F32, 4, K]`・`P[3]`）を読むか（種類と名前を判定するか、数の E0412 だけにするか）

- 空白: §4.5 の 123 行は、型引数の並びの要素を型の位置の並びと同じに読み、要素の種類（型か定数式か）が宣言の位置と合わなければ E0308（名前の段）、数が宣言と合わなければ E0412（型の段、S-103）とする。§18.1 は依存する段の間では位置によらず先の段の誤りを報告する。
  宣言の型パラメータの数を超えた要素（宣言の位置が無い要素）を読むか（種類と名前を判定するか）は書いていない。
  形: `struct P`（型引数なし）、`struct Ring[T, const N: U32]`、`const K: U32 = 4` の後の、`P[3]`、`Option[I32, 3]`、`F32[K]`、`Ring[F32, 4, K]`、`P[Nope]`（`Nope` は見つからない名前）。
  今（W4-05 U4c の作業中の実装）: どれも数の E0412 だけ（超えた要素を下ろさない）。前（`0eb4575`）はどれも数の E0302（名前の段）。宣言の位置のある要素の種類の誤り（`Wrap[3]`、`Ring[3]`）は E0308 で、E0412 より先に残る。
  読み: (1) 超えた要素には宣言の位置が無いので、種類も名前も判定せず、数の E0412 だけ。(2) 超えた要素も型として読む。`P[Nope]` は名前の段の E0302、`Ring[F32, 4, K]` は E0308 が E0412 より先に残る（`P[3]` は E0308 か E0412 か割れる）。
  どちらも誤りのあるプログラムの報告だけが変わる。再現は `target/notes/81/s762/x3_extra.onsa`。
- 決定: 決定（2026-10-29、利用者。81 回目。第 73 組の独立のレビューの答えと親の案が一致）: (1)。
  型の位置で、宣言の型パラメータの数を超えた型引数は読まない（種類も名前も判定しない）。数の E0412 だけを出す（`P[3]`、`Option[I32, 3]`、`F32[K]`、`Ring[F32, 4, K]`、`P[Nope]`）。型パラメータと `impl` の中の `Self` に書いた型引数（`T[Nope]`、`Self[Nope]`）も同じ。
  宣言の位置のある要素は今のとおり判定する（`Wrap[3]`・`Ring[3]` は名前の段の E0308 で、E0412 より先に残る）。
  理由: §4.5 の E0308 は「宣言の位置と合わなければ」で定め、位置の無い要素には定義が無い。読むと名前の段の E0302・E0308 が E0412 を隠し、直し方（引数を除く）から遠い診断が残る。S-759 (2') と組んで `impl P[Nope]` も E0412 だけになる。
  誤りのあるプログラムの報告だけが変わる。仕様は §4.5 の型引数の並びの項に一句。実装は W4-05 U4c（`a0f7d12`、`sig/types.rs::declared_params` と `lower_written`）。事例は `tests/spec/types/type_args_count.onsa`（`Ring[F32, 4, 5]`）と `impl_target_args_count.onsa`。
- 経緯: 81 回目（2026-10-29）、W4-05 U4c/i（onsa-impl）が仕様の空白として挙げ（`SPEC-GAP(NEW)`、仮の扱いは (1)）、親が作業中のバイナリと `P81/w405/u4c/i/onsa-base` で再現した。テストの票の `Ring[F32, 4, 5]` の E0412 は (1) と合う。利用者が外出中なので、(1) を暫定にして第 73 組の助言のレビューに加える。関係: S-103、S-759、R-258。
- 補い（2026-10-29、親）: 81 回目（W4-05 U4c の壊す側の指摘 5）: 型パラメータと `impl` の中の `Self` に書いた型引数（`T[Nope]`、`Self[Nope]`）も、数の E0412 だけで引数を下ろさない（`Nope` の E0302 は出ない）。読み (2) ならこの二つも変わる。
