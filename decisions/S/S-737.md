# S-737 同じ enum の列挙子と、その型の `impl` の関連定数が同じ名前のとき（`pub enum E { A(I32) }` と `impl E { pub const A: I32 = 1 }` の `E.A` が両方を指す）、E0304 か

- 空白: §4.4（95 行）は同じ enum の列挙子名の重複を、§6.2（83 行）は同じ型のメソッドと関連定数の名前の重なりを E0304 とするが、列挙子と、同じ型の `impl` の関連関数（や関連定数）が同じ名前のときを書いていない。
  関数の名前は snake_case、列挙子は UpperCamel なので、関連関数と列挙子は同じ名前にできない（`impl Sh { pub fn Circle(…) }` は E0320）。重なりうるのは関連定数で、`pub enum E { A(I32) }` と `impl E { pub const A: I32 = 1 }` は今通り、`E.A` は列挙子に解決されて関連定数に届く書き方が無い（W4-04 U9/b の報告の例を、文書の点検（78 回目）の確かめで改めた）。
  読み: (1) 型の名前の後の `.` の空間は一つとして E0304。(2) 重なってよく、列挙子が先（今の実装）。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。79 回目、第 70 組）: (1)・(p1)。
  型の名前の後の `.` で引く名前（メソッド、関連定数、enum の列挙子）は一つの空間で、重なると E0304。列挙子との重なりは書いた順によらず `impl` のメンバに付け、列挙子を note で示す（§15.1 の項目と `use` の付け方と同じ形）。使う所（`E.A`、`Self.A`、別名の `F.A`、`E.A =>`）は §18.1 のとおり誤りの名前として黙る。
  同じ型のメンバどうしの E0304 はソースの順で後の宣言に付け、前を note で示す（今の実装は関数を先に表に入れるので定数に付く。R-307）。
  改名の候補が値を黙って変える形（関連定数 `a` の候補 `A` が列挙子と重なる）は、S-652 の判定にそのまま乗って候補なしになる。
  仕様は §6.2 の 83 行に書き、§4.4 の 95 行から指した。`tasks/diag-codes.md` の E0304 の行に足した。
  実装は W4-05（重複実装とメンバの同名、S-725 の `assoc` の前段）: enum の型の `impl` のメンバの名前を列挙子の並びと比べて E0304（約 +10〜15 行）、メンバをソースの順に表へ（R-307）、`rename.rs::item_clashes` に持ち主の enum の列挙子を、`clashes` の `Target::Member` に `assoc` の表を足す（両方向、約 +5〜10 行）。
  事例: 列挙子と同名の関連定数（関連定数の行に `//~ E0304`、`impl` を先に書く形も）、改名の候補が出ない形（79 回目の scratchpad の `g70/probe/s737/rename_const_before.onsa` の形）、`issues/R/R-307/const_then_fn.onsa` の形（後ろの関数に E0304）。
- 経緯: 78 回目（2026-10-28）、W4-04 U9/b（onsa-break）の範囲の外の指摘 5。期限は無い。関係: S-652（E0320 の重なりの判定の `assoc`）。
