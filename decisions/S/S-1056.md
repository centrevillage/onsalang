# S-1056 E0610 の照合（§15.3、§8.5）で `main` とはどの関数か（ルートのモジュールの最上位の `main`、`pub fn main` だけ、どのモジュールの `main` も、`kind = "exe"` のビルドだけ）

- 空白: §15.3 は「`main` または export される関数の効果行に、`provides` に無い効果が含まれていれば E0610」、§8.5 は `main` の効果行の各効果を書く。どの `main` か（ルートのモジュールか、`pub` か、メソッドを除くか、`kind = "exe"` のときだけか）を書かない。今は `check` で照合せず、ビルドの `check_exports`（`crates/onsa_driver/src/build.rs`）は export だけを見る（R-134）。
  再現: `target/notes/150/w603/memo/probe/p4.txt` の `main_alloc`（`provides = []`、`pub fn main() uses {Alloc}`。今は x0）。実装待ちの `tests/spec/negative/build_provides_main.onsa` は `kind = "source"` のターゲットに E0610 を期待する。
  読み: (1) ルートのモジュールの最上位の関数 `main`（可視性によらない） (2) `pub fn main` だけ (3) どのモジュールの `main` も (4) `kind = "exe"` のビルドだけ（実装待ちの事例の期待とぶつかる）。
  急ぎ: W6-03 の R-134 の単位の前。
- 決定: 決定（2026-11-14、利用者。150 回目。段 1 の選択と親の読みが一致し、段 2 は省いた）: (4) の向き。利用者の基準は「実務上困らない範囲で扱いが統一されていればよい」で、親がこの案を示し、利用者が了承した。ターゲットのエントリは、`kind = "exe"` ではビルドするパッケージのルートのモジュールで定義した最上位の関数 `main`、ほかの種類では `@export` の flow と関数で、E0610 はエントリの関数の効果行を照らす。`exe` でないターゲットでは `main` をほかの関数と同じに扱い、照らさない。
  理由: `exe` でないターゲットの成果物に `main` は入らない（`source` の C に `main` は出ない、§16.1 の「プラグインと `staticlib` では `main` が無い」）。(1)〜(3) は、一つのパッケージにヒープのある `exe` とヒープの無い `staticlib` を並べる §15.3 の例の形を、条件コンパイルが無いので塞ぐ。§9 の境界と §12.5 のエントリと同じ「エントリ」の一つの規則になり、例外が無い。
  帰結: この版は `kind = "exe"` が E0200 なので、第 1 期は `main` の照合が働かない。R-134 は `exe` を開く作業（第 2 期）へ送った。実装待ちの `tests/spec/negative/build_provides_main.onsa` は、W6-03 で「`source` では `main` が `Alloc` を持っても通る」正例に書き直す。`pub` を求めるか、総称・`rt`・引数と返り値のある `main`、`@export` を付けた `main` の E0610 の重なりは、`exe` を開く作業の細部（`tasks/phase2.md`）。仕様は §15.3 の E0610 の項、§8.5、§12.3。§15.3 の例の `staticlib` の `main_frame = "static"` を外した（§16.1 と合わない、段 1 が見つけた）。
