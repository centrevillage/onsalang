# S-58

- 空白: fmt の並び（`list()`）がコメントを扱わず、囲みの後ろにまとめて出す。フィールド・列挙子・flow の入力の `///`、引数・腕・要素・フィールドの行末のコメント、空の本体のコメントが、別の場所や別の宣言へ移る（レビュー R-70）
- 提案: 解析の後に、各コメントを最も近い要素へ結び付ける表（前に付く・後ろに付く・空の囲みの中）を一度作り、印字はその表から行う。出し残しは内部エラー（S-56）。R-86 のこの部分を前倒しし、R-63（フィールドなどの doc を AST に持たせる）と同じ回に行う。
  R-113 の fmt の性質テストに、各コメントが同じ要素の行に残ることを加える。`tests/review-phase1/parent/r70/` の 17 の形は、どれも fmt で変わらないことが期待値（2026-10-04 決定。実装は第 2 段。2026-10-05 の R-86 で、結び付けは CST の上で作ることにした。CST が先か同じ回）。
  補い（2026-10-14、W3-11 の U4。出力は同じで内部だけの違いなので親が決めた、`rules/leader.md` 5.10）: 表は作らない。U3 の印字器はトークンとコメントを順に全て出して隙間だけを決めるので、出し残しも重なりも構造上起きない。コメントが消えないことの確かめは W3-11 の U5 の書き込む前の比べが受け持つ
