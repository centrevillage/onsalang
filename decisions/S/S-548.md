# S-548

- 空白: 式の中の空の型引数 `f::[]` と型の位置の `Buf[]`（S-239 の E0002）の修正候補。S-513 は宣言と使う側の空の括弧に括弧ごと除く候補を付け、理由に S-239 と同じ規則にそろえることを挙げたが、S-239 の二つの形の候補は決めていない（今は候補なし。`Buf[]` を除くと `Buf` で、総称なら型引数の数の誤りが残る。`f::[]` は `::` も除く形になる）。W3-13/t（U2）が見つけた（2026-10-15）
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: 既存 §2.5）式の中の空の型引数 `f::[]` と型の位置の `Buf[]`（E0002）に、空の括弧と同じく空の並びを除く候補を付ける（`f::[](1)` は `f(1)`、`Buf::[].zeroed(4)` は `Buf.zeroed(4)`、`P[]` は `P`）。中にコメントがあれば候補なし。総称なら当てた後に E0412 か推論の誤りが後の段に残りうる。
  - 仕様の節: §2.5（空の括弧の項）。
  - 今通るプログラム: 変わらない。
  - 実装の見当: 型引数の並びの構文の「expected a type argument, found `]`」に、`empty_brackets` と同じ候補を足す（10〜20 行）。
  - ぶつかる事例: `tests/spec/negative/syntax_type_args.onsa`（`//~ E0002`）は候補が付くので、器が候補のある診断に `.fixK` を求めるなら足す。`tests/cst/err_type_args.onsa` は CST だけ。
