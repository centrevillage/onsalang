# S-964 Rust の `assert!(c)` が `assert !(c)`（否定の条件）と読まれて通り、意味が逆になる（`assert!(x > 0)` の偽の友人）

- 空白: §7 の `assert e` は文で、`e` は `Bool`。Rust の `assert!(x > 0)` は字句で `assert`・`!`・`(x > 0)` と読め、`assert !(x > 0)`（条件の否定）として検査を通る。今は（dev `5d5cd987`）`fn f(x: I32) { assert!(x > 0) }` が check を通り、`f(-1)` のテストが ok になる（意味が逆。§0.3 の 4 の偽の友人）。文面付きの `assert!(x > 0, "m")` は E0401、Python の `assert x > 0, "m"` は一般の E0002（S-879）。`spec/foreign-forms.toml` に `assert` の行は無い。再現は `target/notes/128/r58/advisor/probe/assert_bang_a.onsa`・`assert_bang_b.onsa`。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1、B7、Y）`assert` の直後に空白なしで `!(` が続く形（`assert!(c)`）は構文の段の E0020 の行 `assert_bang` で、候補は (1) `!` を除く `assert(c)` (2) 空白を置いた `assert !(c)` の二つ。形の範囲は `assert` から `!(` に対応する `)` までで、後ろのトークンは候補に残す（`assert!(a) && b` は `assert(a) && b` と `assert !(a) && b`、Y）。文面付きは `assert_message` の一つの形（候補 `assert c` だけ）。空白のある `assert !(c)`、`assert!c`、`if!c` は今のまま。
  - 仕様の節: §7 の `assert` の項（親が置く文）、一覧の行。
  - 今通るプログラム: **変わる。** `fn f(x: I32) { assert!(x > 0) }` と `test "t" { assert!(1 < 2) }` が今は通り（否定の条件）、E0020 になる（B7 で了承済み）。
  - 実装の見当: S-879 と同じ所。
  - ぶつかる事例: なし（`assert!(` は Rust のテストのコードにだけあり、`.onsa` の事例に無い）。
- 経緯: 128 回目（2026-11-09）、期限が W5-11 の未決の S 58 件に共通の規則を敷けるかの独立の検討（onsa-advisor の段 1）が想定漏れとして見つけ、親が固定のバイナリで再現した。S-879（文面付きの形）と一つの形で決めうる。
