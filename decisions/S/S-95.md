# S-95

- 空白: C の API の名前空間と ABI の版が仕様に無い。既定の prefix `onsa_` で、別々にビルドしたパッケージの名前が重なり（静的リンクが黙って片方を使う）、利用者の名前がランタイムの公開の名前と重なる（cc の誤りになり、E1011 は出ない）。空の prefix とパッケージ名 `onsa` で、ヘッダがランタイムの `onsa.h` を上書きする（レビュー R-121）
- 提案: `[export]` の `prefix` の既定（今は `onsa_`）を取り除いて必須にし、形（小文字の英字・数字・`_`、英字で始まり `_` で終わる、`__` を含まない、`onsa_` で始まらない）をマニフェストを読むときに検査する（マニフェストの誤りの出し方は R-130 で決める）。
  生成するファイルの名前を `<prefix><package>.h` / `.c` と `lib<prefix><package>.a` にする（今は `onsa_<package>.c`、`libonsa_<package>.a`）。`onsa.h` に `ONSA_ABI_VERSION` を置き、パッケージのヘッダが取り込んだ直後に確かめる。`onsa.h` の中身を設定に依らなくするのは S-53 の分割と同じ回に行う（今の flow のヘッダは `onsa.h` の前に `ONSA_PANIC_POISON` を定義している）。`examples/voice_host`、golden の C、テストの事例のマニフェストに prefix を書く。`tests/review-phase1/parent/r121/` の期待値と今の出力は `host.c` と各 `onsa.toml` の先頭のコメント（2026-10-05 決定。実装は第 3 段）
- 時期: M4
