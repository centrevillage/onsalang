# S-707 本体の経路で flow の名前空間に無い名前（`g.nosuch(…)`、型で無いと決まった `one.process_inplace(…)`）を呼ぶ・読むときの診断のコード（E0302 か、今の E0401 か）

- 空白: §15.1 は「名前が見つからなければ E0302」とし、§11.6 は「中の項目の名前は上の一覧に固定され」とするが、本体の経路が flow の名前空間に無い名前を引く形の規則は書かれていない。
  今の実装は E0401（「`one` is a flow; outside a flow body use its namespace」）を出す。`pub type Count = I32` と `pub flow one(x: F32 at sample) -> Count at sample { x.trunc_i32() }` の後の test の `one.process_inplace(inout st, one.Params {}, inout xs)`（型で無いと決まった生成項目）、`two.nosuch(inout st)`、`let f = one.process_inplace` のどれも E0401。
  読みは (1) 一般の規則どおり E0302 か、(2) 今の E0401 かで割れる。
- 決定: 決定（2026-10-26、利用者が ID を挙げて了承。74 回目、確認だけ）: (1) E0302。型で無いと決まった生成項目を本体の経路で引く形（`one.process_inplace(…)`、`let f = one.process_inplace`）も、flow の名前空間に無い名前で、§15.1 の「名前が見つからなければ E0302」のとおり。R-147（2026-10-08）の判断と同じで、仕様は変えない。
  期待値は `tests/spec/negative/flow_inplace_absent.onsa`（実装待ち）。実装は R-147 の直し（W4-04）。
- 経緯: 71 回目（2026-10-26）、W4-03 U5a/t（onsa-test）が見つけ、親が dev で再現した（`one.process_inplace` の形が E0401）。U5a の事例には入れていない。本体の名前は W4-04 の範囲。関係: S-694。
  74 回目（2026-10-26）、親が dev `65a1073` で再現し（`one.process_inplace(…)`・`let f = one.process_inplace`・`two.nosuch(…)` はどれも E0401）、R-147 が `process_inplace` を生成しない flow の形を含めて既に決めているので、確認だけとして出した。
- 補い（2026-10-26、親）: 72 回目の文書の点検の指摘: 例の `two.nosuch(inout st)` は §15.1 の「名前が見つからなければ E0302」で既に決まっていて、今の E0401 は実装の誤りの疑いが濃い（R-254 のモジュールの形と同じ類、W4-04）。本当の空白は、型で無いと決まった生成項目（`one.process_inplace(…)`、`let f = one.process_inplace`）を本体の経路で引く形に絞れる。
