# S-682 `use` の頭の自分のパッケージ名の候補（S-663）を、足す辺が循環を閉じるので出さないときの note（`cyc3` で一つを当てた後の `use fx.a.{f}`）

- 決定済みで戻さないもの: §18.1 の候補の約束（当てた後に同じ段かそれより前の段の誤りを残さない。E0310 は名前の段）。S-663 の `use` の頭の自分のパッケージ名の候補（`fx.` を外す。`use fx` は候補なしで note）。S-673 の本体の経路の候補と「候補を出さないときの note は正しい形を示す」。
  S-678（失敗した `use` は辺を張らない、67 回目に決定）。
- 論点: §18.1 は、当てた後に同じ段の誤りが残る候補を出さない。S-663 の頭の候補（`fx.` を外す）は、足す辺が循環を閉じるときは出ない。S-673 は本体の経路の候補について「候補を出さないときの note は正しい形を示す」としたが、`use` の頭の E0302 の同じ場面は書いていない。
- 今の実装: `cyc3` で一つを当てた後の `b.onsa` の E0302「cannot find `fx`」は、候補も note も無い（`c335496`、`P67/g59/work/cyc3_c335496_first`）。`g_cyc3_one` も同じ。書き手は、外せば循環になることを知らずに `fx.` を外し、次の検査で E0310 を見る。
- 案: (a) note で、外した形（`use a.{f}`）と、それが循環を閉じること（相手のモジュール）を示す。(b) 今のまま（候補も note も無い）。
- 他言語: 該当なし。
- 推奨と理由: (a)。確度: 中。候補を出さない理由が循環だけなので、書き手の意図（外した形）は一つに決まり、次に出る誤りを先に示せる。実装は `use_head_fix` の循環の枝に note の一文（約 +5〜10 行）。
  - S-678 で (3) を採ると、この形は E0310 が先に出るので要らなくなる。
- 影響: 仕様は §15.1 の S-663 の文に「循環を閉じるときは候補を出さず、note で外した形と循環を示す」を足す。作業は W4-03 の U3a2。事例は `use_cycles.rs` の cyc3 の事例に note の有無を足す。今の実装と違う案は (a)。
- 独立のレビュー: onsa-advisor の二段（67 回目）。段 1 は (a)（中〜高）を選び、下書きと一致した。同じ形の `use` の片方だけ候補が理由なく消えると、書き手（LLM）が別の形と誤読する。S-663 の `use fx`、S-673、S-679 と同じく、候補を出さないときは note で形と理由を示す（criteria 7.4）。
  循環のときは正しい形が無いので、note は外した形と、それが閉じる循環の相手を示す。段 2 は、S の補い（本体の経路 `main.inner.g()` の rule が循環を閉じる `use main.inner` を勧める）も同じ読みで決まるとした。S-678 が (1) なので、この場面は残り note が要る。
- 回答: （2026-10-25、会話、67 回目）(a) と本体の経路の同じ場面を確認だけで了承（A10）。
