# S-514 式の `None()` と単位形の `E.A()` のコードと候補

- 族の規則と決定済みのもの: S-607 の族の表と「決定済みで戻さないもの」（`S-607.draft.md`）。S-607 の規則で宣言と prelude のコードはそろえる。
- 論点: §4.4「単位形の列挙子は値で、括弧を付けずに書く」。式の中で単位形の列挙子を呼んだ形（表の 14・15 行）のコードを書かない。§4.5 は数の誤りを E0412（関数の引数の数と同じコード）とし、パターンの空の括弧は構文の段の E0002（S-513）とした。
  式の `E.A()` は、構文の段では関連関数の呼び出し `E.f()` と見分けられないので、S-513 のパターンと同じ段にはできない。名前の解決で単位形の列挙子と分かる。
  S-607 の規則で宣言と prelude のコードはそろえるので、残るのはどのコードと段にするかと、候補である。
- 今の実装: `None()`・`None(1)` は E0401「`None` is not a function」、`E.A()`・`E.A(1)` は E0412「`A` is a unit variant and takes no arguments」で、どちらも型の段、候補なし（x07〜x10）。
  `None` は組込みの名前の分岐（`calls.rs` の 116・176 行の E0401）を通り、`E.A` は列挙子の分岐（218 行の E0412）を通る。W5-03 で `None` を std の enum の列挙子にすると、`None()` も列挙子の分岐を通り、そのままでは E0412 になる。
  `tests/spec` に式の `None()`・`E.A()` の事例は無い。

- 案:
  - (a) どちらも E0412 で、型の段（今の `E.A()` と同じ）。候補は、括弧の中が空でコメントが無ければ空の括弧を除く形（`None()` は `None`）。引数のある形（`E.A(1)`）は候補なしで、note で単位形の列挙子は値で括弧を付けないことを示す。
    当て続けると: 空の括弧を除いた形は値の列挙子で、一回で収束する。期待型と合わなければ同じ型の段の E0401 が出るが、それは呼び出しと別の誤り（どの直し方でも残る）である。引数のある形は意図（`Some(1)` か別の列挙子か）が一つに決まらないので止まる。
    実装: 候補と note（5〜10 行）。`None()` の E0401 を E0412 に替える分岐（1〜3 行。W5-03 の後は分岐ごと無くなる）。事例: E0412 の否定例と候補の事例 3 件以上。
    費用の要因: W5-03 までは、組込みの `None` の分岐に E0412 を出す一時の枝が残る（親が見出しを足した）。
  - (b) どちらも E0412 で、名前の段（名前の解決で単位形と分かる最初の段）。候補は (a) と同じ。
    実装: W4-12 の名前の段の呼び出しの形の判定に枝（10〜20 行）と、型の段の列挙子の分岐の削除。登録簿の E0412 に名前の段を足す。費用の要因: E0412 が、単位形の呼び出しは名前の段、要素を持つ形の数（18・19 行）は型の段に分かれる。
  - (c) どちらも E0401（値は関数でない）で、型の段。候補は (a) と同じ。
    実装: `E.A()` の E0412 を E0401 に替え、候補と note（5〜10 行）。W5-03 の後に列挙子の分岐で E0401 を出す。費用の要因: パターンの `E.A(x) =>`（17 行の E0412）と式の `E.A(x)` のコードが分かれる。
  - (d) コードだけそろえ（E0412）、候補は出さない（今の `E.A()` のまま）。実装: 1〜3 行。費用の要因: 空の括弧は直し方が一つに決まるのに、書き手が手で直す。
- 他言語:
  - rustc 1.94.1（手元、`r2.rs`・`r3.rs`）: `None()` と `E::A()` はどちらも E0618「expected function, found enum variant」で、help「is a unit enum variant, and does not take parentheses to be constructed」。
  - Swift 6.3.1（手元、`s2.swift`）: `E.a()` は「enum case 'a' has no associated values」。`Optional.none()` はコンパイラが「failed to produce diagnostic for expression」の誤りを出す。
  - OCaml・Haskell: 未確認。
- 推奨と理由: (a)。確度: 中〜高。
  - 直し方は引数の並びを除くことで、要素を持つ形の数の誤り（18・19 行）とパターンの `E.A(x) =>`（17 行）と同じ「引数・要素の数」の誤りである。E0412 にすると、式とパターンと要素を持つ形が一つのコードの下で一つの直し方（数を合わせる）を示す。
  - 段を今の型の段のまま変えないので、実装は候補と note だけである。W5-03 で prelude の列挙子を std の enum にすると、`None()` は宣言した列挙子と同じ分岐を通り、そろえるための分岐も無くなる。
    (b) の名前の段に移すと、単位形の呼び出しと数の誤りで E0412 の段が分かれ、W4-12 に枝が増える。段は仕様の診断の約束を変えない細部なので、実装を増やさない方を選ぶ。
  - 空の括弧を除く候補は一回で収束し、括弧の中のコメントがあれば出さない（S-513 のパターンと同じ）。引数のある形は意図が一つに決まらないので出さない。
  - 後で緩められるか: コードと候補の選び方で、通るプログラムは変わらない。第 2 期と JS / WASM には関わらない。
  - あわせて決めること: W4-12 の名前の段は、単位形の列挙子の呼び出しを `f(x)` の形の誤り（E0020）にしない（S-607 のあわせて決めること）。
  - 別の S にしてよい論点: 無い。
