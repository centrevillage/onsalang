# S-875 `as` で書ける組の `narrow_*`（`Option[T]` を返す）の E0413 の修正候補の形（`x as T` か `Some(x as T)` か、期待の型で選ぶか）

- 空白: §3.3 の 82 行は「`as` で書ける組の変換メソッド（`F32` の `round_f64()`、`I32` の `narrow_i64()`、同じ型への `round_f32()` と `narrow_i32()` など）は無い（E0413。修正候補は `as` の形）」とする。
  `round_*` は返り値の型が `as` と同じ（`F64`）なので候補は `x as F64` に決まる。`narrow_*` は §3.3 の表で `Option[T]` を返すので、`as` の形の候補が一つに決まらない。
  読み: (1) `x as T`（型が `Option[T]` から `T` に変わる。期待の型が `Option[T]` の位置では、当てた後に E0401 が残り、§18.1 の候補の約束（S-236）に当たる）。(2) `Some(x as T)`（元の型と値を保つ。`as` で書ける組の `narrow_*` は常に `Some` を返すので意味が同じ）。
  (3) 期待の型が `T` なら (1)、`Option[T]` なら (2)、決まらなければ候補なし。(4) `narrow_*` には候補を出さず note で `as` を示す。
  今（`dd4e4e97`）はどの形も候補の無い E0413（再現は `decisions/S/S-875/narrow.onsa`。`x as I64` と `Some(x as I64)` は通る）。
  事例: `tests/spec/negative/scalar_method_as_pairs.onsa` の `narrow_*` の 25 件は全て `Option[T]` を返す関数の中で、候補が付くと器が自動で確かめる。`tests/spec/fixes/e0413_forms.onsa` の `widen_int(n: I32) -> I64 { n.narrow_i64() }` と写し `.fix1` は (1) を期待している（W5-14 を待つ事例）。
  急ぎ: W5-14 の E0413 の候補の単位のテストの票の前
