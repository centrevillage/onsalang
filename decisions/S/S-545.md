# S-545

- 空白: 値の無い末尾の `return` を外すと、直前の式の文がブロックの値になり、プログラムの意味が変わる形。`fn g() -> I32` のとき `fn f() {` 改行 `g()` 改行 `return` 改行 `}` は `check` を通るが、`return` を外すと `g()` が本体の値になり E0401（親が W3-12 の U1a の実装で再現した、`P27/probe/u1a/disc.onsa`）。
  逆に `fn f() -> I32 {` 改行 `1` 改行 `return` 改行 `}` は E0401 から通るプログラムに変わる（U1a/i が見つけた）。仕様 §6.1 は「値の無い `return` も含む」とし、§18.2 は fmt がプログラムの意味を変えないとする。構文の段では式の型が分からない。2026-10-15
- 提案: 決定（2026-10-15、利用者が親の確認だけの案を了承）: §18.2 の約束を優先する。値の無い末尾の `return` は、直前の文が式の文なら残す（連なりは先頭だけ残す）。構文で値が `()` と決まる式（`else` の無い `if`、`while`・`for`、代入）と、式でない文の後は外す。
  迷う形（呼び出し、`else` のある `if`、`match`、括弧で包んだ式）は残す。`spec/tools.md` §3.3。実装は W3-12 の U1a。改め（2026-10-15、S-547）: 値の無い末尾の `return` は外さないことにしたので、この規則は要らなくなった
- 時期: W3
