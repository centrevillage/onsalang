# S-364

- 空白: `onsa interface` の署名の文字列（テキストと JSON の `signature`）で、外側の `uses` が続く関数型の返り値を括弧で囲むか（`pub fn a() -> (fn()) uses {Alloc}` と `pub fn b() -> fn() uses {Alloc}` は型が違う）。§18.2 は署名の文字列の形を書かない。
  R-43 で `(T)` が書けるようになり、W3-20 の前は二つが同じ文字列になっていた。W3-20/b で見つけ、W3-20 は括弧で区別する（`TyStore::parens_before_uses`、型を文字列にする一か所で診断の文面も同じ）。W3-20/b で見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が了承。親の案）: 署名の型は、読み直して同じ型になる形で書く（外側に `uses` が続く関数型の返り値は括弧で囲む）。修復のループが署名を写して使うので約束に頼る使い手がいる。§18.2 の interface の文に一文を足す。仕様 §18.2。
  実装は W3-20（`TyStore::parens_before_uses`、`crates/onsa_cli/tests/interface_fn_return.rs`）。W3-12 の fmt はこの括弧を外さない
- 時期: W3
