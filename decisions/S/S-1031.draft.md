# S-1031 族: 関数型の向きのある互換（効果行の包含、`rt` の向き）が当たる範囲。期待する型が一つに決まらない所（`if`・`match`・配列の合流、型変数の推論 `pick(r, k)`）と型引数の中（`Option[F]` を `Option[G]` の位置へ）

- 決定済みで戻さないもの: §8.1 の位置の一番外の向き（R-27 (2)、R-26）、関数型の中の関数型は完全に一致（§8.1 の規則 1）、期待する型の無い `if` の合流の一番外の `rt` を落とすこと（第 80 組。`match`・配列も同じ「合流」の字に入る読み）、モードは型の一部（S-874、S-190）、効果行変数は第 1 期 E0200（R-27 (3)）、前の枝の型を期待型として渡すこと（S-880、§4.7）。

- 論点: §8.1 の関数型の互換は「関数 F を、関数型 G を期待する位置（引数、注釈付きの `let`、返り値、struct のフィールド）で使える」条件を規則 1〜3 で定める。
  期待する型が書き手の注釈から来ず、前の枝・前の引数・最初の `return`・初期化から決まる所（§4.7 の「前の枝の型」、型変数の推論、無名関数の返り値、`var` の代入）と、型引数の中の関数型（`Option[F]` を `Option[G]` の位置へ）を書かない。
  §4.7 を字のとおりに当てると、後の枝・引数は前に決まった型を期待型として §8.1 で比べられ、順で合否が変わる。
  - 残る論点: 期待する型の無い合流の一番外の効果行、入れ子の合流、型変数の推論、無名関数の返り値、型引数の中の向き（下の案 (a)〜(f)）。
  - あわせて決める点（どの案でも要る）:
    (i) `inout` の引数と `inout self` の受け手。`inout` は場所を渡し、呼ばれる側が書き戻す。(i-1) 向きを持たず型が等しいことを求める。(i-2) 他の引数と同じ向きで比べる。
    (i-2) では、`rt fn` の型の変数を `fn` の `inout` に渡すと `rt` でない関数が書き込まれる（`inout_rt_hole` は `rt` を見ない今も通る）。効果行でも、純粋な型の変数を `uses {Alloc}` の `inout` に渡す形（`inout_alloc_pos`、今は E0401）が通り、変数が `uses {Alloc}` の関数を持つ。期限は U2b でなく U2a の前である。
    (ii) 期待する型の無い合流で後の腕に渡す期待型。(ii-1) 前の腕の型をそのまま渡す（今の実装）。(ii-2) 前の腕の型から一番外の `rt` を外した型を渡す（効果行は残す）。

- 今の実装: 形の表のとおり。効果行は全ての位置で等しさ（違えば E0401。§8.1 の位置の包含は W6-01 の U2a で入る）、`rt` は全ての位置で見ない。
  そのため、`rt` の違いは今は順によらず通り、効果行の違いは順によらず E0401 である（`cases.txt` の 93 件で、順を入れ替えた組は全て同じ結果）。`if c { r } else { k }` を `rt fn` の中で呼ぶ形は通り（`use_rt_call_rt_pure`）、逆順は E0901（`use_rt_call_pure_rt`）。

  - (f) (b) に、型パラメータを通した期待型は等しさで比べる規則を足す（期待する型が型変数なら向きを持たない）。`pick`・`Some`・無名関数の返り値はどちらの順も E0401 で、順で割れる形は (b) より減る。注釈で直す道（`let f: G = pick(r, k)`）も E0401 になる。

- 他言語:
  - swiftc 6.3.3（`other/s_merge.swift`・`s_ff2.swift`・`s_ok.swift`・`s_ff.swift`・`s_inout.swift`）: `throws` の有無は関数型の部分型である。三項演算子・`if` 式・配列のリテラル・総称の推論 `pick(k, t)` と `pick(t, k)` は、どちらの順も `(Int) throws -> Int` に合わせる。
    `c ? Optional.some(k) : Optional.some(t)`、`c ? [k] : [t]`、`c ? (k, 1) : (t, 2)` も中まで合わせる。注釈の位置で `Optional`・`Array`・タプルの中は共変、関数型の引数の型は反変（`((Int) -> Int) -> Int` を `((Int) throws -> Int) -> Int` へは誤り）、返り値の型は共変。
    `var v = k` の後の `v = t` は誤りで（変数の型は初期化で決まる）、`inout` は「inout argument could be set to a value with a type other than '(Int) -> Int'」と誤りにする（不変）。
  - rustc 1.94.1（`other/r.rs`）: `fn` の項目と `unsafe fn` の項目を `if` の腕と配列に並べると、どちらの順も `unsafe fn` のポインタに合わせる。`pick(k as fn, u as unsafe fn)` は E0308、逆順は通る（先の引数で `T` が決まる）。
    `Option<fn>` の値を `Option<unsafe fn>` へは E0308、`let m7: Option<unsafe fn(u32) -> u32> = Some(k)` は通る（その場で作る値）。`if c { Some(k as fn) } else { Some(u as unsafe fn) }` は E0308「`if` and `else` have incompatible types」。
  - Apple clang 21（`other/c.cpp`、`-std=c++20`）: 条件演算子 `c ? &n : &k`（`n` は `noexcept`）はどちらの順も `int(*)(int)`（合成ポインタ型、[expr.cond]）。テンプレートの `pick(&n, &k)` はどちらの順も「no matching function」（推論の食い違い）。
    `std::optional<int(*)(int) noexcept>` から `std::optional<int(*)(int)>` へは、ライブラリの変換の構築子で通り、逆は誤り。`noexcept` でない関数ポインタを `noexcept` のポインタへは誤り。
