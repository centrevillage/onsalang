# S-905 `default()` の `rt` と効果行

- 決定済みで戻さないもの:
  第 88 組の下書きの写しは `target/notes/117/g88/draft.md`、入力は `P117/g88/probe/`（消えうる）、段 1・段 2 の答えは `target/notes/117/g88/advisor/`、親の入力は `target/notes/117/g88/parent/`。
- 論点: §6.3・§6.4 は `default` の `rt` と効果行を書いていない。`rt fn f() -> P { P.default() }`、`rt fn g[T: Default]() -> T { T.default() }` が通るか（E0901）、手書きの `fn default` に `rt` や `uses {Alloc}` を書けるか、derive が作る `default` が `rt` か、が決まらない。
  §6.3 の `Drop` は `rt` と `uses {Alloc}` を明示するが、`Default` には文が無い。W5-06 の U2・U3 と S-697 の (e) がこれに頼る。
- 今の実装: `K.default()` は E0302、`T.default()` は E0302（`e04`）で、`rt` の判定まで進まない。
- 案:
  - (a) `default` は `rt` で効果行が空: trait の宣言を `rt fn default() -> Self` と読む。手書きも `rt fn default` と書く（無ければ E0901 の見方）。derive は `rt`。`Str` の既定値（空）は静的なオブジェクトで確保しない見込みである。
  - (b) `rt` でない: `rt fn` の中で `T.default()` は E0901。derive も同じ。
  - (c) derive は `rt`、手書きは書き手が選ぶ: `T.default()` は `rt` でない読み。総称と具体的な型で判定が割れる。
  - 書き手から見て: (a) は手書きの `rt` の書き忘れで 1 回の修復（語を足す候補で止まる）。(b) は `rt` の中で既定値を作る書き手が定数へ移す 1 回。(c) は読みが二通りになる。通るプログラムは変わらない（今は全て E0302）。
  - 規則と例外: (a) は trait の宣言の一語で、手書きに確保を許さない制限である（後で緩められる）。別の所に同じ形がある: `Drop` は `rt` が要件である。(b) は足さない。実行の結果: どの案も値は変わらない。`prev~` の既定値を読む位置と `rt` の関係は確かめていない。
  - 実装の量（見当）: (a) +5〜10（U2・U4）、(b) 0〜3、(c) +10〜15。後の段の手当ては要らない。
- 他言語: 対応する形は未確認。Rust の `const` の trait は別の機能である。
- 推奨と理由: (a)。確度: 低。
  - DSP の `rt` の処理で既定値を作る形は自然で、derive の既定値は確保しない。手書きを `rt` に縛る方が厳しく、後で緩めても今のプログラムは壊れない。ただし実例が無く、手書きの `default` が確保を要する用途（`Array` を持つ型）を塞ぐので、確度は低い。
- 影響: 仕様は §6.3。診断は E0901。作業: W5-06 の U2・U4。
- 独立のレビュー: 段 1 は (a) で下書きと一致し、確度は高である（下書きは低）。§11.5 の `match~` の取られない腕、`when~` の保持、イベントの最初の値が sample の刻みで `T.default()` を使う。
  段 2: 手書きも `rt fn default() -> Self` と書く（`rt` は関数型の一部、§10。§6.3 の `Drop` と揃う。可視性は関数型の一部でないので継ぐ）。§6.4 の例を `rt fn` に改める。derive の `Default` の型は他のモジュールからも `P.default()` を呼べることを §6.4 に一句書く。
