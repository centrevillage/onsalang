# S-775 見出しの誤りが型の段（E0412、E0416）の `impl` で、メンバの本体や関連定数の型に名前の段の誤りがある形（`impl[T] Q[T, T] { fn n(self) -> I32 { zz } }`）: S-763 の署名と同じく段の順で名前の誤りが先に残るか、と §18.1 の「メンバは検査しない」の書き方

- 空白: §18.1 の 61 行は、`impl` の見出しに誤りがあれば `impl` 全体を一つの単位とし、メンバは検査しないとする。63 行（S-763）は、見出しの誤りが型の段（E0412、E0416）のときは、段の順でメンバの署名の名前の段の誤り（E0302 など）が先に残るとする。
  83 回目の文書の点検（onsa-docs）が、この二つの文は読み手に矛盾と読まれうると報告した（名前の段がメンバの署名の名前を読むことが書いていない）。親が再現したところ、名前の段の誤りが先に残るのは署名だけでない。
  メンバの本体の名前（`impl[T] Q[T, T] { fn n(self) -> I32 { zz } }` の `zz`）と関連定数の型（`const K: Gone = 1`）の E0302 も、見出しの E0412 より先に残り、見出しの誤りは出ない。見出しが E0416 の形（`struct P[T: Num]` の後の `impl[T] P[T]`）も同じ。
  再現は `target/notes/83/s775/`（`h3`・`h5`・`h6`・`h7`）。
  S-763 の決定は署名だけを言い、本体と関連定数の型は書いていない。どちらも誤りのあるプログラムの報告だけが変わる（通るプログラムは変わらない）。
  読み: (1) 入る（今の実装。名前の段は単位の全て（メンバの署名と本体）の名前を読むので、段の順で名前の段の誤りが残る。S-763 と同じ理由）。(2) 入らない（本体の名前の誤りは捨て、見出しの E0412・E0416 を出す。名前の段の時点で分からない型の段の見出しの誤りを待つ仕組みが要る）。
  仕様の文: (1) なら 61 行の「メンバは検査しない」と 63 行を、「名前の段はメンバ（署名と本体）の名前も読む。見出しの誤りが型の段のときは、段の順でメンバの名前の段の誤りが先に残り、見出しの誤りは報告しない（`impl` 全体で一つの単位なので、誤りは一つ）」の形に改める。
- 決定:
- 経緯: 83 回目（2026-10-29）、`d70ae82..e993b29` の文書の点検（onsa-docs）が §18.1 の 61 行と 63 行の読みの割れを報告し、親が再現で本体と関連定数の型の形を見つけた。親の読みは (1)（S-763 と同じ理由で一つに決まる）で、確認だけにする。関係: S-763、S-764、S-756、S-103。
