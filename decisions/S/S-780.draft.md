- 他言語: 
  - rustc 1.94.1（`probe/other/r1.rs`〜`r3.rs`）: `const NONE: Option<Vec<f32>> = None` の後の `let o = NONE; take(o)` と `take(NONE)` 二回は通る。`static SNONE` からの `let o = SNONE` と `take(SNONE)` は E0507「cannot move out of static item `SNONE`」。
    Reference の Constant items は「Constants are essentially inlined wherever they are used, meaning that they are copied directly into the relevant context when used. This includes … non-`Copy` types」とする（https://doc.rust-lang.org/reference/items/constant-items.html）。`const` の名前は使うたびに新しい所有の値で、(c) の「その場に初期化式を書いたのと同じ」に近い（E0704 は無い）。`static` は (a) に近い。
  - Apple clang 21（`-std=c++23`、`probe/other/c1.cpp`・`c2.cpp`）: `constexpr std::optional<std::unique_ptr<int>> K = std::nullopt` は書け、`take(std::move(K))` は「call to implicitly-deleted copy constructor」。`const` のローカルも同じで、`const` でないローカルは `std::move` で渡せる。
  - swiftc 6.3.1（`probe/other/s1.swift`・`s2.swift`）: `~Copyable` の型の `Optional` を、ローカルの `let o: NC? = nil` から `consuming` の引数へ渡すのは通る。大域の `let g: NC? = nil` を渡すと「cannot consume noncopyable stored property 'g' that is global」。
  - 比べ: 三つとも、ローカルにリテラルを束縛した名前は所有で、移動できない（(a) に近い）のは名前の付いた定数・大域の値である。Onsa の静的な値の借用の行は、ローカルの `let` のリテラルにも当たる点がどの言語とも違う。
    C 系・TypeScript・Python・Java・C# は移動だけの型を持たないか、この形を確かめておらず未確認。
