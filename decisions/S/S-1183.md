# S-1183 細部: 当てた後に別の E0811（枝・ガード・連鎖の条件の状態を持つもの）が残る `~` の候補を出すか（枝の中の状態を持つ `par` に `~` を足す形、入れ子の普通の枝の内の `if` を `if~` にする形）

- 空白: §11.5 は状態を持つものを本体に含む `par` の E0811 に `~` を足す候補を示し、S-394 はガードと `if` / `if~` の連鎖の二つ目からの条件の中の状態を持つものに `~` の候補（`if~` / `match~` にする）を出さないとする。それ以外の位置で、候補を当てた後に別の E0811 が残る形（`if c { par i in 0 ..< 2 { lp~(x) } } else { … }` の `par` に `~` を足すと枝の E0811 が残る、`if a { if b { lp~(x) } else { x } } else { x }` の内の `if` を `if~` にすると外の枝の E0811 が残る）で、その候補を出すかを書いていない。
  読み: (1) S-394 の範囲だけ出さない（他は出す。候補はその診断を消し、残るのは別の位置の診断で、当て続ければ止まる）、(2) 当てた後に E0811 が残る候補は全て出さない、(3) 二つの編集を一つにした候補を出す。実装待ちの `tests/spec/fixes/e0811_par_in_a_plain_branch_leaves.onsa`（W4-20）は `~` を足す候補が枝の E0811 を残す形（`leaves`）を期待し、(1) の読み。
  仮の扱い: (1)（実装を足さない側。`SPEC-GAP(S-1183)`）。通るプログラムは変わらない。急ぎ: W7 の区切りで確認だけ。
- 決定:
- 補い（2026-11-20、親）: W7-06 U0/t（onsa-test）: 枝の中の状態を持つ `par` では、`par` の E0811 と枝の E0811 が同じ位置・同じコードになり、§18.1 の順では文面で決まる。仮は `par` の E0811（`~` を足す候補）が先（`tests/spec/fixes/e0811_par_in_a_plain_branch.onsa` の `fixes = 1` のまま）。この S と一緒に W7 の区切りで確認だけ。
- 経緯: 170 回目（2026-11-20）、W7-06 U0b の設計メモの補い（onsa-impl、`target/notes/170/w706/memo2/memo.md` の 5.1 の空白 1）が挙げた。空白は、親が文書の点検の後に §11.5 に足した「当てても誤りが残る候補は出さない」（S-394 の範囲を越えた字。戻した）から見えた。親が登録した。
- 補い（2026-11-20、親）: W7-06 U1/b（onsa-break）: ガードか `&&` / `||` の右辺か連鎖の二つ目からの条件の中にある枝（`match k { 0 if (if d { prev~(x) > 0.0 } else { false }) => 1.0, _ => 0.0 }`、`c && (if d { prev~(x) > 0.0 } else { false })`）でも、最も内側の位置（S-1188）で決めるので枝の `if~` の候補が出て、当ててもガード（右辺）の E0811（E0806）が残る。S-394 の「当てても誤りが残る `~` の候補を出さない」がこの形に当たるかを、この S と一緒に決める。仮は (1) のまま（今は `if~` が E0200 で見えない）。
