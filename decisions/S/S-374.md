# S-374 `->`・`=`・`as`・`at` の前後の改行

- 空白: 継続の一覧の記号（`->`、`=`）と `as` / `at` の前後の改行の、括弧の中と外の違い。
  括弧の外では行頭の `->`（`fn k(a: I32)` 改行 `-> I32 {`）、行頭と行末の `as`（`let y = a` 改行 `as I64`、`let y = a as` 改行 `I64`）が E0002 で、括弧の中では `f: fn(I32)` 改行 `-> I32`、`(a` 改行 `as I64)`、`(a as` 改行 `I64)` が通る（fmt が一行にする）。
  （属性の引数の `@param(min` 改行 `= 0.0, …)` の E0002 は改行でなく `=` のため。属性の引数は `min: 0.0` と書く。第 17 組の下書きで確かめた）S-370 の「置き場所の規則は括弧の中でも同じ」に入れるかを決める。第 16 組の下書きで見つけた（2026-10-09）
- 提案: 決定（2026-10-10、利用者が ID を挙げて Fable の (c) を選んだ。`->`・`=` は下書きと Fable が一致、`as`・`at` は下書きの (a) と割れた、第 17 組）: `->` と `=` は行末に置く。行頭の `->`・`=` は括弧の中でも外でも E0020 で、候補は記号を前の行の末尾（コメントの前）へ移す形（S-124 と同じ）。
  候補の前提として、W3-06 が行末の `->` の継続（今は E0002）を同じ作業で直す。`as`・`at` は置き場所の規則を持たず、`:`・`=>`・`;` と同じく括弧の中では前後の改行も空白、括弧の外は今の E0002（候補なし）。理由: `as` の右は型の名前、`at` の右はクロックの名前一つで、どの流儀でも折る位置でなく、規則を足す割に利益が薄い（S-351）。
  宣言の `x: F32` 改行 `at sample` の非対称も生まない。W3-09 の `at_starts_a_line` の期待値（E0002）は変わらない。仕様 §2.5。実装は W3-06
