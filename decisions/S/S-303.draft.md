  - (b) その文で決める: 型引数を書かずに値に置いた総称の関数は、その文の中（`let` の注釈、引数とフィールドの型、返り値の型）で型パラメータが全て決まらなければ、文の終わりに参照の位置へ E0406。

- 他言語: 
  - rustc 1.94.1（`probe/gap/other/r303*.rs`）: `let g = id;` の後の `let a: u8 = g(250); let b: f32 = g(1.5);` は二つ目に E0308「mismatched types」。使わない `let g = id;` は E0282「type annotations needed」で help は `id::<T>`。一回の使用は通り、250 を出す。
  - swiftc 6.3.3（`s303*.swift`）: `let g = id` は後で `g(250)` と使っても「generic parameter 'T' could not be inferred」。`let g: (UInt8) -> UInt8 = id` は通る（宣言の文で決める形）。
  - Apple clang 21（`c303.cpp`、C++20）: `auto g = id;`（関数テンプレート）は「incompatible initializer of type '<overloaded function type>'」。`int (*h)(int) = id;` は通る（受ける型で決める）。
  - TypeScript: 手元に `tsc` が無く未確認。Handbook の Generics（https://www.typescriptlang.org/docs/handbook/2/generics.html）は、総称の関数を総称の関数型の変数 `<Type>(arg: Type) => Type` に入れる例を示す（値は総称のまま）。Python は静的な型を持たない。
  - 一覧の外（参考）: Haskell の let 多相と単相の制限（Haskell 2010 Report §4.5.5）、ML の値の制限は、束縛を総称に一般化する側の設計である。手元で確かめていない。
