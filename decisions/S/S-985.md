# S-985 `extern` のメンバの関数の名前に書いたキーワード（`extern "C" lib "m" { fn type(x: F64) -> F64 }`）に、末尾の `_` の候補を出すか（名前は C の記号）

- 空白: §2.3（S-654）は、名前の形が `snake_case` の位置（fn・flow・メソッドの名前を含む）のキーワードに末尾の `_` の候補を出し、`use` の取り込む名前には「相手のモジュールの名前」なので出さないとする。`extern` のメンバの関数の名前（§14.1。名前は C の記号）は、どちらにも挙がっていない。候補 `type_` を当てると、別の C の記号を束ねる宣言になる。
  決めること: `extern` のメンバの名前に候補を出すか。W5-24 U2c は、決まるまで出さない側にして `SPEC-GAP` の印を付ける（候補を出さないのは §18.1 の約束の内）。
- 決定: 決定（2026-11-12、利用者「他の (A) は現状で OK」。140 回目、W5-13 の前の確認だけ）: 今の実装のまま。`extern` のメンバの関数の名前に書いたキーワードには、末尾の `_` の候補を出さない（名前は C の記号で、`_` を足すと別の記号を束ねる宣言になる）。§2.3 の候補を出さない位置に足した。`parser/failure.rs` の `SPEC-GAP(S-985)` の印は W5-13 で外す。
- 経緯: 133 回目（2026-11-10）、W5-24 U2c の壊す側（onsa-break）が報告し、親が U2c のバイナリで再現して登録した。急ぎでない。
