# S-1208 細部: 変換の flow の集める入力の輪と配る出力の配列の、状態の欄の名前（語）と、ノードの部分どうしの §12.4 の順

- 空白: §11.6 は処理系の置く状態の欄の名前を `<名前>.buf`・`.w`・`.init`・`.held` と挙げ、§11.9 は「集めた値は呼び出し側の値」「配った値は呼び出し側の `sample` の値」とする。変換の flow を `.down~(N)` で動かす呼び出しが呼び出し側に持つ、集める入力の輪（入力ごとに `[T; 2^k]`）と配る出力の配列（`[T; 2^m]`）の欄の語と、ノードの部分どうし（`Own`・`.init`・`.held` との）§12.4 の順が書いていない。S-1137・S-1138 の族の規則（処理系が作る名前は `.` を含むか `_` で始まる）で形は一つに決まるが、語と順は決まらない。通るプログラムは変わらず、`onsa interface` の写しと C の構造体の欄の名前と順が変わる。
  読み: 名前は (1) ノードの部分として `<ノードの名前>.<語>`（語の候補: 集める輪は `gather_<入力の番号>` か `.in_<入力の番号>`、配る配列は `deal`。入力の名前をそのまま使うと W7-10 の `.held` と、`held` という名前の入力で重なる）、(2) 巻き上げの欄と同じ `<修飾>._hoist_N` の列。順は (a) ノードの欄の内訳（`Own` の後、`.init` と同じ扱い）、(b) 巻き上げの欄の列。
  仮の扱い: (1)(a)。語は W7-16 U6a の実装が候補から一つ選び、`SPEC-GAP(S-1208)` の印を付ける。interface の写しの期待値は仮の語で書く。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-22、利用者。177 回目。確認だけで了承「S-1208: OK」）: (1)(a)。語は `_` で始まる形（巻き上げの欄 `_hoist_N` と同じ族。利用者の識別子は `_` で始まらないので、ノードの名前 `<let>.<flow の名前>_<番号>` と重ならない）: 集める入力の輪は `<ノードの名前>._gather_<境界>_<入力>`、配る出力の配列は `<ノードの名前>._deal_<境界>`。境界は連鎖の `.down~`・`.up~` の番号（`.when~`・`.reset_if~` は数えない）、入力は連鎖の頭の flow の入力の宣言の順の番号（どちらも 0 から。境界が一つの形にも番号を付け、U6b の境界が二つ以上の連鎖で付け直さない）。順はノードの欄の内訳でインスタンスの状態（`Own`）の後、境界の順に、その中は集める輪を入力の番号順、次に配る配列。仕様 §11.6。
- 経緯: 175 回目（2026-11-22）、W7-16 U0 の設計メモ（onsa-impl、NEW-1）が挙げ、メモの独立の審査（onsa-advisor）が「形は族の規則で決まり、語と順は決まらない」とした。親が細部として登録した（控えは `target/notes/175/w716/`）。
- 補い（2026-11-22、親）: W7-16 U6a の設計の審査（onsa-advisor、176 回目）: 語は「`<識別子>_<数字>` の形にならない」ことが要る。`gather_<n>`・`deal_<n>`・`in_<b>_<i>` の形は、`sample` の `let` の値そのものの連鎖でノードの名前 `<let>.<種類>_<番号>`（flow `deal`・`gather_0`・`in_0` の呼び出し）と重なり、`crates/onsa_sema/src/flow/plan/fields.rs` の `unique()` の内部エラーになる（再現 `target/notes/176/w716/u6a0/review/r1.txt`、今は `check` 0 で降下が E0200）。重ならないのは `_` で始まる語（`_hoist_N` の族）か、`.` をもう一段挟む形。番号の無い `deal` と `in_<n>`（`in` は予約語）は重ならない。急ぎ: W7-16 U6a2 の前（語を使う単位）に利用者へ確認。
