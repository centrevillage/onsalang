# S-784 `?` の被演算子が Affine の場所のとき（消費するか、どう書くか）

- 空白: §9 は後置 `?` の被演算子のモード（消費か借用か）を書かず、§5.4 の表にも `?` の行が無い。§5.2 は `move` を書ける消費の位置を並べるが `?` を含まず、`move` の被演算子は後置式なので `move r?` は `r?` への `move`（E0711「`move` needs a place」）になる。
  読みは (1) 消費する位置で、所有の Affine の場所を移す（印を書く形が無い）、(2) 被演算子を借用して中身を写すので Affine の場所は誤り（E0711）で、`match move r { Ok(v) => move v, Err(e) => { return Err(e) } }` と書く（腕の `return` はブロックに書き、腕の末尾は `move v`。第 75 組の下書きで確かめた）、(3) (1) で `?` に限り印を書かない（返り値の位置と同じ）。
  今は `let b = r?`（`r: Result[Buf[F32], U32]`）が、`move` の引数でも借用の引数でも通り、同じ `r` から二度取り出す形も通る（誤った受理で Core と後端に届く。`check` で確かめた）。
  再現は W4-07 の設計メモの入力 `P86/w407/i/probe/q1_try_place.onsa`・`q2_move_try.onsa`（P86 は 86 回目の scratchpad、写しは `target/notes/86/`）。
  設計メモの仮の扱いは、新しい modes（W4-07 U2）で被演算子が Dup でない型の場所なら E0200（`match move r` の形を note）、場所でない値（`f()?`）と Dup の場所は通す。
