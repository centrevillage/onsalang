# S-758 `move` の引数の型に `Span[T]`（`[Span[T]; N]`、生成型の `In`・`Out`）を書く宣言（`fn f(move xs: Span[F32])`）を E0710 にするか（§5.3 の表は既定と `inout` の書き方だけを挙げる。今は通る）

- 決定済みで戻さないもの: `Span` の名前・部分ビューを `move` の引数へ渡す E0710（§5.4 の 133 行）と、所有の行の `Span` の束縛（134 行）。返り値とフィールドの E0710（§5.3、R-135）。
  別名を通した第二級の型の位置（S-757）。呼ぶ側で Dup 値に `move` を書かないこと（S-609。今の E0703 は W4-09 で直る）。
  第 73 組の下書きの「S-758 の仕組みの出所」と「S-758 の形の表」の節（写しは `target/notes/81/g73/draft.md`）。
- 論点: §5.3（82・84 行）の表は、`Span[T]` と `[Span[T]; N]` の書き方を既定と `inout` の引数だけ挙げる。§5.2 の `move` の引数は所有権を受け取る位置で、§5.4（133 行）は `Span` の名前を `move` の引数へ渡すと E0710 とする。
  `move` の引数の型に `Span[T]`（`[Span[T]; N]`、生成型の `In`・`Out`）を書く宣言そのものが誤りかは書いていない。表を閉じた一覧（二つの書き方だけ）と読むか、「引数の位置」には全てのモードが入ると読むかで割れる。
- 今の実装: 形の表のとおり。宣言は通る。呼べるのは配列と所有の `Buf` を `move` で渡す形だけで（`Span` の値を渡す形は E0710 か E0703）、`Buf` を渡すと呼ぶ側の `b` が消費される。
  本体では、`xs` は所有の `Span` として扱われ、束縛すると E0710（借用の引数なら束縛できる、§5.4 の 133 行）、書き換えると「borrowed parameter」の E0701 になる。`move o: pan.Out` は、ビューの破棄に `Alloc` が要るという E0601 になる。
- 案: どの案も、既定と `inout` の `Span` の引数、関数型の `inout Span[F32]`（`tests/spec/concurrency/device_run.onsa` の 10 行）は変えない。
  - (a) 宣言の E0710（候補なし）: `move` の引数の型の根が第二級の `Span` の型（`Span[T]`、`[Span[T]; N]`、`In`・`Out`、それらを指す別名）なら E0710。位置は引数の型。note で書ける形（`xs: Span[T]` / `inout xs: Span[T]`。所有して持つなら `Buf[T]`）を示す。
    関数型の引数のモード（`fn(move Span[F32]) -> F32`）と無名関数の引数も同じ。
  - (b) 宣言の E0710 と、`move` を消す候補: (a) と同じ誤りに、`move` を消して借用の引数にする候補を付ける。
  - (c) 通す: 宣言は誤りでない。`move` の引数の `Span` の意味（`Buf` を `move` で渡したときに消費された記憶域の破棄、配列を複製して渡すときの一時の値、本体での束縛と書き換え、`Out` の破棄）を決める。
  - 形ごとの出力: `m01`・`m06`・`m14`・`m13`・`m15`・`m08` は、(a)・(b) が宣言の E0710（(b) は候補付き）、(c) が通る（`m15` は今の E0601 の扱いを決める）。呼ぶ側の `f(move b)` は、(a)・(b) では宣言が誤りの関数の呼び出しで、署名は読めるので今のとおり検査する。
  - 書き手から見て（修復のループの回数）: `move` を書く書き手は、所有のビュー（Rust の `Vec` を受ける形）か、書き換え（`inout` のつもり）か、他言語の「値渡しのビュー」（C++ の `std::span`）を意図しうる。
    (a) は一回の検査で宣言の所に規則を示し、意図に合う書き方（借用、`inout`、`Buf`）を書き手が選ぶ。(b) の候補は借用を選ぶので、`inout` か `Buf` のつもりなら当てた後に別の誤り（`fill!` の E0701、呼ぶ側の E0703）がもう一回出る。
    (c) は宣言が通り、本体の束縛（E0710）や書き換え（「borrowed parameter」の E0701）で、宣言の `move` から離れた位置に初めて誤りが出る。
  - 修正候補: (a) と (c) は候補が無く、当て続けても止まる。(b) の候補は宣言の `move` を消すだけで、当てた後の宣言の単位に誤りは残らない（本体で書き換える形は E0701 で、modes の段で型の段より後）。
    呼ぶ側の `f(move b)` は別の単位で、当てた後に E0703（借用の引数に `move`）になり、その候補で止まる。意図が一つに決まらない（借用、`inout`、`Buf`）ので、候補の約束の「書き手の意図が一つに決まる」に当たるかは割れる。

- 他言語: 他言語の「値渡しのビュー」は、ビューの値を複製して渡すだけで、指す記憶域の所有を移さない。Onsa の `move` は所有を受け取る印で（Affine 値は呼ぶ側で使えなくなる）、同じものではない。
  - rustc 1.94.1（`probe/other/r7.rs`）: `fn f(xs: &[f32])` は借用を値で渡す唯一の形で、`&[T]` は Copy なので複製になる。所有を受け取るなら `Vec<f32>` か `Box<[f32]>` と書く。
  - clang 21（`probe/other/c2.cpp`、C++20）: `std::span<float>` の値渡しと `std::span<float>&&` はどちらも通る。値渡しが普通の書き方で、記憶域の所有は移らない。
  - swiftc 6.3.1（`probe/other/s2.swift`）: `consuming Span<Float>` と `borrowing Span<Float>` はどちらも通る。`Span` は Copyable で ~Escapable で、`consuming` は値の複製を消費するだけで、元の記憶域の所有は移らない。
