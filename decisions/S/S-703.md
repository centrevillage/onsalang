# S-703 Rust の書き方の `use std.option.{Option}`（最後の名前が prelude の名前で、途中のモジュールが無い）の E0302 に、prelude にあり `use` は要らないことを note で示すか

- 空白: Rust の書き方の `use std.option.{Option}` は、途中のモジュール `option` が無いので「cannot find `option`」の E0302 で、候補も note も無い（S-659 のどの案でも同じ。`target/notes/70/g63/probe/p1_option_use.onsa`）。
  最後の名前が prelude の名前のとき、note で「prelude にあり `use` は要らない」と示すかが決まっていない（重大度は低）。
- 決定: 決定（2026-10-26、利用者。72 回目）: note で示す。条件は一般の形にし、Rust の書き方に限らない。名前の段で失敗した `use`（E0302）の取り込む名前が prelude の名前なら、修正候補は無く、note でその名前は `use` 無しで書けることを示す。
  prelude の名前は §15.1 の一覧の全て（`Option`・`Result`、列挙子、`panic`、`Alloc`・`Block`、演算子 trait と標準 trait、`Copy`・`Dup`、組込み型）。
  当たる形: `use std.option.{Option}`（途中のモジュールが無い）、`use std.math.{Option}`（モジュールに名前が無い）、`use option.{Result}`（頭のモジュールが無い）、`use std.option.Option`（並びの無い形）、`use std.core.{Some}`（S-659 の細部 (1) の E0302）。
  並びでは prelude の名前の要素にだけ付ける（`use std.option.{Option, Foo}` の `Foo` には付けない）。
  当たらない形: 定義元から取り込み直す `use std.core.{Option}` の E0304（S-611）、見えない名前の E0303、prelude に無い名前（標準の効果、クロックの名前、§11.3）。
  理由: 例外の規則ではなく、§15.1 の「候補を出さないときは note で正しい形を示す」と、自分のモジュールを取り込む `use main` の E0302 の note（自分の項目は名前だけで書く）と同じ類である。診断のコードと通るプログラムは変わらない。一覧の一部だけに付けると、外す理由が別に要る（利用者が全てとした）。
  仕様は §15.1 の prelude の段落に一文。実装は W4-03 の U5b（`use` の E0302 を出す所、約 10〜20 行）。
