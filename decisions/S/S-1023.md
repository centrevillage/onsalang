# S-1023 細部: E0418 の `let _` の候補を当てると、E0418 の停止に隠れていた文の式そのものの型の段の誤り（`Some(5000000000)` の E0408、`k(1.5)` の E0405）が出るとき、候補を出すか

- 空白: §6.1 は E0418 の修正候補を `let _ = e` とし、`e` の型に整数のリテラル以外のまだ決まっていない型変数が残るときは出さない。§18.1 は「候補が置く式は元の式が持つはずだった型を持ち、その型を受ける他の式（隣の被演算子、後の文）の誤りは、元から二つ目の誤りを持つ入力であり、約束の前提の外」「この約束を満たす候補を作れなければ、候補を出さない」とする。文の式そのものの型の段の誤りが E0418 の停止に隠れていて、`let _` を当てると初めて出る形を、どちらに数えるかは書いていない。
  今（`2a416e35`）は、`5000000000` だけの文は E0418 で候補なし（`body/reach.rs::end_is_clean` が、文の型が整数リテラルの型変数そのものの形だけ、当てた後の終わりの検査を試す）。`Some(5000000000)`・`(5000000000, 1)` の文は `let _` の候補があり、当てると E0408（範囲の外）。`k(1.5)` の文も候補があり、当てると E0405（`tests/fuzz/left_seen.txt` に親の読んだ印がある類）。
  読みは (1) 文の式そのものの誤りは元から二つ目の誤りなので `let _` を出す (2) 当てた後に初めて出る誤りは候補が残した誤りなので出さない（今の `end_is_clean` の読みを全ての形に広げる）。どちらも誤りとして拒む（通るプログラムは変わらない）。仮の扱いは今のまま（W5-13 U8 は変えない）。再現は `target/notes/142/w513u8_memo/cases1.txt`・`cases2.txt` の `l1_lit_some_overflow`・`l2_lit_overflow`・`l4_tuple_overflow`・`f1_float_let`（台本 `scripts/fixes.py`）。
