# S-338 見出しの範囲の記号の直後の `{`（見出しの中のブロック式）

- 空白: `for` / `par` の見出しで、範囲の記号の直後の `{`（`for i in 0..<{ n } { … }`）を端のブロック式とするか、本体の始まり（端の無い範囲）とするか。§3.1 は端を式とし、ブロック式を端に書けないとは書かない（`if { c } { }` は通る）。W3-18 の実装は本体の始まりとして E0002（`SPEC-GAP(S-338)`）。W3-18 の前は `0..{ n }` が通っていた。W3-18/b で見つけた（2026-10-09）
- 提案: (c)。見出しの式（`if` / `while` / `match` / `for` / `par`）の中で、括弧の外の式の始まりにある `{` は全て本体の始まりと読み、ブロック式は struct リテラル（S-08、§4.4）と同じく括弧で囲む（`0..<({ n })`、`if ({ c }) {`）。キーワードに続く `{` はその式のもの。
  違反は構文の段の E0002 と note（struct リテラルと揃え、括弧で囲む候補は作らない）。代償: 今通る `if { c } {`、`while { s < n } {`、`match { n } {`、`for x in { xs } {`、`0..<n + { 1 }` が誤りになる（リポジトリに用例は無い）。
  範囲の記号の直後だけの例外にせず、§4.4 の規則を広げる一つの規則にした（仕様 §4.4、§3.1、`spec/tools.md` §3.3。2026-10-09 決定、利用者、第 12 組。実装は W3-21: `parser.rs` の `no_struct_lit` の判定を `parse_primary` の `{` にも当て、W3-18 の範囲の直後の `{` の専用の検査と `SPEC-GAP(S-338)` を消す）
