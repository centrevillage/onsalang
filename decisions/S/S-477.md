# S-477

- 空白: `lib` の無い extern のブロック `extern "C" {`（Rust の `extern "C" { fn f(); }`、C++ の結合指定）。今は「expected `lib`, found `{`」の E0002 で、ブロックの関数が全て消え、使う所に E0302 が出る。ライブラリの名前は書き手しか知らないので候補は作れない。
  S-435 の形で読み続けて、ライブラリを未知（S-460 の形）にするか。Rust の 2024 年版の `unsafe extern "C" {` は、S-459 の `unsafe` の後にこの形になる。第 27 組の下書きの付録で見つけ、Fable も別の S にするのに同意した（2026-10-13）
- 提案: 後の段（extern のブロックは今は E0200。急ぎは低）
- 時期: W3
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目、第 38 組）: 族の規則 S-593 の (1) から決まる。extern の見出しが `{` の前で読めず `{` が同じ行にあれば（表 1 の 20〜22 行）、`extern` から `{` の前までを一つの E0002 にし（候補なし、note で `extern "C" lib "…" {`）、メンバを読み続ける。ブロックは一つの単位でメンバは検査しない。
  ABI とライブラリは読めなければ未知（`ExternDecl::abi`・`lib` を `Option<StrLit>`。独立のレビューの段 2 の補い）。`unsafe extern "C" {` は 2 周、改行の形は読み続けない。使う所の出力が変わるのは R-246 と extern のブロックの実装の後。
  構文の部分は W5-11 で入れ、詰まれば extern のブロックを実装する作業へ回してよい。仕様 §18.1
- 経緯: 55 回目（2026-10-23）、W4 の前の S の下書き（X-8）の第 38 組（族 S-593、下書き `S-477.draft.md`、助言の担当の二段）。
