# S-881 総称の浮動小数のコードの小数の定数（`x * 0.5`（`x: T: Float`）は E0401、`T.round_from(0.5)` は浮動小数のリテラルに既定の型が無く E0405、`T.round_from(2)` は通る）

- 空白: §6.6 はリテラルを型パラメータ `T` の値にしないので、総称の浮動小数のコードの小数の定数（係数、`0.5 * (a + b)`）を書く形が無い。`x * 0.5`（`x: T: Float`）は E0401「a float literal cannot have type `T`」。
  S-231 の `T.round_from[S: AnyNum](x: S)` に小数のリテラルを渡すと、浮動小数のリテラルに既定の型が無いので E0405（`T.round_from(2)` は整数の既定の `I32` で通る）。`0.5 as F64` は E0420。今は `let half: F64 = 0.5` の後の `T.round_from(half)` と書くことになる。
  候補: この書き方で足りるとする、変換元を `F64` に固めた関連関数を足す、期待の型が `T: Float` の小数のリテラルを具体化のときに丸める規則（`Float` は組込みの型に閉じている）など。再現は第 82 組の下書き `target/notes/111/g82/draft.md` の NEW-1（`forms/f14`・`lit/l01`）。
  急ぎ: W5-05 の設計メモの前（W5-05 が総称の std を増やす前）
- 決定: 決定（2026-11-05、利用者。116 回目、第 87 組。下書きと伏せた独立のレビューが一致。下書きは `S-881.draft.md`）: (c)。小数のリテラルは、境界が `Float` を含む型パラメータ `T` の値になる（`x * 0.5`、`0.5 * (a + b)`、`impl[T: Float]` の `const HALF: T = 0.5`）。値は具体化した型へ §2.4 の規則で一度だけ丸める。
  理由: `Float` を実装する型が `F32`・`F64` に閉じているので（§6.3）、どの型でも値を持てる字面かを定義の位置で判定でき、使う場所の奥で誤りにならない（A-10 と同じ原理で、`Num`・`AnyNum` は固定小数点が、`Int` は第 2 期に利用者が実装しうるので当たらない）。`T = F32` のコードに `F64` の値と変換が入らず、具体的な型のリテラルと同じ値になる。§6.6 の前の文は実装のレビュー T-3 を写したもので、決定に設計の理由が無かった。
  細部: 字面が `F32` か `F64` のどちらかで §2.4 の範囲に当たれば定義の位置で E0408（文面は型を名指す）。`T: Num`・`T: AnyNum` の小数のリテラルは E0401 のままで候補なし、note は「小数のリテラルは境界が `Float` を含む `T` の値になる」。`T: Int` の整数のリテラルは変えない（A-10 は保留のまま）。`T.round_from(0.5)` は E0405 のままで、note に `T` の位置に直接書く形の例を添える。
  §11.4 の `T.ONE` はそのまま。
  仕様 §6.6・§4.7・§19.1。作業は W5-05。
