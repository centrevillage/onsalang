# S-605 族: §5.2 の move を書ける位置

- 決定済みで戻さないもの: 直接の `move` を書ける位置と書けない位置（1・3・7・8・12・17・20・22・24・26・27・29・31 行）、末尾の受理（2・7 行）と 4 行の正しさ（S-100）、被演算子の後置式（24・40 行、R-42）、32〜36 行。

- 論点: §5.2「`move x` は、値が消費される他の位置にも書く式の形である: `let` / `var` の初期化…、代入の右辺、struct / 配列 / タプルのリテラルの要素、`match` の対象（`match move x`）、`for` の反復元（`for s in move xs`、§5.4）」、「`move` と `inout`（呼び出し位置の印）の被演算子は後置式（名前と、それに続くフィールド・添字・呼び出し）で、二項演算子の被演算子にはならない」。

- 案: どの案でも、直接の `move` の扱い（決定済みの行）は変えない。違いは、ブロックの末尾の `move` と、場所でない被演算子の段とコードである。
  (a) modes が、継いだ位置で一か所で判定する。構文は今のとおり、全てのブロックの末尾に `move` を読む。
  - 末尾の `move` は、直接の `move` を書ける位置（消費する位置、返り値の位置、`match`・`for` の見出し）に置いたブロックでは受理する。見出しの末尾の `move` は、腕の束縛と反復を所有にする（M1 の 21・25 行）。
  - それ以外の位置に置いたブロックの末尾の `move` は、位置によらず modes の E0703（書いた印が位置のモードと合わない）。候補は、その末尾の `move` を消す形。消した後は場所を読むだけで、誤りの無い形になる。
  - 被演算子が場所でない `move`（37〜39 行のうち場所でないもの、6・9・13 行）は、位置によらず modes の E0711（R-198 の段とコード）。候補は、ブロックと `if`・`match` なら外の `move` を消して各末尾の Affine の変数に `move` を置く形、それ以外は `move` を消す形。
    場所でない値を `move` の引数に渡すときは `move` を書かない（5 行は通る）。
  - 収束: どの候補も `move` の語を消すか腕へ移すだけで、同じ位置に戻す候補は無い。一回で誤りの無い形になるか、次の段（W5-08 の後の E0418 など）の誤りで止まる。
    書き手の意図が一つに決まるのは、消費しない位置では読むだけの形しか無く、`move` の付いたブロックでは消費される変数が末尾で決まるからである。
  - 実装: modes の E0200 の分岐を E0703 と候補にする（約 10 行）、見出しの末尾を消費として読む（M1 の見出しの判定と同じ。約 5 行）、場所でない被演算子の E0711 を一つの述語にして引数と見出しにも当てる（約 10 行）、候補（約 20 行）。構文は変えない。事例は約 10 件。
    費用の要因: 直接の `if move fl {` は構文の段の E0002、末尾の `if (if c { move fl } else { true }) {` は modes の E0703 と、同じ位置でコードと段が違う。
  (b) 直接の形と同じ段とコードにする。末尾の `move` も、文・条件・演算子の被演算子・添字・範囲の端では構文の段の E0002、借用と `inout` の引数では modes の E0703。見出しの末尾の `move` は (a) と同じく受理する。
    被演算子は、構文の段で名前で始まる後置式に限り（`move (a)`、`move { a }`、`move if …`、`move 1` は E0002）、名前で始まる場所でないもの（`move mk()`、`move K`）は modes の E0711。
  - 収束: E0002 に候補が無ければ `no-candidate` で止まる。候補を `move` を消す形にすると、文の位置の末尾（21 行）は消した後に E0418（W5-08 の後）で `let _ = …` の候補になり、さらに E0711 で各腕へ `move` を戻す三回で収束する。
  - 実装: 構文の段で、ブロックを読む関数に「置かれた位置が値を消費するか」を渡す（`if`・`match`・ブロック・入れ子、約 30〜50 行）、被演算子を名前で始まる後置式に限る（約 10 行）。modes は引数の E0703 と E0711（約 10 行）。事例は約 14 件。
    費用の要因: 消費する位置の一覧が、構文（引数は全て消費する位置として通す）と modes の二か所になり、位置を足すときに両方を直す。文の位置の末尾の `move` が E0002 で止まり、E0418 の候補が出る前に書き手の印を消す。
  (c) 消費として読む。末尾の `move` をどの位置でも受理し、そのブロックが値を消費する（文の位置では破棄、条件では複製、借用の引数では一時の値を渡して呼び出しの後で破棄）。被演算子は (a) と同じ。
  - 収束: 誤りにならないので候補は無い。実装: modes で全ての位置の末尾を消費として扱う（約 10 行）と、降下で一時の値を破棄する（W8 の降下に約 20〜40 行）。事例は約 8 件。
    費用の要因: `let _ = move a` と同じことを文の位置の `if` で書け、書き方が二つになる。借用の引数に置いた `move` が呼び出しの後の破棄になり、読み手に見えない。

- 他言語: Swift 6.3.1（手元、`s1.swift`〜`s3.swift`）: `consume` は借用の引数（`look(consume a)`）、`for i in consume x`、文の `_ = consume a`、条件（`if consume fl`）、括弧の中の被演算子（`1 + (consume x)`）に書ける。
  Copy の型には「'consume' applied to bitwise-copyable type 'Bool' has no effect」の警告。
  被演算子は局所の束縛と引数だけで、`consume mk()` と `consume p.v`（Copy の型）は「'consume' can only be used to partially consume storage of a noncopyable type」、`consume (x)` と `consume 0..<n` は `consume` を関数の名前と読んで「cannot find 'consume' in scope」。
  Rust 1.94.1（手元、`r2.rs`）: 印は無く、文の位置の `if c { a } else { b };` は `a` か `b` を動かして破棄する（後の `a` の使用は E0382）。(c) と同じ読み。
  C++（Apple clang 21、`c1.cpp`、`-Wall -Wextra`）: `std::move` はどの位置にも置け、`std::move(mk())` と `return std::move(y)` に「-Wpessimizing-move」、文の `std::move(a);` に「-Wunused-result」の警告が出るだけ。
  Mojo: 転送の印 `^` は「the postfix `^` transfer sigil on an argument at the call site」（https://mojolang.org/docs/manual/values/ownership の「Transfer arguments (`var` and `^`)」）。他の位置と場所でない値は文書に無く、未確認。
- 推奨と理由: (a)。確度: 中。
  - 位置を継ぐ判断を一か所に置く。どの位置が値を消費するか（S-100 の「置かれた位置」）は modes が持つ位置の情報で、末尾の `move` の可否も、腕の E0711 と引数の E0703（S-100 で決まっている）も同じ所で判定する。(b) は同じ一覧を構文にも持たせ、二か所を揃え続けることになる。
  - 直接の形とコードが分かれるのは、直接の形は字面の位置で決まり、末尾の形は継いだ位置で決まるからである。引数の位置の直接の `move`（29・31 行）が既に modes の E0703 で、末尾の形もそれと同じ分け方になる。
  - 修復のループが一回で収束する。(b) は文の位置で書き手の印を消してから戻す回り道になる。W5-08 で E0418 が入ると、文の位置は (a) では型の段が先に `let _ = …` を示し、書き手の意図（どちらかを捨てる）どおりの形になる。
  - (c) は意味を持たせることで、`let _ = move a` と同じことの二つ目の書き方を作り、借用の引数の `move` が見えない破棄になる。後で (a) から (c) へ緩めても通っていたものは壊れないが、逆は壊すので、今は誤りにしておく。
  - 実装の量は (a) が最も少なく、構文を変えない。作り直す modes に、位置ごとの判定を一つの表（消費する、返り値、見出し、それ以外）として置ける。第 2 期の新しい位置（`Map` のリテラルの要素など）は、その表に一行足すだけで直接と末尾の両方に効く。
