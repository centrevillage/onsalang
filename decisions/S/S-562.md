# S-562 イベントを修飾子の条件に使うこと

- 空白: §19.1 は「イベントのクロックの値を `when` / `reset_if` の条件に直接書けるか（その刻みにイベントがある）」を入れるときに決めることに挙げる。第 33 組で、`when` のクロックを呼び出しの位置のクロック K の刻みのうち条件が真の刻みと定義し（S-558）、`reset_if~` は水準で読む（S-559）。決めること:
  1. イベントの値を条件にそのまま書けるか（`x.reset_if~(start)`）、`Bool` に変える形（std の flow か関数）を通すか。
  2. イベントで動くインスタンス（`x.when~(<イベントがある>)`）の意味: K をイベントのクロックに広げるか。止まっている間の保持（S-558）と、同じ位置の複数のイベントで複数回動くこと（S-561）。
  3. 同じ位置に二つのイベントがあるときの `reset_if~`（二回初期化するか）。MIDI の Start / Stop / Continue（§19.1）の書き方の例。
- 決定: 決定（2026-10-21、利用者が ID を挙げて了承。47・50 回目）: `when~` の条件にイベントの値から作った `Bool` を書くと、連鎖のレートの刻みでその位置までの最後の値として読む水準になる（`present` は要らない）。`when~` はレートを変えず、止めるのはサンプルレートに結び付く処理で、止まっている部品に来たイベントも処理する。`reset_if~` のイベントの条件は、そのイベントの刻みで、続く段の前に初期化する（外の `when~` が止めている間も）。
  イベントのレートの受け手への `when~` は何も止めない印として E0020 の類。仕様 §19.1
- 経緯: X-7（W3 の終わり、2026-10-15、利用者）で、W4 の前に決めて第 1 期の範囲を W4〜W10 に割り当てることになった。第 34 組（イベントのクロック）の一つで、第 33 組（S-555〜S-559）の決定を前提にする。export の形・C の API・std の型・`onsa test` と `render` での与え方は第 35 組。
