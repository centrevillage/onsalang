# S-1037 所有の `for` の反復元（`for s in move xs`、`for s in f(...)`）の、ヒープの容れ物と途中の出口の残りの要素の破棄

- 空白: §5.4 の表は `for s in move xs`・`for s in f(...)` を「所有。反復元を消費する」とし、破棄を「要素ごとに起きる（§12.2）」と書く。§12.2 は所有する Shared 値・`Buf` とそれらを含む値の破棄に `Alloc` が要るとする。仕様は、ループの後のヒープの容れ物（`Array`）の破棄と、`break`・`return`・`?` で途中で出たときのまだ反復していない要素の破棄を書かない。
  今（`702a4619`）: `for s in move xs { return sink(move s) }`（`xs: [Buf[F32]; 2]`）は通る（二つ目の `Buf` の破棄を数えない）。`for s in move xs { t = t + s }`（`xs: Array[F32]`）は E0601（今は `xs` が Dup で複製になり、元の `xs` を後で破棄するため）。入力は `target/notes/146/w602/memo/probe/` の `c.txt`・`e.txt`。
  読み: (1) 反復元は出口で破棄する（容れ物はループの後に必ず、残りの要素は途中の出口で） (2) 表のとおり要素ごとだけを数える。
  S-1030 との関係: 消費する位置の最後の使用で Dup の値を移す読みを採ると、`for s in move xs` の `Array` は `for` に移るので、(1) で容れ物の破棄を数えないと `Alloc` の無い関数が容れ物を解放する形が通る。
  急ぎ: W6-02 の早い出口の単位（U3）の前。
- 決定: 決定（2026-11-13、利用者が確認だけで了承。146 回目、第 100 組。中立の要約と独立のレビューの段 1 が (1) で、段 1 は仕様の字で決まると見た）: (1)。所有の `for`（`for s in move xs`、`for s in f(...)`）は、ループを出るとき（終わり、`break`、`return`、`?`）に、まだ反復していない要素とヒープの容れ物（`Array`・`Buf`）を破棄し、`Alloc` に数える（§12.2 の 2 行目）。固定長の配列を終わりまで回せば残りは無い（`[T; N]` に容れ物は無い）。`continue` は出口でなく、panic の道は数えない（§9.2）。
  理由: §5.4 の表の「要素ごとに起きる」は束縛 `s` の行の記述で、反復元の残りは所有の値の破棄として §12.2 が当たる。数えないと `rt` の関数が容れ物や残りの要素を解放できる。今の木で誤りになる事例は 0 件（粗い走査）。
  作業は W6-02 の U3（`IterRest` を通常の出口（容れ物だけ）と早い出口（残りの要素と容れ物）に分ける）。仕様 §5.4 の表の `for s in move xs`・`for s in f(...)` の破棄の欄

- 補い（2026-11-13、親）: 中立の要約（Q2）と独立のレビューの段 1（onsa-advisor、146 回目）: (1)。段 1 は空白でなく字で決まると見た（§5.4 の「要素ごとに起きる」は束縛の行で、反復元の残りは §12.2 の 2 行目）。出口（終わり、`break`、`return`、`?`）で、まだ反復していない要素とヒープの容れ物を破棄する。固定長の配列を終わりまで回せば残りは無い。`continue` は出口でない。今 `rt fn` で通る `for s in move xs`（`Buf[F32]`、借用の `Array`）と固定長の途中の出口が誤りになる（`target/notes/146/g100/advisor/probe/q2b.txt`）。`tests/`・std・`examples/` の粗い走査では 0 件。
