# S-854 数のリテラルの型変数に型の頭を要する操作を当て、どの数の型でも同じ誤りになる形の報告（`17.(x)`・`n.x`・`n.0`・`n[0]`・`n?`・どの数の型にも無いメソッド）

- 空白: §4.7 は「その場で既知を要する操作」（フィールド `.f`、メソッドの呼び出し、添字、`as` の左辺、`match` の対象、`?` の対象、関数値の呼び出し）の対象が型変数なら E0420 とし、リテラルの型変数も未解決に数える（180〜181 行）。
  数のリテラルの型変数は数の型にしか決まらないので、関数値の呼び出し（`17.(x)`）・フィールド（`n.x`）・タプルの添字（`n.0`）・添字（`n[0]`）・`?`（`n?`）・どの数の型にも無いメソッド（`n.nope()`）は、どの型に決まっても誤りで、注釈すると E0401・E0413・E0414 になる（`let n = 17` の後も同じ）。今はどれも E0420「add an annotation」で、注釈しても誤りは消えない。
  一方、`as` の左辺と、型によって有無が違うメソッド（`n.abs()`、§4.7 の `0.round_f32()`）は、決まる型で答えが変わる。数以外のリテラル（`"a"`・`'a'`・`true`・`()`・配列・タプル・`None`）は型の頭が決まっているので、今も `.(` で E0401 になる。
  §15.1 の 77 行は「`.(` で呼んだ値の型が関数でない場合（`x: F32` の `x.(1.0)`）は型の誤りで E0401」とする。S-350 の決定の本文に「型の段の数値リテラルの呼び先の文面（E0420 より E0401 が合う）は W4 / W5 の記録」があり、W5-01 の持ち越しが `17.(x)` を E0401 にするとしているが、§4.7 の文は改めていない。
  読み: (A) 全て E0420 のまま（文面だけ改めうる）。(B) `.(` だけ E0401。(C) 型の構造で決まる操作（`.(`・フィールド・タプルの添字・添字・`?`）を、注釈したときと同じコードにする。(D) (C) に、どの候補の型にも無いメソッドを加える。どの読みでも、通るプログラムは変わらない（報告のコードと文面だけ）。再現は 105 回目の scratchpad の `s854-advisor/probe/`。
- 決定: 決定（2026-11-03、利用者。105 回目）: (C)。リテラルの型変数の候補は整数の型か浮動小数の型に限られるので、候補の種類だけで誤りと決まる操作（フィールドアクセス、タプルの添字、添字、`?` の対象、関数値の呼び出し）は、E0420 でなく、注釈したときと同じコード（E0401・E0413・E0414）をその場で報告する。型ごとに有無や結果が決まる操作（メソッド呼び出し、`as` の左辺、`match` の対象）は E0420 のまま。
  細部: 文面は型の名前の所に「整数」「浮動小数」を置く（`an integer is not a function and cannot be called` など。値は束縛 `n`・`i` のこともあるので「整数リテラル」とは書かない）。修正候補は無い（注釈した形にも無い）。文字列の穴の中の `"{n.x}"` も同じ。
  理由: 注釈では消えない誤りに注釈を勧めない（§18.1 のコードは直し方の単位）。`let m = n + x` の後の `m.(x)` は前から E0401 で、書き方による違いを、型で答えの変わらない操作の全てで揃える。
  メソッドを含めない（(D) でない）のは、どの候補の型にも無いかが、W5-02 で std の宣言に移る表と、後の版のメソッドの追加と、利用者の trait の実装（§6.3 の 102 行）で変わるため。前からの `1.5 & 2.5` のその場の E0401 も同じ原則で説明できる。
  仕様 §4.7（181 行の後と 187 行）、§15.1 の 77 行。実装は W5-01 の U2（内部の型変数 `?0` が文面に出る R-353 と同じ所で直す）
- 経緯: 105 回目（2026-11-03）、親が W5-01 の票を書く中で、持ち越しの `17.(x)` の E0420 と §4.7 の文が合わないことを確かめ、利用者の問い（数以外のリテラルでは起きないか）から、同じ形が他の操作にもあると分かった。利用者の指示で助言の担当に回す。前からある。独立のレビュー（助言の担当の段 1、105 回目の scratchpad の `s854-advisor/`）は (C) を選んだ。
  親の推奨は範囲が `17.(x)` だけに見えていた時点の (B) だけで、段 1 が (B) を退ける理由を書いたので、段 2 は省いた
- 補い（2026-11-03、親）: `空白` の「型によって有無が違うメソッド（`n.abs()`…）」の例は誤り: §3.4 の 121 行で `abs`・`min`・`max` は数の型のメソッドでなく E0413（今 `n: I32` の `n.abs()` が通るのは実装の誤りで W5-14 が直す）。
  型で有無が違うメソッドの例は `checked_add`（整数だけ）・`to_bits`（浮動小数だけ）・`0.round_f32()`。決定の規則（メソッドの呼び出しは E0420 のまま）は変わらない。W5-01 U2/t のテストの担当が見つけた
- 補い（2026-11-03、親）: W5-02 U1 の設計メモの D1（2026-11-03、106 回目、利用者）で、一覧の外の形（`n.abs()` など）の拒否（候補の無い E0413・E0302）は W5-02 の U4・U6 が std の宣言を閉じた一覧にして入れ、候補と note は W5-14 に残した
