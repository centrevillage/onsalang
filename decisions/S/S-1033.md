# S-1033 細部: 期待型が前の式から決まって `rt` か効果行だけが違う E0401（`pick(r, k)`、`Option[rt fn]` を `Option[fn]` の位置へ、`inout` の引数）に、型の出所と直し方の note を付けるか

- 空白: S-1031 の (b)（期待する型の無い合流の一番外だけを合わせ、型変数の推論・入れ子・無名関数の返り値・代入は先に決まった型で比べる）の後は、書き手が `rt` も `uses` も書いていない所に「expected `rt fn(U32) -> U32`, found `fn(U32) -> U32`」が出る（`pick(r, k)` の `k`、`Option[rt fn]` の値を `Option[fn]` の位置へ置く形、`rt fn` の変数を `inout g: fn(U32) -> U32` へ渡す形）。
  直し方は、型引数（`pick::[fn(U32) -> U32](r, k)`）か注釈（`var f: fn(U32) -> U32 = r`）で先に型を決めることで、今の E0401 の文からは読めない。
  読み: (1) note を付けない（今のまま） (2) 期待型を決めた所（前の枝、先の引数、最初の `return`、`var` の初期化）と直し方を note で示す。`check_args` は解く前の引数の型を持つので、呼び出しの引数だけなら約 10 行（段 1 の見当）。型引数の中の E0401 には「型引数の中は完全に一致する」の note。候補はどちらも足さない（書き手の意図が一つに決まらない）。
  仮の扱い: W6-01 の U2a・U2b の実装の担当が出す形（文面は約束でない、§18.1）。
- 決定: 決定（2026-11-15、利用者。152 回目、W6 の区切りの確認だけ。「上記はすべて OK」で了承）: 仮の扱いのとおり (1)。型の出所と直し方の note を付けない。文面は約束でないので、仕様は変えない。
- 経緯: 145 回目（2026-11-13）、第 97 組（S-1031）の独立のレビューの段 1（onsa-advisor）が細部として挙げ、下書き（onsa-gap）も別の S の候補として同じ note を挙げた。材料は `target/notes/145/g97/`。関係: S-1031、S-880
