# S-1072 細部: 値を介さない型の輪の中に誤りの別名があるとき（`struct RA { b: AB }`・`type AB = Buf[RB]`・`struct RB { a: Buf[RA] }`）、輪の他の宣言は別名を名指すフィールドを誤りの型として読むか、別名の右辺を書いたとおりに読むか

- 空白: §18.1（S-1066）は、値として含まない位置で互いを名指す型の宣言の集まりでは、集まりの宣言どうしは互いのフィールドを書いたとおりに読んでそれぞれ判定するとし、§4.4 と S-757 は、誤りのある別名を名指す所はその別名を誤りの型として読むとする。S-1066 の `決定` は「別名は今のまま先に置き換える（別名どうしは依存の順）」とする。
  誤りの別名が輪の中にあるとき、輪の他の宣言（`RB`）が、別名を名指すフィールド（`RA.b`）を誤りの型として読むか、別名の右辺（`Buf[RB]`）として読むかを書かない。誤りのあるプログラムだけの形で、通るプログラムは変わらない。
  今（W6-04 U15 の後）: 宣言の順で変わる。`RA`・`AB`・`RB` の順では `AB` の E0416 だけ、`RB` を先に書くと `RB.a` と `AB` の 2 件。
  再現: `target/notes/155/s1066/advisor/cases_ring.txt` の `r04b_alias_ring_ab`・`_ba`。
  読み: (1) 輪の中でも別名を名指すフィールドは誤りの型（`AB` の 1 件。順によらなくするには、成分の判定の前に別名の置き換えだけを先に当てる手当てが要る） (2) 輪の中では別名の右辺を書いたとおりに読む（`AB` と `RB.a` の 2 件。S-1066 の独立のレビューの段 1 の設計と 3 節の表の #4 の見立てで、成分の中の置き換えを全て成分の後へ保留する形）。
  仮の扱い: (2)（W6-04 U16 の実装の形。`RB.a` の誤りは `AB` を直しても `RA` が `Copy` でない限り残る、S-1066 の理由と同じ）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
