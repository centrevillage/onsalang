# S-1028 細部: 括弧の中の行頭の `|` の `,` の抜け（`1 => a % b` 改行 `| 2 => 1,`）の候補 `,` の挿入（§2.5 の 162 行）が、当てた後に行頭の `|` の E0020 を残す（§18.1 の約束と §2.5 の文の噛み合わせ）

- 空白: §2.5（`spec/02-lexical.md` 162 行）は、括弧の中の行頭の `-` と `|` で、前の行の末尾へ移すと二項の読みが成り立たない形（`0 => 2` 改行 `| 1 => 1,`）を `,` の抜けの E0002 とし、「修正候補は `,` の挿入だけ」とする（`- 1` は「`,` を入れても前置の記号の後の空白の誤りが残るので、候補を作らない」）。§18.1 は候補を当てた後に同じ単位に誤りを残さないとする。`| 2 => 1,` の形は `,` を入れた後に行頭の `|` の E0020 が残る（`onsa_cases --fix-contract` の違反）。前からの形（dev `aba52f89` と U7c の後で同じ）。
  読みは (1) 162 行の字のとおり `,` の挿入を出す（残る E0020 は次の検査、S-960 と同じ二段の形と読む） (2) `- 1` と同じく、残る誤りがあるので候補を作らない（162 行の例を改める）。どちらも誤りとして拒む（通るプログラムは変わらない、候補の有無だけ）。仮の扱いは (1)（今のまま）。再現は `target/notes/142/w513u7c/b/o3/arm1.onsa`（`a < b` の版は `arm2.onsa`）。
