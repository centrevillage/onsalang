# S-1028 細部: 括弧の中の行頭の `|` の `,` の抜け（`1 => a % b` 改行 `| 2 => 1,`）の候補 `,` の挿入（§2.5 の括弧の中の行頭の `-` と `|` の段落）が、当てた後に行頭の `|` の E0020 を残す（§18.1 の約束と §2.5 の文の噛み合わせ）

- 空白: §2.5 の括弧の中の行頭の `-` と `|` の段落は、括弧の中の行頭の `-` と `|` で、前の行の末尾へ移すと二項の読みが成り立たない形（`0 => 2` 改行 `| 1 => 1,`）を `,` の抜けの E0002 とし、「修正候補は `,` の挿入だけ」とする（`- 1` は「`,` を入れても前置の記号の後の空白の誤りが残るので、候補を作らない」）。§18.1 は候補を当てた後に同じ単位に誤りを残さないとする。`| 2 => 1,` の形は `,` を入れた後に行頭の `|` の E0020 が残る（`onsa_cases --fix-contract` の違反）。前からの形（dev `aba52f89` と U7c の後で同じ）。
  読みは (1) その段落の字のとおり `,` の挿入を出す（残る E0020 は次の検査、S-960 と同じ二段の形と読む） (2) `- 1` と同じく、残る誤りがあるので候補を作らない（その段落の例を改める）。どちらも誤りとして拒む（通るプログラムは変わらない、候補の有無だけ）。仮の扱いは (1)（今のまま）。再現は `target/notes/142/w513u7c/b/o3/arm1.onsa`（`a < b` の版は `arm2.onsa`）。
- 決定: 決定（2026-11-13、利用者。143 回目、W5 の区切りの確認だけ。「推奨の通り」で了承）: 今のまま (1)。括弧の中の行頭の `|` の `,` の抜けは、§2.5 の字のとおり `,` の挿入の候補を出し、当てた後の検査で腕の頭の `|` の E0020 を報告する（腕の頭に `|` を書く他言語の形で、`,` の抜けと別の誤り。S-960 と同じ二段で、二手で通る）。§2.5 の該当の段落に足した。
- 経緯: 142 回目（2026-11-12）、W5-13 U7c の壊す側（軽い）が範囲の外として報告し、親が再現した。`rules/leader.md` 5.11 の細部として今のままで進め、W5 の区切りで出す。
