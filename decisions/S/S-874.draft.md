# S-874 Copy の引数の型で、モードだけが違う関数型（`fn(T)` と `fn(move T)`）を互いの位置で使えるか（Copy の要素の構築子の関数値を既定のモードの関数型の位置に置く形、§8.1 の規則 1）

- 論点: §4.1（26 行）は関数型の引数のモードを型の一部とし、§8.1 の規則 1 は引数の型が等しいことを求める。Copy の値は、借用の引数にも `move` の引数にも複製して渡すので、呼ぶ側から見た意味は同じである（§5.2 の 37 行の表と 77 行）。

- 他言語:
  - swiftc 6.3.3（`probe/gap/other/s1.swift`〜`s3.swift`）: Copyable の型では、`borrowing`・`consuming`・無印の引数の関数型を互いに変換する。引数、注釈、struct のフィールド、関数型の中の関数型、`@escaping` の値を別の型で返す形、総称の引数の全てで通り、実行結果も正しい。
    `inout` の関数を無印の位置に置くと「cannot convert value of type '(inout P) -> Float' to expected argument type '(P) -> Float'」である。
    `-emit-silgen` では、自明な struct `P` は総称の変換の一か所だけ reabstraction thunk を作り、`String`（参照を数える型）は両方向に thunk を作って、元の関数値を文脈として受ける（Swift の関数値は文脈をヒープに置ける）。
  - rustc 1.94.1（`r1.rs`）: `Copy` の struct `P` でも、`fn(P) -> f32` と `fn(&P) -> f32` は両方向とも E0308（「expected fn pointer `fn(P) -> _`, found fn item `for<'a> fn(&'a P) -> _`」）。引数の `mut`（`fn by_val_mut(mut p: P)`）は型に入らず、`fn(P)` の位置に置ける。閉包 `|p| by_ref(&p)` で包めば通る。
  - Apple clang 21（`c1.cpp`、`-std=c++20`）: 関数ポインタ `float (*)(P)` と `float (*)(const P&)` は互いに「no matching function」である。`std::function<float(const P&)>` は `float(P)` の関数を受け、逆も受ける（型を消した包み）。
    引数の最上位の `const`（`float by_cval(const P p)`）は関数型に入らず、`float (*)(P)` の位置に置ける。
  - Hylo（文書 https://docs.hylo-lang.org/language-tour/functions-and-methods ）: 引数の約束が関数型の書き方に現れる（`(inout Float64, Float64) -> Void`）。違う約束の関数を置けるかの規則は書いておらず、未確認。Mojo と Vale は未確認。
