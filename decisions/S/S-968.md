# S-968 定数式の中に書いた定数式でない形（文を含むブロック、`if`、`match`、`unsafe`、閉包）の中の名前を名前の段が読むか（中の E0302・E0308 を出すか、形の E0417・E0200 だけか）

- 空白: §4.5 は定数式を「整数のリテラル、定数を指す名前、算術の演算子、括弧」とし、「関数の呼び出しは書けない」「定数式でないもの…位置によらず E0417」とする。§18.1 は名前の段が型の段より先。定数式の中に定数式でない形（文を含むブロック、`if`、`match`、`unsafe`、閉包）を書いたとき、その中の名前（`[F32; ({ let q = 1⏎ q }) + zz]` の `zz`、`if zz < 1`）を名前の段が読んで E0302・E0308 を出すか、形の E0417（か、この版の E0200）だけを出して中を読まないかを書いていない。
  読みは (1) 中の名前も読む（本体の `if zz < 1` は今この形） (2) 定数式でない形は E0417 か E0200 の一つで、中は読まない。
  今（W5-16 U1a の後）は、署名と本体が (1)（前の署名は E0200 で、本体にそろった）、flow の `delay~` の位置は文法の外の形が E0417（前から）。どの読みでも通るプログラムは変わらない。S-966（文法の外の形のコード）・S-967（値の後の名前）と同じく、U1b（読み手の文法と型の判断）の前に決める。
  W5-16 U1a の壊す側が見つけた（2026-11-09、129 回目。入力は `target/notes/129/w516u1a/` に写す予定の `s4.txt`・`out3.txt`）。
- 決定: 決定（2026-11-09、利用者。129 回目、S-966・S-967・S-968 の共通の規則。中立の要約（`target/notes/129/s966/summary.md`）と onsa-advisor の段 1 が親の読みと一致し、段 2 は省いた。利用者が ID を挙げて了承）: (1) 読む。定数式でない形（ブロック、`if`、`match`、閉包）の中の名前は、本体の普通の式と同じく名前の段が先に読み、名前の誤り（E0302・E0308）が先に出る（§18.1 の段の順）。本体の歩き手が読まない形（`unsafe`・`handle`、flow の本体の文を含むブロック・閉包・`?`・`move`）は今のまま中を読まない（定数式に固有の規則を増やさない）。形の中の E0304 の名前は使う所の診断でなく、形の誤り E0417 が出る。共通の規則: 定数式の名前は、名前の段が普通の式と同じ歩き手で読む（名前の誤り E0302・E0308 は位置によらず先、§18.1）。型の段の読み手は「葉は型で、節は文法で」判定する。葉（リテラルと名前の鎖）は、定数でない値（ローカル、関数、列挙子、値のフィールド）が E0417、定数式だが型が期待型でないもの（期待型でない定数、整数でないリテラル `1.5`・`true`・`"s"`）が E0401。節（子を持つ形）は、`+ - * / %`・前置 `-`・括弧の外の形（比較・論理・ビットの演算子、`as`・`!`・`?`、添字、呼び出し、値のフィールド、タプル・配列・struct リテラル、ブロック・`if`・`match`・無名関数、`unsafe`）を、子の型と中身を見ずに位置によらず E0417。節を子に依らせないのは、`(1, 2)` を型で E0401 にすると `(g(1), 2)` の中の呼び出しの E0417 が先になり、同じ形でもコードが変わるため。 仕様 §4.5 に書いた。実装は今の形（W5-16 U1a）のまま。
- 経緯: 129 回目（2026-11-09）、W5-16 U1a の壊す側が見つけた。S-966 と同じ流れで決めた。
