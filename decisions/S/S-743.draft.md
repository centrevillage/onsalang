# S-743 E0302 の `use` の候補（§15.1）が、見出しで止まった単位の本体の束縛と同じ名前の `use` を足し、当てた後に E0304 になる形（候補の条件に、単位の束縛と重ならないことを加えるか）

- 決定済みで戻さないもの: 引数と同じ名前の頭の E0308（S-741）、引数とローカルの E0304（S-717）、循環の条件（§15.1）。
  第 71 組の下書きの「S-743 の仕組みの出所」と「S-743 の形の表」の節（写しは `target/notes/79/g71/draft.md`）。
- 論点: §15.1（62 行）は、`use` を足す候補を「当てた後の経路が名前の段で最後まで解決し、足す `use` が循環を閉じないときだけ出す」とする。足す名前と同じ名前の引数とローカルがモジュールにあると、当てた後にそれらが E0304（§5.1）になる。
  この E0304 は触れていない単位に出るので §18.1 の約束の外だが、候補が新しい名前の段の誤りを生み、修復のループがもう一回回る。候補の条件に「束縛と重ならない」を加えるかが書かれていない。
  空白の題は見出しで止まった単位の本体の束縛を挙げるが、形の表のとおり、本体の途中で止まった単位、誤りの無い別の単位、自分のパッケージ名を外す候補、`use` の頭を直す候補も同じ形である。
- 今の実装: 形の表のとおり。候補は引数とローカルを見ずに出る。当てた後の E0304 には候補が無く、ループは `no-candidate` で止まる。
- 案: 
  - (a) 今のまま。候補の条件に束縛を入れない。当てた後の E0304 は次の検査で報告する（§15.1 に「足す名前と同じ名前の引数とローカルは、当てた後に E0304（§5.1）」の一句を書くかは任意）。
  - (b) E0302 の単位の引数とローカル（名前の段が歩かなかった本体を含む）に、`use` が束縛する名前と同じものがあれば候補を出さず、note で正しい形と重なる束縛を示す。
  - (c) (b) の範囲をモジュールの全ての単位に広げる（別の単位の束縛、`use` の頭を直す候補も含む）。
  - (d) 候補は今のまま出し、当てた後に重なる束縛の位置を note で示す。
  - 形ごとの出力: 同じ単位の本体の `let` は、(a) が候補あり、(b)・(c) が候補なしで note、(d) が候補と note。別の単位の束縛と `use` の頭を直す候補は、(a)・(b) が候補あり、(c) が候補なしで note、(d) が候補と note（(d) の範囲もモジュールの全体にするかを決める）。
  - 書き手から見て: どの形も、書き手のプログラムには「`use inner` が要る」と「ローカル `inner` がモジュールの名前と重なる」の二つの直しが要る。後者の直し方（ローカルの名前）は書き手しか決められない。
    (a) は検査が三回（候補を当てる、E0304 でローカルの名前を変える、確かめる）。(b)・(c) は E0302 に候補が無く、note が重なりも示せば二回、示さなければ三回。(d) は候補を当てながらローカルも直せば二回で、候補だけを当てる道具は (a) と同じ三回。
    (a) では、E0304 の note が `use inner` の位置を指すので、書き手がローカルでなく `use` を消して元の E0302 に戻るおそれがある（E0304 の文面は「束縛では隠せない」と言う）。
  - 修正候補: どの案も当て続けて止まる（(a)・(d) は E0304 の `no-candidate`、(b)・(c) は E0302 の `no-candidate`）。`use inner` の追加は経路の頭から意図が一つに決まり、ローカルの改名は決まらない。
  - 通るプログラム: どの案も変わらない。変わるのは候補と note だけである。
  - 規則と例外: (a) は 0（任意の一句）。(b) は候補の条件を一つ足し、範囲を単位に限るので、別の単位の束縛と `use` の頭の候補では同じ重なりが残る（条件が形の一部にしか効かない）。(c) は条件を一つ足し、§15.1 の三つの候補（`use` の追加、頭を外す、`use` の頭を直す）に当てる。(d) は note の内容の一句。
  - 実装の量（名前の段）: (b)〜(d) は、名前の段が歩かなかった本体の束縛を知るため、単位（(c)・(d) はモジュール）の構文木から束縛の名前（`let`・`var`、パターン、引数、無名関数の引数、`for`、flow の入力）を集める歩き手が要る。
    (b) は約 +15〜25 行、(c) は約 +20〜35 行（`free_in_body` を呼ぶ `body_fix` と、`imports.rs` の `use` の頭の候補に条件を足す）、(d) は約 +20〜35 行。(a) は 0 行。後の段への手当てはどの案にも無い。第 2 期に束縛を作る構文が増えると、(b)〜(d) の歩き手も増やす。
- 他言語: rustc 1.94.1（`probe/other/s743.rs`）: 別のモジュールの中の `fn h(_x: inner::T) -> i32 { let inner = 1; inner }` は E0433 と「consider importing this module: `use crate::inner;`」で、当てた形（`s743b.rs`）は通る。
  Rust はモジュールとローカルの名前空間を分け、ローカルがモジュールの名前を隠せるので、この重なりが起きない。Python・TypeScript・Swift の道具の import の候補は未確認。
- 推奨と理由: (a)。確度: 中。
  - 重なりは書き手のプログラムにある別の誤り（モジュールと同じ名前のローカル）で、`use` の追加は経路の頭から意図が一つに決まる正しい直しである。候補を出さなくても、書き手は同じ二つの直しをしなければならず、ループの回数はほとんど減らない。
  - 約束（§18.1）は既に満たされ、条件を足すには歩かなかった本体の束縛を集める仕組みが要る。(b) は単位に限ると同じ重なりが別の単位と `use` の頭の候補に残り、規則が形の一部にしか効かない。(c)・(d) は全てに効くが、仕様が約束しない改善のために束縛の歩き手を足し、束縛の構文が増えるたびに手当てが続く。
  - あわせて決めること: §15.1 に「足す名前と同じ名前の引数とローカルは当てた後に E0304（§5.1）になり、候補の条件に入れない」の一句を書くか（書けば修復のループの使い手が二回目の誤りを予期できる。書かなくても挙動は同じ）。
  - 別の S にしてよい論点: E0304（ローカルが `use` の束縛と重なる）の note に、ローカルの名前を変えるよう示す文を足すか（`use` を消して戻るおそれへの手当て。E0304 の文面の細部で、約束しない）。
- 影響: (a) は仕様の変更が無いか §15.1 の 62 行に一句、実装は 0 行。(b)〜(d) は §15.1 の 62 行の条件か note の文、名前の段（`names/lookup.rs::body_fix`、`names/imports.rs` の `use` の頭の候補、束縛の歩き手）で、置き場所は名前の段の残りを受ける W4-18 の見込み。
