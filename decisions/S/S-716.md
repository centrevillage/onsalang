# S-716 使われない束縛の名前が §2.3 の形に反するとき（`let _x = 1` を読まない）、E0320（候補 `x`）と E0309（候補 `_`）のどちらを報告するか

- 空白: §2.3 は「`let _x = 1` は束縛で修正候補は `x`」（E0320、S-648）とし、§5.1 は一度も参照されない `let` の束縛を E0309（候補は名前を `_` に変える形、S-129）とする。
  読まない `let _x = 1` は両方に当たり、どちらも名前の段で、位置も同じ名前である。仕様はどちらを報告するかを決めていない。今の driver は同じ段・同じ位置ならコードの順で選ぶ（`onsa_driver/src/reduce.rs`）ので、何もしなければ E0309 になる。
  読み: (1) §2.3 に反する名前の束縛は E0309 の対象から外し、E0320 を報告する（当てた後の `let x = 1` で E0309、二回目に `let _ = 1`）。(2) E0309 を報告する（一回で `let _ = 1`。§2.3 の例は読まれる `_x` の形に直す）。
  今の実装は E0320 だけ（E0309 は W4-04 で実装する）。再現は 75 回目の scratchpad の `w404-advisor/probe/unused_underscore.onsa`。
- 決定: 決定（2026-10-27、利用者が ID を挙げて了承。76 回目、第 66 組。A1 は確認だけ）: (b)。使われない束縛の名前が §2.3 の形に反しても（読まない `let _x = 1`）、E0320 より先に E0309 を報告する（修正候補は `_`）。
  E0309 の位置は使われない束縛の名前（選択のパターンでは最初の位置）で、同じ位置の E0320 より §18.1 の並べ方（コードの順）で先になる。flow の本体の E0309 は flow の検査の段（S-129）なので、そこでは E0320 が先である。E0309 の note で、頭の `_` は名前の一部で値を使わない印は `_` だけであることを示す（文面の細部で、約束にしない）。
  仕様は §5.1 と §2.3 の例の括弧、`tasks/diag-codes.md` の E0309 の行に書いた。実装は W4-04 の U7b。今の事例 `tests/spec/negative/naming_leading_underscore.onsa` の読まない 3 件（43・48・54 行）は E0309 に変わる（U7b で直す）。
- 経緯: 75 回目（2026-10-27）、W4-04 U1 の設計メモの審査（onsa-advisor）が指摘し、親が dev `65a1073` のバイナリで今の E0320 を確かめた。期限は W4-04 の使われない束縛の単位の前。
  関係: S-648、S-129、S-714。
