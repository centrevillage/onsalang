# S-719 宣言がこの版の E0200 の利用者の trait と効果の名前（`trait Tr`・`effect Ef`）を、型の位置・値の位置・経路の頭に書いたとき（今は黙る）と、境界・効果行に書いたとき（今は E0200）の扱い

- 決定済みで戻さないもの: 宣言そのものの E0200（第 2 期）と、`pub trait Show` の E0200 だけ（S-712）。`impl Tr for P` と `handle … with` は形の E0200（S-713）。flow の本体の `Tr~(x)` の E0812（S-590）。
  第 66 組の下書きの「S-719 の仕組みの出所」と「S-719 の形の表」の節（写しは `target/notes/76/g66/draft.md`）。
- 論点: §18.1「誤りのある宣言も、名前まで読めれば名前解決に見せる」と、§15.1「名前は見つかったが、その位置に要る種類…でなければ、位置によらず E0308」「E0200 は、要る種類の名前でこの版が扱えないもの（この版が扱えない効果、利用者の trait の境界）に限る」。
  宣言が E0200 の `trait Tr` と `effect Ef` の名前を、見つかった名前（宣言のキーワードから種類が分かる）と読むか、失敗した名前と読むかが書かれていない。今は型・値・経路の頭で黙り、境界と効果行で E0200 になる（どちらとも違う形）。
  prelude と同じ名前の宣言（`pub trait Show`）では、使う所がどちらの `Show` を指すかも書かれていない。
  - この組の外: 宣言が E0200 の handler の名前と extern のブロックのメンバの名前は S-721（後の組）。
- 今の実装: 表のとおり。境界の E0200 は名前の種類を見ず、`T: Ef` でも「user-defined traits」と言う。効果行の E0200 は `uses {Tr}` でも `Tr` を効果と言う。
- 案: 
  - (1) 宣言のキーワードの種類（trait、効果）で見つかった名前として読み、S-713 の規則を当てる。宣言のメンバ（trait のメソッド、効果の操作）は読めなかった部分で、使う所は黙る（値の位置では、§18.1 の失敗した名前の値の位置と同じく、その単位の以後を検査しない）。
  - (2) 宣言が E0200 の名前を失敗した名前に入れる（§18.1 の E0200 の `pub use` の名前と同じ）。全ての位置で黙る（境界は未知の境界、効果行は開いた行）。§15.1 の E0200 の例「利用者の trait の境界」は、この版で出なくなるので消す（S-713 の文を改める）。
  - (3) 今の形を規則にする: 境界と効果行は名前の種類によらず E0200、他の位置は黙る（構造体のリテラルとパターンは今のコード）。第 2 期に宣言を入れるときに (1) の形に揃える。
  - 形ごとの出力:

    | 位置 | (1) | (2) | (3) |
    |---|---|---|---|
    | 型・値・`impl` の対象・リテラル・パターン（`x: Tr`、`let a = Ef`） | E0308 | 黙る（値の位置とパターンは単位の以後を検査しない） | 黙る（リテラルは E0401、パターンは E0302） |
    | `Tr.y()`・`Tr.tm(p)` | E0308（trait は名前空間でない。`Show.show(1)` と同じ） | 黙る | 黙る |
    | `Ef.op()`・`Ef.y()` | 黙る（メンバは読めなかった部分） | 黙る | 黙る |
    | `T: Tr`・`uses {Ef}` | E0200 | 黙る | E0200 |
    | `T: Ef`・`uses {Tr}` | E0308 | 黙る | E0200（名前の種類を誤って言う） |

  - 書き手から見て: 例として、Swift の書き手が `trait Shape { … }`、`fn total(s: Shape)`、`fn sum[T: Shape](x: T)` と書く（Swift はプロトコルを型として書ける）。
    (1) は一回の検査で、宣言の E0200、`s: Shape` の E0308（trait は型でない、版によらない）、境界の E0200 を並べる。(3) は `s: Shape` が黙り、宣言を消した後に E0302「cannot find」になる。
    (2) は宣言の E0200 だけで、消した後に二つの E0302 になる。E0302 は「名前を足すか綴りを直す」の直し方で、名前が在った誤りの直し方と違う。
  - 修正候補: どの案も、新しく出る E0308 と E0200 に候補は無い（S-713 と同じ）。当て続けても `no-candidate` で止まる。
  - 規則と例外: (1) は S-713 の規則と §18.1 の文のままで、新しい規則は無い（メンバを読めなかった部分とするのは「中の名前を読まない」の読み）。(2) は失敗した名前の集まりに一項を足し、§15.1 の例を改める。(3) は「宣言が E0200 の名前」の例外を一つ足す。
  - 実装の量（U8 の `kind_error(entity, want)` を置き場所とする）: (1) は `names/collect.rs` が E0200 の trait と効果に種類を持たせ（`DefKind::Unsupported` に種類の欄、`Unsupported` を見る約 10 か所は形だけ変わる）、型と値の位置はそれを `kind_error` へ回す。
    境界と効果行は、S-713 で分ける E0308 と E0200 の枝の E0200 の側に入れる。約 +15〜25 行。
    (2) は名前の引きが `Unsupported` を失敗した名前として返し（`names/imports.rs` の 387 行と同じ形）、境界と効果行の E0200 を外す。約 +5〜10 行。(3) は `kind_error` が `Unsupported` を飛ばし、境界と効果行の今の枝を残す。約 +5 行。
  - 第 2 期に trait と効果の宣言を入れるとき: (1) は種類の欄が本物の宣言に替わり、境界と効果行の E0200 が消える（機能を開く作業そのもの）。使う所の E0308 は変わらない。
    (2) は失敗した名前の項を外し、全ての位置の出力が黙りから E0308 や通るに変わる。(3) は例外を外し、型・値・経路の頭の出力と `T: Ef` の文面が変わる。どちらも、その位置の事例を直す。
  - 細部（どの案でも決める）: prelude と同じ名前の宣言（`pub trait Show`）の後の使う所（`T: Show`、`x: Show`）。
    (p1) どちらの `Show` も引かず黙る（今の実装）。S-675 の E0304 になった名前の扱い（使う所はどちらの宣言も引かない）で、今の実装でも `pub trait Show` は E0304 になった名前として扱われ、その E0304 が同じ単位の先の位置の E0200 に隠れている。
    (p2) 利用者の宣言として、上の案で読む（(1) なら `T: Show` が E0200、`x: Show` が E0308）。
    (p3) prelude の trait を指す（`T: Show` が通る）。
    費用: (p1) は足すものが無い。第 2 期に宣言を入れると、`pub trait Show` は E0304（S-611）になり、S-675 の扱いで使う所は黙るので、出力は変わらない。
    (p2) は引きが同じ名前の prelude より宣言を先にする枝（約 +5 行）。(p3) は引きが同じ名前の宣言を飛ばす枝（約 +5 行）。どちらも第 2 期に宣言が E0304 になると、使う所の出力が黙りに変わり、その事例を直す。
- 他言語: rustc 1.94.1（`probe/rs/t.rs`、edition 2021）: trait を型の位置に書く `fn f(x: Tr)` は E0782「expected a type, found a trait」、値の位置の `let a = Tr` は E0423「expected value, found trait `Tr`」。
  Swift 6.3.1（`probe/rs/t.swift`）: プロトコルを型の位置に書く `func f(x: Tr)` は、`-swift-version 6` でも診断なしで通る（存在型）。読みが言語で割れる形である。
- 推奨と理由: (1)。確度: 中〜高。
  - 宣言の名前は読めていて、種類はキーワードで決まる。§18.1 の「名前まで読めれば名前解決に見せる」と S-713 の規則をそのまま当てる形で、規則が増えない。§15.1 の E0200 の例「利用者の trait の境界」も、この読みを前提にしている。
  - 型の位置の `x: Tr` は、trait を型として書ける言語の書き手が書きうる形で、版によらない誤りである。(1) はそれを最初の検査で示す。(2)・(3) は宣言を消した後の E0302 に回し、直し方の違うコードで示す。
