# S-675 族: §15.1 の E0304 の報告する側と残す側

- 空白: §15.1 は E0304 になる組（同じ名前の空間の中の二つの名前）を決め、§11.2 は E0305 を「ソースの順で後の宣言に付け、前の宣言を note で示す（E0304 と同じ）」とする。§18.1 は「誤りのある宣言も、名前まで読めれば名前解決に見せる」とする。
  E0304 の組のうち、どちらに付けるか（報告する側）と、使う所と他のモジュールの経路がどちらを引くか（残す側）を、組ごとに書いていない。W4-03 の単位（64 回目、親）は、引く順で残す側を決め（本体の空間は prelude・組込み型 → 項目 → `use` の束縛、名前空間は子モジュール → 項目）、項目と `use` の組は書いた順によらず `use` の側に付けるとした。
  族の規則の案: 報告する側と残す側を一つの規則で決める（例: 報告は後の宣言、残すのは先の宣言。または、組の種類ごとの決まった順）。この族の S: S-676（項目と `use` の組の報告する側）、S-677（項目と子モジュールの組の残す側）。
- 決定: 決定（2026-10-25、利用者。67 回目、第 59 組。残す側は (B) として例と今の実装 (b) との比べを示して (d1)、報告する側と細部は ID を挙げて確認だけで了承（A1・A5〜A8））: 報告する側は今の実装のまま、残す側は (d1)。
  報告する側（A1）: 片方がソースの外の名前（prelude、組込み型、組込みの flow の名前、子モジュール、依存のパッケージ名）ならこのモジュールの宣言、項目と `use` の束縛なら書いた順によらず `use`、同じ種類の二つならソースの順で後の宣言に付け、もう一方を note で示す。
  残す側（(d1)）: どちらも残さない。E0304・E0305 になった名前は、その空間（本体、モジュールの名前空間、経路の頭、S-611）で S-462 の誤りの名前の集合に入れ、使う所と他のモジュールの経路に診断を出さない。報告しなかった側の宣言の単位は検査する。
  細部: 組込みの flow の名前と重なった名前は、本体の空間の全体で黙る（flow の本体に限らない、A6）。ルート直下のモジュールと依存のパッケージ名の重なりも族に入れ、経路の頭のその名前は黙る（A7）。項目どうし・`use` どうし・項目が先の組の位置と note は今のまま、`interface` の見出しと LSP の飛び先は S にしない（A8）。ローカルの E0304 は §18.1 の単位の規則で閉じる（S-681、A5）。
  仕様は §15.1 の E0304 の段落（報告する側の一文）、§18.1 の S-462 の段落（E0304・E0305 の名前の一文）、§11.2 の括弧書き（同じ種類の二つの E0304 と同じ）。実装は W4-03 の U3b（S-462 の集合に乗る、約 +20〜35 行と事例 5〜6 件）。
- 経緯: 66 回目（2026-10-25）、W4-03 U3a1 のテストの票（onsa-test）が見つけた。関係: S-611、S-17、R-177、S-666。
- 補い（2026-10-25、親）: W4-03 U3a1 の壊す側（66 回目）: prelude・組込み型の名前の項目と `use` の E0304（`struct F32`、`enum Option`、`type Bytes = U8`、`use m.{Span}`）の後、使う所は残す側の prelude を引くので、E0401（`F32` is not a struct）や E0302（`Option` takes 1 type argument）が続く。
  前からの連鎖に E0304 が加わった形で、§18.1 の偽の連鎖を出さない約束と緊張する。再現は `P66/w403/u3a/b/cases5.py`（写しは `target/notes/66/w403/u3a/b/`）。
