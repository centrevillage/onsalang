# S-825 既定の値を書いた `main_frame = "stack"`・`memory.bulk = false` も E0200 か

- 空白: §15.3 は未対応のものを「使った位置で E0200」とし、E0200 の閉じた一覧（`tasks/diag-codes.md`）は「`main_frame`」「ターゲットの `memory.bulk`・`fast_budget`・`bulk_budget`」をキーで挙げる。
  既定の値を書いたとき（`main_frame = "stack"`・`memory.bulk = false`）も E0200 かを書いていない。読みは (1) キーを書けば値によらず E0200 (2) 既定と違う値だけ E0200（既定の値は今の動きと同じ）に割れる。
  今の実装は `main_frame` を読んで捨て、`static` も黙って通る（R-166、`target/notes/95/w402/probe/` の `a12_main_frame`）
- 決定: 決定（2026-11-01、利用者が ID を挙げて了承。95 回目、第 77 組）: (b)。既定の値を書いた項目（`main_frame = "stack"`、`memory.bulk = false`、中身の無い `bind`）は E0200 にしない。E0200 の一覧は値で書く（`main_frame` の `"static"`、`memory.bulk = true`、中身のある `bind`、`fast_budget`・`bulk_budget` の値）。
  理由: 既定の値はこの版の動きと同じで、黙って無視されるものが無い。`fp = "strict"`・`provides = []` が通るのと揃い、「既定の値はどのキーでも通る」が一様になる。後で対応しても通っていたものは止まらない。仕様 §15.3 の 166 行、`tasks/diag-codes.md` の E0200 の行
- 経緯: 95 回目（2026-11-01）、W4-02 の設計メモ（onsa-impl）が見つけた。急ぎ: W4-02 U3 の前
