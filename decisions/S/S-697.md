# S-697 struct リテラルで、書かないフィールドを既定値で埋める構文（見えないフィールドを持つ struct を、他のモジュールでもリテラルで作る）

- 空白: struct リテラルは全てのフィールドを一度ずつ書く（過不足は E0410、§4.4）。見えないフィールドを持つ struct は、そのフィールドが見えない場所ではリテラルで作れず（E0303）、作る関数を通す（§15.1）。
  既定値は trait `Default` だけで（derive は各フィールドの既定値を並べる、§6.4）、書かないフィールドを既定値で埋める構文は無い（`Q { x: 1, ..Q.default() }` は今 E0002）。
  そのため、`priv` のフィールドを一つ持つ struct は、他のモジュールでは全てのフィールドを作る関数の引数で渡すことになり、扱いづらい。
  ```onsa
  pub struct Ring: Default { data: [F32; 4], priv head: U32 }
  // 他のモジュール: Ring { data: …, head: 0 } は E0303。Ring { data: [0.0; 4] } も §15.1 の文ではリテラルで作れない
  ```
- 論点（親の見立て。下書きの前の控え）: 構文の形（残りを埋める印か、元の値の式か）。既定値の出所（型の `Default` か、フィールドごとの宣言か）。
  見えないフィールドを他のモジュールから既定値で埋める範囲は利用者が確かめた（経緯）。検討では、§15.1 の不変条件を守るために隠すという理由との関係を説明する。フィールドを足したときに、書き忘れが黙って既定値になること（§7 のパターンが `..` を持たない理由と同じ懸念）。
  他言語（手元の rustc 1.94.1、2026-10-26）: Rust の `Ring { data: …, ..Ring::new() }` は、`head` が非公開なら E0451 で、非公開のフィールドを元の値から埋めることも許さない。省いた形は「cannot construct `Ring` with struct literal syntax due to private fields」。
- 利用者の案（70 回目、2026-10-26。下書きと独立のレビューの前の材料。伏せる段では伏せる）:
  ```onsa
  struct Item {
    x: U32,              // 既定値の無いフィールドはリテラルで省けない
    y: F32 = 0.0,        // フィールドの宣言に既定値を書く
    z: F32 = CONST_VAL,
  }
  let v = Item { x: 1, ... }          // 書かないフィールドを既定値で埋める
  let Item { x: a, _ } = v            // パターンで残りのフィールドを捨てる（`_` は最後）
  let Item { z: c, x: a, _ } = v      // 途中を省くのと、順の入れ替えは許す
  ```
  - 既定値の式は `const` の初期化式の規則（§6.6）に揃える（効果行が空か `{Alloc}` の関数だけ、結果は静的に配置できる型で違えば E0407、評価の panic は E0419）。コンパイル時に一度だけ評価して焼き込み、リテラルを書いても実行時の副作用は起きない。
    `Buf` は静的に配置できないので既定値を持てない。Shared を含む型は、この版の `const` と同じく第 2 期。
  - `...` で全てのフィールドを書いた形と、`...` の後に既定値の無いフィールドが残る形は誤り。残るフィールドの無い `_` も冗長で誤り。
  - パターンの `_` は §7 の「フィールドを足したとき、全てのパターンが落ちるようにする」を見直す（書き手が `_` を選んだパターンは落ちない）。
  - `priv` のフィールドに既定値を書くのは、外から既定値で作ってよいという struct の設計の側の選択。外から作らせたくなければ既定値を書かない（Rust・C++20・Swift はどれも許さない、論点に書いた）。
  - 総称のフィールド（型引数に頼る型のフィールド）の既定値は、一旦なしで考える。
  - derive の `Default` は宣言した既定値を使う（同じ回に利用者が (i) を選んだ）。既定値を書いたフィールドは型の `Default` を要らず、既定値の無いフィールドは今のとおり型の `Default`（無ければ E0416）。`...` は宣言した既定値だけを使い、trait の `Default` は呼ばない。
    手で書いた `impl Default` はそれが `T.default()`。Rust の nightly も derive が宣言した既定値を使う（手元の rustc で確かめた）。
- 決定:
- 経緯: 70 回目（2026-10-26）、W4-03 U4a で、他のモジュールの struct リテラルが見えないフィールドを省いた形を E0303 とする読みを確かめたときに、利用者が「リテラル使用時に、明示されてない値をデフォルト値で埋める構文が欲しい。priv フィールドを含む struct がとても扱いづらいものになってしまうので。入れる時期はともかく、検討対象として追加したい」と言った。
  時期は同じ回に決めた: W4 を終えた区切り（W4-18 の見直しの前後）で空白の流れに回し、期限は W5-06（`default()` の降下を作る作業より前に、埋める形を決める）。入れる作業は決めるときに割り当てる（第一の候補は W5-06）。
  案の範囲（利用者が確かめた）: 書いたフィールドはその値、書かないフィールドは既定値で埋め、他のモジュールから見えない `priv` のフィールドも既定値で埋まる。埋める印の形と、既定値を定義する構文は、検討のときに決める。
  同じ回に利用者が足した: struct のパターンで残りのフィールドを無視する印も、このリテラルの印と対で検討する（見えないフィールドを残すパターンは今 E0303、S-366 の補い）。表記（`..`・`...`・`_` など）は検討のときに具体的に決める。
