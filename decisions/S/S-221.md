# S-221 入れ子の深さの数え方

- 空白: 入れ子の深さ（§2.5、E0006）の数え方の細部: どのノードを 1 段と数えるか（`a.b()` のメンバと呼び出し、`if` 式とその本体のブロック、`else if` の一つの連鎖、型引数の並び、引数の並び、リテラルの要素、`match` の腕、パターン、無名関数）、数え始め（宣言ごとか、本体のブロックを何段目とするか）、E0006 の主の位置、閉じない括弧が 257 個を超えるときの E0002 との順、fmt が冗長な括弧を外す前と後のどちらで数えるか。
  W3-14/t で見つけた（2026-10-08）
- 提案: (a) を規則の形で書く。宣言の単位ごとに 0 から数え、式・型・パターンの形とブロックを一段、名前・リテラル・`_`・並び・文・宣言の見出しは数えない。二項演算子の連鎖は §3.1 の木の高さ。補間の穴は名前の経路を式に書いたときと同じに数える（Fable の入れ子の例は §2.4 で書けないので、推奨を改めた）。
  書かれたソースで数え、主の位置は最初に 256 を超えた形のトークンで、その単位の読み取りを止める（仕様 §2.5。2026-10-08 決定。利用者の方針: 一貫して環境でずれなければ、処理しやすい方法でよく、表の管理を軽くする。実装は W3-14（`Parser::height` で `NodeKind` をワイルドカードの無い `match` で 0 / 1 に、連鎖は W3-07 と同じ強弱の表）。腕の多い `match` を連鎖に降下しないことは W8-06 の設計メモで確かめる）
