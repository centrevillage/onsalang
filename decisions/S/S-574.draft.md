# S-574 境界の入出力の別のレート（`sample / N`・`sample * N`）

- 決定済みで戻さないもの: 組の全体は S-570 の下書きの頭（第 33・34 組で決めた §19.1 の三つの項、S-565 の R12、§14.2 の C の API の原則）。
- 論点: §19.1「境界（export）の入出力の `sample / N`・`sample * N` は、第 35 組まで E0810」。§19.1「`sample / N` の刻みはカウンタが N の倍数の刻みで…ホストの区切りに依らない（ホストのブロックの長さを 2^N に揃える必要は無い）」。§14.2「全てのチャンネルが一つの `frames` を使う」。
  - 範囲は一番外の flow（export する flow、Onsa のコードから `process` で呼ぶ flow）だけで、中の flow の変換の入出力（S-566、S-567）は決定済み。
  - (1) E0810 のままにするか、生成する API と C の API の形（入出力ごとの長さ、`frames` が N の倍数でないとき）を決めるか。(2) 形を決めるなら、位相のカウンタとの関係と `render` の長さ。
- 今の実装: `x: F32 at (sample / 32)` は E0002「expected the name of a clock, found `(`」（`q06`。`at (` を今の構文解析器が読まない）。`sat~(x).up~(2)` は E0812 で、修正候補は `~` を外す形（`r11`。修飾子は未実装）。
- 案:
  - (a) E0810 を第 1 期の規則にする（「第 35 組まで」を外す）。一番外の flow の入出力のクロックは `init`・`block`・`sample`・イベントだけ。遅い値は `-> F32 at sample` の保持で出し、全体が制御のレートの flow はホストが `sample_rate / N` で `init` する（S-565）。
    誤りの位置は、その flow の `process`・`process_inplace`・`render` を使う所と `[export]` の項目。`init`・`reset`・`State` は使える（`.down~` で中に置く変換の flow のため）。
  - (b) `sample * N` だけを開く。入出力のバッファは `N × frames` で、長さはいつも決まる（位相に依らない）。用途は、ホストが既にオーバーサンプリングした信号を渡す場合。
  - (c) 両方を開き、`sample / N` のバッファの長さを、その呼び出しの中の遅い刻みの数にする（位相のカウンタで決まり、呼び出しごとに変わる）。ホストは呼び出しの前に数を問い合わせる関数（`<p>_slow_len(s, frames)` など）を呼ぶ。費用の要因: ホストに位相が漏れ、§14.2 の一つの `frames` の原則が崩れる。
  - (d) 両方を開き、`frames` を N の倍数に限る（違えば 2）。長さは `frames / N`。費用の要因: パラメータの変化で呼び出しを分ける形（S-565 の R12）と、S-570 の区切りが、その flow では N の倍数でしかできない。
  - コード: (a) は言語の規則なので E0810（境界の形の誤り。struct の `sample` の入力、入れ子の配列と同じ）。(b)〜(d) を選んで実装を後にするなら、それまでは E0200。
- 他言語: CLAP（`process.h`）の `frames_count` と VST3 の `ProcessData::numSamples` は、全てのポートに一つである。Cmajor の一番外の processor の周波数とホストのレートの関係は未確認。
- 推奨と理由: (a)。確度: 中〜高。
  - プラグインのホストは全てのポートに一つのフレームの数を渡すので、(b)〜(d) が役に立つのは自作のホストだけである。(c) は位相をホストに見せ、呼び出しごとに長さが変わり、ラッパーと `render` を複雑にする。(d) は区切りの自由（決定性の約束を区切りに依らせない前提）を崩す。(b) は長さが決まるが、使う実例が無い。
  - (a) から (b) へは後で開いても今のプログラムを壊さない。E0810 は既に境界の形の誤りのコードで、新しいコードは要らない。
  - 決定性と区切り: (a) では境界の入出力が全て `sample` なので、§19.1 の位相のカウンタの約束（区切りに依らない）がそのまま当たる。
  - あわせて決めること: E0810 の note で、中に `.down~(N)` の部品を置き、一番外を `sample` にする書き方を示す。
- 影響:

  - 診断のコード: E0810（範囲と note）。
  - 作業: E0810 を出す所（生成した API の名前を引く所と、W10-01 の export の計画）、W7。`render` の長さは今のまま。
