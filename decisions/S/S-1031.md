# S-1031 族: 関数型の向きのある互換（効果行の包含、`rt` の向き）が当たる範囲。期待する型が一つに決まらない所（`if`・`match`・配列の合流、型変数の推論 `pick(r, k)`）と型引数の中（`Option[F]` を `Option[G]` の位置へ）

- 空白: §8.1 の関数型の互換（規則 2 の効果行の包含、規則 3 の `rt` の向き）は「関数 F を、関数型 G を期待する位置（引数、注釈付きの `let`、返り値、struct のフィールド）」で使える条件を定め、期待する型が一つに決まらない所と、型引数の中の関数型を書かない。
  当たる形: (a) 期待する型の無い合流。`let f = if c { k } else { b }`（`k` は純粋、`b` は `uses {Alloc}`）、`match` の腕、配列 `[k, b]`。§4.7 は後の枝の期待型を前の枝の型とする。`rt` は第 80 組の決定（W6-01 の持ち越し）で「`rt` を落とした関数型」に合わせるとしたが、§4.7 にも §8.1 にも文が無く、効果行は決めていない。
  (b) 型変数の推論。`pick(r, k)`（`pick[T](a: T, b: T)`、`r` は `rt`、`k` は `rt` でない）で、先の引数で `T` が決まり後の引数を向きで比べると、引数の順で合否が変わる（`pick(k, r)` は通り、`pick(r, k)` は E0401。S-1010 の `FixedStr` のリテラルは左から決まる先例）。注釈の無い無名関数の返り値の推論（`return r` の後の末尾の `k`）、入れ子の合流（`if c { Some(r) } else { Some(k) }`）、`var f = r` の後の `f = k` も同じ族。
  (c) 型引数の中。`let o: Option[fn(U32) -> U32 uses {Alloc}] = opt_pure`（`opt_pure: Option[fn(U32) -> U32]`）、`Option[rt fn(U32) -> U32]` の値を `Option[fn(U32) -> U32]` の位置へ置く形。
  今の実装（dev `ea8d73f6`）: 単一化は向きの無い等しさで `rt` を見ない。(a) の効果行の違いは E0401（`m3`・`m4`・`m6`）、`rt` の違いは先の腕の型を取って通る（R-26 の族）。(b) の `pick(r, k)`、(c) の `Option[rt fn]` を `Option[fn]` へ置く形、`f = k` は通る。
  W6-01 の設計メモの案: U2a は一番外の期待する型の位置だけを向きのある互換にし、型引数の中と入れ子は `rt` を含めて等しさにする（(b)・(c) の今通る形の一部が E0401 になり、順で合否が変わる）。U2b は期待する型の無い合流の一番外だけを合わせる（`rt` を落とし、効果行はこの S の決定に従う）。
  読み: (1) 一番外の期待する型の位置と合流の一番外だけ（合流の効果行は和）。推論と型引数の中は等しさで、推論は左から決まる (2) 合流と推論は「合わせ」（効果行は和、`rt` は全てが `rt` のときだけ）で順によらない。型引数の中は等しさ (3) 型引数の中まで向きを通す（`Option` などで共変）。
  急ぎ: W6-01 の U2b（合流）の前。U2a は (1) の側で実装でき、後で (2)・(3) へ緩めても、その時に通っていたプログラムは止まらない。
