# S-582 プラグインのノートとボイス: ホストのノートと MIDI のイベントの写し方、ポリフォニー

- 空白: S-572（第 35 組）は、export の境界のイベントの型を `midi.Message`（MIDI 1.0 を `U32` に詰めた型）と `transport.Event` などにした。
  CLAP はノートを MIDI とは別のイベント（`CLAP_EVENT_NOTE_ON` など。`note_id`、ノートの表情）でも渡し、VST3 も `NoteOnEvent` などの構造で渡す。ボイスの割り当ては、§17.6 の例では Onsa のコード（`Poly`）が書く。決めること:
  1. ホストのノートと MIDI のイベントを flow のイベントの入力へ写す形（MIDI 1.0 へ変えるか、`note_id`・ノートの表情・MPE をどう扱うか）と、MIDI の出力。
  2. ポリフォニー: ボイスの割り当てを誰が持つか（利用者の Onsa のコード（§17.6 の `Poly`）をプラグインの入口にする形、ラッパーが持つ形、言語の機能）と、ボイスの終わりの通知（CLAP の `CLAP_EVENT_NOTE_END`）。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51・52 回目）: ホストのノートと MIDI は全て `midi.Message` に写し（CLAP のノートは MIDI 1.0 のノートオン・オフ、`note_id` と表情は捨てる）、`midi.Message` の入力ごとに一つのノートのポートを持つ。
  VST3 の CC・ピッチベンド・チャンネルプレッシャーは `IMidiMapping` の隠したパラメータで受けて MIDI に戻し、AU のターゲットで `midi.Message` の入力が二つ以上なら E0200。flow の `midi.Message` の出力は、CLAP の `CLAP_EVENT_MIDI`、VST3 はノートのイベントと `LegacyMIDICCOutEvent`、AU は MIDI の出力の block に写す。
  `transport.Event` の入力には再生の状態の変化を写す。ボイスの割り当ては export する flow が持ち、§17.6 の `Poly` は export できない。§17.6 は `Poly` の例を残してプラグインの入口の flow の例を足す（回答の (r2)）。仕様 §19.1
- 経緯: 第 36 組（プラグインの出力）の一つ。第 35 組（境界、S-570〜S-574）の決定の見込みの上に立ち、C の API がラッパーの要求を満たすかを W10 の前に確かめる。利用者が「VST/CLAP/AU用の出力は主要な機能の一つなので、今考えておきたい」「避けられる手戻りは前もって避けた方が良い」とし、出力の形まで決める範囲（(β)）を選んだ（2026-10-22、51 回目）。関係: S-570、S-571、S-572、§17.6。
