- 今の実装（表の外で確かめたこと）:
  - C の名前の重なり: パッケージに `voice.onsa`（`pub fn _f`）と `voice_.onsa`（`pub fn f`）を置くと、どちらも C の名前 `voice___f` になる。`onsa build --target host` は「the C compiler rejected the generated C … redefinition of 'voice___f'」の内部エラーで終了コード 101（`target/notes/62/gap52f/probe/cname/`）。
    §11.6 の「識別子に `__` は書けないので（§2.3）、利用者の名前と重ならない」は、経路の要素が頭か末尾に `_` を持つと成り立たない（`a_` と `.` と `f`、`a` と `.` と `_f` が同じ `a___f`）。
    重なる二つの経路は、どちらも要素の片側にだけ `_` を持つ（`voice_.f` は末尾だけ、`voice._f` は頭だけ）。重なりの条件は「一つの経路の中で、ある要素が `_` で終わり次の要素が `_` で始まる」ではなく、「ある要素の末尾の `_` と、別の要素の頭の `_` の両方を書ける」ことである（一つの経路の中で両方が続く `a_._b` は `a____b` で、それだけでは切れ目が一つに決まる）。
    片側の `_` しか書けない規則なら、区切りの `__` の前後の `_` の並び（`_` 3 つは末尾の `_` と区切り、の一通り）から切れ目が一つに決まる。

- 案: どの案も、形の定義を §2.3 で一度だけ書き、(1)〜(3) が同じ定義を使う。下の「芯」は、頭と末尾の `_` を除いた部分で、英字で始まり、`snake_case` は小文字・数字と語を区切る一つの `_`、`UpperCamel` は英字と数字（`_` なし）、`UPPER_SNAKE` は大文字・数字と語を区切る一つの `_` からなる。
  どの案でも `__` は S-149 のとおり E0320 なので、頭と末尾の `_` は付けても一つまでになる。`_` だけは名前でなく「値を使わない」印（§2.2）。「1 語」は (α)・(β)・(γ)・(ε)・(ζ) で外し、(δ) は残す。
  - (α) `_` は語の区切りだけ: 名前は芯だけ。頭と末尾の `_` はどの形でも書けない（`_x`・`x_`・`Point_`・`MAX_`・`_a.onsa`・`b_.onsa` は E0320）。
    S-243 を改める: 規則に揃えた名前が予約語になるときは候補を出さず、note で別の名前にすることを示す（§2.3 の S-243 の文を差し替える）。
    仕様: §2.3 に芯の定義の一文、S-243 の文の差し替え、表 B の所の読み（頭の `_` を飛ばした最初の字）の一文。§11.6・§14.2 は今のまま成り立つ。
    実装: `Shape::matches` を芯の判定に揃え（約 5 行）、表 B の 7 か所が使う判定を一つの関数にし（約 10 行）、S-243 の分岐を「候補なし」に替え（約 3 行）、「1 語」の腕を消す（約 20 行減る）。
    事例: `e0320_keyword.onsa`（`Match` の候補 `match_`）と `naming.rs` の単体のテスト（`match_`・`clock_`・`T_`）を改める。費用の要因: 予約語と同じ語の名前（`in`・`type`・`match`）を書く手段が無くなる。後で末尾の `_` を許しても壊れない。
  - (β) 頭と末尾の `_` を全ての形で受ける: 名前は、頭に一つの `_`、芯、末尾に一つの `_`（`_x`・`x_`・`_Point`・`Point_`・`_MAX`・`_T`・`_e` は通る）。字面で種類を決める所は、頭の `_` を飛ばした最初の字で決める（`_e` は効果行変数、`_x` は束縛、`_T` は型パラメータ、`_P {` は構造体）。
    S-243 はそのまま全ての形に当たる（`Self_` は通る）。`_0` のように芯が数字で始まる名前は、種類が字面で決まらないので書けない（E0320）。
    仕様: §2.3 に定義の一文と表 B の読みの一文。§11.6 と §14.2 の C の名前の写し方を改める必要がある（頭か末尾の `_` と区切りの `__` が続く形を別の綴りにする、または C の名前の重なりを誤りにする）。
    実装: `Shape::matches`（約 8 行）、表 B の判定の関数（約 10 行）、C の名前の写し方の変更か重なりの検査（約 20〜40 行、見積もり）。事例: R-260 の再現が通るようになる。
