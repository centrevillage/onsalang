# S-1076 細部: S-1065 で §5.4 の「破棄の要らないリテラル」の要素が「破棄の要らない値」（経路、`if`・`match`・ブロック式）に広がった後、§11.3 の flow の初期化に書ける値（「静的な値と破棄の要らないリテラル（§5.4）」）も広がるか

- 空白: §11.3 は flow の初期化に「静的な値と破棄の要らないリテラル（§5.4）」を書けるとし、これで flow とその初期化はヒープを使わないとする。S-1065 の D3 は「§11.3 の flow の初期化に書ける値は変えない」と書いたが、同じ決定で §5.4 の破棄の要らないリテラルの要素に破棄の要らない値（経路、発散しない末尾が全て破棄の要らない値の `if`・`match`・ブロック式）が入ったので、§11.3 の字のままでも書ける値が広がるように読める（`pick(Some(if c { "a" } else { "b" }))` の形）。
  どちらの読みでもヒープは使わない。誤りのあるプログラムか通るプログラムかが変わりうる（広がる読みなら今通らない形が通る）。今の実装は確かめていない。
  案: (1) 広がる（§5.4 の定義どおり。D3 の「変えない」は §11.3 の字のこと）。(2) 広がらない（§11.3 に要素の限りを書く）。仮の扱い: 今の実装を確かめて、その挙動を仮にする（W7 の区切りまでに）。
