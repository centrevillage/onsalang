# S-800 印を書いた引数（`inout x`・`move x`）の E0703 の位置（印を含む引数の頭か、被演算子か）

- 空白: 呼び出しの引数の印（`inout`・`move`）が宣言のモードと合わない E0703、構築子の要素の `inout` の E0703（S-792）、Dup の値に書いた `move` の E0703（S-609）の診断の位置を、仕様は決めていない（§5.2 は印と候補だけ、§18 は位置の一般の約束を持たず、§18.1 の 77 行は単位の診断を開始の位置の順に選ぶ）。
  修正候補はどちらでも印を消すか置き換える編集で、通るプログラムは変わらない（変わるのは CLI・LSP の列と、同じ単位の他の診断との選びの順だけ）。
  dev（`c867200`）は印を含む引数の全体を指し（`rd(inout n)` の `inout n`、`Some(inout x)` の 8 列）、W4-07 U3a の新しい modes は被演算子を指す（`n`、14 列）。
  新しい側は `tk(move n)`・`rd(inout n)`・`io(move n)`・`Some(inout n)` のどれも被演算子で揃う（親が `P88/bin/onsa-u3bwired` で確かめた。`target/notes/88/s800/marks.onsa`）。
  読み: (1) 印を含む引数の全体（書いたままの引数）。(2) 被演算子（印の無い引数の E0703・E0711 と同じ所）。
- 決定: 決定（2026-10-30、利用者。88 回目）: (2)。印を書いた引数の E0703（宣言のモードと合わない印、構築子の要素の `inout`、Dup の値の `move`）は被演算子を指す（`rd(inout n)` の `n`）。印の無い引数の E0703・E0711 と同じ所で、W4-07 U3a の新しい modes の形のまま。修正候補の編集は今のまま印を消すか置き換える。
  仕様の文は変えない（診断の位置は約束にしない）。W4-07 U4 のテストの票（t2）の事例 `ctor_inout_dup_clean.onsa` の `[[test.fix]]` の `at` を被演算子の列にする。
- 経緯: 88 回目（2026-10-30）、W4-07 U4 のテストの票（t2）の担当が空白として報告した（`tests/spec/negative/ctor_inout_dup_clean.onsa` の `[[test.fix]]` の `at` が要る）。親が二つのバイナリで再現して登録した。
