# S-344

- 空白: 強弱の無い群（剰余と加法など）が、木の中で被演算子として隣り合わない式（`a % b == c + d`、`x + 1 == y % n`、`a * b < c % d`）を E0010 にするか。
  §3.1 は「強弱の無い群どうしを括弧なしで混在させるとエラー（E0010）」とし、字面では一つの式に強弱の無い群が二つあれば誤りと読めるが、部分順序で読みが一つに決まる（`(a % b) == (c + d)`）。W3-07 の実装は木の辺（被演算子として直接つながる演算子どうし）で判定し、これを通す（`SPEC-GAP(S-344)`）。W3-07/t で見つけた（2026-10-09）
- 提案: 親の案: 木の辺で判定する形に §3.1 の文を明確にする（読みが一つに決まる式は誤りにしない）。後の段で確かめる
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R6）強弱の無い群の混在（E0010）は、一方の群の演算子の式が、強弱の無いもう一方の群の演算子の被演算子に括弧なしで直接なる形だけである。互いの被演算子でなければ誤りでない（`a % b == c + d` は `(a % b) == (c + d)`）。今の実装（木の辺で判定）のとおり。
  - 仕様の節: §3.1 の頭の段落に一文。
  - 今通るプログラムが変わるか: 変わらない（`a % b == c + d`、`x + 1 == y % n`、`a * b < c % d` は今も通る）。
  - 実装の見当: `onsa_syntax/src/groups.rs` の `SPEC-GAP(S-344)` の印を `§3.1` を指す注釈に改める（数行）。
  - ぶつかる既存の事例: なし。
