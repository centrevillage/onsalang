# S-553 候補の編集の範囲の中にあるコメント

- 論点: 仕様 §18.1「編集は、変えるトークンだけを置き換える最小の編集で、間のトークンとコメントを範囲に含めない（`<T>` を `[T]` にする候補は、`<` と `>` を置き換える二つの編集である）」。
  消す（か置き換える）トークンが並び、その間にコメントがあるとき、(1) 変えるトークンの間なのでコメントごと消してよいか、(2) コメントは範囲に含めないので編集を分けて残すか、(3) 残せない形では候補を出さないか、が書かれていない。
  近い形は決まっている: 残すトークンの間のコメント（R-210。範囲の外に置くよう直した）、要素の無い括弧の中のコメント（S-513: 候補なし）、ガードの形でまとめる枝の中のコメント（S-317: 候補なし）、fmt が落とす範囲の中のコメント（S-536: 書き換えない、`spec/tools.md` §3.4）。
  今ある候補のうち、消すトークンの間にコメントが入りうる形は次のとおり（行コメントは改行を伴うので、改行を書ける括弧の中の形が主である）。

  | 形 | 例 | 今の実装 |
  |---|---|---|

  | E0005 の属性の余分な引数（R-238） | `@fp(relaxed, // c` 改行 `x)`、`@repr(c, // c` 改行 `packed)`、間のコメントだけの行 | `, // c` 改行 `x` を消し、コメントが消える（c08、d03、d06） |
  | E0002 の要素の無い括弧（S-513） | `A( // nothing` 改行 `)` | 候補なし（c10） |
  | E0020 のガードの形（S-317 など） | `n @ // c` 改行 `1..<5 =>`、`0.5 // half` 改行 `\| 1.5 =>` | E0002 で候補なし。note「a comment in the part the guard form would rewrite would be lost」（c11、c16） |

- 案:
  - (a) 範囲に含めないと作れない候補は出さない。一つの編集の範囲（最初に変えるトークンから最後に変えるトークンまで）に、その候補が直すコメント（E0004 の doc、E0020 のブロックコメント）でないコメントがあれば、候補を出さず、note で「範囲の中のコメントが消えるので候補が無い。コメントを外へ移すか手で直す」と示す（ガードの形の note と同じ）。
    実装: 範囲の中のコメントを見る共通の判定を一つ置き、E0807 と E0005 の二か所で使う（10〜20 行と note）。器: 当てる前と後で、コメントの言葉（`//`・`///`・`//!` の後ろと、ブロックコメントの中）の多重集合が同じことを確かめる（20〜30 行。移す候補と種類を変える候補は通る）。
    事例: E0807・E0005 のコメント入りの否定例 2〜3 件。費用の要因: E0503 の腕と文を消す候補では、中にコメントのある腕に候補が無くなる。
  - (b) 消すトークンの間のコメントは残す。消す範囲をコメントの前後で分け、コメントとその後の改行を残す（c01 は g01 の形）。残した改行が文や要素の区切りの読みを変える位置と、消すだけでない候補（ガードの形、要素の無い括弧）では候補を出さない。
    実装: 消す範囲をコメントで分ける共通の関数（20〜40 行）と、改行を残せる位置の判定を候補ごとに持つ。器は (a) と同じ。
    費用の要因: 要素の無い括弧（S-513）とガードの形（S-317）の「中にコメントがあれば候補なし」と fmt（S-536）とで、コメントの扱いが二通りになる。候補の数を決める規則（残した改行を書ける位置）が候補ごとに要り、テストの役割はそれを読んで数を出す。
  - (c) 消すトークンの間のコメントは一緒に消してよい（今の E0807・E0005）。§18.1 に一文。実装: 0 行。
    器: コメントを消す編集を誤りと見分けられない（R-210 の形は、範囲の両端の外側が残るトークンかを五つ目の確かめに足して見る）。費用の要因: 書き手の説明が黙って消える。S-513 と S-317 の決定（候補なし）と食い違い、二つを残すなら例外になる。
  - (d) コメントを移す。消す範囲のコメントを、範囲の始まる行の上に独立の行として置く（S-302 のブロックコメントの置き場所と同じ）。実装: 30〜60 行。
    費用の要因: コメントの付く先が変わり（`// the signal` が呼び出しの上へ）、上の行へ置けない位置（式の途中、見出しの中）では別の規則が要る。

- 推奨と理由: (a)。確度: 中。
  - 一つの規則で、決まっている近い形（要素の無い括弧の S-513、ガードの形の S-317、fmt の S-536）と同じ答えになる。§18.1 の「コメントを範囲に含めない」を字のとおりに読み、含めないと作れない候補は §18.1 の「満たす候補を作れなければ、候補を出さない」に従うので、新しい区別を足さない。
  - 器の確かめが単純で漏れない。当てる前後でコメントの言葉が同じかを当てた前後の状態だけで判定でき、消す編集も置き換える編集も同じ確かめに入る。五つ目の確かめが見ない形（消す編集）を、ここで閉じる。
  - 実装が小さい。今コメントを消す候補は E0807 と E0005 の二つで、どちらも括弧の中の引数で、書き手がその間にコメントを挟むことは少ない。候補が無くても note に直し方があり、修復のループは手で直して先へ進む。
  - 後で緩められる。(a) から (b) へ移ると、候補の無かった形に候補が増えるだけで、プログラムは壊れない（事例の候補の数は書き直す）。E0503 の腕と文を消す候補（W5-08・W5-09）で、中にコメントのある形が多いと分かったら、そのときに (b) の分け方を足せる。
  - (c) は書き手の説明を黙って消し、決まっている S-513・S-317 と食い違う。(d) はコメントの付く先を変え、置き場所の規則が増える。
  - どの案も、R-210 の直し方（残すトークンの間のコメントは範囲の外に置く）と食い違わない。(c) でも、R-210 のコメントは消すトークンに挟まれていないので消してよい形に入らない。
  - あわせて決めること: 「範囲」は候補の各編集の範囲で、fmt の §3.4 の行末のコメントの付く先（最後のコードが落ちれば範囲の中）は使わない。消す要素の後ろの行末のコメント（`1, // the length` の `1` を消す形）は範囲の外で、そのまま残る（d05 の今の出力）。
  - あわせて決めること: 候補の数を仕様から出せるよう、E0807 の候補が消すのは長さの引数とその前の `,` であると §11.4 に書く（今の実装。c01 は前の `,` との間にコメントがあるので、(a) では候補なし）。E0005 の余分な引数も、引数とその前の `,`（今の実装、R-238）。
  - あわせて決めること: 器の確かめ（コメントの言葉の多重集合）はテストの側の決まりで、§18.1 には書かない（X3-1g と同じ）。今の事例に違反は無い見込み（上の掃引で、コメントを範囲に含むのはコメントを直す候補だけ）。
- 影響: 仕様 §18.1 の「編集は…範囲に含めない」の後に一文（(a) 含めずに作れない候補は出さない、(b) 分け方と残せる位置、(c) 消すトークンの間は消してよい、(d) 移す先）。§11.4（E0807 の候補が消す引数）。診断のコードは増えない。

- 回答（2026-10-23、会話で利用者。55 回目）: (c)、消すトークンの間のコメントは一緒に消してよい（下書きと助言の (a) でなく、利用者の見方）。
  - 利用者の理由: fmt は書き手の選択を経ずに書き換えるのでコメントを保つが、修正候補は提案で、書き手は字のまま当てなくてよい。消えたコメントが大事なら書き手が残す形に直す。一意に決まらなければ複数を示して書き手が選ぶ余地もある。候補が守るべきは、当て続けたら正しい構文に収束するか、収束できないとして止まるかで、コメントを消すことはどちらにも触れない。
  - 1. §18.1 の「編集は…間のトークンとコメントを範囲に含めない」を言い直す: 残すトークンの間のコメントは範囲に含めない（最小の編集）。消すトークンの間のコメントはトークンと一緒に消してよい。
  - 2. 実装: 今の E0807・E0005 の候補はこの形のまま（0 行）。下書きの器の確かめ（コメントの言葉の多重集合）は足さない（(c) の正しい削除を捕まえるため）。
  - 3. R-210（複合代入の候補が、残す演算子と右辺の間のコメントを消す）は 1 の前半に反するので、誤りのまま直す。
  - 4. 既決の S-513・S-317（中にコメントがあれば候補なし）は今のまま（止まる側で誤りでない）。揃えて候補を出す向きは、候補が増えるだけで壊れないので後で決めてよい。
  - 残る見た目の問題（約束の外）: E0807 の例で `x` の説明の `// the signal` が消え、消した `1` の説明の `// the length` が `x` の後ろに残る。書き手に任せる。
