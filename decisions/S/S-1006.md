# S-1006 `FixedStr[N]` の「大きさは `N + 4` バイト」（§4.2、S-614 の A1）が、§12.4 の配置（宣言の順と自然な整列。`N = 5` で 12）と合わない

- 空白: §4.2 と S-614 の決定（A1）は `FixedStr[N]` の「大きさは `N + 4` バイト、整列は 4」とするが、宣言 `{ priv bytes: [U8; N], priv len: U32 }` を §12.4 の配置（宣言の順と自然な整列、`onsa_sema` の `layout.rs`）に当てると、`len` の位置は `N` を 4 の倍数に切り上げた所で、大きさは「`N` を 4 の倍数に切り上げて 4 を足した値」（`N = 5` で 12）。`N` が 4 の倍数のときだけ `N + 4` と一致する。
  割れる読み: (1) §12.4 の配置のとおり（仕様と決定の文の誤り） (2) 字のとおり `N + 4`（詰めた配置。§12.4・§14.2 の C の自然な整列と合わない）。
  仮の扱い: 配置は §12.4 の規則で決まる（実装は変えない）。
- 決定: 決定（2026-11-11、利用者「いったん (b) で」。139 回目）: §4.2 から大きさの文（`N + 4` バイト、整列 4）を外し、大きさと整列は普通の struct と同じく §12.4 の配置による、とだけ書く（`N` を 4 の倍数に切り上げて 4 を足した大きさ、整列 4。同じ規則を二か所に書かない）。実装は変えない。§12.4 の配置は言語の約束（flow の状態の `SIZE`・`ALIGN`、`fast_budget` の E0820、`onsa interface`、ホットリロードのオフセット）で、`FixedStr` だけを詰めた配置にする例外は作らない。利用者: 詰めた大きさが要るなら、将来、配置の指定（padding の指定）を足せば扱える。
- 経緯: 139 回目（2026-11-11）、W5-12 の設計メモ（onsa-impl、`P/w512/memo/memo.md` の 9 章）が挙げた。
