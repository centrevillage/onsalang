# S-1237 細部: 自分の出力で刻むイベントの源（`let d = g~(prev~(^d))`、`g` は入力のイベントごとに出す）を誤りにするか、決して刻まない値として通すか

- 空白: イベントの入力のイベントごとに出す flow `g`（`flow g(m: U32 at event) -> U32 at event { Some(m) }`）を、自分の出力に刻ませる形 `let d = g~(prev~(^d))` は、クロックの検査を通る（引数のクロックは `d` のクロック、`d` のクロックは `g~` の出力）が、外から刻むものが無いので決して刻まない。誤りにするか、最初のイベントの前の値のまま通すかが字に無い。
  仮の扱い: E0200（作らない。W7-11 U2 の門）。`check` は通す。W7 の区切りで確認だけ。
- 決定: 決定（2026-11-26、利用者。188 回目）: 誤り（E0815、flow の検査の段）。呼び出しの出力を刻むもの（呼び先の出力の式のクロック。それが呼び先の入力のクロックなら、その入力への引数のクロック）をたどって、その呼び出し自身に戻る形は、決して刻まない。
  判定はクロックの構造だけで決まり、値のせいで出ないだけの形（`None` だけを出す呼び先、0 を読み続けて出さない作り手、自分のイベントの水準で止まる `when~`）は当たらない。輪にぶら下がるだけの呼び出し（輪の出力を受けるだけ）は当たらない。
  仕様の字は §11.11 の出力の項の一文とコード例（`loops`: `a`・`b`・`p` の三つの形が E0815、`c`・`d`・`g` が通る）。誤りは単位に一つ（§18.1）なので、輪の数の文は置かない。
  実装の扱い（字に書かない）: 位置は輪の中でソースの順に最初の呼び出しの、出力を刻む入力への引数。note で呼び先のどの入力で出すかを示す（判定が呼び先の本体に依るため）。修正候補は無い（外のイベントを渡すか、呼び先で周期の刻みに出すかで意図が割れる）。呼び先が誤りの flow（クロックが決まらない、E0817 など）なら呼び出し側には出さない（E0817・E0808 と同じ扱い）。読まれない輪は E0309 でなく E0815（§18.1 の段の順）。
  利用者の経過: 188 回目、親が形の表（落とす形と、似ていて通す形）と案の比べ（誤り・通す・E0200 のまま。実装量と管理）を示し（推奨は誤り、段 1 の助言も誤り）、利用者「(1)で良いと思いますが、宣言をまたいで判定する形としてはより詳細に踏み込んでいると思うので、落とすべきケースのみ落とせるか、は慎重になる必要があると思います」。
  親は、字だけの境界の表（onsa-advisor、103 形: 落とす 49・通す 46・他の誤り 8。今のバイナリの判定と全て一致、`target/notes/188/w717/s1237b/adv/`）と、実装の対応の読むだけの設計（onsa-impl、一つの呼び出しで出力を出す段は高々一つの不変条件 I1〜I5、今この E0200 に当たる事例は `tests/` の 83 件で 0 件、`target/notes/188/w717/s1237b/map/design.md`）を回し、字の監査（高 0・中 4・低 5）で「同じ呼び出し」を「その呼び出し自身」に、「引数」を「引数のクロック」に直し、「（輪ごとに一つ）」を消した字と例を示して、利用者「上記で良いです」。
  実装は W7-17 U6b（今の E0200 の門 `event_gate` を消し、計画の段の輪の検出で E0815 を出す）。
