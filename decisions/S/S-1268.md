# S-1268 細部: 注釈の無い無名関数で、`?`・`return`・末尾が返り値の種類かエラーの型で食い違うとき、どれに診断を付けるか（仮は書いた順で先のものが返り値を決め、後のものが `?` なら E0414、末尾か `return` なら E0401）

- 空白: §9.1 は「注釈の無い無名関数では、`?` が返り値の型を `Result[_, E]` / `Option[_]` に決める」とし、§4.7 は無名関数の本体を検査してから返り値の型を単一化するとする。一つの無名関数の `?`・`return`・末尾が返り値の種類（`Result` と `Option`）かエラーの型で食い違うと、プログラムはどの読みでも誤りだが、どれに診断を付けるかを字が決めない。
  読み: (1) 書いた順で先のものが返り値を決め、後のものに付ける（後の `?` は E0414、後の末尾と `return` は E0401。返り値の型を書いた無名関数と同じ位置）、(2) `?` がいつも決め、`?` より前の `return None` のほうを E0401 にする。仮は (1)（W8-15 の実装と事例 `tests/spec/negative/try_closure_infer.onsa`。`?` の前の `return None` は `?` の行の E0414「it returns `Option[_]`」で、W8-15 の前のバイナリと同じ。再現 `target/notes/192/w815/probe/return_before_try.onsa`）。
- 決定:
- 経緯: 192 回目（2026-11-27）、W8-15 のテストの票（onsa-test）が、`?` の前の `return None` の形を空白に挙げた。実装（onsa-impl）は (1) を自然に出し、事例の三つの読み（後の `?` の E0414、後の末尾と `return` の E0401）と一致した。通るプログラムを変えないので細部として、W8 の段の区切りで確認する（`rules/leader.md` 5.11）。改めるなら無名関数を扱う W8-09 で直す。
- 補い（2026-11-27、親）: 192 回目、W8-15 の壊す側（onsa-break）が同じ族の形を挙げた: `?` だけが返り値を決め、`Result[_, E]` の `_` が最後まで決まらない形（`fn(m) { let v = parse(m)?  panic("x") }`）は E0406 で、付く位置が形で違う（無名関数の全体、後の `return Err(…)` の `Err(…)`、末尾の `None`）。§4.7 の決まらない型の E0406 の一般の規則のとおりで、通るプログラムは変わらない。仮は今の実装の位置。再現は W8-15 の壊す側の `k1.onsa`（`target/notes/192/w815/probe/undecided_try.onsa` に写した）。
