### S-567 修飾子とクロックの設計の見直し

- **論点:**
  - §11.3 は「遅いクロックの値を速いクロックの式で使うのは、値を変えない」とし、「flow の呼び出し（組込みの遅延を含む）の結果のクロックは、その出力の宣言のクロック…で、引数のクロックによらない」とする。
    S-566 の答えは「部品の速さを変えるのは、修飾子 `.up~(N)`・`.down~(N)` だけ。引数の値の速さや、つなぎ方からは決めない」。
    このため、部品（flow のインスタンス）のクロックを引数から推論する総称の flow（`prev~(v)` が `v` のクロックで一つ前を返す、イベントの値を渡すとイベントで動く）は書けない。
  - §19.1 の修飾子の項は「各修飾子は左の全体を包む（合成）。順も重ねがけも自由」（S-557）、「引数の位置に書いたインスタンスの呼び出し `f~(…)` は、呼び先によらず出力の値」（S-555）とする。
    `hb~(osc~(f)).up~(2)` の `osc` は呼び出し側の 1 倍で動く。いくつかの部品をまとめて別のクロックで動かすには、名前を付けた flow で包む。
  - `x.when~(c)` の `c` は「クロックは呼び出し側のクロック以下」（S-558）、`x.reset_if~(r)` は「条件のクロックの制限の字は無い」（S-559）。
    出力は、`when~` が K で保持、`.down~` が `sample / N` の値、`.up~` が配列で受ける `sample * N` の値（S-566 の答え）。同じ連鎖の形で、出力の読み方と条件のクロックの扱いが分かれる。
  - 書かれていないこと: 部品をイベントの刻みで動かす書き方（`designs.md` の 3 の (ア)・(イ)）。イベントの値を条件にした `reset_if~` の読み（S-559 の「水準で読む」は、K の刻みで保持した値を読む形を前提にしている）。
    イベントの値を `sample` の式で読む形と、`sample` の値をイベントの刻みの式で読む形（S-563）。止まっている部品・遅い部品の中の部品に来たイベント。
  - 決めること: 全体の設計（今の形のまま細部を直すか、保持を明示して部品のクロックを推論するか、範囲の構文か、組み合わせか）と、決定済みの S-555〜S-559 と、S-565・S-566 の答えのどこを改めるか。
- **今の実装:**（親が渡した `bin/onsa-4aaa028` の `check`。入力は `s567/probe/`、回す道具は `s567/probe/run.py`。終了コードは 0 と 1 だけだった）
  - `lp~(x, cutoff)`（`cutoff` は `block`）は通る（`a1_param`）。`prev~(p)`（`p` は `block`）は E0813（`a2_prev_block`）。
  - `osc~(f).when~(c)`・`osc~(f).on~(m)`・`osc~(f).reset_if~(r)`・`lp~(lp~(x, c), c).up~(2)` は E0812（「`osc~(f).when` is not a flow」）。修飾子の連鎖は未実装（S-555 の実装の前）。
  - 入力の `m: U8 at event` は E0302（「cannot find the clock `event`」）。式の `x when c` は E0200（「running an instance on a condition (the reserved word `when`)」）。
  - 式の `f at (sample * 2)` は E0002（「expected the name of a clock, found `(`」）。式の位置の `flow { … }.up~(2)` は E0002（「expected an expression, found `flow`」）。

  ```onsa
  flow lp(x: F32 at sample, c: F32 at block) -> F32 at sample        // 1 次の低域通過
  flow osc(f: F32 at block) -> F32 at sample                         // 発振器
  flow hb(x: F32 at sample) -> F32 at sample                         // 半帯域の低域通過
  ```

  - **(a) 今の設計を保ち、細部を直す。**
    - 意味: S-555〜S-559 と S-566 の答えのまま。部品のクロックは呼び出しに付けた修飾子だけで決まり、引数のクロックからは決めない。遅いクロック（定数・`init`・`block`・`sample / N`）の値は、速い式と入力で保持で読める。
      修飾子の出力は、`when~` が K で保持、`.down~(N)` が `sample / N` の値、`.up~(N)` が `sample * N` の値（変換の flow が配列 `[T; N]` で受ける）。
    - 直す所:
      - (a-1) 修飾子 `.on~(e)` を足す（`designs.md` の 3 の (イ)）。`e` は `at event` の入力の名前。本体の `sample` は E(e) を指し、`prev~` と遅延はイベントで数え、`sample_rate()` は外と同じ（周期が無い。`when~` と同じ）。
        `sample_tick()` はそのイベントの位置の値（S-566 の答え）。呼び出し側は出力を K の刻みごとに読み、イベントの間は最後の出力を保つ（一度も動いていなければ `T.default()`、無ければ E0816。S-558 と同じ）。
        引数はイベントの刻みで読むので、クロックは E(e) 以下（定数・`init`・`block`・E(e)）。`sample` の値を渡すと E0815（その位置の値はまだ無い。S-563 の 2）。
      - (a-2) `when~(c)` の `c` がイベントのクロックの `Bool` なら、今の規則（呼び出し側のクロック以下）のまま E0815。note で `.on~` の形と、`.on~` の部品で保持した値を条件にする形を示す。
      - (a-3) `reset_if~(r)` の `r` がイベントのクロックの値なら、そのクロックの刻みごとに一回読み、真の刻みでその位置の部品が動く前に初期化する（MIDI の Start のイベントでだけ初期化する）。他のクロックの `r` は S-559 のまま（K の刻みで水準で読む）。
      - (a-4) イベントの値を `sample` の式で読む形は E0815（最大のクロックが無い。S-563 の 1）。候補は読みごとに二つ（最後の値を保つ: `.on~` の部品の出力、その位置だけ真: std の脈の flow）。どちらも std の flow に書ける（`latest~(v).on~(e)`、`pulse~(e)`）。
      - (a-5) 入れ子の部品に来るイベント: イベントの部品は、`.down~`・`.up~` の部品の中でも全ての位置のイベントで動く（`.up~` の中では、その位置の最初の刻みの前。S-566 の下書きが新しい S の候補に挙げた位置の丸め）。
        `when~` で止まっている部品の中の部品には、止まっている間のイベントは届かない。動いているかは直前の K の刻みで決まる（その位置の `c` はイベントの後に計算されるため）。
        （親の直し: この扱いは S-562 の「止まっている部品・遅い部品に来たイベント」の問いで、決まっていない。ここでは一つの形として書く。`when~` の部品と `.down~` の部品で扱いを分けるかも、その問いで決める。）
      - (a-6) `x.on~(a).on~(b)` のように `.on~` を `.on~` に直接重ねる形は誤り（E0812 の note）。読みが三つに割れる（両方の和、一致した刻みだけ、内側は `a` で動き外は `b` で読む）。
        名前の flow を通して重ねた形（`.on~(b)` で動く本体の中の `.on~(a)`）も同じ問いで、読みは (a-5) の問い（止まっている部品・遅い部品に来たイベント）の答えと揃えて決める（親の直し。決めるまで誤り）。

  - **(b) 同期言語の形（Lustre・Lucid Synchrone・Heptagon・Scade）: 刻みのクロックの保持を明示し、部品のクロックを引数から決める。**
    - クロックの種類: パラメータの種類（定数・`init`・`block`）と、刻みのクロック（`sample`、`sample / N`、`sample * N`、E(e)、条件で間引いた `k on c`）に分ける。
      パラメータの種類の値は、Lustre の定数と同じく、どの刻みのクロックの式でもそのまま読める（場面 1 は今と同じ）。刻みのクロックの値どうしは、同じクロックでなければ一つの式に混ぜられない。
    - 総称の flow: 宣言の `at sample` は「その部品のクロック α」を指し、`at (sample / N)`・`at (sample * N)` は α の比。呼び出しの α は、それらの入力に渡した刻みのクロックの引数から、一階の単一化で決める（食い違えば誤り）。
      刻みのクロックの引数が無ければ、呼び出し側の α（Scade の基準のクロックと同じ）。出力は α を基準にした宣言のクロック。`prev~(v)` は `v` のクロックで一つ前を返し、イベントの値を渡した部品はそのイベントで動く。
    - 間引く: `e when c`（`c` は `e` と同じクロックの `Bool` の名前。`when` は予約済みの語で、二項演算子にする）。周期で間引くのは `e when (sample / N)`。値は `k on c` か `k / N` のクロックになる。
      パラメータの種類の値を間引くと、その刻みのクロックの値になる（`rate when (sample / 32)`）。
    - 戻す（保持）: 周期のクロック（`sample / N`）は、どの刻みにも値があるので `at` で上げる（`k at sample`。今の昇格の字の範囲）。条件とイベントのクロックは、一度も値が無い区間があるので、組込みの flow `hold~(v)`・`hold~(v, init)` で戻す（初期値が無ければ `T.default()`、無ければ E0816）。
      Lustre の `current` は値の無い区間に nil を出し、Scade 6 は代わりに `merge` と保持の node を置いた（他言語）。音声のレートの値を `at` で `sample * N` へ上げる形は誤り（補間の変換の flow を通す）。
    - 合わせる: `merge` は持たない（`if~` と `hold~` で書く）。
    - 修飾子: `reset_if~(r)` だけを残す（Scade 6 の `restart … every` に当たる）。`when~` は `e when c` と `hold~` に置き換え、`.up~`・`.down~` は引数のクロックに置き換える。
    - パラメータを音声の flow に渡す所: 今と同じ（`lp~(x, cutoff)`）。変種 (b′) として `block` も刻みのクロックに数えると、本体の `c * (x - …)` が誤りになり、`c at sample` が全ての係数の所に要る。
    - 推論の方法: flow ごとに、本体の一度の走査（`design/05-flow-lowering.md` の `let` の順の走査）で式のクロックの項を決める。項は α、α の比、`k on c`（`c` は名前の同一で比べる。Lucid Synchrone と Scade 6 と同じ）、E(e)、パラメータの種類。
      宣言は完全注釈なので、推論は本体の中に閉じる（P1）。呼び出しごとに α を決め、本体のコードは α によらず一つ（α は呼ぶ側の刻みと `sample_rate()` だけを変える）。
    - 誤りの形: 刻みのクロックの食い違い（`x + lf`、`svf~(x, k)` の `k` が `sample / 32`）は E0815 の新しい形で、候補は読みごとに二つ（遅い方を `at`・`hold~` で上げる、速い方を `when` で間引く）。
      条件の名前が違うクロック（`(a when z) + (b when (x == 0))`）は、`z = x == 0` でも誤り（Lucid Synchrone の講義資料の例と同じ）。
    - 改める決定: S-555（`when~` を外し、連鎖は `reset_if~` だけ）、S-556（修飾子の一覧と、予約語 `when` を演算子に）、S-557（重ねがけは `reset_if~` だけ）、S-558（`hold~` と `when` に置き換え）、S-566 の答え（修飾子を引数のクロックに置き換え）、§11.3（結果のクロックが引数のクロックによる。保持の明示）、§11.4（E0813 を外し、`block` の値だけを誤りに残す）。
      `f at (sample * 2)` が部品のクロックを決めるので、§19.1 が避けた「`at` でインスタンスを別のクロックで動かす」読みに、引数を通して間接になる。S-559 と S-565 は変えない。
    - 計画: 一つの本体の中に、刻みのクロックごとの段（`k on c` は条件の中、`k / N` は刻みの条件、`k * N` は繰り返し）が並ぶ。

- **他言語:**（どれも手元で動かしていない。出典は末尾）
  - Lustre（Scade 6 の論文 §II）: `x when h` は `h` が真の刻みだけの値で、部品は引数のクロックで動く（「`f(x when h)` has clock h」）。遅い値を速いクロックへ戻すのは `current` で、`h` が初めて真になるまで nil を出す。
    nil に出力が依るかの判定は一般に決定不能なので、Scade 6 は専用の初期化の解析を置いた。クロックは node ごとに一つの変数 α で、宣言を要する。
  - Scade 6（同じ論文 §III・§V）: `current` の代わりに Lucid Synchrone の `merge` を採った（nil を出さず、メモリを使わない）。保持は `merge` と `pre` で書く node `hold(i, h, a)`。
    部品の初期化は呼び出しの単位の `(restart sum every c)()` で、Lustre には部品を条件で初期化する手段が無く、書き手が初期化の条件を至る所に書く必要があったとする。式の範囲を条件で動かす `activate if … then … else` の範囲の構文と、状態機械を持つ。
  - Lucid Synchrone（Pouzet の講義資料）: クロックの型を ML の推論（algorithm W）で決め、node は `'a -> 'a` のようにクロックに総称。クロックの同値は構造の同値で、`let z = x = 0 in (1 when z) + (2 when (x = 0))` は誤り。
    初期の型の環境は `pre : ∀α.α → α` で、遅延は引数のクロックで刻む（(総)・(U′) の総称の遅延と同じ形）。
    一般の判定は NP 完全から決定不能まであるので十分条件で検査するとし、クロックを「書き手には強い制約だが安全性を上げる」とする。Lustre は node ごとに一つのクロックの変数で、過剰標本化を書けない。
  - Lustre と Lucid Synchrone のパラメータと刻みのクロック（Pouzet の講義資料）: Lustre の定数は全て node の基準のクロックにあり（総称でない）、Lucid Synchrone の定数は、規則 (Const) でどのクロックにも置ける（使う式のクロックの値として読める）。
    実行時のパラメータを刻みのクロックと別に扱う種類は、どちらにも無い。Scade 6 の node の `<<K, T>>` はコンパイル時の定数の引数である（同じ論文 §IV の `fwd_Euler`）。
  - クロックの推論と帰還: Lucid Synchrone の規則 (rec) は、`rec x.e` の `x` と `e` に同じクロックを置いて単一化する（講義資料）。Kronos は、帰還の接続に「未完のクロックの源」を置き、輪が閉じた所で見えた源から決める（博士論文 2.2 の Reactive Analysis）。
  - Heptagon（手引き §2）: `when`・`whenot`・`merge` と、クロックの推論（注釈は省ける）。「遅延を含む関数では、入力を間引くことと出力を間引くことは同じでない（`f(x when c)` ≠ `(f x) when c`）」と表で示す。
    `reset … every` は宣言の範囲を条件で初期化する範囲の構文。
  - Faust（IFC 2024 の発表）: `ondemand(C)` はクロックの信号 H で入力を間引いて C に渡し、出力を H で保持して広げる。部品のクロックは C に付けた H で決まり、引数からは決めない。`oversampling(C)`・`undersampling(C)` は C の見るサンプリング周波数も比で変える。
    2015 年の `mute`・`enable` から 2024 年の `ondemand` まで、間引きと保持を部品の単位で足してきた。部品の初期化の手段は発表に無い（未確認）。
  - Cmajor（Language Reference）: ノードのレートはグラフの中で `* 4`・`/ 2` と明示し、接続から推論すると書く所は無い。イベントの入力は処理系の関数（handler）で受ける。状態を初期化する専用の手段は文書に見当たらない。
  - SOUL（`SOUL_Language.md`）: イベントの handler が状態の変数に書き、ストリームの `run()` のループがそれを読む（例 `EventToStream`）。保持は状態の変数で書き手が明示する。ノードのレートは Cmajor と同じく明示で、既定の補間を持つ。
  - Pure Data: 部分パッチの単位で `block~`・`switch~` がレートと停止を決め、止めた部分パッチの信号の出口は 0（§19.1 の注、S-566 の下書きの調べ）。
  - SuperCollider: UGen ごとに `ar`・`kr` でレートを選んで作る。状態の初期化は UGen ごとの trigger の入力で、`Phasor` の `trig` は「非正から正へ越えたとき」（立ち上がり）に `resetPos` へ飛ぶ。
  - Kronos（Norilo の博士論文）: 各入力が根のクロックになり、コンパイラが依存を辿って節のクロックを決め、境目に状態を自動で置く（引数から決める形と暗黙の保持の組み合わせ）。

  - Csound: 変数の名前の頭（i・k・a）でレートを決める。`reinit` は、ラベルから `rireturn` までの範囲の初期化をやり直す（範囲の構文の初期化）。

### K. クロックの種類と順序

- K1（利）クロックは二つに分かれる。パラメータの種類（定数 < `init` < `block`）と、刻みのクロック（本体の `sample`、`sample / N`、`sample * N`、入力ごとの E(e)）。分かれ目は状態を持てるか（E0813 と同じ線）。
  `sample * N` は変換の flow の入出力の宣言と、`.up~(N)` の部品の中に現れる（S-566 の A1・A9 のまま）。
- K2（利）パラメータの種類の値は、使う所のクロック（`sample / N`・E(e) を含む）で変換なしに読める。他に決めるものが無ければ、本体の `sample` として読む。
  帰結: `lp~(x, cutoff)` はそのまま。`let c = prev~(^c) + 1` の輪は `sample` で刻む。イベントで数えるつもりの書き方は note で示す（規則は足さない）。
- K3（利）周期の刻みのクロックの値を別の周期のクロックで使うには `at` を書く（軸 2）。`at` は遅い→速いだけ（`lf at sample`、`lf` は `sample / 32`）で、行き先は本体の `sample` まで（`sample * N` へは変換の flow、S-566 の A5・A9）[確 8]。速い→遅いは変換の flow（S-566 のまま）。`at` の無い形は E0815。
  S-566 の B2（`sample / N` の暗黙の保持）を改める。S-566 の A5 の「遅い値は保持で読める」から `sample / N` を外す（A-11）。変換の flow の本体の `sample / N` の入力も同じく `at sample` で読む（S-566 の A1 を改める）[確 5]。
- K4（利）イベントの値は、`block` と同じく暗黙に読める。使う所の周期のクロックの刻みで、その位置までの最後の値（その位置のイベントを全て処理した後）を読む。最初のイベントの前は `T.default()`、無ければ E0816。
  順序では E(e) を全ての周期のクロックの下に置く（S-560 の案 (2c) の形）。`v at sample`・`v at (sample / N)` も書ける（同じ意味で、変換の場所を留める）。
  式の被演算子のクロックに最大が無いとき（別の入力のイベントの値だけからなる式、`a.x + b.y`）は E0815。周期のクロックの被演算子があれば、どちらのイベントの値もその刻みで最後の値として読む（`(a.x + z) + b.y`、`z` は `sample`）[確 13]。
  （補）一方の入力の状態で他方の入力のイベントを選ぶ形（`if runs(tr) { Some(shift(m)) } else { None }`）は、この規則と K5 の 4 で書けない。和の型の一つの入力で書く（note）。
  （補）§11.3 には三つに分けて書く: 周期の刻みのクロックの被演算子は揃っていること（K3）、パラメータの種類とイベントの値は自由に混ざること、最大が無ければ E0815。
  イベントの段の式では、周期のクロックの値は読めない（S-563 の (2iii) のまま）。パラメータの種類は読める。
- K5（利）規則: 次の四つの所で、暗黙に読んだイベントの値が周期のクロックの値と混ざると E0815。値は `let` の先まで追う（§11.3 の「`let` は名前を付けるだけ」を保つため）。
  1. 組込みの遅延の第 1 引数（`prev~(m.note + bend)`。候補 `prev~(m.note) + bend` と `prev~(m.note at sample + bend)`）。
  2. 帰還の輪（`let s = prev~(^s) + m.vel * g`、`g` は `sample`）。
  3. `reset_if~` の条件（`is_start(tr) && armed`、`armed` は `sample`）。
  4. `at event` の出力の式（`if gate { Some(shift(m)) } else { None }`、`gate` は `sample`）。
  理由（補）: この四つは式のクロックが状態の刻み・初期化の刻み・出す刻みを決めるので、書き換えで刻みが黙って変わる。他の所（演算、`rt fn` の引数）は値の変換が一つに決まる。
  混ざるの定義（補）[確 7]: `let` を通した式の被演算子に、`at` の下に無いイベントのクロックの値（`at event` の入力、第 1 引数がイベントの総称の遅延の出力、flow のイベントの出力）と、周期の刻みのクロックの値の両方があること。
  `rt fn` の結果、`if`・`match`、struct・配列・タプルのリテラルは被演算子を継ぐ（フィールドを分けて追わない）。flow のインスタンスの出力と、`at` を書いた値で追いは止まる（`prev~(lp~(a))` は通る）。
  候補の字: 2 は `m.vel at sample`、3 は `at sample`（水準）か脈の flow、4 は `thr_of(m) at sample`（閾値をイベントから取る (1a) の検出器 `if x > thr_of(m) { Some(Hit) } else { None }` も当たる）。
- K6（利）`sample_tick()` は `sample_rate()` と同じく、式のクロックを引き上げない（使う所の刻みのクロックに合わせる）。ただし下限は刻みのクロックで、他に刻みのクロックが無ければ本体の `sample`（`block` の段で読むとホストの区切りに依る値になるため、§13.4）。
  帰結（補）: `p * sample_tick()`（`p` は `block`）は `sample`。`prev~(sample_tick())` は本体の `sample` で一つ前。イベントの段の式（`stamp(m, sample_tick())`）ではその位置の値。`rt fn` の引数が `sample_tick()` とパラメータの種類だけなら同じ扱い。
  利用者の flow の出力は `sample` の値で、イベントの段では読めない（(2iii)）。
  細部（補）[確 12]: `sample_tick()` と、それとパラメータの種類だけに依る式は、`sample_rate()` と同じく巻き上げず、使う所の段で評価する（§11.3 の巻き上げない名前に足す）。
  `.up~(N)` の部品の中のイベントの段では、その位置の最初の刻みの値。`.down~(N)` の部品の中のイベントの段では 1/N の刻みの値で、同じ区間の二つのイベントは同じ値になる（note）。
  落とし穴（note）: `let last = if is_on(m) { sample_tick() } else { prev~(^last) }` の後の `sample_tick() -% last` は E(m) の式になり、いつも 0。経過を `sample` で取るのは `sample_tick() -% (last at sample)`。
- K7（S-560 の E4 の 1、変えない）式に `e at event` は書けない。`at event` は入出力の宣言にだけ書く。

### P. 部品のクロック

- P1（利、S-566 の B1 のまま）利用者の flow は、呼び出しの位置のクロック（その本体の `sample`）で動き、引数のクロックからは決めない。別のレートで動かすのは `.down~(N)`・`.up~(N)` だけ。名前は `.down~`・`.up~` のまま（B15、50 回目）。
- P2（利、軸 1）組込みの遅延（`prev~`・`delay~`・`vdelay~`）はクロックに総称。第 1 引数のクロックで刻み、出力もそのクロックの値。
  - `prev~(x)` は 1 サンプル前、`prev~(lf)` は 1/32 の刻みで一つ前、`prev~(note_of(m))` は一つ前のイベント。
  - 第 1 引数の `at` も刻みを決める。`prev~(p at (sample / 32))`（`p` は `block`）は 32 サンプルごとの一つ前で、出力は `sample / 32`。
  - `prev~(p)` は第 1 引数がパラメータの種類なので E0813 のまま（候補 `prev~(p at sample)`、note に `prev~(p at (sample / N))`）。
  - 長さ（`delay~(x, n)` の `n`、`MAX`）は第 1 引数のクロックの刻みで数える。`vdelay~` の `d` のクロックは、第 1 引数のクロックと同じか、暗黙に読めるもの（パラメータの種類、イベントの値）。速ければ E0815（§11.4 の「`d: T` は `sample` 以下」を改める）[確 6]。遅い値の `vdelay~` の長さを `sample_rate()` から作るときは、書き手が合わせる（§11.4 に書く）。
  - （補、A-4）第 1 引数に書けるクロックは、本体の `sample`・`sample / N`・E(e)。呼び出し側の `sample * N` の値（変換の flow の出力）は誤り（S-566 の A9 と同じ理由）。
  - （補、A-10）書き方は二つ残る（`prev~(lf)` と、刻みを留める `prev~(lf at (sample / 32))`）。どちらも認める。
- P3（補）帰還の輪のクロックは、輪の式の刻みのクロック（K3 により周期のクロックは一つに揃う。イベントと周期が混ざれば K5 の 2 で E0815）。刻みのクロックが無ければ本体の `sample`（K2 の帰結）[確 11]。
- P4（利、軸 6）連鎖のレートの起点は最初の呼び出し（利用者の flow は位置のクロック、総称の遅延は第 1 引数のクロック）。`.down~`・`.up~` がレートを変え、`when~`・`reset_if~` はレートを変えない。
  連鎖の全ての `.down~`・`.up~` を起点に当てたレートを R と呼ぶ。受け手の引数と `when~` の条件は R に合わせる（C1）。
  帰結: `x.when~(c).down~(4)` と `x.down~(4).when~(c)` は同じ意味。止めた刻みの 4 回に 1 回で動かすのは、名前の flow で包む（`slow~(r).when~(c)`、S-566 の A7 のまま）。
  総称の遅延に `.down~`・`.up~` を付けると、R が第 1 引数のクロックとずれるので、いつも誤り（`prev~(lf).down~(32)` は誤り、利）。
  `when~`・`reset_if~` どうしの順の意味（S-557 の例）は変わらない。
- P5（利、C1）`when~` の条件に書けるもの: R の値、パラメータの種類、イベントの値（R の刻みでその位置までの最後の値。`at` は要らない）、R より遅い周期のクロックの値（保持で読む）。
  R より遅い値を `at` なしで読めるのは組込みの `when~` だけ（言語にクロックの順を比べる機能が無いため。K3 の例外）。
  R より速い条件は誤りで、下げる変換は利用者の flow で書く（`when~(dws32~(c))`）。R 以外のクロックへの `at` も誤り。
  `when~(is_note_on(m))` は水準の読み（最後のイベントがノートオンの間は真）で、note で示す。
  （利、確かめの (B) 2、50 回目）R がイベントのクロックの受け手（第 1 引数がイベントの値の総称の遅延、`prev~(note_of(m)).when~(is_on(m))`）への `when~` は、P7 により何も止めない。意味を与えると B6 を覆すので与えない。
    意味の無い印なので、クロックの解析の段で誤りにする（E0020 の類: 書き手の誤解を示す冗長な印。条件の種類は問わない）。修正候補は `.when~(…)` を外す形。
    note: 規則（イベントのレートの受け手は `when~` で止まらない）と、選ぶ書き方（`let cur = if is_on(m) { note_of(m) } else { prev~(^cur) }`、`let pn = prev~(cur)`）。
    `reset_if~` は H3 で意味があるので対象外。利用者の flow への `when~` は、イベントだけを処理する flow を含めて、止まっている間は出力を保持するので意味がある。
- P6（利、C2）変換の flow（出力のクロックが本体の `sample` と違う flow）を `when~` の受け手にしてよい（`dws4~(x).when~(c)`）。呼び出し側は、自分の出力のクロックの刻みで最後の出力を読む（S-558 の保持の欄）。`up2~` も同じ。
- P7（利、B6）`when~` が止めるのは、flow のサンプルレートに結び付く処理（`sample` の刻みと、そこから作る周期の刻み）で、イベントの刻みの処理は止めない。止まっている間に来たイベントも処理する。
  副作用（イベントで進む状態は止まらない、入力のイベントごとの出力は止まっている間も出る）は、止まっている間にイベントを送らないことで明示に対処する（利）。
  （補）送らない形は、イベントの出力を持つ flow で書く（E3 の (1b)）[確 3]。引数に `if ok { Some(m) } else { None }` と書くと、`None` も E(m) の刻みのイベントとして届く。
    `flow gate(m: Msg at event, ok: Bool at block) -> Msg at event { if ok { Some(m) } else { None } }` を書き、受け手は `alloc~(gate~(m, ok)).when~(c)`。
    書けるのは、条件がパラメータの種類か同じイベントの入力から作るものの場合。`sample` の信号の条件はイベントの段で読めない（(2iii)）。
- P8（補、A-5）`.down~`・`.up~` の部品の中の `at event` の入力: イベントのクロックは部品のクロックから作らない（入力ごとの E(e)）ので、全ての位置のイベントで動く。`.up~` の中では、その位置の最初の刻みの前。
- P9（補、A-7）`when~` で止まる部品の `at (sample / N)` の入力は、呼び出し側の値を、部品の中の刻みの時点で読む（中の格子は動いた刻みで数えるため、S-566 の A7）。

### E. イベント

- E1（利、軸 5）`.on~` は持たない。イベントごとに状態を進める処理は、`at event` の入力を宣言した flow の本体に、式と総称の遅延で書く。使い回しは `at event` の入力を持つ flow と、flow のイベントの出力で書く。利用者の flow をイベントの刻みで動かす手段は無い。

  ```onsa
  flow alloc(m: Msg at event) -> Voices at sample {
    let v = assign(m, prev~(^v))   // m の刻みの式。prev~ は一つ前のイベントの v
    v at sample                    // その位置までの最後の値
  }
  ```

- E2（S-560 の E4 の 2 を K4 で直す）イベントの入力への引数はイベントの値で、インスタンスのその入力のクロックは引数のクロックに結び付く（同じインスタンスの別のイベントの入力は別のクロックでよい、同じクロックを二つの入力に渡してよい）。
  イベントの値を `sample`（と `sample / N`）の入力に渡すと、K4 の暗黙の読み（受け手の入力のクロックの刻みで最後の値）。`block`・`init` の入力へは E0815 で、候補は入力の宣言を `at sample`（か `at (sample / N)`）にすること [確 14]。
  `sample * N` の入力へも E0815（S-566 の A9 と同じ向き。後で開ける）[確 9]。`sample` の値やパラメータの種類をイベントの入力へ渡すと E0815。
- E3（利）flow のイベントの出力 `-> E at event`: 入力の `at event` と同じく決まったクロックを名指さず、本体の出力の式のクロックの刻みで出す。
  出力の式が `sample` なら、その `sample` の刻みで（S-564 の (1a)）、`sample / N` ならその刻みで、E(m) なら、m のイベントごとに（(1b)）。パラメータの種類だけなら K2 により本体の `sample` の刻み [確 10]。一つの刻みに一つまで、`None` は出さない。本体の型は `Option[E]`（(t1)）。出す位置は出した刻みの位置（(2a)）。struct の出力にイベントを含めない（(3a)）。暗黙の読みは起きない。
  （補）止まっている刻みに出さないのは (1a) の出力だけ。(1b) の出力は P7 により止まっている間も出る。
  （補）出力のイベントのクロックの刻みは、出した刻みの直後に並ぶ [確 4]。(1a) なら作り手の出力の式の評価の直後（その位置の `sample` の段の中）、(1b) なら作り手の入力のその刻みの直後。
    名前の順で作り手より下の式だけがその値を読むので、S-171 の「`sample` の式からは全て処理した後の状態が見える」は読む側から見て保たれる（S-564 の (2a) と独立のレビュー）。S-560 の E1 の「同じ位置の刻みは `sample` の刻みより前」は入力のイベントの字に限る。
  （補、E8 の細部）一つの出力は一つのクロックを持つので、同じ位置に複数の出力が出るのは、(1b) で同じ位置に入力のイベントが複数あるとき（入力の列の順）と、`.up~(N)` の部品の中の (1a) の出力（内側の刻みの順）だけ。
    `.up~(N)`・`.down~(N)` の部品の中から出るイベントの位置は、その内側の刻みが属する呼び出し側の位置（S-565 の R8 の置き換え、S-566 の A14 の 1）。細かい時刻が要れば値に入れる。
    プログラムの中の受け手に置き場所は要らない（出した刻みの直後に受け手の段が動くので、値の欄は一つ）。境界（一番外の flow の出力）の列の大きさは、フレームの数・入力のイベントの数・`.up~` の倍率の積で決まり、決め方は第 35 組（フレームの数に固定した API にしない、S-564 の独立のレビュー）。
- E4（利、B5、50 回目）同じ位置のイベントの順: 一つの入力の中はホストの列の順（S-561 の E5）。入力をまたいだ順は、境界が渡す順（S-561 の (2b)）。
  境界に求めること: ホストの列に順があればそれを保つ。順が無いとき（別のホストの列から来る）は外の flow の宣言の順。渡し方（通し番号か、一つの列は一つの入力だけに受けるか）と `render` の書き方は第 35 組。
  （補）flow の出力のイベントと入力のイベントの順は、出した刻みの位置で決まる（E3）[確 4]。
  （補）S-567 の答えの上で順が結果に出るのは、`reset_if~` の条件のイベントと、部品の中で畳み込むイベントが別の入力から来る形だけ（`count~(clk).reset_if~(is_start(tr))`）。
- E5（S-560 の E4 の 4、変えない）イベントの段の panic も、`process` の中の panic と同じく状態を poisoned にする。
- E6（補、A-6）イベントの値の `at (sample / N)` は、その刻みの位置までの最後の値（`at (sample * N)` は K3 の行き先の上限で書けない）[確 9]。CC で制御のレートを動かす形は `lfo~(cc_rate(m) at (sample / 32)).down~(32)`（K4 により `at` を省いても同じ）。

### H. 保持と初期化

- H1（利）`when~` の保持した出力は `reset_if~` で `T.default()` に戻る（S-559 の「保持した出力」は `when~` の欄、S-566 の A10）。
- H2（利）`.down~` の出力と、部品の外に書いた `at` の欄は、次の自分の刻みまで前の値。戻したいときは `at` を部品の本体の中に書く。
- H3（補、A-1）`reset_if~` の条件が刻みのクロックなら、その刻みのうち真の刻みで、その刻みに続く部品の段の前に初期化する。パラメータの種類なら、呼び出しの位置のクロックの刻みで水準（S-559 のまま）。
  イベントの条件（Start で初期化）は例外でなく、この規則から出る。`sample / N` の条件はその刻みで読む。
  同じ `is_start(tr)` が、`when~` では R の刻みの水準、`reset_if~` ではイベントの刻みで一回になる（設計どおりの違い）。
  （利、確かめの (B) 1、50 回目、(i)）外の `when~` が止めている間も、イベントの条件の `reset_if~` はその刻みで初期化する（P7: イベントの刻みの処理は止めない）。内側の形 `x.reset_if~(is_start(tr)).when~(on)` も同じ。
    S-559 の内側と外側の違いは二つに残る: パラメータの種類と周期のクロックの条件では、内側は動いている刻みにだけ初期化する（S-559 のまま）。保持した出力（`when~` の欄）は、どの条件でも外側だけが戻す（初期化の範囲）。
    止まっている間の Start を無視する形は、条件を `sample` の脈に変えて内側に書く（`seq~(tick).reset_if~(pulse~(is_start(tr))).when~(on)`、`pulse` は例の名前）。S-559 の (ii)（印を置いて判定を遅らせる）・(iii)（次に動く刻みの前）は採らない。
- H4（補、A-2）位相のカウンタは `reset_if~` の範囲に入らない（S-566 の A7）。§19.1 に S-559 の「poisoned には触らない」と並べて書く。
- H5（補、A-9）`v at sample` の欄は §11.3 の巻き上げの隠れた欄で、初期値 `T.default()` を持ち、生成する `reset` で戻る。S-152（`at` は状態を作らない）は改めない。
- H6（補、A-8）S-562 の「同じ位置の二つの Start は二回初期化しても一回と同じ」は、その入力のイベントの段を持たない部品に限る（`alloc~(m).reset_if~(is_start(m))` では一つ目の Start の処理が消える）。
