- 案: どの案も、添字を読む `par~` と、添字の重なり・`at`・`~` の誤りは変えない。
  - (a) 対象外のまま: §5.1 の対象外の文に `par~` の添字を足す（関数の引数と同じ扱い）。`_` は書けないまま。
  - (b) E0309 の対象にし、`_` を書けるようにする: 添字を一度も読まない `par~` は E0309（位置は添字の名前、候補は `_`）。構文は `par~ _ in a ..< b { e }` を受ける。
  - (c) E0309 の対象にし、`_` は書けないまま: 添字を読まない `par~` は E0309 で、候補なし。note で「添字を読まない複製は全て同じ値を作る」ことと、添字を読む形（`xs[i]`）か一つの値を繰り返す形（`[e; N]`）を示す。
    `var` の E0309（候補なしで note、S-714）と同じ形である。
  - 形ごとの出力: 形の表のとおり。(b) と (c) の違いは、`par~ _ in` が通るか（(b)）E0002 のままか（(c)）と、読まない添字の候補の有無だけである。
  - 書き手から見て: 添字を読まない `par~` は、§19.1 のとおり N 個の同じ値を作り、状態だけが N 倍になる。意図した形は、添字で入力を選ぶ（`par~ i in 0 ..< 4 { lp~(xs[i]) }`）か、一つを繰り返す（`[lp~(x); 4]`）かである。
    FAUST の `par(i, N, e)` は複製ごとに別の入力の線を取るので、添字を読まない `par(i, 4, lowpass)` が 4 チャンネルを処理する。同じ形を Onsa に写した `par~ i in 0 ..< 4 { lp~(x) }` は、同じ `x` を 4 回処理する（誤読）。
    (a) はこの誤読を黙って通す。(b) は E0309 で気付かせるが、候補 `_` を当てると誤読のまま黙る（候補が書き手の意図と逆の向きに収束する）。(c) は note で添字を読む形を示し、候補を当てて黙らせる道が無い。
    修復のループは、(a) が 0 回、(b) が候補を当てて 1 回、(c) が書き手の直し（添字を読むか `[e; N]`）で 1 回である。
  - 修正候補: (a) は E0320 の 1 歩で止まる。(b) は E0320 → E0309 の 2 歩で `clean`（fn の `_i` と同じ）。(c) は E0320 の後に E0309 の `no-candidate` で止まる（どの形でも止まる）。
