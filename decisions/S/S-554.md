# S-554 `assert` 文の規則と、テストの失敗の種類

- 空白:
  1. `assert` 文の節が仕様に無い（§6・§7 に無い）。式の型、書ける場所（fn と test の本体。flow の本体は E0806、§11）、`span` を、キーワードの一覧（§2）、§9.2 の一覧の一語、§18.1 の `message` の約束から逆に読むしかない。§9.2 は `panic(msg)` を「値の要る位置に置ける `assert`」と、`assert` から定義している。
     失敗の文面は決まっている（`onsa test` の `message` は §18.1 の `assert <式のソース>`、通常の実行の文面は約束しない、S-298）。
  2. test の本体の確かめ（本体の `assert`、`assert_near` などの補助の呼び出し）と、本体が呼んだコードの panic は、§18.1 の `calls`（呼び出しの並び）の位置で分かれる。§11.8 にこの一文が無い。
  3. `onsa test --json` の `failure` に種類 `kind`（`assert` / `panic`）を足すか。足すなら、`assert_near` の許容の誤りと `check` の反例をどちらに分けるか。
  4. `check` の失敗の位置。§11.8 は `check` を「panic する」とだけ書き、`assert_near` には「呼び出しの位置の panic」と書いている。
- 前提（2026-10-19、利用者）: `assert` は一つの機能のまま保ち、テストの側の確かめと検査されるコードの失敗の区別は、位置（§18.1 の `calls`）と種類で付ける。テスト専用の構文は足さない（同じ確かめに書き方が二つできる。得る情報は 3 の種類と同じ）。
  1 と 2 は読みが一つで、確認だけの見込み（助言の担当）。判断が要るのは 3 と 4。
- 決定: 決定（2026-11-04、利用者。110 回目、第 81 組。1・2・4 は (A) の確認だけで下書きと独立のレビューが一致。3 は下書き (a)、段 1・段 2 (b1)、利用者「B2: (b1)で。」）:
  1. `assert e` は文で、`e` は `Bool`（違えば E0401）、式の位置に書けず（E0002）、値は `()` で発散せず、`e` は常に評価し偽なら panic。fn・test・無名関数の本体と `const` の初期化式、`rt` の関数に書け、flow の本体は E0806（§7 に節）。
  2. 本体で起きた失敗は `calls` が空、呼んだ先は空でない。本体の中の確かめと本体の式の組込みの検査は位置では分かれず、`kind` で分ける（§18.1）。
  3. (b1): `failure` に `kind` を足す。`"assert"` は `assert` 文・`assert_near`・`check` の反例、`"panic"` はそれ以外（`panic(msg)`、組込みの検査、`unwrap`、性質の関数の中の panic）。テキストには出さない。
  4. (a): `check` の反例は `check` の呼び出しの位置の panic で文面は約束しない。関数値を呼ぶ std の関数（`array.from_fn`、`check`）の呼び出しは、関数値の中の panic の `calls` に入る（本体に書いた無名関数でも同じ）。今の `from_fn` のずれは R-363。
  作業は W5-08（`kind` を `--json` に出す。`tests/README.md` の PANIC の括弧を `kind` で言い直す）と W8-09（`check` と `from_fn` の `calls`）。別の論点の `assert x, "msg"` は S-879。下書きは `S-554.draft.md`。仕様 §7・§11.8・§18.1
- 経緯: X-9 の事例の印 `//~ PANIC`（X9-36、U18 `fcdc12f`・U20 `1bb829a`）で、事例の器が test の本体の確かめと検査されるコードの panic を分ける必要が出た。今は Core の出所の欄（`PanicOrigin`）を器だけが使い、`--json` には出していない（2026-10-19、43 回目）。
  下書きの注意（2026-10-19、文書の点検）: 3 を決めるときに、`tests/README.md` の「印」の PANIC の括弧（「§9.2 ではどちらも panic で、器が位置と種類で分ける」。`assert_near` の失敗の根拠は §11.8）を見直す。
