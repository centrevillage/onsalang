# S-641 `[[plugin]]` の `flow` が `@export` の flow でないときの誤りの段・位置・終了コード（E1103 と §18.1 の「ソースより先」「ソースの編集では直らない」）

- 空白: 51-A7（S-639）は「`[[plugin]]` の `flow` が `@export` の flow でなければ E1103（`onsa.toml` の位置、終了コード 2）」とし、§14.3 と §15.3 の表に書いた。一方 §18.1 は、マニフェストを読む全てのコマンドがソースを読む前にマニフェスト全体を検査するとし、終了コード 2 の理由を「マニフェストの誤りはソースの編集では直らないので、修復のループが止まるよう終了コードで分ける」（51-A8）とする。
  食い違いは二つ: 1. `@export` があるかはソースを読まないと分からないので、「ソースより先」の検査ではできない（`tasks/diag-codes.md` の E1103 の段の欄も「マニフェスト（ソースより先）」）。2. この誤りは、ソースの flow に `@export` を足しても直り、理由の文に合わない。
  読みは (1) 51-A7 のまま（E1103、`onsa.toml`、終了コード 2）で、検査はプラグインのターゲットのビルドとし、理由の文を弱める。(2) 経路の flow が無ければ E1103（`onsa.toml`、2）、flow はあるが `@export` が無ければその flow の宣言の位置でソースの誤り（終了コード 1、note で `onsa.toml` の行を指す。コードと `@export` の挿入の候補を決める）、に割れる。
  今の実害は無い（`clap`・`vst3`・`au` の `kind` は E0200 で、`[[plugin]]` を使うターゲットは M10 まで無い）。仮の扱いは (1)。
- 決定:
- 経緯: 61 回目（2026-10-24）、第 50・51 組の反映の文書の点検（onsa-docs、`389e40a..b625e65`）の 2 で見つけ、親が §14.3・§15.3・§18.1 と diag-codes の E1103 の行で確かめた。利用者が (1)〜(3) のうち (3)「S として登録し、M10 の前に空白の流れで決める」を選んだ（「(3)で良いです」）。関係: S-639（51-A7・51-A8）、S-580、S-597。
