# S-815 flow の外の `~` の呼び出しで呼び先を引くか（`nope~(x)`、`g~(x)`、`x.prev~(0.5)`）

- 決定済みで戻さないもの: flow の `lp~(x)` と組込みの遅延の `prev~(x)` の E0821（§11.1、§11.4、S-720）。E0821 は候補なし（§11.1）。E0811・E0812 は flow の本体の中だけ（S-101）で、flow の外の flow でない名前を E0812 にする読みはこれと矛盾するので並べない。タプルの添字の `t.0~(1)` は構文の段の E0002（S-591）。
  第 76 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/93/g76/draft.md`）。
- 論点: §11.1（21 行）は、flow の外にインスタンスの呼び出し `f~(...)`（組込みの遅延を含む）を書くと E0821（候補なし）とし、§11.4（112 行、S-720）は flow の外では見えない名前の `prev` に `~` を付けた `prev~(x)` も E0821 とする。S-101 は E0811・E0812 を flow の本体の中だけとする。
  flow の外の `~(` の呼び先が見つからない名前（`nope~(x)`）なら E0302 か E0821 か、flow でない名前（`g~(x)`、`K~(x)`、`P~(x)`、`x.prev~(0.5)`、`sample_rate~()`）なら E0812 か E0821 かを書いていない。
- 今の実装: fn の本体の `g~(x)`・`f~(x)`・`K~(x)`・`P~(x)`・`math~(x)`・`nope~(x)`・`sample_rate~()`・`lp~(x)` は型の段の E0812「`~(` creates a flow instance and is only written inside a flow body (§11.5)」と候補「remove `~`」（`m/fn.out`、`test`・`const`・無名関数も同じ）。
  当てると `g~(x)` は誤りなし、`nope~(x)` は E0302、`lp~(x)` は E0401、`x.prev~(0.5)` は E0413（`x/loop.out`、no-candidate）。`prev~(x, 0.0)` は宣言ごとの関門の E0200「… outside a flow body (its error E0821)」（w128）。
- 案: どの案も、`lp~(x)`・`prev~(x)` の E0821 と、候補なし（§11.1）は変えない。
  - (a) 呼び先を引かずに E0821: flow の外の `~(` は、呼び先の名前によらず E0821（§11.3 の flow の外の `at` がクロックの名前を引かないのと同じ）。呼び先の経路は名前の段で読まない（単位はそこで止まる）。
  - (b) 呼び先を引く: 見つからない名前は E0302、見えない名前は E0303、名前空間でない名前の後の `.` は E0308、それ以外は E0821。flow の外で見えない組込み名（`prev`・`delay`・`vdelay`）は E0302 にせず E0821 とする（S-720 を保つ例外）。
  - 形ごとの出力: `nope~(x)` は、(a) が E0821、(b) が E0302。`g~(x)`・`K~(x)`・`P~(x)`・`x.prev~(0.5)` は、(a)・(b) が E0821。
    `sample_rate~()` は、(a) が E0821、(b) が E0302（見えない名前。`prev` の例外に入れるかも決める）。`lp~(x)`・`prev~(x)` は、どの案も E0821。
  - 書き手から見て（修復のループの回数）: flow の外の `~(` を書く書き手は、fn の中でインスタンスを作れると読んでいるか（S-101 の note が `voice.init` などを示す）、`~` を取り違えている。
    `nope~(x)` は、(a) が二回（E0821 で `~` を外す → E0302）、(b) が二回（E0302 で名前を直す → E0821）。`g~(x)` は、どちらも書き手が note を見て `~` を外す一回。
    どちらの順でも、直す所は二つで、回数は同じ。(a) は flow の外の `~` の規則を先に示し、(b) は名前の誤りを先に示す。
  - 修正候補: (a)・(b) は候補なしで止まる（今の「remove `~`」の候補が E0302・E0401・E0413 を作る形は消える）。
  - 通るプログラム: どの案も変えない。
  - 規則と例外: (a) は S-811 の (a) の 1 から決まり、§11.1 の文のまま。`prev~(x)`（見えない名前）と `lp~(x)` と `g~(x)` が同じ規則で E0821 になり、例外は無い。§11.3 の `at` と同じ形である。
    (b) は、呼び先を引く一句と、見えない組込み名の例外（S-720 の `prev~(x)` の E0821 を保つ）を足す。
  - 実装の量（W4-12 の U3）: (a) は、メモ 2.4 の計画のとおり本体の歩き手で `CallKind::Flow` を見たら呼び先を引かずに E0821（増えない）。
    (b) は、U2 の `Place::Instance` の解決の誤りの報告（メモ 2.3 の (a)）を flow の外でも呼び、組込み名の例外を足す約 +8〜12 行で、U3 が U2 の構造に頼る。
  - 後の作業への手当て: (a) は無い。(b) は、flow の外で見えない組込み名が増えるたびに（第 2 期の組込みの flow）例外の並びを足す。W7-10 の修飾子の flow の外の形（`.when~(c)`、§11.10 の 423 行は E0821）も、(b) では受け手の解決の後に置く。
- 他言語: 同じ形（文脈でだけ書ける呼び出しの印）を持つ言語は確かめた範囲に無い。参考に、rustc は見つからない名前のマクロ `f!(2)` を「cannot find macro」とし、名前の解決と印の誤りを分けない（`probe/other/r1.rs`）。
- 推奨と理由: (a)。確度: 高。
  - flow の外の `~(` は、呼び先が何であっても書けない構文で、§11.1 の文がそのまま当たる。S-720 が決めた `prev~(x)`（flow の外で見えない名前）の E0821 と、§11.3 の `at` がクロックの名前を引かない規則と同じ形で、例外が要らない。
  - (b) は `prev` などの見えない組込み名に例外が要り、組込みの flow が増えるたびに並びを足す。
