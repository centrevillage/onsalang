# S-460 読み続けた項目の、誤りの属性が与えるはずだった性質

- 空白: S-435 で読み続けた項目の、誤りの属性（`@derive(Eq)`、`#[derive(Debug)]`、`#[repr(C)]`）が与えるはずだった性質（trait の境界、配置）。S-435 の決定は、属性の形を読み続けた項目を、使う側を検査しない `Failed::Heading` にする。S-260 の形（trait と配置だけを未知にする）へ緩めるか。
  候補が作る `: Eq` を AST に先取りする案は、規則の表が AST の意味を決めることになり（R-87 の (4)、D-15）、第 25 組の Fable は推さない。
  第 25 組の下書きの付録で見つけた（2026-10-13） 補い（2026-10-13、第 26 組の下書き）: 独立の行の `#[derive(PartialEq)]` は、今も属性が余分なトークンの単位になり、`struct P` が derive 無しで読まれて、別の単位の `a == b` に偽の E0401 が出る（親が dev の `f4b9a8b` で再現した）。
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (b) を了承し、未知の表し方は Fable の案を選んだ。下書きと Fable が一致、第 26 組）: 属性の形で読み続けた項目は `Failed::Unit`（読み切った扱い）。
  struct・enum の宣言の derive の一覧と `@repr` の値を「未知」にし（§18.1 の「読めなかった部分は誤りの型として扱い」の形）、それに頼る使う側（`satisfies` の trait の判定、W5-06 の derive が作るメソッドの引き、§6.4 の derive と手の `impl` の重なり、FFI の配置）は未知なら診断を出さない。
  属性の中身は読まない（`#[derive(Debug)]` でも一覧の全てが未知）。fn・flow・const の属性の形は未知の欄を持たない。S-435 の細部（属性の形は `Failed::Heading`）をこれに置き換える。仕様 §18.1 に一文。
  実装は W3-08（構文解析器の印、`sig.rs` の `lower_derives` の呼び出し元、`satisfies` の分かれ。10 行前後）
