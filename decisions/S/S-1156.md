# S-1156 細部: 要素もフィールドも無い値（`[T; 0]`、`()`、フィールドの無い struct とタプル）の状態の配置の大きさと整列（§12.4 の `SIZE`・`ALIGN`、`onsa interface` の型の大きさ）

- 空白: §12.4 は配置の規則（フィールドは宣言順、各型の自然アラインメント、並べ替えなし）と「`SIZE` / `ALIGN` は…ターゲットの `memory.bulk` とポインタの幅だけで決まり、libc や C コンパイラに依存しない」を定めるが、要素もフィールドも無い値の大きさを書かない。
  読みは (1) 0 バイト（W7-07 U2b の前の Core と sema の配置）、(2) ISO C の表現どおり、長さ 0 の配列は要素一つ分の大きさと要素の整列、`()` と、フィールドの無いタプルと struct は 1 バイト（C の後端の表現 `a[1]`・`onsa_empty`）、(3) C の側で大きさ 0 の欄を消す、に割れる。違いは状態の `SIZE`・`ALIGN` と `onsa interface` の型の大きさの値だけで、通るプログラムと値は変わらない。
  (1) では C の状態の静的な表明が落ちていた（R-504、R-377）。(3) は ISO C に大きさ 0 の型が無いので、その型の値を読み書きする全ての式を C の生成で消す要がある。
  仮の扱い: (2)（`crates/onsa_core/src/layout.rs` の `size_align_for`（印 `SPEC-GAP(S-1156)`）と、同じ規則を持つ `crates/onsa_sema/src/layout.rs`）。enum の要素の無い変種は C が union から除くので、ペイロード 0 のまま。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
