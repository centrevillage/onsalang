# S-233 `onsa test --json` の形

- 空白: `onsa test --json` の形: S-215 のオブジェクトに足すテストの結果の欄の名前と中身、テストの記録の `span` の形（§18.1 に揃える、R-162）、検査で止まったときの結果の欄。S-215 の下書きで見つけた（2026-10-08）
- 提案: Fable の案。(b) `tests` の記録は `{module, name, status}` で、失敗のときだけ `failure: {message, span, calls}`。`kind` は外す。
  (l2) `span` は panic した位置、`calls` はテストの本体まで遡る呼び出しの位置の並びで、要素は `{span}`。`calls` が空なら `span` がテストの本体の中。止まったときの `tests` は (e1) 空の配列。
  並べ方は `module`、次に `name` の文字列の順。`status` は `ok` / `failed`。`message` は `assert` の失敗と `panic(msg)` だけを約束。パッケージの外のファイルの `span.file` は `<パッケージ名>/<そのルートからの経路>`（`std/dsp/test.onsa`）。
  §11.8 の結果のテキストの形は `spec/tools.md` §4 へ移し、§11.8 の「`"kind": "test"` と `"module"` を加える」の文を改めた（仕様 §11.8、§18.1。2026-10-08 決定。実装は W2-10）
