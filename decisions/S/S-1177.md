# S-1177 `par` と `par~` を本体の状態の有無で書き分けるか（状態を持つものの無い複製を `~` の無い `par` にし、状態の無い `par~` を E0812 にするか。fn の本体でも `par` を書けるか）

- 空白: 利用者の提案（170 回目）。S-745 は flow の構造の複製を常に `par~` と書き、`~` の無い `par` を fn の側の意味に残した（flow の本体の `par` は E0811 で `~` を足す候補、flow の外は E0821）。そのため本体に状態を持つもの（インスタンス、組込みの遅延）の無い `par~` も誤りにせず、`if~`・`match~`（状態を持つものを枝に含まなければ E0812）と違う扱いになった（S-745 の決定 4）。
  この違いから、普通の枝の中の状態の無い `par~` を状態を持つものと数えるか（S-844）と、`let` の値そのものの状態の無い `par~` のノードの名前（S-1175）の二つの空白が出た。
  案: (B) 本体に状態を持つもの（入れ子の `par~` を含む）があれば `par~`、無ければ `par` と書き分ける。状態の無い `par~` は E0812（`~` を外す候補）、状態を持つものを本体に持つ `par` は E0811（`~` を足す候補。今と同じ）。`par` は状態を持つものでないので、普通の `if`・`match` の枝とガード、`&&`・`||` の右辺に書け、取られたときだけ評価する。S-844 は空白ごと消え、S-1175 は「`par` は状態のノードでない」から (1′) の形になる。
  (C) (B) に加えて、fn の本体（`test` を含む）でも `par` を書ける（今は E0821）。(A) 今の形（S-745 のまま。S-844 は別に決める）。
  費用の要因: (B)・(C) は今通る状態の無い `par~` を E0812 にする（粗い数え: 事例に約 610 か所・約 250 ファイル、Rust のテストに約 90 か所、仕様の例に 3 か所。新しい E0812 の候補で機械的に直せる）。W7-06 は枝の中の状態の無い `par` を守りの中で降ろす（W7-06 のメモの S-844 (2) の行で +5〜8）。(C) は fn の側の意味（評価の順、効果、本体から外への制御、外の `var`、所有の値、空の範囲と総称の端）を決める。
- 決定: 決定（2026-11-20、利用者。170 回目。利用者の提案で、親が位置ごとの扱いを例で言い直し、advisor の段 1 の指摘を足した案を利用者が了承）: (B)+(C)。
  1. 本体に状態を持つもの（インスタンス（修飾子の連鎖を含む）、組込みの遅延、入れ子の `par~`）がある複製を `par~`、無い複製を `~` の無い `par` と書く（`if` と `if~` と同じ書き分け）。状態を持つものがあるかは、書いた `~` でなく中身（呼び先の種類と入れ子）で決める（印で決めると候補が往復する）。S-745 の決定 2・4 を改める。
  2. flow の本体で、状態を持つものを本体に含む `par` は E0811（`~` を足す候補）、含まない `par~` は E0812（`~` を外す候補）。枝の E0811 と `if~`・`match~` の E0812 と同じ述語で、flow の検査の段（§18.1 の名前の段の文から `par~` を移す）。`par` は状態を持つものでないので、普通の枝・ガード・`&&`・`||` の右辺に書け、取られたときだけ評価する。S-844 は空白ごと消える。
  3. `par` は状態のノードでないので `let` の名前で呼ばず、`let` の値そのものでも `<let>.par_N`（S-1175 は (1′) で決まる）。種類 `par` の番号は二つの綴りで一つの列。
  4. flow の外の式（fn・`test`・無名関数の本体と `const` の初期化式）でも `par` を書ける（`par~` は E0821 のまま）。複製を評価する順は決めない（展開と並列の実行を妨げない）。複数の複製が panic しうるとき、どれを報告するかも決めない（利用者）。本体は順に頼る形を書けない: 外の値は無名関数の捕捉と同じく読むだけ（代入と `!` は E0701、`inout` 引数と Affine 値は E0712）、本体は効果行が空の範囲（E0601）、本体から外へ出る `return`・`break`・`continue`・`?` はこの版では E0200（本体の中で閉じるものは書ける）。
  5. 空の範囲の E0808 と、結果の要素が信号の値型で Copy の規則（E0810）は `par` にも当てる。§19.1 の `ser` / `ser~` も同じ書き分け。`onsa graph` は `par` も枠に描き、見出しは書いた綴り。
  6. 時期: flow の側は W7-06（状態の無い `par~` の付け替えを最初の単位に）。fn の側の実装（検査・降下・インタプリタ）は W7-06 の後の新しい作業。
  仕様の文は §2.6・§3.5（ブロックに似た式）・§4.4・§4.5・§5.1・§5.3 の表・§7・§11.1・§11.3・§11.5・§11.6・§11.10・§12.3・§18.1・§19.1・`spec/tools.md` §1.3 に入れた。`const` の初期化式に書けることは、親が「fn の側」を値の世界の式の全てと読んで足した（利用者に報告する）。
- 補い（2026-11-20、利用者）: fn の側の実装は W8-12（W8-01 の設計メモに含める）。
- 経緯: 170 回目（2026-11-20）、利用者の提案。親が S-745 の決定 4、§11.5、§2.6、§18.1 の名前の段の行、S-844・S-1175 との関係を確かめた。fn の側も書けるようにするのは利用者の意見（「状態を持たない演算が fn で使えないのは利用者視点だと不可解で、今対応して手戻りが発生する話ではない」）。advisor の段 1 に回した（控え `target/notes/170/s1177/`）。利用者はさらに、fn の `par` では先頭から順に処理される前提の処理を許さない（内部のループの展開や将来の並列の実行を妨げない）とした。本体から外へ出る `return`・`break`・`continue`・`?` も、いったん無しとした（「順序と組み合わせて使いたくなる」「無名関数と同じく内部で閉じるなら意味が出るが、利用者には挙動が予測しづらい」）。
