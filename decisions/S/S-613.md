# S-613 Copy の型の要素に任意の式を持ち、Shared の葉が静的な値の集成体（`("gain", v)`、`Param { name: "gain", value: v }`）を、破棄の要らない値として扱うか

- 空白: S-610 の (b1) で、全ての要素が静的な値（`const`、補間の無い文字列リテラル、Copy のリテラル、ペイロードの無い列挙子と、その集成体）のリテラルは静的な値で借用の行になった。静的な値は構文で決まり、演算子・呼び出し・ローカルの名前を含む式は所有の行である。
  そのため、Shared の葉は静的な値で Copy の型の要素に任意の式を持つ集成体（`("gain", v)`、`Param { name: "gain", value: v }`、前置の `-` の `("gain", -1)`、`("gain", n + 1)`。`v` は `F32`、`n` は `U32`）は所有の行で、破棄に `Alloc` が要る（rt の関数では E0601）。
  実行時には、`"gain"` は不滅の静的オブジェクトで、`v` や `n + 1` は Copy の値なので、破棄で何も起きない。§12.3 のヒープの無いターゲットでは、`main` と export する関数の効果行に `Alloc` を書けないので、この形をどの関数のローカルにも置けない（利用者「組み込みで書けないとなると制限が大きそう」）。
  束縛の状態は名前の段で構文から一度だけ決める（R-85 (2)、D-15）ので、`v` の型（`F32` なら破棄が要らず、所有する `Str` なら要る）を見られない。型を見る規則（Copy の型の要素は任意の式でよい、など）を足すか、破棄の側で数えないか、今のまま所有にするかが決まっていない。
- 決定:
- 経緯: 58 回目（2026-10-23）、第 44 組の S-610 の独立のレビューの段 1 が抜けとして挙げ（C6。この組では決めない）、利用者が説明を聞いて、組込みで書けないと制限が大きいので前もって検討したいとし、親が W4-07 の前の S として登録した。関係: S-610、S-80、R-85、S-604、§12.3。
