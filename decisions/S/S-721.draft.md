# S-721 宣言がこの版の E0200 の handler の名前と、extern のブロックのメンバの名前を、他の位置に書いたとき（`let a = hh`・`fn g(x: hh)`・`c_sin(1.0)` は今は黙り、`fn k[T: hh]` は handler を trait と呼ぶ E0200）

- 決定済みで戻さないもの: 宣言そのものの E0200、extern のメンバを名前の表に入れて正しい使い方に偽の E0302 を出さないこと（R-246）、extern のメンバの可視性（S-491）、`handle … with` の形の E0200（S-713）、宣言が E0200 の trait と効果（S-719）、`X~(x)` の E0812 の候補の規則（S-590）。
  第 67 組の下書きの「族「§15.1 の E0308 の位置」の仕組みの出所」と「S-721 の形の表」の節（写しは `target/notes/78/g67/draft.md`）。
- 論点: §15.1「名前は見つかったが、その位置に要る種類（値、型、…）でなければ、位置によらず E0308」の種類の並びに handler が無い。§18.1 は宣言が E0200 の `trait`・`effect` をキーワードの種類で見せると書く（S-719）が、handler と extern のメンバは書いていない。
  extern のメンバは関数（`fn`）か不透明型（`type`）で、宣言の形から種類が分かる。handler も宣言のキーワードから分かるが、要る種類として受ける位置は `handle … with` だけで、この版ではその形の全体が E0200 である。
  読みは、S-719 と同じく種類で読むか、失敗した名前と読むか、今のまま（境界と効果行は E0200、他は黙る）かに割れる。
- 今の実装: 表のとおり。値・型・経路の頭・補間の穴は黙って続け、境界は名前の種類によらず「利用者の trait」と呼ぶ E0200、効果行は名前を効果と呼ぶ E0200 である。
  `handler_value.onsa`（`let a = hh`）と `extern_use.onsa`（`let a: c_sin = 1`）は、W4-04 U7b2 から読まれない `a` に E0309 が出る（単位を止めないため）。
  extern の関数の呼び出し `c_sin(1.0)` は、署名が読まれていないので型付けが誤りの型として続ける（後ろの `let zz: Bool = 2` の E0401 が出る）。宣言が E0200 の効果の操作 `Ef.op()` も今は続く（S-719 の「値の位置では止める」は U8 で入る）。
- 案: 
  - (1) 宣言の形の種類で見つかった名前として読み、S-713 の規則を当てる。handler は §15.1 の種類の並びに「handler」を一つ足し（要る位置は `with` の後で、この版では形の E0200）、名前空間でない名前にも足す。extern の `fn` は関数、`type` は型である。
    メンバの署名（ブロックを検査しないので読まれない）は読めなかった部分である。
  - (2) 宣言が E0200 の handler の名前と extern のメンバを、失敗した名前に入れる（§18.1 の E0200 の `pub use` の名前と同じ）。全ての位置で黙る（型の位置は誤りの型、値の位置は単位の以後を検査しない、境界は未知の境界、効果行は開いた行）。
  - (3) 今の形を規則にする: 境界と効果行は E0200、他の位置は黙る。第 2 期に handler と extern を入れるときに揃える。
  - あわせて (v) extern の関数を値の位置に書いたとき（`c_sin(1.0)`、`let f = c_sin`。(1) で決める細部。(2) は止める、(3) は続ける）:
    (v1) 署名を読めなかった部分の値として、§18.1 の値の位置と同じく単位の以後を検査しない（S-719 の効果の操作 `Ef.op()` と同じ）。
    (v2) 誤りの型の値として続ける（今の実装。後の段は誤りの型の値の呼び出しを既に扱う、S-692 の補いの A3）。
  - 形ごとの出力:

    | `T: hh`、`uses {hh}` | E0308 | 黙る | E0200（trait・効果と呼ぶ） |

  - 書き手から見て: 例として、Rust の trait や Swift のプロトコルの感覚で `handler quiet: Log { … }` を型や境界に書く（`fn run(h: quiet)`、`fn k[H: quiet]`）。
    (1) は最初の検査で、宣言の E0200 と `h: quiet` の E0308（handler は型でない、版によらない）を並べる。(2) は宣言の E0200 だけで、宣言を消すと E0302「cannot find」になる（名前を足す直し方で、名前が在った誤りの直し方と違う）。
    (3) は `H: quiet` を「利用者の trait」と呼び、誤りの種類を取り違えさせる。extern の正しい使い方（`c_sin(1.0)`、`h: CHandle`）はどの案でも黙る（R-246 のまま）。
    この版では handler と extern のブロックがどちらも E0200 なので、当たる書き手は少ない（`tests/` と `examples/` で、handler の名前を `with` の外に書くものは無い）。
  - 修正候補: 新しく出る E0308 には候補が無い（S-713 と同じ）。`c_sin~(x)` の候補は S-590 の規則で、当てると `c_sin(x)` は名前の段を通る。当て続けて `no-candidate` か `clean` で止まる。
  - 通るプログラム: どの案も変わらない（宣言の E0200 が同じパッケージに残る）。変わるのは、宣言の E0200 と同時に出る使う所の診断と、後ろの誤りが同じ検査で出るか（止めるか続けるか）だけである。
  - 規則と例外: (1) は §15.1 の種類の並びと名前空間でない名前の並びに handler を一つ足し、§18.1 の S-719 の文に handler と extern のメンバを足す。既にある規則への例外は無い。
    (2) は失敗した名前の集まりに二項を足し、宣言が E0200 の項目の扱いが trait・効果（種類で読む）と handler・extern（失敗した名前）の二通りになる。(3) は「宣言が E0200 の handler と extern のメンバ」の例外を一つ足す。
  - 実装の量（W4-04 の U8 の `kind_error(entity, want)`。S-719 で `DefKind::Unsupported` に種類の欄を足すのを前提にする）:
    (1) は `names/collect.rs` の三か所で種類（handler、関数、型）を入れ（約 +3）、`kind_error` と名前空間でない名前の判定に handler を足す（約 +5）。(v1) は歩き手の `resolve` で、種類が関数の `Unsupported` を値の位置に読んだら `Fail::Held` にする（約 +3〜5）。合わせて約 +10〜15 行で、境界と効果行は S-713 の E0308 の枝がそのまま当たる。
    (v2) は型付けの今の枝（誤りの型）のままで、足すものは無い。
    (2) は名前の引きが handler と extern の `Unsupported` を失敗した名前として返し、境界の E0200 の枝から外す（約 +8〜12。trait と効果を種類で読む S-719 の枝と分ける）。(3) は S-719 で種類を読む枝が handler と extern を飛ばす（約 +3）。
  - 後の作業: 第 2 期に handler と extern を入れるとき、(1) は種類の欄が本物の def に替わり、使う所の出力は E0200 が消えるだけである（(v1) の止まりも、署名を読むようになって外れる）。
    (2)・(3) は、そのときに全ての位置の出力が黙りや E0200 から E0308 や通るに変わり、その位置の事例を直す。JS / WASM の変換先には関わらない（どれも検査の段の扱い）。
