# S-498 「1 段深く」の基準

- 空白: 「1 段深くする」の基準。
  (a) 継続の段を重ねるか（`let x =` 改行 `a +` 改行 `b`、`type Op =` 改行 `fn(I32) ->` 改行 `I32`。今の fmt は段を重ねず、`=` と `->` の後の改行を継ぐ（R-143）。`canonical = false` の `continuation_function_types.onsa` の 2 段は事例の書き手の字面で、第 28 組の下書きで確かめた）。
  (b) 継続した行で開いた囲みの中身と閉じ括弧の字下げ（今は構造の深さで決め、`let x = foo +` 改行 `bar(` 改行 `1,` 改行 `)` は `bar(` と `1,` が同じ 2 段、`)` が 1 段）。§3.2 は「継続した行は 1 段深く」「要素を 1 段深く」とだけ書く。W3-11/i の設計メモの G3（2026-10-13）
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (a1)＋(b2) を了承。下書きと Fable が一致、第 28 組。Fable は一段目の (a1′) を二段目で改めた）: 段を重ねない。継続した行と要素の中で改行した行は、それを含む文・項目の見出し・並びの要素が始まる行より 1 段深い。囲みの中身は基準の行より 1 段深く、閉じ括弧は基準の行にそろえる。
  基準の行は `(`・`[` の並びでは開き括弧の行、`{` の囲みではそれを持つ形が始まる行。(h)（継続した見出しを 2 段深くする）は採らない（r70 の `15_if_cond` が変わる）。理由: 次の行の字下げが演算子の強弱によらず持ち主の行で決まり、閉じ括弧が開いた行より浅くならない。`spec/tools.md` §3.2。
  実装は W3-11 の U3（`lex/continuation_operators.onsa` の 6 行が変わる）
