# S-1021 細部: 境界が Dup を要する型パラメータ（`T: Copy`、数の trait）に暗黙の Dup を満たさない型引数を渡したとき、`T: Dup` と「`T: ?Dup` と宣言しない限り」の案内を出すか（案内のとおり `T: Copy + ?Dup` と書くと E0416）

- 空白: §4.5 は要求を複数満たさない型引数に「暗黙の `Escape`、暗黙の `Dup`、書いた境界」の順で最初に満たさないものを報告する（S-1013、S-862）。同じ節は `?Dup` を Dup を要する境界（`Copy`、数の trait など）と並べる形（`T: Copy + ?Dup`）を E0416 とする。境界が Dup を要するとき、暗黙の `Dup` を境界と別の要求に数えるかは書いていない。
  今（`2a416e35`）は、値の使用の `fn mk[T: Copy](move x: T)` に `Buf[F32]` を渡すと「`Buf[F32]` is not Copy or Shared, so it does not satisfy `T: Dup` of `mk`; a type parameter takes only Copy or Shared types unless it is declared `T: ?Dup`」で、案内のとおり `T: Copy + ?Dup` と書くと E0416 になる。
  型を書いた位置（`struct N[T: Copy]` の `N[Buf[F32]]`）は今「does not satisfy the bound `T: Copy` of `N`」で、W5-13 U5b（S-1013 の順を揃える）の後は値の使用と同じ文面になる。
  読みは (1) 今のまま（`T: Dup` と案内を報告） (2) `T: Dup` を報告し、境界が Dup を要するときは案内だけ外す (3) 境界が Dup を要するときは暗黙の `Dup` を別の要求に数えず、境界を報告する。どれもコードと位置は E0416 で同じ（文面だけ）。仮の扱いは (1)（S-1013 の字のとおり）。U5b の後は判定が一か所なので、どの読みでも直しは数行。
  再現は `target/notes/142/w513u5_memo/in/forms.txt` の `a3_value_copy_bound`・`a2_sig_ret_copy_bound`、`forms2.txt` の `b8`、事例 `tests/spec/negative/maybe_dup_declared_requirement.onsa` の `copy_asked_of_the_maybe_dup_wrapper`。
- 決定: 決定（2026-11-13、利用者。143 回目、W5 の区切りの確認だけ。「推奨の通り」で了承。2026-11-15 に (3) へ改めた、下の補い）: 仮の扱いのとおり (1)。境界が Dup を要する型パラメータでも、暗黙の `Dup` を境界と別の要求に数え、`T: Dup` と「`T: ?Dup` と宣言しない限り」の案内を報告する（S-1013 の順の字のとおり。W5-13 U5b の後は値の使用と型を書いた位置で同じ文面）。文面だけなので仕様は変えない。
- 経緯: 142 回目（2026-11-12）、W5-13 U5 の設計メモの担当が報告した（メモ `target/notes/142/w513u5_memo/memo.md` の 6 章の NEW-B）。`rules/leader.md` 5.11 の細部として仮の扱い (1) で進め、W5 の区切りで出す。
- 補い（2026-11-15、利用者）: 155 回目、W6-04 U9 で (3) に改めた。
  境界が `Dup` を要する型パラメータ（`T: Copy`、数の trait。`traits::implies` で `Dup` を含意する境界を一つでも書いたもの）では、暗黙の `Dup` を別の要求に数えず、書いた境界を報告する（`fn need[T: Copy]` に `U: ?Dup` の `U` を渡すと「`U` does not satisfy the bound `T: Copy` of `need`」）。
  値の使用、型を書いた位置、定数式、std の列のメソッド（`[T; N]` の要素）で同じ規則である。仕様 §4.5 の順の文に括弧書きで足した。
  理由: (1) の案内のとおり `T: Copy + ?Dup` と書くと E0416 になる。加えて W6-03 U6b（`4de5d162`）が S-1040 の `fill!` の文面のために、列のメソッドの境界が `Copy` のときだけ暗黙の `Dup` を問わない例外を入れていて、§4.5 の順の字と (1) に合わなかった。
  例外の外の `add_from!`（境界 `AnyNum`）は Dup でない要素に「Copy or Shared (`Dup`) の要素なら持つ」と言い、Shared の要素（`Str`）にすると別の E0416 になった。
  (1) に揃えると `fill!`・`slice`・`copy_from!` の文面が「Copy か Shared の要素なら持つ」になり S-1040 の「要素が Copy のとき」に反し、今のままでは §4.5 と決定に例外の一文が要る。(3) だけが例外を持たず、案内に従って別の誤りになる文面を残さない。
  どの読みでも判定は `requirement.rs::requirements` の一か所で、後の作業の手当ては無い。
  影響: コードは `requirement.rs::requirements` の暗黙の `Dup` を数える式だけ（列の例外の式を置き換える）。E0416 の文面が 15 ファイルの約 30 か所で変わる（事例はコードと位置で比べるので書き換えは無い）。S-1021 を固定する CLI のテスト（`crates/onsa_cli/tests/cli/type_argument_requirements.rs` の 2 件）を書き直す。
