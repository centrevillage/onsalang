# S-614 組込みで使う、Copy で容量の決まった文字列の型を足すか

- 空白: 文字列の型は `Str`（UTF-8、不変、Shared）と `Bytes` だけで（§4.1）、ヒープの無いターゲット（§12.3）と rt の関数では、値を埋めた文字列を作れない。補間は `Alloc` を要し（§12.2）、`Log` の操作は `rt fn info(msg: Str)`（§8.1）なので、渡せるのは既にある `Str`（リテラル、引数）だけで、値を埋めた文字列は作れない。
  利用者（58 回目）: 「組み込みでも、OLED ディスプレイへの文字出力や、シリアル経由でのデバッグログ出力など文字列を使う場合がある」ので、組込みで使える容量付きの文字列（C の文字列に相当するもの）が早めに必要。案: Copy の型の文字列 `CStr` を入れる。内部はバイト配列で、バイト長を持つ。入れられる文字は ASCII の範囲。リテラルには専用の書き方が要る見込み。
  ASCII に限ると文字数とバイト数が一致し、固定のバイト長で持ちやすい。UTF-8 では文字ごとにバイト数が変わる（利用者）。
  型を足すか、足すなら名前、容量の書き方、文字の範囲、容量を超えたときの扱い、ヒープを使わずに中身を作る方法（数の書式化）、出力の API（`Log` など）との関係、`Str`・`Bytes` との変換、リテラル、入れる時期が決まっていない。
  S-613 の下書き（`decisions/S/S-613.draft.md`）の案 (e)（静的な文字列の型）と、S-615（静的な Shared 型。L5 のプリセット名で重なる）と、S-613 の範囲の外のまとめの L5（状態に文字列を持つ形、`tasks/phase2.md`）に関わる。
- 決定: 決定（2026-10-24、利用者が了承。58 回目、第 46 組）: std の Copy の型 `FixedStr[N]`（`std.text`）を足す（B1 の (ii)。名前は B2 で `FixedStr`、短い名前の案が出れば実装の前に改めてよい）。`pub struct FixedStr[const N: U32] { priv bytes: [U8; N], priv len: U32 }` で、容量 `N` はバイト、大きさ `N + 4`、整列 4（A1）。
  文字は ASCII（NUL と制御文字を含む）で、長さと容量はバイト（A2）。不変条件（`len <= N`、使っていない後ろのバイトは 0、全てのバイトが ASCII）の上で、等値・順序・`Hash`・`Default` は derive（A6）。Copy で記憶域は値、リテラルは静的な値、置き場所は S-612（A5）。
  リテラルは期待の型で選ぶ（B3 の (l1)）。容量を超えるか ASCII の外は E0408、補間は E0401、`N` が決まっていなければリテラルの長さ。`match` のパターンの文字列リテラルも `FixedStr` の値に対してはその型で読み、使った長さとバイトの等値で比べる（A8 の (b)。理由（利用者）: 既存の決定と整合性の取れない形で、`Str` と同じリテラルで初期化できる時点で特別扱いはされている）。
  書き足しは入る分だけ書き、容量を超えた分は黙って捨てる（B4 の (t1)。理由（利用者）: 毎回 `let _ =` が要るのは煩雑）。収まるかは書き手が書き足す前に長さを足して確かめ、std の文書に注意を書く。書式化は整数の 10 進（第 1 期は型ごと）と、`F64` に広げて `10^d` を掛け最近接偶数で丸める式で定めた固定の桁の浮動小数（A3）。
  出口は `Span[U8]`（引数に渡すと使った長さの部分、§5.3）と `write_to(self, inout out: Span[U8]) -> U32`（A4・A7）。`Log` の `Span[U8]` の操作、`extern`、`Str` との変換、`Show` は第 2 期（A4・A9、`tasks/phase2.md`）。
  時期は第 1 期に作業を一つ足す（B5 の (p1)、W5-12。理由（利用者）: API のインタフェースが影響を受けそうなので、早めに導入する）。新しい S は S-617（`Show` の操作の形）・S-618（`Char` と整数の変換）・S-619（`Str`・`Bytes` を `Span[U8]` と C へ渡す形と `Log` の引数の型）、R は R-257（E0411 の文面）と R-96 への再現（A10・A11）。
  S-615（静的な Shared 型）とは補い合う関係で、L5 のプリセット名は名前が静的なリテラルだけなら S-615 の形でも書ける見込み。S-615 の結果でこの決定を書き換えない（A12）。仕様 §4.2、§2.4、§4.7、§5.3、§7、§8.2、§19.1
  補い（2026-10-24、利用者が ID を挙げて了承「C1: OK」「C2: OK」。58 回目の五つ目の文書の点検の 1・3）: C1 総称の `N` が決まっていない所（`fn show[const N: U32](t: FixedStr[N])` に `show("warm")`）では、リテラルの長さを `N` にする（配列のリテラルの `cap([1, 2, 3])` と同じ）。
  C2 代入の右辺には左辺の場所の型が期待型になり（`p.cur.name = "init"`。数のリテラルの `x = 300` が左辺の型で E0408 になるのと同じ）、比較の一方が補間の無い文字列リテラルなら他方の型が期待型になる（`t == "warm"`、`"warm" == t`）。§4.7 の期待型の一覧に足した。
  点検の 2 から、`FixedStr` は `inout` の `Span[U8]` には渡せない（E0401。A6 の不変条件を型の外から壊せないため）。
- 経緯: 58 回目（2026-10-24）、S-613 の範囲の外のまとめ（`target/notes/58/alloc58/draft.md`）の L2 の判断のときに、利用者が案を出し、親の意見（利用者の ASCII の案に賛成し、長さと容量をバイトで定める。名前 `CStr` は C・Rust の NUL 終端の文字列の名前とぶつかる、など）を聞いて、S として下書きを作ることにした。時期は下書きの見積もりの後に決める。
