# S-678 名前の段で失敗した `use`（E0302）が E0310 の辺を張るか（`use fx.b.{g}` と `use fx.a.{f}` の取り込み合い、最後の名前が見つからない `use`）

- 決定済みで戻さないもの: モジュールを取り込む `use` は、そのモジュールと下の全てのモジュールへの辺（自分自身と別のパッケージは除く）。項目を取り込む `use` は項目のモジュールへの辺（S-594、§15.1）。E0310 は依存が `use` だけで決まる検査（R-39）。
  名前の段で失敗した `use` の名前は束縛として数えない（S-462）。自分のパッケージ名の頭の候補（S-663）、自分を取り込む `use` の E0302（S-679）。E0310 の位置と数は仕様の外。
- 論点: §15.1「依存は `use` だけで決まるので、この検査は `use` の一覧で閉じる。モジュール（パッケージを含む）を取り込む `use` は…下の全てのモジュールへの依存として数える」。名前の段で失敗した `use` を数えるかを書いていない。
  §18.1 は失敗した `use` の名前を束縛として数えないが、辺には触れない。形は三つある。(i) 頭が解決しない（`use fx.b.{g}`）。(ii) 頭は解決し、途中か最後の名前が見つからないか見えない（`use b.{nosuch}`、`use b.nosuch.{x}`、`priv` の `use b.{h}`）。(iii) 自分を取り込む `use main`（S-679 の E0302）。
- 今の実装: (i) `cyc3`（`use fx.b.{g}` と `use fx.a.{f}`）: どちらのバイナリも頭の E0302 が二つと、使う所の E0302 が二つ（使う所は U3b で S-462 のとおり黙る）。`c335496` は頭の E0302 に候補「`fx.` を外す」を付ける。
  一つを当てると、もう一方の E0302 は候補を失い（当てると循環を閉じる）、note も無く止まる。二つを同時に当てると E0310 だけになる（`fixloop.py c335496 cyc3 first`・`all`）。`g_cyc3_one`（片方だけ自分のパッケージ名）は、初めから候補の無い E0302 で止まる。
  (ii) `nosuch`: `aa8a918` は `nosuch` の E0302 と `b.onsa` の E0310。`c335496` は E0310 が `a.onsa` の `use b.{nosuch}` の全体（1:1）に付き、同じ `use` の E0302（1:8）は出ない。
  同じ単位に一つを残す仕組みによることを、ファイルの名前を入れ替えた `g_nosuch_sw` で確かめた（E0310 が `b.onsa` に移ると `z.onsa` の E0302 も出る）。`g_nosuch_mid`（途中）と `g_hidden`（E0303）も E0310 だけになる。
  `g_wrongmod`（`a` の `use b.{helper}`、`helper` は実は `c` にある）は、E0310 と note「every `use` of the cycle takes an item, so no path narrows to cut it」だけで、直す形（`use c.{helper}`）では循環が無い。
- 案: (1) 失敗した名前は辺を張らない（経路が失敗すれば並びの全ての名前、要素が失敗すればその名前。S-462 と同じ範囲）。並びの解決した名前は張る。(i)・(ii)・(iii) とも辺なし。
  (2) 解決した経路の範囲で張る。(i) は辺なし、(ii) は読めた最後のモジュールへ、(iii) は自分を除く下のモジュールへ（今の実装は (iii) を張らない）。
  (2') (2) で、E0310 を成分の中の失敗していない `use` に優先して付ける（同じ `use` の E0302 を隠さない）。
  (3) 書いた経路から意図したモジュールを読んで張る。(i) は S-663 の候補の経路（`fx.` を外した形）、(ii)・(iii) は (2) と同じ。
  - (i) の診断の列（S-462 で使う所が黙った後）: (1)・(2) は E0302 が二つ（候補付き）→ 一つを当てると候補の無い E0302 で止まる。E0310 は書き手が手で直してから出る。
    (3) は初めから E0310（`a.onsa` の `use` の全体）と `b.onsa` の候補の無い E0302 で、`a.onsa` の E0302 は同じ単位で隠れる。止まる所は同じ（循環は本物）。
  - (ii) の診断: (1) は E0302 だけ。名前を `b` の項目に直すと E0310 が出て、別のモジュールに直すと通る。(2)・(3) は E0310 が先に見え、同じ `use` の E0302・E0303 が隠れる（`g_wrongmod` では直す形と違う向きを示す）。(2') は両方が見える。
  - S-462 との揃い: (1) は「失敗した `use` は何も取り込まない」を辺にも当てる。(2)・(3) は取り込めなかった `use` を依存に数える。
  - 実装（`c335496` から）: (1) は `resolve_import` の失敗の枝の `dep(…)` の 2 か所を消す（約 −5 行、`Walk.last` の整理を含む）。(2) は 0 行。(2') は `Dep` に失敗の印と `check_cycles` の並べ方で約 +10 行。
    (3) は頭の候補の経路を辿って辺を足し、`use_head_fix` の循環の判定から自分の辺を除く（約 +25〜35 行）。
- 他言語:
