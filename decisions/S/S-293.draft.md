- 推奨と理由: (e)。確度: 中。
  - 何を落としたいかで分けると、三つの形は同じ所に立つ。書いた物が何も判定せず何も変えず、それが型と字面だけで分かる。E0309・E0503 と同じく値を見ずに構造で判定でき、偽陽性は処理系の試験を除いて見つからない。
  - `x >= 0` の根拠が最も強い。`U32` の `-u` は型だけで誤りと決まるので E0401 で、`x >= -1` は既に E0401、`x < 256`（`U8`）は既に E0408 である。`x < 0` だけが通るのは同じ誤解の中の抜けである。Onsa は添字と `len()` が `U32` なので、符号付きの添字の言語の `while i >= 0` がここで起きる。検査で止めれば、実行の panic まで待たない。
  - `x == x` と `y = y` は書き損じの形で、結果の変わる読みが無い。`y = y` は E0309 の抜け道も塞ぐ（今は `var y = 1`、`y = y` が通る）。
  - 名前の付いた定数を外す（(f) を採らない）。§7 が定数の値を見ないのと揃い、調整用の定数の正しいコードを落とさない。W9-03 で合否が変わることも避けられる。
  - 浮動小数を外す（(g) を採らない）。`x != x` は誤解でも書き損じでもなく、どの変換先でも同じに働く。落とす実害が示せず、直す 77 か所と 15 ファイルの量に利益が見合わない。`is_nan` の試験が `is_nan` に頼ることにもなる。
    `x < x`（F7）だけを落とすのは、規則に例外を足すだけで効く場面が無い。
  - (b) を採らない。誤りでない出力は、LLM の書き手の修復ループに入らず、仕様に無い種類を一つ増やす。誤りにする価値が無い形なら言わない方が揃う。
