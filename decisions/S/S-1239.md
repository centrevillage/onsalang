# S-1239 `if~`・`match~` の腕に別のイベントの値を並べ、条件や対象が周期の刻みの形（`if~ c { det~(x, a) } else { det~(x, b) }`、`c` は `sample`）が E0815 か、`sample` の式として通るか

- 空白: §11.11 は「呼び出しの出力のイベントのクロックは、呼び出しごとに別のクロックで…互いに比べられない（`[det~(x, a), det~(x, b)]` と `if~` の腕に並べた形は E0815）」と、条件のクロックによらずに書く。§11.3 は「最大が無ければ E0815（部分式ごとに確かめ…）」で、条件も被演算子なので、条件が `sample` なら最大があり、`sample` の式として通る（腕はその位置までの最後の値。`f(a.x, b.y, z)` が通るのと同じ）。
  読み: (1) §11.11 の字のとおり、条件や対象のクロックによらず E0815。(2) §11.3 のとおり、条件や対象が周期の刻みなら通る（§11.11 の例は、条件がパラメータの種類の形を言う）。
  `~` の無い `if c { a } else { b }`（`c` は `sample`、`a`・`b` は別の入力のイベント）と `match` と、`let` に分けた `let d1 = det~(x, a)` の後の `if c { d1 } else { d2 }` は (2) の規則で通る。
  仮の扱い: (1)（保守的な側。後で (2) に広げても今通る形は壊れない。`SPEC-GAP` は `crates/onsa_sema/src/flow/clocks.rs` の `join_arms`）。値が付くのは W7-11 U2 から（複製と腕は W7-17 U6）。
- 決定:
- 経緯: 184 回目（2026-11-25）、W7-11 U1a の実装（onsa-impl）が、テストの担当の期待（§11.11 の字）と §11.3 の `join` の食い違いとして挙げ、親が登録した。
