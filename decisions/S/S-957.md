# S-957 境界の `?`・属性の `@`・前置の `~` の後の改行とコメント（`T: ?` 改行 `Escape`、`@ // c` 改行 `fp(relaxed)`、`~` 改行 `m`）の診断

- 空白: S-511・S-489 の `決定` は「`?`・`@` の後の改行とコメントの扱いも §2.5 の他の印と同じ」とする。§2.5 の「名前に付く印と前置の記号も…」の項が改行を書くのは、`-` / `!` / `^` と被演算子の間と後置の `?` の前だけで、コメントは書いていない。名前と印 `~` / `!` の間の改行は E0002。S-938 の `決定` は前置の `~` の同じ行の空白だけを書き、`~` の後の改行とコメントは書いていない。
  読み: (1) 空白と同じ E0020 で、候補は改行やコメントを除く形。(2) 名前と印の間の改行と同じ E0002（候補なし）。(3) 括弧の中の改行は空白なので受理（境界の `?` の後の改行は `[` の中）。
  今の出力（固定のバイナリ `891862e`）: `pub fn f[T: ?` 改行 `  Escape](x: T) -> U32 { 0 }` と `[T: ? // c` 改行 `Escape]` は受理。`@` 改行 `fp(relaxed)` 改行 `pub fn f…` と `@ // c` 改行 `fp(relaxed)` は E0002「expected attribute name, found newline」（候補なし）。`@ /* c */ fp(relaxed)` は E0020（ブロックコメントの規則）。`let n = ~` 改行 `m` と `~ // c` 改行 `m` は E0002「found `~`」（候補なし）。
  関係: R-384 の一つ目の形（`[T: Dup + ? // c` 改行 `Escape]`。今は `Dup` の E0020 の候補が `?` まで消す）の事例は、この答えを待つ。
- 決定: 決定（2026-11-09、利用者。126 回目）: (1) 前置の記号と同じ。
  境界の `?` と名前の間、属性の `@` と名前の間、前置の `~` と被演算子の間の改行（間の行コメントの後の改行を含む）は、§2.5 の前置の `-` / `!` / `^` と被演算子の間の改行と同じく、括弧の中でも外でも E0020 で、修正候補は記号を相手の行へ移す形（`~` は `!` にして移す）。間の行コメントは残る。
  ブロックコメントはそれ自体の E0020 が先（今のまま）。`if` / `match` の後の `~`（S-385）は変えない。今通る境界の `?` の後の改行が誤りになるが、`tests/`・std・`examples/` に当たる形は無い。§2.5 と §2.6 に書いた。
  実装は W5-11（U10d2 の引き継ぎの単位。`-` の改行の候補 `newline_after_prefix` の作り方を使い回す、約 +15〜30 行）。R-384 の一つ目の形（`[T: Dup + ? // c` 改行 `Escape]`）は、この規則で `?` の後の改行の E0020 になる。
- 経緯: 126 回目（2026-11-09）、W5-11 U10d2/t（onsa-test）が仕様の空白（NEW）として報告した。事例は書いていない。急ぎは W5-11 U10d2（R-384 の一つ目の形）。
