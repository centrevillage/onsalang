# S-480

- 空白: 名前の付いた handler（`snake_case`）の後の `{`。今は同じ行の `with quiet { … }` をインライン形式の本体と読み、括弧の中の次の行の `{` は E0003。§8.3 は `snake_case` を名前の付いた handler とし、本体を書かない。仮の扱いは今の読みのまま（S-421 の (d) は `UpperCamel` の名前だけを変えた）。W3-23/t で見つけた（2026-10-13）
- 提案: 後の段（急ぎは低）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: 既存 §8.3、Y）名前の付いた handler（`snake_case`）は本体を持たず、後ろの `{` は `handle` 式の一部でない。見出しの深さ 0 では本体の始まり、それ以外は同じ行でも括弧の中の次の行でも式の後ろの余分なトークンの E0002 で、note でインライン形式の本体は効果の名前に続くことを示す。 帰結として、`if handle { true } with quiet { 1 } else { 2 }` は今の E0002「expected a declaration」から構文の段を通り、この版では E0200 になる（handler の実装後は通る、Y）。
  - 仕様の節: §8.3 のインライン形式の項に一文。
  - 今通るプログラムが変わるか: この版では変わらない（handler は E0200）。構文の段の読みは変わる: `let r = handle { 1 } with quiet { … }` は E0200 → E0002、括弧の中の次の行の `{` は E0003（候補を当てると E0002 が残る）→ E0002、`if handle { true } with quiet { 1 } else { 2 }` は今の E0002「expected a declaration」→ 構文は通り E0200（段 1 が書いていない帰結）。
  - 実装の見当: `onsa_syntax/src/parser/expressions.rs` の `KwHandle`（約 585〜600 行）の `else if self.at(TokenKind::LBrace)` の枝を消し、文の終わりの E0002 に note を付ける所を足す。約 10〜20 行。`layout_tests.rs`の事例の注記「read as before」を改める。
  - ぶつかる既存の事例: `crates/onsa_syntax/src/layout_tests.rs`（E0003 が無いことだけを確かめ、通るまま）。
