# S-743 `use` を足す（直す）候補（§15.1）が、当てた後に同じ名前の引数・ローカルを E0304 にする形（候補の条件に、束縛と重ならないことを加えるか）

- 空白: §15.1 は、E0302 の `use` の候補を「当てた後の経路が名前の段で最後まで解決…するときだけ出す」とする。署名の型の経路の頭（`fn h(x: inner.T)`、`use` の無い子モジュール `inner`）の E0302 は候補「add `use inner`」を出すが、同じ単位の本体に同じ名前の束縛（`let inner = 1`）があると、当てた後にその束縛が E0304 になる（§5.1、S-717）。
  経路は字の上では解決し、§18.1 の約束も、挿入は単位の外なので字の上では守られる。当てた後に新しい名前の段の誤りが出て、修復のループがもう一回回る。見出しの誤りで単位が止まるので、本体の束縛は候補を作るときに分からない。
  引数と同じ名前の形（`fn f(inner: I32, x: inner.T)`）は、W4-19（S-741 (b)）で頭がローカルの E0308（候補なし）になり、この形から外れた。
  読み: (1) 候補の条件に「足す `use` の名前が、その単位の束縛（引数、本体のローカル）と E0304 にならないとき」を加える。(2) 今のまま（当てた後の E0304 は次の検査で報告する）。
  今の実装（W4-19 の後、`88f730f`）: 当てる前の `target/notes/79/s743/before/` で E0302 と候補「add `use inner`」が出るのは、本体に `let inner` を持つ `h` だけ（`f` は E0308、`g` は E0417）。当てた後の `after/` は、引数の `inner`（2 行、触れていない単位）と本体の `let inner`（5 行）の E0304。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。確認だけ。79 回目、第 71 組）: (a)。
  `use` を足す（直す）候補の条件（§15.1 の 62 行）に、引数とローカルの束縛を入れない。候補を当てた後に同じ名前の引数・ローカルが E0304（§5.1）になるのは、触れていない単位の誤りで §18.1 の約束の外であり、次の検査で報告する（ローカルの名前の直し方は書き手にしか決められず、候補が無くても直す回数はほとんど減らない）。
  範囲は見出しで止まった単位に限らない（本体の途中で止まった単位、誤りの無い別の単位、自分のパッケージ名やモジュールを外す候補、`use` の頭を直す候補も同じ）。候補を作るのは本体を歩く前なので、条件を足すには束縛を集める歩き手が新しく要る。
  仕様は変えない（§15.1 に一句は書かない）。実装は今のまま（0 行）。当てた後の E0304 の事例を足すなら名前の段の残りの作業（W4-18）で足す。E0304 の note の文面は約束しない。
- 経緯: 79 回目（2026-10-28）、第 69 組の独立のレビュー（onsa-advisor）の段 1 が見つけ、段 2 が R でなく空白と判断した。親が再現した。期限は無い（通るプログラムは変わらない）。関係: S-741、S-717、S-683。
