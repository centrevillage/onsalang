# S-293 結果が型と被演算子の同一性で決まる比較と自己代入

- 空白: 言語の側で、意味が型や被演算子の同一性で決まる書き方を誤りにするか: 整数と `Bool` の `x == x`（常に真）、符号なしの `x >= 0` と `x >= T.MIN`、自己代入 `y = y`、浮動小数の NaN の判定の `x != x`（`x.is_nan()` がある）。どれも今は `onsa check` を通る。
  誤りにするなら候補（`x != x` は `x.is_nan()`）と note。名前の付いた定数との比較（`x >= LO`、`LO = 0`）を含めるかで割れる。仕様には警告の概念が無く、黙って捨てる・消し忘れの形を誤りにする前例（E0309、E0418、E0503）がある。第 7 組の下書き（S-288）で見つけた（2026-10-08）
- 提案: 型の段の作業（W5）の前に決める。S-288 の決定とは独立
- 時期: W5
- 決定: 決定（2026-11-07、利用者。121 回目、第 91 組）: (a) 何も足さない。整数の `x == x`、符号なしの `x >= 0`、自己代入 `y = y` などは検査を通るままで、言語の誤りにしない。§13.4 の「意味の決まった有効な形」の文もそのままである。仕様と実装は変えない。
  理由: 式としては間違っていない（利用者）。仕様に警告の概念は無く、誤りでない出力の種類も足さない。報告が欲しくなったら `onsa audit` の項目にする案を `tasks/phase2.md` に残す。後で足しても通るプログラムは壊れない。
  経緯の補い: 下書きと独立のレビュー（段 1）は (e)（同一性と型の範囲を誤りにする）で一致したが、利用者の判断で (a) にした。自己代入が E0309 をすり抜ける形は S-944 に分けた。本文の `x.is_nan()` は `is_nan(x)` の誤りである（`is_nan` は `std.math` の関数、§3.4）。
