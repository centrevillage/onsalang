# S-1197 細部: 条件の位置で書ける「名前とそのフィールドを読むだけ」（§11.3、`lf at sample`）に、構造体のフィールドと組の要素の読み（`lf.x at sample`）を含むか

- 空白: §11.3「名前とそのフィールドを読むだけなら書ける（`lf at sample`）」の「フィールド」が、名前の値を置く状態のフィールドか、構造体のフィールドと組の要素の読み（`lf.x at sample`）も含むか。読み: (1) 前者で、`lf.x` は計算した部分式（条件の位置の制限と欄が当たる。`(lf at sample).x` と書けば名前の読み）、(2) 後者。
  仮の扱い: (1)（今の `hoistable` は `Field` を除かない、+0）。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-25、利用者。185 回目）: (C3)。名前の struct のフィールド・組の要素の読みは計算した部分式で、隠れたフィールドの型はその読み（連なりの全体）の型である（`M` に `Default` は要らない。`let v = m.vel` に分けた形と同じ値）。条件の位置では、名前とフィールド・組の要素の連なりを取り出すだけの式（括弧を通す）は、刻みで読んでも届いたときに読んでも同じ値で（初めの値と `reset_if~` の後だけ違う）panic しないので書け、守りを付けずに刻みごとに読む。添字の読み（`m[0]`）と添字を挟む連なりは書けない（E0815）。`sample / N` の値もイベントの値も同じ。仕様の字は §11.3・§11.11。
  利用者の経過: 親は (C1) を推して出したが、利用者「書きやすさ読みやすさなら (C3) と思います。S-1210はどういう話で、どういう理由で決定してますか？」に、S-1210・S-1158 の理由（刻みで計算した値と届いたときの値が違う、panic）を引いて説明し、「(C3) は S-1210 とぶつかる」を訂正して (C3) に改めた。利用者「それで良いです」。伏せた段 1 の助言は欄の型の確信が高、(C1)・(C3) は中で (C1)。 字は監査（onsa-advisor、`target/notes/185/reports/onsa-advisor-adcb0a8c6bf52140a-001.md`、高 1・中 5・低 6）の後に `target/notes/185/spec_text_next2.md` を示し、利用者「上記の字の案で良いです」。
  実装は W7-11 U2b の後の小さな単位（`tick_field`・`of_name`・欄の置き場と事例）。

- 補い（2026-11-25、親）: W7-11 U1b: イベントの値の名前のフィールドの読み（`m.pitch`、`if g { m.vel } else { … }`）は、名前の読み（読み (2)。欄は struct の全体、`Default` も全体に要る）にした（テストの票の親の読み）。`sample / N` の値は仮の (1) のままなので、同じ形の扱いが割れている。揃え方の案: (1) に揃える（イベントも計算した部分式。`if g { m.vel }` は E0815）、(2) に揃える（`sample / N` も名前の読み。`Default` を満たさない struct のフィールドを速い段で読む今通る形が E0816 になる）、(3) 欄はフィールドの型のまま、条件の位置では守りなしで刻みごとに読んで置く（フィールドの読みは panic しないので、条件によらず評価できる。どちらも通る）。W7-11 U3（値）の前に決める
