# S-484

- 空白: `@fp` の値の誤りの候補が意味を逆にしうる形（`@fp(strict)` に一覧の値 `relaxed`）。§6.5 は「修正候補は一覧の値」。仮の扱いは仕様の文どおり。W3-08/t1 が見つけた（2026-10-13）
- 提案: 後の段（急ぎは低）
- 時期: W3
- 判断（2026-11-09、利用者）: 期限を W5-24 に改めた（2026-11-09、129 回目）。W3 は `before` に X-4 を書けないための仮の期限だった（`issues/X/X-8.md`）。今の候補は `fix-loop` の歩きで往復 0・発散 0（868 ファイル）なので、W5-24 が候補を足す前に約束と gate をそろえる（利用者が (A) を選んだ）。
- 決定: 決定（2026-11-09、利用者。129 回目、中立の要約と onsa-advisor の二段のレビューを経た。段 1 と親が (b) で一致。利用者が ID を挙げて了承）: (b)。`@fp` の値の誤りのうち、属性を付けないときと同じ意味を名指す値（`strict`、§15.5 の既定）と、属性で選べない浮動小数のプロファイルの名前（`strict-ftz`、マニフェストの `fp` で選ぶ）は、同じ E0005 で、修正候補は属性を除くこと（`@ fp(strict)` は空白も除く。`strict-ftz` は note でマニフェストの `fp` を示す）。
  §12.4 の `@mem(fast)`（既定を名指す形で、候補は外すこと）と同じ形。ほかの名前（`fast`・`precise`・`default`・`Relaxed`・文字列の `"strict"` など）は、綴りや意味の近さによらず今のまま一覧の値を候補にする。`@repr`・`@host` には既定を名指す名前が無い。一覧の値が並ぶ形（`@fp(relaxed, strict)`）は今の規則（余分な引数を除く）が先。
  理由: 候補は書き手の意図が一つに決まる直し方で、`@fp(strict)` の意図は既定のままなので、逆の意味の `relaxed`（ビット一致の保証を外す）を候補にしない（`rules/criteria.md` 7.27）。名前の表は仕様自身の名前に限り、推測を含めない（S-602、S-965 の R1）。
  仕様 §6.5 に一文。実装は W5-24 の S-834 と同じ単位（`onsa_syntax/src/attrs.rs` の `@fp` の表に既定を名指す名前の欄。`strict-ftz` は S-834 の括弧の中の読みに乗る。見当 10〜20 行）。今通るプログラムは変わらない。
- 経緯: 129 回目（2026-11-09）、S-475 と同じ流れで決めた（`target/notes/129/s475/`）。`strict-ftz` を表に入れるのは段 1 の案（S-834 の後に `@fp(strict-ftz)` の候補が `relaxed` に落ちるのを防ぐ）。
