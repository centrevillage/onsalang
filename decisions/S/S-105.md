# S-105

- 空白: `strict-ftz` を受け付けるだけで、生成コードもインタプリタも FTZ / DAZ を扱わない。誰がいつ設定するかが仕様に無い（impl-review の §13.4 `strict-ftz`）
- 提案: C: `onsa__runtime.h` に制御レジスタの保存・設定・復元の補助を置く（x86 は `_mm_getcsr` / `_mm_setcsr` で FTZ と DAZ のビット、AArch64 は FPCR の FZ、ARMv7 / Cortex-M は FPSCR の FZ）。
  export の wrapper の入口で保存と設定、出口と panic の `longjmp` の後で復元する（`setjmp` と同じ場所）。扱い方を知らないアーキテクチャと WASM / JS は、そのターゲットのビルドで E0200。インタプリタ: `strict-ftz` のターゲットとして実行するとき、浮動小数の各演算の入力と結果の非正規化数を符号を保った 0 にする。
  適合性テストで、x86 と ARM の実機の結果を比べ、最小の正規化数の境界の違い（§15.5）を確かめる。マニフェストの `fp` を読む（今は古い名前の `numeric`、S-99）。`tests/review-phase1/parent/strict_ftz/` の期待値と今の出力は `m.onsa` の先頭のコメント（2026-10-06 決定。実装は第 3 段）
- 時期: M4
