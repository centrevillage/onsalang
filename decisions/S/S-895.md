# S-895 第 1 期の `impl Tr for Ty` の見出しをどこまで読むか（§6.3 の E0307 と §18.1 の「形の E0200 で、中の名前を読まない」）

- 空白: §6.3 は孤児規則・宣言の名前で書くこと・対象の型引数・`Float`・`Ordinal` の違反を全て E0307 とする。§18.1 は `impl Tr for P` を「形の全体がこの版に無いもの」として形の E0200 で、中の名前を読まないとする（S-713）。X-23 の X23-8 は第 1 期を「`Float`・`Ordinal` は E0307、`Hash` は E0200、`Show` と数・演算子の trait は第 2 期」とした。
  `db59c807` では見出しの形によらず全て E0200 で（`impl Float for P`、`impl Show for F32`、`impl Nope for P`、`impl Show for Nope`、`impl Show for A`（別名）、`impl Show for (U32, U32)`、`impl[T] Show for T`、`impl P for Q`（`P` は struct））、どの見出しの規則を E0200 より先に出すかが決まっていない。再現は `target/notes/115/w504/probe/`。
- 決定: 決定（2026-11-05、利用者。115 回目、組 86。細部は ID を挙げて了承）: (3)。`impl Tr for Ty` の見出し（`Tr`、`Ty`、`impl` の `[ ]`）を、固有の `impl` と同じ規則で名前の段まで読む（E0302、E0308、E0307）。名前の段の誤りがあればそれが単位の誤りで、形の E0200 は出さない。誤りが無ければ形の E0200 で、メンバは読まない。型の段の見出しの誤り（E0412、E0416）は段の順で報告しない。
  細部（確認だけ）: A1 `impl Iter[F32] for P` のような trait の位置の型引数は、今の E0002 をやめて構文で受け、見出しを読んで形の E0200 にする（§6.3 が認める形）。A2 §6.3 の規則は変えず、§18.1 の文だけを改める。A3 W5-04 の U1 に入れる。
  理由: §18.1 の「既存の規則の読みで拒めればその規則のコードにする」に最も素直に合い、§6.3 の E0307 に例外を作らない。型の段の順は固有の `impl` と同じ規則で済む。名前の段の検査は W5-06 の `impl Default` と第 2 期がそのまま使う。見積もりは +50〜80 行。
  独立のレビュー（段 1）も (3) で親の読みと一致し、段 2 は省いた。形の表と想定漏れの表は `target/notes/115/s895-advisor/`。
- 経緯: 115 回目（2026-11-05）、親が W5-04 の票を書く前に、§6.3 と §18.1 の文と `db59c807` のバイナリを突き合わせて見つけた。関係: S-70、S-108、S-138、S-139、S-145、S-713、S-719、S-756、X-23 の X23-8。
