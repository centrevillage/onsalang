# S-231 変換先の型を扱える変換と丸めの書き方（総称の `T: Float` へ `U32` などを変換する形）と、今の変換メソッドとの関係

- 決定済みで戻さないもの: S-98（`as` は情報を失わない組と同じ型だけ、型の組ごとに書き方は一つ）、S-210（型パラメータの素の `as` は E0411）、S-189（縮小は `Option`、浮動小数から整数は切り捨てと飽和）、S-875・S-880（`as` で書ける組の候補）、§6.6（リテラルは `T` の値にならない）、S-239（`::[…]`）。
  第 82 組の下書きの全文（「仕組みの出所」「形の表」と A-09 の節）の写しは `target/notes/111/g82/draft.md`、入力は `P111/g82/probe/`（消えうる）
- 論点: §3.3 は数の型の間の変換を表で閉じ、`as` で書けない組を「変換元の型のメソッド」（名に変換先を書く）で書く。型パラメータの値には `as` を書けない（83 行）。
  変換先が型パラメータ `T` のとき（`U32` → `T: Float`、`F64` → `T`、`T` → `U`）と、変換元が `T` のとき（`T` → `U32`）の書き方が無い。`vdelay` の疑似コード（§11.4、S-212）は前置きで済ませ、総称の平均（`acc / (N as T)`）は書けない。
  決めるのは、総称の変換を書く形と、それが具体的な型の今のメソッドと二通りの書き方にならないための扱いである。
  - 決定済み（論点から外す）: `as` を情報を失わない組と同じ型に限ること（S-98）。型パラメータの素の `as` が E0411 であること（S-210。候補の有無だけは下の (b)・(a) の帰結で触れる）。型の組ごとに書き方は一つ（S-98）。
    縮小が `Option` を返すこと、浮動小数から整数が切り捨て（panic）と飽和の二つであること（§3.3 の表、S-189）。`as` で書ける組のメソッドの E0413 と候補（S-875・S-880）。リテラルが `T` の値にならないこと（§6.6）。`::[…]` の記法（S-239）。
- 今の実装: 形の表のとおり。総称の変換は `as`・メソッドのどちらで書いても誤りで、`as` の E0411 は候補を持たない。具体的な型の今の形は全て通る。
- 案: どの案も、`as`（情報を失わない組と同じ型）は今のまま残す。下の名は例で、名の細部は「あわせて決めること」。
  - (a) `as` に方式を書く形: `k as(round) T`、`y as(trunc) I32`、`y as(trunc_sat) I32`、`x as(narrow) I8`（型は `Option[I8]`）。型パラメータには境界が方式を与える（`T: Float` は `as(round)` の変換先、`T: Int` は `as(narrow)`・`as(trunc)`・`as(trunc_sat)` の変換先）。
    今の変換メソッドは外す（残すと具体的な型で二通り）。`as` で書ける組に方式を書いた形は誤り（候補は素の `as`）。
  - (b) 変換先の型の関連関数: `T.round_from(k)`、`F32.round_from(k)`、`I32.trunc_from(y)`、`I32.trunc_sat_from(y)`、`I8.narrow_from(x)`（`Option[I8]`）。前例は `F32.from_bits(u)`・`Mode.from_ordinal(n)`。
    std が組込みの型の `impl` に変換元を型パラメータに持つ関数として宣言し（浮動小数に `round_from[S: AnyNum]`、整数に `narrow_from[S: Int]`・`trunc_from[S: Float]`・`trunc_sat_from[S: Float]`。浮動小数 2 型と整数 8 型で 26 個）、数の trait（`Float`・`Int`）にも同じ名を置いて `T.round_from(k)` を境界から引く。
    今の変換メソッドは外す。`as` で書ける組（変換元と変換先がどちらも具体的な型）の呼び出しは E0413（候補は `as` の形。`narrow_from` は S-875・S-880 と同じく期待の型で `x as T` か `Some(x as T)`）、同じ型への呼び出し（`T.round_from(x)`、`x: T`）は E0413 で候補は呼び出しを外す形。
  - (c) 変換先を期待の型か型引数で決める総称の関数: `round_to(k)`、`trunc_to(y)`、`trunc_sat_to(y)`、`narrow_to(x)`（`Option[D]`）。宣言は `round_to[S: AnyNum, D: Float](x: S) -> D` の形で、`D` は期待の型か後の文で決まり、明示は `round_to::[U32, F32](k)`（`_` が無いので二つとも書く）。
    置き場所は prelude（後から足すと壊れる名、§11.4 の版の項）か `std.num`（`use` が要る）。変換元のメソッドの形（`k.round_to()`、`k.round_to::[T]()`）も同じ類である。今の変換メソッドは外す。
  - (d) 数の trait の関連関数を総称のコードにだけ置く: (b) と同じ名を `Float`・`Int` に置き、型パラメータから `T.round_from(k)` と引く。具体的な型では今のメソッドを残し、`F32.round_from(k)` は E0413（候補は今のメソッドの形）。
  - (e) 何も足さない: 総称の変換は書けないまま、幅ごとに具体的な関数を書くか、呼ぶ側が変換した値や変換の関数値（`conv: fn(U32) -> T`）を引数で渡す。§11.4 の前置きと A-09 の保留はそのまま。
  - 形ごとの出力（`vdelay` の `k` と `f`、具体的な `F32` の今の形は `let k = dc.trunc_u32()`・`dc - k.round_f32()`）:
    (a) `let k = dc as(trunc) U32`・`dc - (k as(round) T)`（括弧は E0011）。(b) `let k = U32.trunc_from(dc)`・`dc - T.round_from(k)`。
    (c) `let k: U32 = trunc_to(dc)`・`dc - round_to(k)`（`D` は `-` の相手の `T` で決まる。`infer/i01` と同じ型付け）。(d) 総称では (b) と同じで、具体的な `F32` では今の形。(e) 総称では書けない。
    `sqrt(power).round_f32()`（`F64` → `F32`）は、(a) `sqrt(power) as(round) F32`、(b) `F32.round_from(sqrt(power))`、(c) `let m: F32 = round_to(sqrt(power))`、(d)・(e) は今のまま。
  - 具体的な型で二通りになるか: (a)・(b)・(c) は今のメソッドを外すので一通り（残すと二通りで、§3.3 の「型の組ごとに書き方は一つ」に反する）。fmt は型を見ないので、揃える役は E0413 の候補と `onsa fix` になる。
    (d) は具体的な型と型パラメータで書き方が分かれ、`F32.round_from(k)` を E0413 にする例外が要る。(e) は変わらない。
    別名で精度を切り替える形（`type Sample = F32` → `F64`）は、どの案でも書き直す位置が残る（`U32` → `F64` は `as` の組で、変換の形が E0413 になる。S-98 の一つの書き方の規則のまま）。総称の `T` で書けば (a)〜(d) で切り替えられる。
  - 範囲外の扱い: 縮小の `Option` は、(a) が `as(narrow) I8` の書いた型と結果の型（`Option[I8]`）のずれを規則にする。(b) は名と返り値（`I8.narrow_from(x) -> Option[I8]`）で示し、(c) は期待の型を `Option[I8]` にする。
    切り捨てと飽和は、(a) が方式の語、(b)・(c) が名で分ける。丸めは最近接偶数の一つで、どの案も方式は一つ（`round`）。(d)・(e) は今の名のまま。
  - 書き手から見て（LLM を含む）: (b) は変換先の型が式の頭に見え、他の言語の多数の形（変換先の型の名で作る形）に近い。続けて書く形（`x.f().round_f32()`）は入れ子になる。
    (a) は `as` を知る書き手に近いが、`as(…)` の形はどの言語にも無く、二項演算子の中では括弧が要る。(c) は変換先が呼び出しに見えず、期待の型の無い位置（注釈の無い `let`、受け手）では E0406・E0420 で一回増える。

  - 修正候補: E0411 の具体的な型の候補は、(a) が方式の挿入（`k as F32` → `k as(round) F32`）、(b) が関数で包む形（`F32.round_from(k)`）、(d)・(e) が今のメソッド。

- 推奨と理由: (b)。確度: 中。
  - 一つの形が具体的な型と型パラメータの両方に当たり、書き方が文脈で分かれない。`as` で書ける組の E0413 は今のメソッドの規則をそのまま新しい形に当てるだけで、例外を足さない。(d) は具体的な型と型パラメータで書き方が分かれる例外を足し、変換を足すたびに二か所の手当てが続く。
  - 「変換先の型の値を作る」形は、既に `F32.from_bits(u)`・`Mode.from_ordinal(n)`・`T.default()` が変換先の型の関連の名前で書いている。型パラメータからは §6.6 の `T.ZERO` と同じ道で引け、新しい言語の仕組みが要らない。
    (a) は構文と方式の一覧と、縮小で書いた型と結果の型がずれる規則を足し、変換の知識を std の宣言からコンパイラに戻す。(c) は変換先が呼び出しに見えず、期待の型の無い位置で検査の回数が増え、明示の形は型引数を二つ書く。
  - 書き手から見て、変換先の型と方式が式の頭の名に出て、返り値の型（縮小の `Option`）が名から分かる。E0411 の候補は関数で包むだけで、前置の `-` の括弧の手当てが要らず、`k as T` にも候補を出せる。
  - 後の追加では、利用者の型（第 2 期の固定小数点）への変換を、その型の `impl` に関連関数として置ける。今のメソッドの形は、変換先が利用者の型のとき組込みの型にメソッドを足せない。
  - 費用は書き換えの量（`tests/spec` の 850 か所など）で、受け手の大半が名前なので台本で行える。利用者もリリースもまだ無く、W5-14 U2・U3 が今の名で候補とテストを書く前に置き換える方が、後で候補とテストを作り直すより手戻りが少ない。続けて書く形が入れ子になる代償は残る。
  - あわせて決めること:
    - 名: `round_from`・`trunc_from`・`trunc_sat_from`・`narrow_from`（今の `trunc_<型>_sat` の `_sat` を方式の語の後に置く）。前例の `from_bits`・`from_ordinal` は変換元の種類を `from_` の後に書くので、方式を前に書く形との違いは名の一覧で示す。
    - 宣言: 浮動小数（`F32`・`F64`）に `round_from[S: AnyNum](x: S) -> Self`、整数 8 型に `narrow_from[S: Int](x: S) -> Option[Self]`・`trunc_from[S: Float](x: S) -> Self`・`trunc_sat_from[S: Float](x: S) -> Self`。`Float` と `Int` に同じ名を置く（`Int` は第 2 期に利用者の型が実装する前に足すので壊れない、A-09 の理由）。
    - 組の判定: 変換元と変換先がどちらも具体的な型（別名は解決した型）で `as` で書ける組なら E0413（候補は `as` の形。`narrow_from` は S-875・S-880 の期待の型の規則）。変換元か変換先が型パラメータなら、具体化で情報を失わない組（`F64.round_from(x)`、`x: T: Float`）でも書ける（`as` を書けないため）。
