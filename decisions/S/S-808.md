# S-808 借用の `for` の本体で、Dup の値の反復元に `move` を書く形（`for s in names { let c = move names }`、`names: [Str; 3]`）が E0715 か

- 空白: §5.4 の 135 行は、借用の `for` の本体で反復元とその一部への変更を「代入、`inout` への受け渡し、`!` のメソッドの呼び出し、`move` は E0715」とし、`move` の値の種類を区別しない。
  §5.2 の 58 行は Dup の値の `move`（`let y = move s`）を複製とし、77 行は重なりで読みとして数える。§5.4 の 140 行は E0715 の理由を、反復の途中で要素が変わらず記憶域が解放されないこととする。
  読み: (1) Dup の値の `move` は複製で元を変えないので、変更でなく E0715 に当たらない。(2) 135 行の字のとおり、Dup の値でも `move` と書けば E0715。
  dev（`dc86ef24`）は (1)。`for s in names { let c = move names }`（`names: [Str; 3]`）と `[U32; 3]` の形は通り、`[Buf[F32]; 2]` は E0715（W4-09 U1 の modes は Dup の値の `move` を移動の処理に入れない）。再現は `issues` に置かず、事例 `tests/spec/values/borrow_for_dup_move.onsa`。
- 決定: 決定（2026-10-31、利用者。91 回目。確認だけ。親の読み）: (1)。借用の `for` の本体の Dup の値（Copy、Shared、関数値の変数、境界の無い `T`）の `move` は複製で読みなので、反復元とその一部への `move` でも E0715 に当たらない。仕様 §5.4 の 137 行の「当たらない」の並びに一文を足した。実装は W4-09 U1 で済み（変更なし）。
- 経緯: 91 回目（2026-10-31）、W4-09 U1 の壊す側（onsa-break）が空白の候補として挙げ、親が §5.2 から決まると読んで S を作らなかった。同じ回の文書の点検（onsa-docs、`66a0f22c..db70cdb6`）が、§5.4 の 135 行が `move` を条件なしに挙げ、その読みを書いていないと報告した。親が説明し、利用者が (1) を了承した。
