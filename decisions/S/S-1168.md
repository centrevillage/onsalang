# S-1168 細部: `onsa graph` の `par~` の添字の頂点の名前が、同じ `par~` の中の節点の名前と重なる（`par~ lp_0 in …` の本体の `lp~`）

- 空白: `spec/tools.md` §1.3 は、複製の添字の頂点の名前を `par~` の名前で修飾し（`saws.i`）、「入れ子でも重ならない」とする。§11.6 の節点の名前は `<種類>_<番号>`（`lp_0`）で、添字は利用者の名前なので、`par~ lp_0 in 0 ..< 2 { lp~(x * F32.round_from(lp_0)) }` では添字の頂点 `saws.lp_0` と本体の節点 `saws.lp_0` が同じ名前になる（`spec/tools.md` §1.3 の文と、`spec/tools.md` §1.2 の「実線の辺だけでは閉路を作らない」が破れる）。
  読みは (1) 添字の頂点の名前を、処理系の名前とも利用者の名前とも重ならない形にする（`saws.(i)` の類。全ての添字の頂点の名前が `spec/tools.md` §1.3 の例と変わる）、(2) 重なるときだけ別の名前にする（ふつうの形は `spec/tools.md` §1.3 のまま）、(3) `spec/tools.md` §1.3 の形のまま（重なった頂点は Graphviz で一つになる）、に割れる。S-1138（生成する名前を利用者の書けない形にする）と同じ向きの問い。
  再現: `target/notes/169/w715/memo/cases6.txt`（今は添字を `par~` の頂点に対応付けるので重ならない。W7-15 U3 で添字の頂点を描くと重なる）。
  仮の扱い: (2)。別の名前の形は W7-15 U3 の実装で選んで報告し、`SPEC-GAP(S-1168)` の印を付ける。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
