# S-705 extern が効果行で主張した効果を、handler で処理したとき（C の関数は handler を通らない）

- 空白: extern 宣言の効果行は検証されない主張である（§14.1）。handler で処理した効果は `handle` 式の効果行から消える（§8.3）が、extern の C 関数は handler を通らない。
  `uses {Fs}` と主張した C 関数を呼ぶ関数を `handle { … } with memory_fs` で包むと、`Fs` は効果行から消えるが、C の関数は本物のファイルに触れる。`uses {Alloc}` と主張した C 関数を `arena` で包むと、ヒープの無いターゲットでもシグネチャの検査を通るが、C の関数は本物のヒープを使う。
  §8.3 と §14 にこの関係の規則が無い。§8.2 の「`Block` は handler で処理できない」は、この場合の一つが `Block` で表に出たものである（S-704）。
- 決定:
- 経緯: 71 回目（2026-10-26）、S-704 の議論で親が見つけた（§8.3・§14 を読み、extern と handler の関係の文が無いことを確かめた）。
  利用者: `Block` を処理できる穴は使う側の問題で、`unsafe` を使うようなものである。言語が保証する範囲の外と思う。
