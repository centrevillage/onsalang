- 論点: §12.2 は「所有する Shared 値・`Buf` と、それらを含む値の破棄」に `Alloc` が要るとし、一時の値の段落で、消費しない位置（受け手、借用の引数、被演算子、条件、添字とフィールドを読む基）の一時の値は、使う呼び出しか演算の後に破棄されるとする。
  §11.5 は効果を持つ fn の呼び出しを E0805 とし、「flow とその初期化はヒープを使わない」とする。§11.6 は「`init` は効果を持たず、ヒープを使わない」とする。
  flow の本体の一時の値の破棄が誤りか、誤りならどのコードか（`rt fn` と同じ E0601 か、flow の E0805 か、値の型の E0810 か）が書かれていない。flow には効果行が無いので、§8.1 の「効果行に無い効果の使用」の字にそのままは当たらない。
- 今の実装: 形の表のとおり。flow の本体の一時の値は、型によらずどの診断にもならない。同じ式を `rt fn` に書くと E0901（「`mk(1)` is dropped after it is used, whose destruction needs `Alloc`; `rt` functions cannot allocate」）、`fn` に書くと E0601 である。
  flow の本体の補間（`"a{x}".len()`）も通る（`rt fn` は E0901、`fn` は E0601）。E0805 の文面は「`mk2` has effects; a flow calls effect-free functions only (§11.5)」で、修正候補は無く、`--fix-loop` は `no-candidate` で止まる（`effect_fn`）。
  効果の段（`effects.rs`）と `rt` の段（`rt.rs`）は `DefKind::Fn` だけを見て、flow を見ない。E0805 は flow の段（`flow/rate.rs` の 376 行）が呼び出しごとに呼び先の効果行を見て出す。
