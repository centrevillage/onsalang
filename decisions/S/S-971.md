# S-971 定数式の位置に書いたホール `_`（`[F32; _]`、`[0.0; _]`）のコード: 定数式の文法の外の E0417 か、式の位置のホールの E0421 か

- 空白: §18.1 は「式の位置に `_` を書くと、期待される型、使える効果、スコープ内の候補が報告され（E0421）」とし、§4.5 は「定数式でないもの…を書くと、位置によらず…E0417」とする。定数式の位置（配列の長さ、繰り返しの数、const 引数、遅延線の長さ、`par~` の端）のホール `_` はどちらにも読める。
  読みは (1) 定数式の文法の外の形なので E0417、(2) 式の位置なので E0421「hole of type `U32`」、に割れる。どちらも誤りで、通るプログラムは変わらない。違うのはコードと文面だけ。
  dev `3d61c76c` は、署名・本体が E0200「expressions as array lengths」、flow が E0417。
  親の読み: (1)。§15.1 の「その形にコードを定める位置に固有の規則があれば、そのコードが先である（…ローカルの束縛を書いた配列の長さの E0417（§4.5）など）」により、定数式の位置の規則が先になる（S-967 の値の後の名前と同じ当て方）。
  仮の扱い: (1)（W5-16 U1b1 の読み手、`crates/onsa_sema/src/constarg.rs` の `SPEC-GAP(S-971)`）。
- 決定: 決定（2026-11-12、利用者「他の (A) は現状で OK」。140 回目、W5-13 の前の確認だけ）: 仮の扱いの (1)。定数式の位置のホール `_`（`[F32; _]`、`[0.0; _]`）は E0417（§15.1 の、位置に固有の規則のコードが先、の当て方）。§4.5 に足した。`constarg.rs` の `SPEC-GAP(S-971)` の印は W5-13 で外す。
- 経緯: 130 回目（2026-11-10）、W5-16 U1b1 の実装の担当が報告した（再現 scratchpad の `w516u1b/i/probe/p5.onsa`・`p1.onsa`）。
- 補い（2026-11-10、親）: W5-16 の仮の扱いは W5-16（U1b1・U1b2）で入れた。W5-16 を DONE にしたので、担う作業を W5-13（期限と同じ）にした。決定が仮の扱いと違えば W5-13 で直す（131 回目）。
