# S-610 静的な値の範囲: 静的な値だけを要素にする集成体のリテラル（`["a", "bc"]`）を静的な値と扱うか

- 空白: §5.4 の静的な値（借用の起点）は `const` と補間の無い文字列リテラルだけで、§12.8 は補間の無い文字列リテラルと Shared の `const` を静的オブジェクトとして静的領域に置く。§6.6 は `const` の結果を Copy か静的に配置できる Shared（`Str`、`Bytes`、要素が静的に配置できる `Array`）とするが、今の実装は Shared の `const` を E0407 にする（R-85）。
  静的な値だけを要素にする集成体のリテラル（`["a", "bc"]`、`("a", 1)`）を静的な値として静的領域に置くか（借用の起点にするか）が書かれていない。
  置かなければ、rt の関数の `let t = ["a", "bc"]`（§5.4 の静的でないリテラル）は破棄に `Alloc` を要して E0601 で、S-604 の後は `for s in ["a", "bc"]`（場所でも静的な値でもない反復元）も同じになり、今の実装は Shared の `const` も E0407 にするので、rt の関数で文字列の表を持つ手段が無い。
  どこまで静的領域に置くか（リテラルの形、`const` の Shared、入れ子、補間の無い文字列の配列）は言語全体に関わるので、W4 の前に決める（利用者）。
- 決定: 決定（2026-10-23、利用者が了承。58 回目、第 44 組）: (b1)。静的な値だけでできた集成体のリテラルも静的な値で、借用の行（rt の関数でも `let t = ["a", "bc"]`、`for s in ["a", "bc"]`、`g(["a", "bc"])`、`match ("a", 1)` が通る）。置き場所は約束しない（組込みの Flash と RAM の置き場所は S-612）。
  理由（利用者）: 組み込み環境ではそもそも `Alloc` が使えない。理由（助言の担当）: S-80 の根拠（不滅の静的オブジェクトの複製と破棄は何もしない）がそのまま当たり、式の形の区別に意味の根拠が無い。
  静的な値は、`const`（関連定数と総称の定数のパラメータを含む）、補間の無い文字列リテラル、数・真偽・文字のリテラル、ペイロードの無い列挙子と、全ての要素が静的な値の配列（`[e; N]` を含む）・タプル・struct のリテラル・ペイロード付きの列挙子・括弧（入れ子を含む）。
  演算子・呼び出し・ローカルの名前を含むものは所有（`("a", 1 + 2)`、`("a", -1)`、`["a", x]`、`("a", v)`）。構文で決まり、名前の段で一度だけ判定して、束縛の状態と破棄点が同じ印を読む。
  §6.6 の「静的に配置できる」は型の構造で定める（Copy、`Str`・`Bytes`、要素・フィールド・ペイロードが全て静的に配置できる `Array[T]`・`[T; N]`・タプル・struct・enum。`Map`・`Set`・Affine を含む型は E0407）。この版の Shared を含む型の `const` は E0407 でなく E0200（S-67、R-85 の記録。S-87 の前提のまま）。
  §12.2 の「Shared 値の生成」はヒープのオブジェクトの生成で、Shared を含む値の型を組むことは入らない。所有する Shared を含む値の破棄は `Alloc` が要り、静的な値の複製と破棄（一時の値を含む）は要らない。
  Copy の型の要素を持つ集成体（`("a", v)`）はこの組で決めず、利用者が組込みで書けないと制限が大きいので前もって検討したいとして S-613（W4-07 の前）にした（下書きの回答の「`decisions/A/` の候補」を改めた）。rt の関数で `move` の引数の Shared 値を返す E0901 は R-255。仕様 §5.4、§6.6、§12.2、§12.8
  改め（2026-10-24、S-613）: §5.4 の「構文で決まり、型を見ない」は静的な値に限る。Copy の型の要素を持つ集成体（`("a", v)`、`("a", 1 + 2)`、`("a", -1)`）は破棄の要らないリテラルで借用の行（S-613）。静的な値の判定は今のまま構文で決まる。
  補い（2026-10-24、利用者が了承「F7はOKです」。S-613 の文書の点検の F7）: 自分の型が `Drop` を実装する（Affine の）リテラルと列挙子は、全ての要素が静的な値でも静的な値にならず、所有の行（§4.6、§6.3）。§5.4 の「構文で決まり、型を見ない」は「要素の型を見ない（`Drop` を実装する型は除く）」に改めた。
  改め（2026-10-24、S-613 の補い L4）: 破棄の要らない束縛の名前を要素にするリテラル（`let nm = "gain"; (nm, v)`）も、破棄の要らないリテラルで借用の行（S-613）。静的な値の判定は今のまま構文で決まる。
- 経緯: 57 回目（2026-10-23）、第 42 組（S-604）の助言の担当の段 1 が新しい S の候補にし、利用者が W4 の前に決めると了承した（B17。「どこまで静的領域に配置するかという言語全体に関わる論点」）。今の実装は rt の `for s in ["a", "bc"]` を通す（第 42 組の `m1s/s34`）。関係: S-80、S-604、R-85、§6.6、§12.8。
  58 回目、第 44 組の二回目（族「静的な値の範囲」、下書き `S-610.draft.md`、助言の担当の二段）。下書きは (a)（集成体のリテラルは所有）、段 1・段 2 は (b1) で割れ、利用者が (b1) を選んだ。利用者が組込みの論点（Flash と RAM の速さと容量、表を RAM に置く高速化）を挙げ、親が S-612 を登録した。
- 補い（2026-10-29、親）: 84 回目、W4-16 の設計メモと助言の審査から（利用者が了承、A1）: 静的な値の判定は名前の段でなく、本体の型の推論の後の確定（W4-16 の `onsa_sema/src/binding/`）で一度だけ行う。判定が式の型を見る（F7、関連定数 `T.ZERO` は型の段で解決する）ため。束縛の状態と破棄点（W6-02）が同じ印を読む目的は保つ（`BodyInfo.lits`）。外に見える出力は同じ。
