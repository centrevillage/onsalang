# S-582 プラグインのノートとボイス: ホストのノートと MIDI のイベントの写し方、ポリフォニー

- 決定済みで戻さないもの: 組の全体は S-580 の下書きの頭（第 35 組の境界の見込み、S-565 の R12、`@param` と数値の ID、S-172、§14.2 の C の API の原則、ランプは扱わない）。第 35 組の C の API への影響（A1〜A8）は S-580 の下書きの「影響」。
- 論点: S-572 は境界のイベントの型を `midi.Message`（MIDI 1.0）と `transport.Event` にした。CLAP はノートを MIDI と別のイベント（`CLAP_EVENT_NOTE_ON` など。`note_id`、ノートの表情）でも渡し、VST3 はノートを構造で渡して CC をイベントで渡さない。
  §17.6 は「Onsa では同じ言語で書け」として、ボイスの割り当てを struct `Poly` と関数で書く。
  - 決定済み: 境界のイベントの型（S-572。std の型を後で足しても壊さない）と一つの列（S-570）。flow の中ではイベントの段の状態で割り当てを書ける（§19.1「`let v = assign(m, prev~(^v))` は m の刻みの式」）。
  - §17.6 の `Poly` は struct と関数なので、export（flow と、スカラと `Span` の関数だけ。§14.2）に出せず、プラグインの入口にならない。
  - (1) ホストのノートと MIDI の写し方（入力と出力、入力が二つ以上のとき、トランスポート）。(2) ボイスの割り当ての持ち主。(3) ボイスの終わりの通知（CLAP の `CLAP_EVENT_NOTE_END`）。
- 今の実装: イベントのクロックは未実装で、`notes: Note at event` は E0302「cannot find the clock `event`」（第 35 組の `q02`）。std に `midi` は無い（`std/` は `dsp`・`math`・`array`・`test`）。それ以上は試していない。
- 案:
  - 写し方:
    - (n1) 全て `midi.Message` に写す。CLAP のノートのイベントは MIDI 1.0 のノートオン・オフに（速さ `round(v × 127)`、ノートオンは 1 以上）、CLAP の MIDI はそのまま。
      VST3 の `NoteOnEvent`・`NoteOffEvent`・`PolyPressureEvent` を写し、CC・ピッチベンド・チャンネルプレッシャーは `IMidiMapping` の隠したパラメータで受けて MIDI に戻す。AU は MIDI のまま。
      `note_id` とノートの表情は捨てる。出力は CLAP の `CLAP_EVENT_MIDI`、VST3 はノートと `LegacyMIDICCOutEvent`、AU は MIDI の出力の block（AUv2 は `kAudioUnitProperty_MIDIOutputCallback`）。費用: VST3 の隠したパラメータ（16 チャンネル × (128 の CC + 2)）の表。std の型は増えない。
    - (n2) std にノートの型（`note.Event`: 種類、`note_id`、チャンネル、キー、`F32` の速さ、表情の番号と値）を足し、ホストのノートをそれに写す。MIDI 1.0 しか来ない所（AU、CLAP の MIDI の方言）では `note_id` を −1 にする。費用: std の型と C の表し方（struct）を一つ決め、MIDI からノートへの写しを持つ。
    - (n3) 入力の型で選ぶ: `midi.Message` の入力には MIDI を、`note.Event` の入力にはノートを写す（(n1) と (n2) の両方を持つ）。費用: 両方の写しと、ホストへ示す方言の選び方。
  - どの案でも: イベントの入力の `midi.Message`（か `note.Event`）ごとに一つのノートのポート（宣言の順、最初が主）。`transport.Event` の入力には、ホストの再生の状態の変化を写す（止まる→動くで `START` か `CONTINUE`、動く→止まるで `STOP`）。
  - ボイス:
    - (v1) 利用者の Onsa のコード: export する flow が MIDI を受け、イベントの段の状態と `par` でボイスを割り当てる。ラッパーは MIDI を渡すだけ。費用: ラッパーに無い。書き手が割り当てを書く（std に割り当ての flow を置けば減る）。
    - (v2) ラッパー: `[[plugin]]` に `voices = 8` と書き、export する flow は一つのボイスで、ラッパーが 8 個の状態を持ち、ノートを割り当て、出力を足す（奪い方はラッパーの決まり。Faust の `mydsp_poly` の形）。費用: 割り当ての規則を仕様に書き、C のラッパーと `render`・`onsa test` の両方に持つか、テストで再現できないままにする。
    - (v3) 言語の機能（ボイスの割り当ての構文か組込みの flow）。費用: 構文と意味の設計が要る（第 2 期より後）。
  - 終わりの通知: (e1) 第 1 期は出さない。(e2) flow のイベントの出力の std の型（`note.End`。`note_id`、チャンネル、キー）で出し、ラッパーが `CLAP_EVENT_NOTE_END` に写す。費用: (e2) は std の型と、ノートの入力との対応。
- 他言語:
  - CLAP（`ext/note-ports.h`、`events.h`）: 方言は `CLAP_NOTE_DIALECT_CLAP`・`MIDI`・`MIDI_MPE`・`MIDI2`。`clap_event_note` は `note_id`（「host provided note id >= 0, or -1」）と `double` の速さ（0〜1）。
    `NOTE_END` は「useful to help the host to match the plugin's voice life time」「When using polyphonic modulations, the host has to allocate and release voices for its polyphonic modulator」。`ext/voice-info.h` はボイスの数を示す。
  - VST3（`ivstevents.h`）: イベントの種類は `kNoteOnEvent`・`kNoteOffEvent`・`kDataEvent`・`kPolyPressureEvent`・`kNoteExpressionValueEvent` など。CC は上の `IMidiMapping` のとおりパラメータに写す。
  - AU（`AUAudioUnit.h`、`AUAudioUnitImplementation.h`）: 描画のイベントの `AURenderEventMIDI` と MIDI 2.0 の `AURenderEventMIDIEventList`、`supportsMPE`、`MIDIOutputEventBlock`。
  - Faust（`poly-dsp.h`）: 一つのボイスを生成し、architecture の `mydsp_poly` が `/freq`・`/gate`・`/gain` の名前の入力に割り当てる（奪い方は `getFreeVoice`）。Cmajor: 割り当ては std の `std::voices::VoiceAllocator`（Cmajor のコード）。
    nih-plug: 割り当ては利用者のコードで、`NoteEvent::VoiceTerminated` を `NOTE_END` に写し、ボイスごとの変調はノートのイベントで渡す（`src/wrapper/clap/wrapper.rs`）。
- 推奨と理由: (n1)、(v1)、(e1)。確度: (1) 中、(2) 中〜高、(3) 中。
  - (n1): 境界の型は既に `midi.Message` で、三つの形式で同じ写しになり、std の型が増えない。`note_id` と表情が要るのは、ホストのボイスごとの変調と MPE より細かい表情で、どちらもこの組の後に回す。
    (n2)・(n3) は後で std の型を足す形で入り（`onsa_event_kind` の末尾、std は prelude の外）、今のプログラムを壊さない。
  - (v1): 割り当てを `onsa test` と `render` で確かめられ、三つの形式と JavaScript・WASM で同じ動きになる。言語には既に手段（イベントの段の状態、`par`、`reset_if~` のイベントの刻み）があり、マニフェストのキーもラッパーの規則も増えない。
    (v2) は割り当ての規則がラッパーと Onsa の二か所に要るか、テストで再現できない。(v3) は大きい。
  - (e1): `NOTE_END` が要るのはホストのボイスごとの変調のときで、S-581 の (mo1) で受けない。(e2) は (mo3) と一緒に足せる。
  - あわせて決めること: 速さの写し（`round(v × 127)`、ノートオンは 1 以上。逆は `v / 127`）。`START` と `CONTINUE` は、動き出した位置の `beat` が 0 なら `START`、それ以外は `CONTINUE`。
    AU のターゲットで `midi.Message` の入力が二つ以上なら E0200（AUv2 の `MusicDeviceMIDIEvent(inUnit, inStatus, inData1, inData2, inOffsetSampleFrame)` はポートを持たない。`MusicDevice.h`）。SysEx は写さない（`midi.Message` が持たない、S-572）。
    MPE はチャンネルの情報を保つので MIDI 1.0 のまま通り、ホストに MPE を示す印（CLAP の `MIDI_MPE`、AU の `supportsMPE`）は `[[plugin]]` のキーとして後で足す。
  - 新しい S の候補: std のボイスの割り当ての flow（M5。奪い方を引数で選ぶ形）と、§17.6 の例をイベントの入力の flow で書き直すこと。
