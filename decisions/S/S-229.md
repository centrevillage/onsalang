# S-229

- 空白: 呼び出しの深さ（§12.5、S-222）で「呼び出し」と数えるものの範囲。std の関数（Onsa で書かれる、§6.6）の中の呼び出しを数えるか（数えると利用者のコードの境界が std の実装で動く）、組込みのメソッド（プリミティブ）と、演算子の trait の実装の呼び出しを数えるか。
  あわせて確かめること: 引数の位置の呼び出し `f(g(x))` は動的な深さで数え（`g` は `f` の入れ子でない）、`f.(x)` は 1 回の呼び出し（W2-04/t2 がこの読みで事例を書いた）。W2-04/t2 で見つけた（2026-10-08）
- 提案: 空白の流れ（`rules/process.md` 8.6）で下書きと独立のレビューに回す。急ぎは後の段（W5 の std を Onsa で書く作業の前に決める）
- 時期: W5
- 決定: 決定（2026-11-03、利用者が ID を挙げて了承。105 回目、第 78 組。下書きと独立のレビュー（段 1）が一致）: (b)。数える呼び出しは、std の外（利用者のパッケージと依存のパッケージ）で宣言した関数・メソッド・無名関数の呼び出しで、どこから呼んでも（std の本体や処理系が与える実装から、関数値を通しても）数える。
  std の関数（本体の有無によらない）と、処理系が構造から与える実装（タプル・配列・`Option` の `==`、derive）は数えない。引数の位置の呼び出しは §3.5 のとおり入れ子にならない。
  細部: 関数値の呼び出し `f.(x)` は呼ばれる関数の宣言で決まる。`array.from_fn` に渡した利用者の無名関数も要素ごとに 1 に数える（今の展開の所で深さを足す）。数えない std の本体と `==` の入れ子も実のスタックを使うので、W9-03 で R-05 の測りを確かめ直す。
  理由: 上限で止まるかが利用者のソースだけで決まり、W5-02・W5-07・§6.6 の musl の移植・W8-10 で境界が動かない。止まらない再帰は利用者の関数を通ってしか起きないので、数えなくても守りは減らない。
  仕様 §12.5 の 67 行。作業: Core の関数の印と `onsa_interp` の `call_with`（W5-02。std の本体が入る前か同じ単位で）と、評価器（W9-03）。
