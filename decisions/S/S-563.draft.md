# S-563 イベントのクロックの値と他のクロックの値を混ぜる規則

- 決定済みで戻さないもの: §11.3（遅いクロックの値は速いクロックで値を変えずに読め、速いクロックから遅いクロックへ移す書き方は無く、間引きは明示の flow）。S-152（`at` は値も評価の段も変えず、状態を作らない）。S-171（変換は std の flow で、flow の組込み名にしない）。§11.4（組込み名を後から足さない）。
- 論点: 記号: E(e) は「イベントの入力 `e` のイベントの刻み」を指す説明の記号で、Onsa の構文ではない。入力の番号（p01 など）は、47 回目に dev `4aaa028` の release の `check` で試した入力（S-560 の「今の実装」の表）。
  §19.1「入れるときに決めること: … イベントのクロックの値と他のクロックの値を混ぜる規則」。§11.3「遅いクロックの値を速いクロックの式で使うのは、値を変えない（次に変わるまで同じ値が続く）」。イベントの値は刻みの間に値が無く、同じ位置に複数あることがある。
  - (1) イベントの値を `sample` の式で読む形。(2) `sample`・`block`・`init` の値をイベントの段の式で読む形。(3) std の flow で書く変換と、言語が持つ仕組みの境界。
  - 決定済み（§11.3、S-171）: (3) のうち、変換を flow の組込み名（`prev~` と同じ扱い）にする案は採らない。論点から外す。
- 今の実装: イベントは無い（E0302）。flow は型引数を持てない（p19 の E0002）。数える flow と `n != prev~(n)` は書ける（p20）。
- 案:
  - (1a) 最後の値を保つ（Esterel の `?S` と同じ）。最初のイベントの前は `T.default()`（無ければ E0816）。実装: 巻き上げの隠れたフィールドと同じ仕組みで、イベントの段で書き `sample` の段で読む。
    費用の要因: 同じ位置の複数のイベントは最後の一つしか見えず、同じ値の続くイベント（同じノートの二度の打鍵）は区別できない。読み手には暗黙の状態である。
  - (1b) `Option[T]` で読む（その位置にイベントがあれば最後の一つの `Some`、無ければ `None`）。有無は見えるが、複数のイベントは最後の一つだけである。型が宣言と変わる。
  - (1c) 誤り。`sample` で使うには、イベントで動くインスタンス（S-562）の出力を通す。S-562 で出力を `sample` で保持して読む形（(o1)）なら、その位置の全てのイベントで動いた後の値が見える。
  - (2) `init`・`block`・定数: その `process` の呼び出しの値で読める（遅い値を読む §11.3 の規則のとおりで、選ぶ余地は小さい）。
  - (2i) `sample` の値: 一つ前の位置の値を読む。費用の要因: 書かれていない一サンプルの遅延になる（§11.2 は遅延を書き手が置く）。
  - (2ii) `sample` の値: その位置の値を読む。その位置のイベントに依らない部分の `sample` の段を、イベントの段の前に評価するよう計画を分ける。費用の要因: 依存の向きで段が割れ、閉路の誤りが要る。
  - (2iii) `sample` の値（入力を含む）は誤り。その位置の値が要るときは、`sample` の側で `when~`（イベントがあった位置で真の `Bool`）を使って取る。
  - (3a) 変換は今の言語の仕組み（S-562 の修飾子、S-564 の出力、総称の `rt fn`）で書いた std の flow にする。
    ただし flow は型引数を持たない（§4.5、p19）ので、利用者の型の値を保つ flow は、型ごとに一行の flow（`flow keep(n: Note at sample) -> Note at sample { n }`）を書くか、std の型の分だけ std が持つ。
  - (3b) 変換を std の中の、コンパイラが知る項目（`Prim` の表の lang item、W5）にする。型ごとに書かずに済むが、実装は (3a) より多く、std の宣言に本体の無い flow ができる。
- 他言語:
  - Esterel v5（primer §4.4）: 「The value is permanent: at any instant, the expression ?S yields the current value of S, which is either the current value of S if S has been emitted in the instant or the previous value of S otherwise」。
    有無は `present` の文（§4.7.7）で別に問う（(1a) と有無の組）。
  - Pure Data（手引き §2.5.3）: 制御から信号へは `sig~`・`line~`・`vline~` で変え、「The other direction, signal to control, requires that you specify at what moments you want the signal sampled」（`snapshot~`）。
  - Lustre V6（§1.2.4）: 部分のクロックの値は `current` で明示に戻す。
  - SuperCollider（`Trig`）: イベントを信号の立ち上がりとして表す。
- 推奨と理由: (1c)、(2) は `init`・`block` を読めて `sample` は (2iii)、(3a)。確度: 中。
  - (1c): S-171 の「`sample` の式からは、その位置のイベントを全て処理した後の状態が見える」は、状態（S-562 の保持された出力）で読める。イベントの値そのものを読む (1a)・(1b) は、同じ位置の複数のイベントを黙って捨てる。
    (1c) で始めれば、後で (1a) か (1b) に緩めても今のプログラムを壊さない。逆は壊す。
  - (2iii): (2i) は隠れた遅延、(2ii) は計画の段を依存で割る大きな仕組みになる。(2iii) なら、イベントの段の値はイベントの値と `block` 以下の値の関数だけになり、S-561 の (2c) と S-562 の (o1) の前提が保てる。後で (2i) か (2ii) に緩められる。
  - (3a): 実装を足さずに、S-171 の方針（std の flow）で書ける。例: 有無 `present(e)`（総称の `rt fn`、p16）、最後の値 `keep~(e).when~(present(e))`、その位置にイベントがあったか（数える flow を `when~(present(e))` で動かし、`n != prev~(n)`、p20）。
    型引数の無い flow の制限は、std の型の分は std が持ち、利用者の型は一行の flow で足りる。
  - 新しい S の候補: 総称の flow（`flow keep[T: Copy + Default](x: T at sample) -> T at sample`）。イベントの変換を利用者の型に一つの std の flow で書くために要る。`::[…]` の高階（S-556）と同じ場所に関わる。

  - 診断のコード: (1c)・(2iii) なら E0815 の範囲（イベントの値を `sample` で、`sample` の値をイベントの段で）。修正候補は付けず、note で `when~` の形を示す（候補）。
  - 作業: クロックの解析（W7-02）、巻き上げと計画（W7-03、W7-05）。(3b) なら W5 の `Prim` の表と std。
