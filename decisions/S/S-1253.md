# S-1253 細部: 構文の段で、後ろの読みが切れて AST の無い式の E0010〜E0013 が、位置が後の別の誤り（ブロックコメントの E0020、型引数の空白の E0020）に隠れ、§18.1 の「並べ方で最初のもの」の字とずれる（仮は今のまま）

- 空白: §18.1 は「残った診断のうち、並べ方で最初のものを報告する」とするが、構文の段の E0010〜E0013（括弧の要る式の形）は構文解析の後に AST の上で検査する（`crates/onsa_syntax/src/groups.rs` の `check`）ので、後ろで読みが失敗して切れた式には AST が無く、位置が前のこの誤りが出ない。位置が後の別の誤りが先に報告され、その候補を当てた後に出る。
  形: `Option[F32 as U32 / a .b]`（型引数の空白の E0020 が先、位置が前の E0011 は当てた後）、`let y = x as I64 + 1 /* c */`（ブロックコメントの E0020 が E0011 を隠す）、本体の `x as U32 / a .b`・`… + (1 +)`・E0010 の形・`xs [0]` も同じ（R-509 の (3)、L2 の設計 `target/notes/188/w717/l2/d/design.md`）。
  どれも誤りが二つのプログラムで、当て続ければ止まる（候補の約束には触れない）。
  `crates/onsa_syntax/src/lib.rs` の注釈は「文の単位の回復（S-59）まで」の受け入れとしている。
  仮の扱い: 今のまま（通るプログラムは変わらない）。W7 の区切りで確認だけ。確認のときに、§18.1 に今の順の一文を足すか、文の単位の回復まで字を残すかを選ぶ。構文解析器が E0011 を先に出す案は同じ判断を二か所に置き（D-15）、部分式を AST に下ろす案は文の単位の回復と重なる。

- 経緯: 188 回目（2026-11-26）、W7-17 L2（R-509）の読むだけの設計（onsa-impl）が (3) の原因として挙げ、親が細部として登録した。
