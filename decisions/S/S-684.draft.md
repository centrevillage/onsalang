# S-684 本体の経路が自分のパッケージ名と自分のモジュールで始まるとき（`a/b.onsa` の `fx.a.b.f()`、`d.onsa` の `fx.d.f()`）の E0302 の修正候補

- 決定済みで戻さないもの: S-673（自分のパッケージ名・自分の絶対経路・自分の名前の頭を外す候補とその細部）、S-663（`use` の頭の自分のパッケージ名の候補）、S-679（自分を取り込む `use` は E0302）、S-682（循環で出さない候補の note）、S-683、R-268（候補は経路が最後まで解決し循環を閉じないときだけ）、S-594 の辺の数え方。
  第 60 組の下書きの「仕組みの出所と目的」の節（写しは `target/notes/67/g60/draft.md`）。
- 論点: §15.1「経路の頭が自分のパッケージ名か、自分のモジュールを名指す部分（モジュール自身の名前か、自分の絶対経路）のときは、修正候補はその部分を外すことで、外した後の頭を取り込む `use` が無ければ足す」。
  二つの部分が続く形（パッケージ名の後に自分の絶対経路）を書いていない。パッケージ名の規則だけを当てると、外した後の頭（`a`、`d`）の `use` を足す読みになる。絶対経路の規則も当てると、両方を外す読みになる。
- 今の実装: `c77f3f3` の `not_in_body` は、パッケージ名の後の自分の絶対経路、パッケージ名の後のルート直下のモジュール、自分の名前の順に読む。
  `g4`（`d.onsa` の `fx.d.f()`）は「take off `fx.d.`」、`g5`（`a/b.onsa` の `fx.a.b.f()`）は「take off `fx.a.b.`」（当てた `p5_A_applied` は終了コード 0）。`g6`（ルート直下の `b.onsa` もある `fx.b.g()`）は「take off `fx.` and add `use b`」。
  `p4_child`（`fx.d.inner.g()`）は「take off `fx.d.` and add `use d.inner`」、`p5_child`（`fx.a.b.inner.g()`）は「take off `fx.a.b.` and add `use a.b.inner`」。
  `p5_child_cycle`（`a/b/inner.onsa` が `use a.b.{f}`）は候補なしで、rule はパッケージ名の一般の文（「`use util`, then `util.…`」の字のまま）。`p6_noroot`（ルート直下の `b` が無い `fx.b.g()`）は候補なし。
- 案:
  - (a) 二つの部分を一つの候補で外す。子モジュールが続けば、その `use` を足す（S-673 の `main.inner.g()` と同じ）。
  - (b) パッケージ名だけを外し、外した後の頭を取り込む `use` を足す（S の本文の (1)）。外した後の頭が自分のモジュールなら、`use` が自分を取り込む E0302（S-679）になるので候補なし。
  - (c) パッケージ名を外した後の経路を本体の経路として読み直し、その候補と合わせる。(a) と違うのは、パッケージ名の後が自分の名前だけの形（`p6_noroot` の `fx.b.g()`）で、(c) は `g()`。
  - (d) 候補を出さず、note で外した形（`f()`）を示す。

  | 入力 | (a) | (b) | (c) | (d) |
  |---|---|---|---|---|
  | `g5` `fx.a.b.f()` | `f()` | `use a` と `a.b.f()`（`p5_B_applied` は 0） | (a) と同じ | なし、note `f()` |
  | `g4` `fx.d.f()` | `f()` | なし（`use d` は S-679） | (a) と同じ | なし、note `f()` |
  | `p4_child` `fx.d.inner.g()` | `use d.inner` と `inner.g()` | なし | (a) と同じ | なし |
  | `p5_sibling`（`a/c.onsa` が `use a.b.{f}`） | `f()` | なし（`use a` が閉じる。`p5_sibling_B_applied` は E0310） | (a) と同じ | なし |
  | `p6_noroot` `fx.b.g()` | なし | なし | `g()` | なし |
  | `g6` `fx.b.g()`（ルート直下の `b` あり） | `use b` と `b.g()`（決定済み） | 同じ | 同じ | 同じ |

  - §18.1 の約束: (a)・(b)・(c) は S-673 の細部の条件（解決、名前が空く、循環を閉じない）で出すので、当てた後に E0302・E0304・E0310 を残さない。(b) の `use a` は `a` の下の全てへの辺なので、兄弟のモジュールが自分を取り込むと閉じて候補を失う。
  - 当て続け: (a)・(c) は一回で誤りが無くなる。(b) は `g5` では一回で無くなり、`g4`・`p4_child`・`p5_sibling` では候補なしで止まる。(d) は候補なしで止まる。
  - 書き手から見た形: (a) は一つの削除で、題が外す部分を名指す。(b) の当てた後の `a.b.f()` は、`use a` が無ければ S-673 が `f()` に直す形（`p5_plain_abs` は「take off `a.b.`」）で、同じ意図に二つの形が残る。
  - S-682 の note との揃い: (a)・(c) で循環のために出さないとき（`p5_child_cycle`）は、`use a.b.inner` と `inner.g()` と相手のモジュールを示し、`main.inner.g()` と同じ。(b) の `g4` の note は S-679 と同じく `f()` を示し、候補が出さない形を正しい形として示す。
  - 実装（`not_in_body`）: (a) は 0 行（今と同じ）。(b) はパッケージ名の後の絶対経路の読みを外し、`g4` の note の枝を足す（約 +2〜5 行）。(c) はパッケージ名の後の自分の名前の読みを足す（約 +3〜5 行）。(d) は候補を外して note の枝（約 +2〜4 行）。
- 他言語: rustc 1.94.1（手元）: `a::b` の中の `crate::a::b::f()` は通る（自分を名指す経路を許すので、対応する誤りは無い。`P67/g60/probe/other/own.rs`）。Go・TypeScript の対応する形は未確認。
- 推奨と理由: (a)。確度: 中〜高。
  - S-673 は、パッケージ名と自分の絶対経路のそれぞれを外すと決めた。続けて書いた形も両方を外せば、`fx.a.b.f()`、`a.b.f()`、`f()` の意図が同じ一つの形になる。(b) は S-673 が `use dsp` を足さずに外すと決めた形（`use a` と `a.b.f()`）を作り直す。
  - (b) は `use a` で親の下の全てへの辺を足し、`g4`・`p4_child`・`p5_sibling` で候補を失う。書き手の意図は一つに決まっているので、候補を失う理由が無い。
  - 実装を増やさない（今と同じ）。仕様の約束に関わらない細部で、(c) の `p6_noroot` は自分の経路でない `fx.b` を自分と読む推測で、書く書き手も少ない。後で (c) に広げても通るプログラムは変わらない。
  - あわせて決めること: `p5_child_cycle` の rule がパッケージ名の一般の文（字のままの `use util`）になるのは、`not_in_body` の rule の枝の順による。S-682 の note（U3b）で、パッケージ名の後に自分の絶対経路が続く形も `use a.b.inner` と相手のモジュールを示す。
- 影響: 仕様は §15.1 の本体の経路の候補の文に例を一つ（(a)・(c) は「パッケージ名の後に自分の絶対経路が続けば両方を外す（`a/b.onsa` の `fx.a.b.f()` は `f()`）」、(b) は「パッケージ名だけを外す」、(d) は「候補を出さない」）。診断のコードは変わらない。
