# S-290 多相再帰と具体化の数

- 空白: 多相再帰と具体化の数。`fn g[T](x: T, n: U32)` が `g(Some(x), n - 1)` を呼ぶと具体化が終わらない。今の `check` は通り、降下の具体化（`onsa_core::lower` の worklist）に上限が無い。
  型の上限（S-264）は一つ一つの具体化の型を抑えるが、数を抑えない（`g[T]` が `g[Option[T]]` と `g[(T, I32)]` を呼ぶと、上限の中で 2^256 通り）。案: 呼び出しの閉路の中で型引数が型パラメータを包む呼び出しを型の段の誤りにする（Go の InvalidInstanceCycle と同じ考え）、具体化の数の上限、など。
  あわせて、具体化を検査の段で作るか（`check` で見つかるか）と、具体化の型の E0422 の段を決める。第 6 組の下書き（S-264）で見つけた（2026-10-08）
- 提案: W5 の推論の作業か W8-01（降下）の前に決める。空白の流れで下書きに回す
- 時期: W5
- 決定: 決定（2026-11-07、利用者。121 回目、第 90 組。下書きと独立のレビュー（段 1）が一致）: (c)。§4.4 の深さ 256 と大きさ 4096 を降下が作る具体化の型に当て、加えてパッケージの具体化の数に上限 65536 を置く（新しいコード E0423）。段は Core への降下で、`check` は通り、`test`・`build`・`interface` が報告する。
  あわせて決めたこと: 具体化は検査の段で作らない。具体化の型の E0422 の段は降下で、位置は上限を初めて超えた型を作った呼び出し、型の宣言の中で超えたらそのフィールドの型。超えたら降下をそこで止め、一つだけ報告する（§18.1 の「全て報告」の例外）。E0422 の note は降下で出すときは型引数が包まれる道を示し、診断の文に大きな型の全体を書かない。
  数えるのは降下が作る `(項目, 型引数)` の組（関数、テスト、struct と enum、`impl` の定数と既定値）で、総称でない項目も一つと数え、生成する関数と derive が作るメンバは数えない。根は命令と `--filter` によらずパッケージの全てで、枝の条件の値は見ない。数える細部は版によるので、上限の近くで止まる位置は版で変わりうる（§7・§12.5 と同じ）。後で値を上げても既存のプログラムは壊れない。
  構造の検査の案 (d) は今は足さない。W8-01 で具体化の段を決めるときに、検査の段へ移す案 (e) と一緒に比べる。S-911 (d) の検査も同じ時に移せるかを見る。
  理由: §4.4 を具体化に当てるだけで増える形は止まるが、一つ一つが小さくて数が指数の形は残る。S-782 の (d) で型の側の指数の形も降下へ移るので、数の上限が要る。具体化を作る処理は降下にしかなく、今 `check` に作ると降下の暗黙の具体化を二か所で持つことになる。
- 経緯: 121 回目（2026-11-07）、第 90 組で決めた。下書きは `decisions/S/S-290.draft.md`。利用者は「ひとまず (c) で。(d) も安全側の考えとしてはありだと思います」「値はひとまず 65536 で」と答えた。
- 補い（2026-11-06、親）: 117 回目、S-911 (d) で具体化で決まる `rt` の循環を降下の後の Core で調べると決めた。この S が具体化を検査の段で作ると決めれば、その検査は検査の段へ移せる（落ちるプログラムの集合は変わらない）。
