# S-414 `} else` 改行 `if`

- 空白: `else` の後の改行と `if`（`} else` 改行 `if d { … }`）。§2.5 は `else` を前の `}` と同じ行に置く規則と、ブロックの `{` を見出しと同じ行に置く規則を書き、`else` と後ろの `if` の間の改行を書かない（継続の一覧に行末の `else` は無い）。
  括弧の外は今、`else` の後の改行の位置の E0002「expected `{`, found newline」（候補なし）で、括弧の中（`two(if c { 1 } else` 改行 `if d { 2 } else { 3 }, 1)`）は今は通る。S-370 の「記号の置き場所の規則は括弧の中でも外と同じ」に入れるか、候補（`if` を前の行へ移す形）を出すか。
  W3-06/i の設計メモで見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 22 組）: `else` の後の `if`（`if~` を含む）も `else` と同じ行に書く。違反は E0003 で、主の位置は `if`、候補は `if` からその行のコメントの前までを `else` の行の末尾（コメントの前）へ移す形。
  括弧の中でも外でも同じ（`else` の後は構文解析器が既に次の行を見るので、条件は増えない）。`with` 改行 handler の名前は入れない（キーワードと被演算子の間の改行で、`if` 改行 条件と同じ種類。S-416 で決める。今の出力のまま。2026-10-10、利用者が Fable の案を了承）。仕様 §2.5。実装は W3-06 の単位 2
