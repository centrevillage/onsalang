# S-1247 細部: フィールドの読みの根が、腕が取られたときだけ値を持つ束縛（普通の `match` の腕の束縛、`match~` のガードの中の束縛）のときの読み方（`if g { match v { V.B(q) => x + q.vel, V.A => x } } else { x }`、`v` はイベント）

- 空白: §11.3（S-1197）は「名前と、そのフィールド・組の要素の連なりを取り出すだけの式は…書ける」「フィールド・組の要素の読みは、条件によらず、守りを付けずに刻みごとに読む」とし、名前にはパターンの束縛も入る。普通の `match` の腕の束縛と、`match~` のガードの中の束縛は、腕のパターンが合うときだけ値を持つので、条件によらずには読めない。
  `if g { match v { V.B(q) => x + q.vel, V.A => x } } else { x }`（`g` は `sample`、`v: V at event`、`q: Pd`）。`sample / N` の値では、対象と腕のクロックが混ざって E0815 なので書けず、イベントの値だけの形である。
  読み: (1) 書けて、欄は読みの型。束縛するパターンだけを守りにして刻みごとに書く（最初のイベントの前は `F32.default()`）。(2) 書けて、届いたときに束縛から読む（最初のイベントの前は `V.default()` の中身の `vel`）。(3) 書けない（条件が他の段なら E0815）。
  (1) と (2) で値が違うのは、最初のイベントの前と初期化の後だけ（`V.default()` が `V.B(…)` で、その `vel` が `F32.default()` でないとき）。
  比べ: `if g` の外に置いた同じ `match v { V.B(q) => x + q.vel, V.A => x }` は、選ぶ条件がその刻みだけなので守り付きの欄（S-1158）で、(1) と同じ値になる。パターンで取り出した `V.B(Pd { vel, .. }) => x + vel` は名前の読みで、(2) と同じ値になる。
  仮の扱い: 条件が定数・`init`・同じ刻みだけなら守り付きの欄、他の段の条件があれば欄を作らず届いた所で読み、E0816 は読みの型で判定する（`SPEC-GAP(S-1247)`、`crates/onsa_sema/src/flow/reads.rs` の `Marker::place`。前から通る形を E0815 にしない。`Default` の無い型のフィールドの読みだけ、前は通り、今は E0816）。
  W7 の区切りで確認だけ。値が動くのは W7-11 U3 から（U3 の票で、どちらの値になっているかを事例にせずに報告させる）。
