# S-570 境界のイベントの入力: 生成する API と C の API の形、入力をまたいだ順の渡し方

- 空白: §19.1 のイベントの項（S-560・S-561）は、イベントの入力の意味（入力ごとのクロック、位置はホストが決める、一つの入力の中はホストの列の順、入力をまたいだ順は境界が渡す順で、ホストの列に順があればそれを保ち、無ければ外の flow の入力の宣言の順）を決め、渡し方を第 35 組に送った。§11.6 の `process` と §14.2 の C の `_process` には、イベントの入力の引数が無い。決めること:
  1. 生成する API（§11.6、Onsa のコードから呼ぶ `process`）と C の API（§14.2）のイベントの入力の形（入力ごとの列か、入力の印付きの一つの列か。位置と値の表し方）と、入力をまたいだ順の渡し方。
  2. 列の前提（位置の順に並ぶこと、位置が `frames` より小さいこと）と、守られないときの扱い。`frames` が 0 の呼び出しのイベント。
  3. 関数と型の形を flow によらず一定に保つ約束（§14.2）との関係（イベントの入力の無い flow の引数）と、`process_inplace`・`In` との関係。
