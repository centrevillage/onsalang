# S-1107 細部: flow の本体の `^` の誤りのコード（`par~` の中の見えている名前への `^`、関数への `^`、遅延の外の未定義の `^zz`）

- 空白: §11.2 は見えている名前への `^` を E0020 とし、`par~` の中の `^` は W7-07 まで E0200 の門、§2.6 は `^` を `let` の名前にだけ付くとする。次の三つのコードが決まらない: `par~` の中の見えている名前への `^`（E0020 か E0200）、関数の名前への `^`（`^g`）、遅延の外の未定義の `^zz`（E0302 か E0801）。どれも誤りのプログラムで、通るプログラムは変わらない。
  今は `g4_visible_caret_in_par` が E0200@2:29、`g5_undefined_caret_outside_delay` が E0302@2:12、`g6_caret_on_a_function` が E0200@3:9。再現は `target/notes/158/w704/u2/t/gaps.txt`。
  仮の扱い: W7-04 U2 の実装の出す診断。テストの票は期待を書いていない。
  急ぎ: W7-07（`par~` の中の `^`）の前に確認だけ（`rules/leader.md` 5.11）。
- 補い（2026-11-19、親）: W7-04 U2 の実装の後の出力は、`g4_visible_caret_in_par` が E0020@2:29（「`^` marks a later `let`; this name is visible here already」、`par~` の外と同じ）、`g5_undefined_caret_outside_delay` が E0302@2:12、`g6_caret_on_a_function` が E0020@3:9 で、上の「今は」の E0200 とは違う（固定のバイナリ `c56f3c7` で確かめた）。

- 決定: 決定（2026-11-19、利用者。168 回目。細部の確認だけ、`rules/leader.md` 5.11）: 仮の扱いのとおり、今の出力のまま。
