# S-735 E0320 の候補の「全ての使用箇所」に、誤りで止まった単位の後ろの使用（型や名前の誤りの後、構文の誤りで切れた本体、E0304 の空間）を含めるか

- 決定済みで戻さないもの: 使用箇所は段の記録から集める（S-82）。候補の約束の範囲（§18.1、S-236）。重なる名前の候補なし（S-652）。構文の誤りの単位の本体と、E0304 の空間の使う所を解決しないこと（§18.1）。
  第 70 組の下書きの「S-735 の仕組みの出所」と「S-735 の形の表」の節（写しは `target/notes/79/g70/draft.md`）。
- 論点: §2.3「宣言と、パッケージの中の全ての使用箇所の名前を直す」は、誤りで検査を止めた単位の、止まった所より後ろの使用を含むかを書いていない。§18.1 の候補の約束は、元から誤りのある単位に及ばない。
- 今の実装: 表のとおり。段が記録した使用だけを直す。修復のループは、どの再現も E0320 の候補を当てた後に止めた誤り（E0302、E0401、E0002、E0806）で `no-candidate` で止まる（`--pick first`・`last` で同じ）。
- 案: 
  - (a) 段が解決して記録した使用に限る（今の実装）。§2.3 に「誤りで止まった単位の、止まった所より後ろの使用は直さない」の一句を足す。
  - (b) 名前の段だけ、止まった後ろも名前を引いて記録する（診断は出さない）。型の段のフィールドとメソッド、構文で切れた本体、E0304 の空間、flow の E0806 の後は (a) のまま。
  - (c) 全ての段で、止まった後ろも解決を続けて記録する（型の段も診断を出さずに型付けを続ける）。構文で切れた本体と E0304 の空間は、どの段でも解決できないので残る。
  - (d) 誤りで止まった単位に同じ綴りの名前が残るときは候補を出さず、note で規則に揃えた名前と、その名前の位置を示す（直せる全てを直せないなら直さない）。
  - 書き手から見て（`repro_partial_after_names_error.onsa` と `…_after_type_error.onsa`。止めた誤りは書き手が手で直す）: (a) は、一回目の検査で候補を当てて手で直した後、二回目に残った古い名前が E0302・E0413 で出る。
    一つの単位は一つの誤りなので、型の段の形（`p.someX + p.GetIt()`）は残った名前が一つずつ出て、さらに一回の検査が要る（残った名前の数だけ増えうる）。(b) は名前の段の形が二回で済み、型の段の形は (a) と同じ。(c) は構文で切れた本体を除いて二回。
    (d) は候補が無く、書き手が手で全てを改名する（note の位置を見れば二回）。誤りの多いファイルほど候補が減る。
  - 修正候補を当て続けて止まるか: どの案も止まる（残る誤りは候補の無い E0302・E0413 か、止めた誤り）。§18.1 の約束は、直さない単位が元から誤りを持つので、どの案でも満たす。
    残った古い名前は §2.3 に反する綴りなので、同じ綴りの正しい宣言は無く、黙って別のものを指すことは見つけた形では無い（`two_structs.onsa` の別の型の同じ名前のフィールドも、その型の E0320 として別に出る）。
  - 通るプログラム: どの案も変わらない。変わるのは候補の編集の範囲と候補の有無だけである。
  - 規則と例外: (a) は §2.3 に一句（S-82 の「記録から集める」を書き下す）。(b) は「名前の段は止まった後ろも引く」の規則を足し、他の段は (a) の句のまま（段で扱いが分かれる）。(c) は全ての段に同じ規則。(d) は候補を出さない場合を一つ足す（§18.1 の候補の数の約束に関わる）。
  - 実装の量: (a) は 0 行。(b) は名前の段の歩き手の `W = Result<(), Stop>` の早い戻りを、止まった後は診断を出さずに記録だけ続ける形にし、スコープを保つ（約 +30〜60 行。見積もりの確度は低い）。flow の本体の先の宣言（`prescan`・`flow_stop`）と W7-04 の E0806 にも同じ手当てが要る。
    (c) はさらに型の段の `body/` の止まり方の全てに同じ手当て（約 +80〜150 行、確度は低い）。(b)・(c) は、後の作業で名前の段や型の段に止まる所が増えるたびに、記録を続ける手当てが続く。
    (d) は `rename_fixes` で、誤りのある単位のトークンから同じ綴りの識別子を探す（約 +20〜30 行）。後の段への手当ては無い。
- 他言語: 比べられる言語は調べていない（未確認）。rustc の名前の規則の警告（`non_snake_case`）は改名の候補でなく宣言の綴りの提案なので、比べられない。
- 推奨と理由: (a)。確度: 中〜高。
  - 使用箇所を段の記録から集めることは S-82 で決まっており、誤りで止まった単位の後ろには、どの段も正しく解決した記録を持たない。(c) でも構文で切れた本体と E0304 の空間は残り、「全て」は字のとおりにならない。
  - 残った古い名前は規則に反する綴りなので、黙って別のものを指さず、止めた誤りを直した後に必ず診断として出る。費用は、誤りのある単位に残った名前の数だけ検査が増えうること（一つの単位に一つずつ出る）に限られる。
  - (b)・(c) は止まった後も歩く仕組みを段ごとに持ち、後の作業が止まる所を足すたびに手当てが続く。(d) は誤りの多いファイル（LLM の出力に多い）で候補を減らし、候補の数の約束に場合を足す。
  - あわせて決めること: §2.3 の 73 行の「全ての使用箇所」に「（段が解決した使用。誤りで検査を止めた単位の、止まった所より後ろは含まない、§18.1）」を添える。
  - 別の S にしてよい論点: 直さなかった同じ綴りの位置を note で示すか（(a) に約 +20〜30 行。note は約束でなく、実装の細部）。親が要ると見たときだけ、実装の改善として W4-18 に置く。
- 影響: 仕様 §2.3 の 73 行（(a) は一句、(b) は名前の段の規則の文と一句、(c) は規則の文、(d) は候補を出さない場合の文と note）。`tasks/diag-codes.md` は変わらない。
