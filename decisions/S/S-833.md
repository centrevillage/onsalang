# S-833 export の必須の E0809（`@export` の flow の `block` の入力に `@param` も `@host` も無い）の修正候補（今の `build` は型によらず `@param(min: 0.0, max: 1.0, default: 0.0)` を挿入する）

- 空白: §11.7 は、export する flow（`@export`）の `block` の入力に `@param` か `@host` を必須とし（E0809）、§14.2 と S-632・S-639 はこの必須を `onsa check` が宣言の位置で出すとする。修正候補は仕様に書かれていない。
  今の `build` の E0809（`crates/onsa_driver/src/build.rs` の `check_exports`）は、入力の型によらず `@param(min: 0.0, max: 1.0, default: 0.0) ` を入力の前に挿入する候補を付ける。
  §11.7 では、`Bool` の入力に書けるのは `default`・`unit`・`label`・`id` だけ（`min`・`max` は E0809）で、値は入力の値型の値（整数の入力に `0.0` は E0401）なので、`Bool` と整数の入力ではこの候補を当てても同じ段かそれより前の段の誤りが残り、§18.1 の候補の約束に合わない。`@param` を付けられない型（`I64` など）の入力でも E0809 が残る。
  今は `@param` の値の検査が無い（R-216）ので、当てた後の `check` は通り、`build` は内部エラーになる（`Ctl[Bool]` の `@param`、R-99。再現 `target/notes/96/s833/e0809bool`・`e0809bool.fixed`、`P96/bin/onsa-e611775`）。W4-02 の U1 は E0809 を `check` に移すので、候補が修復のループに乗る。
  読みは (1) 候補を出さない（`@param` と `@host` の二通りの直し方があり、`default` の値は書き手が決める） (2) 型に合わせた `@param(default: <その型の零>)`（`F32`・`F64` は `0.0`、整数は `0`、`Bool` は `false`）を出し、`@param` を付けられない型では出さない (3) 今の字を `F32`・`F64` の入力だけに残し、他の型では出さない、に割れる
- 決定: 決定（2026-11-01、利用者。96 回目）: (1)。export の必須の E0809（`@export` の flow の `block` の入力に `@param` も `@host` も無い）には修正候補を付けない。当たるのはこの E0809 だけで、`@param` を書いた後の値の誤り（E0809・E0401）、S-823 の E0303 の候補、`@export(…)` の E0005 の候補は変えない。
  理由: 直し方が `@param` と `@host` の二通りあり、`@param` の値（`default`・`min`・`max`・`label`）はホストの UI に出る公開の情報で書き手が決める（候補は書き手の意図が一つに決まるときだけ）。実装は今の候補を付けないだけで、sema の他の E0809 も候補を付けていない。`@host` を足すときに決め直さない。
  仕様は候補の形を書かないので、仕様の文は変えない。実装は W4-02 の U1（事例 `tests/spec/negative/export_flow_param_required.onsa` の `fixes = 0`）
- 経緯: 96 回目（2026-11-01）、W4-02 の U1 の票を書く前に、親が今の `build` の E0809 の候補を `Bool` と `I32` の入力に当てて確かめた。設計メモ（`target/notes/95/w402/memo.md` の 2.6）は「今の `check_exports` と同じ挿入の候補」としていた。急ぎ: W4-02 の U1 の実装の E0809 の前。関係: S-632、S-639、R-216、R-99
