# S-728 失敗した名前を指す型別名（`use util.{Gone}` の後の `type A = Gone`）を値の位置の経路の頭に書いたとき、単位の以後を検査しないか（今は `A.V` で止まり、`A { a: 1 }` は続く）

- 決定済みで戻さないもの: 失敗した名前の位置ごとの扱い（S-692）、別名の型の位置で続けること（S-692、R-271）、別名から偽の連鎖を出さないこと（R-271）、`let s = A` の E0308（S-713。種類の誤りで、別名の右辺によらない）。
  第 67 組の下書きの「族「§18.1 の失敗した名前の後の検査」の仕組みの出所」と「族の形の表」の節（写しは `target/notes/78/g67/draft.md`）。
- 論点: §18.1「値の位置（失敗した名前を経路として書いた式とパターン…）では、その単位の以後を検査しない」と、§4.4「型の名前を書ける全ての位置…で、元の型と同じに使える」。
  失敗した名前を指す別名を値の位置の経路の頭に書いた形が、失敗した名前の値の位置に入るか（止める）、誤りの型の型の名前として続けるかが書かれていない。今は形によって違う（表の別名の三行）。
  通るプログラムは変わらない。変わるのは、失敗した `use` のある包みで、同じ単位の後ろの本物の誤り（E0401 など）と読まれない束縛の E0309 が、同じ検査で出るかだけである。
- 今の実装: 表のとおり。別名の struct リテラルと struct のパターンは、名前の段の `item`（`names/body/paths.rs` の 330 行）が別名の誤りの型を型付けに渡し、型付けが黙って続ける（R-271 の直し）。
  別名のメンバの経路（`A.V`、`A.new(1)`）は、型の名前空間の引き（`typed_members`）が誤りの型で失敗し、`Analysis::unread` が黙らせて止める（`Fail::Held`）。
  `B`（別名の別名）も同じ。`4fb3fda`（W4-04 U7b1）でも同じ出力である（親の確かめ）。
- 案: 
  - (1) 誤りの型の別名を値の位置の経路の頭に書いた形は、指す名前を書いたのと同じく、単位の以後を検査しない（struct リテラルと struct のパターンも止める）。
  - (2) 誤りの型の別名は、値の位置でも誤りの型の型の名前として続ける（`A.V` は誤りの型の値、`A.new(1)` は誤りの型の呼び先）。
  - (3) 今の形を規則にする: 型の名前だけを書く形（struct リテラル、struct のパターン）は型の位置として続け、メンバを引く形（`A.V`、`A.new(1)`、`A.V =>`）は止める。直接の `Gone { a: 1 }` は止めたまま。
  - (4) struct リテラルと struct のパターンの型の名前は、直接の失敗した名前でも型の位置として読み、続ける（`Gone { a: 1 }` も続く）。S-692 の決定の文の値の位置（「失敗した名前を経路として書いた式とパターン」）から、この二つの形を外すことになる。
  - 形ごとの出力（後ろに `let zz: Bool = 2` がある本体）:

    | 形 | (1) | (2) | (3) | (4) |
    |---|---|---|---|---|
    | `A { a: 1 }`、`let A { a: q } = x` | 止まる | 続く（E0401） | 続く | 続く |
    | `A.V`、`A.new(1)`、`A.V =>` | 止まる | 続く | 止まる | 止まる |
    | `Gone { a: 1 }`、`let Gone { a: q } = x` | 止まる | 止まる | 止まる | 続く |
    | `Gone.V`、`Gone.f(x)` | 止まる | 止まる | 止まる | 止まる |

  - 書き手から見て: この形は、失敗した `use` のある包みにだけ出る。その `use` の E0302 はどの案でも報告され、書き手はまず `use` を直す。
    止める案では、同じ単位の後ろの本物の誤りが `use` を直した次の検査で出る（修復のループが一回増えうる）。続ける案では同じ検査で出る。
    (3) は、同じ名前を `A { … }` と書けば後ろの誤りが出て、`A.V` と書けば出ないという、書き方だけの違いを書き手に見せる。
  - 修正候補: どの案も、使う所には診断が無く候補も無い。後ろの誤りの候補は、その誤りの規則のままである。
  - 規則と例外: (1) は §4.4 の「元の型と同じに使える」から決まり、§18.1 に「別名を通して書いても同じ」の一句で足りる。例外は無い。
    (2) は S-692 の値の位置の扱いに、別名を通した形の例外を一つ足す。(3) は §4.4 の「元の型と同じ」に、struct リテラルとパターンの例外を一つ足す。(4) は S-692 の値の位置の定めを改める。
  - 実装の量:
    (1) は `paths.rs::item` の別名の枝で、別名の型が誤りの型なら `Fail::Held` にする（`alias_type` の `Ok(None) | Err(_)` を、誤りの型と struct でない型に分ける。約 +3〜6 行）。パターンの止まりは既にある `fail_at_let` が受ける。
    型付けの R-271 の枝（誤りの型の struct リテラルを黙らせる）は残る（他の入口が無いかは未確認で、消すなら W4-18）。
    (2) は、歩き手が誤りの型の別名のメンバに記録（誤りの型の項目）を置き、型付けが誤りの型の値と呼び先にし、引数のモードの段が経路の呼び先の分からない呼び出しを扱い、flow の定数式（`delay~(x, A.N)`）と定数の評価（`const C: U32 = A.N`）も誤りの型を受ける。
    S-692 が (c) を退けた手当てを別名の形について行うことになり、W4-04 だけで約 +30〜50 行、W5・W7・W9 に手当てが続く。
    (3) は 0 行（仕様の一文）。(4) は歩き手の struct リテラルとパターンの失敗した頭で、止めずに誤りの型の記録を置く（約 +5〜10 行）。型付けは R-271 の枝で既に受け、別名の struct のパターンの束縛も今続いている。
  - 後の作業: (1)・(3)・(4) は後の段に手当てが続かない（止めるか、既にある誤りの型の値で続ける）。(2) は上のとおり後の段ごとに続く。
- 他言語: rustc 1.94.1（`probe/rs/s728.rs`、edition 2021）: `type A = Missing;` は別名に E0425「cannot find type `Missing`」だけを出し、`A { a: 1 }` と `A::V` には何も出さない。
  rustc は単位で止めず全ての誤りを出すので、三つの関数の後ろの `let b: bool = 2;` の E0308 はどれも出る。直接の `Missing { a: 1 }` には E0422 を出す（Rust に失敗した名前を黙らせる仕組みは無い）。参考にとどめる。
- 推奨と理由: (1)。確度: 中〜高。
  - 別名は指す型と同じに使える（§4.4）ので、失敗した名前を指す別名を値の位置に書けば、失敗した名前を値の位置に書いたのと同じに扱うのが、既にある規則の読みである。書き方（`A { … }` と `Gone { … }`、`A { … }` と `A.V`）で結果が変わる形が無くなる。
  - R-271 の目的（別名から偽の連鎖を出さない）は保たれる（使う所は黙ったまま）。
  - 実装は名前の段の数行で、後の段に手当てが続かない。(2) は S-692 が実装の収束のために退けた (c) の費用を、別名の形について払う。
  - 失うのは、失敗した `use` のある包みで、別名の struct リテラルの後ろの誤りが次の検査に回ることだけである（`use` の E0302 は必ず出るので、黙って通るプログラムは無い）。後で (4) のように struct リテラルを型の位置へ緩めても、通るプログラムは変わらない。
  - (4) は第一の検査で出る誤りが増えるが、S-692 の値の位置の定めを改める。その利益は、失敗した `use` のある包みの修復のループの一回に限られる。
  - あわせて決めること: 止める別名は、右辺が誤りの型になった全ての別名とする（失敗した名前、見つからない名前の E0302、循環の E0310（R-182 で E0311）、大きさの E0422。§4.4 の E0422 の文も「誤りの型として扱う」）。判定は別名の型が誤りの型かの一つで、理由ごとに分けない。
    `let s = A` と `"{A}"` は、どの案でも S-713 の E0308（U8）である。
  - 別の S にしてよい論点: 無い。
- 影響: 仕様 §18.1 の失敗した名前の段落（(1) は「型別名を通して書いても同じ」の一句、(2)・(3) は例外の一文、(4) は値の位置の定めの改め）。`tasks/diag-codes.md` は変わらない。
  作業は W4-04 を終える前（U8 か、単独の小さな単位）。テストの票に、表の別名の行（`A`・`B`、fn・flow・`const` の初期化式）と、見つからない名前と循環の別名の行を足す。
  今の事例: `tests/spec/packages/failed_after_error_type/by_use.onsa` の `alias_literal`・`chain_literal`（`let _ = A { a: 1 }`）と `alias_path`・`alias_assoc`・`chain_*`（`let p = A.V`、`p` は読まない）は、使う所に診断を期待しない。
  (1)・(3)・(4) では変わらない。(2) では `alias_path` などの単位が続き、読まない `p` に E0309 が出て期待が変わる（`p` を `_` にするか読む形に直す）。
  `issues/R/R-271/alias` の `s` も、どの案でも使う所に診断が無い。Rust のテストで別名の struct リテラルの後ろの誤りを数えるものは未確認。
