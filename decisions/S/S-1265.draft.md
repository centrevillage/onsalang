### S-1265（細部） 上書きの代入で前の値を破棄する時機と直接構築

- **論点:** §12.2 の表は「代入で上書きされる前の値の破棄」を数えるが、時機を書かない。§3.5 は右辺の後に代入先の場所を評価する。破棄の要る宛先（`Buf` を含む値。第 2 期は Shared と `impl Drop`）で、前の値を右辺の前に壊すか後に壊すかが割れる。
  第 1 期は観測できない。破棄の要る値はインタプリタだけの `Buf` を含む値で C に届かず、arena は bump allocator（§8.4）なので、破棄の時機で尽きる点は変わらない見込みである。違うのは写しの数だけである。第 2 期の `impl Drop` で、破棄の効果と右辺の効果の順が観測できる。
  - S-1264 の答えとの揃い方: S-1264 が (a) なら、検査付きの添字は既に一時を通るので、下の (2) の条件「添字が検査を持たない」は (a) の直接構築の範囲と一致する。(1) なら一時を通す理由が二つ（検査付きの添字、破棄の要る型）になる。
  - S-1264 が (b)・(c) なら、検査の後に直接構築する宛先が増え、破棄の要る型では (1) が一時を戻し、(2) は「検査を先にした後」に条件を広げる形になる。(d) なら、破棄の要る型は (1) の一時に落ちる。
- **今の実装:** Core に破棄の文は無い（メモ 3.1）。試していない。
- **案:**
  - (1) 右辺と添字の評価の後、書く前に破棄する。破棄の要る宛先は常に一時に作ってから移す（`Let(t, e); Drop(p); Assign(p, Move(t))`、メモ 3.4）。順は「右辺、場所、前の値の破棄、書き込み」の一つ。
  - (2) 右辺が宛先を読まず、添字が検査を持たないときは、前の値を先に破棄して直接構築する。破棄が右辺の効果より先になる。条件の外は (1)。
  - (3) 前の値の破棄の要る部分（ハンドル）だけを先に一時へ退け、宛先に直接構築し、右辺の後に退けた部分を破棄する。順は (1) と同じで、写すのはハンドルの分だけ。右辺が宛先を読む形と、早い出口のある形は (1) に落ちる。
- **他言語:** 手元で、Rust（`d.rs`）は `x = mk(2)` で「rhs、drop old」、要素は「rhs、index、drop old」の順。C++17（`d.cpp`）は右辺の一時を作ってから移動代入の中で前の値を手放す。Swift（`ds.swift`）と Python（`dp.py`）も前の値の解放は右辺の後だった。どれも (1) の順である。
- **推奨と理由:** (1)。確度: 中。
  - 順が §3.5 の代入の順の続きの一つで、条件が無い。手元で確かめた言語の順とも同じである。
  - 第 1 期は観測できず、C に届かないので、写しの数だけが違う。速さのための (2)・(3) は、破棄の効果が観測できるようになる第 2 期の `impl Drop` と Shared の C の設計の前に決め直せる。その時までに当たるプログラムは無いので、手戻りは無い。
  - (2) は破棄の効果を右辺の効果より先に動かし、第 2 期に順の例外を仕様に書くことになる。(3) は順を保つが、ハンドルの部分を退ける形と落ちる条件が Core と後端に増える。
  - 費用: 破棄の要る大きな集成体（`Buf` と大きな配列を持つ struct）の上書きで、一時と写しが起きる。第 1 期はインタプリタだけである。
  - あわせて決めること: 仕様の字を今置くか。推すのは、決定にだけ書き、§12.2 か §3.5 の一句（「前の値は右辺と代入先の場所の評価の後に破棄される」）は第 2 期の `impl Drop` の回に置くこと。
- **影響:**
  - 仕様: (1)・(3) は §3.5 か §12.2 に順の一句（今置くか、第 2 期の `impl Drop` の回に置くか）。(2) は順の例外の文。
  - 作業: W8-04（`Drop` の置き場所、メモ 3.4）、W8-05（写しの記録）。
  - テスト: 第 1 期に観測できないので、事例は無い。`audit --memory` の写しの数（W8-05 の後）だけが案で違う。
- **独立のレビュー:** 段 1 は (1)（確度 高）で一致。確かめるだけ（A、細部）。(3) は同じ順の最適化で、仕様の案でなく実装の自由。字の案「代入先の前の値は、場所を評価した後、書き込む直前に破棄する（§12.2）。」は今入れる方を弱く推す（第 2 期の `impl Drop` の回でもよい）。(1) の費用で下書きに無いもの: ヒープの尖頭が「前の値 + 新しい値」になる（第 2 期）。
- 回答: (1)（2026-11-27、利用者「(1)で。ただし対応する実行環境に組み込みがあるので、メモリの最適化は必要です」）。仕様の字は第 2 期の `impl Drop` の回。メモリの条件は決定の M1〜M3。

## 新しい S の候補と別の問題

- 別の問題（W8-01 のメモ 4.2・15 章の判断 4 への注意、仕様の空白ではない）: メモはリテラルの要素を宛先の要素ごとに直接作る形（`P { a: f(), b: g() }` は `f` を `d.a` に、`g` を `d.b` に）を推す。
  宛先が既に生きている場所（代入先）で、後の要素が早い出口を持つと（`w.p = P { a: nine(), b: r? }`、`b` の腕の一つが `return`）、`w.p.a` を書いた後に抜け、代入が起きていないのに `inout` の `w` が半分だけ書き換わる。
  今のインタプリタも C も前の値のまま通る（`P/g121/probe/gap/c5/`。C は要素を一時に取ってから複合リテラルを代入する）。宛先の要素ごとの直接構築は、後の要素に早い出口が無いときに限るか、新しい束縛の宛先に限る条件が要る。S-1264 の (b)・(d) で添字の要素に直接作るときも同じ条件が要る。
- 新しい S の候補は無い。
