# S-918 フィールドの既定値の式が struct の型引数を読めるか（`struct G[T: AnyNum] { v: T, b: Bool = T.ZERO == T.ZERO }`）

- 空白: §4.4 は「既定値の式は `const` の初期化式の規則（§6.6）に従い、コンパイル時に一度だけ評価して焼き込む」「型引数に頼る型のフィールドの既定値は E0200 で、型引数を持つ struct の他のフィールドには書ける」と書く。
  フィールドの型は型引数に頼らず、式だけが型引数を読む形（`struct G[T: AnyNum] { v: T, b: Bool = T.ZERO == T.ZERO }`）の文は無い。
  読みは (1) 読めない（トップレベルの `const` と同じく名前が無く E0302。既定値は struct に一つ）、(2) 読める（具体化ごとに一つの定数。§6.6 の `impl[T]` の定数と同じ）、(3) E0200 で第 2 期に開く、の三つである。
  再現: `target/notes/118/w522/memo/probe/g2_param_in_value.onsa`。今は宣言の `=` が E0002 で止まる。
- 決定: 決定（2026-11-06、利用者。118 回目。同じ回に (1) から改めた）: (2) 型が型引数に頼らないフィールドの既定値の式は、`impl` の定数（§6.6）と同じく struct の型パラメータと const パラメータを読める。既定値は具体化ごとに一つである。`Self` と他のフィールドの名前は E0302 である。想定外の実害が出たら見直す。
- 経緯: 118 回目（2026-11-06）、W5-22 の設計メモが挙げた（G2）。親が「確認だけ」で出し、利用者が了承した。
  親は (1) で確認を取ったが、説明で、`impl[T]` の定数が既に同じことをしていて、変えても数行で済むことを落としていた。テストの担当が const パラメータの扱いを挙げ、利用者が「constパラメータの場合は許可しても問題はないように思いましたが、どこで問題が発生し得ますか？」と問うた。
  親が `impl` の定数の道で動かすと、const パラメータも型パラメータも `onsa test` が通った（`target/notes/118/w522/s918/`）。変わる点は §4.4 の文、`onsa interface` が値を出せないこと、誤りが具体化でだけ出ることで、最後のものは `impl` の定数と同じである。
  親が推奨を (2) に改め、利用者が「では(B)にしましょう。もし想定外の実害が出たら再検討で」と答えた。
- 補い（2026-11-06、親）: 既定値は、式がパラメータを読まなくても、型パラメータか const パラメータを持つ struct では具体化ごとに一つである（`impl` の定数と同じ）。§4.4 の括弧の字を決定に揃えた。値の同じ定数を畳むかは W8-01 の持ち越しにある。
