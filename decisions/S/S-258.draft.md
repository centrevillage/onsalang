- 案:
  - (a) 綴りの近い名前を候補にしない。E0302 の候補は決まった形（1〜5 行）だけで、クロックは S-359 の note のまま。§15.1 に一文。実装: 0 行。
    費用の要因: E1102・E1103 の「綴りの近い」の基準は、別に決める（W4-02 の前）。
  - (b) 見えている名前のうち、その位置に要る種類で綴りの近いものを候補にする（名前を置き換える一つの編集）。
    一（基準）: 綴りの近さは、文字の挿入・削除・置き換えと、隣どうしの二文字の入れ替えを一回と数えた最小の回数で、書いた名前の文字数の 3 分の 1（切り捨て）以下とする。1〜2 文字の名前には候補を出さない。§18.1 に一つ置き、E1102・E1103 も同じ基準にする。
    二（範囲）: その位置から見える名前（ローカル、モジュールの項目、`use` で取り込んだ名前、prelude、組込み型。`use` の要素ではそのモジュールの取り込める名前、`at` の後ろではクロックの名前、関連の名前ではその型の関連定数と関連関数）のうち、置き換えた後にその位置で名前の段の誤り（E0302・E0303・E0308・E0811・E0812）が出ないもの。
    三（数）: 最も近いものが三つ以下なら全てを並べ、超えれば候補を出さない（E0010 と同じ上限）。閉じた名前空間も同じ規則で、全てを並べる規則は作らない（`at smaple` は `sample` が候補、`at fast` は候補なしで S-359 の note）。
    実装: 距離の関数（20〜30 行。W4-02 の E1102・E1103 と共有）、位置ごとの名前の集め方と絞り込み（W4-04 の `names/fixes.rs` に 50〜80 行）。事例: 種類ごと（値、関数、型、定数のパターン、`use` の要素、クロック、関連の名前）に 1 件以上と、候補が二つの事例・四つ以上で候補なしの事例。
    費用の要因: 名前空間が増える（第 2 期の利用者の trait、クロックの宣言、利用者の効果）たびに集め方に足す。今の事例のうち近い名前が見える E0302 は、候補の数を書き直す（影響）。
  - (c) (b) の名前を note で示す（「a similar name: `gain`」）。候補にしないので、数の約束に入らない。実装: (b) の集め方（絞り込みは要らない、40〜60 行）。
    費用の要因: 修復のループが note の文字列を読んで直すことになり、当てた後の安全（S-236）を器が確かめられない。
  - (d) 閉じた名前空間（今はクロックの名前）だけ、その全てを候補に並べる。他は (a)。実装: 10 行。

- 推奨と理由: (b)。確度: 中。
  - §18.1 は既に E1102・E1103 で「綴りの近い」を候補の数の約束に使っていて、その基準を仕様に置く必要がある。基準を一つ決めれば、E0302 に当てるのは集め方の追加だけで、マニフェストのキーと名前で別々の規則にならない。
  - 書き手に効く形がある。C から移す書き手の `sqrtf`・`powf`・`floorf`（取り込んだ `sqrt`・`pow`・`floor` と 1 文字違い）、綴りの入れ替え（`Optoin`、`Soem`、`smaple`）。既存言語の別の名前（`String`、`Vec`）は距離が遠く候補にならず、相手の言語の意味を写さない（S-250 で表に入れなかったのと同じ結果）。
  - 当てた後の安全を器が確かめられる。置き換えた名前がその位置で名前の段を通るものだけを候補にするので、同じ段の誤りを残さず、後の段の型の誤りは出てよい（S-236）。候補が複数の形は、直し方が一つに決まらないときの §18.1 の書き方と同じ。
  - 閉じた名前空間に別の規則を作らない。クロックは見えている名前の一つの種類として同じ規則に入り、クロックの宣言で名前空間が開いても規則は変わらない。
  - 1〜2 文字の名前を外すのは、`y` に `x`・`a`・`b` を並べるような当て推量の候補を避けるため。(c) は数の約束に入らず、修復のループが当てられない。(d) は閉じた一覧に依る規則を足す。
  - 後で緩められるか: (a) から (b) は候補が増えるだけで、プログラムを壊さない。ただし基準は E1102・E1103 のために W4-02 の前に決める必要があり、そのときに E0302 に当てるかも決まる。
  - あわせて決めること（取り込んでいない同じ名前、9 行）: 見えない名前と同じ名前の取り込める項目が、std・依存のパッケージ・自分のパッケージの他のモジュールに一つから三つあれば、`use` の挿入を候補にする（`sqrt(x)` に `use std.math.{sqrt}`）。確度は中。
    §15.1 の `use` の無い経路と §8.1 の標準の効果の候補を、名前だけの使う所に広げるもので、W4-04 の「E0302 は `use` の挿入」をこの形まで含める。綴りの近い名前を他のモジュールから探すことはしない（範囲が広く、数が決めにくい）。
    第 39 組の S-462 の下書き（答え待ち）の (a) では、失敗した `use` の名前を使う所は黙るので、この候補は出ない。S-462 が (c) なら使う所にこの候補が出て、元の `use` と重なる（S-462 の (c) の費用の要因のとおり）。
  - あわせて決めること（`use` の要素、7 行）: `use std.math.{sqr}` の要素には、そのモジュールの取り込める名前から (b) の候補（`sqrt`）を出す。S-462 の下書きが前提にする「失敗した `use` の要素の候補だけを出す形」と食い違わない。
