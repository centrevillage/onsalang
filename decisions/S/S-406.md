# S-406 他の言語の文字列の区切り

- 空白: 他の言語の文字列の区切り（Rust の `r#"…"#`、Swift の `#"…"#`、Python・Kotlin・Swift の `"""…"""`、C# の `@"…"`・`$"…"`、JS の `` `…` ``）。
  今は `#` と `@` の位置の E0002、`$` と `` ` `` は E0001「invalid character」、一行の `"""x"""` は三つのリテラルで S-388 の形（まとめる候補を二回当てると `"x"` になる）。どれも候補なし。
  （直し 2026-10-11、第 24 組の下書き: 一行の `"""x"""` が S-388 の形になるのは並びの中（`f("""x""")`）だけで、文の位置は一般の E0002。行を立てる言語の判断は `rules/criteria.md` 7.32 の一覧で行う（`"""…"""` は Python・Swift・Java・C#）。C++ の `R"(…)"` と C# の `"…"u8` は S-400 で決まっている）S-400 の名前の直後の形には入らない。
  既存言語の形として検出するか。第 20 組の下書きで見つけた（2026-10-10）
- 提案: 決定（2026-10-11、利用者が ID を挙げて推奨の (b) を了承し、細部の S-400 との向きも推奨を了承。下書きと Fable が一致、第 24 組）: `$"…"`、`@"…"`、`$@"…"`、`r#"…"#`、`#"…"#`、`"""…"""`、`'''…'''`、`` `…` `` を一つの E0002 の行（字句の段、例: `string_delimiter`）にし、候補は出さず（`$"…"` も、S-400 の `f"…"` と揃えて候補なし）、note で Onsa の文字列の書き方を示す。
  範囲は開きの区切りから同じ行の閉じの区切りまで（閉じが同じ行に無ければ開きだけ）。中身は読まず、中身の E0001 は出さない。S-400 の名前に接する形も同じく、形の E0002 を報告して中身を読まない（S-400 の読みの補いを改めた）。一字でない文字のリテラル（`'abc'`）は E0001 のままで、note で文字列は `"…"`。仕様 §2.4。
  実装は W3-05（字面の作業。字句の段の行）
