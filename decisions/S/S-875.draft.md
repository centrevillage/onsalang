# S-875 `as` で書ける組の `narrow_*`（`Option[T]` を返す）の E0413 の修正候補の形（`x as T` か `Some(x as T)` か、期待の型で選ぶか）

- 決定済みで戻さないもの: E0413 にすること（S-98、S-210、R-158）と、`round_*` の候補（`x as T`）。本当の縮小の `narrow_*` と、`as` で書けない組の E0411（候補なしで note）。
  第 81 組の下書きの「S-875 の仕組みの出所」と「S-875 の形の表」の節（写しは `target/notes/110/g81/draft.md`、入力は `target/notes/110/g81/probe/`）。
- 論点: §3.3（82 行）は `as` で書ける組の変換メソッドを E0413 とし、候補を「`as` の形」とする。`round_*` は返り値の型が `as` と同じで候補が一つに決まるが、`narrow_*` は `Option[T]` を返すので、`as` の形が `x as T`（型が変わる）か `Some(x as T)`（元の型と値を保つ）かで割れる。
  `as` で書ける組の `narrow_*` は常に `Some` を返すので、`Some(x as T)` が意味の同じ書き方である。期待の型が `T` の位置では、書き手は `narrow_*` が `T` を返すと誤解している。
- 今の実装: 形の表のとおり。どの形も候補の無い E0413。
- 案: 
  - (1) 常に `x as T`。(2) 常に `Some(x as T)`。
  - (3a) 期待の型で選ぶ、分からなければ候補なし: 期待の型が `T` なら `x as T`、`Option[T]` なら `Some(x as T)`。期待の型が無いか型変数の位置（`let y = …`、`match` の対象、`?` の被演算子、受け手）は候補を出さず、note で二つの形を示す。
  - (3b) 期待の型で選ぶ、分からなければ `Some(x as T)`: (3a) と同じだが、期待の型が分からない位置は、メソッドの型を保つ `Some(x as T)`。
  - (4) `narrow_*` には候補を出さず、note で `as` の形を示す。
  - 形ごとの出力: 返り値 `Option[I64]`（25 件の事例）は、(1) の候補が E0401 を残し、(2)・(3a)・(3b) が通る、(4) が候補なし。返り値 `I64`（`widen_int`）は、(1)・(3a)・(3b) が通り、(2) が E0401 を残し、(4) が候補なし。
    `let y = x.narrow_i64()` の後で `Option` として使う形は、(1) が後の文に E0401、(2)・(3b) が通り、(3a)・(4) が候補なし。後で `I64` として使う形は、(1) が通り、(2)・(3b) が後の文に E0401。
  - 書き手から見て（修復のループ）: 候補が通れば一回。(1)・(2) は、期待と逆の位置で候補を当てると E0401 が出て二回。(3a) は候補の出る位置で一回、出ない位置は note を読んで手で直して一回。(4) はどの位置も手で直す。
  - 修正候補: §18.1 の約束（当てた後に同じ段の E0401 を残さない）を、(1) は期待の型が `Option[T]` の位置で、(2) は `T` の位置で破る。(3a) は期待の型で決まる位置だけに出すので破らない。(3b) は期待の型が分からず後で `T` として使う形で破る。(4) は候補が無いので当たらない。
    候補が書き手の意図で一つに決まるのは、期待の型が分かる位置だけである（分からない位置では、`Option` を期待したか `T` を期待したかが後の文にある）。
  - 通るプログラム: どの案も変わらない（E0413 の候補だけ）。
  - 規則と例外: (1)・(2) は §3.3 の「`as` の形」をそのまま読む（(2) は「`Some` で包む」の一句）。(3a)・(3b) は §3.3 に「期待の型で選ぶ」の一文（(3a) は加えて「分からなければ候補なし」）。(4) は §3.3 の候補の文から `narrow_*` を除く一句。
  - 実装の量（W5-14 の E0413 の候補の単位）: `round_*` の候補（受け手のソースと ` as T`、被演算子の位置の括弧、§3.3 の E0011）はどの案でも作る。(1) はそれを `narrow_*` にも使う（約 +2）。(2) は `Some(` の挿入を足す（約 +5）。
    (3a)・(3b) は期待の型の頭を見る分岐（約 +10〜15。`expected` は既に引数にある）。(4) は 0。後の段への手当ては、どの案も無い（候補は検査の段だけ）。
  - 事例: 25 件の事例は、(1) では候補を当てた後の E0401 で器の約束の確かめに落ち、(2)・(3a)・(3b) は写しが要る（25 件。`fixes` の数を書く）。`e0413_forms.onsa` の `widen_int` と `.fix1` は、(1)・(3a)・(3b) で今の期待どおり、(2) で写しの書き直し、(4) で `fixes` の数の書き直し。

- 推奨と理由: (3a)。確度: 中。
