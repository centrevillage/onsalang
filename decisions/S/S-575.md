# S-575 export する flow の `block` の入力でホストの情報（テンポ、拍の位置）を受ける形と、`@param` の必須（E0809）

- 空白: S-172 の方向は「ホストの情報は `block` の入力で渡す」で、S-572 の下書き（第 35 組）もテンポと位置をトランスポートのイベントに入れず `block` の入力に置く。一方 §11.7 は、export する flow の `block` の入力に `@param` を必須にしている（E0809）。このままでは、テンポや拍の位置が、自動化できるパラメータとしてホストに見える。決めること:
  1. `@param` の無い `block` の入力を export で認める印（ホストが与える入力）の形と、C の `Params`・`_param_info` での扱い。
  2. ホストが与える情報の一覧（テンポ、拍の位置、小節の頭、拍子、再生中か）と、その型と名前（std の型か、印の引数か）。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51・52 回目）: `block` の入力に `@host(<種類>)` を付けると export でも `@param` が要らず、ラッパーが呼び出しの最初のサンプルの時点の値を書く。種類は `tempo`・`beat`・`bar_start`・`sig_num`・`sig_den` の閉じた一覧（型と既定の値は種類ごと）で、ラッパーは種類ごとの条件を満たさない値の代わりに既定の値を書く（回答の (hv2)）。
  C では `Params` の欄に置き、表 `<p>_host_info`・`<P>_HOST_COUNT` と `onsa_host_kind`・`onsa_host_info` で示す。種類の誤りは E0005、型の違いと `@param` との重なりは E0809。仕様 §19.1
- 経緯: 第 35 組（X-7）の下書き（onsa-gap、S-572 の新しい S の候補）と、独立のレビューの段 2（別の S にする。イベントでなくパラメータの話で、第 35 組の範囲の外）から立てた（2026-10-22、51 回目）。関係: S-172、S-565、S-572。
