# S-698 固有の impl のメンバに、型より広い `pub`（S-662 の E0020）と、届く範囲より狭い型の名前（S-665 の E0303）が両方あるとき（`impl Pkg { pub fn leak() -> Hid }`）

- 空白: §15.1 は、型の可視性より広い `pub` をメンバに書くと冗長で E0020（候補は外すこと）とし、固有の `impl` のメンバの届く範囲をメンバと型の狭い方とする。§18.1 は、冗長の E0020 の後ろから宣言を読み続け、一つの単位の中では最初の誤りで検査を止める。
  両方が一つのメンバに当たるとき（`Pkg` は無指定、`Hid` は `priv` の `impl Pkg { pub fn leak() -> Hid }`）、読みが (1) E0020 だけ、(2) E0303 だけ、(3) 両方、に割れうる。再現は `target/notes/70/w403/u4b/t/probe/gap1.onsa`（U4b の前は診断なし）。
- 親の案（確認だけ）: (1)。一つの単位の一つの誤りで、`pub` の E0020 は名前の段、見出しの型の E0303 はその後の検査なので、段の順で E0020 が先に出る。候補（`pub` を外す）を当てた後は、届く範囲がパッケージのままなので E0303 が出て、候補なしで止まる（§18.1 の修正候補の約束に合う）。仕様の文は変えない。
- 決定: 親の案のとおり (1)。E0020 だけを出し、候補を当てた後は E0303 で止まる。見えない名前・フィールド・メンバの E0303 が名前の段であることは §18.1 に一文を足した（同じ回）。仕様の文は他に変えない。W4-03 の U4b（2026-10-26 決定、利用者が OK）。
- 経緯: 70 回目（2026-10-26）、W4-03 U4b/t（onsa-test）が空白として報告した（期待値を書かず、事例を分けた）。U4b の実装は分岐を足さずに進める。
- 補い（2026-10-26、親）: 71 回目の文書の点検（指摘 4）を受けて、利用者が了承し（2026-10-26）、§18.1 に「見出しに書いた名前が宣言の届く範囲より狭い E0303（§15.1）は型の段である」を足した。決定が頼る「見出しの E0303 は名前の段の E0020 の後」を仕様に書いたもので、挙動は変わらない（実装は `sig/types.rs::check_reach`）。
