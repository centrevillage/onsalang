# S-1145 細部: flow の辿れない `let` が、他の辿れない `let` か `^` の輪からだけ読まれるときの E0309 の修正候補（`let a = x * 2.0`・`let b = a + 1.0`・出力 `x` で、`a` を `_` にすると `b` の `a` が E0302 になる）

- 空白: §5.1 は E0309 の修正候補を「名前を `_` に変える形」とし、flow の本体では「出力と `let _` から辿れない `let` が使われない束縛である（`^` の帰還だけで互いを参照する組も含む）」とする。
  辿れない `let` が他の辿れない `let` か `^` の輪からだけ読まれるとき（`let a = x * 2.0`・`let b = a + 1.0`・出力 `x`。`let a = prev~(^b)`・`let b = a + x`・出力 `x`）、`a` を `_` にすると `b` の中の `a` が名前の段の E0302 になり、§18.1 の候補の約束（当てた後に同じ段か前の段の誤りを残さない）に反する。
  今はどちらも通る（flow の E0309 は W7-14 が入れる）。再現は `target/notes/166/w714/memo/probe/unused.txt` の `feedback_cycle_only` と `gaps.txt` の `g2_chain`。候補と note だけが変わり、通るプログラムは変わらない。
  仮の扱い: 名前の段の読みが 0 の束縛にだけ `_` の候補を出し、読みのある束縛は候補なしで、読む `let` を note で示す。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
