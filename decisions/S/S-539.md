# S-539

- 空白: 既定値と等しいリテラルの `init`（仕様 §11.4、S-29）の範囲。(a) 綴りの違う 0（`0.00`、`0e0`、`0x0`、`0b0`、`00.00`）を外すか。(b) 整数の `-0`（前置の `-` と `0`）を外すか。
  (c) 型と合わないリテラル（`x: F32` の `prev~(x, 0)`。今は E0401）と、局所の名前が遅延の名前を隠す形（E0812）も外すか（構文の段では型も名前の解決も見えない。W3-12/i の設計メモが補った）。§11.4 は「値が既定値と等しいリテラルの `init`（`0`、`0.0`、`false`。`-0.0` は既定値と違うので残す）」と書く。
  W3-12/t（U1）が見つけた（2026-10-15）
- 提案: 決定（2026-10-15、利用者が (c3a) を選んだ。親の確認だけの案は、助言の担当の二段を経て取り下げた）: `onsa fmt` は既定値と等しい `init` を取り除かない（S-29 の fmt の部分を撤回）。`check` は書いた形も省略した形も受理する（E0020 にもしない）。
  リテラルが `T` を決める形（`let y = prev~(^y, 0)` は通り、`init` を外すと E0406）があり、構文だけでは判定を保てないため（§18.2 の原則、S-546）。(a)・(b)・(c) は問わなくなった。書き手の注意に頼る書き方なので、仕様の例・`docs/`・examples・std は省略の形に揃え、gate で確かめる（道具は持ち越しの「W3 の終わり」）。
  テストのコードの明示の 0 も省略の形に直し、明示の受理を確かめる 2 件だけを残した（W3-12）。仕様 §0.2 の P2・§11.4、`spec/tools.md` §3.3
