# S-626 `onsa --version` の出力の形と、埋め込みの std の版の値

- 決定済みで戻さないもの: 一致しなければ E1103 で、note に埋め込みの版を示すこと（S-83、S-597）。表示は `onsa --version`（S-160）。比べ方が一致であること（S-83。下の他言語は下限で比べるが、この組では戻さない）。
  第 77 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/95/g77/draft.md`）。
- 論点: §15.3（198 行）は「std はコンパイラに埋め込まれている。`std = "x.y.z"` と書くと版の固定になり、埋め込みの std の版と一致しなければ E1103。埋め込みの std の版は `onsa --version` で表示する」とする。版の値（コンパイラの版と同じか、std が自分の版を持つか、仕様の版に結ぶか）と、出力の形を書いていない。§18.2 のコマンドの表に `--version` が無い。
  std の版の固定は R-88・S-83 で入った。std は埋め込みで差し替えられないので、固定は「この std で書いた」ことを確かめる印になる。
  - 本文の「今の実装は `onsa 0.1.0` の 1 行」は W4-01 の前の挙動で、今は 2 行である（下）。
- 今の実装: `onsa --version` と `-V` は、標準出力に `onsa 0.1.0` と `std 0.1.0` の 2 行を出し、終了コード 0（W4-01 の仮の扱い、`SPEC-GAP(S-626)`）。値は `onsa_sema` の `CARGO_PKG_VERSION`（ワークスペースの版 `0.1.0`）。
  `[dependencies]` の `std = "9.9.9"`・`"0.2.0"`・`"0.1"`・`"latest"` はどれも 0（照合しない）。`crates/onsa_cli/tests/package_model.rs` は、`std` の語を含む行の最初の `x.y.z` を読む。
- 案: 値:
  - (a) コンパイラの版と同じ値（今の実装）。§15.3 に「埋め込みの std の版はコンパイラの版である」と書く。
  - (b) std が自分の版を持つ（`std/` に版を置き、std の公開の項目を変えたときに上げる）。
  - (c) 仕様の版に結ぶ（仕様の版が変わるときに上げる）。
  - 出力の形: (f1) 2 行 `onsa x.y.z`・`std x.y.z`（今の実装）。(f2) 1 行 `onsa x.y.z (std x.y.z)`。(f3) 1 行 `onsa x.y.z` だけ（(a) と組むときだけ成り立つ。std の版はコンパイラの版と書く）。どれも標準出力、終了コード 0 で、§18.2 の表に行を足す。
  - 書き手から見て: E1103 の note が埋め込みの版を示すので、修復のループはどの案でも一回で正しい版を書ける。CI が版を読むときは、(f1)・(f2) が `std` の語で、(f3) が先頭の行で読む。
  - 版を上げたときに固定が誤りになる範囲: (a) は、コンパイラの版を上げるたびに std を固定した全てのマニフェストが E1103 になる（std が変わっていなくても）。(b) は std を変えたときだけ。(c) は仕様の版を上げたときだけで、std の修正が版に現れない。
  - 通るプログラム: リポジトリで std を固定するのは 9 件で、どれも `0.1.0` でない（`"0.2.0"` が 7 件、`"9.9.9"` が 2 件）。(a) では全てが E1103 で、(b)・(c) でも、最初の版を `0.2.0` にしない限り同じである。
    `examples/voice_host` は `example_host.rs` がビルドするので、W4-02 で行を直すか消す（このマニフェストは旧い名前 `numeric`・`flows`・`memory.bulk_threshold` と `prefix = "onsa_"` でも、どの案でも直す）。
  - 規則と例外: (a) は §15.3 に一句。(b) は版を上げる規則（何を変えたら上げるか）と、それを守らせる仕組み（std の中身と版を突き合わせる検査）が要る。(c) は仕様の版の形（`0.3` などの二つの欄）と `x.y.z` の食い違いを決める。
  - 実装の量: (a)+(f1) は 0 行（`SPEC-GAP(S-626)` の印 2 か所を外す）。(f2) は 1 行と、テストはそのまま（`std` の語の行に版がある）。(f3) は 1 行とテストの直し。
    (b) は版の置き場と `build.rs` の読み（約 +10〜20）、版を上げ忘れない検査（約 +20〜40、std を変える全ての作業に手当てが続く）。(c) は仕様の版の定数（約 +5）と形の食い違いの扱い。
  - 後で改められるか: (a) から (b) へ移すときは、std の版をその時のコンパイラの版から始めれば、そのとき一致していた固定は一致したままである。(f3) から版を分けると出力の形が変わり、先頭の行を読む CI が壊れる。(f1)・(f2) は値を分けても形が変わらない。
- 他言語: rustc 1.94.1 の `rustc -vV` は `release: 1.94.1` などの「名前: 値」の複数行で、標準ライブラリはコンパイラと同じ版で別に示さない。`cargo --version` は `cargo 1.94.1 (29ea6fb6a 2026-03-24)`。
  `go version` は `go version go1.27.2 darwin/arm64`（標準ライブラリはツールチェーンの版）。`swift --version` は 2 行（ドライバと Swift の版、`Target:`）。`python3 --version` は `Python 3.14.5`、`node --version` は `v26.11.1`（構成要素の版は `process.versions` に 30 項目）。
  版の固定: Cargo の `rust-version = "1.99"` は「p@0.1.0 requires rustc 1.99」、`go.mod` の `go 1.99` は「go.mod requires go >= 1.99」、`swift-tools-version:9.0` は「using Swift tools version 9.0.0 but the installed version is 6.3.1」で、どれも下限で比べる（`probe/other/`）。
- 推奨と理由: (a) と (f1)。確度: 中。
  - std はコンパイラに埋め込まれ、コンパイラと一緒にしか変わらない。版を分けると、上げる規則とそれを守らせる検査が要り、std を変える全ての作業に手当てが続く。同じ値なら規則は一句で、実装は今のままである。
  - (a) の代償は、コンパイラの版を上げるたびに std の固定が E1103 になることで、固定を一致で比べる決定から来る。E1103 の note が正しい版を示すので、直すのは一回である。std だけの版が要ると分かれば、その時の版から始めて (b) へ移せ、そのとき一致していた固定は壊れない。
  - 出力は今の 2 行が、std の版を名前付きで示し、後で値を分けても形が変わらない。(f3) は分けるときに形が変わる。
  - あわせて決めること: §18.2 の表に `onsa --version` の行を足し、出力（標準出力の 2 行 `onsa x.y.z` と `std x.y.z`、終了コード 0）を書く（CI と修復のループが読む出力なので基本仕様に置く）。`-V` は同じ。
    固定の値の形は `major.minor.patch`（10 進の三つの欄）で、形に合わない値（`"0.1"`、`"latest"`）と表（`{ version = "0.1.0" }`）は E1103（値の形）、形に合って違う値は E1103（不一致、note に埋め込みの版）。比べるのは文字列の一致である。
- 影響: 仕様 §15.3 の 198 行に一句（(a) は「埋め込みの std の版はコンパイラの版である」、(b)・(c) は版の決め方）、§18.2 の表に `onsa --version` の行。`tasks/diag-codes.md` の E1103 の行は変わらない。
