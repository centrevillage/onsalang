# S-831 族: §15.3 の provides の名前

- 決定済みで戻さないもの: 標準の効果で `Alloc` 以外はビルドで E0200（S-824）、値の形の誤りは全てのコマンドで E1103（S-99）、一つの項目の誤りは独立に全て報告（S-827）、ターゲットの E0200 は `check`・`test` を止めない（S-154）、綴りの候補は出さない（S-597）、E0610 の規則（§15.3、R-134 で `main` も W6-03）、利用者の効果の宣言はこの版で E0200。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/149/gap/g102/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版・入力は `advisor/`、下書きと段 1 の報告は `target/notes/149/gap/onsa-gap-a6cf48a7c211ae464-001.md`・`g102/onsa-advisor-a8304a351ab8aa35f-001.md`。
- 論点: §15.3 の表は `provides` を「効果の名前の配列」とし、「`main` または export される関数の効果行に、`provides` に無い効果が含まれていれば E0610」とする。
  何を「効果の名前」とするか（std の宣言か、パッケージの宣言も含むか、素の名前か経路か）と、効果でない名前・同じ名前の重なりのコード・出す段が書かれていない。
  今の実装は `Alloc` 以外の全ての名前を、効果か否かを問わずそのターゲットのビルドの E0200 にする。`check`・`test` は名前を読まない。
- 今の実装: 形の表のとおり。`check` は `["Allc"]`・`["Str"]`・`["alloc"]`・`["std.core.Alloc"]`・`["Alloc", "Alloc"]`・`[]` のどれも診断なし（終了コード 0）。
  `build --target t` は `Alloc` 以外の要素ごとに E0200「this version does not support `provides` other than `Alloc` (`Allc`)」を出し、終了コード 2。note も候補も無い。`["Alloc", "Alloc"]` はビルドも通る。
- 案:

    同じ名前を二度書く形は E1103 で、後の要素に付け、前の要素を note で示す（§4.5 の集合の並びと同じ形）。一覧に無い名前は重なりに数えない。一覧の名前でこの版が与えないものは S-824 のまま E0200。
  - (b) 名前の段で解く。要素は std の公開の効果の宣言を名指す名前（素の名前か、`std.time.Clock` のような std からの経路）とし、ソースの解析の後に std の宣言から引く。
