# S-628 `[package] name = "std"` の診断のコード

- 決定済みで戻さないもの: §15.3 の表の `[package]` の `name` は「`std` は書けない」（172 行）。E1103 はパッケージ名の形が規則に合わないことを含む（§18.1 の 80 行、S-99）。
  第 77 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/95/g77/draft.md`）。
- 論点: `python3 -B tools/docs.py show S-628` の `空白`（`name = "std"` のコードが、パッケージ名の形の E1103、ルート直下の名前が依存と重なる E0304、別のコードのどれか）。下書きでは S-827 の規則から決まる S として、個別の節を持たない。
- 今の実装: `name = "std"` は `check`・`test`・`build` とも 0 で、`build` は `onsa_std.c` を書く（族の形の表の「パッケージ名 `std`」の行）。
- 案: 読み (1) パッケージ名の形の E1103（値の位置、全てのコマンドのマニフェストの検査）。読み (2) ルート直下の名前が依存と重なる E0304（ソースの段）。読み (3) 別のコード。
- 他言語: S-827 の「他言語」のとおり。
- 推奨と理由: `std` は書けないことは §15.3 の表の `name` の規則で、版によらない。値 `"std"` に E1103（パッケージ名の形）を全てのコマンドで出し、note で `std` が埋め込みの標準ライブラリの名前であることを示す。候補は出さない（別の名前は書き手が決める）。
  E0304（ルートの名前の重なり）はソースの段のコードで、マニフェストの検査はソースより先なので当たらない。
- 影響: `tasks/diag-codes.md` の E1103 の行にパッケージ名の `std`。作業は W4-02 の U2b。
