# S-697 struct リテラルで、書かないフィールドを既定値で埋める構文（見えないフィールドを持つ struct を、他のモジュールでもリテラルで作る）

- 決定済みで戻さないもの: 見えないフィールドを書いた形の E0303 の位置（S-35 の補い）。derive と手書きの `impl` の重なりの E0304（§6.4）。`enum` の `Default` の derive の E0416（S-49）。`Default` の上位の trait が無いこと（S-900・S-902 の後の §6.3）。
  第 88 組の下書きの写しは `target/notes/117/g88/draft.md`、入力は `P117/g88/probe/`（消えうる）、段 1・段 2 の答えは `target/notes/117/g88/advisor/`、親の入力は `target/notes/117/g88/parent/`。
- 論点: §4.4 と §15.1 により、`priv` のフィールドを持つ struct は他のモジュールではリテラルで作れず、作る関数を通す。§6.4 の既定値は型全体の `Default` だけで、一部のフィールドを書いて残りを埋める形が無い。
  形を足すか、足すなら既定値の出所（フィールドごとの宣言か、型の `Default` か、元の値か）、印の有無、見えないフィールドを埋めるかを決める。
  - 出所:
    - §4.4 の「全てのフィールドを一度ずつ書く」は、0.3 の初版（`55d421d6`、2026-10-01）からの文である。元は 0.2 のレビューの G-03（`history/review-draft-0.2.md` 290 行、`history/onsa-0.3-changes.md` 34 行）の「struct リテラルの省略形は採らない」で、G-03 の主題は構文を借用元に揃えることである。
      既定値で埋める形を比べて退けた記録は見つからなかった。過不足の E0410 は S-109（本文にコードを書く）と S-179（重複）である。
    - §7 の「残りを省く `..` は無い」も G-03 のパターンの一覧から来る。「フィールドを足したとき、全てのパターンが落ちるようにする」は初版からの文で、理由を議論した決定は無い。パターンの論点は下のS-903 に分けた。
    - §15.1 の `priv` は S-35（レビュー R-38）で、補い（2026-10-26）が「見えないフィールドを持つ struct は、書いても省いてもリテラルで作れず、パターンでも分解できない」とした。§15.1 の理由の文は「隠すのは、不変条件を守るために外から書き換えられては困るフィールドだけにする」である。
      この文が言うのは書き換えからの保護で、作る関数が唯一の入口であることは、作る側の設計として残る。
    - §6.1: 多重定義、既定引数、可変長引数、名前付き引数は無い。作る関数の引数は位置だけで決まる（`Ring.new(data)`、`F32` が五つ並ぶ `Adsr.new(…)`）。フィールドの名を書いて値を渡せる形は struct リテラルだけである。
    - §6.3・§6.4・S-49: `P.default()`、`T.default()`。struct の derive は各フィールドの既定値を並べる。§11.4 の `prev~` の `init` の省略と `match~` の取られない腕も `T.default()` を使う。

  `onsa interface` は `priv` のフィールドも表示する（`priv head: U32  // offset 16`、`c01`）。`pub const INIT` は評価した値を表示する。
  リポジトリの Onsa のコードと仕様の例の struct の宣言は約 2744 個で、`priv` のフィールドを持つのは 32 個（std の `Gen`、§14 の `Conv` の他は可視性の事例）である。`: Default` は 2 個である。std の struct は `Gen` の 1 個、`examples/` は 0 個で、既定値を埋めたい形の実例はまだ少ない。
- 案: 例は `pub struct Ring { data: [F32; 4], priv head: U32 }` を他のモジュールで作る形である。(b)・(c)・(f) は宣言を `priv head: U32 = 0` と書く。
  - (a) 何も足さない: §4.4・§15.1 はそのままである。作る関数（`Ring.new(xs)`）か、関連定数を写して書き換える形（`var r = Ring.INIT` と `r.data = xs`）か、W5-06 の後の `var r = Ring.default()` で書く。
  - (b) 宣言の既定値とリテラルの印: フィールドの宣言に `= 式` を書き、リテラルの最後の `...` が、書かないフィールドを宣言の既定値で埋める（`Ring { data: xs, ... }`）。印の無いリテラルは今のまま全て書く。
    既定値の式は `const` の初期化式の規則（§6.6）に揃え、コンパイル時に一度だけ評価して焼き込む。`Buf` は E0407、Shared を含む型はこの版の `const` と同じく E0200 である。型引数に頼る型のフィールドの既定値は置かない。
    `...` で全てのフィールドを書いた形と、`...` の後に既定値の無いフィールドが残る形は誤りである。`priv` のフィールドも既定値があれば他のモジュールで埋まり、書くかどうかは struct の設計の側の選択である。
    derive の `Default` は宣言した既定値を使い、既定値を書いたフィールドは型の `Default` を要らない。`...` は宣言した既定値だけを使い、trait の `Default` を呼ばない。
  - (c) 宣言の既定値で印なし: 宣言は (b) と同じで、既定値のあるフィールドはリテラルで省ける（`Ring { data: xs }`）。§4.4 の E0410 は既定値の無いフィールドに残る。
  - (d) 元の値の式から埋める: `Ring { data: xs, ..Ring.INIT }`、`Ring { data: xs, ..Ring.new(ys) }`。宣言は変えない。書かないフィールドは元の値から取り、見えないフィールドも取る（今の `var r = …; r.data = …` と同じ値）。元の値は式で、一度だけ評価する。
  - (e) 型の `Default` から埋める印: 宣言は変えない。型が `Default` を満たすとき、`Ring { data: xs, ... }` は `Ring.default()` の値の書いたフィールドを置き換えた値である。型が満たさなければ E0416 である。作る側の選択は `: Default` か手書きの `impl Default` である。
  - (f) (b) から見えないフィールドを除く: 宣言と印は (b) と同じで、見えないフィールドは既定値があっても埋まらず、今の E0303 のままである。
  - 形ごとの出力（`Ring` を他のモジュールで作る）:

    | 案 | 書く形 | 宣言の変更 | `data: Buf[F32]` でも書けるか |

    | (a) | `Ring.new(xs)`、または `var` の 2 行と値の行 | 作る関数か定数を置く | 作る関数で書ける |
    | (b) | `Ring { data: xs, ... }` | `head` に `= 0` | 書ける |

    | (d) | `Ring { data: xs, ..Ring.INIT }` | 値を出す定数か関数を置く | `const` に置けないので関数の値から（上書きされる `Buf` の破棄が要る） |
    | (e) | `Ring { data: xs, ... }` | `: Default` | 書けない（`Buf` は `Default` を持たない、§6.3） |
    | (f) | 他のモジュールでは `Ring.new(xs)` | `head` に `= 0` と作る関数 | 作る関数で書ける |

  - 書き手から見て（LLM を含む）: 最初の形はまず `Ring { data: xs }` か、Rust の `Ring { data: xs, ..Default::default() }` である。
    (a) は E0303 の note で作る関数を探す。関数が無い他のパッケージの型は、読み手の側で直せない。引数が多いと位置の取り違えが検査で見つからない（同じ `F32` が並ぶ）。修復は 1 回である。
    (b) は `Ring { data: xs }` の後に誤りの note で `...` を知り、修復 1 回である。Rust の形も 1 回で直る。(c) は最初の形がそのまま通り、修復 0 回である。ただし読み手はリテラルからフィールドが省かれたことを知る印を持たない。
    (d) は Rust の形に近いが、`Default::default()` を `Ring.default()` に直す一回が足され、見えないフィールドの無い型でも元の値を用意する必要がある。`..r` で Affine のフィールドを持つ値を消費する形はモードの誤りが一回増えうる。
    (e) は (b) と同じ 1 回だが、`Default` を満たさない型には書けず、`Ring.default()` の値を上書きする形と二重に読める。(f) は可視のフィールドは (b) と同じで、見えないフィールドは (a) と同じである。
    (b)・(e) の `...` は仕様の例の省略の記法（`{ ... }`、§7・§8）と同じ字で、書き手が省略のつもりで `Item { ... }` と書くと通りうる（全てのフィールドに既定値があるときだけ）。
  - 修正候補（§18.1）: どの案も候補の要る新しい形は誤りの形に限る。(b)・(f) の「全てのフィールドを書いた上の `...`」は `, ...` を消す候補で、意図は一つで、止まる。
    (b)・(c)・(f) で「既定値の無いフィールドが残る」形は値が分からないので候補を作らず note である。(b)・(f) の `Ring { data: xs }` に `...` を足す候補は、書き忘れの読み（値を書くつもりだった）も残るので意図が一つに決まらず、note で示す形が合う。
    (d) の候補は元の値を決められないので作らない。(e) の `Ring { data: xs }` も同じ見方で note である。Rust の `..Default::default()`（今の E0002）は、どの案でも書き手の意図に対応する値が同じとは言えない（手書きの `Default` がありうる）ので候補を作らない。
  - 通るプログラム: どの案も今通るプログラムを誤りにしない。`tests/`・`examples/`・`std/`・`spec/` の ```onsa ブロックで、フィールドの宣言の `= 式`、リテラルの `...`・`..` を書く形は 0 件で、今の E0002 を期待する事例も無い（検索で 0）。
    変わるのは今の E0002 が通る向きだけである。見えないフィールドの E0303 の事例（`tests/spec` の 40 ファイルが E0303 を含む）は既定値を書いていないので、どの案でも期待は変わらない。`spec/` の例も、§4.4・§15.1 の本文の文を除いて変わらない。
  - 規則と例外: (a) は足さない。(b) は宣言の形を一つ、印を一つ、§4.4 に「印のあるリテラルは書かないフィールドを宣言の既定値で埋める」、§15.1 に既定値のある見えないフィールドの例外を足し、E0410 に形が二つ増える。
    (c) は印が要らない代わりに、§4.4 の「全てのフィールドを書く」が宣言によって変わる例外になり、使う所から見えない。(d) は形を一つ足し、§15.1 に元の値の例外を足す。元の値の評価と上書きされるフィールドの破棄の規則（§5.2）を足す。

  - 別の所に既に同じ形があるか: 「書かなかった値が黙って既定値になる」は `prev~` の `init` の省略（§11.4）と `P.default()` の後の `r.x = …` にある。フィールドを足しても落ちないのは (a) の `var` の形も同じである。

- 他言語: 参考にとどめる。入力は `P117/g88/other/`。
  - rustc 1.94.1（`r1.rs`）: `m::Ring { data: …, ..Default::default() }` と `..m::Ring::new()` は、非公開のフィールド `head` のある型で E0451。(`r1b.rs`) `let mut r = m::Ring::new(); r.data = d` は通る。
  - rustc 1.94.1 の nightly の機能（`RUSTC_BOOTSTRAP=1`、`default_field_values`、`r2.rs`・`r3.rs`・`r3b.rs`・`r7.rs`）: `Item { x: 1, .. }` は宣言の既定値で埋まる。非公開のフィールドに既定値があっても外からは E0451。`..` の無い `Item { x: 1 }` は E0063。全てのフィールドを書いた `Item { x: 1, y: 2.0, .. }` は通る。
    `derive(Default)` は宣言の既定値を使い、既定値のあるフィールドの型は `Default` を要らない。[RFC 3681](https://rust-lang.github.io/rfcs/3681-default-field-values.html) は既定値を定数式に限り、見えないフィールドは現れる範囲でしか作れないとする。
  - swiftc 6.3.1（`sw/`）: 既定値のあるプロパティはメンバごとの初期化子で省ける（`Item(x: 1)`）。`private` と `fileprivate` のプロパティに既定値があっても、他のファイルでは「initializer is inaccessible due to 'private' protection level」。
