# S-693 他のモジュールの本体の経路の最後の要素が、E0200 の `pub use` の取り込む名前のとき（`use main.inner` の後の `inner.g()`、`g` は `main/inner.onsa` の `pub use util.{g}`）

- 空白: §18.1 は、E0200 の `pub use` の取り込む名前を失敗した名前とし、他のモジュールがそれを取り込む `use main.{g}` の名前も黙らせ、経路の途中に通す `use main.inner.{g}` は E0302 とする（S-596）。他のモジュールの本体の経路の最後の要素がその名前のとき（`use main.inner` の後の `inner.g()`）を書いていない。
  読みは (1) 他のモジュールの経路は項目と子モジュールの定義だけを引くので E0302（S-611）、(2) `use main.{g}` の最後の要素と同じく失敗した名前として黙る、に割れる。
  W4-03 U3b2 の実装（69 回目）は (1)（事例は無い）。急ぎ: 後の段（本体の経路の歩き手は W4-04）。
- 決定: 決定（2026-10-27、利用者。74 回目、第 64 組。割れた項目として (a) と (b) の比べを示して）: (a)。
  他のモジュールの本体の経路は、最後の要素も途中も、そのモジュールの項目と子モジュールの定義だけを引き（§15.1、S-611）、E0200 の `pub use` の取り込む名前は E0302 である（`use main` の後の `main.g()`、`use main.inner` の後の `inner.g()`・`inner.Mode.A`）。
  S-596 の黙る扱いは `use` の最後の要素（`use main.{g}`）だけのまま広げない。
  理由: 仕様の文と S-611 は本体の経路を既に一般則の側に置いていて、例外を広げない。この版では使う所は必ず直す誤りで、一回の検査で全てを示す。実装は 0 行（`names/lookup.rs` の `SPEC-GAP(S-693)` の印を消す。呼び出しの形の E0401 は R-254 の直しで E0302 になる）。(b)（最後の要素は黙り、途中は E0302。`use` と本体で揃い、約 +6 行）は採らない。第 2 期に再公開を入れるときに決め直す。
  仕様 §18.1 に一文。実装は W4-04（U4、R-254 と同じ所）。
- 経緯: 69 回目（2026-10-25）、W4-03 U3b2/i（onsa-impl）の空白の報告 NEW-2 から登録した。関係: S-596、S-611、S-462。
  74 回目（2026-10-26〜27）、第 64 組（下書き `S-693.draft.md`）: 下書きは (b)、助言の担当の二段は (a) で割れ、親が比べを示し、利用者が (a) を選んだ。
