# S-362

- 空白: `for` の見出しの `move` と範囲（`for i in move 0..<n`、`for i in move lo + 1..<hi - 1`）。§7 は「範囲には消費する値が無いので `move` は付けない（`for i in move 0..<n` は E0703）」とし、計画 §5 の E0703 も `for i in move 0..n` を含む。
  一方 §5.2 は「`move` と `inout` の被演算子は後置式で、二項演算子の被演算子にはならない（`move y + 1` は E0002）」とする。
  読みは (1) 見出しの `move` は範囲の全体に付く印で、`move lo + 1..<hi - 1` も E0703（`tests/spec/negative/range_move.onsa` の期待値。R-42 の前に書かれた）、(2) 印は範囲の全体を覆うが始まりの端は後置式で、`move lo + 1..<hi - 1` は `+` の E0002（§5.2）、に割れる。
  W3-20 は (2)（木は dev と同じ `For { moved: true, iter: Range }`、`SPEC-GAP(S-362)`。`range_move.onsa` の 28 行目は `+` の E0002、他は型の段の E0401）。W3-20/i で見つけた（2026-10-09）
- 提案: W4-09 の前に決める
- 時期: W4
- 決定: 決定（2026-10-23、利用者が了承。57 回目、第 42 組）: (a)。`for` の見出しの `move` は反復元の全体に付く印で、構文は `in` の後を見出しの式として先に読む。範囲なら、始まりの端の形によらず E0703（`for i in move lo + 1..<hi - 1` も同じ。候補は S-103 の `move` を消す形）。
  範囲でない二項式（`for s in move a + b`）は今の §5.2 の E0002。`let i = move lo + 1` は §5.2（R-42）の E0002 のまま。
  理由（利用者）: 構文解析で範囲の始まりが `lo + 1` と `0` で挙動が違うのは不自然で、今の解析器の作りがおかしい。`tests/spec/negative/range_move.onsa` の 28 行目の E0703 の期待値はそのまま。仕様 §7
