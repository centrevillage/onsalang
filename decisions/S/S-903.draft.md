# S-903 struct のパターンで残りのフィールドを無視する印（S-697 から分けた）

- 決定済みで戻さないもの: 見える残りがある `..` の E0020 と `_` を並べる候補（S-366）。フィールド名の省略形が無いこと（§4.4）。`Drop` を実装する型を分解できないこと（E0711）。
  第 88 組の下書きの写しは `target/notes/117/g88/draft.md`、入力は `P117/g88/probe/`（消えうる）、段 1・段 2 の答えは `target/notes/117/g88/advisor/`、親の入力は `target/notes/117/g88/parent/`。
- 論点: 残りのフィールドを無視する印を足すか。足すならどの字で、どの範囲か。見えないフィールドが残るパターンは今 E0303 で、入れ子のパターンでは読む手段が腕の束縛の後の `.x` だけである。
  - 出所:
  §7 の「全てのフィールドを書く」「残りを省く `..` は無い」は S-697 の出所のとおり。S-109 が `..` の E0020、S-366 が段と候補（残りを `_` で並べる）と、見えないフィールドが残るパターンの E0303 を決めた。
    今の note は「so that a field added later makes every pattern of the struct an error (§7)」である。一方、フィールドの読み `p.x` はフィールドを足しても落ちず、enum の `_ =>` の腕は列挙子を足しても落ちない。書き手が `_` を選んだ所は既に落ちない。

- 案: 例は `let Item { x: a, _ } = v`、`match r { Ring { data: d, _ } => d[0] }` の形である。
  - (p) 何も足さない: 不要なものは `_` で並べ、見えないフィールドのある struct は `.x` で読む。
  - (q) `_` を並びの最後に書く: 残りのフィールドを無視する。途中を省くのと順の入れ替えは許す。見えないフィールドが残ってもよい。残るフィールドの無い `_` は誤りである。`..` は今の E0020 のままである。
  - (r) `..` を受理する: S-109・S-366 の E0020 を外す。意味は (q) と同じである。
  - (s) `...` を受理する: 字はリテラルの印と同じで、意味は (q) と同じである。`..` は今の E0020 のままである。
  - (t) (q) の字で、見えないフィールドが残るときだけ書ける: 見えるフィールドは今のまま全て書く。§7 の文は見えるフィールドに残る。
  - 形ごとの出力（`Item { x: U32, y: F32, z: F32 }` から `x` だけ取る）: (p) `Item { x: a, y: _, z: _ }`。(q) `Item { x: a, _ }`。(r) `Item { x: a, .. }`。(s) `Item { x: a, ... }`。
    (t) は同じ型のモジュールの中でも見えるフィールドなので `Item { x: a, y: _, z: _ }` で、`Ring` を他のモジュールで分解するときだけ `Ring { data: d, _ }` である。
  - 書き手から見て（LLM を含む）: 最初の形はまず `..`（Rust）である。(p)・(q)・(s)・(t) は E0020 で 1 回の修復である。(r) は 0 回である。(q) は `_` が他の位置の「値を使わない」と同じ字で読める。(s) はリテラルの `...` と見た目が揃うが、埋める意味と捨てる意味が同じ字になる。
    (t) は同じパターンがモジュールによって書けたり書けなかったりする。(p) は `Ring` の入れ子のパターンが書けず、腕の束縛と `.data` に書き直す。
  - 修正候補（§18.1）: (p) は今のまま止まる（S-366）。(q)・(s)・(t) の `..` の候補は、見える残りは今の `_` の並び、見えない残りは (q) なら `..` を `_` に置き換える一か所の編集で、当てると止まる。残るフィールドの無い `_` は消す候補で止まる。(r) は `..` の候補が消える。全て書いた `, ..` は (r) でも誤りにするなら今の消す候補が残る。
  - 通るプログラム: どの案も今通るプログラムを誤りにしない。変わるのは事例の期待である: (q)・(s) は `visibility_field_rest/main.onsa` の `//~ E0303` の 6 か所（`..` に見えない残りがある形）を E0020 と候補に改める案と、E0303 のまま残す案がある。
    (r) は `e0020_patterns_rest*.onsa` の 3 ファイル（`..` の字が約 36 か所）、`pkg_patterns_rest/` と `struct_pattern_rest` の行を消すか書き直す。(t) は E0020 の候補の分岐が増える。`spec/` の ```onsa ブロックは §7 の本文を除いて変わらない。
  - 規則と例外: (p) は足さない。(q) は §7 に印を一つ足し、§15.1 の「struct のパターンで分解できない」に例外を足す。「`_` は最後」「残りが無ければ誤り」の 2 文が要る。(r) は `..` の行を消す代わりに同じ 2 文が要り、S-109・S-366 の決定を改める。
    (s) は (q) と同じ数で、字がリテラルの印に揃う。(t) は (q) に「見えないフィールドが残るときだけ」の条件を足し、見える残りのある `_` の誤りの形が一つ増える。
  - 別の所に既に同じ形があるか: 「足したものが落ちない」は `match` の `_ =>` の腕とフィールドの読みにある。`let Holder { buf: bb, n: _ } = hh` の `_` は読まない（§7）ので、省いたフィールドも同じ扱いにできる。
  - 実行の結果: どの案も、省いたフィールドは `y: _` と同じである。所有する値の分解では、取り出さなかったフィールドをその場で破棄する（§5.2、S-85）。見えないフィールドが Affine か Shared なら、破棄の `Alloc` は今の `y: _` と同じ規則で要る。

- 他言語: 参考にとどめる。
  - rustc 1.94.1（`r1b.rs`・`r2b.rs`）: `let m::Ring { data: d, .. } = …` は非公開のフィールドが残っても通る。リテラルの側は E0451 で、パターンの方が緩い。
  - swiftc 6.3.1（`sw/pt`）: `let S(x: a) = s` は誤りで、struct を分解するパターンが無い。タプルの `_` はある。
  - Zig（未確認、言語の文書）: 分解はタプル・配列・ベクトルで、struct の分解の項は見当たらなかった。OCaml（未確認、[manual の Patterns](https://ocaml.org/manual/5.3/patterns.html)）: レコードのパターンは `; _` で終えて「全てのフィールドを挙げていない」ことを示せる。省くこと自体は `; _` が無くても許す（警告 9 の扱いは未確認）。
  - Node 26（`js1.js`）: `const {x, ...rest} = a` は残りを集める形で、捨てる形とは意味が違う。
- 推奨と理由: (q)。確度: 中。
  - 見えないフィールドのある struct を入れ子のパターンで読む手段が今は無く、(p) は分解の書き直しになる。書き手が `_` を選んだ所が落ちないのは `_ =>` の腕と同じで、印の無いパターンは今の「全て書く」のまま落ちる。§7 の目的は印の無い形に残る。
  - `_` はパターンの位置で既に「値を使わない」の字で、新しい字を足さない。リテラルの「埋める」と「捨てる」は違う意味なので別の字にする（(s) は同じ字に二つの意味を持たせる）。(r) は S-109・S-366 の E0020 と事例を外す利点が修復 1 回の差だけで、§7 の「`..` は書き手の誤解」の読みを改める理由が足りない。
  - (t) はモジュールで書ける形が変わり、規則が一つ増える。代償は、`_` と `y: _` の二通りが残ることである。足したときに落ちるか、という意味の違いがある。
  - あわせて決めること:
    - `..` に見えない残りがある形は E0020 にし、候補は `..` を `_` に置き換える（S-366 の補いの「`_` で書いても E0303 になるので直し方が無い」が、この案で無くなるため）。`visibility_field_rest` の 6 か所が変わる。見える残りだけの `..` の候補は今の `_` の並びのまま。
    - `Ring { _ }` のようにフィールドを一つも書かない形: 誤りにしない（型を確かめて全て捨てる形で、`Ring { .. }` の候補の先になる）。
    - fmt は `..` と同じ扱いで、要素に数えず、後ろに `,` を置かない（`_,` は E0002）。
    - E0020 の note の文を「`_` を書かないパターンは落ちる」に改める。
