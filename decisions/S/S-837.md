# S-837 `platform` に書いた三つ組がホストかの判定と、三つ組の OS の読み方（`aarch64-apple-ios` の `staticlib` がホストの `cc` で macOS 向けの `.a` になる）

- 空白: §15.3 の 198 行は「ホストの `platform` では PATH の `cc` と `ar` を使う」「クロスの `platform` で外部のツールチェーンを要する `kind`（`staticlib`、プラグインなど）は、この版ではそのターゲットのビルドで E0200」と書き、178 行は「トリプルの OS の欄が `none` のもの（`thumbv7em-none-eabihf`）を OS の無いプラットフォーム」とするが、書いた三つ組がいつホストか、OS をどの欄から読むかを書かない。
  今の実装（`build.rs` の `platform()` と `Platform::is_host`、M4 から）は、`"host"` を機械の三つ組に置き換え、アーキテクチャの語と、残り全体の部分文字列から読んだ OS（`darwin` か `apple` を含めば macOS、`none` を含めば OS 無し）が機械と同じならホストとする。
  そのため `kind = "staticlib"`・`platform = "aarch64-apple-ios"` は、この機械（aarch64 の macOS）で終了コード 0 になり、ホストの `cc` で macOS 向けの `libonsa_p.a` を作る（iOS 向けのフラグは無い。98 回目に親が U3b の前後の `P98/bin/onsa-w402u3a2`・`onsa-w402u3b` で確かめた）。`aarch64-nonexistent-apple-darwin` は `nonexistent` の中の `none` で OS 無しと読まれる。
  逆に `arm64-apple-darwin`（同じ機械の別名）は U3b からクロスの E0200 になる（前は C のソースだけで終了コード 0）。
  `is_host` を使うのは、`staticlib` をホストでコンパイルする所、U3b のクロスの E0200（S-161）、器の C の検査とホストの手順の四か所。
  読みは (1) `"host"` と、機械の三つ組に字で一致する三つ組だけがホスト (2) アーキテクチャと OS が同じならホスト（今の形。OS を読む規則も決める） (3) 別名（`arm64` と `aarch64` など）も同じ機械とする、に割れる。(1) は今終了コード 0 の `aarch64-apple-ios` の `staticlib` を E0200 にする。
