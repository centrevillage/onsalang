# S-1094 `match~` の、取られた腕より後ろの腕のガードを評価するか

- 空白: §11.5 は「`if~ c { a } else { b }` と `match~ x { ... }` は、全ての枝を評価してから一つを選ぶ」「腕は `match` と同じく、パターンとガードで選ぶ」とする。ガードが panic しうるとき（`x if 100 / d > 1 => …`）に、取られた腕より後ろの腕のガードを評価するかが決まらない。
  読み: (1) 選ぶ側は `match` と同じで、最初に合った腕で止める（後ろのガードは評価しない）。(2) 全ての腕のガードも評価する。panic の有無が変わる。
  今は `match~` が E0200（W7-06）で試せない（`target/notes/158/w701/memo/probe/q_matchtilde.onsa`）。
  仮の扱い: W7-01 の参照評価器は (1) で書き、`SPEC-GAP(S-1094)` を付ける。期待値は書かない。
- 決定: 決定（2026-11-20、利用者。170 回目）: (1)。選ぶ側（`match~` の対象とパターンとガード、`if~` の連鎖の条件）は普通の `match` / `if` と同じく上から評価し、最初に合った腕か真になった条件で止める（後ろのガードと条件は評価しない）。`~` が全て評価するのは枝と腕の本体。評価の順は、選ぶ側を先に、次に全ての枝と腕の本体を書いた順。
  `if~` の `else if` の連鎖は、上から真になった所で止める選びと読む（利用者:「直感に近い」。advisor の段 1 と親は、後ろの条件を else の枝の中と読み常に評価する案を推した）。`else { if~ … }` と入れ子に書いた形とは panic の有無が違いうるが、`if` / `if~` を開き直しているので単位が違うのは直感に反しない（利用者）。
  そのため `match~` のガードと `if~` の連鎖の二つ目からの条件は条件の位置（§11.3）に入る。そこに書いた状態を持つものの扱いは S-394。W7-06 で参照評価器の `if~` の順（今は条件と枝の交互）と `select_all` の印を改める。§11.3・§11.5 に入れた。
- 経緯: 158 回目、2026-11-16、W7-01 U1 の設計メモ（onsa-test）が空白として挙げ、親が登録した。
- 補い（2026-11-18、親）: W7-18 U2 の参照評価器は「選ぶ（パターンとガード、上から）→ 全ての腕の本体を書いた順に評価」で書いた（`SPEC-GAP(S-1094)` は `branch.rs` の `select_all`）。選びのガードの panic と、取られない腕の本体の panic のどちらが先かも、この S の範囲で決める（評価の順は仕様に無い）。
