# S-885 `as` で書ける組の変換の関連関数を、呼ばずに値として取る形（`let g: fn(F32) -> F64 = F64.round_from`）

- 空白: §3.3（S-231 の反映の案）は `as` で書ける組について「変換の関連関数は無い（E0413）」と書き、決定は「呼び出しは E0413」と書く。`let g: fn(F32) -> F64 = F64.round_from` は呼び出しでなく、組込みの型の関連関数を値として取る形（§6.1、R-295）で、`S` は期待の型で `F32` に決まる。読み: (1) 値の形も E0413（候補なし）。(2) 呼び出しだけを E0413 にし、値の形は通す。
  今の変換メソッドを値として取る形は E0413（`x.round_f64` は「no field」）。関連関数の値の実行は今 E0200。W5-14 の S1 の判定に当たる（同じ見積もりの NEW-3）
- 決定: 決定（2026-11-04、利用者。112 回目、第 83 組。親の読みと段 1 が一致、段 2 は省いた。利用者は表を見て (c1) を選んだ）: (c1)。`as` で書ける組の変換の関連関数を値として取る形も E0413（候補なし、note で無名関数の形）。値の形は既に宣言の要求を検査しており（§4.5）、判定を同じ所に足す。`let g: fn(F32) -> F64 = F64.round_from`、`(F64.round_from).(y)`、`array.from_fn(F64.round_from)`（`U32` → `F64`）は E0413。`as` で書けない組の `array.from_fn(F32.round_from)` は通る。仕様 §3.3（反映は W5-14 の S2）
- 経緯: 112 回目（2026-11-04）、W5-14 の S-231 の置き換えの見積もり（読むだけの実装の担当）が NEW として挙げ、親が固定のバイナリと利用者の `impl` の近似で再現した。要約と段 1 は `target/notes/112/g83/`。関係: S-231、S-875、S-880、S-236
- 補い（2026-11-04、親。112 回目）: 値の形の変換元は期待の型から決まるので、期待の型と関数の型が合わない `let g: fn(F32) -> Bool = F64.round_from` は呼び出しと違って E0401 が先である（S1・S2 の壊す側が挙げた）。誤りのコードの順だけの違いで通るプログラムは変わらず、一度の単一化で決まる実装のままにして §3.3 に文を足した
