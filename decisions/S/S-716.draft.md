# S-716 使われない束縛の名前が §2.3 の形に反するとき（`let _x = 1` を読まない）、E0320（候補 `x`）と E0309（候補 `_`）のどちらを報告するか

- 決定済みで戻さないもの: `_x` を束縛と読むことと E0320 の候補 `x`（S-648）、`var` の E0309 は候補なし（S-714）、重なる名前の候補なし（S-652）、引数は E0309 の対象外（§5.1）、flow の本体の E0309 の段（S-129）。
  第 66 組の下書きの「S-716 の仕組みの出所」と「S-716 の形の表」の節（写しは `target/notes/76/g66/draft.md`）。
- 論点: §2.3「宣言する名前（`[…]` の並びとパターンの束縛）は、読んだ種類の E0320 にする（…`let _x = 1` は束縛で修正候補は `x`）」と、§5.1「使われない束縛は E0309。…修正候補は名前を `_` に変える形である」。
  読まない `let _x = 1` は両方に当たる。どちらも名前の段で、同じ単位にある。E0320 の位置は宣言の名前（§2.3）だが、E0309 の位置は仕様に書かれていない。
  同じ位置なら §18.1 の並べ方（コードの順）で E0309 になり、違う位置なら先の位置のものになる。仕様の字だけでは決まらない。
  当たるのは頭の `_` だけでなく、§2.3 に反する全ての束縛の名前（`fooBar`、`a__b`）である。
- 今の実装: E0309 は無い（W4-04 の U7b）。表のとおり、どの形も E0320 だけである。
  W4-04 の設計メモの 2.10 は、E0309 を束縛の最初の位置（名前）に出すとし、2.11 は E0320 を今のとおり `onsa_syntax::naming` が名前の段で出すとする。driver は同じ段の中で並べ方の最初を選ぶ（`onsa_driver/src/reduce.rs` の `per_unit`）ので、何も足さなければ E0309 になる。
- 案: 
  - (a) E0320 を先にする。§5.1 に「名前が §2.3 に反する束縛は E0309 に数えない」と書く。`let _x = 1` は E0320 → `let x = 1` → E0309 → `let _ = 1` の二回。
  - (b) E0309 を先にする。§5.1 に E0309 の位置は束縛の名前（選択のパターン `Some(x) | Ok(x)` では最初の位置）と書き、同じ位置の E0320 より §18.1 の並べ方で先になる。`let _x = 1` は E0309 → `let _ = 1` の一回。
  - (c) E0320 を報告し、使われない束縛の E0320 は候補を `_` にする。一回で `let _ = 1` に着く。
  - 形ごとの違い: 表の読まない形で、(a) は二回、(b)・(c) は一回（`var` はどの案も最後が候補なし。重なる形は (a) の一回目が候補なしで、書き手が名前を選んだ後に E0309）。読む `_x`・引数・無名関数の引数・flow の本体は、どの案も E0320 だけである。
    一つの本体に読まない名前が N 個あると、単位ごとに一つずつ報告するので、(a) は 2N 回、(b)・(c) は N 回の検査になる。
  - 書き手から見て: 頭の `_` を「使わない」の印として書く書き手の意図は `_` で、(b)・(c) の候補はそれに合う。(a) の一回目の候補 `x` は §2.3 に合うが、意図とは違う名前を一度経る。
    どの案も候補は一つで、当て続けると `let _ = 1` で止まる（`var` は `no-candidate`）。
  - fn と flow: flow の本体の E0309 は後の段なので、どの案でも flow の本体では E0320 が先で二回になる。(b)・(c) では fn の本体が一回、flow の本体が二回と違う。(a) は両方二回。
  - 規則の数: (a) は E0309 の対象に例外が一つ。(b) は E0309 の位置の一文で、例外は無い。(c) は E0320 の候補に例外が一つで、名前の形の規則の候補が使われ方で変わる。
  - 実装の量（設計メモの 2.10・2.11 の置き場所）: (a) は `names/body/scope.rs` の E0309 の探しで名前の形を確かめる約 3〜5 行（`naming` の形の判定を公開する）。(b) は 0 行（E0309 の位置を確かめる事例を足すだけ）。
    (c) は `names/rename.rs` が E0309 の結果を読んで候補を替える約 10〜15 行で、名前の段の二つの判断が互いを読む。どの案も第 2 期と JS / WASM に手当ては続かない。
- 他言語: 
  - rustc 1.94.1（`probe/rs/a.rs`）: 読まない `let _x = 1;` は警告なし。読まない `let Foo = 1;` は `unused_variables`（help は `_Foo`）と `non_snake_case`（help は `foo`）を同じ位置に両方出す。`let _Bar = 1;` は `non_snake_case` だけで、help は頭の `_` を残す `_bar`。
    rustc の文書は `unused_variables` を「黙らせるには `_x` のように頭に `_` を付ける」とする（[rustc の lint の一覧の unused-variables](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html#unused-variables)）。どちらも警告なので、一度に両方を出せる。
  - Swift 6.3.1（`probe/rs/s.swift`）: 読まない `let _x = 1` も「was never used; consider replacing with assignment to '_'」の警告になる。頭の `_` に意味を持たせない。名前の形の検査は無い。
  - Python と TypeScript の linter の `_` の扱いは未確認。
- 推奨と理由: (b)。確度: 中。
