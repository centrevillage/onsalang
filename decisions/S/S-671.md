# S-671 §16.1 の `std.audio.device` の `run` の注記「実装はターゲットの bind が与える」が、std の `target` 宣言を `bind` で差し替えられないこと（S-69 (4)）と食い違う

- 空白: §16.1 の例の注記「std.audio.device の登録関数の形（実装はターゲットの bind が与える）」は、§15.2 の「std の `target` 宣言は、処理系が与える。`bind` は書かず、std のモジュールを `bind` の左辺に書くこともできない」（S-69 (4)）と食い違う。
  S-69 (4) の理由は §13.4 の精度の約束で、オーディオの入出力の `run` には当たらない。`std.audio.device` の `run` を誰が与えるか（処理系の変換先ごとのランタイムか、利用者の `bind` か）と、§16.1 の文を決める。今の std に `audio` のモジュールは無く、`run` を実装する作業も `tasks/` に無い。
- 決定:
- 経緯: 65 回目（2026-10-25）、第 55 組（S-670）の下書き（onsa-gap）が新しい S の候補として挙げ、独立のレビューの段 2 も別の S とした。関係: S-69、S-609、§15.3 の `bind` の例（利用者のモジュール `audio.device`）。
