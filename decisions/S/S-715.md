# S-715 型の段で無いと分かった `process_inplace` を取り込む `use` の名前を、本体の注釈（`let x: process_inplace = 1`）に書いたとき、S-708 の「有無によらず E0308」か、§11.6・§18.1 の「以後の使う所は失敗した名前として黙る」か

- 空白: §11.6 の `process_inplace` の項は、無い flow から取り込む `use` を「型の段の E0302 になる（以後の本体の使う所には診断を出さない、§18.1）」とし、次の文で「`use` で取り込んだ `process_inplace` を型の位置（署名と本体の注釈）に書いても、…有無によらず型でない名前の誤りである」とする（S-708）。
  §18.1 は「型の段で無いと分かれば、その `use` に E0302 を出し、以後その名前を失敗した名前として扱う」とする。署名は型の段の前に読むので E0308 が先に出るが、本体の注釈は型の段で無いと分かった後に読むので、二つの文の両方に当たる。
  今の実装（dev `65a1073` のバイナリ、コードは `381bb7e` と同じ）: `use dsp.synth.one.{process_inplace}`（`one` は持たない）の後の `let x: process_inplace = 1` は黙る（`use` の E0302 だけ）。同じ所の `let x: reset = 1` は E0302「`reset` is not a type」（S-103 の E0308 は W4-04）。
  再現は 75 回目の scratchpad の `w404/parent/f1/`（`tests/spec/packages/use_flow_absent_type_position_kinds` の `dsp` を写した）。事例は署名・返り値・フィールド・別名だけで、本体の注釈の事例は無い。
- 決定: 決定（2026-10-27、利用者が ID を挙げて了承。75 回目、第 65 組の A11、確認だけ）: (p)。本体の注釈も S-708 どおり E0308。失敗した名前の黙りは値の位置の使う所に限り、種類が §11.6 の一覧で決まる型の位置の E0308 は黙らない。
  仕様は §18.1（「型の位置の E0308 は、§11.6 の項目の種類で出す」）と §11.6（「以後の値の位置の使う所には」、型の位置の並びを S-708 に揃える。文書の点検の F7）。実装は W4-04（U3a で本体の型の位置を名前の段で解決した後の U8）。
- 経緯: 75 回目（2026-10-27）、文書の点検（`83cb82b..381bb7e`、onsa-docs）の F1 が見つけ、親が再現した。同じ点検の F7（§11.6 の「署名と本体の注釈」が S-708 の位置の列挙より狭い）も、この決定と一緒に直す。
  関係: S-708、S-694、S-462、S-713。
- 補い（2026-10-27、親）: A5（2026-10-27、75 回目、利用者が了承）: 期限は W4-04 の U3a（型付けの切り替え。本体の型の位置も名前の段で解決する、B1）の前。
