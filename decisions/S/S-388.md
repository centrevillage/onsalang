# S-388

- 空白: 隣り合う文字列リテラル（`f("a"` 改行 `"b")`、`["a"` 改行 `"b"]`、同じ行の `f("a" "b")`）。今は E0002 で候補なし。Python 3.14.5 と C（Apple clang 21）は改行を挟んでも一つのリテラルにつなぎ、Ruby 3.4.9 は同じ行だけつなぐ（改行を挟むと `,` の抜けの誤り）。
  S-384 の (a) をそのまま当てると `,` の候補だけが出て、配列では長い文字列を行で折る書き方を黙って要素二つにする候補になる。`,` の挿入と一つのリテラルにまとめる形の二つを並べるか。第 18 組の下書きで見つけ、Fable が急ぎを上げた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて Fable の案を了承。第 18 組の Fable のレビューの補足 5）: 隣り合う文字列リテラル（改行を挟む `f("a"` 改行 `"b")` も、同じ行の `f("a" "b")` も）は、一つのリテラルにつなぐ読み（Python、C）と `,` の抜けの読みに割れるので、E0002 で、修正候補は `,` の挿入と、一つのリテラルにまとめる形の二つ（この順。S-89 の改行の後の `(` と同じ形）。
  S-384 の `,` の挿入だけの候補にしない（配列で長い文字列を折る書き方を黙って要素二つにしない）。仕様 §2.5。実装は W3-06
