# S-967 定数式の中で、値の項目（定数・関数）の後に名前が続く形（`P.N.x`、`F32.PI.x`、struct の定数の `K.x`、`g.y`）のコード: E0308 か E0417 か

- 空白: 配列の長さと const 引数の定数式（§4.5）に、値の項目の後に名前が続く形を書いたときのコード。
  §15.1 は「名前空間でない名前の後に `.` を書く」を E0308 とし、名前空間でない名前を「名前空間でも値でもない名前」と定める。一方「値の後の `.` はそのフィールドとメソッドで、型の段が読む（関数の名前の `g.y` は E0413）」「その形にコードを定める位置に固有の規則があれば、そのコードが先」（例に配列の長さの E0417）。§4.5 は定数式の文法にフィールドアクセスを含めず、「定数式でないもの…位置によらず E0417」とする。
  読みは (1) E0308（W4-04 U8b の事例 `tests/spec/types/kind_length_names_after_members.onsa` の読み。「`PI` is a constant, which has no members」） (2) E0417（定数は値なので後の `.` はフィールドで、定数式の文法の外。位置に固有の規則が先）。値の位置（`let a = P.N.x`）は型の段の E0413 で、この問いの外。
  今は署名と本体の長さが E0308（`P.N.x`、`F32.PI.x`、`K.x`、`g(K.x)`、`g.y`）、flow の `delay~(x, g(K.x))`・`par~ … 0..<g(K.x)`・`K.x.()` が E0417。W5-16 U1a は位置によらず同じにする（メモの案では E0308 にそろえる）。どの読みでも通るプログラムは変わらない。
  W5-16 U1a のテストの担当が見つけた（2026-11-09、129 回目。入力は `target/notes/129/w516/` と事例 `tests/spec/types/length_names_after_constant_places.onsa`・`tests/spec/flow/length_names_after_constant_flow_calls.onsa`）。U1b（定数式の文法の外の形、S-966）の前に決める。
- 決定: 決定（2026-11-09、利用者。129 回目、S-966・S-967・S-968 の共通の規則。中立の要約（`target/notes/129/s966/summary.md`）と onsa-advisor の段 1 が親の読みと一致し、段 2 は省いた。利用者が ID を挙げて了承）: (2) E0417。値の後の `.` はフィールドで型の段が読み（§15.1）、フィールドアクセスは定数式の文法の外なので、位置に固有の規則の E0417 が先（§15.1 の「値の後の `.` はそのフィールドとメソッドで、型の段が読む」、§4.5）。`P.N.x`・`K.x`・`(K).x`・`K.x()`・`g.y`・const パラメータの後の `M.x`・`T.BITS.x`・`Self.N.x` が同じ E0417 にそろう（今は括弧の有無と呼ぶかで E0308 と E0417 に割れる）。型を通したメソッド（`P.get.zz()`、`Str.len.zz()`、S-205）は値でないので E0308 のまま。共通の規則: 定数式の名前は、名前の段が普通の式と同じ歩き手で読む（名前の誤り E0302・E0308 は位置によらず先、§18.1）。型の段の読み手は「葉は型で、節は文法で」判定する。葉（リテラルと名前の鎖）は、定数でない値（ローカル、関数、列挙子、値のフィールド）が E0417、定数式だが型が期待型でないもの（期待型でない定数、整数でないリテラル `1.5`・`true`・`"s"`）が E0401。節（子を持つ形）は、`+ - * / %`・前置 `-`・括弧の外の形（比較・論理・ビットの演算子、`as`・`!`・`?`、添字、呼び出し、値のフィールド、タプル・配列・struct リテラル、ブロック・`if`・`match`・無名関数、`unsafe`）を、子の型と中身を見ずに位置によらず E0417。節を子に依らせないのは、`(1, 2)` を型で E0401 にすると `(g(1), 2)` の中の呼び出しの E0417 が先になり、同じ形でもコードが変わるため。 仕様 §4.5 に書いた（§15.1 は変えない）。実装は W5-16 U1b で、U1a の名前の段の `after_value` を消し、読み手が鎖の記録が値で終わる形を E0417 にする（`const_path_names` の経路の形も）。事例の `//~ E0308` の 56 行（`length_names_after_constant_places.onsa` の 45 か所、`kind_length_names_after_members.onsa` の 5 か所、`length_names_after_constant_flow_calls.onsa` の 9 か所、`tp_const_expression_e0417.onsa` と `length_names_module_places/main.onsa` の 1 か所ずつ）を E0417 に書き直す。
- 経緯: 129 回目（2026-11-09）、W5-16 U1a のテストの担当が見つけた。S-966 と同じ流れで決めた。
