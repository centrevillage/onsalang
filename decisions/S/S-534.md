# S-534 `onsa diff --ast` の比べ方の細部

- 空白: `onsa diff --ast` の比べ方の細部。(a) 普通のコメントと `//!`（モジュールの doc）の違いを報告するか（仕様 §18.2 の表は「構造的な差分。fmt の書き換えだけの違いは差分にしない」、`spec/tools.md` §3.5 は書き込む前の確かめと「同じ比較を使う」とし、その比較はコメントのテキストの並びも見る。今は報告しない）。
  (b) fmt が残す同じ群の括弧（`(a + b) + c` と `a + b + c`。外しても木は同じ）だけの違いを報告するか（今は報告する）。(c) コメントの違いの示し方（§3.5 の「最初に違った項目」にコメントの項目が無い。今の fmt の 101 は `comment N of the file differs or is missing` と位置）。
  親が W3-12 の票を書くときに見つけ、W3-11/b（U5）の空白の報告 2 と W3-12/t（U2）の空白を合わせた（2026-10-15）
- 提案: 決定（2026-10-15、利用者が (a3)・(b1)・(c1) を選んだ。(a) は下書きと Fable の (a1') と割れた）: (a3) `diff --ast` は同じ正規化を施した構造だけを比べ、doc コメント（`///`・`//!`）も普通のコメントも項目の順も報告しない。
  あわせて AST は doc を持たない（D-02 の改定。どの宣言に付く doc かは CST の上で決めて引く）。理由: `diff --ast` が doc を報告する独立の要件は無く（S-56 の「同じ比較」の帰結だった）、fmt の確かめは CST の全てのコメントを比べるので、AST の doc は要らない。
  (b1) 同じ群の括弧の違い（`(a + b) + c` と `a + b + c`）は報告する（今のまま。括弧の節を除いて比べる形は、除き方の抜けが例外の発生源になりうる）。(c1) fmt の 101 の示し方は今のまま。fmt の書き込む前の確かめは、書き換えを施した AST に加えて、項目の順、doc の付く宣言、全てのコメントのテキストの並びを比べる。
  S-56 と `spec/tools.md` §3.5 の「同じ比較」は「同じ正規化」に改めた。仕様 §18.2 の表、`spec/tools.md` §3.5。実装は W3-12 の U1
