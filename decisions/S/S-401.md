# S-401

- 空白: 文の並びの同じ行の並置（`let c = a b`、`let y = neg x`、`let a = 1 let b = 2`、括弧の中のブロックの `two({ a b }, 1)`）。今は E0002「expected newline or `}`」で候補なし。読みは関数適用（Haskell、Ruby の `neg x`）と、改行を書き落とした二つの文に割れる。
  次のトークンが文しか始められない形（`let`、`var`、`return`）は、`;` の行（候補は改行）と同じく改行の挿入が唯一の直し方。候補を出すか。第 19 組の下書きで見つけた（2026-10-10）
- 提案: 後の段（W3-06 の頃か後）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R2、X、Y）文と項目の並びで、終わりの後に改行も `}` も無く、同じ行の次のトークンが文か項目しか始められないとき（`let`・`var`・`return`・`break`・`continue`・`assert`・`while`・`for`、ブロックの中では `let` の属性の `@`（§12.4。`@` はブロックの中では `let` の属性しか始めない、X）、トップレベルでは属性の `@`・`#[` を含む項目の始まり（Y））は、今の E0002 に、次のトークンの前で行を改める候補を付ける（括弧の中のブロックも同じ）。次が式も始められるとき（`a b`、`neg x`、`if`、`match`）は候補なし。行は立てない。
