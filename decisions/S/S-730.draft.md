# S-730 二つ以上の型別名の循環（`type C = D`、`type D = C`）の E0311 を、循環ごとに一つ報告するか、循環の中の別名ごとに報告するか

- 決定済みで戻さないもの: コードは E0311（R-182）、展開を別名ごとに一度だけ求めること（R-303）、循環の外から使う別名と項目は誤りの型として黙ること（§18.1、§4.4 の E0422 と同じ扱い）、自分を指す別名は一つ。
  第 68 組の下書きの「S-730 の仕組みの出所」と「S-730 の形の表」の節（写しは `target/notes/78/g68/draft.md`）。
- 論点: §4.4「型別名の循環 `type A = B`、`type B = A` も同じ（E0311）」は、二つ以上の別名の循環で、E0311 を循環ごとに一つにするか、循環の上の別名（それぞれ診断の単位）ごとに出すかを書いていない。一つにするなら、どの宣言に付けるかも決まっていない。
- 今の実装: 表のとおり。別名の全体が誤りの型になる形（`type C = D`、`type D = C`）は別名ごとに出て、型の中を通る形（`type A = (I32, B)`）は最初の別名に一つで、同じ循環でも書き方で数が変わる。修正候補は無い（`--fix-loop` は `no-candidate`）。
- 案: 
  - (1) 循環ごとに一つ。循環は別名の参照の強連結成分（自分を指す一つの別名を含む）とし、位置を一つの別名の宣言に決め、循環の他の別名を note で示す。どれに付けるかは次の二つ。
    (p1) 診断の並べ方で最初の別名（同じモジュールならソースの順で最初）。(p2) ソースの順で最後の別名（E0304 の「後の宣言」に揃える）。
  - (2) 循環の上の別名ごとに一つ（各単位に誤りがある）。強連結成分の全ての別名に出る（`type C = (D, E)` の三つの別名に三つ）。
  - 形ごとの出力: 二つの循環は (1) が一つ（(p1) は `C`、(p2) は `D`）で note が `D`（`C`）、(2) が二つ。三つの循環は (1) が一つ、(2) が三つ。型の中を通る形も同じ数になる。自分を指す別名と、外から使う別名はどの案も同じである。
  - 書き手から見て: 循環はどこか一つの別名を直せば消える。(2) は N 個の誤りを並べるので、書き手（とくに全ての診断を一つずつ直そうとする LLM）が全ての別名の右辺を書き換え、意図した型を崩しうる。
    (1) は一つの誤りで、note が循環の別名を並べるので、書き手は一か所を選んで直す。どちらも正しく一か所を直せば、検査は一回で済む。
  - 修正候補: どの案も候補は無い（どこで切るかは書き手しか知らない）。当て続けても `no-candidate` で止まる。
  - 通るプログラム: どの案も変わらない。変わるのは、誤りの数と位置と note だけである。
  - 規則と例外: (1) は §4.4 に「循環ごとに一つで、位置と note」の一文を足す。循環の他の別名の単位は、誤りがあっても診断が無い（E0304 の報告しなかった側と同じ形）。(2) は §18.1 の単位の規則のままで、文を足さない（足すなら「循環の上の各別名に」の一句）。
  - 実装の量（W4-05。R-182 のコードと R-303 の直しと同じ所）: どの案も、別名の参照の循環を別名ごとに一度だけ求める仕組み（強連結成分か、三つの状態を持つ深さ優先の探索）が要り、これは R-303 の直しそのものである。
    (1) はその上で成分ごとに位置を一つ選んで note を並べる（約 +5〜10 行）。(2) は成分の全ての別名に出す（約 +3 行）。差は小さい。`names/cycles.rs` の強連結成分の関数（モジュールの循環用）を使えるかは未確認。
    struct と enum の E0311（R-02、同じ W4-05）でも同じ選びが要り、同じ関数で決められる。後の段への手当ては無い（別名の展開は署名の段で閉じ、使う側は誤りの型）。
  - モジュールをまたぐ循環: 別名の参照は `use` を通るので、モジュールをまたぐ循環はモジュールの循環（E0310）も作る。(p1) は位置が最初のファイルになり、絞った `check b.onsa` には出ない（S-645 と同じ形。E0310 も最初のファイルに付く）。
- 他言語: 
  - rustc 1.94.1（`probe/other/s730.rs`・`s730b.rs`）: 別名の循環は循環ごとに一つの E0391「cycle detected when expanding type alias `C`」で、位置はソースの順で最初の別名の右辺、他の別名は note。struct の循環も一つの E0072「recursive types `A` and `B` have infinite size」。
  - swiftc 6.3.1（`probe/other/s.swift`）: 循環ごとに一つの「type alias 'C' references itself」で、位置は最初の別名、他は note。
  - Go と TypeScript は未確認。
- 推奨と理由: (1)・(p1)。確度: 中。
  - 循環は一つの直しで消える一つの誤りで、(2) の N 個の報告は、書き手に N か所の直しを促し、意図した型を崩す危険がある。E0304 も、二つの宣言にまたがる誤りを一つに付けて相手を note で示している。
  - 位置は、どの別名を先に下ろすかによらず決まる形にする。(p1) は診断の並べ方と、今のモジュールの循環の E0310 の付け方に揃う。(p2) の「後の宣言」は、E0304 では後から重ねた側という意味があるが、循環ではどの別名も同じだけ責任があり、その理由が当たらない。
  - 実装は R-303 の直しの上の約 +5〜10 行で、(2) との差は小さい。今の実装は書き方で数が変わるので、どの案でも W4-05 で直す。
  - あわせて決めること: struct と enum の値の循環の E0311（R-02、W4-05）も同じ規則（成分ごとに一つ、診断の並べ方で最初の宣言、他は note）にする。note の並びは循環を辿る順にする（文面の細部で、約束にしない）。
  - 別の S にしてよい論点: 定数の循環の E0312（§6.6。今は検査されない）と、モジュールの循環の E0310（今は成分ごとに一つで、仕様は数と位置を書いていない）の数と位置。宣言をまたぐ循環を一つの族にするか（下の新しい S の候補）。
