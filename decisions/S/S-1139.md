# S-1139 `let` の値そのものがノードで、その値を速い段で読む欄も要る形（`let c = lp~(x).down~(4)` を `sample` で読む）の、ノードの欄と `let` 自身の欄の名前（§12.4 の「その `let` 自身のフィールド」が二つになる）

- 空白: §12.4 は `sample` から読まれる遅い `let` の値を「その `let` 自身のフィールド」に置き、§11.6 は値そのものがノードの `let` のノードを `let` の名前で呼ぶ。`let c = lp~(x).down~(4)` を `sample` で読むと、ノード `c` の欄と `let` `c` の値の欄が同じ名前になりうる。今は `.down~` が E0812 で試せない。族の S-1138 の規則と W7-09 の設計メモで決める。
- 決定: 決定（2026-11-20、利用者。170 回目、第 115 組）: (a)。`let` のクロックが `sample / N` かイベントのクロックなら、値そのものがノードでも `<let>.<種類>_<番号>`（`c.lp_0`）と呼び、`let` の値の欄は `c`（S-1138 の「`let` のフィールドは利用者の名前のまま」）。判定は W7-09 の設計メモの `frame != 0` でなく `let` のクロック（修飾子の無い変換の flow、遅い刻みの遅延、イベントの遅延、`par~` の値も含む。段 1 の L10・L11。`Namer::new` に `let` のクロックを渡す口が要る、+10〜20）。§11.6 と §12.4 の `@mem(bulk)` の名前の文に入れた。S-1175 (1′) と同じ型の規則で、名前は読まれ方で変わらない。下書き・段 1・親が一致。
- 経緯: 165 回目、2026-11-18、第 110 組の段 1（onsa-advisor）が新しい S の候補として挙げ、W7-03 U0 の設計メモ（onsa-impl）も同じ形を範囲の外に挙げた。親が登録した。
