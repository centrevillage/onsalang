# S-747 同じ境界の重なりと矛盾する組（`T: Copy + Copy`、`T: ?Dup + ?Dup`、`T: Dup + ?Dup`、`T: Copy + ?Dup`）の診断（今はどれも黙って通る）

- 決定済みで戻さないもの: `?` を `Dup` 以外に付けた形（S-711 の E0416）、`Copy`・`Dup` が種の制約であること（S-140）、境界の名前の種類の誤り（S-713 (c)、S-719、S-689 の未知の境界）、`? Dup` の空白（S-511、未決の別の S）、`?Sized`（S-746、族「一覧に無い他言語の形」S-749）。
  第 72 組の下書きの「S-747 の仕組みの出所」と「S-747 の形の表」の節（写しは `target/notes/80/g72/draft.md`）。
- 論点: §4.5（145 行）は境界を `+` で並べるとだけ書き、同じ境界を二度書く形（重なり）と、`?Dup` を Dup を要する境界と並べる形（矛盾）を書いていない。
  重なりは、どう読んでも意味が一つの余分（§0.5.1 の受理して fmt が除く類）か、並びの同じ要素の重なり（Onsa の他の並びでは誤り）かで読みが割れる。
  矛盾は、`?Dup` が外した制約を `Dup`・`Copy`（と `Num`・`Float` の上位の要求）がまた足す形で、今は Dup を要する方の意味になり、書き手が `?Dup` で示した意図（Affine も受ける）と逆になる。
- 今の実装: 形の表のとおり。重なりも矛盾も黙って通る。矛盾は Dup を要する方の意味で、呼び出し側の E0416 の文面は、宣言に書いた `?Dup` を書けと読める（`b03`・`b06`）。
- 案: 重なりは、名前を引いた後に同じ境界（同じ種の制約か同じ trait。`?Dup` を二度を含む）を同じ並びに二度書く形とする。矛盾は、`?Dup` と、満たせば Dup を満たす境界（今の判定の `implies` で `Dup`・`Copy`・`Num`・`Float`）を同じ並びに書く形とする。
  - (a) 重なりと矛盾をどちらも E0416（境界の誤り）にする。候補は出さない。重なりは前の同じ境界を note で示し、矛盾は相手の境界を note で示して規則（`?Dup` は暗黙の `Dup` を外す印で、Dup を要する境界と並べると外すものが無い）を述べる。
  - (b) 重なりは受理し、fmt が後の重なりを取り除く（§0.5.1 の余分として `spec/tools.md` §3.3 に一行）。矛盾は (a) と同じ E0416。
  - (c) 重なりは受理し、fmt も揃えない。矛盾は (a) と同じ E0416。
  - (d) 重なりは E0416 で、後の重なりを `+` ごと除く削除の候補を出す。矛盾は (a) と同じ E0416（候補なし）。
  - (e) 今のまま（どちらも受理。矛盾は Dup を要する方の意味）。呼び出し側の E0416 の文面は直す。
  - 形ごとの出力: `Copy + Copy` は、(a) が E0416、(b) が通って fmt が `Copy` に、(c) が通る、(d) が E0416 と削除の候補、(e) が通る。`Copy + ?Dup`・`?Dup + Num` は、(a)〜(d) が E0416（候補なし）、(e) が通って `Copy`・`Num` を要求する。
    `Copy + ?Dup + Copy` は、(a)・(d) が位置の順で最初の誤り（`?Dup` の矛盾）、(b)・(c) が矛盾だけ。どの案も、含意で重なる形（`Copy + Dup`、`Ord + PartialOrd`）と `T: Dup` は通す。
  - 書き手から見て: 矛盾は現実にありうる。
    §4.5 が `?Dup` を「Rust の `?Sized` と同じ形」と書くので、`?Sized` を他の境界と並べる Rust の形（`T: ?Sized + Debug`）にならうと `?Dup` を他の境界と並べる書き方になり、その境界が `Copy` や数の trait だと（`T: ?Dup + Copy`、`T: ?Dup + Num`）`?Dup` が効かない。
    Rust の `?Sized` は多くの trait と独立で、同じ並べ方が矛盾にならない。
    矛盾の意図は一つに決まらない（Affine も受けたいなら `Copy`・`Dup` を外す、Copy だけでよいなら `?Dup` を外す）。(a)〜(d) は一回の検査で規則を示し、(e) は意図と逆の要求のまま通り、呼び出し側の E0416 で初めて気付く。
    重なりは、境界を足す編集の誤りか、別の境界を書くつもりの書き損じ（`Num + Num` で `Num + Int`）である。(a)・(d) は書き手に見せ、(b) は書き損じを消して、要る境界が欠けていれば本体の E0401（§6.3 の候補は境界を足す形）で次の回に気付く。
  - 修正候補: (a)〜(c) と (d) の矛盾は候補が無く、当て続けても `no-candidate` で止まる。(d) の削除の候補は意味を変えず、当てた後に誤りが残らないので収束する。fmt の (b) は二度かけても同じ。
  - 通るプログラム: (a)・(d) は今通る重なりと矛盾の形を誤りにする。(b)・(c) は矛盾の形だけを誤りにする（(b) は fmt の出力も変える）。(e) は変えない。`tests/`・`std/`・`examples/` に当たる形は無い（R-37 の再現の入力の 5 行だけ）。
  - 規則と例外: (a) は §4.5 に一文で、既にある E0416（境界の誤り）の範囲に入る。並びの同じ要素を誤りにする他の並び（`use`、型パラメータ、フィールド、`@latency`）と揃う。
    (b) は §0.5.1 の余分の一覧に一つ足し、境界の並びだけを他の並びと違う扱いにする。(c) は同じ意味の書き方を二つ残す（P2）。(d) は (a) に候補の形を一つ足し、他の並びの重なり（候補なし）と違う。(e) は規則を足さない。
  - 実装の量（W4-05 の U4、`lower_generics`。S-711 の腕と同じ所）: (a) は、並びの要素ごとに（境界、位置、`?` の有無）を覚え、前の要素と同じなら重なり、`?Dup` と `implies(b, Dup)` の境界が並べば矛盾とする約 +12〜18 行（文面二つ。`implies` は U4 で `satisfies` と一緒に署名の段から見えるようにする）。
    (b) は矛盾の分の約 +8〜12 と、`onsa_fmt` の境界の並びの重なりの除去（コメントの扱いを含む）約 +20〜30 と `spec/tools.md` の一行と fmt の事例。(c) は約 +8〜12。(d) は (a) に削除の範囲と候補で約 +5〜8。(e) は文面の直しで約 +2〜4。
  - 後の作業への手当て: どの案も、矛盾の判定は `implies` を読むので、W5-05 で数の trait（`AnyNum`、`Int`、`Unsigned`）が境界になって `implies` に行が増えれば、そのまま矛盾の判定に入る。trait の宣言の頭と上位の trait（第 2 期）は `lower_generics` と別の所で、同じ判定を呼ぶ一行が要る見込み（未確認）。

- 推奨と理由: (a)。確度: 中。
  - 矛盾は、書き手が `?Dup` で示した意図と逆の要求を黙って足す。誤りにする方が厳しく、後で意味を与えて緩めても既存のプログラムを壊さない。判定は今の `implies` を読むだけで、数の trait が増えても手当てが要らない。
  - 重なりは意味を変えないが、Onsa の並びの同じ要素の重なりは、取り込む先が同じ `use` を含めて誤りで、候補を出さない。(a) は境界の並びをそれと揃え、規則は既にある E0416 の範囲の一文で足りる。
    (b) は境界の並びだけを他の並びと違う扱いにし、fmt に別の仕組みを足す。(c) は同じ意味の書き方を二つ残す。(d) の候補は安全だが、他の並びの重なりと違う形を一つ足す（必要が分かってから足せる）。
  - 矛盾の判定と同じ環で重なりを見るので、(a) の重なりの分は数行である。
  - あわせて決めること: 位置は並びの後の要素（`Dup + ?Dup` は `?Dup`、`?Dup + Copy` は `Copy`）で、前の要素を note で示す。一つの並びに二つ以上あれば、位置の順で最初の一つ（§18.1）。段は S-711 と同じ型の段（E0416 の段）。
    名前の段の誤り（E0302、E0308）と未知の境界（失敗した名前、S-689）は比べない。この版で境界にできない trait の重なり（`Add + Add`）は、S-711 と同じく E0200 より先にこの E0416 を出す。当てる並びは `lower_generics` の全て（fn、struct、enum、`impl` の型パラメータ）。
    含意で重なる形（`Copy + Dup`、`Ord + PartialOrd`、`Float + Num`）は誤りにしない。上位の trait の関係で決まる重なりで、誤りにすると W5-05 と第 2 期で上位の関係が増えるたびに、今通る並びが誤りに変わりうる（要るなら別の S にする）。
