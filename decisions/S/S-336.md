# S-336 範囲の端の冗長な括弧

- 空白: 範囲の端の冗長な括弧（`0..<(n + 1)`）を fmt が外すか。§3.1 は強弱で読みが決まる位置の括弧を fmt が外すとし、`spec/tools.md` §3.3 は「強い群の式を弱い群の被演算子として囲む括弧」とするが、範囲の記号が群に当たるかを書かない。今の fmt はどの位置の冗長な括弧もまだ外さない（W3-12 が未着手）。W3-18/t で見つけた（2026-10-09）
- 提案: (a)。fmt は範囲の端の全体を囲む冗長な括弧を外す（`0..<(n + 1)` は `0 ..< n + 1`、`(lo + 1)..<hi` は `lo + 1 ..< hi`）。外す一覧の「文・引数・要素・見出しの式の全体」に「範囲の端の全体」を足す（範囲の記号を群の表に入れない）。無いと誤りになる括弧（見出しの struct リテラルを含む端）は残す。
  見出しの範囲の全体を囲む `for i in (0..<n)` は見出しの外の範囲の E0002 で、fmt はそのファイルを書き換えない（`spec/tools.md` §3.3 と仕様 §7 の例に一文）。
  端の `as` / `at` の括弧が残るかは S-340 に従う（`spec/tools.md` §3.3、仕様 §7。2026-10-09 決定、利用者、第 12 組。実装は W3-12）
