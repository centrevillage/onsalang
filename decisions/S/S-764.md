# S-764 見出しが E0412（対象の型引数の数）か E0416（対象の型引数が型の宣言の要求を満たさない）の固有の `impl` のメンバを、E0307 の見出しと同じく対象の型の `.` の空間に数えるか（§18.1 の 87 行は E0307 の見出しだけを書く）

- 空白: §18.1 の誤りのある宣言の段落（87 行）は、見出しが E0307 の固有の `impl`（対象に書いた別名、対象の型引数、孤児規則）も、対象の型が決まればメンバをその型の名前の後の `.` の空間（§6.2）に数え、E0304 の相手にし、使う所は他の `impl` のメンバと同じに引くとする（S-748）。見出しが他のコードの誤りのときは書いていない。
  S-756 の `決定` は、対象の型引数が型の宣言の要求を満たさない見出しの E0416 について「メンバは S-748 のとおり `.` の空間に数える」とするが、仕様の文は E0307 のままである。S-759 の見出しの E0412（`impl[T] P[T]`、`P` は型引数を取らない）は、`決定` も仕様も書いていない。
  形（82 回目に親が HEAD `d70ae82` の `target/debug/onsa` で確かめた。入力は `target/notes/82/s764/`）: `impl[T] P[T] { pub const Q: F32 = 1.0 }` の後の `impl P { pub const Q: F32 = 2.0 }` は、見出しの E0412 と、後ろの `Q` の E0304（note は前の `Q`）。`P.R`（E0412 の `impl` だけが持つメンバ）を読む関数には何も出ない。
  今の実装は数えている。
  読み: (1) 数える。S-748 の理由（見出しの誤りは書き方の誤りで、どの型のメンバかは一つに決まり、指す先がある）は E0412・E0416 の見出しにも当たる。対象の型の名前は見つかっていて型が決まる。§18.1 の 87 行を「見出しが誤りの固有の `impl`（E0307、E0412、E0416）」に広げる。
  (2) E0307 だけで数え、E0412・E0416 では数えない。数えない理由が仕様に無く、メンバを使う所に E0302 が出て、見出しを直せば消える連鎖になる。実装に分岐が要る。
- 決定: 決定（2026-10-29、利用者。82 回目。確認だけ）: (1)。
  見出しが E0412（対象の型引数の数）か E0416（対象の型引数が型の宣言の要求を満たさない）の固有の `impl` も、E0307 の見出しと同じく、対象の型が決まればメンバをその型の名前の後の `.` の空間に数え、E0304 の相手にし、使う所は他の `impl` のメンバと同じに引く（メンバは検査しない）。
  理由: S-748 の理由（見出しの誤りは書き方の誤りで、どの型のメンバかは一つに決まり、指す先がある）が当たる。数えないと、メンバを使う所に見出しを直せば消える E0302 が出る（連鎖）。誤りのあるプログラムの報告だけの話で、通るプログラムは変わらない。
  仕様は §18.1 の誤りのある宣言の段落（87 行）を見出しが誤りの固有の `impl`（E0307、E0412、E0416）に広げ、§6.2 の `.` の空間の文も揃えた。`tasks/diag-codes.md` の E0304 の行に足した。
  実装は今のまま（足す行は 0）。E0416 の見出しは W4-05 U4a で入り、事例に E0412・E0416 の見出しの `impl` のメンバとの E0304 と、使う所に何も出ない形を一つずつ置く。
