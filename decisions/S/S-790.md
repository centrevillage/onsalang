# S-790 後置 `?` の被演算子の中のブロック・`if` の末尾に書いた `move`（`({ move r })?`、`(if c { move r } else { move s })?`）を受け付けるか

- 空白: §5.2 の 40 行は、返り値の位置と中身を取り出す形（`move self` の受け手と後置 `?` の被演算子）を、印を書かなくても消費が見える例外とする。49 行は返り値の位置に書いた `move`（そこに置いたブロックの腕の `move a` を含む）を「意味を変えない余分な情報で、検査は受け付けるが、書かない」とするが、`?` の被演算子に置いたブロック・`if` の末尾の `move` に触れない。S-784 も「印を書かない」とするだけである。
  `({ move r })?` と `(if c { move r } else { move s })?` は、W4-07 U2b の新しい modes では `r` を移して通る（返り値の位置と同じ扱い）。`(move r)?` は構文の E0002、`{ move r }?` は E0013（括弧が要る）。再現は W4-07 U2b の壊す側の `c8.py` の `t_blk_move`・`t_if_move`（写しは `target/notes/87/w407/u2b/b/`）。
  読み: (1) 返り値の位置と同じく、余分な印として受け付ける（今の実装）。(2) 印を書く所でないので、末尾の `move` を E0703 にして消す候補を示す（S-605 の消費しない位置の末尾の `move` と同じ形）。
  親の読み（確認だけの案）: (1)。40 行が `?` の被演算子を返り値の位置と同じ例外の組に置くので、49 行の扱いも同じにそろえる。仕様の 49 行の後に「中身を取り出す形の被演算子に置いたブロックの腕の `move` も同じ」と足す。
- 決定: 決定（2026-10-30、利用者。87 回目。確認だけ。親の読み）: (1)。中身を取り出す形（`move self` の受け手と後置 `?` の被演算子）の被演算子に置いたブロック・`if` の腕の `move` は、返り値の位置と同じく意味を変えない余分な印で、検査は受け付けるが、書かない。仕様 §5.2
- 経緯: 87 回目（2026-10-30）、W4-07 U2b の壊す側（onsa-break）が空白として報告した。親が仕様の 40・49 行を確かめて登録した。
