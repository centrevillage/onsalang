# S-1232 イベントの値と `sample_tick()` だけを混ぜた式のクロック（`when~(sample_tick() -% t0(m) < len)` の時間が、イベントの位置で止まるか、使う所の刻みで進むか）

- 空白: §11.11 は「周期の刻みのクロックの被演算子の無いイベントの値の式は、そのイベントのクロックの式で、その刻みごとに評価する」「イベントの段の式では…パラメータの種類と `sample_tick()` は読める」、§11.4 は「使う所の刻みのクロックに合わせる」「合わせるのは書いた本体の刻み（イベント、`sample / N`、`sample`）まで」「イベントの段の式ではその位置の値である」とする。
  イベントの値（`m` から作った始まりの時刻 `t0(m)`）と `sample_tick()` だけを混ぜた式を、修飾子の条件（`when~(sample_tick() -% t0(m) < len)`）や頭の引数（`h2~(sample_tick() -% t0(m))`）に書いたとき、`sample_tick()` が合わせるのがイベントのクロック（被演算子）か、使う所（条件を読むクロック W、入力のクロック）かが一つに決まらない。
  読み: (1) イベントのクロックの式（字の向き）。時間はイベントの位置で止まり、経過時間のゲートにならない（`when~` は最後の値の水準で読むので、常に「0 < len」の形になる）。書き手は `(sample_tick() at sample) -% t0(m) < len` か `sample_tick() -% (t0(m) at sample) < len` と書く。
  (2) 使う所の周期の刻みに合わせる（イベントの値は、その刻みまでの最後の値として暗黙に読む）。`reset_if~` の条件では、イベントの値と周期の値が混ざる E0815（§11.11 の四つの所）になる。(3) 混ぜた式を誤りにして `at` を求める。
  経過時間の判定は `sample_tick()` の典型（S-565 の B11）なので、書き手が黙って止まる形を書かないかも比べる。今は `at event` が E0302 で書けない。
  仮の扱い: 無し（W7-11 の設計メモの前に決める）。S-1230 (G) の字は「イベントの値を読まない引数と条件」に限り、この空白をどちらにも塞がない。
