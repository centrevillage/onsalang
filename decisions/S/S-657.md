# S-657 パッケージの中のファイルを渡した `interface`・`graph` で、パッケージの別のモジュールに診断があるとき、どの診断を出すか（そのファイルの診断だけか、全てか）

- 空白: §15.1 は、パッケージの中のファイルを渡すとパッケージ全体を集めて解決し、結果をそのファイルのモジュールに絞るとし、「診断が結果であるコマンド（`check` と LSP）は、そのファイルの診断だけを出す」「`interface` はそのモジュールの宣言、`graph`・`play`・`probe` はそのモジュールの中の flow」を出すとする。§18.2 の `onsa test` は「走らせるのを止めた診断は、渡したファイルによらず全て出す」と書く。
  `interface`・`graph` にファイルを渡し、パッケージの別のモジュールに診断があるときに出す診断を書いていない。読みは、(1) `check` と同じくそのファイルの診断だけを出し、そのファイルが清潔なら結果を出して 0、(2) パッケージの全ての診断を出して 1（今の実装）、(3) `test` と同じく止めた診断を全て出す、に割れる。
  再現: `alpha.onsa` に E0302、`sub/beta.onsa` は清潔なパッケージで、`check sub/beta.onsa` は 0 で出力なし、`interface sub/beta.onsa` と `graph` は `alpha.onsa` の E0302 を出して 1（dev `ade71e1`、63 回目の scratchpad の `w414u4/t/probe3.py`）。
  仮の扱い: (2)（今の実装のまま。W4-14 U4 の実装の担当に伝えた）。
