# S-966 定数式の文法の外の形で、形から型も `U32` でないと分かるもの（比較 `N < 2`、論理 `a && b`、タプル `(1, 2)`、配列 `[1]`）のコード: E0417 か E0401 か

- 空白: §4.5 は定数式の文法（整数のリテラル、定数を指す名前、`+ - * / %`、前置の `-`、括弧）を挙げ、「普通の式と同じ規則で、期待型を `U32` として検査する（`U32` でない定数は E0401）」と「定数式でないもの（関数の呼び出し、ローカル変数など）を書くと、位置によらず E0417」の二文を持つ。文法の外の形で、形から型も `U32` でないと分かるもの（比較 `N < 2`、論理 `a && b`、タプル `(1, 2)`、配列 `[1]`）が、どちらの文に当たるかを書いていない。
  読みは (1) 文法の外の形なので E0417（中は見ない） (2) 期待型 `U32` と合わないので E0401（普通の式と同じ） (3) 今の flow の分け方（タプル・配列は E0401、演算子は E0417。比較は形から `Bool` と分かるのに E0417）。
  今は flow の比較が E0417、flow のタプルが E0401、署名と本体はどれも E0200「expressions as array lengths」（W5-16 の設計メモの `probe/h/gap_*`、`target/notes/129/w516/`）。どの読みでも通るプログラムは変わらない。W5-16 U1 の設計メモが見つけた（2026-11-09、129 回目）。仮の扱いは (1) で、読み手の枝に `SPEC-GAP` を付ける。
- 決定: 決定（2026-11-09、利用者。129 回目、S-966・S-967・S-968 の共通の規則。中立の要約（`target/notes/129/s966/summary.md`）と onsa-advisor の段 1 が親の読みと一致し、段 2 は省いた。利用者が ID を挙げて了承）: (1) E0417。比較・論理・タプル・配列は文法の外の節で、中の型によらず E0417（flow の今のタプル・配列・`true && false` の E0401 と、署名・本体の暫定の E0200 が E0417 に変わる。どれも誤りのまま）。整数でないリテラル `1.5` は葉で E0401（`const H: F32 = 1.5` を書いた `[F32; H]` の E0401 と同じ）。共通の規則: 定数式の名前は、名前の段が普通の式と同じ歩き手で読む（名前の誤り E0302・E0308 は位置によらず先、§18.1）。型の段の読み手は「葉は型で、節は文法で」判定する。葉（リテラルと名前の鎖）は、定数でない値（ローカル、関数、列挙子、値のフィールド）が E0417、定数式だが型が期待型でないもの（期待型でない定数、整数でないリテラル `1.5`・`true`・`"s"`）が E0401。節（子を持つ形）は、`+ - * / %`・前置 `-`・括弧の外の形（比較・論理・ビットの演算子、`as`・`!`・`?`、添字、呼び出し、値のフィールド、タプル・配列・struct リテラル、ブロック・`if`・`match`・無名関数、`unsafe`）を、子の型と中身を見ずに位置によらず E0417。節を子に依らせないのは、`(1, 2)` を型で E0401 にすると `(g(1), 2)` の中の呼び出しの E0417 が先になり、同じ形でもコードが変わるため。 期待型は、大きさを表す位置（配列の長さ、繰り返しの数、遅延線の長さ、`vdelay~` の最大、`par~` の端）では `U32`、const 引数では const パラメータの型（この版の const パラメータは `U32` だけで、他の型は E0200）と書き分けた。利用者の指摘: 大きさは本質的に `U32` だが、const 引数が `U32` なのはこの版の制限で、たまたま同じ扱いになるだけ。`U32` でない const 引数の文法は、その const パラメータを足すときに別に決める。 仕様 §4.5 に書いた。実装は W5-16 U1b（読み手の判断の表）。
