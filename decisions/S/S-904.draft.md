# S-904 手書きの `impl` のメンバの署名が trait と違うときの診断のコードと `pub`

- 決定済みで戻さないもの:
  第 88 組の下書きの写しは `target/notes/117/g88/draft.md`、入力は `P117/g88/probe/`（消えうる）、段 1・段 2 の答えは `target/notes/117/g88/advisor/`、親の入力は `target/notes/117/g88/parent/`。
- 論点: §6.3 は `Default` を `default() -> Self` とするだけで、手書きの `impl` のメンバの署名の違い（`fn default(self) -> Mode`、`fn default() -> I32`、`fn default(x: I32) -> Mode`、`fn default[T]() -> Mode`）のコードと、`pub fn default`（§15.1 の可視性を書ける位置に trait の `impl` のメンバは無い）を書いていない。
  W5-06 の U4 で要る。S-852 の題の外なので分けた。
- 今の実装: 全て `impl` の E0200 に隠れる（`e03`）。§6.4 の例は `-> Mode`、§6.3 は `-> Self` と書く。`Self`（§2.2）で書いた形と型の名で書いた形はどちらも同じ型である。
- 案:
  - (a) 既にあるコードに写す: 引数の数と型引数の数は E0412、引数と返り値の型は E0401、`self` の有無は E0413 に写す。`pub`・`priv` は §15.1 の容れ物の形と同じ E0002 か、E0020（語を外す候補）にする。
  - (b) 一つのコードにまとめる: 署名の違いは全て E0416（trait を満たさない）。
  - (c) 新しいコード。
  - 書き手から見て: (a) は主文が具体的で、note が trait の署名を示す。(b) は note に頼る。修復の回数はどれも 1 回である。修正候補はどの案も作らない（本体が変わる）。`pub` の E0020 は語を外す候補で止まる。通るプログラムは変わらない（今は全て E0200）。
  - 規則と例外: (a) は既にあるコードの読みのままで、§6.3 に一文。(b) は E0416 の読みが広がる。(c) はコードが増える。別の所に同じ形がある: 関数値の型の不一致は E0401、数は E0412 である。
  - 実行の結果はどの案も無い。実装の量（見当）: (a) +25〜35、(b) +15〜25、(c) +30〜40。どれも U4 の内で、増分は 0〜15 行である。第 2 期に同じ検査を使う。
- 他言語: 参考にとどめる。rustc 1.94.1（`r6.rs`）は `self` の違いを E0185 とする。
- 推奨と理由: (a)。確度: 中。
  - 既にあるコードの読みのままで、主文が直す位置を指す。`pub` は語を外しても意味が変わらない（trait の `impl` のメンバの可視性は trait に従う）ので、E0020 と語を外す候補とする（§15.1 の容れ物の E0002 は意図が変わる形の規則で、ここには当たらない）。
- 影響: 仕様は §6.3、§15.1。診断は、(a) なら E0401・E0412・E0413 と `pub` のコード、(b) なら E0416、(c) なら新しいコード。作業: W5-06 の U4。
- 独立のレビュー: 段 1 は下書きに無い案を選んだ: 署名の違いは全て E0401 で、位置はメンバの名、note に trait の署名を示す。`rt` の欠けは足す候補を出す。親も同じ読み。
  段 2: 失うのは引数の数（E0412）と `self`（E0413）の区別がコードから消えること。得るのは `self` を未知のメンバに写す無理が無いことと、同時に違う形の順の規則が要らないこと。文面で最初に違う部分を名指す。S-894 と揃う。`pub`・`priv` は §15.1 で決定済みで E0020（外す候補）である。
