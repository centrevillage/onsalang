# S-172

- 空白: `sample_rate()` と `prev~` が「サンプルレート」「1 サンプル遅延」と定義され、将来インスタンスを別のクロックで動かすと意味が変わる。ホストの情報を組込み名で足すと、後で利用者の名前を壊す（将来の機能の構造の検討）
- 提案: インスタンスのクロックを基準に定義し直した（今の振る舞いは変わらない）。ホストの情報は `block` の入力で渡す方針。§19.1 のマルチレートの方向（`with` で付ける、効果にしない、2 のべき乗、`block` は状態を持てない、導くクロックの位相のカウンタ、制御と音声の区別）（2026-10-06 決定。実装は第 2 期以降のマルチレート）
- 時期: —
- 補い（2026-10-21、親）: S-565〜S-567（2026-10-20・21、第 34 組）で、マルチレートの方向のうち「`with` で付ける」「制御と音声をクロックの宣言で区別する」を改め、修飾子 `.down~(N)`・`.up~(N)` と変換の flow、周期の刻みのクロックの間の明示の `at` にした。2 のべき乗、`block` は状態を持てない、位相のカウンタは保つ（仕様 §19.1）
- 補い（2026-10-22、親）: S-575（2026-10-22、第 36 組）で、export する flow のホストの情報は `@host(<種類>)` を付けた `block` の入力にした（種類の閉じた一覧、ラッパーが値を書く。再生の状態は S-572 の `transport.Event`）。
