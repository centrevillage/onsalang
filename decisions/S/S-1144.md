# S-1144 細部: 値そのものがノードの `let` の名前を取るノードが、中の同じ種類のノードの番号を使うか（`let a = lp~(lp~(x))` の中のノードは `a.lp_0` か `a.lp_1` か）

- 空白: §11.6 は「番号は `let` ごと・種類ごとに、呼び出しの名前が字面に現れる順に 0 から振る」と「パターンが名前一つだけの `let` の値がインスタンス・遅延・`par~` の呼び出しそのものなら、そのノードは `let` の名前で呼ぶ」とする。`let` の名前で呼ぶ外側のノードが種類の番号を一つ使うかが書かれていない。読み: (1) 使わない（`let a = lp~(lp~(x))` は `a` と `a.lp_0`）、(2) 使う（`a` と `a.lp_1`）。表示の名前だけが変わり、通るプログラムは変わらない。
  仮の扱い: (1)（W7-03 U1c の実装とテストの担当の期待。`tests/spec/flow/state_names_let_node.onsa` の `node_and_inner`）。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認だけ。「(A)と(B1)はS-1148以外OKです」）: 仮の扱いのとおり。`let` の名前で呼ぶノードは種類の番号を使わない。
  突き合わせ: 助言の担当が固定のバイナリ `onsa-d02ddee` で再現し、仮の扱いが今の挙動と合い、既決とぶつからないことを確かめた（`target/notes/189/reports/onsa-advisor-a5d87f2cf05f2cfce-001.md`）。
- 経緯: 165 回目、2026-11-18、W7-03 U1c の壊す側（onsa-break）が空白として挙げ、親が登録した。
- 補い（2026-11-18、親）: 165 回目、W7-03 を閉じる前の文書の点検: 仮の扱いの SPEC-GAP の印がコードに無い（S-1141〜S-1143 は `crates/onsa_sema/src/flow/plan/names.rs` にある）。決めるときに `Namer::name` の値そのもののノードの所で合わせる。
