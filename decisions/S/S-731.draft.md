# S-731 一つの単位に、要る種類でない名前の E0308 と、離れた位置のこの版の E0200 が並ぶとき（`fn f(x: Zq) -> I32 uses {Ef}`）、§15.1 の「E0200 より先に E0308」を単位の全体の順とするか、同じ並び（効果行・境界）の中の順とし離れた位置は §18.1 の位置の順とするか

- 決定済みで戻さないもの: 一つの名前に E0200 でなく E0308 を付けること（`uses {I32}`、`T: I32`、S-713 の A7）、要る種類の名前の E0200（`T: Tr`、`uses {Ef}`、S-719）、段の違う誤りの順（§18.1）。
  第 68 組の下書きの「族「§15.1 の E0308 の位置」の仕組みの出所」と「S-731 の形の表」の節（写しは `target/notes/78/g68/draft.md`）。
- 論点: §15.1 の 75 行「要る種類でない名前は E0200 より先に E0308 にする」と §18.1 の E0200 の段落「名前の種類の誤り（E0308）は版によらないので E0200 より先に出し」が、一つの名前に付けるコードの規則か、一つの単位の中の誤りの順の規則かが書かれていない。
  §18.1 の単位の規則は、段の順の次に位置の順で一つを選ぶ。署名の E0200 と本体の式の型引数の E0200 は、E0308 と同じ名前の段である。
- 今の実装: 表のとおり。署名の型パラメータの並びの境界どうしと、一つの効果行の中だけ、E0308 を E0200 より先にする（`sig.rs::lower_generics` の `traits.filter(|_| !wrong)`、`read_effects` の `unsupported.filter(|_| !wrong)`）。
  同じ並びでも const パラメータの型の E0308 は対象でなく（`[T: Tr, const N: helper]` は E0200）、離れた位置と本体は位置の順である。本体の歩き手は名前の段の E0200 で止まるので、後ろの E0308 を見ない。
- 案: 
  - (1) 単位の全体で、要る種類でない名前の E0308 を同じ段の E0200 より先にする（位置によらない）。
  - (2) 同じ並び（一つの効果行、一つの型パラメータの並び）の中だけ E0308 を先にし、離れた位置は §18.1 の位置の順（今の形に近い。並びの範囲は決める: 境界だけか、const パラメータの型も含むか）。
  - (3) §15.1 の文は一つの名前に付けるコードの規則とし、順は並びの中でも §18.1 の位置の順にする（`uses {Ef, I32}` は `Ef` の E0200、`uses {I32, Ef}` は `I32` の E0308）。
  - 形ごとの出力: (1) は表の「—」の行が全て E0308。(2) は今の出力（const パラメータの型の行は並びの範囲で決まる）。(3) は同じ並びの三行が位置の順になり（`uses {Ef, I32}`・`T: Tr + I32`・`[T: Tr, U: I32]` は E0200）、他は今のまま。
  - 書き手から見て: どの案でも二つの誤りを直すには二回の検査が要り（単位に一つずつ）、変わるのは先に見る誤りだけである。
    (1) は版によらない誤りを先に見せる。(2)・(3) は書いた順に見せる。E0200 も本物の誤り（この版で書けない形）で、書き手を誤らせる文面ではない（それは A7 が一つの名前について既に直した）。
  - 修正候補: E0308 には候補が無い。E0200 のうち `Feature::ConstGenericKinds` だけが候補（「write `U32`」）を持つ。§18.1 の候補の約束は「唯一の誤りなら」なので、どの案でも約束は変わらない。
  - 通るプログラム: どの案も変わらない。
  - 規則と例外: (1) は §18.1 の単位の選び（段、次に位置）に「同じ段では E0308 を E0200 より先」の例外を足す。理由の「版によらない誤り」は E0308 だけでなく E0200 でない全てのコードに当たるので、同じ理由で E0401 なども先にと広がりうる。
    (2) は「同じ並びの中」の例外を足し、並びの範囲（境界だけか、並びの全体か、第 2 期の上位の trait の並び `trait A: X + Y` や `with` の並びを含むか）を決め続ける。(3) は例外を足さない。
  - 実装の量: (1) は単位の選び（`Diagnostic::unit_order` か driver の `reduce.rs::per_unit`）にコードの比べを足し（約 +3〜5 行）、署名の `Sema::keep` も同じにする（約 +2 行）。
    さらに本体の歩き手が名前の段の E0200 で止まらずに後ろの E0308 を探す必要があり（`exprs.rs::type_args` など、止めて読まない形の後を歩く）、偽の連鎖を避ける手当てが要る（約 +20〜40 行、見積もりの確度は低い）。後の作業で名前の段の E0200 が増えるたびに、同じ手当てが続く。
    (2) は今の実装で 0 行（並びの範囲に const パラメータの型を含めるなら約 +3 行）。第 2 期に並びの形が増えるたびに範囲を決める。
    (3) は二つの `filter(|_| !wrong)` と `wrong` を外す（約 −6 行）。後の作業の手当ては無いが、W4-04 U8b（`7560d6e`）で入れたばかりの並びの中の順を戻す手戻りで、その事例（`kind_effect_row.onsa`・`kind_bounds.onsa`）の期待を直す（親が足した）。
- 他言語: 比べられる言語は調べていない（未確認）。rustc と swiftc は一つの単位の全ての誤りを出すので、一つを選ぶ順の問題が無い。
- 推奨と理由: (3)。確度: 中。
  - §15.1 の文の出所（S-713 の A7）は、型の名前を効果や trait と呼ぶ一つの名前の E0200 を直すことで、単位の中の順を決めたものではない。一つの名前のコードが決まれば、順は §18.1 の一般の規則（段、次に位置）で足り、例外が要らない。
  - どの案も直す回数は同じで、先に見る誤りが変わるだけである。(1) は §18.1 の選びの例外と、本体の歩き手が E0200 の後を歩く手当てを持ち込み、名前の段の E0200 が増えるたびにその手当てが続く。
  - (2) は今の実装で費用が無いが、「同じ並び」の範囲が今も閉じておらず（境界だけで、const パラメータの型は外れる）、第 2 期の並びの形ごとに決め直す。(3) は今の実装から約 6 行を消すだけである。
