# S-893 `unwrap` の panic の位置（呼び出しの位置か、std の本体の中の位置か）

- 空白: §9.1 は `unwrap` が `None` / `Err` で panic するとし、§9.2 は通常の実行で「メッセージと位置を出力してプロセスを終了する」、§18.1 は `failure` の `span` を「panic した式の位置」、`calls` を「panic した位置からテストの本体まで遡る呼び出しの位置」とする。
  §14 の `ONSA_PANIC_HANDLER` は `(const char* msg, const char* file, uint32_t line)` で呼ばれ、`panic_messages = false` では `msg` と `file` が空で行番号は残る（§9.2）。
  S-71・S-785・S-873 は `unwrap` を std の本体（`pub rt fn unwrap(move self) -> T`、`None => panic(…)`）にするので、`panic` の式は `std/core.onsa` の中になる。「panic した式の位置」が std の本体の中か、`.unwrap()` を書いた位置かを仕様が書かない。
  今（`01aff7bf`）は、組込みの表の `unwrap` は呼び出しの位置の panic で（`failed at` の行は `.unwrap()` の行で、`calls` は空）、std の `target` のメソッド（`xs.slice`、`rem_euclid`）も呼び出しの位置である。
  std の Onsa の本体の中の panic の今の例は `std.dsp.test.energy` の `assert` だけで、`failed at` の行は `std/dsp/test.onsa` の中で、`calls` に呼び出しの位置が入る。
  再現は `P114/s893-advisor/probe/a2.onsa`・`b1.onsa`・`f1.onsa`・`p1.onsa`（写しは区切りで `target/notes/114/s893-advisor/`）。
  急ぎ: 次の作業の前（W5-03 の U2 のテストの票の期待値が変わる。U1 は進められる）
- 決定: 決定（2026-11-05、利用者。114 回目。独立のレビューの段 1 が (1)+(4) を選び、設計メモの (1) に親が (4) を足す形で一致したので段 2 は省いた）: (1)+(4)。
  言語の規則は変えない。`unwrap` は std の Onsa の本体で、その panic の位置は本体の `panic` の式である。§18.1 の文がそのまま当たり、`span` は `std/core.onsa` の中、`calls` に `.unwrap()` の呼び出しの位置が入る。利用者が同じ形で書いた関数と同じで、`unwrap` に限らず std の Onsa の本体の全ての panic に当たる。
  `onsa test` のテキストの `failed at` の位置だけは、`span` と `calls` のうち std の外で最も内の位置にする（`spec/tools.md` §4）。`--json` は変えない。`std.dsp.test.energy` の `assert` の失敗のテキストも呼び出しの行に変わる。依存のパッケージが入るときは「std の外」か「検査中のパッケージの中」かを見直す（第 2 期）。
  C の `ONSA_PANIC_HANDLER` の `file`・`line` は panic した式の位置のままで、`std/core.onsa` の行になる。実害が出たら、呼び出しの位置で報告する印の仕組み（案 (2)）を §19.1 の panic の地点の番号と一緒に考える。そのとき変わるのは `--json` の `span` と `calls` だけである。
  降下で `unwrap` を開く案 (3) は採らない（std の本体と降下の二重の定義、S-71 の使い道の例外）。`onsa audit --panics`（第 2 期）は `.unwrap()` の呼び出しを列挙する形で作る（利用者の補助関数の panic も呼び出しを通して伝える要があるのと同じ）。
  作業は W5-03 の U2。仕様 §9.1、§9.2、`spec/tools.md` §4
