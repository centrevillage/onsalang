# S-1131 `match~` の腕の束縛を読む `block` のクロックの式（インスタンスの `block` の入力など）を評価する段と、その束縛のクロック

- 空白: §11.5 は「`match~` の取られない腕の束縛は、値型の既定値 `T.default()` になり…腕は `match` と同じく、パターンとガードで選ぶ」、§11.3 は「高い段で使う、遅いクロックの部分式の値は、状態の隠れたフィールドに置く…名前（入力、`let`、`par~` の添字）…は巻き上げない」とする。`match~` の腕の束縛を `block` のクロックの式（インスタンスの `block` の入力の引数など、呼び出し側の `block` の段で評価する式、S-1128）が読むとき、どの段でその束縛の値（取られた腕なら対象の部分、取られない腕なら既定値）を決めるかが書かれていない。
  腕の束縛は巻き上げない名前の一覧に無い。
  あわせて、束縛のクロック（今の実装は対象のクロック）は、腕が取られるかを対象より速いガードが決めるとき（`n if x > 0.0 => lp~(y, n as F64)`、`x` は `sample`）に、値が `sample` で変わる（取られない腕では既定値）のに `block` として読める。
  読み: (1) 腕の選び（パターンと、対象のクロック以下のガード）を `block` の段でも行い、束縛の値をその段で決める（ガードが対象より速いなら束縛のクロックはガードのクロックに上がり、`block` の入力へ渡すと E0815）。(2) 腕の束縛を読む `block` のクロックの式は、腕の中（`sample` の段）で評価する（`block` の入力を毎フレーム作り直す）。(3) `match~` の腕の束縛を `block` のクロックの式で読む形を当面の誤りにする。
  再現（W7-18 U2 のテストの担当、参照評価器を検査の外で走らせた）: `flow lp(x: F64 at sample, g: F64 at block) -> F64 at sample { x * g }` と `flow top(x: F64 at sample, k: U32 at block) -> F64 at sample { match~ k { n => lp~(x, (n as F64)), } }` を `k = 3`、`x = 2.0` で `process` に渡すと、評価器は `n` に値が無く内部エラー（今のコンパイラは `match~` を E0200 で止める、W7-06）。
  仮の扱い: 参照評価器は、腕の束縛を読む `block` の引数を評価できないとき `Unavailable` にする（W7-18 U2b）。期待値は書かない。
  待つもの: W7-06 の `match~` の降下と巻き上げ（W7-05）、評価器の `match~` の比べ（W7-19）。
