# S-838 `@export` の項目も `prefix` も無いパッケージのビルドが書くファイルの名前の幹（§14.2 の `<prefix><package>`）

- 空白: §14.2 は「生成するファイルの名前は `<prefix><package>` を幹にする: ヘッダ `<prefix><package>.h`、C のソース `<prefix><package>.c`、静的ライブラリ `lib<prefix><package>.a`」と書き、別の文は「`@export` の項目が無いパッケージでは `prefix` は要らず」と書くが、`prefix` が無いときの幹を書かない。
  今（W4-02 U3b の後、`P98/bin/onsa-58e8c87`）は、`@export` の無いパッケージ `demo` の `build` が `onsa_demo.c` を書き（API のヘッダは書かない）、`prefix` があっても C のソースと静的ライブラリは `onsa_<package>` の幹で書く（別の文とのずれ。W10-02 の「C の名前と形」で直す。テスト `crates/onsa_cli/tests/manifest_prefix.rs` の `the_c_source_is_named_after_the_prefix` が `#[ignore = "W10-02"]`）。
  W4-02 U3c は既定の `prefix`（`onsa_`）をやめるが、ファイルの名前の幹は今のまま残す。読みは (1) `<package>`（`demo.c`、`libdemo.a`） (2) 今の `onsa_<package>` (3) export が無ければ C のソースを書かない、に割れる。
- 決定:
- 経緯: 98 回目（2026-11-01）、W4-02 U3c のテストの担当が見つけた。幹が要るのは W10-02 で C のソースと静的ライブラリの名前を `<prefix><package>` に直すときなので、期限を W10-02 の前にした。
