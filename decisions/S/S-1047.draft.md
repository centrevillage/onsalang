# S-1047 flow の本体の `par~` の結果の要素型が Copy でない形を受け付けるか

- 決定済みで戻さないもの: `let` に置く形の E0810（§11.3、S-616）、本体の呼び出しの結果と補間の E0805（S-1043）、名前の無い遅延の値型の E0810（R-458、W7-07 で直す実装の誤り）、関数値の E0806・E0810（S-372）、巻き上げる値の型（S-1046、別の S）。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/166/g111/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版（親の直し `parent_edits.md`）・入力は `advisor/`、下書きと段 1 の報告は `onsa-gap-a1c71ded76168b5c9-001.md`・`-002.md`・`onsa-advisor-a3feadd0f744eff07-001.md`。
- 論点: §11.3（102 行）の E0810 は入出力と本体の `let` の値型に掛かり、名前の無い式の値には掛からない。§11.5（194・195 行）の E0805 は、破棄に `Alloc` の要る所有の値を作る式（呼び出しの結果、所有の行のリテラル）を誤りにし、静的な値と破棄の要らないリテラル（§5.4）を書けるとする。
  `par~` の結果はどちらの一覧にも無い。要素が静的な値の `par~`（`(par~ i in 0 ..< 2 { "a" })[0].len()`）は、配列のリテラルと同じに破棄の要らない値と読むことも、所有の値を作る式（E0805）と読むことも、信号の値（E0810）と読むこともできる。
- 今の実装: 形の表のとおり。名前を付けない `par~` の結果は、要素型によらず通る。`let` に置くと E0810。降下は `Str` を含む flow の式を全て E0200 で止める。
- 案:
  - (a) 破棄の要らない値に数える: `par~` の結果は、本体が破棄の要らない値なら破棄の要らない値である（`[e; N]` と同じ）。§11.5 の `par~` の段落か §5.4 の一覧に一句。本体の呼び出しと遅延は、それぞれの規則（S-1043、R-458）で誤りになる。
  - (b) E0805: 要素型が Copy でない `par~` の結果を、所有の値を作る式に数える。位置は `par~`、候補なし。
  - (c) E0810: `par~` の結果の要素型（信号の値型）は Copy でなければならない。位置は `par~`、候補なし。§11.3 の 102 行に一句。
  - (d) (c) と同じ出力で、一つの文にする: flow の構文が作る値（インスタンスの出力、組込みの遅延の値、`par~` の結果の要素）の型は信号の値型（Copy、E0810）である。インスタンスの出力は宣言の E0810 で既に満たし、遅延は R-458 と同じ規則になる。
  - 形ごとの出力: 形の表のとおり。(a) は名前の無い `par~` の結果を `[e; N]` と同じに通し、(b)〜(d) は要素型が Copy でない `par~` を誤りにする。誤りにする形で、(b) は暗黙の `Alloc` のコード、(c)・(d) は信号の値型のコードである。
  - 書き手から見て: Copy でない要素の `par~` を書く用途は見当たらない。`par~` は状態を持つ構造を複製するための構文で、`Str` などは `rt fn` に渡す静的な値か表の要素として現れる（`par~` の外の `["a", "bb"][k]` で書ける）。
    (a) は通すので直しは要らない。(b)〜(d) は一回の検査で `par~` の位置に出て、直し方（`par~` の外で値を選ぶ、Copy の値を作る）は書き手が選ぶ。(b) の文面「flow はヒープを使わない」は、静的な値しか作らない `par~` では実際に確保が起きないので、書き手に誤った理由を示す。
  - 修正候補: どの案も候補を出さない（直し方が一つに決まらない）。当て続けると `no-candidate` で止まる。
  - 通るプログラム: (a) は変えない。(b)〜(d) は今通る名前の無い `par~` の Copy でない結果を誤りにする。`tests/`・`std/` に当たる正例は無い（`text_in_a_par` は `let` の E0810 で、同じ行に出る）。
  - 規則と例外: (a) は破棄の要らない値の一覧に flow だけの形を一つ足す（§5.4 は fn の世界の定義なので、§11.5 に置くなら flow の側に別の一句）。`par~` は `[e; N]` と揃い、インスタンスと遅延（Copy を要する）とは揃わない。
    (b) は E0805 の「作る式」の三種に四つ目を足す。確保の無い値を確保の規則で誤りにする。(c) は E0810 の列挙に一句で、`par~` は `[e; N]` と揃わず、インスタンスの出力と揃う。
    (d) は E0810 の列挙を「名前と境界の値」と「flow の構文が作る値」の二つにまとめ、R-458 の根拠（§12.4 の状態の値型）と同じ文に置く。
  - 実装の量（W7-14）: (a) は、S-1043 の所有の行のリテラルの判定（`binding::no_drop`）が `par~` を破棄の要らない値に数える約 +5〜10 行（`Some((par~ … { "a" })[0])` を所有の行にしないため）。
