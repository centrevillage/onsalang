# S-1130 遅延の第 1 引数の中の修飾子の条件に `^名前` を書けるか（`prev~(lp~(x).when~(^c))`。§11.2 は利用者の flow の引数だけを禁じる）

- 決定済みで戻さないもの: `^名前` を書ける範囲（S-116: 遅延の第 1 引数の中だけで、その中の利用者の flow の引数は E0801）、S-117・S-395・S-1107。
  下書きの全文は `target/notes/179/g117/draft.md` の「S-1130」の節、入力は `probe/caret.txt`（出力 `probe/mine_caret/`）と `adv/probe_caret/`。
- 論点: 第 1 引数の中のインスタンスに付けた修飾子の条件（`prev~(lp~(x).when~(^c))`、`prev~(prev~(x).reset_if~(^c))`）は、利用者の flow の引数でも遅延の第 1 引数そのものでもなく、§11.2 の字に無い。
  閉路は外の遅延で切れる。`let a = prev~(lp~(x).when~(^c))`・`let c = a > 0.0` は、`let a = prev~(^l)`・`let c = a > 0.0`・`let l = lp~(x).when~(c)` と全ての刻みで同じ値になる。
- 今の実装: 名前の段の `arg_reach`（`crates/onsa_sema/src/names/body/flow_order.rs`）は修飾子の引数を外の到達のまま歩くので、遅延の第 1 引数の中の条件の `^c` は E0801 にならず、`.when~`・`.reset_if~` の E0200 で止まる。遅延の外の `lp~(x).when~(^c)` は E0801（候補は `prev~(` の挿入）、`prev~(lp~(^a).when~(c))` は E0801。
- 案: (1) 字のとおり書ける。(2) E0801（修飾子の引数も利用者の flow の引数と同じ。修正候補は無く、note で修飾子の呼び出しを `let` に出す形を示す）。(3) 受け手で分ける（利用者の flow なら E0801、組込みの遅延なら書ける）。
- 他言語: Faust の `~` は帰還に 1 サンプルの遅延を暗黙に入れるので、遅延の位置を書き手が置く規則が無い。条件の位置の規則を持つ言語は見つからない（未確認）。
- 推奨と理由: 下書き（onsa-gap）も段 1・段 2 の助言も (2)（確度 中〜中高）。§11.2 の理由（遅延を閉路を切る所に明示し、ほぼ同じ帰還を二通りに書けるようにしない）がそのまま当たる。(3) は同じ形の答えが受け手の種類で変わる。今は全て E0200 なので、W7-10 で開く前に決めれば壊すものは無い。
- 影響: 仕様 §11.2（43・52 行の「利用者の flow の引数」を「インスタンスの引数と修飾子の引数」に）。診断は E0801。作業は W7-10（名前の段の `arg_reach` と事例。+10〜25 の見当）。S-1209 の選択には依らない。
