# S-656 頭の `_` の後に英字が無い名前（`_0`）を、字面で種類を決める所でどう読むか（`let _0 = 1` は束縛の E0320 か解決の E0302 か、`[_0]` は型パラメータか効果行変数か）

- 空白: §2.3 は、字面で種類を決める所は頭の `_` を飛ばした最初の字で読むとするが、`_` の後が数字の名前（`_0`）には字が無い。§8.1 は `[…]` の小文字で始まる名前を効果行変数、大文字で始まる名前を型パラメータとし、§7 は `snake_case` の名前を束縛とする。
  読みは、(1) 小文字でないので束縛でなく、`[…]` では型パラメータ（`let _0 = 1` は E0302「cannot find `_0`」、`[_0]` は型パラメータの E0320）、(2) 大文字でないので束縛か効果行変数と読み、E0320（候補なし）、に割れる。どちらも受理はせず、違うのは診断のコードと文面だけ。宣言の位置（`struct _0`、引数の `_0`）は種類が決まっていて E0320（候補なし）。
  `_` だけからなる `__` も同じく頭の `_` の後に字が無い（`let __ = 1`・`match n { __ => … }` は E0302、`[__]` は E0320 で候補なし。W4-14 U3 の壊す側）。
  仮の扱い: (1)（W4-14 U3 の実装、`crates/onsa_syntax/src/naming.rs` の `SPEC-GAP(S-656)`）。
