# S-656 頭の `_` の後に英字が無い名前（`_0`）を、字面で種類を決める所でどう読むか（`let _0 = 1` は束縛の E0320 か解決の E0302 か、`[_0]` は型パラメータか効果行変数か）

- 空白: §2.3 は、字面で種類を決める所は頭の `_` を飛ばした最初の字で読むとするが、`_` の後が数字の名前（`_0`）には字が無い。§8.1 は `[…]` の小文字で始まる名前を効果行変数、大文字で始まる名前を型パラメータとし、§7 は `snake_case` の名前を束縛とする。
  読みは、(1) 小文字でないので束縛でなく、`[…]` では型パラメータ（`let _0 = 1` は E0302「cannot find `_0`」、`[_0]` は型パラメータの E0320）、(2) 大文字でないので束縛か効果行変数と読み、E0320（候補なし）、に割れる。どちらも受理はせず、違うのは診断のコードと文面だけ。宣言の位置（`struct _0`、引数の `_0`）は種類が決まっていて E0320（候補なし）。
  `_` だけからなる `__` も同じく頭の `_` の後に字が無い（`let __ = 1`・`match n { __ => … }` は E0302、`[__]` は E0320 で候補なし。W4-14 U3 の壊す側）。
  仮の扱い: (1)（W4-14 U3 の実装、`crates/onsa_syntax/src/naming.rs` の `SPEC-GAP(S-656)`）。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: 既存 §2.3・§7、X）パターンに書いた名前は、大文字で始まらない名前（頭の `_` を飛ばして読む。`_0`・`__` を含む）を束縛と読み、大文字で始まる名前を解決する（§7 の文の言い直し。有効な名前では今の文と同じ読みで、違うのは英字の無い `_0`・`__` だけ）。`let _0 = 1`、`match n { __ => … }` は束縛で、宣言の位置の命名の E0320（§2.3 の「規則に揃えた名前が識別子にならないときは候補を出さない」により候補なし）。`[_0]` は今のまま効果行変数の E0320。
  - 仕様の節: §7 のパターンに書いた名前の項（一文の言い直し）。
  - 今通るプログラム: 変わらない（今は E0302「cannot find」）。
  - 実装の見当: 名前の段のパターンの名前を束縛か解決かに分ける条件を「大文字で始まるか」にする（5〜15 行）。
  - ぶつかる事例: なし（`git grep` で `let _0`・`__ =>` の事例は見つからない）。
- 経緯: 63 回目（2026-10-24）、W4-14 U3 の実装の担当とテストの担当がそれぞれ空白として報告し、組 52 の反映の文書の点検も同じ形を挙げた。関係: S-650、S-648、S-651、R-168。
- 補い（2026-11-09、親）: 今は（dev `5d5cd987`）`let _0 = 1` が宣言の位置なのに E0302「cannot find `_0`」になる（§2.3 の「`_0` は候補を出さない」は宣言の誤り（E0320）を前提にしている）。128 回目の独立の検討が見つけた。
