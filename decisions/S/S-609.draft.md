# S-609 Copy の変数を `move` の引数に渡す印の非対称（直接の `tk(move n)` と腕の `tk(if c { n } else { 0 })`）

- 決定済みで戻さないもの: S-605（族の規則。場所でない被演算子は位置によらず modes の E0711、新しい値と Copy のリテラルは `move` 無しで `move` の引数へ）。S-100（消費する位置のブロックの腕は `let y = <腕の値>` と同じに扱い、Affine の変数には書く）。
  §5.2 の Affine の扱い（E0703・E0711）、借用している Affine 値の E0711、`move self` に印を付けない、Dup の `move` は複製。§5.4 の束縛の種類。既定のモードの関数型の引数の E0710（S-190）。
- 略記: `tk` は `move x: U32`、`ts` は `move x: Str`、`take` は `move x: Buf[F32]`、`ap` は `move f: fn(I32) -> I32` の引数を取る関数。`eat` は Copy の struct `P` の `move self` のメソッド。`put` は `[T](move x: T)`。
  `n`・`m` は `U32`、`h` は Copy のフィールド `n` を持つ struct、`s` は `Str`、`a`・`b` は `Buf[F32]`、`f` は関数値の変数、`inc` は関数の項目。「腕」は `if`・`match`・ブロック式の末尾。

- 論点: §5.2 の表は `move` の引数の呼び出し位置を `f(move x)` とし、「`inout` と `move` は呼び出し位置にも書く。読み手は呼び出し 1 行で、何が変わるかを知る」と書く。Copy の値も「借用している Dup 値（Copy か Shared）を `move` 引数に渡すと、その場で複製して渡す」とし、例は `make_op(1, move inc)` である（4〜9 行）。
  S-100 の段落は、消費する位置に置いたブロックの各腕を `let y = <腕の値>` と同じに扱い、「新しく作った値と Copy の値には書かない」とする。`let` では Copy の変数に `move` があってもなくてもよい（16 行）ので、腕では `tk(if c { n } else { 0 })` も `tk(if c { move n } else { 0 })` も正しい形になる（5 行）。
  直接の形は一つ（`tk(move n)`）、腕の形は二つで、書き手が直接と腕を行き来すると印の有無が変わる。S-100 の文は Shared の変数（8 行）と関数値の変数（9 行）を名指ししない。
  - `move` の引数での `move` の観測できる効果は「以後使えない」ことだけである（§5.2 の `move self`。`let` などの位置の Shared では、借用束縛と所有の束縛を分ける、16・17 行）。Dup の値の `move` は複製なので、`tk(move n)` の後も `n` を使える（`tests/spec/values/move_assign.onsa` の「the caller keeps its value」）。
  - `onsa fmt` は `move` を取り除かない（§5.2 の末尾。`move` の後ろが場所かは名前の段で決まる）。値の種は型の段で決まるので、どの案でも、印を揃えるのは fmt でなく検査である。
  - §5.2 の「値が呼び出しの外へ出る側に印が付く（P10）」は、関数型の引数の宣言（`move f: fn(...)`）の印の理由として書かれている（S-190）。呼び出し位置の `move inc` は、S-190 の解説で代償として挙げた形である（`history/spec-gaps-w1.md` の S-190）。
- 今の実装: 表の「今の実装」の列のとおり。`move` の引数は、値の種によらず、直接の `move` の無い場所を E0703（候補は `move ` の挿入）にし、腕は印の有無によらず全て E0703 で、候補は外に `move ` を足す形（S-605 では E0711 になる形）。
  `let` などの位置では、Copy と Shared の変数は印があってもなくても通る。関数の項目は `let y = move inc` が E0711 で、`ap(move inc)` は通る（R-198 と同じ根）。

- 案: どの案でも、Affine の扱い（1〜3・20 行）、`let` などの位置の Dup の `move`（16〜19 行）、場所でない値（S-605）は変えない。違いは、`move` の引数に置いた Dup の場所（4〜9・14 行）の印である。
  (a) 引数のモードで決める。`move` の引数では、直接も腕も、場所に値の種によらず `move` を書く。場所でない値には書かない（S-605）。S-100 の「Copy の値には書かない」は、`let` などの位置の腕と、`move` の引数の腕の Copy のリテラル・新しい値の文になる。
  - 誤りと候補: 印の無い場所は直接も腕も E0703 で、腕ごとに一件、候補はその場所の前への `move ` の挿入。`tk(move if c { n } else { 0 })` の E0711（S-605）は、外の `move` を消して各腕の場所に `move` を置く候補にすると一回で直る（Affine の変数だけに置くと、次に E0703 の挿入で二回）。
  - 収束: 候補は印を足すか消すかで、同じ位置に戻す候補は無い。意図は一つに決まる（値は変わらない）。
  - 実装: modes の `move` の引数の判定は場所かどうかだけで、値の種を見ない（今の直接の判定のまま）。腕の判定は位置ごとに分ける（引数は場所、`let` などは Affine の場所）。E0711 の候補の置き先を位置で選ぶ（数行）。事例は約 3 件（Copy と Shared の腕の否定例と正例）。
  - 費用の要因: Copy の値に効果の無い印が付き、`tk(move n)` の後に `n` を使える。`let` の腕（`let y = if c { n } else { 0 }`）と引数の腕（`tk(if c { move n } else { 0 })`）で印が違う。第 2 期に `[T: ?Dup](move x: T)` の総称の API（受け渡しの口など）が増えると、Copy の値の変数の引数にも全て `move` が付く。
  (b) 値の種で決める。`move` の引数では、Affine の場所にだけ `move` を書き、Dup の場所（Copy、Shared、関数値の変数、総称の Dup の `T`）には書かない。書けば誤り。
  - 誤りと候補: Dup の場所の `move` は E0703（新しい文面「値は複製されるので `move` を書かない」）で、候補は `move` を消す形。Affine の場所の印の無い形は今の E0703（挿入）。腕も同じで、腕ごとに一件。
  - 収束: 消すか足すかで収束し、意図は一つに決まる。型の段に誤りのある本体では modes を走らせない（S-605）ので、種の分からない値で揺れない。
  - 実装: E0703 の判定に値の種を足す（直接と腕の同じ述語、約 10〜15 行）、消す候補と文面（約 10 行）。事例は約 4 件。今の事例の書き換えが約 5 行（下の「影響」）。
  - 費用の要因: 呼び出し位置の印が、引数の型の種（構造で決まる）に依る。struct に `Buf` のフィールドを足すと全ての呼び出しに印が要り、外すと全ての印が誤りになる。`let y = move n` は通り `tk(move n)` は誤りになり、同じ `move n` が位置で分かれる。読み手は `tk(n)` から `tk` の引数のモードを読めない。
  (c) どちらも受理する。`move` の引数の Dup の場所は、`let` などの位置と同じく印があってもなくてもよい（`move` の引数を他の消費する位置と同じ規則にする）。
  - 誤りと候補: Affine の場所の印の無い形だけが E0703（挿入）。収束し、意図は一つ。
  - 実装: 直接の E0703 の判定に値の種を足して Dup を外す（約 5 行）。事例は約 3 件。
  - 費用の要因: 一つの意味に二つの書き方が残り、fmt は種を知らないので揃えられない。§0.5.1 の「受理するが書かない」の一覧に足すか、仕様の例と std の書き方を決める規則が要る。
  (d) 種の中で分ける。例: Copy の値（関数値を含む）には書かず、Shared の場所には書く。または、関数値の変数にだけ書き（保存されることを示す）、他の Dup には書かない。
  - 誤りと候補、収束は (b) と同じ形。実装は (b) に種の分かれ目を一つ足す（約 5 行）。費用の要因: 規則が一つ増え、分かれ目の理由を Onsa の言葉で示す必要がある（Shared の複製は参照数の増加で、P10 の注意の一覧に無い）。
  (e) 今の文のまま。直接は値の種によらず場所に `move` を書き、腕は S-100 のとおり `let` と同じ（Dup の場所は印があってもなくてもよい）。
  - 誤りと候補: 直接の印の無い場所は E0703（挿入）、腕は Affine の変数だけ。収束する。実装: 直接と腕で述語が二つ（W4-09 の S-100 の腕の判定のまま）。事例は約 2 件。費用の要因: S-609 の非対称が残り、腕に二つの書き方がある。

- 推奨と理由: (a)。確度: 中。
  - 呼び出し位置の印が、呼ぶ関数の宣言だけで決まる。書き手も検査も、引数の型の種を調べずに印を決められ、struct のフィールドや総称の境界を変えても呼び出し位置の印は変わらない。(b)・(d) は印が値の種に依り、種は構造で決まるので、型の編集が離れた呼び出しへ波及する。
  - 腕は置かれた位置を継ぐ（S-100）ので、`move` の引数の腕は直接の `move` の引数と同じ規則になる。直接と腕で印が揃い、一つの意味に書き方が一つになる。(c)・(e) は二つの書き方を残し、fmt では揃えられない。
