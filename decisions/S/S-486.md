# S-486

- 空白: 括弧に接する前置の `~(` の中に `_` がある形（FAUST の帰還 `x + ~(_ * 0.5)`）。R-202 の読み（`~(a)` は `!(a)` の候補）では `!(_ * 0.5)` の候補になり、`_` は式の位置では型付きホール（E0421）なので、候補は必ず誤りを残す。
  仮の扱いは、括弧の深さ 0 に `_` があれば `faust_bit_not` に当てず一般の E0002（誤った候補が出うる形は候補なしとしてきた判断、S-400・S-466 に揃える。`foreign/faust.rs` の `SPEC-GAP(S-486)`）。前置の積み重ねの中の `_`（`~-(_)`）には今も候補 `!(-(_))` が出る（W3 の終わりの持ち越し）。
  W3-23/b が見つけた（2026-10-13）
- 提案: 決定（2026-10-13、利用者。確認だけ）: FAUST の文法の形は対象にしない（`rules/criteria.md` 7.32）。今の扱い（括弧の深さ 0 に `_` があれば `faust_bit_not` に当てず一般の E0002）は害が無いので残し、`foreign/faust.rs` の印を対象外のコメントに改めた。前置の積み重ねの中の `_`（`~-(_)`）は直さない
- 時期: W3
