# S-1077 族: 導くクロックと修飾子の比

- 決定済みで戻さないもの: 修飾子の N が定数式で 2 以上の 2 のべき乗であること、定数でないものの E0417、値の範囲の E0808（行 1〜6、S-566 の A4、S-565 の B9、S-132）。入れ子の比の積の上限 2^24（S-566 の A4）。
周期の被演算子が揃うこと（行 35、S-567 の K3）、`at` は遅い→速いで行き先は本体の `sample` まで（S-567 の K3）、同じ位置のイベント・遅い刻み・`sample` の順（行 41、S-578）。一番外の flow の E0810（行 34、S-574）。
- 論点: §11.9 は修飾子の N を「2 以上の 2 のべき乗の定数式（違えば E0808・E0417 の類）」とし、§11.3 は導くクロックの N を書くだけで種類を書かない。§4.5 の定数式の型の位置の一覧には、どちらの N も無い。
  §11.3 の順序は `sample / N` を一つの段として並べ、比の違う `sample / N` どうしの大小を書かない。§11.9（S-578）は同じ位置の遅い刻みと `sample` の刻みの順を書くが、遅い刻みどうしの順を書かない。
  一つの規則で決める論点は三つ: N の期待型とコード（表の行 7〜10）、導くクロックの N の形と制約（行 16〜23）、比の違う周期のクロックの大小と同じ位置の順（行 36〜39）。
- 今の実装: 構文が無いので、どの形も E0002（導くクロック）か E0812（修飾子）で止まる（表の「今」の欄）。
  比べに使える既にある位置は遅延線の長さで、`2.0`・`true` は E0401、`I32` の定数は E0401 と候補「make `K` a `U32`」、`-2` は E0401、`4294967296` は E0408、入力とローカルと呼び出しは E0417（`cases2.txt`・`cases3.txt`）。
  クロックの表現は `crates/onsa_sema/src/ty.rs` の `Rate`（`Init`・`Ctl`・`Sig` の三つ）と `flow.rs` の `FlowRate`（定数を足した四つ）で、比を持たない。`types.rs` の `parse_clock` は `at` の後ろの名前一つだけを読む。
- 案: 比の値（S-969、S-1078 の N）と、順（S-1079）の二つに分けて並べる。どちらの組み合わせもありうる。
  - 比の値:
    - (a) 一つの種類の値にする: 修飾子の N と導くクロックの N はどちらも §4.5 の大きさを表す位置に加え、期待型 `U32` の定数式として検査する（E0401・E0408・E0417・E0419 は今の規則のまま）。値は 2 以上の 2 のべき乗で、違えば E0808。
      周期の刻みのクロックは「本体の `sample` × 2^k」の一つの尺度に並び、合成は指数の足し算になる。
      費用の要因: §4.5 の一覧に一句。導くクロックの N を名前の段と型の段に通す配線（入出力のクロックが定数の評価の後に決まる）。同じ比を値で比べる（`K = 4` の `sample / K` と `sample / 4` は同じ）。
    - (b) 導くクロックの N を整数のリテラルだけにする: 修飾子の N は決定のまま定数式で、導くクロックの N は構文の段で整数のリテラルだけを読む。他は (a) と同じ（`U32`、2 以上の 2 のべき乗）。
      費用の要因: 比を書く位置のうち、導くクロックだけが定数の名前を受けない例外が一つ増える。`(sample / K)` と `(sample / 2.0)` のコード（構文の段の E0002 か、型の段の E0401 か）を別に決める。
      同じ比を `.up~(OS)`・`[F32; OS]`・`at (sample * 4)` と名前とリテラルで書き分けることになり、比を変える書き換えで宣言の字が残りうる（型の段の配列の長さか、呼び出しのクロックで検出はされる）。
    - (c) 導くクロックの N を 2 のべき乗に限らない: 導くクロックの N は `U32` の定数式で 2 以上なら何でもよく、修飾子の N は決定のまま 2 のべき乗。
      費用の要因: S-565 の B9 の閉じ方が崩れる。`dws3(x: F32 at sample) -> F32 at (sample / 3)` を `.up~(2)` で呼ぶと出力は呼び出し側の 2/3 で、受けるクロックが無い。
      閉じない組み合わせを誤りにする規則を足すか、有理数の比のクロックを入れるかが要る。同じ位置で動く遅い刻みの集まりが入れ子にならない（3 の倍数と 2 の倍数）。
  - 順（比の違う周期のクロックの大小と、同じ位置の刻みの順）:
    - (p) 比で決める: 順序の `sample / N` は N が大きいほど下（`sample / 4 < sample / 2 < sample`）。同じ位置の遅い刻みは、遅い方（N の大きい方）から並ぶ。
      S-578 の「イベント、遅い刻み、`sample`」は、この順の続きとして読める（低い段を先に評価し、高い段が最新の値を読む）。
      費用の要因: §11.9 の同じ位置の順に、遅い刻みどうしを比の大きい方から並べる一文が要る。同じ位置で、速い方の刻みが遅い方の刻みの新しい値を読む向きに固まり、後から順を変えると値が変わる。
    - (q) 速い方から: 大小は (p) と同じだが、同じ位置の遅い刻みは N の小さい方から並ぶ。
      費用の要因: 順序（`at` の向き）と段の順が `sample / N` の間だけ逆になる一文が要る。下の例の `b` は同じ位置の前の `a` を読み、`a at sample` は新しい `a` を読む。
    - (r) 依存の順で決め、依存の無い刻みどうしは決めない: 同じ位置で値を読む道（遅い→速いの `at`）がある刻みは読まれる方を先にし、他は決めない。
      費用の要因: 依存の無い刻みでも、別の入力のイベントの順（S-567 の E4 の (補)、`reset_if~` の条件と畳み込むイベントが別の入力から来る形）で結果に出うる。変換先（インタプリタと C、後の JS / WASM）の間で順が揃う約束が別に要る（§13.4）。
  - 例（行 36 と 39 の形。`p` は `block`）:

    ```onsa
    flow g(p: F32 at block) -> F32 at sample {
      let a = prev~(p at (sample / 4))   // 4 サンプルごとの一つ前
      let b = prev~(a at (sample / 2))   // 位置 c（4 の倍数）で読む a は、c で新しくなった値か c − 4 の値か
      b at sample
    }
    ```

    (p) では `b` の刻みは位置 c で新しい `a` を読む。(q) では c − 4 の `a` を読み、同じ位置の `a at sample` だけが新しい `a` を読む。(r) では読む道があるので (p) と同じになる。
- 他言語: 手元に処理系が無く、どれも動かしていない。文書とソースの写しから読んだ。

  - SuperCollider（<https://doc.sccode.org/Classes/ServerOptions.html>）: 制御のレートはサーバの `blockSize`（既定 64）で決まり、言語の値や型に比は無い。2 のべき乗の制限の文は無い。Halide は未確認。
  - 比をクロック（または処理の単位）の性質にし、値の型にしない点はどれも同じである。同じ時点の遅いレートどうしの評価の順を文書で決めている例は、読んだ範囲に無い。
- 推奨と理由: (a) と (p)。確度: 中（(a) の期待型と 2 のべき乗、(p) は高。定数式とリテラルの分かれ目は中）。
  比の値を一つの種類にすると、N の誤りは遅延線の長さと同じ文面とコードになり、書き手は一つの規則を覚えればよい。`.up~(N)` の部品の中で `sample * N` の入出力が `[T; N]` に見えるので、導くクロックの N は実際に配列の長さであり、大きさの位置に入れるのは字面でなく中身で揃う。
  期待型を `U32` 以外の整数に広げると、§4.5 のどの位置にも無い規則が一つ増える。2 のべき乗を導くクロックにも当てるのは、修飾子だけに当てると、変換の flow の宣言の比を通して §11.9 の「閉じる」が崩れるからである（案 (c) の例）。
  (b) は後で (a) へ緩められ、W7 の構文は少し軽い。ただし W7 では算術が W9-03 まで E0200 なので、(a) が W7 で足すのは定数の名前を引く分だけで、その引き方は遅延線の長さに既にある。
  (b) は比を書く位置のうち一つだけを例外にし、将来 flow が const パラメータを持ったとき（総称の flow は §19.1 の未決）に `at (sample * N)` を書けない形を残す。
  順は (p) を推す。同じ位置の依存は遅い→速いの向きにしか無い（速い→遅いは過去の N サンプルを集める変換の flow だけ、S-578）ので、(p) の順はどの依存とも食い違わない。
  (p) では、部品の位置は合成した比だけで決まる。`.down~(4)` の部品と、`.down~(2)` の部品の中の `.down~(2)` は、どちらも `sample / 2` の本体より先に動く（行 40 は S-578 を部品の本体に当てると既に中が先）。
  (q) では、この二つの順が、同じ比なのに書き方で分かれる。(r) は依存の無い刻みの順を変換先に任せ、イベントの順を通して結果に出うる。
  W7-02 の設計メモには、周期の刻みのクロックを一つの符号付きの指数（本体の `sample` が 0、`sample / 4` が −2）で表す形が効く。順序は指数の比べ、修飾子と宣言の合成は足し算、同じ位置で動く遅い刻みは「c を割る 2^k」の連なりになる。
  (c) を採ると、表現は有理数の比になり、W7-16 の段の並びと後の変換先（W8 の Core の作り直し、JS / WASM）が入れ子でない格子を扱い続ける。
