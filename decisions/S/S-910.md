# S-910 E0304 の相手になった型の名前の後のメンバを使う所の扱い（§18.1 の空間の一覧）

- 空白: §18.1 は「E0304・E0305 になった名前も、その空間（本体、モジュールの名前空間、経路の頭、§15.1）では、使う所と他のモジュールの経路はどちらの宣言も引かず、その名前を誤りとして扱う」と書く。括弧の一覧に型の名前の後の `.` の空間（§6.2）が無い。
  実装は固有のメンバどうしの重なりで既に同じ扱いである（`impl P { fn make() -> I32 }` と `impl P { fn make() -> Bool }` の後の `P.make()` は E0304 の一件だけで、使う所は黙る。`modules.clashed_assoc`）。
  S-851 で derive が作るメンバも同じ空間に入ったので、`struct P: Default` と `impl P { fn default() -> I32 }` の後の `P.default()` の扱いが要る。親の読み: 同じ扱いで、使う所はどちらも引かず黙る。§18.1 の括弧に「型の名前の後の `.` の空間（§6.2）」を足す。
