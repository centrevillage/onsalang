# S-1068 細部: 関数の引数・返り値・定数・flow の入力の型が E0416（境界の誤り）のとき、フィールドと同じく誤りの型にして使う側の診断を出さないか

- 空白: §18.1 は「誤りのある宣言も、名前まで読めれば名前解決に見せる。読めなかった部分（引数の型、フィールドなど）は誤りの型として扱い、それを使う側には診断を出さない」とする。
  実装は、構造体のフィールドと列挙子の項目の型が E0416 などの判定の誤りのとき、その型を誤りの型に書き換える（`sig/wellformed.rs` の `unread`。W6-04 U5 の R-464 はこれを宣言の順によらない形にした）。関数の引数・返り値、定数の型、flow の入力の型は書き換えないので、使う側に連鎖の診断が出る。
  判定の誤り（E0416）を「読めなかった部分」に数えるかを書かない。誤りのあるプログラムだけの形で、通るプログラムは変わらない。
  今（W6-04 U5 の後。前も同じ）: `pub fn g(x: Array[Buf[F32]]) -> I32 { 0 }` と `pub fn h(y: F32) -> I32 { g(y) }` は、`g` の E0416 の他に `h` の E0401。返り値・定数の型も同じ（E0401、E0407）。
  flow の入力 `k: Array[Buf[F32]] at init` の E0416 の他に、`fa.Config` を `OC[…]` に渡す構造体に E0416（入力の型を別名 `type AE = Array[Buf[F32]]` にすると、別名が誤りの型になって出ない）。
  再現: `target/notes/153/w604/u5b/sib.txt`（`fn_param_error_call`・`fn_ret_error_use`・`const_error_use`・`flow_input_error_params_in_fn`・`flow_input_error_cfg_user`、`compare.py probe` の形）。
  読み: (1) 判定の誤りの型も「読めなかった部分」とし、引数・返り値・定数・flow の入力もフィールドと同じに誤りの型にする（フィールドと揃う） (2) 「読めなかった部分」は名前や構文が読めなかった部分で、判定の誤りを誤りの型にするのはフィールドと列挙子の項目だけ（今の実装）。
  仮の扱い: (2)（今の実装。`rules/leader.md` 5.11）。
  急ぎ: W6 の区切りで確認だけ。(1) にするなら、書き換える所を署名の段に足す作業が要る（見当は未見積もり）。
- 決定: 決定（2026-11-16、利用者。155 回目、W6 の区切り。確認だけで (2) を了承した後、S-1066・S-1067 の独立のレビューが flow の入力の連鎖を見つけ、改めた形を「上記の通りで進めてください」で了承）: (2) を改めた形。
  境界の誤り（E0416）で誤りの型にするのは、フィールド、列挙子の項目、flow の入力（flow が生成する型のフィールド、§11.6）の型で、関数の引数・返り値・定数の型は今のまま誤りの型にしない（使う側の診断を黙らせない）。仕様 §18.1 の 103 行の段落に書いた。
  理由: flow の入力は生成する型（`fl.Params`）のフィールドで、置き換えないと `pub flow fl(…, p: Array[Buf[F32]] at block)` の後の `struct H { ps: Buf[fl.Params] }` に、入力を直すと消える「`fl.Params` is not Copy」が出る（偽の連鎖。入力 `target/notes/155/s1066/advisor/cases_more.txt` の `v03`）。
  S-1066 の成分ごとの保留に入力を含めて直す。W6-04 U16。
