# S-1261 `onsa test` の `assert` の比べ（`==`・`!=`・`<`・`<=`・`>`・`>=`）が失敗したとき、両辺の値を出す

- 空白: `onsa test` の失敗は `test <名前> failed at <ファイル>:<行>: assert <式のソース>` だけを出し（`spec/tools.md` の `onsa test`、§18.1 の JSON の `message` が約束するのは `assert <式のソース>` だけ）、値を出さない。Onsa には値を表示する手段が無い（`panic(msg)` は補間の無いリテラル、§9.2）。開発の担当は 1 フレームの値をビットごとの `test` で割り出していた（177・182・187・188 回目。X-27 の「値を出す口」）。
  案: 最上位が比べの `assert` の失敗で、両辺の値を `Show`（§6.3）の文字列で出す。読むだけの見積もり `target/notes/190/assertvals/memo.md`（今の仕組み、最小の形、割れる点 P1〜P6、Rust の `assert_eq!`・pytest・Zig の `expectEqual` の出典つきの比べ、W8 との手戻り）。
- 決定（2026-11-26、利用者。190・191 回目）: 採る。`assert` の式が、外側の括弧を除いて比べ（`==` `!=` `<` `<=` `>` `>=`）で、被演算子の型が `Show` を満たすとき、比べに使った両辺の値を出す（§18.1 の `failure` の `left`・`right`、`spec/tools.md` §4 の値の行）。
  190 回目に X-27 で「利用者にとっても有益なので採りたい。ただし、実装量が想定内に収まる場合のみ」とし、親が見積もり（Rust 150〜250 行の条件に、数・`Bool`・`Char` だけで約 100 行、`Show` を実装する型の全てで約 190 行）を示した後、「Show を実装する型で対応で良い」。
  191 回目に第 120 組（下書き `S-1261.draft.md` の G1〜G7、推奨を伏せた独立のレビューと一致）を「記述されている内容で異論はありません」「長い表示をどこで切るか？は基準を決めれば良い」とし、基準と `--json` の扱いの案に「上記の通りでひとまず良いです」:
  - G1 `Show` を満たさない型（`()`、この版の利用者の struct・enum（derive が E0200）、`FixedStr` など）は値を出さず、今の文面だけ。
  - G2 総称の本体では、被演算子の型が境界で `Show` を満たすかで決まる（§4.5。具体化した型では判断しない）。`T: PartialEq + Show` なら出す。
  - G3 長い値は途中で切る。テキストと `--json` の欄で同じ文字列にし、切る長さと印は約束しない。基準は診断の引用（`crates/onsa_diag/src/quote.rs` の 120 字と `...`）を流用する（利用者「コンパイル時のエラー表示なども長い表示を切る処理が入っていた記憶があるので、流用可能かもしれません」）。
  - G4 浮動小数は §6.3 の `Show` だけ（ビットは添えない）。
  - G5 `Char` と `Str` の値は、最上位でも中に入れたときの形（`'a'`）で書く。
  - G6 テキストは値の行があることだけを約束し、形は約束しない（実装は `left: <値>`・`right: <値>` の二行、演算子ごとの言い方は足さない）。条件と欄は §18.1 に書き、`spec/tools.md` §4 はそれを指す。`message` は変えない。
  - G7 中に入れた `Char` のエスケープの細部は S-270 のまま（W8-13 の実装に SPEC-GAP の印、S-270 の補い）。
  - §6.3 の「`{` と `}` は `{{` と `}}`」は `Str` だけに当たる（`'{{'` は E0001。確認だけの直し）。
  - 独立のレビューが挙げた候補: `check` の反例の表示は S-1262（W8-09 の前）、`const` の初期化式の `assert` は S-1263（細部、W9-03 の前）。この版で struct・enum の `Show` の derive を開く案は、機能の一部だけを開くので採らない（親）。
- 経緯: 190 回目（2026-11-26）、W7 の区切りの道具の案の仕分け（X-27、助言の担当）が (B) の族として挙げ、利用者が条件付きで採り、親が読むだけの見積もり（onsa-impl）を回して登録した。191 回目、残りの点を第 120 組として下書きし（onsa-gap）、推奨を伏せた独立のレビュー（段 1・段 2）を経て利用者が決めた。控えは `target/notes/191/g120/`。
