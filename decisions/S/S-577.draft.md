# S-577 std の制御のレートの変換の flow: 方式と、比の名前

- 決定済みで戻さないもの:
  - 制御のレートは `.down~(N)` の部品で書き、N は 2 以上の 2 のべき乗である。パラメータの種類の値は部品へ変換なしに渡せる。
    音声の信号を遅いクロックへ下げるのは変換の flow（速い側を `[F32; N]` で受ける flow を `.down~(N)` で動かす形）だけで、`at` では書けない（E0815）。遅い値を `at sample` で読むと保持（階段）である（S-565〜S-567、§19.1）。
  - 集めて配る時点: 遅い刻みで直前の N サンプルを渡し（`x[N - 1]` が最新）、出力の配列はその遅い刻みから N 刻みに順に配る。集めて配ると N サンプル遅れる（S-566 の A3、§19.1）。
  - flow は型引数も定数の引数も持たないので、比は名前に入る。名前の形はアルゴリズムの名前 + `up`・`down` + 比（`fir_up2`。番号はアルゴリズムの名前の後ろ `fir2_up2`）。std の名前は特別な場合を除き 10 文字以内（S-568 の回答）。
  - std は prelude の外で、グロブの import が無いので、後で std に名前を足しても利用者のコードは壊れない（§15.1）。
  - 線形位相の FIR は制御の信号の変換に使わない（S-568 の回答。ステップの前から動き、遅れが大きい）。音声のオーバーサンプリング（`fir_up2`・`fir_down2`）は S-568 で、ここの論点にしない。
  - 試した入力: 51 回目に dev `4aaa028` の release で試した。入力と出力は `target/notes/51/gap577/probe/`（51 回目の scratchpad の写し）（`p1`〜`p6`、出力は `out.txt`）。
    遅れの数は `probe/sim.py`（Python で上の集めて配る時点をまねた）、F32 の丸めは `probe/lerp.py` で確かめた。終了コードは 0 と 1 だけだった。
- 論点: §19.1「フレームに集めるのは `x: F32 at (sample * 256)` の flow を `.down~(256)` で動かす形、ばらすのは `-> F32 at (sample * 256)` の flow を `.down~(256)` で動かす形で、組込みの変換（`frame~` など）は持たない」。
  §19.1「決めていないこと: std の変換の flow（名前、フィルタの係数と演算の順、§13.4 のビット一致。S-568）」。S-568 は音声のオーバーサンプリングだけを決め、制御のレートの変換の一覧が無い。
  §13.4「超越関数を通らない出力はビット一致…判定は flow 単位で…超越関数のプリミティブに到達する flow は全ての出力を許容誤差で」比べる。
  - (1) 下げる方式（音声 → 制御）と上げる方式（制御 → 音声）。上げる側は変換の flow の形と、保持した値を本体の `sample` で均す普通の flow の形がある。
  - (2) 呼び出しの形: 呼び出し側が `.down~(N)` を書くか、std の flow が中に包むか（足した論点）。
  - (3) 置く比の一覧と名前（10 文字以内、方式が名前から分かること）。
  - (4) 遅れと、§13.4 の演算の順。
- 今の実装: 変換の flow と修飾子は未実装で、試せたのは今の誤りの出方と、std の中身に使う関数だけである。
  - `flow avg_down4(x: F32 at (sample * 4))` と `x: F32 at (sample / 4)` は E0002「expected the name of a clock, found `(`」（`p2`・`p4`）。`g~(x).down~(4)` は E0812（`p3`）。
  - `[const N: U32]` で総称の `rt fn` は今も書け、flow の本体から呼べる（`p1`、0）。`mean[N]` は `sum(xs) * (1.0 / N.round_f32())`、`ramp[N]` は返り値の型 `[F32; 4]` から N が決まる。
    `onsa test`（`p5`）で `ramp(0.0, 1.0)` が `[0.25, 0.5, 0.75, 1.0]`、`mean([1, 2, 3, 6])` が 3.0 で通った。`N as F32` は E0411（修正候補は `.round_f32()`）。
  - 保持した値を本体の `sample` で均す普通の flow（`smooth~(g at sample, 0.01)` の `exp` で係数を作る形と、係数 `k` を受ける形）は 0（`p6`）。
- 案: 例の `lf` は呼び出し側の `sample / 32` の値、`x` は `sample` の音声。遅れは `sim.py` で数えた（入力のステップから、出力を `at sample` で読んだ値が動くまでの本体の `sample` の刻み）。
  数は、遅い刻みを同じ位置の `sample` の刻みより先に評価すると置いた（S-567 の A-14 で字の無い所）。逆の順では、数が 1 刻みずれうる（推測。確かめていない）。
  - 下げる方式（変換の flow の本体は遅い刻みで `x: [F32; N]` を受ける）:
    - (d1) 最後の値 `x[N - 1]`。演算が無い。折り返しを止めない。ゲートや段の信号（0 と 1）は値を保つ。遅れは 1〜N（ステップのブロックの中の位置による）。
    - (d2) ブロックの平均 `sum(x) * (1.0 / N)`。和は `xs[0]` から左へ畳む（`std.dsp.sum`）。1/N は 2 のべき乗の逆数で正確なので、`/ N` と同じビットになる。
      遅い側の Nyquist（`fs / 2N`）で −3.9 dB、`fs / N` の倍数に零点。動き始めは 1〜N、届くのは N〜2N−1。ゲートは中間の値（0.5 など）になる。
    - (d3) ピーク `max(abs(x[j]))`。メーターとエンベロープの検出向けで、符号を捨てるので一般の変換ではない。
    - (d4) 一次の低域通過の後に最後の値（係数 1/N で時定数は約 N サンプル、`fs / 2N` で −10 dB）。超越関数を通らない。状態が一つ増え、指数で近づき届かない。動き始めは 1〜N。
    費用の要因: どれも集める N 個のバッファを処理系が置く（(d1) は最後の一つ、(d2) は左の畳みを刻みごとに足していけば同じビットで、バッファを省ける。最適化は実装の選択）。
  - 上げる方式:
    - (u1) 線形の補間（変換の flow。本体は遅い刻みで `x` を受け、`-> F32 at (sample * N)` に前の値 `a` から今の値 `b` へ N 個を配る）。重みは (j + 1) / N（正確）。
      `at sample` の保持から見て同じ刻みで動き始め、N − 1 刻み後に `b` に届く。行き過ぎは無い。パラメータは無い。
      式は最後の要素が `b` に一致する形に固定する: F32 の `a + (b − a)` は `b` に戻らないことがある（`lerp.py`: a = 1000.3、b = 0.001 で 0.0009765625、a = 0.3、b = −0.1 で −0.09999999403953552）。`b − (b − a) * ((N − 1 − j) / N)` なら最後は `b`。
      費用の要因: 配る N 個のバッファ、最初の刻みの `a`（0 から上がるか、`b` から始めるか）を決める。
    - (u2) 一次の平滑（普通の flow `smooth(x: F32 at sample, time: F32 at init)` を `smooth~(lf at sample, 0.01)` で使う）。比を持たないので名前に比が要らず、`block` のパラメータにも使える。
      動き始めは同じ刻み、指数で近づき届かない。時定数を秒で受けると係数に `exp` が要り、使う flow の全体が §13.4 の許容誤差の比べに移る。係数を受ける形（`smooth_k~(…, 1.0 / 32.0)`）ならビット一致する。状態は一つ。
    - (u3) 決めた長さの直線（普通の flow。値の変化を見つけて、長さ `len` の刻みで直線に動く。JUCE の `SmoothedValue` の Linear に当たる）。比を持たないが、格子の位置を知らないので、遅い刻みの途中で変わる値（`block` のパラメータ）との揃え方と、動いている途中の変化の扱いを決める必要がある。状態は三つ（目標、増分、残り）。
    - (u4) 置かない。保持（`lf at sample`）と利用者の flow で書く。
  - 呼び出しの形:
    - (k1) 素の変換の flow を呼び出し側が `.down~(N)` で動かす。`avg_down32~(x).down~(32)`、`lin_up32~(lf).down~(32)`。
      比を名前と修飾子の二か所に書く。食い違い（`avg_down32~(x).down~(16)`）は引数の速さが合わず検査で止まる（S-566 の A5）。上げる flow に `.down~` が付き、`up` と `down` が一つの式に並ぶ。
    - (k2) std の flow が中に包む。遅い側を `at (sample / N)` で宣言し、本体で `priv` の変換の flow を `.down~(N)` で動かす。
      ```onsa
      priv flow avg32(x: F32 at (sample * 32)) -> F32 at sample {
        mean(x) // sum(x) * (1.0 / 32.0)
      }

      pub flow avg_down32(x: F32 at sample) -> F32 at (sample / 32) {
        avg32~(x).down~(32)
      }
      ```
      呼び出しは `avg_down32~(x)`、`lin_up32~(lf)` で修飾子が要らない。S-568 の `fir_up2~(x)`・`fir_down2~(…)` も修飾子なしで呼ぶので、std の変換の flow の呼び方が揃う。
      費用の要因: 公開の名前ごとに `priv` の flow が一つ増える。外の flow の出力 `sample / N` と中の `.down~(N)` の組み合わせを、std の例として検査が通すこと（S-568 の段 1 の補いの「入れ子の読みを仕様の例で確かめる」と同じ種類）。
    - (k3) std には配列の関数（`mean`・`ramp` など、`[const N: U32]` で総称）だけを置き、比ごとの flow は利用者が 2〜3 行で書く。比の名前が std に増えない。書き手（LLM）が毎回変換の flow を書く。
  - 比の一覧と名前（方式の名前は (d1) `last`、(d2) `avg`、(d3) `peak`、(d4) `lp`、(u1) `lin`）:
    - (r1) 32 だけ（48 kHz で 1.5 kHz、0.67 ms）。名前は方式の数だけ。
    - (r2) 16・32・64。名前は方式の数 × 3（(d1)・(d2)・(u1) で 9）。
    - (r3) 8〜256 の 2 のべき乗の全て（6 つ）。名前は方式の数 × 6。3 桁の比で長くなる（`avg_down128` は 11 文字）。
    - (r4) 比の名前を置かず、(k3) の関数で比を総称にする。
    - 長さ: `avg_down32`・`avg_down64` は 10、`lin_up32` は 8、`lp_down32` は 9、`last_down32`・`peak_down32` は 11。10 文字に収める言い換えは `sh_down32`（標本と保持、9）、`snap_down32`（Pd の `snapshot~`、11）など。

- 推奨と理由: (d1) と (d2)、(u1)、(k2)、(r2)。名前は `last_down16`・`last_down32`・`last_down64`、`avg_down16`〜`avg_down64`、`lin_up16`〜`lin_up64`（`std.dsp`）。確度: 中〜低。

- 独立のレビュー（2026-10-22、助言の担当の二段）:
  - 下げる方式 (d)・上げる方式 (u)・呼び出しの形 (k)・比 (r) は一致した。名前、(u1) の式、(u1) の最初の刻みが割れた。
  - (u1) の式: 段 1・段 2 は 2 乗算の形 `(1 − w) * a + w * b`（`w = (j + 1) / N`、`w` と `1 − w` は共に正確）。下書きの `b − (b − a) * ((N − 1 − j) / N)` は有限なら最後が `b` に一致するが、`b − a` が溢れる入力（`a = −3e38`、`b = 3e38`）では全ての要素が無限大か NaN になる。
    2 乗算の形は同じ入力で有限のまま、最後は `b` にビットで一致する（段 1 の `probe/lin.py`）。§11.4 の `vdelay` が同じ理由で 2 乗算の形を選んでおり、std の補間の形を揃えられる。実装の量は同じ。段 2 は直して採る（確認だけ）。
  - (u1) の最初の刻み: 段 1・段 2 は `prev~(x)` の既定値 0 から上がる形。下書きは今の値から始める形。今の値から始めるには最初の刻みを知る状態（`Bool` 一つと分岐）が要る。既定値から始める形は状態を足さず、`delay~`・`when~` の保持・集める配列（S-578 の 2）と同じ「状態は既定値から」の規則に乗る。
    音で分かる違いは `init` と生成する `reset`・`reset_if~` の直後だけで、既定値からなら出力は 0 から N サンプル（32 なら 48 kHz で 0.67 ms）で今の値へ上がり、今の値からなら跳ぶ。段 2 は既定値からを推し、音の違いがあるので利用者の判断に出す（B）。
  - 名前: 段 1・段 2 は `sh_down32`（標本化と保持の略、9 文字）、下書きは `last_down32`（11 文字、特別な場合とする）。意味・実装・音は変わらず、名前の読みやすさと 10 文字の条件の守り方の話なので、利用者の判断に出す（B）。
  - 理由の書き方（段 2）: 下書きの「Pd と SuperCollider の既定のブロックの長さ 64 を含む」「Csound の窓が標準の形」「Csound の `imode` に当たる」は他言語を理由にしている（`rules/criteria.md` 7.1）。結論は同じなので、理由を Onsa の側の文（補間の遅れが 0.3〜1.3 ms に収まる帯、「今の値」と「区間の平均」というパラメータの無い二つ）に置き換える。
  - (k2) の理由の補い（段 2）: std の変換の flow は呼び出し側の `sample` を基準に宣言し、修飾子は利用者の処理にだけ付く。std に無い比は、S-568 の 4 倍と同じく入れ子で書く（入れ子だけは std の flow に修飾子が付く）。
  - 論点の抜け（段 1。段 2 の扱い）:
