# S-1191 細部: `if~` の連鎖の二つ目からの条件にだけ状態を持つものがあり、枝には無い形（`if~ x > 1.0 { 1.0 } else if prev~(x) > 0.0 { 2.0 } else { 3.0 }`）で、条件の E0811 に加えて E0812 も出すか

- 空白: §11.5 は「状態を持つものを枝に含まなければ E0812」と「`if~` の連鎖の二つ目からの条件 … には、状態を持つものを書けない（E0811）」を書き、条件にある状態を持つものを `if~` の E0812 の数えに入れるかを書いていない。
  読み: (1) 条件の状態も数えて E0811 だけ（W7-06 の設計メモ 2.5 の前の形）、(2) 条件は枝でないので E0812 も出る（位置の順で `~` の E0812 が先。`~` を外す候補の後に普通の連鎖の条件の E0811 が残り、前の `let` の候補で止まる。設計メモの補い `target/notes/170/w706/memo2/memo.md` の 1 章の 2.5 の行）。
  仮の扱い: (2)（字のとおり、実装を足さない側。`SPEC-GAP(S-1191)`）。通るプログラムは変わらない。急ぎ: W7 の区切りで確認だけ。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認。「それぞれ推奨案で進めて」）: S-1183 の 1（別の位置に誤りが残る候補も出す）を決めたので、仮の扱いのとおり。E0812 は枝・腕の本体だけを数え、条件・ガードの状態は数えない。
  突き合わせ: 助言の担当が固定のバイナリ `onsa-d02ddee` で再現し、仮の扱いが今の挙動と合うことを確かめた（`target/notes/189/reports/onsa-advisor-a4f41d23ad112f9fe-001.md`）。
- 経緯: 171 回目（2026-11-20）、W7-06 U2/t（onsa-test）が挙げ、親が登録した。
- 補い（2026-11-20、親）: 同じ問いが `match~` のガードにある（ガードにだけ状態を持つものがあり、腕の本体には無い `match~`）。E0812 は腕の本体だけを数える（設計メモの補いの 1 章の 2.5 の行）ので、仮は同じく E0812 も出る。W7-06 U3a で一緒に扱う。W7-06 U2/b（onsa-break）: flow 一つに報告は一つで、位置の順で `~` の E0812 が先に出て、`~` を外す候補の後に E0811 が出る（仮の (2) と合う）。
