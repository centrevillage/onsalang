# S-721 宣言がこの版の E0200 の handler の名前と、extern のブロックのメンバの名前を、他の位置に書いたとき（`let a = hh`・`fn g(x: hh)`・`c_sin(1.0)` は今は黙り、`fn k[T: hh]` は handler を trait と呼ぶ E0200）

- 空白: §15.1 の種類の並び（値、型、モジュール、関数、flow、trait、種の制約、効果、列挙子、定数）に handler が無い。S-713 は「形の全体がこの版に無いもの（`impl Tr for P`、`trait`・`effect` の宣言）は形の E0200 で、中の名前を読まない」とする。
  宣言がこの版の E0200 の handler の名前と、extern のブロックのメンバの名前を、他の位置に書いたときの扱いが書かれていない。読みは二つに割れる。(1) handler の種類を並びに足す（第 2 期の `with h` の位置が要る種類）か、値や関数と数え、extern のメンバは関数として読む。(2) 種類の並びに無い宣言の名前と、E0200 の形の中の名前は、失敗した名前として全ての位置で黙る。
  今の実装（dev `7cd8d17` のバイナリ）: `handler hh: Alloc { }` の後の `let a = hh` と `fn g(x: hh)` は黙り、`fn k[T: hh]` は E0200「user-defined traits as bounds」（handler を trait と呼ぶ）。`extern "C" lib "m" { fn c_sin(x: F64) -> F64 }` の後の `c_sin(1.0)` と `let a: c_sin = 1` は黙る。
  どれも宣言の単位の E0200 だけで、終了コード 1。
  再現は `target/notes/76/g66/probe-s721/`（`handler_pos.onsa`・`handler_value.onsa`・`extern_use.onsa`）。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。78 回目、第 67 組）: (1)・(v2)。
  宣言の形がこの版で E0200 の handler と、extern のブロックのメンバ（`fn` は関数、`type` は型）も、S-719 の trait・効果と同じく名前と宣言のキーワードの種類まで読めるので、その種類の名前として見せ、S-713 の規則を当てる。
  handler は §15.1 の種類の並びと名前空間でない名前に足した（要る位置は `with` の後で、この版では形の E0200）。`let a = hh`・`fn g(x: hh)`・`T: hh`・`uses {hh}`・`hh.y()` は E0308 になり、境界で handler を trait と呼ぶ E0200 は無くなる。extern の `type` を境界に書く `T: CHandle` も E0308 である。
  extern の関数の署名は読めなかった部分で、`c_sin(1.0)`・`let f = c_sin` は誤りの型の値として検査を続ける（(v2)、今の実装のまま）。見出しの読めなかった `fn` の呼び出しと同じ類で、名前が解けない効果の操作 `Ef.op()` は S-719 のとおり止まる。
  `[F32; c_sin]` は E0417（S-713）、`c_sin~(x)` は E0812 と候補（S-590）、不透明型の `CHandle { b: 1 }` は今の E0401「not a struct」のまま（種類の中の形の違い、S-713）。
  仕様は §15.1 の種類の並びと名前空間でない名前の並び、§18.1 の誤りのある宣言の段落、`tasks/diag-codes.md` の E0308 の行に書いた。実装は W4-04 の U8（約 +10〜15 行）。
