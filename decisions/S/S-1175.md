# S-1175 細部: `let` の値そのものである、本体に状態を持つもの（インスタンス、組込みの遅延）の無い `par~` のノードの名前（`let` の名前か、名前の無い節点の `<let>.par_N` か。`let` の値の欄との重なり、R-507）

- 空白: §11.6 は「パターンが名前一つだけの `let` の値が…`par~` の呼び出しそのものなら、そのノードは `let` の名前で呼ぶ」「`let` のフィールドは利用者の名前のまま」とし、§11.5 は本体に状態を持つもの（インスタンス、組込みの遅延）が無い `par~` は状態のフィールドを作らないとする。W7-05 U3 の仮の形（S-1140: 状態の無い `par~` も巻き上げの欄があれば複製の構造体を持つ）では、`let v0: [F32; 3] = par~ i in 0 ..< 3 { p * F32.round_from(i) }`（`p` は `block`）の `v0` を速い段で読むと（サンプルごとの条件の枝、`&&` の右辺、出力の式の枝、`prev~(v0 at sample)`）、`let` の値の欄 `v0` と複製の構造体 `v0` が同じ名前になり内部エラー（R-507）。
  案: (1) 重なるときだけ `par~` を名前の無い節点 `v0.par_0` で呼ぶ、(1′) 本体に状態を持つもの（入れ子の `par~` の中も含む）の無い `par~` は、`let` の値そのものでも常に `<let>.par_N` で呼ぶ（分解する `let`・名前を束縛しない `let` と同じ並び。`let v0 = (par~ …) at block` の今の形と同じ配置）、(2) 重なるときだけ `let` の値の欄を処理系の名前（`v0._value` の類）にする、(3) その `par~` の巻き上げの欄を State の頂の配列にする（80 行超）。
  費用の要因: (1′) は名前の判定（`Namer` の `whole` の表）の一か所で字面だけで決まり、名前は読み方で変わらない。今の写しの改めは interface の `hoist_par_state_names` の `no_node`（`ys` → `ys.par_0`）と Rust のテスト数件、graph は状態の無い `let ys = par~ …` に頂点 `ys.par_0` が一つ増える。(1)・(2) は重なるかが流れ全体の読み方に依り、名前を作った後の解析の結果を名前へ戻す。
  独立のレビュー（170 回目、onsa-advisor の段 1、控え `target/notes/170/s1175/stage1_report.md`）: (1′) を推す（確信 中〜高）。親の伏せた読みも (1′)（`target/notes/170/s1175/s1175_parent.md`）。仮の形を改めて全ての `par~` の巻き上げの欄を頂の配列にするなら (3′) でこの空白ごと消える（S-1140 の確認のときの候補）。§11.6 に足す一句の案は段 1 の報告の 5 章。
  仮の扱い: (1′)（R-507 の直し W7-15 U2b `1fff2a56` で実装した。`SPEC-GAP(S-1175)` は `crates/onsa_sema/src/flow/plan/names.rs` の `Namer`）。急ぎ: W7 の区切りで S-1140 と一緒に確認だけ（`rules/leader.md` 5.11。通るプログラムの値は変わらず、欄の名前だけ）。状態を持つノードの同じ形（`.down~`・イベント）は S-1139（W7-09 の前）で、この形と揃えて決める。
- 経緯: 170 回目、2026-11-19、R-507 の直し（W7-15 U2b/i、onsa-impl）が、名前の形が §11.6 と S-1140 の仮の形を外れるので書く前に止め、親が登録した（原因 `target/notes/170/r507/cause.md`、案 `estimate.md`）。利用者は離席中で、advisor の段 1 に回した。
