# S-410

- 空白: 前置の記号の後の空白と、前置の記号の重ねが同時にある形（`- - x`、`! ! b`、`- -x`）。§2.5 の「前置の `-` / `!` と被演算子の間に空白を空けると E0020」（S-123）と、§3.1 の「前置演算子を重ねるには括弧が要る（`-(-x)`、E0012）」が同時に当たる。
  読みは (1) 空白の E0020 で、空白を除く候補は `--x`（増減の字句）や `!!b` の重ねになって S-236 で落ちるので、候補なしの E0002、(2) 空白の E0020 で、候補は空白を除いて内側を括弧で囲む形（`-(-x)`）、(3) 今どおり E0012 で、候補は空白も除いた `-(-x)`。今は E0012（候補は内側を括弧で囲む形）。
  既存の事例は `tests/spec/fixes/e0012_prefix_spaced.onsa` と `tests/spec/negative/syntax_groups.onsa` の 34 行（`- -x`）。W3-06/i の設計メモで見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて親の案（確認だけ）を了承）: (3)。間に空白を空けた前置の重ね（`- - x`、`- -x`、`! ! b`）は E0012 の一つの誤りで、修正候補は空白も除いて内側を括弧で囲む `-(-x)`・`!(!b)`。§2.5 の前置の記号の後の空白の E0020 は重ねて出さない。
  理由: S-250 の回答の親の整理で「空白を空けた `- - x` は E0012 のまま」と決めており、S-236 の約束（当てた後に同じ段以前の診断を残さない）を満たす候補はこの形だけ（今の `-(- x)` は空白の E0020 を残す）。仕様 §3.1。
  実装は W3-06 の単位 1b（`tests/spec/fixes/e0012_prefix_spaced.onsa` に `.fix1` を足し、`tests/spec/negative/syntax_groups.onsa` の 34 行は E0012 のまま）（読みの補い、2026-10-10、親: 間が改行の重ね（`two(-` 改行 `-a, 1)`）も同じ E0012 の一つの誤りで、候補は改行も除いた `-(-a)`（S-248）。W3-06/b（単位 1b）が見つけた）
