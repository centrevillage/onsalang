# S-1039 所有の見出し（`match move o`、`match f(...)`）のガードで、腕の束縛を消費・変更する形（`Some(b) if eat(move b) => 1, Some(c) => len_of(c)`）

- 空白: §7 は、借用の `match x` のガードで `x` とその一部を変更できない（代入、`inout` への受け渡し、`!` のメソッド、`move` は E0715）とする。所有の見出し（`match move o`、場所でない対象の `match f(...)`。§5.4 で腕の束縛は所有）のガードで、腕の束縛を消費・変更する形を書かない。
  今（`702a4619`）: `match move o { Some(b) if eat(move b) => 1, Some(c) => len_of(c), None => 0 }`（`eat` は `move b: Buf[F32]` を取る）が通る。ガードが偽なら、次の腕 `Some(c)` が、移した後の値を束縛する（R-454）。入力は `target/notes/146/w602/review/r1.txt` の `guard_moves_owned_arm`・`guard_moves_owned_arm_temp`。
  読みの候補: (1) 借用の見出しと同じく、ガードの中で腕の束縛（と見出しのその部分）を消費・変更すると E0715 (2) ガードの中の消費は、ガードが偽の道で次の腕を試さない（字面の順の判定が変わる） (3) ガードが偽の道では束縛を見出しへ戻せないので、消費した後は後の腕が誤り。
  急ぎ: W6-02 の U2 の前（腕とガードの状態、ガードが偽の道で腕の束縛が見出しへ戻る前提）。
- 決定: 決定（2026-11-13、利用者。146 回目、第 101 組。中立の要約と独立のレビューの段 1 が (1) で一致、W6-02 の設計メモの仮の扱いと同じ）: (1)。所有の `match`（`match move x` と場所でない対象、§5.4）のガードでは、その腕の束縛を消費できない（`move`、Affine のフィールドの取り出し、束縛の見出しの `move`、`?` の被演算子、`move self` の受け手、返り値の位置は E0715、修正候補は無い）。腕が選ばれるまで対象の値は一つのままで、ガードが偽なら後の腕が同じ値で判定される。腕の束縛が中身を所有するのは、腕が選ばれた後である。
  変更（代入・`inout`・`!`）は、所有の腕の束縛が書き換えられないので既に E0701（§5.1 に一言足す: `for` と `match` の腕の所有の束縛も書き換えられない）。Dup の値は複製して読むので当たらない。外の場所は今の流れの判定のまま。`Some(b) if eat(move b) => 1, _ => 0`（実行上は壊れない）も E0715 になる。直し方は腕の本体へ移す形（`Some(b) => if try_send(move b) { 1 } else { … }`）。
  理由: 「腕が選ばれるまで対象の値は一つ」の不変条件が一文で立ち、ガードが偽の道に破棄点も部分の移動の状態も生じない（§5.2 はフィールドごとに移動の状態を持たない）。S-623 の読みに依らない。(2) は後の腕の形で合否が分かれ、残りの破棄点が要る。(3) は健全さに要らない。今の木で当たる形は 0 件。
  作業は W6-02 の U2b（`frozen.rs` のガードの枠に腕の束縛を積む、約 30〜50 行。`SPEC-GAP(S-1039)` の仮の扱いと同じ形）。R-454 はこれで直る。仕様 §7（E0715 の文の次）、§5.1（E0701）
