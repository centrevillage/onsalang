# S-304

- 空白: 総称の型の関連定数と関連関数を、型引数を決めずに参照したとき（`Rg.CAP`、`impl[T, const N: U32] Rg[T, N] { pub const CAP: U32 = N }`）。値が型パラメータに依らなくても型変数が残るので E0406 にするか（§4.7 の読み）、依らなければ決めなくてよいか。
  今は `check` を通り、`onsa test` で内部エラー（R-187）。同じ形の列挙子 `E2.B` は E0406。S-239 で `Rg::[F32, 4].CAP` と書ける。第 9 組の下書き（S-239）で見つけた（2026-10-08）
- 提案: W5-05 の前に決める。空白の流れで下書きに回す
- 時期: W5
- 補い（2026-11-02、親）: X-23（W5 の見積もり）で、期限を本文の提案に合わせて W5-05 にした（R-187 のコードを決める）。
- 決定: 決定（2026-11-05、利用者。116 回目、第 87 組。下書きと伏せた独立のレビューが一致。下書きは `S-304.draft.md`）: (b)。総称の `impl` の関連定数を型の名前で読むと、`impl` の型パラメータは関数・列挙子と同じに決める（型引数、別名、期待型の注釈、後の文）。決まらなければ関数の終わりに経路の全体の位置へ E0406。
  値が型パラメータに依らなくても同じで、今通る `Rg.CAP`（`const CAP: U32 = 4`）も E0406 になる。
  細部: 文面は `Rg.cap()` の E0406 と同じ。候補なしで、note に `Rg::[…].CAP`（W5-10 の前は別名）と、`impl` の中では `Self.CAP` を示す。定数式の位置の `[F32; Rg.CAP]` も E0406（実装は W5-16）。型引数が決まったら `impl` の境界を検査する（E0416）。
  宣言の型が型パラメータに依る定数は、列挙子と同じく型変数を立てて期待型と単一化する。見出しが誤りの `impl` のメンバ（`P.R`、`W.K`）は今のまま診断を出さない（§18.1）。
  R-187 は E0406 で閉じる。`R4.CAP`・`Self.CAP` の内部エラー、型の漏れ、境界の不判定は実装の不具合で、同じ作業で直す（R-187 の補い）。
  仕様 §4.5・§4.7。作業は W5-05、定数式の読み手は W5-16。
- 経緯: 第 9 組の下書き（S-239）で見つけた（2026-10-08）。116 回目（2026-11-05）、第 87 組で決めた。関係: R-187、S-239、S-595
