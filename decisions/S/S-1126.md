# S-1126 細部: flow の遅延が保存する式の panic の時期（第二相で本体の全ての `let` の後か、書いた位置の順か）

- 空白: §11.4 は「各サンプルで、全ての遅延の出力（保存値）を先に読み、保存する値 `e` を全て評価してから、まとめて保存する」（二相）とし、§11.2 は `let` を書いた順とする。保存する式が panic するとき、その panic が本体の後の `let` の panic より後か（第二相で評価）、書いた位置の順かを書いていない。
  読みは (1) 保存する式は第二相（本体の全ての `let` と出力の後）で評価し、その panic は本体の panic の後、(2) 書いた位置の順に評価する（panic の順は書いた順）に割れる。違いは panic の位置だけで、値と panic の有無は変わらない。
  再現: `let a = prev~(10 / x)`、`let b = 5 / x`、`x = 0` → 今のインタプリタは `b` の行の「division by zero」で止まる（(1)）。参照評価器（W7-18 U1b）も (1)。入力は `target/notes/163/w718/u1b/probe/order.onsa`。
  仮の扱い: (1)。参照評価器の `state.rs` の `commit` に `SPEC-GAP(S-1126)`。W7 の区切りで確認だけ（W7-07 の遅延の降下と W7-19 の比べで一緒に見る）。
- 決定: 決定（2026-11-25、利用者。185 回目、第 119 組、確認だけ）: (1)（族の規則 S-1233）。遅延が保存する式の残りは段の終わりに評価し、その panic は本体の `let` と出力の後。第 1 引数の中のインスタンスの呼び出し（とその引数）だけは書いた位置。
- 経緯: 163 回目（2026-11-17）、W7-18 U1b のテストの担当（onsa-test）が仕様の空白に挙げ、親が細部として登録した。
