# S-748 別名を対象にした `impl`（E0307）のメンバを、同じ型の直接の `impl` のメンバとの E0304 の相手に数えるか（W4-05 U2 で、前に書いた E0307 の `impl` のメンバとの E0304 が出なくなった）

- 空白: §4.4（92 行）は `impl` の対象に別名を書けない（E0307）とし、§18.1 は E0307 を `impl` の見出しの誤りとしてメンバを検査しない。§6.2 の型の名前の後の `.` の空間の E0304（S-737）に、E0307 の `impl` のメンバを相手として数えるかは書いていない。
  §18.1 の 86 行は「誤りのある宣言も、名前まで読めれば名前解決に見せる」とする一方、失敗した `use` の名前は束縛として数えない（§18.1 の 90 行）。
  読み: (1) 数えない（E0307 の単位のメンバは名前を持たない）。(2) 書いた順に数える。
  今の実装（W4-05 U2 の後、`728ebb7`）: `type A = S`、`impl A { fn f }`、後に `impl S { fn f }` は E0307 だけ（U2 の前の `2296e83` は E0307 と、`impl S` の `f` に E0304）。順を逆にした形は前も今も E0307 だけで、今は順によらず (1) の形。
  再現は `target/notes/79/s748/`（`e0307_first.onsa`・`e0307_last.onsa`・`e0307_two_direct.onsa`）。
- 決定: 決定（2026-10-28、利用者。80 回目、第 72 組。細部は ID を挙げて了承）: (a)。
  見出しが E0307 でも対象の型が決まる固有の `impl` のメンバは、その型の名前の後の `.` の空間（§6.2）の名前に数える（§18.1 の、名前まで読めた宣言を名前解決に見せる規則）。E0307 は書き方の誤りで、どの型のメンバかは一つに決まる。失敗した `use` の名前と違い、指す先がある。
  E0304 は同じ型のメンバどうしの規則のまま（ソースの順で後、列挙子との重なりは `impl` のメンバ、S-737）。E0307 の単位の中に付いた E0304 は単位の規則で隠れる。読む所は全ての位置（本体、署名、別名と定数の型、直接の `impl` のメンバの型、他のモジュールの経路）で、直接の `impl` のメンバと同じに引く。
  細部（確認だけ）: A1 対象の型が決まる E0307 の全て（別名、対象の型引数、孤児規則）に当てる。孤児の形（利用者の `impl F32 { const PI }` が std の `PI` と重なる）の帰結は W5-04 の前に確かめる。A2 別名の右辺が名前の無い型（タプル、配列）なら、メンバはどこにも入らない（今のまま）。
  A3 読む所は、メンバの型（署名）と値（初期化式）を直接の `impl` のメンバと同じに読む。A4 E0307 の `impl` の中の同名も書いた順で数える。A5 仕様は §18.1 の段落に一文と §6.2 の指しで、§4.4 は変えない。
  §18.1 の修正候補の約束は当たらない（E0307 の候補を当てた後の E0304 は、当てる前から単位の持つ誤り）。
  仕様は §18.1 の誤りのある宣言を名前解決に見せる段落と、§6.2 の `.` の空間の文に書いた。`tasks/diag-codes.md` の E0304 の行に足した。
  実装は W4-05 の U3: 署名の段の頭の一度の環で、全ての固有の `impl` のメンバを書いた順に名付け、別名の `impl` の鍵は別名の右辺の経路の頭を下ろさずに辿って決める（差し引き約 +5〜10 行。二度目の `name_members` と `aliased` の分岐を除く）。`SPEC-GAP(S-748)` を外す。
  事例は重なり（E0307 の `impl` が先・後、関連定数、`impl` の中の同名、列挙子）と読む所（本体、fn の署名、別名と定数の型、直接の `impl` のメンバの型、他のモジュール）。
- 経緯: 79 回目（2026-10-28）、W4-05 U2/i2（onsa-impl）が空白として報告した（U2 の `decls.rs::name_members` が直接の `impl` のメンバの名前を先に入れるため）。期限は `impl` のメンバの同名を扱う W4-05 の U3 の前。関係: S-737、S-134、R-307。
