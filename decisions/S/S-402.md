# S-402

- 空白: パターンの選択の他言語の書き方（`0, 1 =>`、`0 or 1 =>`）。今は E0002「expected `=>`, found `,`」と「found identifier」で候補なし。
  Swift の `case 0, 1:` と Kotlin の `0, 1 ->` は選択肢、C# は `0 or 1`、Python 3.10 以降の `case 0, 1:` は列のパターン（読みが割れる。rustc は `0, 1 =>` にタプルにする help と `|` にする help の二つを出す）。E0020 で候補を並べるか。
  第 19 組の下書きで見つけ、Fable が Python の読みを足した（2026-10-10）
- 提案: 後の段（W3-06 の頃か後）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: B6、Y）腕のパターンを `,` で並べる形（`0, 1 =>`）は E0020 で、候補は `0 | 1 =>` と `(0, 1) =>` の二つ（後者は対象がタプルでなければ型の段の E0401 が残る）。一つの腕の `,` の全てが一つの形。C# の `0 or 1 =>` は E0020 で候補 `0 | 1 =>` だけ。`,`・`or` の後にパターンが続かなければ E0002。 `,` と次のパターンが同じ行にあるときだけこの形で、`,` の後で改行する形（`0,` 改行 `1 => 2`）は `=>` の抜けの一般の E0002（腕の本体の書き忘れを黙って選択に直さない、Y）。
