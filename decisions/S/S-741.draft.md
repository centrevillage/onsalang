# S-741 族: §15.1 の型の位置から見える値の束縛

- 決定済みで戻さないもの: 見えているローカルは型の位置で E0308、定数式で E0417（S-729、S-713 (a1)）。fn の本体で見えていない名前は E0302（S-729）。効果行の型・関数の名前は E0308（S-713 (b)）。
  第 69 組の下書きの「族「§15.1 の型の位置から見える値の束縛」の仕組みの出所」と「族の形の表」の節（写しは `target/notes/79/g69/draft.md`）。
- 論点: §15.1「名前は見つかったが、その位置に要る種類でなければ、位置によらず E0308」と S-729 は、本体の型の位置が「見えている」ローカルを引くとしたが、束縛がどこから見えるかは値の位置の規則（§5.1、§11.2）にしか無い。
  値の位置の無い所（署名、無名関数の見出し、`let` の自分の注釈）の範囲と、効果行が型の位置と同じ範囲を見るかが書かれていない。そのため今の実装は、位置の種類ごとに引きが違う（表の S-733・S-738・S-739・S-740 の行）。
  例: 本体の `[F32; n]` は E0417、署名の `[F32; n]` は E0302。無名関数の `-> x` は E0308、同じ見出しの `uses {x}` は E0302。flow の `as a`（後ろに `let a`）は E0308、`let b: a` は E0302。
- 今の実装: 表のとおり。どの形も候補は無い。
- 案: 族の規則の候補は、束縛ごとに一つの範囲を決めて全ての種類の位置（値、型、効果行、型の中の定数式）に当てるか（(a)〜(c)）、位置の種類ごとに決めるか（(d)）である。
  (a)〜(c) は §5.1 に一文を足す: 「束縛は、型の位置（型の中の定数式と効果行を含む）からも、値の位置と同じ範囲で見える。`let`・`var` の束縛はその文の後ろから見える（自分の注釈と初期化式からは見えない）。引数の範囲は…」。違うのは引数の範囲だけで、値の位置からは区別がつかない（見出しに値の式は無い）。
  - (a) 引数（fn・メソッド・無名関数の引数、flow の入力）は本体だけで見える。
  - (b) 引数は見出しの全体（全ての引数の型、返り値の型、効果行、型パラメータの境界）と本体で見える。
  - (c) 引数は、その引数より後ろの見出し（後ろの引数の型、返り値の型、効果行）と本体で見える。自分の型と、引数より前の境界からは見えない。
  - (d) 族の規則を置かず、S-733・S-738・S-739・S-740 を一件ずつ決め、それぞれの位置の文を足す。
  - 形ごとの出力（flow の後ろの `let` は S-740 で、どの案でも別に決める）:

    | 形 | (a) | (b) | (c) |
    |---|---|---|---|

  - 書き手から見て: 当たりやすいのは署名の配列長である。C の可変長配列の引数（`void f(int n, float a[n])`）や Zig の comptime の引数の感覚で、引数で長さを決めるつもりの `fn f(n: U32, a: [F32; n])` を書く。
    E0417「`n` is a local, not a constant: a constant expression names constants (§4.5)」は、一回目で「定数式には定数を書く」を示す（書き手は const パラメータ `[const N: U32]` か `Span[F32]` へ直す）。E0302「cannot find `n`」は、真横に引数 `n` があるのに無いと言い、綴りやスコープを疑わせる。
    名前を足す直し（`const n: U32 = 4`）は、引数と同じ名前の E0304（§5.1、S-717）になり、もう一回の検査が要る。後ろの引数（`fn f(a: [F32; n], n: U32)`）と自分（`fn f(n: n)`）も、(c) では同じ「見つからない」になる。
  - 修正候補: どの案も無い（書き手の要る型や定数は一つに決まらない）。当て続けても `no-candidate` で止まる。

- 他言語: 
  - rustc 1.94.1（`probe/other/r1.rs`・`r2.rs`）: 署名の `fn f(n: usize, a: [f32; n])`・`-> [f32; n]`・後ろの引数の `fn f(a: [f32; n], n: usize)` は

- 推奨と理由: (b)。確度: 中。
  - 引数は呼び出しで一度に束縛され、見出しの型は上から評価されない。`let` は初期化式を評価した後に束縛されるので、自分の注釈と初期化式から見えない。(b) はこの束縛の時機で範囲を決め、値の位置で既に決まっている範囲を変えない。
  - 型の位置がローカルを見ても、見つかる名前が別のものに変わることは無く、通るプログラムも変わらない。見る範囲が広いほど、真横に在る名前の「見つからない」が「使い方の誤り」に変わるだけである。
    (c) の順の制限は、守る通るプログラムが無いまま、後ろの引数と自分の型に「見つからない」を残す。(a) は当たりやすい署名の配列長に「見つからない」を残し、E0304 を経た検査を招きうる。
  - 本体の `[F32; n]` の E0417 と署名の同じ書き方の E0302 の食い違いが消える。差は名前の段に閉じた約 +30〜45 行で、`Cx::locals` は署名にも渡せる形で既にある。後の段にも、第 2 期の効果行変数にも手当てが続かない。
  - 族の規則から決まる件（上の形ごとの出力の表の (b) の列）: S-733 は (1)（見出しの全体）、S-738 は (1)、S-739 は (3)（`let` は E0302、無名関数の引数は見出しの全体で E0308・E0417）。S-740 だけは §11.2 の読みが残るので、下に項目を置く。
