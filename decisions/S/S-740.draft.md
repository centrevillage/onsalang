# S-740 flow の本体の `let` の型の位置で、後ろの `let` の名前を指す前方参照（`let b: [F32; a]` の後に `let a`）は、値の位置と同じ E0801 か、名前の引きの E0302 か

- 決定済みで戻さないもの: 上の `let` と入力は E0308・E0417（S-729）。fn の本体の後ろの `let` は E0302（S-729。fn の値の位置も E0302）。値の位置の前方参照は E0801（§11.2）。
  第 69 組の下書きの「族「§15.1 の型の位置から見える値の束縛」の仕組みの出所」と「族の形の表」の節（写しは `target/notes/79/g69/draft.md`）。
- 論点: §11.2「名前は上から順に定義する。定義より前で（自分自身の定義の中も含む）名前を参照するには `^名前`」「印の無い前方参照は E0801」は、型の位置（注釈、配列長、`as`）で後ろの `let` を指す形のコードを書いていない。
  順の規則を「flow の本体の名前の見える範囲」と読めば、型の位置も値と同じ E0801 である。「値を読む参照の規則」と読めば、型の位置は値を読まず帰還も作らないので当たらず、本体の全ての `let` が見えて、ローカルを型に書いた E0308（定数式は E0417）である。
- 今の実装: 表の S-740 の行（`probe/s740.out`・`more.out`）。注釈は E0302（`walk_flow` の最初のループで、その `let` の名前を宣言する前に集める）、`as` は E0308（全ての `let` を宣言した後に集める）で、同じ型の位置で割れている。
  `let b: ^a = x` は E0002「expected a type, found `^`」、`let b: [F32; ^a]` は E0200「expressions as array lengths」。
  E0801 は今 flow の段なので、前の行の値の位置の前方参照（`let c = a`）より、後ろの行の型の位置の E0302 が先に出る（`value_fwd_then_type_fwd`。W7-04 で E0801 を名前の段へ移すと直る）。
- 案: 
  - (1) 型の位置の前方参照と自分も E0801（値の位置と同じ。note は今の E0801 と同じ「上へ移す」「帰還なら `prev~(^名前)`」）。`as` も E0801 にする。
  - (2) 型の位置は上の `let` と入力だけを見て、後ろの `let` と自分は E0302（注釈の今の形）。`as` も E0302 にする。
  - (3) 型の位置は順を問わず本体の全ての `let` と入力を見て、E0308（定数式は E0417）。`as` の今の形で、注釈を揃える。
  - 書き手から見て（`let b: a = x` の後に `let a = x * 2.0`、「`a` と同じ型」のつもり）: (1) は「下で定義」と言い、`let` を上へ移すと E0308 でもう一回の検査が要る。`^a` を足すと型の位置では E0002 になる。
    (2) は下に `let a` があるのに「見つからない」と言い、上へ移すと E0308 になる。(3) は一回目で「`a` はローカルで型でない」と示す。
  - 修正候補: どの案も無い（(1) の `^` の候補は遅延の第 1 引数の中だけで、型の位置は当たらない）。当て続けても `no-candidate`。
  - 通るプログラム: どの案も変わらない。
  - 規則と例外: (1) は §11.2 の順の規則をそのまま当てる読みで、文を足さない（E0801 の文の「参照」に型の位置を含めると一句）。(3) は §11.2 に「順の規則は値の参照の規則で、型の位置には当たらない」と一句足す。
    (2) は S-741 のどの案とも違う範囲（値の位置は E0801 なのに型の位置は見えない）を足す例外である。
  - 実装の量: (3) は flow の注釈の `site` を、全ての `let` を宣言した後に集める（`walk_flow` の最初のループから二つ目へ移す、約 ±5 行）。W7-04 を待たずに入れられる。
    (1) は `site` に「後ろの `let`」の名前を別に記録し、`lower_types` で E0801 と「defined here」の note を作る（約 +15〜25 行）。E0801 が名前の段へ移る W7-04 の中で入れる（先に入れると、値の位置の E0801 より先に出る）。
    (2) は `as` の `site` を「上の `let`」に絞る（約 +5〜10 行。W7-04 の名前の段の E0801 が要る「ここまでに定義した名前」の集合と同じもの）。
- 他言語: flow の名前の順に当たる規則を持つ言語は 7.32 の一覧に無い。fn の本体の後ろの `let` は rustc 1.94.1 で E0425「cannot find type」（`probe/other/r2.rs`。S-729 の決定済みの形に当たる）。
- 推奨と理由: (3)。確度: 中。
  - §11.2 の順の規則の目的は、帰還を参照の位置で見せることと、因果性の検査を名前の順の検査にすることである。型の位置は値を読まず、閉路を作れないので、この目的に当たらない。一方 flow の本体は一つのブロックで、後ろの `let` も値の位置では「在る」名前（E0801 は見つからないでなく順の誤り）なので、型の位置は S-741 の規則どおりそれを見る。
  - (1) と (2) は、上へ移す直しの後にもう一回の E0308 を招き、(1) の note の `^` と `prev~` は型の位置では使えない。(3) は一回目で使い方の誤りを示す。
  - 実装は約 ±5 行で、`as` の今の形に注釈を揃える向きである。W7-04 の E0801 の移しに依らない。
  - あわせて決めること: flow の `let` の自分の注釈（`let a: a = x`、`let (a, b): (F32, a)`）も同じく E0308 で、fn の本体の `let a: a`（S-739、E0302）と違うのは、値の位置の範囲が fn は文の後ろから、flow は本体の全体（順の誤りは E0801）と違うことから出る。
- 影響: 仕様 §11.2（(3) は順の規則が値の参照の規則である一句、(1) は E0801 の「参照」に型の位置を含める一句、(2) は型の位置の範囲の一文）。`tasks/diag-codes.md` の E0801（(1)）か E0308（(3)）の行。
  作業は W7-04 の前（(3) は名前の段の小さな単位か S-741 と同じ単位でよく、(1) は W7-04 の中）。
  事例 `tests/spec/type_names/body_locals_not_visible.onsa` の 126 行（`name_declared_later_in_a_flow`）は E0302 を期待する。(1) は E0801、(3) は E0308 に改め、(3) では `kind_body_locals.onsa` の flow の節へ移す。(2) は今のままで、`as` の事例を足す。

  理由: §11.2 の順の規則の目的（帰還の可視化、因果性）は信号を読む参照の話で、型の位置は読まず `^a` も書けない（E0002）ので、E0801 の note が型の位置に当たらない。(2) は値の位置で「見つかる」名前が型の位置で「見つからない」例外になる。
