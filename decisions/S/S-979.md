# S-979 族: 式の中の ::[…] の誤りの段とコード

- 空白: 式の中の `::[…]` を、型引数を取らないものや種類の合わない位置に書いた形の全体（関数、型、列挙子、ローカルの束縛と引数、メソッド、フィールド、モジュール、組込みの名前）で、コードと段を決める一般の規則。
  §4.5 の既決の文は、名前の段が宣言を知る形（総称でない関数・flow・型パラメータ・列挙子の名前は E0412、ローカルの束縛と引数は E0308、種類の合わない要素は E0308）を決めている。残る個々の形は S-977（宣言が型の段でしか分からない形）と S-978（モジュールと組込みの flow の名前）。
  段 1（onsa-advisor）の表から足した形: 定数と const パラメータと関連定数（`K::[I32]`、`N::[I32]`、`Rg.CAP::[F32, 4]`、`F32.PI::[I32]`）、`Self`・別名・総称でない型（`Self::[I32]`、`R::[I32].CAP`）、パッケージと子モジュール、効果の名前と操作、型パラメータの境界のメンバ（`T.ZERO::[I32]`）、`panic::[I32]("x")`。
  メソッドの並びの数を超えた要素は S-981。
- 決定: 決定（2026-11-10、利用者。133 回目）: 式の中の `::[…]` の誤りのコードと段は、次の四つで決める。
  (1) `::[…]` の前がその場の値（ローカルの束縛、引数、フィールド）なら E0308。段は、名前が何か分かる段（経路は名前の段、フィールドは型の段、S-977）。
  (2) それ以外で、型パラメータを宣言していない名前なら E0412（宣言は 0 個）。判定は名前の段が持ち、報告は型の段。総称でない関数とメソッド、flow と組込みの flow の名前、型パラメータと const パラメータ、定数と関連定数、列挙子の名前、`Self`・別名・総称でない型、モジュールとパッケージ（S-978）、効果の名前と操作、型パラメータを宣言していない組込みの関連関数と型パラメータの境界のメンバ（`T.ZERO::[I32]`）、`panic` が当たる。修正候補は無い（S-306）。
  (3) 要素の種類の誤りは E0308。段は、宣言が分かる段（関数、型、関連関数は名前の段、メソッドは型の段、S-977）。
  (4) 名前がその位置自体で誤りなら、今ある名前の段の診断が先である（`let m = util::[I32]`、`let p = prev::[F32]`）。
  定数と const パラメータ（`K::[I32]`、`N::[I32]`、`Rg.CAP::[F32, 4]`、`F32.PI::[I32]`）は (2) の E0412 にした（利用者が実装の簡単さと管理のしやすさで選んだ。判定は「型パラメータを宣言しているか」の一つで、値の類の一覧を持たない。既決の型パラメータ `T::[I32]` の E0412 と揃う）。独立のレビュー（onsa-advisor の段 1）は (1) の E0308 を弱く推した。
  仕様: §4.5 の E0412 の列挙を「型パラメータを宣言していない名前」の文にまとめる。W5-10（U1a が名前の段で分かる形、U2b がメソッド）。
- 経緯: 133 回目（2026-11-10）、W5-10 の設計メモ（onsa-impl、U1a/i）が決めていないこととして挙げ、親が固定のバイナリ（dev `f90b68ed`）で再現して登録した。再現の入力は 133 回目の scratchpad の `s977-advisor/probe/`（写しは区切りで `target/notes/133/s977-advisor/`）。
- 補い（2026-11-10、親）: 決定の前の例のうち「組込みの関連関数（`F32.round_from::[U32](k)`）」は誤りだった。std の `round_from[S: AnyNum]` は自身の型パラメータを宣言しているので、(2) の判定（型パラメータを宣言しているか）では関数自身の並びで、E0412 ではない（W5-10 U1a の実装の担当が指摘し、親が `std/core/num.onsa` で確かめた）。判定は変えず、例を外した。
