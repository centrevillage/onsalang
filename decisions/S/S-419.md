# S-419 S-384 の字句の条件と、候補の約束の緊張

- 空白: S-384 の字句の条件（並びの種類ごとの「要素を始められる字句」だけで `,` の挿入を出し、次の要素を試しに読まない）と、S-236 の約束（一つだけの誤りなら、当てた後に同じ段の診断を残さない）の緊張。
  腕の並びの中の `0 => one` 改行 `(1),` は、`(` が腕（タプルのパターン）を始められるので `,` が出るが、当てると `(1),` が腕にならず E0002「expected `=>`」が残る（もう一つの候補の「改行を除く形」は残らない）。
  列挙子の要素の `V(Option` 改行 `[I32])`（タプル型と関数型の引数も同じ）も、`[I32]` が配列の型として読めない（`;` が無い）のに `,` が出て、当てると構文の段の誤りが残る（型引数の `Option[Option` 改行 `[I32]]` は、当てた後に名前の段の E0302 だけが残るので約束に反しない。第 23 組の下書きが直した）。
  逆向きの形もある: 腕の `(0, 0) => one` 改行 `(a, b) => a + b,` では改行を除く候補が、同じ行の `one (a, b) => …` では空白の E0020 の候補が、`=>` の E0002 を残す（第 23 組の下書き）。
  読みは (1) 今のまま（字句の条件を優先し、まれな形は約束の外とする）、(2) 字句の走査で条件を絞る（腕の並びでは次の `,`・`}` より前の深さ 0 に `=>` があるときだけ、型の位置の `[` は中に `;` があるときだけ。S-386 の走査と W3-06 の単位 1a の `Detached::joins` と同じ形）。
  W3-06/b（単位 1a の再確認）で見つけた（2026-10-10。仮の扱いは (1)）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (3) を了承。下書きと Fable が一致、第 23 組。利用者の注意: 例外的な処理なので、副作用を生じないか気を付ける）: S-89 の二つの候補（`,` の挿入と改行を除く形）は、トークンの走査（次の要素を試しに読まない）で読める方だけを出す。
  腕の並びでは、次の深さ 0 の `,`・`}` より前に深さ 0 の `=>` があれば `,` だけ、無ければ改行を除く形だけ。型だけの並び（列挙子の要素、タプル型、関数型の引数）の `[` は、中に `;` があるときだけ要素を始める。競わない `,`（`0 => 1` 改行 `y,`）は S-384 のまま。
  どの候補でも直らない形（`0 => one` 改行 `(1 + 2) => 3,`）は、誤りが二つある入力として約束の外（器の事例では一つの誤りにしない）。仕様 §2.5。実装は W3-06 の単位 2
