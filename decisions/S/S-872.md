# S-872 `map_err` の `f: fn(move E) -> F`（§9.1 の宣言）に、列挙子の構築子（`fn(E) -> …`、§4.4）と既定のモードの関数が型として合わない（§9.1 の例 `map_err(ConfigError.Io)` が E0401）

- 空白: §9.1 は `map_err` を `pub fn map_err[F](move self, f: fn(move E) -> F) -> Result[T, F]` と宣言し、使い方の例に `Fs.read(path).map_err(ConfigError.Io)?` を挙げる。
  §4.4 の 88 行は、タプル形の列挙子を捕捉の無い関数値（`Circle` は `fn(F32) -> Shape`、既定のモード）とし、同じ例 `map_err(ConfigError.Io)` を挙げる。
  §4.2 の 26 行は「関数型の引数のモード（`inout`、`move`）は型の一部」とする。よって §9.1 の宣言のままでは、§9.1 と §4.4 の例が E0401 になる。既定のモードの関数の項目（`fn conv(e: E) -> F`）と無名関数（`fn(e: E) -> F { … }`）も同じく合わず、`move` の引数の形（`fn conv(move e: E)`、`fn(move e: E) -> F { … }`）だけが合う。
  再現: `target/notes/109/w502u6/probe/m4.onsa`（`map_err` と同じ型の利用者の関数）と `m2.onsa`。`bff9c843` で、構築子は「expected `fn(move Low) -> High`, found `rt fn(Low) -> High`」の E0401、既定のモードの項目と無名関数は「found `fn(Low) -> U32`」の E0401。`rt fn` と `fn` の違いは合う（`move` の引数の `rt` の項目は通る）。
  読み: (1) §9.1 の宣言を `f: fn(E) -> F`（既定のモード）にする。構築子と既定のモードの関数が合い、`move` の引数の関数は合わない。Affine の `E` を持つ構築子の関数値の型も決める要がある。
  (2) 構築子の関数値の引数を `move` にする（`fn(move E) -> …`。構築子は引数を値に入れて持つ）。§4.4 の `Circle` の型の書き方と、Copy の引数の `move` の扱いを改める。
  (3) 関数型の互換で、`move` の引数の位置に既定のモードの関数を渡せるようにする（呼ぶ側が値を渡し、呼ばれた側が借りて、呼んだ後に捨てる）。後端に包みの関数が要る。
  (4) 構築子だけを特別に扱う。
  同じ宣言の型パラメータ `F`: §9.1 は `map_err[F]` と書き、§4.5 の 143 行で型パラメータに暗黙の `Dup` が付くので、字のとおりなら Affine の型へのエラーの変換（`conv(move e: Buf[F32]) -> Buf[F32]`）は E0416 になる。§4.1 の `Result` の宣言は `T: ?Dup, E: ?Dup` を明記する。
  読み: (F1) 字のとおり `F` は暗黙の `Dup`。(F2) `Result[T, F]` を作るので `F: ?Dup`（§9.1 の書き落とし）。再現は `target/notes/109/w502u6/probe/affine_err_conv_len.onsa`（W5-02 U6 の壊す側）。
  仮の扱い（W5-02 U6）: §9.1 の宣言のまま `fn(move E) -> F` と `map_err[F]`（暗黙の `Dup`、(F1)）で実装し、std の宣言に `SPEC-GAP(S-872)` の印を付ける。
  構築子を渡す事例（`tests/spec/types/map_err_constructor.onsa`）と、構築子を `map_err` に渡す実装待ちの 2 件（`semantics/try_map_err.onsa`・`enum_variant_values.onsa`）は、この S を理由に実装待ちに置く。
  急ぎ: W5-03 の前（`Option`・`Result` を std の enum にするとき、`map_err` の宣言と構築子の関数値の型が揃っている要がある）。読みによって std の宣言の一行と事例の期待値が変わる
