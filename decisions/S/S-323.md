# S-323

- 空白: コマンドが受ける経路の引数の形。
  §18.2 の表は `check`・`fmt`・`test`・`build` の経路を書かず、`interface` は `<mod>`、`graph` は `<flow>` とするが、実装は `interface` と `graph` がファイルかディレクトリの経路を受け、`build` がディレクトリか `onsa.toml` だけを受ける（ファイルを渡すと `onsa.toml` として読む）。
  第 11 組の下書きで見つけた（2026-10-09）
- 提案: 後の段（W4-02 の前。S-312 と同じ回でもよい）
- 時期: W4
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目、第 37 組）: (a)。パッケージを読む全てのコマンドで、経路は最後の省ける位置の引数（`.onsa` のファイル、ルートのディレクトリ、`onsa.toml`）で、名前を取るコマンドは名前を先に置く（`graph <flow> [<経路>]`、`play`・`probe` も同じ）。`interface` の `<mod>` は `[<経路>]` に改める。
  ファイルは結果をそのファイルのモジュールに絞る（`interface` はその宣言、`graph`・`play`・`probe` はその中の flow、`audit` はその箇所）。`build` にファイルを渡すのは使い方の誤り（2）。
  あわせて: `.onsa` でも `onsa.toml` でもないファイルは 2（`fmt` は今のまま名前を問わない）。経路を省いて上に `onsa.toml` が無ければ 2（単一のファイルのパッケージはファイルを渡したときだけ）。
  `<flow>` は、モジュールの経路付きの名前か、選んだ範囲で一つに決まる名前で、決まらなければ 2 で候補の経路を並べる。`graph <flow> <ファイル>` で経路付きの名前がファイルのモジュールと食い違えば 2（独立のレビューの補い）。表に `fmt [--check] <ファイル>…` と `diff --ast <旧> <新>` を書く。
  仕様 §15.1・§18.2。`fmt` にディレクトリか経路なしを渡す形は S-599
