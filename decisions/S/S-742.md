# S-742 flow のインスタンスの循環（E0817）の報告: 循環ごとに一つで宣言の名前に付けるか（S-730 と同じ）、インスタンスを書いた位置に付けるか

- 空白: §11.5 は「flow が自分自身を、直接または他の flow を経由してインスタンスにすると E0817（状態の大きさが決まらない）」とするが、循環の中のどの宣言かどの位置に、いくつ報告するかを書いていない。
  S-730 は型の循環の E0311 を、互いに辿り合う型の集まりごとに一つ、診断の並べ方で最初の宣言の名前に付け、他を note で示すと決めた。既にある事例 `tests/spec/flow_semantics/rules_negative.onsa` の 238 行と 242 行は、自分を指す形の E0817 をインスタンスを書いた位置（本体の `instance_of_itself~(x)`）に置く。
  読みは二つに割れる。(1) S-730 と同じく循環ごとに一つで、宣言の名前に付ける。(2) インスタンスを書いた位置に付ける（循環の中のインスタンスごとか、循環ごとに一つか）。
  今の実装（`d8e0472`）: E0817 は未実装で、自分を指す `fs~(x)` も、相互の `fa`（本体が `fb~(x)`）・`fb`（本体が `fa~(x)`）も `check` を通る。再現は `target/notes/79/g70/flow_mutual.onsa`。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。79 回目、第 70 組）: (1)。
  E0817 は flow のインスタンスの集まり（自分を指す一つの flow を含む）ごとに一つで、診断の並べ方で最初の flow の宣言の名前に付け、集まりの flow の本体にある集まりの flow のインスタンス（`~` の呼び出し。`par`・`if~` の中を含む）の位置を全て note で示す（文面と並びは約束にしない）。S-734 の規則のとおり。
  E0817 は名前（どの flow を `~` で呼ぶか）だけで決まるので名前の段の誤りとし、§18.1 の 69 行の一覧に足した（利用者に説明した。今の登録は flow の段）。
  仕様は §11.5 の 174 行と §18.1 に書いた。`tasks/diag-codes.md` の E0817 の行に足し、段を名前解決にした。
  実装は W4-05 の U4（81 回目の名では U5。R-03）: 名前の段の記録（`Place::Instance`）から flow のグラフを作り `components`、約 +5〜10 行。`crates/onsa_diag/src/codes.rs` の E0817 の段を Flow から Names に。
  降下の E0200 の表（`unsupported.rs`）から `FlowSelfInstance` を外し、`lower/flow/mod.rs` の `ensure_flow` の守りを内部エラーにする。
  事例 `tests/spec/flow_semantics/rules_negative.onsa` の 238・242・247 行の `//~ E0817` を宣言の行（237・241・245 行）へ移し、頭のコメント（「印は誤りの構文の行」）に E0817 の例外を一行添える。相互の循環の事例を足す（最初の flow に一つ）。
