# S-1060 細部: E0601 の候補で、足す効果の名前がその module でその効果を指さないとき（E0304 で隠れた `Alloc` など）、候補を出すか

- 空白: §8.1 は `rt` でない関数の E0601 に効果行への追加を候補として示し、§18.1 は候補を当てると誤りが消え新しい誤りを作らないと約束する。足す効果の名前（`Alloc`）が、その module では効果を指さない（`pub enum Alloc { A }` が prelude の `Alloc` と E0304 になり、S-675 の (d1) で名前がどれも指さない）とき、候補を出すかを書かない。
  再現: `target/notes/151/w603/u4b/probe/shadow.txt` の `shadow_ok_norow`（E0304@1:10 と E0601@2:26）。W6-03 U4a の後は ` uses {Alloc}` を出し、当てても E0601 が残って二手目で `uses {Alloc} uses {Alloc}`（E0002）になる（前からの候補の約束の破れ）。U4b の初めの実装は行の中へ足し続け、`tests/fuzz/09c63014.onsa` の fix-loop が手数の上限まで回った。
  読み: (1) 候補を出さない (2) 修飾した名前（`core.Alloc`）を足す。
  仮の扱い: (1)（名前がその効果を指すことを `modules.lookup` で確かめ、指さなければ候補なし。書き手の直しは名前の重なりを解くことで、候補が一つに決まらない。コードに `SPEC-GAP(S-1060)` の印、`effects.rs::first_use`）。
  関係: 行に書いた `uses {Alloc}` の `Alloc` が同じく E0304 の名前のとき（`shadow_ok_row`）、S-691 の決定は「未知の効果を含む行は開いた行で、その名前が指しえた効果に頼る判定は黙る」とするが、W6-03 の前から E0601 が出る。W6-03 の `持ち越し`（U7）に送った。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
