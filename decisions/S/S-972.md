# S-972 E0304・E0305 で誤りになった名前の後のフィールドが、括弧の有無で割れる（`[F32; D.x]` は無診断、`[F32; (D).x]` は E0417）

- 空白: §4.5 は値のフィールド（`K.x`、`P.N.x`、`(K).x`）を「中の型によらず E0417」とし、S-967 は `K.x` と `(K).x` を同じコードにした。§18.1 は E0304・E0305 になった名前を誤りとして扱い、それを使う側には診断を出さない。誤りになった名前 `D`（`const D: U32 = 1` と `const D: U32 = 2`）の後のフィールドは、今（W5-16 U1b2）は、鎖の葉の `D.x`・`D.x.y`・`D.x + 1` が E0304 だけで、節の `(D).x`・`D.x()`・`(D.x).y`・`g(D.x)` は E0417 も出る。
  読みは (1) 今のまま（鎖は葉として黙り、括弧や呼び出しの節は形の E0417。S-968 の「形の中の E0304 の名前は形の E0417」と同じ当て方）、(2) `D.x` も `(D).x` も E0417 にそろえる（S-967 の括弧の有無で割れない形）、(3) `(D).x` も黙らせる（§18.1）、に割れる。どれも誤りのプログラムで、違うのはコードだけ。
  仮の扱い: (1)（事例 `tests/spec/types/length_names_errored_module_const_field.onsa` が `D.x` の無診断を押さえる。`(D).x` の側の事例は無い）。
