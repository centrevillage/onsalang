# S-911 境界と derive を経る `rt` の再帰（E0903）: `T.default()` の具体化と derive の `default` の呼び出しを辺に数えるか

- 空白: §10 の規則 5 は `rt fn` の再帰を禁じ（直接・相互とも E0903）、「モジュール間の import は循環しないので、この検査はモジュールの中で閉じる」と書く。§12.5 は、これによりスタックの上限が計算できるとする。手書きの `impl Default`（W5-06 U4）を開くと、この前提の外の二つの形ができる。
  形 1: derive の `default` を経る。`struct P: Default { q: Q }` と `impl Default for Q { rt fn default() -> Q { let p = P.default()  p.q } }`。derive の `P.default` は本体を持たず、`Q.default` を呼ぶことが検査に見えない。
  形 2: 境界を経る。`rt fn mk[T: Default]() -> T { T.default() }` と `impl Default for Q { rt fn default() -> Q { mk[Q]() } }`。`mk` の中の `T.default()` が `Q.default` に届くのは具体化の後である。`impl` と総称の関数は別のモジュールに置けるので、循環はモジュールの中で閉じない。`onsa check` は具体化しない。
  第 1 期に利用者のコードに届く境界のメンバは `default` だけである（数の trait のメンバは std の宣言で、利用者の `impl` が無い）。第 2 期に利用者の trait を開くと同じ形が一般に起きる。再現は `target/notes/117/w506/memo/probe/gap_rt1.onsa`・`gap_rt2.onsa`（今は `impl Default` が E0200 で止まる）、比べの直接の相互再帰は `gap_rt3.onsa`（E0903）。
- 決定: 決定（2026-11-06、利用者。117 回目）: (d) 境界と derive を経る `rt` の再帰も E0903 に数える。呼び先が名前で決まる循環は今のまま検査で報告し、具体化で決まる循環（`T.default()`、derive が作る関数を経る形）は降下の後の Core の呼び出しで調べ、Core への降下の診断として報告する（`test`・`build`・`interface` など降下に進む命令）。`check` と LSP に出るかは W9-03 に従う。
  報告するのは手で書いた `rt` の関数を含む循環だけで、生成する関数だけの循環は報告しない（S-914）。位置は循環の中の手で書いた呼び出しのうちソースの順で最初のもので（S-778 のこの形の分）、循環の道を note で示す。循環ごとに一つである。関数値を経る呼び出しは数えない（§12.5）。
- 経緯: 117 回目（2026-11-06）、W5-06 U2〜U4 の設計メモ（onsa-impl）が仕様の空白として挙げた。期限は U4 の前。
- 補い（2026-11-06、親）: 第 89 組で決めた。下書き `decisions/S/S-911.draft.md`。下書きと段 1 が一致したので段 2 は省いた。
