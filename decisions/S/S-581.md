# S-581 プラグインのパラメータの写し方: `@param` とホストのパラメータ、変化の届け方、変調

- 空白: §11.7 の `@param`（ID、範囲、`step`、`scale`、`unit`、`label`）は「プラグイン（CLAP / VST3 / AU）のパラメータ情報」に使うとするが、写し方は無い。ホストはパラメータの変化をブロックの中の位置付きで渡す（CLAP は入力の列の `CLAP_EVENT_PARAM_VALUE`、VST3 は `IParamValueQueue` の点、AU は描画のイベントの `AURenderEventParameter`）。決めること:
  1. `@param` とホストのパラメータの対応（数値の ID、正規化した値（VST3 は 0〜1）、表示の文字列、`step` と離散の値、`Bool`）。
  2. 変化の届け方: ラッパーが変化の位置で呼び出しを分ける形（S-565 の R12）か、C の API のイベントの列でパラメータの変化を届け、生成したコードが中で分ける形か（どちらも `block` の意味は同じで、出力はビットで同じ。同じ位置のノートとの順だけが違う）。直線の変化（VST3 の点の間、AU の `AURenderEventParameterRamp`）は扱わない（利用者、51 回目）。
  3. CLAP の変調（`CLAP_EVENT_PARAM_MOD`）とボイスごとの変調、UI の文脈からの変化とオーディオの文脈の受け渡し（§16）。
- 決定:
- 経緯: 第 36 組（プラグインの出力）の一つ。第 35 組（境界、S-570〜S-574）の決定の見込みの上に立ち、C の API がラッパーの要求を満たすかを W10 の前に確かめる。利用者が「VST/CLAP/AU用の出力は主要な機能の一つなので、今考えておきたい」「避けられる手戻りは前もって避けた方が良い」とし、出力の形まで決める範囲（(β)）を選んだ（2026-10-22、51 回目）。関係: S-565、S-570、S-575、§11.7、A-13。
