# S-831 族: §15.3 の provides の名前

- 空白: 族の S（S-608・S-830）は、`provides` に書く名前（効果でない名前、同じ効果の重なり）の扱いを §15.3 が書いていないことから出た。族の一般の規則（`provides` の要素の形と重なりのコード・位置）を一つ決め、個々の形はそこから決める
- 決定: 決定（2026-11-14、利用者。149 回目、第 102 組。下書きと独立のレビューの段 1 が (a) で一致し、段 2 は省いた）: (a)。`provides` の要素は §8.2 の表の標準の効果の名前で、表を std の効果の全てとする（見出しの「主な」を外す）。表に無い名前は全てのコマンドのマニフェストの検査で E1103（要素の位置、note に表の一覧、修正候補なし、E0200 を重ねない）。表の効果でこの版のターゲットが与えないものは、S-824 のまま、そのターゲットのビルドで要素ごとに E0200。細部（利用者が A1〜A9 を了承）: A1 TOML の文字列の値で比べ、大文字と小文字を区別し、前後の空白を切り落とさない。経路（`"std.core.Alloc"`）は受けない。A2 表は 8 つ（`Block` を含む）、延期の名前（`Net` など）も E1103。A3 重なりは同じ配列の中で表の名前だけを数え、二つ目以降の各要素に E1103（note で最初の要素）。知らない名前と文字列でない要素は数えない。`["Fs", "Fs"]` はビルドで要素ごとの E0200 も独立に出す（S-827）。A4 表の外の要素は E1103 だけ。A5 実装の正本はマニフェストの表の一覧の一か所で、std の効果の宣言との一致と名前の一意を Rust の自己テストで確かめる。A6 S-824 に補い（決定は変えない）。A7 W6-03 の E0610 の照合は、第 1 期は `Alloc` を与えるかの真偽のまま。A8 実装は W6-03 の頭の独立の単位。A9 仕様は §15.3 の表の行と箇条、§8.2 の見出し、§18.1 の E1103 の括弧。将来（利用者の意向）: 第 2 期に効果を std の定義（操作と handler を持つ宣言）で与えるようになったら、マニフェストの名前は std の宣言を正本にして引き、表の一覧の写しを外す（今の案 (b) の形。そのときに §18.1 のマニフェストを先に検査する順との関係を決める）。
- 経緯: 95 回目（2026-11-01）、族の未決の S が二つになったので登録した（`rules/process.md` 8.6 の仕様の空白の流れの 2）
