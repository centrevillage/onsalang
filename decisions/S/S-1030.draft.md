# S-1030 `move` で受けた所有の Shared の値を、消費する位置（構築子・struct・タプルの要素、`let y = move x`）に置く形が `Alloc` を要するか（§12.2 の「`move` の引数に渡す」の行と、§5.2 の「その場で複製して渡す」）

- 決定済みで戻さないもの: 返す形・`move` の引数・`move self` の受け手・`?` の被演算子の `Alloc`（R-255、W6-02 で直す）、印の規則（S-609、S-795: Dup の値の `move` は値を置く位置と `move` の引数で E0703、束縛の見出しで受け付ける）、構築子の関数値の型（S-872）、型を組むことと静的な値の破棄（S-610・S-613）、`var` の上書きの破棄（第 2 期の L1）、片方の道の破棄（R-32）、Shared の捕捉（第 2 期）、E0601 の位置（S-783）。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/146/g98/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版・入力は `advisor/`、下書きと段 1 の報告は `onsa-gap-ab22fd86542d2a3e2-001.md`・`onsa-advisor-a78c32665847cacee-001.md`。
- 論点: §12.2 の表は「受け取った Shared 値を、そのまま返す・`move` の引数に渡す」に `Alloc` が要らないとし、「所有する Shared 値・`Buf` と、それらを含む値の破棄」には要るとする。§5.2 は消費する位置を、束縛の見出し、値を置く位置（代入の右辺、リテラルと構築子の要素）、`move` の引数、返り値、取り出す形に分ける。
  §5.2 は、消費する位置に置く Dup の値を「その場で複製して渡す」とし、字のとおりなら元の値は残って後で破棄され、`Alloc` が要る。§12.2 の行は、返り値と `move` の引数だけを手放す位置として挙げ、他の消費する位置を書かない。
  S-872 は `g.(x)`（構築子の関数値）を `W.A(x)` と同じ意味とするが、`g.(x)` は字のとおり `move` の引数なので、§12.2 の行に当たる。読みは (1) 消費する位置の全てで、最後の使用なら手放す、(2) §12.2 の二つの行だけで、他の消費する位置は複製して破棄する、に割れる。
  どの読みでも、`move` の引数の行は「後でまた読む」形（`take(x)` の後の `x.len()`）を除く要がある（その `x` は後で破棄される）。仕様にこの条件の文は無い。
- 今の実装: 形の表のとおり。`uses {Alloc}` の無い関数では、受けた Shared の値を返す・渡す・置く全ての形が E0601（「`f` uses `Alloc`, which is not in its effect row」、位置は関数の頭、note は「`x` owns a `Str`, whose destruction needs `Alloc`」）で、`rt fn` では E0901 である。
  借用の引数を置く形（`rt fn g(x: Str) -> Option[Str] { Some(x) }`）は通る。所有の `move x: Str` にすると E0901 になる（`borrow.txt`）。
  E0601 の候補は `uses {Alloc}` の挿入で、`--fix-loop` は 1 回で `clean` である（`o_pos/later_use`）。E0901 は候補が無く `no-candidate` で止まる（`out/ctor_rt`）。
- 案:
  - (a) 読み (2)。§12.2 の二つの行（返す、`move` の引数。取り出す形は R-255 の補い）だけで手放す。他の消費する位置は、元の値を複製して置き、元の値は後で破棄する（`Alloc` が要る）。
    `move` の引数の行に「その経路で後に読まないとき」の条件を足す。構築子の関数値の呼び出し `g.(x)` は `move` の引数なので要らず、直接の `W.A(x)` は要る（S-872 の「同じ意味」に、`Alloc` だけ違うという注を足す）。
  - (b) 読み (1)。所有する Dup の値（局所の変数の全体）を消費する位置に置き、その経路でその後に読まないなら、移す（元の値を破棄しない）。後で読むなら複製し、元の値は後で破棄する。
    §12.2 の行を「所有する Dup の値を、その経路の最後の使用で消費する位置（§5.2）に置くこと: 要らない」に広げ、§5.2 の「複製して渡す」に「後で使わなければ移す。違いは `Alloc` の要否だけで、値は同じ（§12.2）」の一句を足す。
  - (c) 位置で限る。返り値、`move` の引数、取り出す形と、値を置く位置（構築子とリテラルの要素、代入の右辺）では (b) と同じく移す。束縛の見出し（`let`・`var` の初期化、`match`・`for` の見出し）では複製し、元の値は後で破棄する。
  - (d) 印で選ぶ。Dup の値に `move` を書いた所だけ移し、以後その変数は使えない（Affine と同じ E0704）。印の無い所は複製する。返り値と `move` の引数は R-255 のとおり印なしで手放す。
    S-609・S-795 の「値を置く位置の Dup の値の `move` は E0703」を改めて受け付け、束縛の見出しの `move` の意味（今は複製）を移動に改める。
  - 形ごとの出力: 形の表のとおり。(a) は今の挙動に R-255 の直しを足したもので、(b)・(c) は今の E0601・E0901 を通す向き、(d) は今の E0703 を通す向きである。今通るプログラムを誤りにするのは (a) と (d) である。(a) では、境界の無い `T` を構築子に置く形が W6-02 の後に E0601 になる（W6-02 が総称の `T` の破棄を数えるとき）。(d) では、束縛の見出しの Dup の `move` の後に元の値を読む形（`let y = move x` の後の `x.len()`、今は通る）が E0704 になる。
  - 書き手から見て（修復のループの回数）: 受けた文字列を構造体や `Option` に包んで返す関数（`fn tag(move name: Str) -> Param { Param { name: name, value: 0.0 } }`）は、(a) では 1 回（E0601 を見て `uses {Alloc}` を足す）で、その関数を呼ぶ全ての関数にも `Alloc` が要り、呼ぶ側ごとに 1 回ずつ増える。
    `rt fn` では E0901 に候補が無く、直すには引数を借用（`name: Str`）に変える。所有で受けた方が `Alloc` が要り、借用で受けた方が要らない、という向きは文面の「move it on」とも合わない。
    同じ値を返すか包むかだけで `Alloc` の有無が変わる形の数は、(a) で 9（表の「構築子の直接」「リテラルの要素」「両方の道」「束縛の見出し」「印の無い束縛」「分解する見出し」の三つ、「境界の無い `T`」）、(c) で 5（束縛の見出しの側）、(b) で 0 である。
    (d) は印を書けば 0 だが、書き手は `move` の引数と返り値では印を書かず、構築子とリテラルでは書く、と位置ごとに覚える要がある。今の E0703 の候補（`move` を消す）とも逆向きになる。
  - 修正候補: どの案も、E0601 の候補（`uses {Alloc}` の挿入）は当てて止まり、E0901 は候補なしで止まる（§18.1）。(a) では S-795 の E0703 の候補（境界の無い `T` の `Some(move t)` の `move` を消す）を当てた後に E0601 が残り、ループが 1 回増える。
    (d) では「`move` を足す」候補を E0601 に付けるかを決める要があり、付ければ印を足した後に後の使用が E0704 になる形で、候補が別の誤りを作る。
  - 通るプログラムと事例: `std/` と `examples/` と §17 の例に当たる形は無い（std の `move` は `T: ?Dup` の `unwrap`・`map_err` だけで、どの案でも移す）。
    `tests/` の E0601・E0901 の印の事例のうち、所有の束縛を消費する位置に置くものは 2 件である（`uses.out`）。(b) では誤りは残るが、破棄する局所が後の束縛に移り、E0901 の位置が 1 行下がる: `negative/binding_literal_names_owned.onsa` の 70 行（`W { p: p, k: 1 }` で `p` が `o` に移る）と `negative/binding_tail_owned_rt.onsa` の 83 行（`let q = t`）。
    実装待ち（W6-03）の `negative/binding_static_interp.onsa` の 20 行（`let t = s`）も、(b) では note の局所が `t` に移る。
    (c) は前者だけ変わる。(a) は R-255 の実装待ちの `types/drop_through_ptr_move_on.onsa` の他は変わらない。ただし W6-02 が総称の `T` の破棄を数えた後、`fixes/e0703_dup_unbounded_type_parameter.onsa`（`clean = true`、候補の後の `pub fn unbounded[T](move t: T) -> Option[T] { Some(t) }`）が `clean` でなくなる。
    (d) は E0703 を期待する事例（67 ファイル。Dup の値の分は数えていない）の一部と、束縛の見出しの Dup の `move` の後に元の値を読む正例（`letmove_then_use_x` の形）が変わる。
  - 規則と例外: (a) は §12.2 に「後に読まない」の条件と、S-872 の「同じ意味」への `Alloc` の注（直接の構築子と関数値の呼び出しで違う）。§5.2 の消費する位置の分け方とは別の、二つの位置だけの例外になる。
    (b) は §12.2 の行を一つ広げ、「最後の使用」の定義の一文と §5.2 の一句を足す。消費する位置の一覧は §5.2 の既にある分け方をそのまま指し、例外は足さない。
    (c) は (b) の定義に加えて、束縛の見出しを除く一句。`let y = move x; y` と `{ x }` が `Alloc` で違う理由を書く要がある。
    (d) は S-609・S-795 の改め、Dup の値の E0704、束縛の見出しの `move` の意味の改め、返り値と `move` の引数は印なしという例外の、四つ。

- 推奨と理由: (b)。確度: 高。
  - `Alloc` を効果に出す目的は、関数がヒープを使うかをシグネチャで分かることである。受けた値を包んで返すだけの関数は、確保も解放もしない。(a) はこの関数に `Alloc` を書かせ、呼ぶ側の全てに広げ、ヒープの無いターゲット（§12.3）の `main` から呼べなくする。シグネチャが実際と違うことを示す。
  - (a) は表面の食い違いを多く作る。同じ値を返すか包むかだけで 9 の形が分かれ、`g.(x)` と `W.A(x)` が `Alloc` で違い（S-872 の「同じ意味」と食い違う）、借用で受けた方が所有で受けた方より安くなり、`[T: ?Dup]` と `[T]` が境界だけで分かれる。どれも書き手の誤りではなく、直し方（`uses {Alloc}` を足す、借用に変える）は意図から離れる。
  - (b) は規則を減らす。§5.2 の消費する位置の分け方をそのまま使い、例外を足さない。Affine の値が消費する位置で移るのと同じ形になり、違いは「後で読めば、Affine は E0704、Dup は複製」だけである。S-609 の「印は前の値が以後使えなくなる所にだけ付ける」とも揃う（(b) でも Dup の値は後で読め、使えなくならない）。
    §5.2 の「複製になる」は値の意味の文（後で元の値を読める）で、(b) でも値の意味は変わらない。
  - 実装は、R-255 を直すのに要る「その経路で後に読むか」の仕組みを共有し、位置の判定は (a) より一つ少ない。生成も、返り値と `move` の引数と `?Dup` の総称で要る移動の形を使う位置が増えるだけである。今通るプログラムを誤りにせず、変わる事例は印の位置が 1 行下がる 2 件だけである。
  - (c) は (b) の利点の半分で、束縛の見出しに理由の無い例外を残す。(d) は S-609・S-795 を改め、`move` の引数と返り値は印なし、構築子とリテラルは印あり、という位置ごとの覚え方を作る。
  - あわせて決めること:
