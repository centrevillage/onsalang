# S-439

- 空白: 文字列の中の単独の `}`（`"}"`、`"a } b"`、`"{a}}"`）。§2.4 は `{{` と `}}` をエスケープとし、単独の `}` を書かない。今は E0001。W3-04/t が見つけた（2026-10-11）
- 提案: W3-04 は今のまま E0001 の仮の扱い。後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1、X）文字列の単独の `}`（`"}"`、`"a } b"`、`"{a}}"`）は字句の段の E0020 の行 `lone_brace` で、候補は `}}`（他の言語の普通の文字列では `}` が一字で、候補は値を変えない。`\x41`・`1'000` を字句の段の E0020 にするのと揃う）。単独の `{`（`"{"`、`"a { b"`）は補間の閉じ忘れと読みが割れるので今の E0001 で候補なし。
  - 仕様の節: §2.4（`{{` と `}}` の文の後ろに二文）、一覧の行 `lone_brace`。
  - 今通るプログラム: 変わらない（今は E0001「lone `}` in string」で候補なし）。
  - 実装の見当: `lexer.rs`の診断を行の E0020 にし、`}}` の候補を付ける（10〜20 行）。
  - ぶつかる事例: 未確認（単独の `}` を `//~ E0001` で期待する事例を探していない）。
