# S-1121 細部: `@param` を付けた入力の型が使えない（E0810、または値型が §11.7 の一覧の外）とき、その属性の他の E0809（一覧に無いキー、値、二度目のキー）を出さないか、位置の並びで競わせるか

- 空白: §18.1 は互いに依存しない段の診断を「どれも本物」とし、位置の並びで最初のものを報告する。§6.5 の「重なった属性の引数は検査しない」は E0005 の重なりだけを言う。E0809 と E0810 はどちらも flow の検査の段である。
  読みは (1) 入力の型が使えなくても `@param` の E0809 を位置の並びで他の診断と競わせる（属性は型より前にあるので、属性の E0809 が先に出る）、(2) 入力の型が使えないときは、その属性を読まず型の診断だけを出す（入力が読めないので、§6.5 と同じ向き）に割れる。違いは報告の位置とコードだけで、通るプログラムは変わらない（型を直した後に属性の E0809 が出る）。
  今の実装（W7-13 U4a）は (2): `@param(color: "a", default: 0.0) p: Str at block` は E0810（型）だけ、`@param(color: "r", default: 0) p: I64 at block` は値型の E0809（型の位置）だけ。前（`aea4ce78`）は属性の位置の E0809。`@param` を付けない `@export` の `p: Str at block` は、`@param` の必須の E0809（属性の位置の無い入力の位置）が E0810 より先に出る（別の検査）。再現は `target/notes/163/w713/u4a/` の壊す側の報告の低-1・低-2（入力 `e810.txt`・`order.txt`）。
  仮の扱い: (2)。`crates/onsa_sema/src/sig/generated.rs` の `check_generated` と `sig/param.rs` の `lower_param_attr` に `SPEC-GAP(S-1121)`。W7 の区切りで確認だけ。U4b で値の E0809 を足すときも同じ扱い。
