# S-1092 細部: 名前の無い入力（`_: F32 at init`）を持つ flow の `Config` のフィールド（今は `_` のフィールドができ、リテラルに書けないので `init` を呼べない）

- 空白: §11.6 は `Config` を「init の入力をフィールドに持つ struct」とし、名前の無い入力 `_` を書かない。今（W7-12 U1 の前も後も）は `_: F32 at init` の入力が `Config` の `_` のフィールドになり、`w.Config {}` は「missing field(s) `_`」の E0410 で、フィールド名 `_` のリテラルは書けないので `init` を呼べない。
  読み: (1) `_` の入力は `Config`（`Params` も同じ）のフィールドにしない、(2) 名前の無い入力を見出しで誤りにする。
  仮の扱い: 今のまま（W7-12 の単位で (1) の形を足すかを票で決める）。再現 `target/notes/157/w712/u1/b/c8.txt` の `wild`。
  急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認。「(2)で良いです」）: (2)。flow の入力の名前に `_` を書くのは誤りにする（宣言の見出しの検査一つ）。flow の入力の名前は生成する型（`Config`・`Params`・`In`）の欄の名前、C の名前、`@param` の `id` の既定、graph の頂点の名前になるので、名前が要る。読まない入力には名前を付けたままでよい（§5.1 で、関数と flow の引数は E0309 の対象外）。関数の引数の `_` は欄にならないので今のまま書ける。コードと位置は実装の単位の細部（仮は E0810、位置は `_`、候補なし。名前は書き手しか決められないので note で名前を付ける形を示す）。今の事例と std に当たる形は無い。後で `_` を欄にしない形（読み (1)）へ緩めても今の形は壊れない（`rules/criteria.md` 7.5）。S-1256 と R-525 はこの直しで起きなくなる。実装は W7-17 の L4。
  利用者の経過: 親が (1) 欄にしない・(2) 誤りにする・(3) 位置の名前を付ける を、今通る宣言・外からの `init`・実装の手当ての数・関数との揃い・後で変える向きで比べ、推奨 (2) と、段 1 を回してから決める選択肢を示した（助言の担当の仕分けの推奨も (2)、`target/notes/189/reports/onsa-advisor-a5d87f2cf05f2cfce-001.md`）。
