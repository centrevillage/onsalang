# S-811 族: 呼び出しの印（`(`・`.(`・`!(`・`~(`）と呼び先の種類が合わない形の、コードの順と修正候補

- 空白: 呼び出しの形は呼び先の種類で決まる（§6.1: 項目・関連関数・名前空間の関数・効果の操作・列挙子の構築は `f(x)`、関数値は `f.(x)`。§2.6: `inout self` のメソッドは `名前!(…)`、flow のインスタンスと組込みの遅延は `名前~(…)`）。
  印と種類の組のうち、決まっているのは、`f(x)` と `.(` の取り違え（§6.1・§15.1 の E0020）、flow の本体の `~` の付け忘れ（E0811）と flow でないものの `~`（E0812。候補は S-590、組込み名の後の `.` は S-723）、flow の外の flow だけの構文（E0821、§11.1）、メソッドを型の名前で関数の形で呼ぶ形（§15.1 の E0308）である。
  値や flow に `!(` を付けた形（S-812・S-813）、型の名前で書いたメソッドに `~` を付けた形（S-814）、flow の外の `~` の呼び先が見つからないか flow でない形（S-815）、flow を `.(` で呼ぶ形（S-816）、flow の組込み名 `sample_rate`・`sample_tick` に `~` を付けた形の候補（S-817）は書かれておらず、どれも二つ以上のコード（E0020・E0302・E0308・E0714・E0811・E0812・E0821）の規則に当たる。
  どの規則が先か（名前の段と型の段のどちらの、どのコードか）と、修正候補（正しい印に置き換える形か、候補なしか）を、一つの規則で決められるかが問いである。候補を当てた後に同じ段か前の段の誤りが残る今の形が、S-812〜S-814 にある（§18.1）。
