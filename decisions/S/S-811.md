# S-811 族: 呼び出しの印（`(`・`.(`・`!(`・`~(`）と呼び先の種類が合わない形の、コードの順と修正候補

- 空白: 呼び出しの形は呼び先の種類で決まる（§6.1: 項目・関連関数・名前空間の関数・効果の操作・列挙子の構築は `f(x)`、関数値は `f.(x)`。§2.6: `inout self` のメソッドは `名前!(…)`、flow のインスタンスと組込みの遅延は `名前~(…)`）。
  印と種類の組のうち、決まっているのは、`f(x)` と `.(` の取り違え（§6.1・§15.1 の E0020）、flow の本体の `~` の付け忘れ（E0811）と flow でないものの `~`（E0812。候補は S-590、組込み名の後の `.` は S-723）、flow の外の flow だけの構文（E0821、§11.1）、メソッドを型の名前で関数の形で呼ぶ形（§15.1 の E0308）である。
  値や flow に `!(` を付けた形（S-812・S-813）、型の名前で書いたメソッドに `~` を付けた形（S-814）、flow の外の `~` の呼び先が見つからないか flow でない形（S-815）、flow を `.(` で呼ぶ形（S-816）、flow の組込み名 `sample_rate`・`sample_tick` に `~` を付けた形の候補（S-817）は書かれておらず、どれも二つ以上のコード（E0020・E0302・E0308・E0714・E0811・E0812・E0821）の規則に当たる。
  どの規則が先か（名前の段と型の段のどちらの、どのコードか）と、修正候補（正しい印に置き換える形か、候補なしか）を、一つの規則で決められるかが問いである。候補を当てた後に同じ段か前の段の誤りが残る今の形が、S-812〜S-814 にある（§18.1）。
- 決定: 決定（2026-10-31、利用者が ID を挙げて了承。確認だけ。93 回目、第 76 組）: (a)。
  呼び出しの印（`(`・`.(`・`!(`・`~(`）が呼び先の種類に合わず二つ以上の規則が当たるときは、呼び先の名前の解決の誤りの後、その文脈で書けない印（flow の外の E0821、flow の本体の `!(`・`.(` の E0806）、書いた印が呼び先に合わない規則（`~(` は E0812、`!(` は E0714、`.(` は値の位置の規則）、印の無い `(` に呼び先の種類が求める規則（E0020、E0811、E0713、E0308、E0412）の順で最初に当たるものを報告する。
  呼べない値の誤り（E0401、E0412）は E0714 より先。
  修正候補は、書いた印を呼び先の種類の印に置き換える一つの編集（種類の印が無ければ消す）で、当てた後に同じ段か前の段の誤りが残らないときだけ示す。既決の S-590・S-723・S-791・S-720 はこの規則の例で、改めない。
  この規則から決まる形: S-812〜S-817。flow の本体の `g.(x)`（`f(x)` で呼ぶ項目）は E0806 で候補 `g(x)`、値の `K.(x)`・入力の `x.(x)` は E0806 で候補なし（W7-04）。flow の本体で `let` の束縛の `inout self` のメソッドを `!` 無しで呼ぶ `q.put(x)` の E0713 は、候補「`!` を足す」が前の段の E0806 を作るので候補なし（W7-04、R-340）。
  小さな S の流れの下書き（onsa-gap）と、推奨を伏せた独立のレビューの段 1（onsa-advisor）が七件とも一致したので、段 2 は省いた。仕様 §2.6、§5.2、§11.1、§11.2、§15.1
