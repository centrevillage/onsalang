# S-629 利用者のパッケージの `target` 宣言に本体を書いたときの診断のコード

- 空白: §15.2 は「std の `target` 宣言は、本体を持てる（std だけに許す書き方）」とするが、利用者のパッケージの `target fn` に本体を書いたときのコード（構文の段の E0002、この版で std の外には使えない E0200、別のコード）を書いていない。
  今の実装は E0002「this declaration is a signature and takes no body」。std を役割で見分ける実装（R-88 (1)、W4-01・W4-03）の観察できる側。
- 決定: S-670 の規則と S-669 から。印の無い `{` の本体は、全てのパッケージで構文の段の E0002「this declaration is a signature and takes no body」のまま（std の本体も `else` の後なので、文面がどこでも正しい）。`else` の本体は std の外で名前の段の E0200（宣言の全体に一つ、note なし）。
  次の行の `else` は E0003（候補は前の行の末尾へ。`target` の後ろの文面は「宣言の見出しと同じ行」）。次の行の `{` と `target type Device {` は今のまま。W4-03 の U3b で出力は変わらず、`else` の形は W5-02 で入る（2026-10-25 決定）。
- 経緯: 59 回目（2026-10-24）、W4-01 U1 のテストの担当が見つけた。
  65 回目（2026-10-25）、第 53 組の前提（S-108 の宣言に本体を書く形）が S-669 で論点になり、族 S-670 の第 55 組として下書きをやり直した。利用者が A14 を了承した。
