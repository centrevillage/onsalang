# S-1032 注釈も期待する型も無い無名関数（`let l = fn(y: I32) -> I32 { bump(y) }`）の効果行

- 決定済みで戻さないもの: 期待する型のある位置の無名関数（§8.1、R-27 (1)・R-26 の後半。W6-03）。効果行を注釈した無名関数は書いた行で照らすこと（§8.1、S-546）。期待する型の無い合流の型は合わせ（効果行は和、`rt` は全ての枝が `rt` のとき。S-1031）。型変数が先に決まった後の式は、その型を期待する型として §8.1 で比べること（S-1031）。
  無名関数の引数のモードは期待する型から推論しないこと（S-872）。捕捉する無名関数は `let` に置けないこと（§5.3）。効果行変数は第 1 期は宣言で E0200（R-27 (3)）。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/146/g99/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版・入力は `advisor/`、下書きと段 1 の報告は `onsa-gap-a7dca9eb9bdc9d42e-001.md`・`onsa-advisor-a982bf7222dfa77ff-001.md`。
- 論点: §8.1 は「無名関数の `uses {}` は効果行の注釈で、省くと期待型から決まる形」「無名関数は、期待する関数型の効果行と `rt` に照らして本体を検査する」とし、期待する関数型が無い位置（注釈の無い `let`・`var`、その場で呼ぶ対象、期待する型の無い合流の枝、型変数を期待する型とする引数 `id(fn…)`・`Some(fn…)`、タプルの要素）の無名関数の効果行と `rt` を書かない。
  §6.1 も「期待型が分かる位置では注釈を省略できる」とだけ書く。そのため、本体の `Alloc` を無名関数に数えるか外側の関数に数えるか、`rt` の関数の中でその無名関数を呼べるかで読みが割れる。
  - 残る論点: (i) 効果行の決め方、(ii) 期待する型の無い合流の後の枝に置く無名関数が前の枝から何を受けるか（S-1031 から回した）、(iii) `rt` の決め方（W6-01 の U2a の後は「`rt` でない」で、`let c = fn(x: U32) -> U32 { x }` の後の `take_rt(c)` が E0401 になった。U2a の壊す側の `r02`）。三つは組で比べる。
    (ii) の受け方は三つある。(ii-1) 前の枝の型をそのまま受ける（`rt` も受ける）。(ii-2) 前の枝の型から一番外の `rt` を外して受ける（効果行は受ける。今の実装）。(ii-3) 前の枝の型から引数と返り値の型だけを受け、効果行と `rt` は期待する型の無い無名関数と同じに決める。
    どれも合流の型は合わせなので同じになる。違いは W6-03 で無名関数の本体を照らすときに出る。(ii-1) は `rt` で順が割れ（`if c { r } else { fn(x: U32) -> U32 { heavy(x) } }` は本体の E0901、逆順は通る）、合わせの「`rt` は全ての枝が `rt` のとき」と食い違うので、下の案には組まない。
- 今の実装: 形の表の今の実装の欄のとおり。型の段では、期待する型の無い無名関数は空の行で `rt` でない（(a) と同じ型）。本体の使用は外側の関数に数える。
  そのため、外が `uses {Alloc}` なら本体の `Alloc` は通り（`k7_outer_alloc`、`pass_to_pure_param`。後者は純粋な `ap` の中で `Alloc` を使う関数値を呼ぶ）、外が純粋なら外の頭に E0601 が出て note が無名関数の中の使用を指す（`k8_outer_pure`、`l_drop_outer_pure` の note「`s` owns a `Str`, whose destruction needs `Alloc`」）。
  `rt` の関数の中では、無名関数を呼ぶ位置が E0901「`rt` function calls a function value whose type is not `rt fn`」（`l_in_rt_call`）で、呼ばなくても本体の `heavy` が外の E0901 になる（`l_in_rt_nocall_heavy`、R-451）。
  W6-03 の後は、期待する型のある無名関数だけが自分の型で照らされる。今の数え方を期待する型の無い無名関数に残すと (f) になり、`pick(k, ca)` は E0601、`pick(ca, k)` は通る、のように書き方で結果が分かれる（今はどちらも通る。`pick_k_ca`・`pick_ca_k`）。
- 案:
  - (a) 名前付きの関数の省略と同じにする。期待する関数型の無い無名関数は、効果行を書かなければ空の行（純粋）で、`rt` でない。本体はその型で照らし、外側の関数には数えない（ca は無名関数の E0601）。合流の後の枝は (ii-3)。
    `rt` の無名関数が要るときは期待する型を書く（`let l: rt fn(U32) -> U32 = fn(y) { y }`）。`Alloc` を使う無名関数は効果行を書く（`fn(y: U32) -> U32 uses {Alloc} { … }`）。
  - (b) (a) と同じで、合流の後の枝は (ii-2)（前の枝の効果行を受け、`rt` は受けない）。
  - (c) 効果行は本体の使用から決まる（効果の段で決まる）。`rt` は (a) と同じく「`rt` でない」。合流の後の枝は (ii-3)。
    型の段では無名関数の行を未決の内部の変数にし、その行に頼る比べ（`ap(l)` の §8.1 の比べ、合わせの和、外側の関数が `l.(1)` で数える効果）を効果の段まで延ばす。行は無名関数の本体の使用（入れ子の無名関数と呼ぶ関数値の行を含む）で、延ばした比べに外れれば効果の段で E0401。
  - (d) (c) に、`rt` も本体から決める規則を足す。本体の効果行に `Alloc` が無く、呼ぶ関数と関数値が全て `rt` なら `rt`（§10 の規則 1〜4。再帰は無名関数では起きない）。`rt` に頼る比べと E0901 も延ばす。
  - (e) 外側の関数（無名関数の中なら、その無名関数）の効果行と `rt` を受ける。型の段で閉じる。本体はその型で照らす。`test` の本体の無名関数は、`test` に与えられる効果（D-08）を受ける。合流の後の枝は (ii-3)。
    変種 (e′) は、効果行は (a) の空の行で、`rt` だけを外側から受ける（`rt` の関数の中の無名関数は `rt`）。
  - (f) 今の数え方を残す。型は (a) と同じ空の行で `rt` でなく、本体の使用は外側の関数（の効果行と `rt`）に数える。W6-03 は期待する型のある無名関数と注釈した無名関数だけを自分の型で照らす。合流の後の枝は (ii-2)。
  - 書き手から見て（修復のループの回数）:
    - (a)・(b): `Alloc` を使う無名関数を注釈せずに `let` に置くと、無名関数の位置に E0601 が出る。名前付きの関数と同じく効果行を書けば 1 回で直る。外が純粋で無名関数を呼ぶなら、次に外の E0601 が出る（2 回。入れ子は呼ぶ段ごとに 1 回）。
      純粋な位置へ渡す形（`pass_to_pure_param`）は、効果行を書くと `ap(l)` の E0401 になり、設計を変える要がある（`Alloc` を使わない本体にするか、`ap` の型を変える）。これは名前付きの関数を同じ位置に渡す形（R-27 の挙げた E0401）と同じ結果である。
      `rt` の関数の中で無名関数を呼ぶには `let` に `rt fn(…)` の型を書く（1 回）。今の木には当たる形が無い。(b) は合流の ca と `b` の 1 行で順が割れる。
    - (c): `Alloc` を使う無名関数は注釈なしで通り、誤りは使う位置（`ap(l)` の E0401）に出る。誤りの原因（本体の使用）と位置が離れるので、note で本体の最初の使用を指す要がある。
      延ばした E0401 は効果の段なので、同じ単位に型の段の誤りがあると出ず、直した後に初めて出る（ループが 1 回増えうる。rustc の E0525 と同じ形、下の他言語）。
    - (d): (c) に加えて、`rt` の関数の中の無名関数が注釈なしで呼べる。一方、本体の小さな変更（`heavy` の呼び出しを足す）で無名関数の型が `rt` から外れ、離れた位置（`take_rt(l)`、`rt` の関数の中の `l.(1)`）に誤りが移る。`var` の代入と推論の cp と `k` で、今通る形が E0401 になる。
    - (e): `uses {Alloc}` の関数と `test` の本体で、純粋な本体の無名関数を `let` に置いて純粋な位置へ渡すと E0401 になる（`test_let_prop` の `check(…, p)`。`check` の `p` は純粋な `fn(T) -> Bool`）。直すには `let` に純粋な型を書く（1 回）。書き手は本体で何も確保していないのに `uses {Alloc}` と言われる。
      (e′) は `rt` の側だけで同じことが起き（`rt` の関数の中の `var l = cp` の後の `l = k`）、効果行は (a) と同じである。
    - (f): 今と同じで、`Alloc` を使う無名関数を `let` に置いても注釈は要らない。代わりに、同じ無名関数を引数に直接書くと W6-03 の後に E0601 になり、`let` に置くと通る（`check(…, fn(x) { "{x}"… })` と `let p = …` の後の `check(…, p)`）。推論の ca と `k`、合流の ca と `k` で順が割れる。
  - 修正候補: (a)・(b) の無名関数の E0601 には、無名関数の本体の `{` の前に ` uses {Alloc}` を足す候補がありうる。ただし、当てると無名関数の型が変わり、同じ単位に型の段の E0401（`ap(l)`）か外の E0601（`l.(1)`）が出うる。
    §18.1 は、当てた後の触れた単位に同じ段か前の段の診断を残さないことを求めるので、候補を出すのは当てた後に検査し直して誤りが残らないときに限るか（§6.1 の E0418 のつないだ形と同じ確かめ方）、出さずに note で書き方を示すかを決める要がある（下の「新しい S の候補」）。どちらでも、当て続けて止まる（効果行は `Alloc` を足すだけで減らない）。
    (c)・(d) の延ばした E0401 には候補が無く（今の E0401 と同じ）、止まる。(e) の E0601 の候補は外に足す形で、外の行を受ける無名関数の型も変わるので、(a) と同じ確かめが要る。(f) は今の外の E0601 の候補のままで、止まる。

- 他言語:
  - swiftc 6.3.3（`other/s1.swift`・`s2.swift`、`-swift-version 6`）: 文脈の無いクロージャ（`let l = { (y: Int) -> Int in try bump(y) }`）は本体の `try` から `throws` の型になり、純粋な引数へ渡すと使う位置で「invalid conversion from throwing function of type '(Int) throws -> Int' to non-throwing function type '(Int) -> Int'」。
