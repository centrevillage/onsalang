# S-1012 細部: `FixedStr` の `t.write_to(inout out)` が、書いた数の後ろの `out` のバイトを変えるか（変えない・0 を詰める・NUL で終える）

- 空白: §4.2 は「`t.write_to(inout out)` は `out` に入る分を書き、書いた数を返す」とし、書いた数の後ろの `out` のバイトを書かない。読みは (1) 変えない (2) 0 を詰める (3) NUL で終える。
  仮の扱い: (1) 変えない（書く分だけを写す。`rules/leader.md` 5.11）。U3b の事例は後ろのバイトを確かめない（書いた数、書いたバイト、`out.slice(from, to)` の外が変わらないことだけ）。
- 決定: 決定（2026-11-12、利用者。140 回目、W5 の区切りの確認だけ。「全て現状のまま」で了承）: 仮の扱いの (1)。`t.write_to(inout out)` は、書いた数より後ろの `out` のバイトを変えない（0 を詰める (2) と NUL で終える (3) は採らない。長さを持つ `Span` の作りに合い、手間は書く長さの分だけで、NUL 終端が要る C の側は返り値の位置に自分で書ける）。§4.2 の出口の行に足した。`std/text.onsa` の `write_to` の `SPEC-GAP(S-1012)` の印と、doc の「This version leaves … (§4.2 does not fix them)」は W5-13 で §4.2 の決まりの文に改める。
- 経緯: 140 回目（2026-11-12）、W5-12 U3b のテストの担当（onsa-test、NEW-2）が挙げた。
