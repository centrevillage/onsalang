# S-822 型引数を付けた `~` 無しの flow の呼び出し（`lp[F32](x)`）のコード

- 決定済みで戻さないもの: S-811（印と呼び先の種類の順）、S-239（`lp::[F32]` の E0412）、S-606（`lp[F32]~(x)` の構文の段の E0002）、S-256・S-277・S-333（`lp<F32>(x)` などの構文の段の E0020）、S-816（`lp.(x)` の E0308）。下書きの全文（各 S の「仕組みの出所」と「形の表」）は `target/notes/132/g95/draft.md`、入力は同じ所の `probe/`。
- 論点: §11.1 は flow の外の `~` 無しの flow の呼び出しを E0821 とし、§2.6 は flow の本体の `~` 無しの呼び出しを E0811 とする。§6.1 と §4.5 は、名前の経路に `[…]` を付けた呼び先を、項目なら型引数の E0020（候補 `::`）とする。§15.1 は flow を値の位置に書くと E0308 とする。
  `lp[F32](x)` は、flow の呼び出しの誤り（(1)）、項目の `P[…](…)` の E0020（(2)）、`lp[F32]` という添字の土台に flow を書いた値の位置の誤り（(3)）のどれにも読める。
  - 決定済み（論点から外す）: `lp::[F32](x)` と `lp::[F32]~(x)` の扱い（S-811 の順と S-239 の E0412。形の表）。`lp[F32]~(x)`・`lp[F32]!(x)` の構文の段の E0002（§2.6）。`lp<F32>(x)`・`lp::<F32>(x)`・`lp[F32, F32](x)` の構文の段の E0020（S-256、S-277、S-333）。`lp.(x)` の E0308（S-816）。
- 今の実装: 形の表のとおり、flow の外でも本体でも名前の段の E0308「`lp` is a flow, not a value」で、候補も note も無い。`lp[0](x)`、`lp[F32].(x)`、`let f = lp[F32]` も同じ E0308 である。
- 案: 
  - (a) 値の位置の E0308: `lp[F32]` は添字の土台に flow を書いた形で、§15.1 の flow を値の位置に書く E0308（`lp.(x)`・`lp[0](x)` と同じ）。候補なし、note は S-816 と同じ（本体なら `lp~(…)`、外なら名前空間の関数）。§6.1 の `P[…](…)` の E0020 の「項目」は関数と型で、flow は含めない。
  - (b) flow の呼び出しの誤り: `lp[…](…)` を `~` 無しの flow の呼び出しに数える。外は E0821（候補なし）、本体は E0811。E0811 の候補（`~` を足す）は当てると構文の段の E0002（`lp[F32]~(x)`）が残るので出さない。
  - (c) 項目の `P[…](…)` の E0020: flow も項目として名前の段の E0020。候補 `lp::[F32](x)` は、当てると同じ名前の段の E0821（外）か E0811（本体）が残るので出さない（§18.1）。note で `::[…]` の書き方を示す。
  - (d) 文脈で分ける: 外は E0821（(b) と同じ）、本体は (a) か (c)。
  - 形ごとの出力: 外の `lp[F32](x)` は、(a) が E0308、(b)・(d) が E0821、(c) が E0020。本体は、(a) が E0308、(b) が E0811、(c) が E0020、(d) が (a) か (c) に従う。どの案も候補は無い。
    `lp[0](x)`・`let f = lp[F32]` は、(a) では `lp[F32](x)` と同じ E0308。(b) では型引数か添字かで `lp[0](x)` の扱いを決める必要がある（中身で分けるか、全て flow の呼び出しに数えるか）。(c) では `let f = lp[F32]` も E0020（呼ばない形も R-179 の E0020）。
  - 書き手から見て（修復のループの回数）: この版の flow は型引数を取れないので、直った形は外なら名前空間の関数を使う書き直し、本体なら `lp~(x)` である。
    (a) は note がその形を示し、一回で直る（本体で `[F32]` を残して `~` だけ足すと、§2.6 の E0002 の note で二回目）。(b) は外の E0821 の note が同じ形を示し一回、本体の E0811 は「`~` が要る」だけを示すので、`lp[F32]~(x)` の E0002 を経て二回か三回。
    (c) は note が `::[…]` を示すので、外は `lp::[F32](x)` の E0821 を経て二回、本体は E0811（候補 `~`）と E0412（S-306 の候補）を経て三回。
  - 修正候補を当て続けて止まるか: どの案も `lp[F32](x)` に候補は無く、`no-candidate` で止まる。
  - 通るプログラム: どの案も変わらない（形は全て誤り）。
  - 規則と例外: (a) は §15.1 の flow を値の位置に書く規則をそのまま当て、§6.1 の E0020 の「項目」を関数と型に限る一句（または §15.1 の例に `lp[F32](x)` を足す一句）を足す。
    (b) は §11.1 の E0821 と §2.6 の E0811 の呼び出しの形に「名前の経路に `[…]` を付けた形」を足し、`lp[0](x)` の扱いを書く。(c) は規則を足さず、候補なしは §18.1 の約束から決まる。(d) は文脈で分ける一文を足す。
  - 実装の量: (a) は 0 行（W5-10 が `P[…](…)` の E0020 を入れるとき、flow を今の E0308 の道に残す。note を足すなら約 5〜10 行）。(b) は添字の呼び先の土台が flow なら `names/body/flow.rs::call_outside` と E0811 の道へ回す約 10〜20 行と、`lp[0](x)` の扱い。
    (c) は W5-10 の E0020 に flow を含め、候補を出さない条件で約 5〜10 行。(d) は (b) と (a) か (c) を合わせて約 15〜25 行。
  - 後の作業への手当て: (a) は値の位置の E0308 の道のままだが、flow が型引数を取る版になれば、`lp[F32](x)` を値の位置の E0308 から `P[…](…)` の E0020 へ移すか（flow を除く一句を外すか）を見直す。(b)・(d) は flow の呼び出しの形の判定に添字の形が加わり、W7-04（flow の本体の検査）と W7-10（修飾子）で同じ形を見る。(c) は、flow が型引数を取る版になれば候補を開くかを見る。
- 他言語: flow（状態を持つインスタンスを作る呼び出し）に当たる構文は一覧の言語に無い。型引数を取らない呼び先に角括弧の型引数を書いた形の他言語の扱いは、S-306 の他言語の項（rustc の E0107、Swift の「cannot specialize」）と同じで、手元でそれ以上は確かめていない。
- 推奨と理由: (a)。確度: 中。
  - 式の中の `[…]` は添字で（§4.5）、`lp[F32]` は flow を添字の土台という値の位置に書いた形である。`lp.(x)` を値の位置の E0308 にした S-816 と同じ理由がそのまま当たり、`lp[0](x)`・`lp[F32].(x)`・`let f = lp[F32]` と一つの規則で同じコードになる。
  - この版の flow は型引数を取れず、直した形（本体の `lp~(x)`、外の名前空間の関数）は型引数を含まない。note がその形を示すので、修復のループが最も短い。(c) は書き手を `::[…]` へ導き、E0821・E0811・E0412 を順に経る。
  - (b) は外では (a) と同じ回数だが、本体の E0811 が `[F32]` の誤りを示さず、`lp[0](x)` との区別の規則が増える。
  - 実装は今の道のままで、W5-10 は `P[…](…)` の E0020 を関数と型にだけ入れればよい。
  - あわせて決めること: `lp[F32](x)` の E0308 に、S-816 と同じ note（本体なら `lp~(…)`、外なら名前空間の関数）を付ける。`lp.(x)` の note と一緒に入れる（下の「別の問題」）。
  - 別の S にしてよい論点: flow が型引数を取る版での形（`lp::[F32]~(x)` の具体化）は、その版の決定で決める。
