# S-756 総称の `impl` の対象が、型の宣言の型パラメータの境界を満たさない形（`struct N[T: Num]` の後の `impl[T] N[T]`）: 見出しの E0416 にするか、`impl` の型パラメータが型の宣言の境界を受け継ぐか

- 決定済みで戻さないもの: 対象の型引数の書き方（パラメータを一度ずつ、S-137 の E0307）と、そこに書いた別名（S-753・S-754）。境界の並びの重なりと矛盾（S-747）、`?` を `Dup` 以外に付けた形（S-711）。
  型の宣言の境界の失敗した名前（S-689 の未知の境界）。別名の右辺の境界の誤り（S-757）。trait の `impl`（`impl[T] Show for N[T]`）はこの版では形の E0200（§18.1）で、この S に入らない。
  第 73 組の下書きの「S-756 の仕組みの出所」と「S-756 の形の表」の節（写しは `target/notes/81/g73/draft.md`）。
- 論点: §6.2（81・82 行）は総称の `impl` の対象の型引数を `impl` の型パラメータを一度ずつ並べたものに限り（E0307）、§4.5 は型の宣言の型パラメータに境界を書ける（`struct N[T: Num]`）。
  `impl[T] N[T]` のように、`impl` の型パラメータが型の宣言の境界を満たさないとき、見出しが誤りか、`impl` の `T` が型の宣言の境界を受け継ぐかは書いていない。
  R-37 は署名の `N[Bool]` を誤りとし、W4-05 の計画は `fn f[T](x: N[T])` も E0416 とするが、§18.1 が型の位置に数える `impl` の見出しの対象をそこに入れるかは決めていない。
- 今の実装: 形の表のとおり。見出しには何も出ず、`impl` の `T` は `Num` を持たない。境界に頼るメンバだけが、その本体で E0401（演算子）か E0416（struct のリテラル）になり、頼らないメンバは通る。
  関数の署名の `N[T]`・`N[Bool]` は今は通る（R-37 の前）。
- 案: どの案も、`impl` の型パラメータに書いた境界の意味と、対象の型引数の E0307 は変えない。
  - (a) 見出しの E0416: 対象の型引数が、型の宣言の境界（暗黙の `Dup` を含む）を満たさなければ E0416。`impl` の `T` が満たすかは、`impl` の `[ ]` に書いた境界だけで決める（関数の署名の `fn f[T](x: N[T])` と同じ判定）。
    見出しの誤りなので `impl` の全体が一つの単位で、メンバは検査しない（§18.1 の 61 行）。
  - (b) `impl` だけが受け継ぐ: `impl` の型パラメータは、書いた境界に、対象の同じ位置の型の宣言の境界を足したものを持つ。見出しは誤りにならず、`twice` の E0401 が消える。関数の署名は R-37 の計画のまま（`fn f[T](x: N[T])` は E0416）。
  - (c) 今のまま: 見出しを判定せず、受け継がない。境界に頼るメンバが、本体（E0401、E0416）か署名（U4a の後、メンバの署名の `N[T]` の E0416）で個別に誤りになる。
  - (d) 型の位置の全てで受け継ぐ: (b) を関数の署名にも当て、`fn f[T](x: N[T])` の `T` も `Num` を持つ。R-37 の計画の `fn f[T](x: N[T])` の E0416 を改める。
  - 形ごとの出力: `n01` は、(a) が見出しの E0416 だけ、(b)・(d) が通る、(c) が `twice` の E0401（U4a の後も同じ）。`n02` は、(a) が E0416、(b)〜(d) が通る。
    `n05`（`impl[T: Show]`）は、(a) が E0416、(b)・(d) が `T: Show + Num` で通る、(c) が通る。`n06`（`struct W[T]`、`impl[T: ?Dup]`）は、(a) が E0416、(c) が通る。(b)・(d) は書いた `?Dup` と受け継ぐ `Dup` が矛盾し、その扱いの規則が要る（S-747 の矛盾の E0416 に揃えるか、受け継ぐ方を勝たせるか）。
    `n08` は、(a) が見出しの E0416 だけ、(b)・(d) が通る、(c) がメンバの単位ごとに E0416。
  - 書き手から見て（修復のループの回数）: `n01` は、(a) が二回（E0416 を見て `impl[T: Num]` と書く）、(b)・(d) が一回、(c) が二回（E0401 を見て、`impl` の境界に `Num` を足す。今の E0401 は候補を持たない）。
    メンバが多いとき、(c) は境界に頼るメンバごとに誤りが出て、どれも同じ一か所（`impl` の `[ ]`）を直す。(a) は一つの誤りで直す所を示す。
    (b)・(d) は書かずに済むが、`impl` を読む人は `T` の境界を型の宣言まで見に行く。(b) では `impl` と関数で書き方が違い、関数で同じ形を書くと E0416 になる。
  - 修正候補: どの案も候補は要らない形で決められる。(a) で `impl[T: Num]` を足す候補を出すなら、意味を変えない（`N[T]` は `T: Num` のときだけ型になる）ので、当て続けて止まる。
    当てると `impl` の全体だった単位が見出しとメンバの単位に分かれるが、メンバに隠れた誤りがあれば当てる前の E0416 は唯一の誤りでないので、§18.1 の候補の約束は当たらない（S-748 の E0307 と同じ）。関数の署名の E0416 と揃えるなら、候補は出さない。
  - 通るプログラム: (a) は、今通る境界に頼らないメンバだけの `impl`（`n02`、`n05`、`n06`）を誤りにする。`tests/`・`std/`・`examples/` に当たる形は無い。
    (b)・(d) は、今の E0401 の形（`n01`）を通す。(d) は R-37 の計画で誤りになる関数の署名も通す。(c) は変えない。
  - 規則と例外: (a) は、型の位置の型引数を型の宣言の境界で判定する一つの規則（R-37）に、`impl` の見出しの対象を含めると一句書く。例外は足さない。
    (b) は、`impl` の型パラメータの境界の求め方の規則と、書いた `?Dup` と受け継ぐ `Dup` の矛盾の規則を足し、関数との違いが例外になる。(c) は、`impl` の見出しの対象を判定の根から外す例外を一つ書く。
    (d) は (b) の規則を関数にも広げ、R-37 の判定を「受け継いだ境界で満たす」に改める。
  - 実装の量（W4-05 の U4a）: (a) は、整形性の段の根に `impl` の対象を置き（見積もりの根の集めに入っている）、`impl` の generics で型パラメータの引数を判定する（関数の根と同じ道）。
    見出しの誤りで `impl` の全体を一つの単位にするのは、`impl` の def に診断を付ける今の E0307 の道に乗れば 0〜3 行（確かめていない）。
    (b) は、`lower_generics` の後に対象の型の宣言の境界を位置で写し、`?Dup` の矛盾を判定して約 +10〜20 行。型の宣言の generics が `impl` の見出しより先に下りているかは確かめていない。(c) は根から `impl` の対象を外して 0〜−2 行。
    (d) は (b) に関数の署名の型の歩きで境界を集める分を足し、呼ぶ側の要求の判定（`satisfies`）と `onsa interface` の境界の表示も改める（見積もっていない。数十行の見込み）。
  - 後の作業への手当て: (a) は、W5-05 で境界にできる trait が増えても、判定は共有する `satisfies` を読むので何も足さない。第 2 期の trait の `impl`（`impl[T] Show for N[T]`）も同じ判定の根に入る。
    (b)・(d) は、境界を受け継ぐ所が増えるたびに（trait の `impl`、上位の trait、第 2 期の利用者の trait）、受け継ぐ規則と §6.3 の E0401 の候補（既にある境界を置き換える）との関係の手当てが続く。(c) は、メンバの署名の E0416 がメンバごとに出る形が残る。
- 他言語: 
  - rustc 1.94.1（`probe/other/r1.rs`・`r2.rs`）: `struct N<T: Num>` の後の `impl<T> N<T> { fn get(self) -> T }` は E0277「the trait bound `T: Num` is not satisfied」を、見出しの `N<T>`（4:9）とメソッドの `self`（5:16）の二か所に出し、どちらも help で `impl<T: Num> N<T>` を示す。
    `fn g<T>(n: N<T>) -> T` も E0277。型の宣言の境界を受け継ぐ implied bounds は RFC 2089（[RFC](https://rust-lang.github.io/rfcs/2089-implied-bounds.html)）で提案されたが、1.94.1 では受け継がない（`r1`・`r2` の結果）。
  - swiftc 6.3.1（`probe/other/s1.swift`）: `struct N<T: Numeric>` の `extension N { func twice() -> T { a + a } }` は通る（extension は型パラメータを書き直さず、型の制約を持つ）。`func g<T>(_ n: N<T>) -> T { n.a + n.a }` も通る（署名の型から要求を推論する）。
  - Haskell: `data Eq a => Foo a = …` の datatype contexts は、その制約を関数に与えず（使う関数にも `Eq a` が要る）、廃止予定の拡張である（[GHC User's Guide](https://haskell.org/ghc/docs/latest/html/users_guide/exts/datatype_contexts.html)、[Discourse](https://discourse.haskell.org/t/datatypecontexts-has-something-changed-since-it-was-marked-deprecated/7560)）。
    手元に処理系が無く、動かしていない。
  - C#・Java・Kotlin・TypeScript は手元に無く未確認。
- 推奨と理由: (a)。確度: 中。
  - 型の位置の型引数を型の宣言の境界で判定する規則（R-37）を、§18.1 が型の位置に数える `impl` の見出しにもそのまま当てる形で、例外を足さない。関数の署名の `fn f[T](x: N[T])` と `impl[T] N[T]` が同じ答えになる。
  - `impl` の型パラメータの境界が `[ ]` に書いたものだけで決まり、読む人が型の宣言を見に行かずに済む（§6.2 の「宣言の形は関数の型パラメータと同じ」と揃う）。
    (b) は関数との違いと `?Dup` の矛盾の規則を足し、(d) は R-37 の判定と表示を改め、どちらも境界を受け継ぐ所が増えるたびに手当てが続く。
  - (c) は、メンバの署名と本体の誤りが、直す所（`impl` の `[ ]`）から離れた位置にメンバごとに出る。(a) は一回の検査で直す所を示す。
  - 誤りにする方が厳しく、後で受け継ぐ規則を足して緩めても既存のプログラムを壊さない。今通る形を誤りにするが、`tests/`・`std/`・`examples/` に当たる形は無い。
  - 実装は U4a の計画の根の一つで、足す行が少ない。
  - あわせて決めること: 位置は対象の型引数（`N[T]` の `T`）で、型の宣言の境界を位置付きの note で示す（関数の署名の E0416 と同じ形）。段は型の段で、名前の段の E0307 の見出し（`impl N[Bool]`、別名）には出さない（§18.1 の段の順）。
    候補は出さない（関数の署名の E0416 と揃える。要れば後で両方に足せる）。境界の判定は関数の署名と同じで、型の宣言の境界の未知の境界（S-689）と、`impl` の型パラメータの未知の境界（S-711・S-747 の E0416 を付けたもの）は判定しない。
    メンバの名前は、見出しの誤りのある `impl` でも型の `.` の空間に数え、使う所は他の `impl` のメンバと同じに引く（§18.1 の 86 行の一般則。E0307 の `impl` の文と同じ扱い）。
  - 別の S にしてよい論点: 無い。仕様の本文に、署名の型引数が型の宣言の境界を満たさない E0416 の一般の文が無いことは、R-37 の反映（W4-05）で書く（下の「別の問題」）。
- 影響: 仕様 §6.2 の 82 行の後に一句（(a) は「対象の型引数が型の宣言の境界を満たさなければ E0416、§4.5」、(b) は受け継ぐ規則と `?Dup` の扱い、(c) は対象を判定しない例外、(d) は §4.5 の境界の求め方の規則）。`tasks/diag-codes.md` の E0416 の行に S-756。
