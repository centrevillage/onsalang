# S-218

- 空白: 利用者の関数の引数の型に、flow の生成する型 `voice.In` / `voice.Out` を書けるか。§11.6 と §5.3 は引数の位置の struct リテラルだけを示す。W2-11/t で見つけた（2026-10-08）
- 決定（2026-11-16、利用者、159 回目、第 106 組）: (b)。借用の起点（既定のモードの引数、借用の束縛）の生成型 `In` / `Out` そのものは、`Span` と同じく借用の行で `let`・`match` の腕に束縛でき、名前は第二級のまま（返す・保存する・捕捉する・`move` は E0710）。`inout` の引数からと所有の行は E0710（S-217 と同じ）。§5.3 の「引数の位置にだけ現れる」をビューの束縛に改め、S-927 の結論（`?Escape` の型引数に `In` / `Out` は E0710）は変えず、理由を「`Out` の配列ができる（S-770）」に書き直した。
  理由: 書き手が困るケースはどちらの案にも無い。(b) は `Span`・平面の配列と同じ規則で第二級の類が一つ少なく、Core では既に `Span` と同じ形（`let k: T = o`）に下り、U3・W8・W10-02 に追加の手当てが要らない（第 106 組の段 1 と、(b) の想定漏れの確かめ `target/notes/159/g106/`）。利用者「もし想定外の問題が起きたら考え直しましょう」: 実装で想定外の問題が出たら比べ直す。
  実装（W7-12 U2）: modes の `class_of` に生成型をビューとして入れる。署名の段の `fits` は `?Escape` の型引数の位置 `LIFTED` が束縛の位置 `Pos::Bind` を共有するので、生成型を足すと S-927 の E0710 が黙って外れる。S-927 の三形（書いた型引数、推論、struct の型引数）の事例を先に置き、`LIFTED` と平面の配列の注釈を分ける（+8〜15）。
- 提案: W7-03 の着手の前に決める
- 時期: W7
- 補い（2026-10-23、利用者が了承。58 回目、文書の点検）: S-217 で借用の起点から取った `Span` を束縛できるようにしたので、`In` / `Out` を引数の型に書けるようにするなら、`In` / `Out` そのもの（`let i = inp`）とフィールドの `Span`（`let l = inp.l`）を束縛できるかもあわせて決め、§5.3 と §11.6 の「引数の位置にだけ現れる」の文をそのときに改める
