# S-462

- 空白: 名前の段の誤りの `use`（`use std.math.{nosuch}`）から使う所への E0302 の連鎖（`use` の 1:15 と使う所の 4:3 に二つ）。R-180 は構文の段で失敗した `use` だけを扱い、§18.1 の S-59 の文は構文の段の話である。
  解決できなかった `use` の名前を誤りの定義に束縛し、使う所を黙らせるか（R-180 の扱いを名前の段に延ばす。第 25 組の下書きと Fable の見立て）。W4-04 の後は使う所の E0302 に `use` の挿入の候補が付き、修復のループが無関係の編集をする。第 25 組の下書きの付録で見つけた（2026-10-13）
- 提案: W4-03 の範囲（空白の組）
- 時期: W4
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目、第 39 組）: (a)。名前の段で失敗した `use`（取り込む先が無い、見えない、取り込めない種類）の取り込む名前は誤りとして扱い、使う所に診断を出さない（経路が失敗すれば並びの全ての名前、要素が失敗すればその名前）。見えない項目（E0303）の取り込みも同じ。
  失敗した `use` の名前は束縛として数えず（見つからない名前を黙らせる集合に入れる）、E0304 の相手にしない。同じ名前の本物の束縛が見えていれば、使う所はそれを指す（S-17 の二度目の `use` の E0304 は解決した `use` の間の規則）。一つの `use` で複数の名前が失敗しても報告は単位ごとに一つ。
  R-180 のモジュール単位の印は、取り込む名前を全部は読めなかった `use`（並びの途中で失敗した形）に限る。取り込む名前が読めている構文の段の誤り（S-594 の `use kp.clock` の E0200 など）は、この決定の集合に入れる。空の並びは何も取り込まないので印を立てない。
  仕様 §18.1。`pub use` で再公開した失敗の名前を他のモジュールが取り込む形は、モジュールの再公開（S-596）と一緒に決める
  改め（2026-10-23、S-596）: 再公開は第 2 期まで E0200 になった。E0200 の `pub use` の取り込む名前も失敗した名前で、他のモジュールが取り込む `use main.{g}` の名前も誤りとして扱う（§18.1）。
- 経緯: 55 回目、第 39 組（族「名前の段の誤りの連鎖」、下書き `S-462.draft.md`、助言の担当の二段）で決めた。E0304 の相手にするかは段 1 と割れ、段 2 が下書き（相手にしない）を採った。
- 補い（2026-10-25、親）: 69 回目（W4-03 U3b2 の壊す側の空白 G2、利用者が了承）: 並びの要素が予約語かキーワードの `use kp.{clock}`・`use std.{test}` は、取り込む名前まで読めているので「取り込む名前を全部は読めなかった `use`」に当たらず、モジュールの見つからない名前を黙らせない（その名前だけが失敗した名前。並びの無い `use kp.clock` と同じ）。
