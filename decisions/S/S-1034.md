# S-1034 所有する Dup の値のフィールドの経路を、最後の使用で消費する位置に置く形の `Alloc`（`fn f(move p: (Str, U32)) -> Str { p.0 }`、`fn into(move self) -> Str { self.s }`）

- 空白: §5.2 は、所有する値の Copy と Shared のフィールドは複製されるので値を消費しないとする。そのため `fn f(move p: (Str, U32)) -> Str { p.0 }` と `impl H { fn into(move self) -> Str { self.s } }`（`H` は `s: Str` だけの struct）は、`p`・`self` の全体の破棄で `Alloc` が要る（今は E0601、target/notes/146/g98/probe/gap/ の `o_more` の `dup_field_ret`・`o_pos` の `moveself_recv`）。分解の `let (s, _) = move p` の後の `s` なら、S-1030 で消費する位置の最後の使用を移す読みを採れば要らない。
  Affine の取り出し（S-85、§5.2）と同じく「フィールドを取り出し、残りを破棄する」形を Dup のフィールドにも当てるか。取り出しの降下（W8-04。今は `Feature::TakenFields` の E0200）と残りの破棄の判定（`rest_drops`）に関わる。
  今入れると、取り出しの E0200 が境界の無い `T` の経路（`fn first[T](move p: (T, U32)) -> T { p.0 }`）に当たり、W8-04 まで dev が後退する（第 98 組の段 1）。後で入れても通るプログラムは壊れない。フィールドごとの状態を持たないので、`(p.0, p.1)` は取り出しを入れても残りの破棄が残る。
