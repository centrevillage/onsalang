# S-686 既にある循環の成分の中に辺を足す `use` の候補は「循環を閉じる」か（`a`→`b`→`c`→`a` の循環で、`a` の本体の `c.h()` の候補 `use c`）

- 決定済みで戻さないもの: S-673（自分のパッケージ名・自分の絶対経路・自分の名前の頭を外す候補とその細部）、S-663（`use` の頭の自分のパッケージ名の候補）、S-679（自分を取り込む `use` は E0302）、S-682（循環で出さない候補の note）、S-683、R-268（候補は経路が最後まで解決し循環を閉じないときだけ）、S-594 の辺の数え方。
  第 60 組の下書きの「仕組みの出所と目的」の節（写しは `target/notes/67/g60/draft.md`）。
- 論点: §15.1「これらの候補は、当てた後の経路が名前の段で最後まで解決し、足す `use` が循環を閉じないときだけ出し」。既にある循環の成分の中に辺を足すとき、足した辺は新しい循環（`a`→`c`→`a`）の上にあるが、E0310 の成分（`a`、`b`、`c`）は変わらない。
  どちらを「閉じる」とするかを書いていない。同じ語は `use` の頭の候補（S-663）と S-682 の note にも使う。
- 今の実装: `h5`（`a.onsa` は `use b.{g}`、`b.onsa` は `use c.{h}`、`c.onsa` は `use a.{f}`、`a` の本体に `c.h()`）: `a.onsa` の 1 行目に E0310「the modules `a`, `b`, `c` import each other」と rule「no `use` of the cycle narrows to cut it」。`c.h()` の E0302 に候補も note も無い。
  当てた形 `h5_1_applied`（`use c` を足し `c.h()`）は、同じ E0310 だけで、位置も 1 行目のまま（足す `use` は最後の `use` の後に入るので、そのファイルで最初にならない）。
  `n1`（`a.onsa` は `use p` と本体 `p.k()`、`p/q.onsa` は `use r.{h}`、`r.onsa` は `use a.{f}`、`a` の本体に `r.h()`）: E0310 の成分は `a`、`p.q`、`r` で、note「narrow it to what is used (`use p.{…}`)」。`r.h()` に候補なし。
  `n1_1_applied`（`use r` を足した形）は、同じ成分の E0310 で、note が「no `use` of the cycle narrows to cut it」に変わる。`n1_narrowed`（E0310 の note に従って `use p.{k}` に狭めた形）は E0310 が消え、`r.h()` の E0302 が候補なしで残る（`use r` は新しい循環を閉じる）。
  `n2_head`（`h5` の `a` に `use fx.c.{h}`）: 頭の E0302 に候補なし（S-663 の候補も同じ判定）。
- 案:
  - (1) 新しい成分を作るか、成分にモジュールを加えるときだけ閉じる。自分が既に二つ以上のモジュールの成分にあり、足す辺の先から自分へ戻る道が全てその成分の中のモジュールだけを通るなら、閉じない。
  - (2) 当てた後に足した辺が循環の上にあれば閉じる（成分の中の辺も閉じる）。今の実装と同じ。
  - (3) (1) に加え、当てた後に E0310 の狭め方の note が無くなる（狭めて切れた循環が切れなくなる）ときも出さない。

  | 入力 | (1) | (2) | (3) |
  |---|---|---|---|
  | `h5` | 候補 `use c`。当てた後も同じ E0310（rule のまま） | 候補なし、S-682 の note（`use c` と相手 `c`） | (1) と同じ |
  | `n1` | 候補 `use r`。当てると E0310 の狭め方の note が消える | 候補なし、note | 候補なし、note |
  | `n2_head` | 候補「`fx.` を外す」（`use c.{h}`） | 候補なし、note | (1) と同じ |
  | 循環の無いパッケージ（`pkg_body_path_cycle`） | 候補なし | 候補なし | 候補なし |

  - §18.1 の約束: (1)・(3) では当てた後も E0310 が残る。今の位置（成分の中の最初の `use`）では足した `use` に付かないので、触れた単位に残らない。E0310 の数と位置は仕様が決めておらず（S-645）、`use` ごとに付ける形に変えると、足した `use` に付いて約束を破る。(2) は位置によらない。
  - 当て続け: (1) は E0302 が消え、E0310 だけで止まる。(2) は候補の無い E0302 と E0310 で止まる。どちらも、書き手が循環を手で直すまで通らない。
  - 書き手から見た形: (1) では本体の単位が型の段へ進み、後の段の誤りが一回早く見える。代わりに循環の辺が一つ増え、`n1` では狭めて直せた循環が、`use` を外さないと直らない循環になる。(2) では、note が「この `use` も循環に入る」ことを示す。
  - S-682 の note との揃い: (2) は、循環で出さない全ての候補に同じ note を付ける（既にある循環でも、足す `use` は相手のモジュールと循環する）。(1) は新しい循環のときだけ note を付ける。
  - 実装（`names/cycles.rs` の `closes_cycle`）: (2) は 0 行。(1) は、成分ごとのモジュールの数を作るときに数え、辿る印を「自分の成分の外のモジュールを通ったか」に変える（成分が二つ以上のモジュールのとき。約 +6〜10 行と事例 2〜3 件）。
    (3) は (1) に加え、当てた後の狭めたグラフで切れるかを足す辺ごとに確かめる（約 +15〜25 行）。
- 他言語:

- 推奨と理由: (2)。確度: 中。
  - 足した `use` は、書き手が後で循環を直すときに外す辺の一つである。(1) の候補はその辺を足し、`n1` のように狭めて直せた循環を直せない循環に変える（`n1_1_applied`）。(2) なら、note が「その依存は循環する」ことを先に示す。
  - (1) が §18.1 の約束を満たすのは、E0310 の位置という仕様が決めていない細部による。(2) は位置によらず、後で E0310 の位置を決めても変わらない。
  - 実装を増やさない（今と同じ）。候補を出さない向きなので、後で (1) に緩めても通るプログラムは変わらない。(3) は判定が二つになる割に、(1) の利点（本体が型の段へ進む）が `h5` の形に限られる。
  - あわせて決めること: 同じ意味を `use` の頭の候補（S-663、`n2_head`）と S-687 の判定にも当てる（三つが `closes_cycle` を共有する）。§15.1 の語は「足す `use` が循環の上に来ない」と言い換える。
- 影響: 仕様は §15.1 の本体の経路の候補の文の「循環を閉じない」に一文（(1) は「新しい循環を作らない（E0310 の成分を変えない）」、(2) は「既にある循環の中に辺を足すときも出さない」、(3) は (1) と狭め方の条件）。S-663 の文も同じ語を指す。診断のコードは変わらない。
