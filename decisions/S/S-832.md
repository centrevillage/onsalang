# S-832 `@export` の項目を出すビルドの `prefix` の E1104 の段（S-641 の `prefix` の分。§18.1 の「ソースを読む前に」と「同じ回」）

- 空白: §18.1 は、マニフェストを読む全てのコマンドがソースを読む前にマニフェスト全体を検査するとし、S-827 の細部で「`--target` を取るコマンドは、そのターゲットに依る検査もマニフェストの検査と同じ回に行い、まとめて報告する」を足した。別の文が挙げるターゲットに依る検査には「`prefix` が要るか（`@export` の項目を出すか、§14.2）」があるが、`@export` の項目があるかはソースを読まないと分からない。
  S-641 はこの形（ソースを読まないと決まらないマニフェストの誤り）を M10 の前に決めるとしていたが、`prefix` の E1104 は W4-02 の U3 が作る（設計メモ `target/notes/95/w402/memo.md` の 2.3 は、ソースの検査の後に出す仮の扱いで `SPEC-GAP(S-641)`）。
  読みは (a) `build` がソースの検査を通った後に調べる (b) 構文の段の後に `@export` の有無を見て、検査の誤りと同じ回に出す (c) C を出すターゲットでは `@export` によらず必須にする（ソースを読まずに決まる。S-639 の (p2) を逆にする）に割れる
- 決定: 決定（2026-11-01、利用者。96 回目）: (a)。`prefix` の E1104 は、`build` がソースの検査を通った後に調べる（§14.2 のターゲットで決まる検査と同じく、そのターゲットのビルドの検査）。検査の誤りがあれば検査の誤り（終了コード 1）だけを出し、E1104 は出さない。
  E1104 は `onsa.toml` を指すので終了コード 2（§18.1）。`test --target` と `interface --target` は C を出さないので `prefix` を調べない。§18.1 の「同じ回」は、ソースを読まずに決まるターゲットの検査（`platform` が要るか、そのプラットフォームを扱えるか）に限る。
  理由: 実装は設計メモの U3 の予定のままで、仮の印を外すだけ。規則は「ソースを読まずに決まる検査はソースの前、ソースで決まる検査はソースの検査の後」の一本の線で分かれ、新しい規則（終了コードが混ざるとき、`@export` が読めないファイルがあるとき）を足さない。
  往復が増えるのは `prefix` が無く検査の誤りもある場面だけで、候補 `prefix = "<package>_"` は一つに決まる。案 (b) は二つの規則を足し、(c) は既決の S-639 の (p2) を逆にする。仕様 §18.1、`tasks/diag-codes.md` の E1104 の行。実装は W4-02 の U3（`SPEC-GAP(S-641)` を外す）
- 経緯: 96 回目（2026-11-01）、95 回目の範囲の文書の点検（onsa-docs、`020e8fae..2aa630af`）の指摘 8 で見つけ、親が §18.1、§14.2、S-827 の下書き（「`prefix` の E1104 の段（S-641、未決）」と、段 2 の置き場の答えの「`platform`・`prefix` の E1104 をマニフェストの検査と同じ回」）、設計メモの 2.3 で確かめた。
  S-641 の `prefix` の分を分けた（S-641 は `[[plugin]]` の `flow` の E1103 の分が OPEN のまま）。関係: S-641、S-827、S-639
