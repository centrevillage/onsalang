# S-1264 検査付きの添字の代入先に集成体を直接構築する形（`ps[i] = mk(k)`）で、右辺の panic と添字の検査のどちらが先か（§3.5 の「右辺を先に評価し、その後に代入先の場所」と、§12.7 の代入先への直接構築がぶつかる）

- 空白: §3.5 は「代入は右辺を先に評価し、その後に代入先の場所（添字の式）を評価する」「この順で最初に panic する式が報告される」とし、§12.7 は集成体を返す式を置き場所（代入先を含む）に直接構築するとする。添字の検査の前には代入先の番地が決まらないので、検査付きの添字の代入先 `ps[i] = mk(k)`（`mk` が集成体を返す）では、(1) §3.5 のとおり右辺を先に評価し、一時に作って写す（§12.7 の直接構築の外）か、(2) 直接構築を保ち、添字の検査を右辺より先にする（§3.5 の例外）かが割れる。
  今: 解釈器は右辺が先（`i = 5`、右辺が 0 で割る入力で `division by zero`）。C は `emit/fns.rs` の `assign_into` と `index_access` で `mk(&ps.a[onsa_idx(…)], k)` となり添字が先の見込み（走らせていない）。大きな状態（`self.voices[i] = voice.init(…)`）では、(1) はスタックの一時と写しが増える。再現の入力 `target/notes/191/w801/p1review/probe/p3b.onsa`。
- 決定（2026-11-27、利用者。191 回目）: (1)（下書きの (a)）。§3.5 の代入の順を例外なしに保つ（`ps[i] = mk(k)` で `mk` も添字も panic するなら `mk`）。添字を含む代入先と、要素を作った後に早い出口（`?`・`return`・`break`・`continue`）で抜けうる右辺（`w.p = P { a: mk(k), b: r? }`）では、§12.7 の直接構築を保証しない（コンパイラは一時に作ってからコピーしてよい）。保証の外を「範囲の検査が要る添字」に限らないのは、字の監査が、検査を除ける添字（`ps[next(inout k) % N] = mk(k)`）を保証に入れると §3.5 と食い違うと示したため。直接作る自由は P1〜P3 の実装に残す。要素に直接作る書き方は `fill(inout ps[i], k)`。
  利用者は、性能の影響（一時と写しの費用の測り）と、順を直さないときの弊害（ラウンドロビンのボイスの割り当てで、インタプリタは `vs[1]`、今の C は `vs[0]` に書く）の説明の後に「(a)で良いですが、実行性能を落とさないよう注意して」。性能の条件は、親が次の約束にして W8-03・W8-05 に渡す:
  - P1 一時に作るのは、宛先が範囲の検査を持ち、かつ右辺が panic しうるか何かを書きうるときだけ。右辺が純な形（`self.notes[i] = Some(note)`）は直接作る。
  - P2 範囲内と決まる添字（定数の添字、`for` の添字、降下が作る添字: `par`・`par~` の `init`・`reset`、遅延の書き位置）を検査付きにしない（§9.2 の検査の除去）。今の C が直接作っている降下の生成コードに一時を入れない。
  - P3 残る形（動的な添字と、panic しうるか書きうる右辺）でも、§3.5 の順が見えない条件（添字の式が純で panic せず、右辺が添字の読む変数と宛先を読まず書かない）では、添字を先に求め、範囲内なら直接作り、範囲外のときだけ右辺を一時に作ってから panic する形を W8-05 のメモで設計して測る（範囲外の道の一時を速い道の枠に置かない）。
  - P4 W8-03・W8-05 の単位の受け入れに、`examples/`・std・事例の生成した C の写しの数（`audit --memory`）、`audit --stack`、`compare.py speed` の前後を入れ、今より増える所は一つずつ説明する。
  あわせて: C が代入先の場所を先に評価する形は R-93 の補い（W8-03）、同じ場所を出力と引数に渡す形は R-09 の補い（W8-05）とした。§3.5 の panic の箇条に例を一つ足す。要素を作った後に抜ける右辺は、独立のレビューの足しで同じ §12.7 の一項に含めた（下書きは空白でないと見ていた）。P3 の範囲内の道で右辺が途中で panic したときの宛先の値は S-1266（細部）。
- 経緯: 191 回目（2026-11-27）、W8-01 の設計メモ部 1 の独立の審査（onsa-advisor）が、利用者の判断が要る点の漏れとして挙げた（メモ 2.4 の 5 は (1) を黙って選んでいた）。W8-03（正規形と評価順）の前に決める。
