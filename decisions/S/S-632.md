# S-632 族: @param・@host・@latency の責任範囲

- 空白: §6.5 は `@param`・`@host`・`@latency` を「UI とホストのための情報」とし、ターゲットに固有の事情が関わらない段までの解釈を変えないとする（S-624）が、どの段がこれらの情報を持ち、使い、誤りを出すかを書かない。
  §11.6 の `params_default()`・`latency()` はターゲットを選ばない段の Onsa のコードに属性の値を見せ（S-625）、`@host` と `@latency` の場所と値の誤りの段も決まっていない（S-588）。族の規則を一つ決め、S-625 と S-588 をそこから決める。
- 決定: 決定（2026-10-24、利用者が了承。60 回目、第 50 組）: 族の規則。属性（`@param`・`@host`・`@latency`）の値を読むのは、ターゲットの段（C の API、ラッパー、WASM）と道具（`onsa interface`、`onsa test --flows`、IDE）で、この版の Onsa のコードには属性の値を読む手段が無い（軸 A の (ii)）。
  §6.5 の 1 文目（S-624）は変えず、この文を後に足す。Onsa のコードから読むリフレクションの API は A-15 に保留した。
  軸 B（誤りの段）: 属性自身の誤り（位置と値。族の表の 2〜4・7〜14 行）は、export するかによらず `onsa check` で出す。export の必須（E0809）と境界の型（E0810）も、S-639 の `@export` により宣言の位置で `onsa check` が出す（51-A3）。ターゲットで決まるもの（E0610・E0820・E1011、プラグインの条件の S-581・S-583）はそのビルドで出す。
  `onsa interface` は `@host`・`@latency` も出す（A4。§18.2 の「@param だけを出力」を直した）。規則から決まる S: S-625（`params_default()`・`latency(s)` を Onsa の生成する API から外す）、S-588 の誤りの段。
  理由（下書きと独立のレビューが一致）: §6.5 の 1 文目を例外なしに保ち、属性をコード生成の注釈にとどめる。既定の値と遅れの式は同じパッケージの `const` と fn で書け、C のホストは Onsa の `const` を読めないので C の `<p>_params_default`・`<p>_latency` は残す。後で読む API を足しても、名前空間に利用者の項目は入らないので既存のプログラムを壊さない。仕様 §6.5、§11.6、§11.7、§14.2、§18.2
- 経緯: 60 回目（2026-10-24）、同じ族の未決の S が二つ（S-625・S-588）なので族の規則の S として登録した。族と整理する範囲は S-625 の経緯（59 回目、利用者が了承）。
  60 回目（2026-10-24）、第 50 組（族「`@param`・`@host`・`@latency` の責任範囲」、下書き `S-632.draft.md`、助言の担当の二段）。下書きと段 1・段 2 は軸 A の (ii) で一致し、段 2 は利用者の向き（案 (v) のリフレクション）から軸 A を利用者の判断にした。軸 B は下書きの (e2) と段 1・段 2 の (e1) に割れ、S-639（第 51 組）で決まった。
  利用者は B1 で「Onsa内でのリフレクションは必要になるまで実装しない、で良いと思います」とし、親の「この版では」の字と A-15 の案を了承した。確認だけの項目 A1〜A5 を了承した（「A1-5: OK」）。
