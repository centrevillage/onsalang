# S-403 入力と出力の完全に同じポインタで、要素の型が違う形

- 空白: 入力と出力に完全に同じポインタを渡し、要素の大きさが違う形（`F32` の入力と `F64` の出力）。§14.2 は「完全に同じポインタ（in-place 処理）であってよい。部分的な重なり … は検出して 2 を返す」とし、始まりが同じで長さのバイト数が違う範囲を書かない。
  読みは (1) 始まりが同じなら型によらず許す（0 番のサンプルの出力が入力の 1 番を壊す）、(2) バイトの範囲が同じときだけ許し、長さが違えば部分的な重なりとして 2、(3) 型まで同じときだけ許す。今の実装は範囲を一方の要素の大きさで測るので 0 を返して入力を壊す（R-141）。W2-08/i の設計メモで見つけた（2026-10-10。仮の扱いは (2)）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (3) を了承。下書きと Fable が一致、第 21 組）: in-place として許すのは、入力と出力の組ごとに要素の型が同じときだけ。
  型が違えば、始まりが同じでも、大きさが同じ（`F32` と `I32`、`U8` と `Bool`）でも 2（C では違う型として同じ記憶域を読み書きすることになり、実効型の規則 C11 §6.5p7 に反する）。
  生成は、型の違う組を二つの出力の組と同じ `(const void*)a == (const void*)b ||` の形で出し、ランタイムは変えない（判断は生成のときの型の比較一か所）。struct の出力はフィールドごと、`[Span[T]; N]` はチャンネルごとの `T` で比べる。仕様 §14.2。実装は W2-08
