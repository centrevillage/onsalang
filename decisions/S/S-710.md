# S-710 flow の見出しの字面で決まる誤り（入出力の時計の欠けと出力の時計の E0810、入出力のモードの E0806）が §18.1 のどの段か（名前の段か、flow の検査の段か）

- 空白: §11.3 は「flow の入力と出力には `at` が必須（E0810）。出力のクロックは `sample`、…それ以外は E0810」とする。§18.1 は段の順（名前 → 型 → flow の検査）と、名前の段に入る flow の検査（「名前と字面で決まるもの」: E0811・E0812・E0821・E0801・本体の制限の E0806）を挙げるが、見出しの時計の誤りと、見出しの入出力のモード（`inout`）の E0806 がどの段かは書いていない。
  一つの flow の見出しに誤りが二つあるとき、どれを報告するかがこれで決まる。読みは (1) 値の型の E0810 と同じ flow の検査の段（同じ flow の中では位置の順）、(2) 字面で決まるので名前の段（型の段の E0408 や、値の型の E0810・`@param` の E0809 より先）、で割れる。
  W4-03 U5a の後の実装は (2) で動く（`flow g(@param(min: 99999999999999999999999999999999999999999.0) x: F32 at block, y: F32) -> F32 at sample` は E0810 の時計の欠け、U5a の前は位置の順で E0408）。時計の欠けと名前の段の E0302 は、どちらの版も位置の順。
- 決定: (2)（2026-10-26、利用者。71 回目）。flow の見出しの時計の欠けと、入出力に書いた時計の種類（E0810）、入出力のモード（E0806）は字面で決まるので、§18.1 の名前の段の flow の検査の一覧に足す。W4-03 U5a の後の実装のとおりで、実装は変えない。
  理由: `at` を書いたかと、時計の名前が指すものは、型を調べずに字面と名前の解決で決まり、§18.1 の原則（名前と字面で決まるものは名前の段）に当たる。
  将来のクロック総称（`flow g[clock c](x: F32 at c)` の形。仕様は未定）を考えても違いは無い: `at` の欠けと時計の名前が指すもの（パラメータか組込みの時計か）は名前の段のままで、時計の値に頼る制約（`sample / N` の N など）は字面で決まらないので、原則によって名前の段の外に入る（利用者が問い、違いが無ければ (2) とした）。
- 経緯: 71 回目（2026-10-26）、W4-03 U5a の壊す側（onsa-break）が、段の分けで残る診断が変わる形（指摘 1）として見つけ、親が U5a の前と後のバイナリで再現した（再現は `target/notes/71/w403/u5a/pp/` の `a1`〜`a4`）。
- 補い（2026-10-26、親）: 72 回目の文書の点検（指摘 1〜3）を受けて、利用者が了承した（2026-10-26）。(1) 決定の「実装は変えない」は誤りだった。
  実装の診断の段の印（`sig/flow_sig.rs` の `Stage::Flow`）が古いままで、見出しの誤りと本体の名前の誤り（E0302）が同じ単位にあると E0302 を報告する（§18.1 では位置の順で見出しの E0810。親は見出しの中だけで確かめていた）。
  W4-03 の U5b で、印と登録簿（`codes.rs`、`tasks/diag-codes.md`）を §18.1 に揃える。(2) 出力にはモードを書けない（構文の E0002）ので、§18.1 の「入出力のモード」を「入力のモード」に改め、入力のモードの E0806 を §11.2 に書いた（M2 の実装の規則で、仕様の文も S も無かった）。
  (3) 一番外の flow の境界の `sample / N`・`sample * N` の E0810（§11.9）は使い方で決まるので flow の検査の段のままで、§18.1 に書き添えた。
- 補い（2026-10-26、親）: W4-03 U5b（`bbf69ce`、72 回目）で、flow の見出しの E0810・E0806 の印を名前の段にし、登録簿（`codes.rs`、`tasks/diag-codes.md`）を §18.1 に揃えた。上の補いの「U5b で揃える」は済んだ（73 回目の文書の点検）。
