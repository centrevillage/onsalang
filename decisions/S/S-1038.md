# S-1038 `inout` の引数（全体・フィールド・要素）への代入で、前の値を破棄するか（`fn f(inout s: Str, t: Str) { s = t }`）

- 空白: §5.4 の表は `inout` の引数を「`inout`（所有しない）」とし、破棄を「起きない」とする（束縛の有効範囲の終わりの行）。§12.2 は所有する Shared 値・`Buf` の破棄に `Alloc` が要るとし、R-32 の決定は上書きを見落とさないとする。`tasks/phase2.md` の L5（決定済み、第 2 期）は、`rt` の関数の `inout st` の `st.cur.name = "mix"` が E0601 になることを前提にする。仕様は、`inout` の場所への代入で前の値（呼び出し側が所有する値）が破棄されることを書かない。
  今（`702a4619`。上書きを数えない R-32）: `fn f(inout s: Str, t: Str) { s = t }`、`fn f(inout u: Ui, move b: Buf[F32]) { u.cur = move b }`、`rt fn f(inout b: Buf[F32], move c: Buf[F32]) { b = move c }`、`fn f(inout xs: [Str; 2], t: Str) { xs[0] = t }` はどれも通る。入力は `target/notes/146/w602/memo/probe/c.txt`。
  読み: (1) 代入は前の値を破棄する（`Alloc` が要る。上書きの破棄点に `inout` の場所への代入も含め、§12.2 に一句） (2) 破棄に数えない（`rt` の関数が `inout` への代入で解放できる）。設計メモは (1) を「確認だけ」の候補とした。今通るプログラムを誤りにする向きなので、確認だけで出す前に独立のレビューの段 1 に回す。
  急ぎ: W6-02 の上書きの単位（U5）の前。
- 決定: 決定（2026-11-13、利用者。146 回目、第 100 組。中立の要約と独立のレビューの段 1 が (1) で、段 1 は字と L5・S-614 の前提で決まると見た）: (1)。代入は代入先の場所の前の値を破棄する。根が `var`・`move` の引数・`inout` の引数のどれでも同じで、場所の型の破棄が `Alloc` を要するなら `Alloc` が要る（`rt` の関数なら E0901、そうでなければ E0601）。§5.4 の表の `inout` の行（破棄は起きない）は束縛の有効範囲の終わりの欄で、改めない。
  利用者が影響を問い、親が二つの場面を示した: `rt` の関数の中で `inout` の状態の `Str`・`Buf` を丸ごと入れ替える形（`st.buf = move fresh`）は E0901 になり、今の仕様と std には代わりの操作が無い（`inout` から `move` で取り出せない E0711、前の値を返す入れ替えの操作が無い）。要素ごとの書き込み（Copy の要素）と `FixedStr`（S-614）は困らない。`rt` でない補助（`reset(inout o: Option[Buf[F32]]) { o = None }`）と総称の `put[T]`・`swap[T]` は `uses {Alloc}` か `T: Copy` が要り、呼ぶ側へ広がる。利用者は (1) で進め、入れ替えの操作を将来の実装の候補にした（A-19）。
  理由: 解放は呼ばれた `rt` の関数の中で起きるので「呼ぶ側の責任」とは読めず、(2) は `rt` の約束が外れる。L5 は (1) を前提にする。今通って誤りになるのは約 16 ファイル 25 関数（事例の補助）と std の `[T; N].fill`（S-1040）で、`examples/` と §17 の例には当たらない。
  作業は W6-02 の U5b（`Overwrite` の破棄点。事例の書き直しは U5b のテストの票）。仕様 §12.2 の表の 2 行目
