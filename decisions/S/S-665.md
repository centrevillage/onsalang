# S-665 族: §15.1 の公開の宣言に書いた型の位置

- 空白: §15.1 の S-144 の文は、宣言より狭い可視性の型を書くと E0303 になる「宣言の外に見える部分」を、関数の引数と返り値、型別名の右辺、定数の型、フィールドと列挙子の中身、trait のメンバと並べるが、並べ方の一般の規則を書いていない。
  一覧に無い位置が、固有の `impl` のメンバ（S-662）、flow の入出力と効果の操作の引数と返り値（S-664）と見つかった。どの位置を含め、宣言の可視性を何と比べるか（宣言自身の可視性か、持ち主の型との狭い方か）を一つの規則にする。
- 決定: (d)。可視性を持つか継ぐ宣言の見出し（本体と初期化式を除く部分）に書いた名前（型・trait・効果。型の中の型を含む）は、その宣言の届く範囲より狭い可視性を持てない（E0303。位置は書いた名前で、修正候補は無い）。今の位置の一覧は例として残す（固有の `impl` のメンバと `impl` の見出しの境界、flow の入出力、効果の操作、handler の引数、境界の trait、上位の trait、効果行の効果を足す）。
  届く範囲は宣言の可視性で、固有の `impl` のメンバではメンバの可視性と型の可視性の狭い方（A10）。flow の生成項目は flow の見出しで一度だけ検査する（§11.6 に一句）。`pub struct P { priv i: Inner }` は通る。
  今通る形の検査は W4-03 の U4、trait・効果・handler の宣言と extern のブロックの見出しは、それを受け付ける作業（`tasks/phase2.md`）。§15.1・§11.6（2026-10-25 決定）。
- 経緯: 64 回目（2026-10-24）、同じ族の未決の S が S-662 と S-664 の二つになったので、親が族の規則の S を登録した（第 54 組）。関係: S-144（決定済み、族の既決の形）、S-662、S-664。
  65 回目（2026-10-25）、利用者が A9（一つの規則にする）と A10（届く範囲は狭い方）を了承した。A10 は、`priv struct Hidden` の語の無い `fn make() -> Hidden` が通る形で確かめた（下書き・助言の二段とも (d)）。
