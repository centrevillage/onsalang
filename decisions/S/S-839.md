# S-839 `prefix` の E1104 と、同じビルドの後の段の診断（E0610、後端の E0302）の順: E1104 だけで止めるか、並べるか

- 空白: §18.1 は「`prefix` が要るかはソースを読まないと決まらないので、`build` がソースの検査を通った後に調べる（検査の誤りがあれば、それだけを出す）」と書き、同じ節で「Core への降下とビルドの診断は、検査を全て通った単位にだけ出る。…全て報告する」とも書くが、`prefix` の E1104 と、同じビルドの後の段の診断（`@export` の関数の効果が `provides` に無い E0610、§14.2。後端の総称の export の E0302）が両方当たるときの順と、終了コード（E1104 は 2、E0610 は 1）を書かない。
  W4-02 U3c の実装（親の読み）は (1) E1104 を先に出してビルドを止め、後の段の診断は `prefix` を書いた後に出る。`@export pub fn f() -> U32 uses {Alloc}`（`provides` に `Alloc` が無い）か `@export pub fn f[T: Num](x: T) -> T` で `prefix` が無いパッケージの `build` は、U3c の前は E0610 か E0302 で終了コード 1、後は E1104 だけで 2（壊す側の `P98/w402u3c/b/h1.py`）。
  読みは (1) E1104 だけで止める (2) E1104 と後の段の診断を同じ回に並べる (3) 後の段の診断を先に出し、E1104 は最後、に割れる。どれも止まる誤りで、違うのは往復の数と終了コード。
- 決定:
- 経緯: 98 回目（2026-11-01）、W4-02 U3c の実装の担当が空白として挙げ、親が (1) に決めて S に登録しなかった。壊す側（中 1）が、仕様の空白で `SPEC-GAP` の印が無いと指摘したので登録した。
