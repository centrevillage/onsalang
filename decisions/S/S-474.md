# S-474

- 空白: キーワード・`_`・`true`・`false` に空白を空けずに接するリテラル（`if"a"`、`"a"if`、`_"a"`、`true"a"`）。§2.4（S-400）は「名前の直後」「リテラルの直後」の名前を `string_prefix` とし、キーワード類を書かない。
  今は識別子だけを名前とし（`lexer::word_kind`）、これらは `,` の抜けの E0002 と `,` の候補になる（`two(true"a", 1)` の候補は `true, "a"`）。読みは (1) 識別子だけ（今） (2) キーワード類も含める。
  W3-05 の再確認の壊す側が見つけた（2026-10-13。17 回目の scratchpad の `w305b3/edge.py`）。親が W3-05 の版で確かめた
- 提案: 後の段（S-458・S-469 と一緒に）
- 時期: W3
- 決定: 決定（2026-11-03、利用者。105 回目、第 79 組。下書きと独立のレビュー（段 1）が一致。利用者は「修正に複数回かかること自体は良い。規則に例外が増えるかが気になる」とし、例外の数で比べて (B)＋(i) を選んだ）: 族の規則 S-856 の (B)＋(i) から。キーワード・`_`・`true`・`false` は名前に数えず、今のまま（文法が読む所は読み、読めない所は一般の規則で、`,` の候補は 1 手で止まる）。
