# S-536 fmt がトークンを落とす囲みの中か前後のコメントと改行

- 空白: fmt がトークンを落とす囲みの中に、コメントか残す改行があるとき。(a) コメントだけを持つ空の `uses {` 改行 `// c` 改行 `}` を外すか（S-68）。(b) 冗長な括弧の中のコメントだけの行（`(a + b` 改行 `// c` 改行 `)`、`(` 改行 `// c` 改行 `a + 1)`）。
  (c) 開き括弧の直後で改行した冗長な括弧（`let y = (` 改行 `a + b)`。今の fmt は並びのブロック形として整える。`spec/tools.md` §3.2 は括弧の直後の改行が残る改行かを書かない）。
  (d) 落とすトークンの前後の改行の間に行末のコメントがある形（`fn f() // c` 改行 `uses {} {}`、`fn g() -> // c` 改行 `() {}`。コメントの無い形は構文の段を通り、外せる。W3-12/i の設計メモが補った）。
  (e) (2') の表の (b) の形（`let y = ( // c` 改行 `a + 1)` を `let y = // c` 改行 `a + 1` にする）と、`fn h() -> () // c` 改行 `uses {Alloc} {}` を `fn h() // c` 改行 `uses {Alloc} {}` にする形は、gate の fmt-comments の性質（コメントを除いて整形し直した形が、コメントの無い入力の整形と同じ）に反する。
  コメントの守る改行だけで成り立つ形を書き換えないか、性質を緩めるか。W3-12/i の U1b が見つけ、仮に前者で実装した（2026-10-15）。§3.4 の「コメントを含む囲みは 1 行にまとめない」、S-513（要素の無い括弧は中にコメントがあれば候補なし）と関わる。W3-12/t（U1 と U2）が見つけた（2026-10-15）
- 提案: 決定（2026-10-15、利用者が (1)・(c-i) を選んだ。下書きと Fable の (2') と割れた。(2') に (e) が見つかった後、他言語の整形器の調べと助言の担当の二段を経て、親も推奨を (1) に改めた）: 落とす範囲（最初に落とすトークンから最後に落とすトークンまでと、一緒に落とす改行の隙間）にコメントがあれば、その書き換えはしない。
  接する改行はトークンと一緒に落とし、文と項目の区切りの改行と、残る並びの縁の改行は残す。(c-i) `let y = (` 改行 `a + b)` は `let y = a + b`。理由: 規則が一つで後から例外が増えず、書き手が「コメントを含む囲みは外れない」と予測できる。`spec/tools.md` §3.3・§3.4。
  W3-12 で当たるのは末尾の `return` だけ（括弧・`-> ()`・`uses {}` の除去は第 2 期）
