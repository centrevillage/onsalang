# S-722 一つの無名関数が捕捉できない値を二つ以上捕捉するとき（`inout` 引数と Affine 値）、E0712 がどの捕捉を名指すか

- 決定済みで戻さないもの: E0712 のコードと段（モード）、捕捉できないものの範囲（§5.3）。
  第 67 組の下書きの「S-722 の仕組みの出所」の節（写しは `target/notes/78/g67/draft.md`）。
- 論点: §5.3「`inout` 引数と Affine 値は捕捉できない（E0712）」。一つの無名関数が両方を捕捉するとき、一つの E0712 がどちらを名指すかが決まっていない。
  §18.1 の並べ方を、捕捉ごとの E0712（同じ位置、同じコード）の文面で比べる読みもある。今の実装は U3b の前後で文面だけが変わった（親の登録の文）。
- 今の実装: `target/notes/76/w404/u3b/b/h/ord.onsa`（`onsa-u7b2` と `onsa-5fc054e` で同じ）: どれも位置は外の無名関数の全体で、
  t1（内の `{ k }` の後に `b.len()`）は 4:9 の `k`（`inout`）、t2（`b.len() + k`）は 7:9 の `b`、t3（内の `{ b.len() }` の後に `k`）は 10:9 の `b`。三つとも、無名関数の本体でソースの最初に読む捕捉できない値を名指す。
- 案: 
  - (a) 無名関数ごとに E0712 を一つにし、本体で最初に読む（ソースの順）捕捉できない値を名指す（今の実装）。
  - (b) 捕捉ごとに E0712 を作り（位置は無名関数の全体で同じ）、§18.1 の文面の比べで選ぶ。今の文面では、捕捉した名前の綴りの順になる（t1 は「`b` is Affine」が「`k` is an `inout`」より先）。
  - (c) E0712 の位置を、捕捉した値を読む所（`{ k }` の `k`）にする。§18.1 の開始の位置の比べで、最初に読む所が選ばれる（t1 は 4:54 の `k`）。
  - (d) 無名関数ごとに一つの E0712 で、捕捉できない値を全て示す（二つ目からは位置付きの note）。
  - 書き手から見て: 捕捉できない値はどれも直す必要があり、直し方は値ごとに違う（`inout` は引数で渡す、Affine は借用で渡すか外で計算する）。(a)〜(c) は一つずつ直して二回の検査、(d) は一回である。
    (c) は位置が狭く、どこで捕捉したかを直接示す。(a)・(b)・(d) は無名関数の全体（数十字）を示し、note で宣言を示す。
    (b) の選び方は文面の言い回しで変わり、読みの順と関係しない。
  - 修正候補: E0712 には候補が無く、どの案も変わらない。
  - 規則と例外: (a) は規則を足さない（仕様に書くなら §5.3 の一句）。(b) は §18.1 のままだが、捕捉ごとに誤りを数えることを書く必要がある。(c) は E0712 の位置の一文。
    (d) は「一つの診断は一つの誤り」（§18.1）に、無名関数の捕捉をまとめる例外を足す。
  - 実装の量（W4-09 で E0712 と捕捉の検査を直す）: (a) は 0 行で、W4-09 が捕捉の記録を読みの順に保てばよい（U3b から名前の段の記録がその順）。(b) は全ての捕捉の診断を作って文面で選ぶ（約 +5 行）。
    (c) は捕捉の記録に読んだ所の位置を持たせ（今の `captures` は束縛の番号だけ）、位置を替える（約 +5〜10 行）。事例の期待は行で書くものが多く、同じ行なら変わらない（複数行の無名関数は未確認）。(d) は note を並べる（約 +5〜10 行）。
