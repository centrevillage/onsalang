# S-239 呼び出しの位置の型引数の記法と、入れる時期

- 空白: 呼び出しの位置で型引数を明示する書き方が無い（§4.5「呼び出し位置で型引数は書かない」。式の中の `[...]` を常に添字か配列リテラルとして読むため、`f[T](x)` は構文の段で読みが割れる）。型は期待型の注釈か後の文で決めるので、変換先の型を引数に取る関数（S-231）や、返り値だけに型パラメータが現れる関数を、式の途中で型を示して呼べない。
  利用者は、言語の制限として大きく、将来の言語機能として考えたい（2026-10-08、S-231 の事前検討で）。足すときは今は誤りになるトークンの並びを使えば既存のプログラムを壊さない（例えば関数値の呼び出し `.(`（S-191）と並ぶ `f.[T](x)`）
- 提案: 式の中の型引数は、総称の項目を指す名前の経路の直後に `::[…]` で書く（`parse::[U32]("1")`、`Buf::[F32].zeroed(4)`、`Rg::[F32, 4].CAP`、`Pr::[U8] { a: 250 }`、`v.m::[I32](x)`、`let g = id::[U8]` の後の `g.(250)`、`None::[I32]`、`E::[I32].B`）。
  型引数は、その型パラメータを宣言した項目の名前に付ける（メソッドに与えるのはメソッド自身の型パラメータ）。型の位置は今どおり `[…]` で、型の位置に書いた `Buf::[F32]` は E0020（候補は `::` を除く。利用者が Fable の案を選んだ）。
  数の誤りと型パラメータを持たない項目（総称でない関数、flow、型パラメータ、列挙子の名前）は E0412、関数値（ローカルの束縛と引数）は E0308、名前の経路でない式の後・空の並び `f::[]`・宣言の `fn f::[T]`・パターンの `None::[I32] =>`・行頭の `::` は E0002、名前と `::` と `[` の間の空白は E0020（候補は空白を除く）。`!` は並びの後（`buf.push::[F32]!(x)`）。`_` の部分的な推論は無い。`::[…]` は入れ子の深さで一段（段を作るトークンは `[`）。
  経路の `::` の E0020 は `[` が続かない `::` で、S-248 の一つの経路は `::[…]` の前後を問わない（`Buf::[F32]::zeroed(4)` は一つの誤りで、候補は `Buf::[F32].zeroed(4)`）。型引数を書いた呼び出しの型パラメータはその文で決まる（要求の検査もその文）。
  §6.1 の S-191 の文を「候補が `ops` の種類で分かれる（項目なら `ops::[…](x)`、値なら `ops[i].(x)`）ので名前の段」に改めた。fmt は `::[` の前後に空白を置かず、期待型の注釈と型引数を互いに書き換えない。
  他言語の形の候補は `::[…]` への構文上の編集（S-277）（(a) と (p)。利用者が 1〜4 を挙げて了承。第 9 組の下書き。仕様 §2.5、§2.6、§4.1、§4.5、§6.1、§18.1、spec/tools.md §3.2。2026-10-08 決定。実装は W3-19（構文、fmt、構文の段の候補）、W4-13（名前の段と型の段の具体化）、W5-02（メソッドの `v.m[…](x)` の候補）。K-22）。
  明記（2026-10-09、利用者）: 空の並びは式の中の `f::[]` と型の位置の `Buf[]` のどちらも構文の段の E0002（了承した細部「型の位置の空の並びと同じ」の前提を §4.5 に書いた。前の実装は型の位置を名前の段の E0302 にしていた。W3-19 で揃えた）
