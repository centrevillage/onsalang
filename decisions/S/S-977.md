# S-977 メソッド自身の型引数と関数型のフィールドの後の `::[…]`（`v.m::[4](x)`、`h.f::[I32](1)`）の誤りの段とコード（宣言が型の段でしか分からない）

- 空白: §4.5 は「要素の種類（型か定数式か）が宣言の位置と合わなければ、名前でない型の形と定数式も E0308 である（§15.1）」「ローカルの束縛と引数（関数値。一つの具体化を指し、型引数を取らない）に書くと E0308」とするが、段を書かない。E0308 は登録簿（`crates/onsa_diag/src/codes.rs`）で名前の段だけのコードである。関数の `id::[4](1)` は名前の段が宣言を知るので、名前の段で判定できる。
  メソッド自身の型引数（`conv[T]` への `v.conv::[4](1)`、`cn[const N: U32]` への `v.cn::[I32]()`）は、メソッドが受け手の型で決まるので、種類が合うかは型の段でしか分からない。
  関数型のフィールドの後の並び（`f: fn(I32) -> I32` の `h.f::[I32](1)`）と、メソッドでないメンバの後の並び（`v.a::[I32]`）も、メンバが何かは型の段でしか分からず、§4.5 の E0308 の文は「ローカルの束縛と引数」だけを挙げる。
  決めること: これらの形のコードと段（型の段の E0308 にして登録簿の段を広げるか、型の段のコードにするか）。今はどれも名前の段の E0200（式の中の型引数は W5-10 まで未実装。`p01`・`p02`・`p03`・`p19`）。
- 決定: 決定（2026-11-10、利用者。133 回目）: (a)。メソッド自身の型引数の種類の誤り（`v.conv::[4](1)`、`v.cn::[I32]()`）と、関数型のフィールドとメソッドでないメンバの後の並び（`h.f::[I32](1)`、`v.a::[I32]`）は、どちらも型の段の E0308 である。
  宣言が受け手の型で決まるので判定と報告は型の段で行い、コードは関数（`id::[4](1)`）とローカルの束縛（`g::[I32](1)`）と同じにする。登録簿の E0308 の段を名前の段と型の段に広げる（E0302・E0303・E0304 と同じ形）。同じ単位に名前の段の誤りがある間は出ない（§18.1 の段の順のまま）。
  仕様: §4.5（メソッド自身の型引数は種類を型の段で判定する。E0308 の「ローカルの束縛と引数」にフィールドを足す）、§15.1（E0308 の例）、§18.1（名前の種類の E0308 は名前の段で、受け手の型で決まるものだけ型の段）。W5-10 U2b。
  実装の担当の設計メモと独立のレビュー（onsa-advisor の段 1、`target/notes/133/s977-advisor/`）が一致した。メソッドの並びの数を超えた要素の名前は S-981。他言語の形の `h.f[I32](1)`（今は型の段の E0401）を E0308 に揃えるかは、この決定に含めない。
- 経緯: 133 回目（2026-11-10）、W5-10 の設計メモ（onsa-impl、U1a/i）が決めていないこととして挙げ、親が固定のバイナリ（dev `f90b68ed`）で再現して登録した。再現の入力は 133 回目の scratchpad の `s977-advisor/probe/`（写しは区切りで `target/notes/133/s977-advisor/`）。
