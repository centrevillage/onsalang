# S-435 名前より前の構文の誤りで項目が名前解決から消える

- 空白: 項目の見出しの名前より前にある構文の誤り（可視性の `pub(crate)` など）で、項目が名前解決から消え、使う側に偽の E0302 が出る（`pub(crate) fn h()` と別の関数の `h()` は、`pub_crate` の E0020 に加えて `h()` の位置の E0302「cannot find `h` in this scope」。`const`、`struct`、`use`、`pub(super) use` も同じ）。
  属性の誤り（`#[inline] fn h()`）や引数の誤りでは出ない。§18.1「誤りのある宣言も、名前まで読めれば名前解決に見せる…それを使う側には診断を出さない」の「名前まで読めれば」を、誤りが名前の前にある形にも当てるか（構文解析器が可視性の誤りの後も名前まで読む）。修復のループが偽の E0302 に `use` の追加などを当てると、関係の無い編集になる。
  第 24 組の下書きで見つけた（2026-10-11。親が dev の `826fc8a` で `pub(crate) fn h` の形を再現した） 直し（2026-10-13、第 25 組の下書き）: 「属性の誤り（`#[inline] fn h()`）…では出ない」は属性を独立の行に書いたときだけで、同じ行の `#[inline] fn h()` と `@fp(relaxed, 1 +) fn h()` は E0302 が出る。
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (c) を了承し、細部も Fable の案を了承。下書きと Fable が一致、第 25 組）: 名前より前（属性と可視性）にある表の形で、範囲が同じ行の中で閉じるもの（`pub(crate)`・`pub(pkg)`・`pub(super)` など、同じ行の `#[…]`、W3-08 の `derive_attribute`・`relaxed_attribute`・`priv_use`・`field_pub`）は、報告した後に形の後ろから属性・可視性・宣言を読み続け、読み切った宣言として名前解決に見せる（単位には構文の誤りがあるので本体は検査しない）。
  表に無い語で止まった項目は登録しない（S-459）。読み続けた項目の可視性は無指定。可視性の形は `Failed::Unit`、属性の形は使う側を検査しない `Failed::Heading`（緩めるかは S-460）。
  改め（2026-10-13、S-460 の決定）: 属性の形も `Failed::Unit` で、struct・enum の derive の一覧と `@repr` の値を未知にする。閉じない形（`pub(crate fn h()`）と改行を挟む形は読み続けない。仕様 §18.1。実装は W3-08（`parse_vis`、`parse_item`、`lower.rs` の可視性。30〜45 行）
