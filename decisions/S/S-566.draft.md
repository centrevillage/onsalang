# S-566 レートの変換の単位: インスタンスの修飾子か、値のクロックか

- 位置付け: 第 34 組（イベントのクロック、S-560〜S-565）の確認で立った S-566 の一件の重い比べ。族の組ではないので、族の規則の S は無い。
  親の材料 `designs.md`（二つの設計の今の形の中立の要約）から始め、設計 2 と組み合わせの案の細部（意味・構文・誤りの形）を埋めてから比べた。
- 比べの基準（利用者の指示）: 今の修正の量より将来の影響を重く見て、(1) 誤解の少なさと誤解する書き方を防げるか、(2) 計算の費用、(3) メモリの費用、(4) 保守の費用、で比べる。各案に例のコードと、差が出る所を書いた。
- 決定済みで論点に戻さないもの:
  - 修飾子は呼び出しへの連鎖で書き、名前に `~` を付ける。各修飾子は左の全体を包み、順も重ねがけも自由（S-555、S-557）。引数の位置の `f~(…)` は呼び先によらず出力の値（S-555、§11.5）。
  - `when~(c)` のクロックは呼び出しの位置のクロック K の刻みのうち c が真の刻みで、止まっている間は出力を保つ。c は呼び出し側のクロック以下（S-558）。`reset_if~` は水準で読み、範囲は生成する `reset` と同じ部分木（S-559）。
  - flow の本体の意味（`sample_rate()`、`prev~` と遅延の刻み）は、そのインスタンスのクロックを基準に決まる（S-172、§11.3、§11.4）。
  - `at` は値も評価の段も変えない注釈で、補間を伴うレートの変換は状態を持つので flow で書く（S-152、点検 C-40、§11.3）。
  - クロックの文脈は効果にしない。比は 2 のべき乗。`block` は状態を持てない。導くクロックは自分の位相のカウンタを持ち、ホストの区切りと独立に刻む（S-172 の方向、§19.1）。
  - `block` のクロックの位置付けは S-565 で決め、この S では変えない前提で比べる。イベントのクロックは半順序で、式のクロックは最大があればそれ、無ければ誤り（第 34 組の前提）。
  - S-172 の方向のうち「付ける構文は `with`」と「制御と音声をクロックの宣言で区別する」は、案によって改める（各案の「既決との関係」）。R-132 の (7) は、マルチレートを本格的に入れる段で改めて考えるとした。
- 今の実装: 親が渡した `bin/onsa-4aaa028` の `check` で確かめた（修飾子もクロックの宣言も未実装）。入力は `s566/probe/`、回す道具は `s566/run.py`。終了コードは 0 と 1 だけだった。
- 他言語: 手元に処理系は無いので、どれも動かしていない。文書と処理系のソースを出典付きで引いた（末尾の「出典」。取得した写しは `s566/dl/`）。
  これらは基本仕様 §0.3 の 3 が信号処理の部分の借りる先に挙げる言語とその仲間で、`rules/criteria.md` 7.32 の一覧の外にある。診断の行を立てるためではなく、設計の比べのために調べた。
- **論点:** 基本仕様 §11.3 は「遅いクロックの値を速いクロックの式で使うのは、値を変えない（次に変わるまで同じ値が続く）」「速いクロックから遅いクロックへ移す書き方は無い。間引きが要る場合は明示的な flow（`sample_and_hold` など）を使う」とする。
  同じ節は「flow の呼び出し（組込みの遅延を含む）の結果のクロックは、その出力の宣言のクロック（この版では `sample`）で、引数のクロックによらない」とする。
  §19.1 のマルチレートは、導くクロックの宣言（`clock fast = sample / 32`）と宣言の `at fast`、式の中の `p at (sample / 32)` を方向とし、付ける単位（式、`let`、インスタンス、`par` のような構築子）を「入れるときに決めること」に挙げる（候補は `with`: `lp~(x) with os2`）。
  あわせて「制御と音声をクロックの宣言で区別」「制御の値を速いクロックへ保持するのは暗黙でよい」「音声のアップサンプルは明示」「ダウンサンプルは常に明示（エイリアス）」とする。
  - 分かれ目は、レートを変えた計算と呼び出し側の間で値をどう渡すかである。設計 1 は境界で保持・間引きし（方法は書かない）、呼び出し側には呼び出し側のクロックの値だけが出る。設計 2 は値がクロックを持ち、変換を明示する。
  - 設計 1 の `up~` の出力（N 回目の値）と `down~` の入力（N 刻みに 1 回読む）は、補間なしの間引きである。これが §11.3 の「速いクロックから遅いクロックへ移す書き方は無い」と §19.1 の「ダウンサンプルは常に明示（エイリアス）」に反するかは、読みが分かれる。
    (i) レートを変えることは修飾子で書かれているので、明示と読む。(ii) 間引きの方法（補間もフィルタもしない）は書かれず境界で起きるので、エイリアスについては暗黙と読む。
  - 設計 2 は §19.1 の方向に近いが、インスタンスを置く書き方、変換の flow の書き方、本体の中の状態の刻み、`sample_rate()` の定義が決まっていない（`designs.md`）。
  - 決めること: どの設計か（または組み合わせか）と、その案で決まる細部。
- **今の実装:**（`probe/` を `check`）
  - `osc~(f).down~(4)`・`osc~(f).up~(2)`・`osc~(f).when~(c)`・`decimate~(osc~(f).up~(2)).down~(2)` は E0812（「`osc~(f).down` is not a flow」、候補は `~` を除く形）。修飾子の連鎖は未実装（S-555 の実装の前）。
  - `clock fast = sample / 32` は E0200（「the declaration of a derived clock (the reserved word `clock`)」）。`f: F32 at fast` は E0302（「cannot find the clock `fast`」、note で `init`・`block`・`sample`）。
  - 式の `f at (sample / 32)`、入力の `x: F32 at (sample * 2)`、出力の `-> F32 at (sample / 256)` は E0002（「expected the name of a clock, found `(`」）。`osc~(f) with os2` は E0002（「expected newline or `}`, found `with`」）。
  - `let y = osc~(f) at block` は E0815（`at` は値を遅くできない）。`prev~(p)`（`p` は `block`）は E0813。
- **案:** 四つの案を、同じ部品で書く。部品の flow は次のとおり（本体は略す）。
  `osc(f: F32 at block) -> F32 at sample`（発振器）、`hb(x: F32 at sample) -> F32 at sample`（半帯域の低域通過）、`lp`・`heavy`・`smooth`・`rev`（`x: F32 at sample` を受けて `F32 at sample` を返す普通の flow）、`lfo(rate: F32 at block) -> F32 at sample`。
  - **(a) 設計 1: インスタンスの単位、境界は保持と間引き（方法は書かない）。**
    - 意味: `designs.md` のとおり。`x.down~(N)` は x を呼び出し側の N 刻みに 1 回動かす（最初の刻みで動く。位相のカウンタは修飾子ごとの状態で、`init` と `reset` で 0）。引数は呼び出し側の刻みごとに評価し、x は自分の刻みでだけ読む。呼び出し側は最後の出力を保持で読む。
      `x.up~(N)` は x を呼び出し側の 1 刻みに N 回続けて動かす。入力は N 回の間同じ値で、呼び出し側は N 回目の値を読む。x の中の `sample_rate()` は 1/N か N 倍、`prev~` は x の刻みで数える。
    - 構文: 修飾子の名前 `up`・`down` を修飾子の名前空間（S-556、閉じた一覧）に足す。N は 2 のべき乗の定数（違えば E0808 の類）。呼び出し側の式のクロックは変わらず、導くクロックは式にも宣言にも出ない。`clock` の宣言と `at (…)` は使わない（予約は残す）。
    - 補間と帯域の制限は、x の本体の中（`up~`）か前後の呼び出し側（`down~`）に flow で書く。状態の欄は `.held` と `.phase`。
    - 誤りの形: 受け手の規則は S-555 のまま（E0812）。境界の値のクロックの誤りは無い（全て呼び出し側のクロックで受ける）。
    - 既決との関係: 境界の間引き（`up~` の出力、`down~` の入力）と保持（`up~` の入力）は、読み (ii)（論点）では、§11.3 の速い→遅いの規則と §19.1 の「ダウンサンプルは常に明示」「音声のアップサンプルは明示」を、インスタンスの境界で改める。読み (i) では、修飾子がその明示に当たる。制御と音声の区別（S-172 の方向）は持たない。
    - 計画: 修飾子ごとに、一つのインスタンスの呼び出しを N 回の繰り返しか刻みの条件で包む。呼び出し側の段は今のまま。
  - **(b) 設計 2: 値のクロック（§19.1 の方向を具体化した形）。**
    - 宣言: モジュールの項目 `clock os2: audio = sample * 2`、`clock ctl: control = sample / 32`。名前はクロックの名前空間に入る。`:` の後ろの種類は閉じた一覧（`audio`・`control`。キーワードを増やさない）で、`sample * N` は `audio` だけ。比は 2 のべき乗の定数で、各インスタンスの `sample` を基準にする。
    - 値: 全ての式がクロックを持つ。順序は `ctl < sample < os2`、`init` は全ての下、`block` と `ctl` は比べられない（§19.1）、イベントのクロックと導くクロックも比べられない。式のクロックは最大（無ければ誤り）。flow の入出力に宣言したクロックを書ける（`x: F32 at os2`、`-> F32 at ctl`）。
    - 保持: 制御の種類（定数・`init`・`block`・`control` の宣言）の値は、速いクロックの式でそのまま読める。音声の種類どうし（`sample`・`audio` の宣言）は変換の flow を通す。速い→遅いは常に明示。
    - 変換: 本体の中で値のクロックを変える書き方として、組込みの flow が二つ要る（間引き: 速い値を遅いクロックの刻みで取る。挿入: 遅い音声の値を速いクロックへ 0 か保持で広げる。名前は例として `keep~`・`stuff~`）。
      組込みの名前は後から足すと利用者の名前を壊すので、今予約する（§11.4 の一覧に足す）。std の `up2~`・`down2~` は、これとフィルタで書く。
    - 本体の状態: `prev~(e)` の `e` は `sample` か導くクロック（E0813 を緩める）で、遅延はその値のクロックの刻みで数える（`env` が `ctl` なら `prev~(^env)` は 32 サンプル）。`sample_rate()` は `sample` のレートで、他のクロックのレートは `sample_rate() / 32.0` と書く（組込みを足すなら今決める）。
    - インスタンスのクロック: `sample` の入力に渡した音声の種類の値のクロックから決まる（`lp~(o)` は `o` が `os2` なら 2 倍で動く）。音声の入力の無い flow（発振器など）は `with` で置く（`osc~(f) with os2`、§19.1 の候補）。
    - 誤りの形: 音声のクロックを変換なしで混ぜる（`o + x`、`lp~(x) with os2` の `x` が `sample`）は新しいコード（候補なし、note で変換の flow）。速い→遅い（`x at ctl`、`ctl` の入力に `sample` の値）は E0815。`with` と引数で決まるクロックが食い違えば誤り。
    - 既決との関係: S-172 の方向（`with`、宣言で種類）のまま。S-555 は、インスタンスに付ける書き方を後置の節でなく連鎖にした（`saw~(f0) when c` は構文の誤り）。`with` を後置の節で入れると、インスタンスに付ける書き方が二つになる。
    - 計画: 一つの本体の中に、クロックごとの段（`ctl` は刻みの条件、`os2` は 2 回の繰り返し）と、段ごとの状態が並ぶ。
  - **(c) 組み合わせ 1: 修飾子でインスタンスを動かし、値はインスタンスの境界でクロックを持つ。**
    - 構文: 置く書き方は (a) の修飾子 `.up~(N)`・`.down~(N)`。導くクロックは名前の無い `sample * N`・`sample / N` で、flow の入出力の宣言と式の `at (…)` に書く（§19.1 の括弧の形）。`clock` の宣言は入れない（予約は残す）。
    - 枠: 各インスタンスの本体は、自分の `sample` を基準にした枠を持つ。入出力の宣言のクロックは、呼び出し側では、そのインスタンスのクロック B を基準に読む（`x: F32 at (sample * 2)` の入力は、呼び出し側の B の 2 倍の値を受ける）。
    - B の決め方: `sample` 以上（`sample`・`sample * N`）のクロックの引数から、入力の宣言の比で割り戻して決める（一つに決まらなければ誤り）。そういう引数が無ければ修飾子（`.up~(N)` は呼び出し側の `sample` の N 倍、`.down~(N)` は 1/N）、それも無ければ呼び出し側の `sample`。
      引数で決まるインスタンスに修飾子を付けると誤り。`sample / N` の値を、より速いクロックの入力（`at sample` など）へ修飾子なしで渡すと、遅く動かす読みと保持して速く動かす読みに割れるので誤りにし、候補を二つ出す（`.down~(N)` を付ける形と、`at sample` で昇格する形）。
    - 保持: 各枠で、`sample` より遅いクロック（定数・`init`・`block`・`sample / N`）の値は、速いクロックの式でそのまま読める（§11.3 の規則を `sample / N` に広げる）。`sample` 以上の値は暗黙に別のクロックへ移らない。速い→遅いは E0815、`sample` から `sample * N` へは新しいコード。
    - 変換の flow: 入出力のクロックが違う flow。出力が本体の `sample` より遅いと、出力の式はそのクロックの刻みで読む（明示の間引き）。入力が `sample` より遅いと、本体はそれを保持で読む。組込みの名前は増えない。
      std は `up2(x: F32 at (sample / 2)) -> F32 at sample`（呼び出し側で `x` が `sample` なら B は 2 倍、出力は `sample * 2`）と `down2(x: F32 at (sample * 2)) -> F32 at sample` を、フィルタ付きで置く。
    - 状態を持つ組込みは本体の `sample` だけ（E0813 のまま。イベントのクロックを足すかは S-565 の 3 で決める）。別のレートの状態は、別のクロックに置いたインスタンスの中にだけある。`sample_rate()` は B のレート。
    - カウンタ: 導くクロックの位相のカウンタは、枠と比ごとに一つ（`init` と `reset` で 0）。部分木の `reset_if~` は呼び出し側の枠のカウンタを動かさない（`x.down~(4).reset_if~(r)` の後も、x は呼び出し側の `sample / 4` の刻みで動く）。
    - 修飾子との合成: `x.up~(2).when~(c)` の `c` は呼び出し側のクロック以下（S-558）。`x.when~(c).up~(2)` は内側の K が `sample * 2` なので、`c` が `sample` の値なら新しいコードの誤り（note で順を入れ替えた形を示す）。
    - 計画: 呼び出し側の枠にクロックごとの段が並ぶ。`sample / N` は刻みの条件の段で、遅い値に掛かる式は今の巻き上げと同じ規則でその段に出る。`sample * N` は N 回の繰り返しの段で、同じクロックのインスタンスと点ごとの式をまとめる。`sample * N` の値を別のインスタンスへ渡すときは N 個の配列で渡す。
    - 既決との関係: S-172 の方向の「`with` で付ける」を、S-555 の連鎖にそろえて修飾子に改める。「制御と音声をクロックの宣言で区別」を、枠の `sample` を境にした規則（遅いものは制御として保持、`sample` 以上は音声として明示）に改める。§11.3 の「結果のクロックは引数のクロックによらない」を改める。
  - **(d) 組み合わせ 2: 修飾子を基本にし、速い側から遅い側へ渡る値だけにクロックを付ける。**
    - 意味: (a) の修飾子のうち、速い側から遅い側へ渡る二つの境界だけを値のクロックにする。`x.up~(N)` の出力は `sample * N` の値で、`x.down~(N)` の `sample` の入力は `sample / N` の値を要する。他の境界は (a) のまま（`up~` の入力は保持、`down~` の出力は保持して `sample`）。
    - 変換の flow: 入出力に `at (sample * N)`・`at (sample / N)` を書ける（`down2(x: F32 at (sample * 2)) -> F32 at sample`、`dec2(x: F32 at sample) -> F32 at (sample / 2)`）。出力が遅いときの読み方は (c) と同じ。
    - B は修飾子だけで決まり、引数からは決めない。`sample * N` の値は点ごとの式に書ける（式のクロックは最大）が、状態を持つ組込みには渡せない（E0813）。
    - 誤りの形: `sample * N` の値を `sample` の入力・出力へ、`sample` の値を `.down~(N)` の入力へ渡すと E0815。
    - 既決との関係: §11.3 の速い→遅いの規則は保つ。制御と音声の区別は持たない（遅い→速いは全て保持）。
    - 計画: (a) に、呼び出し側の `sample * N` の段（`up~` の出力に掛かる点ごとの式と、変換の flow への受け渡し）が加わる。
  - **共通の例:** 2 倍で動かして帯域を制限する発振器、32 刻みに 1 回の LFO で動かすフィルタ、2 倍で動かす歪み。部品の `svf~(x, c)` は係数の struct `c` を受けるフィルタ、`svf_coefs(fc, q, sr)` は係数を作る `rt fn`。

    ```onsa
    // (a)
    flow saw2(f: F32 at block) -> F32 at sample { hb~(osc~(f)) }          // 2 倍で動かす前提。帯域の制限は本体の中
    flow drive2(x: F32 at sample, d: F32 at block) -> F32 at sample {      // 2 倍で動かす前提。x は 2 刻みの間同じ値
      hb~(tanh(lp~(x) * d))                                                // lp が補間、hb が帯域の制限
    }
    pub flow voice(f: F32 at block, rate: F32 at block, d: F32 at block) -> F32 at sample {
      let s = saw2~(f).up~(2)                                              // 2 回目の値
      let m = lfo~(rate).down~(32)                                         // 32 刻みに 1 回動き、出力は保持（m は sample）
      let y = svf~(s, svf_coefs(cutoff(m), 0.7, sample_rate()))            // 係数は毎サンプル
      drive2~(y, d).up~(2)
    }

    // (b)
    clock os2: audio = sample * 2
    clock ctl: control = sample / 32
    pub flow voice(f: F32 at block, rate: F32 at block, d: F32 at block) -> F32 at sample {
      let s = down2~(osc~(f) with os2)                                     // osc は os2、down2 は os2 → sample
      let m = lfo~(rate) with ctl                                          // m は ctl
      let y = svf~(s, svf_coefs(cutoff(m), 0.7, sample_rate()))            // 係数は ctl の段
      down2~(tanh(up2~(y) * d))                                            // tanh は os2 の点ごと
    }

    // (c)
    pub flow voice(f: F32 at block, rate: F32 at block, d: F32 at block) -> F32 at sample {
      let s = down2~(osc~(f).up~(2))                                       // osc は 2 倍。down2 は sample * 2 → sample
      let m = lfo~(rate).down~(32)                                         // m は sample / 32（保持で読める）
      let y = svf~(s, svf_coefs(cutoff(m), 0.7, sample_rate()))            // 係数は 32 刻みに 1 回
      down2~(tanh(up2~(y) * d))                                            // up2 は引数から 2 倍で動く。tanh は sample * 2 の点ごと
    }

    // (d)
    flow drive_in(x: F32 at sample, d: F32 at block) -> F32 at sample { tanh(lp~(x) * d) }   // 2 倍で動かす前提
    pub flow voice(f: F32 at block, rate: F32 at block, d: F32 at block) -> F32 at sample {
      let s = down2~(osc~(f).up~(2))                                       // up~ の出力は sample * 2。down2 を通す
      let m = lfo~(rate).down~(32)                                         // 出力は保持して sample
      let y = svf~(s, svf_coefs(cutoff(m), 0.7, sample_rate()))            // 係数は毎サンプル
      down2~(drive_in~(y, d).up~(2))                                       // y は保持で 2 倍へ。補間は本体の中
    }
    ```

- **他言語:**（どれも手元で動かしていない。出典は末尾）
  - Faust（ノードの単位）: IFC 2024 の発表は、`ondemand(C)` を「入力をクロック H で間引いて C に渡し、結果を H で保持して広げる」と定め、`oversampling(C)`・`undersampling(C)` を「C を周りの N 倍・1/N で動かし、C が見るサンプリング周波数も比で変わる」とする。
    2015 年の `mute`/`enable`、2020 年の仕様、2022 年の試作を経て 2024 年に入れたとある。文法の中の名前は `experimental-ondemand` の枝の字句解析に `ondemand`・`upsampling`・`downsampling` があり、`master`・`master-dev` には無い（2026-10-20 に確かめた）。境界でフィルタを掛けるかは発表に無い（未確認）。
    値の単位の多レート（ベクトルの型でレートを下げ、直列化で上げる依存型の設計）は 2010〜2011 年の論文にあり、Kronos の博士論文は、それを Kronos の決定的な多レートの一部とする。
  - Cmajor（ノードの単位）: グラフのノードを `MyProcessor * 4`・`/ 2` で速く・遅く動かし、接続ごとに補間の方法 `[latch]`・`[linear]`・`[sinc]` を選ぶ。既定は、速いノードは出入りとも `sinc`、遅いノードは入りが `latch`、出が `linear`。補間できるのはスカラの stream だけで、他の型は誤り。
    値（`value`）の端点は stream と別の種類で、サンプル単位でなく、目標と長さを与えた傾斜を持つ。比の制限と、速いノードの中の `processor.frequency` の値は文書に無い（未確認）。
  - SOUL（ノードの単位）: `Waveshaper * 4`・`Visualiser / 100` の形で、比はコンパイル時の整数の定数（例に 2 のべき乗でない `/ 100` がある）。部分グラフにも付き、入れ子では掛け合わさる。既定は、速い側は両方向 `sinc`、遅い側は入りが `latch`、出が `linear`。遅く動かすのは主に制御のレートとする。
  - Pure Data（部分パッチの単位）: `block~`・`switch~` が窓ごとにブロックの大きさ・重なり・上げ下げの比を決める。比は 2 のべき乗でなければ誤り（`d_ugen.c`）。`inlet~` の上げ方は `hold`（0.44 からの既定）・`lin`・`pad` で、`outlet~` の下げ方は一つだけで、フィルタを掛けない（`g_io.c` の注、`d_resample.c` は N 個ごとに一つ取る）。
    `samplerate~` は、囲む窓の比を掛けた値を返す（`canvas_getsr`）。例 `J07.oversampling.pd` は、16 倍の部分パッチの中に 3 次の Butterworth を置き、「無いと `outlet~` で下げるときに折り返す」と書く。`block~` の文書は、止めた部分パッチの `send~`・`delwrite~` を読む側が古い値を繰り返す落とし穴を挙げる。
  - Max（部分パッチの単位）: `poly~` の `up`・`down` が読み込んだパッチの中のレートを変え、`resampling` の属性が高品質の再標本化のフィルタを切り替える（既定で有効）。
  - SuperCollider（UGen ごとのレート）: UGen は `ar`・`kr`・`ir` のどれかで作り、制御の 1 刻みは音声のブロック（`BUFLENGTH`、制御の周期のサンプル数）である。音声の UGen に制御の値を渡したときの扱いは UGen の実装ごとで、二項演算の `ar * kr` はブロックの中で直線で傾ける（`BinaryOpUGens.cpp` の `mul_ak`、`CALCSLOPE`）。
    `K2A` は直線補間で変え、`A2K` はブロックの最初のサンプルを返す（`LFUGens.cpp` の `A2K_next`、フィルタ無し）。一部の UGen は音声の入力を要し、違えば「input … is not audio rate」の誤り（`UGen.sc` の `checkNInputs`）。
  - Csound（変数ごとのレートと、後から足したインスタンスの単位）: 変数の頭の字で i（音の初め）・k（制御の周期ごと）・a（サンプルごと）を決める。`setksmps` は楽器か UDO の中の制御の周期を変える（実験的とある）。
    7.0 で `oversample`・`undersample` を足した。UDO の中だけで使え、その中の `sr` を変え、入出力の変換の方法（Secret Rabbit Code の sinc の段階、0 次の保持、直線）を選ぶ。高品質の方法は少し遅れる。配列の引数は使えず、大域の変数とバスは使わないようにとある。
  - Lustre・Heptagon・Lucid Synchrone（値のクロック）: クロックは値がある刻みを表す型で、`when` で間引き、`merge` で補い合う二つを一つにする。演算は同じクロックの値どうしだけで、クロックの計算が同期で動かせない形を静的に落とす。
    Pouzet の講義資料は、一般には NP 完全から決定不能まであるので十分条件で検査する（Lucid Synchrone は構造の同値）とし、「書き手には強い制約だが安全性を上げる」とする。Prelude は厳密な周期のクロックに `*^`（各要素を k 回繰り返す）と `/^`（k 個に一つ取る）を持つ（Blair と Xi の 2017 年の説明）。
  - Kronos（値ごとのクロックを流れで伝える）: 各入力が根のクロックになり、コンパイラが依存を辿って各節の更新のクロックを決め、レートの境目に状態を自動で入れる（暗黙の保持）。`Resample`・`Downsample`・`Audio:Signal` で明示に変え、優先度で、どのクロックが他を抑えるかを決める。
    遅延の刻みは、つないだ信号のクロックの更新の間隔になる。著者は「UI の更新が遅延を進めないよう、この間隔を正確に制御する必要がある」として優先度を入れた。決定的な上げ下げで、制御の刻みと音声の刻みを分岐なしに交互に並べるベクトル化をする。
  - ChucK: レートの型を持たず、書き手が `=> now` で時間を進めた分だけ計算し、どのレートでも制御できるとする。
  - Reaktor: Core の音声の信号は、サンプルのクロック（`SR.C`）が刻むイベントとして扱う。Core の文書は、一次の層の event / audio（処理の速さの区別）と Core の audio / control / event / logic（意味の区別）は別の分類で、混同しないようにと書く。
- **推奨と理由:** (c)。確度: 中。
  - 誤解: (c) は、設計 1 の弱点の形（レートをまたぐ連鎖、入れ子の呼び出しに付けた修飾子、帯域の制限と補間の書き忘れ）を、上りと下りの両方で検査で落とす。遅い値を速い入力へ渡す形は、遅く動かす読み（Lustre・Kronos）と保持して速く動かす読み（Pd・設計 1）に割れるので、誤りにして読みごとの候補を出す。
    設計 1 は同じ形を通す。信号処理の部分で仕様が借りる先に挙げる言語の間でも、Cmajor・SOUL・Max は既定で境界に補間を入れ、Pd は既定で保持とフィルタ無しの間引き、Faust の `ondemand` も保持と間引きで定めるので、`x.up~(2)` の意味が借りる先によって割れる。設計 1 はその一方の読みで検査を通す形になる。
    設計 2 も弱点の形を落とすが、本体の中の状態を値のクロックで刻むので、式に速い値を一つ足すと `prev~` の刻みが黙って変わる（Kronos の著者が優先度を足した理由と同じ）。(c) は状態を本体の `sample` だけに置いたままにし、この誤りの源を持たない。
  - 計算: 遅い値に掛かる式（フィルタの係数）は、今の巻き上げと同じ規則で遅い段に出る。設計 1 で同じ節約をするには係数を区間の中へ移す必要があり、そうすると中の `sample_rate()` が 1/N になって係数が黙ってずれる。STFT の窓は出力の刻みだけ作る。オーバーサンプリングの回数は全ての案で同じ。
  - メモリ: 差は小さい（枠と比ごとのカウンタ、遅い段の巻き上げの欄、速い値を渡す N 個の配列）。どれも大きさがコンパイル時に決まる。
