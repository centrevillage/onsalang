# S-375

- 位置付け: 族「§2.3 の名前の形」（S-650、組 52）の一つ。試した入力と独立のレビューは `S-650.draft.md`。
- 論点: §7「`-` の後が定数の名前であること（最後の名前が `UPPER_SNAKE` の形の名前と経路）は字面で決まる（§2.3）」、`@` の右の「字面で定数と分かる名前と経路」。§2.3 の表は列挙子を `UpperCamel`、定数を `UPPER_SNAKE` とするが、`[A-Z][A-Z0-9]*` の名前（`A`・`N`・`T`・`OK`・`IO`・`LIMIT`）は両方に合う。
  `k @ Status.OK`（列挙子）は定数と読まれ、候補を当てると `Status` が `PartialEq` を持たなければ型の段の E0401 が残る。
  - 決定済み（論点から外す）: `-LIMIT` は構文の段（S-319 の (c)）。`@` の右の定数の字面と候補 `k if k == LIMIT`（S-352）。S-352 の下書きは「一文字の列挙子（`k @ E.A`）にも候補 `k if k == E.A` を出す。当たる値は同じで、網羅の判定（W5-09）や `PartialEq` の誤り（型の段）が後で出うるが、後の段の誤りなので約束（S-236）の内である」と、重なりを代償として書いた。
    S-375 の本文の「列挙子と重なる場合を見ていない」は、S-352 の決定の行についてで、下書きは一文字の場合を見ている（全て大文字の `OK` は書いていない）。
  - パターンの名前だけ（`match s { OK => … }`）は §7 のとおり名前の解決で決まり、論点にならない。重なりが効くのは `-` の後、`@` の右、FAUST の `x@N` の三つ（S-650 の表 B）だけである。
- 今の実装: `k @ Status.OK` は E0020 と候補 ` if k == Status.OK`、当てた後は E0401（`target/notes/62/gap52f/probe/at_ok.onsa`・`at_ok_fixed.onsa`）。`k @ Status.Ok` は E0002。`const OK`・`enum E { OK }`・`struct OK` はどれも通る（`target/notes/62/gap52f/probe/matrix.tsv`）。
  既にあるコードで二つの形に合う名前は、定数の宣言 1642 件のうち 1479 件（`N`・`LIMIT`）、列挙子 123 件（`A`・`B`・`F32`）。
- 案:
  - (a) 重なりを残し、字面で定数と読む所は S-352 の判定（最後の名前が `UPPER_SNAKE` に合えば定数）のまま。仕様に重なりがあることと、その所では定数と読むことを一文で書く。実装は今のまま。
    費用の要因: 二つの形に合う列挙子（`Status.OK`、一文字の `E.A`）を `@` の右と `-` の後で定数と読むので、候補を当てた後に型の段の E0401（`PartialEq` が無い）や網羅の判定の誤りが残りうる（S-352 の代償）。書き手は列挙子を定数として咎められる文面を読む。
  - (b) 重なりを残し、その所では重なる名前を名前の段で解決する（定数なら E0020 と候補、列挙子なら E0002）。S-319 と S-352 の「構文の段」を重なる名前で改める。定数の約 9 割が重なるので、`-LIMIT` と `k @ LIMIT` の多くが名前の段の判定になる。実装は構文の段に仮の読みを置き、名前の段で決める（約 60〜120 行、見積もり）。
  - (c) 重なる名前を、その所では定数とも列挙子とも決めず E0002 と note にする（ガードで書くことを示す）。`k @ LIMIT` の候補が無くなり、S-352 の決定を改める。
  - (d) 形の定義で重なりを減らす: `UpperCamel` は大文字を二つ続けない（`IO` は `Io`、`HTTPServer` は `HttpServer`、`OK` は `Ok`）。一文字の `A`・`T`・`N` は残るので、残りは (a)〜(c) のどれかが要る。今の型の名前で大文字が続くものは 20 件（`HTTPServer`、`InAVariant` などの一文字の語）。
- 他言語: 定数と列挙子を字面で分ける言語は、調べた範囲（Rust・Swift・Python・Go）に無い。rustc 1.94.1 はパターンの一つの名前を名前の解決で決める（S-650 の他言語）。
- 推奨と理由: (a)。確度: 中。重なりを残し、字面で定数と読む所は S-352 の判定のまま。
  - 重なりを形の定義で無くすには、型パラメータの `T`、定数のパラメータの `N`、定数の `PI`・`MAX` のどれかを書けなくする必要があり、(d) でも一文字の重なりは残る。形の定義は三つの形を一度ずつ書くだけにし、重なりは「どちらの形でもある」とする方が規則が増えない。
  - 重なりが効く所は三つで、S-352 が既に重なる名前を定数と読む代償（後の段の誤りが残りうる）を見て決めた。その理由は全て大文字の `OK` にも同じに当たる（当たる値はガードと同じで、残るのは後の段の誤り）。
  - (b) は一つの形の誤りを名前で構文の段と名前の段に分け、S-352 の下書きが (b) を退けた理由（仮の読みが要る）がそのまま当たる。定数の約 9 割が名前の段に移る。(c) は `k @ LIMIT` の候補を失い、S-352 を戻す。
  - あわせて決めること: §2.3 か §7 に、二つの形に合う名前は字面で定数と読む所では定数と読むことを書き、`naming.rs` 28 行の `SPEC-GAP(S-375)` を外す。W5-09（書けない型の定数）も同じ判定を使う。
- 影響: 仕様 §7（S-319・S-352 の文。(a) は一文を足すだけ、(b)・(c) は文を改める）、§2.3。診断のコードは E0020・E0002。作業は W4-14 U3（印を外す）、(b) は名前の段の作業、W5-09。
  事例: (a) は変えない。(b) は `e0020_patterns_at_forms.onsa`・`pattern_negated_const.onsa` の段、(c) は `k @ LIMIT` の `.fix1` と期待のコード、(d) は `HTTPServer` などの型の名前 20 件。
- 回答（2026-10-24、62 回目、会話）: B-3 は (a)。親が、B-3 は修正候補と報告の段の話で通るプログラムは変わらないと説明した後に「それなら(a)で良いです。」
