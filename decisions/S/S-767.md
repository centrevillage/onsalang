# S-767 `Array[T]`・`Map[K, V]`・`Set[T]` の要素に Affine の型（`Array[Buf[F32]]`）を書けるか: 今は通り、`(a, a)` で複製でき `a.get(0)` で `Buf` を取り出せる（§4.6 の表は Shared の「それらを含む型」と Affine の「それらを含む型」が重なる）

- 空白: §4.6 の表は Shared を「`Str` `Bytes` `Array` `Map` `Set`、それらを含む型」、Affine を「`Buf`、`Drop` 実装型、flow の状態、それらを含む型」とし、`Array[Buf[F32]]` のように両方を含む型の種を書いていない。
  §4.5 の暗黙の `Dup` は宣言の型パラメータの規則で、組込みの `Array`・`Map`・`Set` の要素の要求は仕様に無い（要求を書くのは `Buf`・`Span` の要素の `Copy` だけ、§4.5 の 145 行）。
  今の実装は `fn twice(a: Array[Buf[F32]]) -> (Array[Buf[F32]], Array[Buf[F32]]) { (a, a) }` と、`a.get(0)` で `Option[Buf[F32]]` を取り出す形を通す（`target/notes/82/s767/arr_affine4.onsa`、HEAD `18ec94d`。`body/bounds.rs::satisfies` は `Array`・`Map`・`Set` を `Dup` とする）。
  Shared の値の複製で、複製できないはずの Affine の値（§4.6）に二つの持ち主ができる（実行時の帰結は確かめていない）。
  読み: (1) 要素（`Map` は鍵と値）に暗黙の `Dup` を求め、Affine の要素は型の位置の E0416（§4.5 の 146 行の表に組込み型の行を足す。W4-05 U4a の表に一行）。(2) 要素が Affine なら全体を Affine とし、複製を E0711 などで止める（Shared の不変・永続の列の意味が変わり、`get` などのメソッドの型を改める）。(3) 今のまま（健全さを欠く）。
- 決定:
- 経緯: 82 回目（2026-10-29）、親が W4-05 U4a のテストの票の NEW-2（`Option[Buf[F32]]`、S-765）を確かめる中で、組込みの総称の型の要求を見て気付き、HEAD のバイナリで再現した。期限は W4-05（整形性の段の組込み型の行。U4a の実装は今は判定しない）。関係: S-765、R-37、§12。
