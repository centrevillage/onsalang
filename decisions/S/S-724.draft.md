# S-724 失敗した名前をパターンに含む一つの `let` で、同じ `let` の中の誤り（注釈とパターンの形の違い、注釈と初期化式の型の違い）を報告するか（§18.1 の「その単位の以後を検査しない」の「以後」）

- 決定済みで戻さないもの: 値の位置の失敗した名前で止めること（S-692）、同じ単位の誤りの順は検査の順であること（S-692 の補いの A5）、名前の段の誤りはソースの順で報告し、束縛の名前を右辺と注釈より先に確かめること（R-289、W4-04 U7a）。
  第 67 組の下書きの「族「§18.1 の失敗した名前の後の検査」の仕組みの出所」と「族の形の表」の節（写しは `target/notes/78/g67/draft.md`）。
- 論点: §18.1「値の位置（失敗した名前を経路として書いた式とパターン…）では、その単位の以後を検査しない」。「以後」が、ソースの位置の後か、検査の順の後か、文の単位かが書かれていない。
  登録のときは、同じ `let (q, Dd { a: r }): Bool = (x, x)`（`Dd` は E0304 の名前）で、fn の本体は E0401（5:32、注釈と初期化式の違い）を出し、flow の本体は何も出さないと、fn と flow で違っていた。
- 今の実装: 登録のときと事実が変わった。`target/notes/77/s724/fn_let.onsa` は、`onsa-u6` までは 5:32 の E0401 を出し、`onsa-064668f`（W4-04 U7a）から出さず `Dd` の E0304（別の単位）だけになった。`flow_let.onsa` も E0304 だけで、fn と flow は今そろっている。
  今の実装の止まり方（`probe/s724/after.txt`・`pos.txt`。`Dd` は E0304 の名前、`Gone` は失敗した `use` の名前）:
  - 名前の段の誤りで、失敗した名前よりソースで前にあるものは出る（`let (Nope, Dd { a: s }) = (x, x)` の `Nope` の E0302、`let y: Nope = Gone.x` の注釈の E0302。fn と flow で同じ）。
  - 型の段の誤りで、検査が失敗した名前に届く前に見つけるものは出る（`g(1 + true, Gone.x)` の 7:17 の E0401、`match x + true { Dd { a: r } => r }` の E0401。fn と flow で同じ）。
  - 失敗した名前をパターンに含む `let` の、パターンと注釈・初期化式の比べ（注釈との違い、タプルの数）は出ない。
    比べの誤りの位置は、注釈と初期化式の違いなら初期化式（`Dd` より後ろ）、パターンの形の違いならパターンの頭（`let (q, r, Dd { a: s }): (F32, F32) = (x, x)` の 7:7、`Dd` より前）である（失敗した名前の無い `pos.txt` で確かめた位置）。
  - 仕組み: 名前の段の歩き手は失敗した名前で止まり、その後ろ（`let` の注釈と初期化式を含む）に記録を置かない（flow の本体は `fail_at_let` でその `let` まで待つ）。型付けは自分の検査の順で、記録の無い節に届いたところで止まる（`body/named.rs::held_stop`）。
    `let` は初期化式を先に検査するので、パターンとの比べに届かない。
- 案: 
  - (a) 「以後」は検査の順の後とし、どこまで検査するかは約束しない（今の実装。fn と flow でそろっている）。
  - (b) ソースの位置で約束する: 失敗した名前より前に始まり、その名前に頼らずに決まる誤りは報告する（`let (q, r, Dd { a: s }): (F32, F32) = …` のタプルの数の E0401 は、注釈だけで決まり、位置は `Dd` より前）。
  - (c) 文の単位で約束する: 失敗した名前を含む文は、その中の前の誤りも含めて報告しない（`g(1 + true, Gone.x)` の E0401 と `(Nope, Dd { … })` の E0302 も出さない）。
  - 書き手から見て: どの案でも、失敗した名前の誤り（`use` の E0302、宣言の E0304）は別の単位に出るので、黙って通るプログラムは無い。違いは、同じ文の他の誤りが今の検査で出るか、失敗した名前を直した次の検査で出るかで、修復のループが一回増えうるだけである。
    この形（失敗した名前をパターンに含み、同じ `let` に別の誤りがある）は、書き手のプログラムで多くない。
  - 修正候補: どの案も変わらない。
  - 規則と例外: (a) は規則を足さない（書くなら §18.1 に「以後は検査の順で、どこまで検査するかは約束しない」の一句）。(b) は位置と依存の約束を足す。(c) は「文」の単位を §18.1 に足す。
  - 実装の量: (a) は 0 行。(b) は型付けの `let` の検査が、初期化式に記録が無いとき、注釈があればパターンの形を注釈と先に比べる枝（fn は `body/statements.rs`、flow は W7-04 の `check_flow_let`。約 +10〜20 行）で、パターンの形の検査の順に新しい約束が続く。
    (c) は歩き手が文の頭まで戻って記録と誤りを捨て、型付けもその文を飛ばす（約 +10〜15 行）。今出ている前の誤りが消える。
