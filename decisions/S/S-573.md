# S-573 `render` と `onsa test` でのイベントの与え方

- 空白: §11.6 の `render` は全体を一回の `process` として処理し、`block` の入力は全区間で一定である。§18.2 の `onsa test --flows` は export する flow を `@param` の範囲で自動検査する。どちらもイベントの入出力を持たない。§19.1 は `render` の書き方（入力をまたいだ順を書ける形）を第 35 組に送った。決めること:
  1. `render` の引数のイベントの形（S-570 の列と同じか）と、出力のイベントの `Rendered` での表し方（S-571）。
  2. テストでイベントの列を書く書き方（リテラル、`std.dsp.test` の補助）と、入力をまたいだ順の書き方。
  3. `onsa test --flows` の自動検査で、イベントの入力に何を与えるか。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51 回目）: `render` は `process` と同じ位置に同じ形のイベントの列を取り（位置は `render` の頭から）、出力のイベントは `Rendered` の `Buf[(U32, E)]`。テストの補助は足さず、リテラルと作る関数で書く。`onsa test --flows` は境界の型ごとの決まった列を与え、出したイベントの数の上限と、呼び出しを分けても出力がビットで同じことも確かめる。仕様 §19.1
- 経緯: X-7（W3 の終わり、2026-10-15、利用者）で、W4 の前に決めて第 1 期の範囲を W4〜W10 に割り当てることになった。第 35 組（境界）の一つで、第 33 組（S-555〜S-559）と第 34 組（S-560〜S-567）の決定を前提にする。関係: S-561、S-564、S-570、S-571、§11.8。
