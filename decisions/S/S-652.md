# S-652 E0320 の改名の候補が、同じ範囲の既にある名前と重なる（`[Item, Item_]` の候補で `[Item, Item]`、`struct Item` と `struct Item_`）

- 空白: §2.3 と S-82 は、E0320 の候補が宣言と全ての使用箇所の名前を直すとするが、直した名前が同じ範囲の別の宣言と重なるときに候補を出すかを書いていない（`fn f[Item, Item_]` の `Item_` の候補 `Item` で `[Item, Item]`、`struct Item` と `struct Item_` の候補 `Item`、関数の `Foo` と `foo`）。
  §18.1 は約束を満たす候補を作れなければ出さないとするが、重なりが誤り（E0304 など）になるかは S-649（型パラメータ）と名前の段（W4-04）に依る。
- 決定: 決定（2026-10-24、利用者が ID を挙げて了承。62 回目、第 52 組）: (a)。規則に揃えた名前が既にある名前と重なるとき（その名前で宣言すると E0304 になる範囲と、同じ並びの型パラメータ）は候補を出さず、note で規則に揃えた名前を示す。実装は W4-04（S-82 と同じ名前の段の記録）。
- 経緯: 62 回目（2026-10-24）、S-642 の独立のレビュー（onsa-advisor、段 1・段 2）が新しい S の候補として挙げ、族「§2.3 の名前の形」（S-650）の一つとして登録した。関係: S-82、S-649、S-642、W4-04。
