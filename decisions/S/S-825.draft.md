# S-825 既定の値を書いた `main_frame = "stack"`・`memory.bulk = false` も E0200 か

- 決定済みで戻さないもの: 既定でない値（`main_frame = "static"`、`memory.bulk = true`）の E0200 と出すコマンド（S-154、R-166）。値の規則に合わない値（`main_frame = "heap"`）は S-827。対応しているキーの既定の値（`fp = "strict"`、`provides = []`）は誤りでない（§15.3 の表）。
  第 77 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/95/g77/draft.md`）。
- 論点: §15.3（166 行）は、仕様にあって未対応のものを「使った位置で E0200 になり、黙って無視されない」とし、E0200 の一覧は `main_frame` と `memory.bulk`・`fast_budget`・`bulk_budget` をキーで挙げる。§15.3 の表は `main_frame` の既定を `"stack"`、`memory.bulk` の既定を `false` とする。
  既定の値を書いた形が E0200 か（キーを書けば値によらず誤りか、既定でない値だけが誤りか）は書いていない。同じ問いは、中身の無い `[targets.t.bind]`（既定は割り当て無し）にも当たる。`fast_budget`・`bulk_budget` は既定が無い（任意）ので、どの読みでも値を書けば E0200 である。
- 今の実装: `main_frame` は値によらず読んで捨て、`memory.bulk` は読まない（どちらも 0／0／0、`k01`・`k02`・`k05`・`k06`）。今の生成物は、bulk 無効（`@mem(bulk)` は §12.4 のとおり無視の扱いで、`@mem` の意味は W9-06 までソースの E0200）と同じである。
  `main_frame` は `main` のフレームの置き場所（§12.5）で、この版は `main` を持つ `kind = "exe"` が E0200 なので、どの値も生成物を変えない。
- 案: 
  - (a) キーで未対応: キーを書けば値によらず E0200（そのターゲットのビルド）。今の E0200 の一覧の書き方のまま。
  - (b) 既定でない値だけ: 既定の値は、この版の動きと同じ意味なので通す。既定でない値（`main_frame = "static"`、`memory.bulk = true`、中身のある `bind`）だけが E0200。E0200 の一覧の項目を値で書き直す（`main_frame` の `"static"`、`memory.bulk` の `true`）。
  - (c) 既定の値は全てのキーで誤り: 既定の値を書くのは冗長として、対応しているキーも含めて誤り（E1103 か新しいコード）にする。
  - 形ごとの出力: `main_frame = "stack"`・`memory.bulk = false`・中身の無い `bind` の表は、(a) が `build --target t` で E0200、(b) が通る、(c) が全てのコマンドで誤り。`fp = "strict"`・`provides = []` は、(a)・(b) が通り、(c) が誤り。
  - 書き手から見て: LLM の書き手は既定の値を明示しがちで（`provides = []` はリポジトリの 74 ファイルにある）、(a) はそのうち未対応のキーの分だけを E0200 にする。書き手からは `fp = "strict"` が通り `main_frame = "stack"` が誤りになる理由が見えず、行を消す一回が増える。
    (b) は既定の値を書いても書かなくても同じ結果になる。代わりに、この版が扱わないキーを書いたことは、既定でない値に変えるまで知らされない（`main_frame = "stack"` の行は、`exe` を入れる版まで生成物に何も効かない）。(c) は既定の明示を全て一回で知らせるが、`provides = []` のように既定を知らずに書いた形も直させる。
  - 修正候補: (a)・(b) は候補なし（E0200）。(c) は行を消す候補が安全（意味が変わらない）で、当てて収束する。
  - 通るプログラム: リポジトリに `main_frame = "stack"`・`memory.bulk = false`・中身の無い `bind` は無く、(a)・(b) は今のマニフェストの結果を変えない。(c) は `provides = []` の 74 ファイルと `numeric = "strict"` の 5 ファイル（旧い名前で別に E1102）の書き方を変える。
  - 規則と例外: (a) は規則を足さないが、対応しているキーの既定（通る）と未対応のキーの既定（誤り）で表面が食い違う。(b) は一覧の項目を値で書くだけで、「既定の値はどのキーでも通る」が一様になる。(c) は既定の値を誤りにする規則を一つ足し、§15.3 の表の全ての既定に当てる。
  - 実装の量（W4-02 の U3）: (a) はキーの有無で約 +2〜3 行（キーごと）。(b) は既定と比べて約 +2〜3 行（キーごと。既定は閉じた表の行にある）で、E0200 の一覧の項目と `Feature` の文を値で書き直す（約 2 行）。(c) は表の全ての既定と比べる約 +5〜10 と候補、事例。
  - 後の作業への手当て: (a)・(b) とも、W9-06 で `memory.bulk` に対応すると一覧の項目を外すだけで、通るものは減らない。(c) はキーを足すたびに既定の比べが付く。
- 他言語: cargo 1.94.1（`probe/other/cargo/c06`・`c07`）: 未安定のキー `im-a-teapot` は、`true` も既定の `false` も「the `im-a-teapot` manifest key is unstable … feature `test-dummy-unstable` is required」で誤り（キーで止める）。
  既定の値の明示（`[profile.dev] opt-level = 0`、`edition = "2015"`）は警告なしに通る（`c10`・`c12`）。Cargo の未安定のキーは意味が決まっていないキーで、意味が仕様で決まっている Onsa の未対応のキーとは事情が違う。
- 推奨と理由: (b)。確度: 中。
  - 既定の値は仕様が意味を決めていて、この版はその意味のとおりに動く。値が黙って捨てられることも、誤った結果になることも無く、E0200 が守る「黙って無視されない」は (b) でも成り立つ。
  - (b) は「既定の値はどのキーでも通る」を一様に保つ。(a) は書き手から理由の見えない食い違い（`fp = "strict"` は通り `main_frame = "stack"` は誤り）を作り、行を消す一回を足す。(c) は既定を書く普通の形（`provides = []`）まで直させ、規則が一つ増える。
  - 実装の量は (a) と同じで、後で対応しても通るものは変わらない。
  - あわせて決めること: E0200 の一覧の項目を値で書く（`main_frame` の `"static"`、`memory.bulk` の `true`、中身のある `bind`。`fast_budget`・`bulk_budget` はキーのまま）。このとき `main_frame`・`memory.bulk` は値で未対応の項目になり、S-827 の位置の読みでは E0200 の位置が値になる。
- 影響: `tasks/diag-codes.md` の E0200 の行の一覧（(b) は値で書き直す、(a) は今のまま、(c) は E1103 の行か新しいコード）。仕様 §15.3 は、(a)・(b) が変わらない（(b) は 166 行の「未対応のもの」に既定の値が入らないことを一句足すと読みが割れない）。(c) は §15.3 に一文と §0.5.1 との関係。
