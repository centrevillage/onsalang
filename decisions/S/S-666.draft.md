# S-666 ファイルの無いディレクトリだけのモジュール（`a/b/c.onsa` だけのときの `a`・`a.b`）を、`use a`・`use a.{b}`・`use a.b` で取り込めるか

- 決定済みで戻さないもの: 取り込める一覧（依存のパッケージそのもの、ルート直下のモジュール、モジュールの項目、子モジュール、flow の名前空間とその項目）と、二つの書き方が同じ束縛を作ること（S-594）。
  経路の途中のディレクトリに §2.3 の規則を当てること（S-313）。ルート直下のディレクトリの名前と依存のパッケージ名の重なりの E0304（S-246）。モジュールを取り込む `use` を下の全てのモジュールへの辺として数えること（S-594）。
  ディレクトリの引数はパッケージのルートだけで、モジュールのディレクトリは渡せない（S-312。`check <パッケージ>/a` は「has no onsa.toml」で終了コード 2）。表の 7〜12・14〜17 の行。
- 論点: §15.1「1 ファイル = 1 モジュール。モジュールのパスはパッケージルートからのファイルパスで、`mod` 宣言は無い」「モジュールとファイルの経路は一対一である」と、「取り込めるのは、依存のパッケージそのもの（`use std`）、ルート直下のモジュール（`use kp`）、モジュールの項目、子モジュール…」。
  一方で E0304 の文は「ルート直下のモジュールの名前か、モジュールを含むルート直下のディレクトリの名前」と、ディレクトリをモジュールと書き分ける。§2.3 も「モジュールの経路の途中のディレクトリの名前」と書く。
  ファイルの無いディレクトリがモジュールか（取り込めるか）を書いていない。表の 3・5・6 で読みが割れ、13 の重なりと 17 の候補の結果もこの読みで変わる。
  - 仕組みの出所と目的:
    - E0304 の書き分けは S-246（2026-10-08）から。問いは「E0304 が、モジュールでないディレクトリ（`std/` だけがあり `std.onsa` が無い）を含むか」で、利用者の `std/math.onsa` が std を隠して `use std.math.{abs}` が E0302 になるのを防ぐために、ディレクトリも含めた。
      「モジュールでない」は問いの言い方で、取り込めるかは扱っていない。目的は依存の名前を隠す経路を残さないことである。
    - S-313（2026-10-09）は、経路の途中のディレクトリの名前に §2.3 の規則を当てた。目的は、モジュールの経路とファイルの経路を一対一にし、生成する C の名前が重ならないことである。ディレクトリが取り込めるかは扱っていない。
    - `use kp` の例は S-594 の (x1)（2026-10-23）で取り込める一覧に入った。下書きの表の 15 行は、§2.2 の例（S-371 の `kp.clock.tick()`）と、W3-04（2026-10-11）の `tests/spec/packages/reserved_word_modules` の `use kp` を指していた。この事例の `kp` はファイルの無いディレクトリである。

    - 実装は、モジュールの木を作るときに、ファイルの無い要素を「ディレクトリだけのモジュール」の節点として作る（`crates/onsa_sema/src/names/collect.rs` の `module_at`。`ModInfo.file` が `None`）。`use` の解決は節点を区別しない（`names/imports.rs` の `SPEC-GAP(S-666)`）。

  末尾の名前が同じ二つのディレクトリ（`t1_dsp_fx`: `dsp/filters.onsa`・`fx/filters.onsa`、`dsp.onsa`・`fx.onsa` は無い）は、`use dsp` と `use fx` の後の `dsp.filters.g() + fx.filters.g()` が通る。
  `use dsp.filters` と `use fx.filters` を並べると `filters` の E0304（`t2_dsp_fx_dup`）。`onsa test` は 0 で 1 件通る（`z1_test`）。`onsa interface .` はファイルのあるモジュール（`a.b.c`・`main`）だけを並べ、`a`・`a.b` の見出しは出さない。
  U2a は初め (a) の読みを入れ、`reserved_word_modules` が落ちたので、親が今の挙動に戻した（`crates/onsa_sema/src/tests.rs` の `a_use_takes_the_module_of_a_directory_only_and_goes_through_it`）。

- 案: 
  - (a) ファイルの無いディレクトリはモジュールでなく、経路の途中にだけ書ける。それを取り込む `use`（表の 3・5・6）は E0302（候補なし。note「ファイルの無いディレクトリは経路の途中にだけ書ける。下のモジュールを取り込む（`use a.b.c`）か、`a.onsa` を置く」）。
    - 書き手から見える違い: `use a` の後の `a.b.c.f()` は書けず、`use a.b.c` の後の `c.f()` か `use a.b.c.{f}` にする。末尾の名前が同じ二つのディレクトリ（`t1_dsp_fx`）を呼び分けるには、空の `dsp.onsa`・`fx.onsa` を置いて `use dsp`・`use fx` にする。
    - 重なり（表の 13）: `a.onsa` の項目 `b` と `a/b/` は、`a.b` がモジュールでないので §15.1 の「モジュールの項目と、同じ名前の子モジュール」に当たらない。経路の `a.b.c` が項目とディレクトリのどちらを指すか割れるので、E0304 の文に「子モジュールを含むディレクトリ」を足す（S-246 のルート直下の文と同じ形）。
    - S-663 の候補（表の 17）: `use fx.{a}` の候補 `use a` を当てると、`a` がファイルの無いディレクトリなら E0302 が残る。候補を出さない例外を足すか、残る誤りを認める（§18.1 の「候補を当てた後に誤りが残らない」に当たる）。
    - 直し続けて止まるか: E0302 は候補が無いので止まる（直すのは書き手）。
    - 実装の量: `names/imports.rs` で取り込む名前がファイルの無い節点（パッケージの根を除く）なら E0302 と note（10〜15 行）。S-663 の候補の分岐（U3a、数行）。
      事例: `reserved_word_modules` と `interp_path_modules`（W4-04 までの実装待ち）に空の `kp.onsa` を足すか書き方を改める。`tests.rs` の単体テストを否定例に書き換える。否定例 3 件（`use a`・`use a.{b}`・`use a.b`）。
  - (b) ファイルの無いディレクトリは、項目の無いモジュールである。取り込め（表の 3・5・6）、取り込んだ束縛から経路で下のモジュールに届く（今の実装）。
    - 書き手から見える違い: 今のまま。`use a` は、`a.onsa` があってもなくても同じに書け、同じに働く。
    - 読み手から見える違い: `use a` の `a` の定義へ飛ぶ先は、ファイルでなくディレクトリ（か下の最初のファイル）になる。§15.1 の「モジュールとファイルの経路は一対一」は「ファイルのあるモジュールとファイルの経路は一対一」に限る一句が要る。（親の追記。段 2 の指摘で直した）
    - 重なり（表の 13）: `a/b/` が子モジュールなので、§15.1 の今の文（項目と同じ名前の子モジュールは E0304）が当たる。文を足さない。
    - S-663 の候補（表の 17）: 例外なし。`use a` は通る。
    - 実装の量: 0 行（`SPEC-GAP(S-666)` の印を外し、単体テストの注記を改める）。§15.1 に一文（「1 ファイル = 1 モジュール。ファイルの無いディレクトリ（`a/b/c.onsa` だけのときの `a` と `a.b`）は、項目の無いモジュールである」）。E0304 の文はそのまま読める。
  - (c) ルート直下のファイルの無いディレクトリ（表の 3）だけを取り込め、子のファイルの無いディレクトリ（表の 5・6）は (a) の E0302。
    - 書き手から見える違い: `use a` の後の `a.b.c.f()` は書け、`use a.b` は書けない。重なり（13）は (a) と同じく文を足す。S-663 の候補は、`a` がルート直下なので通る。
    - 実装の量: (a) と同じ検査に「親がパッケージの根でない」の条件（10〜15 行）。事例の書き換えは要らない（今の事例はルート直下の `kp` だけ）。
    - 規則: 取り込める一覧の「ルート直下のモジュール」と「子モジュール」で、ファイルの無いディレクトリの扱いが分かれる（一つの条件が増える）。
- 他言語: （参考。ファイルを持たないディレクトリを名前空間として取り込めるか）
  - Python 3.14.5（手元、`other/py/`）: `a/b/c.py` だけ（`__init__.py` 無し）で、`import a`、`import a.b`、`from a import b`、`import a.b.c` が全て通る。`a` は `<module 'a' (namespace)>`（名前空間パッケージ、PEP 420 https://peps.python.org/pep-0420/ ）。
    `import a` だけの後の `a.b` は `AttributeError: module 'a' has no attribute 'b'`（下は `import a.b` で読み込むまで属性にならない）。
  - rustc 1.94.1（手元、`other/rs/`）: `a/b/c.rs` だけで `mod a;` は E0583「file not found for module `a`」（help「create file "a.rs" or "a/mod.rs"」）。
    ファイルの中の `mod a { pub mod b { pub mod c; } }` は通り、`use a::b;` の後の `b::c::f()` が走る（ファイルの無いモジュールは宣言で作る。Onsa には `mod` 宣言が無い）。
  - Node v26.11.1（手元、`other/node/`、ES モジュール）: ディレクトリの `import * as a from "./a"` は `ERR_UNSUPPORTED_DIR_IMPORT`。取り込むのはファイルだけ。
  - Go 1.27.2（手元、`other/go/`。7.32 の一覧の外）: `a/b/c/c.go` だけで `import "example.com/ex/a"` は「no required module provides package example.com/ex/a」。パッケージはファイルを持つディレクトリだけ。
  - Java（未確認、手元に無い）: JLS 21 §7.4.3（https://docs.oracle.com/javase/specs/jls/se21/html/jls-7.html#jls-7.4.3 ）は、コンパイル単位の無いパッケージも下のパッケージがあれば observable とし、§7.5.2 の `import P.*;` は P が uniquely visible（コンパイル単位で宣言される）でなければ誤りとする。
  - C、C++、Swift、TypeScript: ディレクトリを名前空間にする仕組みが無く、比べられない（未確認）。
- 推奨と理由: (b)。確度: 中〜高。
  - `use a` の意味は、`a.onsa` があってもなくても同じである（束縛 `a` を作り、経路で下のモジュールに届く）。読みは割れず、書き手の誤解も示さない。
    (a) は、ファイルの有無という見えにくい条件で合否を分ける。境界とは別の条件で規則を一つ増やし、得るものが無い。(c) はさらに、ルート直下と子で同じ形の合否を分ける。
  - S-594 の (x1) の理由（末尾の名前が同じモジュールを、別名なしで呼び分ける）は、利用者の例の `dsp/filters` と `fx/filters` のように、ファイルの無いディレクトリでよく起きる。
    (a) では、その回避策に空の `dsp.onsa` を置く作法が要る（Python の `__init__.py` に当たる、中身の無いファイル）。
  - (b) は、既にある二つの決定に例外を足さない。表の 13 の重なりは、§15.1 の「項目と同じ名前の子モジュールは E0304」がそのまま当たる。S-663 の候補（`use fx.{a}` を `use a`）は、当てた後が必ず通る。
    (a) と (c) は、E0304 の文を足し、S-663 の候補に例外を足すか、残る誤りを認める。
  - 実装と保守: (b) は 0 行で、今の二つの事例（`reserved_word_modules`、`interp_path_modules`）も変えない。(a) は 10〜15 行と、事例と S-663 の分岐の直しが要る。
  - 厳しさ: (a) から (b) へ後で緩めても壊れない。代わりに (a) の制限は、守る誤りの形を持たない（どの書き手の誤解も示さない）ので、制限として残す理由が無い。
  - 第 2 期と JS / WASM: 依存のパッケージのファイルの無いディレクトリ（`use fx.dsp`）も同じ規則で読める。項目の無いモジュールは生成するコードに何も出さない（C・JS・WASM の名前は項目の経路から作る）。モジュールの再公開（S-596、第 2 期）の規則も、ファイルの有無で分けずに書ける。
  - あわせて決めること:
    - §15.1 の「1 ファイル = 1 モジュール」の文に、ファイルの無いディレクトリは項目の無いモジュールである、の一文を足す。「モジュールとファイルの経路は一対一」は、ファイルを持つモジュールの話として今のまま読める。
    - E0304 の「モジュールを含むルート直下のディレクトリの名前」は、(b) ではルート直下のモジュールの名前に含まれる。文は変えず、S-246 の例（`std/math.onsa`）を残す（変えると文の差分だけが増える）。
    - `onsa interface` は、ファイルの無いディレクトリのモジュールに見出しを出さない（項目が無く、経路に渡せるファイルも無い。今のまま）。
  - 別の S にしてよい論点: 無い。表の 11〜14 の今の挙動は W4-03 の U3a で直す既決の分で、S-666 の読みに依らない（13 の文だけが読みに依る）。
