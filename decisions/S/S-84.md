# S-84

- 空白: `T: Num` の `-x` を検査が通し、`U32` で実体化すると Core の検証器が落ちる（R-03）。`Num` と `Neg` の関係、演算子 trait を境界に書けるか、§6.3 の表の演算子 trait、ラップ・飽和と `!` の trait が決まっていない（レビュー R-94、R-131）
- 提案: 数の trait は `AnyNum` / `Num`（`AnyNum` + `Neg`）/ `Float` / `Int` / `Unsigned`（§6.3）。符号なし整数は `Num` を満たさない。
  第 1 期は暫定の `Bound` と `implies` に足す: 数の trait と演算子 trait（`Not`、ラップ・飽和の 6 つを含む）を境界に書けるようにし、含意は `AnyNum ⇒ Copy, Add, Sub, Mul, Div, Rem, PartialEq, PartialOrd`、`Num ⇒ AnyNum, Neg`、`Float ⇒ Num`、`Int ⇒ AnyNum, Eq, Ord, Hash`、ビット演算、`Not`、ラップ・飽和、`Unsigned ⇒ Int`。
  演算子の検査は、`Num` で代わりに判定するのをやめ、演算子ごとに自分の trait を引く（`+` は `Add`、単項の `-` は `Neg`、`&` は `BitAnd`、`+%` は `WrappingAdd`）。単項の `-` の特別扱いを消す。
  E0401 の修正候補は数の trait に絞る形（§6.3）、符号なしの否定には `-%` の note、E0416 には満たす数の trait の note。`std/math.onsa` の `min` / `max` を `[T: AnyNum]` に、`sum` も `AnyNum`。`tests/review-phase1/parent/r94/` の期待値は各関数の上のコメント（2026-10-05 決定。実装は第 3 段。R-79 の第 4 段で 1 行が 1 つの `impl` の表にするとき、演算子 trait の行も含める）
- 時期: M2
