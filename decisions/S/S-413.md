# S-413 括弧の中の、構造体リテラルとパターンの `{` の前の改行

- 空白: 括弧の中で、構造体リテラルの `{` を次の行に書く形（`two(S` 改行 `{ a: 1 }, 2)`）。§2.5 の置き場所の規則（ブロックの `{` は見出しと同じ行、S-47・S-202）と S-370 の「記号の置き場所の規則は括弧の中でも外と同じ」は、構造体リテラルの `{` を挙げない。
  括弧の外の `let s = S` 改行 `{ a: 1 }` は二つの文（`S` の文とブロック）になり、括弧の中は今は構造体リテラルとして通る（同じ字面を場所で受けたり拒んだりする、R-62）。読みは (1) 括弧の中でも名前と同じ行に置く規則にして E0003（候補は `{` を前の行へ移す形）、(2) 括弧の中は改行を空白として受ける。
  W3-06/i の設計メモで見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 22 組）: 構造体リテラルと構造体のパターンの `{` を置き場所の規則に入れる。`{` は型の名前（型引数があれば `]`）と同じ行に書き、違反は E0003（主の位置は `{`、候補は S-216 の移し方）。括弧の中でも、`let` などのパターンの位置でも同じ。
  括弧の外の式の位置の構造体リテラルは、名前で行が終わる（今の E0002、候補なし）。S-415 と一つの規則。
  細部（2026-10-10、利用者が Fable の案を了承）: 名前の後の `{` を構造体リテラル／パターンと読む判定（型の名前の字面）は今のままで、E0003 はその判定に従う。`two(N` 改行 `{ 1 })` にも字句の条件を足さずに候補を出し、当てた後に残る中身の誤り（`N { 1 }` の E0002）は次の検査で報告する（S-384 の誤りが二つある入力と同じ、S-236 の約束の外）。
  効果行の `uses` の `{` も同じ規則に入れる（関数型の引数の並びの中の `uses` 改行 `{Alloc}` は E0003、括弧の外は `uses` で行が終わる今の E0002）。仕様 §2.5。実装は W3-06 の単位 2
