# S-950 項目の後ろの余分なトークンが継続のトークンで終わるとき、次の行が同じ単位に入るか（`pub type Op = I32 =` の次の行の `fn(I32) -> I32`）

- 決定済みで戻さないもの:
  第 93 組の下書きの写しは `target/notes/124/g93/draft.md`、入力は `target/notes/124/g93/probe/`（台本は `scripts/`）と段 1 の `adv/probe2/`。今の実装は dev `58598795` の固定のバイナリで確かめた。
  S-274（項目と同じ行の後ろの余分なトークンはその項目の単位に入る）と、S-947 の決定済みで戻さないもの。
- 論点: §18.1 の 72 行（S-274）は、項目と同じ行の後ろに置いた余分なトークンをその項目の単位に入れる。その行が継続のトークンで終わるとき（`pub type Op = I32 =` の次の行の `fn(I32) -> I32`）、次の行が同じ単位に入るかは書いていない。
- 今の実装: `skip_unit` の `line` の読み飛ばしは括弧の外の改行で止まり、継続（`goes_on`）を見ない。`b17`・`b18`・`b14` は、余分なトークンの E0002 に加えて、次の行の `fn(` に「expected function name, found `(`」が出る。次の行が `fn z` の `b19` は `z` が残る。
  同じ単位の誤りの後の読み飛ばし（`skip_unit` の `line` でない道）は S-47 の文に従って継続を見るので、今の実装の中で二つの読み飛ばしが食い違う。
- 案: (1) 継続した次の行も同じ単位に入る（行の終わりを §2.5 の行の終わりで決める）。(2) 改行で止まる（今のまま）。(3) 改行で止まるのは、継続しない改行か、次の行の頭が項目の始まりのとき。
  S-947 の (a) は (1)、(b) は (3)、(c) は (2) と組になり、(d) は字下げで (1) か (2) に分かれる。どれも誤りのあるファイルの報告だけが変わる。
  - 費用: (1)・(3) は `line` の止まる判定に条件を一つ足す（約 +2〜4）。(2) は 0 行。
