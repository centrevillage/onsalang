# S-802 `move` の引数に渡した変数そのものを、同じ呼び出しの後の引数で読んで値を作る形（`take2(move b, b.len())`）

- 空白: §5.2 は `move` の効果を「以後使えない」とし（76 行）、§3.5 は引数を左から評価する。
  69〜70 行は「引数は全て評価してから呼び出すので、引数の中で同じ変数を読んで値を作るだけなら重ならない」「（`move` の重なりの E0702 は）引数の順によらない」とし、§7 の 54 行は、変更が呼び出しの直接の引数（`inout`、`!` の受け手、`move`）によるときは派生した束縛が使えなくなるのは呼び出しの後とする。`move` で渡した変数そのものを後の引数で読む形がいつ使えなくなるかを、文は決めていない。
  dev（`c867200`）と W4-07 U4a の新しい modes（`P88/bin/onsa-u4awired`）はどちらも `take2(move b, b.len())` を E0704 にし、`take2r(b.len(), move b)` は通す。
  U4a では、`o` から派生した束縛 `b` の `g(move o, len_of(b))` は §7 の 54 行のとおり通る（dev は §7 を持たないので通る）。`h(move x, x)`（`x` を場所として借用の引数に渡す）は順によらず E0702（S-787）。
  再現は `target/notes/88/s802/move_then_read.onsa`。W4-07 U4a の票で親が今の形（E0704）を保つと書き、U4 のテストの票（t3）の担当が空白として報告した。
  読み: (1) 移動は引数を評価した時点で効く（§3.5 の左からの評価）。後の引数の読みは E0704、前の引数の読みは通る（今の形）。(2) 直接の引数の移動は、§7 の 54 行の派生した束縛と同じく呼び出しの後に効く。後の引数の読みも通り、順によらない。
- 決定:
- 経緯: 88 回目（2026-10-30）、W4-07 U4 のテストの票（t3）の担当が空白として報告した（親も U4a の票で同じ形に触れていた）。親が二つのバイナリで再現して登録した。
