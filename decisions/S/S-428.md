# S-428

- 空白: 範囲のパターンの端が、別の既存言語の形を含むとき（`1..<3u8 =>`、`1..<+3`、`1..<--3`、`1..<3 /* c */`）。§7 は「端が式として読めないときは E0002」、§18.1 は約束を満たす候補を作れなければ出さないとする。今は範囲の始点から端の終わりまでの E0002（候補なし）。
  範囲のパターンの E0020（候補は端を写したガード、端の誤りは次の検査）にするか。(1) なら当てた後に残る誤りの位置が束縛の名前の長さに依る（S-253）。RF/t が見つけた（2026-10-10）
- 提案: 後の段（次の空白の組）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1、R3）範囲のパターンの端が既存言語の書き方の形（`3u8`、`+3`、`--3`、`017`、`0o17`）を含んでも、式として読めれば範囲のパターンの E0020 でガードの候補を出し、端を写す（端の形の誤りは当てた後の検査）。端が読めないとき（閉じない括弧、E0001 のトークン `3abc`）は今の E0002。ガードの形が書き直す部分のコメント（`1..<3 /* c */`）は決定済みの規則で候補なし（S-845 の族、`foreign-forms.toml` の `*_choice` の注記）。
  - 仕様の節: §7 の範囲のパターンの項（親が置く文）、§18.1（R3 の文）。
  - 今通るプログラム: 変わらない。
  - 実装の見当: `foreign/guard.rs`・`foreign/ranges.rs` で、端の式に外来の形のトークン（`ForeignLit`、前置の `+`、増減）を受ける（20〜40 行）。
  - ぶつかる事例: `tests/spec/fixes/e0020_overlap_range_pattern.onsa`の注記（「端の形は here でない」）は事例の外の説明で、直すのは注記だけ。二つの誤りの事例（`1..<3u8`）は `tests/spec/fixes/` の `.fix1`・`.fix2` の形で足す（一覧の例は誤りが一つの前提なので置かない）。
