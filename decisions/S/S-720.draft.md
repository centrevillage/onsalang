# S-720 flow の本体で組込みの flow の名前を呼び出しでない形で書いたとき（`let f = sample_rate`、`prev * x`）の診断（§15.1 の「見つかったが要る種類でない」E0308 か、今の E0302「cannot find」か）

- 決定済みで戻さないもの: 呼び先の E0811・E0812（§2.6）、flow の外の `prev~(x)` の E0821（§11.1、S-101）、束縛の E0304（S-542）、fn の本体の束縛と引数に使えること（S-542）、代入の E0806（S-267）、flow の本体の関数値の E0806（§11.2）、flow の値・型の位置の E0308（S-713）。
  第 66 組の下書きの「S-720 の仕組みの出所」と「S-720 の形の表」の節（写しは `target/notes/76/g66/draft.md`）。
- 論点: §5.1「見えている束縛には…flow の本体の中では flow の組込みの名前（§11.4）も含む」と、§15.1「名前が見つからなければ E0302。名前は見つかったが、その位置に要る種類…でなければ、位置によらず E0308」。
  §11.4 は組込みを呼び出しの形（`prev~(e)`、`sample_rate()`）でだけ書き、呼び先でない位置に書いたときの種類を書かない。組込みを見つかった名前と読めば E0308 で、そのときの種類（flow か関数か、組込みという別の種類か）で、値の位置の `sample_rate` が E0308 か §11.2 の関数値の E0806 かも分かれる。
  今の実装は呼び先でない全ての位置で E0302「cannot find」である。同じ名前の項目 `fn prev()` は E0304「`prev` is a builtin name of a flow」（S-542、W4-03）で、flow の本体の `let prev = x` も U7a で E0304 になる。
  flow の外は名前が見えない（§2.2、S-542）。そこで `~` の無い呼び出しの形（`sample_rate()`、`prev(1.0)`）が §11.1 の E0821 に入るかも書かれていない。
- 今の実装: 表のとおり。flow の本体の呼び先でない形は全て E0302 で、候補も note も無い。
  呼び先でない記録 `FlowBuiltin` は U2b が既に置いている。今の E0302 は型付けの引き方が組込みを知らないことから来ている（仕組みの出所の節）。
- 案: 
  - (a) 組込みに既にある種類を与える。遅延は flow、`sample_rate`・`sample_tick` は関数とし、同じ形の利用者の flow と関数と同じ規則（§15.1、§11.2、§6.1）を当てる。遅延は名前空間の API を持たない flow とする。
  - (b) 組込みの名前は呼び出しの呼び先でだけ引き、他の位置では見つからない名前とする（E0302。今の実装）。§11.4 に一文を足し、§5.1 の「見えている束縛」は束縛の重なり（E0304）の意味に限る。
  - (c) 組込みの名前は見つかった名前で、要る種類になるのは自分の呼び出しの形の呼び先だけとする。他の全ての位置（値、`.(` の呼び先、型、経路の頭、パターン、補間の穴、`^` の後）は E0308 で、note で呼び出しの形を示す。

- 他言語: 
  - rustc 1.94.1（`probe/s720/other/m.rs`、edition 2021）: マクロの名前を値に書く `let f = println;` と `1.0 * line` は、どちらも E0423「expected value, found macro `println`」で、ラベルは「not a value」。見つからない名前の E0425「cannot find value」とは分ける。
  - FAUST は手元に無く、動かしていない。文書は `mem` を「1 サンプルの遅延」の基本の部品とし、名前だけで部品として書く（`process = mem;` と `process = _'` が同じ。[Faust の文法の手引きの `mem` の項](https://faustdoc.grame.fr/manual/syntax/)）。名前だけの `prev` を書く書き手がありうることの参考で、FAUST での誤りの出し方は未確認。
