# S-351 範囲のパターンの後の `|` の読み

- 空白: 範囲のパターンの後の `|`（`1..<5 | 7 =>`）の読み。§7 はパターンの `|` を選択とする。`@` の外の `1..<5 | 7` は、リテラルの枝を置き換えないので置き換えた後の枝の形が違い、S-317 で候補なしの E0002（W3-21/t の期待値も E0002）。
  選択の読みの候補を作るのは `@` の右（`n @ (1..<5 | 7)` は `n if (1 <= n && n < 5) || n == 7`）だけ。swiftc 6.3.1 は `1..<(5 | 7)`（ビット和の端）と読み、rustc 1.94.1 は選択と読む。
  読みが言語で割れる形は候補を読みごとに並べる方針（R-124）から、ビット和の端の候補（`n if 1 <= n && n < (5 | 7)`）を二つ目に並べるか。端がリテラルでも起きる（S-341 の端の形とは別の論点）。第 13 組の下書きで見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が (a) を選んだ。Fable と親の推奨、下書きは (b)、第 13 組）: (a)。`@` の右の範囲と値の選択（`n @ (1..<5 | 7)`）の候補は選択の読みの一つ（`n if (1 <= n && n < 5) || n == 7`）だけ。`@` の外の `1..<5 | 7` は今どおり S-317 で候補なしの E0002。`range_pattern_choice` と `at_binding` の E0002 の note に「パターンの `|` は選択で、端のビット和は括弧で書く（`1..<(5 | 7)`）」の一文を足す（データのファイル）。`n @ (1..5 | 7)` は S-249 どおり記号の二つの候補のまま。
  利用者の理由: 直す量の割に利益が薄い。実装は W3-21
