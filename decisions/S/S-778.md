# S-778 誤りの無い相互再帰の `rt fn` の E0903 を、どの単位のどの呼び出しに出すか（`rt fn d` → `c` → `d`、三つ組の循環）

- 空白: §10 の規則 5 は `rt fn` の直接・相互の再帰を E0903 とするだけで、相互再帰の E0903 を循環のどの単位のどの呼び出しに出すか、いくつ出すかを書いていない。§18.1 の宣言をまたぐ循環の段落（E0310・E0311・E0312・E0817 を集まりごとに一つ、位置は集まりの宣言のうち診断の並べ方で最初のものの名前）は E0903 を挙げない。
  今は、循環の中で先に書いた単位の、相手への呼び出しの行に一つ出す（`rt fn d` → `c` → `d` は `d` の `c(…)` の行）。既にある事例 `tests/spec/negative/rt.onsa` の `ping`・`pong` はこの位置に印を付けている（仕様の文から決まった印ではない）。
  再現は `target/notes/83/s778/unit_stage_rt_cycle_clean.onsa`（E0903）。誤りのあるプログラムの報告の位置だけの話で、通るプログラムは変わらない。
- 決定: 決定（2026-11-08、利用者。126 回目）: (1) 今の位置を仕様に書く。`rt` の関数の再帰の E0903 は、§18.1 の宣言をまたぐ循環の段落に入れ、互いに呼び合う関数の集まり（自分を呼ぶ一つの関数を含む）ごとに一つ報告する。
  位置は、集まりの宣言のうち診断の並べ方で最初のものの本体で、集まりの関数を呼ぶ最初の呼び出し（E0310 が `use` を指すのと同じく辺を指す。直すのは呼び出しなので）。note は呼び先の宣言（今の出力。循環の並びは文面にあり、文面は約束にしない）。§18.1 と §10 の規則 5 に書いた。
  （補い: 具体化した呼び出しの循環の E0903 は S-911 が決めていて（§18.1 の降下の診断の段落。位置は循環の中の手で書いた呼び出しのうちソースの順で最初のもの、note は循環の道）、この決定は呼び先が名前で決まる循環に限る。位置の言い方も S-911 に揃え「集まりの関数を呼ぶ呼び出しのうちソースの順で最初のもの」と書いた。名前で決まる循環では最初の宣言の本体の最初の呼び出しと同じ所である。）
  単位をまたぐ扱いを §18.1 の段落に置くので、補いの「§10 の文が §18.1 の P1 の例外と読まれうる」点も §18.1 の側に書かれた。コードは変えない。83 回目に写さなかった誤りの無い循環の事例を、印を付けて `tests/spec/negative/unit_stage_rt_cycle_clean.onsa` に足した（親）。
- 経緯: 83 回目（2026-10-29）、W4-06 U1/t（onsa-test）が仕様の空白（NEW-1）として報告した。誤りの無い循環の対照の事例は印を付けられないので、W4-06 では写していない。関係: S-776、S-761。
- 補い（2026-10-29、親）: 84 回目の文書の点検（onsa-docs）から: §10 の規則 5 の S-776 の文は、誤りの無い単位の E0903 の有無が別の単位の前の段の誤りで決まるとし、§18.1 の「単位どうしは独立に検査し（P1）」の例外と読まれうる（§18.1 が単位をまたぐ扱いを書くのは、誤りのある宣言の段落と宣言をまたぐ循環の段落）。決めるときに、宣言をまたぐ循環の段落に E0903 を足すかと一緒に見る。
- 補い（2026-11-06、親）: 117 回目、S-911 (d) で具体化した呼び出しの循環の E0903 の位置を §18.1 に足した（循環の中の手で書いた呼び出しのうちソースの順で最初のもの）。名前で決まる循環の位置はこの S の範囲に残る。
