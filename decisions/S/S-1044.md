# S-1044 細部: 所有の見出しの腕の入れ子の単位形のパターン（`Some(None) =>`、`o: Option[Option[Buf[F32]]]`）が当たった部分の破棄を、`Alloc` に数えるか

- 空白: §5.4（`spec/05-values.md`）は、所有の見出しが消費した値のうちパターンが束縛しなかった部分（`_`、最後の `_` が残すフィールド、束縛の無い腕の対象）を腕の終わりに破棄する。S-1036 の決定は「腕の残りは当たった列挙子のペイロードの束縛されない部分で、単位形の腕（`None =>`）には無い」とする。入れ子の単位形のパターン（`match move o { Some(None) => None, rest => rest }`、`o: Option[Option[Buf[F32]]]`）で、`Some` のペイロード（当たった内側の `None`）を束縛されない部分として破棄に数えるかが書かれていない。
  今（`c81228b3`）: 誤りにならない（U6 の前は `_` も数えない）。再現は `target/notes/148/w602/u6/nested_unit_c.onsa`。
  読み: (1) 内側の値は束縛されない部分で、型（`Option[Buf[F32]]`）で `Alloc` を要る（`rt fn` で E0901）。(2) S-1036 の単位形の腕の規則をパターンの節ごとに当てる。当たった単位形の列挙子にはペイロードが無いので、残りは無い（`_` の節はその部分値、リテラルの節（`"a"`）はその部分値、最後の `_` は残りのフィールド、単位形の列挙子の節は無し）。
  仮の扱い: (2)（今通るプログラムを変えない。`rules/leader.md` 5.11）。W6-02 U6 の実装はこの形で作る。
  急ぎ: W6 の区切りで確認だけ。
- 決定:
- 経緯: 148 回目（2026-11-14）、W6-02 U6 のテストの担当が仕様の空白（NEW）として挙げた。事例には書いていない（`drop_wild_panic.onsa` の入れ子は `Some(Some(_)) => panic("x")` にした）。関係: S-1036、R-32、U5a2（名前の無い `None: Option[Buf[F32]]` の一時の値は型で数える。値が分からない一時の値と、当たって `None` と分かった腕とは別）。
- 補い（2026-11-14、親）: 148 回目、W6-02 U6 の実装の担当: 定数のパターン（`G =>`、`G: Str`）も、仮の扱い (2) のリテラルの節と同じく、当たった部分値を破棄に数える形で実装した（`modes/flow.rs::discards`）。今は `Str` の定数が E0200 なので事例では確かめられない。W6 の区切りの確認で、節の一覧に定数を足すかを一緒に確かめる。
- 補い（2026-11-14、親）: 148 回目、W6-02 U6 の壊す側が空白の候補に挙げた同じ原理の形: 所有の `match` のガードの中の早い出口（`Some(b) if r? == 1 => …`、`None if r? == 1 => …`）で破棄するのは、その腕のパターンが束縛した部分と束縛しなかった部分だけで、単位形の腕は何も無い（実装の今の扱い。対象の全体を型で破棄する読みは採らない）。前は `Some(_) if r?` が誤りなしで、U6 で E0601 になった（`_` の `Buf` を出口で破棄）。`None if r?` は誤りなし。再現は `target/notes/148/w602/u6/b/hand9.txt`。W6 の区切りの確認で一緒に確かめる。
