# S-450

- 空白: Python と JS の演算子 `**`（べき乗）、`===`・`!==`（厳密な比較）を、既存言語の形の行（`spec/foreign-forms.toml`）にするか。
  W3-04 は字句でこれらを一つのトークンにしたので、今は一般の E0002（`a ** b` は「expected newline or `}`, found `**`」で、前の「expected an expression, found `*`」の手掛かりも無くなった）。`===` → `==`、`!==` → `!=` は候補を作れ、`**` は `pow` の形か候補なしの note。
  どれも 7 章の 32 の一覧の言語の形。W3-04/b が見つけた（2026-10-11）
- 提案: 後の段（次の空白の組）
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1）`===`・`!==`（JS・TS）は E0020 の行 `strict_equality` で、候補は `==`・`!=`。`**`（Python・JS。C・Rust では `a * (*b)` と読めて割れる）は候補を作れず、一般の文面「expected newline」が誤らせるので E0002 の行 `power_operator`（note で浮動小数は `std.math` の `pow`）。`**=` も `**` の行。
  - 仕様の節: 一覧の行だけ（`forms.toml`）。
  - 今通るプログラム: 変わらない（どれも今 E0002）。
  - 実装の見当: `onsa_syntax` の `foreign/rows.rs` に 2 行、二項の位置の `===`・`!==`・`**` のトークンを拾う一致を `foreign/` に一つ（30〜50 行）。
  - ぶつかる事例: なし（`tests/` の `.onsa` に `===`・`**` は無い）。
