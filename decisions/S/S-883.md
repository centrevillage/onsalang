# S-883 `as` で書ける組で宣言の境界にも反する変換の関連関数の呼び出し（`I64.trunc_from(n)`、`n: I32`）のコード

- 空白: S-231 の決定は「変換元と変換先がどちらも具体的な型で `as` で書ける組なら E0413（候補は `as` の形）」で、宣言は `trunc_from[S: Float]`・`trunc_sat_from[S: Float]`・`narrow_from[S: Int]` なので、境界に反する引数は §4.5 の E0416 である。
  `I64.trunc_from(n)`（`n: I32`）は `I32` → `I64` が `as` で書ける組で、`S = I32` は `Float` を満たさないので、二つの規則が同じ呼び出しに当たる。読み: (1) E0413（`as` の組の判定を境界の検査より前に置き、候補は `n as I64`）。(2) E0416（境界の検査が先で、`as` の形の候補は出ない）。
  `as` で書けない組の `I8.trunc_from(n)` はどちらの読みでも E0416。今の形 `n.trunc_i64()` は E0413。どちらの読みでも通るプログラムは変わらない。W5-14 の S1 の判定の順に当たる（S-231 の置き換えの見積もり `target/notes/112/w514s/est_report.md` の NEW-1）
- 決定: 決定（2026-11-04、利用者。112 回目、第 83 組。親の読みと伏せた独立のレビューの段 1 が一致、段 2 は省いた。確認だけ）: (a1)。`as` で書ける組の判定は、宣言の境界（§4.5）と返り値の型の検査より前に行う。`I64.trunc_from(n)`（`n: I32`）は E0413 で候補は `n as I64`、同じ型の `I32.trunc_from(n)` は E0413 で候補は呼び出しを外す形。`as` で書けない組の `I8.trunc_from(n)` は E0416。仕様 §3.3（反映は S-231 と同じコミット、W5-14 の S2）
- 経緯: 112 回目（2026-11-04）、W5-14 の S-231 の置き換えの見積もり（読むだけの実装の担当）が NEW として挙げ、親が固定のバイナリと利用者の `impl` の近似で再現した。要約と段 1 は `target/notes/112/g83/`。関係: S-231、S-875、S-880、S-236
