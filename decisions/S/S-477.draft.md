# S-477 `lib` の無い extern のブロック

- 族の規則: S-593 の規則から決まる（`S-593.draft.md` の表 1 の 20〜24 行。論点・今の実装・案・他言語・影響は S-593 の下書きにある）。
- 推奨と理由: S-593 の規則から（下書きの推奨は S-593 の (b)）。表 1 の 20〜22 行。extern の見出しが `{` の前で読めず、`{` が同じ行にあるとき、`extern` から `{` の前までを一つの E0002 にする（ライブラリの名前は書き手しか知らないので候補なし。note で `extern "C" lib "…" {` の形を示す）。
  メンバを読み、ライブラリは未知。impl の見出しの誤りと同じく、ブロックは一つの単位でメンバは検査しない。21 行は二つの E0002 で 2 周（S-464 の `unsafe extern "C" fn` と同じ）。24 行は改行の形で読み続けない。
  確度は低: 今は E0200 のブロックのメンバが名前解決に見えないので、使う所の出力は変わらず、効くのは extern のブロックを実装した後である。構文の部分を W5-11 で入れるか、extern のブロックを実装する作業に回すかは、作業量で決めてよい（CST の事例では W5-11 でも確かめられる）。
- 独立のレビュー（2026-10-23、助言の担当の二段）: 一致（読み続け、`extern` から `{` の前までを一つの E0002、ライブラリは未知。`unsafe extern "C" {` は 2 周、改行の形は読み続けない。実装は W5-11、詰まれば extern のブロックの作業へ）。
  段 2 の補い: 22 行（`extern {` など）では ABI も読めないので、`ExternDecl::abi`・`lib` を両方 `Option<StrLit>` にする。決定の文に「使う所の出力が変わるのは R-246 と extern のブロックの実装の後」と書く。
- 回答（2026-10-23、会話で利用者。55 回目）: 読み続け、`extern` から `{` の前までを一つの E0002、ABI とライブラリは読めなければ未知（`ExternDecl::abi`・`lib` を `Option`）。使う所の出力が変わるのは R-246 と extern のブロックの実装の後。了承（(A)）。
