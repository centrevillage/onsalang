# S-420 `pub struct` のフィールドの `pub(crate)` と `pub(pkg)`

- 空白: `pub struct` のフィールドに書いた `pub(crate)`（`pub struct P { pub(crate) x: I32 }`）。`pub_crate` の E0020 の候補（可視性を外す形）を当てると、フィールドは struct の `pub` を継ぎ、パッケージの外へ公開される（検査は通る）。
  §15.1 は「`pub struct` のフィールドをパッケージ内に限る書き方は無い。必要なら `priv` にして、作る関数と読む関数を無指定で置く」とし、S-36 の決定はフィールドの位置を書かない。書き手の意図（パッケージ内に限る）と逆に広げる候補になる。候補を出さない E0002 と note か、`priv` にする候補か。
  第 23 組の下書きの付録で見つけた（2026-10-10。親が dev の `afbfd25` で、外した後の `pub struct P { x: I32 }` が通ることを確かめた）
- 提案: 決定（2026-10-11、利用者が ID を挙げて推奨の (b) を了承。下書きと Fable が一致、第 24 組）: `pub struct` のフィールドの位置の `pub(crate)`・`pub(pkg)` だけ、候補の無い E0002 の行（例: `field_pub_crate`）で、note は「フィールドは struct の可視性を継ぐ。`pub struct` のフィールドをパッケージの中に限る書き方は無い。モジュールの中に限るなら `priv` にして作る関数と読む関数を無指定で置き、外へ出してよければ外す」。
  空白を挟んでも一つの誤り（S-412）。他の位置（項目、無指定と `priv` の struct のフィールド、`use`）は今の E0020 と外す候補のまま。`pub_crate` の文面「which is the default」は「外すと、その位置の既定の可視性になる」の趣旨に改める（文面は約束しない）。仕様 §15.1。実装は W3-08（`pub_pkg` と同じ回）
