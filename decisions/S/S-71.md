# S-71

- 空白: Option / Result が組込みの型で、sema と Core の約 60 か所が特別扱いしている。Option を返すプリミティブは、インタプリタと C が列挙子の番号（Some = 1、None = 0）と配置を直書きしている。`let o = Some(1.5)` は通るが、同じ形の利用者の総称の enum（`let m = Maybe.Just(1.5)`）は E0406 になる（レビュー R-79、R-53）
- 提案: Option / Result を std の enum として宣言する（§4.1）。コンパイラは lang item の表（std の経路 → 役割）の 2 行で知り、使い道は prelude（`use` なしで見え、列挙子を修飾なしで書ける）と `?` に限る。
  sema は `?` ごとに早期に返る列挙子の番号を決めて Core に渡し、Core の `TypeDef` に種別を持たせない。
  std の `target` 宣言の引数と返り値に Option / Result を使わず、Option を返すメソッドは std に Onsa で書く（D-07 の追記）。`tests/review-phase1/parent/r79_enum.onsa` の期待値は先頭のコメント（2026-10-04 決定。実装は第 4 段、R-53 を直した後）
- 時期: M2
