# S-346

- 空白: E0010 の読みの一部だけが候補にできないとき（比較の連鎖の中央が二度評価される読み、入れ子の上限を超える読み）の扱い。できる読みだけを並べて、できない読みを note で示すか、全てを落とすか。W3-07 の実装は、中央の条件では全てを落とし、入れ子の上限ではその読みだけを黙って落とす（`SPEC-GAP(S-346)`）。W3-07/b で見つけた（2026-10-09）
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R6）E0010 の読みのうち候補にできない読み（中央の被演算子が 2 回評価される比較の連鎖、括弧を足すと入れ子の上限を超える読み）は候補から外し、その書き方を note で示し、他の読みは候補に並べる。`a < b & h < c` は候補 `(a < b) & (h < c)` の一つと、`a < (b & h) < c` を `let` で書く note。
  - 仕様の節: §18.1 の E0010 の候補の段落（親が置く文、3）。
  - 今通るプログラムが変わるか: 変わらない。報告と候補だけ（今は中央の条件で全ての候補を落とし、上限を超える読みは黙って落とす。`a < b & h < c` は今は候補なし）。
  - 実装の見当: `onsa_syntax/src/groups.rs` の `Flat::e0010`（約 500〜535 行）: `TwiceEvaluated` で `candidates.clear(); break` をやめてその読みだけ飛ばし、note は候補があっても付ける（`with_rule` の条件を外す）。約 10 行と単体テスト。
  - ぶつかる既存の事例: `crates/onsa_syntax/src/groups.rs`の単体テスト `assert!(c("a < x & b < c").is_empty())`（候補 `(a < x) & (b < c)` が一つになる）。`tests/spec/fixes/e0010_nesting_boundary.onsa` の `three_ops_one_fits` に note が付く（`//~ E0010` と `fixes = 2` は変わらない）。
