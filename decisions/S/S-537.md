# S-537 ブロックに似た式が演算子の被演算子になるときの読み

- 空白: `if`・`match`・無名関数・ブロック式などが二項演算子・前置・後置の被演算子になるときの強さ。仕様 §3.1 の強さの順（後置 > 前置 > `as` と `at` > 二項演算子の群 > 範囲の記号）にこれらが無い。
  今の構文解析は `let a = if c { 1 } else { 2 } + 10` を `(if …) + 10` と読み（構文の段の診断なし。`f(true)` は 11、親が `onsa test` で確かめた）、`-if c { 1 } else { 2 }` も通す。(a) 被演算子の位置のこれらを囲む括弧を fmt が外すか（S-339 の基準の字義では外せる）。
  (b) 括弧の無い形を受理するか（`else` の分岐を `2 + 10` と読む読み手がいる。P2 の「読み手に別の読み方を与えうる書き方は検査で落とす」に当たるか）。W3-12/t（U2）が見つけた（2026-10-15）
- 提案: 決定（2026-10-15、利用者が推奨の (b2) を了承。下書きと Fable が一致、第 32 組）: 被演算子の位置（二項の左右、前置の被演算子、後置の受け手、`as` / `at` の左）に括弧なしで置いた `if`・`if~`・`match`・`match~`・ブロック式・無名関数・`unsafe`・`handle`・`par` は、構文の段の新しい誤り E0013 とする（式の単位で一つ。候補は被演算子の位置にある全てを括弧で囲む一つの形）。
  文・`let` の右・引数・範囲の端などの全体の位置は今のまま。fmt は被演算子の位置の括弧を残す。腕の並びの `{ 1 } - 1 =>` は §2.5 の先読みで E0002 のまま。仕様の文と登録簿・計画 §5・実装待ちの一覧は、実装の作業（W3-13）で揃える。
  補い（2026-10-15、W3-13 の始めに親が論点 J-1〜J-4 を示し、利用者が了承）: ブロックに似た式はブロックを持つ式の全てで、9 つの閉じた一覧（`while`・`for` は文）。後置の受け手にタプルの添字 `.0` を含める（J-1）。
  他の診断の修正候補が当てた形でブロックに似た式を被演算子の位置に置くときは、その式を括弧で囲む編集を含める（一般の規則で、仕様には例だけを挙げる。行頭の演算子のつなぎ、行頭の `- b`・`^ b` のつなぎ、関数値の `.(` の挿入、後置の記号の前の空白の除去、複合代入の書き出しなど、W3-13/i が 10 種類の作り手を見つけた。J-2。候補は一か所で当てて読み直し、E0013 と同じ歩きで括弧を足し、当てた形を確かめて残れば出さない（設計の条件は利用者が停止と収束の保証を求めて了承）。主の範囲は、式の中で最初の括弧の無いブロックに似た被演算子（J-4。`as` / `at` の連鎖の E0011 と同じ形）。U1・U2 にテストの票を置く（J-3）。補い（2026-10-16、W3-13/b の後に親が論点を示し、利用者が了承）: 囲むのは、候補が書き換える文字を含む式（端で接するだけは含まない）の中の全てのブロックに似た被演算子で、元からある被演算子も囲む（D-2 の (丙)。E0010 の候補の題は読みのままで、足した括弧を書かない）。確かめて落とすのは括弧を足した候補だけで、全ての候補を当てた形で確かめる形は採らない（D-1 の (ii)。単位の後ろの隠れた誤りが見えるだけの正しい候補まで落とすため。まれな形のために複雑さを足さない）
