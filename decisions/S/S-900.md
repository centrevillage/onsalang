# S-900 `PartialOrd` が `PartialEq` を含むか（`T: PartialOrd` の `==`、`struct P: PartialOrd` の derive）

- 空白: §6.3 と §6.4 が上位の trait として挙げるのは `Ord: PartialOrd + Eq` と `Eq: PartialEq` だけで、`PartialOrd` の上位は書かれていない。
  今の実装は `PartialOrd` が `PartialEq` を含むとする（前からで、W5-05 U1 で `traits.rs` の `SUPERS` の行になった）ので、`T: PartialOrd` の値に `==` が通り、`struct P: PartialOrd` の derive は `PartialEq` 無しで通る。`PartialEq` を持たない型で `==` が走る。
  再現は `target/notes/116/w505/probe/s900_partial_ord.onsa`。
  読み: `PartialOrd` は `PartialEq` を含む（§6.3 の「`PartialOrd` の大小は `==` と矛盾しない」は `==` があることを前提に読める）、含まない（`T: PartialOrd` では `==` を使えず、derive は `PartialEq` を要さない）。
  急ぎ: W5-06 の前（derive の前提を見る作業）。W5-05 は止めず、今の挙動を `SPEC-GAP(S-900)` で保つ。
- 決定: 決定（2026-11-06、利用者。117 回目）: `PartialOrd` の上位の trait は `PartialEq` である（`pub trait PartialOrd: PartialEq`）。`T: PartialOrd` の本体で `==` が使える。
  derive の一覧は、並べた trait と、型がまだ満たしていない上位の trait を生成する（`struct P: Ord` は `PartialEq`・`Eq`・`PartialOrd`・`Ord` を実装し、`struct P: PartialOrd` の `==` も通る）。上位まで並べた一覧も受理し、fmt は揃えない（境界の含意で重なる形と同じ。S-747 の A4）。フィールドの検査は生成する全ての trait に当たる。
  `onsa interface` は補った後の全ての trait を §6.4 の一覧の順で表示する。R-35 のうち「`Ord` だけの一覧は誤り」を改める。
- 経緯: 117 回目（2026-11-05〜06）、親の中立の要約から独立のレビューを 2 回行った（`target/notes/117/s900-advisor/`・`s900-advisor2/`）。案は (a) 書き手が上位も全て書く、(b) 別々の trait、(c) 今のまま、(d) `PartialOrd` だけ補う、(e) 全ての上位を補う（上位まで書いた一覧を (e1) 残す、(e2) fmt が消す、(e3) E0020）である。
  (b) はタプルと derive の辞書式の「最初の等しくない要素の組」が要素の `==` を要するので、別の条件を足すか R-119 の NaN の規則を変えることになる。(c) は §6.3 の演算子の規則に例外を作る。(d) は `Eq`・`Ord` と扱いが分かれる。(e2) は fmt に trait の関係の表を持ち込み、(e3) は全てを書く書き手を毎回止める。
  レビューは 2 回とも (a) で、親も (a) を勧めた。利用者が「境界の形と、境界を通すために実装する形が異なる。境界を指定する方は上位の知識を結局持っている」と指摘した。親が確かめて推奨を (e1) に改めた: §6.4 は derive を境界と同じ読みと定める。上位の知識は `T: Ord` を読むのに既に要る。境界の側に同じ二通りの綴りがある（§4.5、S-747 の A4）。
  (a) の「満たさなければ E0416」が「満たさなければ生成する」に置き換わるだけで、規則の文は増えない。
- 補い（2026-11-05、親）: 117 回目、W5-21 の候補は `SUPERS` の `SPEC-GAP(S-900)` に頼る: `T: PartialEq` の `<` の候補は `PartialEq` を `PartialOrd` に置き換える。含まないと決めるなら、この置き換えを `+` で足す形に変える。
