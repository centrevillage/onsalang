# S-948 閉じない括弧の報告で「閉じていない」括弧をどう決めるか（字下げを括弧の組に読むか）

- 空白: §18.1 の第 92 組の文は「閉じていない括弧のうち最も内」とした。括弧を順に組にすると、`impl P {` / `  fn a(self) {` / `    1` / 空行 / `  fn b(self) {}` / `}` では `a` の `{` が閉じ、`impl` の `{` が閉じていないことになるが、書き手が忘れたのは `a` の `}` で、今の報告も `a` の `{` を指す。
  逆に `impl S {` が閉じず、閉じたメンバ `m` の本体に字下げの低い `@fp(relaxed) let` がある形では、U3 の実装が閉じている `m` の `{` を指して偽の連鎖を出す（`target/notes/122/u3b/cl1.onsa`）。
  案: (A) 閉じない `{` のあるファイルでだけ、`}` の行が `{` の行より浅い組を閉じていないと数える（約 +31 行、規則 1）。(B) 順の組だけで決める（`a` の例が的外れの 2 件になる）。(C) 止まった位置で開いている最も内の括弧を指す（規則 0、約 −31 行。`m` の例は外れる）。
- 決定: 決定（2026-11-07、利用者。122 回目）: (C)。止まった位置で開いている括弧のうち最も内のものを指し、他の開いている括弧を note で示す。§18.1 の文を改めた。止まるかの判定は今のまま「閉じない `{` があるファイルで、開いた行と同じか浅い行」である。括弧の組は字句の順だけで決め、字下げを読まない。
  字下げで判定を分けるのは §18.1 の回復の止まる位置だけで（§2.5）、(A) は括弧の組の読み替えという二つ目の使い道になる。`m` の例の偽の連鎖は残す（`impl` の `}` を忘れ、かつ閉じたメンバの本体に字下げの低い項目の語がある形だけで、誤りは報告される）。
- 経緯: 122 回目（2026-11-07）、W5-11 U3b の実装の担当が (A) を `SPEC-GAP(NEW)` で足して報告した。利用者は既にある判定の字下げの使い道を確かめて (C) を選んだ。
