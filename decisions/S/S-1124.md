# S-1124 `@export` の flow の `init` の入力に出せる型（§14.2 に無い。struct の `init` の入力は `check` が通り、C のビルドがファイルの頭の E0200）

- 空白: §14.2 は `<p>_config` が `init` の入力をフィールドに持つとするが、フィールドに出せる型と C の型への写し方を書かない（§14.1 の FFI の型の一覧は export する関数の引数の話）。今は `@export` の flow の struct の `init` の入力（`c: C at init`）が `onsa check` を通り、`onsa build --target host` がファイルの頭（1:1、R-138）の E0200「the C backend does not support the `init` input `c` of a non-scalar type in an export in this version」を出す。`block` の入力は `@param`（一覧の型）か `@host` が必須なので決まっている。
  読みは (1) スカラだけ（他は宣言の位置の E0810 を `check` で）、(2) §14.1 の `@repr(c)` の struct なども認め、C の型の写し方を決める、(3) この版は E0200 のまま位置だけ宣言に直す、に割れる。S-640（export する関数のシグネチャの型）と同じ族。再現は `target/notes/163/g109/advisor/probe/a5.txt` の `q06`（親がパッケージを作って build の E0200 を確かめた）。
  急ぎ: S-640 と同じ（W10-01 の前）。
