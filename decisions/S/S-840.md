# S-840 msvc のホスト（Windows）の `kind = "staticlib"`: `.a` を作らず、note が「ホストでない」と食い違う（§15.3 の「ホストでは PATH の `cc` と `ar`」）

- 空白: §15.3 は「ホストの `platform` では PATH の `cc` と `ar` を使う」と書くが、ホストが msvc（Windows）で `cc` と `ar` が無い・使わないときの `staticlib` を書かない。
  今の実装（`crates/onsa_driver/src/build.rs` の `host_triple` と `staticlib` の所、`8ed85a0e`）は、Windows のホストで `"host"` を `x86_64-pc-windows-msvc` に置き換え、ホストと判定する（S-837 の後もホスト）が、`is_host() && !msvc` が偽なので `cc` を呼ばず、`.a` を作らずに終了コード 0 で終わる。
  そのときの note は「sources only: `x86_64-pc-windows-msvc` is not the host (x86_64-pc-windows-msvc); compile with: cc /fp:strict … -c …」で、ホストなのに「ホストでない」と言い、msvc のフラグを `cc` に渡す形を示す。98 回目に親がコードを読んで確かめた（この機械は macOS で、動かしてはいない）。
  読みは (1) msvc のホストの `staticlib` は E0200（この版は msvc のツールチェーンを呼ばない、note で `kind = "source"`） (2) C のソースだけを書き、note を「ホストだがこの版は msvc で `.a` を作らない」に直す (3) `cl` と `lib` を呼んで `.lib` を作る、に割れる。

- 経緯: 98 回目（2026-11-01）、S-837 の助言の担当の段 1（想定漏れの表）が見つけ、利用者が別の S にすることを了承した。
