# S-908 flow が生成する型（`g.Params`、`g.State`）が derive できる trait を持つか

- 空白: §11.6 は `voice.Params` を「block の入力をフィールドに持つ struct（Copy）」と書き、trait を持つかを書かない。§6.3 の表は閉じた一覧で、生成された型は載っていない。今の実装はどの trait も持たない読みで、`g.Params == g.Params` は前から E0401、W5-06 U1 から `struct S: Eq { p: g.Params }` は E0416 になる（前は検査が無く通った）。
  読み: (1) どの trait も持たない（今の実装）。(2) `Params` は入力のフィールドから `PartialEq` などを構造で持つ。
- 決定: 決定（2026-11-12、利用者「advisor の提案通りで良い」。140 回目。親の意見を伏せた onsa-advisor の段 1（`target/notes/140/b3-advisor/`）が親と同じ (1) を選び、段 2 は省いた）: (1)。flow が生成する型（`g.Params`・`g.Config`・`g.State` など）は、derive の並びの無い宣言と同じく標準 trait と演算子 trait を実装しない（`p == q` は E0401、`struct S: PartialEq { p: g.Params }` は E0416）。要るときは同じモジュールに手で `impl` を書く（この版で書けるのは `impl Default` だけで、`impl Default for g.Params` は今通る）。比べるには、フィールドで比べるか補助のメソッド（`impl g.Params { pub rt fn same(self, o: g.Params) -> Bool { … } }`）を書く。構造で trait を持たせる (2)・`PartialEq` だけの (3) は、生成された型だけの trait の一覧という規則を足し、`PartialEq` の無い block の入力を足すと `Params` が黙って trait を失って離れた使う側が止まり、構造の `Default`（0）は `@param` の `default` と食い違い手書きの `impl Default` と衝突するので採らない。後で開くなら「手書きがあれば生成しない」形にすれば今のプログラムは止まらない。生成された型に trait を求めた E0401・E0416 に、生成された型は trait を持たず、フィールドで比べるか補助のメソッドを書くことを示す note を足す（W5-13、8〜12 行の見当）。§11.6 に足した。
- 経緯: 117 回目（2026-11-06）、W5-06 U1/b（onsa-break）が仕様の空白として挙げた。急ぎは後の段で、S-782 と同じ区切りで出す。再現は `struct S1: Eq { p: g.Params }`（`pub flow g` は `@param` の block の入力を持つ）。
