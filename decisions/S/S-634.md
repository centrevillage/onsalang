# S-634 上の階層か子のディレクトリの `onsa.toml` が、壊れたリンク・ディレクトリ・FIFO のとき

- 空白: §15.1 は「`onsa.toml` はリンクでも、リンク先をマニフェストとして読む（集める項目ではない）。上へ探すときも、入れ子のパッケージを見分けるとき（子のディレクトリの `onsa.toml`）も同じである」とし、リンク先が無いか読めないときの扱い（入出力の誤り）は経路として渡した `onsa.toml` にだけ書く。
  上へ探して見つけた `onsa.toml` と子のディレクトリの `onsa.toml` が、壊れたリンク・ディレクトリ・FIFO のとき（`ln -s nowhere pkg/sub/onsa.toml`）の扱いが書かれていない。
  読みは (1) その名前の項目があれば `onsa.toml` があるとみなす（上へ探すときは読んで 2、子のディレクトリなら入れ子とみなして降りない）、(2) 読めるマニフェストでなければ無いとみなす（上へはさらに探し、子のディレクトリには降りる）、(3) 子のディレクトリでも 2、に割れる。
- 決定:
- 経緯: 60 回目（2026-10-24）、W4-14 U1 の実装の設計メモ（onsa-impl）の 5 章の 2 から。W4-14 は (1) を仮の扱いにする（W4-01 の `std_tree.rs` と同じ）。
  同じ回の W4-14 U1 のテストの票（onsa-test）も同じ空白を報告した（`ln -s nowhere.toml g/onsa.toml` の `onsa check g/a.onsa` は今 0、`onsa check g` は今 2）。期待値は経路で渡した壊れたリンクの `onsa.toml`（2）だけに書いた。
