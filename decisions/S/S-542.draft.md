# S-542 組込みの遅延と同じ名前のモジュールの項目と `use` の名前

- 決定済みで戻さないもの: flow の入力と本体の `let` は、組込みの名前（`prev` `delay` `vdelay` `sample_rate` `sample_tick`）で隠せない（E0304。§11.6 の「組込みの名前…も、入力や `let` で隠せない」、R-48。実装は W7-03）。
  今は `let prev = x`（r06、u03）と入力の `sample_rate`（r09、u04）が通る。
- 論点: 仕様 §2.2「`prev` `delay` `vdelay`（組込みの遅延の flow）と `sample_rate`・`sample_tick` は、flow の中で予約された組込み名（§11.4）」、§11.4「後から組込み名を足すと、その名前を使っていたプログラムが壊れる」。
  §5.1「見えている束縛には、モジュールの項目、`use` で取り込んだ名前、prelude、組込み型も含む」「一つの名前は、見える範囲で常に一つのものを指す」。
  書かれていないのは、同じ名前のモジュールの項目（`flow prev`、`fn sample_rate`、`fn delay`）と `use` で取り込む名前を宣言できるか、宣言できるなら flow の本体の中でどちらを指すか、である。flow の本体はモジュールの項目を見るので、同じ名前が二つのものを指しうる。

  | 行 | 形 | 例 | 今の実装 |
  |---|---|---|---|
  | 1 | flow の宣言 | `pub flow prev(…)` | 通る（r01）。flow の本体の `prev~(x)` は組込みを指し（t01 の値が 1 刻みの遅延）、外の `prev.render(…)` は利用者の flow（t02） |
  | 2 | fn の宣言 | `pub fn sample_rate() -> F32` | 通る。fn の本体の `sample_rate()` は利用者の fn（r03）、flow の本体では組込み（t03 の値） |
  | 3 | 同じ名前の fn を flow の本体で呼ぶ | `fn delay(x: F32, n: U32)` と flow の `delay(x, 4)` | E0811「`delay` is a built-in delay」と `~` を足す候補。当てると組込みの `delay~(x, 4)` になって通り、利用者の fn を呼ばない（u06、m02） |
  | 4 | `use` で取り込む名前 | `use util.{prev}` | 通り、flow の本体の `prev~(x)` は組込みを指す（`target/notes/55/gap40/probe/pk2`） |
  | 5 | flow の本体の束縛 | `let prev = x`、入力の `sample_rate` | 決定済み（E0304、R-48）。今は通り、本体の `prev~(prev)` は E0812（u03）、`sample_rate()` は E0401（u04） |
  | 6 | fn の本体の束縛と引数 | `fn coef(fc: F32, sample_rate: F32)`、`let delay = x` | 通る（r07、r08、u05）。fn の本体は組込みの名前を見ない（`sample_rate()` は E0302、u01）。§11.6 の生成する API も `init(cfg, sample_rate: F32)` の引数に使う |
  | 7 | フィールドとメソッド | `s.delay`、`fn delay(self)` | 通る（r10、r11）。`.` の後の名前で、束縛でない |
  | 8 | 定数 | `const delay` | E0320（定数は `UPPER_SNAKE`、r05）。命名で重ならない |
  | 9 | モジュールのファイル | `dsp/delay.onsa` と `use dsp.delay`・`use dsp.delay.{echo}` | 書かれていない |

- 案:
  - (a) flow の本体から見える全ての束縛に使えない。モジュールの項目（flow、fn、handler）と `use` で取り込む名前に組込みの名前を使うと E0304（§5.1 の prelude と同じ扱い）。flow の本体の束縛は決定済み（5 行）。
    fn の本体の束縛と引数（6 行）、フィールドとメソッド（7 行）、モジュールのファイルの名前（9 行。`use dsp.delay.{echo}` の経路の要素）は書ける。モジュールをその名前に束縛する `use dsp.delay` は E0304。
    実装: 名前の段の項目の収集と `use` の束縛で、登録簿の組込みの名前と比べる（10〜20 行。W4-03 か W4-04）。事例: E0304 の否定例 3 件（flow、fn、`use`）。候補なし（他の E0304 と同じ）で、note で予約の理由を示す。
    費用の要因: 組込みの名前を足すと、その名前の項目を持つ利用者のプログラムが E0304 になる（§11.4 の文のとおり）。
  - (b) flow の宣言だけを E0304 にする（S-542 の字面）。fn・handler・`use` は今のまま（flow の外で使え、flow の本体では組込みを指す）。実装: 5〜10 行。
    費用の要因: 3 行の候補が利用者の fn を組込みの遅延に置き換え、黙って意味を変える。直すには E0811 の候補に「同じ名前の項目があれば出さない」を足す（5〜10 行）。
  - (c) 今のまま受理し、§2.2 に「flow の本体の中では、この名前は常に組込みを指し、同じ名前の項目は flow の本体から指せない」と書く。実装: (b) と同じ E0811 の直しだけ。
    費用の要因: 一つの名前が flow の本体の中と外で別のものを指し、§5.1 の原則の例外になる。後から組込みの名前を足すと、その名前の項目を flow の本体で使っていたプログラムが、誤りにならずに組込みを指すように変わる。
- 他言語:
  - rustc 1.94.1（手元、`shadow.rs`）: `fn drop(x: i32)` は prelude の `drop` を黙って隠し、`drop(1)` は利用者の関数を呼ぶ。Python 3.14.5（手元、`shadow.py`）: `def print` と `len = 3` は組込みを黙って隠す。
  - どちらも隠蔽を許す言語で、隠蔽の無い Onsa（§5.1）とは前提が違う。Swift・TypeScript: 未確認。
- 推奨と理由: (a)。確度: 中〜高。
  - §5.1 の「一つの名前は、見える範囲で常に一つのものを指す」を flow の本体に当てると、組込みの名前と同じ名前の項目は本体から見えて衝突する。flow の本体の束縛を禁じる決定（R-48）と同じ理由で、本体から見えるモジュールの項目と `use` の名前も禁じれば、規則は「flow の本体から見える束縛」の一つになる。
  - §11.4 の「後から組込み名を足すと、その名前を使っていたプログラムが壊れる」は、組込みの名前を項目に使えないことを前提にしている。(a) では壊れ方が E0304 として見える。(c) では、使っていたプログラムが黙って組込みを指すように変わる。
  - 今の誤った候補が消える。3 行の E0811 の候補は、利用者の fn を組込みの遅延に置き換えて通す。(a) では宣言が E0304 になり、この候補は出ない。(b) と (c) は E0811 の候補に例外を足す。
  - fn の本体の束縛と引数を残すので、`sample_rate` を引数にする普通の関数（u05）と、§11.6 の生成する API の引数は変わらない。fn の本体は組込みの名前を見ないので、衝突が無い。
  - 実装が小さく、組込みの名前は登録簿の一覧の一か所で決まる（名前を足すときも一覧の一行で済む）。
  - あわせて決めること: flow の本体のパターンの束縛（`match` の腕の `Some(prev)`）も、R-48 の「入力や `let`」と同じく E0304 にする（§11.6 の文を「入力と本体の束縛」と読む）。
  - あわせて決めること: モジュールのファイルの名前（`delay.onsa`）は書けて、経路の要素として使える。その名前を束縛する `use dsp.delay` だけが E0304。第 39 組の S-443（取り込む名前がキーワード・予約語）とは別の一覧で、どちらの答えとも食い違わない。
  - あわせて決めること: 主の位置は宣言の名前（`use` では取り込む名前）で、note で「flow の本体の組込みの名前（§11.4）は、項目と `use` の名前にも使えない」と示す。候補は出さない（E0304 の他の形と同じ。名前は書き手が選ぶ）。
- 影響: 仕様 §2.2（予約の範囲の一文）、§5.1（(a) は見えている束縛に flow の組込みの名前を加える）、§11.6（(a) はパターンの束縛を含める）。(c) は §2.2 に指す先の一文。診断のコード: E0304 の当てはめで、新しいコードは無い。
  作業: (a) は W4-04（名前の隠蔽の E0304、S-79 と同じ回）か W4-03（項目の収集）。flow の本体の束縛は W7-03（R-48）のまま。(b)・(c) は E0811 の候補の直し（W4-12）。

  - 段 1 の補い: `use` でモジュールそのものを組込みの名前に束縛する形（`use dsp.delay`、S-594 の回答で開いた `use kp` の形）も E0304。ファイル名は束縛でないので規則の外。`s.delay`・`fn delay(self)`・fn の引数とローカルは書ける。§2.2 の「flow の中で予約された組込み名」は「flow の本体で引ける組込みの名前で、見えている束縛として隠せない」に言い直す。

- 回答（2026-10-23、会話で利用者。55 回目）: (a) に版の一文を足す形。flow の本体から見える全ての束縛（項目・`use`・入力・`let`・パターン）で組込みの名前は E0304（独立のレビューの補いの `use dsp.delay` も含む）。
  - 利用者の懸念: 組込みの名前はキーワードと違って版で増減しやすく、増えたときに利用者の flow や fn を壊さない回避策が要る。
  - 親が確かめた今の手当て: §11.4「flow の中の組込み名は…だけである。…後から組込み名を足すと、その名前を使っていたプログラムが壊れる」で、新しい機能は std の flow に置く（§11.11 のイベントの変換）。prelude も隠せず、後から足すと壊れるので std に置く（§11.11、§15.1）。
  - 足す一文（§11.4）: 組込みの名前と prelude を足すのは版（マニフェストの `edition`）の変わり目だけで、古い版のパッケージでは足した名前を予約しない。版の仕組みは足すときに入れる（今は 0 行）。
  - 退けた案 (a'): 利用者の項目と `use` の名前が組込みを隠してよい形。壊れないが、隠したモジュールでは組込みを使えず、prelude（隠せない）と扱いが分かれる。
