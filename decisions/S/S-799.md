# S-799 引数に置いたブロック式の中の代入（`fn2(b, { o = None\n 1 })`、`b` は `o` から派生した借用束縛）

- 空白: §3.5 の 161 行は「代入は文なので引数の中に現れず」とするが、引数にブロック式を書けば、その中に代入を書ける。S-193 は他の引数の中の `inout` と `!` を E0702 の窓（引数の評価の始まりから呼び出しの終わりまで）に入れるが、引数の中のブロックの代入に触れない。
  `match o { Some(b) => fn2(b, { o = None
 1 }), None => 0 }`（`b` は `o` から派生した借用束縛）は、dev（`9804880`）でも W4-07 U3b の新しい modes でも通る。呼び出しの前に `o` の記憶域が破棄され、`b` が破棄済みの記憶域を指しうる。再現は `target/notes/87/s796/p2_pass.onsa` の `blk`。
  読み: (1) S-193 の「他の引数の中の変更」に、引数の中のブロックの代入（と `inout`・`!`）を含めて E0702（窓は同じ）。(2) §3.5 の 161 行を改め、引数の中の代入は §7 の変更として左から数える（後の引数と呼び出しの借用の引数で E0704）。
  急ぎ: W4-08（場所の重なりの関数、S-193）の前。
- 決定: 決定（2026-10-30、利用者。90 回目。独立のレビュー（onsa-advisor の段 1、想定漏れの表 約 35 形）と親の読みが一致し、段 1 が変更の種類を `move` まで広げた）: (1)。
  呼び出しの引数（レシーバを含む）の評価の間に起きる変更は §7 と同じ四つ（代入、`inout` への受け渡し、`!` の呼び出し、`move`）で、引数に置いたブロック式・`if`・`match` の腕の中の文と、入れ子の呼び出しの引数を含む。その場所が同じ呼び出しの他の引数の場所と重なれば、引数の順によらず E0702（S-193 の「変更」の一覧の訂正で、規則は増えない）。
  変更が実行されない道（`if` の片方の腕、ループの本体、`&&` の右辺）にあっても数える。引数の中のブロックで宣言した変数への代入は、どの引数とも重ならない。違うフィールドへの代入と、値を作るだけの引数（`fcopy(b.len(), { o = None … })`）も重ならない。
  Copy の `var` を借用の引数に渡し、他の引数で代入する形（`fcopy(m, { m = 5 … })`）も E0702（利用者が了承。C の出力は引数を先に写すので害は無いが、§3.5 の理由と `io_move(inout n, n)` に揃える）。
  引数の中の文の変更は、書いた位置で §7 の変更として効く（後の引数で値を作るだけの `b.len()` は E0704）。
  診断は E0702 で、位置は後に書いた方、note は先に書いた方と束縛の位置。修正候補は無い（ブロックを呼び出しの前に出すと、値が変わるか E0704 が残る）。同じ位置の §7 の E0704 は出さない。仕様 §3.5（161 行）、§5.2（69 行の後）、§7（57 行）。
  担う作業: W4-08（S-193 と同じ、引数の評価の間の変更を集めて他の引数と重ねる仕組み。今は通る入れ子の呼び出しの直接の `move`（`fn2(x, take(move x, 0))`）を含む）。W4-10 の事例に、ガードの中のブロックの変更（`Some(b) if { o = None … true } => …`）を入れる。
