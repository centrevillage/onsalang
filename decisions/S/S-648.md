# S-648 字面で種類を決める所（`[…]` の並び、パターンの束縛）の `_` で始まる名前（`[_e]` は型パラメータか効果行変数か、`let _x = 1` は束縛か）

- 空白: §2.3 は「大文字と小文字で種別を決める（上の表）」とし、型パラメータと効果行変数は同じ `[…]` に並ぶ（§8.1 の `fn map[T, U, e](…)`）。`_` で始まる名前（`[_e]`）は先頭の字に大文字・小文字が無く、どちらと読むかが書かれていない。値の名前の `snake_case` は `_unused` の形を受ける。
  今の実装（dev `fdc4fa5`）の構文解析器は先頭が小文字なら効果行変数、他は型パラメータと読む（`crates/onsa_syntax/src/parser/signatures.rs` 106 行）ので、`fn f[T, _e](g: fn(T) -> T uses {_e}, x: T) -> T uses {_e} { g(x) }` の `_e` は型パラメータで E0320、候補は `E`（候補を当てると種類が変わる）。
  入力は `P62/gap52/probe/names2/ev6.onsa`（62 回目の scratchpad）。
  パターンの束縛も同じ形である: §7 は「パターンに書いた名前: `snake_case` の名前は束縛である…それ以外の名前は解決し」とし、今の実装は `naming.rs` の `is_binding_name`（先頭の小文字）で決めるので、`let _x = 1` の `_x` は束縛にならず、束縛の位置で E0302「cannot find `_x`」になる（dev `fdc4fa5`、`P62/probe/us/v_lead.onsa`）。
  名前の規則の検査（`Shape::Snake`）は `_x` を `snake_case` と認め、`fn _g` は通る。

- 経緯: 62 回目（2026-10-24）、S-642 の下書き（onsa-gap、第 52 組）が新しい S の候補として挙げ、親が再現した。S-642 の決め方（効果行変数の「1 語」を外すか）と関わる。関係: S-642、S-01。62 回目、利用者の `_` の問いの後に、親がパターンの束縛の `let _x` も同じ形と確かめて広げ、族「§2.3 の名前の形」（S-650）に入れた。
- 補い（2026-10-24、親）: 62 回目（2026-10-24）: `let _x = 1` の形は R-168（2026-10-08、親が「直す。名前の段で `_` で始まる名前を普通の束縛として扱い、使われなければ E0309」、W4-04）として登録済みだった。R-168 の判断は §2.3 が頭の `_` を受ける読みに立つので、族「§2.3 の名前の形」（S-650）の決め方で改めうる。
