# S-961 族: §2.5 の記号の前後の空白と改行

- 空白: §2.5 の記号の前後の空白と改行（名前に付く印と前置の記号と相手の間の空白・改行・コメント、空白のある前置の重ね）の未決の S が二つを超えたので登録した（`rules/process.md` 8.6 の空白の流れの 2）。論点は空白の流れで書く。
- 決定: 決定（2026-11-09、利用者。127 回目）: (a)。§2.5 の印と記号（名前と印 `~`・`!`、`::` と `[`、`^`、境界の `?`、属性の `@`、前置の `-`・`!`、後置の `?`、印と `(`、メンバの `.`）と相手の間の同じ行の空白と改行（間の行コメントと空行を含む）は、括弧の中でも外でも E0020 で、修正候補は空白を除くか、記号を相手の行へ移す形。
  前のトークンに付かない位置（名前と印の間の改行、行頭の `::`（括弧の中でも）と `--`、次の行の頭の `.` の継続）は今のまま。
  その記号と相手の間の空白と改行に、同じ段の形そのものの誤り（§3.1 の前置の重ね、§6.5 の属性の誤り、既存言語の書き方の形: 前置の `~` と `+`、増減、`a--b`、経路の `::`、型の位置の `::`）が重なるときは、その誤りだけを報告し、その候補が隙間も直す。別の記号の空白は別の所の誤り（`~ - x`）。既存言語の形に候補が無ければ §18.1 のとおり E0002、属性の誤りは §6.5 のコード。後の段の誤りは段の順で後。ブロックコメントは S-960。
  利用者は「考慮漏れがないよう注意して」と添えた。親が §2.5 の文を記号と隙間の組の全てに当て、新しい onsa-advisor の点検で読みの割れる九か所を直し、点検で見つかった型の位置の `Buf::` 改行 `[F32]` を (iii) に足すことを利用者が了承した。§2.5 と §2.6 に書いた。実装は W5-11 の新しい単位（U10i）。族の決まる S は S-327・S-349・S-429・S-958・S-960・S-962・S-963。
- 経緯: 127 回目（2026-11-09）、S-960 の登録で同じ族の OPEN が S-327・S-349・S-429・S-958・S-960 になり、親が登録した。
