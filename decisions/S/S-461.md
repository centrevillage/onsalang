# S-461

- 空白: fmt がエスケープの綴りを揃えるか（`\u{0041}` と `\u{41}`、16 進の数字の大文字・小文字）と、他の言語のエスケープ（4 桁ちょうどの `\u`、8 桁ちょうどの `\U`、`\x41`）の診断。今は `\` と次の 1 文字だけの E0001「unknown escape」で、後ろの数字を普通の文字として読む。
  4 桁と 8 桁の形は値が一つに決まるので候補 `\u{41}`・`\u{1F600}` の E0020 の行を作れ、`\x41` は C（16 進の桁を貪欲に読む）と Python・JS・Rust（2 桁）で読みが割れる。第 25 組の Fable は fmt の側を「文字列と文字のリテラルの中身を変えない」の一文で閉じる案。第 25 組の下書きの付録で見つけた（2026-10-13）
- 提案: 後の段
- 時期: W3
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: B8、R1、Y）他の言語のエスケープのうち、そのエスケープを持つ対象の言語の全てで値が同じもの（持たない言語の読みは数えない）は E0020 の行 `escape_fixed_width`（字句の段、文字リテラルも同じ）で、候補は同じ値の `\u{…}` の一つ。当たるのは `\u` と 4 桁の 16 進の数字、`\U` と 8 桁の 16 進の数字（どちらも決まった桁の後ろは普通の文字で、`\u00411` は `\u{0041}1`）、`7F` 以下の `\xHH` で後ろに 16 進の数字が続かないもの、`\b`・`\f`・`\v`（`\u{8}`・`\u{C}`・`\u{B}`）。値が言語の間で割れる形（`\x414`、`\xff`、サロゲートの対 `\uD83D\uDE00`、`\a`）と、値がスカラー値でない形（`\uD800`、`\U00110000`）は今の E0001 で候補なし（読みごとの候補と note は採らない。言語ごとの依存が広がる、B8）。`\0` の後ろの数字は普通の文字で、`"\012"` は NUL と `1`・`2`（今のまま通る、B8）。fmt は文字列と文字のリテラルの中身（エスケープの綴り、16 進の大文字・小文字）を変えない。
  - 仕様の節: §2.4（エスケープの段落に `\0` の一文と、行の三文）、`spec/tools.md` §3.2（親が置く文）。
  - 今通るプログラム: 変わらない（`"\012"` は通るまま。行の形は今どれも E0001「unknown escape」）。
  - 実装の見当: `lexer.rs` のエスケープ（706 行の辺り）と `literal.rs` の `escape()` で形を見分け、行を一つ（`\b`・`\f`・`\v` を含めて 40〜70 行）。
  - ぶつかる事例: `tests/spec/negative/lex_escapes.onsa` の `backslash_x`（`"\x41"`、19 行）と `backslash_big_u`（`"\U0001F600"`、23 行）は `//~ E0001` → E0020（`.fix1` が要る）。`tests/cst/lex_escape_u_forms.onsa`（`mode = "none"`）は CST だけ。
