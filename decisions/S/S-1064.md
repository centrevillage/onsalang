# S-1064 細部: 型引数の中の等しさで、両側が開いた行のとき（`{gone.Alloc}` と `{Gone}`。片側の指しえた効果だけが違う）、E0401 を出すか

- 空白: S-1063 の決定 (2) は、型引数の中の等しさでも「指しえた効果で埋まる違いだけを比べない」とし、例に `uses {Gone}` と `uses {Alloc}` の違いは E0401 と書く。両側が開いた行で、片側の指しえた効果だけが違う形（`use kp.{Gone, gone}` が失敗した下で、`Option[fn(U32) -> U32 uses {gone.Alloc}]` の値を `Option[fn(U32) -> U32 uses {Gone}]` の位置に置く。`gone.Alloc` は `Alloc` を指しえ、`Gone` は何も指しえない）を書かない。誤りのあるプログラム（E0302）だけの形で、通るプログラムは変わらない。
  今（dev `e0b47f08` のコード）: 誤りなし。同じ入力で、`{gone.Alloc}` から純粋な行（`path_to_pure`）も誤りなし、`{Alloc}` から `{Gone}`（`alloc_val`）は E0401。
  再現: `target/notes/153/w604/u2t_gap/s1063.onsa`（`path_to_gone` の行）。
  読み: (1) `{gone.Alloc}` は `Alloc` を指しえ、`{Gone}` は何も指しえないので、違いは埋まらず E0401 (2) 指しえた名前が何も指さなければ両側は等しいので、違いは指しえた効果で埋まり、比べない（今の実装。`path_to_pure` が黙るのと同じ読み）。
  仮の扱い: (2)（親の読み: S-1063 の決定の字と、`{gone.Alloc}` から純粋な行が黙る今の形から一つに決まる見込み。事例は確認の後に足す）。
