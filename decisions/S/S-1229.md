# S-1229 イベントの入力を持つ部品を塊（`x.up~(M).down~(N)`）の中で動かす形の、塊の走りより後の位置のイベントの見え方

- 空白: §11.11 は「`.down~`・`.up~` の部品の中の `at event` の入力も、全ての位置のイベントで動く（`.up~` の中では、その位置の最初の刻みの前）」、§11.9 は「部品のイベントの段は、その位置で処理する」とする（S-567 の答えの (a-5) から）。
  その後の S-1207（塊の読み）で、上りを下りが包む連鎖 `x.up~(2).down~(2)` は、境界の刻みの位置 c で、位置 c と c+1 に当たる走りを全て先に走る。位置 c+1 に来たイベントを塊の中の部品 x のどの走りから見えるかが字に無い。
  読み: (1) イベントは来た位置 c+1 で処理し、次の境界の刻み c+2 の走りから見える（一段の `x.down~(2)` と同じ。音声の入力は N サンプル遅れるので、イベントと音声の遅れが揃わない）。(2) 集める入力と同じに境界で集め、N サンプル遅れて、その位置に当たる走りの前に処理する（遅れが揃う。「全ての位置のイベントで動く」の時点が変わる）。(3) 塊の中のイベントの入力は誤りにする。
  同じ族の形: 境界の内に書いたイベントの条件の `reset_if~`（`x.up~(2).reset_if~(is_start(tr)).down~(2)`）、塊の内の部品のイベントの出力の位置（§11.11「内側の刻みが属する呼び出し側の位置」の「属する」位置が c か c+j か）。
  今は `at event` の入力が E0302 で書けない（W7-11）。再現は `target/notes/176/w721/review/cases_r4.txt` の `r13`。
  仮の扱い: 無し（W7-11 の設計メモの前に決める）。
