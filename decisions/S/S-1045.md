# S-1045 `[e; N]` の要素に置いた Copy でない Dup の値（作った値、借用の値の複製、所有の束縛の手放し）を、`N` が 0 か 0 でありうるとき（`[s; 0]`、総称の `const N`）に破棄するか（`Alloc`）

- 空白: §2.4（`spec/02-lexical.md`）は「`[e; N]`（`e` を 1 回評価して N 個に複製する。`e` は Dup 型（でなければ E0416）…）」とし、§5.2 はリテラルの要素を値を置く位置（消費する位置）とする。§12.2 は所有する Shared 値・`Buf` を含む値の破棄に `Alloc` を要るとする。
  `N` が 0 のとき、1 回評価した `e` の値はどの要素にも置かれない。その値が破棄されるか（`Alloc` が要るか）、仕様は書かない。`N` が総称の `const N` なら、本体の検査の時点では 0 かどうかが分からない。
  今（U6 の後の `584bcaa`）: 作った値（`rt fn r(n: U32) -> [Str; 0] { [mk(n); 0] }`）、借用の値の複製（`rt fn r(s: Str) -> [Str; 0] { [s; 0] }`）、総称の長さ（`rt fn r[const N: U32](n: U32) -> [Str; N] { [mk(n); N] }`）は誤りにならない。
  所有の束縛（`rt fn r(move s: Str) -> [Str; 0] { [s; 0] }`）は、U7 の前は複製で元の `s` の破棄が E0901 になり、U7 の後は手放しで誤りにならない（作った値と同じ扱いになる）。
  `[mk(n); 0].len()` のように配列の全体を一時の値として捨てる形は、配列の型の破棄で E0901 になる（U5a）。再現は `target/notes/149/w602/u7/probe/rep0.onsa`・`rep1.onsa`。
  読み: (1) `N` が 0 でありうるなら、`e` の値を破棄すると数える（`Alloc` が要る。`[s; 2]` は要らない）。(2) 要素に一度置いたと数え、`N` が 0 の破棄は数えない（今の扱い。`rt` の関数で解放が起きうる）。(3) `[e; 0]` を Copy でない Dup の `e` で書くことを誤りにし、総称の `N` は (1)。
  U7 の仮の扱い: 作った値と同じく (2)（所有の束縛だけを除くと、決まった後に戻す手間が増えるため）。`SPEC-GAP(S-1045)` の印を `[e; N]` の歩きに付ける。
  急ぎ: W6-04 の前（W6 の見直しで破棄の点を見直すとき）。現実のプログラムで `N` が 0 の繰り返しに `Str`・`Buf` を置く形はまれ。
- 決定: 決定（2026-11-15、利用者。152 回目。利用者の基準「長さ 0 の配列に Shared 値を入れる実用の用途は無さそう、管理しやすいやり方」で親が (1) を推し、利用者の求めで独立のレビューの段 1 を回した。段 1 も (1) を選び（親の推奨を伏せた）、段 2 は省いた）: (1)。`[e; N]` の `e` は値を置く位置で、長さが 0 でありうる（長さが 0 か、総称の定数のパラメータ）とき、置いた値はどの要素にもならずその場で破棄されると数える（`Alloc` が要る。長さが 1 以上と分かれば数えない）。
  借用の場所の `e`（複製）も分けずに数える。破棄の使用の位置は `e` の式（S-783 の「束縛の無い値はその式」）。
  理由: 例外の規則を足さずに §2.4・§12.2 の字のまま `rt` の保証（§10 の規則 1）を保つ。(2) は §12.2 の例外と `rt` の解放の穴を残す（S-1040 で一つの式だけ破棄を数えない例外を採らなかった先例と同じ形）。総称の長さを本体で保守的に数えるのは §12.2 の総称の `T` の破棄と同じ向き。(3) は規則が増え、`uses {Alloc}` を持つ健全な関数まで誤りにする。後で緩めても書いたプログラムは止まらない。
  代償（レビューの困る形の表）: 総称の長さで Copy でない Dup の値を繰り返す関数は、1 以上でしか呼ばれなくても `Alloc` が要る。`rt` の関数では候補も代わりの書き方（`from_fn` は E0200）も無い（`rt fn bank[const N: U32](table: Array[F32]) -> [Voice; N] { [Voice { table: table, phase: 0.0 }; N] }`、実行時は解放しない）。
  借用を包んだ値の破棄の族で、`tasks/phase2.md` の L3 で一緒に緩む（一行足した）。他の形は困る程度が低か無し。
  作業は W6-04（modes の `Repeat` の腕に破棄の点、破棄の種類を足す（`Temp` を使い回さない）、`drop_alloc.rs`・`uses.rs`・`effects.rs` の対応、`SPEC-GAP(S-1045)` の印を外す、事例。レビューの見積もりはコード約 30〜40 行）。仕様は §2.4 と §12.2 の表に一文ずつ書いた。材料は `target/notes/152/s1045adv/`（要約、段 1 の票と報告、入力）。
- 経緯: 149 回目（2026-11-14）、W6-02 U7 のテストの担当（onsa-test）が `[s; N]` の Dup の値の期待を書けないと報告し、親が固定のバイナリ `onsa-584bcaa` と述語を仮に広げたバイナリで、長さ 0 の形を前から見落としていることを確かめた。
  関係: S-1030、R-32、U5a の一時の値、E0416。 152 回目（2026-11-15）、親が問題を説明して (1) を推し、利用者の求めで独立のレビューの段 1（onsa-advisor、`target/notes/152/s1045adv/`）を回して、利用者が (1) に決めた。レビューは範囲の外で R-461 を見つけた。
