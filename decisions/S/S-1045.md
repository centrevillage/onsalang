# S-1045 `[e; N]` の要素に置いた Copy でない Dup の値（作った値、借用の値の複製、所有の束縛の手放し）を、`N` が 0 か 0 でありうるとき（`[s; 0]`、総称の `const N`）に破棄するか（`Alloc`）

- 空白: §2.4（`spec/02-lexical.md`）は「`[e; N]`（`e` を 1 回評価して N 個に複製する。`e` は Dup 型（でなければ E0416）…）」とし、§5.2 はリテラルの要素を値を置く位置（消費する位置）とする。§12.2 は所有する Shared 値・`Buf` を含む値の破棄に `Alloc` を要るとする。
  `N` が 0 のとき、1 回評価した `e` の値はどの要素にも置かれない。その値が破棄されるか（`Alloc` が要るか）、仕様は書かない。`N` が総称の `const N` なら、本体の検査の時点では 0 かどうかが分からない。
  今（U6 の後の `584bcaa`）: 作った値（`rt fn r(n: U32) -> [Str; 0] { [mk(n); 0] }`）、借用の値の複製（`rt fn r(s: Str) -> [Str; 0] { [s; 0] }`）、総称の長さ（`rt fn r[const N: U32](n: U32) -> [Str; N] { [mk(n); N] }`）は誤りにならない。所有の束縛（`rt fn r(move s: Str) -> [Str; 0] { [s; 0] }`）は、U7 の前は複製で元の `s` の破棄が E0901 になり、U7 の後は手放しで誤りにならない（作った値と同じ扱いになる）。
  `[mk(n); 0].len()` のように配列の全体を一時の値として捨てる形は、配列の型の破棄で E0901 になる（U5a）。再現は `target/notes/149/w602/u7/probe/rep0.onsa`・`rep1.onsa`。
  読み: (1) `N` が 0 でありうるなら、`e` の値を破棄すると数える（`Alloc` が要る。`[s; 2]` は要らない）。(2) 要素に一度置いたと数え、`N` が 0 の破棄は数えない（今の扱い。`rt` の関数で解放が起きうる）。(3) `[e; 0]` を Copy でない Dup の `e` で書くことを誤りにし、総称の `N` は (1)。
  U7 の仮の扱い: 作った値と同じく (2)（所有の束縛だけを除くと、決まった後に戻す手間が増えるため）。`SPEC-GAP(S-1045)` の印を `[e; N]` の歩きに付ける。
  急ぎ: W6-04 の前（W6 の見直しで破棄の点を見直すとき）。現実のプログラムで `N` が 0 の繰り返しに `Str`・`Buf` を置く形はまれ。
- 決定:
- 経緯: 149 回目（2026-11-14）、W6-02 U7 のテストの担当（onsa-test）が `[s; N]` の Dup の値の期待を書けないと報告し、親が固定のバイナリ `onsa-584bcaa` と述語を仮に広げたバイナリで、長さ 0 の形を前から見落としていることを確かめた。関係: S-1030、R-32、U5a の一時の値、E0416。
