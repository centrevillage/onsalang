# S-563 イベントのクロックの値と他のクロックの値を混ぜる規則

- 空白: §19.1 は「イベントのクロックの値と他のクロックの値を混ぜる規則」を入れるときに決めることに挙げる。今の規則は、遅いクロックの値を速いクロックで使うのは値を変えない（保持、§11.3）。決めること:
  1. イベントの値を `sample` の式で読む形（最後の値を保つか、`Option` か、誤りか）。
  2. `sample`・`block`・`init` の値をイベントのクロックの式で読む形（その位置の値）。
  3. イベントと信号の変換を std の flow で書く方針（`genv~`、`detect_zero~` など、§19.1）と、言語が持つ変換の境界。
- 決定: 決定（2026-10-21、利用者が ID を挙げて了承。47・50 回目）: イベントの値は `block` と同じく暗黙に読め、使う所の周期の刻みのクロックの刻みでその位置までの最後の値になる（`v at sample` も同じ意味。最初のイベントの前は `T.default()`、無ければ E0816）。
  四つの所（組込みの遅延の第 1 引数、帰還の輪、`reset_if~` の条件、イベントの出力の式）で周期のクロックの値と混ざると E0815。イベントの段の式は周期の刻みのクロックの値を読めず（E0815）、パラメータの種類と `sample_tick()` は読める。変換は std の flow（脈の flow など）で書く。仕様 §19.1
- 経緯: X-7（W3 の終わり、2026-10-15、利用者）で、W4 の前に決めて第 1 期の範囲を W4〜W10 に割り当てることになった。第 34 組（イベントのクロック）の一つで、第 33 組（S-555〜S-559）の決定を前提にする。export の形・C の API・std の型・`onsa test` と `render` での与え方は第 35 組。
