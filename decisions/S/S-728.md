# S-728 失敗した名前を指す型別名（`use util.{Gone}` の後の `type A = Gone`）を値の位置の経路の頭に書いたとき、単位の以後を検査しないか（今は `A.V` で止まり、`A { a: 1 }` は続く）

- 空白: §18.1 は、失敗した名前を値の位置（失敗した名前を経路として書いた式とパターン）に書くと、その単位の以後を検査しないとし、型の位置では誤りの型として読んで検査を続けるとする。失敗した名前を指す型別名（`use util.{Gone}` が失敗した後の `pub type A = Gone`）を値の位置の経路の頭に書いた形は、どちらとも書いていない。
  今の実装（`4fb3fda` と W4-04 U7b2 の後で同じ）: 別名の後のメンバの経路 `A.V` は単位の以後を検査しない（`Gone.V` と同じ）。別名の struct リテラル `A { a: 1 }` は検査が続き、同じ単位の後の `let b: Bool = 2` の E0401 や、読まれない束縛の E0309 が出る（`Gone { a: 1 }` と書くと止まる）。R-271 は誤りの型の別名の struct リテラルを続ける側で直した。
  通るプログラムは変わらない。変わるのは、誤りのある単位（失敗した `use` のある包み）で連鎖して出る診断だけである。
  読み: (1) 別名も失敗した名前の続きとして、値の位置ではどちらも止める。(2) 別名は誤りの型として、どちらも続ける（R-271 の向き）。
  再現は 78 回目の scratchpad の `w404/u7b2/parent/failed/after.onsa`・`w404/u7b2/b/p1/g.onsa` の k9・k10（区切りで `target/notes/78/w404/u7b2/` へ写す）。

- 経緯: 78 回目（2026-10-28）、W4-04 U7b2 の壊す側（onsa-break）の指摘 1。親が `after.onsa` で前の版でも同じことを確かめた。書き方だけで結果が変わる表面の違いなので、W4-04 を終える前に決める。
