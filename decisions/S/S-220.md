# S-220

- 空白: 出力が struct の flow の `process_inplace` で、struct のフィールドが配列（`[Span[T]; N]` の平面）のとき、入出力を数えるときに配列をさらに展開するか（S-197 はフィールドを展開すると決めた）。W2-11/t で見つけた（2026-10-08）
- 提案: W7-03 の着手の前に決める
- 時期: W7
- 決定（2026-11-16、利用者、160 回目、第 108 組）: (1) 配列は展開しない。`process_inplace` の生成の条件で入力と出力の数と型を比べるとき、struct の出力のフィールドだけを展開し（S-197）、`[T; N]` は長さを含めた一つの型として比べる（今の実装のまま）。仕様 §11.6。
  あわせて §14.2 の C の in-place の文を、`process_inplace` の位置の対と読めない形（結果は別々のバッファと同じ、§11.6 の読んでから書く約束）に言い直した（意味は変えない。C の組はチャンネルごとで位置によらない、S-403）。
  理由: この読みで変わるのは Onsa のコードが一本のバッファで呼べる flow の範囲だけで、C の `_process` の in-place とプラグインのラッパーはどの読みでも同じ（チャンネルごと、位置によらない）。入力にスカラも配列も書けるので、(1) で in-place にできない flow の類は無い。
  (2) 全て展開する案は、入力の配列が出力の二つの欄にまたがる対応（型が全て合い、取り違えが黙って通る）と、対応の規則・Core の降下・器の `fits` の手当てを足す。(3) struct のフィールドの配列だけ展開する案は、字のとおりでは今ある `[F32; 2] -> Q { v: [F32; 2] }` の形を消す。(1) は (2) の部分集合なので、後で広げても止まるものは無い。
  §14.3 のバスの束ね方（`[F32; 2]` はステレオのバス一つ）とも合う。段 1（onsa-advisor）が独立に (1) を選び、親の読みと一致したので段 2 を省いた。材料は `target/notes/160/g108/`。
  帰結: 無い `process_inplace` の E0302 に入出力の型の並びの note を足す R-480（W7-12 U3）。事例（`tests/spec/negative/flow_inplace_absent.onsa` に、スカラ二つと配列、配列と struct のスカラのフィールド、またぐ並び、長さ 1 の配列とスカラの形）は W7-12 U3。
- 経緯: 160 回目（2026-11-16）、W7-12 U3 の前に中立の要約と段 1 で決めた（第 108 組）。
