# S-881 総称の浮動小数のコードの小数の定数（`x * 0.5`（`x: T: Float`）は E0401、`T.round_from(0.5)` は浮動小数のリテラルに既定の型が無く E0405、`T.round_from(2)` は通る）

- 決定済みで戻さないもの: 変換を変換先の型の関連関数で書くこと（S-231）。`as` を情報を失わない組に限ること（S-98）。`as` を型パラメータの値に書けないこと（S-210）。リテラルに接尾辞が無いこと（§2.4）。`T.ONE` などの関連定数の一覧（S-46・S-84）。総称のビット表現（A-17 で保留）。

- 論点: §6.6 の文のために、総称のコードで係数を書く一行の形が無い。S-231 の `T.round_from(k)` は整数のリテラルなら書けるが、小数のリテラルは変換元の型が決まらず、W5-05 の後も E0405 になる見込みである。書く形を今の二行で足りるとするか、一行の形を足すかを決める。
  - 出所:
    - §6.6 の末尾「リテラルは型パラメータ `T` の値にならない」は、S-46 の変更の記録（`history/onsa-0.3-changes.md` 466 行）によれば、実装のレビューの T-3（リテラルは `T` に束縛しない）を仕様に写した文である。設計の議論から出た禁止ではない。
      R-94 の決定 (7) は整数のリテラルを `T: Int` の値にする形を「後から足せるもの」として A-10 に挙げ、A-10 は「規則を緩める方向なので、既存のコードは壊れない」「定義の位置で範囲を確かめられ、使う場所の奥で誤りにならない」と書く。小数のリテラルについての文は決定に無い。
    - §3.3（S-98）: 数の型の間の変換は表で閉じ、型の組ごとに書き方は一つである。`as` で書ける組の変換の関連関数は E0413。
    - S-231（決定済み）: 変換は変換先の型の関連関数で書く。`round_from[S: AnyNum](x: S)` の変換元は型パラメータで、引数の型は引数から決まる。片方が型パラメータなら、具体化で同じ型になる組でも書ける。
    - §2.4: 浮動小数のリテラルに既定の型は無い。理由は、`F64` を既定にすると倍精度 FPU の無いマイコンで気付かずにソフトウェア浮動小数を使うこと、`F32` を既定にすると Rust の読み手に偽の友人になることである。
      値は「10 進の値を型へ最近接偶数で一度だけ丸めた値」で、`F32` のリテラルを `F64` を経て二重に丸めない。§4.7 により、`as` の左辺のリテラルの型変数は未解決（E0420）である。
    - §6.3: `Float` を実装するのは `F32`・`F64` だけで、項目も閉じている。利用者の型に開くかは §19.1 の未決である。
    - Rust の実装: 型の段の E0401 は `body.rs` の `Mismatch::Literal` で、小数のリテラルの型変数が `Ty::Param` と単一化できないことから出る。降下は字面を持ち、具体化した後の型へ一度だけ丸める（`crates/onsa_core/src/lower/body/expr.rs` 57〜66 行の `float_value(text, width)`）。

  値の違い（`a11`、`onsa test` で確かめた）: 字面 `1.0000000596046447753906250001` は、`F32` のリテラルで `0x3F800001`、`F64` のリテラルを `F32.round_from` すると `0x3F800000` で、二重の丸めで 1 ULP 違う。
  同じ違いが出る字面の数（`dr.py`、正確な有理数で丸めを比べた）: 小数 6 桁以下の 111 万 1104 個で 0 個、8〜20 桁の乱数 30 万個で 0 個、π・e・√2・1/√2・ln2・τ の 36 桁で 0 個である。出るのは `F32` の丸めの中点に `F64` の値が重なる字面だけで、実際の係数にはほぼ出ない。
  生成する C（`P116/g87/other/cb`、`onsa build`）: `let h: F64 = 0.5` の後の `x * F32.round_from(h)` は `double h = 0.5; return (float)(x * ((float)h));`、`x * 0.5`（`x: F32`）は `(float)(x * 0.5f)` である。
  同じ形の C を clang 21 で試すと、`-O0` は倍精度からの変換の命令（arm64 の `fcvt`）が一つ残り、`-O1` で消える。Cortex-M の結果と Onsa の `-O` の水準ごとの結果は未確認である。
