# S-688 E0304 になった `use` の名前（S-675 の (d1) で黙る名前）を、E0310 の辺に数えるか（`a.onsa` の項目 `b` と `use b`、`b.onsa` の `use a`）

- 空白: S-678 は、名前の段で失敗した `use` の名前を依存（E0310 の辺）に数えないとし、S-675 の (d1) は、E0304・E0305 になった名前を S-462 の誤りの名前の集合に入れて使う所を黙らせるとした。E0304 になった `use` の名前（解決はした）を辺に数えるかを書いていない。
  読みは (1) 解決はしたので辺を張る、(2) 誤りの名前なので失敗した `use` と同じく辺を張らない、に割れる。形は `a.onsa` に項目 `b` と `use b`、`b.onsa` に `use a`（(1) では、E0310 が同じ `use` に付く並びでは E0310 だけ（同じ単位の最初の誤り）、循環の他の `use` に付く並びでは両方。(2) では E0304 だけ。第 62 組の下書きが確かめて直した）。
  W4-03 U3b1 の実装（67 回目）は (1)（印は置いていない）。
- 決定: 決定（2026-10-25、利用者。68 回目、第 62 組、ID を挙げて確認だけで了承（A1〜A5））: (2)。
  E0304・E0305 になった名前（S-675 の (d1) でその空間の誤りの名前）を取り込む `use` は、失敗した `use`（S-678）と同じく依存（E0310 の辺）に数えない。`use` どうしの組は報告しなかった側も含めて両方とも数えず（書く順で結果が変わらない）、prelude・組込み型・組込みの flow の名前との組も同じ。
  同じ `use` の他の束縛になった要素は数える（S-685）。理由は、S-678 が先のモジュールが分かる `use b.{nosuch}` でも名前が束縛にならなければ辺なしとしたこと（辺の条件は束縛が立つこと）と、同じ単位で E0304 が E0310 に隠れず、書き手が一つのモジュールの中で閉じる誤りを先に見ること。
  代償は、循環が本物のとき E0310 が名前を直した次の検査になること（S-678 と同じ）と、別の単位の並びで E0310 が同時に出なくなること。報告した側の `use` だけ数えない (2') は書く順で結果が変わり、E0310 の位置を E0304 の無い `use` に寄せる (3) は判定が二か所に分かれるので採らない（A3）。
  取り込む名前が予約語の `use` と E0200 の `pub use` は §18.1 で決定済みの辺なしで、W4-03 の U3b2 の持ち越し。仕様は §15.1 の E0310 の段落と §18.1 の E0304・E0305 の文に一文（A4）。
  実装は `names/clash.rs` の `use_clashes` の後でその名前の束縛の辺を除く一か所（約 +5 行、A2）で、W4-03 の U3d（U3c・U3b2 の後、A5）。事例 2〜4 件と `--fix-loop` の確認、`onsa explain E0310` の文の確かめ。
- 経緯: 67 回目（2026-10-25）、W4-03 U3b1/i（onsa-impl）が見つけた。急ぎは後の段。関係: S-678、S-675、S-462。
