# S-734 宣言をまたぐ循環（`use` の E0310、型の E0311、定数の E0312）の報告を、循環（強連結成分）ごとに一つにするか、循環の中の宣言ごとにするか、付ける宣言と note

- 決定済みで戻さないもの: 型の E0311 の数・位置・note・外の扱い（S-730）。依存の数え方と狭め方の note（§15.1、S-594、S-683）。絞った `check` で他のファイルの E0310 が見えない件（S-645、未決）。関数を経由する定数の循環（S-173、未決、W9-03）。
  第 70 組の下書きの「S-734 の仕組みの出所」と「S-734 の形の表」の節（写しは `target/notes/79/g70/draft.md`）。
- 論点: §15.1「モジュール間の循環 import は禁止（E0310）」と §6.6「初期化式が、直接または他の定数を経由して自分自身を参照すると E0312」は、循環に入った宣言（それぞれ診断の単位）のどれに、いくつ報告するかを書いていない。
  E0310 では、循環に入るのはモジュールで、診断の単位はその依存を作る `use` である。E0312 では、循環に入る定数（関連定数を含む）がそれぞれ単位である。
- 今の実装: 表のとおり。E0310 は成分ごとに一つで、最初の `use` に付く。成分の他の `use` は、狭めて切れるときの狭められる `use` だけが note に出る。E0312 は出ず、定数の循環は `check` を通る。
  修正候補はどちらにも無い（E0310 は note で狭め方を示す）。
- 案: 
  - (a) S-730 の規則を E0310 と E0312 にも当てる。成分ごとに一つで、位置は診断の並べ方で最初の宣言（E0310 は成分の中に依存を持つ `use`、E0312 は定数の名前）、成分の他の宣言は位置付きの note。成分の外から使う宣言には出さない（E0312 では、外の定数の評価と型の位置の長さは、循環の定数を誤りの値として読む）。
  - (b) 循環の中の宣言ごとに一つ（E0310 は成分の中に依存を持つ各 `use`、E0312 は成分の各定数）。型の E0311 だけが成分ごとになる。
  - あわせて E0310 の note: (n1) 成分の他の `use` を全て位置付きの note で示す（狭めて切れる `use` は、その note で狭め方も示す）。(n2) 今のまま（狭めて切れるときは狭められる `use` だけ、切れなければ規則の note だけ）。
  - 形ごとの出力: 二つのモジュールの循環は、(a) が `a.onsa:1:1` に一つ（(n1) は `b.onsa` の `use a.{f}` の note 付き）、(b) が `a.onsa` と `b.onsa` の `use` に一つずつ。二つの定数の循環は、(a) が `A` に一つで `B` の note、(b) が `A` と `B` に一つずつ。
    循環の他の定数の型の誤り（`B = A + "s"`）は、(a) では `B` の単位を検査して E0401 が出る。(b) では `B` の単位の名前の段の E0312 が先で、E0401 は隠れる。外から使う定数と関数は、どの案も出さない。
  - 書き手から見て: どちらの循環も、どこか一か所を切れば消える。(b) は N 個の誤りを並べ、書き手（とくに全ての診断を一つずつ直す LLM）が全ての初期化式や `use` を書き換えうる。(a) は一つの誤りで、note が循環の宣言を並べるので、書き手は一か所を選ぶ。
    (n2) では、切れない循環の E0310 は他のモジュールの `use` の位置を示さない（メッセージはモジュールの名前だけ）。書き手は他のファイルを開いて `use` を探す。(n1) は位置で示す。
  - 修正候補: どの案も候補は無い（どこで切るかは書き手しか知らない）。当て続けても `no-candidate` で止まる。
  - 通るプログラム: どの案も変わらない。E0312 はどの案でも W4-05 で新しく出るので、今通る定数の循環はどの案でも誤りになる。変わるのは誤りの数・位置・note だけである。
  - 規則と例外: (a) は三つのコードに一つの規則で、§4.4 の S-730 の文を全ての宣言をまたぐ循環に広げる。(b) は E0311 だけが成分ごとになる違いを残す（揃えるなら S-730 を改める）。(n1)・(n2) は note の細部で、規則の数は変わらない。
  - 実装の量（W4-05 の U4。R-02 と同じ所）: E0312 は、定数の初期化式の名前の記録（`BodyNames.paths` の定数と関連定数への解決）から定数の依存のグラフを作り、`cycles.rs::components` で成分を求める。ここまではどの案にも要る。
    (a) は成分ごとに位置を一つ選んで note を並べる（約 +5〜10 行）。(b) は成分の全ての定数に出す（約 +3 行）。どちらも、循環の定数の評価を止めて誤りの値にする所（R-02 のスタック溢れを止める所）が要り、案によらない。
    E0310 は、(a)・(n2) が 0 行（今の実装のまま）、(a)・(n1) が `cycles.rs::cycle` で `deps` の他の `use` に note を足す約 +3〜5 行、(b) が `check_cycles` で成分の全ての `use` に出す約 +5 行と、`tests/spec/packages/cycle*` の期待の直し。
    後の段への手当てはどの案にも無い（循環は名前の段で閉じ、外は誤りの値）。第 2 期と JS / WASM には関わらない。
