# S-1096 `par~` の本体がイベントの出力を持つインスタンスを含むときの、結果の配列のクロック

- 決定済みで戻さないもの: S-564（呼び出しの出力のイベントのクロックは呼び出しごとに別）、§11.5（`par~` の複製は別のインスタンス、結果の値型は `[T; N]`）、S-567 の K5。下書きの全文（出所、前の議論との整合の表、族の形の表、他言語）は `target/notes/183/g118/draft.md`、伏せた版は `blind.md`、段 1 の報告は `stage1_report.md`、値の模型は `model/`（下書き）と `adv/`（段 1）。
- 論点: `par~` の複製の中で作ったイベントの出力を、配列として複製の外へ出す形（`let ys = par~ i in 0 ..< 4 { det~(x, t(i)) }`）の、配列のクロック。複製の中で閉じる形（`par~ i { voice~(alloc~(m, i)) }`）と、複製の中で `at sample` の値にする形は、どの案でも通る。
- 今の実装: `at event` は E0302 で試せない。
- 案: (a) 要素ごとに複製のクロックを持つ（定数の添字だけ使える）。(b) `par~` の複製は一つのクロック（同じ位置は複製の番号の順、どの複製が出たかは値に入らない）。(c) 複製ごとに別のクロックなので最大が無く E0815。(d) 当面 E0200。細部: (c1) `N = 1` は通す、(c2) `N` によらず E0815。
- 比べ（要点）: (a) は `Clock` の形が変わり、動的な添字と全体を渡す形は誤りのまま。(b) は S-564 の「呼び出しごとに別」を読み替え、複製 0 のつもりの受け手が他の複製のイベントでも動く形を黙って通す。(c) は既にある「最大が無ければ E0815」の当てはめで、配列のリテラル `[det~(x, a), det~(x, b)]`（どの案でも E0815）と揃う。
  典型（ボイスごとの `par~` から音符の終わりを外へ出す）は、(c) では、複製が `sample` の値（終わったかの真偽）を返し、外で一つのイベントにまとめる形になる（flow の出力は一つで、struct にイベントを含められない（E0810）ので、音とイベントの両方を返すボイスはどの案でも書けない）。
- 推奨と理由: 下書きは (c)、`N` によらず E0815（c2）（確度 中〜高）。例外 0、`EventSrc` と `Clock` の形を変えず、後で (a) か合流の機能に開ける（(b) を今入れると、開くときに刻みが変わる）。
- 影響: 仕様 §11.5（一文）。診断 E0815。作業は W7-11・W7-17。
- 独立のレビュー: 段 1 は (c)・(c2)（確信 中〜高）で一致。書き方の例を足し、§11.11「和の型の一つの入力で受けて書く」を (b) に不利な先例に足した。整合の表の行 4 の判定を直した。段 2 は省いた。
