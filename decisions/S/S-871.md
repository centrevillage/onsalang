# S-871 署名の E0710（第二級の型の置き場の誤り）の型を使う側に、推論した型引数の E0710 を連鎖で出すか（`take(s: Option[Span[F32]])` の後の `take(None)`）

- 空白: §18.1 は「読めなかった部分（引数の型、フィールドなど）は誤りの型として扱い、それを使う側には診断を出さない」とし、別の文は型の位置を誤りの型として読むとする。署名の E0710（第二級の型を置けない位置に書いた形、§5.3）の型が、この「読めなかった部分」に当たるかを書いていない。
  W5-02 U5a（推論した型引数の E0710、S-862）の後、その型を使う側に新しい E0710 が連鎖して出る: `pub fn take(s: Option[Span[F32]]) -> U32 { 0 }` の後の `take(None)` は、署名の 1:23 の E0710 に加えて `None` の型引数の E0710。`pub fn bad(s: Span[F32]) -> Span[F32] { s }` の後の `id(bad)` は、前の連鎖の E0309 が E0710 になる。
  一方、利用者の総称の型に書いた `W[Span[F32]]` は、型引数が誤りの型に置き換わり、使う側は黙る。再現は `target/notes/109/w502u5a/probe/r09_arg_none.onsa`・`h01_cascade_bad_sig_return.onsa`（前 `97c584a9`、後は U5a）。
  読み: (1) 署名の E0710 の型も読めなかった部分で、誤りの型に置き換えて使う側は黙る（`W[Span[F32]]` と揃う）。(2) E0710 は型を読めた上での置き場の誤りで、型は残り、使う側にも診断が出る（今の U5a）。
  急ぎ: W5-13 の前（誤りのあるプログラムの診断の数だけが違い、今通るプログラムは変わらない）
- 決定: 決定（2026-11-12、利用者「他の (A) は現状で OK」。140 回目、W5-13 の前の確認だけ）: 今の実装の (2)。署名の E0710 は型を読めた上での置き場の誤りで、型は残り、使う側にも E0710 が出る（`take(s: Option[Span[F32]])` の後の `take(None)`）。§18.1 の読めなかった部分に揃えて連鎖を黙らせる (1) は、実装を変える細部なので採らない。仕様は変えない。
- 経緯: 109 回目（2026-11-03）、W5-02 U5a の壊す側（onsa-break）が低の指摘と NEW として挙げた。親が前後のバイナリで再現した。関係: S-862、S-766
