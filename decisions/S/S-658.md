# S-658 `graph <flow>` の `<flow>` が、渡したモジュールに `use` で取り込んだだけの flow か、flow でない名前（`fn`）のときの終了コードと、範囲の中に 0 件のときに候補の経路を並べるか

- 空白: §18.2 は `graph <flow> [<経路>]` の `<flow>` を、モジュールの経路付きの名前か、選んだ範囲で一つに決まる名前とし、決まらなければ 2 とする（S-323）。§15.1 は、ファイルを渡すと `graph` はそのモジュールの中の flow を出すとし、`use` の束縛を引かない。
  書いていないのは、`<flow>` が渡したモジュールに `use` で取り込んだだけの flow の名前（`graph sub.beta.only_in_alpha sub/beta.onsa`）のときと、flow でない名前（`fn`）のときの終了コード。どちらも 2 と読めるが、文に無い。
  また「一つに決まらなければ…候補の経路を並べる」が、範囲の中に 0 件のときにも当たるか（ファイルの範囲に無い同じ名前の flow が他のモジュールにあるとき、`a.voice, dsp.b.voice` を並べるか）を書いていない。
  仮の扱い: どれも 2。0 件のときは候補を並べない（`no flow named …` だけ）。W4-14 U4 の事例には書いていない（`crates/onsa_driver/src/graph.rs` の `find_flow` の `SPEC-GAP(S-658)`）。
- 決定:
- 経緯: 63 回目（2026-10-24）、W4-14 U4 のテストの担当が小さい空白として報告し、0 件の候補は U4 の壊す側が報告した（同じ `find_flow` の細部なので、この S に足した）。関係: S-323、S-657。
