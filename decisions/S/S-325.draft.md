# S-325 キーワードの名前のファイルとディレクトリと、ファイル名の E0320 の note

- 決定済みで戻さないもの: キーワードの名前のファイルとディレクトリは `snake_case` に合い、モジュールの名前として書ける。`use` の経路の頭と `.` の後では名前として読む（§2.2、S-20・S-37・S-371。std 自身が `test.onsa`・`dsp/test.onsa` を持つ）。E0320 にはならない。
  ファイル名とディレクトリの名前の E0320 の形（候補なし、note、位置）は S-300・S-313。`__` を含む名前は E0320（§2.3）。`use kp.clock` のようにキーワードの名前のモジュールそのものを取り込んだ束縛が式の頭で使えない形は S-443（族「§15.1 の use の経路と並び」）。
- 論点: 仕様 §2.3「モジュールの名前はファイル名（拡張子を除く）で、`snake_case` の規則に従う」「規則に揃えた名前が予約語になるとき（`pub fn Match()` の `match`、§2.2）は、末尾に `_` を足した名前（`match_`）を候補にする」「ファイル名の違反の E0320 は…修正候補を出さず、ファイル名を `snake_case` にすることを note で示す」。
  §2.2「キーワードは、パスの `.` の直後と `use` の経路の頭では、モジュール名として使える（`std.test`、`std.dsp.test`、std の中の `use test.{Gen}`）」「`clock.onsa` のモジュールは `kp.clock.tick()` で使える」。
  登録の文は、経路の要素がキーワードのとき（`match/x.onsa`、`match.onsa`）を E0320 の対象と見て、その note を問う。§2.2 の下ではこの前提が成り立たない。残るのは、(1) 規則に合わないファイル名の note が具体的な名前を示すか、示すなら揃えた名前がキーワードのとき（`Match.onsa` → `match`）に `_` を足すか。(2) 揃えた名前を作れない名前（`1x.onsa`、`ä.onsa`、`_.onsa`）の扱い。
- 今の実装: ファイル名の E0320 は未実装で、`nm/` の `My-File.onsa`・`Match.onsa`・`_.onsa`・`1x.onsa`・`x__y.onsa`・`ä.onsa` はどれも `test <名前> "t" ok` で 0。
  キーワードの名前のモジュール（`kw2/` の `match.onsa`、`fn.onsa`、`true.onsa`、`self/x.onsa`、`match/x.onsa`）は、`use match.{f1}`・`use fn.{f2}`・`use match.x.{f5}`・`use true.{f3}`・`use self.x.{f4}` で取り込めて 0。
  `kw4/` の `use match` の後の `match.f1()` は「expected an expression, found `.`」の E0002（S-443 の形。`kw3/` の `use dsp` の後の `dsp.f1()` は通る）。`us/` の `use _.{f}` は「expected module path, found `_`」の E0002。
- 案:
  - (a) note は規則だけを示し、名前を作らない（§2.3 の今の文のまま）。キーワードの名前は §2.2 のとおり書けるので、キーワードの扱いは要らない。揃えた名前を作れない名前も同じ note。
    実装: ファイル名の E0320（S-300、W4-14）の note の文面を一つ置くだけ。費用の要因: 書き手が新しい名前を自分で作る。
  - (b) note に揃えた名前を示す（`Match.onsa` に「`match.onsa` にする」）。揃えた名前がキーワードでもそのまま（§2.2 で書ける）。作れない名前（数字で始まる、ASCII でない、`_` だけ）は規則だけ。
    実装: 識別子の E0320 の候補の名前を作る関数（W4-04 の `names/fixes.rs` の見込み）を使う（約 10 行）。費用の要因: W4-14 が W4-04 より前なので、名前を作る関数を先に置くか、note を後で足す。
  - (c) (b) で、揃えた名前がキーワードなら末尾に `_` を足す（`match_.onsa`）。識別子の候補（S-243）と同じ形。実装: (b) に分岐を一つ。費用の要因: キーワードの名前は書けるのに、note がそれを避ける名前を勧め、§2.2 と食い違って見える。
  - (d) キーワードの名前のファイルとディレクトリを E0320 にする（`match.onsa` も。note で `match_.onsa`）。S-20・S-37・S-371 を改める案で、std の `test.onsa`・`dsp/test.onsa` の改名と、それを使う `use` の書き換えが要る（S-20 は `std.testing` への改名を退けた）。
    実装: キーワードの表との照合（約 5 行）と std・テストの書き換え。費用の要因: 決定済みの三つの S と §2.2 の文を改める。
- 他言語:
  - Python 3.14.5（手元）: `match.py` は `import match` で読める（`match` はソフトキーワード）。`import class` は SyntaxError で、`importlib.import_module("class")` なら読める。
  - rustc 1.94（確かめ）: `mod match;` は「expected identifier, found keyword `match`」。`mod r#match;` は `match.rs` を読む。
  - Go 1.27.2（手元）: ディレクトリ `type/`（`package typ`）は `import "example.com/kw/type"` で取り込めて、`typ.F()` で使える。パッケージの名前をキーワードにした `package func` は「expected 'IDENT', found 'func'」。
- 推奨と理由: (a)。確度: 中。
  - 登録の論点の前提（キーワードの要素は E0320）は、決定済みの §2.2 と S-20・S-37・S-371 で既に退けられている。キーワードの名前のファイルは規則に合うので、note の書き方を問う形が起きない。std 自身がこの規則に頼っている。
  - 規則に合わない名前の note は、規則（`snake_case`、`.` と `-` を含めない）を示せば、書き手が直せる。§2.3 は note で示す内容を「ファイル名を `snake_case` にすること」と書き、名前を示すとは書いていない。名前を作る (b)・(c) は、W4-04 の名前を作る関数を W4-14 の前に置く順の手当てが要り、作れない名前の分岐も残る。後で note に名前を足しても、何も壊れない。
  - (c) は、書ける名前（`match.onsa`）を避ける名前を勧めるので、§2.2 の規則と食い違って見える。(d) は決定済みの三つの S を改め、std の改名が要る。キーワードの名前のモジュールの使いにくさは S-443 の側の論点で、ファイルの名前の規則を変えなくても決められる。
  - 第 2 期の API（`Str`・`Map` などのモジュール）と JS / WASM の変換先には関わらない。生成するコードの名前は経路の要素の `.` を `__` に写す（§11.6）ので、キーワードの要素も他の名前と同じに写る。
  - あわせて決めること: `_` だけの名前（`_.onsa`、`_/x.onsa`）は E0320。`_` は名前でなく（§2.2）、`use` の経路に書けない（今は E0002）。数字で始まる名前と ASCII でない名前も、識別子でないので E0320（識別子の E0001 は字句のトークンの規則で、ファイル名には当たらない）。§2.3 の「`snake_case` の規則」が識別子であることを含むと一文で書く。
  - あわせて決めること: §2.3 の、規則に揃えた名前が予約語になるときの `_` の文は、識別子の修正候補だけの規則と明記する（ファイル名とディレクトリの名前は候補を出さず、キーワードの名前はそのまま書ける）。
- 影響: 仕様 §2.3（キーワードの名前のファイルとディレクトリの扱い（(a)〜(c) は決定済みの §2.2 を §2.3 からも指す、(d) は §2.2 の文も改める）、`_` だけの名前と識別子でない名前の扱い、`_` を足す文の当たる範囲。(b)・(c) では note に名前を示す文）。
  診断は E0320（新しいコードは無い）。W4-14（S-300・S-313 のファイル名とディレクトリの E0320 と同じ所）。(b)・(c) は W4-04 の名前を作る関数に頼る。(d) は std の `test.onsa`・`dsp/test.onsa` と、それを使う std・テスト・仕様の例の書き換え。
  テストベクトルの保留に関係する項目は無い。主のツリーと作業ツリーのテストに、キーワードの名前のファイルを置くものは std の二つのほかに見つけていない。
  - 決定の文の直し（下書きの付録）: S-325 の登録の文は、キーワードの名前の要素（`match.onsa`）を E0320 の対象と見ているが、§2.2 と S-20・S-37・S-371 はキーワードをモジュールの名前として書けるとする。決定の経緯に、登録の文の前提が決定済みで退けられていたことを書く。
- 独立のレビュー（2026-10-23、助言の担当の二段）: (1)・(2) と「あわせて決めること」は一致し、段 2 は確認だけ（A）に置いた。
  - 段 1: note の形は約束の外（`spec/tools.md` §4）なので、仕様の文は今のままにし、揃えた名前を添えるかは W4-04 の名前を作る関数ができた後の実装の自由とする。登録の前提（キーワードの名前は E0320）は §2.2・S-20・S-37・S-371 で退けられている（`kw2` で `use match.{f1}` などが通ることを確かめた）。`_.onsa` は `use _.{f}` が E0002 になるので名前として成り立たず、E0320 に含める。
