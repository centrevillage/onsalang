# S-835 読めないソース（不正な UTF-8 など）とマニフェストの診断のどちらを先に出すか: §18.1 の「ソースを読む前にマニフェスト全体を検査」の「読む」はファイルを開いて読むことか、構文の解析か

- 空白: §18.1 は「マニフェストを読む全てのコマンドと LSP は、ソースを読む前にマニフェスト全体（全てのターゲット）を検査し、誤りがあれば終了コード 2 で止まる」と書くが、ソースのファイルを開いて読む（UTF-8 として読めない、読み込みの入出力の誤り）ことが「読む」に入るかを書かない。
  今（W4-02 U2a2 の後）は、CLI がパッケージの全てのファイルを読んでからマニフェストを検査するので、未知のキーのある `onsa.toml` と不正な UTF-8 の `m.onsa` を持つパッケージの `onsa check --json` は、使い方の誤り「cannot read …/m.onsa: stream did not contain valid UTF-8」（終了コード 2、JSON なし）だけを出し、E1102 は出ない（97 回目に親が `P97/bin/onsa-w402u2a2` で確かめた。壊す側の `P97/w402u2a2/b/t11.py`）。
  読みは (1) ファイルを開いて読む前に検査する（読めないソースがあってもマニフェストの診断を出す） (2) 構文の解析の前に検査する（今のまま）に割れる。どちらも終了コード 2 で、修復のループの分かれ方は変わらない。

- 経緯: 97 回目（2026-11-01）、W4-02 U2a2 の壊す側（低 4）が見つけた。急ぎの見立ては後の段（出力はどちらも終了コード 2）。
