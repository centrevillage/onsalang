# S-724 失敗した名前をパターンに含む一つの `let` で、同じ `let` の中の誤り（注釈とパターンの形の違い、注釈と初期化式の型の違い）を報告するか（§18.1 の「その単位の以後を検査しない」の「以後」）

- 空白: §18.1 は、値の位置（失敗した名前を経路として書いた式とパターン）では「その単位の以後を検査しない」とし、型と宣言の位置では検査を続けるとする（S-692）。一つの `let` の中で、その名前に届く前に見つかる誤りを報告するかは書いていない。
  例: `Dd` が二度宣言した struct の名前（E0304）のとき、`let (q, Dd { a: r }): Bool = (x, x)`。読みは二つに割れる。(1) パターンを外から読み、`Dd` より前のタプルの形が注釈の `Bool` に合わない E0401 を出す。(2) `let` の全体をその名前の使用として、何も出さない。
  今の実装: fn の本体は注釈と初期化式を先に比べ、5:32 の E0401（`expected Bool, found (F32, F32)`。`Dd` より後ろの位置）を出す。flow の本体は W4-04 U4 から (2) で何も出さない（前は 8:7 のパターンの E0401）。同じ `let` が fn と flow で違う。
  再現は `target/notes/77/s724/flow_let.onsa`・`fn_let.onsa`（U4 の後と前の dev `42e2f5c`）。どちらの読みでも、`Dd` の誤り（E0304）は別の単位に報告されるので、黙って通るプログラムは無い。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。確認だけ。78 回目、第 67 組）: (a)。
  「以後」は検査の順の後で、どこまで検査するかは約束しない（S-692 の補いの A5 で決まっている読み）。今の実装で fn と flow はそろっている（W4-04 U7a から）。仕様には書かない。
  W7-04 で flow の本体の `let` の検査を移すときに、`target/notes/77/s724/fn_let.onsa` と `flow_let.onsa` が同じ出力のままであることを事例で確かめる。
- 経緯: 77 回目（2026-10-27）、W4-04 U4/b（onsa-break）の指摘 3。U4 の注釈付きの黙らせるパターンの直し（構築子に記録が無いとき注釈の当てを `check_flow_let` まで遅らせる）で flow の側の出力が変わり、親が fn の本体と比べた。
