# S-1081 予約される「種類と番号の形」の名前の範囲（§11.6 の E0304）

- 空白: §11.6 は「これらの生成する名前（種類と番号の形 `prev_0`、`hoist_0` など）と、状態の固定のフィールド名…は予約されていて、flow の入力と本体の `let` の名前に使えない（E0304）」「種類は、組込みの遅延の名前、修飾を除いた flow の名前、`par`」とする。
  読み: (1) その本体が呼ぶ flow の名前の `<名前>_<数>` だけを予約する、(2) 見える全ての flow の名前の形を予約する、(3) 組込みの遅延・`par`・`hoist` の形だけを予約し、flow の名前の形は修飾で重ならない限り使える（出力の式のノードは修飾しないので、`let lp_0` と出力の中の `lp~` が重なる）。通るプログラムが変わる。
  今: `let prev_0`、入力 `poisoned`、`pub flow hoist`、`flow lp` を呼ぶ本体の `let lp_0` が通る。組 A の仮の案: W7-03 の予約の名前の単位で (3) の形を E0304 にし、flow の名前の形には `SPEC-GAP` の印。
- 決定（2026-11-18、利用者、165 回目、第 110 組。段 1（onsa-advisor）と下書きがどちらも生成する側を書けない形にする案を選び、利用者が「名前の重複を避けるルールはシンプルで破綻の起きづらいやり方」「ルールが揃っている方が良い。余計な例外が不要」として、固定の名前と巻き上げも含めて採った）: 族の規則（S-1138）から決まる。種類と番号の形（`prev_0`・`lp_0`・`par_0`・`hoist_0`）は予約しない（生成する側が `_out`・`_hoist` で重ならない）。予約で拒む読みの細部（分解の束縛の名前、番号の書き方、E0320 の候補の手当て）は要らない。上の補いの「固定の名前の予約はどの読みでも残る」も、固定の欄を書けない形にしたので当たらなくなった。
- 経緯: 157 回目、2026-11-16、X-26 の W7 の見積もり（組 A）と仕分けの段 1（onsa-advisor）が挙げ、利用者が一覧で登録を了承した（X26-26）。
- 補い（2026-11-18、親）: 165 回目（W7-03 U0 の設計メモ、onsa-impl）: 予約で拒む読みでは、細部が二つ要る。(i) 予約に分解する `let` の束縛の名前を含むか（`let (prev_0, q) = …` と出力の `prev~(x)` は今、同名の欄が二つ）、(ii) 番号の書き方（`prev_01`・`prev_00` も予約するか、生成しうる先頭に 0 の無い十進だけか）。生成する側を書けない形にする読みでは、どちらも要らない。族の規則は S-1138。
- 補い（2026-11-18、親）: 165 回目、第 110 組の段 1（onsa-advisor）: 予約で拒む読みでは、E0320 の修正候補が予約の名前を作る形の手当ても要る（`let prev__0 = prev~(x)` の候補は `prev_0`、`let _poisoned` の候補は `poisoned`。§2.3 は E0304 になる名前を候補にしない）。固定の名前の予約はどの読みでも残るので、`_poisoned` → `poisoned` の候補を止める手当ては W7-03 で要る。
