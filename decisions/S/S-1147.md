# S-1147 細部: `par~ i in a ..= b` の個数 `b - a + 1` が `U32` に収まらないとき（`par~ i in 0 ..= 4294967295`）のコード（E0808 か E0409）

- 空白: §11.5 は `par~ i in a ..= b { e }` を `N = b - a + 1` 個並べるとし、結果は `[T; N]`（§4.2 の大きさは `U32`）。`par~ i in 0 ..= 4294967295 { x }` は `N = 2^32` で `U32` に収まらない。
  これを値の範囲の誤り E0808（`par~` の端の検査）にするか、大きさの上限の E0409（W9-04、それまで E0200）にするかが書かれていない。登録時は `..=` の `par~` が全て E0200 だった（`InclusiveRangePar`。W7-14 U3 `e55efe54` で外し、今は仮の扱いの E0808）。
  誤りのプログラムのコードだけが変わり、通るプログラムは変わらない。`4294967295 ..= 4294967295` は `N = 1` で通る形である（排他の上端 `b + 1` が `U32` を溢れるのは実装の扱いで、W7-14 の単位の票に書く）。
  再現は `target/notes/166/w714/memo/probe/gaps.txt` の `g4_closed_full`・`g4_closed_max`。
  仮の扱い: 個数が `U32` に収まらないときは E0808。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認だけ。「(A)と(B1)はS-1148以外OKです」）: 仮の扱いのとおり。個数が `U32` に収まらない複製は E0808（N の上限の先例 S-1216・S-1089 と同じコード）
  突き合わせ: 助言の担当が固定のバイナリ `onsa-d02ddee` で再現し、仮の扱いが今の挙動と合い、既決とぶつからないことを確かめた（`target/notes/189/reports/onsa-advisor-a5d87f2cf05f2cfce-001.md`）。
