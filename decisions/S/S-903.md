# S-903 struct のパターンで残りのフィールドを無視する印（S-697 から分けた）

- 空白: `S-697` の下書きが分けた論点である。§7 の struct のパターンは全てのフィールドを書き、見えないフィールドが残るパターンは E0303 である。残りのフィールドを無視する印を足すかが書かれていない。
- 決定: 決定（2026-11-06、利用者。117 回目）: (q) 並びの最後の `_`（`Item { x: a, _ }`、`Ring { data: d, _ }`）は残りのフィールドを無視する。見えないフィールドが残ってもよい。途中を省くのと順の入れ替えは許し、フィールドを一つも書かない `Ring { _ }` も書ける。残るフィールドの無い `_` は E0410（外す候補）。
  `..` は E0020 のままで、見えないフィールドが残れば候補は `..` を `_` に置き換える形、見えるフィールドだけが残れば今の `_` の並びである。fmt は `..` と同じ扱いで、要素に数えず、後ろに `,` を置かない。E0020 の note は「`_` を書かないパターンは落ちる」の文に改める。字はリテラルの `...` と分ける（埋めると捨てるで意味が違う）。
- 経緯: 117 回目（2026-11-06）、第 88 組の下書き（onsa-gap）が S-697 から分けた。独立のレビューは S-697 の結論を知らずに (p) 何も足さないを勧めた。S-697 が (b) になると、`priv` のある型をリテラルで作れて同じ形で分解できない非対称ができるので、親が (q) を勧め、利用者が (q) を選んだ。S-697 の 70 回目の材料にもこの形がある。
