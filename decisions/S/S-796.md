# S-796 `inout` の引数の場所から派生した借用束縛を、同じ呼び出しの借用の引数に渡す形（`match o { Some(b) => f(b, inout o) }`）

- 空白: §5.2 は、同じ変数を一つの呼び出しで二度 `inout` に渡す形と、`inout` と借用の両方に渡す形（`h(x, inout x)`）を E0702 とし、「引数は全て評価してから呼ぶので、引数の順によらない」とする（S-787 で `move` の場所との重なりも E0702）。
  §7 は、変更した場所と重なる Copy でない束縛を以後使えない（E0704）とする。`inout` の引数の場所から派生した借用束縛（`match o` の腕の `b`）を、同じ呼び出しの借用の引数に渡す形には触れない。
  `match o { Some(b) => f(b, inout o), … }` と `match o { Some(b) => g(inout o, b), … }`（`o: Option[Buf[F32]]` の `var`）は、dev（`9804880`）ではどちらも通る。呼び出しの間に呼び先が `o` を書き換えると、`b` は破棄済みの記憶域を指しうる（R-118 と同じ害）。
  W4-07 U3b の新しい modes は引数を左から歩くので、`g(inout o, b)` は §7 の E0704、`f(b, inout o)` は通る（`SPEC-GAP(S-796)`）。再現は `target/notes/87/derived_inout.onsa`。
  読み: (1) `b` の場所は `o` と重なるので、順によらず E0702（後の引数の位置、note は前の引数）。(2) §7 の「以後」で、`inout o` より後の引数の `b` だけ E0704。(3) 引数は呼ぶ前に評価するので、どちらも通る。
  親の読み（確認だけの案）: (1)。派生した借用束縛は元の場所の一部の借用で、§5.2 の「`inout` と借用の両方に渡す」に当たる。順によらない E0702 は §5.2 の文と S-787 の重なりの読みに合い、(2) は順に頼り、(3) は害を通す。
  U4 の E0702 で、引数の場所を集めるときに派生した借用束縛を元の場所（U3b の索引 `Deps` の場所）に置き換えて重なりを見る。仕様の 5.2 の E0702 の段落に「派生した借用束縛（§5.4）は元の場所として数える」と一句足す案。
- 決定: 決定（2026-10-30、利用者。87 回目。独立のレビュー（onsa-advisor の段 1、想定漏れの表 29 形と補い）と親の読みが一致）: (1)。Copy でない借用束縛とその経路は、派生元の場所として重なりを見るので、順によらず E0702（位置は後の引数、note は前の引数と束縛の位置、候補なし）。
  腕の束縛の場所は対象の場所にパターンのタプル・struct の経路を加えたもので、列挙子のペイロードは対象の全体。Copy の束縛は重ならない。呼び出しの直接の引数による変更で束縛が使えなくなるのは呼び出しの後（値を作るだけの引数 `g1(inout o, len_of(b))` は通る）。仕様 §5.2（70 行の後）、§7（53 行の後）。
  担う作業: W4-07 U4（派生した束縛を派生元の場所に置き換える、直接の引数の無効化を呼び出しの後に）、W4-08（`Span` の束縛と入れ子の `inout` に広げる）、W4-09・W4-10（E0715 も解決した場所で）。再現と表は `target/notes/87/s796/`。
- 経緯: 87 回目（2026-10-30）、W4-07 U3b/i（onsa-impl）が空白として報告した。親が dev のバイナリで再現して登録した。
