- 案: (a) 末尾で決める。初期化式の束縛の種類は、括弧を外し、`if`・`match`・ブロック式は発散しない全ての末尾（入れ子も辿る）で決める。全ての末尾が借用の行なら借用、一つでも所有の行なら所有。
  所有のときは、各末尾を所有の束縛の初期化として検査する（借用の Dup は複製、借用の Affine は E0711、ローカルの Affine は `move` の挿入を候補にする E0711。S-100 の腕の検査と同じ）。
  `for`・`match` の見出し（`move` の無いとき）は、借用の行を「場所か静的な値」として同じ規則で決める。借用のとき、派生元は末尾の場所の並びになる（E0715 と S-42 の無効化は並びの各々を見る）。
  実装: 束縛の状態の関数に末尾を集める再帰（括弧、`if`・`match`・ブロック、発散する末尾を除く）と「全てが借用の行か」の判定（約 20〜30 行）、派生元を並びにする所（約 10 行）。事例は約 8 件。費用の要因: 派生元が一つの場所でなく並びになり、W4-09 の E0715 と W4-10 の重なりが並びを回る。
  (b) 表の行のまま。括弧は中身と同じに読み、`if`・`match`・ブロック式は所有の行に入れる（S-589 の読み (2)）。見出しのブロックは場所でない対象として所有。
  実装: 表を写す関数の追加は無い。事例は約 4 件（E0711 と E0601 を確かめる）。費用の要因: `let t = x` と `let t = { x }` で束縛の種類が変わる。S-100 の「各腕を `let y = <腕の値>` と同じに扱う」が借用の腕で成り立たないので、§5.2 に「束縛は所有」と一文足す。

- 他言語: Rust 1.94.1（手元、`r1.rs`）: `a`・`b` が `&String` のとき `let y = if c { a } else { b }` と `let z = { a }` は参照の値で、元を動かさない。`String` のときは `a` か `b` を動かす。
  C++（Apple clang 21、`c2.cpp`）: `const std::string& y = c ? a : b` は両方が lvalue なので `a` を指し（`&y == &a` が 1）、`c ? a : std::string("z")` は一時の値の複製を指す（0）。末尾が混ざると複製になる (a) と同じ形（[expr.cond]/4〜7）。
  Swift 6.3.1（手元、`s4.swift`、`-emit-sil`）: `borrowing` の非 Copy の引数は `let y = c ? a : b` も `let y = a` も「'a' is borrowed and cannot be consumed」で、局所の借用束縛が無い。
