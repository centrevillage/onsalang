# S-938 前置の `~` が次のトークンに接しない形（`~ x`）の診断と候補

- 空白: 行 `faust_bit_not` の例は全て接する形（`~m`、`~(m)`、`m & ~(m + 1)`）で、接しない `~ x` が書かれていない。§2.5 は前置の `-` / `!` と被演算子の間の空白を E0020 とし、`- 1 =>` は「前置の記号の後の空白の誤りが残るので、候補を作らない」、`+ 1` は「`+` と後ろの空白は除く一つの形なので候補を作れる」とする。
  読み: (1) 行に無い形で、候補なしの E0002（今の出力）。(2) E0020 で、`~` と後ろの空白を `!` に置き換える候補が 1 つ（`+ 1` の先例）。(3) E0020 だが、`! x` では空白の E0020 が残るので候補なし（`- 1` の先例）。通るプログラムは変わらない。
  再現は `let b = ~ a` で、今は E0002「expected an expression, found `~`」、候補 0 件。
  仮の扱い: 今の出力のまま。W5-11 U1 の事例はこの形を持たない（`tests/spec/fixes/fix_keeps_point_and_tilde.onsa` の頭の注）。
- 決定: 決定（2026-11-08、利用者。126 回目）: (2)。式の位置の前置の `~` と被演算子の間に同じ行の空白がある形（`let b = ~ a`）は、接する `~a` と同じ `faust_bit_not` の行の E0020 で、修正候補は `~` と空白を `!` に置き換える一つの編集（`!a`、当てた後の誤りは 0）。
  前置の位置の `~` は状態の印にも FAUST の二項の `~` にも読めず、意図はビット反転に一つに決まる。`+ 1`（§2.5）と `- - x`（§3）の先例と同じく、記号と空白を一つで直す。`if` / `match` の後の `~` の `!` の候補を被演算子に接する形に限る規則（S-385）は変えない。`_` の前と `~(…_…)` の FAUST の帰還の形（S-486）も今のまま。
  §2.6 に書いた。実装は W5-11 U10d（`foreign/faust.rs` の `faust_bit_not` で同じ行の空白を許し、候補の範囲に空白を含める。約 8〜12 行と事例、`spec/foreign-forms.toml` の行の例）。
- 経緯: 121 回目（2026-11-07）、W5-11 U1/t（onsa-test）が挙げた。親の票が候補の残る形に誤って挙げた形で、今は候補が無い。急ぎは後の段である。
