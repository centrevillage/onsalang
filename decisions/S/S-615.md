# S-615 静的な Shared 型（中身が静的なオブジェクトだけと型で分かる版、仮に `static Str`）を言語で特別扱いにするか

- 空白: S-610 と S-613 の静的な値と破棄の要らないリテラルは束縛ごとの判定で、`var`、struct のフィールド、呼び出しの結果、状態には届かない（S-613 の範囲の外のまとめの L1・L2・L5、`tasks/phase2.md`）。Shared 型の値が静的なオブジェクトだけを指すことを、型で表す手段が無い。
  利用者（58 回目）: 「文字列に限らず、「静的な Shared 型」は言語的に特別扱いにする仕組みがあると、後々楽になるような気がします」。親が言い直した範囲を利用者が了承した（「その読みであっています」）:
  どの Shared 型（`Str`、`Bytes`、`Str` を持つ配列や struct）にも、中身が静的なオブジェクトだけと型で分かる版（仮に `static Str`）を用意する。値は静的な値（補間の無いリテラル、`const`）からだけ作れ、複製も破棄も何もしないので Copy と同じに扱い、`var`・フィールド・flow の状態・返り値に置け、`Str` を受ける所へ値を変えずに渡せる。
  例: `const NAMES: [static Str; 2] = ["warm", "bright"]`、`pub struct Preset { name: static Str, gain: F32 }`（Copy の struct）。
  `rt fn rename(inout p: Preset) { p.name = "mix" }`、`rt fn name_of(i: U32) -> static Str { NAMES[i] }`、`var mode: static Str = "a"; mode = "b"`。
  入れるか、入れるなら書き方（型の修飾か別の型か）、総称との関係（`[T: Copy]` に渡せるか）、種の表（§4.6）、変換の規則、後端の量と時期（第 1 期は `Str` の降下が E0200）、S-612（置き場所）・S-87（`Str` の `const`）・S-614（容量付きの文字列。L5 のプリセット名で重なる）との関係が決まっていない。
  S-613 の下書き（`decisions/S/S-613.draft.md`）の案 (e)（静的な文字列の型）はこれを文字列に絞った形である。
- 決定:
- 経緯: 58 回目（2026-10-24）、S-613 の範囲の外のまとめの L5 を S-614 で扱うと決めたときに、利用者が挙げた。利用者の言い方は感覚（「気がします」）で、決める材料は下書きでそろえる。下書きは S-614 の独立のレビューの後（空白の流れの枠）。
- 経緯（2026-10-24、親）: S-614（2026-10-24）で `FixedStr[N]` が決まった。L5 のプリセット名は両方で書けるが補い合う関係（`FixedStr` は値ごとに `N + 4` バイトで実行時の値も持て、静的な Shared 型はリテラルと `const` からだけで容量が要らない）。この S の結果で S-614 を書き換えない。
