# S-615 静的な Shared 型（中身が静的なオブジェクトだけと型で分かる版、仮に `static Str`）を言語で特別扱いにするか

- 空白: S-610 と S-613 の静的な値と破棄の要らないリテラルは束縛ごとの判定で、`var`、struct のフィールド、呼び出しの結果、状態には届かない（S-613 の範囲の外のまとめの L1・L2・L5、`tasks/phase2.md`）。Shared 型の値が静的なオブジェクトだけを指すことを、型で表す手段が無い。
  利用者（58 回目）: 「文字列に限らず、「静的な Shared 型」は言語的に特別扱いにする仕組みがあると、後々楽になるような気がします」。親が言い直した範囲を利用者が了承した（「その読みであっています」）:
  どの Shared 型（`Str`、`Bytes`、`Str` を持つ配列や struct）にも、中身が静的なオブジェクトだけと型で分かる版（仮に `static Str`）を用意する。値は静的な値（補間の無いリテラル、`const`）からだけ作れ、複製も破棄も何もしないので Copy と同じに扱い、`var`・フィールド・flow の状態・返り値に置け、`Str` を受ける所へ値を変えずに渡せる。
  例: `const NAMES: [static Str; 2] = ["warm", "bright"]`、`pub struct Preset { name: static Str, gain: F32 }`（Copy の struct）。
  `rt fn rename(inout p: Preset) { p.name = "mix" }`、`rt fn name_of(i: U32) -> static Str { NAMES[i] }`、`var mode: static Str = "a"; mode = "b"`。
  入れるか、入れるなら書き方（型の修飾か別の型か）、総称との関係（`[T: Copy]` に渡せるか）、種の表（§4.6）、変換の規則、後端の量と時期（第 1 期は `Str` の降下が E0200）、S-612（置き場所）・S-87（`Str` の `const`）・S-614（容量付きの文字列。L5 のプリセット名で重なる）との関係が決まっていない。
  S-613 の下書き（`decisions/S/S-613.draft.md`）の案 (e)（静的な文字列の型）はこれを文字列に絞った形である。
- 決定: 決定（2026-10-24、利用者が了承。58 回目、第 48 組）: 静的なものだけを指す印は今は入れない（論点 1 の (iv)、論点 9 の (t3)）。入れるときの方向は、型ではなく束縛の状態（S-610・S-613 の静的な値）と同じ側の印で、境界（フィールド、返り値、`var`、引数）に書き、本体で推論する（クロックを型から外して `x: F32 at sample` と flow の解析の属性にした S-102 と同じ形）。
  理由（利用者）: 静的の状態を型で表すと、暗黙の型変換の例外になる。flow のイベントレートも、初期案では型だったが、後に型とは別のクロックとして扱いが分かれた。静的領域に置かれる印も、既存の型に収める必要はない。
  書き方はキーワード `static` で、属性にはしない。理由（利用者）: 属性はプログラムの構造を変えない（コード生成用の注釈）約束がある。`static` は今キーワードとして予約し、構文としては受け付けない（`clock`・`ser` と同じく E0200。項目の見出しの前の `static fn` は §18.1 の他の言語の語の読み方のまま E0002）。
  理由（利用者）: C・C++ の書き手は自然に変数名から避け、他の言語の書き手も変数名に使うのを避けるはずなので、閉じても影響が少ない。親は、C++・Java・C# のフィールドの `static` が全てのインスタンスで共有するメンバと読まれうることを挙げた（入れるときの note の候補）。
  入れる契機は、`FixedStr`（S-614）と第 2 期の L1〜L3（`tasks/phase2.md`）で書けない実例（容量を決めない UTF-8 の名前を rt の状態・`var`・フィールドに持つ、静的なものだけを受けると関数の境界で約束する）が出たとき。型にする案の代償と参考の形は下書き `S-615.draft.md` に残す。仕様 §2.2、§19.1
  補い（2026-10-24、利用者が ID を挙げて了承「E1-4: OKです」）: E1 型にする案の参考の形（葉だけ、リテラルは期待の型、flow の状態に置かない、など）は決定に書かず下書きに残す。E2 新しい S-620（`static NAME: T = e` の項目の診断）。
  E3 新しい S-621（§12.8 の `Str`・`Bytes`・`Array` の中身の配置、第 2 期の前）。
  E4 W4-16 の事例に静的な値の添字（`let y = ["a", "bc"][i]`）。`let y = NAMES[i]`（`const`）は、第 1 期は `const` の宣言が §6.6 の E0200（Shared を含む型の `const`）で止まるので、第 2 期の事例（`tasks/phase2.md`。58 回目の X-8 の第二弾で親の誤りを改め、利用者が了承）。
- 経緯: 58 回目（2026-10-24）、S-613 の範囲の外のまとめの L5 を S-614 で扱うと決めたときに、利用者が挙げた。利用者の言い方は感覚（「気がします」）で、決める材料は下書きでそろえる。下書きは S-614 の独立のレビューの後（空白の流れの枠）。
  58 回目（2026-10-24）、第 48 組（族「静的な値の範囲」、下書き `S-615.draft.md`、助言の担当の二段）。下書きと段 1・段 2 は (iv) 入れない（足すなら `use` で取り込む型）で一致し、段 2 が利用者の向きと違うので利用者の判断にした。利用者が型でなく別の次元の印を挙げ、属性でなくキーワードとし、`static` の予約を選んだ（親の推奨は予約しない (a) だった）。
- 経緯（2026-10-24、親）: S-614（2026-10-24）で `FixedStr[N]` が決まった。L5 のプリセット名は両方で書けるが補い合う関係（`FixedStr` は値ごとに `N + 4` バイトで実行時の値も持て、静的な Shared 型はリテラルと `const` からだけで容量が要らない）。この S の結果で S-614 を書き換えない。
