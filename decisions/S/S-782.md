# S-782 種を求める歩数の上限が仕様に無く、上限に当たった型を Affine とみなす扱い（R-30、W4-16 U3）で、構造からは Copy の正しいプログラムが E0711 になる。合否が処理系の内部の値で決まる

- 空白: §4.4 は型の深さと大きさの上限を仕様で固定する（「上限が処理系で違うと、ブラウザの IDE と CLI で同じファイルの合否が変わるので、仕様で固定する」）。種を求める歩きの歩数の上限（実装の `walk.rs` の `STEPS` = 2^20）は仕様に無い。
  W4-16 U3 の R-30 の実装は、種の答えが歩数の上限で出ないときだけ型を Affine とみなす（誤りの型・輪などは §18.1 で黙る）。そのため、構造からは Copy の型でも、歩数の上限に当たると E0711・E0704・E0712 になる。
  形（`target/notes/85/w416u3/dbl_param_12.onsa`）: `G_k[T] { x: G_{k-1}[(T, T)], y: G_{k-1}[Option[T]] }` を 12 段（11 段から）並べ、`pub fn f[T: Copy](g: G12[T]) -> (G12[T], G12[T]) { (g, g) }` が E0711「`g` is borrowed here and Affine」（U1b の後は通った）。
  開いた型のタプルの木が覚えられず、歩数が段ごとに約 3 倍になる。診断は「Affine」と言うが、書き手が直せる形でなく、`move` を足しても E0704 になる。
  読み: (1) 歩数の上限も仕様で固定し、上限を超えたときの扱いを定義する。(2) 上限を超えたときの扱い（Affine とみなす）だけを仕様に書き、上限の値は実装の内部とする。(3) 覚える対象を増やし（タプルの木など）、構造から求まる種に上限で当たらないようにする。どれでも、上限に当たったときの診断の文面（種が求まらないことを言う note）を決める。
- 決定: 決定（2026-11-07、利用者が ID を挙げて了承。121 回目、第 90 組。下書きと独立のレビュー（段 1）が一致）: (d)。種と破棄の要否を宣言ごとの要約（宣言の基底と、値として含む型パラメータの集まり）で求め、この二つの問いから歩数の上限 `STEPS` を無くす。仕様の文は変えない（§4.6 の「全ての型は構造から」のとおりになる）。上限が無いことは約束に書かない。
  あわせて決めたこと: 破棄の要否も同じ要約で求めるので、歩数で答えなしを「要らない」と読む穴が閉じる（`needs_alloc_drop`・`rest_drops`、`rt` の E0901 と効果の E0601 が 11 段から黙る形）。`kind_in_body` の「歩数で答えが出ないときだけ Affine」を消す（R-30 の決定のうち残るのは `?Dup` を境界で読む部分）。
  自分を含む型と誤りの型が答えなしで黙るのは今のまま。配置は歩きと `STEPS` に残す（S-939）。第 2 期の `impl Drop` は宣言の単位で足す（§6.3 で特定の具体化だけの形は無い）。
  無くすのは型を展開して辿る手順の数の上限で、§4.4 の型の深さ 256 と大きさ 4096（S-264）は変えない。
  理由: 歩数の上限の目的は検査の時間を抑えることで、言語の規則でない。種も破棄の要否も引数の種だけで決まるので、指数の歩きそのものが要らない。正しいプログラムが誤りになる形と、`rt` の検査が黙って外れる形が両方閉じ、規則も例外も増えない。
