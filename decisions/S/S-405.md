# S-405 前置の `+`

- 空白: 前置の `+`（`let a = +1`、`[1, +1]`、`two(+x, 1)`）。§3.1 に前置の `+` は無く、今は E0002「expected an expression, found `+`」で候補なし。
  Python・Node・clang・swiftc は `[1, +1]` を通し（値は `[1, 1]`）、rustc は「leading `+` is not supported」と help「try removing the `+`」。読みは割れない（値を変えない余分）。E0020 で `+` を除く候補にするか、文法に入れて fmt が外すか。
  S-398 が `+` を含めない形に決まったときは、`[1 +1]`（二項の `+` の非対称な空白）をこの S の後に同じ規則に入れるかもあわせて決める。第 20 組の下書きで見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (a) と (ii) を了承。下書きと Fable が一致、第 23 組。利用者の注意: この修正は `-`（S-398）に続いて二つ目なので、`-` の所との食い違いに気を付ける）: (a) 前置の `+`（式、属性の引数、パターン）は E0020 の新しい行で、候補は `+` と後ろの空白を除く形。
  行頭の `+` で前の行が被演算子で終わる形は S-124 の行が先。(ii) 二項の非対称な空白の `+`（`[1 +1]`、`two(a +b, 1)`、`let c = a +b`）は S-398 の行に入れ、候補は両側に空白を置いた形と、式を要素とする並びの中では `,` の挿入と `+` の削除を一つにした形（`[1, 1]`）。
  細部（2026-10-10、利用者が了承。下書きの付録と Fable の補足 4）: 括弧の中の行頭の被演算子に接する `+b`（`two(a` 改行 `+b, 1)`、S-370）は、前の行の末尾へ移す形に加えて、二つ目に `,` の挿入と `+` の削除を一つにした形（`two(a, b, 1)`）を並べる（空白のある `+ b` は移す形だけのまま）。
  前の腕の `,` を省いた行頭の `+1` と空白のある `+ 1`（`0 => { 1 }` 改行 `+1 => 2,`・`+ 1 => 2,`、S-386）は E0002 で、候補は `,` の挿入と、`+` と後ろの空白の削除を一つにした形（空白のある `+ 1` は、2026-10-10 に利用者が親の推奨の (1) を了承。`+` と後ろの空白は (a) の一つの直しなので、`,` を入れても別の誤りが残る `- 1` の候補なしと違う。S-386 は変えない）。
  仕様 §3.1、§2.5。実装は W3-06 の単位 2（単位 1b の `SPEC-GAP(S-405)` を外す）
