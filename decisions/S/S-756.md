# S-756 総称の `impl` の対象が、型の宣言の型パラメータの境界を満たさない形（`struct N[T: Num]` の後の `impl[T] N[T]`）: 見出しの E0416 にするか、`impl` の型パラメータが型の宣言の境界を受け継ぐか

- 空白: §6.2 は、総称の `impl` の対象の型引数を `impl` の型パラメータを一度ずつ並べたものに限る（E0307）。§4.5 は型の宣言の型パラメータに境界を書け（`struct N[T: Num]`）、R-37 の決定は署名の型の整形性を位置と型構成子の組で判定し、型引数が境界を満たさない `N[Bool]` を誤りにする（E0416）。§18.1 は `impl` の見出しを型の位置に数える。
  `struct N[T: Num]` の後の `impl[T] N[T]`（`impl` の `T` に `Num` が無い）で、見出しが誤りか、`impl` の `T` が型の宣言の境界を受け継ぐかは書いていない。
  今: 見出しに何も出ず、`impl` の `T` は `Num` を持たない。メンバの `self.a + self.a` に E0401「`+` is not defined for `T` (it needs `Num`; §3.2)」が出て、`self.a` を返すだけのメンバは通る。
  読み: (a) 見出しの E0416（境界は `impl[T: Num]` と書く）。見出しの誤りなので `impl` の全体が一つの単位になる。今通る `impl[T] N[T] { pub fn get(self) -> T { self.a } }` が誤りになる。
  (b) 受け継ぐ（型の宣言の境界が `impl` の `T` に含まれる）。今の E0401 が消え、メンバで `+` が使える。(c) 今のまま（見出しを誤りにせず、受け継がない）。
  再現は `target/notes/81/u4/new3.onsa`。
- 決定: 決定（2026-10-29、利用者。81 回目、第 73 組。下書きと独立のレビューの推奨が一致）: (a)。
  `impl` の対象の型引数は、型の宣言の型パラメータの要求（境界と暗黙の `Dup`）を満たさなければ E0416 で、見出しの誤り（`impl` の全体が一つの単位、メンバは検査しない、§18.1）。`impl` の型パラメータが満たすかは `impl` の `[ ]` に書いた境界だけで決まり、型の宣言の境界は受け継がない（関数の署名の `fn f[T](x: N[T])` と同じ判定）。
  候補は出さない（意図が一つに決まらない。関数の署名の E0416 と揃える）。note で型の宣言の境界を位置付きで示す。型の宣言の境界と `impl` の境界の失敗した名前は未知の境界で判定しない（S-689）。`struct W[T]` の後の `impl[T: ?Dup] W[T]` も E0416。メンバは S-748 のとおり `.` の空間に数える。
  理由: 関数の署名と同じ一つの規則（R-37）で例外が無く、直す所（`impl` の `[ ]`）を一回で示す。誤りにする方が厳しく、後で受け継ぐ規則に緩めても既存のプログラムを壊さない（逆は戻せない）。今通る境界に頼らないメンバだけの `impl` が誤りになるが、`tests/`・std・`examples/` に当たる形は無い。
  仕様は §4.5 に、型の位置の型引数が型の宣言の要求を満たさない E0416 の一般の文（R-37 の反映で抜けていた文）と、§6.2 の対象の型引数の文の後に一句。実装は W4-05 U4a（整形性の段の根に `impl` の対象。約 0〜3 行）。事例は `n01`・`n02`・`n05`・`n06` の形を一つずつの単位に、正例は `n03`・`n04`・`n07`（`target/notes/81/g73/draft.md` の形の表）。
