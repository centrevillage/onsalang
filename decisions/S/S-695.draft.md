# S-695 モジュールが自分の中の flow の名前空間から取り込む `use`（`main.onsa` の `use main.f.{process_inplace}`）を、S-679 の自分を取り込む `use` として E0302 にするか

- 決定済みで戻さないもの: 第 64 組の下書きの「決定済みで戻さないもの」と「形の表」の S-695 の表（写しは `target/notes/74/g64/draft.md`。表の行の番号はその表のもの）。
- 論点:
  - 出所と目的: S-679 は、モジュールが自分自身を取り込む `use`（`main.onsa` の `use main`）を E0302 にした（候補なし、note「自分のモジュールの項目は名前だけで書く」）。
    S-673 の (d) で本体の `main.other()` の候補が `main.` を外す形になり、自分を取り込む `use` を要する書き方が無くなったのがきっかけで、自分の項目の二つ目の書き方（`main.other()`）を作らない。
    子（`use main.inner`）と親（`use dsp`）は通すとし、S-685 は並びの中の自分の要素だけを失敗にした。
  - §15.1 は「自分のモジュールも取り込めない」とし、自分のモジュールの中のものを経路で取り込む `use` を書かない。自分の項目（`use main.{other}`）と自分の flow（`use main.f`）は、項目と同じ名前の束縛を作るので §15.1 の E0304 になる。
    名前の重ならない flow の名前空間の項目（`use main.f.{process_inplace}`）だけが、どちらの規則にも当たらない。読みは (1) モジュールそのものでないので通る、(2) 自分の中を経路で取り込むので S-679 と同じく E0302、に割れる。
- 今の実装: 表の 4 行は通る（q01・q02・q08）。1 行は S-679 の E0302、2・3・6 行は E0304。仮の扱いの印は `names/imports.rs` の 113 行の `SPEC-GAP(S-695)`（自分のモジュールそのものだけを E0302 にする所）。
- 案:
  - (a) 通す（今のまま）。S-679 は取り込む先がモジュールそのもののときだけで、取り込める一覧（§15.1）は取り込む側のモジュールによらない。
  - (b) E0302。`use` の経路が自分のモジュールに着いた後、子モジュールでないもの（項目、flow の名前空間、その項目）を取り込む要素は、S-679 と同じ E0302 で、候補は無く、note で自分の中のものは `use` 無しで書くこと（`f.process_inplace`）を示す。
    2・3 行は E0304 から E0302 に変わる（束縛ができないので重なりも無い）。並びの他の要素は S-685 のとおり取り込む。
  - 書き方の数: (a) は自分の flow の項目に二つの書き方（`use` の後の `process_inplace(…)` と `use` 無しの `f.process_inplace(…)`）を残す。(b) は自分の中のものを `use` 無しの一つの書き方にする（S-679 の自分を取り込む `use` を止めた筋と同じ）。
  - 一回の検査で出る誤り: (a) は 0 件。(b) は `use` の行に一つの E0302 で、使う所（`process_inplace(…)`）は失敗した名前で黙る。
    書き手が `use` を消すだけなら、次の検査で使う所ごとの E0302（候補なし、S-258）が出て二回になる。note のとおり使う所を `f.process_inplace(…)` に直せば一回で終わる。
  - 通るプログラム: (b) は今は通る形を止める向きで、後で許しても壊れない（S-679 と同じ）。(a) で通した形を後で止めると壊れる。
  - 実装: (a) は 0 行（印を消し、仕様に一文）。(b) は `resolve_import` の自分の判定を「経路の最後のモジュールが自分で、取り込むものが子モジュールでない」に広げる（約 +8、note の文 +2）。
    (b) では、W4-03 の事例 `use_flow_own_item_in_signature`・`use_flow_own_item_signature_kind`（8 ファイル）を、flow を別のモジュールに移して書き直す。後の段の手当ては、どちらも無い。
- 他言語:
  - rustc 1.94.1: モジュール `m` の中の `use crate::m::f::process_inplace;`（自分の中の子の項目）と、`o` の中の `use crate::o;`（自分自身）は通る。自分の関数と同じ名前を取り込む `n` の中の `use crate::n::g;` は E0255「the name `g` is defined multiple times」。
  - Python 3.14.5: `pkg/m.py` の中で、定義の後に書いた `from pkg.m import f as f2` は実行時に通る。
  - Swift（モジュールはターゲットの単位で、ファイルが自分を取り込む形が無い）、TypeScript: 未確認。
- 推奨と理由: (a)。確度: 中。
  - (a) は規則を足さない。§15.1 の取り込める一覧（flow の名前空間の項目）はどのモジュールから取り込むかによらず、S-679 は字面どおりモジュールそのものに当たる。他のモジュールの flow から `use dsp.synth.voice.{State}` で取り込めるのと同じ形が、自分の flow にも書ける。
  - 読みは一つで、取り込む名前は自分の flow の生成項目を指すだけである。名前の重なりは §15.1 の E0304 が既に止めている（2・3・6 行）。

  - あわせて決めること: §15.1 の「自分のモジュールも取り込めない」の後に、自分のモジュールの中の flow の名前空間の項目は他のモジュールと同じく取り込めること（`use main.f.{process_inplace}`）を一文で書き、印を消す。
