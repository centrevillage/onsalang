# S-1066 細部: 値を介さない型の輪（`A { b: Buf[B] }`・`B { a: Buf[A] }`）で、どちらのフィールドを読めなかった部分とし、E0416 を幾つ出すか

- 空白: §18.1 は、読めなかった部分（フィールドなど）を誤りの型として扱い、それを使う側には診断を出さないとする。値を介さない型の輪（`A { b: Buf[B] }`・`B { a: Buf[A] }`。`Buf` の要素は Copy、§4.5）では、どちらのフィールドの誤りが先かで、もう一方が「使う側」になる。どちらを読めなかった部分とするか、E0416 を幾つ出すかを書かない。誤りのあるプログラムだけの形で、通るプログラムは変わらない。
  今（W6-04 U5 の後）: 宣言の依存の順（`sig/wellformed.rs::types_first`、輪の中は書いた順）で先に判定した方だけが E0416 で、もう一方はそれを誤りの型として読んで黙る。どちらの順に書いても E0416 は一件で、書いた順で先の宣言の位置（1:23）。文面の型の名前は順で変わる。U5 の前のバイナリも同じ。実装に `SPEC-GAP(NEW)` の印（`types_first`）。
  再現: `target/notes/153/w604/u5i/extra_cases.txt` の `cycle_ab`・`cycle_ba`。
  読み: (1) 先に判定した方だけが誤り、もう一方は黙る（今の実装。§18.1 の宣言をまたぐ循環の「集まりの宣言のうち診断の並べ方で最初のもの」と同じ向き） (2) 両方とも、相手の書いたフィールドで判定して報告する。
  仮の扱い: (1)。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-16、利用者。155 回目、W6 の区切り。二つを一緒にした独立のレビューの段 1 が (2)・(2) を選び親の読みと一致、段 2 は省いた。材料 `target/notes/155/s1066/`。「上記の通りで進めてください」）: (2)。
  値として含まない位置で互いを名指す型の宣言の集まり（強連結成分）では、集まりの宣言どうしは互いのフィールドを書いたとおりに読んでそれぞれ判定し、誤りのフィールドを誤りの型にするのは集まりの全ての判定の後（集まりの外の宣言に見せる）。書いた順によらず、輪の各型の E0416 が出て、輪の外の使う側は黙る。仕様 §18.1 の 103 行の段落に書いた。
  理由: 輪の各フィールドの誤りは相手の構造（`Buf` を含むなど）だけで決まる独立の誤りで、一か所を直しても他は残る（宣言の循環の S-778 と違う）。(1) では輪の外の使う側の診断（E0416・E0601・E0711 など）が書く順で丸ごと入れ替わり（`ring2_outer` の 120 通りが 60 と 60）、R-464 が直した族の残りだった。
  宣言の並べ替えで診断の集合が変わらないことを検査の不変条件にできる。別名は今のまま先に置き換える（別名どうしは依存の順）。費用 +15〜25 行（`sig/wellformed.rs` の成分ごとの保留）。W6-04 U16。
- 経緯: 153 回目、2026-11-15、W6-04 U5（R-464）の実装の担当（onsa-impl）が仕様の空白として挙げ、親が前後の固定のバイナリ（`onsa-u2`、`onsa-u5`）で確かめた。
- 補い（2026-11-15、親）: W6-04 U5 の壊す側（報告 `target/notes/153/w604/onsa-break-a175a484b7da01b0a-001.md` の 2 と L-3、台本 `target/notes/153/w604/u5b/ring.py`・`extras.py`）: 「どちらの順に書いても E0416 は一件」は輪の大きさ 2 だけの話である。
  輪 `R_i { f: Buf[R_(i+1)] }` を n 個並べ替えると、n=3 は常に 2 件、n=4 は輪の順に書くと 3 件、そうでなければ 2 件（24 通りのうち 12 と 12）。
  輪の外の使う側にも及ぶ: `RA { b: Buf[RB] }`・`RB { a: Buf[RA] }`・`type RT = (RA, I32)`・`struct RU { u: OC[RT] }` で、RA と RB の宣言の順を入れ替えると、`RU` の E0416 が出る順と出ない順に割れる（120 通りが 60 と 60）。(1) の下では、診断の数と輪の外の診断が宣言の順で変わる。(2) なら順によらない見込み（未確かめ）。
