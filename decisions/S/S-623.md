# S-623 束縛を持つ選択のパターンの腕のガードが偽のとき、同じ腕の次の枝を試すか

- 空白: §7 は「選択の全ての枝は、同じ名前の集合を束縛する（`(x, 0) | (0, x) => x`）」とし、腕のガードを持てるが、枝ごとに束縛の値が違う選択の腕でガードが偽のとき、同じ腕の次の枝を試すかを書いていない。
  `match p { (x, _) | (_, x) if x > 5 => x, _ => -1 }` に `(1, 9)` を渡すと、(1) 最初に当たった枝（`x = 1`）でガードを一度だけ評価して次の腕へ進めば -1、(2) 同じ腕の次の枝（`x = 9`）を試せば 9 になる。
  rustc 1.94.1 は (2) で 9 を出す（58 回目の scratchpad の `x8est2/B2/scan/g.rs`）。§7 のガードの形の修正候補の規則（「ガードがどの枝で当たったかを区別できず、当たる値が変わる」）は候補を作らない理由で、評価の順を定めていない。今は `check` が通り、`test` と `build` は Core の降下の E0200 `OrPatternBindings` で止まるので、まだ意味を持たない。
- 決定（2026-11-27、利用者。191 回目、第 122 組）: (3a)。選択は左の枝から試し、最初に当たった枝で束縛する。腕のガードはパターンが当たった後に一度だけ評価し、偽なら次の腕へ進む（同じ腕の後の枝は試さない）。ガードが、同じ値に当たりうる二つの枝で値の違う部分に束縛される名前を読むと、型の段の E0504（新しいコード）。当たりえない二つの枝は、同じ位置に違う列挙子か値の違うリテラルを持つものだけで、定数の値は見ない。ガードが名前を読まなければ誤りにしない（今の E0020 の修正候補が作る `(v, E.A(x) | E.B(x)) if v == 0.5` の類を当てた後に誤りにしないため）。入れ子の選択を持つ枝は選択肢ごとの枝に開いて比べ（`(1 | 2, x, _) | (3, _, x) if x > 5` は通る。字の監査が決定の字から決まらないと示し、決定の意図（読みが割れる形だけを誤りにする）に合う側を親が選んだ）、報告はガードの中のその名前の最初の読みに一つ。修正候補は無く、枝ごとに腕を分けることを note で示す。束縛の無い選択（`1 | _ if tick(inout n)`）は今のまま一度で、`match~` の腕も同じ規則。
  利用者「(3a)で進めましょう」（(1)・(2)・(3b) との比べと、Rust が 9・Python と OCaml が -1 になる例の説明の後）。今ビルドできるプログラムは変わらない（束縛を持つ選択の `test`・`build` は E0200）。`check` の通る `tests/spec/control/pattern_choice_bindings_same.onsa` の `with_a_guard` は誤りの事例に移る。検査は型の段（`exhaust::P` の上、約 80〜150 行の見込み、コードの登録は `tasks/diag-codes.md`・`codes.rs`）、降下は W8-06。道具の層の参照評価器（`crates/onsa_tests/src/flow_ref/pattern.rs`、(2) で先に実装）と `pattern_tests.rs` の 6 件は、検査を入れる単位で揃え直す。
  利用者は「開いて比べる、だと性能劣化はある？」と聞き、生成コードは変わらず、検査は組み合わせを全て作らずに名前の出現の組ごとにパターンを再帰で比べればパターンの大きさの多項式で済む、という説明の後に字を了承した。実装の票に「組み合わせを全て作らない」と「深く入れ子にした選択の事例で検査の時間を確かめる」を書く。
- 経緯: 58 回目（2026-10-24）、X-8 の第二弾の見積もり（組 B2、onsa-impl）が、束縛を持つ選択の降下を担う作業の見積もりで見つけた。`before` は降下を担う作業 W8-06（同じ回に S-318 の持ち越しとして利用者が決めた）。
