# S-623 束縛を持つ選択のパターンの腕のガードが偽のとき、同じ腕の次の枝を試すか

- 空白: §7 は「選択の全ての枝は、同じ名前の集合を束縛する（`(x, 0) | (0, x) => x`）」とし、腕のガードを持てるが、枝ごとに束縛の値が違う選択の腕でガードが偽のとき、同じ腕の次の枝を試すかを書いていない。
  `match p { (x, _) | (_, x) if x > 5 => x, _ => -1 }` に `(1, 9)` を渡すと、(1) 最初に当たった枝（`x = 1`）でガードを一度だけ評価して次の腕へ進めば -1、(2) 同じ腕の次の枝（`x = 9`）を試せば 9 になる。
  rustc 1.94.1 は (2) で 9 を出す（58 回目の scratchpad の `x8est2/B2/scan/g.rs`）。§7 のガードの形の修正候補の規則（「ガードがどの枝で当たったかを区別できず、当たる値が変わる」）は候補を作らない理由で、評価の順を定めていない。今は `check` が通り、`test` と `build` は Core の降下の E0200 `OrPatternBindings` で止まるので、まだ意味を持たない。
- 決定:
- 経緯: 58 回目（2026-10-24）、X-8 の第二弾の見積もり（組 B2、onsa-impl）が、束縛を持つ選択の降下を担う作業の見積もりで見つけた。`before` は降下を担う作業 W8-06（同じ回に S-318 の持ち越しとして利用者が決めた）。
