# S-937 名前の後に隣り合うリテラルが続く形（`x"a""b"`）と、名前の無い区切りとの並び（`"a"$"b"`）が、§2.4 の一つの並びか

- 空白: §2.4 は「名前、文字列と文字のリテラル、他の言語の区切りが空白を挟まずに続く並び」を一つの形とし、「名前を挟まずに隣り合うリテラル（`"a""b"`）は §2.5 の形で、この並びではない」とする。名前か区切りを含むひと続きの中で、リテラルが隣り合う形が書かれていない。
  読み: (1) 全体が一つの並び（除くのは名前も区切りも無いひと続きだけ）。(2) `x"a"` と `"b"` に分かれ、`"a""b"` の部分は §2.5 の形。どちらの読みでも誤りで、変わるのは診断の範囲と数だけである。通るプログラムは変わらない。
  再現は `target/notes/121/w511/probe/a4.txt` の `x"a"$"b"`（今は 1:17-1:21 の `string_prefix`）。
  仮の扱い: W5-11 U2 は読み (1) で実装し、`SPEC-GAP(S-937)` を付ける。テストの票はこの形の期待値を書かない。
- 決定: 決定（2026-11-08、利用者。126 回目）: (1)。名前か他の言語の区切りを含む並びは、中で隣り合うリテラル（`x"a""b"`、`"a"$"b"`）も含めて全体が一つの形で、範囲は並びの全体である。§2.5 の隣り合うリテラルの形は、名前も区切りも含まないひと続き（`"a""b"`）だけである。誤りのあるファイルの報告だけで、通るプログラムは変わらない。利用者は、稀な形なので挙動はどちらでもよく、管理のしやすい方を選んだ（コードを変えず、§2.4 の「範囲は並びの全体」に例外を作らない）。今の実装（`lexer.rs` の `Lexer::runs`）のままで、二つの形の事例を足して `SPEC-GAP(S-937)` の印を消すのは W5-11 U10d。
- 経緯: 121 回目（2026-11-07）、W5-11 の設計メモ（onsa-impl）が挙げた。急ぎは後の段で、待つのは U2 の該当の事例だけである。
- 補い（2026-11-07、親）: W5-11 U2 の後の今の出力（`d7c35101`）: `x"a"$"b"` は並び全体の 8 字が範囲で、E0002（`Onsa has no string of this delimiter`）である。本文の「今は 1:17-1:21 の `string_prefix`」は U2 の前の出力である。
