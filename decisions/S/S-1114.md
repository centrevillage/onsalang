# S-1114 部分ビュー・経路・添字の基に置いた `if`・`match`・ブロックの末尾の場所（`two_s((if c { a } else { b }).slice(0, 2), inout a)`）を、同じ呼び出しの `inout` との E0702 に数えるか

- 空白: S-1113 は、借用の引数に置いた `if`・`match`・ブロックの各末尾の場所を、その引数の場所として重なりに数えるとした（§5.2）。§5.2 は部分ビューを「元の場所、その添字、同じ元のほかの部分ビューと重なる」とするが、この文は基が場所である形の文で、基が `if`・`match`・ブロック（§5.2 の `move` の段落は「場所でない値」とする）や生成型のリテラルのときを書いていない。
  経路と添字の形（`(if c { o } else { p }).l`、`(if c { xs } else { ys })[0]`、`pair.In { l: x, r: y }.l`）も、どの文も答えない。
  今は数えない（どの形も通る）。基の値がビュー（`Span`、`[Span; N]`、生成型 `In`・`Out`）のとき、降下は基を写さないので、呼び先は借用で受けたビューの読みと、`inout` で受けた同じ場所の書き込みを重ねられる（§5.2 の約束が破れる）。基が配列のときは、降下が基を一時へ写すので実際の別名は無い。基が `Buf` か `Buf` を持つ struct のときの写しは浅く（ハンドルの写し）、実際の別名になる（`target/notes/161/w712/u2c/audit/advisor/` の `in/t2/`、インタプリタで確かめた。161 回目の監査）。
  直に書いた形（`two_s(a.slice(0, 2), inout a)`）は E0702。束縛の見出しの側（`for v in (if c { a } else { b }).slice(0, 2)`）は E0710 で、穴は引数の側だけ。
  読み: (1) 引数の値の基が `if`・`match`・ブロック・生成型のリテラルなら、その各末尾（要素）の場所に、外の経路と部分ビューの添字を足した場所を数える（下の形は全て E0702。基が配列の形も E0702 になり、`two_s(if c { x } else { y }, inout x)` と揃う。S-1113 の理由の「借用の引数は、呼び出し中は変更されないと約束」をそのまま当てる）。(2) 今のまま数えない（ビューの基で §5.2 の約束が破れるので、型で分けるか基の形を禁じる別の規則が要る）。
  再現（161 回目、今の dev `05ac3002` で全て通る）: `two_s((if c { a } else { b }).slice(0, 2), inout a)`（`a`・`b` は `Span` の引数、降下は `two_s(slice(if c { a } else { b }, 0, 2), inout a)`）、`two_s((if c { xs } else { ys })[0], inout xs[0])`、`two_s((if c { o } else { p }).l, inout o.l)`（`pair.Out`）、`two_s(pair.In { l: x, r: y }.l, inout x)`、`a.copy_from!((if c { a } else { b }).slice(0, 2))`、`two_s((match k { 0 => xs, _ => ys })[1], inout xs[0])`。入力は `target/notes/161/w712/u2c/review/r1.txt`・`r3.txt`。
  構造への影響: W7-12 U2c の設計メモ（`target/notes/161/w712/u2c/memo/memo.md`）の `given` は、(1) なら外の歩み（経路と添字の並び）を持つ形になる。
  急ぎ: W7-12 U2c の実装の前（`given` の形が一度で済む）。
- 決定（2026-11-17、利用者、161 回目）: (1) E0702。借用の引数の値の基（部分ビュー・フィールド・添字の経路の基。括弧を通す）が `if`・`match`・ブロック式なら、その各末尾の場所に外の経路を足した場所を、その引数の場所として同じ呼び出しの他の引数との重なりに数える（S-1113 の末尾の規則を基へ広げる）。
  基の型によらない（ビュー、配列、`Buf`、struct）。基が引数の位置の生成型の struct リテラルなら、選んだフィールドの要素の場所。受け手（`a.copy_from!((if c { a } else { b }).slice(0, 2))`）も同じ。仕様 §5.2。
  理由: (2) は実際の別名を残す（ビューの基、`Buf` の浅い写し）。S-1113 に「末尾の外に経路を書くと数えない」例外を足すことになり、`two_s(if c { a.slice(0, 2) } else { b.slice(0, 2) }, inout a)` は E0702 で `two_s((if c { a } else { b }).slice(0, 2), inout a)` は通る、という書き方だけの違いを作る。(1) から Copy の基を外す方向へは後で緩められる。段 1（新しい onsa-advisor）が独立に (1) を選び、親の読みと一致したので段 2 を省いた。
  帰結: 今通る、基の末尾が同じ呼び出しの他の引数と重なる形が E0702 になる（基が配列で実際の別名の無い形も。直に書いた `hb(x[0], inout x)` と揃う）。修正候補は無く、書き手は先に `let` に取る。束縛の見出しの側は S-1117（細部、今のまま所有の行）。今の事例に当たる形は単位の票の前に数える。実装は W7-12 U2c1 の共通の構造（`持ち越し`）。
- 経緯: 161 回目（2026-11-17）、W7-12 U2c の設計メモ（onsa-impl）が空白の候補 6.1 として挙げ（仮の扱いは (2)、急ぎは後の段）、メモの審査（onsa-advisor）が高として、ビューの基では実際の別名が通ると確かめた。親が再現して登録した。
  同じ回、想定漏れの監査（新しい onsa-advisor、段 1。親の読みと前の審査を伏せた要約 `target/notes/161/w712/u2c/audit/summary.md`）が独立に (1) を選んだ（理由: (2) は実際の別名を残し、末尾の外に経路を書くと数えない例外を S-1113 に足す。(1) から Copy の基を外す方向へは後で緩められる。中間案（Copy の基だけ外す）は型の条件が増え、S-1113・S-799 と食い違う）。利用者が (1) を選んだ。
