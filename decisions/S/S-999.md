# S-999 細部: S-975 の「外の `[…]` の後ろに続きのある形」を、内の `[…]` の後ろ（外の中）に続きがある形（`xs[Rg[F32, 4].CAP]`）と読むか、外の `]` の後ろに続きがある形（`Q[Rg[F32, 4]].CAP`）と読むか

- 空白: §4.5（S-975）は「外の中身が型として読めない形と、外の `[…]` の後ろに続きのある形（`xs[Rg[F32, 4].CAP]`）は、上の内の `[…]` の規則のままである」とする。字は外の `]` の後ろの続きと読め、例は内の `[…]` の後ろ（外の中）の続きである。`let a = Q[Rg[F32, 4]].CAP` は、(1) 例のとおりに読めば外の中身の全体が型なので S-975 が当たり、候補は `Q::[Rg[F32, 4]].CAP` と `Q[Rg[F32][4]].CAP`。(2) 字のとおりに読めば S-333 の内の規則で、候補は `Q[Rg::[F32, 4]].CAP` と `Q[Rg[F32][4]].CAP`。
  今（dev `91885285`）は E0020 で候補は内の `::` の一つ。当てると名前の段の E0020（「`[` alone is an index」）で候補が無い（行き止まり）。
  仮の扱い: (1)（W5-24 U6 の設計メモの見積もり。決定の理由の「内に `::` を挿す形は型を値の位置に置くだけで行き止まり」に合う）。どちらでも候補は収束し、通るプログラムは変わらない（`rules/leader.md` 5.11）。U6b で実装する。
