# S-748 別名を対象にした `impl`（E0307）のメンバを、同じ型の直接の `impl` のメンバとの E0304 の相手に数えるか（W4-05 U2 で、前に書いた E0307 の `impl` のメンバとの E0304 が出なくなった）

- 決定済みで戻さないもの: メンバを `use` で取り込めないこと（§15.1 の 58 行）。メンバどうしの E0304 の位置（S-737、R-307）と、E0304 の名前を読む所が黙ること（S-675 の (d1)、S-737）。
  名前を書いた順によらずに引くこと（S-725）。見出しに書いた失敗した名前の扱い（S-689）と、対象が誤りの型の `Self`（S-728）。E0307 の範囲（S-91、S-139、S-137）。

- 論点: §4.4（92 行）は `impl` の対象に別名を書けない（E0307）とし、§18.1（61 行）は見出しの誤りのある `impl` のメンバを検査しないとする。
  §18.1（86 行）は誤りのある宣言も名前まで読めれば名前解決に見せるとし、89〜91 行は失敗した `use` の名前を束縛に数えない。E0307 の `impl` のメンバが、§6.2（83 行）の型の名前の後の `.` の空間の名前になるかは書いていない。
  読みは (1) 失敗した `use` と同じく名前を持たない、(2) 名前まで読めた宣言として、対象の型のメンバに数える、に割れる。数えるかで、E0304 の相手と、読む所（本体、署名と型の長さ、他のモジュール）の扱いが決まる。
- 今の実装: 形の表のとおり。E0304 は書いた順によらず最初の検査に出ない。読む所は、本体と後で下ろす署名（fn の引数、フィールド）は引け、グラフの順で下ろす別名と定数の型は E0302 で、位置で割れる。
  中の形は「数えるが、別名の `impl` のメンバを常に後にする」で、重なりの E0304 は E0307 の単位の中で隠れる。候補を当てた後の `e0307_last` では、E0304 が触れた単位（元の E0307 の単位から分かれたメンバ）に同じ段で出る。
  読み (1) では当てる前の E0307 が唯一の誤りなので、§18.1 の候補の約束に反する。読み (2) では当てる前の単位に重なり（隠れた E0304）があるので、約束は当たらない。`p02`（E0307 の `impl` の中の同名）も同じである。
- 案: どの案も、E0307 の位置・候補と、メンバを検査しないことは変えない。
  - (a) 名前に数える（ソースの順）: E0307 の `impl` のメンバは、対象の型（別名なら元の型）の `.` の空間の名前である。E0304 は同じ型のメンバどうしの規則のまま（ソースの順で後、列挙子との重なりは `impl` のメンバ）。
    読む所は、全ての位置（本体、署名、別名と定数の型、他のモジュールの経路）で直接の `impl` のメンバと同じに引く（型は署名から、値は初期化式から）。
  - (b) 名前に数え、重なりは E0307 の側に付ける: (a) と同じだが、E0307 の `impl` のメンバとの重なりは書いた順によらず E0307 の `impl` のメンバに付ける（単位の規則で隠れ、見出しを直した次の検査でソースの順の位置に出る）。中の形は今の実装に近い。
  - (c) 失敗した名前と同じ: E0304 の相手にせず、読む所は診断を出さない（値の位置は単位の以後を検査しない、型の位置は誤りの型。§18.1 の 89〜91 行に E0307 の `impl` のメンバを足す）。
  - (d) 無いものとする: E0304 の相手にせず、読む所は E0302（§18.1 の 86 行の例外）。
  - (e) 今の実装のまま: E0304 は数えず、読む所は本体と後で下ろす署名では引き、別名と定数の型では E0302。
  - 形ごとの出力: 重なりで E0307 の `impl` が先の形は、(a) が E0307 と直接の `f` の E0304 を同じ検査で出す。(b)〜(e) は E0307 だけで、E0304 は次の検査。E0307 の `impl` が後の形は、どの案も E0307 だけで、E0304 は次の検査。
    `type B = [F32; S.N]` は、(a)・(b) が通り（E0307 だけ）、(c) が黙り、(d)・(e) が E0302。本体の `S.N` は、(a)・(b)・(e) が引き、(c) が単位の以後を止め、(d) が E0302。
  - 書き手から見て（修復のループの回数）: E0307 の `impl` が先の重なりは、(a) が二回の検査で済む（一回目で E0307 と E0304 の両方を直す）。(b)〜(e) は三回。
    読む所のある形は、(d) と (e) の別名・定数の型で、E0302 を見た書き手が直接の `impl` に `N` を足すと、E0307 を直した次の検査で E0304 になり、回数が増える。(c) は黙るが、本体の値の位置では同じ単位の他の誤りが次の検査に回る。
  - 修正候補: E0307 の候補は、どの案でも当て続けると E0304 の `no-candidate` で止まる（E0304 は候補を持たない）。
    (a)・(b) は §18.1 の約束を満たす。(c)〜(e) は、E0307 の `impl` が後の重なりと `impl` の中の同名で約束に反し、守るには「メンバが重なるときは E0307 の候補を出さない」条件が要る（その判定は (a) と同じ重なりの比べである）。
  - 通るプログラム: どの案も変わらない（形は全て E0307 の誤りを含む）。変わるのは、誤りのあるプログラムの診断の数と検査の回数である。
  - 規則と例外: (a) は §18.1 の単位の段落に一文（対象の型が分かる見出しの誤りでは、メンバの名前はその型の空間に入る）で、例外は足さない。(b) は (a) に E0304 の位置の例外を一つ足す。

- 他言語: 
  - rustc 1.94.1（`probe/other/r1.rs`〜`r3.rs`）: 別名への固有の `impl` は書ける形で、`type A = S; impl A { fn f() } impl S { fn f() }` は E0592「duplicate definitions with name `f`」。
    孤児の固有の `impl`（`impl Vec<u8>` の E0116、`impl u8` の E0390）が二つあると、メンバの重なり（E0592）は出さず、読む所 `Vec::<u8>::f()`・`u8::f()` に E0599「no function or associated item named `f`」が出る（見出しの誤りの `impl` のメンバを名前に見せない形で、連鎖の誤りが出る）。
  - swiftc 6.3.1（`probe/other/s1.swift`）: 別名への `extension` は書ける形で、`extension A { static func f() }` と `extension S { static func f() }` は「invalid redeclaration of 'f()'」。
  - C 系・TypeScript・Python の、型の宣言の外でメソッドを足す書き方（C# の拡張メソッドと `partial`、TypeScript の宣言の併合など）と見出しの誤りの組は、手元で確かめておらず未確認。
- 推奨と理由: (a)。確度: 中。
  - E0307 の `impl` は、どの型のメソッドかが一つに決まり（候補はその型の名前）、誤りは書き方だけにある。名前まで読めた宣言を名前解決に見せる §18.1 の規則がそのまま当たる。
    失敗した `use` を数えないのは指す先が無いからで、E0307 のメンバには持ち主の型がある。
  - (a) だけが例外を足さずに §18.1 の候補の約束を満たす。(c)〜(e) は E0307 の `impl` が後の重なりで約束に反し、守る条件には (a) と同じ重なりの比べが要る。(b) は位置の例外を足し、見出しを直すと E0304 の位置が別の宣言に移る。

  - 実装は、二度に分けた名付けを一度にする形で、差し引きの増える行が少ない。後の段で E0307 の形（型引数、孤児規則）が増えても手当てが要らない。今の位置で割れる出力（(e)）は、別名と定数の型だけが E0302 になる表面の違いで、U3 で直す方がよい。
  - あわせて決めること: 規則は別名の形に限らず、対象の型が分かる固有の `impl` の E0307（別名、対象の型引数、孤児規則）に当てる。別名の右辺がタプル・配列など名前の無い型なら、メンバは名前を持たない（今のまま）。
    読む所は、メンバの型（署名）と値（初期化式）を直接の `impl` のメンバと同じに読む（`p15` の読む所の E0200・E0408 は直接の `impl` の写しと同じで、新しい規則は要らない）。E0307 の `impl` の中の同名（`p02`）もソースの順で数える。
