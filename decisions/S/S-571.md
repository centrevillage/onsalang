# S-571 境界のイベントの出力: 列の大きさと受け取り方

- 空白: §19.1 は flow のイベントの出力 `-> E at event`（S-564）を決め、境界の出力の列の大きさを第 35 組に送った（出力の数は入力のイベントの数と `.up~` の倍率にも依るので、フレームの数に固定しない）。§11.6 の `process`・`Rendered` と §14.2 の C の `_process` には、イベントの出力が無い。決めること:
  1. 生成する API と C の API で、出力のイベントを受け取る形（呼び出し側が容量を持つ列、呼び出し側が渡す関数、など）と位置の表し方。
  2. 容量を超えたときの扱いと、要る容量を書き手が知る方法。
  3. `process` が 0 以外を返したとき（poisoned、重なり）の出力のイベント。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51 回目）: 出力のイベントは呼び出し側が容量を持つ列で受ける（C は `<p>_events_out`（`data`・`cap`・`len`）、生成する API は `inout output: Span[(U32, E)]` で出した数を返す）。
  容量の上限は `A × frames + events_len`（A は `<P>_OUT_EVENTS_PER_FRAME`）で、呼び出しの最初に同じ式を 64 ビットで比べ、足りなければ C は 2、生成する API は panic。
  0 以外を返したら出力のイベントは 0 個。
  C の `<p>_out_event`・`<p>_events_out` と `_process` の出力のポインタは、イベントの出力のある flow だけに置き（§11.6 の数の規則。52 回目の回答）、`frames` が 0 の呼び出しでもポインタは要り `len` に 0 を書く。`sample` の入力の無いイベントを出す flow の生成する API の `process` は `frames` を取り、イベントを出す flow には `process_inplace` を生成しない。
  仕様 §19.1
- 経緯: X-7（W3 の終わり、2026-10-15、利用者）で、W4 の前に決めて第 1 期の範囲を W4〜W10 に割り当てることになった。第 35 組（境界）の一つで、第 33 組（S-555〜S-559）と第 34 組（S-560〜S-567）の決定を前提にする。S-564 の独立のレビューの注文（フレームの数に固定した API にしない）。関係: S-564、S-567、S-570。
