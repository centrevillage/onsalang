# S-727 全て `_` の分解のパターン（`let (_, _) = p`）を `let _ = p` と同じ書き方として揃えるか（fmt の正規形、E0020、そのまま）

- 空白: 分解の全ての要素を `_` にしたパターン（`let (_, _) = p`、`let P { x: _, y: _ } = q`、`Some((_, _))`）と、全体を `_` にした形（`let _ = p`、`Some(_)`）は、同じことの二つの書き方である（P2）。仕様はどちらかに揃えるか（fmt の正規形にするか、E0020 にするか、そのまま両方を書けるか）を決めていない（`spec/05`・`07`・`tools.md` に見当たらない）。
  使われない束縛の E0309（§5.1）の修正候補を当て続けると、`let (a, b) = p` は二回で `let (_, _) = p` になる。候補の約束（§18.1）はどちらでも満たす（`let (_, _) = p` で止まる）ので、W4-04 U7b2 の妨げにはならない。
  決めること: 全て `_` の分解を書けるままにするか、fmt が `_` に畳むか、E0020（候補は `_`）にするか。E0309 の候補が全ての要素を `_` にするとき、全体の `_` にするか。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。確認だけ。78 回目、第 68 組）: (a)・(e1)。
  全て `_` の分解（`let (_, _) = p`、`let P { x: _, y: _ } = q`、腕の中）は書けるままにし、fmt も畳まない。値の形を確かめるパターンで、`let _ = p` とは別のプログラムである（`n: I32` の `let (_, _) = n` は E0401、`let _ = n` は通る）。fmt で畳むと `spec/tools.md` §3.3 の「判定を変えない」に反する。
  E0309 の候補は今のまま（名前を `_` にするだけ）。仕様は §7 の分解の段落に一句書いた。実装は無い。読みを固定する正例と負例の対の事例を足すとよい（後の担当が空白として報告し直さない）。
  W7-04: flow の本体の `let (_, _) = g~(x)`（§11 の例）は §5.1 の到達の根（`let _`）と同じに数える見込みで、確かめる。
