# S-879 `assert x, "msg"`（Python）と `assert!(x, "msg")`（Rust）を、他の言語の書き方の E0020 と修正候補にするか（今は一般の E0002「expected newline or `}`, found `,`」）

- 空白: - 空白: `assert x > 0, "positive"`（Python の形）と `assert!(x > 0, "positive")`（Rust の形）は、今は一般の E0002「expected newline or `}`, found `,`」（第 81 組の下書きの `probe/s554/rules.onsa`）。
  Python と Rust は §18.1 の他の言語の書き方の一覧（E0020）の対象の言語だが、`assert` の文面を付ける形を E0020 と修正候補にするかが決まっていない。
  候補の読み: (1) 文面を落とす `assert x > 0`（安全側）、(2) 文面を保つ `if !(x > 0) { panic("positive") }`（文面がリテラルのときだけ書ける）、(3) 候補なしで note。
  急ぎ: W5-11 の他の言語の書き方の族と一緒に（今も誤りにはなる）
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R1、Y）文面を付けた `assert`（Python の `assert e, m`、Rust の `assert!(e, m)`。複数行も一つの形）は E0020 の行 `assert_message` で、候補は文面を落とした `assert e` の一つ。Python の `assert(e, m)` は今のままタプルの E0401。`assert_eq!(a, b)` は今のまま E0302。 文面は条件の後の最初の深さ 0 の `,` から形の終わりまでで、Rust の書式の引数（`assert!(x > 0, "x = {}", x)` の `"x = {}", x`）も含めて全て落とす（Y）。
  - 仕様の節: §7 の `assert` の項（親が置く文）、一覧の行。
  - 今通るプログラム: 変わらない（Python の形は E0002、Rust の形は E0401）。
  - 実装の見当: `onsa_syntax` の `assert` 文の構文（`parser/`）で `,` と `!(` を見て行を返す（S-964 と合わせて 50〜80 行。新しい `foreign/asserts.rs` か `foreign/calls.rs` の隣）。
  - ぶつかる事例: なし。
- 経緯: - 経緯: 110 回目（2026-11-04）、第 81 組の下書きが S-554 の「別の S にしてよい論点」として挙げ、独立のレビューの段 2 が別の S にして W5-11 の族に置くと勧め、利用者が (A) で了承した。関係: S-554
- 補い（2026-11-09、親）: 今は（dev `5d5cd987`）Python の形は一般の E0002 だが、Rust の `assert!(x > 0, "m")` は E0401「`!` is not defined for `(Bool, Str)`」、`assert!(x > 0)` は通って意味が逆になる（S-964）。128 回目の独立の検討で確かめた。
