# S-250 §18.1 の既存言語の書き方の一覧は閉じているか

- 空白: §18.1 の「既存言語と旧版の書き方」の一覧が例示か閉じた一覧か。
  仕様に無い形の扱い: `&T` と `&x`（今は E0020 で `&` を除く）、`usize`・`bool`（今は E0020 で `U32`・`Bool`）、`char`・`str`（今は E0302）、呼び出しの型引数 `parse::<I32>("3")`（今は E0020 で、候補の `.` を当てると `parse.<I32>` の E0002 が残り S-236 に反する）、struct のフィールドの区切りの `;`（今は候補なしの E0002）。
  閉じた一覧なら W3-15 の規則の表と仕様の表が一対一になり、仕様からテストを書ける（S-109、Q-01）。W3-15/t で見つけた（2026-10-08）
- 提案: (b) の閉じた一覧。ただし基本仕様に表を置かず、機械が読むデータのファイル（TOML）にし、W3-15 の規則の表（`onsa_syntax::foreign`）と一対一にして自己テストで突き合わせる（D-15）。FAUST の表も同じファイルへ移し、§18.1 には置き場所と「一覧に無い形は一般の規則のコード」の一文だけを書く。ファイルの例はテストが仕様から作ったデータとして読む。
  細部: `&T` は `&` を除き、式の `&x` は `x`（引数では `inout x` も並べる）、`&self` は `self`、`&mut self` と `mut self` は `inout self`。引数の型の `&mut T` は `inout 名前: T`、引数でない位置の `&mut` は候補なしの E0002（R-173）。
  小文字の型名は UpperCamel（`usize` は `U32`、`isize` は `I32`）、`String`・`Vec`・`i128`・`u128` は表に入れない（E0302）。`mut self` の候補は `move self`。`;` は除き、`,` で区切る並びの中では `,` にする。複合代入と `++x`・`x++`・`--x`・`x--` は表の行（W3-15 の行）。
  呼び出しの型引数 `f::<T>(x)` の候補は、`::<…>` を除く形から S-239 で `::[…]` に置き換えた（S-277）（利用者。第 4 組の回答。2026-10-08 決定。実装は W3-15（表とファイル、§18.1 の一文）、W3-19（`f::<T>(x)` の行の候補））
