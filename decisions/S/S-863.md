# S-863 利用者の `impl Tr for Ty` のメンバの `target fn`（本体なし・`else` の本体）の E0200 が、この版で `impl Tr for Ty` 自体も E0200 になる中で、いくつ出るか

- 空白: §15.2 は std の外の `target` 宣言を形によらず名前の段の E0200 とし、S-661 は `impl` のメンバならメンバの全体に一つとする。一方、利用者の `impl Tr for Ty` はこの版で見出しの E0200（「this version does not support trait implementations」、`names/collect.rs`、名前の段）である。
  読み: (1) 見出しの E0200 とメンバの E0200 の二つ。(2) §18.1（見出しに誤りがあれば `impl` の全体を一つの単位とし、誤りは一つ）から一つで、二つとも名前の段なので、位置の順で見出しの E0200 だけが出る。
  親の読みは (2)（§18.1 から一つに決まる）。今の固定のバイナリでも、`impl Drop for H` のメンバの誤り（`let y: U8 = 300`）は出ず、見出しの E0200 だけが出る。再現は 106 回目の scratchpad の `w502/u2t/probe/gap1_trait_impl_target.onsa`
- 決定: 決定（2026-11-03、利用者が確認だけで了承。106 回目）: (2)。§18.1（見出しに誤りのある `impl` は全体が一つの単位で、誤りは一つ）から、利用者の `impl Tr for Ty` のメンバの `target fn` は、見出しの E0200（この版の trait の実装）一つだけで、メンバの E0200 は別に出さない（二つとも名前の段で、位置の順で見出し）。仕様は変えない。実装は W5-02 の U2
- 経緯: 106 回目（2026-11-03）、W5-02 U2 のテストの担当（onsa-test）が NEW として挙げ、事例に書かなかった。親が §18.1 と `names/collect.rs` の段を確かめ、(2) に読めるので確認だけで出す
