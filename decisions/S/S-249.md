# S-249 範囲のパターンと `..=` のコードと候補

- 空白: 範囲のパターン（`1..3 =>`、`1..=3 =>`）の診断のコードと修正候補。§7 は範囲パターンが無いとだけ書き、ガードの形の E0020 は `@` の右の範囲（S-186）だけ。`..=` は候補を作れない E0002 と note（W3-15 の行、S-48）だが、仕様の本文に無い。W3-15/t で見つけた（2026-10-08）
- 提案: (a) を S-257 に合わせた形: パターンの範囲は構文の段の E0020 で、候補はガードの形（`1..<3 =>` は `k if 1 <= k && k < 3`、`1..=3 =>` は `k if 1 <= k && k <= 3`、`1..3 =>` は二つを並べる）。`@` の右の範囲（S-186）も同じ規則で、S-186 の候補を改める。
  入れ子と選択の中もガードの形、選択の枝で束縛を共有できない形（`Some(1..3) | None`）は E0002、端の型は問わない。見出しの外の範囲は E0002 と note。ガードの束縛の名前は S-253（利用者。仕様 §7。2026-10-08 決定。実装は W3-07。ガードの候補の E0010（R-72）を範囲のパターンの行より先に直す）。
  改め（2026-10-09、利用者。S-317 の Fable の助言で、「選択の枝で束縛を共有できない形は E0002」だけでは `(1..<3, 1) | (5..<7, 2)` に当たる値を変える候補を許すと分かった）: 浮動小数のリテラルと一つの規則にし、置き換えた後に選択の全ての枝が同じ形になるときだけ候補を作り、枝を一つにまとめて条件を `||` で結ぶ。
  他は E0002（仕様 §7）。W3-07 のデータのファイルに `(1..<3, 1) | (5..<7, 2)` の E0002 の例を足す
