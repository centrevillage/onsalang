# S-1132 細部: poisoned のインスタンスに `init` を呼ぶと poisoned が解けるか（今の降下と参照評価器は解く）

- 空白: §9.2 は export の `process` の panic で「インスタンスを poisoned にする。以後の `process` は無音を出力し、`reset` まで復帰しない」、§11.6 は「`reset` は…poisoned を解く」、§14.2 は `init` の戻り値で「1 と 2 では状態は未初期化のまま（reset では復帰せず、init のやり直しが要る）」とする。
  poisoned のインスタンス（初期化済み）に `init` を呼び直したとき、poisoned が解けるかが書かれていない（§11.6 は「サンプルレートを変えるときは、`init` を呼び直す」）。
  読み: (1) `init` は状態の全体を作り直すので poisoned も解ける。(2) poisoned は `reset` だけで解ける（`init` は poisoned を残す）。
  今: 降下の `init`（`crates/onsa_core/src/lower/flow/phases.rs` の `gen_init`）は `poisoned = false` を書く（(1)）。W7-18 U2b の参照評価器の `Boundary::init` も (1) で、`SPEC-GAP(S-1132)`。通るプログラムの診断は変わらない。
  仮の扱い: (1)。決まったら §11.6 の `init` の段落に一言足す。
