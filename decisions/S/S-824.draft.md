# S-824 マニフェストの E0200 の閉じた一覧に無い、今の実装が拒む値（`provides` の `Alloc` 以外、`bind`、未知の `platform`）

- 決定済みで戻さないもの: プラットフォームを扱えるかは、そのターゲットのビルドで検査すること（§18.1 の 84 行、S-99）。ターゲットの値の E0200 の出すコマンド（S-154）。クロスで外部のツールチェーンを要する `kind` の E0200（S-161）。
  効果でない名前（`provides = ["Allc"]`）は S-608。値の型の誤り（`platform = 64`）は E1103。項目に二つ当たるときと位置は S-827。
  第 77 組の下書きの「仕組みの出所」と「族の形の表」の節（写しは `target/notes/95/g77/draft.md`）。
- 論点: §15.3 は `provides` を「効果の名前の配列」、`platform` を「ターゲットのトリプルか `"host"`」、`bind` を「実装モジュールの経路」とし、どれも仕様の閉じた一覧ではない。E0200 の閉じた一覧（`tasks/diag-codes.md`）は、この版が扱えないこれらの値を挙げない。
  読みは、この版が扱える部分の外を E0200 にする（そのターゲットのビルド）か、E1103（全てのコマンド）にするかに割れる。`platform` は「トリプル」の形を仕様が定めないので、欄の数が足りない形（`nonsense`、`""`）の扱いも割れる。
- 今の実装: 形の表のとおり。`zz80-none` と `x86_64-foo-bar` は `build` だけが「unknown architecture」「unknown operating system」（コードなし）、`nonsense` と `""` は「is not a target triple」。`aarch64-darwin` は macOS として通る。
  `provides = ["Fs"]` と `bind` は `build` だけが文に `(E0200)` を付ける（位置なし）。クロスの `staticlib`（`o06`）は S-161 の E0200 でなく、ソースだけを書いて 0 で終わる（W4-02 で直す、決定済みの誤り）。
- 案: 
  - (a) 全て E0200: この版が扱えない仕様の効果（`Alloc` 以外）、`bind`、この版が見分けられない `platform`（アーキテクチャか OS が分からないもの。欄の数で分けない）を E0200 の閉じた一覧に足す。そのターゲットのビルドと `--target` を取るコマンドで出し、note にこの版が扱える値（`Alloc`、アーキテクチャと OS の表）を示す。
  - (b) 全て E1103: この版が受ける値を閉じた一覧とし、全てのコマンドのマニフェストの検査で E1103 を出す。
  - (c) (a) の上で、`platform` に形の規則を足す: `"host"` か、`-` で区切った二つ以上の空でない欄でなければ E1103（全てのコマンド）。形に合って見分けられないものは (a) の E0200。
  - 形ごとの出力: `provides = ["Fs"]`・`bind`・`zz80-none` は、(a)・(c) が `build --target t` の E0200、(b) が全てのコマンドの E1103。`nonsense`・`""` は、(a) が E0200（ビルド）、(b) と (c) が E1103（全てのコマンド）。`aarch64-darwin` は、どの案も通る。
  - 書き手から見て: 綴りの誤り（`aarch46-apple-darwin`）は形に合うので、どの案でも見分けられない値の診断が一回で、note の表から選び直す。(c) が (a) と違うのは、`-` の無い値を `check` で知らせることだけである。
    (b) は、`provides = ["Fs"]` を書いた一つのターゲットのために、`check` と `test` が止まる。
  - 修正候補: どの案も候補を出さない（綴りの候補を出さない S-597 のまま。どのアーキテクチャか、どの効果を外すかは書き手の意図による）。
  - 通るプログラム: リポジトリの `platform` は `host` と `thumbv7em-none-eabihf` だけで、`provides` は `Alloc` だけ、`bind` は無い。どの案でも今のマニフェストの結果は変わらない。
  - 規則と例外: (a) は E0200 の一覧に三項目を足すだけで、新しい規則は無い。(b) は、仕様にある値（`Fs`）を版で変わる E1103 にし、E1103 は版によらない規則という区別と、未対応のターゲットで `check` を止めない S-154 の目的とに反する（S-154 と §18.1 の 84 行を改めることになる）。(c) は §15.3 に「トリプル」の形の一文と E1103 の項目を足す。
  - 実装の量（W4-02 の U3）: (a) は `platform()` の三つの誤りを一つの `Feature`（約 +1 行）にまとめ、`provides`・`bind` の `Feature` と同じく位置付きの診断にする（U3 がどの案でも行う作り替えの中で約 +5）。
    (b) は `platform()` と `provides` の照合をマニフェストの検査へ移し、E1103 の note の一覧を版の表から作る（約 +10〜15）。(c) は (a) に形の確かめ（約 +5〜8）と事例。
  - 後の作業への手当て: (a)・(c) は、アーキテクチャや効果を足す作業が表に一行足すか一覧の項目を外すだけ。(b) は足すたびに E1103 の閉じた一覧が変わり、版によらない規則の一覧が版で動く。
- 他言語: rustc 1.94.1（`rustc --print cfg --target zz80-none`）: 「error loading target specification: could not find specification for target "zz80-none"」と `--print target-list` の案内で、形の誤りと未知を分けない（`nonsense` も同じ文）。
  go 1.27.2: `GOOS=zz80` と `GOARCH=zz80` は「unsupported GOOS/GOARCH pair zz80/arm64」で、形の規則は無い。Rust の名前のトリプルは欄が三つとは限らない（`thumbv7em-none-eabihf`）。
- 推奨と理由: (a)。確度: 中。
  - 効果の名前と `platform` は、仕様が集合を閉じず、この版が扱える部分を版で広げる値で、E0200 の「仕様にあって、この版が扱えないもの」にそのまま当たる。E1103 を版によらない規則に保ち、未対応のターゲットが `check` を止めない決定とも揃う。
  - `platform` の形の規則（(c)）は、知らせる形が `-` の無い値だけで、綴りの誤りの大半は (a) と同じ診断になる。仕様の「トリプル」は外の慣習の名前で、欄の数も一定でなく、形の規則を書くと規則が一つ増える割に、利益が薄い。
  - 実装は今の `platform()` の誤りを一つの診断にまとめるだけで、作り替えの量が最も小さく、後の作業は表に行を足すだけで済む。
  - あわせて決めること: `bind` は、キー（表の見出し `[targets.t.bind]`）に一件の E0200 を出す（項目ごとに出さない）。中身の無い `bind` の表は S-825 の答えに従う。
    `provides` の E0200 は、未対応の効果の要素ごとに一件。効果でない名前は S-608 が決めるまで今と同じ E0200 の文で、S-608 の答えで改める。
