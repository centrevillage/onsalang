- 論点: §5.3（103 行）は、`Span[T]` のメソッドを `[T; N]` と `Buf[T]` にも与える。§4.5（145 行）が要素を `T: Copy` に限るのは `Buf[T]` と `Span[T]` だけで、`[T; N]` の要素は Shared・Affine・第二級（平面の配列）でありうる。
  そのとき、各メソッドを持つかを仕様は書いていない。値を複製するメソッド（`get` は借用の受け手から要素を、`fill!` は借用の `v` を N 個の要素へ写す）と、`Span[T]` を作るか受けるメソッド（`slice`・`copy_from!`・`add_from!`）が、要素の種で割れる。
- 今の実装: 形の表のとおり。組込みの表が要素の種を見ず、Shared・Affine・平面の配列で六つのメソッドが全て通る。Affine の値の複製（13〜16・18・21 行）と、型の位置では書けない型（`Span[Str]`・`Span[Buf[F32]]`・`Span[Span[F32]]`・`Option[Span[F32]]`）を本体に作る形（9・19・31・32 行）がある。
  `slice` の誤りは、ビューを `Span[F32]` の引数に渡した所で初めて E0401 になる（20 行）。
- 案: 「Copy」は要素が Copy（`Span[T]` を作れる）、「Dup」は要素が Copy か Shared、「全て」は要素の種によらない（第二級を含む）。条件を満たさない要素の呼び出しは、呼び出しの位置の誤り（コードは下のあわせて決めること）。

  |---|---|---|---|---|
  | `len` | Copy | 全て | 全て | 全て |
  | `get` | Copy | Copy | Dup | Dup。Affine は所有の受け手を消費して一つを取り出す |
  | `fill!` | Copy | Copy | Dup | Dup |
  | `slice`・`copy_from!`・`add_from!` | Copy | Copy | Copy | Copy |
  - (A) 列のメソッドは `Span[T]` のメソッドで、`Span[T]` を作れる要素の受け手だけが持つ（D-07 の追記の字のとおり）。§4.2 の `[T; N]` の `len` を要素が Copy の配列に限る。
  - (B) (A) に、全ての `[T; N]` の `len` を足す（長さは型で決まり、要素に触らない）。
  - (C) メソッドごとに、その操作が要る種を求める。`len` は要素に触らない。`get` と `fill!` は値を複製するので Dup（`[e; N]` と同じ）。`slice`・`copy_from!`・`add_from!` は `Span[T]` を作るか受けるので Copy（§4.5）。
  - (D) (C) に、Affine の要素の `get` を `move self` の受け手（受け手の配列を消費し、他の要素をその場で破棄する）として足す。
  - 代わりの形（今どれも通る）: Affine の要素の配列では次のように書く。(A) では `xs.len()` が無いので、長さは const パラメータ `N` か数で書く（x12）。
