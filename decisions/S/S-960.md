# S-960 印と前置の記号と相手の間のブロックコメントの誤りの順（`-` 改行 `/* c */ m` と `~` 改行 `/* c */ m`、同じ行の `~ /* c */ m`、文の頭の `@ /* c */`）

- 空白: §2.1 は閉じたブロックコメントを E0020 とする（候補は言葉を行コメントに残す）。S-957 の `決定` は、境界の `?`・属性の `@`・前置の `~` と相手の間の改行について「ブロックコメントはそれ自体の E0020 が先」とする。§2.5 の前置の `-` / `!` / `^` と被演算子の間の改行の後のブロックコメントと、空白の代わりに同じ行のブロックコメントを挟む形の順は書かれていない。
  今の出力（W5-11 U10d2 の後の主のツリーのビルド。改行の `~`・`@` の形の他は前の `f5fb3bc` と同じ）: `let n = -` 改行 `/* c */ m`（`!` も同じ）は記号の改行の E0020 が先、`~`・`@`・`?` の同じ形はブロックコメントの E0020 が先（U10d2）。
  同じ行の `~ /* c */ m` と `- /* c */ m` は E0002（被演算子が無い）、`~/* c */m` は `~` の E0020、`? /* c */ Dup` と項目の見出しの `@ /* c */ fp(relaxed)` はブロックコメントの E0020。
  文の頭の `@ /* c */ mem(bulk) let n = m` と `@` 改行 `/* c */ mem(bulk) let n = m` は E0002「expected an expression, found `@`」。`@ /* c */ // x` 改行 `fp(relaxed)` は E0002 で候補なし。
  読み: (1) どの記号と位置でもブロックコメントの E0020 が先。(2) 改行の形は `-` に揃えて記号の改行の E0020 が先、同じ行の形は今のまま。(3) 今のまま（記号と位置ごとに違う）。どれも誤りの入力のどの誤りを先に出すかの違いで、通るプログラムは変わらない。
- 決定: 決定（2026-11-09、利用者。127 回目）: (a)。
  空白を空けずに書く位置（§2.5 の印と記号、メンバの `.`、後置の `?`・`(`・`[`、印と `(`、増減と既存言語の形の記号、§2.6 の `if~`・`match~`・`par~`）にあるブロックコメントは、同じ行でも、接していても、改行の前後でも、§2.1 の診断を、その位置の空白と改行の誤りと形そのものの誤りより先に報告し、候補は §2.1 の今の形。
  残る空白と改行は次の検査でその位置の E0020（二回）。S-957 の文はこの一般の文の例になる。文の頭の `@ /* c */ mem(bulk) let`、`+ /* c */ x`、`+` 改行 `/* c */ x`（コメントを消す今の候補は出なくなる）、`-- /* c */ x`、`a --/* c */b` も同じ。§2.5 に書いた。
- 経緯: 127 回目（2026-11-09）、W5-11 U10d2/t2（onsa-test）と U10d2/i3（onsa-impl）が仕様の空白（NEW）として報告した。事例は書いていない。急ぎは後の段。族の規則は S-961。
