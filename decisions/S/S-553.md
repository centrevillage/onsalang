# S-553 候補の編集の範囲の中にあるコメント

- 空白: 候補の編集の範囲の中に、変えるトークンの間のコメントがあるときの扱い。§18.1 は「編集は、変えるトークンだけを置き換える最小の編集で、間のトークンとコメントを範囲に含めない」とする。
  範囲に入れるトークンの間にあるコメントは、(1) 消えてよい、(2) 消さずに残す（編集を分ける）、(3) 別の位置へ移す、に読みが割れる。
  例: `delay~(` 改行 `x, // the signal` 改行 `1, // the length` 改行 `)` の E0807 の候補は、`delay` を `prev` にし、`, // the signal` 改行 `1` を消す。当てた後は `// the signal` が消え、`// the length` が `x` の後ろに残る。
  今の器の五つ目の確かめ（X-3 の X3-1g）は、範囲の中のコメントを書き戻す編集だけを捕まえ、黙って消す編集を見ない。前からある（dev は呼び出しの全体を `prev~(x)` に置き換え、コメントを全て落としていた）。
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目、第 40 組）: (c)。消すトークンに挟まれたコメントは、トークンと一緒に消してよい（下書きと助言の (a) でなく、利用者の見方）。理由: fmt は書き手の選択を経ずに書き換えるのでコメントを保つが、修正候補は提案で、書き手は字のまま当てなくてよい。候補が守るのは、当て続けて正しい構文に収束するか、収束できないとして止まるかで、コメントを消すことはどちらにも触れない。
  1. §18.1 の「編集は…間のトークンとコメントを範囲に含めない」を言い直した: 残すトークンとの間のコメントは範囲に含めない（最小の編集）。消すトークンに挟まれたコメントはトークンと一緒に消してよい。
  2. 今の E0807・E0005 の候補はこの形のまま（0 行）。下書きの器の確かめ（コメントの言葉の多重集合）は足さない（(c) の正しい削除を捕まえるため）。担う作業は無い。
  3. R-210（残す演算子と右辺の間のコメントを消す候補）は 1 の前半に反する誤りで、X-6 V で直した形のままでよい。4. 既決の S-513・S-317（中にコメントがあれば候補なし）は今のまま（止まる側で誤りでない）。揃えて候補を出す向きは、候補が増えるだけで壊れないので後で決めてよい。
  残る見た目の問題（E0807 の例で `// the signal` が消え、`// the length` が `x` の後ろに残る）は約束の外で、書き手に任せる。仕様 §18.1
- 経緯: X-3/U1 の壊す側が見つけた（2026-10-17、`issues/X/X-3/` の U1 の取り込み）。決まるまで、器にこの形を足さない。
  55 回目、第 40 組（族「§18.1 の候補の編集の形」、下書き `S-553.draft.md`、助言の担当の二段。下書きと助言は (a) で一致した）で、利用者が (c) を選んだ。
- 補い（2026-10-18、親）: 関係する R-210（複合代入の候補が、演算子と右辺の間のコメントを範囲に含めて消す）は、残すトークンの間の隙間にあるコメントの形で、§18.1 の既にある規則（コメントを範囲に含めない）に反するので直す。この S は消すトークンの間にあるコメントの扱いで、まだ決まっていない。この S を決めるときに、R-210 の直し方と食い違わないかを確かめる
