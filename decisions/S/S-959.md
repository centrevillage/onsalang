# S-959 空白のある属性（`@ fp(fast)`、`@ relaxed`、`@ foo`）に別の誤り（値の誤り、旧版の形、一覧に無い名前、付けられない位置）もあるとき、空白の E0020 と属性の誤りのどちらを出すか

- 空白: S-489 は属性の `@` と名前の間の空白をどの位置でも E0020（候補は空白を除く）とした。§6.5 は一覧に無い属性と付けられない属性を E0005 とし、値の誤り（`@fp(fast)`）も E0005（候補は一覧の値）、§18.1 は旧版の書き方（`@relaxed`、`@derive(Eq)`）を候補を作れるとき E0020 とする。空白と別の誤りが同じ属性にあるときにどちらを出すかは書かれていない。
  読み: (1) 属性の誤りを先に出し、空白の E0020 は属性に他の誤りが無いときだけ（U10d2 の前の出力に戻る。旧版の候補は空白ごと置き換えるので一度で直る。E0005 の候補の後に空白の E0020 が出る二手は、初めから誤りが二つの入力（S-384）として許す）。(2) 空白を先に、候補なしの E0002（U10d2 の今の実装の向き。値の誤りの形も E0002 にする直しが要る）。(3) 空白を先に、候補あり（当てると別の誤りが残り、§18.1 の約束を破る）。
  今（U10d2 の未コミットの実装）: `@ fp(fast)` は空白の E0020 で候補を当てると E0005 が残る（`--fix-same-place` の違反）。`@ relaxed`・`@ derive(Eq)` は E0002 で候補なし（前は E0020 と候補）。`@ foo` は E0002（前は E0005）。再現は `target/notes/126/w511u10d/` に写す U10d2/b の `repro/`。
- 決定: 決定（2026-11-09、利用者。126 回目）: (1')。`@` と名前の間に空白か改行（S-957）がある属性に、構文の段の属性の誤り（§6.5 の E0005：一覧に無い名前、付けられない位置、値の誤り。旧版の書き方の E0020）も重なるときは、属性の誤りを報告し、その修正候補は空白と改行も除く（`@ fp(fast)` は E0005 で候補 `@fp(relaxed)`、`@ relaxed` は E0020 で候補 `@fp(relaxed)`、`@ foo` は E0005 で候補なし）。
  空白と改行の E0020 は、属性に他の構文の段の誤りが無いときだけ報告する。後の段の誤りは段の順で後（`? Gone` と同じ）。
  利用者は初め「空白が先の方が統一感がある、属性だけ特別扱いになっていないか」と問い、親が調べると、同じ段の同じ所の形の誤りが空白より先で、候補が空白も直す先例（§3.1 の `- - x` の E0012、S-938 の `~ a`）があり、U10d2 の実装（空白を先にし、属性の誤りを予測して候補を落とす）の方が特別扱いだった。
  親の (1)（属性の誤りを先、二手）を先例に合わせて (1')（候補が空白も除く、一手）に改め、利用者が了承した。§6.5 に書いた。実装は W5-11 U10d2 の引き継ぎ（空白の検査を属性の検査の後に回し、`space_after_mark` の予測を外す。属性の誤りの候補に空白を除く編集を足す。約 +10〜20 行）。
- 経緯: 126 回目（2026-11-09）、W5-11 U10d2/b（onsa-break）の指摘 M1・M2・L2 から親が登録した。`{@ p}` の直しの後に同じ所から続けて出た。原因は、空白の検査（`space_after_mark`）が属性の検査（`check_attrs`）の結果を別の所で予測し直していること。急ぎは W5-11 U10d2。
