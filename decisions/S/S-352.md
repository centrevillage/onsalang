# S-352 `@` の右の定数

- 空白: `@` の右の定数（`k @ LIMIT`、`k @ -LIMIT`、`k @ cfg.LIMIT`）。§7 と S-186 は、右が「リテラル・範囲・それらの選択」ならガードの形の候補で E0020、他は E0002 と note とし、W3-21/t は `k @ LIMIT` を E0002 と期待する。
  定数のパターンは書ける形（S-185）で `k if k == LIMIT` の候補も作れる。S-341 で範囲の端に定数を書けると、`k @ 1..<LIMIT` は E0020 と候補で、`k @ LIMIT` は候補なしの E0002 になる。第 13 組の下書きで見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 13 組）: `@` の右の「リテラル・範囲」に、字面で定数と分かる名前と経路（最後の名前が `UPPER_SNAKE`。命名の検査の `UpperSnake` と同じ）と `-` を付けたものを足し、候補は `k if k == LIMIT`（選択の中も同じ、右の全体を条件）。
  構文の段の E0020。列挙子の字面（`UpperCamel`）は今どおり E0002 と note。「定数の字面」の判定は `-LIMIT`（S-319）と共有し、仕様 §7 で一度定めた。一文字の `N`（総称の定数のパラメータ）にも候補 `k if k == N` が出るが、§7 が比べるときはガードで書くとするので正しい書き方。仕様 §7。
  実装は W3-21（W3-21/t の `pattern_guard_candidates.rs` と `e0020_patterns_at_forms.onsa` の `a_constant` を E0002 から E0020 に改め `.fix1` に `k if k == LIMIT`、データのファイルの `at_binding` の `rule` と例（`k @ LIMIT`、`k @ -LIMIT`）、E0002 の例に `k @ Color.Red`）
