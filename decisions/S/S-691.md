# S-691 効果行に失敗した名前・E0304 の名前を含むとき（`uses {Alloc, Gone}`）、読めた効果を残すか、呼び出し側は何を見るか

- 空白: §18.1 は読めなかった部分を誤りの型として扱い、使う側に診断を出さないとし、S-462 は失敗した名前の使う所を黙らせる。効果行に失敗した `use` の名前か E0304 の名前を含むとき（`use kp.{Gone}` の後の `pub fn f() -> I32 uses {Alloc, Gone}`）、読めた効果（`Alloc`、効果の変数）を残すか、呼び出し側は `f` の効果を何と見るかを書いていない。
  読みは (1) 読めた効果は残し、失敗した名前だけ不明とする（呼び出し側の本物の誤りは出す）、(2) 行の全体を不明とし、呼び出し側も黙る、に割れる。
  W4-03 U3b1 の直し（67 回目、WIP `1c39b8f`）は、効果行を空にして def を止める形で、呼び出し側は `f` を純粋と見て、U3b1 の前に出ていた本物の E0601（`h uses Alloc, which is not in its effect row`）が消える。
  並びの順で後ろの本物の E0200 が消える割れもある（`target/notes/67/w403/u3b1/b2/r3.txt` の `alloc_lost`、`r1.txt` の `multi_effect`）。
  親の案（67 回目、次の直しの往復の仮の扱い）: (1)。読めた効果を残し、失敗した名前だけを飛ばす（def を止めない）。S-689 と同じ組で決める。
- 決定: 決定（2026-10-25、利用者。68 回目、第 61 組、ID を挙げて確認だけで了承（A3・A6））: (1)。族の規則 S-692 から。読めた効果（`Alloc`、効果の変数）を残し、失敗した名前だけを未知の効果にして、def もクロージャの本体も止めない（W4-03 U3b1 の `8593dd3` の形）。呼び出し側は読めた効果を見る。
  理由は、`use` に別名が無い（§15.1）ので失敗した名前が読めた効果を指すことはなく（第 2 期でも）、読めた効果から出る診断（呼び出し側の E0601、E0901、rt の E0902）は `use` を直しても消えない本物であること。行の全体を未知にする (2)（S-692 の案 (e)）は採らない。
  未知の効果を含む行は開いた行で、その名前が指しえた効果に頼る判定は黙る（今の版の効果は `Alloc` と効果の変数だけなので出力は変わらない）。関数の型の表示は読めた行だけになる（`uses {Alloc}`。規則ではなく事実）。
- 経緯: 67 回目（2026-10-25）、W4-03 U3b1 の壊す側の再確認（onsa-break）が中の指摘として挙げた。関係: S-689、S-462、S-675。
- 補い（2026-10-25、親）: 68 回目、直しの二往復目（U3b1/i3）は、親の案 (1) を効果行の位置によらず当てる（関数の署名、署名と本体の関数の型、クロージャの効果行）。関数の型は誤りの型にせず、クロージャの本体も止めない。
  効果行が失敗した名前を読んだ def は、本体を止めなくても `unread_users` に入れる（候補が名前を直すと、その def に隠れていた誤り（`uses {util}` の E0200）が出うるため。X-3 の fix-contract）。
- 補い（2026-10-25、親）: 68 回目、U3b1 の二回目の再確認（onsa-break）: (1) では関数の型の効果行から失敗した名前が消えるので、関数の値の型の食い違いの E0401 の期待の型の文字列にも出ない（`fn apply(f: fn() -> I32 uses {Gone})` に `uses {Alloc}` の関数を渡すと「expected `fn() -> I32`, found `fn() -> I32 uses {Alloc}`」）。
  誤りそのものは §8.1 の包含のとおり本物。(1) と (2) を決める材料だった（第 61 組で (1) に決め、この表示は事実として受け入れた。`決定`）。再現は `P68/w403/u3b1/b3/cases/a1.txt` の `fnty_arg_alloc`（P68 は 68 回目の scratchpad）。
