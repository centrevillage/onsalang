# S-695 モジュールが自分の中の flow の名前空間から取り込む `use`（`main.onsa` の `use main.f.{process_inplace}`）を、S-679 の自分を取り込む `use` として E0302 にするか

- 空白: S-679 は、モジュールが自分自身を取り込む `use`（`main.onsa` の `use main`、`dsp/synth.onsa` の `use dsp.synth`）を E0302 とし、自分の項目は名前だけで書くとする。自分のモジュールの中の flow の名前空間から項目を取り込む `use main.f.{process_inplace}` が当たるかを書いていない（本体では `f.process_inplace` と書ける）。
  読みは (1) モジュールそのものでないので通る（今の実装）、(2) 自分の中を経路で取り込むので S-679 と同じく E0302、に割れる。W4-03 U3b2 の事例 `use_flow_own_item_in_signature` は (1) で書いた。急ぎ: 後の段。
- 決定: 決定（2026-10-27、利用者。74 回目、第 64 組、ID を挙げて確認だけで了承）: (a)。モジュールが自分の中の flow の名前空間の項目を取り込む `use`（`main.onsa` の `use main.f.{process_inplace}`）は通す（今のまま）。
  S-679 が止めたのはモジュールそのものを取り込む `use` だけで、flow の名前空間の項目は名前だけでは書けず、子モジュールの項目（`use main.inner.{h}`）と同じ扱いである（§11.6 の名前空間はモジュールと同じ扱い）。自分の項目や flow と名前が重なる形（`use main.{other}`、`use main.f`）は §15.1 の E0304 のまま。
  仕様 §15.1 に一文。実装は変えず、W4-04 で `names/imports.rs` の `SPEC-GAP(S-695)` の印を消す。
- 経緯: 69 回目（2026-10-25）、W4-03 U3b2 の回帰の事例のテストの担当（onsa-test）が、壊す側の B1 の形を書くときに挙げた。関係: S-679、S-673、S-685。
  74 回目（2026-10-26〜27）、第 64 組（下書き `S-695.draft.md`）: 下書きと助言の担当の二段で (a) が一致した。
