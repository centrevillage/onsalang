# S-852 手書きの標準 trait の `impl` に、trait のメンバが足りない・余計なときの診断のコード

- 空白: X-23 で、手書きの `impl Default for Ty` を W5-06 で受け付けることにした。§6.3 は上位の trait を満たさない `impl` の E0416 だけを書き、trait の `impl` に trait のメンバが足りないか余計なとき（`impl Default for Mode {}`、`default` の他に `fn other()` を書く）のコードを書いていない。
  読み: (1) E0416。(2) E0410 と同じ見方の新しいコード。急ぎ: W5-06 の前。第 2 期に trait の実装を一般に開くときも同じ規則を使う。
- 決定: 決定（2026-11-06、利用者。117 回目、確認だけ）: (c) 足りない項目も余計なメンバも E0410 である（§18.1 の「直し方が同じならまとめ」。リテラルとパターンと同じ見方）。位置は足りなければ見出しの trait の名前、余計ならそのメンバの名前で、note に trait の項目の署名を示す。
  余計があるときは足りないを報告しない（綴りの誤りを一度の改名で直せる）。足りない形は見出しの誤りで `impl` 全体が一つの単位、余計はそのメンバの単位で他のメンバは検査する。使う所（`P.default()`、`T: Default`）には診断を出さない。第 2 期の既定メソッドは「要る項目」から除くだけで同じコードである。
- 経緯: 104 回目（2026-11-02）、X-23 の見積もりの組 B（onsa-impl）が X23-8 の案を見積もって挙げた。利用者が X23-8 の (2) を了承した後に親が登録した。
- 補い（2026-11-06、親）: 第 88 組で決めた。下書き `decisions/S/S-852.draft.md`。下書きの (d) と独立のレビューの (c) が割れ、親もレビューと同じ (c) を勧めた。
