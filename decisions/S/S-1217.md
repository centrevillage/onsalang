# S-1217 `sample_tick()`（S-565 の B11）の形の見直し: 経過時間を計算する基準の時間を、どの仕組みで与えるか（今の形は flow ごとの欄と、段の関数への時間の受け渡しと、修飾子ごとの時間の写しを要する）

- 空白: 利用者（176 回目）: 「`sample_tick()` がやりたいことに対して過剰な仕様を産んでいる気がしてきました。欲しいのは、経過時間を計算するための基準時間です。しかし、現状ではそのために flow ごとに欄を持つ必要が出てきてしまい、単純ではありません。他の解決策を考えた方が良いかもしれません。」
  目的（S-565 の B11、48・49 回目）: ダブルタップの判定、チャタリングの除去、押下の状態の保持など、経過時間の要る判定を、使う場所ごとにインスタンスと数える処理を持たずに書く。利用者の当時の言葉: 「`elapsed~` が使う場所のたびにインスタンスと独自のカウント処理を持つのが気になる。`reset` 時（`reset_if~` ではなく）からの経過サンプル数を返す組込みがあってもよい。数が一周したときの扱いは要る」。型は `U32`（組込みの機器で `U64` は遅くアトミック性も無い。間隔は `-%`）。
  今の形（§11.4）と、それが要する仕組み:
  - 値は `reset` からの時間を、書いた場所の `sample_rate()` の刻みの数で表した `U32`。`.up~(N)` の本体では N 倍 + 何歩目か、`.down~(N)` の本体では 1/N、`when~` の中は外と同じ（止まっている間も進む、S-1129 (1)）、イベントの段ではその位置の値。
  - 時間は一番外の数から作り、段の関数の引数 `t` で、時間を読む flow（`reads_time`）とその呼び出しの経路に渡す（W7-16 U5b2）。修飾子の境界ごとに時間を写す（`child_time`、U6a・U6b）。
  - `.down~` の本体で 1/N を 2^32 で一周させるため、上の桁の `U32` の欄（`_tick_hi`）が要る。flow ごとの配置（§12.4）では、経路に `.down~` があり時間を読む flow ごとに欄が出る（S-1211）。
  - 時間を読むだけの flow も位相のカウンタ `_tick` を持つ（`counts_time`）。
  - 細部の決定: S-1127（最初の値）、S-1129（`when~` の中）、S-1210（刻みの `at` を付けた形）、巻き上げない一覧と E0815 の位置、イベントの段の落とし穴の note。
  位相のカウンタ（遅い段の格子、S-566 の A7・S-1179）は `sample_tick()` に依らず要る。時間に固有なのは、`t` の受け渡し、`child_time` の写し、`_tick_hi`、時間を読むだけの flow の `_tick`。
  今の実装と事例: W7-16 U5a（一つの flow の `sample_tick()`）・U5b2（子への時間の引数）で降りている。`sample_tick()` を書いた事例は `tests/` に 36 ファイル（`flow_semantics` の値の事例、`flow_clock`、`fixes`、`negative`、パッケージ）。`sample_tick` を引く決定は 20 件。
  待つもの: W7-16 U6a1 の時間の部分（`child_time` の `.down~` のシフト、`wide`・`_tick_hi`）と S-1211。U6a1 の時間でない部分（下りだけの連鎖の子の段の駆動）と U6a2（集めて配る）は、この S に依らない。
  急ぎ: W7-16 U6a1 の前。進め方: advisor の段 1（利用者の意見と親の案を伏せ、目的と制約から独立の設計を書かせる）→ 親が案を比べ（今の形を含め、実装の量・既決への影響・事例の書き直しを数える）→ 利用者が決める。
- 決定: 決定（2026-11-22、利用者。177 回目。「`sample_tick` を使わない場合にコストを払わないことと、使う場合でもコストは必要最小限にしたいです。それが可能なら A で進めて良いです」。親が条件を確かめてから記録した）: 案 A（今の §11.4 の意味を保つ）。`sample_tick()` は一番外の本体の `sample` が `reset` から刻んだ数（実体は一つ）を、書いた場所の `sample_rate()` の刻みで読んだ `U32`。`.up~(N)` は N 倍して何歩目か（0 から）を足し、`.down~(N)` は N で割って切り捨て（連鎖は外の修飾子から）、`when~` の中は外と同じ（止まっている間も進む）、`reset_if~` は触れない。S-1129 は (1) のまま。理由: flow の作者は使う側が `when~` で止めるか、`.down~`・`.up~` で動かすかを知らない。止めても進む時間は止まらない所（一番外）から来るしかなく、`.down~` の中で `0.005 * sample_rate()` がそのまま 5 ms であるには単位が `sample_rate()` と対でなければならない。どこでも一番外の数を返す形（案 C）は上の桁の欄と境界の変換が要らないが、秒にするのに一番外のレートの組込みが要り、`sample_rate()` と組んでも検査と単独のテストを通って `.down~` の下でだけ誤る。費用（利用者の条件）: 自分も子も時間を読まない flow には、時間のための欄・引数・演算が無い（遅い段の位相のカウンタは別）。使う所は、一番外のカウンタと刻みごとの加算、読む flow までの段の呼び出しの引数 1 語（`.down~` の先で読む経路は 2 語）、その経路の flow のインスタンスごとの欄 4 バイト（`par~` の複製ごと。詰め物で増えうる。どの flow も一番外になりうるために置き、一番外のときだけ使う）、`.down~` の先で読むときだけ上の桁の欄 4 バイト・一番外の繰り上げ・境界のシフト。時間のためだけに `_tick` を持つ flow（遅い段を持たない flow）の加算と、上の桁の繰り上げは一番外の `process` のループで行い、埋め込みの `tick` では進めない。時間の引数を取るのは、時間を読むか時間を読む子を走らせる段の関数だけにする（W7-16 U6a3）。§11.4 の「上の桁の `U32` の欄をプログラムに一つ置く」を外し、欄の条件を §12.4 に書いた（S-1211 は (1)）。仕様 §11.4・§11.9・§12.4。
- 補い（2026-11-23、178 回目、W7-16 を閉じる前の文書の点検、利用者が字を了承）: §11.9 の位相のカウンタの項に、`.up~(N)`・`.down~(N)` の部品の本体のカウンタは外のカウンタから §11.4 の `sample_tick()` と同じ形で作った数（`when~` の中でなければ `sample_tick()` と同じ数）で、本体の `sample / M` の刻みはその数が M の倍数の刻みである、と足した（値は §11.4 とこの決定から一つに決まる。U6b3 の事例と参照評価器がその値）。
