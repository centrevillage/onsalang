# S-758 `move` の引数の型に `Span[T]`（`[Span[T]; N]`、生成型の `In`・`Out`）を書く宣言（`fn f(move xs: Span[F32])`）を E0710 にするか（§5.3 の表は既定と `inout` の書き方だけを挙げる。今は通る）

- 空白: §5.3 は、第二級の値（借用、`Span`、捕捉するクロージャ）は引数の位置にだけ現れるとし、表は `Span[T]` と `Span` の配列の書き方を「引数の型として `xs: Span[T]` / `inout xs: Span[T]`」（`[Span[T]; N]` も同じ）と挙げる。`Span` を `move` の引数へ渡すのは E0710（§5.4）。
  `move` の引数の型に `Span[T]` を書く宣言（`fn f(move xs: Span[F32])`）が誤りかは書いていない。今は宣言も通る（`target/notes/81/u4/new4.onsa`）。
  読み: (1) E0710（位置は引数の型）。表に挙げた二つの書き方だけが `Span` の引数で、所有を受け取る `move` は非所有のビューに意味が無く、§5.4 で `Span` を渡せないので呼べない宣言になる。生成型の `In`・`Out`（§5.3、`Span` を持つ第二級）も同じ。(2) 通す（引数の位置なので第二級の規則に当たらない）。
  W4-05 U4 の整形性の段の表の、`move` の引数の行が変わる。(1) で今通る宣言が誤りになるが、`tests/`・std・`examples/` に当たる形は無い（親が `move <名前>: Span` と `move <名前>: [Span` を検索した）。
- 決定: 決定（2026-10-29、利用者。81 回目、第 73 組。下書きと独立のレビューの推奨が一致）: (a)。
  `move` の引数の型の根が第二級の `Span` の型（`Span[T]`、`[Span[T]; N]`、生成型の `In`・`Out`、それらを指す別名）なら、宣言の E0710（位置は引数の型）。関数型の引数の並びのモード（`fn(move Span[F32]) -> F32`）と無名関数の `move` の引数も同じ。候補は出さず（`move` の意図が借用・書き換え・所有に割れる）、note で三つの書き方を示す。
  根でない所の `Span`（`move x: Option[Span[F32]]`）は位置によらない E0710（R-37）。段は署名の E0710 と同じ型の段。`move f: fn(…)` の規則（§5.2）は変えない。今の `move o: pan.Out` の E0601 と、本体の `fill!` の「borrowed parameter」の E0701 は当たる形が無くなる。
  理由: `move` は所有を受け取る印（§5.2）で、`Span` は非所有のビュー（§5.3）なので、組み合わせに意味が無い。今は所有の `Buf` を `f(move b)` で渡す形が通り、`b` を消費して記憶域を破棄する者がいない見込み。通す (c) は、W4-09・W4-16・W6-02・W7-03 に所有の `Span` の手当てが続く。後で所有のビューを入れるなら、この E0710 を外す（緩める向きで壊れない）。
  今通る宣言と、それを `move` で呼ぶ形が誤りになるが、`tests/`・std・`examples/` に当たる形は無い。仕様は §5.3 の表の後に一段落と、生成型の段落に一句。実装は W4-05 U4a（整形性の段の根の位置に引数のモードを渡す。約 +2〜5 行と関数型の引数の +1〜3 行）。
  事例は `move xs: Span[F32]`、`move xs: [Span[F32]; 2]`、`move o: pan.Out`、別名、`fn(move Span[F32]) -> F32` を一つずつの単位に、正例は既定と `inout`（`move i: swap.In` は W7-03 まで実装待ち）。
- 経緯: 81 回目（2026-10-29）、W4-05 U4/i の見積もり直し（onsa-impl）が仕様の空白の候補（NEW 4、低）として挙げ、親が dev `5aa4557` で今通ることを確かめた。親は §5.3 の表から読みが一つ（(1)）と見て、確認だけにする。期限は W4-05 U4。関係: R-37、R-135。
- 補い（2026-10-29、親）: 81 回目: 利用者が外出の前に、残りの判断を助言のレビューに回すよう求めたので、確認だけで出さず第 73 組の空白の流れ（S-755・S-756 と同じ組）に回した。
- 補い（2026-10-29、親）: 81 回目（第 73 組の下書きで訂正）: 上の `空白` の「§5.4 で `Span` を渡せないので呼べない宣言になる」は誤り。Copy の配列（`f(move a)`）と所有の `Buf`（`f(move b)`）を `move` で渡す形は通り、`b` は消費される（後で使うと E0704）。所有の `Buf` を渡したときの記憶域の破棄は確かめていない（降下を読んだ限りでは漏れの見込み）。
