# S-267 検査の段の順の flow の検査の位置

- 空白: 検査の段の順に flow の検査が無い。§18.1 は「構文 → 名前 → 型 → 引数のモードと移動 → rt と効果」と書き、E08xx（flow の段）と flow の段の E0020 の位置を書かない。単位の中で報告する誤りの選び方（S-214）と、修正候補の約束（S-236。E0811 の候補の後に E0401 が残ってよいか）が変わる。W3-17 の設計メモで見つけた（2026-10-08）
- 提案: (a) 段の順は 構文 → 名前 → 型 → flow の検査 → 引数のモードと移動 → rt と効果（クロックの推論は型の推論と構造的に似ているので型の後、利用者）。
  名前と字面で決まる flow のコードは名前の段: `~` の有無（E0811 / E0812）、flow の外の flow だけの構文（E0821）、flow の本体の名前の順（E0801、見えている名前への `^` の E0020）、本体の制限（E0806。代入の形を含む。Fable の案）。枝の E0811 と `if~` / `match~` の E0812 は flow の段のまま。
  §4.7 の最後の項を「型を付けた本体の上でクロックを推論する」に改めた。
  登録簿の段は、今の検査器が出す段と食い違うと検査が落ちるので、実装する作業が変える（利用者。第 6 組の下書き。仕様 §4.7、§18.1。2026-10-08 決定。実装は W4-06（段の順。`SPEC-GAP(S-267)` を外す）、W4-12（`~` の有無の E0811 / E0812 と E0821）、W7-04（E0801・E0806・`^` の E0020 を名前の段で））
