# S-1127 細部: 最初のフレームの `sample_tick()` の値（`init`・`reset` の直後のフレームが 0 か 1 か）

- 空白: §11.4「`sample_tick()`: `reset` からの時間を、書いた場所の `sample_rate()` の刻みの数で表した `U32`（… `init` と生成する `reset` で 0 になり …）」。最初のフレームの値が 0（`init`・`reset` の直後の時間が 0 で、フレームを終えるごとに 1 上がる）か 1（刻みの数をフレームを作るときに数える）かを書いていない。
  読みは (1) 最初のフレームは 0、(2) 最初のフレームは 1 に割れる。今の検査は `sample_tick()` を E0200（R-288）にするので、評価器でもインタプリタでも走らない。
  仮の扱い: (1)。参照評価器（W7-18 U1c）の `state.rs` の `SampleTick` の腕に `SPEC-GAP(S-1127)`。ignore したテスト `instance_tests.rs` の `sample_tick_counts_the_frames_since_init_and_reset_and_a_child_reads_the_same` の期待値が (1)。W7-09（`sample_tick()` の実装）の前に確認だけ。
- 決定: 決定（2026-11-21、利用者。174 回目、W7-09 を閉じる前の確認だけ）: (1)。最初のフレームは 0（`init`・`reset` の直後の時間が 0 で、フレームを終えるごとに 1 上がる）。§11.4 の `sample_tick()` の項に「その後の最初の刻みで読む値は 0 で、`sample_rate()` の刻みごとに 1 上がる。`sample / N` の段で読んでも同じ数」を足した（後の句は W7-09 U2a の親の判断「刻みの段で読む値はインスタンスの `sample` の刻みの数」の写し。174 回目、U2c/t が「刻み」を使う所の刻みとも読めると挙げたので揃えた）。参照評価器は W7-09 U2a `79980180` からこの値で、Core と後端は W7-16。
- 経緯: 163 回目（2026-11-17）、W7-18 U1c のテストの担当（onsa-test）が仕様の空白に挙げ、親が細部として登録した。
