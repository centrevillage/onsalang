# S-1204 変換の flow の `sample / N`・`sample * N` の入力の値型に、§11.6 の `sample` の入力の制限（スカラか `[スカラ; N]`、struct の入力は E0810、R-41）が当たるか

- 空白: §11.6「`sample` の入出力の値型は、スカラ、`[スカラ; N]`（N は 1 以上）、または（出力のみ）それらを一つ以上フィールドに持つ struct」と §19.1「struct の入力は今は E0810（§11.6）」は、変換の flow の `sample / N`・`sample * N` の入力（呼び出し側の集めて配る境界、§11.9）に当たるかを書いていない。R-41 (a) は境界でない内側の flow の `sample` の入力にも当て（W7-13 U3、`sig/generated.rs` の `boundary_outputs`）、`Option[F32]` やユーザーの enum の `sample` の入力も E0810 である。S-578 の「集める入力の型が `Default` を満たさなければ E0816」は、どちらの読みでも届く（スカラの `Char` は `Default` を持たない、§6.4 の表。親は利用者への説明で「当たると読むと入力では届かない」と誤って書き、決定の後に訂正した）。
  読み: (1) 当たらない: 導くクロックの入力は呼び出し側の値を集める境界で、ホストの `Span` を持たないので、struct・enum・`Option` などを書ける。(2) 当たる: 周期の刻みの入力は全て §11.6 の値型（struct の入力は §19.1 の将来の検討のとき一緒に開く）。今は書けない形なので、どちらも今通るプログラムは変えない。(2) は後で (1) に緩めても今のプログラムを壊さない。
  仮の扱い: (2)（最も保守的な形）。W7-09 U4a/t は (1) で `tests/spec/flow_clock/e0816_conversion_flow_gather_struct.onsa` を書いた（決まるまで実装待ちの一覧に置く）。実装の差はどちらも小さい（E0810 の述語の当たる入力のクロック）。急ぎ: W7-09 を閉じる前に利用者が決める。
- 決定: 決定（2026-11-21、利用者。173 回目）: (2)。変換の flow の `sample / N`・`sample * N` の入出力の値型も §11.6 の `sample` の入出力と同じ（スカラ、`[スカラ; N]`、出力のみ struct。入れ子の配列・長さ 0 の配列・フィールドの無い struct は E0810）。利用者の理由:「(1) は flow での struct の扱いを半端に決めてしまうので、もし struct を書けるようにするなら flow の全体を見直すべきで、その時期は今ではない」。§11.6 に一文、§19.1 に変換の flow の入力と「flow での struct の扱いの全体と一緒に見直す」を足した。W7-09 U4a で E0810 の述語の当たる入出力を周期の刻みの全てに広げる（親が推した (2) と同じ）。U4a/t が (1) で書いた `tests/spec/flow_clock/e0816_conversion_flow_gather_struct.onsa` は、struct の導くクロックの入力を E0810 の期待にし、集める入力の E0816 は `Char` の入力で書き直す。
- 経緯: 173 回目（2026-11-21）、W7-09 U4a/t（onsa-test）が NEW-1 として挙げ、親が登録した（報告の控えは `target/notes/173/w709/u4a/`）。
