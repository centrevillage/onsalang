# S-1269 細部: 関数型の引数の渡し方の印（`inout`・`move`）、`rt`、効果行（`uses {…}`）を、型の大きさの上限（§4.4）の数えに入れるか（仮は入れない。今の実装）

- 空白: §4.4 は大きさを「名前（組込みの型、宣言した型、型パラメータ）、型の形、const 引数をそれぞれ一つと数える」とし、関数型の引数の渡し方の印（`fn(inout X)`・`fn(move X)`）、`rt`、効果行（`uses {Alloc}`）を数えるかを書かない（§4.1 は `fn(U32)` と `fn(move U32)` を別の型とする）。
  読み: (1) 数えない（今の実装。大きさ 4094 の `X` で `fn(inout X) -> U8`・`fn(move X) -> U8`・`rt fn(X) -> U8`・`fn(X) -> U8 uses {Alloc}` はどれも `fn(X) -> U8` と同じ 4096 で通り、`X` を一つ大きくすると E0422）、(2) 印と効果を一つずつ数える（上限のちょうどの形が E0422 になる）。仮は (1)。違いが出るのは上限 4096 のちょうど付近の関数型だけ。再現 `target/notes/192/w814/a3t/probe/`（`plain`・`inout`・`move`・`rt`・`uses`）。
- 決定:
- 経緯: 192 回目（2026-11-27）、W8-14 A3/t（onsa-test、型の上限の境の事例）が空白に挙げ、親が A2 のバイナリ（`target/base/ea15e80`）で再現した。上限のちょうどの形のほかは通るプログラムを変えないので細部として、W8 の段の区切りで確認する（`rules/leader.md` 5.11）。改めるなら sema の形の数（`onsa_sema::ty::form_count`）を直す。担う作業が無いので W8 の依存の最も後ろの W8-18 に置く（`rules/leader.md` 7.4）。
