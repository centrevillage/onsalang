# S-651 名前の形（`snake_case`・`UpperCamel`・`UPPER_SNAKE`）の定義: 頭と末尾の `_`（`fn _g`・`Point_`・`_MAX`・`MAX_`）、大文字の並びと数字の語の境（`IO`・`HTTPServer`・`T2D`）と、受理と候補で語の分け方を一つにするか

- 空白: §2.3 は形の名前と例だけを書き、`_` が頭と末尾に付けられるか、大文字の並び（`IO`・`HTTPServer`）と数字（`T2D`）のどこが語の境かを書いていない（S-243 の予約語の候補 `match_` は、`snake_case` が末尾の `_` を受けることを前提にする）。
  今の実装（dev `fdc4fa5`、`P62/probe/us/`）: `snake_case` の `fn _g`・`fn g_`・`let x_ = 1`・ファイル名の `_a.onsa`・`b_.onsa` は通る。`UPPER_SNAKE` の `MAX_` は通り、`_MAX` は E0320（候補 `MAX`）。`UpperCamel` の型と列挙子は `_` をどこにも受けない（`_Point`・`Point_` は E0320、候補 `Point`）。
  受理の判定（`Shape::matches`）と、候補を作る語の分け方（`split_words`。数字の直後の大文字、大文字が続いて小文字が来る所も境）が違う（S-642 の補い）。
- 決定:
- 経緯: 62 回目（2026-10-24）、利用者の問い「アンダーバ- `_` を終わりと始まりにつけられるかどうかは、他の一般の規則はどうなっていますか？型名や変数名は？」に親が今の扱いを調べ、族「§2.3 の名前の形」（S-650）の一つとして登録した。関係: S-642、S-648、S-243、S-149、R-260。
