# S-687 S-673 の「ルート直下の読みを先にする」で、ルート直下の読みが循環を閉じるとき、自分の名前の読みに移るか（`dsp/util.onsa` の `util.g()`）

- 決定済みで戻さないもの: S-673（自分のパッケージ名・自分の絶対経路・自分の名前の頭を外す候補とその細部）、S-663（`use` の頭の自分のパッケージ名の候補）、S-679（自分を取り込む `use` は E0302）、S-682（循環で出さない候補の note）、S-683、R-268（候補は経路が最後まで解決し循環を閉じないときだけ）、S-594 の辺の数え方。
  第 60 組の下書きの「仕組みの出所と目的」の節（写しは `target/notes/67/g60/draft.md`）。
- 論点: §15.1「頭がルート直下のモジュールの名前でもあるときは、そのモジュールを取り込む読みを先にする（通らなければ外す読み）」。ルート直下の読みの経路は最後まで解決するが、足す `use` が循環を閉じるときに「通らない」とみなすかを書いていない。
  二つのモジュールが同じ名前の項目を持つと、読みによって呼ぶ関数が変わる。
- 今の実装: `c77f3f3` の `not_in_body` は、ルート直下の読み（`body_fix`）が候補を返さなければ、理由によらず自分の名前の読みに移る。
  `h9`（`util.onsa` は `use dsp.util.{f}` と `g`（`f()` を返す）、`dsp/util.onsa` は `f`・`g`（2 を返す）と本体の `util.g()`）: 候補「take off `util.`」。当てた `h9_applied` は 0 で、`dsp/util.onsa` 自身の `g` を呼ぶ。ルート直下の読みを当てた `h9_root_applied` は E0310。
  `h9_nocycle`（`util.onsa` が `dsp/util` を取り込まない）: 候補「add `use util`」で、`util.onsa` の `g` を呼ぶ。同じ `util.g()` の候補が、`util.onsa` の `use` の有無で別の関数を指す。
  `h9_nog`（ルート直下に `g` が無い）: 「take off `util.`」（決定済みの「通らなければ外す読み」）。`h9_noown`（循環を閉じ、自分に `g` が無い）: 候補も note も無い。
- 案:
  - (1) 「通らない」は、ルート直下の読みの経路が名前の段で最後まで解決しないことだけ。解決して循環を閉じるなら、候補を出さず、S-682 の note で `use util` と相手のモジュール `util` を示す。
  - (2) 循環を閉じることも「通らない」に含め、自分の名前の読みに移る。今の実装と同じ。
  - (3) (1) に加え、自分の名前の読みが解決するなら、note で外した形（`g()`）も示す。

  | 入力 | (1) | (2) | (3) |
  |---|---|---|---|
  | `h9` | なし、note（`use util` と相手 `util`） | 「take off `util.`」（自分の `g` を呼ぶ） | なし、note（`use util` と相手、自分の `g` なら `g()`） |
  | `h9_nocycle` | `use util`（決定済み） | 同じ | 同じ |
  | `h9_nog` | 「take off `util.`」（決定済み） | 同じ | 同じ |
  | `h9_noown` | なし、note | なし、note | なし、note |

  - §18.1 の約束: どの案も当てた後に誤りを残さない（(1)・(3) は候補を出さない）。
  - 当て続け: (2) は一回で誤りが無くなる。(1)・(3) は候補なしで止まる。
  - 書き手から見た形: (2) の題「take off `util.`」は循環に触れず、当てた形は `dsp/util.onsa` 自身の `g` を呼ぶ。ルート直下の `g` を意図した書き手には、別の関数を呼ぶプログラムが通り、値の違いは実行して初めて見える。
    (1) は、ルート直下を意図した書き手には循環を、自分を意図した書き手には書き直しを委ねる（自分の項目を名前だけで書くことは S-679 の note と同じ規則）。(3) は二つの意図の両方を note に並べる。
  - S-682 の note との揃い: (1)・(3) は、循環で出さない他の候補と同じ note になる。(2) は、自分の名前の読みも解決しないとき（`h9_noown`）だけ note を付ける。
  - 実装（`not_in_body` と `body_fix`）: (2) は 0 行。(1) は、ルート直下の読みが解決して循環だけで出さないときに、自分の名前の読みへ移らず止める（約 +5〜10 行）。
    循環で出さないことを note に渡す区別は、S-682 の note（U3b）が既に要るので共有できる。(3) は note に外した形の文を足す（約 +3〜5 行）。
- 他言語: 該当なし（経路の頭の読みを依存の循環で選び分ける規則を持つ言語は、確かめた範囲に無い）。
- 推奨と理由: (1)。確度: 中。
  - どちらの読みを選ぶかは名前だけで決め、循環は候補を出すかだけを決める。(2) では、同じ `util.g()` の候補が、別のファイルの `use` によって別の関数を呼ぶ形になる（`h9` と `h9_nocycle`）。書き手の意図が一つに決まらない形に、違う意味の候補を出すことになる。
  - S-673 の細部は、候補の条件（解決、名前が空く、循環を閉じない）を読みの選び方と分けて書いている。(1) は「通らない」を「解決しない」に限り、その書き分けに合う。
  - 実装は小さく（約 +5〜10 行）、S-682 の note と区別を共有する。候補を出さない向きなので、後で (2) に緩めても通るプログラムは変わらない。
  - (3) は note の文が一つ増える割に、自分の項目を名前だけで書くことは既に S-679 の note が示す。別の S にしてよい。
- 影響: 仕様は §15.1 の括弧書き「通らなければ外す読み」に一文（(1)・(3) は「経路が最後まで解決しなければ外す読み。解決して循環を閉じるなら候補を出さない」、(2) は「候補を出せなければ外す読み」）。診断のコードは変わらない。
  作業は W4-03 の U3b2（(1)・(3) は `not_in_body`、note は S-682 と同じ所）。テストベクトルの保留に関係する項目は無い。
