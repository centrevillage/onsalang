# S-757 別名の右辺の整形性の誤り（`type A = W[Buf[F32]]` の暗黙の `Dup`、`type A = Buf[Str]`）を、別名の宣言に出すか、別名を使う所（`fn f(x: A)`）に出すか、両方か

- 空白: R-37 の決定は署名の型の整形性を位置と型構成子の組で判定する（`W[Buf[F32]]` の暗黙の `Dup`、`Buf[Str]` の要素の `Copy`、E0416）。別名の右辺に誤りがあるとき（`type A = W[Buf[F32]]`）、誤りを別名の宣言に出すか、別名を使う所（`fn f(x: A)`）に出すか、両方かは書いていない。下ろした型は別名を展開するので、使う所の根の判定は同じ誤りをもう一度見つける。
  §4.4 の E0422（型の深さと大きさの上限）は、位置を別名の宣言にし、超えた別名を使う別名には出さず、誤りの型として扱う（§18.1）。§18.1 は、誤りのある宣言の読めなかった部分を誤りの型として扱い、それを使う側には診断を出さない（正しい宣言に偽の連鎖エラーを出さない）。
  今: どこにも出ない（`target/notes/81/u4/new2.onsa`）。
  読み: (c) 別名の宣言にだけ出し、別名を誤りの型にする（使う所は誤りの型として読み、診断を出さない。E0422 と同じ）。(a) 使う所だけ（使わない別名は検査しない）。(b) 両方（見積もりの推奨。追加の行が無い）。
  (a) は単位どうしを独立に検査する §18.1 に、(b) は一つの誤りを使う所ごとに数える連鎖になる点で §18.1 の誤りのある宣言の段落に合わない。どの読みも誤りのあるプログラムの報告だけが変わる。
- 決定:
- 経緯: 81 回目（2026-10-29）、W4-05 U4/i の見積もり直し（onsa-impl）が仕様の空白の候補（NEW 2）として挙げ、親が dev `5aa4557` で再現した。親は §4.4 の E0422 の位置と §18.1 から読みが一つ（(c)）と見て、確認だけにする。期限は W4-05 U4。関係: R-37、S-264。
