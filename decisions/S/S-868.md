# S-868 境界に書いた `Escape` の、`?` の無い形（`T: Escape`）と、`?Escape`（E0200）の型パラメータを使う側の扱い

- 空白: §4.5 は型パラメータに暗黙の `Escape` の要求を付けて `[T: ?Escape]` で外すとし、この版では境界の `?Escape` を E0200 とする（S-862）。次の二つを書いていない。
  (a) `?` の無い `T: Escape`（暗黙の要求を書いた形）。同じ形の `T: Dup` は今通り、扱いは S-751（OPEN）で決める。
  (b) E0200 の `?Escape` を書いた型パラメータを使う側（`fn each[T: ?Escape](x: T) -> U32` の後の `each(s)`、`s: Span[F32]`）に、推論した型引数の E0710（S-862 の (1')）を出すか。§4.5 の 159 行は「`?` を `Dup`・`Escape` 以外に付けた並び」の型パラメータを使う側に境界による診断を出さないとするが、`?Escape` はこの並びに当たらない。
  `97c584a9` では、どちらも `Escape` が見つからない E0302 である。
  読み: (a) (a1) `T: Dup` と同じく通す（S-751 に従う）。(a2) E0200（名前を予約した未対応の機能の一部）。
  (b) (b1) 印を読まず、印の無い型パラメータと同じく使う側も E0710。(b2) 印を読み、使う側では第二級の型引数を通す（本体の判定は W5-17）。(b3) §4.5 の 159 行と同じく、その型パラメータを使う側に境界による診断を出さない。
  親の仮の扱い（W5-02 U5a）: (a1) と (b1)。どちらも実装が最も簡単で、(b) は既に E0200 のあるプログラムの診断の数だけの違いである。
  急ぎ: W5-02 の U5a（実装の仮の扱いと `SPEC-GAP` の印）。W5-17 が `?Escape` を入れるときに (b) は消える
- 決定: 決定（2026-11-03、利用者。109 回目）: (a1) と (b1)（親の仮の扱いのとおり）。
  `?` を付けない `T: Escape` は暗黙の要求を書いただけの形で、`T: Dup` と同じに扱う（今は通る。`T: Dup` の扱いは S-751 で決め、`T: Escape` も揃える）。`T: Escape + Escape` は同じ境界の重なりの E0416（S-747）。
  この版の E0200 の `?Escape` を書いた型パラメータを使う側は、`?Escape` の無い型パラメータと同じに判定する（第二級の型引数は E0710、S-862 の (1')）。
  理由: どちらも実装が最も簡単で、今通るプログラムを変えない。(b) は既に E0200 のあるプログラムの診断の数だけの違いで、W5-17 が `?Escape` を入れると無くなる。
  仕様 §4.5 の 145 行。W5-02 U5a の実装（`crates/onsa_sema/src/sig/heading.rs` の `SPEC-GAP(S-868)` の 2 か所）がそのとおり
- 経緯: 109 回目（2026-11-03）、親が W5-02 U5a の票を書くときに、S-862 の細部（A1〜A6）と §4.5 の文に (a)・(b) が無いことを見つけた。関係: S-862、S-751、S-711
