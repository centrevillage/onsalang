# S-649 型パラメータの名前の重なり（同じ並びの `fn f[Item, Item]`、型と同じ名前の `struct Item` と `fn f[Item]`、組込みの型の `fn f[I32]`）

- 空白: §5.1 の「シャドーイングは無い」（E0304）は束縛の規則で、型パラメータの名前に当たるかが書かれていない。§6.2 は `impl` の対象の型引数の重複（`impl[T] Pair2[T, T]`）を E0307 とするが、宣言の型パラメータの並びの重複は書いていない。
  今の実装（dev `fdc4fa5`）は、同じ並びの重複 `fn f[Item, Item](a: Item) -> Item`、型と同じ名前の `struct Item { x: I32 }` と `fn f[Item](a: Item) -> Item`、組込みの型と同じ名前の `fn f[I32](a: I32) -> I32` をどれも通す（終了コード 0）。
  入力は `P62/gap52/probe/c/c2.onsa`・`c3.onsa`・`c7.onsa`（62 回目の scratchpad）。
- 決定: 決定（2026-10-27、利用者。74 回目、第 64 組、ID を挙げて確認だけで了承）: (a)。項目の型パラメータ・const パラメータ・効果行変数は、その項目の中（`impl` の見出しの並びはメンバまで）で見える束縛で、§5.1 の「シャドーイングは無い」をそのまま当てる。
  同じ並びの名前、外の `impl` の並びの名前、モジュールの本体の空間の名前（項目、`use` の束縛、prelude、組込み型）、ローカル（効果行変数と `Err(e)` を含む）と同じ名前を使うと E0304 で、候補は無い。失敗した `use` の名前は相手にしない（S-462）。
  誤りは後（内側）の宣言の位置に出し、ローカルの E0304 と同じくその項目の単位に閉じる。相手の名前は §18.1 の E0304 の名前の扱いにせず、他の単位と他のモジュールからそのまま引ける（独立のレビューの補い）。
  理由: 規則も例外も足さない。今通る形は読み手の読みと意味が違う（`fn f[I32]` が `F32` を通す、`impl[F32] P[F32]` が総称の `impl` になる、`impl[T]` のメンバの `[T]` が使われない）。今は通る形を止める向きで、後で緩めても壊れない。効果行変数とローカルの重なりは書き手の改名が増える（確度 中。位置の重ならない組だけ通す例外は採らない）。
  仕様 §5.1 と §18.1 の E0304 の名前の段落に一文ずつ。実装は W4-04（U5）。`tests/review-phase1/types/bounds.onsa` の 7・8 行（R-37）は E0304 になる。
- 経緯: 62 回目（2026-10-24）、S-642 の下書き（onsa-gap、第 52 組）が新しい S の候補として挙げ、親が再現した。S-642 の候補の案の一つ（先頭の語）が名前の重なりで黙って意味を変える理由になった。関係: S-642、S-134、R-46。
