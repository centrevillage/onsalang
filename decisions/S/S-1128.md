# S-1128 細部: 複数のインスタンスの `block` の段の順（親の `block` の `let` の全ての後に子を呼び出しの位置の順か、子の引数を評価する位置の順か。panic の位置だけに出る）

- 空白: §11.3「`block` の式は `process` の呼び出しごとに 1 回」と §11.2「名前は上から順に定義する」は、子の flow のインスタンスの `block` の `let` を、親の `block` の `let` の前に評価するか後か、複数の子の順を書いていない。違いは panic の位置だけ（値は変わらない）。
  読みは (1) 親の `block` の `let` の全て、続けて子を呼び出しの位置の順（`NodeKey` の順）、(2) 子の引数が評価される位置（親の `let` の中の位置）の順に、子の `block` の段も混ぜる、に割れる。
  再現: `flow child(d: I32 at block, x: I32 at sample) -> I32 at sample { let q = 1 / d ⏎ x + q }` と `flow top(d: I32 at block, x: I32 at sample) -> I32 at sample { let p = 1 / d ⏎ child~(d, x) + p }`、`d = 0`。参照評価器は親の `p` で止まる（(1)）。インタプリタは未確認。
  仮の扱い: (1)。参照評価器の `state.rs` の `block_children` の直前に `SPEC-GAP(S-1128)`。W7 の区切りで確認だけ（W7-19 の panic の位置の比べで一緒に見る）。
- 決定: 決定（2026-11-25、利用者。185 回目、第 119 組、確認だけ）: (2)（族の規則 S-1233）。子の `block` の段（`init` の段も）は、呼び出しを書いた位置で行い、親の `let` と交ざる。今の (1)（親の全ての後）から変わる（panic の順だけ）。実装は W7-11 U2b。
- 経緯: 163 回目（2026-11-17）、W7-18 U1c のテストの担当（onsa-test）が仕様の空白に挙げ、親が細部として登録した。
- 補い（2026-11-17、親）: （2026-11-17、163 回目、W7-18 U1c の壊す側）インタプリタも (1) と同じ順（親の `let p = 1 / d` と子の `100 / d`、子を二つの 3 形で、評価器と panic の位置が一致した。入力は `target/notes/163/w718/u1c/` の壊す側の報告の `h7.onsa`）。
