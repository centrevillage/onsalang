# S-550

- 空白: 値が既定値と等しい遅延の `init` に、配列とタプルの要素ごとの 0 のリテラル（`prev~(a, [0.0; 4])`、`prev~(t, (0.0, 0))`）を含めるか。§11.4 は既定値を「配列とタプルは要素ごと」とし、「値が既定値と等しい `init`（`0`、`0.0`、`false`）を書いても受理するが、書かない」と数と `false` だけを挙げる。
  S-539 の (c3a) の gate の確かめ（W3-13 の `default-inits`）は数と `false` のリテラルだけを見る。今の資料にこの形は無い。W3-13/b（U3）が見つけた（2026-10-15）
- 決定: 決定（2026-11-19、利用者。168 回目。第 112 組。独立のレビューの段 1（onsa-advisor）が (b)。親は (a) 今のままを推していたが、段 1 の理由で (b) に改めた。§11.4 の字は値で定め、既定値は「配列とタプルは要素ごと」なので字の範囲が既に含む。S-539 は省略の書き方を gate で確かめるとした）: (b)。
  要素ごとに既定値のリテラルである配列・繰り返し・タプルのリテラル（入れ子と括弧も。`[0.0; 4]`、`[0.0, 0.0]`、`(0.0, false)`）にも、文書の検査（`tools/default_inits.py`、判定は `crates/onsa_tests/src/default_inits.rs`）を当てる。
  空の `[]` は当てない（S-1104 の (1) では、`Default` を持たない要素の長さ 0 の配列の直し方が `prev~(z, [])`）。名前の定数（`ZERO`）と struct のリテラルは当てない（値が字だけで決まらない）。
  足すのは、W7-07 で配列とタプルの省いた `init` を通す単位と同じ時（それまでは省いた形が E0200 で、文書が書ける形を失う）。利用者のプログラムは変わらない（コンパイラはどちらの形も受理し、`onsa fmt` も取り除かない）。仕様 §11.4 の括弧を改めた。
- 経緯: W3-13/b（U3）が見つけ（2026-10-15）、後の段に回した。168 回目（2026-11-19）、第 112 組として親の中立の要約で段 1 に回し（`target/notes/168/g112/`）、利用者が了承した。
