# S-260

- 空白: 構文の誤りで失敗した struct のフィールドの参照。§18.1 は「読めなかった部分（引数の型、フィールドなど）は誤りの型として扱い、それを使う側には診断を出さない」とするが、名前が読めずに失敗したフィールドや、読めたフィールドに無い名前（`p.zz`）を参照したときを書かない。W3-03/t で見つけた（2026-10-08）
- 提案: 決定（2026-10-08、利用者が ID を挙げて了承。利用者: 壊れた struct や enum のフィールドを半端に参照すると副作用の方が多い。親の案: 構文の段で失敗した struct のフィールドの参照には、名前によらず診断を出さない。読めなかった部分が何を宣言していたか分からないので、書き手が構文の誤りを直した後の検査で出す。失敗した enum の列挙子と網羅性も同じ扱い（W3-03 の設計メモ））。
  W3-03 で実装。W3-03/b の指摘を受けた親の読み（決定の理由「読めなかった部分が何を宣言していたか分からない」による）: 黙らせるのは本体の宣言を読み切れなかった struct と enum だけで、宣言を全て読めた項目（後ろの `;` の E0020 だけの項目など）は対象にしない
- 時期: W3
