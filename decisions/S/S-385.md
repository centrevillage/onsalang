# S-385 `if` / `match` と `~` の間の改行

- 空白: `if` / `match` と `~` の間の改行（`if` 改行 `~c {`）。
  S-354 は同じ行の空白を E0020（候補は空白を除く形）とし、改行の後の `~c` は、括弧の外では今は改行の位置の E0002、括弧の中では `~` の位置の E0002「expected the condition, after a `~` written without a blank」（どちらも候補なし。第 18 組の下書きが括弧の中の事実を直した）。
  S-89 の「改行を除く形」の移し方で S-354 の候補を出すかを決める。第 17 組の下書きで見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 18 組）: 括弧の中の `if` / `match` と `~` の間の改行は、S-354 の同じ行の空白と同じ形（S-370 の一文の「空白を空けない位置の印は相手と同じ行」）。
  E0020 で、修正候補の一つ目は `~` をキーワードの直後へ移す形、`~` が被演算子に接するときだけ二つ目に `!` の形。括弧の中の `else if` 改行 `~d` は S-355 の行。括弧の外は `if` / `match` で行が終わり、今の行末の E0002（候補なし）のまま。
  「被演算子に接する」は同じ行で空白を空けずに被演算子が続く形だけで、`~` の後が改行なら `!` の候補を出さない（W3-09 の実装の誤りを W3-06 で直す）。仕様 §2.6。実装は W3-06
