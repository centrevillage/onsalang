# S-330

- 空白: 呼び出しの名前の経路に付けた `[…]` のうち、型にしか読めない形（`f[fn(I32) -> I32](x)`、`f[[F32; 4]](x)`、`f[(I32, F32)](x)`）を、構文の段の E0020 にするか名前の段にするか。§4.5 は「添字として読めない `[…]`（`pair[I32, F32](1, 2.0)`）は構文の段」とし、W3-19/t は `,` を含む形だけを構文の段の事例にした。W3-19/t で見つけた（2026-10-09）
- 提案: 後の段（W4-13 の前）
- 時期: W4
- 経緯（2026-10-23、親）: X-8: W4-13 を W5-10 へ移したので、期限を W5-10 にした。
- 補い（2026-11-02、親）: X-23（W5 の見積もり）で、期限は W5-10 のまま（読みの一つが名前の段で、決まる前に W5-10 が済むと手戻り）。下書きは S-333・S-548 と同じ組にしてよい。
- 決定: 決定（2026-11-10、利用者。132 回目、第 95 組。材料は `target/notes/132/g95/`）: (a)。名前の後の `[…]` の中身が式として読める型の形（型の名前、型引数のある型、配列型、タプル型、`()`）は名前の段（W5-10 の `type_args_square` の E0020、候補の条件は S-974）。式として読めない本体の無い関数型（`f[fn(I32) -> I32](x)`、`rt fn`）は構文の段の一般の E0002 のまま、行を立てない（角括弧の型引数は `rules/criteria.md` 7.32 の一覧の外の Scala の書き方で、新しい行の基準を満たさない）。
  一般の E0002 に、本体の無い `fn(…)` は型で式の位置に書けない、の note を、式の位置に本体の無い関数型が出た所の全てに付ける（`let t = fn(I32) -> I32` も。約 5 行）。仕様の文は変えない。残る表面の違い: `f[fn(I32) -> I32, I32](x)` は `,` があるので E0020 と候補（S-333）。独立のレビューの段 1 は関数型だけの行の (c) を選び、段 2 で 7.32 の基準から (a) に改めた。W5-10。
