# S-860 S-854 の列挙の外で、数のリテラルの型変数にどの候補の型でも誤りの操作を当てた形（`for i in 17`、`let (a, b) = n`、`Span[T]` の引数への `takes(17)`）が E0420 のまま

- 空白: S-854 の決定（§4.7）は、候補の種類だけで誤りと決まる操作としてフィールドアクセス・タプルの添字・添字・`?` の対象・関数値の呼び出しを挙げ、注釈したときと同じコードにした（理由は「注釈では消えない誤りに注釈を勧めない」）。
  W5-01 U2 の後も、次の三つは数のリテラルの型変数に対して E0420「… must be known here; add an annotation」のままである: `for i in 17`（反復の対象、`statements.rs`）、`let n = 17` の後の `let (a, b) = n`（タプルのパターンの対象、`patterns.rs`）、`fn takes(s: Span[I32])` への `takes(17)`（引数、`calls.rs`）。
  注釈した `n: I32` では、それぞれ E0401（cannot be iterated、expected a tuple pattern target、expected `Span[I32]`）になる。§4.7 の「その場で既知を要する操作」の一覧には、反復の対象とパターン（`match` 以外）と引数が無い（引数は別の文で「未解決でも進められる」）。
  読み: (1) S-854 の列挙で閉じ、三つは E0420 のまま。(2) S-854 と同じ原則で、三つも注釈したときと同じコード（E0401）にする。どちらでも通るプログラムは変わらず、報告のコードと文面だけが変わる。再現は `target/notes/105/w501u2b/` の `b1`・`b3`・`b8`（注釈した形は `b2`・`b4`・`b9`）
- 決定: 決定（2026-11-03、利用者。106 回目）: 読み (2)。S-854 の「候補の種類だけで誤りと決まる操作」に、`for` の反復元、タプルのパターンの対象（`let`・`for` の見出し・`match` の腕の中、flow の本体も）、`Span` と `Span` の配列の引数を加え、リテラルの型変数には E0420 でなく注釈したときと同じ E0401 をその場で報告する。
  細部: 文面は S-854 と同じく、型の名前の所に「整数」「浮動小数」を置く（`an integer cannot be iterated (§7)`、`expected a tuple pattern target, found an integer`、`Span` の引数は `found an integer`。今の平面の配列リテラルの要素の `found `1.5`` も同じ語にする）。修正候補は無い（注釈した形にも無い）。
  リテラルでない型変数（`fn make[T]() -> T` の後の `let v = make()`）では、三つとも E0420 のままである（注釈で直る）。§4.7 の「その場で既知を要する操作」の一覧と、別の文の「引数は未解決でも進められる」の例外に、三つを書き足す（今の実装のとおり。確認だけ）。
  理由: S-854 の理由（注釈では消えない誤りに注釈を勧めない）がそのまま当たる。近い形は前から注釈したときと同じ E0401 で、三つだけが外れていた（構造体と列挙子のパターン、浮動小数の範囲の端、`Option[I32]` の引数への `takes(17)`、`Span` の配列の引数の `[1.5, 2.5]`）。
  メソッドと違い、答えが後で変わらない。組込み型の反復はコンパイラが扱い、`IntoIter` は std の trait なので、孤児規則（§6.3）により利用者は組込み型に実装できない。タプルの形と `Span` に渡せる型（§5.3）は規則で決まっている。
  仕様 §4.7。実装は W5-02（4 か所の `known` を S-854 の `known_shape` に替える）
