# S-860 S-854 の列挙の外で、数のリテラルの型変数にどの候補の型でも誤りの操作を当てた形（`for i in 17`、`let (a, b) = n`、`Span[T]` の引数への `takes(17)`）が E0420 のまま

- 空白: S-854 の決定（§4.7 の 182〜184 行）は、候補の種類だけで誤りと決まる操作としてフィールドアクセス・タプルの添字・添字・`?` の対象・関数値の呼び出しを挙げ、注釈したときと同じコードにした（理由は「注釈では消えない誤りに注釈を勧めない」）。
  W5-01 U2 の後も、次の三つは数のリテラルの型変数に対して E0420「… must be known here; add an annotation」のままである: `for i in 17`（反復の対象、`statements.rs`）、`let n = 17` の後の `let (a, b) = n`（タプルのパターンの対象、`patterns.rs`）、`fn takes(s: Span[I32])` への `takes(17)`（引数、`calls.rs`）。
  注釈した `n: I32` では、それぞれ E0401（cannot be iterated、expected a tuple pattern target、expected `Span[I32]`）になる。§4.7 の「その場で既知を要する操作」の一覧には、反復の対象とパターン（`match` 以外）と引数が無い（引数は 177 行で「未解決でも進められる」）。
  読み: (1) S-854 の列挙で閉じ、三つは E0420 のまま。(2) S-854 と同じ原則で、三つも注釈したときと同じコード（E0401）にする。どちらでも通るプログラムは変わらず、報告のコードと文面だけが変わる。再現は `target/notes/105/w501u2b/` の `b1`・`b3`・`b8`（注釈した形は `b2`・`b4`・`b9`）
