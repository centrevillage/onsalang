# S-611 `use` の束縛と同じ名前の子モジュール（`main.onsa` の `use kp.inner` と `main/inner.onsa`）

- 空白: §15.1 は、同じ名前を二度取り込む形と、モジュールの項目と同じ名前の子モジュール（`a.onsa` の項目 `b` と `a/b.onsa`）を E0304 にするが、`use` の束縛と同じ名前の子モジュールを書かない。
  `main.onsa` に `use kp.inner` と `main/inner.onsa` があるとき、`main` の中の `inner.g()` がどちらを指すかと、誤りにするか（E0304）が決まらない。
  今は通り、`inner` は `use` の束縛を指す（dev `2ebd664` の `issues/R/R-250/hides_child`）。S-596 の下書きの形の表の 18 行で、下書きと助言は再公開を項目だけにする (a) の下で E0304 にする案を出したが、回答の (d) はこの行を決めていない。
  R-250 の再現 `hides_child` は、この形が通る前提で書いた（決定に合わせて期待を見直す）。
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。58 回目、第 44 組）: (a)。E0304 は同じ名前の空間の中の二つの名前だけ。空間は本体（項目、`use` の束縛、prelude、組込み型）、モジュールの名前空間（他のモジュールの経路の `main.X` が引く項目と子モジュール）、経路の頭（ルート直下のモジュールと依存のパッケージ名）で、項目は本体とモジュールの名前空間の両方にある。
  `use` の束縛と同じ名前の子モジュール（`main.onsa` の `use kp.inner` と `main/inner.onsa`）は重ならず、`main` の本体の `inner` は `use` の束縛を、他のモジュールの経路の `main.inner` は途中も最後も子モジュールを指す。R-250 の `hides_child` は通る。
  他のモジュールの経路が引くのは項目と子モジュールの定義だけで、`use` の束縛だけにある名前は E0302（R-250 の判断の延長）。E0200 の `pub use` と同じ名前の子モジュールがあれば、他のモジュールの `use main.{inner}` は子モジュールを指す。空間をまたぐ組（子モジュールとルート直下のモジュール・prelude、項目・`use` の束縛とルート直下のモジュール）は重ならない。
  prelude と同じ名前の項目（関数・定数・flow を含む）と `use` の束縛（`fn panic`、`use kp.panic`）は E0304（§15.1 の「prelude の名前は隠せない」を型と trait から広げた。S-79 と同じ理由）。prelude の名前を定義元から取り込み直す `use std.<モジュール>.{Option}` も E0304（候補なし）。
  `inner.h()`（`inner` は `use kp.inner`、`h` は無い）の型の段の E0401 は R-254。仕様 §15.1、§18.1
