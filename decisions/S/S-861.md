# S-861 std のソースにだけ現れる内部の書き方（名前の無い対象の `impl[T, const N: U32] [T; N]`、`Span[T]` を返す `target fn slice`、W5-05 の前の `T: AnyNum`）が、§15.2 の「std だけに許す書き方」に並んでいない

- 空白: §15.2 は std だけに許す書き方として、`target fn` の見出しの後ろの `else` の本体と、固有の `impl` のメンバの `target fn` を挙げる。W5-02 U1 の設計メモ（onsa-impl）の推奨の設計では、std のソースに、利用者が書くと誤りになる形がさらに三つ現れる。
  名前の無い対象の `impl[T, const N: U32] [T; N]`（利用者が書くと E0307「`[T; N]` is not the name of a type declaration」、§6.3・§4.4）、`Span[T]` を返す `target rt fn slice(self, from: U32, to: U32) -> Span[T]`（§5.3 の返り値の E0710）、W5-05 の前の境界 `T: AnyNum`（今は利用者の境界が E0200）。
  読み: (1) std の内部の書き方は処理系の実装で、仕様に書かない（S-853 が配列のメンバの与え方を「言語の規則はどちらでも同じ」とした読み）。(2) §15.2 の「std だけに許す書き方」に並べる。どちらでも通るプログラムと診断は変わらない（文書だけ）。
  再現は W5-02 U1 の設計メモの `impls.onsa`（106 回目の scratchpad の `w502/u1/probe/`、写しは `target/notes/106/w502u1/probe/`）
- 決定:
- 経緯: 106 回目（2026-11-03）、W5-02 U1 の設計メモ（onsa-impl）が NEW（G1）として挙げた。親が固定のバイナリ（`dc6570a1`）で `impls.onsa` の E0307 を再現した。設計メモの仮の扱いは (1)（SPEC-GAP の印は付けない）
