# S-732 const 引数の位置に、名前でない型の形（タプル型 `(F32, F32)`、関数型 `fn() -> I32`、配列型 `[F32; 3]`）を書いたとき、§15.1 の「型を const 引数の位置に書く」E0308 か、名前の種類の規則の外の E0401 か

- 決定済みで戻さないもの: 名前の形の E0308（`Ring[F32, F32]`、`Wrap[K]`、S-103・S-713）、頭が名前の型の E0308（U8b）、const 引数の中の負の数と型の違う定数の E0401（§4.5）、型引数の付いた定数は種類の中の形の違い（S-713 の B4）。
  第 68 組の下書きの「族「§15.1 の E0308 の位置」の仕組みの出所」と「S-732 の形の表」の節（写しは `target/notes/78/g68/draft.md`）。
- 論点: §15.1 は E0308 の例に「定数を型引数の位置に書く、型を const 引数の位置に書く」を挙げるが、E0308 の定義は「名前は見つかったが、その位置に要る種類でなければ」である。名前を持たない型の形を const 引数に書いたときのコードが書かれていない。
  同じ問いが逆向き（型引数の位置のリテラルと演算 `Wrap[3]`・`Wrap[K + 1]`）にもあり、今はどちらも型の段の E0401 である。
- 今の実装: 表のとおり。名前でない型の形は型の段の E0401 で、同じ単位の名前の段の誤りに隠れる。入れ替えた引数 `Ring[4, F32]` は後ろの `F32` の E0308、`Ring[4, (F32, F32)]` は前の `4` の E0401 で、同じ誤り（並びの順の取り違え）でも位置とコードが型に名前があるかで変わる。修正候補は無い（`--fix-loop` は `no-candidate`、`probe/s732/fx/t.onsa`）。
- 案: 
  - (1) 引数の種類の規則: 型引数の並びで、const パラメータに型（名前でない形も）を書くのも、型パラメータに定数式（リテラルと演算も）を書くのも、名前の段の E0308 にする。
  - (1') const パラメータの側だけを (1) にし、型パラメータの側のリテラルと演算は今の E0401 のまま。
  - (2) E0308 は名前の種類の規則とし、名前でない型の形と名前でない定数式は型の段の E0401 のまま（今の実装）。
  - 形ごとの出力: (1) は表の「—」の E0401 が全て E0308 になり、入れ替えた引数はどちらも前の `4` の E0308、後ろの E0308 との並びは位置の順になる。(1') は型の側だけ。(2) は今のまま。
  - 書き手から見て: どの形も直し方は一つ（その位置の要る種類のもの、定数か型を書く）である。現実に起きやすいのは、パラメータの順の取り違え（`Ring[4, (F32, F32)]`）で、名前の無い型の形をわざと書く書き手は少ない。
    (2) は同じ取り違えに、型に名前があるかで別のコードと別の位置を返し、`explain` の直し方も分かれる（E0401 は「式か型を合わせる」）。(1) は一つのコードと位置の順である。
  - 修正候補: どの案も候補は無い。当て続けても `no-candidate` で止まる。
  - 通るプログラム: どの案も変わらない。
  - 規則と例外: (1) は §15.1 の二つの例に「（名前でない型の形と定数式も）」と添え、E0308 が名前だけでなく型引数の並びの種類の取り違えも扱うことを書く（並びの外へは広げない）。
    (1') は片側だけの添え書きで、二つの向きのコードが違う非対称が残る。(2) は「名前でない形は E0401」の一文を足す。
  - 実装の量: (1) は `sig/types.rs::lower_type_arg` の二つの腕（`not_a_const_arg` と、型パラメータの `ConstArg`）を名前の段の E0308 にする（約 +4 −4 行）。(1') はその片方。(2) は 0 行。
    後の段への手当てはどの案にも無い。第 2 期に `U32` でない const パラメータ（今は `Feature::ConstGenericKinds` の E0200）を入れても、引数の種類の判定は同じ所にある。
- 他言語: 
  - rustc 1.94.1（`probe/other/s732.rs`）: const パラメータの位置の `(f32, f32)`・`fn() -> i32`・`[f32; 3]`・`Option<f32>`・`f32` は全て E0747「type provided when a constant was expected」、型パラメータの位置の `3`・`{K + 1}`・`K` は全て E0747「constant provided when a type was expected」（形によらず一つのコード）。
  - swiftc 6.3.1（`probe/other/s732.swift`、値の総称）: `(Float, Float)`・`Float`・`Optional<Float>` は全て「cannot pass type '…' as a value for generic value 'N'」、`W<3>` は「integer unexpectedly used in a type position」。
- 推奨と理由: (1)。確度: 中。
  - 型引数の並びでの型と定数の取り違えは、形によらず直し方が一つで、§18.1 は直し方が同じ誤りに一つのコードを当てる。§15.1 の例の文（「型を const 引数の位置に書く」）も、字のまま読めば形を限っていない。
  - (2) では、同じ取り違えの位置とコードが、型に名前があるかで変わる（表の入れ替えた引数の二行）。(1') は逆向きにその食い違いを残す。
  - 実装は一つの関数の二つの腕で、後の段に手当てが続かない。E0308 の広がりは型引数の並びの中に限り、他の位置には及ばない。
  - あわせて決めること: §15.1 の二つの例に添え書きをし、§4.5 の const 引数の文から指す。
  - 別の S にしてよい論点: 型引数の付いた定数 `Ring[F32, K[F32]]` の E0401 の文面（「not a type」と言うが `K` は定数）とコード（総称でない項目への型引数の E0412 か）。種類の中の形の違い（S-713 の B4）なので族の規則の外で、低い（下の新しい S の候補）。
- 影響: 仕様 §15.1（(1)・(1') は例の添え書き、(2) は E0401 の一文）、§4.5 の const 引数の文。`tasks/diag-codes.md` の E0308 の行（(1)・(1') は S-732 を足す）。
