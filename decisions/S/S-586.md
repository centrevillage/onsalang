# S-586 `onsa audit` で、flow の構造から決まる遅れ（集めて配る N と子の `@latency`）を経路ごとに示す形

- 空白: S-576（第 36 組）で、ホストに報告する遅れは一番外の flow の `@latency(e)` だけ（無ければ 0）とし、コンパイラは報告する値を本体から数えないとした。書き手が宣言を書く手掛かりとして、構造から決まる遅れを解析の道具（`onsa audit`）が出す（利用者の了承。専用の道具は作らない）。決めること:
  1. 出す値: 入力から出力への経路ごとの、集めて配る N（`.down~(N)`）と子の `@latency` の和。`.up~`・`.down~` の中の値の比での換算、端数の丸め、`delay~`・`vdelay~` と帰還の輪の扱い、`when~` と `if~`・`match~` の扱い。
  2. 出し方: `onsa audit` の旗の名前、経路の示し方（入力と出力の組ごとの値か、最大だけか）、宣言のある flow で宣言と構造の値を並べるか。
- 決定:
- 経緯: S-576 の下書き（onsa-gap）の新しい S の候補（経路ごとの遅れを示す）を、利用者の指摘（遅れには `.down~`・`.up~` の連鎖で決まるものとフィルタによるものがあり、前者は参考の基準値に使える）で、構造から決まる遅れを出す役に広げて立てた（2026-10-22、52 回目）。
  S-576 の旧い推奨 (k2) の合成の規則（経路の最大、比での換算、端数の丸め）は、この S の材料にする。関係: S-576、S-568、S-578、S-569（同じ `onsa audit`。旗の名前は一緒に決める）。
