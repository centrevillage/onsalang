# S-679 自分自身を取り込む `use`（`main.onsa` の `use main`、`dsp/synth.onsa` の `use dsp.synth`）を許すか

- 空白: §15.1 は「自分のパッケージは名前で参照しない」とし、取り込めるものにルート直下のモジュールを含め、循環の数え方で自分自身を除く。モジュールが自分自身を取り込む `use`（`main.onsa` の `use main`、`dsp/synth.onsa` の `use dsp.synth`）を許すかを書いていない。
  今（dev `30b09c5`）は通り、`use main` の後の `main.other()` も通る（`target/notes/66/g58/probe/selfuse`）。項目を取り込む `use main.{other}` は項目と重なる E0304。
- 決定: 決定（2026-10-25、利用者が親の読みを確かめて了承。66 回目、第 58 組）: 許さない。モジュールが自分自身を取り込む `use`（`main.onsa` の `use main`、`dsp/synth.onsa` の `use dsp.synth`）は E0302 で、修正候補は無く、note で自分のモジュールの項目は名前だけで書くこと（`other()`）を示す。
  自分の親（`dsp/synth.onsa` の `use dsp`）と子（`main.onsa` の `use main.inner`）を取り込む `use` は今のまま通る。今は通る形を止める向きだが、後で許しても壊れるプログラムは無い。実装は W4-03 の U3a2（S-673 の (d) と同じ `use` の頭の判定の所）。
- 経緯: 66 回目（2026-10-25）、第 58 組の独立のレビュー（onsa-advisor の段 1）が新しい S の候補として挙げた（S-673 の (d) を採ると、この `use` を要する書き方が無くなる）。利用者が「許さない」とし、問題が出たら許せるとした。
