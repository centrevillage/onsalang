# S-745 `par` を `par~` に改名する（`ser` も `ser~`。flow の構造の複製を `if~`・`match~` と同じ `~` の印にし、`~` の無い語を fn の側に残す）

- 空白: 利用者の提案（79 回目）。flow の構造の複製は今 `par i in a ..< b { e }` と書き（§11.5）、`~` を付けない。直列の複製の `ser`（§19.1）は予約だけで、今は E0200。
  `if`・`match` は fn と flow の両方にあり、flow の全ての枝を評価する形だけを `if~`・`match~` と書く（§2.6）。`par` と `ser` は fn の側でも意味を持ちうるので、そのとき flow 用と fn 用を分ける必要が出る。
- 決定: 決定（2026-10-28、利用者。79 回目。利用者の提案で、親が今の扱いを確かめて 1〜5 の読みを例で言い直し、利用者が了承）: flow の構造の複製を `par~ i in a ..< b { e }` と書く（`let saws = par~ i in 0 ..< 4 { saw~(f0 * detune(i)) }`）。
  利用者の理由: `par` と今後入れる `ser` は fn の側でも意味を持ちうる。そのときに flow 用と fn 用を分けるので、`if` に対する `if~`、`match` に対する `match~` と同じ扱いに予めしておく。
  1. `~` は `par` の直後に空白なしで書く。`par ~` は E0020 で、空白を除く候補（`if~` と同じ字句の規則、§2.6）。
  2. flow の本体の `~` の無い `par i in …` は E0811 で、`~` を足す候補（flow を `~` 無しで呼ぶ形と同じ）。flow の外は `~` の有無によらず E0821（今と同じ）。`par` は予約語のまま残す。
  3. §19.1 の直列の複製の予定の形も `ser~` にする（今は `ser`・`ser~` とも E0200）。
  4. 状態を持つものを含まない `par~` も誤りにしない。`~` を外した形が無いので E0812 を当てない（状態のフィールドを作らないのは今と同じ）。`if~`・`match~` と違う所である。
  5. 状態のノードの名前は `par_0` のまま（`prev~` の `prev_0` と同じ）。
  仕様の文（§2.2、§2.6、§3、§7、§11、§19.1 など約 44 か所）は、W4-20 で実装と同じ作業で改める（仕様だけを先に変えると、事例と食い違う期間ができる）。W4 の終わりに行う（利用者）。
- 経緯: 79 回目（2026-10-28）、利用者の提案。親が今の扱い（§11.5 の `par`、§2.6 の `if~`・E0811・E0812・E0821、§19.1 の `ser` と今の E0200）を確かめた。関係: W4-20。
