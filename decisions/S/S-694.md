# S-694 型で有無が決まる flow の生成項目（`process_inplace`）が無い flow から取り込む `use` を、E0310 の依存に数えるか

- 空白: §18.1 は失敗した名前を依存（E0310 の辺）に数えない（S-678、S-688）。§11.6 の `process_inplace` は `sample` の入力と出力の数と型を比べて有無が決まるので、無いと分かるのは名前の段（E0310 を出す段）の後の署名の段である。無い `process_inplace` を取り込む `use`（E0302 で名前は失敗した名前）を辺に数えるかを書いていない。
  読みは (1) 名前の段では解決したので辺を張る、(2) 失敗した名前なので辺を張らない（E0310 を署名の段の後に回すか、その `use` だけ辺を後で外す）、に割れる。当たるのは、その `use` の辺だけで循環が閉じる形。
  W4-03 U3b2 の実装（69 回目）は (1)。`params_default` は S-625 で名前空間から外れる（W7-03）ので、型で有無が決まる生成項目は `process_inplace` だけになる。急ぎ: 後の段。
- 決定: 決定（2026-10-25、利用者。69 回目、W4-03 U3b2 の壊す側の再確認の後）: (1)。型で決まる有無は名前の段より後の段の誤りと読む（§18.1 の段の順）。無い `process_inplace` を取り込む `use` は名前の段では解決したので E0310 の辺を張り、署名の段の後に E0302 を出し、以後の本体の使う所は黙る。署名の型の位置に書いた名前は関数の名前なので、有無によらず通常の関数の名前と同じ誤り。
  理由: 後に回す束縛（名前の段で仮に失敗した名前にし、署名の段の後に有無を決める）は、二往復の確かめで型の位置の読み、E0304 の向き、自分の生成項目を読む循環（check が通り降下が内部エラー）と欠陥が続き、実装が収束しない（`rules/criteria.md` 7.36）。この読みでは仕組みが要らず、§18.1 の「名前の段で失敗した `use`」にも当たらないので例外の規則にならない。仕様 §11.6 に一文。実装は W4-03 U3b2 の直し。
- 経緯: 69 回目（2026-10-25）、W4-03 U3b2/i（onsa-impl）の「設計の要点と限界」から登録した。関係: S-678、S-688、S-625、R-50。
- 補い（2026-10-25、親）: 69 回目（文書の点検の F9）: `Out` も出力の型（struct か）で有無が決まる（§11.6）。今は常に作り、U3b2 の後は struct でない出力の flow の `use g.{Out}` が通る（dev は E0302）。経路の `dsp.g.Out` は dev でも通る。W7-03（R-264）で有無を入れるときに扱いを決める（R-264 の補い）。
- 補い（2026-10-25、親）: 69 回目（二度目の文書の点検の F1〜F3、利用者が了承）: 仕様 §18.1 の失敗した名前の段落に一文（名前の段では解決した束縛で E0310 の依存に数え、型の段で無いと分かれば E0302、以後は失敗した名前。署名に誤りのある flow で有無が分からないときは E0302 も出さない）、§15.1 の E0310 の段落を「§18.1 の名前の段の失敗した名前」に、§11.6 の「署名の段の後」を「型の段」に改めた。
