# S-741 族: §15.1 の型の位置から見える値の束縛

- 空白: §5.1 は名前空間を分けず、§15.1 は「名前は見つかったが、その位置に要る種類でなければ、位置によらず E0308」（定数式の位置の値は S-713 (a1) の E0417）とする。S-729 は、本体の型の位置（注釈、`as`、無名関数の引数と返り値の型、型引数）が見えているローカルの束縛と引数を引くと決めた。
  型の位置（と効果行・型の中の定数式）が、どの値の束縛を見えているとするかを、位置ごとに書いていない。署名の型の位置と引数（S-733）、本体と署名の効果行（S-738）、宣言の型の注釈と、その宣言が作る束縛（S-739）、flow の本体の後ろの `let`（S-740）で、今の実装は E0302「cannot find」と E0308・E0417・E0801 に分かれる。
  族の規則の案: 型の位置から見える値の束縛の範囲を一つの規則で決める（例: 値の位置と同じ範囲。または、位置の種類ごとの決まった範囲）。この族の S: S-733、S-738、S-739、S-740。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。79 回目、第 69 組）: 族の規則を置き、引数の範囲は (b)。
  束縛の見える範囲は一つで、値の位置にも型の位置（型の中の定数式と効果行を含む）にも同じく当てる。fn の本体の `let`・`var`（分解を含む）はその文の後ろから見え、自分の注釈と初期化式からは見えない。flow の本体の `let` は本体の全体で見え、値の位置の順は §11.2（S-740）。
  引数・flow の入力（メソッドの `self` を含む）は、型パラメータ・const パラメータ・効果行変数と同じく、その項目の見出しの全体と本体で見える（無名関数の引数はその式の中）。見えている値の束縛を型の位置に書くと E0308、型の中の定数式に書くと E0417。
  どの案でも通るプログラムは変わらない（E0304 でローカルの名前は他の束縛と重ならない。子モジュールと `self` の形でも確かめた）。
  仕様は §5.1 の型パラメータの文に引数と flow の入力を足し、範囲の文を書いた。§15.1 の E0308 の例の「本体の型の位置では」を外し、§8.1 の E0308 の例に `uses {n}` を足した。`tasks/diag-codes.md` の E0308・E0417 の行に足した。
  実装は W4-19（新しい作業、W4-05 の前。利用者が了承）。
  名前の段に閉じ、族の全体で約 +30〜50 行: `lower_fn`・`lower_flow` で `Cx::locals` に引数（`self` も）と入力を入れる、境界と効果行は `heading_name` の `listed` にローカルを足す（経路の頭がローカルなら `resolve::no_members` の E0308）、`heads` に関数型の効果行の頭を足す、無名関数は `ahead` で仮に宣言して型と効果行を集める。
  署名の型の引数の使用を `note_use` で記録する（記録しないと `fn f(_n: U32, a: [F32; _n])` の E0320 の候補が宣言だけを直し、約束の違反になる。約 +2〜4 行）。`sig.rs` の 67 行のコメント（S-733）を改める。
- 経緯: 79 回目（2026-10-28）、親が第 69 組の前に登録した（S-733・S-738・S-739・S-740 は族の規則の S を持たず、近い S-729 の族の規則 S-713 は名前の種類の規則で、見える範囲の規則でない）。期限は族の S のいちばん早い S-733 の W4-06。関係: S-713、S-729。
