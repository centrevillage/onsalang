# S-943 閉じない `{` の回復の報告の細部: 二つ閉じないときに指す `{`、タブと空白の混ざった字下げの比べ、深い字下げの項目の語

- 決定済みで戻さないもの:
  第 92 組の下書きの写しは `target/notes/122/g92/draft.md`、入力は `target/notes/122/g92/probe/`・`other/` と `target/notes/122/adv92/`。
- 項目の始まりの定義と、回復が止まる位置（S-593 の (3)、S-487）。
- `(`・`[` に `{` と同じ規則を当てること（S-280）。§18.1 の「宣言の単位で回復する」。
- 閉じない文字列と閉じない区切りのトークンは行末までで、行の残りを読まないこと（S-438、S-406、S-467、S-856）。
- 誤りが二つある入力は候補の約束の外であること（S-384）。
- E0006 の単位に閉じない括弧の E0002 を出さないこと（§2.5）。
- S-937・S-941・S-942 は字句の並びの細部で、ここには関係しない。
- 論点: §18.1 は「`{` が閉じていなければ、それを開いた行と同じか浅い字下げの行頭にある項目の始まり（上記）で回復し、閉じていない `{` を指す E0002 を出す」とする。次の三つが書かれていない。
  - (1) 閉じない括弧が二つ以上のとき、どれを指すか。文は `{` を一つと読める。
  - (2) 字下げの比べでタブと空白が混ざった行。§2.5 は空白を U+0020 とタブとし、`spec/tools.md` §3.2 はタブを使わないとする。タブの幅は書かれていない。fmt は構文の誤りのあるファイルを書き換えないので（§18.2）、混ざった行は誤りのあるファイルに残る。
  - (3) `{` の行より深い行頭の項目の語。深い語では止まらない（S-280）。その後ろに浅い項目が無いと、§18.1 に書かれていないファイルの終わりの扱いになる。これは R-371 と同じ判断なので、R-371 の案で決める。
  - **組の共通の節: 仕組みの出所と目的**
    - **回復の目的（§18.1）:** 「単位どうしは独立に検査し（P1）、全ての単位のエラーを一度に報告する。修復ループ（P8）の回数を減らすためである」。誤りのある宣言も名前まで読めれば見せるのは「正しい宣言に偽の連鎖エラーを出さないため」である。
      報告は単位に一つで、「`diagnostics` の並べ方（開始の位置、終わりの位置、コード、文面の順）で最初のもの」である。閉じない括弧の E0002 は開きの位置を指すので、同じ単位の他の誤りより前に並ぶ。これが三件の共通の根である。
    - **字下げを回復にだけ使う理由（§2.5、§18.1）:** 「インデントは意味を持たない」。閉じ括弧の無い本体がどこで終わるかはトークンから決まらないので、推定にだけ字下げを読む。推定なので正しいプログラムの意味に触れない。
      S-280 は、深い `@param` で止めると一つの flow に E0002 が二つ出た（W3-03/b）ので、「同じか浅い」に限った。
    - **`skip_unit` の判断（2026-10-08、W3-03 `853db2a3`）:** 注釈は「ファイルの終わりでは、読みがそこで止まったときだけ閉じない括弧を報告する。別の誤りが先に止めたとき（E0006 など）は、開いた括弧はその誤りから従うので診断を出さない」とする。
      仕様に残ったのは E0006 の文だけである（§2.5「E0006 を出した単位は、そこで読み取りを止める（閉じていない括弧の E0002 は出ない）」）。§18.1 にファイルの終わりの文は無く、診断の note の規則の文だけが「or at the end of the file」と書く。
      確かめた事実: 読みが止まった後も `skip_unit` は全ての括弧を `scan::pair` で数える。よってファイルの終わりに開いている括弧は、閉じ括弧が本当に足りない（閉じ括弧がリテラルやコメントに飲まれたときを除く）。
    - **閉じない文字列を行末までにする理由（S-438、S-406、S-856）:** 文字列は行をまたげない（§2.4）。残りを Onsa のトークンとして読むと、残りの `/*` がファイルの終わりまでを飲む形を作り、中身を読まない規則に例外が要る（S-856 の (ii) の検討）。
    - **三つの止まり方:** `skip_unit` が単位を終える位置は、(i) 同じか浅い行頭の項目の始まり、(ii) ファイルの終わり、(iii) メンバではメンバの並びを閉じる `}` である。(i) は閉じない括弧を報告する。(ii) は読みがファイルの終わりに届いたときだけ報告する。(iii) は報告しない。

  - (1) 指す括弧。例は N1 と N6 である。

      - (1-c): 一度の報告で全ての位置が分かるので、1 回で直せる。読むのは note である。note を読まない使い手には (1-a) と同じである。
