# S-765 `Option[T]`・`Result[T, E]` の型パラメータの暗黙の `Dup`: §4.1 の std の宣言の文（`pub enum Option[T]`）は §4.5 の暗黙の `Dup` に読め、`Option[Buf[F32]]` が E0416 になるが、§4.1 の表は種を「中身に従う」とし、事例と std の書き方は `Option[Buf[F32]]` を使う

- 空白: §4.1 は `Option`・`Result` を std で `pub enum Option[T]: PartialEq + Eq + Hash + Show { None, Some(T) }`・`pub enum Result[T, E]: … { Ok(T), Err(E) }` と宣言された enum とする。
  §4.5 の 143 行は型パラメータに暗黙の `Dup` を付け、Affine を受けるには `[T: ?Dup]` と書くとする。字のとおりに読むと `Option[Buf[F32]]` は §4.5 の 146 行の E0416 になる。
  一方、§4.1 の表は `Option`・`Result` の種を「中身に従う」とし（Affine の中身なら Affine）、既にある事例は `Option[Buf[F32]]` を通す（`tests/spec/semantics/match_flat.onsa` の 101・116 行、`tests/spec/negative/modes.onsa` の 98・105 行、`tests/spec/fmt/rewrite_move_kept.onsa` の 52 行）。
  今の実装（`body/bounds.rs::satisfies`）も中身で判定する。
  W4-05 U4a のテストの票（NEW-2）が、署名の型引数の要求の E0416 を書く所で挙げた。
  読み: (1) std の宣言の文を `pub enum Option[T: ?Dup]`・`pub enum Result[T: ?Dup, E: ?Dup]` に改める（表と事例と今の実装に合う。derive の trait は中身が満たすときだけ、§6.4）。(2) 字のとおり `Option[Buf[F32]]` を E0416 にする（既にある事例と std の書き方を壊し、Affine の値を持つかもしれない返り値を書けなくなる）。
- 決定: 決定（2026-10-29、利用者。82 回目。確認だけ）: (1)。
  `Option`・`Result` の std の宣言を `pub enum Option[T: ?Dup]`・`pub enum Result[T: ?Dup, E: ?Dup]` とする（§4.1 の宣言の文の書き漏れ）。`Option[Buf[F32]]` は書け、種は中身に従う（§4.1 の表）。derive の trait は中身が満たすときだけ（§6.4）。
  理由: §4.1 の表と、既にある事例（`match_flat.onsa`・`modes.onsa`・`rewrite_move_kept.onsa`）と今の実装に合う。字のとおりの読み（E0416）は既にある正しいプログラムを壊す。
  仕様は §4.1 の宣言の文。実装は W4-05 U4a（整形性の段の組込み型の行で `Option`・`Result` の引数に要求なし）。事例は `tests/spec/types/wellformed_element_copy_fine.onsa` の `Option[Buf[F32]]`。
- 経緯: 82 回目（2026-10-29）、W4-05 U4a のテストの票（onsa-test）が仕様の空白の候補（NEW-2）として挙げ、親が §4.1 の文と事例を確かめた。親の読みは (1)（表と事例と今の実装に合う。§4.1 の宣言の文の書き漏れ）で、確認だけにする。期限は W4-05 U4a（整形性の段の組込み型の行）。U4a の実装には (1) を仮に伝えた。関係: S-756、R-37。
