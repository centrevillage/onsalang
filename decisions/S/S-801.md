# S-801 `move` の引数に渡す Dup の値の場所（`bm(n, n)`、二つ目の引数が `move m: U32`）を、同じ呼び出しの他の引数との重なり（E0702）に数えるか

- 空白: §5.2 の 70 行は「`move` の引数に渡す場所が、同じ呼び出しの他の引数（`inout`、借用、`move`）の場所と重なるときも E0702」とし、64 行は「`move` 引数に渡す Dup 値（Copy、Shared、関数値の変数）には `move` を書かず、その場で複製して渡す」、69 行は「引数の中で同じ変数を読んで値を作るだけなら重ならない」とする。Dup の値の場所を `move` の引数に渡す形が 70 行の「場所」に入るかを、文は決めていない。
  W4-07 U4a の新しい modes は 70 行の字面どおり場所として数え（`calls.rs` の `SPEC-GAP`）、`bm(n, n)`（`bm(n: U32, move m: U32)`）、`mm(n, n)`（両方 `move`）、`io_move(inout n, n)`（二つ目が `move`）、S-796 と重なって `match o { Some((x, y)) => bs(x, y) }`（`Str` の腕の束縛は対象の全体、`bs(s: Str, move t: Str)`）が E0702 になる。`io_move(inout n, n + 0)` は通る。
  dev（`c867200`）は S-609 の前で、これらに E0703（`move` の挿入）を出すので比べられない。借用の引数の `io_and_copy(inout n, n)` は dev も新しい側も E0702（§5.2 の 68 行）。再現は `target/notes/88/s801/dup_move.onsa`（親が U4a を一時につないだ `P88/bin/onsa-u4awired` で確かめた）。
  読み: (1) 字面どおり場所として数え、他の引数（`inout`、借用、`move`）と重なれば E0702。(2) 64 行の複製はその場で作る値なので、69 行の「値を作るだけ」と同じく、どの引数とも重ならない。(3) 借用の引数と同じく読むものとして、`inout` とだけ重なる。
- 決定: 決定（2026-10-30、利用者。88 回目。独立のレビュー（onsa-advisor の段 1、想定漏れの表 約 35 形）と親の読みが一致）: (3)。`move` の引数に印を書かずに渡す Dup の値の場所と、Dup の値の `move self` の受け手（`p.plus(p.x)`、`plus(move self, k: U32)`、`P` は Copy。dev は通り、W4-07 U4a は E0702 にしていた）は、複製して渡すが、重なりでは借用の引数と同じくその場所の読みとして数える。`inout` の場所と重なれば E0702（`io_move(inout n, n)`）、読みどうしは重ならない（`bm(n, n)`、`mm(n, n)`、`bs(x, y)`）。
  理由: S-609 で Dup の値に印を書かないので、呼び出しの行では借用の引数と区別が付かず、(3) なら呼び先の宣言（借用か `move` か）によらず同じ行が同じ結果になる。(2) は Dup の引数を `move` で宣言すると呼び出し側の検査が緩くなる動機を作る。後で (2) へ緩めても (3) で通るプログラムは壊れない。
  Dup かは呼び出しの位置の具体の型で決まる（`T: ?Dup` の関数を `U32` で呼ぶ形も読み）。仕様 §5.2（70 行の後）。W4-07 U4a で `calls.rs::passed` を直す。段 1 の報告と入力は `target/notes/88/s801/`。
- 経緯: 88 回目（2026-10-30）、W4-07 U4a の実装の担当（onsa-impl）が空白として報告した。親が U4a を一時につないだバイナリで再現し、借用の引数と値の引数の対照を足して登録した。
