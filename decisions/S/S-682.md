# S-682 `use` の頭の自分のパッケージ名の候補（S-663）を、足す辺が循環を閉じるので出さないときの note（`cyc3` で一つを当てた後の `use fx.a.{f}`）

- 空白: §18.1 は、当てた後に同じ段の誤りが残る候補を出さない。S-663 の `use` の頭の自分のパッケージ名の候補（`fx.` を外す）は、足す辺が循環を閉じるときは出ない。S-673 は本体の経路の候補について「候補を出さないときの note は正しい形を示す」としたが、`use` の頭の E0302 の同じ場面は書いていない。
  今（`c335496`）は、`tests/review-phase1/types/cyc3` の形（`use fx.b.{g}` と `use fx.a.{f}`）で一つの候補を当てると、残った E0302「cannot find `fx`」に候補も note も無く止まる。片方だけが自分のパッケージ名の形（`target/notes/67/g59/probe/g_cyc3_one`）も同じ。書き手は外せば循環になることを知らずに外し、次の検査で E0310 を見る。
  S-678 の読みによって要るかが変わる（意図したモジュールへ辺を張る読みでは E0310 が先に出る）。
- 決定: 決定（2026-10-25、利用者。67 回目、第 59 組、ID を挙げて確認だけで了承（A10））: (a)。`use` の頭の自分のパッケージ名の候補（S-663）を、外した形が循環を閉じるので出さないときは、note で外した形と、それが閉じる循環の相手のモジュールを示す。本体の経路の候補（S-673）を循環で出さないときも同じで、循環を閉じる形を正しい形として勧めない（`main.inner.g()` の rule）。
  仕様は §15.1 の S-663 の文に一文。実装は W4-03 の U3b（約 +5〜10 行）。
- 経緯: 67 回目（2026-10-25）、第 59 組の下書き（onsa-gap）が見つけた。関係: S-663、S-673、S-678。
- 補い（2026-10-25、親）: 本体の経路の同じ場面（67 回目、W4-03 U3a2 の壊す側）: `main.inner.g()` の S-673 の候補（`use main.inner` を足す）を循環を閉じるので出さないとき、rule が同じ `use main.inner` を勧め、当てると E0310 になる（`target/notes/67/w403/u3a2/b/t/c_s9_child_cycle.txt`）。
  S-673 の「候補を出さないときの note は正しい形を示す」の読みとして、この S と一緒に決める。
