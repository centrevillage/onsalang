# S-349

- 決定済みで戻さないもの: S-961 の決定と、その決定済みで戻さないもの。第 94 組の下書きの全文（「族の仕組みの出所」「族の形の表」）の写しは `target/notes/127/g94/draft.md`、入力は `P127/g94/probe/`（消えうる。`P127` は 127 回目の scratchpad）
- 論点: S-320 の `決定` は「二項の演算子の後に空白を空けずに書いた前置の `-`（`a--b`）」を E0020（候補 `a - -b`）とし、`--` の前後に空白や改行がある形を書かない。字句は `--` を一つのトークンにする。
  `--` と後ろの被演算子の間の隙間を S-961 の隙間と読むか、増減の `--` と読むかで割れる。行末の `--` は二項演算子でないので、継続の規則では行がそこで終わる。
  - 決定済み（論点から外す）: 接する `a--b`（S-320）、`---x`（S-297）、増減の行（S-250）。文の位置の空白のある `x --` はこの組の S-429 の論点である。
- 今の実装: `a --b`、`a --(b)`、`[a --b]`、`two(a --b, 1)` は E0020 で候補 `a - -b`（並びの中でも一つ。`SPEC-GAP(S-349)`）。`a-- b`、`a -- b` は増減の E0002（候補なし）。
  `a --` 改行 `b`、`a -- // c` 改行 `b`、`two(a --` 改行 `b, 1)` も増減の E0002。`a -` 改行 `-b` は通る（`s349e`）。文の位置の `x --` 改行 `y = 0` は E0002、`x--` 改行 `y = 0` は増減の E0020（`u/inc_*`）。
- 案: 
  - (a) 二つの被演算子の間の `--` は、前後の隙間（同じ行の空白、改行、間の行コメント）によらず S-320 の E0020。候補は `a - -b` で、後ろが改行なら二項の `-` を行末に残し、前置の `-` を被演算子の行へ移す（`a -` 改行 `-b`）。
  - (b) 今の実装のまま: 後ろの被演算子に接するとき（`a --b`）だけ S-320 の形。後ろに隙間があれば増減の E0002。
  - (c) 同じ行の隙間（`a --b`、`a-- b`、`a -- b`）は S-320 の E0020 で、候補 `a - -b` が隙間も除く。後ろが改行の `--` は行末の増減として読む（式の位置は増減の E0002、文の位置の `x --` は S-429 の答えの形）。
  - 形ごとの出力: `a --b` はどの案も E0020 と `a - -b`。`a-- b`・`a -- b` は、(a)・(c) が E0020 と `a - -b`、(b) が E0002。`let c = a --` 改行 `b` は、(a) が E0020 と `a -` 改行 `-b`、(b)・(c) が E0002。
    文の位置の `x --` 改行 `y = 0` は、(b)・(c) が S-429 の答えの形（今は増減の E0002。次の行は触らない）。(a) は字面では S-320 の形（`x - -y = 0`）になり、増減と読むには「`--` の後で文が終わるとき」の例外が要る。
  - 書き手から見て: 文の位置で `x --` の次の行に文を書くのは C 系の普通の書き方で、(a) は例外が無いとそれを二項の式に読み、候補が意図と違うコードを作る。`a --` 改行 `b` の式は、JavaScript が `a--` と次の文に読み（下）、意図が一つに決まらない。
    (b) は `a-- b` で候補が無く、`a --b` と字面の近い形で結果が割れる。(c) は同じ行の形を一回で直し、改行の形は増減の note を見て手で直す。
  - 修正候補: どの案も当て続けて止まる。(a) の改行の候補の結果 `a -` 改行 `-b` は通る。(c) の候補は同じ行だけで、意図は Rust と Python の読みの一つ（C 系と JavaScript は同じ行の形を誤りにする）。
  - 通るプログラム: どの案も変わらない（形は全て今誤り）。`tests/`・std・`examples/` に当たる形は無く、`tests/spec/fixes/e0020_binary_minus.onsa` は接する形だけで期待は変わらない。
  - 規則と例外: (a) は S-320 の文を「隙間によらず」に広げ、文の終わりの `--` の例外を一つ足す。(b) は「後ろの被演算子に接する」の条件を S-320 の文に書く（同じ行の後ろの空白が S-961 の (iii) の外になる例外）。
    (c) は S-961 の (iii) の同じ行の隙間そのままで、改行は継続の規則（行末の `--` で行が終わる）のままなので、例外を足さない。
  - 実装の量（`foreign/assign.rs::binary_minus_minus` と候補）: (c) は後ろの同じ行の空白を許し、候補の置き換えの範囲に空白を含める約 +3〜6。(a) は (c) に改行の候補（二つ目の `-` を `move_token_down` の形で移す）と文の終わりの除外で約 +10〜15。(b) は 0（`SPEC-GAP(S-349)` を外す）。

- 他言語: 
  - Apple clang 21（`other/c2.c`〜`c4.c`）: `a --b`、`a -- b`、`a --` 改行 `b` はどれも「expected ';' after return statement」（`a--` と読んで `b` で止まる）。
  - rustc 1.94.1（`other/r1.rs`）: `a --b`、`a -- b`、`a --` 改行 `b` は `a - (-b)` で通る。
  - Node 26.11.1（`other/j.js`）: `a --b`、`a -- b` は SyntaxError「Unexpected identifier 'b'」。`let c = a --` 改行 `b` は通り、`a--` と次の文 `b` に読む（`c` は 5、`a` は 4）。
  - Python 3.14.5: `a --b`、`a -- b` は `a - (-b)`。`a --` 改行 `b` は SyntaxError。swiftc 6.3.3: `a --b` は「consecutive statements on a line」。
- 推奨と理由: (c)。確度: 中。
  - 同じ行の形は、どの言語でも通るなら `a - (-b)` で、C 系と JavaScript は誤りにする。S-320 の割れ方と同じで、S-961 の「形の誤りが先で、候補が隙間も直す」をそのまま当てられる。
  - 改行の形を S-320 に読むと、文の位置の `x --` 改行 `y = 0` と字面が重なり、増減と読むための例外が要る。JavaScript は改行の形を増減と次の文に読み、意図が一つに決まらない。改行で行が終わる継続の規則のまま増減と読む方が、規則も実装も増えない。
  - (b) は `a --b` と `a-- b` で結果が割れる表面の違いを残す。
  - あわせて決めること: 並びの中の `[a --b]`・`two(a --b, 1)` の候補は一つ（`,` の挿入は並べない。`--b` は Onsa の要素として読めず、S-398 の非対称な空白の二つ目の読みが無い）。`a --/* c */b` は S-960 による。`a ---b` は表の外（今の E0002）。
