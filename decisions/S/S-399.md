# S-399 前が名前でないトークンの後の、同じ行の空白の後の `(`・`[`

- 空白: 前が名前でないトークン（`)`・`]`・`}`・リテラル）の後の、同じ行の空白の後の `(`・`[`（`[(1, 2) (3, 4)]`、`two(f(x) (y))`、Julia の横の連結 `[[1, 2] [3, 4]]`）。
  S-89 の E0020 の候補「空白を除く」は、`(` の形と `[[1, 2] [3, 4]]` では構文の段の `callee_expression` などの誤りを残して S-236 で落ち、候補なしの E0002 になる（呼び出しの結果の後の `[h(x) [0]]` は空白を除いた `h(x)[0]` が正しい添字で残る。第 20 組の下書きが直した）一方、S-387 の (a) では `[(1, 2) p]` に `,` が出る。
  改行の形は S-373 が前のトークンで分けた（前が名前でなければ改行を除く形を出さない）。同じ行でも、前が名前でなければ S-89 の候補を出さず `,` の挿入にするか。S-89 の決めた例（`f (x)`、`xs [0]`）は前が名前なので変わらない。第 19 組の下書きの付録が見つけ、Fable が範囲を広げ急ぎを上げた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (b) を了承し、「前が名前」の判定は Fable の案（名前の経路）とした。下書きと Fable は主の案で一致し、判定の単位で割れた、第 20 組）: 同じ行の空白の後の `(`・`[` で、前が名前の経路（呼び先になれる形、§6.1。名前、`p.x` のフィールド、`t.0` のタプルの添字、型引数の付いた名前。判定は `foreign::callee_by_name` の一つ）でないとき（`)`・`]`・`}`・リテラル・`?` の後）は、並びの中では S-89 の改行の形と同じく `,` の無い二つの要素の E0002 で、候補は `,` の挿入と、読めれば空白を除く形（この順。`[(1, 2) (3, 4)]` は `,` だけ、`[h(x) [0]]` は `h(x), [0]` と `h(x)[0]`）。
  読めるかはトークンの走査で決め、次の要素を試しに読まない。並びの外（`let v = g(x) (y)`）と、前が名前の経路の形（`f (x)`、`xs [0]`、`p.x (y)`）は S-89 の空白の E0020 のまま（候補が S-236 で落ちれば E0002）。S-89 の決めた例の出力は変わらない。仕様 §2.5。
  実装は W3-06（S-89・S-384 と同じ所、約 5〜15 行）（読みの補い、2026-10-10、親: 前が名前の経路でも、空白を除いた形が読めないとき（型の位置の `(I32 [I32; 2])` など）は、並びの中では S-384 の `,` の抜けの E0002 で、候補は `,` の挿入。並びの外は候補なしの E0002。W3-06/b が見つけた）
