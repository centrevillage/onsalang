# S-500 ブロック形の構造体のパターンの `..` の後の `,`

- 空白: ブロック形の構造体のパターンの `..` の後の `,`。§3.2 は、ブロック形では全ての要素の後に `,` を置くとするが、`..,` は E0002（「expected `,` or `}`, found `,`」）。`..` を要素に数えるか。W3-11/i の設計メモの G5（2026-10-13）
- 提案: 決定（2026-10-14、利用者が ID を挙げて親の改めた推奨 (A)（下書きの (a)）を了承。下書きと Fable が一致、第 29 組）: `..` を要素に数えず、ブロック形でも後ろに `,` を置かずに独立の行に残す。利用者は「言語に無い形が構文の誤りにならない」こと（S-366）と、その形に fmt がかかることを問うた。
  親は fmt がそのファイルを書き換えない案 (B) を一度推したが、rustfmt 1.8 と swift-format 6.3 も型・名前の誤りのあるソースを整形し、rustfmt は後の段で拒む `impl Tr for S { pub fn f() }`（E0449）も整形すると確かめて、(A) に改めた。fmt の止まる条件（構文の段の診断だけ、S-120）に例外を足さない。
  S-366 は保つ。`spec/tools.md` §3.2。実装は W3-11 の U2（仮の扱いで済み）と U3
