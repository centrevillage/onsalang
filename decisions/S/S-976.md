# S-976 struct リテラルに角括弧と山括弧で書いた型引数（`Pl[I32] { a: 1 }`、`Pl<I32> { a: 1 }`）の診断

- 空白: §4.5 は他言語の形の型引数の一覧に、呼び出し（`parse[I32]("3")`、`parse<I32>("3")`、`parse::<I32>("3")`）、型の経路（`Buf[F32].zeroed(4)`）、メソッド、呼ばずに値に置いた形を挙げ、struct リテラル（式の中は `Pr::[U8] { a: 250 }`）の他言語の形を挙げない。今は `Pl[I32] { a: 1 }` が `{` の位置の一般の E0002「expected newline or `}`, found `{`」、`Pl<I32> { a: 1 }` が `:` の位置の一般の E0002、`Pl::<I32> { a: 1 }` だけが E0020 で候補 `<`・`>` を `[`・`]` に（当てた後の `Pl::[I32] { a: 1 }` は正しい形）。型の位置の `Pl[I32]` からの類推で書きやすい。決めること: 行を立てるか（§18.1 の行の基準、`rules/criteria.md` 7.32 の一覧の言語が正しい形として書くか）、一般の規則のままか。再現: 95 回目の scratchpad の `g95/advisor/probe/c03_struct_lit.onsa`（写しは区切りで `target/notes/132/g95/`）。
- 決定: 決定（2026-11-12、利用者「他の (A) は現状で OK」。140 回目、W5-13 の前の確認だけ）: 今の実装のまま。struct リテラルに角括弧と山括弧で書いた型引数（`Pl[I32] { a: 1 }`、`Pl<I32> { a: 1 }`）は一般の E0002 で、他言語の形の行は立てない（`Pl::<I32> { a: 1 }` は前からの E0020 で、候補は `Pl::[I32] { a: 1 }`）。親は `::` の候補を出す行を立てる案も示した（実装を足す）。仕様は変えない。
- 経緯: 132 回目（2026-11-10）、第 95 組の独立のレビュー（onsa-advisor の段 1）が見つけ、親が今のバイナリ `87c2b2a` で再現して登録した。急ぎでない（構文の段の形で W5-10 は触らない）。期限は W5 の見直しの W5-13 にした。
