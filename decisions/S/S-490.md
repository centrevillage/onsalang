# S-490

- 空白: 同じ項目に同じ Onsa の属性を複数書いた形（`@fp(relaxed) @fp(relaxed) fn`、`@repr(c) @repr(c) struct`）。§6.5 は重複の扱いを書かない。今は通す。W3-08/b1 の空白 G-2（2026-10-13）。旧版の `@derive` の複数は `rules/criteria.md` 7.32 で対象にしない
- 提案: 後の段
- 時期: W3
- 補い（2026-11-09、親）: flow の一つの入力に同じ属性を二度書く形（`@param(min: 0.0) @param(max: 1.0) x: F32 at block`）も今は通る（dev `5d5cd987`。§11.7 の「同じキーは一度だけ」は一つの属性の中の決まり）。128 回目の独立の検討が見つけた。この S の規則で決める。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R9、B2、Y）一つの場所に同じ属性を二度付ける形は、引数によらず E0005 で、重なる最初の属性（二つ目）に付け、一つ目を note で示し、修正候補は無い（全く同じ要素でも候補を付けない）。一つの flow の入力の `@param(min: 0.0) @param(max: 1.0)` も同じ。 重なりの判定は、置く位置を誤った属性（`@fp(relaxed) pub @fp(relaxed) fn h`）も同じ場所の属性に数える（Y）。
  - 仕様の節: §6.5 の場所の段落を「一つの場所には、それぞれの属性を一度だけ付けられる」と一文にまとめ、位置の誤った属性の数え方に一文。§4.5 に重なりの報告の形の文（R9）。
  - 今通るプログラムが変わるか: 誤りになる。`@fp(relaxed) @fp(relaxed) fn`、`@repr(c) @repr(c) struct`、一つの入力の `@param(…) @param(…)`（今は全て通る）。E0005 は構文の段なので、これらのファイルは `onsa fmt` も書き換えなくなる（終了コード 2）。
  - 実装の見当: `onsa_syntax` の `Parser::check_attrs`（`parser/items.rs`）か `attrs.rs` の `check` の呼び出し元で、一つの場所の属性の名前の集合を持つ。約 15〜25 行と note。
  - ぶつかる既存の事例: `tests/spec/fixes/e0004_doc_between_attributes.onsa` と `.fix1`（`@fp(relaxed)` の重ねに頼る。注記に「仕様が誤りにするならこの事例を変える」とある。`@export` と `@fp(relaxed)` の組（`pub fn`）に書き直す）、`tests/spec/fixes/e0020_block_comment_after_attribute.onsa` と `.fix1` の `between_two`（同じ書き直し）。`std/`・`examples/`・仕様の ```onsa に当たる形は無い。
