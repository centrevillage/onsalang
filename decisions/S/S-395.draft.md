# S-395 後の `let` を指す `^名前` の型をその位置でどう決めるか

- 決定済みで戻さないもの: 後の `let` の注釈が前方の参照に効くこと（W3-10/b の M1）、`^` を書ける位置（§11.2 の E0801）、見えている名前への `^` の E0020、候補の種類で決まる操作の E0413 など（§4.7、S-854・S-860）。
  下書きの全文（「仕組みの出所」「形の表」「新しい S の候補」）は `target/notes/166/g111/draft.md`、入力は同じ所の `probe/`、段 1 の票・伏せた版（親の直し `parent_edits.md`）・入力は `advisor/`、下書きと段 1 の報告は `onsa-gap-a1c71ded76168b5c9-001.md`・`-002.md`・`onsa-advisor-a3feadd0f744eff07-001.md`。
- 論点: §4.7 は型の頭の要る操作の対象がその時点で解決済みであることを求め（E0420）、§11.2 は後の `let` を `^名前` で読めるとし、§3.1 は `^y.l` を `y` のフィールドと読む。
  後の `let` に注釈が無いとき、`^名前` の型の頭を後の `let` の初期化式から決めるか、その位置で未解決として E0420 にするかが書かれていない。
  帰還の輪では、後の `let` が指す側の `let` を読むことが多く（`let b = Pr { l: a, r: x }`）、後の `let` を先に検査しても型が決まらない形がある。
- 今の実装: 形の表のとおり。注釈の無い後の `let` を指す `^名前` に型の頭の要る操作を当てると、`^` の位置に E0420「the type of this value must be known here; add an annotation (§4.7)」が出る。
  注釈を書く場所（後の `let`）は文面に無い。遅延を受けた名前を後の `let` の中で読む形（`b11`）は、その名前の位置に出る。
- 案:
  - (a) 今のまま: 注釈の無い後の `let` の束縛は、その文までは未解決で、型の頭の要る操作は E0420 である。§4.7 か §11.2 に一文を書く。E0420 の note で、注釈を書く後の `let`（自分自身の `let` を含む）の位置を示す。
  - (b) 初期化式の外の形で頭を先に決める: 注釈の無い `let` の初期化式の一番外の形が、型の頭を構文で決めるとき（struct リテラル、配列・タプルのリテラル、列挙子の構築、`as T`、返り値の型を宣言した項目の呼び出しとインスタンスの呼び出し）、その頭を本体の検査の前に当てる。
    要素の型（`[a, x]` の要素、総称の型引数）は後の文で決まる。他の形（演算、`if`、`match`、名前）は (a) と同じ。
  - (c) 操作を遅らせる: `^名前` を経て型の決まらない値に当てた型の頭の要る操作は、その場で誤りにせず、結果を新しい型変数にして、後の `let` を検査した後に解決する。本体の終わりに未解決なら、その操作の位置に E0420。
  - (d) 依存の順で検査する: `^` を経ない依存で輪にならないとき、後の `let` を先に検査する（指す側を読まない後の `let` だけが先になる）。
  - 書き手から見て: 帰還の値に struct を使う形（ステレオの帰還、`let s = Stereo { l: x + g * delay~(^s.r, N), r: … }`）は、(a) では `let s: Stereo = Stereo { … }` と注釈が要り、E0420 を見て一回直す。
    note が後の `let` を指せば、直す場所は一つに決まる（今の文面は指さないので、書き手が指す側の `let` に注釈を書いても直らない）。スカラの `let` に分けて書く形（`let l = …`、`let r = …`）は、どの案でも通る。
    (b) はこの形をそのまま通すが、演算の結果（`b06`・`b08b`）は E0420 のままで、通る形と通らない形の線が初期化式の外の形で引かれる。(c) は全て通し、(d) は帰還の輪の形（`b01` など、実際の帰還の多く）を通さない。
  - 修正候補: E0420 は今も候補を持たない。(a) で後の `let` に注釈を足す候補を作るには、その `let` の型が要り、検査を止めた後では分からない（初期化式が総称でない struct リテラルのときだけ `: Pr` が一つに決まる）。どの案も、候補を出さなければ当て続けて `no-candidate` で止まる。
  - 通るプログラム: (a) は変えない。(b)〜(d) は今の E0420 の形の一部を通す（緩める向きで、今通るプログラムは壊さない）。`std/` と検査の期待を持つ事例に当たる形は無い。
  - 規則と例外: (a) は規則を足さず、§4.7 の「その時点で」の当てはめを一文書く。
    (b) は §4.7 の「文の順に一方向」に、後の `let` の頭を先に当てる例外を足し、頭を決める初期化式の形を列挙する（形を足すたびに列挙が増える）。
    (c) は §4.7 の「その場で既知を要する」に、`^` を経た値だけ遅らせる例外を足し、誤りの位置と順（§18.1 の位置の順）が後の文の検査に依る。
    (d) は §4.7 の文の順に、依存の順の例外を足す。
  - 実装の量（型の段、`flow/check.rs::prescan_lets`。W7-14 の作業の範囲に入っていない）: (a) は E0420 の note に後の `let` の位置を足す約 +5〜10 行で、`SPEC-GAP(S-395)` を外す。
    (b) は初期化式の外の形から頭を作る関数（呼び出しは宣言の返り値、総称は頭だけ）と、それを `prescan_lets` で当てる約 +30〜50 行。
    (c) は遅らせた操作の表と、各 `let` の後と本体の終わりの解決、誤りの位置の並べ直しで約 +60〜100 行（見当）。メソッドの選択と `as` の判定を遅らせた後でも同じに行う必要がある。
    (d) は `let` の依存のグラフ（`^` を除く）と検査の順の並べ替えで約 +30〜50 行。クロックの推論（§11.3）は別の歩きなので触れない見込み（確かめていない）。
  - 後の作業への手当て: (a) は無い。(b) は、初期化式の形（第 2 期の構文、総称の flow）が増えるたびに頭の列挙を見直す。(c) は型の段の誤りの順の約束（R-329、§18.1）と、型を読む後の段（巻き上げ、降下）が遅らせた操作の結果を読む前に解決済みであることを保つ。
