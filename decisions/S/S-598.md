# S-598 `use` の二つの書き方（`use a.b` と `use a.{b}`）を揃えるか

- 空白: S-594 は、並びの無い経路の最後の要素と並びの要素を同じ束縛を作る取り込む名前として読み、二つの書き方（`use std.math` と `use std.{math}`、`use kp.inner.g` と `use kp.inner.{g}`）を今のまま残した（fmt は書き手の形を残す）。
  仕様の例は両方を使う（`use std.audio.wav`、§11.6 の `use dsp.synth.{voice}`）。揃えるか、揃えるならどちらの向きか（fmt の正規化か、片方を誤りにするか）が書かれていない。fmt で揃える向きは後でも壊れないが、片方を誤りにする向きは通っていたプログラムを壊す（第 39 組の助言の段 2）。
- 決定: 決定（2026-10-25、利用者が ID を挙げて了承。66 回目、第 58 組）: (b1)。`onsa fmt` は、素の名前が一つだけの並び（`use a.{b}`）を並び無しの形（`use a.b`）に書き換える。並びの中にコメントがあれば書き換えない（`spec/tools.md` §3.4 の括弧と同じ）。二つ以上の名前の並びと、並び無しの経路はそのまま残す。
  判定（合否と診断のコード）と修正候補は変わらない。`spec/tools.md` §3.3 の構造を変える書き換えの一覧に一行を足し、`onsa diff --ast` と fmt の確かめの正規化（§3.5）も同じ書き換えで揃える。§15.1 の「fmt は書き手の形を残す」の一句を改める。
  仕様の例（項目の `use std.math.{sqrt}` など約 15 か所、§11.6 の `use dsp.synth.{voice}`）、std の 2 行、テストのファイルを正規形に直す。第 2 期の別名（`{b as c}`）と `{self}` は、素の名前一つだけの並びでないので書き換えの範囲の外。実装は W5-11。
- 経緯: 55 回目（2026-10-23）、第 39 組（S-594）の新しい S の候補を、利用者の回答（後の段）で登録した。関係: S-594。
  66 回目（2026-10-25）、第 58 組の下書き（onsa-gap）と独立のレビュー（onsa-advisor の二段）。下書きは (a)（両方を残す）、助言は (b1)（§0.5.1 の無害な余分は fmt が揃える原則、§3.3 の書き換えは全て除去の向き）で割れ、利用者が (b1) を選んだ。
