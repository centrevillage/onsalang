# S-341 パターンの範囲の端に書ける形

- 空白: パターンの範囲の端に、定数の名前（`1..<LIMIT`、`-LIMIT..<LIMIT`、`I32.MIN..<0`）や式（`1..<n + 1`）を書いた形。§7 は「端の型は問わない（ガードの比較を型の段で検査する）」とするが、端の形（リテラルだけか、定数の名前も式も書けるか）を書かない。
  ガードの候補（`k if 1 <= k && k < LIMIT`）は、端を写すだけでは作れない形がある（`as` の端は E0011、比較とビットの群の端は E0010 が残る。括弧で囲めば作れる。第 13 組の下書きで確かめた）。W3-21/t で見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 13 組）: 端は見出しの範囲の端と同じ式で読み、式として読める全ての端でガードの候補を作る。パターンの中では括弧の外の `|`・`if`・`=>`・`,`・閉じ括弧の前で終わる（`1..<m + 1 | 5` は範囲と `5` の選択で、S-317 で E0002）。
  struct リテラルとブロック式の端は見出しと同じ文法で S-338 も当てる（`1..<{ n } =>` は E0002）。候補は端を写し、比較の被演算子に置けない端（`as` / `at`、比較・論理・ビットの群の式）を括弧で囲む。
  判定は W3-07 の群の表（`OpGroup::stronger`）を読む一つの関数で、W3-12 の fmt（S-339）と共有する（今の複合代入の `needs_parens` は粗く使えない）。端の裸の `as` / `at` は範囲のパターンの一つの誤りに入れる。読めない端と端の中のコメントは E0002。
  新しい束縛の名前は端の式の中の名前も避ける（S-253、S-319）。`(m, 0..<m)` の端の `m` がパターンの束縛を指すことは条件を足さない。仕様 §7。実装は W3-21
