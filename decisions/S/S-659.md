# S-659 第 1 期の std が宣言する標準の効果と、prelude の名前の定義元のモジュール

- 空白: §8.2 は「`Alloc` … std で操作の無い効果（`pub effect Alloc {}`）として宣言され、prelude にある」、§8.1 は「標準の効果（`Fs` `Stdout` `Stdin` `Clock` `Random` `Log`）は std の `effect` 宣言で、`use` で取り込む」、§15.1 は「prelude の名前を定義元から取り込み直す `use std.<モジュール>.{Option}` も同じ（E0304）」とし、D-08 の追記は「`Random` も std に宣言し（モジュールの名前は仮）」とする。
  第 1 期の std が、`Alloc` と `Random` だけを宣言するか（他の標準の効果の `use std.fs.{Fs}` と効果行の `Fs` は名前の見つからない E0302）、六つの標準の効果を全て宣言して効果行に書けば名前を解決した上で E0200 にするか（D-08 の「名前が解決できた上で E0200」と閉世界の E0200）を書いていない。
  あわせて、`Alloc`・`Random` と標準の効果を置くモジュールの名前（`std.fs` は §15.1 の例にある）と、`Option`・`Result` と prelude の trait を std に宣言するか（今はコンパイラの組込みで、`use std.<モジュール>.{Option}` は取り込む先が無く E0302 になり、§15.1 の E0304 の形が書けない）も書いていない。
  今の std に効果の宣言は無く（`git grep -n effect std/` が 0 件）、`uses {Random}` は `std/test.onsa` だけで、名前の比較で通っている。
- 決定: 決定（2026-10-26、利用者。71 回目、第 63 組。(B) のモジュールの名前は案の比べを示して、他は ID を挙げて確認だけで了承）:
  (A) は (a2)。第 1 期の std は六つの標準の効果を全て、操作の無い形で宣言する（`pub blocking effect Fs {}`、`pub effect Random {}`。`blocking` は §8.2 の表どおり `Fs`・`Stdout`・`Stdin`）。操作は第 2 期に同じ宣言へ足し、名前は変えない。std の doc コメントに「操作は第 2 期」と書く。
  効果の宣言は std の中でだけ受け付ける（利用者の `effect` の宣言は E0200 のまま）。
  (B) は、prelude にある std の名前（`Alloc`、`Block`（S-702）と、後に `Option`・`Result`・trait）を一つのモジュール `std.core` に置く（(b1)）。助言の `std.prelude` は採らない。中身は prelude の全てではなく一部の定義元で、名前を分けると診断の文と仕様の語がぶつからない。
  効果のモジュールは分野ごと（(e1)）: `std.fs`（`Fs`）、`std.io`（`Stdout`・`Stdin`）、`std.time`（`Clock`）、`std.random`（`Random`）、`std.log`（`Log`）。
  D-08 のとおり名前は仮で、第 2 期の std の設計で確定する。`std.fs` は効果のほかに、ファイルの分野の項目（`Path`・`IoError` と関数、第 2 期）も置くモジュールである（利用者が確かめた）。
  (C) は (c2)。U5 では `Option`・`Result`・trait をコンパイラの組込みのまま置き、名前の段は、`std.core` の項目に無いそれらの名前を `std.core` が宣言する名前として prelude の表から引く（`names/lookup.rs` の `Modules::member` の `Entity::Module` の枝の一か所）。
  W5-03 が `Option`・`Result` を、第 2 期の標準 trait を std の宣言にする作業が trait を、本当の項目に置き換える。置き換えても、診断のコードと通るプログラムは変わらない。
  細部: (1) 仮に引く名前は `Option`・`Result` と §6.3 の演算子 trait・標準 trait（数の trait、`Ordinal`）だけで、列挙子は §15.1 のとおり E0302、`panic`・`Copy`・`Dup`・組込み型は定義元が無いので E0302。(2) E0200 の位置は効果行の名前で、`use std.fs.{Fs}` だけのモジュールは通る。
  (3) `use` の無い標準の効果の候補 `use std.….{X}` は、std の `pub` の `effect` 宣言を名前の完全一致で探し、一つ見つかったときだけ出す。(4) 効果行の名前は、経路も含めて他の名前と同じく引く（`uses {fs.Fs}`）。
  (5) 第 1 期は、効果が rt 効果かを操作の集合から計算しない（E0904・E0905 は第 2 期）。`blocking` は宣言の情報として記録する。(6) `std/test.onsa` は `use random.{Random}` で取り込む（S-37）。(7) §17 の `Path`・`IoError`・`std.text` は、第 1 期は E0302 のまま。
  (8) 仕様は §8.2 の表にモジュールの欄、§15.1 の prelude の段落に `Block` と `std.core`。`tasks/phase2.md` と W5-03 に仮の引きを消す行。
  S-703 は別の S のまま急がない。実装は W4-03 の U5（`crates/onsa_cli/tests/package_model.rs` の `PRELUDE` に `Block` を足す）。
- 経緯: 64 回目（2026-10-24）、W4-03 U1 の設計メモ（onsa-impl）が見つけた。待つのは W4-03 の U5（prelude と効果）のテストの票の効果と prelude の取り込み直しの事例と、U3a の prelude の E0304 の `use` の事例のうち std の定義元のもの。U2a〜U4 は進められる。関係: S-74、R-129、D-08、S-611。
