# S-806 呼び出しの引数でない所の評価の中の変更と E0702（呼び先の式 `(if nx(inout k) > 0 { f } else { g })(k)`、構築子・リテラル・演算子の兄弟の要素 `Some((x, nx(inout x)))`・`x + nx(inout x)`）

- 空白: §3.5 の 160〜161 行と S-799 は、呼び出しの引数（レシーバを含む）の評価の間の変更が他の引数と重なると E0702 とする。次の二つの所の変更は書いていない。
  (a) 呼び先の式: `(if nx(inout k) > 0 { f } else { g })(k)`。§3.5 の 155 行は「呼び出しはレシーバ、引数の順に」とし、呼び先の式の順を書かない（冒頭は「Rust と同じ」）。
  (b) 呼び出しでない兄弟の要素: 構築子 `Pr.Two(x, nx(inout x))`・`Some((x, nx(inout x)))`、struct・配列・タプルのリテラル `W { a: x, b: nx(inout x) }`・`[x, nx(inout x)]`、二項演算子 `x + nx(inout x)`（`x` は Copy の `var`）。
  §3.5 は「書いた順に評価する」とする。同じ形の呼び出し `h2(x, nx(inout x))` は E0702（S-799 は Copy の `var` も数える）。
  W4-08 U1 の実装（未コミット）とその前の dev（`d73e460c`）は、(a) と (b) をどちらも通す。受け手の式の中の変更（`nxw(inout w).get(w.a)`）は窓の中で E0702。再現は `target/notes/90/w408/u1/b/in/fp1.onsa` の `fp11_callee_change`、`lit1.onsa` の `lt05`・`lt06`、`en1.onsa` の `en01_ctor_two`。
  読み: (1) どちらも窓の外。呼び先の式は引数の前に評価し、兄弟の要素は値として書いた順に評価して取る（借用の引数の「呼び出し中は変更されない」約束が無い）。(2) §3.5 の理由（評価順を知らないと読めない）が当たるので、どちらも E0702 にする。
  急ぎ: W4-08 を閉じる前（(2) なら W4-08 の比べを広げる）。
- 決定: 決定（2026-10-31、利用者。90 回目。確認だけ。親の読み）: (1)。呼び先の式は引数の前に評価し終わるので、その中の変更は E0702 の窓（引数の評価の始まりから呼び出しの終わりまで）の外である。
  構築子、struct・配列・タプルのリテラル、二項演算子の要素は値として書いた順に評価して取り、借用の引数の「呼び出し中は変更されない」約束が無いので、兄弟の要素の中の変更は重なりに数えない（`x` が Copy の `var` なら `Some((x, nx(inout x)))`、`x + nx(inout x)` は通る。Affine の値は要素で移り、後の要素の変更は §5.2 の E0704）。
  ただし、平面の引数に置いた配列リテラル（§5.3）の要素は引数の場所なので、他の要素の中の変更と重なれば S-799 の E0702（W4-08 U2）。受け手は引数で、窓の中（`nxw(inout w).get(w.a)` は E0702）。
  実装は今のまま（W4-08 U1 `58c6dd5e` が呼び先の式を窓の前に歩く）。仕様 §3.5 の 155 行に呼び先の式の順を足し、161 行の後に二行を足した。
- 経緯: 90 回目（2026-10-31）、W4-08 U1 の壊す側（onsa-break）が空白の候補として二つ挙げた。親が一つの S にまとめて登録した。前からある。
