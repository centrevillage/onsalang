# S-288 有効だが縮退したソースと、警告なしの約束

- 空白: 有効だが縮退したソース（整数の `x == x` の自己比較など）から生成した C にも、§13.4 の「警告を出さない」が及ぶか。今は gcc と clang が `-Wtautological-compare` を 18 件出す（`tests/spec/c_runtime/c_self_compare.onsa`）。W2-09/t で見つけた（2026-10-08）
- 提案: (a) 約束は、検査を通った全てのソースから生成した C に及び、警告になる形を出さないのは生成の側の責任（§13.4 の文を改めた）。意味が型や被演算子の同一性で決まる比較（整数と `Bool` の自己比較、符号なしの `x >= 0` と `x >= T.MIN`）は Core で畳み（浮動小数の自己比較は畳まない）、自己代入は出さない。
  畳んで使われなくなる値と自己代入を消した `var` は、使わない引数と同じく `(void)x` を残す。条件: 対応の費用が高い形があれば、§13.4 に例外を付ける（(c) をその形に限って採る）かを利用者が個別に判断する。実装は無理に畳まず、形と費用の見積もりを報告し、それまでの事例は実装待ちの一覧に置く。
  言語の側で誤りにするかは S-293（利用者。第 7 組の下書き。仕様 §13.4。2026-10-08 決定。実装は W2-09）
