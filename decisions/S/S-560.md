# S-560 イベントのクロックの意味と、クロックの順序の一般の形

- 空白: §19.1（S-171）は、flow の入力にイベントのクロックの値を渡す方向（`notes: midi.Message at event`）、イベントはブロックの中の位置を持ちホストが位置を決めること、イベントのクロックがイベントごとに一回刻む（同じサンプルの中で複数回刻みうる）ことを決めた。決めること:
  1. イベントのクロックの定義（刻みの言葉で。第 33 組の `when` のクロック、S-558 の (4a) と同じ形にする）と、flow の本体の中でイベントのクロックの式が評価される段。
  2. クロックの順序の一般の形。今は `定数 < init < block < sample` の全順序で、式のクロックは最大値で決める（§11.3）。イベントのクロックと、後で入る導くクロック（`sample / 32`、§19.1 のマルチレート）を入れても成り立つ形（半順序と、式のクロックの決め方）。
  3. イベントのクロックの入力を宣言できる型（Copy の型、利用者の型を含む、§19.1）と、一つの flow が持てるイベントの入力の数。
- 決定: 決定（2026-10-21、利用者が ID を挙げて了承。47・50 回目）: イベントのクロックは入力ごとで、イベントごとにその位置で一回刻み、入力のイベントの刻みはその位置の `sample` の刻みより前に並ぶ。順序では全ての周期の刻みのクロックの下、パラメータの種類の上で、別の入力のイベントのクロックどうしは比べられない（最大が無ければ E0815）。
  型の制限は Copy だけ。`at event` は入出力の宣言にだけ書く。イベントの入力への引数はイベントの値で、`sample`・`sample / N` の入力へは最後の値で読み、`block`・`init`・`sample * N` の入力へは E0815。組込みの遅延はイベントの値も受ける（一つ前のイベント）。イベントの段の panic は poisoned にする。仕様 §19.1
- 経緯: X-7（W3 の終わり、2026-10-15、利用者）で、W4 の前に決めて第 1 期の範囲を W4〜W10 に割り当てることになった。第 34 組（イベントのクロック）の一つで、第 33 組（S-555〜S-559）の決定を前提にする。export の形・C の API・std の型・`onsa test` と `render` での与え方は第 35 組。
