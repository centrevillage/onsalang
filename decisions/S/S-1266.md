# S-1266 細部: panic で中断した呼び出しが書きかけた場所（export した関数の `inout` の引数、§12.7 で直接作る宛先）の値を約束するか（仮は約束しない。S-1264 の P3 の範囲内の道と、今の `w.big = mk(k)` の直接構築）

- 空白: §9.2 は、export した関数が panic すると呼び出しを中断して状態の値 1 を返し、結果の出力ポインタは書かないとする（§14.2）。flow の `process` は出力を 0 で埋めて poisoned にする（S-199）。panic の前に書いた `inout` の引数（`inout` のスカラ、`inout` の `Span`）と、§12.7 で直接作る宛先の値については、§9.2 は何も言わない。
  直接作る宛先は、呼び先が途中で panic すると書きかけになる（今の §12.7 の `w.big = mk(k)` で `mk` が途中で panic する形、S-1264 の P3 の範囲内の道の `ps[i] = mk(k)`）。§3.5 の順のとおりなら代入は起きず前の値のままなので、書きかけの値を約束しないと書くか、前の値を約束するかが割れる。見えるのは export した関数の `inout` の引数をホストが読むときと、プローブ・デバッガだけ。仮は約束しない（今の §12.7 の直接構築の実装と同じ）。

- 経緯: 191 回目（2026-11-27）、第 121 組（S-1264・S-1265）の推奨を伏せた独立のレビュー（onsa-advisor、段 1）が細部の候補として挙げた。S-1264 の決定で、利用者の「実行性能を落とさないよう注意して」を受けた P3（範囲内なら直接作る道）がこの扱いに頼るので、親が登録した。通るプログラムを変えないので細部として、W8 の段の区切りで確認する（`rules/leader.md` 5.11）。
