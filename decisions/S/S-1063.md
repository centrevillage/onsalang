# S-1063 細部: 型引数の中（完全に一致する比べ）で、片側が開いた行（S-691）の関数型のとき、どう比べるか

- 空白: §8.1 と S-1031 は、型引数の中の関数型（`Option[F]` と `Option[G]`）を `rt` と効果行を含めて完全に一致させる。§18.1 と S-691 の 152 回目の補いは、開いた行の関数型を期待する向きのある位置に、指しえた効果だけが足りない関数も置けるとする。型引数の中で片側が開いた行のときの比べを書かない。
  今（W6-03 U7a の後）: 指しえた効果で埋まる違いだけを黙り、確実に食い違うものは E0401（`Option[fn(U32) -> U32 uses {Gone}]`（`Gone` は失敗した名前）の値を `Option[fn(U32) -> U32 uses {Alloc}]` の位置に置くと E0401、`found` の表示に `uses {Gone}` は出ない。`Option[純粋]` の位置は黙る）。
  再現: `target/notes/152/w603/u67b/repro/open_row_type_arg.onsa`。
  読み: (1) 片側が開いた行なら、型引数の中の比べは黙る (2) 指しえた効果（経路の最後の名前と同じ名前の効果）で埋まる違いだけを黙る（今の実装。`Gone` は `Alloc` を指しえないので E0401 は本物）。
  仮の扱い: (2)（S-691 の 152 回目の補いの「指しえた効果」の読みから一つに決まる見込み。事例は確認の後に足す）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-15、利用者。152 回目、W6 の区切りの確認だけ。「上記はすべて OK」で了承）: (2)。型引数の中の等しさでも、指しえた効果で埋まる違いだけを比べない（`uses {Gone}` と `uses {Alloc}` の違いは E0401）。§18.1 に書いた。事例は W6-04 で足す。
- 経緯: 152 回目、2026-11-15、W6-03 U6a〜U7b のまとめた壊す側（onsa-break、報告 `target/notes/152/w603/u67b/`）が仕様の空白として挙げ、親が S-691 の補いの字に当てて登録した。
