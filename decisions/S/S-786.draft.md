# S-786 族: `Option`・`Result` の中身を取り出す被演算子のモード

- 決定済みで戻さないもの: S-784 の論点の「決定済み」の全て（S-605・R-198・S-609・S-41・R-117・S-85・S-192・S-175）と、`map_err` の `move self`（S-143）。`unwrap_or`・`is_some` などの今の実装の余分なメソッドは仕様に無く、W5-03 で消す（A-02）。
  第 75 組の下書きの「S-786 の仕組みの出所」と「S-786 の形の表」の節（族は「S-786 の族の形の表」。写しは `target/notes/86/g75/draft.md`）。
- 論点: §9.1 は `Option`・`Result` の中身を取り出す形として `?` と `unwrap` を挙げるが、どちらにも被演算子（受け手）のモードを書かない。同じ節の `map_err` だけが `move self` である。
  中身が Affine のとき、所有の場所から取り出すと場所を移すか、借用・`inout` の場所から取り出せるかが、二つの形で別々に決まりうる。族の規則として、取り出す形のモードを一つの規則で決めるか、形ごとに決めるかを決める。
- 今の実装: 族の形の表のとおり。`?` は被演算子を読む位置で、`unwrap` は借用の受け手として歩くので、どちらもどの場所も消費せず、何も出さない。
- 案: どの案も、場所でない値は一時の値を消費し、Dup の場所（Copy・Shared）は複製する。`map_err` の `move self` は変えない。
  - (A) 取り出す形は消費する: `?` の被演算子と `unwrap` の受け手は、`map_err` と同じく `move self` の受け手の位置で、印を書かない。S-784 は (a)、S-785 は (1)。
  - (B) 取り出す形は借用して写す: `?` の被演算子と `unwrap` の受け手は借用で、写す値（`unwrap` の中身、`?` の中身と脱出で返すエラー）が Dup でない場所は候補なしの E0711。S-784 は (c)、S-785 は (2)。
    `map_err` だけが消費する形になる。
  - (C) 取り出す形は `match` と同じに読む: `r?` と `r.unwrap()` を `match r { Some(v) => v, None => … }`（`unwrap` の `None`・`Err` の腕は panic）と同じ規則で検査し、場所の被演算子からの `let b = …` は借用束縛になる。S-784 は (d)、S-785 は (4)。
  - (D) 族の規則を置かず、形ごとに決める: S-784 は (a)〜(d)、S-785 は (1)〜(4) のどれでもよい。例えば `?` は (b) の印を書く形、`unwrap` は `move self` の印なし（受け手の規則）という組み合わせも取れる。
    (b) は `move` の印を書く形なので、印を書かない `move self` の受け手（`unwrap`）とは一つの規則にならず、(D) の下でだけ取れる。
  - 形ごとの出力は、S-784 の項目の「形ごとの出力」の表（`?`）と、S-785 の項目の同じ表（`unwrap`）にある。(A)〜(C) では、同じ行の答えが `?` と `unwrap` で同じになる（`unwrap` には `Err` の道で返す値が無いので、(B) の `Result[U32, Buf[F32]]` の借用だけが違う。S-785 の表）。
  - 書き手から見て: (A)〜(C) は、`?` で直し方を覚えた書き手が `unwrap` でも同じ直し方をする。(D) は二つの形で答えが違いうる（`r?` は通り `r.unwrap()` は E0711、など）。
  - 規則と例外: (A) は、印を書かない消費の位置（`move self` の受け手）に `?` の被演算子を一つ足し、`unwrap` は `move self` と宣言するだけで、規則は足さない。`map_err` と三つが同じ形になる。
    (B) は「写す値が Dup でない場所は E0711」の制限を二つの形に一つ足し、`map_err` との違いが残る。(C) は `match` への読み替えの文を一つと、§5.4 の表の行（`let y = x?`、`let y = x.unwrap()` など）を足す。`let y = f(...)` を所有とする 105 行の例外になる。
    (D) は形ごとに一つずつ規則を書く。
  - 実装と後の作業: (A) は、W4-07 の U2 で `?` の位置を `move self` の受け手と同じにし（約 +3〜8 行）、組込みのメソッドの表に受け手のモードを一つ持たせる（約 +5〜10 行、S-785）。W5-02・W5-03 は `unwrap` を `pub fn unwrap(move self) -> T` と普通の宣言で書ける。
    (B) は U2 に E0711 の判定を二か所（約 +15〜25 行）で、`unwrap` の宣言は `self` の借用で Affine の中身を返す形になり、普通の宣言の規則では書けない（W5-03 の後も特別扱いが残る）。
    (C) は W4-16 の束縛の状態と §7 の派生元に `?` と `unwrap` の見出しを足し（約 +60〜120 行、確かめていない）、`unwrap` は呼び出しの結果なのに借用になるので、これも宣言では書けない。
    降下と後端は、どの案も変えない（場所の中身を読む今の形が、消費でも借用でも同じ Core になる）。
    (D) の実装と後の作業は、選ぶ組み合わせの S-784 と S-785 の各論の費用の和になる（親が足した行）。S-784 の (b) を含む組み合わせでは、S-784 の「後の作業への手当て」の行のとおり、`move` を書ける位置を足すたびに `p?` の形を考える手当てが続く。
- 他言語: S-784 と S-785 の項目にある。rustc 1.94.1 では `?`（`Try::branch`）と `Option::unwrap` がどちらも受け手 `self` を移す（`other/r1.rs`・`r5.rs` の note）。
  swiftc 6.3.1 では `guard let` と `r!` がどちらも `borrowing` の値を消費できないと言う（`s1`・`s3`）。C++（Apple clang 21）の `std::optional::value()` は参照を返し、`auto b = o.value()` は写すので、移動だけの型では誤りになる（`other/c1.cpp`）。
- 推奨と理由: (A)。確度: 中。
  - 取り出す形は中身を所有して外へ出すので、`map_err` が既に `move self` で書かれている。`?` と `unwrap` も同じ位置とすれば、`Option`・`Result` の中身に触る全ての形が一つの規則（`move self` の受け手、印を書かない）で決まり、規則は `?` の一句だけ増える。
  - `unwrap` を `move self` と宣言すると、W5-02・W5-03 で std の普通の `impl` に書け、特別扱いが残らない。(B) と (C) の `unwrap` は、言語の宣言の規則では書けない形になる。
  - 二つの形で答えが同じなので、書き手は `?` で覚えた直し方を `unwrap` にも当てられる。(D) で答えを分けると、どちらかの形に、他の形に無い規則が一つ要る。
  - 族の規則から決まる S（族の形の表の行を指す）:
    - S-784: (a)。表の「借用の引数」「`inout` の引数」は候補なしの E0711、「同じ場所から二度」「ループの中」「取り出した後に場所を使う」は E0704、「所有のフィールドの経路」は S-85 のとおり根の全体を消費、「添字の経路」は E0711、「`let` の `move`」は S-605 の E0711 のまま。
    - S-785: (1)。表の同じ行が `unwrap` でも同じ答えになる。`u21` の Copy は複製、`u22` は今と同じ E0901（取り出した `Buf` の一時の値を破棄する）。
  - 例外は無い。S-784 の (b)（`move r?` の印）は (A) の下では取らない。
  - あわせて決めること: 族の名前の範囲は、`Option`・`Result` の中身を取り出す組込みの形（今は `?` と `unwrap`）とする。第 2 期に取り出す形（他のメソッド、利用者の型への `?`）を足すときも、この規則に従う。
