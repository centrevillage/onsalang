# S-649 型パラメータの名前の重なり（同じ並びの `fn f[Item, Item]`、型と同じ名前の `struct Item` と `fn f[Item]`、組込みの型の `fn f[I32]`）

- 決定済みで戻さないもの: 第 64 組の下書きの「決定済みで戻さないもの」と「形の表」の S-649 の表（写しは `target/notes/74/g64/draft.md`。表の行の番号はその表のもの）。
- 論点:
  - 出所と目的: §5.1 は「シャドーイングは無い。ある名前の束縛が見えている間は、同じ名前を束縛できない（E0304）」とし、見えている束縛にモジュールの項目、`use` で取り込んだ名前、prelude、組込み型を含める。
    目的は「一つの名前は、見える範囲で常に一つのものを指す」ことと、flow の自己参照との衝突を避けることである。
    §6.2 の E0307（`impl[T] Pair2[T, T]`）は別の理由で、一つの `impl` が型の全ての具体化を覆い、実装が重ならない（特殊化が無い）ためである。
  - §4.5 と §6.2 は、宣言の並びの名前（型パラメータ、const パラメータ、効果行変数）が §5.1 の束縛に入るかを書かない。読みは「並びの名前も束縛で E0304」と「別の範囲で、外の名前を隠す」に割れる。
    §2.3 の S-652 は「同じ並びの型パラメータ」を候補の重なりに数えるが、重なりを誤りにするかは書かない。当たる形は表の 1〜13 行。
- 今の実装: 構文の段で止まる形（12 行）と E0200 の宣言（7 行）を除き、全て通る（終了コード 0）。
  外の名前と重なると、型の位置では型パラメータが外の名前を隠し、本体の struct リテラル・列挙子・prelude の値は外のものを指す（g1・g6・g7）。外の `impl` と重なると、メソッドの型パラメータは使われず呼ぶ側に E0406 が出る（t3）。
- 案:
  - (a) 全て E0304。並びの名前を、その項目の中（`impl` ならメンバも）で見える束縛とし、§5.1 をそのまま当てる。相手は同じ並び、外の `impl` の並び、モジュールの本体の空間（項目、`use` の束縛、prelude、組込み型。S-611 の空間）の名前。
    失敗した `use` の名前は相手にしない（S-462）。位置は内側（後）の宣言で、もう一方を note で示す。
  - (b) 項目の中の宣言どうし（同じ並び、外の `impl` の並び）だけ E0304。外の名前は、項目の中で並びの名前が隠す（今の挙動）。
  - (c) (b) に加え、組込み型と prelude の名前だけ E0304。同じモジュールの項目と `use` の名前は隠してよい。
  - (d) 同じ並びの重複だけ E0304。
  - 一回の検査で出る誤り: (a) は 1〜6・8・10・11・13 行がそれぞれ一つの E0304（単位ごとに一つ）。13 行の効果行変数とローカルの束縛・引数の重なり（`[e]` と `Err(e) =>`）も E0304 で、よく書く形の名前を書き手が変えることになる。(b) は 1〜3 行だけで、10 行の `f[I32]` は `F32` を通す。(c) は 4〜6・8・13 行を通す。(d) は 3 行も通り、E0406 が呼ぶ側に出る。
    どの案も候補は無く（名前を選ぶのは書き手、S-652）、偽の連鎖は無い（E0304 の単位は本体を型検査しない）。
  - 通るプログラム: どの案も今は通る形を止める向きで、(a) が最も多く止める。止めた形は後で緩めても壊れない。(b)〜(d) で通した形を後で止めると壊れる。
  - 実装（並びを降ろす `sig.rs` の `lower_generics`）: (d) は並びの中の重複（約 +8 行）。(b) は加えて外の並び（`cx.generics`）との重なり（約 +5）。
    (a)・(c) は加えて `Modules::lookup` で本体の空間を引き、相手の位置を note に付ける（約 +15〜20）。(a) の効果行変数とローカルの重なりは、W4-04 の U5（ローカルの E0304）が見える束縛に項目の並びを足す（約 +5）。
    trait と effect の並びは、第 2 期の宣言の作業が同じ関数を通す。
- 他言語:
  - rustc 1.94.1: `fn f<T, T>` と `impl<T> P<T> { fn m<T> }` は E0403。`struct Item` と `fn f<Item>`、`fn f<Option>`、`fn f<i32>`、`impl<f32> P<f32>`、`const N` と `fn f<const N: usize>` は通る（小文字は命名の警告だけ。`f([1.0, 2.0])` は 2）。
  - Swift 6.3.1: `func f<T, T>` は「invalid redeclaration of 'T'」。外の `T` を隠すメソッドの `func m<T>` は、既定の言語モードで警告、`-swift-version 6` で誤り。`func f<Item>`・`func g<Int>`・`func h<Optional>` は通る。
  - Python 3.14.5: `def f[T, T]` は SyntaxError「duplicate type parameter 'T'」。`def g[int](a: int)` とクラスの `T` を隠すメソッドの `[T]` は通る。
  - C++（g++ 15.2、Apple clang 21）: `template<class T, class T>` と、クラスの `T` を隠すメンバの `template<class T>` は誤り（「shadows template parameter」）。`struct Item` を隠す `template<class Item>` は通る。
  - Go 1.27.2（一覧の外、参考）: `func F[T any, T any]` は「T redeclared」。`func G[int any](a int)` は通る。TypeScript: 未確認（手元に tsc が無い）。
- 推奨と理由: (a)。確度: 高。
  - §5.1 の規則は既にあり、(a) は並びの名前をその束縛に入れるだけで、規則も例外も足さない。(b)〜(d) は「並びの名前は外の名前を隠せる」という §5.1 の例外を一つ足す。
  - 外の名前を隠す形は、通るのに読み手の読みと意味が違う。`fn f[I32](a: I32) -> I32` は `F32` の値を通し、具体的な型の `impl`（E0307）のつもりの `impl[F32] P[F32]` は総称の `impl` として通る。
    一つの項目の中で、`Item` が注釈では型パラメータ、struct リテラルでは struct を指す。この形は R-37 の入力 `tests/review-phase1/types/bounds.onsa` の 7 行にもあり、書き手が他言語の型の綴りを並びに書く誤りは現実にある。
  - 厳しい方で、後で緩めても通るプログラムは壊れない。(b) との差は約 +15〜20 行で、名前の段の E0304 の仕組み（相手の位置の note）をそのまま使い、後の段に手当ては続かない。
  - あわせて決めること: 効果行変数とローカルの束縛・引数（`[e]` と `Err(e) =>`、引数 `e`）も、(a) の同じ規則で E0304 になる。`Err(e)` はよく書く形なので書き手の手間は増えるが、名前を変えれば済み、例外を足さない（この点の確度は中）。
- 影響: 仕様 §5.1（見えている束縛に、項目の型パラメータ・const パラメータ・効果行変数を含める一文。(a)〜(c) は相手の範囲を書き分ける）、§4.5 か §6.2（外の `impl` の並びとの重なり）。
  §2.3 の S-652 の「同じ並びの型パラメータ」は、どの案でも E0304 の範囲に入るので、文を短くできる。診断 E0304。作業 W4-04（U5、隠蔽）。

  §18.1 の「E0304 になった名前はその空間ではどちらの宣言も引かず」は当てず、ローカルの E0304 と同じく、並びを持つ項目（メンバ、`impl` の見出しの並びなら `impl` 全体）の単位に出し、相手（項目・`use` の束縛・prelude・組込み型・外の `impl` の並び）は他の単位と他のモジュールからそのまま引ける。
  この一文が無いと、`fn f[Item]` 一つで `struct Item` がモジュール中で失敗した名前になる読みが残る。その関数を呼ぶ単位には偽の連鎖を出さない（§18.1 の読めなかった部分の扱い。署名の読み方は実装に任せる）。
