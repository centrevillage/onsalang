# S-874 Copy の引数の型で、モードだけが違う関数型（`fn(T)` と `fn(move T)`）を互いの位置で使えるか（Copy の要素の構築子の関数値を既定のモードの関数型の位置に置く形、§8.1 の規則 1）

- 空白: §4.1 は関数型の引数のモードを型の一部とし、§8.1 の関数型の互換の規則 1 は引数の型が等しいことを求める。Copy の値は、借用の引数にも `move` の引数にも複製して渡すので、呼ぶ側から見た意味は同じである（§5.2）。それでも `fn(T) -> R` と `fn(move T) -> R` は、互いの位置で E0401 になる。
  S-872 の決定で構築子の関数値の引数は `move` になる（`Circle` は `rt fn(move F32) -> Shape`）。そのため Copy の要素の構築子は、既定のモードの関数型の位置に置けない。
  当たる形: 利用者の高階関数 `fn build(make: fn(F32) -> Mode)` に `build(Mode.Gain)`、std の `array.from_fn(Some)`（`f: fn(U32) -> T`）、`let wrap: fn(U32) -> Option[U32] = Some`、§8.1 の将来の `map[T, U, e](xs: Array[T], f: fn(T) -> U uses {e})` に構築子を渡す形。
  書き手は宣言を `fn(move F32)` にするか、`fn(i) { Some(i) }` で包む（E0401 は修正候補を持たない）。
  構築子に限らない: `fn k(x: U32) -> W` を `fn(move U32) -> W` の位置（`map_err` の `f` を含む）に置く形も、`fn k(move x: U32) -> W` を `fn(U32) -> W` の位置に置く形も E0401 である。
  読み: (1) 今のまま（Copy の引数でもモードは型の一部）。(2) 引数の型が Copy のとき、`fn(T)` と `fn(move T)` を互いの位置で使える（両方の向き）。(3) (2) をスカラーの Copy に限る。
  Shared（`Str` など）は含めない見込みである。`move` は参照の数を移すので、互換の包みが破棄（`Alloc`）を要する。
  実装の事実（`127b4537`）: C の後端は、スカラーの Copy を借用でも `move` でも値渡しにする。集成体の Copy（struct・配列・タプル）は、借用なら `const T*`、`move` なら値渡しにする（`crates/onsa_backend_c/src/emit/fns.rs`）。集成体を含めると、関数値の型を変える包みが各後端（C、インタプリタ、JS、WASM）に要る。
  他言語: swiftc 6.3.1 は、Copyable の型で `borrowing`・`consuming`・無印の引数の関数型を互いに変換する（第 80 組の下書きの他言語の節、`target/notes/110/g80/`）。
  (2)・(3) は緩める向きなので、S-872 の決定を先に実装しても、後で足したときに通っていたプログラムは止まらない。
  急ぎ: W6-01 の前（関数型の互換を実装する作業）
- 決定: 決定（2026-11-13、利用者。145 回目、第 96 組。材料は `target/notes/144/g96/`）: (b)。Copy の引数でも、関数型の引数のモードは型の一部のままで、`fn(T)` と `fn(move T)` は互いの位置で E0401（読み (1)）。引数の違いが既定と `move` だけ（数・型・返り値・効果行・`rt`・`inout` は一致）の E0401 に、直し方の note を付ける。要素が Dup の構築子は無名関数で包む形（`fn(x) { Mode.Gain(x) }`）、引数の型が Copy の名前で定義した関数は宣言のモードを揃えるか包む形、候補の無い無名関数は引数のモードの書き方、それ以外（変数、関数型の引数など）は違う引数を名指すだけ（変数と関数型の引数を包むと捕捉になり、保存する位置で E0710）。候補は足さず、S-872 の候補の付く形には note を付けない（文面は約束でない、§18.1）。
  理由: 後で (c)〜(e) に緩めても通っていたプログラムは止まらない（逆は誤りにする）。(c) は `T: Copy` の型パラメータを関数型で具体化すると健全でなく、型パラメータを除く一句を含めて例外が約六つになり、全ての後端（W8-09、WASM、JS）に呼び方の約束が要る。(d) は境界が後端の都合（スカラー）で、第 1 期で主に当たる `map_err(conv)`（Copy の enum）を救わない。(e)（利用者の `auto` の案）は `map_err`（`E: ?Dup`）に書けず、A-16 の語を先取りする。第 1 期に std で関数値を受けるのは `array.from_fn`・`std.test.check`・`map_err` の三つで、モードの違いのために包んだ形は std・examples・§17 に無い。
  §4.1（Copy でもモードは型の一部、理由の一句）、§8.1 の規則 1（モードを明示）と note の一文、§5.2 の重なりの文（関数型としては別の型）に書いた。W6-01 で note を実装する（細部は W6-01 の持ち越し）。第 2 期の見直しの材料（(c) を Core で実現する形と (e) の `auto`）は A-16 の補い。
- 経緯: 110 回目（2026-11-04）、第 80 組の独立のレビューの段 1 が `decisions/A/` の候補として挙げた。S-872 の説明の後に利用者が、構築子の関数値の型が `map_err` の事情だけで決まっていないか、他の場面で不都合が出ないかを問い、親が W6-01 の前に決める S にすることを勧め、利用者が了承した。関係: S-872、S-190、S-609、R-26
- 補い（2026-11-04、親）: 利用者の案（110 回目、A-16 の `auto` と同じ形）: 関数型の引数のモードの位置に `auto` を書き（`fn build(make: fn(auto F32) -> Mode)`）、借用で受ける関数も `move` で受ける関数も置けるようにする。この S の案の一つとして、暗黙の互換（読み (2)・(3)）と比べる。
  親の見立て: Copy の引数では、意味は暗黙の互換と同じで、§8.1 の規則 1 に例外を作らない代わりに、高階関数を書く人が `auto` を書く。スカラーは後端の手当てが要らず、集成体の Copy は借用（`const T*`）と `move`（値渡し）で呼び方が違うので、包みか関数を二通りに作る手当てが要る。
  Affine の引数では、`f` が借用なら呼んだ側が値を持ち続けて破棄する（`Buf` は `Alloc` を要する）ので、本体の効果行と呼んだ後の使用が引数で変わり、後端の呼び方も二通りになる。Affine まで含む形は実例が出るまで足さない見込み（後で足しても `auto` の語の意味と矛盾しない）
