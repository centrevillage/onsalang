# S-874 Copy の引数の型で、モードだけが違う関数型（`fn(T)` と `fn(move T)`）を互いの位置で使えるか（Copy の要素の構築子の関数値を既定のモードの関数型の位置に置く形、§8.1 の規則 1）

- 空白: §4.1 の 26 行は関数型の引数のモードを型の一部とし、§8.1 の関数型の互換の規則 1 は引数の型が等しいことを求める。Copy の値は、借用の引数にも `move` の引数にも複製して渡すので、呼ぶ側から見た意味は同じである（§5.2）。それでも `fn(T) -> R` と `fn(move T) -> R` は、互いの位置で E0401 になる。
  S-872 の決定で構築子の関数値の引数は `move` になる（`Circle` は `rt fn(move F32) -> Shape`）。そのため Copy の要素の構築子は、既定のモードの関数型の位置に置けない。
  当たる形: 利用者の高階関数 `fn build(make: fn(F32) -> Mode)` に `build(Mode.Gain)`、std の `array.from_fn(Some)`（`f: fn(U32) -> T`）、`let wrap: fn(U32) -> Option[U32] = Some`、§8.1 の 39 行の将来の `map[T, U, e](xs: Array[T], f: fn(T) -> U uses {e})` に構築子を渡す形。
  書き手は宣言を `fn(move F32)` にするか、`fn(i) { Some(i) }` で包む（E0401 は修正候補を持たない）。
  構築子に限らない: `fn k(x: U32) -> W` を `fn(move U32) -> W` の位置（`map_err` の `f` を含む）に置く形も、`fn k(move x: U32) -> W` を `fn(U32) -> W` の位置に置く形も E0401 である。
  読み: (1) 今のまま（Copy の引数でもモードは型の一部）。(2) 引数の型が Copy のとき、`fn(T)` と `fn(move T)` を互いの位置で使える（両方の向き）。(3) (2) をスカラーの Copy に限る。
  Shared（`Str` など）は含めない見込みである。`move` は参照の数を移すので、互換の包みが破棄（`Alloc`）を要する。
  実装の事実（`127b4537`）: C の後端は、スカラーの Copy を借用でも `move` でも値渡しにする。集成体の Copy（struct・配列・タプル）は、借用なら `const T*`、`move` なら値渡しにする（`crates/onsa_backend_c/src/emit/fns.rs` の 79 行）。集成体を含めると、関数値の型を変える包みが各後端（C、インタプリタ、JS、WASM）に要る。
  他言語: swiftc 6.3.1 は、Copyable の型で `borrowing`・`consuming`・無印の引数の関数型を互いに変換する（第 80 組の下書きの他言語の節、`target/notes/110/g80/`）。
  (2)・(3) は緩める向きなので、S-872 の決定を先に実装しても、後で足したときに通っていたプログラムは止まらない。
  急ぎ: W6-01 の前（関数型の互換を実装する作業）
