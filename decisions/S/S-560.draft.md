# S-560 イベントのクロックの意味と、クロックの順序の一般の形

- 決定済みで戻さないもの: S-171（`at event` の入力、Copy の値、位置はホストが決める、同じ位置のイベントはイベントごとに一回刻んで順に処理し、`sample` の式からは全て処理した後の状態が見える）。
  S-558 の (4a)。S-172（イベントで動くインスタンスの `sample_rate()` は外と同じ）。§19.1 の「`block` と導くクロックには大小が無い」。
- 論点: 記号: E(e) は「イベントの入力 `e` のイベントの刻み」を指す説明の記号で、Onsa の構文ではない。入力の番号（p01 など）は、47 回目に dev `4aaa028` の release の `check` で試した入力（S-560 の「今の実装」の表）。
  §11.3「クロックは `定数 < init < block < sample` の順に並ぶ」「式のクロックはオペランドのクロックの最大値で、コンパイラが推論する」。§19.1「同じ位置のイベントはキューに溜め、イベントのクロックがイベントごとに一回刻んで順に処理する（同じサンプルの中で複数回刻みうる…）」。
  - (1) イベントのクロックは入力ごとか、flow に一つか。刻みの定義と、その式を評価する段。
  - (2) 順序の一般の形。イベントのクロックは一つの位置で複数回刻み、刻まない位置もあるので、`sample` より速いとも遅いとも言えない。比べられない組を含む式のクロックの決め方。後の導くクロック（`sample / 32`）とも合う形にする。
  - (3) 入力の型（Copy は決定済み）に足す制限と、一つの flow のイベントの入力の数。

- 案:
  - (1a) 入力ごとのクロック。`e: T at event` は自分のクロック E(e) を持ち、E(e) は `e` のイベントごとにその位置で一回刻む。同じ位置の刻みは、その位置の `sample` の刻みより前に並ぶ。
    オペランドに `e` の値を含む式は E(e) の式で、E(e) の刻みごとに評価する（イベントの段。サンプルのループの中の、その位置の `sample` の段の前）。
    実装: クロックの値に入力の番号を持つ種類を足す（W7-02）。計画の表にイベントの段（W7-03）。Core と C で入力ごとの列を位置で混ぜて回すループ（W8、W10）。費用の要因: クロックの集合が固定でなくなる（導くクロックでも要る）。
  - (1b) flow に一つの `event` のクロックで、全てのイベントの入力の和で刻む。各刻みで値があるのは一つの入力だけなので、他の入力の値をどう読むか（`Option` にするなど）の規則が要る。費用の要因: 宣言の型と本体で読む型が違う（型に現れない約束）。
  - (1c) イベントの入力は flow に一つまで（二つ目は誤り）。意味は (1a) の一つの場合と同じ。MIDI とトランスポートを一緒に受けるには、和の型（enum）を作る。後で (1a) に緩めても壊さない。実装は (1a) より、列を混ぜるループの分だけ少ない。
  - (2a) 半順序と最小上界。`定数 < init < block < sample` と、各 E(e) について `block < E(e)`。`sample` と E(e)、二つの E(e) は比べられない。式のクロックはオペランドのクロックの最小上界（全順序なら最大値と同じ）で、無ければ誤り。
    導くクロックが入ると、`block` と制御の `sample / 32` の最小上界は `sample` になり、`p * lfo`（`p` が `block`、`lfo` が `sample / 32`）は黙って `sample` で評価される。
  - (2b) 半順序で、オペランドのクロックに最大のものがあればそれ、無ければ誤り。イベントだけなら (2a) と同じ結果になる。違いは導くクロックで、上の `p * lfo` は誤りになり、片方に `at sample` を書く。(2b) から (2a) へは後で緩められる。
  - (2c) 全順序を保ち、`block < event < sample` と差し込む。`sample` の式でイベントの値を保持して読める（S-563 の (1a)）。二つのイベントの入力の間は比べられないまま残る。
  - (3a) 型に足す制限は無い（Copy だけ。合図だけの `()`、enum、`Option` を含む）。境界に出せる型は第 35 組。(3b) `sample` の境界と同じく、スカラ・`[スカラ; N]`・struct に限る。
- 他言語:
  - Lustre V6（参照の手引き v6.112.1 §1.2.4）: 全てのクロックは基のクロックの部分で、一つの刻みに二度刻まない。部分のクロックの値を使うには `current` で呼び出し側のクロックへ戻し、例 12 の後に「calling current on a stream that is already on the base clock is an error」。
  - Esterel v5（Berry の primer v5_91 §4.4）: 信号は瞬間ごとに有無と値を持ち、「The broadcast value of a valued signal … is unique in each instant」。同じ瞬間の複数回の送出は、結合の関数で一つにまとめる（下の S-561）。一つの瞬間に複数回刻むクロックは無い。
  - Pure Data（手引き `doc/1.manual/2.theory.of.operation.htm` §2.6.1）: 「Messages are never passed to objects during a DSP tick; the ticks are atomic」。
    メッセージは論理時刻を持つが、DSP の刻み（既定は 64 サンプルのブロック）の間に処理する。
  - Cmajor（Language Reference の Event Endpoints）: 入力のイベントの端子ごとに、型ごとの処理の関数を書く。`void` のイベントがある。`advance()` は `main()` からだけ呼べる。
  - CLAP（`include/clap/events.h`）: `time` は「sample offset within the buffer for this event」。
    入力の列は「The host will deliver these sorted in sample order」。VST3 の `Event.sampleOffset` も同じ（`Steinberg::Vst::Event` の文書）。
  - Faust（manual の MIDI）: イベントの型は無く、MIDI は `[midi:…]` の付いた UI の値を更新する。
- 推奨と理由: (1a)、(2b)、(3a)。確度: (1) 中、(2) 中、(3) 高。
  - (1a): MIDI とトランスポートのように由来の違うイベントを、別の入力で受けられる。入力ごとにクロックを分けると、入力の間の順を意味から外せる（S-561 の (2c)）。(1b) は型に現れない約束が増える。
    (1c) は実装が最も少ないが、和の型を利用者か std に作らせる。(1a) との差は、クロックの値に入力の番号を持つことと、列を位置で混ぜるループで、どちらも小さい。
  - (2b): イベントだけでは (2a) と結果が同じで、違いは後の導くクロックにだけ出る。厳しい方で始め、導くクロックを入れるときに (2a) へ緩めるかを決められる。§11.3 の「最大値」の語はそのまま使え、「最大が無ければ誤り」を足すだけである。
    (2c) は S-563 の (1a) を選んだときの形で、そのときは (2) も (2c) に読み替える。
  - (3a): 値は Copy で足り、境界の形は型ごとに第 35 組で決める（S-171）。
  - 定義の文の候補: 「イベントの入力 `e` のクロックは、`e` のイベントごとに、その位置で一回刻む。同じ位置の刻みは `e` の列の順で（S-561）、その位置の `sample` の刻みより前にある。`e` を含む式は、その刻みごとに評価する」。インスタンスの単位では、その位置のイベントの刻みを、そのインスタンスの `sample` の一歩の前に処理する。
  - あわせて決めること（式の `at event`）: 式に書く `e at event` は、どの入力のクロックかが決まらないので誤りにし、`at event` は入出力の宣言にだけ書く（コードは親が決める。候補は E0815 の範囲）。
  - あわせて決めること（呼び出し）: 呼び先のイベントの入力には、呼び出し側のイベントのクロックの値を渡す（`block` 以下の値と `sample` の値は誤り）。呼び先の二つの入力に、呼び出し側の同じクロックを渡してよい。
  - あわせて決めること（誤りのコード）: 最大のクロックが無い式は、E0815 の範囲を広げる（候補。「クロックが合わない」として一つにまとめる）。
