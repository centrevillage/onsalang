# S-774 derive の一覧に見つからない名前や derive できない名前（`struct S: Gone`、`: Clone`）を書いた型を、境界の型引数と呼び出しに使う側（`W[S]` の `W[T: Eq]`、`need(x)`）: 一覧の全ての trait を未知とするか、誤りの要素だけを除いて書いた trait で判定するか

- 空白: §18.1 は誤りのある宣言の読めなかった部分を使う側に診断を出さないとし、S-768 は境界の並びに見つからない名前のある型パラメータを使う側で未知の境界とする。§6.4 は derive の一覧に誤りのある型を使う側の trait を決めていない。R-328（W4-05 U4b）は、この版で derive できない E0200 の trait（`: Show`）を書いたものとして満たすようにした。
  derive の一覧に見つからない名前（`pub struct S: Gone { v: U32 }`、E0302）や、一覧に無い名前（`: Clone`、E0416）を書いた型を、`W[S]`（`W[T: Eq]`）と `need(x)` に使うと、使う側に E0416 が出る（U4b の前も後も同じ。入力は `target/notes/82/s774/c15.txt` の `derive_cascade`）。
  読み: (1) 誤りの要素を除いた一覧で判定する（今の実装）。(2) 一覧に誤りの要素があれば、その型の trait を全て未知とする。(2') 見つからない名前（意図が読めない）があるときだけ全て未知とし、名前の分かる誤り（E0200、E0416）は書いたとおりに判定する（S-768 と同じ見方）。
- 決定: 決定（2026-11-06、利用者。117 回目、確認だけ）: (b) と (9a)。一覧の外の名前（§6.4 の E0416）が一つでもあれば、その型の一覧を未知にする（S-460 と同じ道）。一覧の 8 つの trait の判定、derive が作るメンバ、手書きの `impl` の重なりに診断を出さない。他の trait と種の制約は判定し、`struct G[T]: Gone` の `T` の暗黙の `Dup` も判定する。`x.nope()` は E0413 のままである。
  一覧の名前を型が満たさない E0416（`enum E: Default`、フィールドの型が満たさない形）と、この版の E0200 の trait は、書いた trait として満たす（S-900 の展開の後も同じ）。
- 経緯: 82 回目（2026-10-29）、W4-05 U4b の壊す側（onsa-break）が仕様の空白の候補として挙げた（急ぎは後の段）。期限は derive を扱う W5-06。関係: R-328、S-768、S-711。
- 補い（2026-11-06、親）: 第 88 組で決めた。下書き `decisions/S/S-774.draft.md`。本文の `pub struct S: Gone` の E0302 は誤りで、今の実装は §6.4 のとおり E0416 である。E0302 は失敗した `use` の名前だけである。`Clone` も実装の上では `Gone` と同じ道である。
