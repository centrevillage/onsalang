# S-989 定数式の中の型の場所（無名関数の引数の型、ブロックの `let` の型）にある名前の誤りが、署名の位置では E0417、本体の位置では E0302 になる

- 空白: §4.5 は、定数式に書けない形（ブロック・`if`・`match`・無名関数・`unsafe`）を「中の型によらず E0417」とし、「中の名前は普通の式と同じく名前の段が先に読む」とする。その形の中の**型の場所**（無名関数の引数の型、ブロックの `let` の型注釈）にある名前の誤りを、どちらの文で読むかを書かない。
  今の実装は位置で割れる（dev `97ac83af` でも同じ。W5-10 U1b で型引数の並びの形にも同じ差が出る）: 署名の位置の `pub fn f(a: [F32; (fn(a: Nope) { 1 })]) -> U32` は E0417、本体の位置の `let a: [F32; 2] = [0.0; (fn(a: Nope) { 1 })]` は `Nope` の E0302。`(fn(a: [F32; Rg::[Nope, 4].CAP]) { 1 })` も署名で E0417、本体で E0302。
  読みは (1) 型の場所の名前も名前の段が先（E0302。本体の今の挙動） (2) 中の型によらず E0417（署名の今の挙動）に割れる。どちらも誤りとして拒む（通るプログラムは変わらない）。違いは、一つの定数式に誤りが二つあるときに先に報告するコードだけである。
- 決定: 決定（2026-11-12、利用者「提案通りで進めましょう」。140 回目。親の意見を伏せた onsa-advisor の段 1（`target/notes/140/b3-advisor/`）が二択では (1) を選び、親も同じ読みで段 2 は省いた）: (1)。定数式に書けない形（ブロック・`if`・`match`・無名関数）の中の型の場所（`let` の注釈、無名関数の引数と返り値の型と効果行、`as` の型、型引数）の名前も、普通の式と同じく名前の段が先に読む（`(fn(a: Nope) { 1 })` は、型の中の定数式でも式の中の定数式でも `Nope` の E0302）。§4.5 の「中の名前は名前の段が先」をそのまま当てる読みで、値の名前と型引数の並びの名前（今どちらの位置でも E0302）と揃う。型の場所だけ E0417 にする (2) は、型の場所の中で注釈と型引数の並びが割れるので採らない。W5-13 で、署名の側の `names/body/consts.rs::const_names` が型の場所を読み、別名の循環と順のグラフ（`sig/decls.rs` の `Graph::expr`）が葉の中を辿るようにする（R-436・R-426 と同じ単位。advisor の見当は計 65〜95 行で、グラフの拡張は 20〜35 行）。条件（利用者が了承）: W5-13 でグラフの拡張が見当を大きく超えるか、形ごとの手当てが続くなら、advisor の案 (3)（定数式の位置では定数式でない形の中を読まず、全て E0417。既決の §4.5 の文を改め、今は E0302 の中の値の名前も E0417 になる）と比べ直して利用者に出す。§4.5 に足した。
- 経緯: 134 回目（2026-11-10）、W5-10 U1b の壊す側（onsa-break）が報告し、再現の入力は壊す側の `c27.txt`（`closure_nope`・`b_closure_nope`・`closure_len_list`・`b_closure_len_list`）。急ぎでない。原因は、署名の側の `names/body/consts.rs::const_names` が定数式の中の型の場所を下ろさずに捨てること（R-426 の場所の一つ）。
