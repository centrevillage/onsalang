# S-873 §9.1 の `unwrap`・`map_err` の宣言に `rt` が無く、`rt` の関数から呼べるか（今は組込みの表の `unwrap` が通り、std の `map_err` が E0901）

- 空白: §9.1 は `Option` と `Result` のメソッドを `pub fn unwrap(move self) -> T` と `pub fn map_err[F](move self, f: fn(move E) -> F) -> Result[T, F]` と宣言し、どちらにも `rt` を書かない。§10 の規則 4 は、`rt` の関数は `rt` の関数しか呼べないとする。
  W5-02 U6 の後、`rt` の関数の中の `r.map_err(conv)` は E0901（「`rt` function calls `map_err`, which is not `rt` (§10 rule 4)」）で、組込みの表に残る `r.unwrap()` は通る。W5-03 が `Option`・`Result` を std の enum にし、`unwrap` を std の宣言にすると、字のとおりなら `unwrap` も `rt` から呼べなくなる。
  再現は `target/notes/109/w502u6/probe/rt_context.onsa`・`rt_unwrap.onsa`。
  読み: (1) 宣言の字のとおり `rt` でなく、`rt` の関数からは呼べない（`unwrap` は今通る形が E0901 になる）。(2) §9.1 の宣言を `pub rt fn` にする（本体が確保もブロックもしないので `rt` にできる。`map_err` は `f` が純粋な関数型なので `rt` の本体にできるかを見る）。(3) `unwrap` だけを `rt` にする。
  急ぎ: W5-03 の前（`unwrap` を std の宣言にするとき。今は `map_err` だけが E0901）
