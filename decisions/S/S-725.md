# S-725 署名と型の定数式（配列の長さ、const 引数）が、ソースで後ろに書いた `impl` の関連定数を読む形（宣言の順に頼るか）

- 空白: §4.5 は配列の長さと const 引数に関連定数（`P.N`）を書けるとし、§15.1 は項目の名前の解決を書くが、署名と型の定数式の参照が項目の宣言の順に頼るかを書いていない（本体の名前は順に依らずに引ける）。
  例: (a) `type A = [F32; P.N]` を `impl P { pub const N: U32 = 2 }` より前に書く。(b) `impl` の外の fn の署名 `fn f(a: [F32; P.N])` を `impl P` より前に書く。(c) struct のフィールドの長さが自分の型の関連定数を読む `struct S { a: [F32; S.N] }`（`impl S` に `N`）。
  読みは二つに割れる。(1) 順に依らずに引く（(c) は型の大きさが自分の `impl` に頼る形で、閉路でなければ通す）。(2) 署名の段では先に宣言した項目だけを引き、後ろは E0302。
  今の実装: (a)〜(c) は E0302「cannot find `P.N`」で、`impl` を先に書くと (a)・(b) は通る。同じ `impl` のメンバの署名の長さ（`fn f(a: [F32; Self.N])`）は W4-04 U6 から通る（メンバの名前を署名の前に表へ入れる）。再現は `target/notes/78/s725/`（`d1`〜`d4`、U6 の前の dev `5fc054e` も同じ）。
