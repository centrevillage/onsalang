# S-595 族: Self の名前

- 論点: 仕様 §2.2 は `Self` をキーワードとして並べるだけで、意味と書ける位置を書かない。使う例は trait の宣言の型の位置だけである（§6.3 の `Default` の `default() -> Self`、§6.6 の `trait AnyNum { const ZERO: Self }`、§6.3 の数の trait の関連定数「全て `Self`」）。
  一方、§2.4 は補間の経路の「頭は名前か `self`・`Self`」で「式に書いたときと同じ規則で解決する」とし、`spec/tools.md` §3.2 は「値として書く `self`・`Self`」の空白を決める。どちらも式の位置の `Self` を前提にしている。
  `impl` の中の例（§6.2 の `Point.new`、§6.6 の `impl Point { const ORIGIN: Point = … }`、§6.3 の `impl AnyNum for Q15 { const ZERO: Q15 = … }`）は型の名前で書く。

- 案:
  - (a) 型別名と同じ。`impl`（固有の `impl` と `impl Tr for Ty`。第 2 期の trait の宣言では実装する型）の中の `Self` は、対象の型を右辺にした型別名と同じに扱い、§4.4 の「型の名前を書ける全ての位置（型、関連関数と関連定数、struct リテラル、パターン、列挙子）」に書ける（1〜10 行が通る）。
    総称の `impl` では、型引数を `impl` の型パラメータに決めた型を指す（`impl[T] Pr[T]` の `Self` は `Pr[T]`。§4.4 の「型引数を決めた別名は、その型引数を決める」と同じ）。`Self { a: 1 }` は `Pr[T]` の値で E0401 になり、`Pr { a: 1 }` は `T` を推論する。
    型引数を付けた `Self` は E0412（型パラメータを持たない名前に型引数を書く、§4.5）、値の位置の `Self` だけは E0308（§15.1 の「型を値の位置に書く」）、`impl` の外は E0302（今の文面）。
    実装: 名前の段の経路の頭の解決に `Self` の枝（W4-04 で作り直す `body/names.rs` に 15〜30 行）、型付けで struct リテラルとパターンの `Self` に `impl` の型引数を使う所（10〜20 行）、`Self[…]` の E0412（5 行）。
    事例: 1〜10 行の正例と、11〜18 行の否定例（E0302・E0412・E0308 を各 3 件）。費用の要因: `impl` の中に、同じ型の二つの書き方（`Self` と型の名前）ができる。
  - (b) 型の位置だけ（今の実装）。`Self` は `impl` の中の型の位置（1 行）に書け、式・リテラル・パターン・補間の頭（2〜10 行）は E0302 のままで、note で型の名前で書くことを示す。§2.4 と `spec/tools.md` §3.2 から `Self` を消す。
    実装: `Self[…]` の E0412 と note（10 行）。事例: 否定例。費用の要因: §4.4 の別名と違い、型の名前を書ける位置の一部にだけ書ける名前になる。第 2 期の trait の既定の本体（`Self.ZERO` のように、実装する型の名前が無い所）で式の位置を開くときに、(a) の解決を足す。
  - (c) trait の中だけ。`Self` は、実装する型を指す名前が他に無い trait の宣言の中にだけ書け、`impl` の中では E0020（候補は対象の型の名前）にする（同じ型の書き方を一つにする）。
    実装: `impl` の中の `Self` を見つける所（10〜15 行）、候補（型の位置は対象に書いた型 `Pr[T]`。総称の `impl` の式の位置の `Pr::[T]` は W5-10 まで E0200 なので候補なし。20〜30 行）、`spec/foreign-forms.toml` の行と例。今通る 1 行の形が誤りに変わる。
    費用の要因: trait と `impl` で同じ名前の扱いが分かれ、第 2 期の trait の既定の本体では (a) の解決も要る（規則が二つになる）。Rust・Swift の書き方で `impl` を書く書き手の多くの行（`fn new() -> Self { Self { … } }`）が E0020 になる。
  - (d) 型の位置と経路の頭だけ。S-446 の形（2〜4・9・10 行）は書け、struct リテラルとパターンの `Self { … }`（S-377 の 5〜7 行）は E0302 か E0020（候補は型の名前）。実装は (a) から 5〜7 行の分を除いたもの。

- 他言語:
  - rustc 1.94.1（手元、`self_ok.rs`・`self_bad.rs`・`self_bad2.rs`）: `Self { x }`、`Self::N`、`Self::new(0.0)`、`Self::A(x)`、パターンの `Self { x: a }`・`Self::A(x)`・`Self::N`、`let Self { x: a } = self`、struct のフィールドの `Option<Box<Self>>` が全て通る。
    `Self<i32>` は E0109「type arguments are not allowed on self type」、`impl` の外は E0411、名前付きのフィールドの struct の値の `Self` は「the `Self` constructor can only be used with tuple or unit structs」。`impl<T> Pr<T>` の `Self { a: 1 }` は `Pr<T>` で E0308。
  - swiftc 6.3.1（手元、`self.swift`）: `Self.n`、`Self(x: 0)`、`Self.a(x)`、`case Self.a(let x)` が通る。トップレベルの関数の `-> Self` は「global function cannot return 'Self'」、`Self<Int>` は「cannot specialize 'Self'」。
  - Python 3.14.5（手元、`selfpy.py`）: `typing.Self` は注釈だけで、`Self(x)` は「TypeError: Cannot instantiate typing.Self」、`Self.N` は AttributeError。
  - C++（Apple clang 21、`inj.cpp`）: `Self` は無く、クラステンプレートの中の名前 `Pr` だけで `Pr<T>` を指す（注入されたクラス名）。TypeScript（`this` 型）、C#、Java: 未確認。
- 推奨と理由: (a)。確度: 中。
  - 読みが割れない。どの言語の読み方でも、`impl` の中の `Self` は対象の型で、`Self { x: a }`・`Self.N` が別の意味に読まれる形は無い。誤りにする理由になる誤解の形が無いので、書ける位置を制限しない。
  - 規則が一つで、位置ごとの例外が要らない。§4.4 の型別名の文（型の名前を書ける全ての位置で元の型と同じ）をそのまま当てる。(b) と (d) は位置ごとの区別を足し、(c) は trait と `impl` の区別を足す。
