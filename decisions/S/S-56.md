# S-56

- 空白: fmt と `diff --ast` が、構文エラーの判定を項目ごとに 1 件へ減らした後の診断で行い、E0320 に隠れた E0002 を見落として、失敗した関数をファイルから消す。fmt の前後でプログラムが同じかの確認が無い。最初のファイルの誤りで止まる。終了コードが仕様に無い（レビュー R-69）
- 提案: 構文の診断の有無を、減らす前に明示のフラグで持つ（番号の範囲で判定しない。登録簿の属性への移行は R-87）。命名の検査は AST の根から辿れるノードだけを見る。fmt は全てのファイルを処理し、構文の診断のあるファイルは書き換えない。書き込みは一時ファイルと rename。
  出力を再解析し、書き換えの一覧（末尾の `return`、括弧、既定値と等しい `init`、S-68 の `-> ()` と `uses {}`）を両方に施した AST と doc の比較と、コメントのテキストの並びの比較を通ってから書き込む。違えば最初に違った項目を示して 101。同じ比較を `diff --ast` にも使う。
  終了コード 0 / 1 / 2 / 101 を全てのコマンドで揃える（T0-3 を改める）。AST の不変と冪等性は R-113 の性質テストでも確かめる（2026-10-04 決定。実装は第 2 段）。改め（2026-10-15）: `init` は一覧から外した（S-539）。
  AST は doc を持たず、確かめは書き換えを施した AST、項目の順、doc の付く宣言、全てのコメントの並びを比べる。`diff --ast` は同じ正規化を施した構造だけを比べる（「同じ比較」は「同じ正規化」。S-534）
