# S-951 `trait`・`effect` の宣言の形の E0200 が、メンバの単位を項目の単位にまとめるか（`trait T {` の二つのメンバの構文の誤りが一つしか出ない）

- 空白: §18.1 は `impl` / `trait` / `effect` / `handler` / `extern` の各メンバをそれぞれ一つの単位とし、`impl` の見出しに誤りがあれば `impl` 全体を一つの単位とする（メンバは検査しない）。同じ節は「形の全体がこの版に無いもの（…`trait` と `effect` の宣言）は形の E0200 で、中の名前を読まない」とする。
  `trait`・`effect` の宣言の形の E0200 が見出しの位置に出たとき、メンバの単位を項目の単位にまとめるかは書いていない。今の実装（`onsa_sema` の `Units::assign` の見出しの規則 `heading_holds`）はまとめ、メンバの構文の誤りを項目の単位へ移すので、単位に一つの誤りの規則で一つだけが出る。
  `trait T {` / `  fn n(self) -> I32 x` / `  fn m(self) -> I32 y` / `}` は `check` の E0002 が一つ（`fmt --check` は二つ）、同じ形の `impl` は二つ。閉じない `{` の `trait` では、メンバの誤りが `{` の E0002 に隠れる（R-402）。`effect` も同じ。
  読み: (1) まとめる（今の実装。`trait`・`effect` の全体が E0200 の形なので、`impl` の見出しの誤りと同じに扱う）。(2) まとめるのは `impl` と extern のブロックだけで、`trait`・`effect` のメンバは別々の単位。
  どちらも誤りのあるファイルの報告の数だけが変わり、通るプログラムは変わらない。`trait`・`effect` を実装すると E0200 が消え、どちらの読みでも同じになる。入力は `target/notes/124/w511u10memo/probe/`（`t_two`・`i_two`・`trait_trail`・`e_trail`）。
