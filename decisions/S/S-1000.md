# S-1000 細部: const 引数の組の中の他言語の形の型引数（`Rg[F32, (F32, Rg[F32, 4].CAP)]`）を、値の位置と同じ E0020 にするか、今の E0002（「expected `,` or `)`, found `.`」）のままにするか

- 空白: §4.5 は const 引数の並びの要素を型の位置の並びと同じに読み、値の位置の `Rg[F32, 4].CAP` は他言語の形の型引数の E0020（S-333）とする。const 引数に組（`(F32, Rg[F32, 4].CAP)`）を書いた形は、組そのものが後の段の誤り（E0308）で、中の `Rg[F32, 4].CAP` を E0020 にするかを書かない。
  今（dev `91885285`）は `pub fn f(r: Rg[F32, (F32, Rg[F32, 4].CAP)]) -> U32` が E0002「expected `,` or `)`, found `.`」（9 行 37 桁）。W5-24 U6 の設計メモの先読みは括弧の最初の要素しか見ないので、U6a の後もこのまま。括弧の全ての要素を先読みすれば E0020 にできる（見当 +5 行）。
  仮の扱い: 今の E0002 のまま（`rules/leader.md` 5.11。元から誤りが二つの入力で、通るプログラムを変えない）。
- 決定: 決定（2026-11-12、利用者。140 回目、W5 の区切りの確認だけ。「全て現状のまま」で了承）: 仮の扱いのとおり。const 引数の組の中の他言語の形の型引数（`Rg[F32, (F32, Rg[F32, 4].CAP)]`）は、今の E0002（「expected `,` or `)`, found `.`」）のままにする。元から誤りが二つの入力なので、仕様は変えない。
- 経緯: 138 回目（2026-11-11）、W5-24 U6 の設計メモ（onsa-impl）が細部 D3 として報告した。親が dev のバイナリで今の出力を確かめた。
