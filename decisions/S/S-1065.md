# S-1065 静的な値の経路（`["a", "bc"][i]`）と、末尾が全て静的な値の `if`・`match`・ブロックを、`let` を経ずに値を置く位置（リテラルの要素、早い出口で待つ値、`[e; N]` の要素）に直書きしたとき、破棄が要らないと数えるか

- 空白: §5.4 は、`let` の束縛が破棄の要らない束縛になる初期値を「場所か、静的な値か、破棄の要らないリテラルか、それらの経路」とし、`if`・`match`・ブロック式は発散しない全ての末尾で決める。破棄の要らないリテラルの要素は「静的な値か、第一級の Copy の型の式か、破棄の要らないリテラルか、破棄の要らない束縛の名前とその経路」で、静的な値の経路と、末尾で決まる式を挙げない。静的な値は構文で決まり、ローカルの名前を含む式は静的な値でない。
  このため同じ式が、`let` を経ると破棄が要らず、直書きで値を置く位置に置くと所有の新しい値として破棄が要る（`rt` の関数で E0601）。
  今（`eed963f9`、W6-04 U2 の後）: `let t = ["a", "bc"][i]` の後の `Ok(((t, v), r?))` は誤りなし、直書きの `Ok(((["a", "bc"][i], v), r?))` は E0601。`let t = if c { "a" } else { "b" }` の後の `[t; 0]` は誤りなし、直書きの `[if c { "a" } else { "b" }; 0]`・`[{ "a" }; 0]` は E0601（U2 の S-1045 (1) で新しく出る）、`Ok((if c { "a" } else { "b" }, r?))` は前も後も E0601。
  静的な値の経路を単独で待たせる `Ok((["a", "bc"][i], r?))` は U2 の R-461 の直しで誤りなし（modes は `binding::no_drop` を読み、静的な値の経路を含む）。リテラルの分類（`binding/literal.rs`）は要素に `no_drop_binding`（束縛とその経路）だけを読む。
  再現: `target/notes/153/w604/u2b/gap.txt`（`g1`〜`g9`、W6-04 U2 の壊す側の入力）。
  読み: (1) 字のとおり。直書きの静的な値の経路と、末尾で決まる式は、値を置く位置では所有の新しい値（今の実装）。(2) `let` の初期値と同じ読みを値を置く位置にも当て、破棄が要らないと数える（`binding::no_drop` を、リテラルの要素の分類と末尾で決まる式にも使う）。
  仮の扱い: (1)（今の実装。通るプログラムを変えない。(2) にしても、書いたプログラムが止まることはない）。
  急ぎ: W6 の区切りで判断（`let` を経るかで結果が変わる非対称。(2) なら `binding` の一か所の直しで、見当は 10〜20 行）。
- 決定: 決定（2026-11-15、利用者。155 回目、W6-04 の区切り。独立のレビューの段 1 の後に「提案の通り」で了承）: (2) と D1〜D3。
  静的な値の経路と、発散しない全ての末尾がそれらである `if`・`match`・ブロック式を、置く位置によらず破棄の要らない値に数える（`let` の初期値、リテラルの要素、引数、早い出口で待つ値、`[e; N]` の要素、`for`・`match` の見出し）。
  D1: 経路の根が `if`・`match`・ブロックの形（`(if c { ("a", 1) } else { ("b", 2) }).0`）も含める。
  D2: 借用の引数を末尾に持つ `if` の経路（`let t = (if c { x } else { y }).0`、`x`・`y` は借用の引数。派生元を持つ借用で別の仕組みが要る）は今は行わず、`tasks/phase2.md` の L3 に書いた。
  D3: 仕様 §5.4 に「破棄の要らない値」を一か所で定め、見出しの表・借用の起点・リテラルの要素・破棄の要らない束縛・見出しの文がそれを指す。§12.2 の表の行も同じ語にした（経路と末尾を含む。実装は既に経路を数えない）。§11.3 の flow の初期化に書ける値（静的な値と破棄の要らないリテラル）は変えない。
  理由: `let` を一つ挟むかの書き方だけで E0601 の有無が変わり、呼ぶ先の引数が `move` か借用かでも変わる（`take2(if c { "a" } else { "b" }, r?)`）。§5.2 の「消費する位置に置いたブロックでは各腕を `let y = <腕の値>` と書いたときと同じに扱う」とも食い違っていた。
  入るのは不滅の静的オブジェクトと Copy の値だけでできた値を経路か制御で選んだもので、派生元を持たず、文脈に依らないので健全。通るプログラムが増えるだけ。第 2 期の形 C（`drop_alloc.rs::needs_alloc` の条件）とは判定の場所が違い、作り直しは無い（形 C は `binding::no_drop` を基に条件を足せる）。
  実装の注意（独立のレビュー）: 要素と消費する位置の判定は `binding::no_drop`（派生元の無い値）だけにし、見出しの `Settle::borrowed`（借用の根の場所を受け入れる）を使い回さない（使うと `match o { Some(s) => { let q = (s, 1); o = None; q.0.len() } }` の `q` が解放済みを指す、L3 の形 B）。
  所有のまま残る形（混ざる末尾 `(if c { "a" } else { s }, r?)`、所有の要素を持つリテラルの経路 `["a", s][0]`、腕の束縛を末尾の要素にする形、自分の型が Dup でない値 S-780、`let q = move nm`、`var`）を事例で固定する。
