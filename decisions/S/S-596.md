# S-596 モジュールの再公開（`pub use kp.inner` の後の他のモジュールの `use main.inner.{g}`）

- 空白: §15.1 は「再公開は `pub use` のみで、取り込めるのは `pub` の項目だけ」とし、モジュールは可視性を持たない。今は `pub use kp.inner` と `pub use kp.{inner}` の後に、他のモジュールの `use main.inner.{g}`・`use main.{inner}` が通る（第 39 組の下書きの `reexp.py`）。
  モジュールを `pub use` で再公開できるか、再公開した束縛を通る経路を `use` が辿れるかが書かれていない。S-594 の (x1) で依存のパッケージそのものとルート直下のモジュールも取り込めるようになったので、それらの再公開も同じ問いになる。
  あわせて、`pub use` で再公開した失敗の `use` の名前（S-462 の誤りの扱い）を他のモジュールが取り込む形も決める。
- 決定: 決定（2026-10-23、利用者が了承。57 回目、第 41 組）: (d)。再公開（`pub use`）は std 以外の依存と一緒に第 2 期に決める（§19.1）。この版の `pub use` は `pub` の位置の E0200 で、修正候補は無く、note で使う側が定義の経路で取り込む形（`use kp.inner.{g}`）を示す。
  理由: 再公開はパッケージの外の利用者のための仕組み（公開の API を内部のファイルの並びから切り離す、依存の型を見せる）で、第 1 期は std 以外の依存が E0200 なので使い手がいない。パッケージの中では定義の経路で取り込める。
  `pub use` を黙って普通の `use` として通さず E0200 で止めるので、通るプログラムに `pub use` が無く、後で再公開を入れても名前の解決も名前の重なりも変わらない。
  E0200 の `pub use` の取り込む名前は失敗した名前で、他のモジュールがそれを取り込む `use main.{g}` の名前も誤りとして扱い、診断を出さない（S-462 と同じ）。経路の途中にその名前を通す形（`use main.inner.{g}`）は、経路の途中を子モジュールと項目の定義だけから引くので E0302（R-250 と同じ規則）。
  取り込めるのを項目だけにするか（下書きと助言の (a)）、モジュールとパッケージも再公開できるか、再公開した束縛を経路の途中に通すか、`onsa interface` の表示は、第 2 期に再公開を入れるときに決める（下書きの形の表と独立のレビューの結論はその材料、`tasks/phase2.md`）。S-36 の `pub use` の部分を改める。仕様 §15.1、§18.1、§19.1
- 経緯: 55 回目（2026-10-23）、第 39 組（S-594）の下書きの付録の新しい S の候補を、利用者の回答（W4-03 の前に下書き）で登録した。関係: S-594、S-36、S-462。
  57 回目、第 41 組（族「§15.1 のモジュールの再公開」、下書き `S-596.draft.md`、助言の担当の二段）。下書きと段 1・段 2 は (a)（再公開は項目だけ）で一致した。利用者の問い（再公開は何のためか）から親が (d) を足し、利用者が (d) を選んだ（(d) は助言の担当に回していない）。
- 補い（2026-10-23、利用者が了承。58 回目、文書の点検の F6・F7）: `pub use` の E0200 は名前の段で出す。構文としては読めて、失敗した名前の扱い（S-462）が名前の段の仕組みだからで、`onsa fmt` は `pub use` を含むファイルも整形し（§18.2）、同じ単位の他の名前の段の誤りも報告する。
  予約語の名前のモジュールの `pub use kp.clock` は構文の段の `clock` の E0200 が先に出る（S-443 のまま）。仕様 §15.1、§18.1
- 補い（2026-10-25、親）: 69 回目（W4-03 U3b2/t の空白の報告、利用者が了承）: 誤りのある `pub use` の行は、§18.1 の単位の規則（`use` の一行が一つの単位で、最初の誤りで止める）どおり `pub` の位置の E0200 だけで、その経路はそれ以上解決しない（`pub use util.{missing}`・`pub use util.{secret}`・`pub use nomod.{x}` も E0200 一つ）。
  上の補いの「同じ単位の他の名前の段の誤りも報告する」は、ファイルの他の単位の名前の段の誤りを止めない意味と読む。
