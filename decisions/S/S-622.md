# S-622 経路で渡した `onsa.toml` がシンボリックリンクで、リンクの置き場所と指す先のディレクトリが違うときのパッケージのルート

- 空白: §15.1 は「渡した経路にリンクがあれば（途中のディレクトリのリンクも）、リンクを解いた場所から探す」「`onsa.toml` はリンクでも、リンク先をマニフェストとして読む（集める項目ではない）」とするが、経路として渡した `onsa.toml` そのものがリンクで、リンクの置き場所と指す先のディレクトリが違うとき（`x/onsa.toml -> ../y/onsa.toml`）、ルートが `x` か `y` かを書いていない。集めるファイルの集合が変わる。
  字面は「解いた場所から探す」で `y` と読めるが、`x` を渡すと `x/onsa.toml`（リンク）をマニフェストとして読み `x` がルートになるので、`x` と `x/onsa.toml` で結果が分かれる。
  今の実装は、どちらを渡しても `x` をルートにする（`x/a.onsa` を集め、`y/b.onsa` を集めない。dev `4965cf0` の release、58 回目の scratchpad の `x8est2/probe/link/`）。S-592 の族の表はディレクトリのリンクとファイルのリンクだけで、この形が無い。
  S-592 の (4)「上へ探す起点は、渡した経路のリンクを解いた場所」の字面では `y` になる。cargo 1.94.1 は、リンクの `Cargo.toml` を `--manifest-path x/Cargo.toml` で渡しても、`x` に入って `cargo run` しても、`x` をルートにする（`x/src/main.rs` を使う。58 回目の scratchpad の `x8est2/probe/cargolink/`）。
- 決定: 決定（2026-10-24、利用者が (A) の一覧で ID を挙げて了承。58 回目、第 49 組、X-8 の第二弾の X2-2）: (b)。経路で渡した `onsa.toml` は、その置き場所のディレクトリを渡したのと同じに扱う。リンクを解くのはディレクトリの部分だけで、`onsa.toml` 自身はリンク先をマニフェストとして読む（S-592 の補い）。
  リンク先が無いか読めなければ入出力の誤り（終了コード 2、S-592 の (3)）。`x` と `x/onsa.toml` のどちらを渡しても、集めるファイルの集合は同じになる。今の実装と同じ。理由（親と独立のレビューが一致）: 渡し方だけで結果が分かれる形を残さない。cargo の挙動は参考にとどめる。仕様 §15.1
- 経緯: 58 回目（2026-10-24）、X-8 の第二弾の見積もり（組 A、onsa-impl）が W4-14 の S-592・S-272・S-324 の見積もりで見つけ、親が再現した。下書きの担当は立てず、親の案と仕分けの独立のレビュー（onsa-advisor の二段）が (b) で一致した。
