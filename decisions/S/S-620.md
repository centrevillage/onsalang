# S-620 Rust・C の `static NAME: T = e`（`static int x = 4;`）の項目の診断（`static` を予約した後に、note で `const` を示すか、`const` を修正候補にするか）

- 空白: Rust の `static LIMIT: I32 = 4`（`static mut` を含む）と C の `static int x = 4;` の項目は、今の実装（`static` を予約する前）で E0002「expected a declaration, found identifier」になり、使う所にも E0302 が続けて出る（`target/notes/58/grp48/probe/p13_rust_static_item.onsa`）。
  §18.1 の他の言語の修飾の語の規則（S-459）は、語の並びの直後が見出しを始めるトークンのときだけ当たり、`static` の後に名前が続く形は当たらない。S-615 で `static` をキーワードとして予約した（§2.2）ので、名前まで読んで登録し連鎖を消すか、note で「静的なデータは `const`」と示すか、`const` を修正候補にする E0020（`let mut` から `var` と同じ種類）にするかを決める。`static mut` は候補を出さない見込み。

- 経緯: 58 回目（2026-10-24）、第 48 組（S-615）の下書き（onsa-gap）と独立のレビューの段 1・段 2 が新しい S の候補として挙げ、利用者が了承した（S-615 の E2）。S-615 の結果（`static` の予約）の上に立つ。
