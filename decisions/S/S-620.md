# S-620 Rust・C の `static NAME: T = e`（`static int x = 4;`）の項目の診断（`static` を予約した後に、note で `const` を示すか、`const` を修正候補にするか）

- 空白: Rust の `static LIMIT: I32 = 4`（`static mut` を含む）と C の `static int x = 4;` の項目は、今の実装（`static` を予約する前）で E0002「expected a declaration, found identifier」になり、使う所にも E0302 が続けて出る（`target/notes/58/grp48/probe/p13_rust_static_item.onsa`）。
  §18.1 の他の言語の修飾の語の規則（S-459）は、語の並びの直後が見出しを始めるトークンのときだけ当たり、`static` の後に名前が続く形は当たらない。S-615 で `static` をキーワードとして予約した（§2.2）ので、名前まで読んで登録し連鎖を消すか、note で「静的なデータは `const`」と示すか、`const` を修正候補にする E0020（`let mut` から `var` と同じ種類）にするかを決める。`static mut` は候補を出さない見込み。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: B5、R1、X、Y）項目の位置（トップレベルとメンバ）の頭の `static` は他の言語の書き方として読む。Rust の `static NAME: T = e`（`static` に名前が一つ続く形）は E0020 の行 `static_item` で候補は `const NAME: T = e`。`static mut NAME: T = e` は `static_mut_item`、C の宣言（`static` の後に名前が二つ以上並び、見出しを始めるトークンが続かない形。変数の `static int x = 4;` と関数の `static int f(void) {`、X）は `c_static_item` で、どちらも候補の無い E0002。note は、`static mut` と C の変数の形は B5 の文、C の関数の形（最後の名前の直後が `(`）は「関数は `fn` で書く」（X）。三つとも名前まで読み、`static NAME: T = e` は型 `T` の定数として、`static mut` と C の形は型の読めない宣言として名前解決に見せる（使う所に診断を出さない。`static mut` を定数として見せると、使う所の代入が後の段の誤りになる、Y）。初期化式と C の関数の本体（対応する `}` まで読み飛ばす）は検査しない。`static const int x = 4;` は `const` が見出しを始めるので、見出しの前の修飾の語の E0002（Y）。`static fn`・`static inline fn` は今の修飾の語の E0002、項目の頭の外の `static` は今の E0200。§19.1 に一行（変更できる大域の状態、効果として表す道、詳しくは検討していない）。
  - 仕様の節: §2.2、§18.1（読み続ける形に一文）、§19.1、一覧の 3 行。
  - 今通るプログラム: 変わらない（今どれも E0200 と、使う所の E0302。`static int f(void) {` も同じ）。
  - 実装の見当: `foreign/decls.rs`（S-464 の行の隣）に 3 行、`parser/heading.rs` か `parser/items.rs` で名前まで読んで宣言を記録し、C の関数の本体を読み飛ばす（60〜120 行）。`onsa_diag` の `unsupported.rs` の `StaticMarks` は項目の頭の外で使い続ける。
  - ぶつかる事例: `tests/spec/negative/continue_foreign_words.onsa` の `static fn`・`static inline fn`・`pub static fn`・`static pub fn`（22・51・64・73・105 行）は今のまま E0002（見出しを始めるトークンが続く）で、ぶつからない。
- 経緯: 58 回目（2026-10-24）、第 48 組（S-615）の下書き（onsa-gap）と独立のレビューの段 1・段 2 が新しい S の候補として挙げ、利用者が了承した（S-615 の E2）。S-615 の結果（`static` の予約）の上に立つ。
