# S-673 自分のパッケージ名かモジュール自身の名前で始まる本体の経路（パッケージ `fx` の `fx.util.helper()`、`main.onsa` の `main.other()`）の E0302 の修正候補

- 空白: §15.1 は「`use` の無い経路（`std.math.sqrt(x)`）は E0302（修正候補は `use` の追加）」とし、`use` の頭の自分のパッケージ名には「パッケージ名を外すこと」の候補を定める（S-663）。本体の経路の頭が自分のパッケージ名のとき（`fx.util.helper()`）と、モジュール自身の名前のとき（`main.onsa` の `main.other()`）の候補を書いていない。
  読みは三つある。候補なし。`fx.` を外して `use util` を足す（二か所の編集）。`main.other()` に `use main` を足す（§15.1 は取り込む `use` の辺から自分自身を除くので、自分を取り込める読み）。
  仮の扱いは U2b の実装のまま（事例は候補の有無と形を約束しない。`tests/spec/packages/body_path_undeclared`）。
  あわせて、一要素の頭（`let x = util`、`x: std`、`[I32; util]`、モジュール自身の名前の呼び出し）の E0302 は、U2b で候補なしにした（親の答え。当てても値・型の位置のモジュールの誤りが残るため。壊す側の指摘 2、`target/notes/65/w403/u2b/b/cases/j_*`）。
- 決定: 決定（2026-10-25、利用者が ID を挙げて了承。66 回目、第 58 組）: 論点 1 は (b)、論点 2 は (d)。
  本体の経路の頭が自分のパッケージ名なら、パッケージ名を外し、外した後の頭を取り込む `use` が無ければ足す一つの候補（`fx.util.helper()` → `use util` と `util.helper()`）。
  頭がモジュール自身の名前か、自分の絶対経路（`dsp/synth.onsa` の `dsp.synth.`）なら、その部分を外す（`main.other()` → `other()`、`synth.g()` と `dsp.synth.g()` → `g()`）。外した後が子モジュールで始まるなら、それを取り込む `use` を足す（`main.inner.g()` → `use main.inner` と `inner.g()`）。
  細部（S-673-2・3）: 一要素の頭は候補なし。`use` を足す候補と頭を外す候補は、当てた後の経路が名前の段で最後まで解決し（E0302 も E0303 も残らない）、新しい頭の名前が空いているか同じモジュールの `use` に束縛され、足す `use` が循環を閉じないときだけ出す。頭がルート直下のモジュールの名前で自分の名前でもあるときは、ルート直下の読みを先にする。候補を出さないときの note は正しい形を示す。
  仕様は §15.1 の E0302 の候補の文。実装は W4-03 の U3a2（今の `main.other()` の候補 `use main` と、`dsp.synth.g()` の候補 `use dsp` を置き換える）。今の実装が経路の残りを確かめない違反は R-268。
- 経緯: 65 回目（2026-10-25）、W4-03 U2b のテストの票（onsa-test）が NEW-C として挙げた。期限は `use` の頭の候補を入れる W4-03 の U3a の前。関係: S-663、R-39、R-106。
  66 回目（2026-10-25）、第 58 組の下書き（onsa-gap）と独立のレビュー（onsa-advisor の二段）。論点 1 と細部は一致した。論点 2 は下書きが (c)（`use main` を足す）、助言が (d) で割れた。
  利用者が (d) を選んだ（自分のモジュール名を付けて呼びたい場面は少なく、名前が重なるときは `use` で取り込んだ側をモジュール名の経路で呼べば避けられる。困る場面が出たら考え直すが、(d) なら既存のプログラムを壊さない）。`dsp.synth.g()` も外す形は、利用者が確かめて含めた。
