# S-1005 総称の定数のパラメータを容量に持つ `FixedStr[N]`（`fn is_warm[const N: U32](t: FixedStr[N]) -> Bool { t == "warm" }`）に置く文字列リテラルの容量の検査（E0408 を決められない）

- 空白: §4.2 は「期待の型が `FixedStr[N]` なら … `N` が決まっていなければリテラルの長さを `N` にする。容量を超えるか ASCII の外の文字を含むリテラルは E0408」とし、§4.7 は型が決まった時点で範囲外のリテラルを E0408 とする。容量が囲む総称の関数の定数のパラメータ `N`（`fn is_warm[const N: U32](t: FixedStr[N]) -> Bool { t == "warm" }`）のときは、検査の時点で容量が分からず、E0408 を決められない。
  割れる読み: (1) 型の段で拒む（配列のリテラル `[1, 2]` を `[U8; N]` に置く形が E0401 なのと揃う） (2) 具体化ごとに E0408 を判定する（降下の後の診断） (3) 比較とパターンでは長すぎるリテラルを「等しくない」とし、値を作る位置だけ (1) か (2)。
  今の類例（dev `69326f64`）: 配列のリテラルを `[U8; N]` に置く形は E0401「expected `[U8; N]`, found `[U8; 2]`」。
  `match` のパターンの文字列リテラルも同じ形になる（§7: 対象が `FixedStr[N]` で `N` が囲む関数の総称のパラメータのとき。W5-12 U2/t のテストの担当が挙げた）。
  仮の扱い: (1) の E0401 にコードの `SPEC-GAP(S-1005)` の印を付ける（式は W5-12 U2、パターンは U3a。後で緩める向きにだけ変えられる）。
