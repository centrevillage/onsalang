# S-1148 細部: `xs.slice(from, to)` の `from > to`（`xs.slice(3, 1)`）を範囲外の panic にするか、長さ 0 の `Span` にするか

- 空白: §5.3 の部分ビューの行は「半開区間 `[from, to)` の `Span`。範囲外は panic」、§9.2 は panic の一覧に「範囲外の添字アクセス `xs[i]` と `xs.slice(from, to)`」を挙げる。`from > to`（`xs.slice(3, 1)`、どちらの端も長さ以下）が「範囲外」に入るか（panic）、空の区間として長さ 0 の `Span` を返すかが字で一つに決まらない。
  今（`onsa-4c744d9`）: インタプリタは `slice 3..1 is out of range for a sequence of length 4` で panic し、参照評価器（W7-19 U2b）も panic にした。C は確かめていない。Rust の `xs[3..1]` は panic。再現は `target/notes/166/w719/u2b/t/gap/src/main.onsa`。
  仮の扱い: panic（今の実装のまま）。急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定: 決定（2026-11-26、利用者。189 回目、W7 の区切りの確認。「なるほど、ひとまず (1) にしましょう」）: (1)。`xs.slice(from, to)` の端の逆転（`from > to`、両端は長さ以下）は、添字の範囲外（`to > len`）と別の誤りとして panic する。§5.3 と §9.2 の字で二つを分けて書く。`for` の逆転した範囲が空なのと違うのは、`for` の範囲は回数を決めるだけで、`slice` の長さ `to - from` は負になれないため（手元で確かめた Rust・Go も、範囲外と別の文面で逆転を誤りにし、`for` の逆転は 0 回。Go は端が定数ならコンパイルの誤り）。端が定数でも実行時の panic（`rules/criteria.md` 7.34）。panic の文面は今のまま（細部）。後で空に緩められる（7.5）。
  利用者の経過: 親は初め、範囲外と逆転を混ぜて「空にしても `for` と揃わない」と説明し、利用者が「範囲外について、範囲の逆転と、添字の範囲外を区別せず論じている」「Rust や Go もこの二つを区別していませんか」と指摘した。親が訂正し、逆転だけの問いとして (1)・(2) を比べた（控え `target/notes/189/s1148/`）。
- 経緯: 166 回目、2026-11-18、W7-19 U2b のテストの担当（参照評価器の `slice` の取り出し）が仕様の空白として挙げ、親が登録した。
