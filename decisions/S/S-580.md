# S-580 プラグインの出力の全体の形: `kind = "clap"`・`"vst3"`・`"au"` が生成するもの、SDK と使用許諾、マニフェストの書き方

- 空白: §15.3 の例は `kind = "clap"` のターゲットを持ち、§16.1 は「プラグイン（`clap` / `vst3` / `au`）と `staticlib` では `main` が無く、状態と同期型はホストが持つ。C API（§14.2）はそのまま使う」とするが、プラグインのターゲットが何を生成するかは書かれていない（この版では `kind` の未対応の値で E0200、S-154）。
  §14.2 は、export した flow を既存のホストへ組み込む第一の経路とする。決めること:
  1. 生成するもの（ラッパーのソース、ビルドしたプラグインのバイナリ、その両方）と、SDK（CLAP、VST3、AU）の扱い（同梱するか、利用者が渡すか）と使用許諾。
  2. マニフェストでどの flow をプラグインにするか、プラグインの識別子と表示（ID、名前、作り手、版、種類: 楽器・エフェクト・ノートの処理）の書き方。一つのパッケージから複数のプラグイン。
  3. 実装の時期（第 1 期の段に入れるか。A-13 はプラグインの出力を第 2 期とした）。
- 決定: 決定（2026-10-22、利用者が ID を挙げて了承。51・52 回目）: `kind = "clap"`・`"vst3"`・`"au"`（AUv2）のターゲットは、C のソースとホストの `platform` の束まで作り（PATH の `cc`。束は同一性の約束の外、クロスは E0200）、ラッパーは形式ごとの固定の C と flow ごとの公開しないつなぎで作る。
  CLAP のヘッダと VST3 の `vst3_c_api.h` を埋め込んで使用許諾の文を出力に置き、AU は macOS の SDK を使う。
  マニフェストはパッケージの表 `[[plugin]]`（`flow`・`id`・`name`・`vendor`・`version`・`category`、AU は `au = { subtype, manufacturer }`）で、全てを一つの束に入れ、AU の型は `category` と MIDI の入力から、VST3 のクラスの ID は `id` から決まる。
  CLAP だけを第 1 期の W10・M5 の後に作り、VST3・AU は第 2 期（回答の (t2)）。C の API の `<p>_latency`・`<p>_host_info`・`<P>_HOST_COUNT`・`onsa_host_kind`・`onsa_host_info`・`offset` は W10 で足す。仕様 §19.1
- 経緯: 第 36 組（プラグインの出力）の一つ。第 35 組（境界、S-570〜S-574）の決定の見込みの上に立ち、C の API がラッパーの要求を満たすかを W10 の前に確かめる。利用者が「VST/CLAP/AU用の出力は主要な機能の一つなので、今考えておきたい」「避けられる手戻りは前もって避けた方が良い」とし、出力の形まで決める範囲（(β)）を選んだ（2026-10-22、51 回目）。関係: S-154、S-570〜S-574、S-585（GUI）、A-13。
