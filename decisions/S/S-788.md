# S-788 生成型 `In`・`Out` の `Span` のフィールドを `let` に束縛する形（`let l = o.l`）

- 空白: §5.3 の 91 行は flow の生成型 `In` / `Out` を第二級とし、「`In` / `Out` は引数の位置にだけ現れる（フィールドを受け手や添字の左辺に使うのも同じ）」とする。§5.4 の 138 行は `Span`（平面の要素、`Span` の引数、部分ビュー）を、元が借用の起点か派生なら `let` に束縛できるとするが、生成型のフィールドの `Span`（`o.l`）を挙げない。
  読みは (1) 借用の引数の生成型のフィールドの `Span` も `Span` の引数と同じく借用の行で束縛できる、(2) 生成型のフィールドは受け手と添字の左辺にだけ使え、`let l = o.l` は E0710、(3) 他の形。
  今は借用の引数 `o: swap.Out` からの `let l = o.l` が通り、`inout o` からは部分移動の E0711 になる。再現は `target/notes/86/g75/parent/out_field_let.onsa`。
  W4-07 の設計メモ（2.6）の第二級の述語は、型が `Span` なら束縛の位置で許すので (1) になる。
- 決定: 決定（2026-10-30、利用者。86 回目、第 75 組。確認だけ。独立のレビューの読み）: (1)。借用の起点の生成型 `In` / `Out` の `Span` のフィールド（`o.l`）は、`Span` の引数と同じく借用の行で `let`・`for`・`match` の腕に束縛でき、束縛した名前は第二級のまま。`inout` 引数からは §5.4 のとおり E0710（今は部分移動の E0711）。仕様 §5.3、§5.4
- 経緯: 86 回目（2026-10-30）、W4-07 の設計メモの独立の審査（onsa-advisor）が S の候補として挙げた（重さは低）。親が再現を確かめて登録した（W4-07 の前）。
- 反映（2026-10-30、親）: 87 回目、利用者が了承: `inout` 引数からの `let l = o.l` の E0710 は、W7-03 で生成型 `Out` のフィールドを `Span` にし（R-334）、`Out` と `Rendered` を分けた後に入れる。借用の `o` からの束縛が通る形は W4-07 で入る。
