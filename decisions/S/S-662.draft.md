# S-662 固有の `impl` のメンバの可視性が、型の可視性より広いとき（無指定の `struct Inner` の `impl Inner { pub fn new() -> Inner }`）に S-144 の E0303 にするか

- 決定済みで戻さないもの: `pub struct P` の `impl P { pub fn leak() -> Inner }` は、どの読みでも E0303（S-144）。容れ物の語は S-491。呼び出し（`p.m()`・`Inner.new()`）でメンバの可視性を検査することは R-38。
- 論点: §15.1 の S-144 の文で、固有の `impl` のメンバ（関数と関連定数）の「その宣言の可視性」が、メンバ自身のものか、型の可視性で抑えたものかを書いていない。無指定の `struct Inner` の `impl Inner { pub fn new() -> Inner }` で読みが割れる。
  - 族の規則から決まる部分: 比べる可視性は S-665 の案で決まる。S-665 の (a) なら宣言自身で、この形は E0303。(b)〜(d) なら届く範囲で、この形は通る（S-665 の表の 8・9）。
  - 残る論点: 型より広い `pub` をメンバに書くこと自体を誤りにするか。届く範囲で比べる規則の下では、その `pub` は型の可視性の外に届かない（眠った `pub`）。
- 今の実装: S-144 の検査はまだ無い（W4-03 の U4）。`probe/implpub.onsa`（無指定の `struct Inner`、`impl Inner { pub fn new() -> Inner }`、`pub fn f(i: Inner) -> I32`）は `check` が診断なしで終了コード 0。
  `interface` は `impl Inner` と `pub fn new() -> Inner`、`pub fn f(i: Inner) -> I32` を出し、`Inner` そのものは出さない。`probe/pk2`（`priv struct Hidden` の `impl Hidden { pub fn make() -> Hidden }` を含む）でも `impl Hidden` と `pub fn make() -> Hidden` を出す（R-265）。
- 案: 届く範囲で比べる規則（S-665 の (b)〜(d)）の上で:
  - (a) 足さない。眠った `pub` は通る。
  - (b) 型より広い `pub` をメンバに書くと誤りにする（名前の段。コードは E0303 か、E0020 の閉じた一覧の行。修正候補は `pub` を外すこと）。書いた語の無い無指定のメンバ（`priv` の型の）は対象にしない。`priv` の型の全てのメンバに `priv` を求めると、`priv struct` のフィールドの `priv` が冗長の E0020 であるのと逆向きになるため。

  | 形 | 宣言自身で比べる（S-665 の (a)） | 届く範囲で比べ、(a) | 届く範囲で比べ、(b) |
  |---|---|---|---|
  | 1. 無指定の `Inner` の `pub fn new() -> Inner` | `Inner` に E0303 | 通る | `pub` の誤り |
  | 2. 無指定の `Inner` の `pub fn get(self) -> I32` | 通る（`self` は型を書かない） | 通る | `pub` の誤り |
  | 3. 無指定の `Inner` の `pub fn count() -> I32` | 通る | 通る | `pub` の誤り |
  | 4. `priv` の `Hidden` の `fn make() -> Hidden` | `Hidden` に E0303 | 通る | 通る |
  | 5. `priv` の `Hidden` の `pub fn make() -> Hidden` | `Hidden` に E0303 | 通る | `pub` の誤り |
  | 6. `pub` の `P` の `pub fn leak() -> Inner` | E0303 | E0303 | E0303 |
  | 7. 無指定の `Inner` の `pub fn h() -> Hidden` | E0303 | E0303 | `pub` の誤りと E0303 |

  - 3 段階で言い直すと: 宣言自身で比べると、無指定の型の `pub` のメンバをパッケージの外に見える宣言として扱う。届く範囲で比べると、無指定の型のメンバは `pub` でもパッケージ内、`priv` の型のメンバはモジュール内まで届く。(b) を足すと、書いた `pub` は常にパッケージの外に届く。
  - 書き手から見える違いは、通るかどうかと `interface` の表示だけである。通るプログラムの呼び出しは、どの形でも同じに働く。他のモジュールの `Inner.new()`・`i.get()` は、`Inner` が無指定ならパッケージ内で通る。パッケージの外からは型の名前を書けず、値も得られない（S-665 の規則が塞ぐ）。`Hidden` は他のモジュールで `use` の時点で E0303。
  - 直し続けて止まるか: 宣言自身で比べると、1 は候補の無い E0303 で、直し方は `new` の `pub` を外すか `Inner` を `pub` にするかの二つになる。`Inner` を `pub` にすると、継いで `pub` になったフィールドの型にも E0303 が出る。届く型が全て `pub` になるまで広がって止まる。
    (a) は誤りが無い。(b) は候補（外す）を当てると一度で止まり、型を広げる直し方を選ぶと同じ連鎖になる。
  - 実装の量（U4、S-665 の検査の上に）: (a) 0 行。(b) 語の検査・文面・候補・否定例 3 件以上で 20〜30 行。E0020 にするなら `spec/foreign-forms.toml` に一行。
- 他言語:
  - rustc 1.94.1（`other/lib.rs`）: 非公開の `struct Inner` の `impl Inner { pub fn new() -> Inner; pub fn get(&self) }` は、既定の lint では何も出ない。既定で allow の `unreachable_pub` を warn にすると、`new` と `get` に「unreachable `pub` item」と候補 `pub(crate)` が出る。
  - Swift 6.3.1（`other/a.swift`、`-typecheck`）: `internal` の `struct Inner` の `public func get() -> Inner`・`public static func make() -> Inner`・`public init()` と、`private struct Hidden` の `public func g()` は通る。
  - Kotlin（未確認、手元に無い）: 仕様の「Declaration visibility」（https://kotlinlang.org/spec/declarations.html#declaration-visibility ）は、`public` を「accessed from any other scope their outer scope can be accessed from」とする。
  - Go 1.27.2（`other/gomod`）: 非公開の型の公開のメソッドに、`go vet` を含めて何も出ない。
- 推奨と理由: (a)。確度: 中。比べる可視性は S-665 の規則（届く範囲）から。
  - S-144 が防ぐのは、宣言に届く利用者がその型に届かないことである。メンバに届くには型の名前を書くか型の値を持つ必要があり、どちらも型の可視性の中でしかできない。無指定の型の `pub fn new() -> Inner` に届く利用者は必ず `Inner` にも届くので、防ぐべきことが起きていない。
  - 宣言自身で比べる読みは、害の無い形を誤りにし、しかも形で割れる。表の 1 と 2・3 は外からの届き方が同じなのに、型を書くかどうか（`-> Inner` と `self`）で合否が分かれる。直し方の一つ（型を `pub` にする）は、届く型を次々に `pub` にする連鎖を生み、パッケージの外への公開を書き手の意図より広げうる。
  - (b) は「書いた `pub` は必ず外に届く」を揃え、フィールドの `pub` が E0020 であることとも向きが合う。厳しい方なので、後で (a) に緩めても壊れない。
    一方で、規則と診断の形が一つ増え、他の主な言語が通す書き方（Rust・Swift・Go で確かめた）を禁じる。眠った `pub` の害は、型を `pub` に改めたときにメンバが一度に外へ出ることである。それは `onsa interface` の差分（と第 2 期以降の凍結のポリシー）に出るので、Onsa に固有の実害は薄い。
  - (a) で増える規則は無い（S-665 の一句で足りる）。代わりに、(a) から (b) へ後で締めると、眠った `pub` を持つプログラムが落ちる（候補で外せる）。
