# S-564 flow のイベントの出力

- 決定済みで戻さないもの: §19.1 の方向（flow の `block` の出力、エンベロープの終了通知などは、イベントのクロックの出力として扱う）。S-171（信号からイベントへの変換 `detect_zero~` を std の flow で書く）。S-119（出力の `at` は必須で、今は `sample` 以外は E0810）。
- 論点: 記号: E(e) は「イベントの入力 `e` のイベントの刻み」を指す説明の記号で、Onsa の構文ではない。入力の番号（p01 など）は、47 回目に dev `4aaa028` の release の `check` で試した入力（S-560 の「今の実装」の表）。
  §19.1「flow の `block` の出力（エンベロープの終了通知など。イベントのクロックの出力として扱う方向、下記）」。§11.3「この版では出力のクロックは `sample` だけで、それ以外も E0810」。
  - (1) 出力にイベントのクロックを書く形と、一つの刻みに出せるイベントの数。(2) 出力のイベントの位置と、他の flow のイベントの入力に渡したときに同じブロックの中で届くか。(3) struct の出力の中にイベントを含められるか。
- 今の実装: `-> Done at event` は E0302（p02）。`-> F32 at block` は E0810（p08）。`-> Option[F32] at sample` は E0810（p05。文面は入れ子の配列のことを言い、原因と合わない）。
- 案:
  - (1a) `-> E at event` と宣言し、本体の出力の式は、その flow の `sample` のクロックの `Option[E]` にする。`Some(v)` の刻みで、その位置に一つのイベント `v` を出す。一つの刻みに一つまで。
    実装: 出力のクロックの検査（W7-02）、出力のイベントの書き出し（W8、W10）。一回の `process` で出るイベントは高々フレームの数なので、ホストが用意する場所の大きさが決まる。
  - (1b) (1a) に加えて、本体の出力の式をイベントの入力のクロックにもできる（入力のイベントごとに一つまで。`None` で捨てる）。MIDI のエフェクト（移調、和音を同じ位置に保つ）が書ける。
    費用の要因: 同じ位置に複数の出力のイベントができ、受け手の flow へ渡すときに、作り手の式をイベントごとに評価するか、一時の置き場所（大きさは入力のイベントの数）が要る。
  - (1c) 一つの刻みに複数（`[Option[E]; N]` など）。費用の要因: 境界と受け手の列の大きさの規則。
  - (1d) この版ではイベントの出力を入れない（E0810 のまま）。S-171 の `detect_zero~` は書けず、境界は後で足す。
  - 型の書き方: (t1) 宣言は `E`、本体は `Option[E]`。宣言は受け手が受ける値の型で、入力の `notes: Note at event` と同じ読みになる。費用の要因: 宣言と本体の型が違う（E0401 の note で示す）。
    (t2) 宣言も `-> Option[E] at event`。費用の要因: 受け手のイベントの値の型が `Option[E]` に見え、入力の宣言の読みと合わない。
  - (2a) 出力のイベントの位置は、出した刻みの位置。呼び出し側では、その呼び出しの出力が一つの新しいイベントのクロックになり、他の flow のイベントの入力に同じブロック・同じ位置で渡る。
    受け手は名前の順で作り手より下にあるので、受け手のその位置の `sample` の一歩の前に届く。
  - (2b) 次の位置に出す（一サンプル遅れる）。費用の要因: 書かれていない遅延（§11.2）。ブロックの最後の位置のイベントは次の `process` に繰り越す状態が要る。
  - (3a) struct の出力にイベントを含めない（E0810）。音声と終了通知を一つの flow から出すには、`sample` の struct（`{ level: F32, done: Bool }`、`done` は終わりの位置で真）にするか、通知を別の flow に分ける。
  - (3b) 出力ごとにクロックを書ける複数の出力の構文を足す（`-> (level: F32 at sample, done: () at event)` など）。費用の要因: 新しい構文と、境界の `Out` の形。
  - (3c) `Option` のフィールドを持つ `sample` の struct の出力を許す（イベントのクロックを使わない）。費用の要因: 境界に `Option` が出る（今は E0810）。
- 他言語:
  - Cmajor（Language Reference の Writing to Outputs）: 「For event outputs, multiple events are sent in the order they were added」。
    `processor.eventBufferSize` は「The maximum number of events that can be buffered per block」。
  - CLAP（`events.h`）: 「Output event list. The plugin must insert events in sample sorted order when inserting events」。
  - Esterel v5（primer §4.4.2）: 結合の関数の無い値の信号は「cannot be emitted twice in the same instant」。
- 推奨と理由: (1a) と (t1)、(2a)、(3a)。確度: 中。
  - (1a): S-171 の `detect_zero~` とエンベロープの終了通知（§19.1）が書け、一回の `process` の出力の数に上限があるので、境界の大きさが決まる（P6）。
    (1b) と (1c) は受け手の側に置き場所の規則が要る。後で足しても今のプログラムを壊さない。(1d) は S-171 で決めた std の変換が書けない。
  - (t1): 受け手が受ける型を宣言に書く読みが、入力の `at event` と同じになる。`Option` は「この刻みに出すか」で、`sample` の本体で刻みごとに出す・出さないを表す最小の形である。
  - (2a): 作り手と受け手の順は、名前を上から定義する規則（§11.2）で既に決まっている。遅延を足さず、ブロックの区切りにも依らない。(2b) は隠れた遅延と繰り越しの状態を作る。
  - (3a): §11.3 のとおり、一つの値は一つのクロックを持つ。音声と通知の両方が要る場面は、`sample` の `Bool` か flow を分けて書ける。
  - あわせて決めること（受け手の側）: 呼び出しの出力のイベントのクロックは、呼び出しごとに別のクロックで、入力のイベントのクロックとは比べられない（S-560 の (1a) を選んだとき）。
  - あわせて決めること（`when~` の受け手）: 止まっている刻みにはイベントを出さない（S-562 のあわせて決めることと同じ）。
  - 新しい S の候補: (1b) の入力のイベントごとの出力と、(3b) の出力ごとのクロック。必要な実例（MIDI のエフェクト、エンベロープ）が出たときに決める。
- 影響:
  - 仕様: §11.3 と §11.6 の「出力は `sample` だけ」の文、§11.2 の出力の宣言、§19.1 の `block` の出力の項（(1a) なら閉じる）。
  - 診断のコード: E0810（出力の形、struct の中のイベント）、E0401（(t1) の本体の型）。(1d) なら今のまま。p05 の E0810 の文面の直しは別（下の報告）。
  - 作業: クロックの解析（W7-02）、計画の表（W7-03。出力のノード）、Core と C の生成（W8、W10）。
  - 第 35 組への影響: (1a) なら境界に出力のイベントの列（大きさはフレームの数まで）が要る。(1b) なら大きさは入力のイベントの数にも依る。(3b) なら `Out` の形が変わる。(1d) なら境界は入力だけ。
  - 事例とテスト: 無い。テストベクトルの保留の節は関係しない。
- 独立のレビュー（2026-10-20、助言の担当の二段）:
  - (1a)・(t1)・(2a)・(3a) は一致した（中〜高）。出力のイベントのクロックは作り手のノードの直後に刻み、その値を読む `sample` のノードより前にある（入力のイベントの段の約束と同じ形）。
  - 第 35 組への注文: 出力のイベントの容量を「フレームの数」に固定した API にしない（受け手が容量を持つ列、CLAP の出力の列の形）。固定すると、後で (1b)（入力のイベントごとの出力）を足すときに API が変わる。

- 見直し（2026-10-21、50 回目、親。S-567 の答えに合わせ、S-565 の R8 の置き換えと S-566 の A14 の 1 を書き足した。K・P・E・H の番号は S-567 の下書きの「決まった形」の節）:
  - E8 を次の形に改める（了承を求める）:
    1. (1) は (1a) と (1b) を一つの規則にする（S-567 の E3。利用者が 50 回目に「直すので OK」とした）: `-> E at event` は、入力の `at event` と同じく決まったクロックを名指さず、本体の出力の式のクロックの刻みで出す。
       出力の式が `sample` ならその刻みごと（(1a)）、`sample / N` ならその刻みごと、入力 `m` のイベントの値なら `m` のイベントごと（(1b)、MIDI のエフェクトが書ける）。パラメータの種類だけなら本体の `sample` の刻み（S-567 の K2）。一つの刻みに一つまで、`None` は出さない。暗黙の読みは起きない。
       出力の式でイベントの値と周期のクロックの値が混ざると E0815（S-567 の K5 の 4。`if gate { Some(shift(m)) } else { None }`、`gate` は `sample`）。候補は変換の場所を `at` で留める形（閾値をイベントから取る検出器なら `thr_of(m) at sample`）。
       (1b) を新しい S の候補から外す。(1c)（一つの刻みに複数）は採らない。
    2. 型の書き方は (t1) のまま（宣言は `E`、本体は `Option[E]`）。
    3. (2) は (2a) のまま: 出力のイベントの位置は出した刻みの位置。出力のイベントのクロックの刻みは、出した刻みの直後に並ぶ（(1a) なら作り手の出力の式の評価の直後、(1b) なら作り手の入力のその刻みの直後。S-567 の E3）。
       受け手は名前の順で作り手より下にあるので、その位置の受け手の段の前に届く。呼び出しの出力のイベントのクロックは呼び出しごとに別のクロックで、入力のイベントのクロックとは比べられない（あわせて決めることのまま。(1b) の出力も、入力の刻みのうち `Some` の刻みだけなので別のクロック）。
    4. (3) は (3a) のまま（struct の出力にイベントを含めない）。
    5. 細部（S-565 の R8 の置き換え、S-566 の A14 の 1）: 同じ位置に複数の出力が出るのは、(1b) で同じ位置に入力のイベントが複数あるとき（入力の列の順）と、`.up~(N)` の部品の中の出力（内側の刻みの順）だけ。
       `.up~(N)`・`.down~(N)` の部品の中から出るイベントの位置は、その内側の刻みが属する呼び出し側の位置。細かい時刻が要るときは値に入れる。
       プログラムの中の受け手に置き場所は要らない（出した刻みの直後に受け手の段が動くので、値の欄は一つ）。境界の出力の列の大きさは、フレームの数・入力のイベントの数・`.up~` の倍率の積で決まり、決め方は第 35 組（フレームの数に固定した API にしない、独立のレビューの注文）。
  - あわせて決めること（`when~` の受け手）の改め: 止まっている刻みにイベントを出さないのは (1a) の出力だけ。(1b) の出力は、イベントの刻みの処理が止まらないので、止まっている間も出る（S-562 の B6、S-567 の P7）。止まっている間に出さないときは、送る側で絞る（S-567 の P7 の `gate` の形）。
  - 影響の直し: 第 35 組への影響は (1a) と (1b) の両方（境界の出力の列の大きさは入力のイベントの数と `.up~` の倍率にも依る）。作業は、クロックの解析（W7-02）で出力の式のクロックを決め、Core と C の生成（W8、W10）で出した刻みの直後に受け手の段を置く。
