# S-559 `reset_if` の初期化の時点

- 決定済みで戻さないもの: §11.6 の生成する `reset` の範囲（`prev` / `delay` / `vdelay` の状態、書き込み位置、サブインスタンス、poisoned を解く、`init` のクロックの値は保つ）。
- 論点: §19.1「`reset_if` は動く前に初期化し `init` のクロックの値は保つ（生成する `reset` と同じ）、止まっている間に `reset_if` が真になったときの扱い」を入れるときに決める。
  §11.6「`reset` は、`prev` / `delay` / `vdelay` の状態を `init` 値に戻し、書き込み位置を 0 にし、サブインスタンスを再帰的に `reset` し、poisoned を解く。`init` のクロックの値は保つ」。
  - (1) 初期化の時点と、初期化した刻みの出力。(2) 止まっている間に条件が真になったとき。(3) 初期化が届く範囲（入れ子のインスタンス、遅延、`par` の複製、保持の欄、poisoned）。
  - 修飾子は左の全体を包む（S-557、合成の読み。順も重ねがけも自由）。`x.when~(c).reset_if~(r)` では `reset_if~` が外側なので (2) の場面が起き、`x.reset_if~(r).when~(c)` では内側なので動く刻みにだけ初期化する（親が 2026-10-20 に、S-557 の回答に合わせて直した）。
- 今の実装: 修飾子は無い（p11 の後置の `reset_if` は E0200）。
- 案:
  - (1a) 条件が真の刻みで、その刻みに動く前に初期化する。動く刻みなら、その刻みの出力は初期状態から一歩動いた値（S-170 の文）。(1b) その刻みは動いてから初期化し、次の刻みが初期状態から始まる。
  - (2a) 止まっている刻みでも、その刻みで初期化する。保持していた出力も `T.default()` に戻す（一度も動いていない状態に戻る）。(2b) その刻みで初期化するが、保持していた出力は次に動くまで残す。
    (2c) 覚えておき、次に動く刻みの前に初期化する。実装: 一ビットの欄が要る。(2d) 捨てる（内側の `x.reset_if~(r).when~(c)` の意味）。
  - (3a) 生成する `reset` と同じ部分木（入れ子のインスタンス、遅延の値と書き込み位置、`par` の複製、保持の欄、定数でない `init` の保存先から戻す）。`init` のクロックの値と、巻き上げた `init` の値は保つ。poisoned は触らない（状態の全体の印で、§11.6 の `reset` だけが解く）。
    (3b) 受け手の直下の遅延だけを戻す。
- 他言語: Lustre V6 の例（参照の手引き v6.112.1 §1.2.4 の `COUNTER`）は、初期化を入力 `reset` で書く（`if reset then init else …`）。その刻みの出力は初期値で、刻みの中で初期化してから計算する読みと合う。
  faust-rs の覚え書きは初期化の構文を挙げていない。SCADE の `restart`、Esterel の `abort`・`suspend` は未確認。
- 推奨と理由: (1a)、(2a)、(3a)。確度: 中。
  - (1a): 「状態を初期値に戻してから動く」（S-170）のとおりで、MIDI の Start（初期化と再開が同じ刻み）が初期状態からの最初の出力を返す。(1b) は Start の刻みに古い続きの値が一つ出る。
  - (2a): 外側の `reset_if~` は止まっている刻みにも効く、という合成の読みから決まり、新しい規則を足さない。初期化の要求を捨てないので、止めている間に先頭へ戻す操作（再生位置を 0 にしてから Continue）が効く。
    保持の欄も状態の一部として戻すので、生成する `reset` と範囲が同じになる。(2b) は保持の欄だけを例外にする。(2c) は覚える欄が増え、内側に書けば (2d)、外側に書けば (2a) と、順で書き分けられる以上の利点が無い。
  - (3a): 初期化の範囲を生成する `reset` と一つにし、新しい範囲を作らない。poisoned は export の境界の印で、flow の中の条件で解くと panic の後の状態を黙って使い続ける。
  - あわせて決めること（水準か立ち上がりか）: S-170 の文のとおり、条件が真の刻みは全て初期化する（水準）。押している間ずっと真のボタンを渡すと、その間は初期状態に止まる。立ち上がりだけで初期化したいときは、`let pb = prev~(b at sample)` と取り、`b && !pb` を条件に書く
    （`&&` の右辺に状態を持つものは書けない、§11.5）。この note を §19.1 に置く。
- 影響:
  - 仕様: §19.1 の停止の項（時点、止まっている間、範囲、水準）。§11.6 の `reset` の文は変えない（範囲を指すだけ）。
  - 診断のコード: 無い。
  - 作業: flow の計画（W7-03）と Core（W8）で、修飾子の `reset_if~` を生成する `reset` と同じ部分木の初期化に落とす。C の生成（W10）は、生成する `reset` の内部の関数を、poisoned を触らない形で共有できる。
  - 事例とテスト: 無い。テストベクトルの保留の節は関係しない。
  - 第 34・35 組への影響: イベント（MIDI の Start）を条件に書く形は第 34 組で決める。(2a) は、イベントが止まっている間に来ても捨てないので、イベントの扱いを狭めない。
- 独立のレビュー（2026-10-20、助言の担当の二段）:
  - 段 1 は下書きと一致した（(1) 高、(2) 中〜高、(3) 高）。事前検討に言及は無い。
  - 足すこと: §11.6 の生成する `reset` の文に保持の欄を書き足すか、「部分木の全体」の一語で含めるかは、反映のときに決める（どちらでも意味は同じ）。
- 回答（2026-10-20、会話で利用者。47 回目）: A9〜A12（利用者が ID を挙げて了承）: (1) は (1a)、(2) は (2a)（外側の `reset_if~` の意味）、(3) は (3a)。条件は水準で読む。
  - A12 の補い（会話）: イベントを条件にすると、真になるのはイベントの刻みだけなので、水準のままで初期化はイベント一つに一回になる（第 34 組で K をイベントのクロックに広げる、S-558 (4a)）。違いが残るのは真が続く `Bool`（ゲート、ボタン、ホストのボタンのパラメータ）で、真の間は初期状態に留まる。
    note にこの場面と、立ち上がりの書き方（`let pb = prev~(start)` の後に `reset_if~(start && !pb)`。`&&` の右辺に状態を持つものは書けない、`block` の値は `prev~(start at sample)`）を書く。よく使うなら std に立ち上がりの flow を足せる。
