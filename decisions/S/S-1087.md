# S-1087 細部: 同じモジュールの、失敗した二つの `use` が同じ名前を束縛するとき（`use a.plain.Config` と `use a.with_par.Config`、どちらも E0302）に E0304 を出すか

- 空白: §15.1 は「一つのモジュールで名前は一度だけ束縛」とし、§18.1 は失敗した名前を S-462 の誤りの名前の集合に入れて使う所で黙らせる。S-675 は、解決した名前どうしの重なり（E0304・E0305）の報告する側と残す側を決めたが、二つとも解決に失敗した `use` が同じ名前を束縛するかは決めていない。
  W7-12 U1 の後、`init` の入力の無い flow の `Config` は名前空間に無い（S-112）ので、別の二つの flow の `Config` を同じモジュールで `use` すると両方が E0302 になる。今（`f74bfef`）は両方が解決し、E0304 が出る。
  読み: (1) 失敗した `use` は名前を束縛せず、二つ目も E0302 だけ、(2) 失敗した名前も束縛を占め、二つ目に E0304 も出す。どちらも誤りのプログラムで、E0304 が一つ余分に出るかだけが違う。
  仮の扱い: W7-12 U1 の実装の出す診断（事例は一つのモジュールに同じ名前の失敗した `use` を一つだけ置く）。
  急ぎ: W7 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定（2026-11-16、利用者が確認だけで了承、159 回目、第 106 組）: 空白の三つの形（二つの失敗した `use`、失敗の後の成功する `use`、失敗と同じ名前の宣言）は S-462 で決まっている（失敗した `use` は名前を占めず、E0304 の相手にしない）。今の実装はそのとおりで、仮の扱いがそのまま決定である。
  残る `Out` の有無は (b) 型の段: `Out` は `process_inplace` と同じく型で有無が決まる生成項目で、名前の段は常に作り、署名の段で出力の型（別名を下ろした後）が struct でなければ外す。取り込む `use` は型の段の E0302 で、E0304・E0310 には名前の段の束縛として数える。型の位置と経路の無い `Out` は型の段の E0302 で誤りの型として読み、E0710 より先。`In`・`Event` は入力のクロックと数で決まるので `Config`・`Params` と同じ名前の段（クロックの読めない flow と見出しの切れた flow は作る、R-471）。`Rendered` は常にある。出力が E0810 の flow の型で決まる項目は「分からない」で E0302 を出さない（今の `process_inplace` の E0810 の後の E0302 も揃える）。イベントの出力には `Out` が無い。§14.2 の `<p>_out` は `sample` の出力が struct のとき（S-30）。
  理由: 名前の段で `Out` の有無を決めると、別名と他のモジュールの `use` と自分の `Out` を辿る問い合わせが要り、S-694 で収束しなかった後に回す束縛と同じ形になる（下書きと段 1 が一致、`target/notes/159/g106/`）。
- 経緯: 157 回目、2026-11-16、W7-12 U1/t のテストの担当（onsa-test）が NEW で挙げ、親が S-675 の決定の範囲の外と読んで細部として登録した。
- 補い（2026-11-16、親）: W7-12 U1 の壊す側（157 回目）: 範囲は二つの失敗した use より広い。失敗した use の後の、同じ名前の成功する use と同じモジュールの宣言（pub struct Config）も、前は E0304、今は E0304 なし。生成されない process_inplace の use は、名前が sig の段まで残るので今も E0304 で、Config・Params と分かれる。再現 target/notes/157/w712/u1/b/c10.txt・c11.txt・c17.txt。W7-12 U2 の実装の前に読みを決める。
