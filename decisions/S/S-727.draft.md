# S-727 全て `_` の分解のパターン（`let (_, _) = p`）を `let _ = p` と同じ書き方として揃えるか（fmt の正規形、E0020、そのまま）

- 決定済みで戻さないもの: E0309 の対象・段・候補の意味（S-129・S-726。候補の置き換える文字列は例で約束でない、§18.1 の 27 行）、struct の `..` の E0020 と候補（S-109・S-366）、列挙子のパターンは要素の数を書くこと。
  第 68 組の下書きの「S-727 の仕組みの出所」と「S-727 の形の表」の節（写しは `target/notes/78/g68/draft.md`）。
- 論点: 全ての要素を `_` にした分解（`let (_, _) = p`、`let P { x: _, y: _ } = q`、`Some((_, _))`）と全体の `_` を、P2 の「同じことの二つの書き方」として揃えるか（fmt の正規形、E0020、そのまま）が、§5.1・§7・`spec/tools.md` に書かれていない。
  E0309 の候補を当て続けると `let (a, b) = p` は `let (_, _) = p` で止まる。候補の約束（§18.1）はこれで満たす。
  上の表のとおり、二つは値の形の確かめが違い、型の誤りのある所では判定が違う。同じ判定になるのは、値の型が分解の形に合う所だけである。
- 今の実装: 表のとおり。全て `_` の分解は通り、fmt は変えない（`probe/s727/fmt/a.onsa`）。
- 案: 
  - (a) 両方を書けるままにし、fmt も畳まない。全て `_` の分解は値の形を確かめるパターンで、`_` と同じプログラムではないと読む（仕様に書くなら §7 に一句）。
    P2 の二つ目の項（受理し、fmt は揃えず、仕様の例と std は書かない）に並べる形もある。その場合は §11 の `let (_, _) = g~(x)` の例を改める。
  - (b) fmt が全て `_` の分解を `_` に畳む（`spec/tools.md` §3.3 の一覧に一行）。
    fmt は型を読まないので、`x: I32` の `let (_, _) = x`（E0401「expected a tuple pattern target」）を `let _ = x`（通る）に変え、§3.3 の「判定を変えない」に反する（親が直した: 下書きは `let (_, _) = 5` を E0401 と書いたが、それは E0420。親の再現 `g68/parent/b.onsa`）。
    採るには fmt の約束を改める必要がある。
  - (c) E0020 にし、候補は `_`（`spec/foreign-forms.toml` に行を足す）。候補が型の誤りを黙らせないよう、パターンの型を確かめた後（型の段）で報告する。
    E0309 の候補と struct の `..` の E0020 の候補は、当てた後に全て `_` の分解を残すと §18.1 の候補の約束（同じ段か前の段の診断を残さない）に反するので、その形では全体を `_` にする特別の扱いが要る。
  - あわせて (e) E0309 の候補が分解の最後の名前を `_` にするとき: (e1) 名前を `_` に変えるだけ（今の実装。止まる形は `let (_, _) = p`）。(e2) 全て `_` になる一番小さい分解を、全体の `_` に置き換える（止まる形は `let _ = p`。入れ子の `((_, _), c)` は `(_, c)`）。
  - 書き手から見て: 書き手がわざと全て `_` の分解を書くのは、腕の並びで形を揃えたいとき（`Pair { a: x, b: 0 } | … =>` の後の `Pair { a: _, b: _ } => 0`）や、値の形を確かめたいときである。多くは E0309 の候補の結果として現れる。
    (a) と (e1) は、その形で止まり、書き手の検査は増えない。(c) は、書いた形が誤りになり、(e2) が無ければ E0309 の後にもう一回の検査が要る。
  - 修正候補を当て続けて止まるか: (a)・(e1) は今のとおり `clean` で止まる。(e2) も `clean`（一回少ない書き換え）。(c) は E0309 と `..` の候補に特別の扱いを足せば止まり、足さなければ候補の約束に反する。
  - 通るプログラム: (a)・(e) は変わらない。(c) は全て `_` の分解を書いたプログラム（§11 の例、`pattern_choice_bindings_same.onsa` などの腕）が誤りになる。(b) は誤りのあるファイルの判定を変える。
  - 規則と例外: (a) は規則を足さない（P2 の項に並べるなら一句）が、型の合うプログラムでは同じ効果の二つの書き方（`let (_, _) = p` と `let _ = p`）が残り、書き手（LLM を含む）がどちらを書くかで書き方が揺れ、fmt も揃えない（P2 の「一つの書き方」に照らした費用。親が足した）。(b) は fmt の約束の例外を一つ。
    (c) は E0020 の行を一つと、候補の特別の扱いを二つ（E0309、`..`）。(e2) は E0309 の候補の形の一文（約束でない細部）。
  - 実装の量: (a)・(e1) は 0 行。(e2) は `names/body/scope.rs::unused` の候補で、束縛の位置からパターンの木を上って全て `_` かを見る（約 +10〜15 行）。
    (c) は型の段のパターンの検査で全て `_` の分解を見つける（約 +15〜25 行）、行と note、E0309 と `..` の候補の特別の扱い（約 +15〜20 行）、事例の直し。flow の本体の `let (_, _)`（§11 の名前の付け方と、W7-04 の到達の根に数えるか）にも同じ判定が要る。
    第 2 期にパターンの形（`Map`、配列のパターンなど）が増えるたびに、(c) は全て `_` の形を決め、(e2) は畳む形を決める。(a)・(e1) は手当てが無い。
