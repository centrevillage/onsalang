# S-855 `add_from!` の要素の型の要求（今は `[Bool; 2]`・`[[F32; 2]; 2]` の `add_from!` が検査を通り、`onsa test` で内部エラー）

- 空白: §5.3 は `Span[T]`（`[T; N]`・`Buf[T]` も同じ）のメソッドに `add_from!(other)` を挙げるが、要素の型に何を求めるかを書いていない。`1bb94a0` では、`[Bool; 2]` と `[[F32; 2]; 2]` の `xs.add_from!(ys)` は `check` を通る。
  そして、`onsa test` で内部エラー（`arithmetic on Bool`、`onsa_interp/src/numeric.rs`、R-350）になる。
  読み: (a) 要素は `AnyNum`（全ての数）。(b) 要素は `Num`。(c) 要素の型の `Add` を求める。S-853（族の規則）が `add_from!` の要素に Copy を求めるかと合わせて決める。急ぎ: W5-02 で列のメソッドを std に宣言する前。
- 決定: 決定（2026-11-03、利用者が ID を挙げて了承。105 回目、第 78 組。下書きと独立のレビュー（段 1）が一致）: (a)。`add_from!` の要素は `AnyNum`（符号なしを含む全ての数）に限り、満たさなければ呼び出しの位置の E0416、候補なし。`[T; N]`・`Buf[T]`・`Span[T]` の全ての受け手に当たる。
  理由: `add_from!` は数の列を `+` で混ぜる操作で、負の値を前提にしないので §6.3 の「符号なしも受けるときは `AnyNum`」が当たる。`Num` は符号なしの配列（カウンタの合算）を利益なく失い、`Add` との差は第 2 期まで現れない（後で緩めても壊れない）。
  細部: この版は `T: AnyNum` の境界を E0200 にするので、境界の対応が要る（W5-05 の数の trait（R-94）、W5-07 の `min`・`max`（R-354）と共用。置き場所は W5-02 の設計メモで決める）。仕様 §5.3 の 103 行、`tasks/diag-codes.md`。R-350 はこれで直る。
