# S-588 `@host` と `@latency` の場所と値の誤り: `block` でない入力の `@host`、同じ種類を二つの入力に付けること、`@latency(e)` の `e` の型と値の条件

- 空白: §11.7 は `@host(<種類>)` を `block` の入力に付けるとし、種類の誤りは E0005、型の違いと `@param` との重なりは E0809 とした。§11.6 は `@latency(e)` の `e` を `init` のクロックの式とし、`block` のクロックの式は E0815 とした。
  書いていないこと: 1. `@host` を `sample`・`init`・イベントの入力に付けたときの誤り。2. 同じ種類の `@host` を二つの入力に付けたとき。3. `@latency(e)` の `e` の型（`U32` か）と値の条件、子の flow に付けたときの扱い（子の宣言は合成しない）。4. `@latency` を付けられる場所の誤り（E0005 か）。
- 決定: 決定（2026-10-24、利用者が了承。60 回目、第 50 組）: 誤りの段は S-632 の族の規則で `onsa check`。
  1. `block` でない入力（`sample`・`init`・イベント）の `@host` は E0809（A1）。2. 同じ種類の `@host` を二つの入力に付けると、二つ目の入力で E0809（note で一つ目を指す。(d1)、A2）。4 と子の flow の `@latency` は決定済みのまま（§6.5 の E0005、S-576 の合成しない。A3）。
  3. `@latency` の値の持ち方は (L3): 属性は計算のための定数の情報だけを持ち、計算はターゲットの段が行う。項は `samples`（`U32`）と `seconds`（`F32`）で、どちらもコンパイル時の定数（(k1)。`@param` の値と同じ評価）。
     報告する値は `samples +| (seconds * sample_rate).trunc_u32_sat()`（`F32` で掛け、ゼロ方向に切り捨て（(r1)）、`U32` に飽和）で、§11.6 にこの式を書き、どの後端もこの式とビットで同じ値を出す（A6）。`cfg` に依る遅れは書けない（(g1)）。
  遅れの値の隠れた欄（§12.4）は、C の `_init` が本体の `init` の後に書き、Onsa の `init`（インタプリタと `onsa test`）は触れない（A7）。負・NaN・無限大の `seconds` と項の無い `@latency()` は E0809（A8）。
  E0815（`block` のクロックの式）は `@latency` に当たらない（A9）。`onsa interface` は `@latency(samples: 32, seconds: 0.005)` のように書いたとおりに出す（A10）。
  理由（下書きと段 2）: 属性の計算と panic がコンパイラの出力に入らず、S-632 の (ii) と同じ線に立つ。サンプルレートに比例する先読みは書け、`Config` を持つ flow はプラグインにできない（S-583）のでラッパーの報告には足りる。`cfg` に依る項は、後で項の種類として足しても既存の `@latency` を壊さない。
  付録の `g.Params` の E0302 は R-50、`params_default()` の E0401 の文面は R-147（A5）。仕様 §11.6、§11.7、§6.5、§12.4
- 経緯: 53 回目（2026-10-23）の文書の点検の後半の 6 から。関係: S-575、S-576、§6.5。
  60 回目（2026-10-24）、第 50 組（族の規則は S-632、下書き `S-588.draft.md`、助言の担当の二段）。値の持ち方の (L1)〜(L3) は、利用者の「レイテンシーの計算をアノテーション内でやるのか、それとも計算するための情報だけを持ち、実際の計算はトランスパイラやランタイムがやるのか」から下書きに足した。
  段 2 は (L3) を直して採った（`seconds` と計算を `F32` に、式を仕様に、隠れた欄は `_init`）。利用者が B3 を了承した（「推奨案の通りで良いです。(L3, cfgによる遅れは未対応、切り捨て、F32で持つ)」）。確認だけの項目 A1〜A3・A5（「A1-5: OK」）と A6〜A10（「A6-10: OKです」）を了承した。
  A6 の式の `trunc_u32_sat()` は、段 2 の字の `trunc_u32()`（範囲外で panic）を飽和に合わせて親が直した。
