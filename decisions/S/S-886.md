# S-886 値を返す関数の行末の `return` の次の行の式（`return` 改行 `x * 2`）は、検査の順のままだと `return` の E0401 が先で、§7 の E0503 とつないだ候補に届かない

- 空白: §7 は「修正候補は到達しない文を消す形で、行末の `return` の次の行に式があるときは、つないだ形（`return x * 2`）も並べる」とする。
  `fn f(x: I32) -> I32 {` 改行 `return` 改行 `x * 2` 改行 `}` は、文の順の検査で `return` が先に検査され、値の無い `return` と返り値の型の不一致の E0401 になる（`Return(None)`。`tests/review-phase1/parent/c120.onsa` の注も同じ）。`()` を返す関数では `return x * 2` につなぐと E0401 になりうる。
  読み: (1) 次の項目が式なら E0401 より先に E0503 を出す、(2) `return` の E0401 のままで候補なし。§7 が書くのがどの関数の形かを書いていない。通るプログラムはどちらでも変わらない。W5-08 U3 の事例の `fixes` の数が待つ
- 決定: 決定（2026-11-04、利用者。113 回目、第 84 組。設計メモは (1)、独立のレビューの段 1・段 2 は (3)。利用者「(3)で。」）: (3)。値を返す関数の値の無い `return` は検査の順のまま E0401 で、次の項目が同じブロックの最後の項目で、式の文か最後の式で、返り値の型に合うときだけ、E0401 につないだ形の候補を付ける。
  条件に合わなくても note で `return` は行末で終わること（§2.5）を示す。候補は一つの編集で、残りの項目を消す編集は入れない。試しは式の検査と `check_deferred_now`（型が合わない形とリテラルの範囲の E0408 を落とす）で、S-876 の探りは要らない（文を消さない）。`()` の関数は次の行の E0503 に同じ条件でつないだ形を並べる。
  作業は W5-08。仕様 §7、`tasks/diag-codes.md` の E0401。
