# S-1036 `_` で捨てた部分と取り出しの残りを、panic で抜ける道で破棄に数えるか（`Err2(_) => panic(…)`、`let x = move p.a` の後の `panic(…)`）

- 空白: §5.2 は取り出したフィールド以外を「その場で破棄」し、意味は分解の `let Holder { buf: b, gain: _ } = move s` と同じとする。§9.2・S-873 は panic で抜ける道の生きている値の破棄を `Alloc` に数えず、std の `unwrap` の本体の `Err(_) => panic(…)` は捨てる `E` の破棄の `Alloc` を要しないとする。仕様は `_` で捨てた部分がいつ破棄されるか（パターンを当てた時か、腕・束縛の有効範囲の終わりか）を書かない。
  今（`702a4619`。`_` を数えない R-32・R-390）: `rt` の関数の `match move r { R2.Ok2(x) => x, R2.Err2(_) => panic("x") }`（`Buf` のペイロード）は通る。`let x = move p.a` の後の `panic("x")` は E0901。`{ let x = pass(move b) }` の後の `panic("x")` は E0601。入力は `target/notes/146/w602/memo/probe/` の `b.txt`・`c.txt`・`f.txt`。
  読み（W6-02 の設計メモ）: (1) `_` の部分は有効範囲の終わりまで生き、取り出しの残りはその場で破棄 (2) 先の全ての道が panic で終わる破棄点は数えない (3) 全てその場で破棄し、std の `unwrap` だけを例外にする。中立の要約は (4)（`_` も取り出しの残りも有効範囲の終わり）を足した。
  急ぎ: W6-02 の `_` の破棄点の単位（U6）の前。
