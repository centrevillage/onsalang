# S-742 flow のインスタンスの循環（E0817）の報告: 循環ごとに一つで宣言の名前に付けるか（S-730 と同じ）、インスタンスを書いた位置に付けるか

- 決定済みで戻さないもの: 型の循環（S-730。`flow g(x: h.Params …)` の生成項目を通る循環は型の E0311、R-02 の補い）。インスタンスの循環を誤りにすること（§11.5、R-03）。
  第 70 組の下書きの「S-734 の仕組みの出所」と「S-734 の形の表」の節（写しは `target/notes/79/g70/draft.md`）。
- 論点: §11.5（174 行）「flow が自分自身を、直接または他の flow を経由してインスタンスにすると E0817（状態の大きさが決まらない）」は、循環の中のどの flow のどの位置に、いくつ報告するかを書いていない。
  flow の状態は、本体が作るインスタンスの状態を中に持つので、この循環は S-730 の「型が自分自身を値として含む」と同じ形である。ただし依存を作るのは宣言でなく、本体の中のインスタンスの式（`fb~(x)`）である。
- 今の実装: E0817 は未実装で、自分を指す `fs~(x)` も、相互の `fa`（本体が `fb~(x)`）・`fb`（本体が `fa~(x)`）も `check` を通る（`probe/s734/flow_mutual.onsa`）。
  降下（`onsa_core/src/lower/flow/mod.rs` の 212 行、`ensure_flow`）は、下ろし中の flow に戻ると E0200「a flow that instantiates itself」（`Feature::FlowSelfInstance`）を flow の宣言（`def.span`）に出す（コードを読んだだけで、降下の命令には渡していない）。
  事例 `tests/spec/flow_semantics/rules_negative.onsa` は、自分を指す三つの形（238 行の本体、242 行の `par` の中、247 行の `if~` の枝）の `//~ E0817` をインスタンスの行に置く（頭のコメントは「印は誤りの構文の行」。`tests/pending.toml` で W7-07 待ち）。
- 案: 
  - (1) 循環（flow のインスタンスの強連結成分。自分を指す一つの flow を含む）ごとに一つで、診断の並べ方で最初の flow の宣言の名前に付ける（S-730 と同じ）。循環を作るインスタンスの位置を note で示す。
  - (2) 循環ごとに一つで、循環を作るインスタンスの式のうち診断の並べ方で最初のものに付ける。他のインスタンスの位置を note で示す（E0310 を依存を作る `use` に付けるのと同じ形）。
  - (3) 循環を作るインスタンスごとに付ける（循環の各 flow の単位に一つ。単位の中は §18.1 で最初の一つ）。
  - S-734 との組み合わせ: (1) と (2) は S-734 の (a)（循環ごとに一つ）に揃う。(1) は E0311・E0312 と同じ「宣言の名前」、(2) は E0310 と同じ「依存を作る所」で、(a) の一般の文の「最初の宣言」に、依存がインスタンスの式である場合の句が一つ要る。(3) は S-734 の (b) に揃い、循環ごとに一つと決まった S-730 の型の循環とは食い違う。
  - 形ごとの出力: 相互の `fa`・`fb` は、(1) が `fa` の名前に一つ、(2) が `fa` の本体の `fb~(x)` に一つ、(3) が `fb~(x)` と `fa~(x)` に一つずつ。どれも単位は同じファイルなら `fa` である。
    事例の 238・242・247 行は、(2)・(3) では変わらない。(1) では印が宣言の行（237・241・245 行）に移る。
  - 書き手から見て: 直すのは、循環のどこか一つのインスタンスを外すことである。(2) は直す所を位置で示す。(1) は宣言を示し、直す所は note の位置で示す。(3) は循環の全てのインスタンスを並べ、書き手（とくに全ての診断を直す LLM）が全てを外しうる。
    一つの本体に自分のインスタンスが二つあると、(2)・(3) は一つ目だけを報告し、(1)・(2) の note が全てを示さなければ、直した後にもう一回の検査が要る。
  - 修正候補: どの案も候補は無い（どこで切るかは書き手しか知らない）。当て続けても `no-candidate` で止まる。
  - 通るプログラム: どの案も変わらない（E0817 はどの案でも W4-05 で新しく出る）。変わるのは位置・数・note だけである。
  - 規則と例外: (1) は S-730 の文（S-734 が (a) なら一か所に書く規則）をそのまま当て、文を足さない。(2) は「依存がインスタンスの式なら、その式に付ける」の句を一つ足す。(3) は循環の規則の例外として「E0817 はインスタンスごと」を足す。
  - 実装の量（W4-05 の U4、R-03）: どの案も、flow の本体の名前の記録（`~` の呼び先の flow）から flow のインスタンスのグラフを作り、`cycles.rs::components` で成分を求める。ここまでは共通で、R-02 の型の循環と同じ所にある。
    (1) は成分ごとに最初の flow を選び、インスタンスの位置を note に並べる（約 +5〜10 行）。(2) は辺ごとにインスタンスの式の位置を持ち、最初のものを選ぶ（約 +5〜10 行）。(3) は辺ごとに出す（約 +3 行）。差は小さい。
    どの案でも、検査を通った単位だけを降下するので、降下の E0200（`FlowSelfInstance`）には届かなくなる。W4-05 の持ち越しのとおり、E0200 の表から `FlowSelfInstance` を外し、`ensure_flow` の守りは内部エラーにする（案によらない）。
    第 2 期に flow を値や型引数で選べるようになると、インスタンスの辺は型で決まりうるが、どの案も辺の作り方の問題で、位置の選び方は変わらない。
