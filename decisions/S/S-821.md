# S-821 署名と flow の見出しの他の型の定数式（struct のフィールド、`type` の右辺、enum の要素、`impl` の見出し、`const` の型）の flow の呼び出し（`[F32; lp~(1.0)]`）のコード

- 空白: §11.1 の 18〜19 行は、flow の呼び出しなどの flow だけの構文を「flow の本体にだけ書ける」とし、21 行は「flow の外（fn の本体、`test`、`const` の初期化式）に…を書くと E0821」と例を挙げる。W4-12 の設計（A8、利用者が了承）は、署名と flow の見出しの型の定数式（`fn f(x: [F32; lp~(1.0)])`、`-> [F32; lp~(1.0)] at sample`）も E0821 とした。
  署名でない型の定数式（struct のフィールドの `[F32; lp~(1.0)]`、`type T = [F32; lp(1.0)]`、enum の列挙子の要素、`impl` の見出しの型引数、`const` の型）は、21 行の例に無い。
  W4-12 U3 の実装は、定数式の読み手が一つなので、これらも E0821 にした（前は E0417、`impl G[lp~(1)]` は E0307）。誤りのプログラムの報告するコードが変わるだけで、通るプログラムは変わらない。
  親の読み: 18〜19 行の「flow の本体にだけ書ける」から、flow の本体の外は全て E0821 で、21 行の括弧は例（今の実装のまま）。flow の本体の中の型の定数式（`let a: [F32; lp~(1.0)]`）は flow の本体なので今の E0417 のまま。
  再現: 94 回目の scratchpad の `w412u3/parent/gaps.onsa` の `Z`・`T`、`w412u3/b/c5.txt`・`c14.txt`（写しは区切りで `target/notes/94/w412u3/`）。
- 決定: 決定（2026-10-31、利用者が ID を挙げて了承。確認だけ。94 回目）: 親の読み。§11.1 の「flow の本体にだけ書ける」から、flow の本体の外の型の定数式（署名、flow の見出し、struct のフィールド、`type` の右辺、enum の要素、`impl` の見出し、`const` の型）の flow だけの構文は全て E0821。
  flow の本体の中の型の定数式（`let a: [F32; lp~(1.0)]`）は今の E0417 のまま。W4-12 の U3 の実装がこの形。仕様 §11.1
- 経緯: 94 回目（2026-10-31）、W4-12 U3/b（onsa-break）が空白の候補として報告し、親が §11.1 の 18〜19 行から読みが一つに決まると見て、確認だけの S として登録した。関係: S-267、S-815。
