# S-1207 上りを下りが包む連鎖（`x.up~(M).down~(N)`）の時間: 境界で集めて配る（§11.9・S-566 の A10）か、連鎖のレート一つ（§11.10、今の検査と参照評価器）か

- 空白: §11.9 は「`x.up~(M).down~(N)` も、中の部品の入出力を境界で集めて配る形で読む」とし、S-566 の A10 は「`x.up~(2).down~(2)` は 2 サンプルの塊で処理し、x と同じで 2 サンプル遅れる（音声の入力の無い `osc~(f).up~(2).down~(2)` は遅れず `osc~(f)` と同じ）」とする。一方 §11.10 は「x は、連鎖のレート R（…連鎖の `.down~`・`.up~` を当てたもの）の刻みのうち…動く」「`x.when~(c).down~(4)` と `x.down~(4).when~(c)` は同じ意味」と、連鎖を一つのレートに畳んで書く。M ≠ N の集め方と配り方は字に無い。
  今の実装（W7-09）は連鎖のレート一つ: 検査は `Char` の `sample` の入力を `id~(v).up~(2).down~(2)` に渡す形を通し（`.down~(2)` で集める変換の flow なら E0816）、参照評価器は連鎖を比の和一つにし（`crates/onsa_tests/src/flow_ref/rate.rs` の `chain_of`・`gathers`）、事例 `tests/spec/flow_clock/e0816_conversion_flow_gather_deal.onsa` は「a chain of the ratio one」を `Default` の要らない形とする。W7-16 の設計メモ（4.3）も比の和で降ろす。
  読み: (i) 字のとおり境界で集めて配る（入力のある部品は N サンプル遅れ、集める型と配る型に `Default` が要る。M ≠ N と `when~`・`reset_if~` を交ぜた形の規則を足す）、(ii) 連鎖のレート一つ（遅れない。§11.9 の一句と A10 の一文を改める）。通るプログラム（E0816）と値（遅れ）が変わる。
  仮の扱い: 今の実装（(ii) の形）のまま。W7-16 の `.up~`・連鎖の単位（U6b）の前に決める。
- 決定: 決定（2026-11-22、利用者。175 回目）: (i) 塊の読み。§11.9 と S-566 の A10 のとおり、`.down~(N)` は中の部品（`.up~` を含む連鎖も）を一つの部品として包み、その入出力を境界で集めて配る（`x.up~(2).down~(2)` は 2 サンプルの塊で処理し、入力のある部品は 2 サンプル遅れ、集める型と配る型に `Default` が要る）。仕様の字は今のまま。
  理由（利用者）: 「そうでないと、up / down が独立した flow modulator として解釈できなくなります。レートをまとめてしまうということは up / down に対する特別扱いを行なっていることになり、flow modulator としての共通の機構に載せられなくなります。」
  合成から決まる読み（親の読み、利用者が了承「1&2: OK」）: 各修飾子は左の全体を一つの部品として包む（§11.10「各修飾子は左の全体を包む（合成）」）ので、1. M ≠ N も同じ規則で決まる（`x.up~(2).down~(4)` は、`.down~(4)` の境界から見て中の部品の入出力が呼び出し側の `sample / 2` の流れで、`sample` の入力は今と同じ E0815、`sample / 2` の値は集めて配る）。2. 遅れは境界ごとに足される（`x.up~(4).down~(4)` は 4 サンプル、`x.up~(4).down~(2).down~(2)` は外の境界の 2 と内の境界の 2 刻み（呼び出し側の 4 サンプル）で 6 サンプル。比が同じでも包み方で遅れが変わる）。`when~`・`reset_if~` を連鎖に交ぜた形も同じ合成で読む（W7-10）。
  実装: W7-09 が作った検査（上りを下りが包む連鎖の集める型・配る型の E0816）・参照評価器（連鎖を比の和一つでなく境界の列に）・事例（`tests/spec/flow_clock/e0816_conversion_flow_gather_deal.onsa` の比が 1 の連鎖、`crates/onsa_tests/src/flow_ref/multirate_tests.rs` の注）を改め、W7-16 の降下が境界ごとに集めて配る。
- 経緯: 175 回目（2026-11-22）、第 116 組（S-1089）の下書き（onsa-gap）が新しい S の候補 NEW-1 に挙げ、親が `Char` の入力で再現し（`target/notes/175/g116/` に写す）、段 1（onsa-advisor）が字と実装の食い違いを確かめた。親が登録した。
