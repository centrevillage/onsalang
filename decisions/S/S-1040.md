# S-1040 要素が Copy でない `[T; N]` の `fill!`（`pub rt fn fill(inout self, v: T)`）が要素を上書きで破棄する形と、std の宣言（`rt` で `Alloc` が無い）

- 空白: std の `impl[T, const N: U32] [T; N]` の `pub rt fn fill(inout self, v: T) { for i in 0 ..< N { self[i] = v } }`（`std/core/seq.onsa`）は、S-853 の決定で要素が Dup のとき持つ（Shared の `fill!` を残す）。R-32 の上書きの破棄と総称の `T` の破棄（W6-02）を数えると、要素が Copy でない `T`（Shared）では `self[i] = v` が前の要素を破棄するので、`rt` で `Alloc` の無い本体が E0901 になる（推論）。
  今（`702a4619`）: `rt fn f(inout xs: [Str; 2], s: Str) { xs.fill!(s) }` と総称の同じ形が通る（`target/notes/146/w602/review/r2.txt` の `fill_str_rt`・`fill_generic_rt`）。`tests/spec` の `fill!(` は約 70 ファイル・210 か所。
  読みの候補: (1) `fill` を `T: Copy` に絞る（S-853 の「Dup のとき」を改める） (2) `rt` を外して `uses {Alloc}` にする (3) Copy と Dup の二つの宣言に分ける（`rt` の版は Copy だけ） (4) 上書きの破棄を `fill` の本体だけ数えない例外。同じ形の総称の `swap[T]`・`W[T].set` の事例（`tests/spec/effects/fn_compat_*.onsa`）も同じ問いに当たる。
  急ぎ: W6-02 の上書きの単位（U5）と総称の `T` の単位の前。S-1038（`inout` への代入の破棄）と組になる。
