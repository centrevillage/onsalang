# S-415 struct / enum の宣言の本体の `{` の前の改行

- 空白: struct / enum の宣言の本体の `{` を次の行に書く形（`pub struct P` 改行 `{`、`pub enum E` 改行 `{`）。
  §2.5 は「ブロックの `{` は、それを持つ宣言や見出し（`fn`、`flow`、`impl`、`if`、`while`、`for`、`match`、`par` など）の最後のトークンと同じ行に書く…違反は E0003」とし、struct / enum の本体（並びとして改行を空白として扱う）がこの「ブロックの `{`」に入るかを書かない。読みは (1) 入る。
  E0003 で、候補は `{` を前の行へ移す形（S-216）、(2) 入らない。今のまま E0002「expected `{`, found newline」（候補なし）。今は (2) の形（1:13、6:11）。S-413（括弧の中の構造体リテラルの `{`）と同じ「`{` の置き場所の規則が挙げない位置」の問題。W3-06/t1 で見つけた（2026-10-10）
- 提案: 決定（2026-10-10、利用者が ID を挙げて推奨の (a) を了承。下書きと Fable が一致、第 22 組）: struct / enum の本体の `{` も宣言の本体の `{` として E0003（主の位置は `{`、候補は `{` を見出しの最後のトークン（名前、型パラメータの `]`、derive の最後の trait の名前）の行の末尾へ移す形）。
  trait・effect・handler・extern・test の本体も同じ。S-413 と一つの規則（「`{` は、それが属する形の最後のトークンと同じ行」）。仕様 §2.5。実装は W3-06 の単位 2（`parse_body()`）
