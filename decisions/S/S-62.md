# S-62

- 空白: 数値リテラルの修正候補が値や種類を変える（`0o17` → `0`、`1f32` → `1`、`0x1F_u8` → `0x1F_`）。`123abc` を接尾辞として扱い、`0x_` を桁あふれと報告し、`1.e3` を `1` のフィールドと読む。綴りの揺れを fmt が揃えない（レビュー R-73）
- 提案: 字句解析: 大文字の接頭辞（`0X` `0B`）と指数（`E`）を受理する。`_` は数字の間以外にあっても受理する。`0o` は E0020（候補は 10 進）。`<数字>.e<数字>` は E0020（候補 `1.0e3`）。
  接尾辞は閉じた一覧で認識して E0020（候補は接尾辞と前の `_` を除いた形、整数の形に浮動小数の接尾辞なら `.0` を足す）、一覧に無いものは E0001。接頭辞の後の数字の数え方から `_` を除き、`0x_` は E0001。fmt: 接頭辞と指数は小文字、16 進の数字は大文字、`_` は数字の間に一つずつ、浮動小数の整数部の余分な 0 を外す。
  S-56 の比較は数値リテラルを値で比べる。`tests/review-phase1/parent/r73.onsa` の期待値は各関数の上のコメント（2026-10-04 決定。実装は第 2 段）
