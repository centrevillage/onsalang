# S-1118 借用の位置の末尾に、その腕・ブロックの中で作った破棄の要らない束縛（静的な値か破棄の要らないリテラルで初期化した束縛）の部分ビューや束縛そのもの（`take(if c { let t = [1.0, 2.0, 3.0, 4.0] … t.slice(0, 2) } else { … })`）を置く形を、E0716 にするか、通すか

- 空白: S-1115 は、借用の位置の末尾に、その腕・ブロックの中で宣言した束縛を根とする部分ビューと、そういう Copy でない束縛の場所を置けない（E0716）とした。理由は「束縛はその腕・ブロックの終わりで破棄され、呼び出しと見出しはその後に読む」。
  破棄の要らない束縛（§5.4。静的な値か破棄の要らないリテラルで初期化した借用束縛、`let t = [1.0, 2.0, 3.0, 4.0]`、`let nm = "gain"`、`let p = ("gain", v)`）を腕・ブロックの中で作り、その部分ビューか束縛そのものを末尾に置く形に、S-1115 が当たるかを書いていない。
  形: `take(if c { let t = [1.0, 2.0, 3.0, 4.0] … t.slice(0, 2) } else { y.slice(0, 2) })`、`hs(if c { let t = "abc" … t } else { s })`（`hs(a: Str)`）。今はどちらも `check` を通る。前の形の降下は `t` を腕の中のローカルな配列にし、生成した C ではブロックの外でビューを読む（未定義の動作）。`Str` の形はこの版の降下が E0200。
  既決との関係（161 回目、利用者の求めで親が確かめた）:
  - S-610: 静的な値だけの集成体のリテラルも静的な値で借用の行。置き場所（静的領域か、使う所で組むか）は約束しない（§5.4）。
  - S-613: 破棄の要らないリテラルは「派生元は無く」「値は使う所で組む」。補い L4: 破棄の要らない束縛の名前は「その場にリテラルを書いたのと同じ」で、どの文脈でも解放は起きない。理由は「リテラルを `let` に置くだけで E0601 になる表面の違いを残さない」。
  - S-1065: 破棄の要らない値は置く位置によらず数え、「派生元を持たず、文脈に依らないので健全」。理由は「`let` を一つ挟むかの書き方だけで E0601 の有無が変わる」のを無くすため。
  - §12.8: 補間の無い `Str` の文字列リテラルは不滅の静的オブジェクト。
  - `let` を挟まない形（`take(if c { [1.0, 2.0, 3.0, 4.0].slice(0, 2) } else { … })`）は通り、降下は腕の中の一時 `__arr` のビューを腕の外で読む。これは R-481 の族（腕の中の一時、W7-12 U2c2 で記憶域を呼び出しの文の高さに置く。入るまでは E0200）で、言語は認める形である（`target/notes/161/w712/u2c/t2/literal_view_direct/`）。
  読み: (1) E0716（腕・ブロックの中で宣言した束縛は、破棄の要らない束縛も根とする）。S-1115 の字には沿うが、`let` を挟んだ形だけが E0716 になり、挟まない形は通る。S-613 の L4 と S-1065 が無くした「`let` を挟むかの書き方だけで結果が変わる」違いを、新しく作る。`let t = "abc"` の `Str`（不滅のオブジェクト）も E0716 になる。
  (2) 通す。破棄の要らない束縛は S-1115 の外である（破棄されないので S-1115 の理由が当たらず、名前は「その場にリテラルを書いたのと同じ」）。そのビューの記憶域は、`let` を挟まない形と同じく降下が保つ（R-481 と同じ仕組みで呼び出しの文の高さに置く。静的な値は静的領域に置いてもよい、置き場所は約束しない S-610 のまま）。入るまでは R-481 と同じく E0200。
