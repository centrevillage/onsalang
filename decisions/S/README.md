# 空白（S）

仕様 0.3 が決めていない小さな項目と、その決定。
作業の中で見つけた担当が報告し、親が登録する。決めなくても着手できるが、該当する作業の前に、仕様の空白の流れ（`rules/process.md`）で利用者が決める。

- 一覧は `python3 -B tools/docs.py list S`。期限の作業の前に決める未決の S は `list S --status OPEN --before <作業>`。
- 登録するときは、決定を要る作業を頭の欄の `before` に、見つけた票を `found_by` に書く。
- 空白の下書きは `S-<番号>.draft.md`（頭の欄は `group` と `drafted`）。状態は持たず、道具と gate は正本と見ない。

## 本文のラベル

`docs.py new S` は、この節のラベルを新しい S の雛形にする。

- `空白`: 仕様が決めていないこと（論点）。
- `決定`: 決めたこと。
- `経緯`: 日付、誰が了承したか、下書きと独立のレビューの一致、改めた範囲。

決めた後の補いは、`docs.py note <ID> 補い <文> --by <誰>` で `補い（<日付>、<誰>）` の箇条として足す。

## 表から移した S

S-01〜S-551 は、計画 §2 の表の行から移した。セルを切らず、表の欄の名をラベルにした。本文のラベルは次の四つで、`空白` の他は移した S だけにある。

- `空白`: 表の「項目」の欄。
- `提案`: 表の「提案」の欄。決めた S では、決定の文と経緯もここにある。
- `時期`: 表の「決める時期」の欄。
- `元の下書き`: 空白の資料（`spec-gaps-*.md`）の、その S の見出し。詳しい検討（論点、今の実装、案、他言語、推奨）はそこにある。

`提案` の「実装は第 N 段」「第 N 段」は、レビュー §7 の旧い段の番号である。今の担う作業は頭の欄の `tasks`。

頭の欄は表の行から道具で埋めた。
`status` は表の ✅ の印から（印の無い決定 8 件は親が直した）、`decided` は行の最後の決定の日付から（S-172 までで日付の無いものは計画の頭の文の 2026-10-02）。
`tasks` は作業の表の「実現する決定」の欄の逆引き、`group` は空白の資料の組の見出しから。
