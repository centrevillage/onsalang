# S-584 プラグインに出すパラメータの `scale` と範囲の変更を、ポリシーの凍結（§15.4）で止めるか

- 空白: §15.4 のポリシーの `[interface] frozen` は、公開シグネチャとパラメータ ID の変更を E0630 にする。一方、VST3 はパラメータの値を 0〜1 に正規化した値で保存し（S-581、第 36 組）、正規化は `@param` の `min`・`max` と `scale` で決まる。
  このため、ID を変えずに `min`・`max`・`step`・`scale` を変えると、ホストが保存した自動化とプロジェクトの値が別の値として読まれ、音が変わる。
  CLAP はホストに値そのものの保存を勧め（`ext/params.h`「store plain values in the document (automation)」）、AU の値は単位のままの `float` なので、範囲の変更で値の意味は変わらないが、範囲の外に出た値は格子と範囲に寄せられる（S-581 の (q1)）。決めること:
  1. 凍結の対象に `min`・`max`・`step`・`scale` の変更を入れるか。
  2. 形式で分けるか（CLAP と AU では範囲を広げても保存した値の意味は変わらず、VST3 では変わる）。
- 決定:
- 経緯: 第 36 組（X-7）の S-581 の下書き（onsa-gap）の新しい S の候補と、独立のレビューの段 2（別の S にする。§15.4 の延期と同じ時期）から立て、利用者の了承で登録した（2026-10-22、52 回目）。関係: S-581、S-104。
- 補い（2026-10-22、親）: プロジェクトの状態はラッパーが単位の値で保存する（S-583）ので、VST3 の正規化の違いが効くのは、ホストが正規化した値で持つ自動化である。決めるときは前提を自動化に絞って確かめる（52 回目の文書の点検）。
