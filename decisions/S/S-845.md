# S-845 ガードの候補を作らない腕のうち、選択でない形の中（`-(1.5 // c` 改行 `)` の括弧の中、`@` の右）にコメントがあるものの E0002 の文と行: 選択の行（`*_choice`）か、一つの形の行か

- 空白: `spec/foreign-forms.toml` の `float_pattern_choice`・`range_pattern_choice` の注記は「まとめるときに削除する枝の中にコメントがあれば…候補を作らない」とし、その場合の行（主の文）は選択の行（「…and these alternatives do not merge into one guard」）にしている。
  選択（`|`）を持たない形の中のコメント（`-(1.5 // c` 改行 `)` の括弧の中、`@` の右の中）で候補を作らないときの行は書いていない。
  読みは二つに割れる。(1) コメントが理由で候補を作らない腕は、形によらず選択の行（今の実装）。(2) 選択の行は枝のある形だけで、それ以外は一つの形の行（`float_pattern` など）。
  今の実装（dev `0baaaf64`）: `match x { -(1.5 // c` 改行 `) => 1, _ => 0 }` は E0002「float literals cannot be patterns, and these alternatives do not merge into one guard」（選択が無いのに選択の文）、note は「no candidate: a comment in the part the guard form would rewrite would be lost (§18.1)…」。
  仕様の注記の「削除する枝」に当たる枝が無い形である。再現は W4-18 U4 の probe（`target/notes/101/w418/u4/probe/comments.txt` の `c_line_in_hole`）。
  W4-18 U4 は Y15 を「行を選ぶ判断を一か所に」（Y15-1）にとどめ、この形の行は変えない（仮の扱い）。(2) にするなら、ガードの行を選ぶ一か所（`foreign/guard.rs::Why::row`）に、コメントの位置が枝の中かを渡す（Y15-2）。
