# S-256 呼び出しに書いた型引数 `f[T](x)`、`f<T>(x)`

- 空白: 呼び出しの型引数を `f[T](x)`（Scala、Onsa の宣言の `[T]` からの類推）や `f<T>(x)`（C++・Java・TypeScript）で書いた形。
  今は `parse[I32]("3")` が結果の注釈があっても E0406「annotate the result」（誤った案内）、`parse<I32>("3")` が候補なしの E0010。`f[T](x)` は S-191 の `xs[i](x)` と、`f<T>(x)` は E0010 と形が重なるので、読みごとの候補と段を決める。
  第 4 組の下書き（S-250、S-249）で見つけた（2026-10-08）
- 提案: 呼び出しと型の経路に書いた型引数（`f[T](x)`、`f<T>(x)`、`Buf[F32].zeroed(4)`）は E0020 で、型引数を除く候補、note で期待型の注釈の書き方。段は読みが一つに決まる最初の段（添字として読めない `[…]` と `P<…>(…)` は構文の段、名前の経路に付けた `[…]` は名前の段、メソッドに付けた `[…]` は型の段）。
  S-191 の「`ops[i](x)` は項目でありえない」を、名前の経路では名前の段に改める（候補は今と同じ `ops[i].(x)`）。細部: `P<…>(…)` は型引数を除く候補と比較の連鎖の候補を並べる。
  注釈の無い `let` / `var` の初期化式の全体で返り値の型が全ての型パラメータを含むときは、型引数を注釈に移す候補（`let y: U8 = id(250)`）を出し、それ以外は除くだけ。S-250 の `f::<T>(x)` にも同じ候補を出す。
  S-239 が入れば候補をその形に替える（S-239 で決まり、除く候補と注釈に移す候補、S-250 の `f::<T>(x)` の候補は `::[…]` への構文上の編集に置き換えた。段は変わらない。S-277）（(a)。利用者。仕様 §4.5、§6.1。2026-10-08 決定。実装は W3-19（構文の段。K-22 で W3-07 から移した）、W4-13（名前の段。K-22 で W4-12 から移した）、W5-02（型の段）。R-175 はこの直しで閉じる）
