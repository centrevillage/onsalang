# S-1187 細部: 構文の段の E0020 の候補が `~` を `par`（U2 の後は `if`）の直後へ移した後、中身で決まる E0812 の候補がその `~` を消す道筋を、fix-loop の検査が「cycle (undoes step 1)」と数える（道筋は clean で終わる）

- 空白: §2.6 は `par ~ i`・括弧の中の改行の `par` 改行 `~ i` を E0020（空白を除く候補）とし、§11.5 は本体に状態を持つものを含まない `par~` を E0812（`~` を外す候補）とする。構文の段は本体の中身を知らないので、状態の無い本体では E0020 の候補を当てた後に E0812 の候補が `~` を消し、二歩目が一歩目の編集を戻す形になる。`two(par` 改行 `~ i in 0 ..< 2 { x }, 1.0)` は `onsa_cases --fix-loop --branches` で `cycle (undoes step 1) after 2 steps`（二歩目の後は誤り 0）、同じ行の `par ~ i` は `clean after 2 steps`。U2 の後は `if` 改行 `~ c` の形も同じになる見込み。
  読み: (1) 道筋は clean で終わる（当て続けて止まる）ので許し、fix-loop の検査が数えない形に直す、(2) 戻す編集は循環として、E0020 の候補を変える（構文の段は中身を知らない）か、その形を事例から外す。
  仮の扱い: 事例は本体に状態を持たせて避ける（W7-06 U0/t2 の `fixes/e0020_par_tilde_newline`）。検査を緩める直しは gate の検査を緩めるので、利用者に数え方と実物を見せてから（S を決めるとき）。急ぎ: W7-06 U2 の前（`if~` に広がる）。
- 決定: 決定（2026-11-20、利用者。170 回目）: fix-loop の数え方は変えない。循環と数えたのは括弧の中の改行の形で、E0020 の候補が `~` をキーワードの直後へ移す（§2.6）のに、挿す `~` に書き手の字の印が無かったため（`onsa_syntax` の `move_token_up`）。移す字に書き手の字の印（`Edit::with_writers`）を付け、S-475・S-990 の規則（書き手の字を移した編集の字を後の候補が取り除いても戻しに数えない、`Fix::moves`）に乗せる（利用者の案。親が出した「fix-loop の循環の数え方を変える」案は範囲が広いので取り下げた）。移す先で別の記号に書き換える形は印を付けない。同じ行の `par ~ i` は空白を除くだけの候補で、今も循環にならない。直した後に fix-loop の判定が変わる入力の一覧と実物を利用者に見せてからコミットする。W7-06（U2 の前）。
- 経緯: 170 回目（2026-11-20）、W7-06 U0/i（onsa-impl）が挙げ（再現 `S/w706/u0/i/gap2/`）、親が登録した。
- 補い（2026-11-20、親）: W7-06 で直した（onsa-impl。`onsa_syntax` の `edits.rs` の `move_token_up`・`lifted`、+25 −8）。印は「書き手の字をそのまま移す候補」の全て（`~`、`?`、行頭の二項演算子・`|`・`->`・`=`、そのまま書く `..<`・`..=`、コメントを越えてコードを上へ移す `move_up`）に付け、別の記号に書き換える形（`..` → ` ..<`）には付けない（利用者が範囲を確かめて了承）。前後の比べ（控え `target/notes/170/w706/s1187/`）: gate の fix-loop の入力 1302 件は変化 0、`tests/spec` の全体と fuzz の 6188 件は再現の形の 1 件だけ cycle → clean、候補の数と約束は全て同じ。`move_token_down`（`.`・前置の `-` を下へ移す）は印を付けておらず、同じ形が出れば同じ扱いにする（W7-06 の持ち越し）。
