# S-277 構文の段の形での、型引数を注釈に移す候補の条件

- 空白: S-256 の「型引数を注釈に移す候補」（注釈の無い `let` / `var` の初期化式の全体で、返り値の型が全ての型パラメータを含むとき）の条件は呼び先の宣言を要するが、同じ決定は `[…]` が添字として読めない形（`pair[I32, F32](1, 2.0)`）と `P<…>(…)` を構文の段で出すとし、そこでは呼び先が分からず判定できない。
  S-250 の `f::<T>(x)` も構文の段で同じ。除くだけの候補にすると、当てた後に検査を通ったままリテラルの型が変わりうる（`id<U8>(250)` が `I32`）。第 4・5 組の決定の反映で見つけた（2026-10-08）
- 提案: (a) で閉じる。S-239 の下で、他言語の形の候補は全て `::[…]` への構文上の編集で（`id<U8>(250)` と `id::<U8>(250)` は `id::[U8](250)`、`pair[U8, F32](1, 2.0)` は `pair::[U8, F32](1, 2.0)`）、型引数を残し、呼び先の宣言を読まない。
  段は S-256 のまま（比較の連鎖の候補の条件も S-256 のまま）。S-256 の細部（除く候補、注釈に移す候補）と S-250 の `f::<T>(x)` の候補は、S-256 の回答の条件どおり S-239 で置き換えた。
  名前の経路でもメソッドでもない呼び先（`(e)<I32>(x)`、`g(x)::<I32>(y)`）は、型引数を除いて `e.(x)` にする一つの候補（関数値の型は総称でないので型は変わらない）（利用者が了承。第 9 組の書き直し。仕様 §4.5。2026-10-08 決定。実装は W3-19（構文の段）、W4-13（名前の段）、W5-02（型の段））
