# S-669 std の `target fn` の本体の書き方（宣言に書いた本体が、組込み型でも走るように読める）

- 空白: S-108 は、std の `target fn` に本体を持たせ、組込み型ではプリミティブ、それ以外の型では本体を使うとし、§15.2 と §13.4 はそれを宣言に本体を書く形（`pub target rt fn abs[T: Num](x: T) -> T { if x < T.ZERO { -x } else { x } }`）とする。
  この形では、組込み型では走らない本体が宣言に書かれ、std のソースを読む書き手は、全ての型で本体が走ると読みうる。`F32` の `abs(-0.0)`・`min(x, NaN)`・`min(0.0, -0.0)` は、本体の式どおりなら `-0.0`・`x`・`0.0`、§3.4 のプリミティブでは `+0.0`・`NaN`・`-0.0` で、§3.4 が定める端の場合で食い違う（整数では一致する）。
  本体をどの形で書くか（宣言に書くか、宣言と別に書くか、印を付けるか）と、プリミティブも本体も無い型で呼べるときの扱いを書いていない。決定済みで戻さないもの: S-108 の意味（組込み型はプリミティブ、それ以外の型は本体、単相化で選ぶ）と、`Float` を組込みの浮動小数に限ること。
- 決定: 本体の書き方は (i-1)。std の `target fn` は、見出しの後ろの `else` に本体を持てる（`pub target rt fn abs[T: Num](x: T) -> T else { … }`。「処理系が与え、与えなければこの本体」）。`else` は見出しの最後のトークンと同じ行（次の行は E0003）。印の無い `{` の本体はどのパッケージでも持てない（E0002）。
  プリミティブも本体も無い型: std の `target` 宣言は境界を満たす全ての型で使えるのを原則とし（強い約束にはしない）、弾ける所は境界で弾く。それでも具体化した型にプリミティブも `else` の本体も無ければ、使った位置で E0200（機能名と型を添える。型で決まるので `onsa check` も報告する。§15.2 の変換先の E0200 と同じ形）。
  時期: 構文の段の `else`、std の三つの本体と総称の関数としての検査は W5-02。本体を降下で呼ぶ経路と型ごとの E0200 は、利用者の `impl Num` を開く作業（計画は第 2 期。W5-04 で第 1 期に開くなら、その作業で経路を入れるか届く形を E0200 にし、内部エラーに残さない）。
  std の宣言の境界と処理系の表を突き合わせる単体テストを W5-02 に置く（std を作る側の確かめ。親、`rules/leader.md` 5.10）。§15.2・§13.4・§2.5・`spec/tools.md` §3（2026-10-25 決定）。
- 経緯: 65 回目（2026-10-25）、第 53 組（S-629・S-661）の説明の中で、利用者が読み違いの恐れを挙げた。第 53 組の論点は本体の書き方に依るので、族（S-670）として下書きをやり直す。関係: S-108、S-629、S-661、D-07、S-69、S-208。
  65 回目（2026-10-25）、第 55 組。利用者が B4 で (i-1) を選んだ（下書きと助言の二段も (i-1)。利用者の案の (iii) 宣言と定義を分ける形は、段 2 が利用者の観点で比べ直した）。
  B5 は、下書きと助言の二段の (y)（std の側で保つ）に対し、利用者が「std で保証する内容が大きくなる懸念がある。境界で弾くのが適切な場合は弾くべきだが、(y) は強い約束にせず、解決できない場合は (x) の逃げ道を用意する」とし、親が §15.2 の変換先の規則と同じ形に言い直して了承を得た。
