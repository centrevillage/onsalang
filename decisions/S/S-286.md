# S-286 `onsa test` の範囲の端

- 空白: `onsa test` の範囲の端: テストが一つも無いパッケージ（`--filter` なし）の終了コードと出力、`--filter ""`、パッケージの中の一つのファイルを引数に渡したときに走らせるテストの範囲。仕様は「`--filter` に一つも当たらなければ終了コード 2」（§18.2）だけを書く。W2-10/t で見つけた（2026-10-08）
- 提案: 決定（2026-10-08、利用者。(a) と (e2)。下書きの推奨は (a) と (e1)）: パッケージの中のファイルを `onsa test` に渡すと、そのファイルのモジュールのテストだけを選ぶ（`--filter` と重ねて絞る）。走らせるのを止める診断（検査の誤りと変換先によらない E0200 はパッケージ全体、S-242）は、渡したファイルによらず全て出す。
  §15.1 の「そのファイルの診断だけを出す」は、診断が結果であるコマンド（`check` と LSP）の規則とする。空の `--filter` は付けないのと同じ（テストの無いパッケージでも 0）。空でない `--filter` が当たらなければ 2（S-242 のまま）。
  選んだテストが 0 件なら、テストの無いパッケージでもパッケージの中のテストの無いファイルを渡したときでも 0 で、2 にするのは空でない `--filter` が当たらないときだけ。理由（利用者）: 使い方が間違っているかは、テストが 0 件で返ることで十分に分かり、特別な規則が要らない。マニフェストの無いファイルを複数渡すのは使い方の誤り（2）で、一回の実行は一つのパッケージ。
  理由: 残すと、同じファイル名のモジュールの経路が重なり（`x/a.onsa` と `y/a.onsa` はどちらもモジュール `a`）テストが黙って消える（R-189）ことと、一つのファイルの検査の誤りが別のファイルのテストを止める範囲の規則が要る。複数のファイルのテストを一度に走らせたいときは `onsa.toml` を置いてパッケージにする。
  後で緩めても既存の実行は壊れない（仕様 §15.1、§18.2。2026-10-08 決定。空の `--filter` は W2-10 の実装のまま（`SPEC-GAP(S-286)` の印は W2-13 で外れた）。ファイルの選び方と止める診断の出し方、複数のファイルの使い方の誤りは W4-02（上の階層へ探すのと同じ回））
