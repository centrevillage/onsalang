# S-475

- 空白: 修正候補を一つずつ当てたときの収束と往復が、§18.1 の約束に入っていない。約束は一つの候補を当てた前後の状態だけを見る（「元の診断が…唯一の誤りなら、当てた後の触れた単位の全てに、同じ段かそれより前の段の診断を残さない」）。
  段をまたぐ往復（S-435 の `~` の往復: `pub(crate) flow lp` と `lp~(x)` で、E0812 の候補「`~` を外す」、E0020 の候補「可視性を外す」、E0811 の候補「`~` を足す」の 3 手で 1 手目の編集を戻す）は約束の外にある。
  読みは (1) 約束の範囲の外で、候補の欠陥でなく読み続けの不足（S-435 は W3-08 で直る） (2) 往復しないことも候補の約束として仕様に書く（`rules/criteria.md` 7.17「検証に因果を持ち込まない」・7.18「頼る使い手を示せるものだけ」と合うかを見る）。gate の `fix-loop`（W3-22、今は報告だけ）を落とす形にするときの根拠になる。
  W3-22/b が見つけた（2026-10-13。`onsa_cases --fix-loop --pick last` で `cycle (undoes step 1) after 3 steps`）
- 提案: 後の段（`fix-loop` を落とす形にする前）
- 時期: W3
- 判断（2026-11-09、利用者）: 期限を W5-24 に改めた（2026-11-09、129 回目）。W3 は `before` に X-4 を書けないための仮の期限だった（`issues/X/X-8.md`）。今の候補は `fix-loop` の歩きで往復 0・発散 0（868 ファイル）なので、W5-24 が候補を足す前に約束と gate をそろえる（利用者が (A) を選んだ）。
- 決定: 決定（2026-11-09、利用者。129 回目、中立の要約と onsa-advisor の二段のレビューを経た。利用者が ID を挙げて了承）: (3)。候補を当て続けたときの収束は仕様の約束に書かず、処理系の検査として gate の `fix-loop` を落とす形にする。
  破れに数えるのは `cycle`（前と同じ字の状態と、前の手の編集を戻す手）と `limit`（手数の上限）で、`diverge`（報告する診断が 4 手続けて増える）は数えない（隠れていた誤りが見えてくる正当な歩きでも起きる。`target/notes/129/s475/probe/reveal2.onsa`）。gate の歩きは `--diverge` を効かない値にし、増え続ける形は `limit` で捕まえる（CLI の `--fix-loop` の既定は 4 のまま）。既知の例外は `tests/pending.toml` の `kind = "gate"`・`target = "fix-loop/<tests/ からの経路>"` に R と期限を付けて載せる（新しい置き場所は作らない）。
  理由: 収束は手の並びの性質で、候補の約束を当てた前後の状態で判定する形（`rules/criteria.md` 7.17）でなく、gate が歩かない範囲（パッケージの事例、打ち切った枝）に約束が及ぶ。修復ループは約束があっても手数の上限を外せないので、頼る使い手を示せない（7.18）。S-553 の理由の文は、候補の規則を選ぶときの基準（7.27 と同じ層）と読む。S-435 の往復は候補でなく偽の診断が原因で、§18.1 の「名前まで読めれば名前解決に見せる」で止まっている。今の事例とファズの入力の 868 ファイルは往復 0・発散 0・上限 0。後で仕様の約束に上げても通るプログラムは変わらない。
  仕様の文は変えない。実装は W5-24 の最初の単位（`tools/gate_steps.py` の `fix-loop` の項目を報告だけから `pendable`・`by_case_only` に、`crates/onsa_tests/src/fix_loop/gate.rs` の判定と実装待ちの一覧の読み、テスト。見当 30〜75 行）。`issues/X/X-4.md` の持ち越し（W3-22 の残り）の置き場所と S-475 はこれで決まる。

- 補い（2026-11-10、利用者）: 136 回目、S-990 の補い（`pub @fp(strict) fn h` に移す候補を出す）に伴い、破れに数える「前の手の編集を戻す手」を、その手の編集の全てを元に戻す手に限った。移す候補（元の位置の字を消す編集と、頭へ挿す編集の二つ）の後に、挿した字だけを除く手は、字が元の位置に戻らないので、戻す手に数えない（前は、前の手の編集の一部を戻す手も数えた）。前の手の編集が一つの形（S-435 の `~` の往復）と、前と同じ字の状態、手数の上限は前と同じに数える。事例とファズの入力の 976 ファイルは、直した後も往復 0・上限 0。実装は `crates/onsa_tests/src/fix_loop/walk.rs::undoes`（W5-24 U3c、`616a8eaa`）。
