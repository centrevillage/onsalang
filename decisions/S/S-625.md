# S-625 属性の値と有無を Onsa のコードに見せる生成の API（`params_default`・`latency`）と §6.5 の「解釈を変えない」

- 空白: §6.5 の 1 文目（S-624）は「属性は、ターゲットに固有の事情が関わらない段までのプログラムの解釈（型と計算の結果）を変えない」とするが、§11.6 の生成する API の二つは、属性の有無と値をターゲットを選ばない段の Onsa のコードに見せる。
  `voice.params_default()` は、`block` の入力の全てに `@param` か `@host` があるときだけ生成され、値は `@param` の `default`（`@host` の欄は既定の値）。`rt fn voice.latency(s)` は一番外の flow の `@latency(e)` の値を返し、宣言が無ければ 0。
  どちらもインタプリタと `onsa test` で呼べるので、属性を外すと、呼ぶコードが誤りになるか（`params_default` が無い）、計算の結果が変わる（`latency` が 0）。S-624 で決めた範囲の外で（生成する API を通した読み出しは挙がっていなかった）、前の文（S-150）でも同じ食い違いがあった。
- 決定:
- 経緯: 59 回目（2026-10-24）、二つ目の文書の点検（onsa-docs）が §6.5 の新しい 1 文目と §11.6 の `params_default`・`latency` の行を並べて挙げ、親が §11.6 の 228・230・264 行で確かめた。
  関係: S-575（`@host` と `params_default` の条件）、S-576（`@latency`）、S-588（`@host`・`@latency` の場所と値の誤り）、S-112（生成する API の形）、S-615（7.23 の属性とキーワード）。
  利用者（59 回目、決め方は (a) 空白の流れで、W7-03 の前）: 「param等が実際に必要になるのはホストラッパーやWASMなどだと思うので、一旦param等の責任範囲を整理した方が良いと思います」。
  親の言い直しを利用者が了承（「判断3の時期と範囲はそれで良いと思います」）: 族「`@param`・`@host`・`@latency` の責任範囲」に S-625 と S-588 を入れる。
  整理するのは、(1) どの段（ターゲットを選ばない段の `onsa check`・Core・インタプリタ・`onsa test --flows` と、ターゲットの段の C の API・ホストのラッパー・WASM）がこれらの情報を持ち使うか、(2) Onsa のコードから読める形（§11.6 の `params_default()`・`latency()`、`Params` の欄）を残すか、(3) S-588 の場所と値の誤りをどの段で出すか、を整理する。
  決めた S-575・S-576・S-112 は改めうる前提として下書きに渡す。時期は W7-03 より前の区切りの良い所（例: 60 回目の始め）。
