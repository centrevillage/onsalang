# S-953 既知の境界と未知の境界が並ぶ型パラメータの後の、既知の境界が与えるメンバ（`T: Float + Gone`・`T: Float + ?Dup` の `-> T.PI`）は黙るか、E0308 か

- 空白: §18.1 は、総称の境界の未知の境界（矛盾のある並び、見つからない名前を含む並び）の型パラメータを使う側に、その境界に頼る判定の診断を出さないとする（S-747 の A5）。既知の境界と未知の境界が並ぶ型パラメータ（`T: Float + Gone`、`T: Float + ?Dup`）の後に、既知の境界が与えるメンバを型・境界・効果行の位置に書く形（`-> T.PI`）が、それに当たるかは書かれていない。
  今の実装（dev `55162a4e`）: `fn e[T: Float + Gone](x: T) -> T.PI` は境界の `Gone` の E0302 だけで `T.PI` は黙る。`fn k[T: Float + ?Dup](x: T) -> T.PI` は「cannot find `T`」の E0302（R-404）で、矛盾の E0416 が隠れる。
  読み: (1) メンバがあるかは並びの全体に頼るので黙る（境界の誤りだけを報告する）。(2) `Float` が `PI` を与えると分かっているので、R-404 の形と同じく E0308。
  誤りのあるファイルの報告だけが変わる。入力は `target/notes/125/w511u10e/probe/mixed_bound.onsa`。

- 経緯: 125 回目（2026-11-08）、W5-11 U10e のテストの担当（onsa-test）が NEW として挙げ、事例に書かなかった。親が固定のバイナリで再現した。仮の扱いは (1)（今の `Gone` の形と同じ）で、実装の担当に `SPEC-GAP(S-953)` を付けさせる。
