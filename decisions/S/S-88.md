# S-88

- 空白: `F32` の `vdelay` で `MAX > 2^24` だと、`MAX` の丸めで添字の計算が溢れて実行時に panic する。大きさの上限が無く、巨大な遅延線でコンパイラ自体が溢れで panic する（`layout.rs`、`lower/flow.rs` の `MAX + 1`）（レビュー R-100）
- 提案: sema の遅延の長さの検査（E0808）に「`d` が `F32` なら `MAX <= 2^24`」を足す。
  ターゲットの pass の配置の計算を溢れない算術（64 ビット）で行い、型の大きさか状態の領域が `2^32 - 1` バイトを超えたら E0313（上限を超えた型か flow の宣言に置き、最も大きいフィールドを note で示す）。`vdelay` の `L = MAX + 1` は大きさの検査の後に計算する。`tests/review-phase1/parent/r100/` の期待値と今の出力は各項目の上のコメント（2026-10-05 決定。E0808 は第 3 段、E0313 はターゲットの pass（第 4 段、R-80）と同じ回。それまでも溢れは内部エラーではなく E0313 にする）
- 時期: M3
