# S-226 頭だけが決まった型を対象にする操作

- 空白: 頭だけが決まった型（`Option[?T]`、`Buf[?T]`）が操作の対象のとき（`match none() { … }`、`Buf.zeroed(4).len()`）、E0420 か E0406 か。§4.7 の「解決済み」が型の頭だけを指すかが読めない。W2-06/t で見つけた（2026-10-08）
- 提案: (a)。解決済みは型の頭が決まっていること。型引数の中の型変数は後の文で決まってよく、関数の終わりに残れば型変数を作った式（`None`、`none()`、`Buf.zeroed(4)`、`[]`）に E0406。空の `[]` も含める（Fable の指摘。§2.4 を改めた）。パターンの中のリテラルと列挙子は対象の型引数と単一化する。
  仕様は自己完結の規則で書いた（仕様 §2.4、§4.5、§4.7。2026-10-08 決定。実装は W2-06。R-157。後で決まる型パラメータの境界の検査の時点は S-235）
