# S-1017 細部: 使う所のフィールド名の短縮形 `P { in }` に `in_` の候補を出すか（§2.3 は出すと書くが、§7 の struct のパターンに短縮形が無く、当てると E0002 が残る）

- 空白: §2.3 は「使う所のフィールド名（…struct のパターンの `P { in: v }` と短縮形の `P { in }`）も同じ E0002 で、修正候補は同じく `in_` である（…短縮形では束縛の名前も `in_` になる）」と書く。§7 は struct のパターンを `Point { x: px, y: py }` の形だけにし、短縮形を書かない。§18.1 は、候補を当てた後に同じ段の診断を残さない。短縮形に候補を出すと、当てた後の `P { in_ }` に「expected `:`」の E0002 が残る（W5-13 U1 の担当が `UPDATE_GOLDEN=1` の器で確かめた）。読みは (1) 短縮形にも候補（§18.1 に反する） (2) `:` の前だけ候補（W5-13 U1 の実装、`parser/signatures.rs::parse_field_name` の `SPEC-GAP`） (3) 短縮形を §7 に足す。どの読みでも通るプログラムは変わらない（(3) を除く）。仮の扱いは (2)。事例 `tests/spec/fixes/keyword_name_field_use_short.onsa`（`fixes = 0`）。
