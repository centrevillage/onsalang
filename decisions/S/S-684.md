# S-684 本体の経路が自分のパッケージ名と自分のモジュールで始まるとき（`a/b.onsa` の `fx.a.b.f()`、`d.onsa` の `fx.d.f()`）の E0302 の修正候補

- 空白: §15.1（S-673）は、本体の経路の頭が自分のパッケージ名か、自分のモジュールを名指す部分（モジュール自身の名前か、自分の絶対経路）のときの候補を、それぞれその部分を外す形とする。頭が自分のパッケージ名で、その後ろが自分のモジュールの経路のとき（`a/b.onsa` の `fx.a.b.f()`、`d.onsa` の `fx.d.f()`）を書いていない。
  読みは (1) パッケージ名だけを外し、外した後の頭を取り込む `use` を足す（外した後の頭が自分のモジュールなら S-679 で E0302 が残るので候補なし）、(2) 二つの部分を一つの候補で外す（`f()`）、に割れる。
  今（`c77f3f3`）は (2): `fx.a.b.f()` に候補「take off `fx.a.b.`」、`fx.d.f()` に「take off `fx.d.`」（`target/notes/67/w403/u3a2/t2/g4`・`g5`）。`a/b.onsa` と `b.onsa` があるときの `fx.b.g()` は「take off `fx.` and add `use b`」（`g6`）。
  W4-03 U3a2/t2 の `crates/onsa_cli/tests/use_model.rs` は、この形を生成しない（`SPEC-GAP(S-684)`）。
