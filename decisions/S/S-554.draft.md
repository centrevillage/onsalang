# S-554 `assert` 文の規則と、テストの失敗の種類

- 決定済みで戻さないもの:   第 81 組の下書きの「S-554 の仕組みの出所」と「S-554 の形の表」の節（写しは `target/notes/110/g81/draft.md`、入力は `target/notes/110/g81/probe/`）。
- 論点: 空白の 1〜4。前提（2026-10-19）は論点に戻さない。
  - 1（確認だけの見込み）: `assert` 文の節が仕様に無く、式の型・書ける場所・`span` を §2.2、§9.2、§11.2、§18.1 から逆に読む。読みは一つ: 式は `Bool`（違えば E0401）、文で式の位置に書けない（E0002）、型は `()` で発散しない、fn・test・無名関数の本体と `const` の初期化式に書け、`rt` の関数にも書ける（§9.2）、flow の本体は E0806。
    失敗は panic で、テストでは `message` が `assert <式のソース>`、`span` が文全体（§18.1）、通常の実行の文面は約束しない（S-298）。式は検査を外す設定が未決定なので常に評価する（§9.2、§19.1）。
  - 2（確認だけの見込み）: §18.1 の `calls` の位置で、本体で起きた失敗（`calls` が空）と、本体が呼んだコードの中の失敗（空でない）が分かれる。読みは一つだが、位置で分かれるのは「本体か呼んだ先か」で、本体の中の確かめ（`assert`、`assert_near`）と本体の式の組込みの検査（溢れ、添字、`unwrap`）は、どちらも `calls` が空で位置では分かれない（形の表）。
    補助の関数に書いた `assert`（テストの側の確かめ）も、位置では「呼んだ先」になる。
  - 3: `failure` に `kind`（`assert` / `panic`）を足すか。足すなら `assert_near` の失敗（許容の誤りと `tol` の誤り）と `check` の反例をどちらにするか。
  - 4: `check` の失敗の位置。§11.8 は `assert_near` には「呼び出しの位置の panic」と書くが、`check` には書かない。性質の関数の中で起きた panic の `calls` に `check` の呼び出しを入れるかも書いていない（同じ形の `array.from_fn` は、今、無名関数なら入れず、名前付きの関数なら入れる）。
- 今の実装: 形の表のとおり。`--json` に種類は無く、内部の出所は `assert` 文と `assert_near` が Assert、他が Panic である。
- 案: 
  - 3 (a) 足さない: 種類は `--json` に出さない。`assert` の失敗は約束した `message`（`assert <式のソース>`）で、他は `span` の位置のソースで分かる。内部の出所は事例の器だけが使う。
  - 3 (b1) 足す、役目で分ける: `kind` は `assert`（`assert` 文、`assert_near` の失敗の両方、`check` の反例）と `panic`（`panic(msg)`、組込みの検査、`unwrap`、性質の関数の中の panic）。今の内部の出所と同じ分け方。
  - 3 (b2) 足す、仕組みで分ける: `kind` は `assert` 文だけが `assert` で、std の補助の失敗は `panic`（§9.2 で std の関数の失敗は panic）。
  - 3 (c) 種類を細かく足す: `assert`・`check`・`panic`・組込みの検査（溢れ、添字など）を分ける。
  - 4 (a) 呼び出しの位置: `check` の反例は `assert_near` と同じく `check` の呼び出しの位置の panic（`span` は呼び出し、本体で呼べば `calls` は空）。性質の関数の中の panic は、その位置で、`calls` に `check` の呼び出しを入れる（関数値を呼ぶ std の中の呼び出しは位置が無いので入れない）。
  - 4 (b) 性質の位置: 反例は、`check` に渡した性質の関数（引数の式）の位置。中の panic は (a) と同じ。
  - 4 (c) 書いた形のまま: 反例は (a) と同じだが、性質の関数の中の panic の `calls` は、無名関数なら `check` を入れず（本体に書いた無名関数の中は本体の位置）、名前付きの関数なら入れる（今の `array.from_fn` と同じ）。
  - 形ごとの出力: 3 で、本体の `assert` は (b1)・(b2)・(c) とも `assert`、本体の `assert_near` は (b1) が `assert`、(b2) が `panic`、(c) が `assert` か専用の値。本体の溢れは `panic`（(c) は組込みの検査の値）。(a) はどれも欄が無い。
    4 で、本体に書いた無名関数の性質の中のゼロ除算は、(a)・(b) が `calls` に `check` の呼び出し、(c) が空。名前付きの性質は三案とも `calls` に `check` の呼び出し。
  - 書き手から見て: 修復のループの書き手は、失敗が確かめ（期待か実装のどちらかが違う）か、検査されるコードの panic（実装の誤り）かで直し方を変える。3 (a) では `message` の約束（`assert`）と `span` の位置のソースで分ける。
    (b1) は欄だけで分かり、補助の関数の `assert` も確かめと分かる。(b2) は `assert_near` の失敗が `panic` になり、確かめと検査されるコードの区別に使えない。(c) は値が増え、組込みの検査の一覧の変化が出力の約束に入る。
    4 (c) では同じ性質の失敗が書き方（無名関数か名前付きか）で `calls` を変え、「`calls` が空なら本体」が「本体に書いた無名関数の中」を含む。
  - 修正候補: 無い（テストの結果の欄）。
  - 通るプログラム: どの案も変わらない（`onsa test --json` の出力だけ）。
