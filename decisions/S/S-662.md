# S-662 固有の `impl` のメンバの可視性が、型の可視性より広いとき（無指定の `struct Inner` の `impl Inner { pub fn new() -> Inner }`）に S-144 の E0303 にするか

- 空白: §15.1 は、公開の宣言に書いた型がそれより狭い可視性なら E0303 とし（S-144）、当たる位置（関数の引数と返り値、別名の右辺、定数の型、フィールドと列挙子の中身、trait のメンバ）を並べるが、固有の `impl` のメンバを並べていない。
  無指定（パッケージ内）の `struct Inner` の `impl Inner { pub fn new() -> Inner }` で、メンバの `pub` を見せる可視性として返り値の `Inner` を E0303 にするか、メンバの見える範囲は型の可視性を超えないとしてメンバの可視性と型の可視性の狭い方で比べるか（この形は通る）、`pub` を書くこと自体を誤りにするかを書いていない。
  W4-03 U1 の設計メモは、メンバ自身の可視性を見せる可視性にする（E0303 になる）。
- 決定: 届く範囲は S-665 の規則（メンバの可視性と型の可視性の狭い方）。加えて (b): 型の可視性より広い `pub` をメンバに書くと冗長で E0020（修正候補は `pub` を外すこと。note でメンバは型の可視性を超えて届かないことを示す）。語の無いメンバと `priv` のメンバはどの型にも書ける（`priv` の型の `fn` と `priv fn` はどちらもモジュールの中に届く。型を広げると `priv fn` はモジュールの中に残り、`fn` は型に連動する）。
  `spec/foreign-forms.toml` の行（`kind = "redundant"`、名前の段）は実装の表と一対一なので、実装する W4-03 の U4 で足す。§15.1（2026-10-25 決定）。
- 経緯: 64 回目（2026-10-24）、W4-03 U1 の設計メモの独立の審査（onsa-advisor）が見つけた。仮の扱いは設計メモのとおり厳しい方（E0303）で `SPEC-GAP` の印を付ける。待つのは W4-03 の U4（可視性）。関係: S-144、S-491、S-36。
  65 回目（2026-10-25）、利用者が B2 で (b) を選んだ（理由: `interface` などの解析の出力に、外へ届かない `pub` のノイズが混ざるのは実害）。
  A10 の確かめの中で、利用者が `pub struct` の `impl` の `pub fn` とフィールドの対称性、`priv struct` の `priv fn` が誤りになるか、メンバだけで可視性を読めるかを問うた。
  親が B2 を「届く範囲を変えない語は E0020」に広げて `priv` の型の `priv fn` も含める案を示したが、利用者は採らなかった（理由: `priv` の型を広げたとき、`priv fn` はモジュールの中に残り、語の無い `fn` は型に連動する。どちらも意図を表せるので、両方を許す。無指定の型を `pub` にするときは、要る `fn` を一つずつ `pub` にするので安全側）。
  メンバの可視性は型を超えないと語で書かせる案（R）と、メンバもフィールドと同じく型を継ぐ案（F）も比べ、どちらも採らなかった（F は `pub` の型にパッケージの中だけのメソッドを置けず、語の無い補助のメソッドが外へ出る）。
