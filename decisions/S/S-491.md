# S-491

- 空白: `impl`・`test` に付けた可視性（`pub test "a" { }`、`pub impl P { }`、`priv impl P { }`）。§15.1 は可視性を付けられる項目を書かない。今は通す（`e5619d6` は `priv impl` を E0002 にしていた）。W3-08/b1 の空白 G-3（2026-10-13）
- 提案: 後の段（W4-03 の前、可視性の意味と一緒）
- 時期: W3
- 決定: 決定（2026-10-23、利用者が ID を挙げて了承。55 回目、第 39 組）: (d)。可視性は、他のモジュールから名前で参照する宣言（トップレベルの名前のある項目、`use`、固有の `impl` のメンバ、extern のメンバ、フィールド）にだけ書く。
  メンバが自分の可視性を持つ容れ物（固有の `impl`、extern のブロック）の語は候補の無い E0002（note「可視性はメンバごとに書く」）。trait の実装、`test`、持ち主の可視性を継ぐメンバ（trait・effect のメンバ、trait の実装と handler のメンバ）、列挙子の語は外す候補の E0020（列挙子は今の一般の E0002 から移す）。語をメンバへ写す候補は作らない。
  あわせて: extern のメンバは (i)、トップレベルの関数と同じく自分の可視性を持つ（§14.1）。誤りの語の後は §18.1 の規則で宣言を読み続け、名前解決に見せる。
  仕様 §15.1・§14.1。`spec/foreign-forms.toml` の 2 行（E0002 の容れ物の行、E0020 の継ぐ位置の行）は、実装の表と一対一なので W5-11 で足す。メンバの可視性の検査（固有の impl と extern のメンバ）は W4-03
- 経緯: 55 回目（2026-10-23）、W4 の前の S の下書き（X-8）の第 39 組（族「§15.1 の可視性を書ける項目」、下書き `S-491.draft.md`、助言の担当の二段。全て一致）。
- 補い（2026-10-25、親）: §15.1 の「メンバの可視性はメンバの宣言だけで決まる。」の一文を消した。言いたかったこと（可視性は `impl` のブロックでなくメンバに書く）は同じ文の前半で足り、S-662（メンバは型の可視性を超えて届かない）と S-672（語の無いフィールドは struct に従う）と食い違って読めたため（2026-10-25、利用者が了承。66 回目の文書の点検 A）。
