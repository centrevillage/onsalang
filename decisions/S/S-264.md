# S-264 展開した後の型の深さと大きさの上限

- 空白: 型の別名と総称を展開した後の型の深さと大きさの上限。
  §2.5 の上限は構文の深さだけで、`type A_i = Option[A_{i-1}]` の鎖は構文の深さ 1 のまま展開後の型を任意に深くでき（14000 個で `check` が通り、`test`・`interface` の記憶が個数の二乗で増える）、`type A_i = (A_{i-1}, A_{i-1})` は展開が指数時間（26 個で 9 秒。E0409 の大きさの検査より前に展開する）。
  E0006 の note は型を別名に分けることを勧める。W3-14/b で見つけた（2026-10-08）
- 提案: (a) 検査が作る全ての型（別名を展開し型引数を当てた後。書いた型、推論した型、具体化の型）に、深さ 256 と大きさ 4096 の上限。超えたら E0422。深さは型の形（型引数のある型、タプル型、配列型、関数型）を一段とし、名前は数えない。
  大きさは名前（組込みの型、宣言した型、型パラメータ）、型の形、const 引数を一つずつ数え、宣言した struct と enum は葉でフィールドを数えない。位置は上限を初めて超えた型を作った所（別名はその宣言で、超えた別名を使う別名には出さない。書いた型はその形、本体は型を作った式、具体化の型は具体化を作った呼び出し）。
  §2.5 の E0006 の note を「型を名前付きの struct に」に改めた。値はひとまずで、後で上げても既存のプログラムは壊れない。
  多相再帰と具体化の数、降下の具体化の E0422 の段は S-290。`onsa_diag::stack` の文書は、この上限で有界と書き直す（W4-05）（利用者。第 6 組の下書き。仕様 §2.5、§4.4。2026-10-08 決定。実装は W4-05（別名と書いた型、型の共有）と推論の作業（推論した型。W5 のどの作業かは W4-05 の作業票で決める））
