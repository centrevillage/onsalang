# S-795 族: 意味を変えない位置（代入の右辺、リテラルと構築子の要素）に書いた Dup の値の `move` を E0703 にするか

- 空白: Dup の値の `move` が意味を持つのは、`let` / `var` の初期化と `match`・`for` の見出し（束縛の行を所有にする、§5.4）だけで、代入の右辺・struct / 配列 / タプルのリテラルと構築子の要素では何も変えない（Dup の値は複製される）。
  §5.2 は `move` の引数の位置だけを E0703 とし（64〜65 行、S-609）、48 行の「`let` などの位置の Dup の値の `move` は所有の束縛を選ぶ印として受け付ける」の「など」の範囲は決めていない。今はどの位置でも受け付ける（`(move n, 1)`、`Some(move n)`、`x = move n`）。
  S-609 の原則（`move` の印は所有が移って前の値が以後使えなくなる所にだけ付ける）を、意味を変えない位置まで締めるか（E0703 で `move` を消す候補）、今のまま受け付けるか。S-793 で構築子の要素をリテラルの要素と同じ族に置いたので、決めるときは族で一度に決める。
  急ぎ: 後の段（W4-09 の S-605 の残りの前に見る）。
- 決定: 決定（2026-10-31、利用者。90 回目。独立のレビュー（onsa-advisor の段 1、想定漏れの表 約 22 形）と親の読みが一致し、段 2 を省いた。利用者が `T: ?Dup` の値の扱いを確かめてから）: (2)。
  Dup の値（Copy、Shared、関数値の変数、境界の無い型パラメータ）の `move` は、束縛の見出し（`let` / `var` の初期化、`match` の対象、`for` の反復元）では所有の束縛を選ぶ印として受け付け、値を置く位置（代入の右辺、struct / 配列 / タプルのリテラルと構築子の要素）では、`move` の引数と同じく E0703（その `move` を消す候補）。
  そこに置いたブロックの末尾も位置を継ぎ、末尾ごとに一件。返り値の位置は S-541 のまま受け付ける。
  総称の `T: ?Dup` の値は Affine でありうるので、どの位置でも `move` を書く（本体は境界で一度だけ検査し、`T = U32` で呼ばれたときの本体の `move t` は複製になる。呼び出し側は実引数の型で決まる、`pair_m(n)` は通り `pair_m(move n)` は E0703）。
  `var` の初期化を見出しの側に置くのは、`let y = move n` が通って `var y = move n` が誤りになる差を作らないため。全ての位置を E0703 にする (3) は、Shared の値を元の変更の前に写し取る唯一の書き方（`let c = move b` の後の `o = None`。印の無い `let c = b` は借用束縛で E0704）を塞ぐので採らない。
  候補は `move` を消すだけで、行も値も変わらず一度で止まる。文面は位置の名を言わず「ここでは何も移らない」の形（例: "`n` is Copy, so it is copied; `move` here moves nothing (§5.2)"）。
  S-793 の決定のうち、構築子の要素の Dup の値の `move`（`Some(move n)`）を受け付ける部分を改める（`tests/spec/values/ctor_elements_run.onsa` の 27・37・44・50 行は反転する）。仕様 §5.2 の 48 行と 64〜65 行、`tasks/diag-codes.md` の E0703 の行。
  担う作業は W4-09（S-605 の E0703 の族と同じ所、`modes/walk.rs` の `Pos::Consume` を見出しと値の位置に分け、`modes/consume.rs` の Copy・Shared の腕で E0703）。
  要約・票・入力は `target/notes/90/s795-798/`。
