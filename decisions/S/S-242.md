# S-242 未実装の std の関数を調べる範囲と `--filter`

- 空白: `onsa test` が走らせる前に未実装の std の関数（E0200、S-224）を調べる範囲。今は、`--filter` で外れたテストや、どのテストからも届かない関数も調べ、一つでもあれば絞ったテストも走らせない。
  §15.2 は「それを使うプログラムは、インタプリタでの実行を始める前に、使った位置で E0200」とし、§18.2 の `--filter` は「部分一致で絞る」とだけ書く。全体を調べるか、走らせるテストが届く範囲だけか。W2-03/b で見つけた（2026-10-08）
- 提案: (c)。未実装の std の関数（E0200）を調べる範囲は、走らせるテスト（`--filter` で選んだもの）から静的に届く範囲。§15.2 の「使う」を「その実行やビルドの入口から届く」とし、S-69 の「Core の全体」を改めた。
  変換先によらない E0200 と検査の誤りは今どおりパッケージ全体。`--filter` は完全な名前のテキスト（モジュールの経路、空白一つ、名前を Onsa の文字列リテラルとして書いたもの）の部分一致（コードポイントで比べ、大文字と小文字を区別し、空の値は全てに当たり、一つだけ）で、一つも当たらなければ使い方の誤り（終了コード 2）。
  照合の順は、検査の誤り、変換先によらない E0200、`--filter` の照合、届く範囲の E0200、実行。絞りを付けずにテストが 0 件のパッケージは成功（0。下書きのあわせて決めることで了承され、S-286 の回で §18.2 に書いた）（仕様 §11.8、§15.2、§18.2。2026-10-08 決定。実装は W2-10）
