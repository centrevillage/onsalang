# S-558 止まっているインスタンスの出力と時間（`when` が作るクロック）

- 決定済みで戻さないもの: S-172（`prev~` と遅延の長さは動いた刻みで数え、`sample_rate()` は外と同じ。論点 (2)）。S-110（`match~` の取られない腕の `T.default()` と E0816）。
- 論点: §19.1「入れるときに決めること: 止まっている間の出力（最後の出力を保ち、一度も動いていなければ `T.default()` の方向。Lustre と FAUST は保持、Pure Data は 0）、`prev~` と遅延の長さは動いた刻みで数え（Lustre、SCADE、Esterel と同じ）、`sample_rate()` は変わらない（§11.3）」。
  §11.3「flow の本体の `sample` は、そのインスタンスが動くクロックを指す」「将来、インスタンスを導くクロックや条件で動かすとき（§19.1）も、flow の本体の意味は、そのインスタンスのクロックを基準に決まる」。
  - (1) 止まっている間の出力。(2) 時間の数え方。(3) 条件の値のクロックとインスタンスのクロックの関係、受け手にできるもの、引数と `block` の段を止まっている間に評価するか。
    (4) `when` が作るクロックの定義。イベントのクロック（同じサンプルの中で複数回刻みうる、§19.1）と導くクロック（`with` で付ける方向、§19.1）が後で入るときに食い違わない形にする。
  - 決定済み（S-172、§19.1 のマルチレートの項の箇条）: (2) の `prev~` と遅延の長さは動いた刻みで数え、`sample_rate()` は外と同じ。論点から外す。
- 今の実装: 修飾子は無い（E0413 か E0812）。`if active { saw~(f0) } else { 0.0 }` は E0200（p09、W7-06 で E0811）。
- 案:
  - (1a) 最後の出力を保つ。一度も動いていなければ `T.default()`（`T` が `Default` を満たさなければ E0816、`match~` の取られない腕と同じ）。
    実装: インスタンスのノードに保持の欄を一つ（内部の名前は `<名前>.held` のように `.` で続け、§11.6 の生成する名前を増やさない）。
  - (1b) 止まっている間は常に `T.default()`（Pure Data と同じく 0）。実装: 保持の欄は要らない。費用の要因: `T.default()` が値の意味を持たない型（列挙子の最初の値など）でも、止まるたびにその値が出る。
  - (1c) 保持か `T.default()` かを、書き手が選ぶ（後で `default` の修飾子や引数を足す）。今は (1a) か (1b) を既定に選ぶことになる。
  - (3) 条件: (3a) `Bool` で、クロックは呼び出し側のクロック以下（定数、`init`、`block`、`sample`）。速い値を遅く使う規則（§11.3）のとおり、遅い条件はそのまま刻みごとに読む。
  - (3) 受け手: flow の呼び出し（利用者の flow と組込みの遅延）か修飾子の連鎖（S-555）。`init` の値や `par` は受け手にならない（E0812）。
  - (3) 引数: (3b) 引数は呼び出し側の式なので、止まっている刻みも評価する（引数の中のインスタンスも進む）。(3c) 引数の式も一緒に止める。
  - (3) `block` の段: (3d) 止まっている間も毎ブロック評価する（`block` の段は状態を持たない、§19.1）。(3e) そのブロックで一度も動かないなら評価しない。
  - (4a) 刻みの言葉で定義する: 呼び出しの位置のクロックを K（この版では常にホストのサンプルのクロック）とし、`x.when~(c)` の x は K の刻みのうち `c` が真の刻みだけで動くクロックを持つ。
    x の本体の `sample` はこのクロックを指し、`block` はホストの区切り、`init` は一度だけ。呼び出し側は x の出力を K の刻みごとに読む（保持、(1a)）。
  - (4b) サンプルの言葉で定義する（「`c` が真のサンプルだけ動く」）。後でイベントのクロックを足すときに文を書き直す。
- 他言語: Lustre V6（参照の手引き v6.112.1 §1.2.4）: `STABLE((set,delay) when ck)` のインスタンスは `ck` が真の刻みだけ動き、中の `pre` はその刻みを数え、`current` で呼び出し側のクロックに戻すと最後の値を保つ。最初の刻みは値が無いので、例は `ck = true -> set or second` と最初の刻みを真にしている。
  faust-rs: `ondemand(C)` は「clock input が来たときだけ `C` を動かし、その間は最後に計算した値を保つ」（README）。
  覚え書きは、遅延は「audio sample でなく firing を数える」、外の値は firing の時点で読む、clock の値が 1 を超えると一つの刻みで本体を複数回動かす、`ondemand` は `ma.SR` を変えないとする（`docs/ondemand-note-en.md`）。
  Pure Data: `switch~` で止めたサブパッチの信号の出口には 0 を書く（`src/d_ugen.c` の注釈「the epilog code simply copies zeros to all signal outlets」）。SuperCollider の `Pause`（文書）は「gate が 0 で node を止め、1 で動かす」とだけ書き、止めた間の出力は書かない（未確認）。
  §19.1 の「FAUST は保持」は、FAUST 本体の文書では確かめられなかった（`enable` と `control` は保守しない方針、faust-rs の `ondemand` は保持）。
- 推奨と理由: (1a)、(3a)・(3b)・(3d)、(4a)。確度: 中。
  - (1a): 止まった刻みはインスタンスにとって存在しない刻みで、呼び出し側が読めるのは最後に計算した値である。値の意味を持たない型でも、最初の刻みの前の一度を除いて `T.default()` を作らない。
    0 が欲しいときは `let s = saw~(f0).when~(active)` と取り、`if active { s } else { 0.0 }` と書ける。保持を (1b) から作るには帰還の `prev~` が要り、逆より長い。
    音声に使うと止めた値が直流として残る代償がある。その用途は上の `if` で書く（後で (1c) の `default` を足す余地は残る）。
  - (3a): 条件のクロックは、引数のクロックの規則（§11.5、入力の宣言のクロック以下）と同じ考えで、新しい規則を足さない。
  - (3b): 引数は呼び出し側のもので、修飾子が止めるのは受け手の状態だけ、と範囲が一つに決まる。Lustre の `f(x when c)` も、`x` を作る計算は呼び出し側のクロックで動く。(3c) は引数の中のインスタンスの動き方が、それを使う呼び出しの修飾子で変わる。
  - (3d): `block` の段は状態を持たないので、評価しても結果は変わらない。評価を止める (3e) は、止まり方を `block` の段まで追う計画が要り、違いは panic の時期だけである。
  - (4a): 定義を「刻み」で書けば、第 34 組でイベントの条件を足すときは「K がイベントのクロックになる」と K を広げるだけで、`when` の文は変わらない。
    同じサンプルの中で複数回刻む場合も、呼び出し側からはその位置の全ての刻みの後の状態が見える（§19.1 のイベントの文）と、保持の読み方が一致する。導くクロック（`with`）も K を変える構文として後で足せ、`sample_rate()` を変えるのは導くクロックだけ（S-172）と分かれる。
  - あわせて決めること（クロックの順序）: x の中のクロックは呼び出し側の式に出ない（出力は K で読む）ので、`定数 < init < block < sample` の順序と式のクロックの最大値の規則は、この組では変わらない。全順序でなくなる問題は導くクロックの時に扱う（§19.1）。
  - 新しい S の候補: 定数の条件（`when~(true)`、`when~(false)`）を誤りにするか。今は普通の値として通す案で足りる。
