# S-729 本体の型の位置（注釈）にローカルの束縛や引数の名前を書いたとき（`let a = 1` の後の `let _: a = 2`）、値として見つかった名前の E0308 か、型の位置はローカルを見ず E0302 か

- 決定済みで戻さないもの: 同じ注釈の中の配列長と const 引数のローカルと引数は、位置によらず E0417（§4.5、S-713 (a1)。第 65 組の表は本体の注釈の `let a: [I32; x]` を「決」とした）。今の E0302 は実装の食い違いで、どの案でも直す。
  項目の値（関数、定数）の E0308（S-103、U8a）、flow の組込み名の E0308（S-720）、まだ見えないローカルの E0302。
  第 68 組の下書きの「族「§15.1 の E0308 の位置」の仕組みの出所」と「S-729 の形の表」の節（写しは `target/notes/78/g68/draft.md`）。
- 論点: §15.1「名前は見つかったが、その位置に要る種類でなければ E0308」「値やモジュールを型の位置に書く」は、本体の型の位置の名前の引きが、その位置で見えているローカルの束縛と引数を見るかを書いていない。
  見るなら、ローカルは値なので見つかった名前の E0308。見ないなら、見つからない名前の E0302 である。§5.1 は「一つの名前は、見える範囲で常に一つのものを指す」とするが、位置ごとの引きの範囲までは言っていない。
- 今の実装: 表のとおり。本体の型の位置のローカルと引数は、どの位置でも E0302「cannot find」で、修正候補は無い（`--fix-loop` は `no-candidate`、`probe/s729/fx/local.onsa`）。
  同じ本体の型の位置でも、見出しの束縛（`T`、`Self`）と flow の組込み名（`prev`、`sample_rate`）は引く（`sig/types.rs` の `cx.generics` と `flow_name_as_type`）。flow の組込み名は、ローカルと同じく本体でだけ見える名前である。
- 案: 
  - (1) 本体の型の位置も、その位置で見えている全ての束縛（ローカル、引数、`for` と `match` の束縛、flow の入力と `let`）を引く。ローカルは値なので、型の位置では E0308（文面は「`a` is a local, not a type」の類）。注釈の配列長と const 引数は同じ引きで E0417。
  - (2) 本体の型の位置の名前は、見出しの束縛とモジュールの本体の空間だけを引き、ローカルは見ない（E0302「cannot find」）。注釈の配列長と const 引数（定数式の位置）だけは、決定済みのとおりローカルを見て E0417。
    E0302 に note（「`a` はローカルの束縛で、型の位置には型を書く」）を足す形もありうるが、note を作るには (1) と同じ引きが要る。
  - 形ごとの出力:

    | 形 | (1) | (2) |
    |---|---|---|
    | `let _: a = 2`、`n as a`、`fn(x: a)`、`Option[a]`、`let y: x`（flow） | E0308 | E0302 |
    | `let _: p.x = 2` | E0308（頭がローカル） | E0302 |
    | `let v: [F32; n]`、`Ring[F32, n]` | E0417 | E0417 |
    | `let _: helper`、`let y: prev` | E0308（今のまま） | E0308（今のまま） |
    | 兄弟のブロックや後ろの `let a` | E0302 | E0302 |

  - 書き手から見て: 例として、TypeScript の `typeof n` の感覚で「`n` と同じ型」のつもりで `let y: n = …` と書く。
    (1) は「`n` はローカルで型でない」を示し、書き手は型を書く。(2) は真上に `let n` があるのに「見つからない」を示し、綴りやスコープを疑わせる。名前を足す直し（`type n = …`）は E0320・E0304 になり、もう一回の検査が要りうる。
    同じ注釈の `[F32; n]` は、どちらの案でも「ローカルで定数でない」（E0417）と言うので、(2) では一つの型の中で同じ `n` が「在る」と「無い」に分かれる。
  - 修正候補: どちらの案も候補は無い（書き手が要る型は一つに決まらない）。当て続けても `no-candidate` で止まる。
  - 通るプログラム: どちらの案も変わらない。ローカルと項目は同じ名前を持てず（§5.1 の E0304）、名前の形も違う（§2.3。ローカルは小文字、型は大文字で始まる）ので、ローカルの後ろに本物の型が隠れることは無い。変わるのはコードと文面だけである。
  - 規則と例外: (1) は規則を足さない（本体の他の位置と同じ引き。§15.1 の「値を型の位置に書く」の値にローカルが入る）。
    (2) は「本体の型の位置はローカルを見ない」の一文を足し、同じ本体の型の位置が見出しの束縛と flow の組込み名は見るのにローカルだけ見ない例外と、一つの型の中で型の名前と定数式で引きが違う例外ができる。
  - 実装の量（W4-04 の残り）: どちらの案にも要る分（決定済みの E0417）は、歩き手が型の位置を集める所で配列長と const 引数の式を `const_expr` として歩いて記録し、`lower_type_in_body` から `constarg::expr` に `local` を渡す（今は `&|_| false`）。約 +15〜25 行。
    (1) はさらに、集める所で型の木を辿り（`TypeKind::Path`・`Tuple`・`Array`・`Fn` と型引数、約 15 行）、頭の名前を歩き手のスコープで引いてローカルなら E0308 にする（`NameKind` にローカルは無いので、文面の口を一つ足す、約 5 行）。合わせて約 +30〜45 行で、(2) より約 +10〜20 行多い。
    後の段への手当ては、どちらの案にも無い（名前の段の誤りで単位を止める）。flow の本体の型の位置も同じ `type_sites` を通るので W7-04 に足すものは無い（flow の `let` は先に宣言されるので、(1) では後ろの `let` の名前も E0308 になる。E0801 の名前の順は値の位置の規則）。第 2 期と JS / WASM には関わらない。
- 他言語: 
  - rustc 1.94.1（`probe/other/s729.rs`）: `let _x: a = 2;` と引数の `let _y: n = 2;` は E0573「expected type, found local variable `a`」。`let _v: [f32; n]` は E0435「attempt to use a non-constant value in a constant」。
    署名の `fn g(n: usize, a: n)` も E0573、`fn f(n: usize, a: [f32; n])` も E0435（`sig.rs`）。
  - swiftc 6.3.1（`probe/other/s.swift`）: `let x: a = 2` と `let y: n = 2` は「cannot find type 'a' in scope」（型の名前は値を見ない）。
  - TypeScript（tsc がこの機械に無い）は未確認。clang++ 21 は `a x = 2;` を式として読むので比べられない。
- 推奨と理由: (1)。確度: 中〜高。
  - Onsa の名前は一つの空間にあり、見えている名前は一つのものを指す。本体の型の位置は既に見出しの束縛と、本体でだけ見える flow の組込み名を引いているので、ローカルだけを見ない理由が無い。
    同じ注釈の配列長は決定済みの E0417 でローカルを見るので、(1) は一つの型の中で引きが一つになり、(2) は二つになる。
  - (2) の E0302 は、名前が在るのに「無い」の直し方（名前を足す、綴りを直す）へ向け、E0320・E0304 を経てもう一回の検査を招きうる。(1) は一回目で使い方の誤りと示す。
  - 通るプログラムは変わらず、差は名前の段に閉じた約 +10〜20 行である。後の段にも flow にも手当てが続かない。
  - あわせて決めること: §15.1 の「値やモジュールを型の位置に書く」の値に「ローカルの束縛と引数を含む」と添える。注釈の配列長と const 引数の E0417（決定済みの食い違い）を同じ作業で直す。
  - 別の S にしてよい論点: 署名の型の位置と定数式に引数の名前を書く形（`fn f(n: U32, a: n)`、`fn f(n: U32, a: [F32; n])`）。今は E0302。署名のスコープに引数が入るか（S-713 (a1) の「引数」の E0417 が署名にも当たるか）が書かれていない（下の新しい S の候補）。
- 影響: 仕様 §15.1（(1) は値の括弧に一句、(2) は本体の型の位置の引きの一文と、E0302 の note を足すならその文）。§4.5 は変わらない。`tasks/diag-codes.md` の E0308 の行（(1) は S-729 を足す）。
  作業は W4-04 の残り（U9 と並ぶ小さな単位か U9 の後。期限は W4-04 を終える前）。E0417 の部分はどちらの案でも同じ所。
  今の事例: `tests/spec/type_names/kind_body_annotations.onsa` と `tests/spec/types/kind_array_lengths.onsa` は、この形を書かずに頭のコメントで空白と書いた。表の各行を足す（(1) は E0308、(2) は E0302。配列長と const 引数はどちらも E0417）。
  今の期待で、本体の型の位置のローカルを E0302 とするものは見つけていない（`git grep` の範囲）。
