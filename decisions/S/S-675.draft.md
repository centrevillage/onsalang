# S-675 族: §15.1 の E0304 の報告する側と残す側

- 決定済みで戻さないもの: E0304 は同じ名前の空間（本体、モジュールの名前空間、経路の頭）の中の二つの名前だけ（S-611）。二度目の `use` は E0304（S-17）。prelude・組込み型と同じ名前の項目と `use` は E0304（S-79・R-103・S-611）、組込みの flow の名前の項目と `use` も E0304（S-542、§5.1）。
  項目と同じ名前の子モジュールは E0304 で位置は項目（R-177・S-666）。ルート直下のモジュールと依存のパッケージ名は E0304（S-37・S-246）。flow と同じ名前の宣言は E0305 で、後の宣言に付け前を note で示す（S-176、§11.2）。
  名前の段で失敗した `use` の名前は束縛として数えず、E0304 の相手にせず、使う所に診断を出さない（S-462）。ローカルと見えている束縛は E0304 で位置はローカル（§5.1、S-79）。
  族の形の表（12 行）は、第 59 組の下書きの「族の形の表」の節（写しは `target/notes/67/g59/draft.md`）。
- 論点: §15.1 は E0304 になる組を決め、子モジュールの組だけ「位置は項目」と書く。§11.2 は E0305 を「後の宣言に付け…（E0304 と同じ）」とする。§18.1 は誤りのある宣言を名前解決に見せ、偽の連鎖を出さないとする。
  組ごとの報告する側と、使う所と他のモジュールの経路が引く側は書かれていない。今の残す側では、書き手が残さなかった側を意図した使う所に連鎖が出る（表の 1〜9 行）。連鎖の診断に候補が付く形もある（5 行の「`~` を除く」、8 行の「`~` を足す」）。
- 今の実装: 表の「今の実装」の列。E0304 には候補が無い。E0304 が項目に付くと、その項目の単位は名前の段で止まり、本体の型の誤りが出ない（`g_item_item_body`: 後の `fn f() -> I32 { true }` は E0304 だけ）。
  `use` に付くと項目の本体は検査される（`g_use_item_body`: `use` の E0304 と、項目の本体の E0401「expected `I32`, found `Bool`」）。
  5 行で候補を当てると、正しかった `lp~(x)` が `lp(x)` になり、E0401「expected `F32`, found `I32`」が残る（`fixloop.py c335496 g_item_flow_use`）。
- 案: 報告する側の規則は二つある。R1: ソースの順で後の宣言（片方がソースの外の名前（prelude、組込み型、組込みの flow の名前、子モジュール、依存のパッケージ）なら、このモジュールの宣言）。
  R2: 種類の順で後に引く側（本体は prelude・組込み → 項目 → `use`、名前空間は子モジュール → 項目、経路の頭は依存 → ルート直下のモジュール。同じ種類はソースの順で後）。R1 と R2 が違うのは 3 行だけ。
  - (a) R1 で報告し、先の側を残す（ソースの外の名前は先とみなす）。
  - (b) R2 で報告し、順で先に引く側を残す。
  - (c) R2 で報告し、残す側は、使う所の形で引き分けられる組では引き分け（名前空間で経路が続けば子モジュール、それ以外は項目。`~` の付く呼び出しとインスタンスは flow、他は関数）、引き分けられない組は (b) の順。
  - (d1) R2 で報告し、どちらも残さない。名前はその空間で誤りの名前（S-462 の黙らせる集合）にし、使う所と他のモジュールの経路に診断を出さない。報告した宣言の単位は今と同じく名前の段で止まる。
  - (d2) R1 で報告し、(d1) と同じく黙らせる。
