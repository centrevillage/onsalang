# S-955 外来の形がどの閉じにも閉じられない開き括弧を含むとき（`1..<f(2 => 3,` の後に閉じが無い）、形の範囲はどこで終わるか

- 空白: §18.1 は E0020 の主の範囲を外来の形の範囲（形を作る最初のトークンから最後のトークンまで）とし、形がどの閉じにも閉じられない開き括弧を含むときの最後のトークンを書いていない。範囲のパターンの端に閉じない `(` がある形（`1..<f(2 => 3,`）は、今は形の範囲がファイルの終わりまで延び、後の項目を全て含む（R-412。関数を並べると出力の字とメモリが二乗）。§2.4 の字句の並びは「閉じないリテラルや区切りで終わるときは、その開きの区切りまで」とする。
  読み: (1) 形の範囲はその開きの括弧まで（`1..<f(`）。(2) (1) に加え、種類の合わない閉じが閉じる形（`(` を `match` の `}` が閉じる）も開きの括弧まで。(3) 今のまま。誤りのあるファイルの報告だけで、通るプログラムは変わらない。
- 決定: 決定（2026-11-08、利用者。126 回目）: (1)。外来の形がどの閉じにも閉じられない開き括弧を含むとき、形の範囲はその開きの括弧までである（`1..<f(2 => 3,` の後に閉じが無ければ `1..<f(`。§2.4 の閉じないリテラルと同じ形）。種類の合わない閉じが閉じる形（`1..<f(2 => 3,` の後の `}`）は、閉じまでの今の範囲のまま。
  §18.1 に書いた。実装は W5-11 U10d: U10g の `foreign/guard.rs::form_at` の、最後のトークンをファイルの最後の記号に戻す節を消すと、範囲が開きの括弧で終わる（約 −5 行）。範囲の終わりを固定する事例（`1..<f(2 => 3,` と `n @ 1..<f(2 => 3,`。R-412 の補い）を置く。
  ガードの形の他の一覧の形で、範囲が閉じない括弧の中をファイルの終わりまで延びるものがあれば、同じ単位で形と費用を報告する。
- 経緯: 126 回目（2026-11-08）、W5-11 U10g/i（onsa-impl）が範囲の外で見つけた R-412 の直し方として、親が登録した。急ぎは W5-11 である。
