# S-1275 族: 添字の基の評価

- 空白: 添字 `xs[i]` の基 `xs` が場所（局所変数、`inout` の引数、フィールドと添字の経路）のとき、§3.5 の「`xs` の後に `i` を評価する」の「`xs` の評価」が何を含むか（場所を決めるだけか、基の値を読むか、基の中の添字の範囲の検査を含むか）を決める一般の規則。個々の形は S-1273（添字の中の変更がその基を書く形で、基の要素をいつ読むか）と S-1274（入れ子の添字で、基の範囲の検査と後の添字の式の評価のどちらが先か）。W8-03 の正規化の単位の前に決める（正規化が基の写しと検査の位置をこの規則で決める）。
- 決定: 決定（2026-11-28、利用者。194 回目、第 123 組。「ひとまずF4で。困るケースが出たら再考。」）: F4。基 `xs` の評価は中の添字の範囲の検査を含む（S-1274）。添字 `xs[i]` の `i` の評価の間に `xs` と重なる場所を変更すると E0702（S-1273。`xs` の場所は借用の引数と同じに数え、場所でない基は各末尾の場所、部分ビューは元の場所）。要素を添字の後に読むかは、通るプログラムから見えないので字にしない。今通る `self.voices[self.alloc!()].note_on!(n)` の類は E0702 になり、添字を先に `let` に取る形に直す。実用の書き方で困る形が出たら、場所の経路の基を通す F1′ へ緩めることを再考する（緩める向きは通るプログラムを壊さない）。仕様は §3.5 の添字と panic の箇条、§5.2 の E0702 の段落。実装は W8-03（sema の窓、解釈器と正規化の検査の順）で、R-531〜R-534 を同じ作業で閉じる。
- 経緯: 194 回目（2026-11-28）。W8-03 の設計メモ（onsa-impl）が S-1273 の形を、その独立の審査（onsa-advisor）が S-1274 の形を見つけ、親が族として登録した。下書き（onsa-gap）と独立のレビュー（onsa-advisor、段 1 は伏せた版から）がともに F4 を選び、段 2 は F1′ を対等に並べるべきとした。親が F4 と F1′ を値の表と実装の費用で並べ、利用者が F4 を選んだ。下書きの全文と入力は `target/notes/194/g123/`。
- 補い（2026-11-28、親）: 194 回目、W8-03 U3b の壊す側が、F4 で E0702 になる実用の形を挙げた: リングバッファの書き込み位置を `inout self` のメソッドで進める `self.table[self.advance!()] = x`（`advance!` が書くのは `self.ph` だけだが `inout self` は全体）と、乱数の状態を `self` ごと渡す `self.table[next_rand(inout self) % 4]`。直しは `let i = self.advance!()` を前に出す一行。リポジトリの中に当たる形は 0。Rust（rustc 1.94.1）は配列の同じ形を通し、`Vec` の形は E0499。利用者の判断（2026-11-28）: 「F4 のままで。もし直すにしても、F1′ 案は後の手当が大きいので、別の方法を考えたい。今はアイデアがないので F4 のままで良い。」。再考するときは F1′ でない別の方法を探す。入力は `target/notes/194/w803/u3b/b/p/pract.onsa`。
