# S-734 宣言をまたぐ循環（`use` の E0310、型の E0311、定数の E0312）の報告を、循環（強連結成分）ごとに一つにするか、循環の中の宣言ごとにするか、付ける宣言と note

- 空白: §4.4（型の循環 E0311）、§6.6（定数の循環 E0312）、§15.1（`use` の循環 E0310）は、循環を誤りとするが、循環に入った宣言（それぞれが診断の単位）のどれに、いくつ報告するかを書いていない。
  型別名の循環の数は S-730 で決める。この S は、それ以外の循環（struct と enum の値の循環、定数の初期化式の循環、`use` の循環）を同じ規則にするか。
  今の実装: `use` の循環の E0310 は循環ごとに一つ（第 68 組の下書きの S-730 の節）。型別名は書き方で数が変わる（`type C = D`・`type D = C` は二つ、`type A = (I32, B)`・`type B = (A, I32)` は一つ。`g68/parent/a.onsa`）。
- 決定: 決定（2026-10-28、利用者が ID を挙げて了承。確認だけ。79 回目、第 70 組）: (a)・(n1)。
  宣言をまたぐ循環（`use` の E0310、型の E0311、定数の E0312、flow のインスタンスの E0817（S-742））は、互いに辿り合う宣言の集まりごとに一つで、位置は診断の並べ方で最初の宣言の名前（E0310 は集まりの中に依存を持つ最初の `use`）、集まりの他の宣言は位置付きの note で示す。集まりの外から使う宣言には出さず、誤りの型・誤りの値として扱う。S-730 の文の当てはめで、(n2) は E0310 だけの例外になるので採らない。
  E0312: 循環の定数は評価せず誤りの値とし、それを読む定数と型の中の長さには診断を出さない。E0312 を付けた定数の単位は名前の段で止まり（§18.1）、集まりの他の定数の単位はそれぞれ検査する（型は宣言に書くので値に頼らない。`B = A + "s"` の E0401 は出る。79 回目の文書の点検の F7 で、§18.1 に合わせて言い方を改めた）。モジュールをまたぐ定数の循環は E0310 だけでよい。
  E0310: 数と位置は今の実装のまま。note に集まりの他の `use` の位置を足し、狭めて切れる `use` には狭め方を添える（`names/cycles.rs::cycle`、約 +3〜5 行）。
  仕様は §18.1 の単位の段落に規則を一か所で書き、§4.4（E0311 の段落を指しに縮めた）・§6.6・§15.1・§11.5 から指した。`tasks/diag-codes.md` の E0310・E0311・E0312 の行に足し、E0312 の段を名前解決に揃えた（`codes.rs` は既に Names）。
  実装は W4-05 の U4（R-02・R-182・R-303 と同じ所）: 定数の依存のグラフ（`BodyNames.paths` の定数と関連定数）から `cycles.rs::components`、位置と note で約 +5〜10 行。
  事例 `tests/spec/packages/cycle/a.onsa`・`cycle_below/a.onsa`・`cycle_dir_only/dsp/synth.onsa` の頭のコメント（「仕様は数も位置も決めていない」）を改める。`tests/pending.toml` の E0312 の事例は最初の定数の行だけに `//~ E0312`。
