# S-1088 部品の中の遅い刻みを、呼び出し側の同じ比の段に入れるか（`ctl~(avg_down32~(x)).down~(32)`）

- 空白: §11.9 は同じ位置の遅い刻みと `sample` の刻みの順（S-578）を書くが、修飾子の無い部品の中の遅い刻み（std の `avg_down32` は中で `.down~(32)` の変換の flow を動かす）を、呼び出し側の同じ比の段に呼び出しの位置で入れるか、部品を `sample` の段でまとめて動かすかを書かない。
  後者では `lin_up32~(ctl~(avg_down32~(x)).down~(32))`（§11.9 の例）の `ctl` が一つ前の平均を読み、32 サンプル余分に遅れる。出す値が変わる。W7-02 の計画の表の形（flow ごとの段の入口）に効く。
- 決定: 決定（2026-11-16、利用者。157 回目、第 105 組。「遅い刻みの件は余分な遅延がない方で」）: 部品の中の遅い刻みは、呼び出し側の同じ比の段に呼び出しの位置で入る（`init`・`block` の段が部品をまたいで巻き上がるのと同じ）。例の `ctl` は同じ位置で新しい平均を読み、余分な遅れは無い。W7-02 の計画の表は flow ごとに段の入口を持つ形にする。仕様は §11.9 の集めて配る時点の段落。
- 経緯: 157 回目、2026-11-16、第 105 組の段 1（onsa-advisor）が論点の抜け（または下書きの新しい S の候補）として挙げ、親が登録した。
- 補い（2026-11-18、親）: 165 回目、W7-02 を閉じるときの文書の点検: 決定の「W7-02 の計画の表は flow ごとに段の入口を持つ」は、W7-02 のクロックの表現（`Ratio`、`ClockFrame` は常に `Ratio(0)`）までで、段の入口の表は W7-09（クロックごとの段）と W7-16 が作る（親）。
- 補い（2026-11-18、親）: 166 回目（2026-11-18）、W7-08 の設計メモ（`target/notes/166/w708/`）の案 B を利用者が了承した（「表を作るタイミングは提案の通り」）: W7-08 は段の入口の表を作らず、今の三つの関数（`init`・`ctl`・`tick`）のまま段ごとの読みを計画の問い合わせ（`crates/onsa_sema/src/flow/plan/stage.rs`）から受け取る。表は W7-09 か W7-16 のうち最初の読み手が作る（W7-09 の設計メモで決める）。`tasks` の W7-08 を W7-09 に替えた（親）。
