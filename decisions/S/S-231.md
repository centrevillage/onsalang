# S-231

- 空白: 変換先の型を扱える変換と丸めの書き方。総称の `T: Float` へ `U32` などを変換する書き方が無い（`F32` は `round_f32()`、`F64` は `as`）。`vdelay` の疑似コード（S-212）は記法の前置きで済ませたが、`round_f32()` は行き先の型を名前に書くので、総称のコードでは見た目と中の型がずれる。
  利用者は、違和感のない記述にできる言語機能か関数を決めたい（2026-10-08）。制約は §3.3 の「型の組ごとに書き方は一つ」で、具体的な型で `as` と二通りにならない形。std.math の `round[T: Float](x: T) -> T` は同じ型への丸めで別物。関連は `api-candidates.md` の A-09（総称の整数の変換）
- 提案: 空白の流れ（`rules/process.md` 8.6）で下書きと独立のレビューに回し、W5-02（`as` と変換の型検査）の着手の前に決める。
  事前検討（2026-10-08）: 利用者の案 (A) `x as(round) F64`（変換と丸めを `as` の方式で書く）と、(B) 変換先の型の関連関数 `T.round_from(k)`・`I32.trunc_from(y)`・`I8.narrow_from(x)`（前例は `F32.from_bits(u)`）を比べ、利用者は「新しい言語規則が無い (B) が今の言語の表現の範囲では良い」とした。
  (A) は範囲外の扱い（`Option` を返す縮小）が `as` の書いた型とずれ、二項演算子の被演算子に括弧が要る。どちらも、情報を失わない組（`U32` → `F64`）の書き方は fmt が `as` に揃える。呼び出しの位置で型を明示する書き方は S-239
