# S-231 変換先の型を扱える変換と丸めの書き方（総称の `T: Float` へ `U32` などを変換する形）

- 空白: 変換先の型を扱える変換と丸めの書き方。総称の `T: Float` へ `U32` などを変換する書き方が無い（`F32` は `round_f32()`、`F64` は `as`）。`vdelay` の疑似コード（S-212）は記法の前置きで済ませたが、`round_f32()` は行き先の型を名前に書くので、総称のコードでは見た目と中の型がずれる。
  利用者は、違和感のない記述にできる言語機能か関数を決めたい（2026-10-08）。制約は §3.3 の「型の組ごとに書き方は一つ」で、具体的な型で `as` と二通りにならない形。std.math の `round[T: Float](x: T) -> T` は同じ型への丸めで別物。関連は `api-candidates.md` の A-09（総称の整数の変換）
- 提案: 空白の流れ（`rules/process.md` 8.6）で下書きと独立のレビューに回し、W5-02（`as` と変換の型検査）の着手の前に決める。
  事前検討（2026-10-08）: 利用者の案 (A) `x as(round) F64`（変換と丸めを `as` の方式で書く）と、(B) 変換先の型の関連関数 `T.round_from(k)`・`I32.trunc_from(y)`・`I8.narrow_from(x)`（前例は `F32.from_bits(u)`）を比べ、利用者は「新しい言語規則が無い (B) が今の言語の表現の範囲では良い」とした。
  (A) は範囲外の扱い（`Option` を返す縮小）が `as` の書いた型とずれ、二項演算子の被演算子に括弧が要る。どちらも、情報を失わない組（`U32` → `F64`）の書き方は fmt が `as` に揃える。呼び出しの位置で型を明示する書き方は S-239
- 時期: W5
- 決定: 決定（2026-11-04、利用者。111 回目、第 82 組。下書きと伏せた独立のレビューの段 1 が一致、段 2 は省いた。下書きは `S-231.draft.md`）: (b)。変換先の型の関連関数で書き、今の変換メソッド（`round_<型>`・`trunc_<型>`・`trunc_<型>_sat`・`narrow_<型>`）は外す。
  名は `round_from`・`trunc_from`・`trunc_sat_from`・`narrow_from`（全ての変換が `_from` で終わる）。
  std の組込みの型の `impl` に、浮動小数 2 型の `round_from[S: AnyNum](x: S) -> Self`、整数 8 型の `narrow_from[S: Int](x: S) -> Option[Self]`・`trunc_from[S: Float]`・`trunc_sat_from[S: Float]`（26 個）。
  数の trait の `Float`・`Int` にも同じ名（W5-05 で trait の項目に）。変換元と変換先がどちらも具体的な型（別名は解決した型）で `as` で書ける組なら E0413（候補は `as` の形、`narrow_from` は S-875・S-880 の期待の型の規則）、同じ型への呼び出しも E0413（候補は呼び出しを外す形）、片方が型パラメータなら通す。
  今の名は候補なしの E0413（リリース前の書き方は候補の対象にしない）、リポジトリは台本で書き換える。
  E0411 の候補は新しい形（`k as F32` は `F32.round_from(k)`、浮動小数から整数は `trunc_sat_from` と `trunc_from` の二つ、整数の縮小は候補なしで note に `narrow_from`、型パラメータの `k as T` は `T.round_from(k)`）で、`as` の式の全体を置き換える（R-239 の括弧の手当ては要らない）。
  S-210 の「`x: F32` の `x as T` には候補を出さない」はこの決定で改める。A-09 はこの決定の一部（範囲外は `Option` だけ、置き場所は `Int`）。§11.4 の疑似コードの前置き（S-212）を外して書き直す。
  作業は W5-14（置き換えの単位を U2b2 の後、U2a の前）、W5-05（型パラメータから引く道と trait の項目）、W7-07（§11.4 の写し）。新しく S-881（総称の浮動小数のコードの小数の定数）と A-17（総称のビット表現）。仕様 §3.3・§6.3・§11.4 ほか
- 補い（2026-11-02、親）: X-23（W5 の見積もり）で、期限を W5-05 にした（型パラメータの関連の名前を引く道を作る作業。組込みの行は W5-02 の表に後から足せる）。上の「提案」の W5-02 はこの改めの前の文。
- 補い（2026-11-04、利用者）: 111 回目、期限を W5-05 の前から W5-14 U3 の前に早めた（親の提案を利用者が了承）。(B) を採ると今の変換メソッド（`trunc_<型>()`・`narrow_<型>()` など）を変換先の型の関連関数に置き換えるかが論点になり、W5-14 U3 は E0411 の候補としてそのメソッドの名を書くため。A-09（総称の整数の変換）も同じ組で決める。U2a（`as` の形の候補）には影響しない
- 補い（2026-11-04、親）: 同じ日、上の補いの「U2a（`as` の形の候補）には影響しない」は誤り（第 82 組の下書きが指摘）。今の変換メソッドを置き換える案では、U2a の E0413 の入力（`x.round_f64()` などの `as` で書ける組の形）も新しい形に変わる（候補の期待の `as` の形は変わらない）。影響しないのは今のメソッドを残す案だけ。
  また、事前検討の「情報を失わない組の書き方は fmt が `as` に揃える」は、型を見ない fmt（`spec/tools.md` §3.3）では作れず、揃える役は E0413 の候補と `onsa fix` になる。呼び出しの位置の型引数（S-239）は決定済み（`::[…]`）
- 補い（2026-11-04、親）: 仕様の反映の差分の案（`target/notes/111/g82/spec_patch.diff`・`spec_patch_notes.md`、W5-14 の置き換えの単位と同じコミットで当てる）で、決定から読みが一つに決まる派生の文を親が決めた: §11.4 の疑似コードの `1.0` も `T.ONE` にする（§6.6 でリテラルは `T` の値にならない）、§3.4 の関連関数の閉じた一覧に `default()` を入れる（§6.3 の `Default` と食い違わないため）、境界の無い型パラメータの `as` の E0411 は候補なし（変換の関連関数を持たない）。作業票の「§5.2」の例は §5.3 の表、「§11.6」の例は §11.5 にあった
