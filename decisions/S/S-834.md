# S-834 属性の引数に、属性の引数として読めない字（`@fp(true)`・`@fp(1)`・`@export(1)`）を書いた形のコード: 今の E0002「expected attribute argument」か、§6.5 の値の誤りの E0005 か

- 空白: §6.5 は「`@repr` と `@fp` の値の誤り（`@repr(rust)`、`@fp(fast)`）と `@host` の種類の誤りは E0005 で、修正候補は一覧の値」「`@export(…)` は E0005 で、修正候補は `@export`」とするが、属性の引数として読める字の形を書かない。
  今は、識別子と文字列の引数（`@fp(fast)`・`@fp("relaxed")`）は E0005 と候補 `@fp(relaxed)`、`true` と数の引数（`@fp(true)`・`@fp(1)`）は構文の E0002「expected attribute argument, found …」で候補なし（96 回目に親が `P96/bin/onsa-e611775` で確かめた）。
  W4-02 の U1 で `@export` が属性に入ると、`@export(1)`・`@export(true)` が E0002 か E0005（候補 `@export`）かも同じ問いになる（テストの担当は事例に書かなかった）。
  読みは (1) 読めない字は構文の誤り（今のまま、E0002） (2) 括弧の中が何でも値の誤りとして E0005 と §6.5 の候補 に割れる
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: 既存 §6.5）一覧の値を取る属性（`@repr`・`@fp`・`@host`）と `@export` の括弧の中は、閉じた括弧の中のトークンによらず値として扱い、一覧の値でなければ §6.5 の値の誤りの E0005 で、候補は一覧の値（`@export` は括弧を除く形）。括弧が閉じていなければ E0002。鍵の付く属性（`@param`・`@latency`）の項として読めない引数（`@latency(1)`）は今のまま E0002（この S の外）。
  - 仕様の節: §6.5 の値の誤りの段落に二文。
  - 今通るプログラムが変わるか: 変わらない。コードと候補だけ（`@fp(true)`・`@fp(1)`・`@fp(1.5)`・`@fp(-1)`・`@fp('c')`・`@fp(())`・`@fp(1 + 2)`・`@fp(f(1))`・`@repr(1)`・`@export(1)`・`@export(true)` が E0002 → E0005。`@fp(relaxed strict)` は今の `,` の挿入の候補の E0002 から E0005 と `@fp(relaxed)` に）。
  - 実装の見当: `onsa_syntax/src/parser/items.rs` の属性の引数の読み（178 行の辺り）で、一覧の値の属性と `@export` は括弧の中を釣り合う括弧まで読み飛ばし、`attrs.rs` の `check` に値の範囲を渡す。約 15〜30 行。
  - ぶつかる既存の事例: `git grep` で「expected attribute argument」を期待する事例は見つからない（`tests/cst/lex_delimiters.onsa` は CST の事例で診断を見ない）。
- 経緯: 96 回目（2026-11-01）、W4-02 の U1 のテストの担当（onsa-test）が `NEW` として報告し、親が `@fp` で同じ形を確かめた。今の実害は小さい（候補が無いだけ）。関係: S-639、S-510
