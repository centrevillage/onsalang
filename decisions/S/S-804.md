# S-804 使えなくなった束縛を見出しに置いた `match` の腕が複数あり、腕ごとにパターンが読む経路が違う形（`match hh { Holder { buf: bb, n: _, m: 0 } => …, Holder { buf: _, n: 0, m: _ } => …, _ => 0 }` の後の腕だけが `hh.n` を読む）

- 空白: §7 の 55 行（S-803 の補い D2）は、`match` の見出しに置いた束縛かその経路を「パターンが読む要素の経路の使用」とするが、腕が複数で、腕ごとにパターンが読む経路が違う形（`w.h.n = 5` の後の `match hh { Holder { buf: bb, n: _, m: 0 } => len_of(bb), Holder { buf: _, n: 0, m: _ } => 1, _ => 0 }`。`hh.n` を読むのは二つ目の腕のパターンだけで、一つ目の腕が合えば読まない）で、どの腕のパターンの読みを数えるかを書いていない。
  見出しは一度評価し、腕のパターンは合う腕まで順に試す。どの腕が試されるかは値で決まり、静的には全ての腕が試されうる。
  読み: (1) 全ての腕のパターンが読む経路の和を見出しの使用とする（一つでも変更と重なれば E0704）。(2) 腕ごとに判定する（実行時の値で決まる腕だけを数えることは静的にできないので、(1) と同じになるか、腕ごとに診断を分けるか）。
  親の読み（確認だけの案）: (1)。静的にはどの腕も試されうるので、和が唯一の安全な読み。仕様の文は変えない（「パターン」は見出しの全ての腕のパターン）。U4b-1 の実装で和にする。
  見つけたのは W4-07 U4b のテストの票（t4）。事例は書いていない。再現は `target/notes/89/s804/multi_arm.onsa`（dev は §7 の検査が無いので通り、U4a を一時につないだ新しい modes は束縛の単位で `match hh` を E0704）。
- 決定: 決定（2026-10-30、利用者。89 回目。確認だけ。親の読み）: (1)。腕が複数の `match` の見出しに置いた束縛かその経路の使用は、全ての腕のパターンが読む経路の和で、一つでも変更と重なれば E0704（見出しの式の位置。文面は読んだ経路、その経路を読む最初の腕のパターンの要素に note）。静的にはどの腕も試されうるため。仕様の文は変えない（§7 の 55 行の「パターン」は見出しの全ての腕のパターン）。担う作業: W4-07 U4b-1。
- 経緯: 89 回目（2026-10-30）、W4-07 U4b の S-803 の事例のテストの票（t4）の担当が D2 の直しの中で報告した。親が登録した。
