# S-506 宣言の本体と `match` の本体の `{ }` の 1 行の形と継続形

- 空白: 宣言の本体と `match` の本体の `{ }`（struct のフィールド、enum の列挙子、`match` の腕、impl・handler のメンバ）を 1 行の形と継続形に書いたときの正規形（`struct P { x: F32, y: F32 }`、`enum E { A, B(F32) }`、`match v { E.A => 1, E.B(x) => 2 }`）。
  §3.2 は struct リテラルとパターンの `{ }` の内側に空白を一つ置くとし、並びは三つの形のどれかとするが、本体の `{ }` を名指ししない。今の fmt は入力のまま（内側に空白一つ、継続形は最初の要素の下に揃う）。W3-11/t（U2）が見つけた（2026-10-13）
- 提案: 決定（2026-10-13、利用者が ID を挙げて推奨の (2) を了承。下書きと Fable が一致、第 29 組）: struct リテラルと同じく三つの形を認め、1 行の形と継続形の内側に空白を一つ置く（S-496 の 1 行の `{ }` の規則）。項目の本体はブロックと同じく、メンバ一つの 1 行か複数行。
  理由: §3.2 の並びの箇条は列挙子と `match` の腕を名指しし、三つの形を持つことは既に決まっていた（常にブロック形にする案は既決に例外を足す）。`match` は `if` と同じ式で、1 行の `if` と見た目を揃える。出力は今の fmt と同じ。`spec/tools.md` §3.2。実装は W3-11 の U2（表の SPEC-GAP を外す）と U3
