# S-862 第二級の型（`Span`、平面の配列の要素）が、推論した型引数として型パラメータを具体化する形が通り、返り値として外に出る（`fn id[T](x: T) -> T` の `id(s).len()`）

- 空白: §5.3 は第二級の型（`Span`、`Span` の配列、平面の要素）を引数の位置だけに置き、返り値などを E0710 にする。§4.5 と S-766 は、第二級の型を型引数に「書いた」所を位置の E0710 にする。§5.2 と S-809 は、第二級の関数値を宣言の型が関数型でない引数（総称の `x: T`）へ渡すと E0710 とする（理由は「型パラメータの本体は値を写して持ち出せる」）。
  推論した型引数が第二級の型になる形（`Span` の値を総称の `x: T` に渡す、平面の配列を `xs: [T; N]` に渡して `T` が `Span[F32]` になる）は、どの文も書いていない。
  今は通り、返り値として外に出る: `fn id[T](x: T) -> T { x }` の後の `fn f(s: Span[F32]) -> U32 { id(s).len() }`、`fn first[T, const N: U32](xs: [T; N]) -> T { xs[0] }` の後の `first(xs).len()`（`xs: [Span[F32]; 2]`）、`fn m[T, const N: U32](xs: [T; N]) -> U32 { N }` の `m(xs)`。
  設計メモの見当では、種の判定で `kind_of` が `None` の型を満たすとする所（`body/bounds.rs` の `meets`）が `Span` を `Dup` として通す。
  `Span` は関数値と違い、借用の行なら `let` に束縛できる（S-217。理由はヒープでなくライフタイムの要否）。
  読み: (1) S-809 の関数値と同じく、`Span` の値（と第二級の型を含む値）を型パラメータの引数へ渡すと E0710。(2) 推論した型引数は第二級でもよく、本体の中の扱い（返す、保存する）だけを止める。(3) 今のまま通す。(1) と (2) は今通るプログラムを誤りにする。
  W5-02 との関わり: 設計メモの推奨では、std の配列の `len` を `impl[T: ?Dup, const N: U32] [T; N]` に書くので、平面の配列で `T` が `Span[F32]` になる（§5.3 は平面の配列の `len` を約束する）。(1) に決まれば std の配列のメンバを例外にする。
  再現は W5-02 U1 の設計メモの `infer2nd.onsa`・`planar2.onsa`（106 回目の scratchpad の `w502/u1/probe/`、写しは `target/notes/106/w502u1/probe/`）
- 決定: 決定（2026-11-03、利用者。106 回目）: (1') と、後の版で入れる印 `?Escape`（案 K）。
  推論で決まった型引数（項目の型パラメータと、`Buf.zeroed(2)` などの組込みの総称型の要素の型）も、書いた型引数（S-766・S-771）と同じく、`?Escape` の無い型パラメータが第二級の型か、それを含む型に決まれば E0710 にする。
  位置は型引数を作った式（呼び出し、メソッドの呼び出し、struct リテラル、列挙子、組込みの関連関数）で、後の文で決まったときは型を決めた式を位置付きの note で示す（E0416 と同じ位置の規則、§4.5）。型引数の要求（E0416）は判定しない。修正候補は無く、note で `Span` を総称で受ける形（`xs: Span[T]`・`[Span[T]; N]`）を示す。型の段で、同じ型引数の要求より先に判定する。
  K: 型パラメータには暗黙に `Escape`（値を関数の外へ持ち出せる）の要求が付き、`T: ?Escape` で外す（`?Dup` と同じ形。Swift の `~Escapable`）。種でなく値の性質の印で、§4.6 の「第二級の型は種を持たない」は変えない。
  `?Escape` の型パラメータは第二級の型でも具体化でき、その値は本体の中で第二級である（返す・保存する・捕捉する・`move` の引数は E0710、`T` を返り値・フィールドなどに書いた宣言も E0710）。借用の行の束縛（S-217）はその値にも当てる。
  第二級の型で具体化したときは、種の制約（暗黙の `Dup`、`Copy`）は満たすものとして扱い（呼び出しの中では写せるビュー）、trait の境界は判定する（`T: ?Escape + Show` に `Span` は E0416。判定しないと降下で実装が無い）。第一級の型には暗黙の `Dup` が残り、Affine も受けるには `?Dup + ?Escape`。第二級の関数値（S-809）はこの印の外で、別に考える。
  細部（A1〜A6、利用者が了承）: `Escape` は prelude の名前で、`Copy`・`Dup` と並ぶ（同じ名前の宣言は E0304、§15.1）。この版では境界の `?Escape` は E0200（名前を予約した未対応の機能）。S-711 の「`?` は `Dup` だけ」を「`Dup` と `Escape`」に改め、他の名前は今のまま E0416。
  配列の `len` は W5-02 では今の組込みの表の行のまま残し、W5-17 で std の `impl[T: ?Dup + ?Escape, const N: U32] [T; N]` に移す。
  名前は、利用者が「どれも分かりやすくはないが、良い案が無いので」として `Escape` にした（`Keep`・`Store` と比べた）。
  理由: (3) は §5.3 に反する。C の後端は既に `Span` で具体化した関数と構造体を生成し、元の値を消費した後にビューを読む形が検査を通る。(2) は呼び出しが通るかを呼び先の本体で決め、P1 に反する。
  (1') の位置は、`Span` の値を渡さずに型引数が決まる形（関数型の引数だけで決まる）と後の文で決まる形にも当たり、E0416 の仕組みに乗る。
  K は、一つの定義でチャンネルの配列とスカラーの配列の両方を受ける反復の処理（利用者が定義する `for`・`par`・`ser` のような高階の関数）に要る（`[Span[T]; N]` で受ける形は今も書けるが、`[F32; 4]` は受けない）。
  K を最終的に入れる前提で、手戻りが最も少ない時期として、決定は今、実装は W5-02 の後の W5-17 にした（今は (1') と E0200 の 25〜45 行。後で消すのは E0200 の分岐と `len` の表の行だけで、書き直す仕様と決定の文は無い）。
  値の性質の印にしたのは、S-766・S-771・S-217 の理由を書き直さずに済み、後で第二級の関数値も同じ印に入れられ、`bounds.rs`（W5-05 の R-127）に触れないため。
  仕様 §4.5（新しい箇条）、§4.6、§5.3、§15.1、`tasks/diag-codes.md` の E0200・E0710。実装は W5-02 の U5（(1') と E0200）と W5-17（K）
