# S-1221 細部: 外の when~ が止めている間に、内の修飾子の条件を評価するか（値は変わらず panic の有無と順だけ。仮は評価する）

- 空白: `x.when~(a).down~(4).when~(b)` のように外の `when~` が受け手を止めている間に、内の修飾子（`when~`・`reset_if~`）の条件を評価するか、§11.10 の字に無い。値は変わらず、条件の式の panic の有無と順だけに見える。再現は `target/notes/179/w710/memo/probe_cases.txt` の `g2_inner_cond_panics`（今は E0200）。
  仮の扱い: 止まっている間も評価する（頭の引数と `block` の段は止まっている間も評価する、§11.10。境界の内の修飾子の条件は頭の入力と同じ時点の値を読む）。S-1206 と同じ族の細部。
  同じ族（W7-10 U2b の実装の担当が挙げた、181 回目）: 一つの連鎖の二つの修飾子の条件を評価する順も §11.10 の字に無い（字の順か、段の順か）。`x.when~(c).reset_if~(r)`（x に遅い段が無い）は今 r を c より先に降ろし、`when~` の内の `reset_if~` は外の `when~` の条件の後に読む。これも panic の順だけに見える。仮は今の挙動で、U2e の参照評価器も同じ順を取るかで確かめる。
  補い（2026-11-24、親、182 回目）: S-1228 の (P) で、`x.when~(c).reset_if~(r)` の二つの条件を降ろす順が x の遅い段の有無で分かれる形（案 L の境）は無くなった。順は「段の順、同じ段では外の修飾子の条件が先」（R = W なら頭の遅い段の有無によらず r が c より先）で、W7-10 の (P) の単位で評価器も同じ順に揃えた。境界が集める条件（ポート）の順は、評価器では頭の引数の後に内から並ぶ（`port_exprs`）ままで、panic の順だけに見える。
