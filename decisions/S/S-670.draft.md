# S-670 族: §15.2 の `target` 宣言の本体と std だけの形

- 決定済みで戻さないもの: 利用者の `target` 宣言はこの版で E0200（D-07）。std の `target` 宣言は `bind` で差し替えられない（S-69 (4)）。
  組込み型のメソッド・関連関数・関連定数を std の `impl` に `target` で宣言する（D-07 の追記）。std の特権は名前の段より後で役割を読む（R-88 (1)、`design/03-types.md`）。
  一つの使用への E0200 は一件（S-309）。S-108 の意味（組込み型はプリミティブ、それ以外の型は本体）。`Float` は組込みの浮動小数だけ（E0307）。
- 論点: §15.2「std の `target` 宣言は、本体を持てる（std だけに許す書き方）」と、D-07 の追記の `impl F32 { pub target rt fn to_bits(self) -> U32 }` が、std だけの形を二つ定める。
  どちらも、利用者が同じ形を書いたときの段とコードを書いていない。今の構文の段は、std でも両方を拒む（今の std のソースには、どちらの形も無い）。
  - 族の問いは二つの軸に分かれる。(1) std の本体をどの形で書くか（S-669）。(2) std だけの形を std の外に書いたとき、どの段のどのコードで止めるか（この項目の案）。
    S-629 と S-661 は (2) の問いで、答えの中身は (1) で変わる（下の二つ目の表）。
  - 仕組みの出所と目的:
    - `target` は 0.1 の `virtual`（`history/kumi-lang-spec.md` §13.2）を 0.2 で改名した語で、「実装をビルドターゲットが与える宣言」をそのまま名前にした（`history/onsa-0.2-changes.md` の 48 行）。
      利用者の実装は、マニフェストの `bind` で実装モジュールを割り当てる（OCaml の dune の virtual library が手本、§15.2）。
    - std の `target` 宣言は、std の数学の関数などのプリミティブを Onsa のソースで宣言する形として D-07（2026-10-01）が決めた。
      `extern "C"` にすると核が C 系の外へ出せず、組込みの名前にすると `onsa primer --std` と `interface` に出すものを別に持つからである。利用者の `target` 宣言は、第 1 期に `bind` が無いので E0200 とした。
    - 本体は S-108（2026-10-06、点検 C-16）で入った（S-669 の項目）。std だけとした理由を仕様は書かない。読める理由は、std の `target` 宣言は処理系が与えて `bind` が無く、本体はプリミティブの無い型のための実装だという点である。
    - 構文の段は M1 から、`target fn` を extern のメンバと同じ読みで読み（`parse_target` が `parse_fn(ItemCtx::Extern)` を呼ぶ）、`{` を「takes no body」の E0002 にする。どのパッケージのファイルかを知らない（`onsa_syntax::parse(file, text)`）。
- 今の実装: 試した入力は `target/notes/65/g55/probe/`（`other/` は他言語）と前の組の `target/notes/64/s629/probe/`・`probe2/`。バイナリは dev `03d01e0` のビルドの写し。`check` は特に断らなければ終了コード 1、修正候補は無い。
