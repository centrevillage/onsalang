# S-851 手書きの `impl Default for Ty` のメンバ（`default`）が型の名前の後の `.` の空間に入るか、固有の `impl` の同名のメンバと E0304 か

- 決定済みで戻さないもの: derive と手書きの `impl` の E0304（§6.4）。同じ型への同じ trait の二つの `impl` の E0304（§6.3）。固有のメンバどうしの E0304（§6.2）。関連定数は `UPPER_SNAKE`、関数は `snake_case`、列挙子は `UpperCamel` なので、`default` と重なるのは関数だけである（S-737）。
  第 88 組の下書きの写しは `target/notes/117/g88/draft.md`、入力は `P117/g88/probe/`（消えうる）、段 1・段 2 の答えは `target/notes/117/g88/advisor/`、親の入力は `target/notes/117/g88/parent/`。
- 論点: §6.2 の「型の名前の後の `.` で引く名前（メソッド、関連定数、enum の列挙子）は一つの空間」は、固有の `impl` のメンバを主に書いた文で、trait の `impl` のメンバと derive が作るメンバを入れるかを明示しない。`P.default()` を §6.3 が書くので、`default` はこの `.` で引く名前ではある。
  - 出所:
    - §6.2 の一つの空間は S-737（列挙子と関連定数）と S-134（同じ型の `impl` の同名のメンバ）である。S-737 の理由は、`E.A` が両方を指すと片方に届く書き方が無いことで、同じ型の名前の後の `.` の読みを一つに決めるためである。
    - §6.2「`impl` 内の関数はドット記法でのみ呼ぶ。同じ関数に二つの呼び方は無い」。S-748: 見出しが E0307 の固有の `impl` のメンバもこの空間に入る。
    - §6.3「`Default` は関連関数 `default() -> Self` を持つ。具体的な型では `P.default()`、総称の関数では `T.default()`」。trait の名前を前に書く形は無い（`Default.default()` は E0308、`d12` と `tests/spec/module/dot_after_trait_name.onsa`）。呼び分ける構文が無い。
    - §6.4: derive と手書きの `impl` の重なりは E0304（S-34）。

- 案:
  - (a) 一つの空間: trait の `impl` のメンバと derive が作るメンバは型の名前の後の `.` の空間に入り、固有のメンバと同名は E0304 である。§6.2 の文をそのまま読む形で、新しい規則は足さず、括弧に一句を足す。
  - (b) 別の空間で固有が勝つ: `Mode.default()` は固有を指し、`T.default()`（`T = Mode`）は trait を指す。
  - (c) 別の空間で trait が勝つ: `Mode.default()` は trait を指し、固有は `.` では届かない。
  - (d) 別の空間で、両方あれば使う所で誤り: 宣言は通り、`Mode.default()` は新しいコードの誤りである。呼び分ける形が要る（例: `Mode.Default.default()`）。
  - 「何も足さない」は (a) に当たる。§6.2 の文を変えずに実装の読みだけ決める形も (a) と同じ結果である。
  - 形ごとの出力（`d09` の入力）: (a) `impl Mode` か `impl Default` の後の宣言の `default` に E0304。(b) 通り、`Mode.default()` は `Mode.On`、`T.default()` は `Mode.Off`。(c) 通り、どちらも `Mode.Off`。(d) `Mode.default()` に誤り、`T.default()` は `Mode.Off`。
  - 書き手から見て（LLM を含む）: Rust の書き手は `impl Default` と固有の `new` を並べるが、固有の `default` を書く形はまれである（同じ名を両方に置く理由が少ない）。(a) は宣言で 1 回止まり、どちらかを消すか改名する。(b) は検査を通り、具体的な型と総称で値が変わる。読み手が気付かない。(c) は固有の関数が呼べず、黙って死んだコードになる。(d) は呼び分けの構文を覚える。
  - 修正候補（§18.1）: (a) は今の E0304 と同じで候補なし（どちらを残すかが一つに決まらない）、note で前の宣言を示す。止まり方は `no-candidate` である。(b)・(c) は誤りが無い。(d) は呼び分けの候補が読みごとに二つになる。
  - 通るプログラム: `d03` の形（`struct P: Default` と固有の `default`）は今通る。(a) で E0304 になり、(b) は今のまま通り、(c) は `P.default()` の値が変わり、(d) は使う所が誤りになる。事例は 0 件である（上の検索）。`Ordinal` の形は今 E0200 に隠れているので通るプログラムは無い。
  - 規則と例外: (a) は §6.2 に一句で、例外を足さない。(b)・(c)・(d) は「`.` の名前は一つの空間」に、trait のメンバの例外と解決の順の規則を足す。(d) は加えて構文を一つ足す。
    字面の揃い: (a) は列挙子と関連定数（S-737）と同じ形である。(b) は同じ字面 `.default()` が総称と具体的な型で別のものを指す形を作る。
  - 別の所に既に同じ形があるか: (a) の「第 2 期に二つの trait の同名を書けない」費用は、`Add.add` と固有の `add` の形として第 2 期に出る。今の言語には trait の同名は無い。(b) の値の差に当たる形は言語に無い。
