# S-562 イベントを修飾子の条件に使うこと

- 決定済みで戻さないもの: S-558（`when` のクロックは K の刻みのうち条件が真の刻み、保持と `T.default()` と E0816、引数は止まっている刻みも評価、`block` の段は毎回評価）。S-559（動く前に初期化、外側の `reset_if~` は止まっている刻みにも効く、範囲は生成する `reset` と同じ、水準で読む）。
  S-559 の回答の補い（イベントを条件にすると、真になるのはイベントの刻みだけなので、初期化はイベント一つに一回）。S-557（合成）。S-555（受け手は flow の呼び出しか修飾子の連鎖）。
- 論点: 記号: E(e) は「イベントの入力 `e` のイベントの刻み」を指す説明の記号で、Onsa の構文ではない。入力の番号（p01 など）は、47 回目に dev `4aaa028` の release の `check` で試した入力（S-560 の「今の実装」の表）。
  §19.1「入れるときに決めること: イベントのクロックの値を `when` / `reset_if` の条件に直接書けるか（その刻みにイベントがある）」。§19.1「`c` は `Bool` で、クロックは呼び出し側のクロック以下である」「呼び出し側は x の出力を K の刻みごとに読み」。
  - (1) 条件にイベントの値をそのまま書くか、`Bool` に変えるか。(2) イベントで動くインスタンスの K、引数、出力の読み方。同じ位置の複数のイベントで複数回動くこと。(3) イベントの条件の `reset_if~` と、同じ位置の二つのイベント。MIDI の Start / Stop / Continue の書き方。
- 今の実装: 修飾子は無い（p11 の `reset_if~` は E0812）。`at event` は E0302（p01）。常に真を返す総称の `rt fn` は書ける（p16）。
- 案:
  - (1a) 条件は `Bool` のままで、そのクロックにイベントのクロックを許す（`starts(tr)`、`is_on(n)` のようなイベントの値の関数の結果）。全てのイベントで動かすには、常に真を返す std の関数（`present(e)`。結果のクロックは引数のクロック、§11.5）を通す。
    実装: 修飾子の条件のクロックの検査に一つの場合を足す。費用の要因: std に関数が一つ。
  - (1b) `Bool` か、`Bool` でないイベントの値（あれば真）。`x.reset_if~(start)` と書ける。費用の要因: 型で読みが変わる（`Bool at event` の入力は値で、他の型は有無で読む）。
  - (1c) イベントの値は修飾子に書けない。std の flow で `Bool at sample`（その位置にイベントがあれば真）に変えてから書く。実装は無い。インスタンスは `sample` の刻みで動き、同じ位置の複数のイベントでも一度だけ動くので、イベントごとの状態（ボイスの割り当て）を書けない。
  - (1d) 別の修飾子 `on~(e)`（`e` のイベントごとに動く）を閉じた一覧に足す。費用の要因: 名前が一つ増え、`when~` との使い分けが要る。
  - (2) イベントの条件の `when~`（(1a)・(1b)・(1d)）:
    - (2a) K を条件のイベントのクロックにする（S-558 の (4a) の文のまま、K を広げる）。x は K の刻みのうち条件が真の刻みで動き、同じ位置の複数のイベントでは列の順に複数回動く。
      x の本体の `sample` はこの刻みを指す。x の引数は K の刻みごとに評価し、クロックは K 以下（そのイベントの値か `block` 以下）である。
    - 出力 (o1): 呼び出し側は x の出力を自分のクロック（`sample`）の刻みごとに読み、最後の出力を保つ。その位置の全てのイベントで動いた後の値で、イベントの段の式からは読めない。実装: S-558 の保持の欄を、イベントの段で書き `sample` の段で読む。
    - 出力 (o2): 出力は K の値（イベントの刻みごとの値）。`sample` の式で使うには別の変換が要る（(o1) か S-563 の (1a)）。
    - 出力 (o3): K の刻みでは動いた直後の値、`sample` では最後の値として、両方で読める。費用の要因: その出力と `block` の値を混ぜた式は、評価の段が使う場所で決まる。一か所で評価すると、イベントの無いブロックで `block` の値の変化が反映されない（§11.3 の「値の置き場所は一つ」と合わない）。
  - (3) イベントの条件の `reset_if~`:
    - (3a) 条件が真のイベントの刻みで、受け手の次の一歩の前に初期化する。受け手が `sample` で動くなら、その位置の `sample` の一歩の前。同じイベントのクロックで動くなら、その刻みの一歩の前（S-559 の (1a) と同じ）。
      同じ位置の二つのイベント: `sample` で動く受け手には、二回の初期化は一回と同じ結果になる。イベントで動く受け手は「初期化して一歩」を二回行う。
    - (3b) `Bool at sample` に変えてから書く（(1c) と同じ）。`sample` で動く受け手には (3a) と同じ結果になる。
- 他言語:

  - SuperCollider（`Trig` の文書）: 「A trigger happens when the signal changes from non-positive to positive」。イベントを信号の立ち上がりで表す。
  - Cmajor: 入力のイベントの処理の関数で状態を書き換え、`main()` の中で `advance()` する。処理の関数ごとに一回なので、同じフレームの複数のイベントで複数回動く（関数が呼ばれる時点は Language Reference に書かれていない、未確認）。
- 推奨と理由: (1a)、(2a) と (o1)、(3a)。確度: 中。
  - (1a): S-558 と S-559 の「条件は `Bool`」をそのまま保ち、変わるのは条件のクロックだけである。下の例の `starts(tr)` のように、多くの条件はイベントの値の `Bool` の関数で自然に書ける。
    (1b) は `Bool` の型のイベントだけ読みが変わる。(1b) と (1d) は、後で足しても今のプログラムを壊さない（今は誤りの形）。(1c) は「イベントごとに一回刻む」（S-171）の使い所であるイベントごとの状態を書けない。
  - (2a): 第 33 組で、K を広げるだけで `when` の文が変わらないように定義した（S-558 の (4a)）。止まっている間の保持、`prev~` の数え方、`sample_rate()` も、決めた文がそのまま当たる。
  - (o1): 「`sample` の式からは、その位置のイベントを全て処理した後の状態が見える」（S-171）を、保持の欄だけで実現する。イベントの段で読める値は、イベントの値と `block` 以下の値の関数だけになるので、イベントの段に順や一時の置き場所が要らない（状態の大きさが決まる、P6）。
    (o2) は `sample` へ戻す仕組みが別に要る。(o3) は上の「値の置き場所は一つ」と合わない。(o1) から、出力をイベントの段でも読めるように後で緩めても、今のプログラムの意味は変わらない。
  - (3a): S-559 の (1a) と合成の読み（S-557）から決まり、新しい規則は無い。S-559 の回答の補い（初期化はイベント一つに一回）とも合う。
  - 書き方の例（MIDI のトランスポート。型と関数は例のための利用者の宣言で、std の型は第 35 組）:

    ```
    enum Tr { Start, Stop, Continue }
    rt fn starts(t: Tr) -> Bool { match t { Tr.Start => true, _ => false } }
    rt fn runs(t: Tr) -> Bool { match t { Tr.Stop => false, _ => true } }
    flow keep(b: Bool at sample) -> Bool at sample { b }

    flow player(tr: Tr at event, tick: Bool at sample) -> F32 at sample {
      let running = keep~(runs(tr)).when~(present(tr))
      seq~(tick).when~(running).reset_if~(starts(tr))
    }
    ```

    `running` は Start と Continue の後に真、Stop の後に偽で、最初のイベントの前は `false`（`T.default()`）。Start の位置では、イベントの段で `running` が真になり `seq` が初期化され、その位置の `sample` で初期状態から一歩動く（§19.1 の MIDI の文のとおり）。
  - あわせて決めること（止まっているインスタンスへのイベント）: `when~` で止まっている位置に来た、そのインスタンスのイベントの入力のイベントは処理しない（止まった刻みはインスタンスにとって無い刻み、S-558）。溜めて後で処理すると、状態の大きさが決まらない。
  - あわせて決めること（イベントの出力を持つ flow、S-564）: 止まっている刻みにはイベントを出さず、保持の欄を置かない。
  - 新しい S の候補: イベントで動くインスタンスの出力を、同じイベントの段の式で読むこと（(o3) の形。イベントごとに状態を持って変換する MIDI のエフェクトに要る）。`block` の値と混ぜた式の段の規則と一緒に決める。
