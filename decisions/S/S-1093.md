# S-1093 flow の本体の init・block のクロックの let の式が panic しうるとき、その段で無条件に評価するか、使う位置で評価するか

- 空白: §11.3 は「`init` の式は `init` で 1 回、`block` の式は `process` の呼び出しごとに 1 回…`let` に分けても分けなくても、評価の段と結果は同じ」とし、同じ節で「`if` / `match` の取られない枝と、評価されない `&&` / `||` の右辺の部分式は、巻き上げても panic を起こさない（panic しうる部分式は巻き上げず、その位置で評価する）」とする。`init`・`block` のクロックの `let` の式が panic しうるとき（`let k = 100 / n`、`n` は `block`）に、二つの文が割れる。
  読み: (1) `let` の値は自分の段で無条件に評価する（使われない・取られない枝でだけ使われる `let` も panic する。`let` に分けた形と分けない形で結果が違う）。(2) panic しうる値は使う位置で評価する（「`init` の式は `init` で 1 回」と食い違う。`init` の panic の起きる段が変わる）。通るプログラムの実行の結果が変わる。
  今は (1)（`block` は 0 フレームの `process` でも panic する）。再現 `target/notes/158/w701/memo/probe/g1_split.onsa`・`g1_unused.onsa`（`onsa test`、固定のバイナリ `onsa-96aba2b`）。
  仮の扱い: W7-01 の参照評価器は (1) で書き、`SPEC-GAP(S-1093)` を付ける。W1-09 の `hoisting.onsa` はどちらの読みでも通る。
- 決定:
- 経緯: 158 回目、2026-11-16、W7-01 U1 の設計メモ（onsa-test）が空白として挙げ、親が登録した。巻き上げの設計（W7-05）の前に決める。関係: S-1080（巻き上げの「panic しうる部分式」の範囲）。
- 補い（2026-11-17、親）: 163 回目、W7-18 U1a の壊す側: `block`・`init` のクロックの出力の式（`let` でない最後の式）が panic しうる形も同じ問いである（§11.3「`let` に分けても分けなくても、評価の段と結果は同じ」）。参照評価器は出力の式も仮の (1)（自分の段で無条件に評価）で書く。今のインタプリタは使う位置（フレームごと）で評価し、0 フレームでは panic しない。再現は `target/notes/163/w718/u1a2/` の壊す側の報告の中-2（`r31` の f134）。
