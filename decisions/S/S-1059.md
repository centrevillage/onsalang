# S-1059 細部: 誤りのある宣言（E0902 の `rt` の関数の `uses {Alloc}`）の効果行を、呼び手の E0601 で数えるか

- 空白: §8.1（S-77）は `rt` かどうかによらず、効果を持つ関数の呼び出しを使用とする。呼び先の宣言が誤り（`rt` の関数に `uses {Alloc}` を書いた E0902、§10 の規則 1）のとき、その効果行の `Alloc` を呼び手の使用に数えるかを書かない。§18.1 は誤りのある宣言の「読めなかった部分」を使う側に診断を出さないとするが、この行は読めている。宣言の側が誤りなので、通るプログラムは変わらない。
  再現: `target/notes/151/w603/u4a/probe/e0902_caller.txt`。`rt` でない呼び手（`plain_caller`）は W6-03 U4a の前から E0601（前は署名、後は呼び出しの位置）。U4a で `rt` の関数を E0601 の判定に入れたので、`rt` の呼び手（`rt_caller`）にも E0601 が出るようになった。事例 `tests/spec/negative/rt_cycle_through_failed_unit.onsa` の `h`。
  読み: (1) 書いたとおりの行を数える（呼び手に E0601。呼び先から `Alloc` を外すと消える連鎖の誤り） (2) E0902 の要素は呼び手に数えない（`rt` でない呼び手の今の E0601 も消える）。
  仮の扱い: (1)（今の実装。`rt` でない呼び手の前からの扱いと同じで、特別扱いを足さない。S-1054 の仮の扱いと同じ向き）。コードに `SPEC-GAP(S-1059)` の印（`uses.rs::call_use`）。事例の `h` に `//~ E0601` を書いた（W6-03 U4a）。
  急ぎ: W6 の区切りで確認だけ（`rules/leader.md` 5.11）。
- 決定:
- 経緯: 151 回目、2026-11-14、W6-03 U4a の実装の担当が受け入れの比べ（`compare.py diags`）で分類に当たらない違いとして止まって報告し、親が固定のバイナリ `onsa-u3b` と U4a の後のバイナリで再現した。
- 補い（2026-11-14、親）: 151 回目、W6-03 U4a の壊す側の低 1。同じ読みは呼び手だけでなく、E0902 の `rt` の関数の自分の本体にも当たる。書いた行（`uses {Alloc}`）に照らすので、本体の `Alloc` の使用は E0601 にならず、E0902 だけが出る（`pub rt fn g(move b: Buf[F32]) -> U32 uses {Alloc} { 1 }` は U4a の前は引数 `b` の E0901@1:18、後は E0902@1:43 だけ。再現 `target/notes/151/w603/u4a/probe/cyc.txt` の `e0902_own_param`）。E0902 に候補は無いので、候補の約束には触れない。行を外すと E0601 が現れ、直しは二回になる。仮の扱いは同じ (1)（`uses.rs::Record::lacking` にも `SPEC-GAP(S-1059)` の印）。
  (2) を採るなら、E0902 の関数を通る `rt` の循環の E0903 が宣言の順で出たり出なかったりする前からの形（壊す側の低 3、`cyc2.txt`。U4a の後は (1) の帰結で出ない）が戻るので、一緒に直す。
