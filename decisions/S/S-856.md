# S-856 族: §2.4 の名前に接するリテラルと他言語の区切り

- 空白: 族の S（S-458・S-467・S-468・S-469・S-473・S-474）は、文字列・文字のリテラルが名前・キーワード・他の言語の区切り（`r"…"`、`f"…"`、`$"…"`、`b"…"`、`"""…"""`）に空白を空けずに接する形を、§2.4（S-400 の `string_prefix`、S-406 の `string_delimiter`）がどの行と範囲で報告するかを、形ごとに書いていないことから出た。
  族の一般の規則（接する字の種類と位置ごとに、どの行・コード・範囲・主の位置か、閉じない区切りが行末までをどう読むか）を一つ決め、個々の形はそこから決める
- 決定: 決定（2026-11-03、利用者。105 回目、第 79 組。下書きと独立のレビュー（段 1）が一致。利用者は「修正に複数回かかること自体は良い。規則に例外が増えるかが気になる」とし、例外の数で比べて (B)＋(i) を選んだ）: (B)、閉じない区切りは (i)。
  名前、文字列と文字のリテラル、他の言語の区切りが空白を挟まずに続く並びは一つの形で、範囲は並びの全体（閉じないもので終われば、その開きの区切りまで）、主の位置は並びの始まり。並びに区切りを含めば `string_delimiter`、含まなければ `string_prefix`。
  開きの区切りは最も長く読む（`$`・`@` の並びに続く `"` か三つ以上の `"`、三つ以上の `"` の並び、`#` の並びに続く `"`。`"` の並びは同じ数で、`#` は同じ数の `#` を添えて閉じる）。キーワード・`_`・`true`・`false`・数は名前に数えない（文法が読む所は読み、fmt が空白を置く）。閉じない区切りのトークンは閉じない文字列と同じく行の終わりまで。
  理由: 仕様に足すのは一般の文二つで、例外が 0 で済む。今の挙動を書く (A) は例外が 3〜4 個（区切りの前の名前を形に入れない、リテラル一つに名前一つで前を優先、`$"""` は `$"` で開く、`$$` は E0001）、(C) は条件付きの文、(ii) は閉じない区切りだけの例外が増える。区切りを後で足すときも開きの表の一行で済む。
  仕様 §2.4 の 107 行の後（開きの最長の読み、並びの形、キーワードと閉じない区切り）。`spec/foreign-forms.toml` の例は W5-11 で実装と一緒に足す（`x"a"y`、`"a"b"c"`、`r"""x"""`、`$$"""{{x}}"""`、`""""x""""`、`"""x"""u8` など）。族の規則から決まる S: S-458、S-467、S-468、S-469、S-473、S-474、S-858。
- 経緯: 105 回目（2026-11-03）、X-23 の手順 4（W5-11 の前に決める S を族ごとに空白の流れで回す）で、族の未決の S が 6 件なので登録した（`rules/process.md` 8.6 の仕様の空白の流れの 2）
