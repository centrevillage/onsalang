# S-763 `impl` の見出しの誤りが型の段の E0412 のとき（`impl[T] P[T]`）、メンバの署名の名前の段の誤り（`fn b(self) -> Nope` の E0302）をその単位に数えるか（数えれば段の順で E0302 が残り、見出しの E0412 は出ない）

- 空白: §18.1 は、`impl` の見出しに誤りがあれば `impl` 全体を一つの単位とし、メンバは検査しないとする（61 行。見出しに書いた失敗した名前は当たらない）。また、一つの単位の中では最初のエラーで止め、依存する段の間では位置によらず先の段の誤りを報告する。
  見出しの誤りが型の段（E0412、S-103）で、同じ `impl` のメンバの署名に名前の段の誤り（見つからない名前の E0302）があるとき、メンバの署名の名前の誤りがその単位の診断に入るか（入れば段の順で E0302 が残る）、メンバは検査しないので入らないか（見出しの E0412 が残る）は書いていない。
  形: `struct P { x: I32 }` の後の `impl[T] P[T] { pub fn b(self) -> Nope { 1 } }`。対照の、見出しが名前の段の E0307 の `impl P[I32]` では、同じ段の位置の順で見出しの E0307 が残る。
  今（W4-05 U4c の作業中の実装）: `6:21` の E0302「cannot find `Nope`」だけで、見出しの E0412 は出ない。前（`0eb4575`）は見出しの数の誤りが名前の段の E0302 で、位置の順で見出しが残った。
  読み: (1) 入る（今の実装。名前の段はメンバの署名の名前も引くので、段の順で E0302 が残る）。(2) 入らない（見出しの誤りの `impl` のメンバの署名の誤りは報告しない。見出しの E0412 が残る）。
  どちらも誤りのあるプログラムの報告だけが変わる。再現は `target/notes/81/s763/head.onsa`（3〜6 行）。
- 決定: 決定（2026-10-29、利用者「ひとまず(1)で」。81 回目。助言のレビューは通していない）: (1)。
  `impl` の見出しの誤りが型の段（E0412）のとき、同じ `impl` のメンバの署名の名前の段の誤り（E0302）もその単位に入り、段の順（§18.1）で E0302 が残る（今の実装のまま、足す行は 0）。
  理由（親）: どちらの誤りも本物で、偽の連鎖でないので修復の回数は同じ。(2) は名前の段の時点で分からない型の段の見出しの誤りを待って、メンバの誤りを捨てる仕組みが要る。誤りでない二択なので実装の簡単な方。
  利用者が「ひとまず」と答えたので、仕様の文（§18.1 の 61 行の「メンバは検査しない」）は改めず、見直す余地を残す。見直すなら W4-05 の終わりか W4-18 の前に、§18.1 の 61 行と段の順の関係を一文で書くかを含めて決める。
- 経緯: 81 回目（2026-10-29）、W4-05 U4c の壊す側（onsa-break）の指摘 3（低）として挙がり、親が作業中のバイナリで再現した。急ぎは後の段（誤りのあるプログラムの報告の位置だけ）。関係: S-103、S-689、S-759。
- 補い（2026-10-29、親）: 82 回目の W4-05 U4a/b: 見出しが E0416 の `impl`（S-756）も同じ形で、メンバの名前の段の誤り（`fn m3(self, x: Gone)` の E0302）が段の順で残り、見出しの E0416 は出ない（`target/notes/82/s763/i6_5.onsa`）。見直すときは E0412 と E0416 の見出しを一緒に見る。
- 補い（2026-10-29、親）: 82 回目（W4-05 の終わり）、利用者が見直して (a) に決めた: 今の実装（(1)）のままにし、§18.1 の 61 行に「見出しの誤りが型の段（E0412、E0416）のときは、段の順でメンバの署名の名前の段の誤りが先に残る」を一文足した。見出しが E0416 の `impl`（S-756）も同じ。「ひとまず」は外れた。
