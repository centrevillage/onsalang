# S-763 `impl` の見出しの誤りが型の段の E0412 のとき（`impl[T] P[T]`）、メンバの署名の名前の段の誤り（`fn b(self) -> Nope` の E0302）をその単位に数えるか（数えれば段の順で E0302 が残り、見出しの E0412 は出ない）

- 空白: §18.1 は、`impl` の見出しに誤りがあれば `impl` 全体を一つの単位とし、メンバは検査しないとする（61 行。見出しに書いた失敗した名前は当たらない）。また、一つの単位の中では最初のエラーで止め、依存する段の間では位置によらず先の段の誤りを報告する。
  見出しの誤りが型の段（E0412、S-103）で、同じ `impl` のメンバの署名に名前の段の誤り（見つからない名前の E0302）があるとき、メンバの署名の名前の誤りがその単位の診断に入るか（入れば段の順で E0302 が残る）、メンバは検査しないので入らないか（見出しの E0412 が残る）は書いていない。
  形: `struct P { x: I32 }` の後の `impl[T] P[T] { pub fn b(self) -> Nope { 1 } }`。対照の、見出しが名前の段の E0307 の `impl P[I32]` では、同じ段の位置の順で見出しの E0307 が残る。
  今（W4-05 U4c の作業中の実装）: `6:21` の E0302「cannot find `Nope`」だけで、見出しの E0412 は出ない。前（`0eb4575`）は見出しの数の誤りが名前の段の E0302 で、位置の順で見出しが残った。
  読み: (1) 入る（今の実装。名前の段はメンバの署名の名前も引くので、段の順で E0302 が残る）。(2) 入らない（見出しの誤りの `impl` のメンバの署名の誤りは報告しない。見出しの E0412 が残る）。
  どちらも誤りのあるプログラムの報告だけが変わる。再現は `target/notes/81/s763/head.onsa`（3〜6 行）。
