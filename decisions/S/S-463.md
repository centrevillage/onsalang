# S-463 `#[derive(…)]` の候補の trait の名前

- 空白: `#[derive(…)]`（と旧版の `@derive(…)`）の候補が Rust の trait の名前をそのまま写す（`#[derive(Debug, Clone, Copy, PartialEq)]` を `: Debug + Clone + Copy + PartialEq` に。dev の `f4b9a8b` で確かめた）。
  W3-08 の後は当てると `Copy` の E0020（`copy_bound`）と `Debug`・`Clone` の E0416 が続き、Rust の書き手で最も多い形で 2〜3 周を使う。
  案は、写しの閉じた表（`Debug`・`Display` は `Show`、`Clone`・`Copy` は外す）、一覧に無い名前は候補から外して note、読みが一つの名前だけ写して写せない名前は残し次の検査の E0416 に任せる（第 26 組の Fable）。第 26 組の下書きの付録で見つけた（2026-10-13）
- 提案: 決定（2026-10-13、利用者が親の案 (e) を選び、Fable も賛成した。下書きと Fable は (b) の写しの表で一致していたが、利用者が「特定の言語の事情に踏み込みすぎ」と懸念した。第 27 組）: 名前はそのまま写し、Onsa の規則で宣言の頭に書けない種の制約（`Copy`・`Dup`、§4.6）だけを外す。
  外す名前の一覧は `copy_bound` と同じ定数を読む（D-15）。全て外れれば属性を消すだけ。既に `:` がある宣言は並びの後ろに足し、字面で重なる名前は足さない。仕様は変えない（候補の形はデータのファイルの例、S-315）。実装は W3-08
