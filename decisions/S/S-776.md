# S-776 前の段で誤りのある単位を通る、単位をまたぐ rt の再帰（`rt fn c(n: I32, q: Nope)` と、それを呼ぶ誤りの無い `rt fn d` の循環）: 誤りの無い単位に E0903 を出すか

- 空白: §18.1 は、ある段が誤りを見つけた単位では、その結果に依存する後の段を行わないとする。§10 の規則 5 は直接・相互の再帰を E0903 とするだけで、どの呼び出しに出すかも書いていない（S-778）。単位をまたぐ rt の循環の途中の単位が前の段で誤りのとき、誤りの無い他の単位に E0903 を出すかは書いていない。
  形（`target/notes/83/s776/p9_rt_cycle_sig.onsa`）: 署名に名前の誤りのある `rt fn c(n: I32, q: Nope)` と、それを呼ぶ誤りの無い `rt fn d` の循環。今は `d` に E0903（3:14、cycle: d -> c -> d）と `c` の E0302 が出る。
  同じ形で `c2` の誤りが modes（E0704）のときは `d2` に E0903 が出ない。本体に型の誤りのある `rt fn` を通る循環も、今は E0903 が出ない（`p9b_type.onsa`）。今の実装の中で段により食い違う。W4-06 は段の失敗の記録で、署名の誤りの単位の本体の型・modes・rt・効果を飛ばすので、(1) の形になる。
  読み: (1) 誤りのある単位は rt の段を行わないので、その呼び出しは循環の辺にならず、誤りの無い単位にも E0903 を出さない（`c` を直した後に `d` に出る）。(2) 循環は `c` の誤りと関係なく在るので、`d` の E0903 を出す。
  どちらも誤りのあるプログラムの報告だけが変わる。
- 決定: 決定（2026-10-29、利用者。83 回目。確認だけ）: (1)。
  前の段で誤りを見つけた単位（署名の名前の誤り、本体の型の誤り、modes の誤りなど）は rt の段を行わないので、その呼び出しは rt の再帰の循環に数えず、循環の誤りの無い単位にも E0903 を出さない。その単位を直した後に報告する。
  理由: §18.1 の段の止め方（誤りのある単位では依存する後の段を行わない）のとおりで、今の本体の型の誤りと modes の誤りの扱いと揃う。名前の段の誤りの後のインスタンスを E0817 の辺に数えない S-761 と同じ向き。誤りのあるプログラムの報告だけで、通るプログラムは変わらない。
  仕様は §10 の規則 5 に一文。実装は W4-06 U1（段の失敗の記録で rt を飛ばし、`unread.rs` の `rt_unread` に数える）。事例は U1/t で、署名の名前の誤り・本体の型の誤り・modes の誤りの三つの組。
- 経緯: 83 回目（2026-10-29）、W4-06 U1/i（onsa-impl）の設計メモが仕様の空白（N1）として報告し、親が再現した。期限は W4-06 U1（事例は U1/t）。関係: S-761、S-64、S-267。
- 補い（2026-10-29、親）: 空白の文を直した（83 回目、W4-06 U1/t の報告から）。登録のときに親が設計メモの記述を確かめずに「§10 の rt の再帰の規則は、循環を閉じる呼び出しで一度報告するとだけ書く」と書いたが、§10 にその文は無い（E0903 の位置は S-778）。
  また「modes の誤りのときは E0903 が出ない」は `p9` の `c2` の形のことで、`Buf` を渡す鎖の形（`tests/spec/negative/unit_stage_rt_cycle_modes.onsa`）では W4-06 の前は出ていた。決定は変わらない。
