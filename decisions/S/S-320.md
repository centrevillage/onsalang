# S-320

- 空白: 二項の演算子の後の前置の `-` を、空白を空けずに書いた形（`a--b`、`5--3`）の読み。W3-15 の字句解析器は `--` を増減のトークンにする（S-250、S-297）ので、前の読み（`a - -b`）が変わり、候補なしの E0002 になった。S-250 と S-297 は増減の位置（文の位置の `x--`、前置の `--x`）だけを扱い、この形を書いていない。
  C は `a-- b` と読んで誤り、Rust は `a - (-b)` と読む。W3-15/b で見つけた（2026-10-09）
- 提案: 決定（2026-10-09、利用者が ID を挙げて了承。親の案）: 二項の演算子の後に空白を空けずに書いた前置の `-`（`a--b`、`5--3`）は、読みが言語の間で割れる（C は `a-- b` で誤り、Rust は `a - (-b)`）ので誤りにする（R-124 の方針）。正しい読みは一つなので E0020 で、候補は `a - -b`。
  字句は今の W3-15 のまま（`--` は一つのトークン）で、既存言語の書き方の一覧に行を足す。実装は W3-07（`SPEC-GAP(S-320)` を外す）
