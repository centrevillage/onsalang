# S-512

- 空白: 構造体のパターンの `..,` の E0002 の文面と候補。文面「expected `,` or `}`, found `,`」は `,` を求めながら `,` を誤りとする。文面を「`..` は最後に置き、後ろに `,` を書かない」の趣旨にし、`,` を除く候補を付けるか（当てた後に後の段の E0020 が残る）。第 29 組の下書きの付録（2026-10-13）
- 提案: 後の段（S-500 の後）
- 時期: W3
- 補い（2026-11-06、親）: S-903 の最後の `_` の後の `,`（`let Item { x: a, _, } = v`）も同じ形で、同じ文面の E0002 である。決めるときは `..,` と `_,` とリテラルの `...,` を一つの族として扱う。
- 補い（2026-11-09、親）: 構造体のパターンの最後の `_` の後ろの `,`（`P { x: a, _, }`、複数行の形も）も同じ文面「expected `,` or `}`, found `,`」の E0002 で候補なし（dev `5d5cd987`。128 回目の独立の検討が見つけた）。この S と同じ規則で決める。
- 決定: 決定（2026-11-09、利用者。128 回目、共通の規則 S-965 と利用者の判断 B1〜B8、`target/notes/128/r58/decisions.md`）: （出所: R10、既決 S-500、X）構造体のパターンの最後の `_` の後ろの `,`（`P { x: a, _, }`、ブロック形でも）と struct リテラルの最後の `...` の後ろの `,`（`Item { x: 1, ..., }`、S-512 の補いが同じ族とした）は E0002 で、候補は `,` を除く形。文面は「最後の `_`（`...`）の後ろに `,` を書かない」の趣旨。構造体のパターンの `..,`（`P { x: a, .., }`）は S-500 のとおり構文の段の E0002（文法を広げない）で、候補は `,` を除く形（当てた後に型の段の `..` の E0020。修復は 2 回で、7.27 は収束を求め 1 回を求めない、X）。最後でない位置の `_`（`P { _, x: a }`）も E0002 で、候補は `_` を全て除いて並びの最後に一つ置く形（`P { _, x: a, _ }` も `P { x: a, _ }`。構造体のパターンの `_` の意味は「残りのフィールドを無視する」の一つで意図が一つに決まる。「移す」と定義すると `P { _, _ }` が巡回する、X）。
  - 仕様の節: §7 の struct の項に二文と `..` の項に一文、§4.4 の `...` の文に括弧書き。
  - 今通るプログラムが変わるか: 変わらない。報告と候補だけ（今は「expected `,` or `}`, found `,`」の候補なし）。
  - 実装の見当: `onsa_syntax` の構造体のパターンと struct リテラルの並びの解析で、`_`・`...`・`..` の後の `,` と最後でない `_` を見たら専用の E0002 と候補（約 25〜45 行）。`--fix-loop`（7.27）を票に入れる。
  - ぶつかる既存の事例: なし（`git grep` で `_, }` の事例は仕様と決定の文だけ）。
