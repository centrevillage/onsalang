# S-1089 2^24 の上限の読みとコード（入れ子の比の積か、各クロックの一番外の `sample` との比か）

- 空白: §11.9 は「入れ子の比の積は 2^24 以内（flow をまたぐので降下で確かめる）」とする。「入れ子の比の積」が N の積か、各クロックの一番外の `sample` との比かで、`x.up~(8192).down~(8192)` が分かれる。コード（E0808 か）と、超えた修飾子の位置の読みも決まっていない（S-566 の下書きに位置と note の記述がある）。2^24 の理由の出所は S-565〜S-567 の下書きに見当たらない（段 1）。
  読み: (1) N の積、(2) 各クロックの一番外の `sample` との比（指数が −24〜24）。通るプログラムが変わる。W7-02 のクロックの表現には効かない（k は小さな整数で足りる）。
- 決定: 決定（2026-11-22、利用者。175 回目、第 116 組。下書きと段 1 が一致した推奨を、上限が何を守るかと check の費用と「ひとつの変換での最大値」の比べを説明した後に了承「(a)で良いです」）: (a) ＋ (α) ＋ E0808。一番外の本体からインスタンスまでの経路にある `.down~`・`.up~` の N を、向きによらず全て掛けた積が 2^24 以内（flow をまたいで数える。式とポートの導くクロックの N は数えない）。flow の検査の段で、どの flow もその本体を一番外として確かめる（呼び先から先に flow ごとに数を一つ覚える歩きで、W7-16 U5b の段の入口の表の歩きに載せる。量は flow とノードの数に比例）。E0808、位置は超えた修飾子の名前（flow をまたいで超えるときは包む側の flow の連鎖の修飾子。字の監査の指摘で下書きの句を仕様と決定に入れた）で note に経路、中の flow が単独で超えるときは中の flow にだけ出す。細部（note の文面、同じ連鎖で二つ以上が超えるときの一つ目）は W7-16 の票。
  上限が守るもの（理由の字は無いので親の説明）: 遅い刻みの判定の 64 ビットのカウンタ、集めて配る配列の U32 の長さ、§14.2 の容量の 64 ビットの式の A、クロックの表示。どれも 2^32 以下の上限で足り、2^24 は既決の数（S-566 の A4）として変えない。比べた代わりの (L1) 各修飾子の N ≤ 2^24、(L2) 連鎖一つの中の積 ≤ 2^24 は、flow をまたぐ周期と A の守りを Core と W10-07 に分けて足すことになるので採らない。
  S-566 の A4 の「flow をまたぐので降下で確かめる」は検査の段に改めた。仕様は §11.9 の一文、§11.3 の導くクロックの N の一句、§14.2 の A の句（W10-07 が容量の式で使う）、`tasks/diag-codes.md` の E0808 の行。
- 経緯: 157 回目、2026-11-16、第 105 組の段 1（onsa-advisor）が論点の抜け（または下書きの新しい S の候補）として挙げ、親が登録した。
- 補い（2026-11-21、親）: （172 回目、W7-09 U2r1 の壊す側）式の導くクロックの N にも上限の字が無い（`p at (sample / 2147483648)` は今の実装で診断 0、`Ratio` は `i32`）。修飾子の比の積と同じくこの S の読みで決め、W7-16 の降下で確かめる（W7-09 U2r1 は止めない）。
- 補い（2026-11-21、親）: （173 回目、W7-09 U3b）修飾子の連鎖の比の和が 2^63 を超えると、表示（`Clock::shown`）が内部エラーになったので、U3b は比の和が 2^63 を超える連鎖を最後の修飾子の名前の位置の E0808 にした（仮、`SPEC-GAP(S-1089)`。どちらの読みでも 2^24 を超える）。壊す側は、連鎖の途中の部分和の読みも割れると挙げた（(a) 途中の部分和も 2^24 以内、(b) 連鎖の全体の比だけ。`lp~(p).up~(2147483648).up~(2147483648).up~(4).down~(2147483648).down~(2147483648).down~(4)` は今は正味 0 で通る）。この S と一緒に決める。
- 補い（2026-11-21、親）: （174 回目、W7-09 U2e）参照評価器は、連鎖一つの比と外の連鎖との積の指数の絶対値が 24 を超える形を init で `Unavailable` にした（上りと下りの両方。黙って丸めない、`crates/onsa_tests/src/flow_ref/rate.rs` の `MOST_RATIO`）。U2e/t は、上限が遅い側（`leaf~(p).down~(8192).down~(8192)`、積 2^-26）にもかかるかも読みが割れると挙げた（(1) かからない、(2) 比の大きさで遅い側も誤り）。検査は今これを通す。この S の読みと一緒に決め、評価器の絶対値の扱いをそれに合わせる。
- 補い（2026-11-21、親）: （174 回目、W7-09 U2e の壊す側）変換の flow の入出力の宣言 `x: F32 at (sample * 2147483648)` も検査を通る（ポートの N の上限の字も無い）。参照評価器は資源の上限（`Limits`）で `Unavailable` にする。式の導くクロックの N と同じく、この S の読みで決める。
