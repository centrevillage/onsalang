## 3. 演算子

### 3.1 優先順位と混在の規則

二項演算子は **群** に分かれる。群どうしには、順位が数学と主要な言語で一致する組み合わせにだけ強弱を付ける（部分順序）。強弱の無い群どうしを括弧なしで混在させるとエラー（E0010）。

| 群 | 演算子 | 同じ群内の連鎖 |
|---|---|---|
| 乗法 | `*` `/`、ラップ `*%`、飽和 `*\|` | 左結合で可 |
| 剰余 | `%` | 左結合で可 |
| 加法 | `+` `-`、ラップ `+%` `-%`、飽和 `+\|` `-\|` | 左結合で可 |
| 比較 | `==` `!=` `<` `<=` `>` `>=` | 不可（`a < b < c` はエラー） |
| 論理積 | `&&` | 可 |
| 論理和 | `\|\|` | 可 |
| ビット | `&` `\|` `^` `<<` `>>` | 同じ演算子だけ左結合で可（`a \| b \| c`）。違う演算子の混在は不可 |

強弱（強い群の式は、括弧なしで弱い群の被演算子になれる）:

- 乗法 > 加法 > 比較 > 論理積、論理和
- 剰余 > 比較（剰余と加法・乗法の間には強弱が無い）
- 論理積と論理和の間、ビットと他の全ての群の間には強弱が無い

```onsa
let a = x + y - z         // 加法の連鎖
let b = x + y * z         // x + (y * z)。乗法は加法より強い
let c = (w + 1) % N       // 剰余と加法は混在できない（w + 1 % N は E0010）
let d = lo <= x && x < hi // 比較は論理積より強い
let e = (p && q) || r     // 論理積と論理和は混在できない
let f = (m & 1) == 0      // ビットは他の群と混在できない
```

- 強弱を付けたのは、数学でも主要な言語でも同じ順位になる組み合わせだけである（`a + b * c`、`i + 1 < n`、`lo <= x && x < hi`）。どの言語の読み方でも同じ意味になるので、偽の友人を作らない（§0.3 の規則 4）。積和の多い DSP の式から、情報の無い括弧が消える（P10）。
- 剰余は C 系の言語では乗法と同じ順位だが、数学の mod には決まった順位が無い（`a + b mod n` は `(a + b) mod n` と読まれることが多い）。リングバッファの添字で `w + 1 % N` と書くと `w + (1 % N)` になる典型的な誤りを、括弧の要求で防ぐ。比較より強いことは共通なので、`i % 2 == 0` は書ける。
- `&&` と `||` の順位は誤読されやすい。ビット演算は言語によって順位が違う（C の `x & 1 == 0` は `x & (1 == 0)`、Go の `<<` は乗法と同じ順位）。比較の連鎖は言語によって意味が違う（Python は `a < b < c` を `a < b and b < c` と読む）。これらは括弧を要する。
- ビットの群では、同じ演算子の連鎖（`a | b | c`、`a & b & mask`、`x << a << b`）を左結合で書ける。`&` `|` `^` は結合的でどう読んでも値が同じで、シフトの連鎖も受理する言語は全て左結合で読むので、読みが分かれない（P10）。違うビット演算子の混在（`a & b | c`）は括弧を要する。
- 強弱で読みが決まる位置の括弧（`(a * b) + c`）と、名前・リテラル・後置式・式の全体を囲む括弧（`(x)`、`let y = (a + b)`）は冗長だが書け、`onsa fmt` が外す（P2。外す括弧の基準と例は [`spec/tools.md`](tools.md) §3.3）。
  無いと誤りになる括弧（見出しの struct リテラルとブロック式、前置演算子の重ね `-(-x)`、`as` / `at` の式を二項演算子の被演算子にする `acc + (x as F64)` と `as` / `at` の連鎖、ブロックに似た式を演算子の被演算子にする `(if c { 1 } else { 2 }) + 10`）は、冗長ではない。

結合の強さは、後置（呼び出し `f(x)`、関数値の呼び出し `.(x)`、flow の呼び出し `f~(x)`、レシーバを変える呼び出し `f!(x)`、フィールド `.f`、添字 `[i]`、`?`）> 前置（`-`、`!`。前置の `+` は無く、`+x` は E0020 で、修正候補は `+` と後ろの空白（改行を含む）を除く形。式、属性の引数、パターンで同じ。前置の `-`・`!` と接する `-+x`・`+-x`・`!+x` も前置の `+` の誤り一つで、修正候補は `+` を除く形（`-x`、`!x`）。行頭の `+` で前の行が被演算子で終わる形は、行頭の二項演算子の規則が先、§2.5）> `as` と `at`（§11.3）> 二項演算子の順（Rust / C と同じ）。
帰還の参照 `^名前` は名前の一部で、後置はその参照に掛かる（`^y.l` は `y` のフィールド `l`、§11.2）。`-xs[i]` は `-(xs[i])`、`-x as F64` は `(-x) as F64`。前置演算子を重ねるには括弧が要る（`-(-x)`、E0012）。
間に空白を空けた重ね（`- - x`、`- -x`、`! ! b`）も E0012 の一つの誤りで、修正候補は空白も除いて内側を括弧で囲む形（`-(-x)`、`!(!b)`）である（§2.5 の前置の記号の後の空白の E0020 は重ねて出さない）。
`as` と `at` は連鎖できず、二つ目の被演算子には括弧が要る（`(x as I64) as F64`、`(x as F64) at sample`。E0011）。範囲の `..<` と `..=`（§7）は二項演算子より弱く、範囲は見出しの式の全体である。端には二項演算子の式を書ける（`0 ..< n + 1` の終わりは `n + 1`）。
ブロックに似た式は、ブロックを持つ式の全てで、`if`・`if~`、`match`・`match~`、ブロック式 `{ … }`、無名関数、`unsafe`、`handle`、`par` の 9 つである（`while` と `for` は文で、式の位置に書けない）。
これらを演算子の被演算子にするときは、括弧で囲む（`(if c { 1 } else { 2 }) + 10`、`-(match o { … })`、`(if c { xs } else { ys })[1]`、`(fn(x: I32) -> I32 { x }).(3)`）。
被演算子の位置は、二項演算子の左右、前置の被演算子、後置の受け手（関数値の呼び出しの `.(`、フィールドとメソッドとタプルの添字の `.`、添字の `[`、`?`）、`as` / `at` の左である。
括弧なしで置くと E0013 で、修正候補は、その式の被演算子の位置にある全てを括弧で囲む一つの形である（`if a { 1 } else { 2 } + match o { … }` は二つを囲む一つの誤り）。主の範囲は、その式の中で最初の、括弧の無いブロックに似た被演算子である。
他の診断の修正候補も、当てた形でブロックに似た式が括弧なしで被演算子の位置に来るときは、その式を括弧で囲む編集を含める（§18.1 の候補の約束）。
囲むのは、候補が書き換える文字を含む式（括弧で切れる式の単位で、書き換える範囲と文字を一つ以上共有するもの。端で接するだけの式は含まない）の中の、全てのブロックに似た被演算子である。
例えば、行頭の演算子を前の行の末尾へ移す形（`if a > 0 { 1 } else { 2 }` 改行 `+ 1` は `(if a > 0 { 1 } else { 2 }) +` 改行 `1`、§2.5）、関数値を `.(` で呼ぶ形（`if c { h } else { g }(1)` は `(if c { h } else { g }).(1)`、§6.1）、複合代入を書き出す形（`x += if c { 1 } else { 2 }` は `x = x + (if c { 1 } else { 2 })`）である。
文、`let` と代入の右、引数、要素、フィールドの値、腕の値、`return` の値、見出しの全体、範囲の端には、括弧なしで書く（`let a = if c { 1 } else { 2 }`、`0 ..< if c { 4 } else { 8 }`）。
同じ字面を、文の頭でブロックや `if` の文と後ろの別の式に分けて読む言語があり（JavaScript は `{ n } - 10` をブロックの文と `-10` の文に、Rust は文の頭の `if c { 1 } else { 2 } - 10` を `if` の文と `-10` に読む）、後置の `if c { xs } else { ys }[1]` は `else` の側の `ys[1]` にも見えるからである（P2）。
構造体リテラル（`P { x: 1 }.x`）は型の名前の後の `{` で読みが割れないので、この規則に当たらない。

### 3.2 演算子は trait に脱糖する

`+` は `Add.add`、`+%` は `WrappingAdd.wrapping_add`、`+|` は `SaturatingAdd.saturating_add`、単項の `-` は `Neg.neg`、`!` は `Not.not`、`<` は `PartialOrd.lt` など（§6.3）。オーバーロードはこの経路だけで、型ごとに実装は高々一つ。

### 3.3 変換

`as` は **情報を失わない拡大変換** だけに使える（`I32 as I64`、`F32 as F64`、`I32 as F64`、`U8 as F32` など）。それ以外は、変換元の型のメソッドを使う。

```onsa
let n = i as I64             // OK
let k = n.narrow_i32()       // I64 -> Option[I32]
let s = x.round_f32()        // F64 -> F32、最近接偶数丸め
let c = xs.len().round_f32() // U32 -> F32、最近接偶数丸め
let j = y.trunc_i32()        // F32 -> I32、範囲外は panic
let m = y.trunc_i32_sat()    // F32 -> I32、範囲外は飽和、NaN は 0（Rust の `as`、WASM の trunc_sat と同じ）。rt ではこちらを使う
let b = y.to_bits()          // F32 -> U32、ビット表現（F64 は U64）。逆は F32.from_bits(b)
```

数の型の間の変換は次の表で全てで、型の組ごとに書き方は一つである。メソッドは `as` で書けない組にだけある。

| 変換 | 書き方 |
|---|---|
| 同じ型（値を変えない。型別名は解決した後の型で比べるので、`type Sample = F32` の下の `x as Sample` は書ける）と、情報を失わない変換: 同じ符号の整数の拡大、符号なしからより広い符号付き、`F32` → `F64`、`I8` `I16` `U8` `U16` → `F32`、`I8`〜`I32` `U8`〜`U32` → `F64` | `as` |
| 整数 → 整数（上以外。同じ幅で符号が違うものと縮小） | `narrow_<型>()`。`Option` を返し、範囲外は `None` |
| 浮動小数 → 整数 | `trunc_<型>()`（ゼロ方向に切り捨て。切り捨てた値が型に収まらないときと NaN は panic）、`trunc_<型>_sat()`（範囲外は飽和、NaN は 0） |
| 整数・浮動小数 → 浮動小数（上以外: `F64` → `F32`、`I32` `U32` `I64` `U64` → `F32`、`I64` `U64` → `F64`） | `round_f32()` / `round_f64()`（最近接偶数丸め） |
| ビット表現 | `to_bits()`（`F32` → `U32`、`F64` → `U64`）。逆は関連関数 `F32.from_bits(u)` / `F64.from_bits(u)` |

- `as` で書ける組の変換メソッド（`F32` の `round_f64()`、`I32` の `narrow_i64()`、同じ型への `round_f32()` と `narrow_i32()` など）は無い（E0413。修正候補は `as` の形）。型パラメータの値には `as` を書けない（`x: T` の `x as T` も E0411）。
  型パラメータは境界が与える操作しか持たず、`as` を与える trait は無いからである。`x: T` の `x as T` には `as T` を外す修正候補を出し、`x: F32` の `x as T` には候補を出さない。
- `as` で書けない組の `as` は E0411。読みが一つの組は、その変換のメソッドを修正候補に示す（整数から浮動小数と `F64` → `F32` は `round_f32()` / `round_f64()`）。
  浮動小数から整数は既存の言語で読みが分かれるので、読みごとに並べる（Rust の `as` の意味の `trunc_<型>_sat()` と、範囲外を panic にする `trunc_<型>()`）。
  整数の縮小は、Rust や C の `as` が下位のビットを取るのに対して `narrow_<型>()` は `Option` を返し、意味が違うので修正候補を出さず、note で `narrow_<型>()` を示す。

参考: Rust の `as` は情報を失う変換も許す。Onsa の `as` で書けるのはその部分集合で、検査を通るものは Rust の `as` と同じ結果になる（§0.3 の 4）。変換の意味は、上の表と §3.4 が定める。

`as` 式を、それより弱い記号（二項演算子と範囲の記号、§7）のオペランドにするときは括弧が必要（E0011）: `acc + (x as F64)`、`for i in 0 ..< (n as U32)`（範囲の始まりの端も終わりの端も）。flow の `at` 式（§11.3）も同じ。

暗黙の変換は無い。flow のレート（§11.3）は値の変換ではなく、式のクロックの推論である。

### 3.4 整数と浮動小数の演算の意味

この節の規則が、整数と浮動小数の演算の意味を定める。全ての変換先で同じ結果になる（§13.4）。参考: Rust の同じ演算と一致する。違いは、`MIN % -1` が panic せずに 0 になること、`min` / `max` が NaN を伝えること、整数の溢れがビルドの種類によらず panic することである。

整数（符号付きの `I8`〜`I64` は 2 の補数、符号なしは `U8`〜`U64`）:

| 演算 | 結果 | panic する場合（§9.2） |
|---|---|---|
| `a + b`、`a - b`、`a * b` | 数学的な結果 | 結果が型に収まらない（符号なしの引き算が 0 を下回る場合を含む） |
| `a / b` | 数学的な商を、ゼロ方向に切り捨てた値 | `b` が 0。結果が型に収まらない（`MIN / -1`） |
| `a % b` | `a - (a / b) * b`（符号は被除数と同じ）。`MIN % -1` は 0 | `b` が 0 |
| `-a`（符号付きだけ） | `0 - a` | `a` が `MIN` |
| `a << n`、`a >> n`（`n` は `U32`） | `<<` は下位に 0 を詰め、上位にはみ出したビットを捨てる。`>>` は、符号付きでは算術（符号を詰める）、符号なしでは論理（0 を詰める） | `n` がビット幅以上 |
| `a +% b`、`a -% b`、`a *% b` | 数学的な結果を 2^(ビット幅) を法として型の範囲に表した値（2 の補数のラップ） | しない |
| `a +\| b`、`a -\| b`、`a *\| b` | 数学的な結果を、型の最小値と最大値の間に収めた値（飽和） | しない |
| `a.div_euclid(b)`、`a.rem_euclid(b)` | `r = a.rem_euclid(b)` は `0 <= r < \|b\|`、`q = a.div_euclid(b)` は `a == q * b + r` を満たす。`MIN.rem_euclid(-1)` は 0 | `b` が 0。`div_euclid` の結果が型に収まらない（`MIN.div_euclid(-1)`） |
| `a & b`、`a \| b`、`a ^ b`、`!a` | ビットごとの論理積、論理和、排他的論理和、否定 | しない |
| `a.checked_add(b)` など（下記） | 対応する演算の結果を `Some` に包んだ値。panic する場合は `None` | しない |

- 符号なし整数に単項の `-` は無い（E0401）。0 を除く全ての値で結果が型に収まらず、型だけで誤りと決まるからである。0 を下回る引き算（`a - b`）は値によって決まるので、実行時に panic する。2 の補数の否定は `0 -% u` と書く。
- `std.math` の `abs(a)` は、符号付き整数では `-a` と同じく、`a` が `MIN` なら panic する（結果が型に収まらない。§13.4 のプリミティブも std の本体も同じ）。
- panic するのは、数学的な結果が型に収まらないときだけである。`I32.MIN % -1` と `I32.MIN.rem_euclid(-1)` の結果は 0 で型に収まるので、panic せずに 0 を返す（`checked_rem` / `checked_rem_euclid` は `Some(0)`）。
  Rust はここで panic するが、それは x86 の除算命令が例外を起こすというハードウェアの事情による。WASM の `rem_s` と JavaScript の `%` も 0 を返す。`div_euclid` の `MIN / -1` は結果が収まらないので panic する。
- ラップアラウンドは `+%` `-%` `*%`、飽和は `+|` `-|` `*|` の演算子で書く（Zig と同じ）。符号付きは二の補数でラップする。位相の累積は `phase +% inc`、リングバッファの添字は `(w +% 1) % N`。`wrapping_*` / `saturating_*` のメソッドは無い（演算子が唯一の書き方）。Swift の `&+` を採らなかったのは、C の読み方では `a & +b` になるからである（§0.3 の規則 4）。
- 床除算は `div_euclid` / `rem_euclid` のメソッドで書く。
- panic しうる整数の演算子とメソッドには、全て検査付きのメソッドがあり、panic の代わりに `None` を返す（`Option` を返す）: `checked_add` `checked_sub` `checked_mul` `checked_div` `checked_rem` `checked_neg`（符号付きだけ） `checked_shl` `checked_shr` `checked_div_euclid` `checked_rem_euclid`。
  panic しうる演算を足すときは、検査付きも足す。
- 整数と浮動小数のメソッドは、§3.3 の変換と、上の床除算と検査付きで全てである。それ以外の計算（`abs`、`min`、`max`、`sqrt`、`floor`、`is_nan` など）は `std.math` の関数で書き、メソッドの形は無い（E0413。修正候補は関数の形）。同じ計算に二つの呼び方を作らない（§6.2）。
- 既定の `+ - *` を検査付きにするのは、非 DSP のコード（ボイス割り当て、MIDI の解析）の添字計算のバグを黙って通さないためで、Swift と Rust（デバッグ）と同じ意味である。DSP のラップの意図は演算子で書けるので panic にならず、panic は本当のバグだけになる。

浮動小数（`F32` は IEEE 754 の binary32、`F64` は binary64）:

| 演算 | 結果 |
|---|---|
| `a + b`、`a - b`、`a * b`、`a / b`、`std.math.sqrt(a)` | 数学的な結果を、最近接偶数（roundTiesToEven）で型に丸めた値（正しく丸める） |
| `a % b` | `fmod`: `a - b * trunc(a / b)` を丸めずに求めた値（符号は `a` と同じ）。丸めを含まないので正確である。`b` が 0 か `a` が無限大なら NaN。`a` が有限で `b` が無限大なら `a`（`-0.0` も保つ。上の式は有限の `b` についての定義） |
| `-a` | 符号を反転した値（NaN の符号は下記のとおり未規定） |
| `==` `!=` `<` `<=` `>` `>=` | IEEE 754 の比較。NaN はどの値（自分を含む）とも等しくなく、大小も無いので、NaN を含む比較は `!=` だけが真。`-0.0 == 0.0` は真 |
| 特別な値 | 0 でない数を 0 で割ると、符号の付いた無限大。溢れは無限大。無効な演算（`0.0 / 0.0`、無限大 − 無限大）は NaN |

- 縮約（FMA）と再結合はしない。式は書いた順と形のまま、1 演算ずつ丸める（§13.4）。非正規化数はそのまま扱う（`strict-ftz` は §15.5）。
- 結果が 0 のときの符号: ちょうど 0 になる和は、両方の被演算子が `-0.0` のときだけ `-0.0` で、それ以外は `+0.0` である（差 `a - b` は `a + (-b)` として扱う）。積と商の符号は、二つの被演算子の符号の排他的論理和である（結果が 0 や無限大でも）。0 でない数学的な結果が丸めで 0 になったときは、その結果の符号を持つ。
  `sqrt(-0.0)` は `-0.0`。`floor` `ceil` `trunc` `round` と、`round_f32()`（`F64` → `F32`）、`as`（`F32` → `F64`）は被演算子の符号を保つ。整数から浮動小数への変換の 0 は `+0.0`。0 の符号は `to_bits()`、`Show`、`1.0 / x`、`min` / `max` で見える。
  参考: IEEE 754-2019 §6.3 と同じ規則で、C・WASM・JavaScript の演算はそのまま従う。
- `std.math` の `floor` / `ceil` / `trunc` / `round`（最近接偶数）、`abs`（浮動小数では符号のビットを 0 にした値で、`abs(-0.0)` は `+0.0`）、`min` / `max`（どちらかが NaN なら NaN、`-0.0 < 0.0`）、`is_nan` / `is_finite` は正確に計算する。超越関数の精度は §13.4。
- NaN の符号とペイロード（ビット表現）は、演算の結果としては未規定である。比較、`Show`（`NaN` と表示する）、整数への変換、NaN の伝播は、どの NaN でも同じに振る舞う。
  プログラムからビットを見る唯一の手段である `to_bits()` は、NaN を正の quiet NaN（`F32` は `0x7FC00000`、`F64` は `0x7FF8000000000000`）にそろえて返す。したがって、Onsa のプログラムから見える振る舞いは NaN の表現に依らない。
  ホストに渡る値（`process` の出力、export した関数の結果）の NaN は、NaN であることだけを約束する（§13.4）。

変換（`as` と変換のメソッド、§3.3 の表）:

- `as` は値を変えない（情報を失わない組だけに書ける）。
- `trunc_<型>()` はゼロ方向に切り捨てる。切り捨てた値が型に収まらないとき（範囲外）と NaN は panic（`U32` へは、`-0.9` は 0 で、`-1.0` は panic）。数学的な結果が型に収まらないときだけ panic する整数の規則と揃い、`trunc_<型>_sat()` の範囲と同じ定義になる。`trunc_<型>_sat()` は、範囲外を型の最小値か最大値にし、NaN を 0 にする。
- `round_f32()` / `round_f64()` は最近接偶数で丸める。`F64` から `F32` への溢れは無限大になる。
- `narrow_<型>()` は、値が型に収まれば `Some`、収まらなければ `None`。
- `to_bits()` / `F32.from_bits(u)` / `F64.from_bits(u)` はビットのまま移す（`to_bits()` の NaN は上記）。

### 3.5 評価順

関数の本体の式は、次の順に評価する（Rust と同じ）。全ての変換先で同じ順になる（§13.4）。変換先の言語が順序を決めていない所（C の引数や添字）でも、コンパイラが順序を固定して出力する。

- 左から右に評価する。二項演算子は左の被演算子から、呼び出しはレシーバ、引数の順に、struct / 配列 / タプルのリテラルは書いた順に評価する。
- 代入は右辺を先に評価し、その後に代入先の場所（添字の式）を評価する。`ys[next(inout k)] = next(inout k)` では、右辺の `next` が先に呼ばれる。
- 添字 `xs[i]` は、`xs` の後に `i` を評価する。
- 範囲 `a ..< b` と `a ..= b` は、`a`、`b` の順に、最初の反復の前に一度だけ評価する。本体で端の変数を変えても、反復の回数は変わらない。
- `&&` / `||` の右辺は、左辺で結果が決まらないときだけ評価する。`if` / `match` は、取る分岐・腕だけを評価する。
- 引数を全て評価してから呼び出す。`inout` の排他性（§5.2）は、その呼び出しの引数の評価の始まりから呼び出しの終わりまでについて判定する。その間に `inout` の場所を読むだけなら重ならない（`xs.fill!(xs.len())` は書ける）が、他の引数の中で変更すると E0702（`f(inout x, g(inout x))`、`xs.fill!(g(inout xs))`）。
  変更は、`inout` への受け渡しと `!` の呼び出しである（代入は文なので引数の中に現れず、`move` は既存の重なりの検査で落ちる）。`f` に渡るのが変更の後の値であることは、評価順を知らないと読めないからである。
- panic しうる式が複数あるときは、この順で最初に panic する式が報告される（`xs[i][j]` で両方が範囲外なら `i`）。
- flow の本体は、§11.3 のクロックの段の順（`init`、`block`、`sample`）に評価する。同じ段の中では上の規則に従い、`if` / `match` と `&&` / `||` も fn と同じく、取る分岐と必要な右辺だけを評価する。全ての枝を評価するのは `if~` / `match~` だけである（§11.5）。
