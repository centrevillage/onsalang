## 5. 値・変数・引数モード（可変値意味論）

### 5.1 束縛

```onsa
let x: I32   = 1   // 不変
var acc: F64 = 0.0 // 可変（ローカルのみ）
acc = acc + (x as F64)
```

- `let` の束縛と借用の引数は変更できない（代入すると、また `inout` で渡すと E0701）。代入の左辺は場所（変数、引数、それらのフィールドと要素）でなければならない（E0415）。`const` は場所ではない（`LIMIT = 4` は E0415）。
  `inout` に場所でないもの（定数、一時値、呼び出しの結果）を渡すのも E0415 で、E0701 は場所だが変更できないもの（`let` の束縛、借用の引数）に使う（直し方が違う。E0701 は宣言を `var` にする）。タプルを左辺にする代入（`(a, b) = (b, a)`）は書けない（E0415。`let` で分解してから一つずつ代入する形を note で示す）。
  一つずつの代入と同じことをする二つ目の書き方になるからである（P2）。
- 代入は **値** の代入。`var b = a` の後で `b` を変えても `a` は変わらない（Shared 型は書き込み時コピー、一意なら in-place。Perceus 方式の参照カウント）。
- 参照は値として存在しない。したがってライフタイムも無い。
- **シャドーイングは無い。** ある名前の束縛が見えている間は、同じ名前を束縛できない（E0304）。`let x = x + 1` も、`for i in ...` の中で `let i` と書くこともエラー。兄弟のスコープ（二つの `for i in ...`、二つの `match` の腕の `Some(x)`）では同じ名前を使える。
  見えている束縛には、モジュールの項目、`use` で取り込んだ名前、prelude、組込み型も含み、flow の本体の中では flow の組込みの名前（§11.4）も含む。
  ローカル（引数と flow の入力を含む）がそれらと同じ名前を使うと E0304（`use std.math` の後の `let math`、関数 `gain` のあるモジュールの `let gain` と `fn f(gain: F32)`、`let env = env~(gate)`）。
  項目の型パラメータ・const パラメータ・効果行変数（§4.5）と、引数・flow の入力も、その項目の中（見出しの全体と本体。`impl` の見出しの並びはメンバまで、無名関数の引数はその式の中）で見える束縛で、同じ並びの名前、外の `impl` の並びの名前、上の束縛、ローカルと同じ名前を使うと E0304 である（`fn f[T, T]`、`struct Item` のあるモジュールの `fn f[Item]`、`fn f[I32]`、`impl[T]` のメンバの `fn m[T]`、`fn f[e]` の本体の `Err(e)`）。
  誤りは後（内側）の宣言の位置に出し、その項目の単位に閉じる（§18.1）。E0304 になったローカル（引数と flow の入力を含む）は束縛として数えず、見える範囲の同じ名前は重なった相手を指す（`fn f(a: Item, Item: U32)` の `a: Item` は項目で、誤りは `Item: U32` の E0304 だけ。失敗した `use` の名前と同じ、§18.1）。
  束縛は、型の位置（型の中の定数式と効果行を含む）からも、値の位置と同じ範囲で見える。fn の本体の `let`・`var` の束縛（分解を含む）はその文の後ろから見え、自分の注釈と初期化式からは見えない（`let a: a = 1` は見つからない名前の E0302）。flow の本体の `let` は本体の全体で見え、値の位置の順は §11.2 による。
  見えている値の束縛を型の位置に書くと E0308、型の中の定数式に書くと E0417 である（`fn g(n: U32, a: [F32; n])` は E0417、§15.1、§4.5）。
  flow の本体からはモジュールの項目と `use` で取り込んだ名前も見えるので、これらに組込みの名前を使うと E0304 である（`flow prev`、`fn delay`、`use util.{prev}`、`use dsp.delay`）。
  利用者の項目と `use` の束縛が組込み型や prelude と同じ名前（`struct F32`、`enum Option`、`fn panic`、`use kp.panic`）を使うのも E0304（§15.1）。一つの名前は、見える範囲で常に一つのものを指す。flow の本体はブロックが一つなので、flow の自己参照（§11.2）と意味が衝突しないための規則でもある。
- **使われない束縛は E0309。** 対象は `let` / `var`（分解を含む）、`match` の腕、`for` の束縛で、一度も参照されないもの（代入は参照に数えない）。flow の本体では、出力と `let _` から辿れない `let` が使われない束縛である（`^` の帰還だけで互いを参照する組も含む、§11.2）。
  値を使わないときは `_` で明示する（`let _ = e`、`let (l, _) = pair`、`for _ in 0 ..< n`、`Some(_)`）。修正候補は名前を `_` に変える形である（`var y = e` は `var _` と書けないので候補なしで、`let _ = e` と書く形を note で示す）。
  E0309 の位置は使われない束縛の名前（選択のパターンでは最初の位置）である。E0309 は §18.1 の最後の段で、同じ単位に他の誤りがあれば報告しない。名前が §2.3 の形に反する読まない束縛（`let _x = 1`）は、fn でも flow の本体でも、先に E0320（修正候補は `x`）を報告し、当てた後に E0309（修正候補は `_`）を報告する。
  関数と flow の引数は対象外（シグネチャは呼び出し側との約束で、trait の実装では使わない引数もある）。
  名前を付けて黙って捨てる値を残さないための規則で、文の値の E0418（§6.1）と同じ考え方である。

### 5.2 引数モード

| モード | 宣言 | 呼び出し位置 | 意味 |
|---|---|---|---|
| 借用（既定） | `x: T` | `f(x)` | 読み取り専用。呼び出し中は変更されない。 |
| `inout` | `inout x: T` | `f(inout x)` | 排他的な可変借用。呼び出し側は `var`、`inout` 引数、`move` の引数か `move self` であること。 |
| `move` | `move x: T` | `f(move x)`（Affine 値。Dup 値は `f(x)`） | 所有権を受け取る。Affine 値はこの後使えない。Dup 値は複製して渡す。 |

構築子（列挙子のペイロード。`Some(x)`、`E.A(x)`）の要素は、struct / 配列 / タプルのリテラルの要素と同じ消費する位置で（下）、値で受ける。`inout` の印は E0703 である。

`move x` は、値が消費される他の位置にも書く式の形である: `let` / `var` の初期化（`let y = move x`）、代入の右辺、struct / 配列 / タプルのリテラルと構築子の要素、`match` の対象（`match move x`）、`for` の反復元（`for s in move xs`、§5.4）。
例外は関数の返り値（`return x` と末尾の式）と、中身を取り出す形（`move self` のメソッドの受け手（下）と後置 `?` の被演算子、§9.1）で、値が関数の外へ出ることと取り出されることは書かなくても見える。Affine 値を `move` 無しでこれらの位置に置くと E0711（修正候補は `move` の挿入）。
`move` と `inout`（呼び出し位置の印）の被演算子は後置式（名前と、それに続くフィールド・添字・呼び出し）で、二項演算子の被演算子にはならない（`move y + 1` と `take(move y + 1)` は E0002）。
印の付いた式は、消費する位置と引数の位置にそのまま書き、括弧で囲めるのは 2 要素以上のタプルの要素としてだけである（`1 + (move y)`、`if (move y) == 1 {` は E0002）。

ブロックの末尾の式（`if` と `match` の腕、ブロック式の末尾）は、そのブロックが置かれた位置を継ぐ。消費する位置に置いたブロックでは、各腕を `let y = <腕の値>` と書いたときと同じに扱う。
Affine の変数（フィールドの経路を含む）には `move` を書き（`let y = if c { move a } else { move b }`、`take(if c { move a } else { move b })`）、新しく作った値と Copy の値には書かない（`let y = if c { move a } else { Buf.zeroed(n) }` は正しい）。
  束縛の見出し（`let` / `var` の初期化、`match` の対象、`for` の反復元）の Dup の値の `move` は所有の束縛を選ぶ印として受け付ける（§5.4）。値を置く位置（代入の右辺、struct / 配列 / タプルのリテラルと構築子の要素）と `move` の引数に置いたブロックの末尾の Dup の値の `move` は、直接の `move` の引数と同じく E0703 である（下）。
腕の数を揃える規則ではなく、消費される Affine の変数ごとに印を付ける規則である。関数の返り値の位置に置いたブロック（関数の末尾の `if`）の腕には書かない。片方の腕でだけ消費した変数は、その後で使えない（E0704）。
移動は制御の流れに沿って数える。ループの本体で移した変数を次の反復（条件の再評価と `continue` の道を含む）で使うと、反復の回数によらず E0704 である。移した `var` は全体に代入すると再び使え、フィールドや要素への代入は使用に数える（E0704）。
返り値の位置に書いた `move`（`return move a`、関数の末尾の `move a`、そこに置いたブロックの腕の `move a`）は意味を変えない余分な情報で、検査は受け付けるが、書かない。中身を取り出す形の被演算子に置いたブロックの腕の `move` も同じである。
`match` と `for` の見出しに置いたブロックの末尾にも `move` を書け、そのとき腕の束縛と反復は所有になる（§5.4）。それ以外の位置（文、条件、二項演算子の被演算子、添字、範囲の端、借用と `inout` の引数）に置いたブロックの末尾の `move` は E0703 で、末尾の `move` ごとに一件、その `move` を消す修正候補を示す。
`move` の被演算子は場所（局所の変数と、そのフィールド・添字の経路。括弧で囲んだ場所は中身と同じ）で、場所でない値（呼び出しの結果、リテラル、定数、関数の項目の名前、ブロック、`if`・`match`）に付けると、位置によらず E0711 である（`for` の見出しの範囲に付けた `move` は E0703、§7）。
修正候補は、ブロックと `if`・`match` なら外の `move` を消して各末尾の Affine の変数に `move` を置く形、それ以外は `move` を消す形である。
末尾に `move` を置くのは消費する位置（束縛の見出し、値を置く位置、`move` の引数）だけで、消費しない位置と返り値の位置では外の `move` を消すだけにする（末尾の `move` が上の E0703 になるため、§18.1）。末尾に借用か `inout` の Affine の場所があれば候補は無い。
場所でない値（新しく作った値、Copy のリテラル）を `move` の引数に渡すときは、`move` を書かない（`take(Buf.zeroed(4))`）。
`onsa fmt` は取り除かない。`move` の後ろが局所の変数の場所かは名前の段で決まり、定数への `move K` は E0711 なので、取り除くと検査の結果が変わる（§18.2）。
ただし、§5.4 の借用束縛（借用引数からの `let y = x` など）は消費しない。Dup 値の `move`（`let y = move s`）は複製になる（`move` 引数に `move` 無しで渡した Dup 値と同じ）。

所有する値の Affine のフィールドを消費する位置に置くと（`let b = move s.buf`、`f(move s.buf)`、返り値の `s.buf`）、`s` 全体を消費する。取り出したフィールド以外はその場で破棄され、以後 `s` は使えない（E0704）。
意味は分解の `let Holder { buf: b, gain: _ } = move s` と同じで、他のフィールドが要るときは先に読むか、分解で一緒に取り出す。Rust の部分移動と違い、残りのフィールドを後で使うことはできない（フィールドごとに移動の状態を持たない）。
対象は struct とタプルのフィールドの経路で（`move s.inner.buf` も可）、配列の要素は取り出せない（`move xs[i]` は E0711。要素は `for x in move xs` で取り出す）。経路に `Drop` を実装する型があれば取り出せない（E0711、§6.3）。Copy と Shared のフィールドは複製されるので、`s` を消費しない。
取り出した後に `s` を使った E0704 は、取り出した位置と、先に読むか分解する書き方を note で示す。

- `inout` と `move` は **呼び出し位置にも書く**。読み手は呼び出し 1 行で、何が変わるかを知る。`inout` は Swift、`move` は C++ / Rust と同じ意味。
- `move` の印は、所有が移って前の値が以後使えなくなる所（Affine 値）にだけ付ける。`move` 引数に渡す Dup 値（Copy、Shared、関数値の変数）には `move` を書かず（`tk(n)`、`ts(s)`、`ap(f)`）、その場で複製して渡す。
  代入の右辺とリテラル・構築子の要素の Dup 値も同じで（`x = n`、`Some(n)`、`(n, 1)`）、書くと E0703 で、修正候補はその `move` を消す形である（ブロックの末尾も同じで、末尾ごとに一件）。
  束縛の見出し（`let y = move s`、`match move s`、`for s in move xs`）の `move` は所有の束縛を選ぶ（§5.4）ので受け付ける。総称の `T: ?Dup` の値は Affine でありうるので `move` を書く（本体は境界で検査する）。
  Affine 値は所有していなければ `move` で渡せない。借用引数、借用束縛、`inout` 引数は所有していない。その場所を `move` 引数に置くと、印の有無によらず修正候補の無い E0711 である（`take(a)`、`take(if c { a } else { b })`。直すのは引数のモードか呼ぶ側で、誤りの位置から離れる）。
  `inout` 引数から `move` で取り出すと、呼び出し側の値が破棄済みになるからである。
- 同じ変数を一つの呼び出しで二度 `inout` に渡すと、また `inout` と借用の両方に渡すと（`h(x, inout x)`）エラー（E0702）。借用の引数は、呼び出し中は変更されないと約束しているからである。同じ値の **異なるフィールド**（`self.voices[i]` と `self.params[i]` など）は重ならないものとして扱う。
  同じ配列の添字どうしは、添字が等しいかを静的に判定しないので、重なるものとして扱う。部分ビュー（`xs.slice(from, to)`、§5.3）も範囲によらず、元の場所、その添字、同じ元のほかの部分ビューと重なる（`f(inout a.slice(0, 4), a.slice(4, 8))` は E0702）。
  引数は全て評価してから呼び出すので、引数の中で同じ変数を読んで値を作るだけなら重ならない（`xs.fill!(xs.len())`）。他の引数の中で `inout` に渡すか `!` を呼ぶと重なる（`f(inout x, g(inout x))` は E0702、§3.5）。
  引数に置いたブロック式や腕の中の代入と `move`、入れ子の呼び出しの `move` の引数も同じ変更で、引数の順によらず E0702 である（`fn2(b, { o = None … })`、`fn2(x, take(move x))`。Copy の `var` を借用の引数に渡す `h(m, { m = 5 … })` も）。
  変更が実行されない道（`if` の片方の腕、ループの本体、`&&` の右辺）にあっても数える。引数の中のブロックで宣言した変数への代入は、どの引数とも重ならない。
  `move` の引数に渡す場所が、同じ呼び出しの他の引数（`inout`、借用、`move`）の場所と重なるときも E0702 である（`h(inout x, move x)`、`h(x, move x)`）。引数は全て評価してから呼ぶので、引数の順によらない。Affine のフィールドの経路の `move` は根の全体を消費する（上）ので、根のどの場所とも重なる（`h(inout x.a, move x.b)`）。
  `move` の引数に印を書かずに渡す Dup の値の場所と、Dup の値の `move self` の受け手は、複製して渡すが、重なりでは借用の引数と同じくその場所の読みとして数える。`inout` の場所と重なれば E0702 で（`io_move(inout n, n)`）、読みどうしは重ならない（`bm(n, n)`、`mm(n, n)`、`p.plus(p.x)`）。呼び出しの行の結果が、呼び先が Dup の引数を借用と `move` のどちらで宣言していても変わらないためである。
  `move` の引数で移した変数は、その引数を評価した時点で使えなくなる（§3.5 の左からの評価）。同じ呼び出しの後の引数で読むと E0704 で（`take2(move b, b.len())`）、前の引数で読む形は通る（`take2r(b.len(), move b)`）。派生した借用束縛が使えなくなるのは呼び出しの後である（§7）。
  Copy でない借用束縛（`match` の腕の束縛と、そこから派生した束縛、§5.4）とその経路は、派生元の場所として重なりを見る。
  腕の束縛の場所は対象の場所にパターンのタプル・struct の経路を加えたもので、列挙子のペイロードは対象の全体である（`match o { Some(b) => f(b, inout o) }` と `g(inout o, b)` はどちらも E0702。`match w.a { Some(b) => f(b, inout w.c) }` と `match p { (a, _) => g(inout p.1, a) }` は重ならない）。
  Copy の束縛は束縛した時点の値で、重ならない（§5.4）。
- メソッドのレシーバは `self` / `inout self` / `move self` と宣言する。`inout self` のメソッドの呼び出しは、名前の直後に `!` を付ける（`out.fill!(0.0)`）。無ければ E0713、`inout self` のメソッドでない呼び出し（関数、関数値、構築子を含む）に付ければ E0714。どちらも修正候補は一意。`!` の直後には `(` が続き、名前の一部ではない。
  レシーバは可変な場所（`var`、`inout` 引数、`move` の引数と `move self`、それらのフィールドや要素）でなければならない。
  場所でないレシーバ（呼び出しの結果、定数）は E0415 で、場所だが変更できないもの（`let` の束縛、借用の引数）は E0701 である（`inout` に渡す値と同じ、§5.1）。`move self` には印を付けない。`move` の観測できる効果は「以後使えない」ことだけで、検査器が局所的に捕まえる。
  Ruby / Julia の `sort!` と同じ意味で、連鎖の中でも値を変える呼び出しに印が付く。
  Onsa の呼び出しの形は `f(x)`（関数）、`f~(x)`（インスタンス生成）、`x.f!(y)`（レシーバの変更）、`v.(x)`（関数値、§6.1）と、名前の直後の印と `(` で揃う。
- 関数型の引数もモードに従う。既定のモードの関数型の引数（`f: fn(I32) -> I32`）は、捕捉する無名関数も受け、関数の中では第二級になる（§5.3）。呼ぶことと、別の関数の既定のモードの関数型の引数へ渡すことはでき、返す、保存する（`let` / `var` の初期化、代入、フィールド、要素）、無名関数で捕捉する、`move` の引数へ渡すと E0710。
  関数値を受け取って持つ関数は `move f: fn(I32) -> I32` と宣言し、捕捉の無い関数値だけを受ける（捕捉する無名関数を渡すと E0710）。呼び出し側は `make_op(1, inc)` と書く（関数の項目の名前は場所でなく、`move inc` は E0711）。値が呼び出しの外へ出る側の印は、宣言の `move f` である（P10）。

### 5.3 第二級の値: 借用・`Span`・捕捉するクロージャ

次のものは **引数の位置にだけ** 現れる。返り値、構造体のフィールドにはできない（E0710）。そのため、どれもヒープを使わず、ライフタイムも要らない。借用と `Span`（平面の要素と部分ビューを含む）だけは、§5.4 の規則で `let` と `for` と `match` の腕に束縛できる。
第二級にする理由は値ごとに違う。借用と `Span` は他の値の記憶域を指すので、呼び出しより長く生きるとライフタイムが要る。借用の起点は呼び出しの間に変わらず消えないので、そこから作った借用束縛は関数の中に置ける（§5.4）。
捕捉するクロージャは、捕捉の環境を呼び出し側に置いてヒープを使わないために第二級で、`let` には束縛できない（既定のモードの関数型の引数と同じ、§5.2）。

| もの | 書き方 | 意味 |
|---|---|---|
| 借用 | `f(x)`, `f(inout x)` | §5.2 |
| `Span[T]` | 引数の型として `xs: Span[T]` / `inout xs: Span[T]` | 連続した要素の非所有ビュー（C++20 の `std::span` と同じ意味）。`[T; N]`、`Buf[T]`、`Span[T]` を渡せる（`Span[U8]` には `FixedStr[N]` も渡せ、使った長さの部分を見る。`inout` の `Span[U8]` には渡せず E0401、§4.2）。メソッドは `len()`、`slice(from, to)`、`get(i) -> Option[T]`、`fill!(v)`、`add_from!(other)`、`copy_from!(other)` で全てで、`[T; N]` と `Buf[T]` にも同じものがある（空かどうかは `len() == 0`、§4.2） |
| 部分ビュー | `f(xs.slice(from, to))`, `f(inout xs.slice(from, to))` | 半開区間 `[from, to)` の `Span`。範囲外は panic。`for` の反復元 `for v in xs.slice(from, to)` も引数の位置に含み、`xs` の借用の `for` である（本体で `xs` を変更すると E0715、§5.4） |
| `Span` の配列 | 引数の型として `xs: [Span[T]; N]` / `inout xs: [Span[T]; N]` | チャンネルごとのバッファ（planar）。`[[T; M]; N]`、`[Buf[T]; N]`、`[Span[T]; N]` の値をそのまま渡せる（要素ごとに `Span` へ変換）。別々の変数にあるときは `[a, b]` / `inout [a, b]` と配列リテラルを引数の位置にだけ書け（要素の種類と長さは揃っていなくてよい。長さの約束は `process` / `render` のもの、§11.6）、排他性は要素の場所ごとに検査する。`xs[k]` は `Span[T]` で、引数の位置に現れる（メソッドの受け手 `xs[k].len()`、添字の左辺 `xs[k][i]`、`for` の反復元 `for v in xs[k]` も引数の位置に含む。受け手は `self` の引数である）。`xs` が借用の起点なら、§5.4 の借用束縛にもできる |
| 捕捉するクロージャ | `array.from_fn(fn(i) { k * i.round_f32() })` | 外側の値をコピーで捕捉する無名関数。捕捉した値は読み取り専用で、代入すると E0701。`inout` 引数と Affine 値は捕捉できない（E0712）。既定のモードの関数型の引数（§5.2）に渡せる |

`Span[T]` と `[Span[T]; N]`（別名を通したものも）は `move` の引数の型に書けない（E0710）。非所有のビューを所有で受け取る意味は無いからで、関数型の引数の並び（`fn(move Span[F32]) -> F32`、§5.2）と無名関数の引数も同じである。note で書ける形（読むなら `xs: Span[T]`、書き換えるなら `inout xs: Span[T]`、所有して持つなら `move xs: Buf[T]`）を示す。

flow の生成型 `voice.In` / `voice.Out`（§11.6）も `Span` を持つので第二級で、返り値と構造体のフィールドと `move` の引数と `impl` の対象にはできない（E0710）。引数に書ける平面の配列は `Span` の要素に限り、`[voice.Out; 2]` は E0710 である。
§5.4 の束縛は借用と `Span` だけなので、`In` / `Out` は引数の位置にだけ現れる（フィールドを受け手や添字の左辺に使うのも同じ。`Span` のフィールドは §5.4 の借用束縛にもできる）。

捕捉の無い関数値（名前付きの関数、捕捉しない無名関数）は Copy の第一級の値で、保存も返却もできる。ただし、既定のモードの関数型の引数は捕捉を持ちうるので、受け取った関数の中では第二級で、複製して持ち出せない（返す、保存する、捕捉する、`move` の引数へ渡すと E0710、§5.2）。保存できる関数値を受け取るのは `move` の関数型の引数で、捕捉の無い関数値だけを受けて所有する。変換先では、既定のモードの関数型の引数を関数と環境の組で、保存する関数値を関数だけで表す（§13.5）。

### 5.4 借用束縛

`let` と `for` の束縛は、初期化の元の形と、集成体のリテラルの要素の種によって **借用** か **所有** かが決まる。本体での使い方には依存しない。

| 束縛 | 種類 | 破棄 |
|---|---|---|
| 既定のモードの引数と `self`（関数、メソッド、trait の既定の本体、無名関数、handler の関数）、flow の入力 | 借用（起点） | 起きない |
| `inout` の引数と `inout self` | `inout`（所有しない） | 起きない |
| `move` の引数と `move self` | 所有（書き換えられる） | 起きる |
| `let y = x`、`let y = x.f`、`let y = x[i]`、分解（`let (a, b) = x`）、`Span` の部分ビュー `let y = x.slice(a, b)`（`x` は借用の起点、または起点から派生した借用束縛）。`let y = CONST`、`let s = "abc"`、`let t = ["a", "bc"]`（静的な値）。`let p = ("gain", v)`（破棄の要らないリテラル。`v` は Copy の型） | 借用 | 起きない |
| `let y = f(...)`、`let y = move x`、静的な値でも破棄の要らないリテラルでもないリテラル（`let q = ("gain", s)`、`s` は借用の `Str` の引数）や演算の結果 | 所有 | 起きる |
| `var y = ...` | 所有（書き換えられる） | 起きる |
| `for s in xs`（`xs` は任意の場所か、静的な値か、破棄の要らないリテラルか、それらの経路。部分ビューの `for s in xs.slice(a, b)` は、範囲によらず `xs` の場所を反復元とする） | 借用（起点） | 起きない |
| `for s in move xs` | 所有。`xs` を消費する | 要素ごとに起きる（§12.2） |
| `for s in f(...)`（場所でも静的な値でも破棄の要らないリテラルでもなく、それらの経路でもない反復元。部分ビューを除く） | 所有。一時の値を消費する | 要素ごとに起きる（§12.2） |
| `for i in a ..< b`、`par i in a ..< b` の添字（`..=` も同じ） | 所有（整数） | 起きない（Copy） |
| `match x` の腕の束縛（`x` は任意の場所か、静的な値か、破棄の要らないリテラルか、それらの経路） | 借用（起点） | 起きない |
| `match move x` と、場所でも静的な値でも破棄の要らないリテラルでもなく、それらの経路でもない対象（`match f(...)`）の腕の束縛 | 所有 | 起きる |
| 総称の定数のパラメータ（`const N: U32`）を値として使う | 定数（Copy） | 起きない |
| 無名関数が捕捉した変数 | 読み取り専用のコピー（§5.3）。Shared 型の値の捕捉が複製か借用かは第 2 期に決める | — |

- 借用の起点は、借用引数（既定のモードの引数と `self`。`inout` 引数は含まない）、借用の `for` の束縛（`for s in xs`、`xs` はどの場所でもよい）、借用の `match` の腕の束縛（`match x`、`x` はどの場所でもよい）、静的な値と破棄の要らないリテラル（下）である。
  静的な値と破棄の要らないリテラルは不滅の静的オブジェクト（§12.8）と Copy の値だけでできた値で、複製も破棄も何もせず、解放も in-place 更新も起きないので、起点にしても安全である。そこから `let`、`for`、`match` の腕で作った借用束縛も起点として扱う（派生）。ローカルの `var` / `let` と `inout` 引数は起点にならない。
  `match x` の腕の束縛から派生した束縛は、腕の束縛と同じく、腕の中で `x` を変更すると重なるものが以後使えなくなる（§7）。分解する `let` では、元が起点なら各束縛が借用束縛になる（`let (a, n) = p` は `let a = p.0` と同じ）。
- 借用の `for`（`for s in xs`）の本体では、反復元 `xs` とその一部を変更できない。代入、`inout` への受け渡し、`!` のメソッドの呼び出し、`move` は E0715。
  反復元が派生した借用束縛かその経路（`match o { Some(bs) => for x in bs { … } }` の `bs`、`let cs = bs` の `cs`、`bs.0`、部分ビュー）なら、派生元の場所に経路を合成した場所（§5.2 の E0702 と同じ）で重なりを見るので、派生元とその重なる一部の変更も E0715 である（本体の `o = None`、`reset(inout o)`）。
  異なるフィールドは重ならず、Copy の束縛は束縛した時点の値なので当たらない。Dup の値の所有の反復（`for s in move bs`。複製を反復する）も、本体の Dup の値の `move`（`let c = move xs`。複製で読み、§5.2）も当たらない。
  反復の途中で集合が変わらないので、どの要素が見えるかが一意に決まり、複製の費用も掛からない。反復しながら要素を書き換えるときは、添字で回す（`for i in 0 ..< xs.len() { xs[i] = xs[i] * 2.0 }`）。
- 借用束縛は読み取り専用で、`inout` に渡せない。借用の引数と同じ扱いで、`move` 引数へは Dup 型なら複製して渡し（§5.2）、Affine 型なら渡せない（E0711）。返り値にするときも Dup 型は複製になる。ただし、既定のモードの関数型の引数は捕捉を持ちうるので、`let` に束縛できず、返り値や `move` の引数にして複製することもできない（E0710、§5.3）。Copy の借用束縛は、束縛した時点の値を持つ（後で元の場所が変わっても変わらない、§7）。
- `for` の借用束縛がどの場所からでも安全なのは、本体で `xs` を変更できない（E0715）ので、反復の途中で要素が変わることも、in-place 更新（§12.6）で記憶域が解放されることも無いからである。`let` の借用束縛の起点を限るのは、ローカルの `var` や `let` から借りると、Perceus の in-place 更新で元の記憶域が解放されうるからである。
  `inout` 引数も、関数の中で書き換えられるので同じ理由で起点にしない。借用の `for` の束縛を起点にできるのは、本体で反復元を変更できない（E0715）からで、`match` の腕の束縛を起点にできるのは、対象を変更した後に重なる束縛を使えない（E0704、§7）からである。
- この規則により、借用した `Array[Str]` を読むだけの反復は `Alloc` を要しない。rt の関数でも、定数の表や文字列と、静的な値と Copy の値だけでできたリテラル（`["a", "bc"]`、`Param { name: "gain", value: v }`）を `let` で受けられる。
- 静的な値は、`const`（関連定数と総称の定数のパラメータを含む）、補間の無い文字列リテラル、数・真偽・文字のリテラル、ペイロードの無い列挙子と、全ての要素が静的な値の配列（`[e; N]` を含む）・タプル・struct のリテラル・ペイロード付きの列挙子・括弧（入れ子を含む。`["a", "bc"]`、`("a", 1)`、`Some("a")`）である。
  演算子・呼び出し・ローカルの名前を含む式は静的な値でない。静的な値は構文で決まり、要素の型を見ない（自分の型が Dup でないものは除く、下）。集成体のリテラルの置き場所（静的領域か、使う所で組むか）は約束しない。
- 破棄の要らないリテラルは、静的な値でない集成体のリテラル（配列（`[e; N]` を含む）・タプル・struct のリテラル・ペイロード付きの列挙子・括弧。入れ子を含む）で、各要素が静的な値か、第一級の Copy の型の式か、破棄の要らないリテラルか、破棄の要らない束縛の名前とその経路であるものである。
  例は `("a", 1 + 2)`、前置の `-` の `("a", -1)`、`("a", v)`、`Param { name: "gain", value: sq(v) }`、`(nm, v)`、`W { p: p, k: 1 }` である（`v` は `F32`）。
  破棄の要らない束縛は、静的な値か破棄の要らないリテラルで初期化した借用束縛と、そこから派生した借用束縛（`let q = p`、分解、`for`、`match` の腕）である（`let nm = "gain"` の `nm`、`let p = Param { name: "gain", value: v }` の `p`）。その経路はフィールドと添字の経路（`p.name`、`p.0`、`t[i]`）である。
  `if`・`match`・ブロック式で初期化した束縛は、発散しない全ての末尾が静的な値か破棄の要らないリテラルか破棄の要らない束縛とその経路のときだけ、破棄の要らない束縛である（`if c { p } else { s }` は、`s` が借用の `Str` の引数なら当たらない）。
  静的な値と同じく、複製も破棄も何もしない。派生元は無いので、§7 の重なる束縛の無効化と E0715 は当たらない。値は使う所で組む。
  要素が Copy かは、本体の型の推論の後の型（既定を当てた後）で決める。`T: Copy` の値は Copy で、境界の無い `T` と `T: ?Dup` の値は Copy でない。リテラルと列挙子の自分の型が Dup かも同じ時点の型で決める（境界の無い `T` と `T: Copy` は Dup、`T: ?Dup` は Dup でない）。第二級の値（§5.3）を要素に持つ形は E0710 で、この判定に入らない。
  これらのどれでもない要素を持つリテラルは所有の行である（`["a", s]`・`("a", s)`、`s` は借用の `Str` の引数。`let p = (s, v)` の `p` を要素にする `W { p: p, k: 1 }`）。
  自分の型が Dup でない（Affine か、`T: ?Dup` のように Affine でありうる、§4.5・§4.6）リテラルと列挙子は、要素によらず静的な値にも破棄の要らないリテラルにもならず、所有の行である（`let o: Option[Buf[F32]] = None`、`Buf` のペイロードを持つ列挙子のある列挙の `let e = E.A`、`Drop` を実装する型のリテラル）。
  借用の行にして失うものが無いのは、複製が自由な Dup の値だけだからである。Affine の型の値は所有の Affine と同じく `move` の引数へ渡せる（`Drop` を実装する型の値は、破棄で `drop` が呼ばれる、§6.3）。
- 表に無い初期化の元: 括弧は中身と同じ。`if`・`match`・ブロック式は、発散しない全ての末尾で決め、全ての末尾が借用の行なら借用、一つでも所有の行なら所有である（`let t = if c { x } else { y }` は、`x`・`y` が借用の起点なら借用で、rt の関数でも破棄が起きない）。
  借用のとき、派生元は末尾の場所の全てで、§7 の重なる束縛の無効化はその各々に当たる。`for` と `match` の見出しも同じ規則で決め、見出しの借用の行は場所か、静的な値か、破棄の要らないリテラルか、それらの経路（`match ["a", "bc"][i]`、`for c in TABLE.cols`）で、E0715 も末尾の場所の各々に当たる。
  所有のとき、各末尾は所有の束縛の初期化として検査する（借用の Dup の値は複製、借用の Affine の値と `inout` 引数の値は E0711 で修正候補なし、ローカルの Affine の値は `move` の挿入を候補にする E0711）。全ての末尾が発散する初期化式は §7 の E0503 で、束縛の種類は問わない。
- `Span`（平面の要素 `xs[k]`、`Span` の引数、生成型 `In` / `Out` の `Span` のフィールド `o.l`、部分ビュー）は、元が借用の起点か派生した借用束縛なら、借用の行で `let` と `for` と `match` の腕に束縛できる（`let ch = input[0]`、`for ch in input`）。束縛した名前も第二級のままで、返す・保存する・捕捉する・`move` の引数へ渡すと E0710 である（§5.3）。
  `inout` 引数からの `Span` と、所有の行の `Span`（`let (l, r) = (xs[0], xs[1])`、`move xs[0]`）は束縛できず、束縛の場所に置いた値の位置で E0710 である。
- この表は、文法の全ての束縛の場所を覆う。分解したパターンの各束縛は、その行の種類を受け継ぐ。文法に束縛の場所を足すときは、この表に行を足す。

```onsa
pub fn total_len(xs: Array[Str]) -> U32 {
  var n: U32 = 0
  for s in xs { n = n + s.len() } // s は借用。破棄が無いので Alloc は要らない
  n
}
```
