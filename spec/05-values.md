## 5. 値・変数・引数モード（可変値意味論）

### 5.1 束縛

```onsa
let x: I32   = 1   // 不変
var acc: F64 = 0.0 // 可変（ローカルのみ）
acc = acc + (x as F64)
```

- `let` の束縛と借用の引数は変更できない（代入すると、また `inout` で渡すと E0701）。代入の左辺は場所（変数、引数、それらのフィールドと要素）でなければならない（E0415）。`const` は場所ではない（`LIMIT = 4` は E0415）。
  `inout` に場所でないもの（定数、一時値、呼び出しの結果）を渡すのも E0415 で、E0701 は場所だが変更できないもの（`let` の束縛、借用の引数）に使う（直し方が違う。E0701 は宣言を `var` にする）。タプルを左辺にする代入（`(a, b) = (b, a)`）は書けない（E0415。`let` で分解してから一つずつ代入する形を note で示す）。
  一つずつの代入と同じことをする二つ目の書き方になるからである（P2）。
- 代入は **値** の代入。`var b = a` の後で `b` を変えても `a` は変わらない（Shared 型は書き込み時コピー、一意なら in-place。Perceus 方式の参照カウント）。
- 参照は値として存在しない。したがってライフタイムも無い。
- **シャドーイングは無い。** ある名前の束縛が見えている間は、同じ名前を束縛できない（E0304）。`let x = x + 1` も、`for i in ...` の中で `let i` と書くこともエラー。兄弟のスコープ（二つの `for i in ...`、二つの `match` の腕の `Some(x)`）では同じ名前を使える。
  見えている束縛には、モジュールの項目、`use` で取り込んだ名前、prelude、組込み型も含み、flow の本体の中では flow の組込みの名前（§11.4）も含む。
  ローカルがそれらと同じ名前を使うと E0304（`use std.math` の後の `let math`、関数 `gain` のあるモジュールの `let gain`、`let env = env~(gate)`）。
  flow の本体からはモジュールの項目と `use` で取り込んだ名前も見えるので、これらに組込みの名前を使うと E0304 である（`flow prev`、`fn delay`、`use util.{prev}`、`use dsp.delay`）。
  利用者の型が組込み型や prelude と同じ名前（`struct F32`、`enum Option`）を使うのも E0304。一つの名前は、見える範囲で常に一つのものを指す。flow の本体はブロックが一つなので、flow の自己参照（§11.2）と意味が衝突しないための規則でもある。
- **使われない束縛は E0309。** 対象は `let` / `var`（分解を含む）、`match` の腕、`for` の束縛で、一度も参照されないもの（代入は参照に数えない）。flow の本体では、出力と `let _` から辿れない `let` が使われない束縛である（`^` の帰還だけで互いを参照する組も含む、§11.2）。
  値を使わないときは `_` で明示する（`let _ = e`、`let (l, _) = pair`、`for _ in 0 ..< n`、`Some(_)`）。修正候補は名前を `_` に変える形である。関数と flow の引数は対象外（シグネチャは呼び出し側との約束で、trait の実装では使わない引数もある）。
  名前を付けて黙って捨てる値を残さないための規則で、文の値の E0418（§6.1）と同じ考え方である。

### 5.2 引数モード

| モード | 宣言 | 呼び出し位置 | 意味 |
|---|---|---|---|
| 借用（既定） | `x: T` | `f(x)` | 読み取り専用。呼び出し中は変更されない。 |
| `inout` | `inout x: T` | `f(inout x)` | 排他的な可変借用。呼び出し側は `var` か `inout` 引数であること。 |
| `move` | `move x: T` | `f(move x)` | 所有権を受け取る。Affine 値はこの後使えない。 |

`move x` は、値が消費される他の位置にも書く式の形である: `let` / `var` の初期化（`let y = move x`）、代入の右辺、struct / 配列 / タプルのリテラルの要素、`match` の対象（`match move x`）、`for` の反復元（`for s in move xs`、§5.4）。
例外は関数の返り値（`return x` と末尾の式）だけで、値が関数の外へ出ることは書かなくても見える。Affine 値を `move` 無しでこれらの位置に置くと E0711（修正候補は `move` の挿入）。
`move` と `inout`（呼び出し位置の印）の被演算子は後置式（名前と、それに続くフィールド・添字・呼び出し）で、二項演算子の被演算子にはならない（`move y + 1` と `take(move y + 1)` は E0002）。
印の付いた式は、消費する位置と引数の位置にそのまま書き、括弧で囲めるのは 2 要素以上のタプルの要素としてだけである（`1 + (move y)`、`if (move y) == 1 {` は E0002）。

ブロックの末尾の式（`if` と `match` の腕、ブロック式の末尾）は、そのブロックが置かれた位置を継ぐ。消費する位置に置いたブロックでは、各腕を `let y = <腕の値>` と書いたときと同じに扱う。
Affine の変数（フィールドの経路を含む）には `move` を書き（`let y = if c { move a } else { move b }`、`take(if c { move a } else { move b })`）、新しく作った値と Copy の値には書かない（`let y = if c { move a } else { Buf.zeroed(n) }` は正しい）。
腕の数を揃える規則ではなく、消費される Affine の変数ごとに印を付ける規則である。関数の返り値の位置に置いたブロック（関数の末尾の `if`）の腕には書かない。片方の腕でだけ消費した変数は、その後で使えない（E0704）。
返り値の位置に書いた `move`（`return move a`、関数の末尾の `move a`、そこに置いたブロックの腕の `move a`）は意味を変えない余分な情報で、検査は受け付けるが、書かない。
`onsa fmt` は取り除かない。`move` の後ろが局所の変数の場所かは名前の段で決まり、定数への `move K` は E0711 なので、取り除くと検査の結果が変わる（§18.2）。
ただし、§5.4 の借用束縛（借用引数からの `let y = x` など）は消費しない。Dup 値の `move` は複製になる（引数と同じ）。

所有する値の Affine のフィールドを消費する位置に置くと（`let b = move s.buf`、`f(move s.buf)`、返り値の `s.buf`）、`s` 全体を消費する。取り出したフィールド以外はその場で破棄され、以後 `s` は使えない（E0704）。
意味は分解の `let Holder { buf: b, gain: _ } = move s` と同じで、他のフィールドが要るときは先に読むか、分解で一緒に取り出す。Rust の部分移動と違い、残りのフィールドを後で使うことはできない（フィールドごとに移動の状態を持たない）。
対象は struct とタプルのフィールドの経路で（`move s.inner.buf` も可）、配列の要素は取り出せない（`move xs[i]` は E0711。要素は `for x in move xs` で取り出す）。経路に `Drop` を実装する型があれば取り出せない（E0711、§6.3）。Copy と Shared のフィールドは複製されるので、`s` を消費しない。
取り出した後に `s` を使った E0704 は、取り出した位置と、先に読むか分解する書き方を note で示す。

- `inout` と `move` は **呼び出し位置にも書く**。読み手は呼び出し 1 行で、何が変わるかを知る。`inout` は Swift、`move` は C++ / Rust と同じ意味。
- 借用している Dup 値（Copy か Shared）を `move` 引数に渡すと、その場で複製して渡す。Affine 値は所有していなければ `move` で渡せない（E0711）。借用引数、借用束縛、`inout` 引数は所有していない。`inout` 引数から `move` で取り出すと、呼び出し側の値が破棄済みになるからである。
- 同じ変数を一つの呼び出しで二度 `inout` に渡すと、また `inout` と借用の両方に渡すと（`h(x, inout x)`）エラー（E0702）。借用の引数は、呼び出し中は変更されないと約束しているからである。同じ値の **異なるフィールド**（`self.voices[i]` と `self.params[i]` など）は重ならないものとして扱う。
  同じ配列の添字どうしは、添字が等しいかを静的に判定しないので、重なるものとして扱う。引数は全て評価してから呼び出すので、引数の中で同じ変数を読んで値を作るだけなら重ならない（`xs.fill!(xs.len())`）。他の引数の中で `inout` に渡すか `!` を呼ぶと重なる（`f(inout x, g(inout x))` は E0702、§3.5）。
- メソッドのレシーバは `self` / `inout self` / `move self` と宣言する。`inout self` のメソッドの呼び出しは、名前の直後に `!` を付ける（`out.fill!(0.0)`）。無ければ E0713、`inout self` でないメソッドに付ければ E0714。どちらも修正候補は一意。`!` の直後には `(` が続き、名前の一部ではない。
  レシーバは可変な場所（`var`、`inout` 引数、それらのフィールドや要素）でなければならない。`move self` には印を付けない。`move` の観測できる効果は「以後使えない」ことだけで、検査器が局所的に捕まえる。Ruby / Julia の `sort!` と同じ意味で、連鎖の中でも値を変える呼び出しに印が付く。
  Onsa の呼び出しの形は `f(x)`（関数）、`f~(x)`（インスタンス生成）、`x.f!(y)`（レシーバの変更）、`v.(x)`（関数値、§6.1）と、名前の直後の印と `(` で揃う。
- 関数型の引数もモードに従う。既定のモードの関数型の引数（`f: fn(I32) -> I32`）は、捕捉する無名関数も受け、関数の中では第二級になる（§5.3）。呼ぶことと、別の関数の既定のモードの関数型の引数へ渡すことはでき、返す、保存する（`let` / `var` の初期化、代入、フィールド、要素）、無名関数で捕捉する、`move` の引数へ渡すと E0710。
  関数値を受け取って持つ関数は `move f: fn(I32) -> I32` と宣言し、捕捉の無い関数値だけを受ける（捕捉する無名関数を渡すと E0710）。呼び出し側は `make_op(1, move inc)` と書く。値が呼び出しの外へ出る側に印が付く（P10）。

### 5.3 第二級の値: 借用・`Span`・捕捉するクロージャ

次のものは **引数の位置にだけ** 現れる。返り値、構造体のフィールドにはできない（E0710）。そのため、どれもヒープを使わず、ライフタイムも要らない。借用だけは、§5.4 の規則で `let` と `for` に束縛できる。

| もの | 書き方 | 意味 |
|---|---|---|
| 借用 | `f(x)`, `f(inout x)` | §5.2 |
| `Span[T]` | 引数の型として `xs: Span[T]` / `inout xs: Span[T]` | 連続した要素の非所有ビュー（C++20 の `std::span` と同じ意味）。`[T; N]`、`Buf[T]`、`Span[T]` を渡せる。メソッドは `len()`、`slice(from, to)`、`get(i) -> Option[T]`、`fill!(v)`、`add_from!(other)`、`copy_from!(other)` で全てで、`[T; N]` と `Buf[T]` にも同じものがある（空かどうかは `len() == 0`、§4.2） |
| 部分ビュー | `f(xs.slice(from, to))`, `f(inout xs.slice(from, to))` | 半開区間 `[from, to)` の `Span`。範囲外は panic |
| `Span` の配列 | 引数の型として `xs: [Span[T]; N]` / `inout xs: [Span[T]; N]` | チャンネルごとのバッファ（planar）。`[[T; M]; N]`、`[Buf[T]; N]`、`[Span[T]; N]` の値をそのまま渡せる（要素ごとに `Span` へ変換）。別々の変数にあるときは `[a, b]` / `inout [a, b]` と配列リテラルを引数の位置にだけ書け（要素の種類と長さは揃っていなくてよい。長さの約束は `process` / `render` のもの、§11.6）、排他性は要素の場所ごとに検査する。`xs[k]` は `Span[T]` で、引数の位置にだけ現れる（メソッドの受け手 `xs[k].len()` と添字の左辺 `xs[k][i]` も引数の位置に含む。受け手は `self` の引数である） |
| 捕捉するクロージャ | `array.from_fn(fn(i) { k * i.round_f32() })` | 外側の値をコピーで捕捉する無名関数。捕捉した値は読み取り専用で、代入すると E0701。`inout` 引数と Affine 値は捕捉できない（E0712）。既定のモードの関数型の引数（§5.2）に渡せる |

flow の生成型 `voice.In` / `voice.Out`（§11.6）も `Span` を持つので、同じく引数の位置にだけ現れる（フィールドを受け手や添字の左辺に使うのも同じ）。

捕捉の無い関数値（名前付きの関数、捕捉しない無名関数）は Copy の第一級の値で、保存も返却もできる。ただし、既定のモードの関数型の引数は捕捉を持ちうるので、受け取った関数の中では第二級で、複製して持ち出せない（返す、保存する、捕捉する、`move` の引数へ渡すと E0710、§5.2）。保存できる関数値を受け取るのは `move` の関数型の引数で、捕捉の無い関数値だけを受けて所有する。変換先では、既定のモードの関数型の引数を関数と環境の組で、保存する関数値を関数だけで表す（§13.5）。

### 5.4 借用束縛

`let` と `for` の束縛は、初期化の元によって **借用** か **所有** かが構文的に決まる。本体での使い方には依存しない。

| 束縛 | 種類 | 破棄 |
|---|---|---|
| 既定のモードの引数と `self`（関数、メソッド、trait の既定の本体、無名関数、handler の関数）、flow の入力 | 借用（起点） | 起きない |
| `inout` の引数と `inout self` | `inout`（所有しない） | 起きない |
| `move` の引数と `move self` | 所有 | 起きる |
| `let y = x`、`let y = x.f`、`let y = x[i]`、分解（`let (a, b) = x`）（`x` は借用の起点、または起点から派生した借用束縛）。`let y = CONST`、`let s = "abc"`（静的な値） | 借用 | 起きない |
| `let y = f(...)`、`let y = move x`、静的でないリテラルや演算の結果 | 所有 | 起きる |
| `var y = ...` | 所有（書き換えられる） | 起きる |
| `for s in xs`（`xs` は任意の場所） | 借用（起点） | 起きない |
| `for s in move xs` | 所有。`xs` を消費する | 要素ごとに起きる（§12.2） |
| `for i in a ..< b`、`par i in a ..< b` の添字（`..=` も同じ） | 所有（整数） | 起きない（Copy） |
| `match x` の腕の束縛（`x` は任意の場所） | 借用（起点） | 起きない |
| `match move x` と、場所でない対象（`match f(...)`）の腕の束縛 | 所有 | 起きる |
| 総称の定数のパラメータ（`const N: U32`）を値として使う | 定数（Copy） | 起きない |
| 無名関数が捕捉した変数 | 読み取り専用のコピー（§5.3）。Shared 型の値の捕捉が複製か借用かは第 2 期に決める | — |

- 借用の起点は、借用引数（既定のモードの引数と `self`。`inout` 引数は含まない）、借用の `for` の束縛（`for s in xs`、`xs` はどの場所でもよい）、借用の `match` の腕の束縛（`match x`、`x` はどの場所でもよい）、静的な値（`const` と、補間の無い文字列リテラル）である。
  静的な値は不滅の静的オブジェクト（§12.8）で、解放も in-place 更新も起きないので、起点にしても安全である。そこから `let`、`for`、`match` の腕で作った借用束縛も起点として扱う（派生）。ローカルの `var` / `let` と `inout` 引数は起点にならない。
  `match x` の腕の束縛から派生した束縛は、腕の束縛と同じく、腕の中で `x` を変更すると重なるものが以後使えなくなる（§7）。分解する `let` では、元が起点なら各束縛が借用束縛になる（`let (a, n) = p` は `let a = p.0` と同じ）。
- 借用の `for`（`for s in xs`）の本体では、反復元 `xs` とその一部を変更できない。代入、`inout` への受け渡し、`move` は E0715。反復の途中で集合が変わらないので、どの要素が見えるかが一意に決まり、複製の費用も掛からない。反復しながら要素を書き換えるときは、添字で回す（`for i in 0 ..< xs.len() { xs[i] = xs[i] * 2.0 }`）。
- 借用束縛は読み取り専用で、`inout` に渡せない。借用の引数と同じ扱いで、`move` 引数へは Dup 型なら複製して渡し（§5.2）、Affine 型なら渡せない（E0711）。返り値にするときも Dup 型は複製になる。ただし、既定のモードの関数型の引数は捕捉を持ちうるので、`let` に束縛できず、返り値や `move` の引数にして複製することもできない（E0710、§5.3）。Copy の借用束縛は、束縛した時点の値を持つ（後で元の場所が変わっても変わらない、§7）。
- `for` の借用束縛がどの場所からでも安全なのは、本体で `xs` を変更できない（E0715）ので、反復の途中で要素が変わることも、in-place 更新（§12.6）で記憶域が解放されることも無いからである。`let` の借用束縛の起点を限るのは、ローカルの `var` や `let` から借りると、Perceus の in-place 更新で元の記憶域が解放されうるからである。
  `inout` 引数も、関数の中で書き換えられるので同じ理由で起点にしない。借用の `for` の束縛を起点にできるのは、本体で反復元を変更できない（E0715）からで、`match` の腕の束縛を起点にできるのは、対象を変更した後に重なる束縛を使えない（E0704、§7）からである。
- この規則により、借用した `Array[Str]` を読むだけの反復は `Alloc` を要しない。rt の関数でも、定数の表や文字列を `let` で受けられる。
- この表は、文法の全ての束縛の場所を覆う。分解したパターンの各束縛は、その行の種類を受け継ぐ。文法に束縛の場所を足すときは、この表に行を足す。

```onsa
pub fn total_len(xs: Array[Str]) -> U32 {
  var n: U32 = 0
  for s in xs { n = n + s.len() } // s は借用。破棄が無いので Alloc は要らない
  n
}
```
