## 4. 型

### 4.1 組込み型

| 分類 | 型 | 種（§4.6） | 記憶域（§12.1） |
|---|---|---|---|
| 整数 | `I8 I16 I32 I64 U8 U16 U32 U64` | Copy | 値 |
| 浮動小数 | `F32 F64`（IEEE 754 binary32 / binary64） | Copy | 値 |
| その他スカラ | `Bool Char ()` | Copy | 値 |
| 固定長配列 | `[T; N]`（`N` は定数式、§4.5） | `T` に従う | 値 |
| 文字列・バイト列 | `Str`（UTF-8, 不変）, `Bytes`（不変） | Shared | ヒープ（リテラルは静的） |
| 列 | `Array[T]`（不変・永続、参照カウント） | Shared | ヒープ |
| 集合 | `Map[K, V]`, `Set[T]` | Shared | ヒープ |
| バッファ | `Buf[T]`（可変、長さは生成時に固定） | Affine | ヒープ |
| ビュー | `Span[T]`（引数専用、§5.3） | — | 借用元 |
| 標準 enum | `Option[T]`, `Result[T, E]`（std で宣言された enum。下記） | 中身に従う | 値 |
| タプル | `(A, B)`（2 要素以上） | 要素に従う | 値 |
| 関数 | `fn(A, B) -> R uses {E}`, `rt fn(A) -> R`, `fn(inout A)`, `fn(move A) -> R` | Copy（捕捉の無い値。捕捉する無名関数と既定のモードの関数型の引数は第二級、§5.3） | 値 |
| FFI | `Ptr[T]`（§14） | Copy | 値 |

`Option` と `Result` は、std で `pub enum Option[T]: PartialEq + Eq + Hash + Show { None, Some(T) }` と `pub enum Result[T, E]: PartialEq + Eq + Hash + Show { Ok(T), Err(E) }` と宣言された enum で、prelude にある（§15.1）。
他の enum と違うのは、`use` なしで見えること、列挙子を名前だけで（修飾なしで）書くこと、`?`（§9.1）に使えることだけである。他の enum の列挙子は常に `Type.Variant` と書く。
`Option`・`Result` の型の名前空間から列挙子は引かない（列挙子は prelude の名前である）ので、型や別名で修飾した形（`Option.None`、`Option::[I32].None`、`type O = Option[I32]` の後の `O.None`）は名前の段の E0302 で、修正候補は修飾を除き、修飾が持っていた型引数を名前に付ける形（`None`、`None::[I32]`）、note は「prelude の列挙子は名前だけで書く」である。
修飾なしで書く列挙子に式の中で型引数を書くときは、列挙子の名前に付ける（`None::[I32]`、`Some::[U8](250)`。他の総称の enum の列挙子は型に付ける、§4.5）。

タプルの要素は `t.0`、`t.1` で読む。`.` の直後の数字列は常に整数の添字として字句解析するので、`t.0.1` は入れ子の添字である（Rust と同じ）。関数型の引数のモード（`inout`、`move`）は型の一部で、無名関数も名前付き関数と同じ形で宣言する（§6.1）。

**添字・長さ・大きさの型は `U32` に固定する。** プラットフォームによって幅が変わる整数型（Rust の `usize` に当たるもの）は無い。

- 理由: 幅がターゲットで変わると、オーバーフローで panic する点がターゲットごとに変わり、ソースの意味とバックエンド間のビット一致が崩れる。JavaScript にも対応する型が無い。
- `len()`、添字、`const N`、`SIZE` などは全て `U32`。Java の配列添字（`int`）や JavaScript の配列長と同じ幅である。
- 型の大きさ（バイト数）と、flow の状態の各領域（fast / bulk、§12.4）の大きさも `U32` で表せなければならない（`2^32 - 1` バイト以下）。超えると E0409。大きさはポインタの幅と bulk の設定で変わるので、配置を計算するとき（§12.4）に検査し、診断は上限を超えた型か flow の宣言に置いて、最も大きいフィールドを note で示す。
  flow の状態と他の型で上限を分けない。実用上の上限（組込みの RAM）は `fast_budget` / `bulk_budget`（E0820）で決める。
- 一つの配列・バッファ・文字列は 2³² − 1 要素（バイト）までに制限される。それを超えるデータは分割して扱う（ファイルのオフセットなど、大きさが要る値には `U64` を使う）。
- C の `size_t` は FFI の宣言の中でだけ `CSize` として書ける（§14.1）。`U32` との変換は境界で検査する。

### 4.2 文字列

`Str` は **常に正しい UTF-8 のバイト列** である。長さと位置はバイト単位で数える（Rust、Go と同じ）。

| 操作 | 意味 |
|---|---|
| `s.len() -> U32` | バイト数 |
| `s.as_bytes() -> Bytes` | バイト列として見る（複製しない） |
| `Str.from_utf8(b: Bytes) -> Result[Str, Utf8Error]` | 検証付きの変換。生のバイト列は `Bytes` で扱う |

- 空かどうかは `s.len() == 0` で書く。長さを持つ型（`Str`、`Bytes`、`Span`、`Buf`、`[T; N]`、第 2 期の `Array` `Map` `Set`）は `len()` だけを持ち、`is_empty` は無い（E0413。修正候補は `len() == 0`）。
- `s[i]` の添字は無い（何を返すかが一意でないため）。バイトは `s.as_bytes()` から得る。
- API はこの最低限から始め、用途（プリセット名、パス、ログ、`@param` の `unit` / `label`）が要求したときに足す。部分文字列・検索・文字の反復は最初の版に無い（§19.2）。
- 等値と順序はバイト列の辞書順。UTF-8 のバイト順はコードポイントの順と一致する。正規化はしない。
- 変換先の文字列の表現が UTF-8 でない場合（JavaScript など）も、この意味を保つ（§13.5）。

`FixedStr[N]`（`std.text`）は、容量 `N` バイトの中に ASCII の文字列を値として持つ std の Copy の型である（`pub struct FixedStr[const N: U32] { priv bytes: [U8; N], priv len: U32 }`。大きさは `N + 4` バイト、整列は 4）。ヒープを使わないので、rt の関数とヒープの無いターゲット（§12.3）で文字列を組み立てるのに使う（表示器の行、ログ、状態の名前）。

- 文字は ASCII（0x00〜0x7F。NUL と制御文字を含む）に限る。長さと容量はバイトで数え、文字の数と同じである。使っていない後ろのバイトは 0 で、等値・順序・`Hash`・`Default` は derive による（順序は `Str` と同じバイトの辞書順）。
- リテラル: 期待の型が `FixedStr[N]` なら、補間を含まない文字列リテラルはその型の値になる（§4.7。`var t: FixedStr[16] = "gain="`。引数・フィールドの型、代入の左辺の型（`p.name = "mix"`）、比較の他方の型（`t == "warm"`）も期待の型になる）。`N` が決まっていなければリテラルの長さを `N` にする。
  容量を超えるか ASCII の外の文字を含むリテラルは E0408、補間を含むリテラルは E0401。期待の型が無ければ今までどおり `Str` である。`match` のパターンの文字列リテラルの読み方は §7 による。
- 書き足し（文字列、整数の 10 進、小数点以下の桁を決めた浮動小数）は、入る分だけ書き、容量を超えた分は黙って捨てる。収まるかは、書き手が書き足す前に長さを足して確かめる（長さが容量に達したことだけでは、ちょうど入ったか切り詰められたかを区別できない）。
  桁を決めた浮動小数は、値を `F64` に広げて `10^d` を掛け、最近接偶数で整数に丸め、10 進で書いて小数点を入れた文字とする（NaN・無限大・収まらない値の文字は std で定める）。
- 出口: `Span[U8]` の引数に渡すと、使った長さの部分を見る（§5.3。`inout` の `Span[U8]` には渡せず E0401。中身は書き足しだけで変わり、不変条件を型の外から壊せない）。`t.write_to(inout out)` は `out` に入る分を書き、書いた数を返す（export の境界、§14.2）。
- 最初の版に無いもの: `Str` との変換、`Show` と同じ表記、補間で作ること、`Char` を一字足すこと。書き足しのメソッドの名前は std の作業で決める。

### 4.3 `Map` と `Set` の反復順序

`Map` と `Set` は **挿入した順** に反復する（JavaScript の `Map`、Python の `dict` と同じ）。要素を削除しても、残りの順序は変わらない。ハッシュ関数や実装によって反復の順序が変わらないので、全てのターゲット・変換先で結果が決定的になる。

### 4.4 ユーザ定義型

```onsa
pub struct Point {
  x: F32,
  y: F32,
}

pub enum Shape {
  Circle(F32),
  Rect(F32, F32),
}

type Samples = Buf[F32] // 型別名（新しい型を作らない。`onsa interface` は展開して表示する）
```

- `struct` は名前的。匿名レコード型は無い。struct リテラルは常に `Point { x: x, y: y }` と書き、全てのフィールドを一度ずつ書く（過不足と重複は E0410）。フィールド名と変数名が同じときの省略形は無い。`if` / `while` / `match` / `for` / `par` の見出しの式には、括弧の外に struct リテラルとブロック式を書けない。
  見出しの式の中で、括弧の外の式の始まりにある `{` は本体の始まりと読む（`if s == Shape.Circle {`、`for i in 0 ..< { n } {` で、`{` が本体か式の一部かが曖昧になるため。`if`・`match` などのキーワードに続く `{` はその式のもの）。括弧で囲めば書ける（`if ({ c }) {`）。
- 列挙子はタプル形（`Circle(F32)`。要素は一つ以上で、要素の無い `Circle()` は E0002、§2.5）と単位形だけ。Rust の struct 形（`Rect { w: F32, h: F32 }`）は無く、名前付きのフィールドが要るときは struct を包む（`Rect(RectSize)`）。名前付きのフィールドを持つものは struct の一種類にするためである（§0.3 の規則 1）。
- タプル形の struct（Rust の `struct Hz(F32)`、newtype）は無い。別の型として区別したい値は、名前付きのフィールドが 1 つの struct で書く（`pub struct Q { priv value: F32 }` を `Q.new(x)` で作る、§15.1）。
  タプル形は E0020（修正候補は名前付きのフィールドの struct。候補を作れない形は E0002、§18.1）。newtype と単位の型は、取り違えの検査が要る実例が出てから決める（§19.1）。
- タプル形の列挙子は、捕捉の無い関数値（`Circle` は `fn(F32) -> Shape`）としても使える（Rust と同じ。例: `map_err(ConfigError.Io)`）。単位形の列挙子は値で、括弧を付けずに書く。呼ぶと（`None()`、`E.A()`、`E.A(1)`）要素の数の誤りと同じ E0412 で、括弧の中が空でコメントが無ければ括弧を除く修正候補を示す（引数のある形は候補なしで note）。
- `type 名前 = 型` は型別名で、新しい型を作らない。型の名前を書ける全ての位置（型、関連関数と関連定数、struct リテラル、パターン、列挙子）で、元の型と同じに使える（`Sample.PI`、`P { x: 1.0, y: 2.0 }`、`S.Circle(r)`）。ただし prelude の列挙子は別名でも修飾しない（§4.1）。
  型引数を決めた別名は、その型引数を決める（`type Samples = Buf[F32]` の `Samples.zeroed(n)` は `T = F32` の `Buf.zeroed`）。`impl` の本体の中の `Self`（§2.2）も、対象の型を右辺にした別名と同じである（`Self { x: 0.0 }`、`Self.N`）。
  主な用途は、標本の精度を一か所で切り替えること（`type Sample = F32`。flow は型パラメータを持たないので、精度を変える手段は別名だけである）と、定数で長さの決まる型に名前を付けること（`type Frame = [Sample; CHANNELS]`）である。別名は値を区別しないので、単位の取り違えを防ぐには名前付きのフィールドが 1 つの struct を使う。
- `impl` と `impl Tr for` の対象は型の宣言の名前で書き、別名は書けない（E0307。元の型がそのモジュールで宣言されていれば、修正候補は元の名前）。型のメソッドが宣言の名前で見つかるようにするためで、別名を通して孤児規則（§6.3）を避けることもできない。
- 型別名は型パラメータを持たない（`type V[T] = (T, T)` は E0002。総称の別名は §19.1）。
- フィールドアクセス `p.x` は、`p` の型が注釈またはその場の推論で既知であることを要求する（E0420、§4.7）。
- 同じ struct のフィールド名、同じ enum の列挙子名は重複できない（E0304）。
- 型は自分自身を値として含めない。値として含む位置（フィールド、列挙子の中身、タプル、固定長配列）を辿って同じ型に戻る定義は E0311（`struct Node { v: I32, next: Node }`、`enum List { Cons(I32, List), Nil }`、相互の再帰も含む。型別名の循環 `type A = B`、`type B = A` も同じ）。値型は固定サイズで、Rust の `Box` に当たる箱が無いので、大きさが決まらないからである。
- 検査が作る全ての型（別名を右辺に置き換え、型引数を当てた後の型。書いた型、本体で推論した型（§4.7）、総称の具体化の型（§4.5）を含む）は、深さ 256、大きさ 4096 までである。深さは型の形（型引数のある型、タプル型、配列型、関数型）を一段と数え、名前は数えない。大きさは、名前（組込みの型、宣言した型、型パラメータ）、型の形、const 引数をそれぞれ一つと数える。
  宣言した struct と enum は葉で、フィールドを数えない。超えると E0422 で、位置は上限を初めて超えた型を作った所である: 別名はその宣言（超えた別名を使う別名には出さず、誤りの型として扱う、§18.1）、書いた型はその形、本体は型を作った式（`Some(a)`、タプル、呼び出し）、総称の具体化の型は具体化を作った呼び出し。
  直し方は、途中の型に名前付きの struct で名前を付けることで、note で示す（宣言した型は葉なので、フィールドの型は数に入らない。別名に分けても展開した型は変わらない）。別名の鎖（`type A2 = (A1, A1)`）や文の鎖は、書いたソースの深さを変えずに展開した型を指数の大きさにでき、`onsa interface` の展開した表示、診断の文、検査の時間がそれに比例する。
  深さの上限は型を辿る全ての処理の再帰を、大きさの上限は表示と時間を有界にする。上限が処理系で違うと、ブラウザの IDE と CLI で同じファイルの合否が変わるので、仕様で固定する（§2.5 の入れ子の深さと同じ、P8）。値は実際の型（数個から数十の名前と形）より十分大きく、後で上げても既存のプログラムは壊れない。

### 4.5 ジェネリクス

```onsa
pub fn clamp[T: PartialOrd](x: T, lo: T, hi: T) -> T {
  if x < lo { lo } else if x > hi { hi } else { x }
}

pub struct Ring[T, const N: U32] {
  data: [T; N],
  head: U32,
}
```

- 宣言位置と型の位置で `[...]`（`fn f[T](x: T)`、`Option[I32]`）。式の中では、型引数を総称の項目の名前の後に `::[…]` で書く（`parse::[U32]("1")`）。`::[` の `[` は印の一部なので、式の中の `[...]` は常に添字か配列リテラルであり、構文が曖昧にならない（`A[N].m(x)` は常に、配列 `A` の要素のメソッドの呼び出しである）。型の位置の `[` は添字になりえないので、印は式の中にだけ要る。
  - 書けるのは、式の中で総称の項目を指す名前の経路の直後である: 関数（`parse::[U32]("1")`。値として取り出す形は §6.1）、型の関連関数と関連定数（`Buf::[F32].zeroed(4)`、`Rg::[F32, 4].CAP`）、struct リテラル（`Pr::[U8] { a: 250 }`）、メソッド（`v.m::[I32](x)`。与えるのはメソッド自身の型パラメータで、`impl` の型パラメータはレシーバで決まる）。
    型引数は、その型パラメータを宣言した項目の名前に付ける（`Buf.zeroed::[F32](4)` は `zeroed` が型パラメータを持たないので E0412）。総称の enum の列挙子は型に付け（`E::[I32].B`）、修飾せずに書く prelude の列挙子（§4.1）は列挙子の名前に付ける（`None::[I32]`）。
    パターンには書かない（型は対象の型で決まる。`None::[I32] =>` は E0002）。`T.ZERO` と `F32.PI` のように型の名前で決まるものは、型引数を要らない。
  - 並びの要素は型の位置の並びと同じに読み、const 引数は定数式（下記）である。数が宣言と合わなければ E0412（下記）。型パラメータを持たない項目（総称でない関数、flow、型パラメータ、列挙子の名前）に書いても E0412、ローカルの束縛と引数（関数値。具体化済みで型引数を取らない）に書くと E0308。
    名前の経路でない式とタプルの添字で終わる経路の後（`(e)::[T](x)`、`g(x)::[T](y)`、`t.0::[T](x)`。§6.1）、空の並び（式の中の `f::[]`、型の位置の `Buf[]`、宣言の型パラメータの `fn f[]`。§2.5）、宣言の型パラメータの並び（`fn f::[T](x: T)`）は E0002。`_` は型の位置に書けない（§2.2）ので、一部だけを書いて残りを推論させる形（`pair::[U8, _]`）は無い。
  - 型の位置（注釈、引数と返り値の型、型の中の型引数）に書いた `Buf::[F32]` は E0020 で、修正候補は `::` を除く形である（印が式の中だけという規則の誤解を示す冗長な印、P2）。
  - 型引数を書いた呼び出しの型パラメータは、その文で決まる（下の要求の検査もその文で行う）。期待型の注釈（`let y: U8 = id(250)`）と型引数（`let y = id::[U8](250)`）はどちらも書ける。前者は束縛の型、後者は項目の具体化で、返り値の型が全ての型パラメータを含むときは同じ意味になる。
  - 他言語の形で書いた型引数（`parse[I32]("3")`、`parse<I32>("3")`、`parse::<I32>("3")`、`Buf[F32].zeroed(4)`、`v.m[I32](x)`）は E0020 で、`::[…]` の形を修正候補にする（`parse::[I32]("3")` など。`[…]` の前に `::` を挿す、`<` と `>` を `::[` と `]` に、`::<` の `<` と `>` を `[` と `]` にする構文上の編集で、型引数を残し、呼び先の宣言を読まない）。
    note で、式の中の型引数は `名前::[…]` と書く（`[` だけでは添字）ことを示す。`<` を前の名前に、`(` を `>` に、空白を空けずに続けた `f<T>(x)` は、比較の連鎖の E0010（§3.1）にしない。引数の並びの中（`g(f<A, B>(x))`）も同じで、`,` で二つの比較に分けない。空白を空けた `g(a < b, c > (d))` は二つの比較として読む。
    出す段は読みが一つに決まる最初の段である（添字として読めない `[…]`（`pair[I32, F32](1, 2.0)`）、`f<T>(x)`、`f::<T>(x)` は構文の段、名前の経路に付けた `[…]` は名前の段、メソッドに付けた `[…]`（`v.m[I32](x)`）は型の段。§6.1 と同じ分け方）。
    呼び先が名前の経路でもメソッドでもない形とタプルの添字で終わる経路（`(e)<I32>(x)`、`g(x)::<I32>(y)`、`t.0<I32>(x)`）は `::[` を書けない位置なので、型引数を除いて `.(` で呼ぶ形（`e.(x)`、§6.1）を修正候補にする（関数値の型は総称でないので、除いても型は変わらない）。
- 引数から決まらない型パラメータ（返り値だけに現れるものなど）は、型引数か、期待型の注釈か後の文で決める（§4.7 の単一化変数）: `let n = parse::[I32]("3")`、`let n: I32 = parse("3")`。関数の終わりまでに決まらなければ、その呼び出しの位置に E0406（§4.7）。
  型パラメータの要求（境界と暗黙の `Dup`）は、型パラメータが決まった文で検査し、関数の終わりにはリテラルの既定を当てた後で検査する。満たさなければ、要求を生んだ式（呼び出し、`[e; N]`、演算子、メソッドの呼び出し）の位置に E0416 で、型を決めた式を位置付きの note で示す（リテラルの既定で決まったときは位置の無い note）。
  決まらないまま関数が終われば、要求は検査せず、E0406（浮動小数のリテラルなら E0405）だけを報告する。境界はリテラルの既定を変えない（`fn need_fl[T: Float](x: T)` の `need_fl(3)` は `T` が `I32` に決まって E0416）。途中で型が要る操作（`v.x`、`v?` など）は、その時点で型の頭が決まっていなければ E0420（§4.7）。
  リテラルの型変数に結び付けば、リテラルの既定に従う（`fn or_default[T](o: Option[T], d: T) -> T` の `or_default(Some(3), 9)` は `I32`）。型引数と const 引数の数が宣言と合わなければ E0412（関数の引数の数と同じコード）。
- 配列の長さと const 引数は **定数式** で書く。定数式は、整数のリテラル、定数を指す名前（`cfg.N` のような修飾した名前と、`I32.BITS` のような具体的な型の関連定数を含む）、算術の演算子（`+ - * / %`）と前置の `-`、括弧からなり、型は `U32` である。
  普通の式と同じ規則で、期待型を `U32` として検査する（`U32` でない定数は E0401。修正候補は定数の型を `U32` にすること）。`U32` に前置の `-` は無いので、`-1`、`-0`、`-(1)`、`-N` は位置によらず（配列の長さ、const 引数、遅延線の長さ、`par` の端）E0401 である（§3.4。E0808 は値の範囲の誤りだけ）。
  関数の呼び出しは書けない（`const` の初期化式に分ける）。定数式でないもの（関数の呼び出し、ローカル変数など）を書くと、位置によらず（配列の長さ、const 引数、遅延線の長さ、`par` の回数）E0417。初期化式で計算した定数（`const N2: U32 = N * 2`）は名前で使える。
  値はコンパイル時に評価し、型は評価した値で比べる（`[F32; N * 2]` と `[F32; 8]` は同じ型。`onsa interface` と C のヘッダには値を出す）。溢れとゼロ除算は、その式の位置で E0419（コンパイル時の評価の panic、§6.6）。定数の評価が循環すると E0312（§6.6）。
  例: `Ring[F32, 4]`、`Ring[F32, TABLE_SIZE]`、`[F32; cfg.N]`、`[F32; MAX_SR * 2]`。
- const ジェネリクスは等値比較のみで、const の型パラメータを含む式（`[F32; N * 2]`、`N` は const の型パラメータ）は書けない（E0417。定数式の規則の違反と同じコード）。型の一致を記号の計算に頼らず、溢れなどの誤りを、使う場所の奥ではなく定義の場所で出すためである。
- 型パラメータには、暗黙に `Dup`（複製できる = Copy か Shared）の制約が付く。Affine 型も受け付けるには `[T: ?Dup]` と書いて、この制約を外す（Rust の `?Sized` と同じ形）。その場合、`T` の値は複製できない。生成して返すこと、借用・`inout`・`move` で渡すことはできる。
- `Buf[T]` と `Span[T]` の要素型は `T: Copy` に限る（E0416）。
- 境界を複数付けるときは `+` で並べる（`[T: Num + Default]`）。

### 4.6 種（kind）: Copy / Shared / Affine

全ての型は構造から次のどれかに分類される。注釈は不要で、`onsa interface` に表示される。

| 種 | 該当 | 複製 | 破棄 |
|---|---|---|---|
| Copy | スカラ、Copy 要素の固定長配列・タプル・構造体・enum、捕捉の無い関数値 | ビットコピー | 何もしない |
| Shared | `Str` `Bytes` `Array` `Map` `Set`、それらを含む型 | 参照カウントで共有、書き込み時コピー | 参照カウントを減らし、0 なら解放（`Alloc`） |
| Affine | `Buf`、`Drop` 実装型、flow の状態（`f.State`）、それらを含む型 | 不可（ムーブのみ） | 中身の破棄、`Drop` |

- `Copy`（種が Copy）と `Dup`（複製できる、つまり Copy か Shared）は **種の制約** で、trait ではない。書けるのは境界（`[T: Copy]`、`[T: ?Dup]`、§4.5）と trait の要求（`AnyNum: Copy + …`、§6.3）だけで、trait と同じく `+` で並べる。満たさなければ E0416。
- 種は構造で決まるので、`impl Copy for X` と宣言の `: Copy`（`Dup` も同じ）は書かない（E0020。修正候補は外す形で、note で種の規則を示し、Copy でないフィールドがあれば名指しする）。明示して Copy を付ける言語の書き方で、書き手が種の仕組みを誤解していることを示すからである（P2）。Shared と Affine は境界に書く名前を持たない（Affine も受けるのは `?Dup`、§4.5）。

### 4.7 関数本体の型推論

シグネチャは完全注釈（P1）なので、推論は関数本体の中で閉じる。本体の推論は次の形で行う。

- **文の順に一方向で進める。** 本体全体の制約を集めて解くことはしない。人間がソースを上から読むのと同じ順で型が決まり、エラーは原因の近くに出る。
- **単一化変数で、後の文からの決定を許す。** リテラルは `IntLit` / `FloatLit` の制約付きの型変数になる。`var acc = 0.0` の `acc` は、後の `acc = acc + x` で `x` の型に決まる。演算子、比較、関数の引数への受け渡しは、オペランドが未解決でも進められる（そこで決まる）。
- **期待型は式の中へ下向きに伝わる。** `let` の注釈、呼び出し先の引数の型、返り値の型、struct のフィールドの型が期待型になる。代入の右辺には、左辺の場所の型が期待型になる。比較（`==`・`<` など）の一方が補間の無い文字列リテラルなら、他方の型がその期待型になる（左右どちらに書いても同じ）。
  期待型があればそれに対して検査し、無ければ推論する。`[None; N]`、`Buf.zeroed(48000)`、空の `[]`、期待の型が `FixedStr[N]` の文字列リテラル（§4.2）、返り値だけがジェネリックな関数（§4.5）、無名関数の引数の型はこれで決まる。
- **その場で既知を要する操作。** 次の操作は、左辺（対象）の型がその時点で解決済みでなければならない（E0420）: フィールドアクセス `.f`、メソッド呼び出し `.m()`、添字 `[i]`、`as` の左辺、`match` の対象、`?` の対象、関数値の呼び出し。未解決なら注釈を書く。
  解決済みとは、対象の型の頭（一番外の構成子: 組込みの型の名前、`Option` や `Buf` や struct の名前、配列、タプル、関数型）が決まっていることで、対象が型変数そのもの（リテラルの型変数を含む）なら未解決である。
  型引数の中の型変数は後の文で決まってよい（`let b = Buf.zeroed(4)` の後の `b.len()` と、`let o = None` の後の `match o { … }` は書ける）。選ぶフィールド・メソッド・列挙子は、型の頭で一つに決まるからである（§6.2）。
- **返り値の推論は無名関数だけ。** 名前付き関数の返り値は注釈から取る。無名関数は本体を検査してから返り値の型を単一化する（`array.from_fn(fn(i) { i.round_f32() * 0.5 })` の `T`）。
- **未解決の報告。** 関数の終わりに未解決の整数リテラルの型変数が残れば `I32` にし、浮動小数リテラルの型変数が残ればそのリテラルの位置に E0405。型が決まった時点で範囲外のリテラル（`let x: U8 = 300`。容量を超えるか ASCII の外の文字を含む `FixedStr` のリテラルも、§4.2）は E0408。
  被演算子が、括弧を除くと整数リテラルそのものである前置の `-` は、値に含めて検査する（`I8` に `-128` と `-(128)` は書け、`-129` は E0408。`(e)` は常にグループ化で、§2.4。`onsa fmt` が冗長な括弧を外しても合否が変わらない）。
  値に含める `-` は一つだけで、`-(-128)` は、内側のリテラル `-128` を外側の `-` が否定する式である（`I8` では §3.4 のとおり溢れで panic し、コンパイル時の評価では E0419）。符号なしの型の `-1` と `-0` は E0401（§3.4。`-(-1)` も内側の `-1` で E0401）。値で範囲を検査するのはリテラルだけである。
  計算した値（演算、関数の呼び出し、定数の名前）は型の範囲の外に出られず、出ようとする演算がその場で panic する（§3.4。コンパイル時の評価では E0419、§6.6）。既定の適用は関数の終わりなので、途中で型が要る操作（`0.round_f32()`）は E0420 のままである。
  リテラル以外の型変数（`let x = None` の `Option[T]` の `T`、`Buf.zeroed(4)` と空の `[]` の要素の型）が関数の終わりに残れば、その型変数を作った式（`None`、`none()`、`Buf.zeroed(4)`、`[]`）の位置に E0406。
  発散する式だけが決める型変数も同じで、`let y = f(id({ return }))` の `id` の `T` は、その呼び出しの位置に E0406 である（初期化式の全体が発散する `let` は、束縛が §7 の E0503 になる）。
  演算子の trait（E0401、§6.3）と種の制約（`[e; N]` の `Dup`、`Buf` と `Span` の要素の `Copy`、E0416）も、型パラメータの要求と同じく、型変数が無くなった文で検査し、関数の終わりには既定を当てた後で検査する（§4.5）。
  後回しにした検査（型パラメータの要求、リテラルの範囲と符号なしの `-`、E0406）の報告の順: 要求は文の検査の後に検査するので、同じ文の中の別の型の誤りが先に報告される。同じ時点で満たさない項目が複数あれば、検査が項目を作った順（被演算子が演算子より先）で先のものを報告する。
  後で型が決まる `-(-1)`（`let a = -(-1)` の後の `let b: U8 = a`）の E0401 も、この順で内側の `-1` に出る（`let b: U8 = -(-1)` のように型がすぐ決まるときと同じ位置）。
  パターンの中のリテラルと列挙子は、`==` の被演算子と同じく対象の型引数と単一化する（`let o = None` の後の `match o { Some(3) => 1, _ => 0 }` は `T` を整数リテラルの型変数にし、関数の終わりに `I32` になる）。
- **受け入れる制限。** `var acc = 0.0` の直後に `acc.round_f32()` と書くと、型が決まる前のメソッド呼び出しなので E0420 になる。本体全体の制約解消なら通るが、局所性と引き換えにこの制限を受け入れる。
- flow の本体では、型を付けた本体の上でクロック（§11.3）を推論する（flow の検査の段、§18.1）。
