## 10. リアルタイム（`rt`）

```onsa
use std.math.{abs}

pub rt fn soft_clip(x: F32) -> F32 {
  x / (1.0 + abs(x))
}
```

`rt fn` の検査規則は次の通り（違反は E09xx）。

1. 効果行に `Alloc` を含まない（E0902）。したがって Shared 値と `Buf` の生成も、所有する Shared 値・`Buf` の破棄もできない（§12.2）。本体でそれらを行うと、効果行に無い効果の使用として E0601 になる（§8.1）。
2. 効果行に `blocking` の効果を含まない（E0904）。したがってブロックしない。
3. 効果行の効果は全て rt 効果（全ての操作が `rt`、§8.1）である（E0905）。効果行変数は、`rt fn` の呼び出し位置で rt 効果にしか具体化できない。したがって、どの handler が与えられても操作の呼び出しは rt であり、handler の中身を見ずに `rt` が決まる。
4. `rt` でない関数を呼ばない（E0901）。暗黙の破棄で呼ばれる `Drop` も含む。
5. 再帰しない（直接・相互とも、E0903）。モジュール間の import は循環しない（§15.1）ので、この検査はモジュールの中で閉じる。これによりスタックの上限が計算できる（§12.5）。
6. ループの上限は検査しない（停止性は対象外）。

- `rt` は関数型の一部（`rt fn(F32) -> F32`）で、高階関数でも保持される。`rt fn` の型の位置には `rt` の関数しか置けない（E0401。関数型の互換、§8.1）。`rt` の関数は、`rt` でない位置でも使える（§8.1 の関数型の互換）。
- 1〜3 は効果行だけで決まる。`rt` を付けた関数では、これらとともに 4 と 5 が検査される。
- `extern` 宣言の `rt` は検証されない主張として扱い、`onsa audit` に列挙する（§14）。

参考: Clang の `[[clang::nonblocking]]` / `[[clang::nonallocating]]` と同種の検査を、言語の型に組み込んだもの。
