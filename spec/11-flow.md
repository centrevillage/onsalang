## 11. flow: 信号処理

### 11.1 考え方

flow は **同期データフロー** の信号処理ノード（Lustre / SCADE 系）。FAUST と同じく、

- 状態は遅延にしか現れない（ほかに処理系が置く隠れた欄がある: 遅いクロックの値を速い段で読む欄（§11.3）と、止まる部品の最後の出力（§11.10）、位相のカウンタ（§11.9））
- 結線の誤りはコンパイル時に落ちる
- タイトなループに降下する
- 状態の大きさがコンパイル時に決まる

という性質を持つ。ただし point-free ではなく、**全ての信号に名前がある**。

flow の本体は、**1 サンプルごとに評価される関数の本体** と同じ形で書く。fn の本体と違うのは次の 3 点だけである。

1. 組込みの遅延の flow（`prev~` / `delay~` / `vdelay~`）で、信号の **過去の値** を参照できる。下で定義される信号は、帰還の参照 `^名前` で渡す。
2. 値が **レート**（どのクロックで変わるか）を持つ（§11.3）。
3. flow の呼び出し `f~(...)` は、**状態を持つインスタンス** を作る（§11.5）。

これらと `par`（§11.5）は、flow の本体にだけ書ける。
flow の外（fn の本体、`test`、`const` の初期化式）に、インスタンスの呼び出し `f~(...)`（組込みの遅延を含む）、`~` 無しの flow の呼び出し、帰還の参照 `^名前`、`par`、`if~` / `match~`、レートの `at`（入出力の宣言と式、§11.3）を書くと E0821 で、修正候補は付けない（`at` だけは、それを外すことを修正候補にする）。
flow の外から flow を使うには、名前空間の型と関数（`voice.init`、`voice.process`、§11.6）を通すか、その関数を flow にする（E0821 の note で示す）。値を N 個作るなら `par` ではなく `array.from_fn` か `[e; N]`、過去の値が要るなら状態を `inout` 引数で持つ（同じく note で示す）。
逆向き（fn だけの構文を flow の本体に書くこと）は E0806（§11.2）。

### 11.2 宣言

```onsa
pub flow one_pole(x: F32 at sample, p: F32 at block) -> F32 at sample {
  let y = (1.0 - p) * x + p * prev~(^y)
  y
}
```

- 入力は `(名前: 値型 at クロック, ...)`、出力は `-> 値型 at クロック`（§11.3）。複数の出力は struct を値型にして表す（`-> Stereo at sample`）。イベントの入力は `at event`、イベントの出力は `-> E at event` と書く（§11.11）。
- 本体は `let` 文の並びと、最後の式（出力）。`let` は本体の直下にだけ書け、分岐の腕や `par` の本体などの入れ子のブロックは式一つである（`let` を書くと E0806。計算を分けたいときは flow に分ける）。状態の名前（§11.6）と `^` の範囲（下記）が、`let` が本体の直下にあることを前提にしている。`let` には値型の注釈を書ける。
  クロックを決めるときは式に `at` を付ける（`let ps = p at sample`、§11.3）。
  使える式は次の閉じた一覧である: `let`（タプル・struct の分解を含む）、名前、リテラル、括弧、演算子、`as`、`at`、帰還の参照 `^名前`、効果行が空の `rt fn` の呼び出し（メソッドを含み、`!` の呼び出しを除く）、flow の呼び出し、フィールドアクセス、添字、struct / タプル / 配列リテラル、列挙子の構築（`Some(x)`、`None`、`Mode.Gain(g)`。列挙子を関数値として使う形は、関数値なので書けない）、`if`、`match`、`if~`、`match~`、`par`、インスタンスの修飾子の連鎖（`.when~(c)` など、§11.10）。
  全て点ごとに評価され、`sample` のクロックの `Stereo` のフィールドアクセスや `Option[F32]` の `match` も点ごとである。
  一覧に無いもの（`var`、代入、`!` の呼び出し、`inout` / `move` の引数、`for`、`while`、`return`、`?`、`assert`、関数値、クロージャ、`handle`、`unsafe` など）は書けない（E0806）。新しい構文は、この一覧に足すまで flow の本体では E0806 になる。
- **名前は上から順に定義する。** 定義より前で（自分自身の定義の中も含む）名前を参照するには、帰還の参照 `^名前` を使う。`^名前` を書けるのは、遅延の組込み（`prev~` / `delay~` / `vdelay~`）の第 1 引数の式の中だけで、その中の利用者の flow の引数には書けない（E0801、下記）。過去の値は既に存在するので、前方参照ではない。閉路が参照の位置で見えるので、帰還（発散や不安定が起きうる場所）を読み手が見落とさない（P10）。
  - 印の無い前方参照は E0801。参照が遅延の第 1 引数の中にあるときだけ、`^` の挿入を修正候補にする。外では候補を出さず、「名前は上から順に定義する（`let` を上へ移す）」と「帰還なら `prev~(^名前)`」を note で示す（遅延を足すと意味が変わるので、候補にしない）。
  - 遅延の第 1 引数の外の `^名前`（下で定義される名前）も E0801 で、修正候補は `prev~(^名前)`。note で「`^` は遅延ではない」と示す。
  - 見えている名前（上で定義した `let`、入力、定数）に `^` を付けると E0020（書き手の誤解を示す冗長な印、P2）。遅延の第 1 引数の中では、修正候補は `^` を外すこと（値は同じ）。外では意図が一意に決まらないので、`y` と `prev~(y)` を並べる。
- この規則により、遅延を通らない閉路（瞬時のループ）は書けない。因果性の検査は名前の順序の検査になる。
- シャドーイングは無い（§5.1）ので、`prev~(^y)` の `^y` は常に、その本体の `let y` を指す。
- flow インスタンスを通るフィードバックは、閉路を切る位置に `prev~` を明示して書く: `let y = x + g * lowpass~(prev~(^y))`。FAUST の `~` が暗黙に入れる 1 サンプルの遅延を、Onsa では書き手が置く。
  遅延を内部に持つ利用者の flow も `^` の参照は受け取れない（遅延の第 1 引数の中に書いた `prev~(lp~(^y))` も E0801 で、note で `lp~(prev~(^y))` の形を示す）。遅延の位置を、閉路を切る場所に書き手が明示するためである。ほぼ同じ帰還を二通りに書けるようにしない（P2）。
- flow の宣言は、同じモジュールに同名の名前空間（§11.6）を作る。同じモジュールに同名の宣言があれば E0305 で、ソースの順で後の宣言に付け、前の宣言を note で示す（E0304 と同じ）。名前空間は `use dsp.synth.{voice}` のようにモジュールと同じ形で取り込む。

### 11.3 レート

レートは、値がどのクロックで変わるかである。型ではなく、flow の入出力の宣言と flow の本体の式に `at` で付ける（`x: F32 at sample`、`p at sample`）。値の型は、どこでも普通の型である。

| クロック | 意味 | 評価のタイミング |
|---|---|---|
| （定数） | `const` とリテラル。クロックを持たず、どのクロックにも昇格する | コンパイル時 |
| `init` | 初期化時に決まる値 | `init` で 1 回 |
| `block` | ブロックごとの値 | `process` の呼び出しごとに 1 回 |
| `event` | イベントの入力ごとのクロック（§11.11） | その入力のイベントごと |
| `sample / N` | インスタンスの `sample` の N 刻みに 1 回の値（§11.9） | N 刻みごとに 1 回 |
| `sample` | サンプルごとの値 | サンプルごと |

- `sample * N`（インスタンスの `sample` の 1 刻みに N 個の値）は、変換の flow の入出力の宣言と、`.up~(N)` の部品の中にだけ現れる（§11.9）。式の中で導くクロックを書くときは括弧で包む（`p at (sample / 32)`。`at` の後ろに `/` や `*` が来ると、二項演算子と読みが分かれるため）。`event` は入出力の宣言にだけ書き、式の `e at event` は E0815 の範囲である（§11.11）。
- クロックは、パラメータの種類（定数 < `init` < `block`）と、刻みのクロック（本体の `sample`、`sample / N`、`sample * N`、イベントの入力ごとのクロック）に分かれる。分かれ目は状態を持てるか（E0813 と同じ線、§11.4）である。
  順序は `定数 < init < block < イベントのクロック < sample / N < sample < sample * N` で、別の入力のイベントのクロックどうしは比べられない（`a.x + b.y` は E0815）。`block < sample / N` は評価の段の順で（`block` の値は `sample / N` の段で常に最新で読める）、刻みの頻度ではない。
  コンパイル時定数（`const`、リテラル）はクロックを持たず、この順序の最下位として扱う。定数のクロックの式（定数だけを引数にする、効果行が空の関数の呼び出しを含む。`rt` かどうかによらない）は、`const` の初期化式と同じ評価器でコンパイル時に評価する（§6.6。panic は E0419）。
  値は状態に置かず、静的な領域に一つだけ置く。同じ式を `const` に分けても分けなくても、同じビットになる。
- 読み方: パラメータの種類の値は、使う所のクロック（`sample / N` とイベントのクロックを含む）で変換なしに読める。他に決めるものが無ければ、本体の `sample` として読む（`let c = prev~(^c) + 1` の輪は `sample` で刻む）。遅いクロックの値を速いクロックの式で使うのは、値を変えない（次に変わるまで同じ値が続く）。これは値の変換ではない（言語に暗黙の変換は無い、§3.3）。イベントの値も暗黙に読める（その位置までの最後の値、§11.11）。
  周期の刻みのクロック（`sample`・`sample / N`・`sample * N`）の値を別の周期のクロックで使うには `at` を書く。`at` は遅い→速いで、行き先は本体の `sample` まで（`lf at sample`、`lf` は `sample / 32`）。
  速い→遅いと、`sample * N` へは、変換の flow（速い側を配列で受ける）で書く（§11.9。std に `cut_down32`・`avg_down32`・`lin_up32` などがある）。`at` の無い形は E0815。
- 式のクロックは三つで決まる: 周期の刻みのクロックの被演算子は揃っていること、パラメータの種類とイベントの値は自由に混ざること、最大が無ければ E0815。式のクロックはコンパイラが推論する。
  利用者の flow の呼び出しの結果のクロックは出力の宣言のクロックで、その基準は呼び出しの位置のクロックに連鎖の `.down~`・`.up~` を当てたもの（§11.9）であり、引数のクロックによらない。組込みの遅延の結果は第 1 引数のクロックである（§11.4）。
- `e at k` は、式 `e` のクロックを `k` にする。`k` が `e` の推論したクロックより速ければ昇格（値は変わらない）、同じならそのまま、遅ければ E0815。
  `let ps = p at sample` は遅延に渡すための昇格で（`prev~(p at sample)` とも書ける、§11.4）、`let c = design(freq) at block` は「この値はブロックごと以下で計算する」という約束になる（`freq` が `sample` なら E0815）。`at` は値も評価の段も変えず、状態も作らない。
  クロックの検査と、遅いクロックの値を速い段で読めることを示すだけで、`e` はその推論したクロックの段で評価し、値の置き場所は一つである（`freq` が `init` なら `design(freq)` は `init` で一度だけ計算する）。補間を伴うレートの変換は、状態を持つので flow（`~`）で書く（§11.9）。
  結合の強さは `as` と同じで、二項演算子と範囲の記号の被演算子にするときと、`as` / `at` と連鎖させるときは括弧が要る（E0011、§3.1、§3.3）。`let` の束縛の側にはクロックを書かない（`let y: F32 at sample = x` は E0020、修正候補は `let y: F32 = x at sample`）。
- flow の入力と出力には `at` が必須（E0810）。出力のクロックは `sample`、イベントの出力の `event`（§11.11）、変換の flow の `sample / N`・`sample * N`（§11.9）で、それ以外は E0810（§11.6、§19.1）。`at` を書けるのは flow の入出力の宣言と本体の式だけで、flow の外は E0821（§11.1）。
  型の中（型引数、配列とタプルの要素、関数型の引数と返り値）と、入出力でない宣言の型（struct のフィールド、enum の列挙子の要素、`type` の右辺、`const` の型）の後ろの `at` は、flow の中でも外でも構文の段の E0020 で、修正候補はクロックを書ける場所へ移す形（クロックの無い flow の入出力の型の後ろ、束縛では値の式）か、場所が無ければ除く形である（`fn f(x: Option[F32 at sample])` は E0020、`fn f(x: F32 at sample)` と、handler の関数と無名関数の引数と返り値の同じ形は E0821）。
  関数型の返り値の後ろの `at` は、`uses` と同じく近い方の返り値の型に付き、型の中の `at` として E0020 になる（`g: fn(F32) -> F32 at block` も同じ）。関数型を書いた位置にクロックを付けるときは、関数型を括弧で囲む（`g: (fn(F32) -> F32) at block`。修正候補もこの形で、fmt はこの括弧を外さない）。
  レートを型の形で書く（`x: Sig[F32]`、0.3 の草案の形）と E0020 で、修正候補は flow の入出力では `x: F32 at sample`、flow の外ではレートを外した `x: F32`。
  `Sig` / `Ctl` / `Init` は予約していない普通の名前なので（利用者が `struct Sig[T]` を宣言してよい）、この E0020 は名前が解決できないときだけ、名前の段で出す（§18.1）。
- クロックの名前（`init` `block` `sample` `event`）は、値と型とは別の名前空間にあり、`at` の後ろでだけ引く。`at` の後ろは名前一つか、括弧で包んだ導くクロック（`(sample / N)`、`(sample * N)`）で、経路（`x at a.b`）は E0002。
  クロックの名前空間に無い名前は、値や型に同じ名前があっても E0302（名前の段。主の位置はその名前）。flow の外の `at` は E0821 で、クロックの名前を引かない。`sample` や `block` を変数の名前に使ってもよい（§5.1 のシャドーイングの規則に触れない）。
- flow の本体の `sample` は、そのインスタンスが動くクロックを指す（インスタンスのコンテキスト）。flow は自分がどのクロックで動くかを知らず、呼び出し側が与える。一番外のインスタンスはホストのサンプルのクロックで動き、そのレートは `init` / `render` に渡す `sample_rate` である。インスタンスを別のレートで動かすのは修飾子 `.down~`・`.up~`（§11.9）で、条件で動かすのは `.when~`（§11.10）である。
  flow の本体の意味（`sample_rate()`、`prev~` と遅延の刻み、§11.4）は、そのインスタンスのクロックを基準に決まる。`block` はどのインスタンスでもホストの区切りで、`init` は一度だけである。
- コンパイラは各式を、部分式も含めて、そのクロックの段で評価する（巻き上げ）。`init` の式は `init` で 1 回、`block` の式は `process` の呼び出しごとに 1 回で、サンプルごとに評価されるのは `sample` の式だけである。`let` に分けても分けなくても、評価の段と結果は同じ（`let` は名前を付けるだけ）。
  例えば `x * db_to_amp(level)` の `db_to_amp(level)` は、`level` が `block` なら、毎サンプルではなく `process` の呼び出しごとに計算される。係数計算がサンプルループの外に出ることが、クロックの推論から保証される。
- 高い段で使う、遅いクロックの部分式の値は、状態の隠れたフィールドに置く（名前は §11.6、位置は §12.4）。巻き上げるのは、遅いクロックの部分式のうち最大のもの（それを含む部分式が同じクロックでないもの）だけで、名前（入力、`let`、`par` の添字）、`sample_rate()`、`sample_tick()`、定数のクロックの式は巻き上げない（既に置き場所があるか、状態に置かないため）。
  flow の式には効果が無いので、巻き上げても値と panic の有無は変わらない（変わりうるのは panic の時期だけ）。`if` / `match` の取られない枝と、評価されない `&&` / `||` の右辺の部分式は、巻き上げても panic を起こさない（panic しうる部分式は巻き上げず、その位置で評価する。§11.5）。
- flow の入出力の値型 `T` は Copy でなければならない（E0810）。例: ステレオ信号は `[F32; 2] at sample`、名前付きの複数出力は `Stereo at sample`。
- `block` のクロックは、ホストが `process` を呼ぶ区切り（ブロックの長さ）に従い、サンプルを数えて決まる間隔ではない。`render` は全体を一つのブロックとして扱う（§11.6）。
- `init` は「初期化時」、`const` は「コンパイル時」で、別の概念なので別の語を使う。
- 導くクロック（`sample / N`、`sample * N`）とインスタンスのレートは §11.9、イベントのクロックは §11.11 に定める。

### 11.4 組込み

| 名前 | 型（概略） | 意味 |
|---|---|---|
| `prev~(e)`、`prev~(e, init)` | `e: T` は刻みのクロック（下記）、`init: T` は `init` 以下 | 1 刻み遅延（第 1 引数のクロックの 1 刻み、§11.3）。最初の刻みは `init` |
| `delay~(e, N)`、`delay~(e, N, init)` | `e: T` は刻みのクロック、`N: const U32`、`N >= 2`（`N = 1` は E0807、`N = 0` は E0808）、`init: T` は `init` 以下 | N 刻み遅延。1 刻みは `prev~` と書く（E0807） |
| `vdelay~(e, d, MAX)`、`vdelay~(e, d, MAX, init)` | `e: T` は刻みのクロック、`T: Float`（でなければ E0416）、`d: T` は第 1 引数と同じクロックか、暗黙に読めるもの（パラメータの種類、イベントの値）、`MAX: const U32`、`MAX >= 1`（E0808。`d` の型 `T` が `F32` なら `MAX <= 2^24`）、`init: T` は `init` 以下 | 可変遅延（線形補間）。`d` は `[1, MAX]` に飽和する |
| `sample_rate()` | `F32`（`init`） | インスタンスの `sample` のクロックの 1 秒あたりの刻みの数（§11.3。一番外のインスタンスではホストのサンプルレート、`.down~(N)` の本体では 1/N、`.up~(N)` の本体では N 倍、`when~` の中は外と同じ、§11.9、§11.10） |
| `sample_tick()` | `U32`（使う所の刻みのクロック） | `reset` からの時間を、書いた場所の `sample_rate()` の刻みの数で表したもの（下記） |

- 遅延の長さ（`N`、`MAX`、`d`）は、第 1 引数のクロックの刻みで数える。時間で決まる長さは `sample_rate()` から計算する（`time * sample_rate()`）。
- flow の中の組込み名は `prev` `delay` `vdelay` `sample_rate` `sample_tick` だけである。ホストの情報（テンポ、再生位置など）は組込み名にせず、`block` の入力で渡す。`sample_rate` と `sample_tick` が組込み名なのは、呼び出し側とインスタンスでレートが違いうるからで、インスタンスのクロックに依らない情報は入力で足りる。後から組込み名を足すと、その名前を使っていたプログラムが壊れる。
- `prev~` / `delay~` / `vdelay~` は状態を持つ組込みの flow で、利用者の flow のインスタンスと同じく、呼び出し位置ごとに独立した状態を持つ（`par` では複製ごと、§11.5）。状態のフィールドの名前の付け方、`init` / `reset` での扱い、取られない分岐でも進むことも同じである。
  利用者の flow と違うのは、第 1 引数で帰還の参照 `^名前` を受け取れること（出力が今の入力に依存しないので閉路を切れる、§11.2）、値型 `T` と定数の引数（`N`、`MAX`）を持つこと、`init` を省略できること、名前空間の API を生成しないことである。
- 遅延線の長さ（`N`、`MAX`）は **定数式**（§4.5）でなければならない（でなければ E0417。値の範囲の誤りは E0808）。サンプルレートに依存する長さは、想定する最大のサンプルレートで上限を決める（例: `const MAX_ECHO: U32 = 96000`）。これにより状態の大きさがコンパイル時に決まる（§12.4）。
- 組込みの遅延（`prev~`・`delay~`・`vdelay~`）はクロックに総称で、第 1 引数のクロックで刻み、出力もそのクロックの値である（`prev~(lf)` は 1/32 の刻みで一つ前、第 1 引数がイベントの値なら一つ前のイベント）。第 1 引数の `at` も刻みを決める（`prev~(p at (sample / 32))`、`p` は `block`）。
  第 1 引数に書けるクロックは本体の `sample`・`sample / N`・イベントのクロックで、パラメータの種類は E0813（候補は `prev~(p at sample)`、note に `prev~(p at (sample / N))`。`block` に状態は置かない）。呼び出し側の `sample * N` の値も誤り。
  長さは第 1 引数のクロックの刻みで数え（遅い値の `vdelay~` の長さを `sample_rate()` から作るときは書き手が合わせる）、`vdelay~` の `d` は第 1 引数と同じクロックか、暗黙に読めるもの（パラメータの種類、イベントの値）。総称の遅延に `.down~`・`.up~` を付けると、連鎖のレートが第 1 引数のクロックとずれるので誤り（§11.9）。
  `block` の値を渡しても暗黙には昇格しない。昇格するとブロックの先頭のサンプルだけが前のブロックの値になる信号ができ、意図通りになることがほぼ無いからである。サンプル単位の遅延が要るなら `prev~(p at sample)` と書いて昇格する（E0813 の修正候補）。「前のブロックの値」は取れない。
- 引数 `init` のクロックは `init` 以下（`init` のクロックか定数）でなければならない（E0815。値のクロックが置く位置より速い誤り）。定数でなければ状態に保存し、`reset` で使う。
- `init` は省略できる。省略すると値型の既定値 `T.default()` で始まる（数値は 0、浮動小数は `+0.0`、`Bool` は `false`、配列とタプルは要素ごと、struct は宣言に `Default` を並べたもの。§6.4）。`T` が `Default` を満たさなければ E0816。
  初期値はほとんどの場合 0 なので、書くのは 0 以外の初期値（例: 積の漸化式の `prev~(^g, 1.0)`、`init` の入力から与える `prev~(^y, start)`）だけになり、特別な初期値が目立つ（P10）。値が既定値と等しい `init`（`0`、`0.0`、`false`）を書いても受理するが、書かない（仕様の例と標準ライブラリも省略の形で書く）。
  `onsa fmt` は取り除かない。リテラルが `T` を決める形（`let y = prev~(^y, 0)` は `y` を整数と決める）があり、取り除くと検査の結果が変わる（§18.2）。
  これは flow の組込みの形で、利用者の関数に既定引数は無い（§6.1）。FAUST の `'`、`mem`、`@` もゼロで始まる。
- `sample_tick()`（予約名、§11.6）: `reset` からの時間を、書いた場所の `sample_rate()` の刻みの数で表した `U32`（2^32 で一周し、間隔は `t -% last` で取る。48 kHz で約 24.9 時間）。`init` と生成する `reset` で 0 になり、`reset_if~` は触れない。
  `.up~(N)` の本体では N 倍、`.down~(N)` の本体では 1/N（上の桁の `U32` の欄をプログラムに一つ置く）、`when~` の中は外と同じ（止まっている間も進む）である。
  クロックの推論では、`sample_rate()` と同じく式のクロックを引き上げず、使う所の刻みのクロックに合わせる。下限は刻みのクロックで、他に刻みのクロックが無ければ本体の `sample`（`block` の段で読むと、ホストの区切りに依る値になるため）。巻き上げず、使う所の段で評価する。イベントの段の式ではその位置の値である。
- `vdelay` の `d` の下限が 1 なのは、`d = 0` が遅延を通らない閉路になるからである。
- `d` が `F32` のとき（`d` は信号と同じ型なので、`F32` の信号のとき）、`MAX` は `2^24` 以下でなければならない（E0808）。
  `2^24` を超えると `F32` は連続する整数を表せず、遅延の長さが 2 サンプル以上の刻みになって、線形補間の意味が成り立たないからである（`MAX` を `F32` に変換するときに上へ丸まると、`k` が `MAX` を超えて添字の計算が溢れる）。`F64` の `d` は `U32` の `MAX` を全て正確に表すので、この上限は無い。
  値の型と読み出す位置の型を分けて長い遅延を扱うことは §19.1 に挙げた。

遅延の状態と演算の順序は次の通りに固定し、全ての変換先でビット一致させる（§13.4）。各サンプルで、全ての遅延の出力（保存値）を先に読み、保存する値 `e` を全て評価してから、まとめて保存する。遅延の `e` の中の遅延は、保存の前の出力を読む（`prev~(prev~(x))` は `x[n-2]`）。

- `prev`: 状態は `T` 一つ。出力は保存値で、その後に `e` を保存する。
- `delay`: 状態は `buf: [T; N]` と `w: U32`。各サンプルで、出力は `buf[w]`（= `e[n - N]`）、その後 `buf[w] = e`、`w = (w + 1) % N`。初期値は全要素 `init`、`w = 0`。
- `vdelay`: 状態は `buf: [T; MAX + 1]` と `w: U32`。`L = MAX + 1` として、各サンプルで次の順に計算する。疑似コードの中で `MAX` と `k` を `T` の値として使う所（`d` との比較、`dc` の値、`f` の引き算）は、それを `T` に変換した値を表す（どちらの型でも正確に表せる。`F32` は `MAX <= 2^24` による）。

```
dc = if d >= 1.0 { if d <= MAX { d } else { MAX } } else { 1.0 }   // NaN は 1.0 になる
k  = dc.trunc_u32()                                                  // 1 <= k <= MAX
f  = dc - k                                                          // 0 <= f < 1。k <= dc < 2k なので正確
a  = buf[(w + L - k) % L]                                            // e[n - k]
b  = buf[(w + L - k - 1) % L]                                        // e[n - k - 1]
y  = (1.0 - f) * a + f * b
buf[w] = e
w = (w + 1) % L
```

補間は FAUST の `fdelay` と同じ 2 乗算の形である。`a + f * (b - a)` は `f` が 1 に近いとき `b` に一致しない。
また `a`、`b` が有限でも `b - a` が溢れるとき（`a = -MAX`、`b = MAX`）、`a + f * (b - a)` は `f = 0.5` で無限大、`f = 0` で NaN になるが、2 乗算の形はそれぞれ 0 と `a` になる。`b` 自身が無限大か NaN なら、2 乗算の形も `f = 0` で NaN になる（`0 * inf`）。
式に場合分けは足さない（無限大や NaN の標本が入った時点で信号は壊れている。整数の遅延は `delay~` で書ける）。長さが `MAX + 1` なのは、`d = MAX` のとき `k + 1 = MAX + 1` を読むからである。

### 11.5 呼び出しと複製

flow 本体の中での呼び出しは、呼び出す相手によって意味が決まり、相手の種類は呼び出しの形で分かる（§2.6）。

| 呼び出す相手 | 形 | 意味 |
|---|---|---|
| flow | `saw~(f0)` | 呼び出し位置ごとに独立した状態を持つインスタンスを作る |
| 組込みの遅延 | `prev~(x)`、`delay~(^y, N)` | flow と同じくインスタンスを作る。第 1 引数で帰還の参照 `^名前` を受け取れる（§11.2、§11.4） |
| 効果行が空の `rt fn` | `wrap01(x)` | 点ごとに適用する。結果のクロックは引数のクロックの最大値 |
| 効果行が空の非 `rt` fn | `make_window(n)` | 引数のクロックが `init` 以下（`init` か定数）のときだけ呼べる（でなければ E0815）。式のどこに書いても、引数が全て定数ならコンパイル時、そうでなければ `init` で評価される（§11.3） |
| 効果を持つ fn（`Alloc` を含む） | | 呼べない（E0805） |

- 引数の位置に書いたインスタンスの呼び出し `f~(…)` は、呼び先によらず出力の値である（修飾子の受け手は §11.10）。
- `if c { a } else { b }` と `match` は点ごとの選択で、fn と同じく取る枝だけを評価する（§3.5）。枝と `match` のガードには、状態を持つもの（インスタンス、組込みの遅延、`par`）を書けない（E0811。修正候補は `if~` / `match~` にすることと、状態を持つものを前の `let` に出すこと）。条件と `match` の対象は常に評価されるので書ける。
- `if~ c { a } else { b }` と `match~ x { ... }` は、全ての枝を評価してから一つを選ぶ（FAUST の `select2`、Lustre の `if` と同じ）。全ての枝の状態を持つものが進み、状態を持たない部分も全て評価される。
  `else if` の連鎖では、`~` は連鎖の全体に掛かる（`if~ c1 { a } else if c2 { b } else { e }`）。`else` は省けない（省くと構文の段の E0002 で、修正候補は無く、全ての枝を評価して一つを選ぶので `else` が要ることを note で示す）。`~` は連鎖の最初の `if` にだけ書く。
  後ろの `if` に付けた `~`（`else if~`）は E0020 で、修正候補は、連鎖の頭に `~` があれば後ろの `~` を除く形、無ければ `~` を頭の `if` へ移す形（一つの連鎖に複数あれば `~` ごとの誤り）。状態を持つものを枝に含まなければ E0812（修正候補は `~` を外すこと）。
  `match~` の取られない腕の束縛は、値型の既定値 `T.default()` になり、`T` が `Default` を満たさなければ E0816。腕は `match` と同じく、パターンとガードで選ぶ。
  枝の一部だけを取られた側で評価したいときは、枝の中に普通の `if` を書く（`if~ c { lp~(x) } else { if d != 0 { 100 / d } else { 0 } }`）。
- `&&` / `||` の右辺には、状態を持つものを書けない（E0806。修正候補は前の `let` に出すこと）。
- 取られない枝の状態を止める書き方は、インスタンスの修飾子 `when~` である（`let y = lp~(x).when~(c)` と取ってから `if c { y } else { 0.0 }`、§11.10）。
- flow 本体の中に再帰やループは無い。flow が自分自身を、直接または他の flow を経由してインスタンスにすると E0817（状態の大きさが決まらない）。
- flow の呼び出しの引数のクロックは、入力の宣言のクロック（呼び出しの位置のクロックと連鎖のレートを基準にする、§11.9）以下でなければならない（`block` の入力に `sample` の値、`init` の入力に `block` の値を渡すと E0815）。昇格の逆は無い（§11.3）。
  イベントの値は `sample`・`sample / N` の入力へ最後の値で読め、`block`・`init`・`sample * N` の入力へは E0815（§11.11）。周期の刻みのクロックの間は `at` が要り、`sample / N` の値は `at` なしに `sample` の入力へ読めない（§11.3）。
- `Alloc` を持つ関数を呼べないので、flow とその初期化はヒープを使わない。

**複製** `par i in a ..< b { e }` は、`e` を `N = b - a` 個並べ、`par i in a ..= b { e }` は `N = b - a + 1` 個並べる（`par i in 0 ..< N` は FAUST の `par(i, N, e)` と同じ意味）。
`a` と `b` は定数式（§4.5。でなければ E0417）で、範囲は空であってはならない（`a ..< b` は `a < b`、`a ..= b` は `a <= b` を要し、空の範囲は E0808）。
`i` は `U32` で、各複製の中で `a` から最後の値（`a ..< b` は `b - 1`、`a ..= b` は `b`）までの `init` のクロックの **値**（コンパイル時定数ではない。遅延線の長さなど定数が要る位置には使えない）、結果の値型は `[T; N]`。`e` の中の flow 呼び出しは、複製ごとに別のインスタンスになる。
本体に状態を持つもの（インスタンス、組込みの遅延）が無い `par` は、状態のフィールドを作らない。

`par` は構造の複製であって、反復ではない。Verilog の手続きの `for` と構造を複製する `generate for` の関係に当たる。`for` と読むと「呼び出し位置が一つで、インスタンスを N 回進める」と誤読するので、`for` の見た目は使わない。
値の世界で N 個の値を作る `[e; N]` / `array.from_fn` に対応する、flow の世界の構築子である。コンパイラは複製を状態の配列 `[sub.State; N]` とループに落とす（コードは N 倍にならず、複製方向にベクトル化できる）。複製ごとに違う遅延線の長さが要るときは `vdelay` に上限を与えるか、`let` を並べて書く。

```onsa
use std.math.{sum}

const UNISON: U32 = 4

pub flow unison(f0: F32 at block, detune: F32 at block) -> F32 at sample {
  let saws = par i in 0 ..< UNISON {
    saw~(f0 * (1.0 + detune * spread(i, UNISON)))
  }
  sum(saws) * 0.25
}

/// 0 ..< n を [-0.5, 0.5] に等間隔に並べる
pub rt fn spread(i: U32, n: U32) -> F32 {
  i.round_f32() / (n - 1).round_f32() - 0.5
}
```

`par` は `for` と違う見た目にしてある。`for` は順に実行される反復で、`par` は同時に存在する N 個の構造の宣言だからである。

### 11.6 生成される API

`flow voice(...)` を宣言すると、コンパイラは名前空間 `voice` に次を生成する。flow 自体は型ではない。状態を表す型は `voice.State` である。

```onsa
// 型
voice.State        // 状態。Affine、固定サイズ、ヒープを使わない。遅延線も含む
voice.Config       // init の入力をフィールドに持つ struct（Copy）。init の入力のある flow だけ
voice.Params       // block の入力をフィールドに持つ struct（Copy）。block の入力のある flow だけ
voice.Event        // イベントの入力の値と位置を持つ、中身を見せない Copy の型。イベントの入力のある flow だけ
voice.In           // sample の入力が 2 つ以上のときだけ。sample の入力ごとの Span をフィールドに持つ
voice.Out          // 出力が struct のときだけ。出力のフィールドごとの Span を持つ
voice.Rendered     // render の結果。出力チャンネルごとの Buf（イベントの出力は位置と値の Buf）

// 関数
fn voice.init(cfg: voice.Config, sample_rate: F32) -> voice.State
                                            // cfg は init の入力のある flow だけ（下の数の規則）
rt fn voice.reset(inout s: voice.State)
rt fn voice.process(inout s: voice.State, params: voice.Params, events: Span[voice.Event], <入力>, <出力>)
rt fn voice.process_inplace(inout s: voice.State, params: voice.Params, events: Span[voice.Event], <入出力>)
                                            // sample の入力と出力の数と型が順に一致し、イベントを出さない flow にだけ生成される
fn voice.render(cfg: voice.Config, params: voice.Params, events: Span[voice.Event], <入力>,
                frames: U32, sample_rate: F32) -> voice.Rendered uses {Alloc}
                                            // frames は sample の入力の無い flow にだけある
fn voice.params_default() -> voice.Params   // block の入力のある flow で、その全てに @param か @host がある場合
fn voice.Event.<入力の名前>(pos: U32, v: T) -> voice.Event   // イベントの入力ごと
rt fn voice.latency(s: voice.State) -> U32  // 遅れ（下記）
```

- 名前空間はモジュールと同じ扱いで、関数は `voice.process(inout st, ...)` のように前置で呼ぶ（`fs.read(p)` と同じ形）。`use dsp.synth.{voice}` で名前空間を、`use dsp.synth.voice.{State, Params}` で中の項目を取り込める。名前空間と中の全ての項目は、flow の可視性（`pub` / 無指定 / `priv`）を継ぐ。中の項目の名前は上の一覧に固定され、利用者の項目は入らない。
- 状態の大きさ（fast / bulk 領域のバイト数）は名前空間に無い。ターゲットの設定とポインタの幅で変わるので、C のヘッダ（§14.2）と `onsa interface --target <名前>` にだけ出す（§12.4）。Onsa のコードの意味はターゲットに依存しない。
- 生成された型は flow を宣言したモジュールで定義されたものとして扱うので、同じモジュールに `impl voice.State { ... }` で補助メソッドを書ける（孤児規則 §6.3 の通り）。
- Core IR と生成コードでも名前は `voice.State` の形を保つ（C ではモジュールの経路を含めて `dsp__voice__State` のように `__` でつなぐ。export は `prefix` + `voice`）。生成コードとデバッガで同じ名前が見える。
- `process` の `<入力>` と `<出力>` は、数で形が決まる。
  - 入力: `sample` の入力が無ければ引数は無い。1 つなら `input: Span[T]`（値型が `[T; N]` なら `input: [Span[T]; N]`、チャンネルごとのバッファ、§5.3）。2 つ以上なら `input: voice.In`。`In` は `sample` の入力の名前をフィールドに持ち、各フィールドは `Span[T]` か `[Span[T]; N]`。
  - 出力: 単一の値なら `inout output: Span[T]`、`[T; N]` なら `inout output: [Span[T]; N]`、struct なら `inout output: voice.Out`。`Out` は出力の struct と同じフィールド名を持ち、各フィールドは `Span[T]` か `[Span[T]; N]`。
    イベントの出力（§11.11）は `inout output: Span[(U32, E)]`（長さが容量）で受け、`process` は出した数を返す（`-> U32`）。`sample` の入力が無くイベントを出す flow の `process` は `frames: U32` を取る（`render` と同じ）。
  - イベント: イベントの入力のある flow の `process` は、`params`（あれば）の後、`sample` の入力の前に `events: Span[voice.Event]` を取る。列は入力の印の付いた一つの列で、入力をまたいだ順は列の順だけで決まる。要素は入力ごとの作る関数 `voice.Event.<入力の名前>(pos: U32, v: T)` で作る。
  - 引数は flow のシグネチャにある入力と出力だけである（この数の規則を、`sample` の入出力、イベントの入出力、`block` の入力、`init` の入力の全てに当てる）。`block` の入力の無い flow は `params` の引数と `Params`・`params_default` を持たず、`init` の入力の無い flow は `cfg` の引数と `Config` を持たない（`process`・`process_inplace`・`render`・`init` で同じ）。
    シグネチャと違う呼び出しは型の誤りになる。
  - 引数の名前は `s`、`params`、`events`、`input`、`output` に固定する。利用者の名前（`sample` の入力の名前、出力の struct のフィールド名）は `In` / `Out` のフィールドにだけ現れるので、生成 API の引数の名前と衝突しない。
  - `In` と `Out` は `Span` を持つので、`Span` と同じく引数の位置にだけ現れる（§5.3）。引数の位置に struct リテラルを書いて作り、排他性はフィールドの場所ごとに検査する（`inout [a, b]` と同じ）。
    例: `swap.process(inout st, p, swap.In { l: a, r: b }, inout swap.Out { l: x, r: y })`。入出力が複数あるときは名前で対応が見えるので、左右の取り違えが見た目に出る。よく使う形（入力が 0 か 1、出力が単一の値か配列）は、struct を作らずに `Span` をそのまま渡す。
  - `sample` の入出力の全ての `Span` の長さは等しくなければならず（イベントの列とイベントの出力は含まない）、違えば panic（poisoned）する。長さは呼び出しの最初に、どの状態も進める前に一度だけ比べる。サンプルループの中の入出力の `Span` への添字には検査を置かない（最初の比較が、それらの添字が範囲内であることを保証する。§11.3 の巻き上げと同じく、性能の約束である。サンプルの段から呼ぶ関数の中の添字は §9.2 のとおり検査する）。
  - 長さが 0 の呼び出し（ホストが 0 フレームで呼ぶ場合）も正しい呼び出しで、`block` の段は他の呼び出しと同じく 1 回評価し、`sample` の段は評価しない。
  - イベントの列の前提: `pos < frames`（`frames` は `sample` の入出力の長さ）、列の順に `pos` が減らない。破れば呼び出しの最初に panic する（poisoned。`Span` の長さの不一致と同じ）。`frames` が 0 の呼び出しはイベントを持てない（あれば同じ扱い）。出力のイベントの容量が上限（§14.2）に足りないときも、呼び出しの最初に panic する（黙って捨てない）。
    呼び出しを位置 k で分けると、`pos >= k` のイベントは次の呼び出しの `pos - k` に移り、出力は分けない呼び出しとビットで同じである（`params` が同じとき。`block` は状態を持たず、位相のカウンタはホストの区切りに依らない。`@host` の値はラッパーが分けた位置で進めるので、`@host` を読む flow の出力は最後の桁が変わりうる）。
    呼び出しのイベントの段は、その呼び出しの `params` を読む（同じ位置のパラメータの変化とイベントの順は言語が約束しない。ラッパーは位置 p のパラメータの変化の直前で呼び出しを分け、p のイベントは新しい値を見る）。
- `sample` の入出力の値型は、スカラ、`[スカラ; N]`、または（出力のみ）それらをフィールドに持つ struct。入れ子の配列は境界に出せない（E0810）。
- `process` のサンプルループは、各サンプルで **全ての `sample` の入力を読んでから、全ての出力を書く**。過去の値は状態から読み、入力バッファの他の位置は読まない。この不変条件により、入力と出力が完全に同じバッファでも結果は変わらない。
- `process_inplace` は、`sample` の入力と出力を位置で対にし、`inout output` 一つ（出力と同じ形）にまとめたもの。入力と出力の数と型を比べるとき、struct の出力はフィールドを順に展開して数える（`swap(l: F32 at sample, r: F32 at sample) -> Stereo at sample` にも生成する）。
  イベントを出す flow には生成しない（`sample` の入出力が共に無く、数の比べが空で一致してしまうため）。`process` の排他性（§5.2）を保ったまま、一本のバッファにエフェクトを掛けられる。本体は `process` と同じで、C バックエンドでは同じポインタで内部の関数を呼ぶだけなのでコードは増えない。
- `reset` は、`prev` / `delay` / `vdelay` の状態を `init` 値に戻し、書き込み位置を 0 にし、サブインスタンスを再帰的に `reset` し、poisoned を解く。
  止まる部品の保持した出力（§11.10）と、遅いクロックの値を速い段で読む欄（§11.3、§11.11）も戻し、位相のカウンタ（§11.9）を 0 にする。`init` のクロックの値は保つ（`init` の再実行は非 rt になりうる）。
  export の境界では、`init` が panic して完了しなかったインスタンス（`initialized` が偽）に対する `reset` は何もしない（§14.2）。
- `init` は効果を持たず、ヒープを使わない。返り値は呼び出し側の領域に直接構築される（§12.7。コピーしないことを保証する）。
- `render` はテストと一括処理用。全体を 1 回の `process` として処理するので、`block` の入力は全区間で一定。ブロックごとにパラメータを変えるテストは `process` を自分で繰り返す。`sample` の入力がある flow では `frames` を取らず、`Span` の長さを使う。
  イベントの入力のある flow の `render` は、`process` と同じ位置に同じ形のイベントの列を取り、位置は `render` の頭から数える（`frames` が 0 の `render` はイベントを持てない）。
- `Rendered` は、出力を `Buf` で持つ struct。スカラ出力は `o.out: Buf[T]`、`[T; N]` は `o.out: [Buf[T]; N]`、struct 出力はフィールド名（`o.l`、`o.r`。各フィールドは `Buf[T]` か `[Buf[T]; N]`）、イベントの出力は `o.out: Buf[(U32, E)]`。`render` の `<入力>` は `process` と同じ形。
- 状態の所有者は呼び出し側。サンプルレートを変えるときは、`init` を呼び直す。
- `latency` は flow の遅れのサンプル数を返す（`init` の後の値。未初期化なら 0。C は `<p>_latency`、§14.2）。値は一番外の flow の宣言 `@latency(e)`（`e` は `init` のクロックの式）で、宣言が無ければ 0 である（子の宣言は合成しない）。
  コンパイラは報告する値を本体から数えない（フィルタの群遅延は周波数と係数に依り、遅いレートで動く検出の経路の遅れは音の遅れでないので、機械では正しく決まらない）。構造から決まる遅れ（集めて配る N と子の宣言の、経路ごとの値）は解析の道具（`onsa audit`）が出す（形は未決定、§19.1）。
  `block` のクロックの式は E0815。値は状態の隠れた欄に置き、`reset` は保つ。std の `fir_up2`・`fir_down2` は `@latency` を持つ。
- 状態のフィールドは `let` の名前を保つ（`onsa interface`、トランスパイル結果、デバッガ、プローブで同じ名前が見える）。`let` の値がインスタンス・遅延・`par` の呼び出しそのものなら（`let c = prev~(b)`、`let src = saw~(f0)`）、そのノードは `let` の名前で呼ぶ（`c`、`src`）。
  名前の無い状態のノード（式の中に直接書いたインスタンスと `prev~` / `delay~` / `vdelay~`、`par`）は、それを含む `let` の名前に `.` で続けて、種類と番号で呼ぶ（`let a = prev~(lp~(x)) + prev~(x, 1.0)` の `a.prev_0`、`a.lp_0`、`a.prev_1`）。
  種類は、組込みの遅延の名前、修飾を除いた flow の名前、`par` である。番号は `let` ごと・種類ごとに、呼び出しの名前が字面に現れる順に 0 から振る（`lp~(lp~(x))` は外側が先）。出力の式の中のノードは修飾しない（`lp_0`）。分解する `let` は、パターンの中で最初に束縛する名前で修飾する。
  名前を一つも束縛しない `let`（`let _ = f~(x)`、`let (_, _) = g~(x)`）は、名前の代わりに `_<番号>` を使う（番号は、そのような `let` の字面の順に 0 から）。
  `par` の本体は、その `par` の名前で修飾する（`let saws = par ...` の本体の `saws.saw_0`、入れ子の `par` は `m.par_0.acc_0`）。巻き上げた部分式の値を置く隠れたフィールド（§11.3）も同じ規則で `a.hoist_0`、`hoist_0` と呼ぶ。巻き上げの番号は `let` ごとに、部分式の始まりの字面の順に振る。
  これらの名前は表示（`onsa interface`、生成コード、デバッガ、プローブの宛先）のためのもので、ホットリロードとプローブの付け替えの照合には使わない（§18.3）。
  これらの生成する名前（種類と番号の形 `prev_0`、`hoist_0` など）と、状態の固定のフィールド名（`sample_rate`、`poisoned`、`initialized`、`bulk`）は予約されていて、flow の入力と本体の `let` の名前に使えない（E0304）。
  組込みの名前（`prev` `delay` `vdelay` `sample_rate` `sample_tick`、§2.2）も、入力や `let` で隠せない。flow の名前 `hoist` も予約されていて使えない（E0304。そのノードの名前が、巻き上げのフィールドの `hoist_0` と重なるため）。
  `delay` / `vdelay` の内部の状態は `<名前>.buf` と `<名前>.w`、定数でない `init` の保存先は `<名前>.init`、`when~` を付けたインスタンスの保持した出力は `<名前>.held`（§11.10）。C では `.` を `__` にする（`a.prev_0` は `a__prev_0`。型の名前の `dsp__voice__State` と同じ写し方で、識別子に `__` は書けないので（§2.3）、利用者の名前と重ならない）。
- `onsa interface` は、状態のフィールドを `名前: 型` で表示する。サブインスタンスの型はその flow の `State`（`src: saw.State`）、組込みの flow の状態は呼び出しに合わせた疑似型（`prev[F32]`、`delay[F32, N]`、`vdelay[F32, N]`。`N` は最大の遅延）、`let` 由来の値は値の型である。
  疑似型は interface とホットリロードの照合（§18.3）にだけ使い、Onsa のコードには書けない。内部の状態（`.buf`、`.w`、`.init`、`.held`）は、そのフィールドの配置の内訳として表示する。
  `let` に由来しないフィールド（`sample_rate`、`bulk`、入力の写し、`hoist_N`（遅いクロックの値とイベントの値を速い段で読む欄を含む）、位相のカウンタ、遅れの値、`poisoned`、`initialized`）も配置の一部として表示し、処理系が置くものだと印を付ける。
- flow は第一級の値ではない。flow の外からは、この名前空間の型と関数を通じてだけ扱う。
- flow の出力のクロックは、`sample`、イベントの出力の `event`（§11.11）、変換の flow の `sample / N`・`sample * N`（§11.9）で、それ以外の `at` は E0810（`block` の出力は §19.1）。一番外の flow の入出力の `sample / N`・`sample * N` も E0810 である（§11.9）。

### 11.7 パラメータのメタデータ `@param`

```onsa
use std.dsp.{db_to_amp}

pub flow gain(
  x: F32 at sample,
  @param(min: -60.0, max: 12.0, default: 0.0, unit: "dB")
  level: F32 at block,
) -> F32 at sample {
  x * db_to_amp(level)
}
```

- `@param` は `block` の入力にだけ付けられ、入力の値型は `F32` `F64` `I8` `I16` `I32` `U8` `U16` `U32` `Bool` に限る（それ以外は E0809）。`I64` / `U64` を外すのは、ホストとの受け渡しとメタデータ表（§14.2）で全ての値を正確に表せないからである。
- キーは `min max default step unit scale label id` の閉じた一覧で、同じキーは一度だけ書ける。`default` は必須（E0809）。
  数値のキー（`min max default step`）の値は入力の値型 `T` の値、文字列のキー（`unit label id`）の値は `Str` で、どちらも `const` の初期化式と同じ規則で書き、コンパイル時に評価する（§6.6。`const` の名前、関連定数、関数の呼び出し、補間を書ける。評価の panic は E0419）。
  範囲を本体でも守るとき（下記）は、同じ定数を使える。型の合わない値は E0401（暗黙の変換は無い、§3.3。`F32` の入力の `min: 0` は修正候補 `0.0`、整数の入力の `min: 2.0` は修正候補 `2` で、`2.5` には候補が無い）。`scale` は `"linear"`（既定）か `"log"`。
- 値の制約（違反は E0809）: 数値は有限（NaN と無限大は不可）。両方あれば `min < max`。`default` は範囲の中。`step > 0`。`scale: "log"` は `min > 0` を要する。`Bool` の入力に書けるのは `default`（`true` / `false`）、`unit`、`label`、`id` だけである。
  制約が無ければ `min` / `max` / `step` を書かない（`step` が無ければ、浮動小数は連続、整数は全ての整数の値）。`onsa interface` も、書かれていないキーを出さない。
- 用途: IDE の自動 UI、プラグイン（CLAP / VST3 / AU）のパラメータ情報、`params_default()`、C API のメタデータ表。
- export する flow（§15.3）の `block` の入力には `@param` か `@host`（下記）が必須（E0809）。
- ホストの情報: `block` の入力に `@host(<種類>)` を付けると、export でも `@param` が要らず、ラッパーがその呼び出しの最初のサンプルの時点の値を書く（呼び出しを分けた位置では進めた値、§14.3）。
  種類は `tempo`（`F64`、BPM、既定 120.0）・`beat`（`F64`、四分音符の数の位置、0.0）・`bar_start`（`F64`、今の小節の頭の位置、0.0）・`sig_num`・`sig_den`（`U16`、4・4）の閉じた一覧（再生の状態は `transport.Event` で受ける、§11.11）。種類の誤りは E0005、型の違いと `@param` との重なりは E0809。
  `@host` は export しない flow の入力にも付けられ、意味は export でだけ持つ（`@param` と同じ）。`params_default()` は `@host` の欄を既定の値にし（§11.6）、`onsa test --flows` は `@host` の入力に既定の値を与える（§18.2）。C の表は §14.2。
- プラグイン（§14.3）に出す flow の数値の `@param` は `min`・`max` を要する（無ければそのターゲットのビルドで E0809）。整数は `(max − min) / step ≤ 2^24`（E0809）。AU のターゲットでは `F64` の `@param` は E0200。VST3 の正規化は `scale` で写す。ラッパーが値を格子に寄せて範囲に収めることは §14.3（下の飽和させない約束とは別の層）。
- `id` はパラメータの文字列の ID で、ホストが保存する自動化とプリセットが参照する。省略すると入力の名前（`cutoff`）になる。空でなく、ASCII の英字・数字・`_`・`.` からなり、同じ flow の中で重複してはならない（E0809）。入力の名前を変えても保存した自動化とプリセットを保つには、元の名前を `id` に書く（`id: "cutoff"`）。`onsa.policy` で凍結したインタフェースでは、ID の変更もエラーになる（§15.4）。
- 数値の ID は、文字列の ID から決まる 32 ビットの整数である。CLAP / VST3 / AU のホストはパラメータを整数で識別するので、プラグインのラッパーと C の API（§14.2 の `number` と `_param_index`）はこれを使う。
  作り方は、`id` のバイト列に FNV-1a（32 ビット、オフセット基底 `0x811C9DC5`、素数 `0x01000193`）を適用し、下位 31 ビットを取る（`h & 0x7FFFFFFF`）。
  31 ビットに収めるのは、パラメータの ID を符号付きの整数として扱うホストがあり、無効値 `0xFFFFFFFF`（CLAP の `CLAP_INVALID_ID`、VST3 の `kNoParamId`）も避けられるからである。同じ flow の中で数値が衝突すると E0809（note で `id` を変えることを示す）。
  文字列から決まるので、文字列の ID を変えない限り、入力を足したり並べ替えたりしても数値は変わらない。
- `@param` は宣言（メタデータ）であり、どの呼び出しでも挙動を変えない。export された API も、パラメータを `[min, max]` に飽和させない。`min` / `max` は UI とホストが使う範囲である。C などから直接呼ぶ場合、値の条件を守るのは呼び出し側の責任である。
  範囲を守る必要がある flow は、本体に書く（`let fb = min(max(feedback, 0.0), 0.95)`。§11.3 により `process` の呼び出しごとに 1 回だけ計算される）。こうすると、テストの `render` と実機で挙動が同じになり、UI の範囲と許容する範囲を別々に決められる。

UI の宣言を DSP の式の中に書く FAUST（`hslider(...)`）と違い、パラメータはシグネチャに出る。パラメータの一覧を知るのに本体を読む必要が無い（P1）。

### 11.8 テスト用の補助

一括処理は生成された `render` で行う。`std.dsp.test` には次を置く。

- `impulse(n: U32) -> Buf[F32] uses {Alloc}`
- `magnitude_at(xs: Span[F32], freq: F32, sample_rate: F32) -> F32`（F64 の Goertzel で計算し、結果を F32 に丸める）
- `energy(xs: Span[F32], from: U32, to: U32) -> F64`（半開区間 `[from, to)` の二乗和）
- `assert_near(a: F64, b: F64, tol: F64)`（`a == b || abs(a - b) <= tol` を §3.4 の F64 の演算で計算し、真なら通る。`tol` は有限で負でない値に限り（`-0.0` は 0）、そうでなければ `a` と `b` を比べずに失敗する。NaN は `a` と `b` のどちらにあっても失敗する。失敗は呼び出しの位置の panic で、文面は約束しない）

イベントの入力のある flow のテストは補助を足さず、配列のリテラルと作る関数（`voice.Event.<入力の名前>`、§11.6）でイベントの列を書き、`render` か `process` に渡す（入力をまたいだ順は列の順に書く）。

`test` の名前は、空でない、補間を含まない文字列リテラルで、その値（エスケープで書いた文字を含む）に制御文字（U+0000〜U+001F と U+007F〜U+009F。改行とタブを含む）、U+2028 / U+2029、双方向の制御文字（§2.5 の一覧）を含めない。違反は構文の段の E0002 で、修正候補は出さず、規則を note で示す。
名前は、同じモジュールの中で重複できない（E0306）。同じ名前かは値（コードポイントの並び）で比べ、Unicode の正規化はしない（`"a"` と `"\u{61}"` は同じ名前、`"é"` と `"e\u{301}"` は別の名前）。
テストはモジュールの経路と名前で識別する（`dsp "decays"`。単一ファイルのパッケージではモジュールの経路はファイル名（拡張子を除く）で、§2.3 の規則に従う）。
テストの完全な名前のテキストは、モジュールの経路、空白一つ、名前を Onsa の文字列リテラルとして書いたもの（引用符で囲み、`\` を `\\`、`"` を `\"`、`{` を `{{`、`}` を `}}` にし、他の文字はそのまま並べる。名前は制御文字を含まないので、エスケープはこの四つで決まる）をつないだもので、`onsa test --filter` はこれと照合する（§18.2）。
結果のテキストの形は [`spec/tools.md`](tools.md) §4、`--json` の形は §18.1 に定める。

性質の検査（property-based testing）は構文ではなくライブラリで行う。`std.test` の `check[T: Show](cases: U32, g: Gen[T], p: fn(T) -> Bool) uses {Random}` は、`g` から `cases` 個の値を生成して `p` を検査し、反例を `Show` で表示して panic する。
生成器は `gen.f32(lo, hi)`、`gen.u32(lo, hi)`、`gen.pair(g1, g2)` など。種はテストランナーが与えるので決定的で、`onsa test --seed` で変えられる。

```onsa
use std.test.{check, gen}

test "wrap01 stays in [0, 1)" {
  check(1000, gen.f32(-1.0e6, 1.0e6), fn(x: F32) -> Bool {
    let y = wrap01(x)
    0.0 <= y && y < 1.0
  })
}
```

`std.test` と `std.dsp.test` の補助は普通の std の関数で、`test` の外からも呼べる。呼べる場所は、ほかの関数と同じく効果行と変換先で決まる。`check` は `Random` を要し、`test` の本体ではテストランナーが種を決めた `Random` を与える（§8.5）。それ以外では、呼ぶ関数の効果行に `Random` が要る（E0601）。
変換先が与えない補助は、その変換先で E0200 になる（§15.2）。`Gen[T]` の中身は公開しない。生成器は `gen.*` で作る。

### 11.9 マルチレート

オーバーサンプリング、FFT / STFT、リサンプリング、制御のレートを、インスタンスの修飾子と、入出力のレートの違う flow（変換の flow）で書く。
クロックの宣言（`clock fast = sample / 32`）と `with` の節は使わない（語の予約は残す、§2.2）。クロックの種類と読み方は §11.3、組込みの遅延のクロックは §11.4 に定める。

- 部品のレート: インスタンスを別のレートで動かすのは修飾子 `.down~(N)`・`.up~(N)` だけで、引数のクロックやつなぎ方からは決めない。`x.down~(N)` は x の本体の `sample` を左のレートの 1/N に、`x.up~(N)` は N 倍にする（`sample_rate()` も 1/N・N 倍で、遅延はその刻みで数える）。
  N は 2 以上の 2 のべき乗の定数式（違えば E0808・E0417 の類）で、入れ子の比の積は 2^24 以内（flow をまたぐので降下で確かめる）。修飾子の名前は修飾子の閉じた一覧に足す（予約語は増えない）。
  連鎖は合成で読み、比は掛け合わさる（`x.down~(2).down~(4)` は 1/8、`x.down~(2).up~(4)` は 2 倍。`x.up~(M).down~(N)` も、中の部品の入出力を境界で集めて配る形で読む）。2 のべき乗に限るので、合成の比は `sample * N`・`sample / N`・`sample` のどれかに閉じる（Pure Data の `block~` と同じ制限）。
  連鎖のレートの起点は最初の呼び出し（利用者の flow は呼び出しの位置のクロック、組込みの遅延は第 1 引数のクロック）で、`when~`・`reset_if~` はレートを変えない。連鎖の全ての `.down~`・`.up~` を当てたレートを連鎖のレートと呼ぶ（§11.10）。
  `.down~(N)` の出力は呼び出し側の `sample / N` の値で、次の自分の刻みまで前の値である（保持した出力の欄は持たない）。部品の外に書いた `at` の欄も、次の自分の刻みまで前の値である。戻したいときは `at` を部品の本体の中に書く。`.up~(N)` の出力は `sample * N` の値で、変換の flow が配列で受ける。
  呼び出し側で `sample * N` の値に点ごとの演算をする形（`ovs2~(x) * d`）は当面は誤り（flow に分けて `.up~(N)` で動かす。後で緩められる）。
- 変換の flow: 入出力の宣言に `at (sample * N)`・`at (sample / N)` を書ける（基準はインスタンスの本体の `sample`）。
  本体の中で、`sample * N` の入出力は 1 刻みに N 個の配列 `[T; N]` として見え（`x[N - 1]` が最新、ステレオの `[F32; 2] at (sample * 2)` は `[[F32; 2]; 2]`）、`sample / N` の入力は遅い値（速い式で使うには `at sample`）である。
  `sample / N` の出力は、出力の式のクロックが `sample / N` 以下（パラメータの種類とイベントの値を含む）でなければ E0815。配列で返していない・受けていない本体は型の誤り（E0401 の類）。本体の状態は本体の `sample` だけで、`sample_rate()` は本体の `sample` のレートである。
  フレームに集めるのは `x: F32 at (sample * 256)` の flow を `.down~(256)` で動かす形、ばらすのは `-> F32 at (sample * 256)` の flow を `.down~(256)` で動かす形で、組込みの変換（`frame~` など）は持たない。集めて配ると N サンプル遅れる（`delay~(x, N)` と同じ）。集めた値は呼び出し側の値なので、`reset_if~` は触れない。
- 位相のカウンタ: 時間を作るもの（一番外のインスタンスの本体と `when~`）がカウンタを持ち、`init` と生成する `reset` でだけ 0 になる（`reset_if~` は状態を初期化するが、カウンタには触れない）。`when~` の中の時間は動いた刻みで数える。誰が欄を持つかは実装の選択。
  `sample / N` の刻みはカウンタが N の倍数の刻みで、最初の刻みで動く。ホストの区切りに依らない（§13.4。ホストのブロックの長さを 2^N に揃える必要は無い）。`block` のクロックは状態を持てないので、ホストの区切りの長さは状態に漏れない。状態を持つ制御の信号は `.down~(N)` で書く。パラメータは `block` の入力のままで、ラッパーは変化の位置で呼び出しを分けてよい。
- 境界（一番外の flow の入出力）: 入出力のクロックは `init`・`block`・`sample`・イベントだけで、`sample / N`・`sample * N` は E0810 である（プラグインのホストは全てのポートに一つのフレームの数を渡し、§14.2 も一つの `frames` を使う）。
  誤りの位置は、その flow の `process`・`process_inplace`・`render` を使う所と `[export]` の項目で、`init`・`reset`・`State` は使える（変換の flow を `.down~(N)` で中に置くため）。E0810 の note で、中の部品を `.down~(N)`・`.up~(N)` で包み、一番外を `sample` にする書き方を示す。
  後で `sample * N` を開いても、今のプログラムは壊れない。
- std の変換の flow: std は、2 倍のオーバーサンプリングの `fir_up2`・`fir_down2`（`std.dsp`。線形位相のハーフバンドの FIR、型は `F32` だけ）を置く。4 倍以上は入れ子で書く。
  名前は、方式の名前、`up`・`down`、比の順で、番号を付けるときは方式の名前の後ろ（`fir2_up2`）。IIR の版（`iir_up2`・`iir_down2`）は要ると分かったときに足す（std は prelude の外なので、足しても利用者のコードは壊れない、§15.1）。
  係数は std の本体に 10 進のリテラルで書き（§2.4 の丸めで値はビットまで一つに決まり、生成する C は 16 進の浮動小数で出す）、和は書いた順に取る（§13.4 のビット一致は本体から出る）。
- 集めて配る時点: 同じ位置では、入力のイベントの刻み、遅い刻み、`sample` の刻みの順に並ぶ（段の順 `block < sample / N` から）。位置 c の遅い刻みが集めるのは c − N 〜 c − 1 の N サンプルで（`x[N - 1]` が c − 1）、配る出力は位置 c 〜 c + N − 1 の `sample` の刻みが順に読む。
  同じ位置で `sample` の段が出したイベントは、遅い周期の刻みには次の遅い刻みで見える（部品のイベントの段は、その位置で処理する）。
  位相 0 の遅い刻み（`init` と生成する `reset` の後の最初の刻み）の配列は、前のサンプルの無い所を `T.default()` で埋める（`delay~` の初めの値と同じで、出力は入力のちょうど N サンプル遅れになる）。集める入力の型が `Default` を満たさなければ E0816。配った値は呼び出し側の `sample` の値で、集めた値と同じく `reset_if~` は触れない。
- std の制御のレートの変換の flow: `std.dsp` に、下げる `cut_down16`・`cut_down32`・`cut_down64`（塊の最後の値。間の値は捨て、折り返しを止めない）と `avg_down16`・`avg_down32`・`avg_down64`（塊の平均 `sum(x) * (1.0 / N)`。和は左から）、
  上げる `lin_up16`・`lin_up32`・`lin_up64`（前の遅い値 a から今の値 b へ N サンプルの直線。`y[j] = (1 − w) * a + w * b`、`w = (j + 1) / N`。§11.4 の `vdelay` と同じ 2 乗算の形で、最後は b に一致し、`b − a` が溢れても有限）を置く。型は `F32` だけ。
  std の flow は遅い側を `at (sample / N)` で宣言し、中で公開しない変換の flow を `.down~(N)` で動かすので、呼び出しに修飾子は要らない（`lin_up32~(ctl~(avg_down32~(x)).down~(32))`）。std に無い比は入れ子で書く。
  `lin_up` の最初の刻みは既定値 0 から上がる（`init` と `reset`・`reset_if~` の後、N サンプルで今の値に届く）。今の値から始める版が要れば、総称の flow が入るまでは名前で分けて足す。
  線形位相の FIR は制御の信号に使わない（ステップの前から動き、遅れが大きい）。トリガ（1 サンプルの脈）はイベントで書き、周期の変換に乗せない（ピークの方式は置かない）。比を持たない平滑（一次の平滑など）は未決定（§19.1）。
- 弱いところ: 半分のレートの音声を `at sample` で速い式に読むと保持になり、像は検査で止まらない。外で `sample_rate()` から作った係数を別のレートのインスタンスへ渡す誤りも、検査を通る。

### 11.10 インスタンスの修飾子（停止・再開・初期化）

インスタンスの呼び出しに修飾子を連鎖で付ける（`seq~(tick).when~(running).reset_if~(start)`）。修飾子の名前には `~` を付ける。
`~` は状態を作るか進める印で（§2.6）、印の無い `.when(` は出力の値のメソッドと同じ見た目になり、インスタンスが止まる意味と違うからである。

- `x.when~(c)`: x は、連鎖のレート R（呼び出しの位置のクロックに連鎖の `.down~`・`.up~` を当てたもの、§11.9）の刻みのうち、`c` が真の刻みだけで動く。x の本体の `sample` はこのクロックを指し（`prev~` と遅延の長さは動いた刻みで数え、`sample_rate()` は外と同じ、§11.3）、`block` はホストの区切り、`init` は一度だけである。
  止めるのは x のサンプルレートに結び付く処理（`sample` の刻みと、そこから作る周期の刻み）で、イベントの刻みの処理は止めない。x の中の `at event` の入力に来たイベントは止まっている間も処理し、入力のイベントごとの出力も出る（止めたいときは、送る側をイベントの出力を持つ flow で絞る）。
  呼び出し側は x の出力を、その出力のクロック（R。変換の flow なら出力の宣言のクロック）の刻みごとに読み、止まっている間は最後の出力を保つ（一度も動いていなければ `T.default()`。`T` が `Default` を満たさなければ E0816）。
  `c` は `Bool` で、R の値、パラメータの種類、イベントの値（R の刻みで、その位置までの最後の値として読む水準）、R より遅い周期のクロックの値（保持で読む。`at` なしで遅い値を読めるのは `when~` だけ）を書ける。
  R より速い条件（下げる変換は利用者の flow で書く、`when~(dws32~(c))`）と、R 以外のクロックへの `at` は E0815。`when~(is_note_on(m))` は、最後のイベントがノートオンの間は真の水準である。
  R がイベントのクロックの受け手（第 1 引数がイベントの値の組込みの遅延）への `when~` は何も止めないので、書き手の誤解を示す印として E0020 の類にする（候補は `.when~(…)` を外す形で、note で `let cur = if is_on(m) { note_of(m) } else { prev~(^cur) }` のような選ぶ書き方を示す）。
  x の引数のクロックは x の入力の宣言（R を基準）に合わせる。x の引数と `block` の段は呼び出し側のもので、止まっている間も評価する（一度も動いていないインスタンスの `block` の式も評価され、panic しうる）。
- 条件で動くインスタンス（`when~`）では、周期が無いので `sample_rate()` は外と同じで、遅延は動いた刻みで数える。`when~` で止まる部品の `at (sample / N)` の入力は、呼び出し側の値を、部品の中の刻みの時点で読む（中の格子は動いた刻みで数えるため）。
- `x.reset_if~(r)`: `r` が真の刻みで、その刻みに続く x の段の前に x の状態を初期値に戻す。範囲は生成する `reset`（§11.6）と同じ部分木（入れ子のインスタンス、遅延の値と書き込み位置、`par` の複製、保持した出力）で、`init` のクロックの値は保ち、poisoned と位相のカウンタには触らない。
  条件は水準で読む（条件の刻みのうち、真の刻みは全て初期化する）。条件の刻みは、パラメータの種類なら呼び出しの位置のクロックの刻み、刻みのクロックの値ならそのクロックの刻み（`sample / N` の条件はその刻み、イベントの条件はそのイベントの刻み）である。
  イベントの条件は、外の `when~` が止めている間もその刻みで初期化する（イベントの刻みの処理は止めない）。条件の中で、イベントの値と周期のクロックの値が混ざると E0815（`is_start(tr) && armed`、`armed` は `sample`。§11.11）。真が続く信号（ゲート、ボタンのパラメータ）では、真の間は初期状態に留まる。
  立ち上がりで初期化するには、`let pb = prev~(start)` と取ってから `reset_if~(start && !pb)` と書く（`&&` の右辺に状態を持つものは書けない、§11.5。`block` の値は `prev~(start at sample)`）。
- 各修飾子は左の全体を包む（合成）。
  順も重ねがけも自由で、順が違えば意味が違う。`x.when~(c).reset_if~(r)` は止まっている刻みにも初期化し（保持した出力も `T.default()` に戻る）、`x.reset_if~(r).when~(c)` は動く刻みにだけ初期化する（パラメータの種類と周期のクロックの条件。イベントの条件ではどちらも止まっている間に初期化し、違いは保持した出力を戻すかだけ）。`x.when~(a).when~(b)` は `a && b` の刻みで動く。
  `when~`・`reset_if~` はレートを変えないので、`x.when~(c).down~(4)` と `x.down~(4).when~(c)` は同じ意味である。止めた刻みの 4 回に 1 回で動かすのは、名前の flow で包む（`slow~(r).when~(c)`）。
- 受け手は flow の呼び出し（組込みの遅延を含む）か修飾子の連鎖である。`let` で受けた名前（`let s = saw~(f0)` の後の `s.when~(c)`）、値、`par`、`if~` / `match~` は E0812。
  インスタンスを指す名前（ハンドル）と、止める命令は持たない（flow の本体は命令を持たないデータフローで、インスタンスは呼び出しの位置で作られるため）。
  修飾子を付けた呼び出しも状態を持つもので、`if` / `match` の枝は E0811、`&&` / `||` の右辺は E0806、flow の外は E0821 である。
- 修飾子の名前は別の名前空間にあり、`.名前~(` の頭がインスタンスの式のときだけ引く（頭がモジュールか flow の名前空間なら、今の flow の呼び出し）。組込みは `when`・`reset_if`・`down`・`up` の閉じた一覧で、語の予約（§2.2）は残す。
- 誤りの形: `~` の無い `saw~(f0).when(c)` は E0811（修正候補は `~` を足す形）。頭がインスタンスの式で名前が一覧に無いときと、受け手が値のときは E0812 で、`~` を除く候補は出さず、note で受け手と一覧を示す。後置の節（`saw~(f0) when c`）は構文の段の誤りで、note で連鎖の形を示す。
- 引数の位置に書いたインスタンスの呼び出し `f~(…)` は、呼び先によらず出力の値である（§11.5）。関数の形（`when~(saw~(f0), c)`）は持たない。
- MIDI のトランスポートは `seq~(tick).when~(runs(tr)).reset_if~(is_start(tr))` と書ける（`runs` は Start と Continue の後に真、Stop の後に偽を返す利用者の関数で、`sample` の刻みで最後の値として読む）。
  Start の位置では、イベントの刻みで `seq` を初期化し、その位置の `sample` の刻みで初期状態から一歩動く。
  取られない枝の状態を止める分岐（クロック付きの `if`）もこれで書ける（`let y = lp~(x).when~(c)` と取ってから `if c { y } else { 0.0 }`。枝に直接書く形は E0811 で、全ての枝を進めるなら `if~` / `match~` で書く、§11.5）。
- 他言語: Lustre は `when` で止めたノードの値を `current` で最後の値に保ち、faust-rs の `ondemand` も最後の値を保つ。Pure Data の `switch~` は、止めたサブパッチの信号の出口に 0 を書く。

### 11.11 イベント

イベントは、ノートの発音、モードの切り替えなどを表す。flow の入力に、イベントのクロックの値を渡す（`notes: midi.Message at event`。クロックの名前空間にあるので、利用者の名前とぶつからない）。
値は利用者の型を含む Copy の型で（型に足す制限は無い）、MIDI と組込みのイベント（トランスポートの Start / Stop / Continue など）は std の型にする（組込みかどうかは型で分かれる。C の ABI での表し方、たとえば MIDI 1.0 を U32 に詰める形は、std の型ごとに境界の形として決める。§14.2）。
イベントはブロックの中の位置を持ち、位置はホストが決める（リアルタイムの再生では届いたイベントを次のブロックの位置 0 に、CLAP などではホストがくれた位置に置く。どちらでも flow の意味は同じ）。

- クロック: イベントの入力 `e` ごとにクロックがあり、`e` のイベントごとにその位置で一回刻む（同じサンプルの中で複数回刻みうる）。入力のイベントの刻みは、その位置の `sample` の刻みより前に並ぶ。`at event` は入出力の宣言にだけ書く（式の `e at event` は E0815 の範囲）。
  順序では、イベントのクロックは全ての周期の刻みのクロックの下で、パラメータの種類の上にある。別の入力のイベントのクロックどうしは比べられない（`a.x + b.y` は E0815）。周期の刻みのクロックの被演算子の無いイベントの値の式は、そのイベントのクロックの式で、その刻みごとに評価する（イベントの段）。
- 同じ位置の順: 同じ位置のイベントはキューに溜め、イベントごとに一回刻んで順に処理する。一つの入力の中はホストの列の順である。入力をまたいだ順は境界が渡す順で、境界はホストの列に順があればそれを保ち（一つの MIDI の流れの Clock と Start）、無ければ外の flow の入力の宣言の順で並べる。渡し方は §11.6・§14.2。
  サンプルのクロックの式からは、その位置のイベントを全て処理した後の状態が見える。イベントの段の panic も、状態を poisoned にする。
- 読み方: イベントの値は `block` と同じく暗黙に読め、使う所の周期の刻みのクロックの刻みで、その位置までの最後の値（その位置のイベントを全て処理した後の値）になる。最初のイベントの前は `T.default()`（`T` が `Default` を満たさなければ E0816）。
  `v at sample`・`v at (sample / N)` と書いても同じ意味で、変換の場所を留める（値の欄は §11.3 の巻き上げの隠れた欄で、生成する `reset` で戻る。`at` が状態を作らないこと（§11.3）は変わらない）。
  ただし四つの所（組込みの遅延の第 1 引数、帰還の輪、`reset_if~` の条件、イベントの出力の式）では、`at` の下に無いイベントの値が周期の刻みのクロックの値と混ざると E0815（`prev~(m.note + bend)` の候補は `prev~(m.note) + bend` と `prev~(m.note at sample + bend)`）。
  式のクロックが状態の刻み・初期化の刻み・出す刻みを決める所で、書き換えで刻みが黙って変わらないようにするためである。値は `let`・`rt fn` の結果・`if` / `match`・struct・配列・タプルのリテラルを通して追い（フィールドを分けて追わない）、flow の出力と `at` を書いた値で止める。
  イベントの段の式では、周期の刻みのクロックの値（入力を含む）は読めず E0815 で、パラメータの種類と `sample_tick()` は読める。一方の入力の状態で他方の入力のイベントを選ぶ処理は、和の型の一つの入力で受けて書く。
- 引数: イベントの入力への引数はイベントの値で、インスタンスのその入力のクロックは引数のクロックに結び付く（同じインスタンスの別の入力は別のクロックでよく、同じクロックを二つの入力に渡してもよい）。
  イベントの値を `sample`・`sample / N` の入力へ渡すと最後の値で読み、`block`・`init`・`sample * N` の入力へは E0815（`block` の入力への候補は、入力の宣言を `at sample` にする形）。
- イベントごとの処理: `at event` の入力を宣言した flow の本体に、式と組込みの遅延で書く（`let v = assign(m, prev~(^v))` は m の刻みの式で、`prev~` は一つ前のイベントの v。`v at sample` がその位置までの最後の値）。利用者の flow をイベントの刻みで動かす修飾子は持たない。
  条件の書き方は§11.10（`when~` はイベントの値を最後の値の水準で読み、`reset_if~` はイベントの刻みで初期化する）。`.down~`・`.up~` の部品の中の `at event` の入力も、全ての位置のイベントで動く（`.up~` の中では、その位置の最初の刻みの前）。
- flow のイベントの出力 `-> E at event`: 本体の出力の式は `Option[E]` で、その式のクロックの刻みで、`Some(v)` のときに一つのイベント `v` を出す（`sample` の式なら刻みごと、入力 `m` のイベントの値なら `m` のイベントごと、パラメータの種類だけなら本体の `sample` の刻み）。`None` は出さない。
  出す位置は出した刻みの位置で、出したイベントの刻みは出した刻みの直後に並ぶ（受け手は名前の順で作り手より下にあり、その位置の受け手の段の前に届く）。呼び出しの出力のイベントのクロックは、呼び出しごとに別のクロックである。struct の出力にイベントを含めない（E0810）。
  `.up~`・`.down~` の部品の中から出るイベントの位置は、内側の刻みが属する呼び出し側の位置で、同じ位置には内側の刻みの順に並ぶ（細かい時刻が要るときは値に入れる）。`when~` で止まっている間は、周期のクロックの式の出力は出さず、入力のイベントごとの出力は出る。
- std: イベントと信号の変換（イベントのあった位置で真の脈の flow、`genv~`、`detect_zero~` など）は std の flow で書き、flow の組込み名にしない（§11.4）。イベントの型は prelude に入れず、std のモジュールに置く（後から prelude に足すと、prelude の名前は隠せないので利用者の同名の型が壊れる）。
- 境界の型: export（`[export]` の項目と C の API）の境界のイベントの入出力に出せる型は、§11.7 の `@param` と同じスカラ（`F32 F64 I8 I16 I32 U8 U16 U32 Bool`。JavaScript で 64 ビットの整数を境界に出さないため、§13.5）、`()`、std のイベントの型だけで、それ以外は E0810 である。
  flow の中と、Onsa のコードから呼ぶ生成する API（`process`・`render`）では、利用者の型も含めて自由である（外の境界ではないので、ラッパーと ABI に由来する制限は要らない）。
  `std.midi` の `midi.Message` は、MIDI 1.0 の短いメッセージを `U32` に詰めた中身を見せない型である（bit 16〜23 がステータス、8〜15 がデータ 1、0〜7 がデータ 2、24〜31 は 0。UMP の MIDI 1.0 の語の下位 24 ビット、Cmajor の `std::midi::Message` と同じ並び）。C では `uint32_t`。
  判定と取り出しと作る関数を std に置く。SysEx は持たず、MIDI 2.0 は後で別の型として足す。
  `std.transport` の `transport.Event` は、Start / Stop / Continue の中身を見せない型で、C では種類の番号の `uint32_t`。作る側は関連定数 `transport.Event.START`・`STOP`・`CONTINUE`（`continue` は予約語なので関数にしない）、判定は `transport.is_start` など。
  テンポと位置は `block` の入力で渡す（export では `@host`、§11.7）。
  `Default` は、`midi.Message` が 0 の語、`transport.Event` が Stop。値の正しさ（未知の種類、上位のビット）は検査せず、std の判定の関数が偽を返す。
  イベントのあった位置で真の脈の flow は `std.dsp` に置き、名前は未決定（§19.1）。
