## 2. 字句

### 2.1 コメント

```onsa
//! モジュールのドキュメント（ファイルの先頭にだけ書ける）

// 行コメント
/// ドキュメントコメント（直後の宣言に付く）
const LIMIT: U32 = 16
```

ブロックコメントは無い。閉じたブロックコメント（`/* … */`。行をまたいでもよい）は E0020（§18.1）で、修正候補は言葉を `//` の行コメントに残し、コメントの外のトークンの並びと行の切れ目を変えない（言葉を置く場所は決めない）。
ただし、行をまたぐコメントの `*/` の後ろに同じ行でコードが続くとき（`let a = 1 /* x` の次の行が ` */ + 2`）は、前後のコードの間の改行がコメントの中にしか無く、行の切れ目を変えない候補が別の読みを作りうるので、E0002 で、修正候補は出さず、`//` で書くことを note で示す。
閉じないものと入れ子（`/* a /* b */ c */`）は E0002 で、修正候補は出さず、`//` で書くことを note で示す。

- `///` は直後の宣言に付く（間に空行、`//`、属性があってもよい）。
  付けられるのは、`use` と `test` 以外の項目（`fn`、`flow`、`struct`、`enum`、`trait`、`effect`、`handler`、`extern`、`target` の宣言（§15.2）、`const`、`type`、`impl`）、`impl` / `trait` / `effect` / `handler` / `extern` のメンバ（関連定数、効果の操作、extern の関数と不透明型を含む。インライン形式の handler のメンバも同じ）、struct のフィールド、enum の列挙子、flow の入力で、この一覧は閉じている（§18.1 の単位の並びと同じ）。
  fn の引数には付けない（関数の doc コメントで説明する）。
- `//!` はモジュール（ファイル）のドキュメントで、ファイルの先頭（最初の項目より前）にだけ書ける。
- `/` が 4 つ以上続く行（`////`、区切り線の `//////`）は普通のコメントで、doc コメントではない（Rust と同じ）。
- 付ける宣言の無い `///`（文の前、fn の引数の前、`use` の前、ファイルの末尾など）は E0004 で、修正候補は `//`。ファイルの先頭以外の `//!` も E0004 で、修正候補は `///`（Doxygen では `//!` が `///` と同じく次の項目の説明なので、その読み方で書いたものを黙って通さない）。
  ただし、`///` にしても付く宣言が無い位置では修正候補を出さない（§18.1）。続いた付ける宣言の無い `///` の行は一つの誤りで、修正候補は全ての行を `//` にする一つの候補である（続いた `;` と同じ、§18.1）。
- 属性と宣言の間（属性の間と、最後の属性の後ろ）の `///` は E0004 で、修正候補は、その doc の行を最初の属性の前（既にある `///` の並びの後ろ）へ移す一つである（続いた行は一つの誤り）。
  属性が行の頭に無いとき（`flow g(@param(…)` 改行 `/// x` 改行 `x: F32 at block,`）は、改行を足して属性の直前に置く。間の `//` と空行は動かさない。
  doc の付く先は doc の意味そのもので、属性の後ろの doc は言語で扱いが割れる（Rust と clang は宣言に付け、Swift は捨てる）ので、置き場所を属性の前の一つにする。
- doc コメントは `onsa interface`、`onsa primer`、LSP のホバーに出る（§18.2）。

### 2.2 キーワード（全て）

```
fn rt flow par struct enum trait impl effect blocking handler handle with uses
let var if else match for in while break continue return
pub priv use extern unsafe target test assert
const type as at inout move self Self true false
clock when reset_if ser static
```

`clock`、`when`、`reset_if`、`ser`、`static` は予約している。宣言の名前には使えない。`when`・`reset_if` はインスタンスの修飾子の名前で、`.when~(c)` の形でだけ使う（修飾子の名前は別の名前空間にある、§11.10）。
後置の節（`saw~(f0) when c`）は構文の段の誤りで、note で連鎖の形を示す。`clock` は導くクロックの宣言に使わなくなった（§11.9）が、語の予約は残す。`ser` は flow の直列の複製（§19.1）のために、`static` は静的なものだけを指す印（§19.1）のために予約している。`clock`・`ser`・`static` は構文として受け付けない（現れた位置で E0200、機能名を添える。項目の見出しの前の `static`（`static fn`）は、§18.1 の他の言語の修飾の語の読み方のまま E0002）。
パスの `.` の直後と `use` の経路の頭は、他のキーワードと同じく名前として読む（`s.clock` は後の段の E0413、`clock.onsa` のモジュールは `kp.clock.tick()` で使える）。ただし `use` で取り込む名前（並びの要素と、並びの無い経路の最後の要素）は、現れた位置で E0200 である（`use kp.clock`、§15.1）。後から予約すると、その語を名前に使っていたプログラムが壊れるので、先に予約した。

`prev` `delay` `vdelay`（組込みの遅延の flow）と `sample_rate`・`sample_tick` は、flow の中で予約された組込み名（§11.4）。flow の本体から見える束縛（モジュールの項目、`use` で取り込む名前、flow の入力、本体の `let` とパターン）に使えない（E0304、§5.1）。
fn の本体の束縛と引数、フィールドとメソッド、モジュールのファイルの名前には使える。キーワードは、パスの `.` の直後と `use` の経路の頭では、モジュール名として使える（`std.test`、`std.dsp.test`、std の中の `use test.{Gen}`）。`use` で取り込む名前には使えない（`use std.test` は E0002、§15.1）。
`.` の直後のキーワードは名前として読み、フィールドとメソッドの名前にはキーワードを宣言できないので、`xs.at(0)` のような形は後の段で解決できない誤りになる。`lib` はキーワードではなく、`extern` の見出し（`extern "C" lib "fastconv" {`、§14.1）の中でだけ意味を持つ文脈の語で、他の位置では普通の名前として使える。

`_` は、パターンと引数名では「値を使わない」（Rust と同じ）、式の位置では型付きホール（E0421、§18.1、Haskell と同じ）を表す。型の位置には書けない。

`Self` は、`impl`（固有の `impl` と `impl Tr for Ty`）の本体の中で対象の型を指す名前で、対象の型を右辺にした型別名と同じに扱う（§4.4。型、関連関数と関連定数、struct リテラル、パターン、列挙子、補間の頭に書ける）。trait の宣言の中では、実装する型を指す。
総称の `impl` では、型引数を `impl` の型パラメータに決めた型を指す（`impl[T] Pr[T]` の `Self` は `Pr[T]`）。束縛するのは `impl` の本体で（中の無名関数からも見える）、見出し（対象、型パラメータの境界）と `impl` の外の `Self` は E0302 である。
型引数を付けた `Self`（`Self[I32]`）は E0412、値の位置の `Self` だけ（`let s = Self`）は E0308 である。`onsa interface` は、別名と同じく展開した型を表示する。fmt は `Self` と型の名前を書き換えない。

### 2.3 命名規則（エラー E0320、lint ではない）

| 種類 | 規則 | 例 |
|---|---|---|
| 値・関数・flow・handler・モジュール・効果行変数 | `snake_case` | `wrap01`, `line_count`, `resonator`, `memory_fs`, `e` |
| 型・trait・効果・列挙子・型パラメータ | `UpperCamel` | `Buf`, `Ord`, `Fs`, `Some`, `T` |
| 定数 | `UPPER_SNAKE` | `MAX_VOICES` |

識別子は ASCII の英字・数字・`_` からなり、数字では始まらない。
三つの形は、英字で始まる芯と、任意の末尾の一つの `_` からなる。芯は、`snake_case` が `[a-z][a-z0-9_]*`、`UpperCamel` が `[A-Z][A-Za-z0-9]*`、`UPPER_SNAKE` が `[A-Z][A-Z0-9_]*` である。
頭の `_`（`_x`、`_MAX`）はどの形でも書けない。末尾の `_` は予約語を避ける綴り（`match_`、`Self_`）で、`@export` の項目の名前（§14.2）を除き、どの形にも書ける。
連続する二つの `_`（`__`）は書けない（E0320。修正候補は規則に揃えた名前で、`a__b` は `a_b`）。生成する C の名前で、経路の区切りと状態の名前の `.` を `__` に写すので（§11.6）、利用者の名前と重ならないようにするためである。頭の `_` を書けないのも同じ理由である（書けると `voice._f` と `voice_.f` がどちらも `voice___f` になる）。
それ以外の文字は E0001 で、文面で識別子に使える文字を示す（文字列とコメントには、§2.5 の書けない文字を除く任意の文字を書ける）。大文字と小文字で種別を決める（上の表）ので、大文字・小文字の無い文字では種別が決まらず、形の似た文字（キリル文字の `а` とラテン文字の `a`）の取り違えも防ぐ。

字面で種類を決める所（`[…]` の並びの型パラメータと効果行変数、パターンの束縛、`Name {` の struct、`with` の後の効果、`-` の後と `@` の右の定数）は、頭の `_` を飛ばした最初の字で読む。
宣言する名前（`[…]` の並びとパターンの束縛）は、読んだ種類の E0320 にする（`[_e]` は効果行変数で修正候補は `e`、`let _x = 1` は束縛で修正候補は `x`。読まない束縛なら §5.1 の E0309 を報告する）。使う名前（`_P {`、`-_MAX`）は読んだ種類として扱い、E0320 は宣言の位置に出る。
`UpperCamel` と `UPPER_SNAKE` の両方に合う名前（`A`、`OK`、`N`、`LIMIT`）は、どちらの形を求める所にも書け、字面で定数と読む所（`-LIMIT`、`k @ LIMIT`、FAUST の `x@N`）では定数と読む（§7）。

名前の種別が字面で決まる。モジュールの名前はファイル名（拡張子を除く）で、`snake_case` の規則に従う（`.` や `-` を含められない）。マニフェストの無い単一のファイル（§15.1）のモジュールの名前も同じである（テストの完全な名前のテキスト（§11.8）が、常にモジュールの経路と名前に分けられるためである）。
この規則は識別子であることを含み、`_` だけの名前、数字で始まる名前、ASCII でない文字を含む名前のファイルとディレクトリも E0320 である。キーワードの名前（`match.onsa`、`test/`）は規則に合い、§2.2 のとおり経路で書ける。
E0320 の修正候補は一つで、宣言と、パッケージの中の全ての使用箇所の名前を直す（複数の編集を持つ候補、§18.1）。
直す使用箇所はソースの中だけで、マニフェストが経路で名指す名前（`[[plugin]]` の `flow` が指す flow と、その経路の途中のモジュール、§15.3）の E0320 は候補を出さず、note で揃えた名前とマニフェストの位置を示す（モジュールの名前は下のとおり元から候補なし）。
規則に揃えた名前が予約語になるとき（`pub fn Match()` の `match`、§2.2）は、末尾に `_` を足した名前（`match_`）を候補にする（識別子の候補の規則で、候補を出さないファイル名とディレクトリの名前には当たらない）。
頭の `_` を除いた名前が予約語になるとき（`let _type` の `type`）も同じで（`type_`）、予約語を避けるには末尾に `_` を付けることを note で示す。
規則に揃えた名前が識別子にならないとき（`_0`）は、候補を出さない。既にある名前と重なるとき（その名前で宣言すると E0304 になる範囲と、同じ並びの型パラメータ）も候補を出さず（§18.1 の約束）、規則に揃えた名前を note で示す。読みやすい名前に直すのは、候補を当てる側の責任である。
ファイル名の違反の E0320 は、ファイル名を変える編集をテキストの編集（§18.1）で表せないので修正候補を出さず、ファイル名を `snake_case` にすることを note で示す。位置はファイルの先頭である。モジュールの経路の途中のディレクトリの名前も同じ規則に従う。
違反は E0320 で、一つのディレクトリに一つ、位置はそのディレクトリの下の `.onsa` ファイルのうち診断の並べ方（§18.1）で最初のものの先頭である（候補は出さず、note で示す）。ファイル名とディレクトリの名前の E0320 は宣言の単位に入らず、それぞれ報告する。

- `Fs.read(p)` は効果操作か型の関連関数、`fs.read(p)` はモジュール関数。
- flow の本体の中で、`saw~(f0)` は **状態を持つインスタンス**、`wrap01(x)` は **状態を持たない関数** の呼び出し。違いは名前ではなく呼び出しの形（後置の `~`、§2.6）で表す。

### 2.4 リテラル

- 配列: `[a, b, c]`、`[e; N]`（`e` を 1 回評価して N 個に複製する。`e` は Dup 型（でなければ E0416）、`N` は定数式、§4.5）。空の `[]` は長さ 0 の配列で、要素の型は期待型か後の文で決まる（関数の終わりまでに決まらなければ `[]` の位置に E0406、§4.7）。Affine の配列は `array.from_fn` で作る
- タプル: `(a, b)`（2 要素以上。`(e)` は式・パターン・型のどこでも常にグループ化で、要素 1 個の後の `,`（`(e,)`、`(I32,)`）は E0002）。タプルの添字は 10 進の数字だけで書き、`0` そのもの以外は 0 で始めない（`t.01` は E0020 で、修正候補は頭の 0 を外した `t.1`。添字を 8 進と読む言語は無いので、候補は一つ）。
  `U32` に収まらないタプルの添字（`t.99999999999`）は、値を持てないので構文の段（§18.1）で E0408
- 整数: `42`, `0xFF`, `0b1010`, `1_000_000`。10 進の整数は、`0` そのもの以外は 0 で始めない。`017` は C・Go・Java が 8 進の 15、Rust が 17 と読み、読みが分かれるので E0020 で、修正候補に `17` と `15` を並べる（`00` の候補は `0`）。
  8 進の接頭辞は無い（`0o17` は E0020、候補は `15`）。どの整数型にも収まらない（`U64` の最大値を超える）整数リテラルは、値を持てないので構文の段（§18.1）で E0408 である（型が決まった後の範囲の検査は §4.7）
- 浮動小数: `1.0`, `2.5e-3`, `1e-6`。小数点を書くときは両側に数字が必須（`1.`、`.5`、`1.e3` は E0020 で、修正候補は `1.0`、`0.5`、`1.0e3`）。
  整数の数字の後の `.` は、数字が続けば小数点、名前か `(` が続けばメンバの `.`（`1.abs()`、`1.(x)`。§6.1）、`e`・`E` と（符号を挟んでよい）数字が続けば上の浮動小数の書き方の誤り（`1.e3`、`1.e-3`。修正候補は `1.0e3`、`1.0e-3`）、それ以外（`1.`、`2.*x`、`1.[0]`）は `1.` の E0020 である。
  指数があれば小数点は無くてよい（`48e3` は浮動小数）。値は、10 進の値を型へ最近接偶数で一度だけ丸めた値である（`F32` のリテラルを `F64` を経て二重に丸めない）。型が決まった時点で、丸めた値が有限でないとき（`F32` の `1.0e40`）と、0 でない字面が 0 に丸まるとき（`F32` の `1.0e-50`）は E0408。
  非正規化数に丸まる字面（`F32` の `1.0e-40`）は値が残るので書ける
- 型の接尾辞は無い（`1u8`、`1.0f32` は E0020）。リテラルの型は、期待型と推論で決まる（下記）
- 数値リテラルの綴りの揺れ（接頭辞と指数の大文字・小文字、指数の `+`（`1e+3`）、16 進の数字の大文字・小文字、`_` の数と位置（`1__000`、`1_`、`0x_1F`）、浮動小数の整数部の余分な 0（`01.5`））は値に関わらず、どれも書ける。`_` は読みやすさのためだけで、値に影響しない。`onsa fmt` が一つの綴りに揃える（[`spec/tools.md`](tools.md) §3.2）
- 文字: `'a'`（Unicode スカラ値）
- 文字列: `"..."`（UTF-8）。補間に書けるのは名前の経路、つまり名前と、それに `.` で続くフィールド・タプルの添字・修飾だけで（`{n}`、`{p.x}`、`{self.gain}`、`{t.0}`、`{MAX_VOICES}`、`{cfg.N}`、`{F32.PI}`）、式に書いたときと同じ規則で解決する。
  呼び出し、添字の `[i]`、演算子、リテラル、書式の指定（`{x:.2}`）は書けない（E0001。式には `let` で名前を付けてから補間する、書式の指定は無い、と note で示す）。経路は空白を含まず、頭は名前か `self`・`Self` で、`.` の後のキーワードは名前として読む（§2.2）。
  他のキーワード、`_`、リテラル（`{true}`）、空白を含む形（`{ x }`）も E0001 で、予約語が頭なら E0200。呼び出し（と、それが起こす効果・値の変更・panic）を文字列のリテラルの中に隠さないためである。補間される値は `Show` を実装していなければならない（E0416）。`{{` と `}}` はエスケープ。
  バックスラッシュのエスケープは `\n \t \r \0 \\ \" \' \u{…}` の閉じた一覧（文字リテラルも同じ）。`\u{…}` の中は 16 進の数字 1〜6 桁（大文字・小文字は問わず、`_` は書けない）で、値は Unicode のスカラー値である。サロゲート、`10FFFF` を超える値、0 桁、7 桁以上、16 進でない文字、閉じない形は E0001。
  6 はスカラー値の最大 `10FFFF` の桁の数で、値の幅を超えて 0 を詰めない。補間を含む文字列は新しい `Str` を作るので `Alloc` を要する（§12）。補間を含まない `Str` の文字列リテラルは静的領域に置かれ、`Alloc` を要しない。期待の型が `FixedStr[N]` なら、リテラルはその型の Copy の値になる（§4.2）。文字列リテラルは行をまたげない（改行を含む値は `\n` で書く。閉じないまま行が終わると E0001）。
  行の終わりの読み方（§2.5）が文字列の値を変えないためである（`onsa fmt` が CR LF を LF に揃えても値は変わらない）。文字列と文字のリテラルに接頭辞と接尾辞は無い。
  名前の直後に空白を空けずにリテラルを書く形（`f"{x}"`、`r"\d"`、`b"x"`、`u8"x"`、`b'x'`）と、リテラルの直後に空白を空けずに名前を書く形（`"x"_s`）は、他の言語の接頭辞・接尾辞付きのリテラルとして構文の段の E0002 で、修正候補は無く、note で Onsa の文字列の書き方（UTF-8 の `"…"`、補間は `"{x}"`、バイト列は `"x".as_bytes()`）を示す。
  `,` の抜け（§2.5）としては扱わない。
  他の言語の文字列の区切りで始まる形（`$"…"`、`@"…"`、`$@"…"`、`@$"…"`、`r#"…"#`、`#"…"#`、`"""…"""`、`'''…'''`、`` `…` ``）も無く、字句の段の E0002 で、修正候補は無く、note で Onsa の文字列の書き方（一重の `"…"` を一行に書き、改行は `\n`。補間は `{名前}` で、`${x}` や `\(x)` ではない。`{`・`}` そのものは `{{`・`}}`。エスケープは上の閉じた一覧で、生の文字列は無い）を示す。
  範囲は開きの区切りから同じ行の閉じの区切りまで（同じ行に閉じが無ければ開きの区切りだけ）である。これらの形と、名前やリテラルに接する上の形は、中身を読まない（中身の読み（エスケープ、補間の穴、文字の数）の誤りや閉じていないことの E0001 は出さず、この E0002 を報告する。§2.5 の書けない文字は、コメントの中と同じく E0001 である）。
  一字でない文字のリテラル（`'abc'`）は E0001 で、note で文字列は `"…"` と示す。文字列と文字のリテラルの E0001 の範囲は誤りの部分（エスケープの並び、書けない文字の一字、補間の穴）で、閉じないリテラルは開きの区切りから行の終わりまで、一字でない文字のリテラルは全体である（同じ単位の誤りの選び方（§18.1）が範囲に依るので、範囲を約束する）。
- **浮動小数のリテラルに既定の型は無い。** リテラルの型は、期待型と関数本体の中の推論で決まる。整数のリテラルだけは、関数の終わりまで決まらなければ `I32` になる（Rust と同じ。`for i in 0 ..< 4` の `i` を、型の決まる位置で使わないときなど）。浮動小数のリテラルは決まらなければエラー（E0405）。`var acc = 0.0` は、`acc` の型が本体の中で決まらない限り書けない。

  浮動小数のリテラルが既定で `F64` になると、倍精度 FPU の無いマイコン（Cortex-M4F など）で気付かずにソフトウェア浮動小数を使うことになる。`F32` を既定にすると、Rust の読み手（`1.0` は `f64`）に対して検査を通るのに精度が違う偽の友人（§0.3 の 4）になる。それを避けるための規則である。整数にはどちらの事情も無い。

### 2.5 文の区切り

- 空白は U+0020 とタブ（U+0009）だけで、改行は LF（U+000A）である。CR LF も一つの改行として読み、`onsa fmt` が LF に揃える（[`spec/tools.md`](tools.md) §3.2）。
  単独の CR、タブと改行以外の制御文字（U+0000〜U+001F と U+007F〜U+009F）、U+2028 / U+2029、双方向の制御文字（U+202A〜U+202E と U+2066〜U+2069）は、コメントと文字列の中も含めて書けない（E0001）。
  改行か空白か、行の終わりか、表示の順かの読み方が言語やエディタで分かれる文字で（単独の CR を、Python・Node・Swift は改行、Ruby は空白として読む）、読み手に見えない形でコードをコメントに隠せるからである。コメントと文字列の外では、その他の Unicode の空白（NBSP など）と BOM も E0001 である（識別子に使える文字は §2.3）。
- 改行で文と項目が終わる（トップレベルとブロック `{ }` の中で同じ規則）。ただし行末が二項として読む位置の演算子、範囲の記号（`..<`、`..=`、§7）、`=`、`->`、属性（`@repr(c)` など。属性で項目や文は終わらない）の場合、または次の行が `.` か `uses` で始まる場合は継続する（`uses` は効果行の始まりで、文や項目の始まりにはならない）。
  判定はトークンで決まり、間にあるコメントだけの行と空行は読み飛ばす（継続の間の空行は `onsa fmt` が取り除く）。インデントは意味を持たない（構文エラーのあるファイルで回復点を推定するときだけ字下げを見る。§18.1）。継続した行の字下げは `onsa fmt` が揃える（[`spec/tools.md`](tools.md) §3.2）。
- 二項演算子と範囲の記号は行末に置き、次の行の頭には置かない。二項にしか使わない演算子（`+`、`*`、`==`、`&&` など）と範囲の記号で行を始めると E0020 で、修正候補は演算子を前の行の末尾へ移す形である。行頭の演算子で前の行に続ける流儀の言語もあるが、Onsa の行は行末で終わるので、続かずに新しい文として読まれる。
  つないだ形で前の行の終わりのブロックに似た式が被演算子になるときは、候補はその式を括弧で囲む（§3.1）。
  `match` の腕のパターンの選択の `|` も行末に置く（行頭の `|` は E0020 で、修正候補は前の行の末尾へ移す形。同じ腕の並びの中で置き場所をそろえる）。継続の `->` と `=` も行末に置き、行頭の `->`・`=` は括弧の中でも外でも E0020 で、修正候補は記号を前の行の末尾へ移す形である。
  `as` と `at` は置き場所の規則を持たず、括弧の中ではその前後の改行も空白として扱う（括弧の外では行が終わる）。式の中のキーワードとその被演算子の間（`if`・`match` と条件や対象、`else` の後の `if` の条件、`with` と handler、`move`・`inout` と被演算子）も同じである。
  前置にもなる `-` と `^` で始める行（`- b`）は、下の空白の規則で E0020 になる。
  括弧の中でも同じで（`two(a` 改行 `+ b, 1)` は E0020）、括弧の中の `-` と `^` で始まる行（`two(a` 改行 `-b, 1)`）は、前の要素との二項の読みと、`,` を書き忘れた次の要素の読みに割れるので、修正候補は前の行の末尾へ移す形と `,` の挿入の二つを並べる。
  `+` で始まり被演算子に接する行（`two(a` 改行 `+b, 1)`）も同じで、二つ目の候補は `,` の挿入と `+` の削除を一つにした形（`two(a, b, 1)`）である（Onsa に前置の `+` は無い、§3.1）。
- 丸括弧・角括弧・構造体リテラル・`match` の腕の並び、struct / enum の宣言の本体、`use a.{…}` と効果行 `uses {…}` の並びの中では、改行は空白として扱う（要素は `,` で区切る）。
  ただし記号の置き場所の規則（二項演算子と範囲の記号とパターンの選択の `|`、継続の `->` と `=` は行末、メンバの `.` は次の行の頭、後置の `(` と `[` と空白を空けない位置の印と記号は相手と同じ行、`else`・`with` と `else` の後の `if` は前の `}` や `else` と、`{` はそれが属する形と同じ行、std の `target fn` の `else` は見出しの最後のトークンと同じ行）は、括弧の中でも外と同じで、修正候補もその読みを括弧の中で書いた形である。
- 並びを開く `(` と `[`（呼び出しと handler の引数（`with h(x)`、§8.3）、添字、型引数、宣言と無名関数の引数と型パラメータ、関数型の引数（`fn(I32) -> I32`）、列挙子の宣言の要素（`V(I32)`）、パターンの `Some(x)`、属性）は、前のトークン（名前、キーワード、印）の直後に空白も改行も空けずに書く（`f(x)`、`xs[0]`、`Option[I32]`、`fn f(x: I32)`、`fn(a: I32) -> I32 { a }`）。
  空白を空けると E0020 で、修正候補は空白を除いた形である（`xs [0]` には、`xs` に配列を渡す呼び出し `xs([0])` も並べる。Haskell、Ruby、CoffeeScript はこう読む）。
  前が呼び先になれる名前の経路（§6.1。`p.x` を含み、タプルの添字で終わる `t.0` は含まない）でないとき（`)`・`]`・`}`・リテラル・`?` の後）は、並びの中では改行の後と同じく `,` の無い二つの要素の E0002 で、修正候補は `,` の挿入と、読めれば空白を除く形である（`[(1, 2) (3, 4)]` は `,` の挿入、`[h(x) [0]]` は `h(x), [0]` と `h(x)[0]`）。
  空白を許すと、引数の括弧を省ける言語（Ruby など）の読み方で、`f` と `(x)` を別々に並べたつもりのコードを通すことになるからである。`~(`、`!(`（§2.6）と同じ形になる。
  印と `(` の間にも空白も改行も置かない（`saw~ (f0)`、`v.push! (x)` は E0020 で、修正候補は空白を除く形。`saw ~ (f0)` は一つの形で、候補は両方の空白を除く一つ。印と `(` の間の改行は括弧の中でも外でも E0020 で、候補は改行を除く形）。
  キーワードの `fn` の後の `(` の前の改行は、括弧の中では空白と同じ E0020（候補は改行を除く形）で、括弧の外では `fn` で行が終わる。
  括弧の中でも、改行の後の `(` と `[` と、名前に付く印の `!(`・`~(` は前のトークンに付かず、`,` の無い二つの要素として E0002 になる（修正候補は `,` の挿入と、改行を除く形の二つ。印は、前のトークンが名前でなければ改行を除く形を出さず、`~(` には `,` の挿入を出さない）。
  二つの候補のどちらが読めるかはトークンの走査で決め、読めない方は出さない（次の要素を試しに読まない）。腕の並びでは、次の深さ 0 の `,`・`}` より前に深さ 0 の `=>` があれば `,` の挿入だけ、無ければ改行を除く形だけを出す。型だけの並び（列挙子の要素、タプル型、関数型の引数）の `[` は、中に `;` があるときだけ要素を始める。
  どの候補でも直らない形は、誤りが二つある入力として扱う。`.` は要素の始まりにならないので、改行を越えて前に付く（メソッドの連鎖）。
  並びの中で、要素の後に `,` を置かずに、次のトークンがその並びの要素を始めるとき（改行の後でも、同じ行の空白の後でも、何も挟まなくても。`two(a` 改行 `b)`、`two(a b)`、`[0.1 0.2 0.3]`、`0 => { 1 }` 改行 `_ => 0,`、struct の宣言の `x: I32` 改行 `y: I32`）も、`,` の無い二つの要素として E0002 で、修正候補は `,` の挿入である（前の要素の最後のトークンの直後、その行のコメントの前）。
  要素の最初の字と間の空白の種類によらず、候補の有無を変えない。同じ行の空白の後の `(`・`[`・`!(`・`~(` は上の空白の規則（E0020）である。`a b` を関数適用 `a(b)` と読む言語（Haskell、Ruby の括弧を省いた呼び出し）もあるが、引数の範囲が言語で割れるので、その形は候補にしない。
  括弧の中の行頭の `-` と `|` でも、前の行の末尾へ移すと次の `=>` の前で終わって二項の読みが成り立たないとき（前の腕の `,` を省いた `0 => { 1 }` 改行 `-1 => 2,`、`0 => 2` 改行 `| 1 => 1,`）は、`,` の抜けとして同じ E0002 で、修正候補は `,` の挿入だけである（記号が被演算子に接していない `- 1` は、`,` を入れても前置の記号の後の空白の誤りが残るので、候補を作らない）。
  行頭の `+` の形（`0 => { 1 }` 改行 `+1 => 2,`、`+ 1 => 2,`）も同じ E0002 で、修正候補は `,` の挿入と、`+` と後ろの空白の削除を一つにした形である（`+` と後ろの空白は除く一つの形なので、`- 1` と違って候補を作れる、§3.1）。
  後ろに `=>` が続く同じ行の非対称な空白の形（`0 => { 1 } -1 => 2,`、`0 => { 1 } +1 => 2,`）も同じ E0002 で、修正候補も同じである（両側に空白のある `{ 1 } - 1 =>` は、次の深さ 0 の `,`・`}` より前に深さ 0 の `=>` があるので腕の区切りの抜けとして読み、`=>` の位置の E0002 で候補は無い。ブロック式を二項の被演算子にした E0013（§3.1）は出さない）。
  隣り合う文字列リテラル（`f("a"` 改行 `"b")`、同じ行の `f("a" "b")`）は、一つのリテラルにつなぐ言語（Python、C）の読みと `,` の抜けの読みに割れるので、E0002 で、修正候補は `,` の挿入と、一つのリテラルにまとめる形の二つである。
- 列挙子の宣言の要素、宣言の型パラメータ、handler の宣言の引数と、それを使う側の `with h(…)` とパターンの `E.A(…)`・`Some(…)` は、要素が無ければ括弧ごと書かない。
  空の括弧（`enum E { A(), B }`、`fn f[]()`、`struct S[]`、`impl[] S`、`handler h(): Ask`、`with h()`、パターンの `E.A()`・`None()`）は E0002 で、修正候補は開き括弧から閉じ括弧までを除く形である（`A`、`fn f()`、`handler h: Ask`、`with h`、`E.A`）。
  主の範囲は開き括弧から閉じ括弧まで（候補が除く範囲と同じ）で、主の位置は開き括弧である。
  括弧の中にコメントがあれば候補を作らず、note で括弧を書かない規則を示す。要素を持つ列挙子のパターンと引数を持つ handler の空の括弧（パターンの `Some()`、`with arena()`）は、候補を当てた後に数の誤り（E0412）が残る。
  単位形の列挙子と引数の無い handler は括弧を付けずに使う。空の括弧を受けると、`A()` を要素 0 個の別の列挙子（関数値）と読む言語（Rust）や、`with h()` を `h` を呼んだ結果と読む言語（Python）の読み方を与えるからである（P2）。
  空の括弧が意味を持つ形（呼び出し `f()`・`k~()`・`x.m()`・`g.()`、関数・flow・無名関数・効果の操作の引数 `fn f()`、関数型の引数 `fn() -> I32`、unit の型と値 `()`）は括弧を書く。式の中の空の型引数 `f::[]` と型の位置の `Buf[]` も E0002 である（§4.5）。属性の空の括弧（`@fp()`）は各属性の値の規則による（§6.5）。
- メンバの `.`（フィールド、メソッド、修飾、タプルの添字、関数値の呼び出しの `.(`、§6.1）の前後には行の中で、後置の `?` の前には改行も含めて、空白を空けない（`a.b`、`s.f.(x)`、`x?`）。空白を空けると E0020 で、修正候補は空白を除いた形である。
  `a . b` は二項演算子に、`x ?` は C 系の条件演算子の始まりに見え、読み手に別の読み方を与えるからである（P2）。次の行の頭に置く `.`（メソッドの連鎖の継続、上記）は改行の後なので、この規則に当たらない。メンバの `.` の後には、括弧の中でも改行を置かない（継続は次の行の頭に `.` を置いて書く）。
  行末の `.` は E0020 で、修正候補は `.` を次の行の頭（名前、タプルの添字、`.(` の `(` の直前）へ移す形である。間のコメントと空行はそのまま残る。改行の後が名前・整数・`(` でなければ候補を作れず E0002。行末の `.` を受けると、名前を書き落とした `let a = s.` が次の行の文と黙ってつながるからである。
- 名前に付く印と前置の記号も、空白を空けずに書く: 名前と `~` / `!`（`saw~(f0)`、`buf.push!(x)`）、名前と式の中の型引数の `::[`（`parse::[U32]("1")`。名前と `::` の間と、`::` と `[` の間、§4.5）、`^` と名前（`^y`）、前置の `-` / `!` と被演算子（`-x`、`!done`。パターンの負のリテラル `-1` も同じ、§7）。
  空白を空けると E0020 で、修正候補は空白を除いた形である。前置の `-` / `!` / `^` と被演算子の間と、後置の `?` の前には、括弧の中でも外でも改行も置かない（`two(-` 改行 `a, 1)`、`two(o` 改行 `?, 1)` は E0020 で、修正候補は記号を相手の行へ移す形）。
  名前と印 `~` / `!` の間の改行は、後置の `(` と同じく前のトークンに付かない（上記、E0002）。`saw ~(f0)` は FAUST の二項の `~`（帰還）に、`^ y` は二項の `^`（排他的論理和）に見え、読み手に別の読み方を与えるからである（P2）。前置か二項かは、直前のトークンが同じ式の被演算子かどうかで決まる（`a - b` は二項）。
  二項として読む `-` と `^` の前だけに空白を空け、後ろを被演算子に接して書く形（`a -b`、`[1 -1]`、`two(a -b, 1)`、`[a ^b]`）は、前置の付いた次の要素とも読める（Swift、MATLAB、Julia は `[1 -1]` を要素二つと読む）ので、括弧の中でも外でも E0020 で、修正候補は両側に空白を置いた形と、式を要素とする並び（引数、配列、タプル）の中では `,` の挿入の二つである（`[1 -1]` は `[1 - 1]` と `[1, -1]`）。
  `a -(b)`、`a -1`、`x -^y` も同じ形である。腕の並びで後ろに `=>` が続く形（`0 => { 1 } -1 => 2,`）は、上の `,` の抜けの E0002 である。`a - -b` は、二項の `-` の両側に空白があり、二つ目の `-` は前置なので、この形に当たらない。
  二項の `+` の非対称な空白（`[1 +1]`、`two(a +b, 1)`、`let c = a +b`）も同じ形で、修正候補は両側に空白を置いた形と、式を要素とする並びの中では `,` の挿入と `+` の削除を一つにした形（`[1, 1]`）である（Onsa に前置の `+` は無い、§3.1）。
  行頭の `- b` と `^ b` は前の行に続けるつもりの書き方なので、前の行とつないだ形（`a - b`）も修正候補に並べる（行頭の `- -b` は §3.1 の重ねの E0012 で、つないだ形は並べない）。行頭の `::` は前の行に続かず、E0002 である（行頭で前の行に続くのは `.` だけ、上記）。
- `else` と、`handle { … } with h` の `with` は、直前の `}` と同じ行に書く（std の `target fn` の本体の `else` は、見出しの最後のトークンと同じ行、§15.2）。`else` の後の `if` も `else` と同じ行に書く（`if~` で始まる連鎖でも同じ。後ろの `if` に `~` を付けた `else if~` は §2.6 の E0020）。`{` は、それが属する形の最後のトークンと同じ行に書く。
  属する形は、宣言と見出しの本体（`fn`、`flow`、`test`、`impl`、`trait`、`struct`、`enum`、`effect`、`handler`、`extern`、`if`、`while`、`for`、`match`、`par`、`unsafe`、`handle` など。見出しが継続して複数行にわたるときは、その最後の行。`if a &&` の次の行の `b {`）と、構造体リテラルと構造体のパターン（型の名前か型引数の `]` の後。括弧の中の `two(S` 改行 `{ a: 1 }, 2)` も同じ。括弧の外の式の位置では名前で行が終わり、次の行は別の文として読む）と、効果行の `uses {…}`（`uses` の後。関数型の引数の並びの中の `uses` 改行 `{Alloc}` も同じ。括弧の外では `uses` で行が終わる）と、インライン形式の handler の本体（`with` の後の効果の名前の後、§8.3。効果の名前の後には本体が必ず続くので、宣言の本体と同じく括弧の外でも次の行の `{` はこの規則に当たる）である。
  名前の後の `{` を構造体リテラルと読むかは型の名前の字面で決まり、この規則もそれに従う（定数の後の `two(N` 改行 `{ 1 })` も E0003 で、候補を当てた後に残る中身の誤りは次の検査で報告される）。どれも違反は E0003 で、主の位置は置き場所を誤ったトークン（`else`、`with`、`if`、`{`）である。
  修正候補は、そのトークンから同じ行のコメントの前までを、直前の `}`（`if` では `else`、`{` ではそれが属する形の最後のトークン）の行の末尾へ移すこと。その行の末尾にコメントがあればコメントの前に入れ、コメントは書かれた行に残す（`} // positive` と次の行の `else {` は `} else { // positive`）。
  間にあるコメントだけの行と空行はそのまま残る。一つの候補が直すのは一つの診断で、同じ見出しに E0003 が二つあれば（`}`、`else`、`{` の 3 行）、残りは次の検査で報告される。
  前の行へつなぐ他の修正候補（行頭の二項演算子の E0020、行頭の `- b` と `^ b`、括弧の中の改行の後の後置の開き（`(`、`[`、`!(`、`~(`）の E0002、行頭のパターンの `|` の E0020）も、主の位置と移し方は同じである。
  改行を空白として扱う並びの中でも、上の置き場所の規則のとおり同じで、修正候補も同じである（`onsa fmt` は構文の診断のあるファイルを書き換えない、§18.2）。
- 構文の入れ子の深さは 256 までである。深さは宣言の単位（§18.1）ごとに 0 から数え、式・型・パターンの形とブロックのそれぞれを一段と数える。名前、リテラル、`_`、並び（引数、要素、`match` の腕、フィールド）、文、宣言の見出しは数えない。二項演算子の連鎖は、§3.1 の強弱と左結合で読んだ木の高さで数える（演算子ごとに一段で、`a + b + c` は二段）。
  一段と数える形は、例えば括弧、タプル、配列、構造体リテラル、前置演算子、`as`、`at`、範囲、後置の呼び出し・添字・`.名前`・`.数`・`?`、`if`（`else if` の `if` は前の `if` の一段下）、`match`、`for`、`while`、`par`、無名関数、`handle`、`unsafe`、`move`、型引数のある型、タプル型、配列型、関数型、パターンのタプル・列挙子・構造体・括弧・`|` である。
  文字列の補間の穴は、その名前の経路を式に書いたときと同じに数える。関数の本体のブロックが一段目で、`const` の初期化式は式の形が一段目である。数えるのは書かれたソースで、`onsa fmt` が冗長な括弧を外す前である（fmt の書き換えは深さを増やさない）。
  超えると E0006 で、主の位置は、読み取りの順で最初に 256 を超えた形の、その段を作るトークン（開き括弧、演算子、後置の記号、キーワード）である。名前で始まる形（型引数のある型、構造体リテラル、列挙子と構造体のパターン）の段を作るトークンは、名前の後の開き括弧である。式の中の型引数 `::[…]`（§4.5）は型引数のある型と同じ一段で、段を作るトークンは `[` である。
  左結合の連鎖（二項演算子、後置の連鎖）では、左から読んで高さが初めて 256 を超える演算子（後置の記号）が主の位置で、連鎖を読み切る前に止める（括弧の入れ子と同じ規則）。パターンの `|` は選択肢の数によらず全体で一段、メソッド呼び出し `a.f(x)` は `.f` と呼び出しの二段である。
  宣言の見出しの中の型（引数と返り値の型）は、見出しを数えないので最初の形が一段目である（本体の中の型は、本体のブロックが一段なので二段目から）。部分式を `let` に、型を名前付きの struct に、ブロックを関数に分けることを note で示す（型を `type` の別名に分けても、展開した型の深さは変わらない。§4.4）。
  E0006 を出した単位は、そこで読み取りを止める（閉じていない括弧の E0002 は出ない）。上限が処理系で違うと、ブラウザの IDE（WASM）と CLI で同じファイルの合否が変わるので、仕様で固定する（P8）。256 は実際のコード（FIR の 64 項の和など）より十分大きく、深いスタックを前提にしないので、どの環境でも動く。
- `;` は使わない。

### 2.6 `~`（flow の呼び出しと全ての枝を評価する分岐）、`!`（レシーバを変える呼び出し）、`^`（帰還の参照）

`名前~(引数, ...)` は flow のインスタンスを作る呼び出しである（§11.5）。

- `~` は名前の直後に空白を空けずに書き（空白は E0020、§2.5）、直後に `(` が続く。モジュールで修飾した名前にも付けられる（`filters.resonator~(x, fc, q)`）。
- `~` は flow の呼び出しと、全ての枝を評価する分岐 `if~` / `match~`（§11.5）と、インスタンスの修飾子（`.when~(c)`、§11.10）にだけ使う。
  `if~` / `match~` は、`if` / `match` の直後に空白を空けずに `~` を書く（空白を空けると E0020 で、修正候補は空白を除く形。`if ~c` のように `~` が被演算子に接するときは、前置の `~` の読みの `if !c` を二つ目に並べる。§18.1）。
  括弧の中では改行も空白と同じで（`two(if` 改行 `~c { … } else { … }, 1.0)`、§2.5）、修正候補の一つ目は `~` をキーワードの直後へ移す形である。括弧の外では `if` / `match` で行が終わり、行末の E0002 になる（§2.5）。
  `~` が被演算子に接するのは、同じ行で空白を空けずに被演算子が続くときだけである（`~` の後が改行なら `!` の形を並べない）。
- flow の本体の中で、flow を `~` 無しで呼ぶか、状態を持つもの（インスタンス、組込みの遅延、`par`）を `if` / `match` の枝に書くと E0811。flow でないものに `~` を付けるか、状態を持つものを枝に含まない `if~` / `match~` を書くと E0812。
  E0811 は `~` を足す修正候補を示す（枝の E0811 は、状態を持つものを前の `let` に出す形も並べる）。
  呼び出しに付けた `~` の E0812 は、呼び先が `f(x)` で呼ぶ項目（関数、関連関数、名前空間の関数、効果の操作、要素を持つ列挙子）を指すときだけ `~` を外す修正候補を示し、受け手か呼び先が値（値のメソッド、インスタンスの出力のメソッド、引数、ローカルの束縛、フィールド、定数、単位形の列挙子）なら候補を出さず、note で `~` は flow と組込みの遅延の印で、遅延は `prev~(x, …)` と書くことを示す（§11.10 の修飾子と同じ）。
  状態を持つものを枝に含まない `if~` / `match~` の E0812 は、`~` を外す修正候補を示す（§11.5）。
  flow の外では、flow の呼び出しと `if~` / `match~` は `~` の有無によらず E0821（§11.1）。
- 組込みの遅延 `prev` / `delay` / `vdelay` も状態を持つ flow なので、`prev~(x)` と書く（§11.4）。
- `~` は演算子ではなく、他の意味を持たない。ビット反転は `!` と書く（Rust と同じ）。
- FAUST の `~` はフィードバック、つまり状態を作る演算子である。Onsa の `~` も「状態を持つものを作り、進める」印で、意味の方向は同じである（`if~` の `~` は、全ての枝の状態を進める印）。FAUST の二項演算子としての書き方は使えない。`let y = x + ~ _` は E0020 で、修正候補は `let y = x + prev~(^y)`（§11.2、§18.1）。

`名前!(引数, ...)` は、`inout self` のメソッドの呼び出しである（§5.2）。`!` も名前（型引数を書いたときはその並びの後、`buf.push::[F32]!(x)`、§4.5）の直後に空白を空けずに書き（§2.5）、直後に `(` が続く。
前置の `!`（否定）とは位置で分かれ、`x.f!=y` は `!=` に字句解析される。`~` と `!` はどちらも「名前の直後の印 + `(`」の形で、呼び出しの種類（インスタンス生成、レシーバの変更）を一文字で表す。タプルの添字は名前でないので、その直後には書けない（`t.0~(x)`、`t.0!(x)`、`mk2().0!(x)` は構文の段の E0002 で、修正候補は無く、note で印は項目・メソッド・flow の名前の直後に書くと示す）。

`^名前` は帰還の参照で、flow の本体で下で定義される `let`（定義中のものも含む）を指す（§11.2）。`^` は名前の直前に空白を空けずに書き（§2.5）、`let` の名前にだけ付く。名前の続かない `^`（`^(y)`、`^1.0`、`^^y`）は構文の段の E0002 で、`^` は `let` の名前の直前にだけ書くことを note で示す。
演算子ではなく、他の意味を持たない（二項の `^` は排他的論理和で、位置で分かれる）。書けるのは遅延の組込み（`prev~` / `delay~` / `vdelay~`）の第 1 引数の中だけで、その中の利用者の flow の引数は除く（§11.2）: `let y = x + 0.5 * prev~(^y)`。
