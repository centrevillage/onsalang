## 7. 制御

```onsa
if c { a } else { b }
match v {
  Some(x) => x,
  None => 0,
}
for i in 0 ..< n { ... }    // n を含まない。0 ..= n は n を含む
for s in xs { ... }         // 借用の反復（§5.4）。xs は変わらない
for s in move xs { ... }    // 消費する反復。s は所有する値
while cond { ... }
break / continue / return
```

- `match` は網羅的（E0501）。ガードは `Some(x) if x > 0 => ...`。網羅の判定に数えるのは、`Bool` の `true` と `false`、enum の列挙子、それらを要素に持つタプルと struct のパターンだけである。整数・`Char`・`Str` のリテラル、定数のパターン（下記）、ガードの付いた腕は数えない（`U8` の 256 個の値を全て並べても、`_` か束縛が要る）。判定が単純になり、リテラルの後の `_` は常に到達する。
- 前の腕で覆われて、どの値でも選ばれない腕は E0503（到達しない。`_` や束縛の後の腕、重複した `1 =>`、`true` と `false` の後の `_`）。修正候補は腕を消す形と、覆っている腕が `_` か束縛だけのときは、それを最後へ移す形である。消し忘れか順の誤りで、直し方が到達しない文と同じなので、同じコードにする。`match~`（§11.5）も同じである。
- パターン（Rust と同じ意味のものだけ）:
  - リテラル: 整数（`-1` のように `-` を一つ付けた負の整数を含む。範囲の検査と間の括弧の扱いは式のリテラルと同じ、§4.7。`-(-1)` はリテラルでないので書けず、E0002）、`Char`、`Bool`、`Str`（バイト列の等値。補間を含む文字列は値を作る式なので書けない（E0020。修正候補はガードの形 `v if v == "a{x}b"`。補間する名前が全て定数でも同じ）。`{{` と `}}` だけの文字列は補間を含まない）。
    浮動小数のリテラルは書けない（E0020。リテラルの字面だけで決まるので構文の段で出す。浮動小数の型の定数のパターンは型が要るので型の段で出す。修正候補はガードの形 `x if x == 1.0`。IEEE の等値はガードで書く）
  - 定数: 定数を指す名前（§4.5 と同じ。`LIMIT`、`cfg.LIMIT`、関連定数の `I64.MAX`）は、その値と `==` で比べる。
    書ける型はリテラルのパターンと同じ具体的な型（整数、`Char`、`Bool`、`Str`）で、それ以外の型の定数（浮動小数、struct、型パラメータの型の `T.MAX` など）は E0020（修正候補はガードの形 `x if x == LIMIT`。浮動小数の定数は、浮動小数のリテラルと同じ理由で書けない）。
    定数に前置の `-` を付けた `-LIMIT` も E0020（修正候補は `x if x == -LIMIT`）。`-` の後が定数の名前であること（最後の名前が `UPPER_SNAKE` の形の名前と経路）は字面で決まる（§2.3）ので、`-LIMIT` は構文の段で出し、下の構文の段のガードの形の候補に入る。
    書けない型の定数は型の段で出し、そのガードの形の修正候補も、一つの腕のパターンにある全てを型の段の一つの誤りとし、構文の段の候補と同じ規則（下記の置き換え、`&&`、選択の枝のまとめ方、元からあるガード）で一つの候補を作る。
    候補を当てた後に型の段の誤りが残るとき（定数の型が `PartialEq` を満たさない）と、置き換えた後も選択の枝の形が違うときは、候補を出さず、規則を note で示す（E0020 のまま、§18.1）。
    定数の値は評価で決まる（初期化式から関数を呼べる、§6.6）ので、網羅と到達しない腕の判定では値を見ない（ガードの付いた腕と同じ扱いで、`while ALWAYS` を発散に数えないのと同じ理由）。`ON` と `false` の腕だけの `Bool` の `match` は網羅にならず、同じ値の定数の腕が二つあっても E0503 にならない。
  - `_`、名前の束縛、`Type.Variant(p, ...)` / `Some(p)` / `None`、タプル `(p, q)`、入れ子（単位形の列挙子は括弧を付けない。要素の無い `Type.Variant()`・`None()` は E0002、§2.5）
  - パターンに書いた名前: `snake_case` の名前は束縛である（見えている項目と同じ名前は E0304、§5.1）。それ以外の名前は解決し、定数（`const` と関連定数）か列挙子でなければ E0308（§15.1。型、trait、総称の定数のパラメータ `N` を含む。総称の定数のパラメータと比べるときはガードで書く）。束縛かどうかは字面で決まる（§2.3）ので、定数の名前を書き誤っても束縛にはならず、E0302 になる。
  - struct: `Point { x: px, y: py }`。全てのフィールドを書く（過不足と重複は E0410。struct リテラルと同じ、§4.4）。不要なものは `_`。残りを省く `..` は無い（E0020。修正候補は残りのフィールドを `_` で並べる形。フィールドを足したとき、全てのパターンが落ちるようにする。この位置から見えないフィールドが残るときは候補を作れないので E0410）
  - 選択: `p | q`（式の `|` はビット和で、パターンの中では選択。文脈で分かれる）。`|` は選択肢の間にだけ書き、最初の選択肢の前には書かない。パターンを読み始めるどの位置でも（腕の `| 0 | 1 =>`、入れ子の `Some(| 0 | 1)`、`let | (a, b) = p`）構文の段の E0020 で、修正候補は `|` を除く形である。
    腕は `,` で区切り、`|` は腕の頭の印ではない（OCaml と F# の書き方）。`|` の後にパターンが続かないとき（`| =>`）は候補を作れず E0002 である。
    パターンの中の `||` は E0020 で、修正候補は `|` にする形である（`0 || 1 =>` は `0 | 1 =>`。C と JavaScript の `case 0 || 1:` は式の値と比べ、その値は言語で割れる）。`||` の後にパターンが続かないときと、`|` が続くとき（`0 ||| 1`）は候補を作れず E0002 である
    選択の全ての枝は、同じ名前の集合を束縛する（`(x, 0) | (0, x) => x`）。集合が違えば（`Some(x) | None => x`、`(x, 0) | (0, y)`、`x | y`）名前の段の E0314 で、最初の枝と集合が違う枝に一つ報告し、その枝に無い名前か余分な名前を示す。
    修正候補は無く、全ての枝で同じ名前を束縛するか、枝ごとに腕を分けることを note で示す。入れ子の選択は選択ごとに当てる。同じ名前の型は全ての枝で同じである（違えば型の段の E0401）。
  - 無いもの: 範囲パターン、`@` 束縛。範囲は `for` と `par` の見出しだけに書け、パターンではガードで書く。
    範囲のパターンは構文の段の E0020 で、修正候補はガードの形である（`1..<3 =>` は `k if 1 <= k && k < 3 =>`、`1..=3 =>` は `k if 1 <= k && k <= 3 =>`。`1..3` は二つを並べる。一つの腕に `..` か `...` の範囲が複数あれば、全ての範囲を同じ読みにした二つを並べる）。
    片側の範囲も同じで、`5..` は `k if 5 <= k`、`..<5` は `k if k < 5`、`..=5` は `k if k <= 5`、`..5` は二つを並べる（`...` は `..` と同じ）。範囲が入れ子や選択の中にあってもガードの形にする（`Some(1..<3)` は `Some(k) if 1 <= k && k < 3`。選択の中の扱いは下記）。
    端の型は問わない（ガードの比較を型の段で検査する）。端は見出しの範囲の端と同じ式で読み（§3.1。定数の名前、`-LIMIT`、`I32.MIN`、ローカルの名前、`n + 1` のような式も端になる）、パターンの中では括弧の外の `|`・`if`・`=>`・`,`・閉じ括弧の前で終わる（`1..<n + 1 =>` は `k if 1 <= k && k < n + 1`）。
    修正候補は端を写し、比較の被演算子に置けない端（`as` / `at` の式と、比較・論理・ビットの群の式）を括弧で囲む（`0..<m as U32 =>` は `k if 0 <= k && k < (m as U32)`）。端の裸の `as` / `at` は範囲のパターンの一つの誤りに入る。端が式として読めないとき（`..<` の直後の `if` や `{` を含む）は E0002。
    `@` 束縛は、`@` の右がリテラル・定数（字面で定数と分かる名前と経路と、`-` を付けたもの。`-LIMIT` と同じ判定）・範囲・それらの選択だけならガードの形（`n @ 1..<5` は `n if 1 <= n && n < 5`、`k @ LIMIT` は `k if k == LIMIT`。範囲は範囲のパターンと同じ規則）を修正候補にして E0020、それ以外（`s @ Some(_)`、列挙子の `k @ Color.Red`）は E0002 で、ガードか入れ子の `match` で書くことを note で示す（§18.1）
  - 構文の段のガードの形の修正候補（浮動小数のリテラル、範囲、補間を含む文字列、`-` を付けた定数、`@` 束縛）は、一つの腕のパターンにあるそれらの全てを一つの誤りとし、一つの候補で直す（§18.1 の一つの構文の形）。
    `@` 束縛でないものはそれぞれを新しい束縛に置き換え、`@` 束縛は左の名前に置き換えて右の全体（整数などのリテラルを含む）を条件にし（`n @ (1 | 1..<3)` は `n if n == 1 || (1 <= n && n < 3)`）、条件を `&&` で結ぶ（`(0.0, 1.0) =>` は `(v, v2) if v == 0.0 && v2 == 1.0 =>`）。
    `@` は `|` より強く結び（`n @ 1 | 2` は `n @ 1` と `2` の選択）、`@` の右の選択は括弧で囲んで書く。
    パターンが選択（`p | q`）を含むときは、置き換えた後に選択の全ての枝が同じ形（`@` 束縛の左の名前を含む）になるときだけ候補を作り、枝を一つにまとめ、枝ごとの条件を `||` で結ぶ（`0.5 | 1.5 =>` は `v if v == 0.5 || v == 1.5 =>`、`(0.5, n) | (1.5, n) =>` は `(v, n) if v == 0.5 || v == 1.5 =>`、`Some(0.5 | 1.5)` は `Some(v) if v == 0.5 || v == 1.5`）。
    置き換えた後も枝の形が違うもの（`(0.5, 1) | (1.5, 2)`、`(1..<3, 1) | (5..<7, 2)`、`Some(1..<3) | None`）は、ガードがどの枝で当たったかを区別できず、当たる値が変わるので、候補を作らず E0002 である。腕に元からガード `if g` があれば、作った条件と `g` を `&&` で結ぶ。
  - ガードの形の修正候補が新しく置く束縛の名前は、その位置で見えている名前と、範囲の端や補間の中の名前と重ならない名前で、当てた後に E0304（§5.1）を残さない（§18.1 の修正候補の約束）。どの名前にするかは決めない。上の候補の `x` と `v` は例である。
- `match x` の束縛は借用束縛（§5.4）で、`x` は変わらない。`match move x` は所有する値を消費し、腕の束縛は中身を所有する（`for s in xs` / `for s in move xs` と同じ対称形）。
- 借用の `match x` のガードでは、`x` とその一部を変更できない（代入、`inout` への受け渡し、`!` のメソッド、`move` は E0715）。腕の判定が字面どおりに決まる。
- 腕の本体では `x` を変更できる（段の遷移 `match self.stage { Stage.Attack => { self.stage = Stage.Decay } }` など）。変更すると、変更した場所と重なる Copy でない束縛（腕の束縛と、そこから `let` などで派生した借用束縛）は、move した値と同じく以後使えない（E0704）。
  重なりは `inout` の重複（E0702、§5.2）と同じく判定し、異なるフィールドは重ならない。Copy の束縛は束縛した時点の値なので、そのまま使える。
- 反駁可能な `let` は無い（E0502）。分解は反駁不能なパターン（タプル・構造体）だけ: `let (a, b) = pair`。enum のパターンは、列挙子が一つでも E0502 である（列挙子を一つ足しただけで、離れた `let` が壊れる性質を持ち込まない。中身を一つ持つ型は struct で書く、§4.4）。
- `return`、`break`、`continue` は文で、式の位置には書けない。`match` の腕に直接書くと（`None => return 0,`）E0020 で、修正候補はブロックで囲む形（`None => { return 0 },`）である。
- 値を返さずに抜けるもの（`return`、`break`、`continue`、`panic(...)`）は発散する。それで終わるブロックと `panic(...)` の呼び出しは、どの型の位置にも置ける（`_ => panic("unreachable")`、`let k = if c { 1 } else { return 0 }`）。発散を表す型は書けない（戻らない関数は宣言できない）。
- 条件がリテラルの `true` で、そのループを抜ける `break` を含まない `while true { ... }` も発散する。`return` や `panic` で抜ける探索のループを、関数の末尾に置ける。内側のループの中の `break` は、内側のループを抜けるので数えない。定数（`while ALWAYS`）や式（`while 1 == 1`）の条件は対象外。
- 発散する文（発散するものそのもの、それで終わるブロック、全ての枝が発散する `if`（`else` を持つもの）と `match`、上の `while true`）の後に、同じブロックの文や最後の式があると E0503（到達しない）。判定は文の構造だけで行い、条件の値は見ない（`if false { … }` の中は誤りにならない）。
  修正候補は到達しない文を消す形で、行末の `return` の次の行に式があるときは、つないだ形（`return x * 2`）も並べる（`return` は行末で終わる、§2.5）。消し忘れたコードと、行末の `return` で黙って抜ける誤りを捕まえるためである。
- 初期化式の全体が上の発散する形である `let` と `var`（`let x = { return 1 }`、`let x: I32 = if c { return 1 } else { return 2 }`）も、発散する文である。初期化式を評価してから束縛するので、到達しない最初の部分は束縛で、後の文の有無によらず、パターンに E0503 を出す。
  修正候補は、パターン・注釈・`=` と後の文を消し、初期化式を文として残す形である（`let x = { return 1 }` と後の `x + 1` は `{ return 1 }`）。到達しない部分は文の順の検査の中で見つかるので、関数の終わりの検査（E0406、E0405、後回しにした E0416、§4.7）より先に報告する。
- `loop {}` は無い（`while true` と書く）。
- 範囲は `a ..< b`（終わりの `b` を含まない）と `a ..= b`（`b` を含む）の二つである。`..` と `...`（`a..b`、`a...b`）は、終わりを含むかが言語で分かれる（§0.3 の規則 4）ので E0020 で、修正候補は `a..<b` と `a..=b` を並べる。端は整数の型である（違えば E0401）。
  `for i in a ..= b` は、`b` が型の最大値でも溢れずに終わる。始点が終点以上（`a ..< b`）か終点より大きい（`a ..= b`）範囲は空で、`for` は本体を一度も実行しない（端は §3.5 の順に両方を評価する）。
  端が定数で分かっても誤りにしない（`par` の空の範囲の E0808（§11.5）は、複製の数が 0 になる構造を作らないための規則で、反復には当てない）。
- 範囲は `for` と `par`（§11.5）の見出しにしか書けない。見出しの片側の範囲（`for i in 0.. {`、`for i in ..<n {`）は E0002 で、両端を書くことを note で示す。
  見出しの外の範囲（`let r = 0..<n`、`xs[1..<3]`、括弧で囲んだ見出しの範囲 `for i in (0..<n)`）は E0002 で、部分は `xs.slice(from, to)`（§5.3）で書くことを note で示す。範囲には消費する値が無いので、`move` は付けない（`for i in move 0..<n` は E0703）。
  見出しの `move` は反復元の全体に付く印で、範囲の始まりの端の形によらず E0703 で（`for i in move lo + 1..<hi` も同じ）、修正候補は `move` を消す形である。他の場所でない反復元（呼び出し、定数、`if`）に付けた `move` は E0711（§5.2）。
- 組込みの集合（`[T; N]`、`Buf`、`Span`、`Array`、`Map`、`Set`、範囲）の借用の反復はコンパイラが直接扱い、要素の複製と破棄を伴わない。消費する反復は `IntoIter` に脱糖し、要素は所有する値になる。ユーザ定義型の反復（`IntoIter` の実装）は必要になるまで延期する（§19.1）。
- 末尾呼び出しの最適化は保証しない。反復は `for` / `while` で書く。
