## 19. 未決定事項と、実装しない機能

### 19.1 未決定事項

- マルチレート（S-565・S-566・S-567、第 34 組。方向を決めた。本体の §2・§11 へは第 1 期の範囲を割り当てるときに移す）: オーバーサンプリング、FFT / STFT、リサンプリング、制御のレートを、インスタンスの修飾子と、入出力のレートの違う flow（変換の flow）で書く。
  クロックの宣言（`clock fast = sample / 32`）と `with` の節は使わない（語の予約は残す）。S-172 の方向の「`with` で付ける」「制御と音声をクロックの宣言で区別する」は改めた。式の中で導くクロックを書くときは括弧で包む（`p at (sample / 32)`。`at` の後ろに `/` や `*` が来ると、二項演算子と読みが分かれるため）。
  - クロックの種類: パラメータの種類（定数 < `init` < `block`）と、刻みのクロック（本体の `sample`、`sample / N`、`sample * N`、イベントの入力ごとのクロック、下のイベントの項）に分かれる。分かれ目は状態を持てるか（E0813 と同じ線）。
    `sample * N` は、変換の flow の入出力の宣言と、`.up~(N)` の部品の中にだけ現れる。
  - 読み方（§11.3 の昇格の規則を改める）: パラメータの種類の値は、使う所のクロック（`sample / N` とイベントのクロックを含む）で変換なしに読める。他に決めるものが無ければ、本体の `sample` として読む（`let c = prev~(^c) + 1` の輪は `sample` で刻む）。
    周期の刻みのクロック（`sample`・`sample / N`・`sample * N`）の値を別の周期のクロックで使うには `at` を書く。`at` は遅い→速いで、行き先は本体の `sample` まで（`lf at sample`、`lf` は `sample / 32`）。速い→遅いと、`sample * N` へは、変換の flow で書く。`at` の無い形は E0815。
    式のクロックは三つで決まる: 周期の刻みのクロックの被演算子は揃っていること、パラメータの種類とイベントの値は自由に混ざること、最大が無ければ E0815。順序では `block < sample / N`（`block` の値は `sample / N` の段で常に最新で読める。順序は評価の段の順で、刻みの頻度ではない）。
  - 部品のレート: インスタンスを別のレートで動かすのは修飾子 `.down~(N)`・`.up~(N)` だけで、引数のクロックやつなぎ方からは決めない。`x.down~(N)` は x の本体の `sample` を左のレートの 1/N に、`x.up~(N)` は N 倍にする（`sample_rate()` も 1/N・N 倍で、遅延はその刻みで数える）。
    N は 2 以上の 2 のべき乗の定数式（違えば E0808・E0417 の類）で、入れ子の比の積は 2^24 以内（flow をまたぐので降下で確かめる）。修飾子の名前は修飾子の閉じた一覧に足す（予約語は増えない）。
    連鎖は合成で読み、比は掛け合わさる（`x.down~(2).down~(4)` は 1/8、`x.down~(2).up~(4)` は 2 倍。`x.up~(M).down~(N)` も、中の部品の入出力を境界で集めて配る形で読む）。2 のべき乗に限るので、合成の比は `sample * N`・`sample / N`・`sample` のどれかに閉じる（Pure Data の `block~` と同じ制限）。
    連鎖のレートの起点は最初の呼び出し（利用者の flow は呼び出しの位置のクロック、組込みの遅延は第 1 引数のクロック）で、`when~`・`reset_if~` はレートを変えない。連鎖の全ての `.down~`・`.up~` を当てたレートを連鎖のレートと呼ぶ（下の修飾子の項）。
    `.down~(N)` の出力は呼び出し側の `sample / N` の値で、次の自分の刻みまで前の値である（保持した出力の欄は持たない）。部品の外に書いた `at` の欄も、次の自分の刻みまで前の値である。戻したいときは `at` を部品の本体の中に書く。`.up~(N)` の出力は `sample * N` の値で、変換の flow が配列で受ける。呼び出し側で `sample * N` の値に点ごとの演算をする形（`ovs2~(x) * d`）は当面は誤り（flow に分けて `.up~(N)` で動かす。後で緩められる）。
  - 変換の flow: 入出力の宣言に `at (sample * N)`・`at (sample / N)` を書ける（基準はインスタンスの本体の `sample`）。本体の中で、`sample * N` の入出力は 1 刻みに N 個の配列 `[T; N]` として見え（`x[N - 1]` が最新、ステレオの `[F32; 2] at (sample * 2)` は `[[F32; 2]; 2]`）、`sample / N` の入力は遅い値（速い式で使うには `at sample`）である。
    `sample / N` の出力は、出力の式のクロックが `sample / N` 以下（パラメータの種類とイベントの値を含む）でなければ E0815。配列で返していない・受けていない本体は型の誤り（E0401 の類）。本体の状態は本体の `sample` だけで、`sample_rate()` は本体の `sample` のレートである。
    フレームに集めるのは `x: F32 at (sample * 256)` の flow を `.down~(256)` で動かす形、ばらすのは `-> F32 at (sample * 256)` の flow を `.down~(256)` で動かす形で、組込みの変換（`frame~` など）は持たない。集めて配ると N サンプル遅れる（`delay~(x, N)` と同じ）。集めた値は呼び出し側の値なので、`reset_if~` は触れない。
  - 組込みの遅延（`prev~`・`delay~`・`vdelay~`）はクロックに総称で、第 1 引数のクロックで刻み、出力もそのクロックの値である（`prev~(lf)` は 1/32 の刻みで一つ前、第 1 引数がイベントの値なら一つ前のイベント）。第 1 引数の `at` も刻みを決める（`prev~(p at (sample / 32))`、`p` は `block`）。
    第 1 引数に書けるクロックは本体の `sample`・`sample / N`・イベントのクロックで、パラメータの種類は E0813 のまま（候補は `prev~(p at sample)`、note に `prev~(p at (sample / N))`。`block` に状態は置かない）。呼び出し側の `sample * N` の値も誤り。
    長さは第 1 引数のクロックの刻みで数え（遅い値の `vdelay~` の長さを `sample_rate()` から作るときは書き手が合わせる）、`vdelay~` の `d` は第 1 引数と同じクロックか、暗黙に読めるもの（パラメータの種類、イベントの値）。総称の遅延に `.down~`・`.up~` を付けると、連鎖のレートが第 1 引数のクロックとずれるので誤り。
  - 位相のカウンタ: 時間を作るもの（一番外のインスタンスの本体と `when~`）がカウンタを持ち、`init` と生成する `reset` でだけ 0 になる（`reset_if~` は状態を初期化するが、カウンタには触れない）。`when~` の中の時間は動いた刻みで数える。誰が欄を持つかは実装の選択。
    `sample / N` の刻みはカウンタが N の倍数の刻みで、最初の刻みで動く。ホストの区切りに依らない（§13.4。ホストのブロックの長さを 2^N に揃える必要は無い）。`block` のクロックは状態を持てないので、ホストの区切りの長さは状態に漏れない。状態を持つ制御の信号は `.down~(N)` で書く。パラメータは `block` の入力のままで、ラッパーは変化の位置で呼び出しを分けてよい（第 35 組の前提）。
  - `sample_tick()`（flow の中の組込み名。§11.4 の一覧に足し、予約名にする）: `reset` からの時間を、書いた場所の `sample_rate()` の刻みの数で表した `U32`（2^32 で一周し、間隔は `t -% last` で取る。48 kHz で約 24.9 時間）。`init` と生成する `reset` で 0 になり、`reset_if~` は触れない。
    `.up~(N)` の本体では N 倍、`.down~(N)` の本体では 1/N（上の桁の `U32` の欄をプログラムに一つ置く）、`when~` の中は外と同じ（止まっている間も進む）である。
    クロックの推論では、`sample_rate()` と同じく式のクロックを引き上げず、使う所の刻みのクロックに合わせる。下限は刻みのクロックで、他に刻みのクロックが無ければ本体の `sample`（`block` の段で読むと、ホストの区切りに依る値になるため）。巻き上げず、使う所の段で評価する。イベントの段の式ではその位置の値である。
  - 条件で動くインスタンス（`when~`）では、周期が無いので `sample_rate()` は外と同じで、遅延は動いた刻みで数える。`when~` で止まる部品の `at (sample / N)` の入力は、呼び出し側の値を、部品の中の刻みの時点で読む（中の格子は動いた刻みで数えるため）。
  - 境界（一番外の flow の入出力、S-574、第 35 組）: 入出力のクロックは `init`・`block`・`sample`・イベントだけで、`sample / N`・`sample * N` は第 1 期の規則として E0810 である（プラグインのホストは全てのポートに一つのフレームの数を渡し、§14.2 も一つの `frames` を使う）。
    誤りの位置は、その flow の `process`・`process_inplace`・`render` を使う所と `[export]` の項目で、`init`・`reset`・`State` は使える（変換の flow を `.down~(N)` で中に置くため）。E0810 の note で、中の部品を `.down~(N)`・`.up~(N)` で包み、一番外を `sample` にする書き方を示す。
    後で `sample * N` を開いても、今のプログラムは壊れない。
  - std の変換の flow（S-568、第 35 組）: 第 1 期の std は、2 倍のオーバーサンプリングの `fir_up2`・`fir_down2`（`std.dsp`。線形位相のハーフバンドの FIR、型は `F32` だけ）を置く。4 倍以上は入れ子で書く。
    名前は、方式の名前、`up`・`down`、比の順で、番号を付けるときは方式の名前の後ろ（`fir2_up2`）。IIR の版（`iir_up2`・`iir_down2`）は要ると分かったときに足す（std は prelude の外なので、足しても利用者のコードは壊れない、§15.1）。
    係数は std の本体に 16 進の浮動小数のリテラルで書き、和は書いた順に取る（§13.4 のビット一致は本体から出る）。仕様には形（タップの数、遅れのサンプル数）を書き、値は M5 で決める。入れ子（`fir_up2~(fir_up2~(x)).up~(2)` の類）が `sample * 4` と読めるかは、仕様の例を一つ書いて確かめる。
  - 集めて配る時点（S-578、第 35 組）: 同じ位置では、入力のイベントの刻み、遅い刻み、`sample` の刻みの順に並ぶ（段の順 `block < sample / N` から）。位置 c の遅い刻みが集めるのは c − N 〜 c − 1 の N サンプルで（`x[N - 1]` が c − 1）、配る出力は位置 c 〜 c + N − 1 の `sample` の刻みが順に読む。
    同じ位置で `sample` の段が出したイベントは、遅い周期の刻みには次の遅い刻みで見える（部品のイベントの段は、その位置で処理する）。
    位相 0 の遅い刻み（`init` と生成する `reset` の後の最初の刻み）の配列は、前のサンプルの無い所を `T.default()` で埋める（`delay~` の初めの値と同じで、出力は入力のちょうど N サンプル遅れになる）。集める入力の型が `Default` を満たさなければ E0816。配った値は呼び出し側の `sample` の値で、集めた値と同じく `reset_if~` は触れない。
  - std の制御のレートの変換の flow（S-577、第 35 組）: `std.dsp` に、下げる `cut_down16`・`cut_down32`・`cut_down64`（塊の最後の値。間の値は捨て、折り返しを止めない）と `avg_down16`・`avg_down32`・`avg_down64`（塊の平均 `sum(x) * (1.0 / N)`。和は左から）、
    上げる `lin_up16`・`lin_up32`・`lin_up64`（前の遅い値 a から今の値 b へ N サンプルの直線。`y[j] = (1 − w) * a + w * b`、`w = (j + 1) / N`。§11.4 の `vdelay` と同じ 2 乗算の形で、最後は b に一致し、`b − a` が溢れても有限）を置く。型は `F32` だけ。
    std の flow は遅い側を `at (sample / N)` で宣言し、中で公開しない変換の flow を `.down~(N)` で動かすので、呼び出しに修飾子は要らない（`lin_up32~(ctl~(avg_down32~(x)).down~(32))`）。std に無い比は入れ子で書く。
    `lin_up` の最初の刻みは既定値 0 から上がる（`init` と `reset`・`reset_if~` の後、N サンプルで今の値に届く）。今の値から始める版が要れば、総称の flow が入るまでは名前で分けて足す。
    線形位相の FIR は制御の信号に使わない（ステップの前から動き、遅れが大きい）。トリガ（1 サンプルの脈）はイベントで書き、周期の変換に乗せない（ピークの方式は置かない）。比を持たない平滑（一次の平滑など）は S-579。
  - 弱いところ: 半分のレートの音声を `at sample` で速い式に読むと保持になり、像は検査で止まらない。外で `sample_rate()` から作った係数を別のレートのインスタンスへ渡す誤りも、検査を通る。
  - 決めていないこと: std の平滑の flow（S-579）、`when~` を配る形の部品（出力が `sample * N` の配列の部品）に付けたときの「最後の出力を保つ」の意味、flow の遅れを境界に出す形（S-576）、外で作った係数の取り違えの注意（`onsa audit`、S-569）、状態の配置（カウンタの欄）、ホットリロードの照合、graph と `onsa interface` の表示、生成する API、範囲の構文、遅い制御の値と音声の値の区別、総称の flow（型引数）。
- `sample` の入力に struct を使うこと。struct の入力は今は E0810（§11.6）。flow の `block` の出力は持たず、エンベロープの終了通知などはイベントの出力で書く（下のイベントの項）。
  必要になりうる場面は、struct を出力する flow を別の flow へそのままつなぐとき（`width~(pan~(x, p), w)`）で、今は `let s = pan~(x, p)` と受けて `width~(s.l, s.r, w)` と分解して書く。認めるなら、export の境界の形（`In` の中に入れ子の `Span`）を、実例に合わせて決める
- flow の直列の複製。`par` が全ての複製に同じ入力を配るのに対し、`ser i in a ..< b { e }` は一つ前の段の出力を次の段の入力に渡し、各段が別のインスタンスを持つ（FAUST の `seq` に当たる。名前は `par`（並列）と対の直列（series）から採り、シーケンサの名前に使われやすい `seq` を避けた）。一つ前の段の値を本体で受け取る構文は、機能を入れるときに決める。キーワードは予約済み（§2.2）。
- インスタンスの停止・再開・初期化（修飾子、S-555〜S-559。第 34 組の S-562・S-566・S-567 で改めた）。インスタンスの呼び出しに修飾子を連鎖で付ける（`seq~(tick).when~(running).reset_if~(start)`）。修飾子の名前には `~` を付ける。
  `~` は状態を作るか進める印で（§2.6）、印の無い `.when(` は出力の値のメソッドと同じ見た目になり、インスタンスが止まる意味と違うからである。
  - `x.when~(c)`: x は、連鎖のレート R（呼び出しの位置のクロックに連鎖の `.down~`・`.up~` を当てたもの、上のマルチレートの項）の刻みのうち、`c` が真の刻みだけで動く。x の本体の `sample` はこのクロックを指し（`prev~` と遅延の長さは動いた刻みで数え、`sample_rate()` は外と同じ、§11.3）、`block` はホストの区切り、`init` は一度だけである。
    止めるのは x のサンプルレートに結び付く処理（`sample` の刻みと、そこから作る周期の刻み）で、イベントの刻みの処理は止めない。x の中の `at event` の入力に来たイベントは止まっている間も処理し、入力のイベントごとの出力も出る（止めたいときは、送る側をイベントの出力を持つ flow で絞る）。
    呼び出し側は x の出力を、その出力のクロック（R。変換の flow なら出力の宣言のクロック）の刻みごとに読み、止まっている間は最後の出力を保つ（一度も動いていなければ `T.default()`。`T` が `Default` を満たさなければ E0816）。
    `c` は `Bool` で、R の値、パラメータの種類、イベントの値（R の刻みで、その位置までの最後の値として読む水準）、R より遅い周期のクロックの値（保持で読む。`at` なしで遅い値を読めるのは `when~` だけ）を書ける。
    R より速い条件（下げる変換は利用者の flow で書く、`when~(dws32~(c))`）と、R 以外のクロックへの `at` は E0815。`when~(is_note_on(m))` は、最後のイベントがノートオンの間は真の水準である。
    R がイベントのクロックの受け手（第 1 引数がイベントの値の組込みの遅延）への `when~` は何も止めないので、書き手の誤解を示す印として E0020 の類にする（候補は `.when~(…)` を外す形で、note で `let cur = if is_on(m) { note_of(m) } else { prev~(^cur) }` のような選ぶ書き方を示す）。
    x の引数のクロックは x の入力の宣言（R を基準）に合わせる。x の引数と `block` の段は呼び出し側のもので、止まっている間も評価する（一度も動いていないインスタンスの `block` の式も評価され、panic しうる）。
  - `x.reset_if~(r)`: `r` が真の刻みで、その刻みに続く x の段の前に x の状態を初期値に戻す。範囲は生成する `reset`（§11.6）と同じ部分木（入れ子のインスタンス、遅延の値と書き込み位置、`par` の複製、保持した出力）で、`init` のクロックの値は保ち、poisoned と位相のカウンタには触らない。
    条件は水準で読む（条件の刻みのうち、真の刻みは全て初期化する）。条件の刻みは、パラメータの種類なら呼び出しの位置のクロックの刻み、刻みのクロックの値ならそのクロックの刻み（`sample / N` の条件はその刻み、イベントの条件はそのイベントの刻み）である。
    イベントの条件は、外の `when~` が止めている間もその刻みで初期化する（イベントの刻みの処理は止めない）。条件の中で、イベントの値と周期のクロックの値が混ざると E0815（`is_start(tr) && armed`、`armed` は `sample`。下のイベントの項）。真が続く信号（ゲート、ボタンのパラメータ）では、真の間は初期状態に留まる。
    立ち上がりで初期化するには、`let pb = prev~(start)` と取ってから `reset_if~(start && !pb)` と書く（`&&` の右辺に状態を持つものは書けない、§11.5。`block` の値は `prev~(start at sample)`）。
  - 各修飾子は左の全体を包む（合成）。順も重ねがけも自由で、順が違えば意味が違う。`x.when~(c).reset_if~(r)` は止まっている刻みにも初期化し（保持した出力も `T.default()` に戻る）、`x.reset_if~(r).when~(c)` は動く刻みにだけ初期化する（パラメータの種類と周期のクロックの条件。イベントの条件ではどちらも止まっている間に初期化し、違いは保持した出力を戻すかだけ）。`x.when~(a).when~(b)` は `a && b` の刻みで動く。
    `when~`・`reset_if~` はレートを変えないので、`x.when~(c).down~(4)` と `x.down~(4).when~(c)` は同じ意味である。止めた刻みの 4 回に 1 回で動かすのは、名前の flow で包む（`slow~(r).when~(c)`）。
  - 受け手は flow の呼び出し（組込みの遅延を含む）か修飾子の連鎖である。`let` で受けた名前（`let s = saw~(f0)` の後の `s.when~(c)`）、値、`par`、`if~` / `match~` は E0812。
    インスタンスを指す名前（ハンドル）と、止める命令は持たない（flow の本体は命令を持たないデータフローで、インスタンスは呼び出しの位置で作られるため）。
    修飾子を付けた呼び出しも状態を持つもので、`if` / `match` の枝は E0811、`&&` / `||` の右辺は E0806、flow の外は E0821 である。
  - 修飾子の名前は別の名前空間にあり、`.名前~(` の頭がインスタンスの式のときだけ引く（頭がモジュールか flow の名前空間なら、今の flow の呼び出し）。組込みは `when`・`reset_if`・`down`・`up` の閉じた一覧で、語の予約（§2.2）は残す。
  - 誤りの形: `~` の無い `saw~(f0).when(c)` は E0811（修正候補は `~` を足す形）。頭がインスタンスの式で名前が一覧に無いときと、受け手が値のときは E0812 で、`~` を除く候補は出さず、note で受け手と一覧を示す。後置の節（`saw~(f0) when c`）は構文の段の誤りで、note で連鎖の形を示す。
  - 引数の位置に書いたインスタンスの呼び出し `f~(…)` は、呼び先によらず出力の値である（§11.5）。関数の形（`when~(saw~(f0), c)`）は持たない。
  - MIDI のトランスポートは `seq~(tick).when~(runs(tr)).reset_if~(is_start(tr))` と書ける（`runs` は Start と Continue の後に真、Stop の後に偽を返す利用者の関数で、`sample` の刻みで最後の値として読む）。
    Start の位置では、イベントの刻みで `seq` を初期化し、その位置の `sample` の刻みで初期状態から一歩動く。
    取られない枝の状態を止める分岐（クロック付きの `if`）もこれで書ける（`let y = lp~(x).when~(c)` と取ってから `if c { y } else { 0.0 }`。今は E0811 で、全ての枝を進める `if~` / `match~` で書く、§11.5）。
  - 後で足す修飾子の方向: 連鎖で呼ぶ利用者の修飾子は、宣言の `self` を頭にし（`flow random_when(self, p: F32 at block) -> F32 at sample { self.when~(…) }`）、頭以外の引数は値とする。
    flow の高階（flow を受ける flow）は、呼ぶ前の flow を名前で、型引数と同じ場所 `::[…]` に渡し（`branch::[saw, sin]~(f0, sel)`、宣言は `flow branch[flow a(F32 at sample) -> F32 at sample, …](…)`）、渡す flow ごとにコンパイル時に展開する（flow は第一級の値ではない、§11.6）。
    利用者の修飾子の本体の `self` は受け手になれる（利用者の修飾子を足すときに、上の受け手の規則に加える）。どちらの形も今は誤りなので、開いても今のプログラムを壊さない。宣言の語（`flowmod` など）は予約しない。
  - 他言語: Lustre は `when` で止めたノードの値を `current` で最後の値に保ち、faust-rs の `ondemand` も最後の値を保つ。Pure Data の `switch~` は、止めたサブパッチの信号の出口に 0 を書く。
  制限を外す向きの変更なので、今の規則で書いたコードは壊れない
- イベント（ノートの発音、モードの切り替えなど。S-560〜S-564・S-567、第 34 組で決めた。境界は第 35 組の S-570〜S-573 で決めた）。flow の入力に、イベントのクロックの値を渡す（`notes: midi.Message at event`。クロックの名前空間にあるので、利用者の名前とぶつからない）。
  値は利用者の型を含む Copy の型で（型に足す制限は無い）、MIDI と組込みのイベント（トランスポートの Start / Stop / Continue など）は std の型にする（組込みかどうかは型で分かれる。C の ABI での表し方、たとえば MIDI 1.0 を U32 に詰める形は、std の型ごとに境界の形として決める。下の境界の項）。
  イベントはブロックの中の位置を持ち、位置はホストが決める（リアルタイムの再生では届いたイベントを次のブロックの位置 0 に、CLAP などではホストがくれた位置に置く。どちらでも flow の意味は同じ）。
  - クロック: イベントの入力 `e` ごとにクロックがあり、`e` のイベントごとにその位置で一回刻む（同じサンプルの中で複数回刻みうる）。入力のイベントの刻みは、その位置の `sample` の刻みより前に並ぶ。`at event` は入出力の宣言にだけ書く（式の `e at event` は E0815 の範囲）。
    順序では、イベントのクロックは全ての周期の刻みのクロックの下で、パラメータの種類の上にある。別の入力のイベントのクロックどうしは比べられない（`a.x + b.y` は E0815）。周期の刻みのクロックの被演算子の無いイベントの値の式は、そのイベントのクロックの式で、その刻みごとに評価する（イベントの段）。
  - 同じ位置の順: 同じ位置のイベントはキューに溜め、イベントごとに一回刻んで順に処理する。一つの入力の中はホストの列の順である。入力をまたいだ順は境界が渡す順で、境界はホストの列に順があればそれを保ち（一つの MIDI の流れの Clock と Start）、無ければ外の flow の入力の宣言の順で並べる。渡し方は下の境界の項（S-570）。
    サンプルのクロックの式からは、その位置のイベントを全て処理した後の状態が見える。イベントの段の panic も、状態を poisoned にする。
  - 読み方: イベントの値は `block` と同じく暗黙に読め、使う所の周期の刻みのクロックの刻みで、その位置までの最後の値（その位置のイベントを全て処理した後の値）になる。最初のイベントの前は `T.default()`（`T` が `Default` を満たさなければ E0816）。
    `v at sample`・`v at (sample / N)` と書いても同じ意味で、変換の場所を留める（値の欄は §11.3 の巻き上げの隠れた欄で、生成する `reset` で戻る。`at` は状態を作らないとした S-152 は改めない）。
    ただし四つの所（組込みの遅延の第 1 引数、帰還の輪、`reset_if~` の条件、イベントの出力の式）では、`at` の下に無いイベントの値が周期の刻みのクロックの値と混ざると E0815（`prev~(m.note + bend)` の候補は `prev~(m.note) + bend` と `prev~(m.note at sample + bend)`）。
    式のクロックが状態の刻み・初期化の刻み・出す刻みを決める所で、書き換えで刻みが黙って変わらないようにするためである。値は `let`・`rt fn` の結果・`if` / `match`・struct・配列・タプルのリテラルを通して追い（フィールドを分けて追わない）、flow の出力と `at` を書いた値で止める。
    イベントの段の式では、周期の刻みのクロックの値（入力を含む）は読めず E0815 で、パラメータの種類と `sample_tick()` は読める。一方の入力の状態で他方の入力のイベントを選ぶ処理は、和の型の一つの入力で受けて書く。
  - 引数: イベントの入力への引数はイベントの値で、インスタンスのその入力のクロックは引数のクロックに結び付く（同じインスタンスの別の入力は別のクロックでよく、同じクロックを二つの入力に渡してもよい）。
    イベントの値を `sample`・`sample / N` の入力へ渡すと最後の値で読み、`block`・`init`・`sample * N` の入力へは E0815（`block` の入力への候補は、入力の宣言を `at sample` にする形）。
  - イベントごとの処理: `at event` の入力を宣言した flow の本体に、式と組込みの遅延で書く（`let v = assign(m, prev~(^v))` は m の刻みの式で、`prev~` は一つ前のイベントの v。`v at sample` がその位置までの最後の値）。利用者の flow をイベントの刻みで動かす修飾子は持たない。
    条件の書き方は上の修飾子の項（`when~` はイベントの値を最後の値の水準で読み、`reset_if~` はイベントの刻みで初期化する）。`.down~`・`.up~` の部品の中の `at event` の入力も、全ての位置のイベントで動く（`.up~` の中では、その位置の最初の刻みの前）。
  - flow のイベントの出力 `-> E at event`: 本体の出力の式は `Option[E]` で、その式のクロックの刻みで、`Some(v)` のときに一つのイベント `v` を出す（`sample` の式なら刻みごと、入力 `m` のイベントの値なら `m` のイベントごと、パラメータの種類だけなら本体の `sample` の刻み）。`None` は出さない。
    出す位置は出した刻みの位置で、出したイベントの刻みは出した刻みの直後に並ぶ（受け手は名前の順で作り手より下にあり、その位置の受け手の段の前に届く）。呼び出しの出力のイベントのクロックは、呼び出しごとに別のクロックである。struct の出力にイベントを含めない（E0810）。
    `.up~`・`.down~` の部品の中から出るイベントの位置は、内側の刻みが属する呼び出し側の位置で、同じ位置には内側の刻みの順に並ぶ（細かい時刻が要るときは値に入れる）。`when~` で止まっている間は、周期のクロックの式の出力は出さず、入力のイベントごとの出力は出る。
  - std: イベントと信号の変換（イベントのあった位置で真の脈の flow、`genv~`、`detect_zero~` など）は std の flow で書き、flow の組込み名にしない（§11.4）。イベントの型は prelude に入れず、std のモジュールに置く（後から prelude に足すと、prelude の名前は隠せないので利用者の同名の型が壊れる）。
  - 境界（S-570〜S-573、第 35 組で決めた。本体の §11.6・§14.2・§18.2 へは第 1 期の範囲を割り当てるときに移す）:
    - イベントの入力（S-570）: 一番外の flow のイベントの入力は、入力の印の付いた一つの列で渡す。入力をまたいだ順は列の順だけで決まる（ホストの列が一つならその順を写し、分かれていればラッパーが宣言の順で混ぜる）。
      生成する API（§11.6）は、名前空間に中身を見せない Copy の型 `voice.Event` と、イベントの入力ごとの作る関数 `voice.Event.<入力の名前>(pos: U32, v: T) -> voice.Event` を置き、`process` は `params` の後、`sample` の入力の前に `events: Span[voice.Event]` を取る（イベントの入力が無い flow は取らない。§11.6 の数の規則）。
      C の API（§14.2）は、`<p>_event`（`uint32_t pos`、`uint32_t input`、入力ごとの欄を持つ union `v`。全ての入力の値が `()` か、イベントの入力が無ければ `v` を置かない）と、入力の番号のマクロ `<P>_EV_<入力の名前の大文字>`（宣言の順に 0 から）を生成する。
      `_process` は常に `params` の後に `const <p>_event* events, uint32_t events_len` を取る（イベントの入力が無い flow は NULL と 0。`params`・`bulk` と同じく、どの flow も同じ形で呼べ、後でイベントの入力を足してもホストの呼び出しの形は変わらない）。
      列の前提: `pos < frames`、列の順に `pos` が減らない、`input` は入力の数より小さい。破れば C は 2（状態を進めず、出力を 0 で埋め、poisoned にしない。重なりと同じ）、生成する API は呼び出しの最初に panic（poisoned。`Span` の長さの不一致と同じ）。
      `frames` が 0 の呼び出しはイベントを持てない（あれば同じ扱い）。イベントの入力が無い flow に長さが 0 でない列を渡すのも同じ。
      呼び出しを位置 k で分けると、`pos >= k` のイベントは次の呼び出しの `pos - k` に移り、出力は分けない呼び出しとビットで同じである（`block` は状態を持たず、位相のカウンタはホストの区切りに依らない）。
      呼び出しのイベントの段は、その呼び出しの `params` を読む（同じ位置のパラメータの変化とイベントの順は言語が約束しない。ラッパーは位置 p のパラメータの変化の直前で呼び出しを分け、p のイベントは新しい値を見る）。
      ラッパー向けに、`<p>_event_in_info`（入力ごとの名前と種類。長さは `<P>_EVENT_IN_COUNT`）、出力のイベントの種類の `<P>_EVENT_OUT_KIND`、`onsa.h` の種類の列挙 `onsa_event_kind`（下の境界の型。末尾に足す限り ABI を変えないので、`ONSA_ABI_VERSION` は 1 のまま）を置く。`onsa interface` はイベントの入力と番号を出す。
      この項と下の出力の項の C の名前は、§14.2 の閉じた一覧に足す（重なりは E1011）。
      構造体の配置は C の自然な整列で決まり、JavaScript と WASM の包みはそれを読む（出し方は M6・M8）。
    - イベントの出力（S-571）: 呼び出し側が容量を持つ列で受ける。C は `<p>_out_event`（`uint32_t pos` と値の欄 `value`）と `<p>_events_out`（`<p>_out_event* data`、`uint32_t cap`、`uint32_t len`）を生成し、`_process` は出力の位置にそのポインタを取って `len` を書く。
      生成する API は `inout output: Span[(U32, E)]`（長さが容量）を取り、出した数を返す（`-> U32`）。
      容量の上限は `A × frames + events_len` で、係数 A はコンパイラが出力のクロックから決めて `<P>_OUT_EVENTS_PER_FRAME` に出す（周期のクロックの出力は 1 刻みに一つで、A は連鎖の `.up~` の比の積。入力のイベントのクロックの出力は、その入力のイベントごとに一つまでで、A は 0。子の flow の出力のイベントのクロックは、子の本体の式のクロックに戻して同じく数える）。
      `process` は呼び出しの最初に、公開した式と同じ式を 64 ビットで計算して容量と比べ、足りなければ C は 2、生成する API は panic（poisoned）。黙って捨てない。
      0 以外を返した呼び出しは `len` を 0 にする（途中の panic でも、その呼び出しで出したイベントは捨てる。音声の出力を 0 で埋めるのと同じ）。

      flow の中と、Onsa のコードから呼ぶ生成する API（`process`・`render`）では、利用者の型も含めて自由である（外の境界ではないので、ラッパーと ABI に由来する制限は要らない）。
      `std.midi` の `midi.Message` は、MIDI 1.0 の短いメッセージを `U32` に詰めた中身を見せない型である（bit 16〜23 がステータス、8〜15 がデータ 1、0〜7 がデータ 2、24〜31 は 0。UMP の MIDI 1.0 の語の下位 24 ビット、Cmajor の `std::midi::Message` と同じ並び）。C では `uint32_t`。
      判定と取り出しと作る関数を std に置く。SysEx は持たず、MIDI 2.0 は後で別の型として足す。
      `std.transport` の `transport.Event` は、Start / Stop / Continue の中身を見せない型で、C では種類の番号の `uint32_t`。作る側は関連定数 `transport.Event.START`・`STOP`・`CONTINUE`（`continue` は予約語なので関数にしない）、判定は `transport.is_start` など。
      テンポと位置は `block` の入力で渡す（S-172。export での受け方は S-575）。
      `Default` は、`midi.Message` が 0 の語、`transport.Event` が Stop。値の正しさ（未知の種類、上位のビット）は検査せず、std の判定の関数が偽を返す。
      イベントのあった位置で真の脈の flow は `std.dsp` に置き、名前は std の一覧（M5）で決める（S-563 の例の `pulse` は仮の名前で、候補に `trig`）。
    - `render` と `onsa test`（S-573）: `render` は `process` と同じ位置に同じ形のイベントの列を取り、位置は `render` の頭から数える（`frames` が 0 の `render` はイベントを持てない）。出力のイベントは `Rendered` の `o.out: Buf[(U32, E)]`。
      テストは補助を足さず、配列のリテラルと作る関数で列を書く（入力をまたいだ順は列の順に書く）。
      `onsa test --flows` は、イベントの入力に境界の型ごとの決まった列（位置は頭・中ほど・最後と、別の入力の同じ位置を宣言の順と逆の順の両方）を与え、出したイベントの数が上限を超えないことと、同じ入力を二通りの区切りで `process` に渡した出力（音声とイベント）がビットで同じことも確かめる。

- enum（列挙子に中身の無いもの）の `block` の入力に `@param` を付けること。波形やモードの選択に使う。表示名（列挙子の名前か `label`）、値の番号（`Ordinal` の番号を使える、§6.4）、C の `Params` と `onsa_param_info` での表現を決める。今は E0809（§11.7）
- ファームウェアのエントリ: 割り込みとメインループの二つの文脈を提供する `target` モジュールの標準形（§16.1）。bulk を持つ flow の状態の持ち方も一緒に決める。
  今は Onsa の中から呼ぶ `init` に bulk 領域を渡す口が無く、bulk を持つ状態を `main` のローカルに置けない（E0819、§12.4）ので、bulk を持つ flow は C のホストから使う（§17.5）。方向の候補は、ターゲットが bulk 領域を与えて `init` が受け取る形と、登録の関数（`device.run`）が状態と bulk 領域の確保を引き受ける形
- ターゲット提供の「後回しの仕事」（サンプルの読み込みなど）: `std.worker.run_later(f, move arg)` のような文脈で、マイコンではメインループで直列に、デスクトップではスレッドプールで実行する案。言語は並列性を約束しない
- デスクトップのターゲットだけが `provides` する並列計算の効果（ライブラリとして。核には触れない）
- `Alloc` の確保失敗を、panic ではなく値として扱う API
- panic の地点の番号: `panic_messages = false` でも位置とメッセージを復元できるよう、ランタイムの panic の関数には地点の番号だけを渡し、番号から「ファイル・行・メッセージ」を引く表を `onsa build` がバイナリの外に出す（組込みの Rust の `defmt`、Zephyr の辞書式のログと同じ考え方）。番号の安定、表の形式、`onsa audit --panics` との関係を決める。今は文字列を除いて行番号を残す（§9.2）
- 補間の中の呼び出しと式。穴の評価順（§3.5）、効果、`!` / `inout` の呼び出し、panic の扱いを決める必要があるので、今は名前の経路だけ（§2.4）
- `panic` のメッセージに、組み立てた文字列（`"index {i}"`）を渡すこと。`Str` の実装と一緒に決める。rt の中では、組み立てにヒープが要る（§9.2）
- ホットリロードで、型の変わったフィールドの扱い
- probe で見るためだけに名前を付け、出力には使わない信号。今は使われない束縛（E0309、§5.1）なので書けない。必要な実例が出たときに、印の形（属性など）を決める（`onsa probe`、§18.2）
- Onsa から `extern "C"` の関数（§14.1）を呼ぶ間の浮動小数の状態。export の入口ではプロファイルの環境に設定する（§15.5）ので、そのまま呼ぶと C の関数はその環境で動く。呼ぶ前後でホストの状態に切り替えるかを、FFI の実装のときに決める
- 変換先の優先順位（C の次に何を作るか）
- F64 のハードウェアが無い機器で、F64 のソフトウェアの演算を、ツールチェーンの soft-float ではなく Onsa の実装（`std.math` の musl の移植と同じ扱い）に差し替えること。FZ の扱いも含めて、全ての機器で同じ計算にできる（今は生成コードがソフトウェアで非正規化数を 0 にする、§15.5）
- クロスのビルドで、外部の C ツールチェーンを指定する形（マニフェストのキーか、探し方の規則）。今は外部のツールチェーンを要するクロスの `kind` は E0200（§15.3）
- `@fp(relaxed)` の flow の、`--backends all` での許容の値を flow ごとに指定する形。今は差を表示するだけで、合否には使わない（§13.4）。どの閾値が妥当かは、指定したい実例が出てから決める
- 超越関数をビット一致させる `std.math.exact`（Onsa 実装）を提供するか
- flow の状態からポインタを無くし、bulk 領域の中のオフセット（`U32`）で持つ案。ベースのポインタは export の wrapper が持つ。状態がポインタを含まない普通のデータになり、複製・退避・ホットリロード（IDE での需要がある）で扱いやすくなるが、C API と入れ子の bulk の作りを変える。言語の部分を固めた後で検討する（§12.4）
- `Map` / `Set` の鍵の要件。§6.3 は `Ord` を鍵に使うと書き、§4.3 は挿入順のハッシュ表としている。`Eq` + `Hash` にするか（第 2 期に `Map` を実装するときに決める）
- `init` のクロックの大きな配列（ウェーブテーブル）を bulk 領域に置く指定（今は `@mem(bulk)` を遅延線にだけ付けられる、§12.4）
- 検査の水準: 整数のオーバーフローの検査をターゲットの設定で外すか（Rust の `overflow-checks = false` に当たる `overflow = "wrap"`。panic しない実行の結果は変わらず、`onsa audit` に表示する）。組込みのターゲットで検査の費用を実測してから決める。添字の検査は外さない（C で未定義動作になり、メモリ安全性が崩れるため）
- 言語全体の変換（段階 2）の既知の差: 言語ごとの FFI、JavaScript の 64 ビット整数と文字列の性能、arena の枯渇（§13.5）
- 逃げるクロージャ（保存できるコールバック）、トレイトオブジェクト
- クロージャの捕捉のモード: 今は値のコピーで捕捉し、読み取り専用である（§5.3）。`move`（Affine の値を移して捕捉する）や `inout`（外側の変数を書き換える捕捉）を指定できるようにするか。クロージャは引数の位置にだけ現れる第二級の値なので、`inout` の捕捉も呼び出しの間だけのものとして安全に定義できる見込みがある。必要な実例が出てから決める。
  既定のモードの関数型の引数を、引数の位置の無名関数が捕捉する形（`array.from_fn(fn(i) { f.(i) })`）も、環境の寿命が呼び出しに収まるので開ける見込みがある（今は E0710、§5.2）。Shared 型の値を捕捉したとき、複製（参照カウントの増加）か借用か（§5.4）も第 2 期に決める
- async / await
- std 以外の依存: 取得元（パス、レジストリ、git など）、版の解決（菱形の依存で、同じパッケージの違う版を同居させるか）、`onsa.lock` の形。第 2 期に依存を入れるときに決める（パッケージの `tests/` の役割も、パスによる依存を前提にするので一緒に決める。この版では `tests/` の `.onsa` は E0200、§15.1）
- 延期（用途が出てから）: `Net` 効果、ユーザ定義型の反復（`IntoIter` の実装）、`Array` の `map` / `filter`、`@deprecated`、`onsa.policy`（§15.4）

### 19.2 実装しない機能（理由付き）

| 機能 | 理由 |
|---|---|
| Onsa からのスレッド・タスクの生成（`spawn`、`scope`、`Task`、`join`）と、ブロックする同期型（`Chan`、`Mutex`）、効果 `Spawn` / `Sync` | 用途（プラグイン、マイコン、worklet、CLI）のどれも実行の文脈をホストが与える。言語がスレッドを作ると、スケジューラで直列化される環境と意味が分かれる。文脈の登録（§16.1）で足りる |
| `Sleep` 効果 | 待機が要る用途が無い。時刻は `Clock` |
| `Str` の文字列処理（部分文字列、検索、文字の反復） | 文字列の用途は作る・比べる・出すだけ。必要になった API から足す（§4.2） |
| Rust の借用検査器、ライフタイム | §0.4 |
| トレイトオブジェクト、マクロ、遅延評価、高階型 | §0.4、§6.3 |
