## 19. 未決定事項と、実装しない機能

### 19.1 未決定事項

- マルチレート（§11.9）で決めていないこと: std の平滑とフェードの flow（S-579）、`fir_up2`・`fir_down2` の形（タップの数、遅れのサンプル数）と係数の値（仕様には形を書く。入れ子の `fir_up2~(fir_up2~(x)).up~(2)` の類が `sample * 4` と読めることを、仕様の例を一つ書いて確かめる）、`when~` を配る形の部品（出力が `sample * N` の配列の部品）に付けたときの「最後の出力を保つ」の意味、外で作った係数の取り違えの注意（`onsa audit`、S-569）、状態の配置（カウンタの欄）、ホットリロードの照合、graph と `onsa interface` の表示、後で `sample * N` を境界に開くときの生成する API（S-574）、範囲の構文、遅い制御の値と音声の値の区別、総称の flow（型引数）。
- `sample` の入力に struct を使うこと。struct の入力は今は E0810（§11.6）。flow の `block` の出力は持たず、エンベロープの終了通知などはイベントの出力で書く（§11.11）。
  必要になりうる場面は、struct を出力する flow を別の flow へそのままつなぐとき（`width~(pan~(x, p), w)`）で、今は `let s = pan~(x, p)` と受けて `width~(s.l, s.r, w)` と分解して書く。認めるなら、export の境界の形（`In` の中に入れ子の `Span`）を、実例に合わせて決める
- flow の直列の複製。`par` が全ての複製に同じ入力を配るのに対し、`ser i in a ..< b { e }` は一つ前の段の出力を次の段の入力に渡し、各段が別のインスタンスを持つ（FAUST の `seq` に当たる。名前は `par`（並列）と対の直列（series）から採り、シーケンサの名前に使われやすい `seq` を避けた）。一つ前の段の値を本体で受け取る構文は、機能を入れるときに決める。キーワードは予約済み（§2.2）。
- 後で足す修飾子の方向（§11.10）: 連鎖で呼ぶ利用者の修飾子は、宣言の `self` を頭にし（`flow random_when(self, p: F32 at block) -> F32 at sample { self.when~(…) }`）、頭以外の引数は値とする。
  flow の高階（flow を受ける flow）は、呼ぶ前の flow を名前で、型引数と同じ場所 `::[…]` に渡し（`branch::[saw, sin]~(f0, sel)`、宣言は `flow branch[flow a(F32 at sample) -> F32 at sample, …](…)`）、渡す flow ごとにコンパイル時に展開する（flow は第一級の値ではない、§11.6）。
  利用者の修飾子の本体の `self` は受け手になれる（利用者の修飾子を足すときに、§11.10 の受け手の規則に加える）。どちらの形も今は誤りなので、開いても今のプログラムを壊さない。宣言の語（`flowmod` など）は予約しない。
- イベント（§11.11）で決めていないこと: イベントのあった位置で真の脈の flow（`std.dsp`）の名前（候補に `pulse`・`trig`）。
- プラグインの出力（§14.3）で決めていないこと: プラグインの独自の画面（GUI、S-585）、`onsa audit` が示す構造から決まる遅れの形（S-586）、変調とボイスごとの変調とノートの表情（`note.Event`）、パラメータの変化をイベントの列で届ける形、`scale` と範囲の変更の凍結（§15.4、S-584）。
  CLAP の作業で決めるもの: ラッパーが呼び出しを分ける最小の長さ（密な自動化で `block` の段がサンプルごとに走るのを抑えるか。本物のホストで測って決める）、表示の文字列の形、フェードインの長さと形、状態の形の文法の字、`_init` が 0 以外を返したときのラッパーの振る舞い、スカラと `()` のイベントの入力のプラグインでの扱い、ホストが再生中に起動したときの `transport.Event`。
  候補: `_init` の失敗は起動を失敗として返す（§14.2 では復帰は `init` のやり直しだけで、起動に失敗したインスタンスは `_process` を呼ばれない）。スカラと `()` のイベントの入力はそのターゲットで E0200（ホストに写す元が無い）。再生中の起動は、ラッパーの初めの状態を停止とし、最初の呼び出しの位置 0 に `CONTINUE`（`beat` が 0 なら `START`）を写す。
  VST3・AU の作業で決めるもの: VST3 のクラスの ID の関数の中身、VST3 の隠したパラメータの ID の式と上限（`0xFFFFFFFF` は使わない）、AU の SDK の探し方（§15.3 の環境変数の例外を増やさない形）。
- 総称の型別名（`type Pair[T] = (T, T)`）。境界、`const` のパラメータ、使われないパラメータの扱いを、実例が出てから決める（§4.4）
- 単位の型と newtype。取り違えの検査が要る実例が出たら、newtype（`struct Hz(F32)`）と単位代数（F# の units of measure）を比べて決める。今は、名前付きのフィールドが 1 つの struct で書ける（§4.4）
- 固定小数点型（`Q15`, `Q31`、飽和演算）を標準ライブラリに置くか、言語に入れるか
- 利用者の型への `Float` の実装。今は組込みの浮動小数だけが実装する（§6.3）。開くときは、超越関数と `vdelay` の計算を型ごとに与える形（std の本体か、trait のメソッドか）を決める。制限を外す向きの変更なので、今の規則で書いたコードは壊れない
- 長いサンプル列を扱う遅延と読み出し（組込みのサンプリングルーパーなど）: 値の型（`F32`）と読み出す位置の型（`U32` か `F64`）を分ける。今は `vdelay` の `d` が信号と同じ型で、`F32` の信号では `MAX <= 2^24`（§11.4、48 kHz で約 349 秒）。整数の位置で補間しない読み出し、補間の計算の順（§13.4 のビット一致）、型の混ぜ方を含めて API を見直す。型の組み合わせを許す方向の変更なので、今の規則で書いたコードは壊れない
- enum（列挙子に中身の無いもの）の `block` の入力に `@param` を付けること。波形やモードの選択に使う。表示名（列挙子の名前か `label`）、値の番号（`Ordinal` の番号を使える、§6.4）、C の `Params` と `onsa_param_info` での表現を決める。今は E0809（§11.7）
- ファームウェアのエントリ: 割り込みとメインループの二つの文脈を提供する `target` モジュールの標準形（§16.1）。bulk を持つ flow の状態の持ち方も一緒に決める。
  今は Onsa の中から呼ぶ `init` に bulk 領域を渡す口が無く、bulk を持つ状態を `main` のローカルに置けない（E0819、§12.4）ので、bulk を持つ flow は C のホストから使う（§17.5）。方向の候補は、ターゲットが bulk 領域を与えて `init` が受け取る形と、登録の関数（`device.run`）が状態と bulk 領域の確保を引き受ける形
- ターゲット提供の「後回しの仕事」（サンプルの読み込みなど）: `std.worker.run_later(f, move arg)` のような文脈で、マイコンではメインループで直列に、デスクトップではスレッドプールで実行する案。言語は並列性を約束しない
- デスクトップのターゲットだけが `provides` する並列計算の効果（ライブラリとして。核には触れない）
- `Alloc` の確保失敗を、panic ではなく値として扱う API
- panic の地点の番号: `panic_messages = false` でも位置とメッセージを復元できるよう、ランタイムの panic の関数には地点の番号だけを渡し、番号から「ファイル・行・メッセージ」を引く表を `onsa build` がバイナリの外に出す（組込みの Rust の `defmt`、Zephyr の辞書式のログと同じ考え方）。番号の安定、表の形式、`onsa audit --panics` との関係を決める。今は文字列を除いて行番号を残す（§9.2）
- 補間の中の呼び出しと式。穴の評価順（§3.5）、効果、`!` / `inout` の呼び出し、panic の扱いを決める必要があるので、今は名前の経路だけ（§2.4）
- `panic` のメッセージに、組み立てた文字列（`"index {i}"`）を渡すこと。`Str` の実装と一緒に決める。rt の中では、組み立てにヒープが要る（§9.2）。`FixedStr`（§4.2）で組み立てた文字列を渡す形が候補である
- 静的なものだけを指す印。入れるなら、型ではなく束縛の状態（§5.4 の静的な値）と同じ側の印として、境界（フィールド、返り値、`var`、引数）にキーワード `static`（§2.2 で予約）で書き、本体で推論する（クロックが型でなく、`x: F32 at sample` と flow の解析の結果であるのと同じ形）。§6.5 の属性はコード生成の注釈なので使わない。
  実例（`FixedStr` と、`var`・呼び出しの結果・借用の `Str` の要素を緩める第 2 期の規則で書けない形。容量を決めない UTF-8 の名前を rt の状態に持つ、静的なものだけを受けると関数の境界で約束する、など）が出たら決める
- `Log` の `Span[U8]` を受ける rt の操作の名前（§8.2 の表）。第 2 期の `Log` の作業で、借用した `Str` を `Span[U8]` に渡せるか（`Str` の操作と一つに畳めるか）と一緒に決める
- ホットリロードで、型の変わったフィールドの扱い
- probe で見るためだけに名前を付け、出力には使わない信号。今は使われない束縛（E0309、§5.1）なので書けない。必要な実例が出たときに、印の形（属性など）を決める（`onsa probe`、§18.2）
- Onsa から `extern "C"` の関数（§14.1）を呼ぶ間の浮動小数の状態。export の入口ではプロファイルの環境に設定する（§15.5）ので、そのまま呼ぶと C の関数はその環境で動く。呼ぶ前後でホストの状態に切り替えるかを、FFI の実装のときに決める
- 変換先の優先順位（C の次に何を作るか）
- F64 のハードウェアが無い機器で、F64 のソフトウェアの演算を、ツールチェーンの soft-float ではなく Onsa の実装（`std.math` の musl の移植と同じ扱い）に差し替えること。FZ の扱いも含めて、全ての機器で同じ計算にできる（今は生成コードがソフトウェアで非正規化数を 0 にする、§15.5）
- クロスのビルドで、外部の C ツールチェーンを指定する形（マニフェストのキーか、探し方の規則）。今は外部のツールチェーンを要するクロスの `kind` は E0200（§15.3）
- `@fp(relaxed)` の flow の、`--backends all` での許容の値を flow ごとに指定する形。今は差を表示するだけで、合否には使わない（§13.4）。どの閾値が妥当かは、指定したい実例が出てから決める
- 超越関数をビット一致させる `std.math.exact`（Onsa 実装）を提供するか
- flow の状態からポインタを無くし、bulk 領域の中のオフセット（`U32`）で持つ案。ベースのポインタは export の wrapper が持つ。状態がポインタを含まない普通のデータになり、複製・退避・ホットリロード（IDE での需要がある）で扱いやすくなるが、C API と入れ子の bulk の作りを変える。言語の部分を固めた後で検討する（§12.4）
- `Map` / `Set` の鍵の要件。§6.3 は `Ord` を鍵に使うと書き、§4.3 は挿入順のハッシュ表としている。`Eq` + `Hash` にするか（第 2 期に `Map` を実装するときに決める）
- `init` のクロックの大きな配列（ウェーブテーブル）を bulk 領域に置く指定（今は `@mem(bulk)` を遅延線にだけ付けられる、§12.4）
- 検査の水準: 整数のオーバーフローの検査をターゲットの設定で外すか（Rust の `overflow-checks = false` に当たる `overflow = "wrap"`。panic しない実行の結果は変わらず、`onsa audit` に表示する）。組込みのターゲットで検査の費用を実測してから決める。添字の検査は外さない（C で未定義動作になり、メモリ安全性が崩れるため）
- 言語全体の変換（段階 2）の既知の差: 言語ごとの FFI、JavaScript の 64 ビット整数と文字列の性能、arena の枯渇（§13.5）
- 逃げるクロージャ（保存できるコールバック）、トレイトオブジェクト
- クロージャの捕捉のモード: 今は値のコピーで捕捉し、読み取り専用である（§5.3）。`move`（Affine の値を移して捕捉する）や `inout`（外側の変数を書き換える捕捉）を指定できるようにするか。クロージャは引数の位置にだけ現れる第二級の値なので、`inout` の捕捉も呼び出しの間だけのものとして安全に定義できる見込みがある。必要な実例が出てから決める。
  既定のモードの関数型の引数を、引数の位置の無名関数が捕捉する形（`array.from_fn(fn(i) { f.(i) })`）も、環境の寿命が呼び出しに収まるので開ける見込みがある（今は E0710、§5.2）。Shared 型の値を捕捉したとき、複製（参照カウントの増加）か借用か（§5.4）も第 2 期に決める
- async / await
- std 以外の依存: 取得元（パス、レジストリ、git など）、版の解決（菱形の依存で、同じパッケージの違う版を同居させるか）、`onsa.lock` の形。第 2 期に依存を入れるときに決める（パッケージの `tests/` の役割も、パスによる依存を前提にするので一緒に決める。この版では `tests/` の `.onsa` は E0200、§15.1）。
  再公開（`pub use`、S-596）も、パッケージの外の利用者のための仕組みなので一緒に決める（取り込めるのを項目だけにするか、モジュールとパッケージも再公開できるか、再公開した束縛を経路の途中に通すか、`onsa interface` の表示）。この版では E0200（§15.1）なので、開いても今のプログラムを壊さない。
- 延期（用途が出てから）: `Net` 効果、ユーザ定義型の反復（`IntoIter` の実装）、`Array` の `map` / `filter`、`@deprecated`、`onsa.policy`（§15.4）

### 19.2 実装しない機能（理由付き）

| 機能 | 理由 |
|---|---|
| Onsa からのスレッド・タスクの生成（`spawn`、`scope`、`Task`、`join`）と、ブロックする同期型（`Chan`、`Mutex`）、効果 `Spawn` / `Sync` | 用途（プラグイン、マイコン、worklet、CLI）のどれも実行の文脈をホストが与える。言語がスレッドを作ると、スケジューラで直列化される環境と意味が分かれる。文脈の登録（§16.1）で足りる |
| `Sleep` 効果 | 待機が要る用途が無い。時刻は `Clock` |
| `Str` の文字列処理（部分文字列、検索、文字の反復） | 文字列の用途は作る・比べる・出すだけ。必要になった API から足す（§4.2） |
| Rust の借用検査器、ライフタイム | §0.4 |
| トレイトオブジェクト、マクロ、遅延評価、高階型 | §0.4、§6.3 |
