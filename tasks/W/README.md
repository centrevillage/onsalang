# 作業（W）

第 1 期の反映の作業（段 W1〜W10）。一つの作業は、決定（S・D・K・Q）と R を実装に移す単位で、テスト・実装・壊す側の票で進める（`rules/process.md`）。
作業を足すのは親で、利用者と段の範囲を決めたとき。担う決定と直す R は、決定の `tasks` と R の `fix` に書き、作業のファイルには書かない（`docs.py show <ID>` が出す）。段の一覧と目的は [`../stages.md`](../stages.md)。

- 一覧は `python3 -B tools/docs.py list W`、段ごとは `list W --stage W4`。作業票の骨組みは `docs.py ticket <ID> <単位>/<役割>`。

## 頭の欄

| キー | 形 | 値 | 要る | 意味 |
|---|---|---|---|---|
| `status` | 閉じた値 | `PLAN` / `PENDING` / `DOING` / `DONE` | はい | 状態 |
| `size` | 閉じた値 | `S` / `M` / `L` | いいえ | 大きさ |
| `depends` | ID の並び（W、段） | — | いいえ | 依存（段はその段の作業の全て） |
| `marks` | 閉じた値の並び | `危険` / `メモ` / `基盤` / `テスト` / `テスト・壊す側` | いいえ | 役割の例外と印 |
| `doing` | 文字列の並び | — | いいえ | 出ている票 |
| `commit` | 文字列 | — | いいえ | 済んだときのコミット |

- `status`: `PLAN` は計画にある、`PENDING` は検討の結果今はやらない（本文に `保留（<日付>、<誰>）` の箇条）、`DOING` は票が出ている、`DONE` は済んだ。着手できるか（依存が済んだか）と決定待ちかは、道具が `depends` と決定の `tasks`・`before` から出す。
- `marks`: 表の「役割・印」は、`rules/process.md` 8.6 の役割の例外と印だけを書く（空欄は三つの票の組）。
- `doing`: `DOING` の中の票（`U2/i`、直しは `U2/i-fix1`）。

## 本文のラベル

`docs.py new W` は、この節のラベルを新しい W の雛形にする。

- `内容`: 何をするか。
- `単位`: 単位の分け方と、親の答え。
- `持ち越し`: 前の作業の報告などから入れること（出所の票と日付と一緒に）。作業が済んでも消さない。
- `結果`: 済んだときの一行。
- `保留`: `保留（<日付>、<誰>）` の形で、今はやらない理由。

## 反映の作業の表から移した W

W1-01〜W10-06 は、`docs/rework-phase1.md` §3 の表の行から移した（2026-10-17）。

- `実現する決定`: 表の「実現する決定」の欄（ID 以外の修飾を含むので本文に残した。関係の正本は決定の `tasks` と R の `fix`）。題は表の「作業」、`内容` は「内容」の欄。
- 頭の欄は表から道具で埋めた。✅ → `DONE`（他は `PLAN`）、規模 → `size`、依存 → `depends`（同じ段の範囲は ID に開いた）、役割・印 → `marks`（〔〕を外した）。W3-13 の「基盤（U3）」は `marks` の `基盤` と `単位` の箇条に分けた。済んだ作業の `commit` は書いていない（`git log --grep <ID>`）。
- `持ち越し` は、持ち越しの文書（`docs/carryovers.md`）の頭が W の ID の項目を、字を変えずに移したもの。
