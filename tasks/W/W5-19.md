# W5-19 std の解析の事前計算（プリコンパイル）: 一回ごとの検査が std を解析し直す費用を除く

- 内容: 一回だけの `onsa check` と、プロセスごとに回る命令は、毎回 std を構文解析して解析し直す（W5-18 の使い回しはプロセスの中だけに効く）。その費用は std の大きさに比例し、W5-14 U1 で std の関数が 176 から 221 になると `compare.py speed` の `check` が約 +28 % になった（一回の空の入力は debug で 12.0 → 15.6 ms）。W5-03・W5-05・W5-06 で std はさらに増える。
  std の解析の結果を事前に作って使う仕組み（プリコンパイル）で、この費用を除く。形の候補: (P1) コンパイラのビルドの時に std の解析の結果（W5-18 の `Base`）を作り、直列化してバイナリに埋める。(P2) 初回の実行で作ってキャッシュのファイルに置き、次から読む。(P3) 事前計算でなく、普段の検査で std の本体の検査を省き、std の正しさは gate で確かめる。
  使い回しの側の基の写しの費用（W5-03 の持ち越しの C3）も同じ設計で扱う。
- 決定の範囲: X-20、W5-02 の D7（106 回目、std の検査の費用は解析の使い回しで）の続き、110 回目の利用者「プリコンパイル的な仕組みが必要と見ました」。
- 単位: U1 読むだけの設計メモ（形の比べ: 直列化の形と行数、読み込みの時間と今の解析の時間、std とコンパイラの版の一致の確かめ、IDE とブラウザ（WASM）での扱い、出力の決定性、`Analysis` の型が変わるたびの保守）→ 残りの単位はメモで決める。
