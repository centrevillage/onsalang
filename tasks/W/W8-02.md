# W8-02 検証器の規則

- 内容: `design/04-core.md` の規則のうち V-01〜V-08・V-20（ID の範囲）・V-22（式と文の深さ。降下の直後と driver の検証で数える）と、役割つきの子の列挙（`walk.rs`）を、規則ごとの否定のテストと一緒に入れる。V-09・V-10・V-21・V-23・V-24 は W8-03、V-11・V-12 は W8-04、V-13・V-14 は W8-05、V-17 は W8-07、V-15 と V-16 はターゲットの pass の後の規則なので W9-04 と W9-05（番号の割り当ては W8-01 の設計メモ部 1 の 9 章、191 回目の親の判断）。release でも段の境目ごとに常に動かし、失敗は内部エラー
- 決定の範囲: R-82 (1)(2)
- 持ち越し:
  - **W8-01 の設計メモから（2026-11-27、191 回目）:** 部 1 の 9 章（規則の割り当て）・6.2（子の列挙）・7.2（深さの規則 V-22 と `CORE_DEPTH_LIMIT` の測定）と、部 4 の 2.4（`lower/flow/branches.rs::every` を二分の木に、V-22 の前に）を読む。入れるのは V-01〜V-08・V-20・V-22 と、役割つきの子の列挙（`walk.rs`）。番号 V-25 からは各作業が足す（部 4 は V-25〜V-28、部 2 は V-29〜V-33）。
    W8-14 と W8-16 の後。S-224 の判断の (2) の前提（R-319 の式の側）は V-22。
  - **W8-02:** 検証器が範囲外の ID（`FnId(999)`、`ConstId(999)`）で panic し、`TypeId(999)` を素通りする。
    - 規則の一覧に ID の範囲を入れる。
    - `onsa_core::lower` / `lower_with` / `verify` が pub のままで、driver の段の関数を通らずに呼べば検証を飛ばせる。
    - gate に「呼び出しは driver の一か所」の検査を足す案。
    - release でも常に検証し、CLI の `verify_core_in_debug_only` を消す。
