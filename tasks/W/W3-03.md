# W3-03 診断の単位と回復

- 内容: 診断の単位は宣言。構文の誤りがある単位では本体の名前解決と型検査をしない。失敗した項目を AST から消さない。構文の診断の有無を明示のフラグで持つ。命名の検査は根から辿れるノードだけ。
  fmt と `diff --ast` を止めるのは構文の段の診断（コードによらない。予約語の E0200、値を持てない整数リテラルとタプルの添字の E0408、E0006 を含む）で、報告は `check` と同じ選び方（単位ごとに一つ）。
  単位の中の選び方は、依存する段の間では先の段の誤りを報告し、構文の誤りがある単位では見出しの命名の誤り E0320 も報告しない（S-214。`check` の `first_per_item` を位置でなく段の順で選ぶ）。`SPEC-GAP(S-214)` の印を外し、`fmt_syntax_failures.rs` で E0408 のファイルの終了コード 2 を確かめる。
  全てのコマンドで、診断は標準出力、診断でない文は標準エラー（fmt の構文の診断を標準出力へ。`crates/onsa_cli/tests/fmt_many_files.rs` の標準エラーの検査を改める。S-232、`spec/tools.md` §4）。fmt の止めたときの報告と複数のファイルの扱いは `spec/tools.md` §3.1。
  項目と同じ行の後ろの `;`（`const A: Bool = 1;`）は、その項目の単位に入れ、項目の構文の誤りにする（S-254、K-19）。どの項目にも入らない余分なトークンのひと続きは、次の項目の始まりまでで、行をまたいでも一つの単位（S-259）
- 決定の範囲: S-120 の fmt の部分
