# W4-02 マニフェスト

- 内容: キー・値・既定の閉じた表（E1101〜E1104）、未知のキーはエラー（旧名のキー `numeric` なども他の未知のキーと同じ E1102 で、専用の修正候補は無い）、`platform` は C かネイティブのコードを出すターゲットで必須で、要否はそのターゲットのビルドで検査する（E1104）、`prefix` の必須と形（C の名前は W10-02）。
  マニフェストの E0200 の扱いと終了コード、上の階層へ探す。パッケージ直下の `tests/` は E0200。命名とファイル・モジュールの対応。
  マニフェストの無い単一のファイルとパッケージの中のファイルの名前に §2.3 のモジュールの名前の規則を当て、違反は E0320（候補なし、note でファイル名を `snake_case` にすることを示す、位置はファイルの先頭。今は `My-File.onsa` も通る。S-300）。`onsa test` にパッケージの中のファイルを渡すと、そのファイルのモジュールのテストだけを選び（`--filter` と重ねて絞る）、走らせるのを止める診断はファイルによらず全て出す（§15.1 の「そのファイルの診断だけ」は `check` と LSP の規則）。
  選んだテストが 0 件なら 0。マニフェストの無いファイルを複数渡すのは使い方の誤り（終了コード 2。同じファイル名のモジュールのテストが黙って消える R-189 を塞ぐ）（S-286）。テストのマニフェストを今の形に書き換える（`numeric` など） S-311: `--filter` の照合はパッケージ全体で、ファイルの指定は絞るだけ（0 件なら 0）。
  S-312: パッケージを読むコマンドの経路は一つ（`read_input` が一つの経路からルートを探す。`sig.rs` の `build_module_tree` の上書きは内部エラーに。`check_json_document.rs` の 3 件を書き換える）。
  R-189 は記述より広い（同じ経路のモジュールを丸ごと置き換え、`check` の診断も消える。第 11 組の付録）。 S-313: ディレクトリの名前の E0320（一つのディレクトリに一つ、位置は下の最初のファイル）、`.` で始まるディレクトリは集めない、モジュールの同一性は経路の要素の並び。
