# W10-01 export の計画

- 内容: ターゲットの pass の後に、シンボル・API と入出力の形・配置への参照・`@param`・panic の扱い・関数のシグネチャを一度だけ記録する段を置く。C・WASM・JS・`play`・IDE は計画を読む。シンボルは `prefix` + 名前。flow が生成する名前の閉じた集合（§14.2 の表）から flow ごとの名前の集合を作り、重なりを E1011 で判定する。
  export する項目は宣言の `@export` の印から読む（S-639。マニフェストの `flows` / `fns` は W4-02 で外す）。`onsa interface` に doc コメントを出す。C の型の登録と export の E0200 に原因の位置を付ける（R-138）
- 決定の範囲: R-89 (1)、S-112 の E1011、R-63 の interface
- 持ち越し:
  - **W10-01:** 手順の器の `onsa_tests::capi` は、`<symbol>_init` / `_reset` / `_process` / `_params` と `<UPPER>_SIZE` などを §14.2 の接尾辞で組み立てている（バックエンドの `export.rs` と出どころが二つ。W1-11/b の 5 (d)）。
    - export の計画が全ての名前を記録したら、capi はそこから読む。
    - flow の生成する名前の重なり（`poison_boundary.onsa` で `boom` の `pb_boom_init` と flow `boom_init` が重なった例）を E1011 の否定例に入れる。
  - **X-7 から（2026-10-23、53 回目、利用者が X-7 の全てを第 1 期に入れると決めた）:** export の計画に、イベントの入出力と `@host` の入力を記録する（W10-07・W10-08 が読む）。
    境界のイベントの型の E0810（S-572）と、一番外の flow の `sample / N`・`sample * N` の E0810（S-574。誤りの位置は `process`・`process_inplace`・`render` を使う所と `@export` の印）。`onsa interface` にイベントの入力と番号を出す。
  - **第 51 組から（2026-10-24、61 回目）:** S-639: export の計画は宣言の `@export` の印を読む（W4-02 が `@export` を入れた後）。export される項目の集合はパッケージごとに一度作り、`check` の宣言の検査と export の計画（ターゲットごと）が同じ集合を読む（D-15）。依存のパッケージの `@export` は出さない。
    境界の型の E0810（S-572、S-574）は `onsa check` が宣言の位置で出す（S-632・S-639）。S-574 の誤りの位置は `@export` の印。R-138 の位置（C の型の登録と export の E0200）は `@export` の宣言になる。export する関数のシグネチャの誤りのコードは S-640（期限 W10-01）。
    下の X-8 からの持ち越しの `[export]` の経路の E0302 / E0303 の位置は、経路が無くなるので当たらない。`onsa interface` に `@export` を出す（§18.2）。
  - **X-8 から（2026-10-23、54 回目）:** W4-02 から: `[export]` の名前の誤り E0302 / E0303 は、位置が `FileId(0)` の 0 バイト目でマーカを書けない。`onsa.toml` と断片の中の位置にする（S-165 の E1103 と同じ道具。W4-02 がマニフェストの全ての値の位置を持つ）。
