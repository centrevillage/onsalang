# W2-06 検査を通って落ちる入力

- 内容: 決まらない型パラメータ E0406、リテラルパターンの範囲（補間を含む文字列のパターンは W3-07、S-225）、`-(I32.MIN)` の畳み込み。宣言どうしの閉路（E0311、E0312、E0817）は W4-05、`par` の look-back は W7-04（K-03、K-10）。総称の呼び出しの型パラメータを関数の終わりまで待つ（S-174）。
  前置の `-` を含めた範囲の検査（S-184）。パターンの負の整数（S-185）。前置の `-` を値に含めるのは、括弧を除いた被演算子が整数リテラルそのものであるもの一つだけで、`-(-x)` の外側は値の否定（S-227。`-(-1): U32` の E0401 は内側のリテラルに、R-163）。
  const 引数・配列の長さ・遅延線の長さ・`par` の端の前置の `-` は E0401（S-228。`Ring[F32, NEG]` も、R-154。`negative/const_args.onsa:19` の期待値を E0401 に）。「解決済み」は型の頭が決まっていること: 型引数の中の型変数と空の `[]` の要素の型は後の文で決め、残れば型変数を作った式に E0406。
  パターンの中のリテラルと列挙子を対象の型引数と単一化する（S-226、R-157）。後で決まる型パラメータの要求（境界、暗黙の `Dup`、演算子の trait、種の制約）は、型変数が無くなった文で検査し、関数の終わりは既定を当てた後で検査する。E0416 は要求を生んだ式に出し、型を決めた式を位置付きの note で示す。
  型変数が残れば要求は検査せず E0406 / E0405 だけ（S-235）。後回しにした検査の報告の順は、文の中の誤りが先、同じ時点の項目は検査が作った順（被演算子が演算子より先）で、後で型が決まる `-(-1)` も内側の `-1`（S-255。この作業の実装を仕様に書いた）
- 決定の範囲: S-185 の負の整数
