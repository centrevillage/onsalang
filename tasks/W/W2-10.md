# W2-10 テストの識別

- 内容: Core の関数にテストの印を持たせ、テストをモジュールの経路と名前で識別する。`onsa test` の `--filter` と `--json` の `"module"`。`onsa test --json` の出力を S-215 の一つのオブジェクトにし、テストの結果の欄を足す。
  テストの記録の `span` を §18.1 の形にする（R-162）。`diagnostics` の欄は W3-16 の形を使う。`tests` の記録は `module`・`name`・`status`（`ok` / `failed`）で、失敗のときだけ `failure`（`message`、panic した位置の `span`、テストの本体まで遡る呼び出しの位置の並び `calls`）。`kind` を外す。
  テストを走らせなかったときは空の配列、並べ方は `module`、次に `name`。`calls` のために、インタプリタの枠に呼び出しの位置を持たせる。パッケージの外のファイルの `span.file` は `std/dsp/test.onsa` の形。
  結果のテキストの行にモジュールを入れる（`spec/tools.md` §4）。`crates/onsa_cli/tests/deep_recursion.rs` の `json_output_of_a_deep_recursion` の `"kind"` の検査を `tests` と `"module"` の検査に改める（S-233）。`--filter` は完全な名前のテキストの部分一致で、一つも当たらなければ終了コード 2。`--filter` の照合を、検査の誤りと変換先によらない E0200 の後、実行の前に置く（届く範囲の E0200 は W2-13、S-242）。`assert_near` を `a == b || abs(a - b) <= tol` にし、`tol` が有限で負でない値でなければ比べずに失敗、NaN は失敗にする。
  失敗の文面の値を §6.3 の `Show` で書き（`spec/tools.md` §4）、文面を `std/dsp/test.onsa` の doc コメントに書く（S-241）。`test` の名前は空でない、補間を含まない文字列リテラルで、値に制御文字（改行とタブを含む）、U+2028 / U+2029、双方向の制御文字を含めない。
  違反は構文の段の E0002 と note で候補なし（今の `test "a{X}b"` の E0001 と、式の補間の文面を改める）。同じ名前は値で比べ、正規化しない（今の実装どおり）。完全な名前のテキストのエスケープは `\`、`"`、`{`、`}` の四つ（S-244）
- 決定の範囲: S-215 の `test`、S-242 の `--filter`
