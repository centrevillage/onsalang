# W4-20 `par` を `par~` に改名（S-745）

- 内容: flow の構造の複製を `par~ i in a ..< b { e }` と書く（S-745、`if~`・`match~` と同じ `~` の印）。`~` は `par` の直後に空白なしで書き、`par ~` は E0020 で空白を除く候補。
  flow の本体の `~` の無い `par` は E0811 で `~` を足す候補、flow の外は `~` の有無によらず E0821。`par` は予約語のまま。状態を持つものを含まない `par~` も誤りにしない（E0812 を当てない）。状態のノードの名前は `par_0` のまま。
  §19.1 の予定の形を `ser~` にする（`ser`・`ser~` とも E0200）。仕様の文（約 44 か所）は、この作業で実装と同じに改める。事例（`.onsa` 約 137 ファイル・337 行）と golden は台本で置き換える。
  字句のキーワードの表、構文、診断の文と候補、fmt。決定・作業の文のうち今の形を書いた所も改める（`history/` は変えない）
- 決定の範囲: S-745
- 単位（100 回目）: 一つ（U1）。実現する決定は S-745 の 1 件で、単位の目安に収まる。親が仕様を改め（未コミットのまま、実装と同じコミットにした）、テストの担当が作業ツリーで新しい規則の事例を、実装の担当が主のツリーでコードと既にある事例の置き換えを並べて行った。
  - U1（済み、`10c4afa2`）: テストとデータを除いて +97 −66（着手の前の見積もり約 40、票の見込み 70、止まる線 150）。
    構文（`branch_tilde` で `par` の直後の `~`、AST の `tilde`）、表の `space_after_branch_keyword`（`Branch::Replication`、`!` の形を並べない）、名前の段の E0811（`par_without_tilde`）と E0821 の位置（`par_head`）、文言、fmt、図のラベル。
    置き換えの台本 `target/notes/100/w420/i/rename.py`（205 ファイル・635 か所、`tests/fuzz/` は外した）。新しい事例 30 件（うち 2 件は W7-04・W7-06 の実装待ち）。決定の 3〜5 は事例 `e0200_ser_*`（`ser~`）・`par_tilde_stateless`（E0812 を当てない）と、名前を変えない状態のノード（`par_0`）の既にある事例で確かめた。壊す側は高・中なし。
  - 親の読み: `~` の無い `par` の E0811 の位置は `par` の 3 字（仕様が約束しない細部。呼び出しの E0811 に倣う）。一つの flow に `~` の無い `par` が二つある事例は、候補の後に残る二つ目を `[[test.fix]]` の `leaves` に書いた（親が足した）。
    決定の S-151・S-257・S-393 の `提案`・`空白` の `par i in` はその時の記録として変えず、今の形を書いた開いた作業（W5-08・W7-04）と R（R-03・R-16・R-195）だけを改めた。
    `~` を読むのが構文・表・fmt・降下の四か所にあるのは層ごとの読みで、同じ判断の重複ではない（壊す側の低 3。`!` を並べるかの判断は親が `Branch` に寄せた）。
  - 壊す側の低 1（前の位置の E0801 と `^` の名前が、名前の段の E0811 に負ける）は R-286 の補い（W7-04 で直す類）、低 2（図のラベルのテスト）は親が `graph.rs` に足した。
