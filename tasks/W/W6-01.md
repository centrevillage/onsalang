# W6-01 関数型の互換と無名関数の効果

- 内容: 引数と返り値は等しく、効果行は含まれる関係、`rt` は同じ向き。無名関数の効果を期待する型の効果行で照合する。効果行の変数は宣言の時点で E0200
- 決定の範囲: R-27 (1)(2)(3)、S-190 の関数型の互換（モードは型の一部。第二級の規則は W4-11）
- 持ち越し:
  - **第 1 期の効果行変数（2026-11-13、144 回目、利用者が了承）:** R-27 (3) のとおり、効果行変数の宣言（関数・メソッド・struct・enum の `[…, e]`）を E0200 にする。最初の小さな単位にすると、残りの単位は変数を含む効果行を考えなくてよい（独立のレビューの段 1、`target/notes/144/r27/`）。
    - E0200 は、名前の段の誤り（E0320・E0304・E0602・E0308・E0302）を隠さない位置に出す（型の段の署名の診断か、`sig/impls.rs` の `name_reported` の先例）。名前の段の位置の順に並べると、効果行変数の名前の規則の事例（約 46 単位）と `tests/spec/fixes/e0320_*.onsa` の候補が見られなくなる。
    - E0200 にした宣言を使う側には、その効果行に頼る診断（今の E0401「`uses {<0>}`」と E0406）を出さない。型引数の数（S-982 の E0412）は今のまま判定する。
    - 事例: 宣言する約 80 単位のうち、期待する診断の無い約 34 単位（16 ファイル。`target/notes/144/r27/effvar_kinds.txt` は誤りの無い 10 ファイルと誤りの 19 ファイル）に `//~ E0200` を足す。`tests/spec/fmt/lists_types_attributes.onsa` と `tests/spec/types/interface_impl_method_params.onsa` は個別に見る。
      実装待ちの 4 項目（`types/type_args_fn_effect_row.onsa`・`type_args_method_effect_row.onsa`・`type_args_fn_effect_row_declared.onsa`・`type_args_method_effect_row_declared.onsa`）は、宣言に E0200、呼ぶ側は診断なしの形に書き直して木に残し、一覧から外す。
    - 包含（R-27 (2)）は変数の無い効果行（空と `{Alloc}`）だけで書く。第 2 期に効果の多相を入れるときの持ち越しは `tasks/phase2.md` の効果行変数の項。
  - **W5-13 の前の洗い出しから（2026-11-12、140 回目、利用者が送り先を了承）:** M5（`target/notes/140/w513_survey/survey.md`）: `sig::Sema` が「宣言を集めて署名を下ろす段の状態」と「本体から呼ぶ型式の下ろし手」を兼ね、空の `flat` が「本体から」の印になっている（`sig/types.rs` の `lower_type_in_body`・`lower_args_in_body`、`flat.is_empty()` の分岐 3 か所、診断を長さの印で切り出す形 5 か所）。関数型の下ろしを触るときに、下ろしの文脈 `Cx` に「署名か本体か」と診断の受け皿を持たせる形を見る（+50 −40 の見当）。
  - **W6-01（12 回目、W3-06/t3）:** 名前の付いた純粋な関数を `fn(I32) -> I32 uses {Alloc}` の引数へ渡すと E0401「expected `fn(I32) -> I32 uses {Alloc}`, found `fn(I32) -> I32`」になる（`fn apply(f: fn(I32) -> I32 uses {Alloc}, x: I32) -> I32 uses {Alloc} { f(x) }` に `apply(double, x)`、`let` で束縛した無名関数も同じ）。
    - §8.1 の関数型の互換の 2（純粋な関数は `uses {Alloc}` の位置で使える）に反する。
    - R-27 の (2) の未実装で、この形を W6-01 のテストに入れる（親が dev の `ade4450` で確かめた）。
  - **第 80 組から（2026-11-04、110 回目、利用者が了承）:**
    - 期待する型の無い合流（`let f = if c { Hold.C } else { k }`、`Hold.C` は `rt`、`k` は `rt` でない）の型は、`rt` を落とした関数型にする（`rt fn` は `rt` でない位置で使える、§8.1 の規則 3）。
      今の実装は先の腕の型を取り、`rt fn` の中で上の `f.(1)` が通る（腕を入れ替えると E0901。R-26 の族、再現は `target/notes/110/g80/parent/if_merge.onsa`）。S-872 で構築子の関数値の引数が `move` になると、`move` の引数の関数との合流もモードが揃って `rt` の差だけになる。
    - R-26 を直して `rt fn` の位置の無名関数の本体を `rt` の規則で検査するとき、捕捉した Shared の値の扱いを決める。§5.4 の表は、捕捉が複製なら環境の破棄が `Alloc` を要し、`rt fn` の位置の無名関数は Shared を捕捉できないとする（複製か借用かは第 2 期）。第 2 期の決定まで保守的に拒むか（E0712 の側）を、この作業で決める。
      S-873 で `map_err` は `rt` でないので、当たるのは利用者の `rt fn` 型の引数に渡す無名関数だけである。
    - Copy の引数の型の `fn(T)` と `fn(move T)` の互換は S-874（この作業の前に決める）。
