# W6-01 関数型の互換と無名関数の効果

- 内容: 引数と返り値は等しく、効果行は含まれる関係、`rt` は同じ向き。無名関数の効果を期待する型の効果行で照合する。効果行の変数は宣言の時点で E0200
- 決定の範囲: R-27 (1)(2)(3)、S-190 の関数型の互換（モードは型の一部。第二級の規則は W4-11）
- 持ち越し:
  - **W6-01（12 回目、W3-06/t3）:** 名前の付いた純粋な関数を `fn(I32) -> I32 uses {Alloc}` の引数へ渡すと E0401「expected `fn(I32) -> I32 uses {Alloc}`, found `fn(I32) -> I32`」になる（`fn apply(f: fn(I32) -> I32 uses {Alloc}, x: I32) -> I32 uses {Alloc} { f(x) }` に `apply(double, x)`、`let` で束縛した無名関数も同じ）。
    - §8.1 の関数型の互換の 2（純粋な関数は `uses {Alloc}` の位置で使える）に反する。
    - R-27 の (2) の未実装で、この形を W6-01 のテストに入れる（親が dev の `ade4450` で確かめた）。
  - **第 80 組から（2026-11-04、110 回目、利用者が了承）:**
    - 期待する型の無い合流（`let f = if c { Hold.C } else { k }`、`Hold.C` は `rt`、`k` は `rt` でない）の型は、`rt` を落とした関数型にする（`rt fn` は `rt` でない位置で使える、§8.1 の規則 3）。
      今の実装は先の腕の型を取り、`rt fn` の中で上の `f.(1)` が通る（腕を入れ替えると E0901。R-26 の族、再現は `target/notes/110/g80/parent/if_merge.onsa`）。S-872 で構築子の関数値の引数が `move` になると、`move` の引数の関数との合流もモードが揃って `rt` の差だけになる。
    - R-26 を直して `rt fn` の位置の無名関数の本体を `rt` の規則で検査するとき、捕捉した Shared の値の扱いを決める。§5.4 の表は、捕捉が複製なら環境の破棄が `Alloc` を要し、`rt fn` の位置の無名関数は Shared を捕捉できないとする（複製か借用かは第 2 期）。第 2 期の決定まで保守的に拒むか（E0712 の側）を、この作業で決める。
      S-873 で `map_err` は `rt` でないので、当たるのは利用者の `rt fn` 型の引数に渡す無名関数だけである。
    - Copy の引数の型の `fn(T)` と `fn(move T)` の互換は S-874（この作業の前に決める）。
