# W8-03 正規化と評価順

- 内容: 正規形 R1〜R4。評価順（左から右、代入は右辺が先、添字は基の後、短絡、引数を全て評価してから呼ぶ、panic は順で最初のもの）。
  範囲の端は `a`、`b` の順に一度（S-188）。`for i in a..=b` は終わりを先に比べてから増やす降下にし、`b` が型の最大値でも溢れずに終わる（W3-18 の `for` の `..=` の E0200 `InclusiveRangeFor` を外し、`tests/spec/negative/range_inclusive_for_e0200.onsa` を意味の事例に置き換える、S-257）。
  始点が終点より大きい `..=` は最初の比較で 0 回（S-219。新しい比較は要らない。`tests/spec/control/` に `a > b` と `1..=n` の `n = 0` の事例を足す）
- 決定の範囲: R-81 (1)、S-257 の `for` の降下、S-219 の `..=`
- 持ち越し:
  - **S-1264 の決定から（2026-11-27、191 回目、利用者「(a)で良いですが、実行性能を落とさないよう注意して」）:** 代入は §3.5 のとおり右辺が先。範囲の検査が要る添字を含む代入先と、要素を作った後に `?`・`return` で抜けうる右辺では、正規化が右辺を一時に作ってから写す。性能の約束（決定の P1・P2・P4）:
    - P1 一時に作るのは、宛先が範囲の検査を持ち、かつ右辺が panic しうるか何かを書きうるときだけ（右辺が純なら直接）。
    - P2 範囲内と決まる添字（定数、`for` の添字、降下が作る `par`・`par~` の `init`・`reset` と遅延の書き位置）を正規化の前に検査付きにしない形にし、今の C が直接作る降下の生成コードに一時を入れない（§9.2 の検査の除去。W8-01 のメモで置き場所を決める）。
    - P4 単位の受け入れに、`examples/`・std・事例の生成した C の写しの数（`audit --memory`）、`audit --stack`、`compare.py speed` の前後を入れ、増える所は一つずつ説明する。
    - 評価順の事例: `target/notes/191/g121/`（下書き `draft.md` の「当たる形」の 3・13〜17、段 1 の「添字の後にフィールド」「添字の式が panic」「場所の写し」「総称」）。R-93 の補いと同じ。
  - **W8-13 から（2026-11-26、191 回目、壊す側の中 1）:** 値を出す `assert`（S-1261）の降下は、効果のある被演算子があると左から順に一時の局所変数 `__shown` に置く（`lower/body/mod.rs` の `assert_comparison`）。一時は C にも出て、`rt fn` の中の `assert a == big(b)`（`a: [F32; 64]`）では効果の無い左辺の集成体まで写す（`onsa_arr_f32_64 onsa__shown_6 = (*a);`。再現 `target/notes/191/w813/b/c1/`）。評価順を正規化するとき、この一時を正規形の一時に寄せ、写しが要るのは右辺の効果が左辺の場所を変えうるときだけにする（W8-04 の借用の束縛と合わせて）。
  - **W5-13 の前の洗い出しから（2026-11-12、140 回目、利用者が送り先を了承）:** K13（`target/notes/140/w513_survey/survey.md`）: C の後端が出力した C の字から構造を推し直す族（`emit/fns.rs` の `is_stable`・`names_result`・`condition`・`dot`・`c_param_name`、`assign_into` の `"(*out)"`）。R-438 は W5-13 U3（`cd9d7ef0`）で狭く直した。根（R-81・R-93）はこの作業の正規形で除く。
