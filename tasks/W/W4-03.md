# W4-03 名前の段: 収集と `use`

- 内容: `sig.rs` を収集・`use`・署名の型・flow の生成項目の段に分ける。`use` は絶対経路で独立に解決し、モジュールの間は依存の順。`use` を必須にする。可視性（`pub` / 無指定 / `priv`、フィールドは struct を継ぐ）とメソッドの可視性。公開の宣言に書ける型。
  演算子 trait・標準 trait・`Copy`・`Dup` を prelude へ（暫定の `Bound` も同じ名前で引く）。std の `effect` 宣言と prelude、効果の名前の解決。
  ルート直下のモジュールの名前か、モジュールを含むディレクトリの名前が依存のパッケージ名（`std` を含む）と重なれば E0304（`std.onsa` も `std/math.onsa` も。同じ場所の `a.onsa` と `a/` は重ならない。S-37、S-246）。別のモジュールから取り込んだ総称の型の型引数の数は、定義の型パラメータから数える（R-197）
- 実現する決定: R-84 (1)(2)(4)、S-78、R-50、S-37、R-39、S-36、R-106、S-35、R-38、S-144、S-107、C-15、S-74、R-129、S-246、R-197
- 持ち越し:
  - **W4-03（20 回目、W3-08）:** `onsa interface` は無指定の項目を並べない（W3-08 は無指定と `priv` をどちらもモジュールの中として扱う。`resolve.rs` の `visible` の注記）。無指定がパッケージ内に見えるようにするときに表示を決め直す。`std/test.onsa` の `Gen.seed` を `priv` にする（S-36）。
  - **W4-03（9 回目）:** パターンでのフィールドの可視性の検査が無い（`body.rs`・`flow.rs` のどちらにも無い。W3-21/i の報告。`priv` のフィールドの構文は W3-08）。別のモジュールの `priv` のフィールドをパターンに書くと誤りにする。S-366 の「見えないフィールドが残る `..` は E0410 と note」もこのとき確かめる。
  - **W4-03（9 回目、追記）:** `FieldDef::vis` は書いた可視性で、無指定は `Private`（§15.1 の「struct の可視性を継ぐ」と合わない。W3-21/i の報告）。`structpat.rs` はフィールドの可視性を struct の可視性と見なしている。
  - **W4-03（13 回目、W3-04/i）:** std の自分のパッケージ名での参照 3 か所（`std/dsp.onsa` の `use std.math.{pow}`、`std/dsp/test.onsa` の `use std.math.{cos, sqrt}`、`std/test/gen.onsa` の `use std.test.{Gen}`）が S-37 の決定（自分の名前で参照しない、`use test.{Gen}` にする）のまま直っていない。
    - 自分のパッケージ名での参照の E0302（R-106）を入れる回に直す。
    - W3-04 で `use` の経路の頭のキーワードを名前として読むようにしたので、std の中で `use test.{Gen}` が解決できることは W3-04/i が確かめた。
