# W3-15 E0020 の規則の表

- 内容: E0020 の検出を `onsa_syntax::foreign` の一つの規則の表に集める（行は検出の段・文脈・見つけた書き方・修正候補の作り方・note の正しい規則を持つ）。
  構文の段の行は、構文解析器の誤りの入口で表に問い合わせ、構文解析器に書き方ごとの分岐を置かない（構文の段の E0020 は項目を失敗させる、R-87 (4)。読み替えて続ける作りと、そのための `NodeKind`・低下の読み替え・位置の癖を消す）。正しく読めてしまう型名（`i32`）だけ差し込み口を置く。
  今の字句解析器と構文解析器の E0020（約 25 か所）を表へ移し、移すときに今の候補の誤り（ブロックコメントの候補が後のコードを巻き込む、`&mut T` の候補がモードを失う、`;` を消すと二つの文が一行につながる）を直す。名前・型・flow の段は表の行を引いて報告する形にする。
  表に S-191 の三つの段、S-185、S-186、S-203 の行を置く（検出は S-203 が W3-06、S-186 と S-191 の構文の段が W3-07、名前の段が W4-12、型の段が W5-02、S-185 が W5-09）。`..=` は正しい書き方になったので、今の `..=` の E0002 と note は表へ移さない（S-257。範囲の構文は W3-07）。
  sema の浮動小数のパターンの E0002 を E0020 に（S-109）し、浮動小数のリテラルのパターンは構文の段の行にする（S-252。浮動小数の型の定数のパターンは型の段の行で、検出は W5-09）。修正候補の編集は変えるトークンだけを置き換える最小の編集にし、間のトークンとコメントを範囲に含めない（S-251。`<T>` は `<` と `>` の二つの編集）。
  ガードの形の候補が新しく置く束縛の名前は見えている名前と重ならないものにし、テストは `.fixK` でなく「当てた後が検査を通る」性質で確かめる（S-253）。後の作業が行を足す手順を表のモジュールの doc に書く。表に S-225 の行（補間を含む文字列のパターン、検出は W3-07）を置く。ブロックコメント（S-247、R-174）: 字句解析器は `*/` を行をまたいで探す。
  閉じたものは E0020 で、候補は言葉を `//` に残し、コメントの外のトークンの並びと行の切れ目を変えない（その場か、始まる行の上の独立した行）。`/** */` は付けられる宣言が続けば `///`、無ければ `//`（継続行の ` * ` は剥がない）。`/*! */` はファイルの先頭なら `//!` と `///` を並べる。
  閉じないものと入れ子は候補なしの E0002 と note。一つの構文の形（S-248。一つの経路の全ての `::`、一つの型引数の並びの入れ子の括弧、続いた `;`）は一つの診断と一つの候補で、編集はトークンごと。別々の文の `;` は別々の誤り。何を一つの形と数えるかは CST の構造で決める。
  既存言語の書き方の閉じた一覧（S-250）: 一覧は機械が読むデータのファイル（TOML）にし、規則の表とファイルを一対一にして自己テストで突き合わせる（D-15）。FAUST の表も同じファイルへ移し、仕様 §18.1 に一覧の置き場所と「一覧に無い形は一般の規則のコード」の一文を書く。ファイルの例（見つける書き方と、候補を当てた後の形）はテストが仕様から作ったデータとして読む。
  置き場所と欄の形はこの作業票で決める。`String` は表に入れない（E0302）。`mut self` の候補は `move self`。
  複合代入（`+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=`）と `++x`・`x++`・`--x`・`x--` は表の行で、文の位置で左辺が名前かフィールドの経路なら候補 `x = x + 1` の形、添字など評価が二度になる左辺と式の位置（`let y = x++`）は候補なしの E0002 と note。
  空白を空けない `--x` と `++x` は増減として拾い、`- - x` は E0012 のまま。
  同じ段で開始の位置が同じ診断の選び方（S-281）: `crates/onsa_driver/src/reduce.rs` の鍵を `diagnostics` の並べ方（段、開始、終わり、コード、文面）にし、単体テスト `of_one_stage_at_one_place_the_one_found_first` の期待値を E0002 に改め、`SPEC-GAP(S-281)` を外す。
  字句の外来の形がトークンになった後も選ぶのは `reduce` の一か所で、構文解析器は入口で形の誤り（E0020）と置き場所の誤り（E0002）を一つに絞らず両方出す。
  修正候補の約束の範囲（S-302、S-314）: W3-17 の器の `touched` を補集合の定義（当てる前の単位の表と編集の範囲から、ずらした同じ範囲に残った単位を除く）にし、全ての候補に範囲の外の字句の読みを変えない検査（ずらしは端に接する挿入を中に入れない別の関数で、`Applied::map_span` は使わない）を足し、ファズの `same_place` にも足し、`SPEC-GAP(S-302)` を外す。
  ブロックコメントの候補は S-302 の決定の細部（行の先頭か途中のものは上の独立した行、行の途中の `/** */` は `//`、行をまたぎ後ろにコードが続く形は E0002）による 浮動小数のパターン（S-317）: 一つの腕のパターンの全てのリテラルを一つの誤りとし、選択は置き換えた後に全ての枝が同じ形になるときだけ枝をまとめて `||`、他は E0002。
  穴の種類を抽象し、W3-07 の範囲が同じ仕組みに乗るようにする。
