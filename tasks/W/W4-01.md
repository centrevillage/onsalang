# W4-01 パッケージのモデル

- 内容: パッケージ ID と依存の表、同じパッケージは一度だけ解析する、std は役割で見分ける、`std` は暗黙の依存（埋め込みの std の版を取り出すまで。版を比べて E1103 を出すのは W4-02）、埋め込みの std の版を `onsa --version` で表示する。std のモジュールの一覧は build.rs で生成する
- 実現する決定: R-88 (1)(2)、S-83、S-160、R-80 (4)
- 持ち越し:
  - **X-8 から（2026-10-23、54 回目）:** `std` の版の照合の診断（E1103）は `onsa.toml` の中の位置が要るので W4-02 に移した（S-83）。W4-01 は依存の表を作るだけにし、`resolve.rs` の `lookup` の意味は変えない（見える名前は W4-03 の `use` の頭の規則で決まる）。
    - `sig/collect.rs` の側（std を役割で見分ける所、モジュール木）は W4-03 が作り直すので、W4-01 では `Package` と driver の側だけを直し、`sig/collect.rs` の分は W4-03 に入れる。
  - **X-8 の第二弾から（2026-10-24、58 回目）:** `Package` に ID と役割を持たせるとき、`flatten(pkg) -> Vec<&Package>` の形を保つ（重複を除くのは中だけ）と、`modes.rs`・`rt.rs`・`effects.rs`・`onsa_core` への波及が 0 になる。テストの `Package { …, is_std }` の直書き（sema のテストの 9 ファイル）は、作る関数を一つ足すと波及が小さい。
