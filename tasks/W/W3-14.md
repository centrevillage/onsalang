# W3-14 入れ子の深さの上限

- 内容: 構文解析器で、仕様 §2.5 の規則（S-221: 宣言の単位ごとに 0 から、式・型・パターンの形とブロックが一段、名前・リテラル・`_`・並び・文・見出しは数えない、二項演算子の連鎖は §3.1 の木の高さ、補間の穴は名前の経路を式と同じに）で深さを数え、256 を超えたら E0006（主の位置は最初に超えた形のトークン。名前で始まる形は名前の後の開き括弧、左結合の連鎖は左から読んで高さが初めて超える演算子で、連鎖を読み切る前に止める。パターンの `|` は全体で一段、`a.f(x)` は二段、見出しの中の型は最初の形が一段目（S-240）。note で `let`・`type`・関数に分ける形。その単位の読み取りを止める）。
  深さを数える唯一の関数 `Parser::height` で、`NodeKind` をワイルドカードの無い `match` で 0 / 1 に対応させる（節点の種類を足すと、段を決めるまでコンパイルが通らない）。連鎖の高さは、E0010 の群の判定（W3-07）と同じ強弱の表で求める。テストは構文ごとでなく区分ごとの境界（256 は通り、257 は E0006）と連鎖の事例。
  fmt の性質テストに「深さが増えない」を足す。後の段は再帰のまま有界になる。CLI とテストの実行器の大きなスタックの扱いを見直す。上限で止まりプロセスが落ちないことを確かめてから、`tools/fuzz.py --deep` を既定の gate に入れる。`SPEC-GAP(S-183)` の印と、実装待ちの一覧の E0006 を外す
