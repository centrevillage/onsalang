# W7-19 flow の参照評価器とインタプリタの比べ

- 内容: W7-01・W7-18 の参照評価器の期待する出力をデータとして残し、Core を経たインタプリタと比べる（Q-02 (b)、R-113）。W7-01 から分けた（2026-11-16、158 回目、利用者）。受け入れ条件に、W1-09 の手書きの期待値（`test` の assert を機械で取り出す。`init`・`process`・`reset` の列も）との一致を含める（独立した二つの源、K-04）。データは `tests/flow_ref/`（`tests/vectors/` と同じ作り: 生成、`MANIFEST`、`FORMAT.md`）。比べるのはインタプリタだけで、`conformance.rs` は書き換えない。インタプリタ（Core）と C の対応は、この作業の外（別のタスク。利用者、158 回目）
- 決定の範囲: Q-02 (b)
- 単位: W7-01 U1 の設計メモ（2026-11-16、158 回目、`target/notes/158/w701/memo/memo.md`（口の確かめは `target/notes/158/w701/api2/api2.md`））の見積もり: U1 `InterpHost`（`host.rs`。値の変換、包みのパッケージ、関数の引き当て）130 → U2 `data.rs` と `tests/flow_ref*.rs`（取り出し、データ、`gen`・`check`、インタプリタとの比べ）100（ほかにテストの側 400〜500。U2 の票で取り出しと比べに分けるかを決める）
- 持ち越し:
  - **W7-01 U3 の壊す側から（2026-11-16、159 回目）:** 評価器とインタプリタの差分（型の付いたランダムな式を作り、`onsa check` で通るものを評価器の flow の本体とインタプリタの `fn` の本体の同じ本文で比べる。値・panic の種類・位置）を、決まった種で数百件の `cargo test` にし、全数は壊す側に残す（`rules/leader.md` 4.9）。壊す側の台本は `target/notes/158/w701/u3/b/`（`gen.py`・`cmp.py`・`cmpc.py`）。
  - **W7-01 から（2026-11-16、158 回目）:** データを作り直す命令は U2 の票で決める（既にある `UPDATE_GOLDEN=1` の流儀に揃える向き。許可の行は親が提案する）。降下が止まる事例は走らせず「待ち」と数え、実装待ちの一覧と数を照らす。取り出しの数（`tests=… extracted=… skipped=…`）をデータの頭に持ち、数が変われば失敗にする。前の要約 `api.md` 5.2 の `render` の例（`Config {}`・`Params {}` を渡す形）は W7-12 U1 の後で古いので、今の事例の形（`one.render(xs, 8.0)`）で取り出す
