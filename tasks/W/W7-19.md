# W7-19 flow の参照評価器とインタプリタの比べ

- 内容: W7-01・W7-18 の参照評価器の期待する出力をデータとして残し、Core を経たインタプリタと比べる（Q-02 (b)、R-113）。W7-01 から分けた（2026-11-16、158 回目、利用者）。受け入れ条件に、W1-09 の手書きの期待値（`test` の assert を機械で取り出す。`init`・`process`・`reset` の列も）との一致を含める（独立した二つの源、K-04）。データは `tests/flow_ref/`（`tests/vectors/` と同じ作り: 生成、`MANIFEST`、`FORMAT.md`）。比べるのはインタプリタだけで、`conformance.rs` は書き換えない。インタプリタ（Core）と C の対応は、この作業の外（別のタスク。利用者、158 回目）
- 決定の範囲: Q-02 (b)
- 単位: W7-01 U1 の設計メモ（2026-11-16、158 回目、`target/notes/158/w701/memo/memo.md`（口の確かめは `target/notes/158/w701/api2/api2.md`））の見積もり: U1 `InterpHost`（`host.rs`。値の変換、包みのパッケージ、関数の引き当て）130 → U2 `data.rs` と `tests/flow_ref*.rs`（取り出し、データ、`gen`・`check`、インタプリタとの比べ）100（ほかにテストの側 400〜500。U2 の票で取り出しと比べに分けるかを決める）
- 持ち越し:
  - **W7-18 R488 の壊す側から（2026-11-17、163 回目）:** 定数のクロックの `let` をその場で展開した双子の flow と突き合わせる乱択（`target/notes/163/w718/r488/b/gen.py`、約 1 秒に 100 ファイル）は、比べの入口の材料になる。決まった種の数十件を Rust のテストにするかは、比べの入口を作るときに決める。
  - **W7-18 U1b の壊す側から（2026-11-17、163 回目）:** 評価器は、まだ評価しない形（`par~`、子の flow の呼び出し、`sample_rate()`・`sample_tick()`）を `Instance::init` で `Unavailable` にする（取られない枝の中でも、入力によらず）。比べの入口は、`init` の `Unavailable` を「評価器が使えない」と読み、評価器の誤りに数えない。`init` のクロックの `let` の panic は `Unavailable` より先に出る（止まる順は S-1093 の仮の扱いの延長）。
  - **W7-18 U1a の壊す側から（2026-11-17、163 回目）:** 比べの入口で、(1) 定数のクロックの `let` と出力の式の panic は、仕様では E0419（コンパイル時、§11.3）で、評価器は `init` の panic として返すので、コンパイル時の誤りとして扱う（今のコンパイラは E0419 を出さない）。(2) チェックが flow の段の誤り（E0815 など）を出す flow も、表が揃えば評価器は値を返すので、比べの対象はチェックを通る flow に限る。(3) 乱択の差分（壊す側の `fz.py` の形、`target/notes/163/w718/u1a2/` の壊す側の報告）は、`at` と出力の式と定数のクロックの panic を除けば値の食い違いだけを見る gate の項目にできる（`rules/leader.md` 4.9）。panic の有無と位置は、巻き上げ（W7-05、S-1093・S-1080）が決まるまで意図した差が混ざる。
  - **W7-01 U5 から（2026-11-16、159 回目）:** `InterpHost` は `HostCall.callee.def`（`DefId`）で `Interp` の関数を引く（`qualified_name` は手書きの表のための名前）。host へ渡した関数の中の呼び出しを評価器の呼び出しの深さ（§12.5 の 128）に足すか、`Interp` が数え直すかを、`InterpHost` の設計で決める（今は host の呼び出しを 1 段と数える。評価器の深さ 127 で `Interp` の 128 段の再帰を呼ぶと、インタプリタで一つに通せば 129 を超える形が panic しない）。`panic(msg)` の文面と呼び出しの位置の並び（§18.1 の `calls`）まで比べるなら、評価器の `Fault`・`Stop` に持たせる。(a′) の判定の結果を `DefId` ごとに控える（`fib(25)` が debug で約 0.95 秒、大半が判定の歩き）。パターンにだけ文字列を持つ本体は、評価器が評価して `Unavailable` になりうる（この版の検査が文字列を E0200 で止めるので今は届かない）。
  - **W7-01 U4 の壊す側から（2026-11-16、159 回目）:** 評価器の `match` の照合を、Python の別の実装（`target/notes/159/w701/u4/b/gm.py`、ガード・選択・入れ子の列挙子と struct）と突き合わせる器と、集成体の差分（`ga.py`）、定数の行と初期化式の突き合わせ（`gc.py`）。インタプリタはガード・リテラル・選択を含む `match` を E0200 で拒むので、評価器の `match` の源は手で導いた値と rustc の出力だった。決まった種で数百件を `cargo test` に入れる案（`rules/leader.md` 4.9）。
  - **W7-01 U3 の壊す側から（2026-11-16、159 回目）:** 評価器とインタプリタの差分（型の付いたランダムな式を作り、`onsa check` で通るものを評価器の flow の本体とインタプリタの `fn` の本体の同じ本文で比べる。値・panic の種類・位置）を、決まった種で数百件の `cargo test` にし、全数は壊す側に残す（`rules/leader.md` 4.9）。壊す側の台本は `target/notes/158/w701/u3/b/`（`gen.py`・`cmp.py`・`cmpc.py`）。
  - **W7-01 から（2026-11-16、158 回目）:** データを作り直す命令は U2 の票で決める（既にある `UPDATE_GOLDEN=1` の流儀に揃える向き。許可の行は親が提案する）。降下が止まる事例は走らせず「待ち」と数え、実装待ちの一覧と数を照らす。取り出しの数（`tests=… extracted=… skipped=…`）をデータの頭に持ち、数が変われば失敗にする。前の要約 `api.md` 5.2 の `render` の例（`Config {}`・`Params {}` を渡す形）は W7-12 U1 の後で古いので、今の事例の形（`one.render(xs, 8.0)`）で取り出す
