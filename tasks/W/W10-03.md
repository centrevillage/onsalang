# W10-03 C の API の意味

- 内容: 入出力の引数の形。`@param` の飽和を削る。パラメータの ID と数値の ID。`platform = "host"`、`PARAM_COUNT`、`onsa_reset_hook()` などの §14.2 の表。
  export した関数の wrapper は状態の `int` を返し、結果は最後の `T* out`。`<prefix>take_panic()` と panic の印のスレッドごとの変数を消す。`panic_messages = false` では補助関数のメッセージを空にし、生成した呼び出しは `onsa__panic("", "", 行)`。
  OS の無いプラットフォームでは `onsa build` が `ONSA_NO_TLS` を定義する。NULL の `bulk` / `cfg` で `_init` は 2。`onsa_param_info` を型付きの値に。`reset` は `void`（S-198）。`process_inplace` は struct の出力を展開して数える（S-197）。
  0 フレームの呼び出し（S-204）は W2-08 で実装した（`In` / `Out` の構造体を入れるこの作業で、構造体へのポインタも同じ `frames != 0` の形で読まない）。driver を作る部分を新しい API に合わせる（K-14）
- 決定の範囲: S-30 の C の側、S-87 の C の表
- 持ち越し:
  - **W7-12 U3 から（2026-11-17、162 回目）:** R-15 の C の側。生成する C の `process` の引数と wrapper の局所変数の名前が、利用者の信号の名前・出力のフィールドの名前と重なる（`swap(l, r) -> Stereo { l, r }`（§11.6 の例）、信号の名前 `s`・`p`・`q`・`frames`、平面の `x` と信号 `x_spans`、入力の名前 `out`）。§14.2 の形（`input`・`output`、利用者の名前は `<p>_in`・`<p>_out` のフィールド）にすれば構成で消える。W7-12 U3a は、重なりのある flow の `process_io` を E0200 にする門を置く（黙って不正な C を出さないため）。この作業で門を外す。再現は `target/notes/162/w712/u3/review/in/cnames/`・`cname_s/`。
  - **W4-02 U3d から（2026-11-01、99 回目）:** 今の `onsa build` は `-DONSA_NO_TLS` を `build.rs` の `platform()` の `thumbv*` の枝だけで足し、`riscv32imac-unknown-none-elf` などの他の OS の無いプラットフォーム（§15.3 の `platform` の行）では足さない（U3d の壊す側の中 1、前からの形）。
    U3d で OS の無いの判定は `Platform.hosted`（`-` で切った語に `none`）の一か所になったので、`ONSA_NO_TLS` も `hosted` から出し、判断を二か所に置かない（D-15）。
  - **W10-03:** R-107 の `panic_messages = false` で、`onsa.h` の補助関数のメッセージの文字列（`"integer overflow in `+`"` など）も除く（W2-05/i が残っていることを確かめた）。`ONSA_PANIC_HANDLER` をホストが定義すると trap / reset でもハンドラを先に呼ぶ（R-10 の「比較と分岐だけ」は定義しないときの話）。
