# W10-03 C の API の意味

- 内容: 入出力の引数の形。`@param` の飽和を削る。パラメータの ID と数値の ID。`platform = "host"`、`PARAM_COUNT`、`onsa_reset_hook()` などの §14.2 の表。
  export した関数の wrapper は状態の `int` を返し、結果は最後の `T* out`。`<prefix>take_panic()` と panic の印のスレッドごとの変数を消す。`panic_messages = false` では補助関数のメッセージを空にし、生成した呼び出しは `onsa__panic("", "", 行)`。
  OS の無いプラットフォームでは `onsa build` が `ONSA_NO_TLS` を定義する。NULL の `bulk` / `cfg` で `_init` は 2。`onsa_param_info` を型付きの値に。`reset` は `void`（S-198）。`process_inplace` は struct の出力を展開して数える（S-197）。
  0 フレームの呼び出し（S-204）は W2-08 で実装した（`In` / `Out` の構造体を入れるこの作業で、構造体へのポインタも同じ `frames != 0` の形で読まない）。driver を作る部分を新しい API に合わせる（K-14）
- 実現する決定: S-30 の C の側、R-21、S-104、S-92、R-107、S-113、R-49、S-87 の C の表、S-197、S-198、S-204、K-14、R-144
- 持ち越し:
  - **W10-03:** R-107 の `panic_messages = false` で、`onsa.h` の補助関数のメッセージの文字列（`"integer overflow in `+`"` など）も除く（W2-05/i が残っていることを確かめた）。`ONSA_PANIC_HANDLER` をホストが定義すると trap / reset でもハンドラを先に呼ぶ（R-10 の「比較と分岐だけ」は定義しないときの話）。
