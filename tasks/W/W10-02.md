# W10-02 C の名前と形

- 内容: C の名前の衛生的な改名を C バックエンドの一か所に（ランタイムは利用者が使えない接頭辞 `onsa__`）。フィールド名の `.` → `_` を単射に。ヘッダは `<prefix><package>.h` の一つで、C の名前は `prefix` + 名前の最後の要素。
  関数と型の形は空かどうかによらず一定（Config は構造体のポインタ、空の構造体は予約のメンバ `_unused`、`bulk` は常に置き、`BULK_ALIGN` は 0 のとき 1）。`init` の形を §14.2 の `init(s, bulk, const cfg*, sample_rate)` にする（R-140。適合性テストのプログラムも合わせる）。
  C の出力の入れ子の深さを抑える（同じ群の連鎖は括弧なしで平らに出す、S-183）。浮動小数の定数を、どのコンパイラでも同じビットになる 16 進の浮動小数のリテラルで書く（R-164、S-211）
- 持ち越し: 52 回目（2026-10-22、X-7 の文書の点検の見直し、S-570・S-112）で、`params`・`cfg` は `block`・`init` の入力のある flow だけが持つことにした。公開の `<p>_params`・`<p>_config` にフィールドの無い struct は出ないので、`内容` の「空の構造体は予約のメンバ `_unused`」は要らない（仕様 §19.1。内部の Core IR の形は実装が決める）。
  - **W7-03 U1c の壊す側から（2026-11-18、165 回目）:** C の後端は bulk 領域のポインタの欄を自分で `void* bulk;`・`s->bulk`・`.bulk` と書く（`crates/onsa_backend_c/src/emit/types.rs`・`emit/fns.rs`・`export.rs`）。Core の配置と interface の名前は `_bulk`（S-1138）で揃わず、`let bulk` と C の欄が重なりうる（今は `memory.bulk = true` が E0200 で届かない）。C の欄の名前を Core の配置から引く形にする（低）。
  - **第 110 組から（2026-11-18、165 回目、S-1138・S-1081・S-1136・S-1137）:** 状態のフィールドの C の名前: `.` を `__` にする写しで、`_` で始まる生成する名前を `.` の後に持つ形（`a._hoist_0`）と末尾の `_` の名前（`a_.hoist_0`）が同じ C の名前になる組を、処理系が重ならない名前に選ぶ（仕様 §11.6、S-1138。W8-11 の型名と同じ規則）。固定の欄は `_sample_rate`・`_poisoned`・`_initialized`・`_bulk`（W7-03 で名前を変える）。
  - **W7-12 U1 から（2026-11-16、157 回目）:** Core は C の API の形を保つため、Onsa の側に無い `Config`・`Params` を空の struct で作り（`Lowerer::flow_ty`）、`implicit_params` で仮引数と呼び出しに差し込む。位置の表（`init` の 0、`process`・`process_inplace` の 1、`render` の 0・1）は sema の `fill_by_output` の並びの二つ目の写しで、C の API から `cfg`・`params` を外すときに、この型と表を消す。C のソースに内部の空の struct（`{ uint8_t onsa_empty; }`）が出るのも同じ時に消える。
- 決定の範囲: R-48 の C の側、S-112 の C の形、S-183 の C の出力、S-655（パッケージのヘッダは `#pragma once`、`onsa.h` と `onsa__runtime.h` はマクロのガード）
  - **X-7 の本体への移しから（2026-10-23、53 回目）:** `内容` の「`init` の形を §14.2 の `init(s, bulk, const cfg*, sample_rate)` にする」も、`init` の入力の無い flow では `cfg` を取らない形（§14.2 の形の原則）に読み替える。仕様 §11.6・§14.2 へ移した。
- 持ち越し（2026-11-01、親）: 96 回目、W4-02 U1 の壊す側から（低）: `@export` では別のモジュールに同じ名前を書くのが自然な形になる（`a.version` と `b.version`、flow の `a.gg` と `b.gg`）。
  今は `check` も `build` も通り、C の名前 `pk10_version` が重なり、ヘッダ `pk10_gg.h` が 2 回並ぶ（E1011 は実装待ちの一覧の diag-code で until W10-02）。再現 `target/notes/96/w402u1/b/pk10`。前の `[export]` の経路でも同じ。
- 持ち越し（2026-11-01、親）: 98 回目、W4-02 U3c のテストの担当から: §14.2 は生成するファイルの名前を `<prefix><package>` の幹（ヘッダ、C のソース、静的ライブラリ）にするが、今はヘッダだけが `<prefix><package>.h` で、C のソース・`.o`・`lib….a` は `prefix` によらず `onsa_<package>` の幹。`crates/onsa_cli/tests/cli/manifest_prefix.rs` の `the_c_source_is_named_after_the_prefix` が `#[ignore = "W10-02"]`。
  直すときに、`@export` の無いパッケージ（`prefix` が無い）の幹を S-838 で決める。
