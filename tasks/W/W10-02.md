# W10-02 C の名前と形

- 内容: C の名前の衛生的な改名を C バックエンドの一か所に（ランタイムは利用者が使えない接頭辞 `onsa__`）。フィールド名の `.` → `_` を単射に。ヘッダは `<prefix><package>.h` の一つで、C の名前は `prefix` + 名前の最後の要素。
  関数と型の形は空かどうかによらず一定（Config は構造体のポインタ、空の構造体は予約のメンバ `_unused`、`bulk` は常に置き、`BULK_ALIGN` は 0 のとき 1）。`init` の形を §14.2 の `init(s, bulk, const cfg*, sample_rate)` にする（R-140。適合性テストのプログラムも合わせる）。
  C の出力の入れ子の深さを抑える（同じ群の連鎖は括弧なしで平らに出す、S-183）。浮動小数の定数を、どのコンパイラでも同じビットになる 16 進の浮動小数のリテラルで書く（R-164、S-211）
- 持ち越し: 52 回目（2026-10-22、X-7 の文書の点検の見直し、S-570・S-112）で、`params`・`cfg` は `block`・`init` の入力のある flow だけが持つことにした。公開の `<p>_params`・`<p>_config` にフィールドの無い struct は出ないので、`内容` の「空の構造体は予約のメンバ `_unused`」は要らない（仕様 §19.1。内部の Core IR の形は実装が決める）。
- 実現する決定: R-48 の C の側、S-149、S-52、R-64、S-112 の C の形、S-95、R-121、R-140、S-183 の C の出力、R-164、R-181
  - **X-7 の本体への移しから（2026-10-23、53 回目）:** `内容` の「`init` の形を §14.2 の `init(s, bulk, const cfg*, sample_rate)` にする」も、`init` の入力の無い flow では `cfg` を取らない形（§14.2 の形の原則）に読み替える。仕様 §11.6・§14.2 へ移した。
