# W5-02 組込みの表

- 内容: 組込み型のメソッド・関連関数・関連定数を std の `impl` に宣言し、プリミティブだけを `target` にする。`Prim` の表（シグネチャ、rt と効果、演算の分類）と lang item。sema は表の ID を Core へ渡し、降下は名前を読み直さない。
  各バックエンドは `Prim` を `_` 無しで網羅し、走らせる・生成する前に Core の全体を照らして E0200。std の `target` 宣言は `bind` で差し替えられない。宣言と `Prim` の 1 対 1 をテストで確かめる。M5 までの `std.test` の `check` / `gen` は表に未対応の印を付ける。
  `target` の構文（`impl` のメンバの `target fn`、見出しと同じ行の `else` の本体）と、利用者の `else` の本体の E0200。`map_err` の宣言。`Option` を返すメソッドは std に Onsa の本体で書く（S-71 のこの部分）。`Str` のメンバを §4.2 の一覧にする（R-96 の `Str` の部分）。関連定数を std の `impl` の値にする（R-136 の `BITS` もここで通る）。
  gate の直書きの許可リストを減らす。組込みの閉じた一覧と変換の診断は W5-14、呼び出しの形の型の段は W5-15、R-127 の表の組み替えは W5-05、`abs` / `min` / `max` の std の本体は W5-07（X-23）
- 決定の範囲: S-669 の `else` の構文と利用者の `else` の E0200（三つの本体は W5-07）、S-661（`impl` の `target fn`）、S-670・S-629 の `else` の形、S-71 の `Option` を返すメソッドの Onsa の本体、R-96 の `Str` の部分
- 単位: X-23 の見積もり（2026-11-02、104 回目、`issues/X/X-23/estimate.md`。素の行数で、テストを除く）: Rust 約 740〜1,100 行（足す。別に約 1,000 行を消す）・std の Onsa 200〜340 行、5 単位（組 A）。
  - U1 設計メモ（std の置き方と生成の要否、`Prim` の表と lang item、列の受け手、S-794・S-847・S-229 の当て方、`body/calls.rs`（約 50%）と `names/prelude.rs` の判断、`panic` の置き方）→ U2 `target` の構文（他の単位に依らないので最初に置ける。`else` の本体を持つ std の宣言はまだ無いので、構文の正例は CST の事例で持つ）→ U3 `Prim` の表と後端の網羅 → U4 スカラーの宣言（S-69 (1)、R-104）→ U5 列・`Str`・`Option`・`Result` のメンバと `builtin.rs` の撤去（S-143・S-785・S-786・S-809）。
