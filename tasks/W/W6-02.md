# W6-02 経路を見た破棄の点

- 内容: 破棄点を modes が経路を見て列挙し、rt と効果が共有する。一時値・上書き・総称の `T`。`Copy` の無い `T` の破棄は `Alloc` を要する
- 決定の範囲: S-610 の破棄の行、S-613 の破棄の行、R-251 の束縛の無い一時の値
- 持ち越し:
  - **W4-09 U2 から（2026-10-31、91 回目）:** R-32 の片方の道で移すか取り出した値を、もう片方の道で全体として破棄する `Alloc` は、S-85 の取り出し（`if c { Some(move h.buf) } else { None }`）と `var` への入れ直しにも届く。
    実装待ちの `tests/spec/negative/drop_on_the_other_path.onsa` を外す。
    取り出しの残りの破棄は `rt.rs::rest_drops_alloc` が `BodyInfo::taken` から数え、総称の `T` の残りは `drops_alloc` の答えに乗るので、`T` の破棄を直すと `negative/take_out_rest_alloc_generic.onsa` も通る見込み。
    破棄点を経路で列挙するとき（`design/06-placement.md` の 14 行）、取り出しの残りの破棄もそこへ揃える。
  - **W4-16 の設計メモから（2026-10-29、84 回目、利用者が了承 A6）:** R-30 の「分からない種は Affine」は W4-16 で modes の問いだけに当てる。破棄に `Alloc` が要るかの答えなし（`rt.rs::needs_alloc_drop` の `unwrap_or(false)`。`rt fn drop_q[T: ?Dup](move x: T) {}` に E0901 が出ない）は、ここで総称の `T` の破棄（§12.2）と一緒に直す。
  - **第 44 組から（2026-10-23、58 回目）:** S-610: 静的な値（W4-16 の印）の一時の値と束縛の破棄は数えない（§12.2）。Shared を含む値の型を組むことは `Alloc` を要さず、所有する Shared を含む値の破棄は要る。
    R-255: rt の関数で `move` の引数に受けた Shared 値をそのまま返すか、`move` の引数に（S-609 で `move` 無しで）渡すと E0901 になる（移動を記録しない見込み）。
  - **第 45 組から（2026-10-24、58 回目）:** S-613: 破棄の要らないリテラル（W4-16 が確定した束縛の状態と式の印）の一時の値と束縛の破棄は数えない（§12.2）。集成体のリテラルの破棄点の記録に、リテラルを所有の行にした最初の要素を持たせる（W6-03 の E0601 の note が読む）。
  - **第 2 期のために（2026-10-24、58 回目）:** 破棄点ごとの「`Alloc` が要るか」の判定を一つの関数に置く。第 2 期の解放の起きない破棄（`tasks/phase2.md`、L1 など）を、そこに条件を一つ足して入れられるようにするため（決定ではなく作りの注意）。
  - **X-8 の第二弾から（2026-10-24、58 回目）:** R-251 のうち、束縛の無い一時の値（`match f(move s) { _ => 0 }`）の破棄を数えることを W4-07 から移した（`rt.rs` は W6 の R-83 で作り直す）。見出しの束縛を所有にする分は W4-16、場所でない対象の腕は W4-07。
