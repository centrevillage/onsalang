# W3-02 診断の基盤

- 内容: 修正候補は `title` と `edits`、挿入は空の範囲（`Note` は位置を持たないこともある）。`span` は `end_line` を常に、列は文字（変換は一か所）。候補を当てる関数と重なりの判定を一つにし、編集の範囲はトークンの境界に限る。診断は出した段を持ち（作る所が渡す）、登録簿は出しうる段の集合・修正候補が必須か・規則の note が必須かを持つ。
  番号の範囲で構文の診断を判定する所（fmt、`diff_ast`、テストの器）を段の判定に置き換え、fmt は構文の段の診断のあるファイルを書き換えない（R-146、S-214）。診断の契約（必須の候補と note、範囲）を確かめる一か所と、テストの器の修正候補の期待値（断片の `fixes = N` と事例の隣の `.fixK`、当てた後のソース）。キーワードの判定を明示の一覧に。
  JSON の形（S-213）を CLI のテストで確かめる
- 実現する決定: R-87 (1)〜(3)、R-87 のキーワード、S-81、S-120 の fmt の判定、R-146、S-213、S-214
