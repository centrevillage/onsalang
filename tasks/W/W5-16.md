# W5-16 定数式と推論した型の上限

- 内容: 定数式の文法と型（E0417、E0401）。型の位置で使う定数のうち計算で決まるものは W9-03 まで E0200 で、小さな評価器は作らない（今の「リテラルとリテラルの定数だけ」のまま、K-05）。値の位置の定数（`const NAN: F32 = 0.0 / 0.0`）には当たらない。
  定数式の前置の `-` は普通の式と同じ規則で、`U32` には E0401（S-228）。署名・本体の `[x; N]`・flow の定数式を一つの読み手にする（W5-08 の持ち越しの二重の解決）。
  種の制約は W5-20 へ分けた（2026-11-05、115 回目）。推論した型の上限（S-264、深さ 256・大きさ 4096）。W5-08 から分けた（X-23）
- 決定の範囲: S-50 の文法、S-132 の型の部分、S-228 の文法と型、S-264 の推論した型、S-304 の定数式の位置、S-329 の構文の枝と `Self.CAP` の E0417、S-849 の推論した型の E0422 の位置、S-898 の読み手
- 単位: 設計メモ（2026-11-09、129 回目、`target/notes/129/w516/memo.md`。素の行数で、テストを除く）: 足す約 510〜580 行、消す約 450 行、5 単位（X-23 の見積もり 約 310〜355 行を上回る。名前の解決を名前の段へ移す分と、型変数を通した型の測りの分）。
  U1a 名前を一度だけ引く（署名と本体に書いた型の定数式も名前の段の歩き手が `names/body/consts.rs` の入口で引き、型の段の読み手は記録だけを読む。W5-08 の持ち越しの二重の解決、W5-05 U3/b の `T.NAME`、S-898 の呼び出しの形、署名の S-329 の E0200 の揃え、R-321。出力はほぼ変えない）→ U1d `::[…]` と `[…, …]` の構文（S-329 の構文の枝。`parser/types.rs`）→ U1b 文法と型（読み手を帰りがけ順に。S-50、S-132、S-228、R-61、S-966）→ U1c 関連定数の型引数（S-304、S-329 の `Self.CAP`、R-277）。U2 推論した型の上限（S-264、S-849、R-280）は U1 と触るファイルが重ならず、作業ツリーで並べられる。
  親の決め（2026-11-09、129 回目。出力が同じ内部の選択か、既決の決定から読みが決まるもの、`rules/leader.md` 5.10）:
  名前の解決は全ての位置で名前の段の歩き手が一度だけ行う（メモの案 B。`constarg.rs` の歩き手の判断の写しを消す、D-15。W5-10 の `::[…]` の読みが歩き手の一か所で定数式の全ての位置に効く）。`constarg.rs` は読み手の部分を作り直し、値の部分（`of_entity` など）を修正する。U1b の読み手はメモの 2.4 の表（仕様から組んだ設計）から書き、前の `Reader` を手直ししない（`rules/process.md` 8.6）。
  U1d は U1a の後に W5-16 の中で行い、W5-24 の S-333・S-548・S-471 の単位（W5-24 の U6）をその後に置く（W5-24 の U6 が待つ `parse_type_arg` の `::` の枝を先に入れる。R-196 のファズの形が戻らないことを確かめる）。
  `R4.CAP`（`CAP: U32 = N`）は、初期化式が `impl` の const パラメータの名前だけなら型引数の値を読む（第 87 組の持ち越し「型引数の決まった型の関連定数は、定数の読み手が型引数を読む」）。定数式の E0406 は `Rg.cap()` の E0406 と同じ組み立てで、関数の無い位置では「by the end of the function」を言わない（S-304 の「文面は同じ」を位置に合わせた読み。文面は約束しない）。`const Z: T` を別名で読む形の E0401 の文面（「`Z` is `<0>`」）は U1c で型引数を当てて直す。
  U2 は `resolve` などの頭で型変数の印が無ければ歩かない近道（約 10 行）を入れ、`compare.py speed` の前後を報告に並べる（効かなければ外す）。
  R-277・R-280 は `85400d9b` で直っていた（X-23）。事例を足して閉じる。
