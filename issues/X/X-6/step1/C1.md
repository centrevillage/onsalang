## 2. 項目ごとの修正方針

### RF-8 (A) `children()` を一つにする

- 子の列挙は構文の知識なので、`onsa_syntax/src/ast.rs` の `impl Ast` に `pub fn sub_exprs(&self, e: ExprId) -> Vec<ExprId>` を置く。中身は今の `graph.rs:142` の `children` の並びのまま（ブロックの文、callee、`Field` の base、`Repeat` の長さ、`par` の端を含む全ての直の部分式）。`Error` は空を返す（内部エラーを呼ぶかは呼ぶ側が決める）。
- `graph.rs`: `children(self.ast, e)` を `self.ast.sub_exprs(e)` にし、`Error` の内部エラー（S-59 の前提）は `Graph::visit` の頭で調べて残す。並びが同じなので DOT の辺の順は変わらない。
- `flow.rs`（sema）: `mark` の `_` の腕を `self.ast.sub_exprs(e)` にし、`children` を消す。core の `children` は (B) で `ReadWalk` ごと消える（(B) を行わないなら同じく差し替える）。
- 出力が変わらない根拠: sema と core の列挙が graph のものと違うのは `Repeat` の長さ・入れ子のブロックの文・`Closure`/`Handle` の本体・`Error` だけで、`Field`・`Call`・`Par` は `mark` と `ReadWalk` が `_` の腕より前に別の腕で扱う。
  違う 4 つは完全な flow（`mark` は診断の無いときだけ走り、降下と graph は `complete` の flow だけ）には現れない: 長さは `const_len` で定数（局所変数を読めない）、入れ子のブロックの文と閉包・`handle`・`?`・`unsafe` は E0806（`check_flow_stmt`・`check_flow_expr`）、`Error` は本体が不完全になる。`Target::Local` は単独の名前と `^名前` にだけ付く（`body/names.rs:134`、`flow_map.rs:92`）。
- 確かめ: `cargo test -p onsa_syntax -p onsa_sema -p onsa_core -p onsa_driver`、golden の `tests/golden/graph/voice.voice.dot` と `tests/golden/core/*`、`compare.py diags`（差 0 件の見込み）、〔危険〕なので `gate.sh --work`。

### RF-8 (B) 状態に置く判断を sema の一度の走査にする

- sema の `mark` を「各局所変数を読む最も速いクロック」を記録する走査にする: `FlowInfo` に `pub read_at: HashMap<LocalId, FlowRate>`（S-05。入力・`let`・`par` の変数・match の束縛の全て）を足し、`mark` は `Target::Local` を読むたびに最大を取る（今の `ReadWalk::note` と同じ）。`sample_rate_at` と `non_rt_here` は今のまま。
- `FlowLet.state` は走査の後に `read_at` から一度だけ出す: `rate >= Init` かつ、その `let` の局所変数のどれかが `rate` より速く読まれる（今の `mark` の条件と同じ）。`flow_tests.rs` の `let_rate` はそのまま通る。
- core の `lower_flow`: 236〜249 行の `ReadWalk` の走査を消し、`reads` を `info.read_at` に替える（入力の欄 261 行、定数の `let` の段 271 行）。
  282 行の `l.state || above` は `l.state` だけにする（定数でない `let` では `above` が立てば `state` も立つので同じ）。`ReadWalk` の構造体と impl と core の `children` を消す。`flat_nodes` は 712 行で使うので残す。
- 出力が変わらない根拠: 二つの走査は、完全な flow では読む局所変数とクロックが一致する（違いは `Field` に局所変数でない対象があるとき base を辿るかだけで、その base は型やモジュールの名前で `Target::Local` を持たない。遅延の `init` は sema が `init_expr` を、core が `InitArg::Init` を辿るが、定数に畳まれた `init` は局所変数を含まない）。
- R-91 の決定 (1)（`let` と入力を状態に入れる判断を計画を作るときに一度だけ、`decisions`/計画 §3.5、D-15）の一歩に当たる。W7-03 の計画の表はこの欄を表へ移すだけになる。
- 確かめ: (A) と同じ。加えて `onsa_cases --c`・`--vectors` は gate の中で回る（C の状態の欄の並びが変わらないこと）。
