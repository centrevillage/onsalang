# X-6 手順 1 の判断の点と決めたこと

手順 1 の案は領域ごとの `A.md`（構文解析器と AST）・`B.md`（字句・他言語の形・fmt）・`C1.md`（意味解析と RF-8）・`C2.md`（降下・インタプリタ・C の生成）・`D.md`（テストの器・診断の順・道具）。実装の担当 5 体が書いた（44 回目、2026-10-19）。
材料の前の回の壊す側の報告は scratchpad から消えていたので、親が担当の記録から取り戻し、各案の 5 章に要点を書かせた（W3-22/b の最初の回の報告だけは見つからなかった）。
判断の点は、親の案を伏せた版で助言の担当が独立に選び（段 1）、その後で親の案と突き合わせた（段 2）。(B) は利用者が決め、(A) は決定・前例・規則・確かめた事実から向きが決まる。

## (B) 利用者が決めたこと（2026-10-19）

| 点 | 決めたこと | 理由 |
|---|---|---|
| B1 検査の道具（Q3） | 並列の流れの前に道具の単位を一つ入れ、`compare.py` に二つのバイナリの fmt の出力の比べと `dump --core` の比べを足し、`speed` の長い入力に `fmt --check` を足す。C と `test --json` の比べは足さない | `diags` と `speed` は `onsa check` だけを回し、降下・fmt の直しを確かめない。Core が同じなら C も同じで、`test` は `gate.sh --work` の vectors と事例が回る |
| B2 R-210 の編集（Q4） | `=` と右辺の間に改行かコメントがあるときだけ、`=` の直後に差し込んで間のものを残す。空白だけなら今の置き換えのまま | 常に差し込むと `x +=1` が `x = x +1` になり、非対称な空白（S-398 の類）の新しい誤りを作る。S-251 の「間のトークン」に改行を含め、隣の空白は変える部分と読む |
| B3 `emit.rs`（Q10、段 1 の足した点 1） | X-6 では分けない。W8-01 の持ち越しの E-1（2026-10-13）のとおり、W7 と W8 の区切りに移す | W8 まで触る作業が無く、W10-02〜05 で C の名前・API・ヘッダが変わる |
