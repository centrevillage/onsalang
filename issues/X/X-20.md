# X-20 コンパイラの性能: 段ごとの時間の測定、性能の要件、対策（今まで性能の要件を明示していない）

- 決めたこと: 79 回目（2026-10-28）、利用者が「コンパイラ検査の件は、どこかでちゃんと性能測定して対策しましょう。コンパイラ自体の性能要件は特にこれまで明示していなかったので、あまり注意が払われていない可能性は高いです。開発速度を全体的に遅くしますし、ユーザー体験も悪くなりますし」と言った。
  性能は、開発の速さ（gate、担当の試行）と利用者の体験（CLI、ブラウザの IDE で書くたびの再検査）の両方に効く。今の規則にある性能の確かめは、リファクタリングの前後の `compare.py speed`（`rules/refactoring.md` 8.2）だけで、単位ごとの検査の時間の変化は見ていない。

  - W4-05 で見つけた最悪の形: 宣言を辿る時間が段の数の指数（R-313、今は歩数の予算で有界だが答えなしになる）、別名の鎖の指数（U1/b の F3、U2 で直した）、総称の深い入れ子の 2 乗の時間と記憶（U2/b の B-4、3000 個 × 250 段で 2.5 秒・524 MB、U2/i3 の後 3.1 秒・587 MB）、`Option` の別名の鎖 3000 段（U2 の前 3.3 秒、後 0.16 秒）。
