# X-2 ドキュメント整理

## 問題点

現在、ほとんどのドキュメントが `docs` ディレクト以下に集まっており、カテゴリごとに分けられていない。
また、一つの巨大なファイルを更新する作業が増えており、トークン効率も悪い。
(このために、 `sed` / `grep` / `find` などの外部ツールの使用や軽量スクリプトの自作に頼っており、手法の標準化、効率化ができていない)
エージェントが知るべき情報は多過ぎても少な過ぎても問題で、情報の単位を適切に設計する必要がある。

## 改善の手順

1. W3 でドキュメント参照・編集時に非効率だった部分を洗い出す
  - 独自のスクリプト、ワンライナーのシェルの痕跡
  - 必要のない文章まで読んでいる痕跡
  - 必要な文章を読み飛ばしている痕跡

2. ドキュメント構造のあるべき形を決める
  - ドキュメントを関心の範囲で構造化
  - ルートディレクトリに各ディレクトリ/ファイルへの索引を置く
  - SSoT (Single Source of Truth) の順守
  - 仕様/規則/作業管理用ドキュメントのディレクトリを分ける
    - 例えば作業管理は `issues` ディレクトリにissueごとに起票するなど
  - 仕様を概要と詳細に分け、各詳細ごとに別ドキュメント化(現在の基本仕様とツール仕様の分割をもっと細かく考えるイメージ)

3. ドキュメントごとのフォーマットを決める
  - 仕様のフォーマット
  - 規約のフォーマット
  - 報告表のフォーマット
  - 作業表のフォーマット

4. ドキュメント参照・編集のためのツールを整備する
  - 分割後のドキュメントを毎回 `find` や `grep` しなくてもいいように、ツールを整備する
    - 例1: あるドキュメントから参照されているドキュメントのパスを返すスクリプト
    - 例2: 作業状態管理ツール(PLAN/PENDING/DOING/DONE 等の状態を一覧で確認、またissue番号を指定して状態更新)
    - 例3: ドキュメントフォーマッタ(200文字程度での字下げを考慮した自動改行など)

5. ドキュメント管理エージェントの必要性を議論し、必要となったら導入
  
観点:
  - ドキュメント管理エージェントの責務の明確化
    - 案としては、事実を変えない編集のみ可能(リーダーの責務と干渉させない)
    - ドキュメント構造が保たれているか、矛盾が発生していないか、重複が発生していないか、の検証が主な仕事
    - 新しくドキュメント構造の見直しが必要になった場合の実作業も担当
    - ツールでできることはエージェントに任せない。ツールでできないタスクはエージェントで。

6. 旧ドキュメントを新しいドキュメント構造に作り直す
  - 情報が掛けないよう、事前にチェックツールを作る
  - ドキュメント管理エージェントがいる場合はそのエージェントが作業担当
