# X-12 `docs.py due` が、点検の取り込みのコミットより前の変更を、点検の範囲の外も含めて全て済みと数える

- 決めたこと:
- 持ち越し:
  - **53 回目（2026-10-23、利用者が `docs.py` の直しのタスクにした）:** `tools/docs.py` の `due`（gate の `docs-due`）は、HEAD から遡って最初の `Docs-Checked:` の行のあるコミットを点検の位置とし、それより前の変更を全て点検済みと数える（`_last_check` と `cmd_due`）。
    - 見たこと: 前半の点検（範囲 81f2da5..11b3e29）を `6a06a15` で取り込んだとき、範囲の外の `07b8580`（後半の §19.1 から本体への移し）と `e5d2056` も済みの扱いになり、`docs.py due` は「no document changed after the docs check」を出した。親が気づいて後半の点検（11b3e29..6a06a15）を別に立てた。
      点検を並べて走らせ、その間に親が文書をコミットする進め方（53 回目）で起きる。
    - 直す向きの候補: `Docs-Checked: A..B` の範囲を読み、`B` の後から取り込みのコミットの前までに改めた文書を、点検の要るものとして残す（取り込みのコミット自身の直しは済みとする）。範囲の重なりと、範囲の外のコミットを、点検の印の付いた全てのコミットから集める形も考えられる。
      改行の位置だけの変更（`docs.py fmt` だけのコミット）を点検の要るものから外すかも、あわせて決める（53 回目に全ての文書を一度正規化した）。
    - それまでは、親は点検を並べて走らせた間のコミットを控えに書き、取り込みの後に `git log <B>..<取り込み>` で範囲の外のコミットを確かめる。
