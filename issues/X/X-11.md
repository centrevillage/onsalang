# X-11 担当の報告を保存するフックが、届く前の報告か前の報告を保存する

- 決めたこと:
- 持ち越し:
  - **52 回目（2026-10-22、利用者がタスクにした）:** `tools/hooks/claude_hook.py` の `subagent_stop`（SubagentStop）が `handback/` に保存する報告が、担当の最後の報告と合わない。
    - 見たこと（52 回目の scratchpad の `handback/`）: 文書の点検の担当の一つと助言の担当の 001・002 は「SubagentHandback が無い」（001 は `last_assistant_message` に報告の本文があった）。
      SendMessage で段 2 を渡した後の 003・004 は、段 1 の報告を保存した（段 2 の報告ではない）。後で `handback.py save` で同じ記録から取り出すと、正しい報告が取れた。
    - 見当: SubagentStop が走る時点では、最後の SubagentHandback がまだ記録（`agent_transcript_path` の jsonl）に書かれていない。続けて呼んだ担当では、`handback.last_report` が前の報告を拾う。
    - 直す向きの候補: 保存の時点を遅らせる（報告が記録に書かれてから）、保存した報告が今の呼び出しのものかを確かめて違えば印を付ける、区切りの `work.py close` か `handback.py` に、記録から取り出し直す命令を足す。確かめ方は、続けて呼ぶ担当を含む実際の記録で保存の中身を比べる。
    - それまでは、親は報告を `handback.py save` で記録から取り出す（`rules/leader.md` 2.9 の「フックが保存していない分」と同じ扱い）。
