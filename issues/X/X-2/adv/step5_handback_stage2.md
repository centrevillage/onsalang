- 2026-10-10 の提案（`docs/carryovers.md` 215〜224 行）: 整理の判断は親、担当は親の指示で直す。任せる大きさは「決定の組の反映・持ち越しの整理・再編は担当、一行の直しは親」。
- 手順 5 の観点（後に書かれた）と親の DM-2・私の第 1 段: 事実を変えない編集だけ。決定の記録は親。
- 選ぶと何が変わるか:
  - 「親の指示で記録も書く」: 親の文脈から記録の書き込み（W3 で親の出力 114 万字、`step1_eval.md` 3.）が外れる。代償は、決定の中身を担当が書く往復（親の文を写すだけなら利得は小さく、担当が文を起こすなら事実に触れる）と、親と担当の責務の境が不明瞭になること。新しい構造では決定の記録は「決定のファイル一つの Edit と `set`・`amend`」（DT-6）になり、W3 の 3〜7 か所の揃えが無くなるので、外す量そのものが減る。

  - 私の見立て: 10-10 の提案は旧構造（記録が 3〜7 か所に散る）を前提にした分担で、X-2 の構造と道具がその前提を消したので、後の観点（事実を変えない編集だけ）を採る。確信 中〜高。中間の形として「親が決定の文を票に書き、担当はそれを `new`・Edit・`set`・`amend` で置く」は、親の文脈からは出力の分だけしか減らず、往復が一つ増えるので、今は採らずに様子を見る。

### D3 モデル: opus（親）か sonnet（私、10-10 の案と同じ）

- opus: 長い日本語の文の意味の矛盾を読み取る精度。代償は費用（同じ文脈で高い）。
- sonnet: test・break と同じ級で安い。読み比べの手順が規則で固定されていれば足りる見込み。代償は、微妙な向きの矛盾（S-501/S-506 の類）を見落とす恐れ。
- どちらも未測。費用を測る最初の数回を opus で回して収穫を見てから sonnet に落とす、または逆、のどちらかを利用者が選ぶ。確信 低。

### D4 規則の置き場所: 定義の中（親、DM-8 に手順の本文）か、`rules/documents.md` の節（私、番号付き）か

- 定義の中: 一か所で読める。足す規則の文書が少ない。代償は、定義は利用者が編集する場所（`leader-rules.md` 6.7）で、点検の手順を直すたびに利用者の編集になること、親が報告を審査するときの基準（「どの行に当たるか」）を定義から引くこと、DF-3 の「定義は規則の行を指すだけにする（定義に一覧を写さない）」の向きと逆になること。
- `rules/documents.md` の節: 番号で指せる（報告の「5.5 に当たる」、親のレビューの基準）。親が提案し利用者が了承する今の流れのまま。代償は、規則の章が一つ増え、定義は短い参照になる（私の第 1 段の形）。

### D5 「写しを ID の参照にする」の条件と、頭の欄の状態

- 親: 「正本が残り、意味が同じとき」。私: 「字面が同じか、改行・字下げ・句読点の差だけ」。
- 意味で判定: 言い換えの写しも畳めて、残る写しが減る。代償は、「意味が同じ」が担当の判断になり、第 1 段で挙げた S-501 の行と設計メモ G6（同じ主張の別の語で、両方不正確）のように差に意味が隠れる危険。親の差分の読みで受ける。
- 字面で判定: 機械的で、担当の裁量が無い。代償は、言い換えの写しは全て「重なり」の指摘として親に戻ること（件数が多ければ親の手間）。
- 状態の欄（上の誤り 4）: 「本文に日付付きの『決定:』『判断:』があるときだけ `status` と `decided` を合わせてよい」（私）か「状態は一切変えず報告」（親の表の右列）か。前者は gate の整合に寄与し根拠が本文にある。後者は線が単純。移行の ✅ と `status` の食い違い（DF-4）は件数が多い見込みなので、ここだけは「一覧を出して親が決め、担当が当てる」で両案が一致する。確信 中。

### D6 範囲の上限の決め方: ファイルの差分 + 二段目 10 ファイル（親）か、ID の件数の上限（決定 30・作業 15、一段のみ）（私）か

- 折衷: 範囲は差分で決め、一覧の数が上限（例: 決定 30・作業 15・他の文書 10）を超えたら親が票を分ける、二段目は 10 ファイルまで。確信 中。
