# X-3 修正候補の約束と、空白の族（38 回目、2026-10-17、決定）

**決定（2026-10-17、利用者）:** X3-1a〜X3-1g と X3-2 の全て。項目ごとの答えは各節の頭にある。
X-3 は細かい項目なので、利用者の文（問題点と改善の手順）の代わりに、親が持ち越しから論点を一つずつ出し、利用者が会話で決めた。
advisor の独立のレビューは X3-1b と S-345 の二つ（`adv/handback_x3_1b.md`、`adv/handback_s345.md`）。実験の道具は `tools/`（`contain.py`、`titles.py`）。

## X3-1a 仕様が修正候補について約束すること

- 決定: 案 B。約束は三つの層だけにする。
  - L1 安全: 当てた後、触れた単位に同じ段以前の診断を残さない（S-236）。
  - L2 編集の形: 変えるトークンだけの最小の編集と、範囲の外の字句の読み（S-251）。
  - L3 候補の数: 複数を出すのは直し方が一つに決まらないときだけ。候補を出さないことも数に含む。
- 約束しない層: L4 候補の順（S-315、E0010 の並べ方）、L5 当てた後の全文。
  候補の文字列と順は実装が選び、それを決める S を起こさず、親のレビューで見る。
- 利用者の理由: X-6 の大きなリファクタリングの前に、候補の細部の制約で実装が収束しなくなるのを避ける。
- 基準: `rules/criteria.md` 7.18。L4 と L5 に頼る使い手（CI、修復のループ、テスト）を挙げられない。§18.2 に候補を自動で当てるコマンドは無い。
- 材料: 12 回目の数えで、S-300〜S-424 の 125 件のうち 71 件が修正候補の形・数・順の項目だった。

## X3-1b テストで候補を確かめる形

- 決定: 案 Q と advisor の 1。
  - 約束のテストは、器の L1 と範囲の外の読み、`[[test.fix]]` の性質（`clean`・`same_code`・`leaves`）、候補の数にする。
  - 全文（`.fixK`、`spec/foreign-forms.toml` の `fixed`）は実装の回帰の写しにする（Q-04 の golden の扱い）。
    違いは器が失敗にするが、仕様の違反ではない。意図した変化なら `UPDATE_GOLDEN=1` で書き直し、報告に並べ、親が差分を読む。
  - 道具が書き直すのは全文だけにする。数（`fixes = N`、`candidates`、`fixed` の個数）と `[[test.fix]]` の性質は手で直す。
  - 写しの違いは `fix-contract` と別の種類の失敗にし、実装待ちの一覧で互いに黙らせられないようにする。
- 退けた案: P（全文の比べをやめる。L1 を守るが意図と違う候補に気付けない）、R（違いを警告だけにする。読まれずに溜まる）。
- 材料: 全文の比べは `fixed` 352 か所（113 行）と `.fixK` 247 個（fix1 209、fix2 37、fix3 1）。
  性質は toml の `property` 60 と、事例の `[[test.fix]]` 127（`clean` 6、`same_code` 14、`leaves` 80）。
  器 `crates/onsa_tests/src/fix_contract.rs` は全ての候補で L1 と範囲の外の読みを確かめ、最小の編集は見ていない。
  「編集は診断の範囲に収まる」の性質は、今の候補 2,259 のうち 1,191 が外れて使えない（`tools/contain.py`）。
- 他の言語: rustc の UI テストの `.fixed` は `--bless` で実装の出力から作り、当てた後にコンパイルできることも求める（rustc-dev-guide の「UI tests」）。
  rustc は JSON の候補ごとに `suggestion_applicability` を付ける（rustc 1.94.1 で確かめた）。

## X3-1g 器で最小の編集の一部を確かめる

- 決定: 案 g1。器に五つ目の確かめを足す。一つの編集の範囲のトークンと置き換える文字列のトークンを比べ、次を見つける。
  - 縮められる編集（先頭か末尾のトークンが同じ）。
  - コメントを範囲に含めた編集（範囲の中のコメントが置き換える文字列にそのまま出る）。
  - 二つに分けるべき編集（中に共通のトークンがある）。
- 時機: X3-1b の器の直しと同じ単位で、X-6 の前。今の違反は、少なければ同じ単位で直し、多ければ `fix-contract` の実装待ちの項目にする。
- 過大な編集（文をまるごと消すなど）は機械で判定できず、写しと親のレビューが受け持つ。
- 見つけた違反は R-237 に登録した（`tests/spec/fixes/e0020_clock_after_fn_type.onsa`）。

## X3-2 仕様の空白を規則の族ごとに決める

- 決定:
  - x2a: 空白の流れで、親が登録のときに族を付け、下書きの担当は一つの族を一つの組として受け持つ。
    下書きは族の全ての形（記号と位置の組み合わせ）を既決のものも含めて表にし、族の一般の規則を案にする。規則の文は親が案を出し、利用者が了承してから書く。
  - x2b: X-8 で、期限を過ぎた S の段を決め直すときに、未決の S を族に分け直す。
- 基準: 二つの空白は、仕様の同じ規則の文を一つ直せば両方決まるか。決まるなら同じ族である。
- 材料: §2.5 の行頭の記号と空白の族が S-370 → S-386 → S-398 → S-405 → S-423 と時期をずらして決まり、後の決定が前の文を広げ直した。
  今の未決にも固まりがある（§2.4 の字句の形 約 12、§2.5 の空白と改行 約 8、§2.1 のコメント 4、§11.3 のクロック 3 以上）。
