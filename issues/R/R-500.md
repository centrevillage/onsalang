# R-500 失敗した const を読む定数の位置に E0200 が出る（flow の定数の位置の impl の関連定数 `S.BAD`、fn の世界の配列の長さ `[F32; BAD]`）

- 場所: `crates/onsa_sema/src/flow/consts.rs`（`flow_const_u32` の `names_failed_const` は直下の `const` だけを見る）と、fn の世界の配列の長さ（`ComputedArrayLengths`）。
- 内容: §18.1（読めなかった部分を使う側には診断を出さない）に反し、型の誤りのある `const` を読む定数の位置に E0200 が出る。
  (1) flow の定数の位置で `impl` の関連定数を読む形（`impl S { const BAD: U32 = true }` と `delay~(x, S.BAD)`）は `FlowConstExprs` の E0200。W7-14 U3 は R-499 の直しで、先に型付けする `const` をモジュールの直下に限った（`impl` の `const` まで先にすると、`constarg` の読めない判定（`impl` の単位の失敗）に効く恐れがある）。
  (2) fn の世界の配列の長さ `[F32; BAD]`（署名と本体）は `ComputedArrayLengths` の E0200。署名は `const` の値より先に読む。
  どちらも誤りのある単位のある入力で、通るプログラムは変わらない（余分な診断だけ）。再現は横の `R-500/flow_impl_const.onsa`、`R-500/fn_array_length.onsa`。
- 経緯: 167 回目、2026-11-18、W7-14 U3 の実装の担当が R-499 の残りとして報告し、親が登録した。
- 判断: 直す（低）。二つの E0200 はどちらも定数式の値の計算（R-195、W9-03）が外す門なので、W9-03 で失敗した `const` を誤りの値として読む形にする。
- 補い（2026-11-18、親）: W7-14 U3 の壊す側（167 回目）が同じ類の形を三つ足した: 失敗した `const` を読んだだけの `const`（`const B2: U32 = BAD`、`BAD + 1`）と、署名の失敗した関数を呼ぶ `const`（`const C: U32 = bad(1)`）を、flow が遅延の長さや `par~` の端で読むと `FlowConstExprs` の E0200（前からの挙動）。`B2` は自分の診断を持たないので `Failures` に載らない。
  この三つの E0200 は連鎖でなく版の制限で、R-500 の (1)・(2) と類が違う（2026-11-19 に改めた。下の補い）。再現は横の `R-500/flow_const_chain.onsa`・`R-500/flow_const_from_failed_fn.onsa`
- 補い（2026-11-19、親）: 168 回目、利用者の了承（離席中の控えの P-2）: 上の三つの形の E0200 は、`BAD` を正しい値（`const BAD: U32 = 4`）にしても同じ位置に出る（`const B2: U32 = 4 + 1` も同じ）。
  flow の定数の位置は、この版では値が整数リテラルの `const` だけを読む（`FlowConstExprs` の E0200 の note の字）ので、失敗した `const` を読むことでなく、値がリテラルでないことで出る版の制限で、`BAD` を直しても残る。§18.1 の偽の連鎖エラーではなく、今は直さない。
  (1) の `impl` の関連定数は、値を正しくすると誤りが消えるので連鎖のまま。W9-03 で制限を外すとき、失敗した `const` を読む `const` の値は誤りの値として伝え、使う側に診断を出さない（再現は横の `R-500/flow_const_chain.onsa`・`R-500/flow_const_from_failed_fn.onsa`）
