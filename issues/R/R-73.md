# R-73 数値リテラルの修正候補が値を変える

- 中・直す + 要判断・観点 1 / 3｜`crates/onsa_syntax/src/lexer.rs:136`、`:179-209`｜§2.4
- 値を変える修正候補:
  - `0o17` と `0X1F` が「型の接尾辞は無い」の E0020 になり、修正候補が `0` になる（値が変わる）。
  - `0x1F_u8` の修正候補が `0x1F_` になる。
- 誤った文面: `0x_` が「larger than any integer type holds」になる。
- 判断（R-73）: 小数点の無い `1e3` を浮動小数として受理しているが、仕様の例は `2.5e-3` だけで、`impl-review` にも記載が無い。
  - (a) 許す（Rust と同じ）。
  - (b) 小数点を必須にする。
  - 推奨は (a)。
- 範囲（2026-10-04 に追加で確かめた）: `0B101` も候補 `0`、`1_000_i32` は候補 `1_000_`、`1f32` は候補が整数の `1` になる。`123abc` は型の接尾辞として扱われる。`1.e3` は `1` のフィールド `e3` と読まれて E0420 になる。`017` は 10 進の 17 として通る（R-124）。`1E3`、`0xff`、`1__000`、`1_`、`0x_1F`、`01.5` は通り、fmt も揃えない。
- 決定（2026-10-04）: (a) 許す（理由は Rust ではなく、主要な言語が全て浮動小数と読むことと P10）。S-62: 修正候補は値も整数か浮動小数かも変えない。既存言語の形（`0o17`、`1.e3`、型の接尾辞）は E0020 で、接尾辞は閉じた一覧で認識し、一覧に無いものと `0x_` は E0001。
  綴りの揺れ（接頭辞と指数の大文字、16 進の数字の大小、`_` の位置、浮動小数の余分な 0）は受理して fmt が揃える。先頭が 0 の整数は R-124（S-63）。再現は `tests/review-phase1/parent/r73.onsa`。
- 判断: (a) 許す。S-62: 指数があれば小数点は不要（`48e3`）。修正候補は値も整数か浮動小数かも変えない。既存言語の形（`0o17` → `15`、`1.e3` → `1.0e3`、型の接尾辞は閉じた一覧で認識して除き、整数の形に浮動小数の接尾辞なら `.0`）は E0020。一覧に無い接尾辞と `0x_` は E0001。
  綴りの揺れ（接頭辞と指数の大文字、16 進の数字の大小、`_` の位置、浮動小数の余分な 0）は受理し、fmt が揃える（Black と同じ向き）。fmt の安全装置はリテラルを値で比べる。再現は `tests/review-phase1/parent/r73.onsa`
- 反映: 仕様 §2.4 / §18.1 / §18.2 に反映済み（2026-10-04）。実装は W3-05
