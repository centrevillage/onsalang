# R-254 `use` で取り込んだモジュールに無い名前の `inner.h()` が、名前の段の E0302 でなく型の段の E0401「`inner` is not a value」になる

- 場所: 本体の名前の解決（`use` の束縛の名前の経路。W4-04 の `body/names.rs` の作り直しの範囲）
- 内容: 再現は横の `body_missing_name/`（`main.onsa` の `use kp.inner` と、`kp/inner.onsa` に無い `h` を引く `inner.h()`）。型の段の E0401「`inner` is not a value」になる。§15.1 と §18.1 の段の順では、取り込んだモジュールに無い名前は名前の段の E0302（「`inner`（`kp.inner`）に `h` が無い」）。
  E0200 の `pub use` と子モジュール `main/inner.onsa`（`h` が有る）の後の他のモジュールの `use main.{inner}` と `inner.h()` も今は同じ文面だが、S-611 では子モジュールを指して通るのが正しく、W4-03 で直す（`target/notes/58/gap44/probe/ov2.out` の `pubuse_child_other_list`）。
- 経緯: 第 44 組の一回目（S-611）の下書き（onsa-gap、2026-10-23、58 回目）の付録が文面の問題として挙げ、独立のレビューの段 1・段 2 がコードと段の両方が違うので R にすると決め、利用者が了承した（A6）。直しは W4-04。
- 判断:
- 補い（2026-10-27、親）: 74 回目: S-693 で、他のモジュールの本体の経路が E0200 の `pub use` の名前を引く形（`use main.inner` の後の `inner.g()`）も E0302 に決めた。この R の直しで、その形の E0401 も E0302 になる。
- 補い（2026-10-27、親）: 75 回目（2026-10-27）: 型の頭でも同じ割れがある。`pub struct P` の後の `P.y` は E0302「cannot find `P.y`」、`P.y()` は E0401「`P` is not a value」（`body/calls.rs` の経路の呼び出しが失敗すると受け手を値として型付けする道に落ちる、R-254 と同じ根）。
  W4-04 の U5 で E0302 に揃える。第 65 組の助言の段 1・段 2 が見つけ、親が再現した。
- 補い（2026-10-27、親）: 76 回目（2026-10-27）、W4-04 U3a: 型付けの切り替えで、呼び先の最後の名前が無い形は歩き手が名前の段の E0302 にする。実装待ちの `body_path_member_missing`・`pub_use_child_module_missing_name`・`visibility_use_binding_path` は通り、項目を外した。`review-phase1/types/flowimpl.onsa` の `voice.SIZE` も E0401 から E0302 になった。残りの U5 の形（文面、候補、`P.y()`）は U5 で確かめる
