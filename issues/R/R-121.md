# R-121 C の API の名前空間、版、panic の通知が仕様に無い

- 中・要判断・観点 3｜`runtime/c/onsa.h`、`crates/onsa_backend_c/src/export.rs`｜§9.2、§14.2、§15.3、`impl-review` B-8
- `prefix` を空にできるかが決まっていない。空にしてパッケージ名が `onsa` なら、ヘッダ `<prefix><package>.h`（S-52）がランタイムの `onsa.h` と重なる。
- `prefix` の既定は `onsa_` で、二つのパッケージから作ったライブラリを一つのバイナリにリンクすると、同名の flow（`onsa_voice_process` など）が重なりやすい。既定をパッケージ名（`voice_`）にする案がある。
- ランタイムの版: 二つのライブラリのヘッダを一つの C ファイルから取り込むと、インクルードガードで先に読んだ `onsa.h` だけが使われ、版が違うと `onsa_param_info` の配置などが黙って食い違う。ABI の版のマクロと、各パッケージのヘッダでの静的な検査が要る。
- export した関数の panic: §9.2 は「エラーコードに変換する」とするが、値を返す関数には返す場所が無い。実装はゼロ値を返し、`<prefix>take_panic()` で 1 回だけ読める（B-8、仕様に無い）。
- 判断（R-121）:
  - `prefix` を空にできるか、既定を何にするか。
  - ABI の版の検査を入れるか。
  - 関数の panic の通知: (a) `take_panic` を仕様にする、(b) C の形を `int f(…, T* out)` にして戻り値で状態を返す（flow の `process` と同じ形）。
- 経緯: R-64 の議論で見つけた（2026-10-04）。
- 経過（2026-10-05）: 関数の panic の通知は、R-107 で (b) に決めた（S-92）。残りは `prefix` と ABI の版。ABI の版の検査は、S-87 で `onsa_param_info` の配置を変えたことにも関わる。
- 範囲（2026-10-05 に追加で確かめた）:
  - 既定の prefix の二つのパッケージ（`pa` と `pb`。どちらも flow `gain` と関数 `version`）を一つのホストにリンクすると、コンパイルもリンクも警告なしに通り、`pb` の `onsa_version` は黙って捨てられる（`pa=1 pb=1`）。flow のヘッダもガードが同じなので、後のものは読まれない。
  - `prefix = ""` でパッケージ名が `onsa` なら、パッケージのヘッダがランタイムの `onsa.h` を上書きし、cc が 20 個の誤りで失敗する（診断コードは無い）。
  - 関数 `param_info` / `reset_hook` を export すると、`onsa.h` の型 `onsa_param_info` や、ファームウェアのフック `onsa_reset_hook` と重なり、cc の誤りになる（E1011 はパッケージの中の重なりだけを見る）。
    §14.2 の「ランタイムの内部の記号（`onsa__`）とは重ならない」は内部の記号だけの保証で、公開の名前は既定の prefix と同じ名前空間にあった。ランタイムに公開の名前を足すたびに、既存のパッケージの名前と重なりうる。
  - `onsa.h` のガードは `ONSA_H` だけで、版を持たない。違う版の `onsa.h` を前提にしたパッケージのヘッダを一つの C ファイルで取り込むと、先に読んだ方の配置で黙って読む。
  - 生成物のファイル名（今は `onsa_<package>.c`、`libonsa_<package>.a`）は仕様に無かった。
  - 再現は `tests/review-phase1/parent/r121/`（`pa`・`pb` と `host.c`、`onsa`、`rt`）。
- 決定（2026-10-05）: S-95。
  - (1) `prefix` は、flow か関数を export するなら必須で、既定は無い（(c)）。書かなければマニフェストの誤りで、文面に `prefix = "<package>_"` の形を示す。利用者の判断: 重なりを避ける上で最も柔軟。既定をパッケージ名にすると、偶然重なったときに避ける手段がパッケージ名の変更しか無く、その事情でパッケージ名を変えるのは余分な判断になる。
  - (2) 値は小文字の英字・数字・`_` からなり、英字で始まって `_` で終わる。空、`__` を含むもの（C++ では予約）、`onsa_` で始まるものは書けない（マニフェストの誤り。出し方は R-130 で決める）。ランタイムは `onsa_` と `ONSA_` で始まる名前を全て持ち、生成する名前とは構造で分かれる。
  - (3) `onsa.h` の中身は設定に依らず、ABI の版 `ONSA_ABI_VERSION`（この版は 1）を定義する。パッケージのヘッダは取り込んだ直後に版を確かめ、違えば `#error` で止める（(a)）。版は `onsa.h` の共有の部分（型、列挙子、フックとマクロの名前と形）を互換でなく変えたときに上げ、コンパイラの版とは結び付けない。ヘッダと、別のビルドで作ったライブラリの組み合わせは検査しない。
  - (4) 生成するファイルの名前は `<prefix><package>` を幹にする（ヘッダ `.h`、C のソース `.c`、静的ライブラリ `lib<prefix><package>.a`）。`onsa.h` と `onsa__runtime.h` は固定の名前（`onsa_build.json` は仕様に無いままで、この決定では扱わない）。
  - 仕様の例の prefix を `onsa_` から `vc_` に改めた。prefix の規則は C の名前に掛かる。WASM / JS（第 1 期、仕様 §20 の 6、7）はモジュールが名前空間を持つので、その出力を作るときに要るかを決める。
- 判断: S-95: `prefix` は export するなら必須で既定なし（利用者の判断: 既定がパッケージ名だと、偶然の重なりを避ける手段がパッケージ名の変更しか無い）。値は小文字の英字・数字・`_` で英字で始まり `_` で終わる。
  空・`__` を含むもの・`onsa_` で始まるものは書けない（ランタイムが `onsa_` / `ONSA_` を持つ）。`onsa.h` に `ONSA_ABI_VERSION`（1）、パッケージのヘッダが `#error` で確かめる。生成するファイルは `<prefix><package>` を幹にする。仕様の例の prefix は `vc_`。
  panic の通知は R-107（S-92）で決定済み。再現は `tests/review-phase1/parent/r121/`
