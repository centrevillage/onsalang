# R-06 値を返す `match` の一般経路が、インタプリタでも C でも動かない

- 高・直す・観点 1 / 2｜`crates/onsa_core/src/lower/body.rs:693`、`verify.rs:189`｜§7｜再現（親）
- 対象: `Switch` にならない値の `match`。ガード付き、`Bool`・整数・`Char` のリテラルパターン、タプルや struct のパターン、enum でない対象への束縛。
- 症状: インタプリタは `internal: local read before initialization` で落ち、C は `unknown local` でビルドできない。
- 原因: `__result` を一時変数として作るだけで、宣言していない。検証器は「代入で定義済みになる」規則を持つので、これを通した。
- 例: `match n { 1 => 10, 2 => 20, _ => 30 }`。flow の §11.2 の `match c { true => ..., false => ... }` も同じである。
- 既存のテスト `tests.rs:101` は、dump に `__result` が含まれることしか見ていない。
- 直し方: `__result` を宣言し、検証器から「代入で定義」の規則を除き、各パターンの形を実行するテストを足す。
