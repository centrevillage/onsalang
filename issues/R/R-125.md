# R-125 std のテスト用の補助を、テストの外から呼べるか

- 中・要判断・観点 3｜`std/test.onsa`、`std/test/gen.onsa`、`std/dsp/test.onsa`、`crates/onsa_interp/src/lib.rs:1134`｜§11.8、§15.2
- 内容: §11.8 は `std.test` の `check` と `gen.*`、`std.dsp.test` の `assert_near` を定めるが、どこから呼べるか、どの変換先が与えるかを決めていない。`std/test.onsa` の doc コメントは「第 1 期は `test` の本体の中だけ」とするが、仕様に無く、検査もしていない。
- 今の動き（2026-10-04 に確かめた）:
  - `check` は `uses {Random}` を持つので、`main` や export する関数から呼ぶと、`provides` に `Random` の無いターゲットでは E0610 で止まる。
  - `gen.*` と `assert_near` は効果を持たず、どこからでも呼べる。`gen.u32(0, 9)` を呼ぶテストは `check` を通り、`onsa test` の実行時に「not available in this version of the interpreter」で落ちる（M5 で実装する予定）。`assert_near` を export する関数で使うと、`onsa build` で E0200。
  - C で `assert_near` を与えるには、浮動小数の `Show` の書式（§6.3）が C のランタイムに要る。
- 判断（R-125）:
  - (a) テスト用の補助は `test` の本体の中でだけ呼べる。それ以外はエラーにする（規則と診断コードを足す）。
  - (b) 制限しない。全ての変換先が与える。この版で与えない変換先で使うと、そのビルドで E0200（R-79 の論点 3、4）。
  - 推奨は (b)（暫定）。規則を足さずに済む。R-79 の論点 4（std の `target` 宣言を誰が与えるか）と一緒に見直す。
- 経緯: R-79 の議論で見つけた（2026-10-04）。
- 範囲（2026-10-05 に追加で確かめた）:
  - 仕様 §8.5 は、`test` の本体でテストランナーが `Alloc` と種を決めた `Random` を与えると書く。R-79 の (3)(4)（S-69、§15.2）で、std の `target` 宣言を与えない変換先は E0200 と決まっていた。
  - 効果行の無い関数から `check`（`uses {Random}`）を呼んでも `onsa check` を通る。第 1 期の効果の検査は `Alloc` だけ（S-23）。`uses {Random}` と書くと E0200（S-74 のとおり）。
  - `Gen[T]` は `pub struct` でフィールド `seed` が可視性を継ぐ（S-35）ので、`Gen { seed: 7 }` と生成器を通さずに作れる。仕様 §11.8 は `Gen` の中身を定めていない。今の `seed` だけでは `gen.f32(lo, hi)` の範囲も表せない。
  - `check` を呼ぶテストは、無名関数の値の降下が M5 なので今は E0200（R-08 の補足）。
  - 再現は `tests/review-phase1/parent/r125.onsa`。
- 決定（2026-10-05）: S-97。
  - (1) (b) を暫定でなく正式にする。テスト用の補助は普通の std の関数で、`test` の外からも呼べる。呼べる場所は効果行（`check` は `Random`。`test` の本体ではランナーが与える）と §15.2 の変換先の規則で決まる（§11.8）。
    `test` の本体に限ると、補助を関数に切り出すために「テスト専用の関数」の印が要り、第 2 期の `tests/`（R-122）にも広がる。`Random` を効果行に書けない第 1 期は、新しい規則なしに事実上テストの本体だけになる。
  - (2) E0601 は、第 1 期から std が宣言する全ての効果の使用を検査する（S-23 の「第 1 期は `Alloc`」を改めた。判定は S-77 の使用の記録を読む）。第 1 期の `Random` の E0601 は修正候補を出さず、「この版では `Random` はテストの本体でだけ与えられる」と note で示す（D-08 の追記）。
  - (3) `Gen[T]` の中身は公開しない（§11.8）。std の宣言のフィールドを `priv` にし、本当の表現は `check` を実装する M5 で決める。`std/test.onsa` の doc の「第 1 期は `test` の本体の中だけ」は、仕様に無い規則なので「`Random` はテストの本体でだけ与えられる」に改める。
- 判断: S-97: テスト用の補助は普通の std の関数で、`test` の外からも呼べる（(b) を正式に）。呼べる場所は効果行（`check` の `Random` はテストの本体でランナーが与える）と §15.2 の変換先の規則で決まる。
  E0601 は第 1 期から std の全ての効果の使用を検査する（S-23 を改めた。`Random` の E0601 は修正候補を出さず note）。`Gen[T]` の中身は公開しない（フィールドを `priv`）。再現は `tests/review-phase1/parent/r125.onsa`
- 反映: 仕様 §11.8 に反映済み、計画 D-08 と S-23 に追記（2026-10-05）。実装は W6-03（E0601 は R-83 と同じ回）
