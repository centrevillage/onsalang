# R-518 flow の `let` の値が構文の誤りで読めなかった型の値を読むと、`check` が内部エラー（`post_check` の「まだ診断が無い」に頼る確かめ）

- 場所: `crates/onsa_sema/src/flow/clocks.rs` の `post_check`。
- 内容: 型の宣言が構文の誤りで読めなかった（`pub struct Note:  {`）とき、その型の値を読む flow の `let`（`let v = vel(m) * 2.0`、`m: Note at block` か `at event`）のクロックは診断なしに `Error` になる。`post_check` は「まだ診断が無ければ `Error` の `let` は無い」と確かめていて、構文の誤りはモジュールごとの診断で `a.diagnostics` に入らないので、内部エラーになった（178 回目の「まだ診断が無い」に頼る守りと同じ類）。
- 経緯: 184 回目（2026-11-25）、W7-11 U1b の壊す側（onsa-break）が `at event` の事例の 1 トークンの消しで見つけた。`0100f4c2` でも `block` の入力の形で再現するので、前からある。
- 判断: 直した（W7-11 U1b のコミット）。`post_check` から「まだ診断が無い」の条件を外し、二つの段のクロックの食い違いだけを確かめる。事例 `tests/spec/flow_clock/let_of_a_type_in_error_r518.onsa`。
