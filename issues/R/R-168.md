# R-168 `let _x = 1` が束縛の位置で E0302 になる

- 低・直す・観点 1｜名前の段｜§5.1、§2.3
- 内容: `let _x = 1` を書くと、束縛の位置に E0302「cannot find `_x`」が出る。`_` で始まる名前は §2.3 で書け、特別な意味は無い。使われない束縛なら E0309（§5.1）で、使われるなら普通の束縛である。束縛として登録されないまま、参照として解決しようとしているように見える。
- 経緯: S-243（E0320 の候補が予約語になるとき）の検討で、先頭の `_` の扱いを確かめて見つけた（2026-10-08）。`pub fn _match()` は通る。
- 決定（2026-10-08、親）: 直す。名前の段の本体の解決（W4-04）で、`_` で始まる名前を普通の束縛として扱い、使われなければ E0309 にする。
- 判断: 直す（親、仕様が明確）。`let _x = 1` を普通の束縛として扱い、使われなければ E0309。S-243 の検討で見つけた
- 反映: 実装は W4-04
- 補い（2026-10-24、親）: 62 回目（2026-10-24）: 同じ形が S-648（族「§2.3 の名前の形」、S-650）の論点に入った。判断の前提（§2.3 が頭の `_` を受ける）は S-650 の決め方で改めうる。原因は名前の段でなく構文解析器の `naming.rs` の `is_binding_name`（先頭の小文字）で、構文の段で束縛にならない（S-650 の下書き）。
- 判断（2026-10-24、親）: 改めた（2026-10-24、62 回目、S-648・S-650 の決定）: `_x` は頭の `_` を飛ばして束縛と読み、名前の規則（頭の `_` は書けない）で E0320、候補は `x`。直すのは W4-14 U3（構文解析器の `is_binding_name` と名前の規則）。
