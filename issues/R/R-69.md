# R-69 `onsa fmt` が、構文エラーのある関数を黙って削除する

- 高・直す・観点 1 / 2｜`crates/onsa_syntax/src/fmt.rs:16`、`parser.rs:278-280`、`:2026`、`naming.rs:168-184`、`groups.rs:12`、`crates/onsa_cli/src/main.rs:195`｜§18.2｜再現（親）
- 原因:
  - fmt は「E0001〜E0020 があれば拒否する」と判定するが、見ている診断は項目ごとに 1 件へ間引いた後のものである。
  - 命名の検査は、失敗した項目の残骸まで走査して E0320 を先に出す。
  - そのため E0002 が消え、fmt は拒否せずに進む。AST に入らなかった失敗項目は出力されない。
- 再現: `fn f() {\n  let badName = 1\n  let = 2\n}\n\nfn g() {}` に `onsa fmt` を実行すると、exit 0 で、ファイルの中身が `fn g() {}` だけになる。`diff --ast` も同じ判定を使う。
- 直し方:
  - 「失敗した項目がある」ことを明示のフラグで持つ。
  - 命名の検査は、AST の根から辿れるノードだけを対象にする。
  - fmt の出力を再解析し、AST が変わらないことを確かめてから書き込む安全装置を入れる。
- 決定（2026-10-04）: 直す。S-56: 構文の診断（E00xx）のあるファイルは書き換えず、複数のファイルは全て処理する。fmt が AST を変える書き換えは閉じた一覧（末尾の `return`、冗長な括弧、既定値と等しい `init`）にし、安全装置はその書き換えを施した AST、doc、コメントの並びを比べる。`diff --ast` も同じ比較を使う。終了コードは全てのコマンドで 0 / 1 / 2 / 101 とし、安全装置が働いたら 101。
- 判断: 直す。S-56: 構文の診断の有無を、減らす前に明示のフラグで持ち、命名の検査は AST の根から辿れるノードだけにする。fmt は構文の診断（E00xx）のあるファイルを書き換えず（E03xx 以降は妨げない）、複数のファイルは全て処理する。fmt が AST を変える書き換えは閉じた一覧（末尾の `return`、冗長な括弧、既定値と等しい `init`）。
  書き込む前に再解析し、一覧の書き換えを施した AST、doc、コメントの並びを比べ、違えば書き換えずに内部エラー。`diff --ast` も同じ比較。終了コードは全てのコマンドで 0 / 1 / 2 / 101。冪等性は性質テスト（R-113）。
  改め（2026-10-15）: `init` を一覧から外した（S-539）。`diff --ast` は同じ正規化を施した構造だけを比べる（S-534）
- 反映: 仕様 §18.2 に反映済み（2026-10-04）。実装は W3-03
