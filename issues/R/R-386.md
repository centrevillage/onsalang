# R-386 根の頭が同じ腕が並ぶ match の到達の判定が腕の数の二乗で増える

- 場所: `crates/onsa_sema/src/exhaust.rs`（`Seen::rows_for`、`Checker::useful`）
- 内容: 根の索引は根の頭が違う腕だけを分ける。`(i, j)`、`Some(i)`、struct のように根の頭が全て同じ腕は、腕ごとに前の全ての行を見るので、E0503 の判定が腕の数の二乗になる。前の実装は判定が E0501 の一回だけで、この二乗が無かった。
  前後（debug の固定のバイナリ `onsa-dfb90a8` と `onsa-w509u2`、上限 65536、`onsa check` の壁時計）: 列挙子 10 個の 4 列の全ての組 10000 腕は 0.09 → 0.83 秒、8 個の 5 列 32768 腕は 0.27 → 9.9 秒、9 個の 5 列 59049 腕は 0.5 秒 → 30 秒超。`Some(0)`〜`Some(19999)` は 0.06 → 2.2 秒、`(i % 7, i)` の 20000 腕は 0.05 → 2.6 秒。
  release の `pairs4000` は 0.105 秒、`pairs1000` は 0.011 秒。
  上限（S-930）は分かれる数を数えるので、この二乗には効かない。上の測りは決定の前の上限 65536 のバイナリで、全ての組の表は今の上限 4096 では `_` が無ければ E0501 で止まる。測り直すときは `_` を足した形にする。腕が数千までのふつうの大きさでは小さい。
- 経緯: 120 回目（2026-11-07）、W5-09 U2 の設計メモ 6 章が見込み、実装の測りと壊す側が確かめた。台本は `target/notes/120/w509u2/`（`lim4.py`、`wide.py`、`measure.py`）。
- 判断: 親: 今は直さない。全て具体的な腕どうしの完全一致を集合で引く形なら約 20 行だが、`(i, _)` のように `_` を持つ腕の二乗は残り、下の列まで索引を持つ形はその作り直しになる（手戻り）。W5-13 の見直しで全体の形を決める。`issues/X/X-20/measure_stages.py` の二乗の族に `pairs` を足す案も同じ時に見る。
- 反映（2026-11-12、親）: W5-13 U6b で、到達の問いの前の行の候補を頭の木（`exhaust.rs` の `Tree`、節ごとに部分木の行）から引くようにした。根の頭が同じ腕の形（`Some(i)`、`(i, j)`、`(i, _)`、`(_, i)`、struct、入れ子、全ての組の表）は線形になった。残る二乗は X-20 の補いへ送った。出力は変えない（木と全ての行で診断が同じかを `exhaust_tests.rs` が決まった種で確かめる）。
