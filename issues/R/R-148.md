# R-148 型パラメータの推論が、期待される型とリテラルの既定を使わない

- 中・直す・観点 1｜`crates/onsa_sema`（総称の struct リテラルと総称の関数の呼び出しの推論）｜§4.5
- 内容: (1) `let w: Wrap[Wrap[I32]] = Wrap { v: Wrap { v: 7 } }` が E0406（`type parameter T of Wrap cannot be determined`）になる。2 段の入れ子で再現する。§4.5 は期待される型から決まるとする。
  (2) `let x = id([5][0])`（`id[T](x: T) -> T`）が E0406。§4.5 は、リテラルの型変数に結び付けば既定（`I32`）に従うとする。`hold(7, 20)`（`[T: Copy]` の関数にリテラルだけを渡す）も同じ（W2-04/t で見つけた）。
- 経緯: W3-14/t で見つけた（2026-10-08）。再現は scratchpad の `w314/t/a2.onsa`・`c2.onsa`（事例では呼び出しの形に置き換えた）。
- 決定（2026-10-08、親）: 直す。仕様は明確で、判断は要らない。総称の呼び出しの型パラメータを関数の終わりまで待つ W2-06（S-174）と同じ回に、期待される型とリテラルの既定を推論に使う。
- 判断: 直す（親、仕様が明確）。型パラメータの推論に、期待される型とリテラルの既定を使う。W3-14/t で見つけた
- 反映: 実装は W2-06
