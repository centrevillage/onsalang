# R-08 `from_fn` に渡した無名関数の中の `?` が、外側の関数から戻る

- 高・直す・観点 1 / 3｜`crates/onsa_core/src/lower/body.rs:1027-1047`、`:307`、`:1282`｜§9.1｜再現（親）
- 原因: 無名関数の本体をその場に展開するとき、`?` を外側の関数の `Return` として降下している。外側の返り値の型が違っても、検証器を通る。
- 再現: `build() -> Option[U32]` の中で `from_fn(fn(i: U32) -> Option[U32] { let h = half(i)?; Some(h) })` を呼び、末尾で `Some(7)` を返す。結果は `None` になる。
- 直し方: 展開した本体に「要素の値」へ抜ける出口を作る。または、`return` と同じく `?` も E0200 にする。

@centrevillage
直し方は前者が良いと思うが、現在無名関数内のreturnを対応していないのであれば一緒に直すべき。
難しければ両方検証エラー。
一方が通って一方が通らない状態は統一感がない。

- 決定（2026-10-02）: 展開した本体に「要素の値」へ抜ける出口を作る。無名関数の中の `return` も同じ仕組みで対応する。難しければ `?` と `return` の両方を E0200 にする。片方だけ通る状態にはしない。
- 決定の補足（2026-10-02）: 無名関数は今 `array.from_fn` の中でだけ使え、その場に展開される。M5 で `std.test.check` のために本物の関数値を降下するときに、`from_fn` の展開もその仕組みに寄せるかを再検討する。
- 判断（2026-10-02）: 展開した本体に「要素の値」へ抜ける出口を作る。無名関数の中の `return` も同じ仕組みで対応する。難しければ `?` と `return` の両方を E0200 にする。片方だけ通る状態にはしない
