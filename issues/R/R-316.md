# R-316 降下の後の配置の計算（`onsa_core::layout::size_align_for`）が宣言の答えを覚えず、一段ごとに同じ struct を二つ持つ鎖を使う関数で、`interface`・`dump --core` などの降下に進むコマンドの時間が段の数の指数になる

- 場所: `crates/onsa_core/src/layout.rs` の `size_align_for`・`record_for`（`Ty::Struct`・`Ty::Enum` の中身を、問うたびに辿る）。
- 内容: R-313 と同じ鎖（`struct A_k { x: A_{k-1}, y: A_{k-1} }`）を関数で使う形（横の `double22.onsa`、`fn f(a: A22) -> A22`）は、`check` が 0.00 秒で、`interface` が 18 段 0.04 秒、20 段 0.16 秒、22 段 0.63 秒、24 段 2.55 秒（W4-05 U2b の後。標本の時間は全て `size_align_for` と `record_for`）。
  手数は型を平らにしたときのフィールドの数（固定長配列は掛け算で、数えない）に比例するので、ふつうの大きさの型では小さい。指数になるのは、宣言の数に比べて型の大きさが極端に大きい形だけである。誤りの診断は変わらず、時間だけの問題。
  降下は型を中身の無い形（`TypeDefKind::Opaque`）で登録してから中身を埋める（`lower/mod.rs`、`lower/flow/mod.rs`）ので、答えを覚えるなら、覚え始める時機に W4-05 U2b（R-313）と同じ注意が要る。見当は約 25〜40 行。
- 経緯: 80 回目（2026-10-28）、W4-05 U2b の親のレビューで、R-313 の入力の `interface` が U2b の後も 2.55 秒（前は 4.17 秒）かかることから見つけた。前からある。
- 判断（2026-10-28、利用者）: 特殊な形だけで起きるので、優先して直さない。X-20 の材料にし、測定で降下の配置が目立てば対策の候補にする。
