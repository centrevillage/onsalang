# R-94 総称の `-x`: `Num` と `Neg` の関係が決まっていない

- 中・要判断・観点 1 / 3｜`crates/onsa_sema/src/body.rs:1354`、`:2764-2777`（`implies`）｜§6.3（演算子 trait の `Neg` は `Num` と別に挙げてある）
- 現状: `T: Num` の `-x` を検査が通し、`U32` で実体化すると内部エラーになる（R-03）。
- 判断（R-94）:
  - (a) `Neg` を境界として書けるようにし、総称の `-` には `Neg` を要求する（Rust の `num-traits` に近い）。
  - (b) `Num` は符号無し整数を含まないと定める。
  - (c) 総称の単項 `-` を禁止する。
  - 推奨は (a)。
- 範囲（2026-10-05 に追加で確かめた）:
  - 観点: R-56（S-46）で §6.3 に「`Num` に `Neg` を含めないのは、符号なし整数に無いからである」と書いたので、今は仕様と実装のずれ（観点 1）でもある。
  - 原因: 型パラメータの `-x` を `Num` を満たすかで通す（`body.rs:1354`）。二項の算術も `Num` で代わりに判定し（`require_operand`）、ビット演算は具体的な整数だけを受ける。
    演算子 trait と利用者の trait は境界に書けず、`[T: Num + Neg]` は E0200「user-defined traits as bounds」（`Neg` は標準 trait なので文面も合わない）。具体的な `-u`（`U32`）は E0401 で正しい。
  - 仕様の空白: §6.3 の組込み型の表（閉じた一覧）に演算子 trait が一つも無い（`Neg`、ビット演算）。§3.2 の脱糖先の `WrappingAdd` / `SaturatingAdd` と、`!` の trait が §6.3 の一覧に無く、演算子 trait のシグネチャも無い（R-131 として登録した）。符号付きの `>>` が算術シフトであることも仕様に無い（実装は算術シフト）。
  - 他の言語: 基底に否定を含め、符号なしは折り返す（Haskell の `Num`、Scala の `Numeric`、.NET の `INumberBase`）。符号なしを含む基底に否定を足した細分を置く（Swift の `Numeric` → `SignedNumeric`、num-traits の `Signed: Num + Neg`）。
    否定を独立の能力にする（Rust の std の `Neg`、Lean、F#）。引き算ごと分ける（PureScript の `Semiring` / `Ring`）。型の分類（Go、C++20、Julia）。符号なし整数を主な「数」の概念から外した主流の例は無い。
  - 再現は `tests/review-phase1/parent/r94/`（`check.onsa` は検査、`run.onsa` は実行。期待値と今の出力は各項目の上のコメント）。既存の `body/t2_neg_generic.onsa` も同じ不具合。
- 決定（2026-10-05）: 原案の (a)〜(c) ではなく、数の trait を組み直した（S-84）。利用者の指摘から: 符号付きは普通の計算に使う値、符号なしは「負数を持たない」制約の付いた特殊な数（ID、添字、アドレス）で、用途が分かれる。違いは否定より引き算に出る（`-x` を使わない `a + (b - a) * t` は、`Num + Neg` の分解では `T: Num` のまま `U32` を受け、普通の入力で panic する）。
  - (1) `AnyNum`（全ての数。`Copy` `Add` `Sub` `Mul` `Div` `Rem` `PartialEq` `PartialOrd` と `ZERO`）と `Num`（`AnyNum` と `Neg`。符号付き整数・浮動小数・固定小数点）に分け、符号なし整数は `Num` を満たさない。既定の数の境界を安全な意味にする（P10）。
    `std.math` の `min` / `max` / `sum` は `AnyNum`、`abs` は `Num`。`Float` は `Num` を満たすので否定を持つ。
  - (2) `AnyNum` は `Sub` を含み、0 を下回る引き算は実行時に検出する。`Sub` を除いて `+ Sub` を要求する案は、`AnyNum` を選んだこと自体が印なので印が二重になり、具体的な `U32` の引き算と規則が分かれ、符号なしを受ける総称の関数に頻出する（P10。元の推奨を比べ直して改めた）。
    名前は `AnyNum`（`Arith` は中身と、`NumBase` は .NET の `INumberBase` と、`Numeric` は `Num` と紛れる。`Scalar` は仕様の「スカラ」と衝突する）。
  - (3) `Int`（全ての整数）と `Unsigned`（`Int` の印）を今置く。`Int` は `AnyNum` `Eq` `Ord` `Hash`、ビット演算の 5 つ、`Not`、ラップ・飽和の 6 つを満たし、`ONE` `MIN` `MAX` `BITS` を持つ（`Show` / `Default` は `Num` / `Float` と同じく含めない）。
    `Unsigned` は負数を持たず `>>` が論理シフト。添字・長さ・大きさは `U32` に固定（§4.2）なので、`Unsigned` が要るのは幅について総称のビット操作（`T: AnyNum + Shr` で書いた最上位ビットのループは `I32` の負の値で終わらない）。符号付き整数は `Num` と `Int` を満たし、別名（`Signed`）は付けない。
    `Num + Int` が要るのは否定と整数の機能を両方使う稀な場面に限られ、`AnyInt` / `Int`（符号付き）に揃える案は、多い場面に長い名前が付き、他の言語の「整数」（符号なしを含む）と読みがずれる。`Unsigned` と `Num` が両立しない否定の規則は置かない。
  - (4) 演算子 trait に `Not` とラップ・飽和の 6 つ（`WrappingAdd` など、演算子ごとに一つ）を足す（R-131 の一覧の部分）。§6.3 の表に組込み型の演算子 trait を全て書く。シフトの右辺は `U32`、`>>` は符号付きで算術・符号なしで論理（§3.4）。
  - (5) 第 1 期の実装: 暫定の `Bound` と `implies` に数の trait と演算子 trait を足し、演算子ごとに自分の trait を検査する（単項の `-` の特別扱いを消す）。第 2 期は表の出所を std の宣言に替えるだけになる（R-127）。
  - (6) 診断: 符号なしの否定は、型だけで成り立たないと決まるので E0401 のまま（`0 - x` は値で決まる引き算なので通る。2 の補数の否定は `-%` で書ける）。修正候補は演算子 trait ではなく数の trait に境界を絞る形（否定は `Num`、ビット演算・`!`・ラップ・飽和は `Int`）。
    絞れないとき（`T: Unsigned` の否定、`T: Float` のビット演算）は出さない。符号なしの否定には `-%` の書き方を、E0416 には満たす数の trait を note で示す。
  - (7) 後から足せるもの（総称の整数と具体的な整数の変換、整数のリテラルを `T: Int` の値にすること）は `api-candidates.md` の A-09 / A-10 に挙げた。
- 判断: 数の trait を組み直す（S-84）。`AnyNum`（全ての数、`Sub` を含み、0 を下回る引き算は実行時に検出）、`Num`（`AnyNum` と `Neg`、符号なし整数は満たさない）、`Float`、`Int`（全ての整数。ビット演算・`Not`・ラップ・飽和と `ONE` `MIN` `MAX` `BITS`）、`Unsigned`（`Int` の印、`>>` は論理シフト）。
  符号付き整数は `Num + Int`（別名なし）。`min` / `max` / `sum` は `AnyNum`、`abs` は `Num`。§6.3 の表に演算子 trait を全て書く。第 1 期は暫定の `Bound` に足し、演算子ごとに自分の trait を検査する。符号なしの否定は E0401 のまま（型だけで決まる。`-%` の note）、修正候補は数の trait に絞る形。
  変換とリテラルは A-09 / A-10。再現は `tests/review-phase1/parent/r94/`
