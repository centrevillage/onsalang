# R-443 空白付きの `- b` を前の行につなぐ E0020 の候補が、`%`・ビット演算・`<<`・`as` の式の後で E0010・E0011 を残す（§18.1）

- 場所: `crates/onsa_syntax/src/foreign/spaces.rs`・`foreign/lines.rs` の構文の段の E0020 の「前の行につなぐ」候補。
- 内容: `a % b` 改行 `- b`（行頭の空白付きの `-`）の E0020 のつなぐ候補（fix2）は、当てると `a % b - b` が E0010（演算子の組の混ぜ書き）になり、`onsa_cases --fix-contract` で「after it, the units its edits touch hold 27:3 E0010 of its stage or an earlier one」。ビット演算・`<<` の後も E0010、`as` の後は E0011。`let`・`if`・`match`・`while`・`for`・`test`・無名関数の中の同じ形も（壊す側の掃引で 20 件）。`a` の次の行が `- /* c */ b` のとき、候補 `write a line comment` が E0020 を残す形も同じ所（`cm_cmt_in_neg.onsa`）。前からの形（dev `d8503f23` と U8b の後で同じ）。E0418 のつなぐ候補（`onsa_sema/src/body/reach.rs::joined_line` の `on_the_left`）は AST で `%`・ビット演算・`as` の後を外しているが、構文の段の候補はトークンで判定して同じ判断を持たない（D-15）。再現は `issues/R/R-443/`（`onsa_cases --fix-contract`）。
- 経緯: 142 回目（2026-11-12）、W5-13 U8b/b（onsa-break）が見つけ、親が前のバイナリで再現した（4 ファイルで 4 件の違反）。
- 判断（2026-11-12、親）: 構文の層を触る W5-13 U7b で直す（候補の有無だけが変わる）。
- 補い（2026-11-12、親）: 142 回目（2026-11-12）、W5-13 U7b の担当が格子（前の行 24 形 × 次の行 8 形の 192 件、`target/notes/142/w513u7b/r443/`）で範囲を確かめた: 前のバイナリで違反 81 件。`- b` のつなぐ候補は `%`・ビット演算・`<<`・`>>` の後で E0010、`as` の後で E0011（比較・`&&`・`||` の後は違反なし）。`^ b` のつなぐ候補（`foreign/spaces.rs`）も `+`・`*`・比較・`&&` の後で E0010。行頭の二項演算子を前の行の末尾へ動かす候補（`foreign/lines.rs::leading_symbol`、題 `move it to the end of the line before`）も群の組み合わせで E0010・E0011。`- /* c */ b` の形は別の原因（R-444）。E0418 の `on_the_left` の判断をそのまま当てると `a < b` 改行 `- b` のように誤りを残さない候補も消えるので、構文の段の判定は「つないだ字面が誤りなく読めるか」（`ast.rs` の `BinOp::takes` の表）で見る（親が U7c の票で決めた）。
- 補い（2026-11-12、親）: 142 回目（2026-11-12）、W5-13 U7c で再現の入力（`issues/R/R-443/`）を事例 `tests/spec/fixes/e0020_leading_minus_join_clashes.onsa`・`e0020_leading_operator_clashes.onsa` などへ移して消した。`cm_cmt_in_neg.onsa` は R-444 へ移した（R-444 は仕様どおりで WONTFIX）。
