# R-291 `@param` の文字列のキー（`label`・`unit`・`id`）の補間の穴が解決されず、黙って落ちる（`label: "Gain {CH}"` が `onsa interface` で `"Gain "`、どこにも無い名前の `{nope}` も通る）

- 場所: `@param` の文字列のキーの値の読み（flow の見出しの属性の検査）。本体の歩き手と型付けは、この値の補間の穴を読まない。
- 内容: §11.7 は文字列のキー（`unit label id`）の値を `const` の初期化式と同じ規則で書き、補間を書けるとする。今は数値のキーが字句だけを受ける（`default: NOPE` は E0809）一方で、文字列のキーの字句の補間の穴は解決も検査もされず、値から黙って落ちる。
  `label: "Gain {CH}"` は `onsa check` を通り、`onsa interface` で `label: "Gain "` になる。どこにも無い名前の `"Gain {nope}"` も通る。§18.1 は扱えない形を黙って誤った結果にせず E0200 にするとする。
  再現は横のディレクトリの `label_holes`（W4-04 U4 の前の dev `42e2f5c` も同じ）。
- 経緯: 77 回目（2026-10-27）、W4-04 U4 の報告を確かめる親が、定数の穴が初めて検査を通るようになった後ろの読み手を探して見つけた。前からの形で、U4 で入ったものではない。
- 判断: 直す。数値と文字列のキーを `const` の初期化式と同じ道で型付けする W7-04 で、穴を解決して値に入れる（どこにも無い名前は E0302）。それまでの間の扱い（穴のある文字列のキーを E0200 にするか）は W7-04 の着手の前に親が見る。
