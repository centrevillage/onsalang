# R-28 ループの中の移動の追跡に穴がある

- 高・直す・観点 1｜`crates/onsa_sema/src/modes.rs:354-415`、`:577`｜§5.2（E0704）｜再現（親）
- 再現: 次のどれも、エラーなしで通る。
  - `while … { take(move b); continue }`
  - `if i > 1 { take(move b); continue }`
  - ループの中の `if i == 1 { take(move b); break }` と、ループの後の `take(move b)`
  - `while eat(move b) {}`
- 原因:
  - `continue` を `return` と同じ発散として扱っている。
  - `break` で抜けた分岐の状態を、ループの後に合流させずに捨てている。
  - `while` の条件を、ループの外で一度だけ辿っている。
- 資料の誤り: `impl-review` M-3 の記述とも合わない（§4）。
- 直し方:
  - `continue` は、本体の終わりに達したものとして扱う。
  - `break` の時点の状態を、ループの後へ合流させる。
  - 条件は、ループの本体と同じ扱いで辿る。
- 決定（2026-10-03）: 直す（`continue` は本体の終わりに達したものとして扱い、`break` の時点の状態をループの後へ合流させ、`while` の条件を本体と同じ扱いで辿る）。
- 判断: 直す（`continue` は本体の終わりに達したものとして扱い、`break` の時点の状態をループの後へ合流させ、`while` の条件を本体と同じ扱いで辿る）
- 反映: 実装（W4-09）
- 反映（2026-10-30、親）: 90 回目の文書の点検: W4-07 U1 の流れの歩き手（`6522794`）と S-789 で、4 形とも E0704 になった（`0cf4f723` の配線の後、`tests/review-phase1/body/m1_continue.onsa`〜`m4_while_cond.onsa`）。spec の事例は `continue` の道と条件の再評価だけなので、`break` の後の使用と `while eat(move b)` の事例を W4-09 のテストの票で足してから閉じる（W4-09 の `持ち越し`）。
