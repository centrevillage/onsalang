# R-331 `Span` の引数と束縛した名前を無名関数が捕捉する形（`apply(fn(n) { xs.len() + n })`、`xs: Span[F32]`）が通る。§5.3 は `Span` を引数の位置にだけ置き、§5.4 は束縛した名前「も」捕捉すると E0710 とする

- 場所: modes の第二級の値の位置の検査（`crates/onsa_sema/src/modes.rs` の E0710。無名関数の捕捉の位置を第二級の値の検査に数えていない）。
- 内容: `pub fn captured_xs(xs: Span[F32]) -> U32 { apply(fn(n) { xs.len() + n }) }` は何も出ない（横の `capture.onsa` の 13 行、dev `5caf188` のコード）。
  束縛した名前の捕捉（`let ch = input[0]` の後の捕捉、7〜10 行）は、`5caf188` では `let` の E0710 で止まっていた。W4-16 U1a（`3838cb3`）で `let` が通り、捕捉も何も出ない（85 回目の文書の点検）。
  §5.3 は `Span` を「引数の位置にだけ現れる」とし、§5.4 は「束縛した名前も第二級のままで、返す・保存する・捕捉する・`move` の引数へ渡すと E0710」とする。束縛していない `Span` の引数の捕捉も E0710 と一つに読める（親の読み。仕様の空白でない）。
- 経緯: 84 回目（2026-10-29）、W4-16 U1a/t（onsa-test）が仕様の空白の候補として報告し、親が §5.3・§5.4 の字で決まると読み、再現した。前からの形。
- 判断: 直す（低。捕捉するクロージャは第二級で呼び出しの外へ出ないので、今の形で値が壊れる形は見つかっていない。仕様が禁じる形を通す）。W4-07 の modes の作り直しで、第二級の値の位置の検査に無名関数の捕捉を含める（S-217 の名前の第二級と E0710 と同じ所）。
