# R-270 文字列の補間 `"{MAXV}"` がモジュールの定数と `use` の束縛を引かず、E0302「cannot find for the interpolation」になる

- 場所: 本体の文字列の補間の名前の解決（W4-04 の `body/names.rs` の作り直しの範囲）
- 内容: §2.4 は補間にモジュールの定数を書ける（`{MAX_VOICES}`）とするが、`pub const MAXV: U32 = 8` の後の `"{MAXV}"` は E0302「cannot find `MAXV` for the interpolation」になる。有効な `use` の束縛も同じ。補間はローカルだけを引く。失敗した `use` の名前（S-462）を黙らせる口からも漏れる。再現は `target/notes/67/w403/u3b1/b/c7.txt`。
- 経緯: W4-03 U3b1 の壊す側（onsa-break、2026-10-25、67 回目）が範囲の外で見つけた。前からの欠落。
- 判断:
- 補い（2026-10-25、親）: W4-03 U3c の壊す側（onsa-break、68 回目）: 失敗した `use` の名前を補間に書いた `"{KK}"`・`"{gone}"`・`"{KK.a}"` に、E0302「cannot find `KK` for the interpolation」の偽の連鎖が出る（前から。§18.1 の失敗した名前を使う所は黙る）。
  誤りの型の局所 `"{x}"` は黙る。補間の名前の解決を直すときに、S-462 の集合も読む。再現は `R-270/failed_interp`。
- 反映（2026-10-27、親）: W4-04 U4（`46daa93`）で直した。歩き手が穴の経路を式の鎖と同じ道で引き、型付けは記録を式と同じ口で読む。定数・関連定数・`use` の束縛を頭にした穴が通り、失敗した名前の穴は黙る（事例 `tests/spec/lex/interp_paths_heads.onsa`・`tests/spec/packages/interp_path_heads`・`failed_use_interp_holes`）
