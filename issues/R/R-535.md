# R-535 C の後端が `for` の範囲の端を、変換で始まる字（`((uint32_t)x)`）なら安定とみなしてループの見出しに置き、本体で端の変数を変えると端を読み直す（`for _ in 0 ..< (x as U32) { x = 0 }` は解釈器 3、C 1）

- 場所: `crates/onsa_backend_c/src/emit/fns/text.rs::is_stable`（C の字の前置き `((uint`・`((int` を安定とみなす）と、`emit/fns/stmt.rs` の `StmtKind::ForRange` の腕（安定な端を見出しに置く）。
- 内容: `var x: U8 = x0` の後の `for _ in 0 ..< (x as U32) { x = 0; n = n + 1 }`（`x0 = 3`）は、§3.5（端は最初の反復の前に一度、本体で端の変数を変えても回数は変わらない、S-188）と解釈器で 3 回だが、C は `onsa_ < ((uint32_t)x)` を反復ごとに読んで 1 回。`& 255`・`| 1`・`^ 0`・`(x as I64)` の端も同じ。素の局所変数の端は一時に取るので当たらない。dev（`7084e02`）の `..<` で起き、W8-03 U4 の `..=` は端を二度読むので同じ形に当たる。再現の入力はこの R の横の `src/`・`onsa.toml`。
- 経緯: 194 回目（2026-11-28）、W8-03 U4 の壊す側（onsa-break）が見つけた。親が `target/base/7084e02/onsa` の C の字で再現した。
- 判断: 直す。通るプログラムの C の値が解釈器と違う（§13.4）ので、見つけた作業の W8-03 U4 の直しで、`for` の端を数字のほかは一度だけ一時に取る形にする。`is_stable` の族そのものは U8 で除く（K13）。
- 反映（2026-11-28、親）: W8-03 U4 の直し（194 回目）で、`for` の端を数字のほかは見出しの前に一度だけ一時に取る形にした（`emit/fns/stmt.rs::range_end`）。事例 `tests/spec/c_runtime/c_range_ends_once.onsa`。
