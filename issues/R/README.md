# 問題（R）

実装の誤り（仕様からのずれ、構造の不健全、仕様に無い前提）の指摘と、直すかの判断。
壊す側・テスト・ファズ・親の確かめが見つけたものを、親が登録する。直す作業は頭の欄の `fix` に書き、作業のファイルには書かない（作業の側の「直す R」は道具が出す）。

- 一覧は `python3 -B tools/docs.py list R`。宛先の作業の無い R は `list R --no-fix`。
- 登録するときは、見つけた票を `found_by` に書く。テストにしない再現の入力は、横のディレクトリ `issues/R/R-<番号>/` に置く（scratchpad の経路は書かない）。

## 頭の欄

| キー | 形 | 値 | 要る | 意味 |
|---|---|---|---|---|
| `status` | 閉じた値 | `OPEN` / `WONTFIX` / `DONE` | はい | 状態 |
| `severity` | 閉じた値 | `高` / `中〜高` / `中` / `低〜中` / `低` | はい | 重さ |
| `aspect` | 閉じた値の並び | `1` / `2` / `3` | いいえ | 観点 |
| `spec` | 節の並び | — | いいえ | 仕様の節 |
| `decisions` | ID の並び（S） | — | いいえ | 決定 |
| `fix` | ID の並び（W） | — | いいえ | 直す作業 |
| `found_by` | 文字列 | — | いいえ | 見つけた票 |

- `status`: `OPEN` は直す（作業待ち）、`WONTFIX` は直さない（記録だけ）、`DONE` は直したか、他の決定で論点が無くなった。`fix` の作業が全て済んだ R は `OPEN` にできない（`docs.py check`）。
- `aspect`: 1 は仕様からのずれ、2 は構造の健全さと保守性、3 は仕様に無い前提。複数の観点にまたがり、どれが大きいとも言えないときは並べる。

## 本文のラベル

`docs.py new R` は、この節のラベルを新しい R の雛形にする。

- `場所`: 誤りのあるコードの場所。
- `内容`: 誤りと、再現の入力。
- `経緯`: 見つけた票、日付、前からあるか。
- `判断`: 直すか、直し方、時機。`判断（<日付>、<誰>）` の形で、判断が改まったら箇条を足し、`status` を最後の判断に合わせる。
