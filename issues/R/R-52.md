# R-52 `panic(msg)` が無い。`while true` で終わる関数に型が付かない

- 中・直す + 要判断・観点 1 / 3｜`crates/onsa_sema/src/body.rs:1647-1652`、`:780`｜§9.2（`panic(msg)`）、§7「`loop {}` は無い（`while true` と書く）」｜再現（親）
- `panic`: `panic("negative")` が E0302 になる。Str は第 1 期では未対応だが、E0200 として扱われていない。
- `while true`: `-> U32` の関数を `while true { … return i … }` で終えると、E0401「expected `U32`, found `()`」になる。
- 影響: `loop` を廃止したのに無限ループの関数を書けず、`panic` が無いので末尾を埋める手段も無い。
- 直し方: `panic` を実装する。引数は静的な文字列リテラルに限ってよい。
- 判断（R-52）:
  - (a) `break` を含まない `while true` を、発散する式として扱う。
  - (b) 末尾に `panic("unreachable")` を書かせる。
  - (c) `loop` を戻す。
  - 推奨は (a)。
- 決定（2026-10-03）: `panic` は prelude の関数で、引数は文字列リテラル。`return` / `break` / `continue` / `panic(...)` は発散する。`while true` は (a)（S-40）。
- 判断: S-40: `panic(msg)` を prelude の関数にし、引数は文字列リテラル（組み立てた文字列は §19.1）。`return` / `break` / `continue` / `panic(...)` は発散し、どの型の位置にも置ける（発散の型は書けない）。(a) 条件がリテラルの `true` で、そのループを抜ける `break` を含まない `while true` も発散する。末尾の型の不一致の診断は、末尾の位置に出す
- 反映: 仕様 §7 / §9.2 / §15.1 / §19.1 に反映済み（2026-10-03）。実装は W5-08
- 補い（2026-10-26、親）: W4-03 U5b（72 回目）で `panic` が prelude に入り、名前は見つかる。`panic("negative")` は今は E0200 で、呼び出しは W5-08 まで E0200（`tests/spec/module/prelude_panic_value.onsa`）。上の「E0302 になる」は登録の時の観察（73 回目の文書の点検）。
