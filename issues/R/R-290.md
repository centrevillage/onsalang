# R-290 補間の穴のタプルの添字の形の誤り（`{t.01}`、`{t.99999999999}`）を字句の段が通し、式の `t.01` の E0020・`t.99999999999` の E0408 でなく、型付けの E0413 になる

- 場所: 字句の段の補間の穴の経路（`onsa_syntax` の `literal.rs::hole_path`）。型付けは W4-04 U4 から、式の添字の規則に合う名前（`onsa_syntax::hole_tuple_index`）だけをタプルの添字と読み、他はフィールドとして読む。
- 内容: §2.4 は補間の穴を「式に書いたときと同じ規則で解決する」とする。式の `t.01` は構文の段の E0020（添字は 0 で始めない）、`t.99999999999` は E0408（`U32` に収まらない）だが、穴の `"{t.01}"`・`"{t.99999999999}"` は字句の段を通り、型付けの E0413「`(I32, I32)` has no field `01`」になる。
  拒むことは同じで、通るプログラムは変わらない。コードと段だけが式と違う。再現は横のディレクトリの `t01.onsa`・`t_large.onsa`（W4-04 U4 の前の dev `42e2f5c` も同じ）。
- 経緯: 77 回目（2026-10-27）、W4-04 U4/i（onsa-impl）が範囲の外で見つけ、親が再現した。前からの形。
- 判断: 直す。字句と構文の残りを扱う W5-11 で、穴の経路の添字の要素を式の添字と同じ規則（E0020・E0408）で読む。
- 補い（2026-10-27、親）: W4-04 U4/b（onsa-break）の指摘 5: タプルの添字かどうかの判断が、式の構文（`parser/expressions.rs`）と降下（`lower/exprs.rs`）と穴の型付け（`onsa_syntax::hole_tuple_index`）の三か所で組み立てられている（小さな部品 `tuple_index_value`・`tuple_index_unpadded` は共有）。
  直すときは、穴の経路の添字を式と同じ一つの判断で読み、型付けの `hole_tuple_index` を外す。
