# R-187 型引数の決まらない総称の関連定数が検査を通り、`onsa test` で内部エラーになる

- 中・直す・観点 1｜型の段｜§4.7、§18.1
- 内容: 総称の `impl` の関連定数（`impl[T, const N: U32] Rg[T, N] { pub const CAP: U32 = N }` の `Rg.CAP`）を型引数を決めずに参照すると、型パラメータの決まらないまま `onsa check` を通り、`onsa test` で内部エラー（終了コード 101、「unbound const parameter」）になる。
  同じ形の列挙子 `E2.B`（`enum E2[T] { A(T), B }`）は E0406。内部エラーは検査の誤りの見逃しである（§18.2 の 101 は降下の予期しない失敗）。
- 経緯: 第 9 組の下書き（S-239）で見つけた（2026-10-08。親と Fable が再現）。
- 決定（2026-10-08、親）: 直す。どのコードにするか（E0406 か、値が型パラメータに依らなければ通すか）は S-304 で決め、数の trait と関連定数を扱う W5-05 で行う（S-239 の後は `Rg::[F32, 4].CAP` と書ける）。
- 判断: 直す（親）。型引数の決まらない総称の関連定数（`Rg.CAP`）が検査を通り `onsa test` で内部エラーになる見逃しを無くす（コードは S-304）。第 9 組の下書き（S-239）で見つけた
- 反映: 実装は W5-05
- 補い（2026-10-27、親）: 78 回目、W4-04 U6/b（onsa-break）の指摘 1: U6 から、別名と `Self` の経路も同じ内部エラーに届く（`type B3 = B2[3]` の `B3.LEN`、`impl` の中の `Self.LEN`、`D = Self.LEN + 1` の `B3.D`）。
  別名は型引数を決めるので（§4.4）、`B3.LEN` は 3 になるはずである。名前の段の記録の `owner` に別名の型があるが、U6 は関連定数に `owner` を当てない。直すときに `owner` の引数を読む。
  再現は横のディレクトリの `alias_len.onsa`・`self_len.onsa`・`alias_derived.onsa`（U6 の前の dev `5fc054e` は別名の形が E0302 で止まった）。
- 補い（2026-11-05、親）: 116 回目、S-304 の決定 (b) で、コードは E0406（値が型パラメータに依らなくても）。第 87 組の下書きが同じ範囲の形を足した（再現は横のディレクトリ）。
  (1) 宣言の型が型パラメータに依る定数の型が使う側に漏れる（`const Z: Option[T] = None` の `let z: Option[F32] = Rg.Z` は E0401「`Option[<0>]`」、`fn f[U: Copy]() -> Option[U] { Rg.Z }` は位置が偶然合って通り、二つ目の型パラメータでは E0401「`Option[A]`」、`let _ = Rg.Z` は `onsa test` で内部エラー「unbound generic argument」）。
  (2) `impl` の境界を満たさない型引数の関連定数が通る（`type RB = Rg[fn() -> I32]` の `RB.B`、同じ形の関数は E0416）。(3) `impl` の中の `Rg.CAP` も同じ内部エラー。どれも定数の腕で型引数を作る直しで閉じる。
