# R-106 `pub(pkg) use`、パッケージ名とルート直下のモジュールの優先

- 中・要判断・観点 3｜`crates/onsa_sema/src/resolve.rs:164`、`:228`、`crates/onsa_driver/src/lib.rs`｜§15.1、`impl-review` の指摘 S1
- `pub(pkg) use`: 受理するが、非公開として扱う。
- 名前の優先: パッケージ名と同名のルート直下のモジュールがあるとき、どちらが優先するかが決まっていない（R-46 の `std.onsa`）。
- `impl-review` の指摘 S1 との関係: S1（パッケージは自分の名前でも参照できる）は、R-39 の解決順の誤りの原因になっている。
- 判断（R-106）:
  - `pub(pkg) use` は、許して意味を書く。
  - 自分のパッケージ名での参照は、禁止する（S1 の統一案「自分の名前は書かない」）。
  - std と同名のパッケージとモジュールは、E0304 にする。
  - 推奨は以上の 3 つ。
- 決定（2026-10-03）: `pub(pkg) use` は S-36（可視性の既定をパッケージ内にし、`pub(pkg)` を無くす）で書き方ごと無くなった。残りの 2 つは S-37（`use` の経路を絶対経路にする）で、自分の名前は書かず、ルート直下のモジュールと依存のパッケージ名の重なりは E0304 とした。
- 判断: S-36: 可視性を `pub` / 無指定（パッケージ内）/ `priv`（モジュール内）にし、`pub(pkg)` を無くす。`use` の束縛は無指定でもモジュール内、再公開は `pub use` だけで、取り込めるのは `pub` の項目だけ（E0303）。フィールドの狭め方は `priv` だけ。flow の生成項目は flow の可視性を継ぐ。
  std の `Gen.seed` は `priv` にする。S-37: `use` の経路は絶対経路で、頭はルート直下のモジュールか依存のパッケージ名だけ。自分のパッケージ名は書かない（impl-review の指摘 S1 の統一案）。
  ルート直下のモジュールと依存のパッケージ名の重なり（利用者の `std.onsa` など）は E0304。`use` がたどれるのはパッケージ、モジュール、flow の名前空間だけ。`use` の経路の頭にもキーワードのモジュール名を書ける（S-20 を広げた。std の `use test.{Gen}`）。衝突を別名で避ける手段は、必要になってから
- 反映: 仕様 §2.2 / §11.6 / §15.1 に反映済み（2026-10-03）。実装は W3-08（構文）と W4-03（検査）
