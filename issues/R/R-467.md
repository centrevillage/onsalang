# R-467 リテラルの変数を総称関数の引数に n 回渡す形（`let a = 1` の後に `need_dup(a)` を n 個）で、型の段がほぼ三乗（W6-04 U8 の後も前と同じ）

- 場所: `crates/onsa_sema/src/deferred.rs::Waits::wake` と `crates/onsa_sema/src/infer.rs::Infer::bind`（W6-04 U8 で、後回しの項目を待つ型変数が束縛されたときと、リテラルの種類が変わったとき（`kinded`）だけ問い直す形にした）。
- 内容: `let a = 1` の後に `let _ = need_dup(a)`（`fn need_dup[T](x: T) -> T`）を n 個並べ、最後に `let r: I32 = a` と書いた本体の型の段が、n = 250・500・1000 で 18・132・1024 ms（debug）。`need(a)`・`same(a, 1)`・`same(1, a)` も同じ。U8 の前と同じ値で後退ではない（R-448 の形は U8 で三乗から二乗に下がった）。出力は正しい。
  見立て（壊す側、推測）: 呼び出しでは、リテラルの種類を持つ `a` の変数が、新しい型引数の変数 `T_k`（種類なし）へ束縛される向きになり、`bind` が `T_k` を「種類が変わった」と記録するので、`wake` が `a` から移したばかりの項目を含めて `T_k` の項目を全て起こす（文ごとに溜まった項目の数だけ問い直す）。`lit_eq`・`lit_arr`（`a == 1`、`[a, 1]`）は向きが逆でこの道を通らず、U8 の直しで線形になった。
  直し方の見当（壊す側）: 移す前に `on[u]` に元からある項目だけを `kinded` で起こす（束縛された側の種類が変わらなければ、開いた側の元の項目だけ）。数行。
  再現: `target/notes/153/w604/u8b/forms.py` の `lit_call1`〜`lit_call6`（`P13` の `w604/u8/b/measure.py` で測る）。
  同じ報告の低: 前提を固定する検査の不足（項目の置き場の位置の順と `seq` の一致、`has_vars` と `open_vars` の一致。`wait()` で「`Look::Wait` なのに待つ変数が空」を内部エラーにする案）、gate の候補の事例 3 つ（`target/notes/153/w604/u8b/hand1.cases` の `nested_order1`〜`3`、外の式の項目と内側の文で決まる順）。
- 経緯: 153 回目、2026-11-15、W6-04 U8（R-448）の壊す側（onsa-break、報告 `target/notes/153/w604/onsa-break-a99eaa02d83adfdaf-001.md` の F1・F3）が見つけた。`design/README.md` の性能の要件（二乗以上は R に登録して担う作業を決める）により登録する。
- 判断（2026-11-15、利用者）: W6-04 の小さな単位 U14 で直す（155 回目、利用者「直してみて、想定より大変ならまた考え直しましょう」）。直しは `deferred.rs`・`infer.rs` の数行の見当（束縛の前から待っていた項目だけを起こす）。同じ報告の低（項目の順を固定する事例 `nested_order1`〜`3`、`Look::Wait` なのに待つ変数が空なら内部エラー）も入れる。見積もりを超える形なら止めて形と見積もりを利用者に出す。
- 反映（2026-11-16、親）: W6-04 U14（`59189c20`）で直した。`Infer` が束縛で種を変えた変数の添字を覚え、`wake` が束縛を順に回って、種が変わったときだけ項目を起こし、それ以外は直接の対象だけへ移す。リテラルの変数を総称関数に n 回渡す形の型の段が n = 1000 で 1021 → 29 ms、n = 2000 で 8021 → 112 ms（debug）、出力不変。待つ変数が空の `Look::Wait` は内部エラー。項目の順は `tests/spec/negative/infer_deferred_nested_order.onsa` で固定。`check_deferred_now` で起こした項目が `Look::Wait` で戻るときの確かめは無い（届く形は見つからない）。残る二乗は X-20 の補いに書いた。
