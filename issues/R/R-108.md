# R-108 `const` の評価の超越関数が、ビルドするホストの libm に依存する

- 低・要判断・観点 3｜`crates/onsa_driver/src/build.rs:429`｜§15.3「onsa.lock が同じなら成果物は同一」、§6.6
- 内容: const の初期化をインタプリタで評価し、C に焼き込む。Rust の `f32::sin` などは OS の libm を呼ぶので、macOS と Linux で表の最後の桁が変わりうる（推測）。
- 判断（R-108）:
  - (a) const の評価の超越関数は、D-11 の Onsa の実装（musl の移植）を使う、と仕様に書く。
  - (b) 違いを許容し、仕様に書く。
  - 推奨は (a)。D-11 の実装ができるまでは、既知の制限として記録する。
- 範囲（2026-10-05 に追加で確かめた）:
  - インタプリタの `MathFn` は Rust の `x.exp()`、`x.sin()`、`x.tanh()`、`x.powf(y)` などで、ビルドする機械の libm を呼ぶ。`const` の評価もこれを使う（R-89）。D-11 の `std/math/soft.onsa` はまだ無い（M6）。D-09 によりインタプリタは外部のクレートを使えない。
  - 一台の機械では違いを示せない（macOS の libm と glibc の差は推測のまま）。再現は `tests/review-phase1/parent/r108/`（二台の機械で生成した C の表を比べる手順）。
- 決定（2026-10-05）: S-93。
  - (1) (a): `const` の評価の超越関数は `std.math` の Onsa の実装（musl の移植）で計算し、ビルドする機械に依らない。§15.3 の再現性を保つ。焼き込んだ値と実行時の値の違いは §13.4 の許容誤差の範囲と書いた。
  - (2) (a1): インタプリタ全体（`const` の評価、`onsa test`、`play` のインタプリタの実行）で同じ実装に結び付ける。実装は一つで、`onsa test` の結果も機械に依らない。`const` の評価だけの案と、Rust に同じ算法を書く案は採らない。費用はテストの速さ。
  - D-11 ができるまでは既知の制限。前倒しするかは、着手の時期を決めるときに決める。
- 判断: S-93: `const` の評価の超越関数は `std.math` の Onsa の実装（musl の移植、D-11）で計算し、ビルドする機械に依らない（§15.3 を保つ）。インタプリタ全体（`const` の評価、`onsa test`）も同じ実装に結び付ける（(a1)）。D-11 ができるまでは既知の制限。再現は `tests/review-phase1/parent/r108/`
- 反映: 仕様 §6.6 / §13.4 に反映済み（2026-10-05）。実装は W9-02（D-11 の W9-01 の後）
