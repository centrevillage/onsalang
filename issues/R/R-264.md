# R-264 flow の生成項目の `Config`・`Params` を、`init`・`block` の入力が無くても作る

- 場所: `crates/onsa_sema/src/sig/flow_sig.rs` の `flow_members`（flow の生成項目を作る所。`Config`・`Params` を入力のクロックによらず作り、`Event`・`Rendered` は作らない）
- 内容: §11.6 は「`block` の入力の無い flow は `params` の引数と `Params` を持たず、`init` の入力の無い flow は `cfg` の引数と `Config` を持たない」とするが、`sample` の入力だけの flow の `f.Params`・`f.Config` を型に書いた関数が診断なしで通る（再現は横のディレクトリの `noparams.onsa`、dev `3895f4d` の `check` で終了コード 0。期待は E0302）。
- 経緯: 64 回目（2026-10-24）、W4-03 U1 の設計メモ（onsa-impl）が範囲の外で気付き、親が再現した。W4-03 の U3b の設計（型で有無が決まる生成項目に `absent` の印を付け、それを指す `use` を E0302 にする）で表せる形だが、直すのは生成項目の Onsa の側を扱う W7-03。
- 判断:
- 補い（2026-10-25、親）: 69 回目（文書の点検の F9）: §11.6 の `Out` も「出力が struct のときだけ」で、出力の型で有無が決まる。今は常に作る。W4-03 U3b2 で `use` が生成項目に届くようになったので、struct でない出力の flow の `use g.{Out}` も通る。
  経路で書く `dsp.g.Out` は dev `49c469b` でも通る（前から）。`Out` は型なので、署名で型として読まれた後に無いと決まると連鎖の誤りが出うる。W7-03 で有無を仕様どおりにするときに、`Config`・`Params` と一緒に扱いを決める（無い `use` は S-694 の (1) に揃えるのが第一の案）。
