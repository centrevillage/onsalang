# R-132 レートが型の形をしているが、普通の型として使えない。マルチレートへの備え

- 高・要判断・観点 2 / 3｜`crates/onsa_sema/src/`（`Ty::Rate`、flow の解析の `local_rates` / `expr_rates`）｜§11.1、§11.3、§11.6、§12.4
- 内容:
  - レート（`Init[T]` `Ctl[T]` `Sig[T]`）は型の形で書くが、普通の型と違う。最も外側にしか付けられない（§11.3）、言語で唯一の暗黙の変換（昇格）を持つ、flow の本体では点ごとに剥がれて値型として扱われる。実装も、型の表現には専用の構成子 `Ty::Rate` を持ち、flow の解析では型と別にローカルと式ごとのレートを属性として持つ（巻き上げはこの属性で決める）。
  - fn のシグネチャ、struct のフィールド、fn の本体の `let` にもレート型を書けてしまい、宣言では何も出ない。使う所で分かりにくい E0401 になる（T-5 の議論で確かめた。`tests/review-phase1/parent/t5.onsa`）。
  - 利用者の指摘（2026-10-05）: 型のようで普通の型として使えないので、利用者には違和感がありうる。レートを型以外で表せないか。
  - 利用者の将来の要望（2026-10-05）: マルチレートに対応したい。今は `Sig`（サンプルレート）・`Ctl`（ブロックレート）・`Init` の三つで、`Ctl` はブロックに束縛されている。遅い制御と速い制御の使い分けや、アップサンプル・ダウンサンプルで `Sig` のレートそのものを変える需要が出る。レートを指定できれば、三つの区別すら不要になるかもしれない。レートの表し方を見直すなら、同じときに考慮に入れる。
- 判断（R-132）: 論点を整理してから決める。案の一つは、レートを型ではなく flow の束縛（入力・出力）の印にし、本体では推論する形（`sig x: F32`）。
- 経緯: T-5 の議論で見つけた（2026-10-05）。T-5 のうち、レート型を flow の外に書いた場合の扱いは、この項目の結論を待つ。
- 範囲（2026-10-05 に追加で確かめた）:
  - 三つのレートは生成する API の境界に対応する（`Init` は `Config`、`Ctl` は `process` の呼び出しごとの `Params`、`Sig` は `Span`）。`Ctl` はホストのブロックの区切りに依存し、決まった間隔の制御レートではない。`sample_rate()` は `Init`。
  - `let ps: Sig[F32] = p` の注釈は、`prev~` に `Ctl` の値を渡すための明示の昇格の役目を持つ（E0813）。
  - 書き換えの規模は、仕様で約 37 行、テスト・std・例・実装で約 100 ファイル。graph のラベルも `F32 @Sig` の形でレートを出していた。
- 決定（2026-10-05）: S-102。
  - (1) レートは型ではなく、flow の入出力の宣言と本体の式に付ける（論点 1）。値の型はどこでも普通の型。実装の `Ty::Rate` を取り除き、flow の解析の属性を唯一の表現にする。
  - (2) レートはクロックとして説明する（論点 2）。基準のクロックは `init`・`block`・`sample`（順序、推論、巻き上げは今と同じ）。この版では基準の三つだけを入れ、導くクロックは将来。
  - (3) 書き方は、置き場所を示すキーワード `at` 一つと、名前で書くクロック（論点 3、(d)）。宣言は `x: F32 at sample` / `-> F32 at sample`（型の後ろは `as` と同じ位置）、本体は式の `e at k`（利用者の提案。`let ps = p at sample`、`prev~(p at sample)`）。
    速くすれば昇格、遅くすれば E0815 で、「ブロックごと以下で計算する」約束にもなる。結合の強さは `as` と同じ（E0011）。`let` の束縛の側にクロックは書かない（E0020）。
    退けた案: クロックごとのキーワード（`sample x`。クロックが増えるたびにキーワードが増える、利用者の指摘）、属性（`@rate(sample)`。§6.5 の「属性は受理されるプログラムを変えない」を破る、利用者の指摘）、型のまま位置を検査する案。
  - (4) クロックの名前は、値と型と別の名前空間に置き、`at` の後ろでだけ引く（`let sample = …` が書ける）。`Init` `Ctl` `Sig` を prelude から外す。
  - (5) 診断: `at` の無い入力は E0810、flow の外の `at` は E0821（T-5 の残りはこれで解消）、古い形 `Sig[F32]` は E0020（修正候補は flow では `F32 at sample`、外では `F32`）、E0813 の修正候補は `prev~(p at sample)`、レートの誤りの文面はクロックの言葉。
  - (6) 生成する API は変えない。`@param` は `block` の入力に付け、`sample_rate()` は `init` のクロックの値。
  - (7) マルチレートは、今は構文の方向だけを決め、本格的に入れる段で改めて考える（論点 4、利用者の判断）。§19.1 に構文の方向（`clock fast = sample / 32`、式の中の導くクロックは括弧で包む）と、入れるときの問い（付ける単位、インスタンスの `at` の意味、昇格と補間、決定性、API、`sample_rate()` と `prev~`、状態・ホットリロード・表示）を書いた。
  - (8) 実装は第 4 段の構造の変更で行う。それまで `tests/spec` の写しは古い形のままで、仕様の flow の例は実装待ちになる。
- 判断: S-102: レートは型ではなくクロックで、flow の入出力の宣言（`x: F32 at sample`）と本体の式（`e at k`）に `at` で書く。基準のクロックは `init` `block` `sample`。速くすれば昇格、遅くすれば E0815。クロックの名前は別の名前空間で、`Init` `Ctl` `Sig` は prelude から外す。
  診断は E0810 / E0821 / E0020 / E0813 の修正候補。生成する API は変えない。マルチレートは構文の方向（`clock fast = sample / 32`）と問いだけを §19.1 に書き、入れる段で改めて考える。退けた案: クロックごとのキーワード（増え続ける）、属性（§6.5 に反する）、型のまま
