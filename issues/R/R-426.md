# R-426 名前の鎖と型引数の並びの読みが五か所にあり、型の中の定数式の安全網が本体の安全網と同じ判断の二つ目になっている

- 場所: `crates/onsa_sema/src/` の、名前の鎖を辿る五か所（`names/body/paths.rs` の `Walker::chain`、`constarg.rs` の `chain_nodes`、`sig/decls.rs` の `Graph::chain`、`names/body/mod.rs` の `BodyNames::args_diag`、`body/named.rs` の `Checker::reported_args`）と、報告していない並びの診断の安全網の二か所（`body.rs` の本体の検査の終わり、`sig/types.rs` の `read_const`）。
- 内容: `Graph::chain`（W5-10 U1b で足した）は `constarg::path_of` とほぼ同じ処理で、違いは `TypeArgs` の節を通ることと、経路の範囲を更新しないことだけである（`path_of` は `sig/types.rs` でまだ使う）。`read_const` の安全網は本体の安全網と同じ判断（並びの表に診断が残っているか）を別に書いている。
  `const_names` の結果は `ConstNames::lower` を通してから読む約束で、通さずに定数式の読み手へ渡すと `owner` が空のまま読まれる（今の呼び出しは `read_const` だけ）。出力の違いは再現していない（保守の費用の指摘）。
- 経緯: 134 回目（2026-11-10）、W5-10 U1b の壊す側（onsa-break）がコードを読んで報告した。
- 判断: 低。`goes_to` の枝を実装に替え、関数自身の並びを定数式の読み手にも通す W5-10 U2a で、鎖の読みを増やす前に `Graph::chain` と `path_of`、二つの安全網を一つにできるかを見る（R-424 と同じ単位）。
- 反映（2026-11-10、親）: W5-10 U2a（`10a0b8f9`）で、二つの安全網を `BodyNames::all_reported` の一つにした。`Graph::chain` と `constarg::path_of` は一つにしていない（`path_of` は `Field` で経路の範囲を式の全体に広げ、`Graph::chain` は広げないので、一つにすると宣言の順の診断の位置を確かめる手間が要る。見込みは素の +15 −26）。U2a の壊す側の指摘を足す: `sig/types.rs` の下ろしが、並びの付け先を名前の段の記録（`Listed.own`）でなく `DefKind::Fn` で判定し直している（今は結果が一致する）。U2b で見る。
