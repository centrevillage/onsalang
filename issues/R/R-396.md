# R-396 型の位置の `fn z` で、型の読みが `fn` を食べて `z` で失敗し、行頭の項目の始まりで単位が終わらない（`struct P {` / `  v:` / `fn z()`）

- 場所: `crates/onsa_syntax/src/parser/types.rs` の `fn`（`rt fn`）の腕。式の読みは `starts.rs` の `declares_a_function`（`fn` の後に名前）で `fn` の位置で失敗するが、型の読みにはこの判定が無い。
- 内容: 型を読む位置で切れた次の行の頭に `fn z()` があると、型の読みが `fn` を食べてから `(` を求めて `z` で失敗し、読み飛ばしが `fn` の後から始まる。そのため `z` の宣言が前の単位に飲まれ、使う側に偽の E0302 が出る。
  継続のトークンが無い形でも起きる（`struct P {` / `  v:` / `fn z() -> I32 { 1 }` は `{` の E0002 と `z` の E0302。列挙子の `B(` の次の行も同じ）。§18.1 の「行頭にある項目の始まりで単位が終わる」に合わない。
  入力は `target/notes/124/g93/adv/probe2/p04_field_type_fn.onsa` と `target/notes/124/g93/probe/err/` の `d04`。
- 経緯: 124 回目（2026-11-07）、第 93 組（S-947）の下書きの担当が継続の形で見つけ（形 9）、段 1 の助言の担当が継続の無い形でも起きると示し、親が固定のバイナリ（dev `58598795`）で `p04` を再現した。
- 判断: 直す（親）。S-947 と同じ単位で、型の読みも式の読みと同じく `fn` の後に名前が続けば `fn` の位置で失敗させる。
- 反映（2026-11-08、親）: W5-11 U9（`d2e5a182`）: 型の読みの `fn` の腕は、`fn`（`rt fn`）の後が名前なら食べずにそこで失敗し、行頭なら単位が終わる。事例は `tests/spec/negative/recover_type_fn_unit.onsa`・`recover_type_fn_cut.onsa`
