# R-250 `use` の経路の途中が同じモジュールの `use` の束縛を引き、書く順で結果が変わり、他のモジュールから子モジュールへの経路を隠す

- 場所: `crates/onsa_sema/src/sig/collect.rs` の `resolve_imports`（モジュールの中の `use` を書いた順に解決する）と `crates/onsa_sema/src/resolve.rs` の `member`（経路の各要素を、モジュールの束縛の表（項目と `use` の束縛）から先に引き、無ければ子モジュールを引く）
- 内容: `pub use` の無い形で二つ起きる（再現は横のディレクトリ）。
  `order_after`: `main` の `use kp.inner` の後に書いた `use main.inner.{g}` が、`main` 自身の `use` の束縛 `inner` を経路の途中に通して通る。`order_before`: 同じ二行を逆の順に書くと `inner` の E0302 と使う所の E0302 になる。
  §15.1 の「各 `use` は、書く位置にも他の `use` にもよらずに決まる」と食い違い、`main` に子モジュール `inner` は無いので、どちらの順でも E0302 が正しい。
  `hides_child`: `main` の `pub` でない `use kp.inner` が、他のモジュールの `use main.inner.{h}`（子モジュール `main/inner.onsa` の `h`）を `inner` の E0303「`inner` is not visible here (it is not `pub`)」と使う所の E0302 にする。正しいプログラムを拒む。
  `use` の束縛はモジュールの中だけのもので（§15.1）、再公開（`pub use`）は第 2 期まで E0200 になる（S-596）ので、経路の途中の要素は子モジュールと項目の定義だけから引く。
- 経緯: 第 41 組の下書き（onsa-gap、2026-10-23、57 回目）が S-596 の確かめで `pub use` のある形（r30・r32・r39）として見つけ、親が `pub use` の無い形でも起きることを dev `2ebd664` の release の `check` で再現した。直しは `use` の解決を作り直す W4-03。
- 判断:
- 判断（2026-10-23、親）: `hides_child` の「正しいプログラム」は、`main` の `use kp.inner` と子モジュール `main/inner.onsa` の名前の重なりが誤りでない前提に立つ。その前提は S-611（W4-03 の前）で決め、期待をそれに合わせる（58 回目の文書の点検）。
