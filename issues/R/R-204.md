# R-204 `onsa fmt` が、書き込む前に出力を解析し直して確かめない

- 中・直す・観点 1｜CLI（`crates/onsa_cli/src/main.rs` の fmt、`onsa_driver::format_file`）｜§18.2、`spec/tools.md` §3.5
- 内容: `spec/tools.md` §3.5 は「`onsa fmt` は、書き込む前に出力を解析し直し、元と同じプログラムであることを確かめる。…違えば fmt の不具合なので、ファイルを書き換えず、最初に違った項目を示して内部エラー（終了コード 101）」と定める。
  今の `format_file` は `onsa_syntax::format` の出力をそのまま返し、CLI はそれを書き込む。確かめが無いので、R-203 のように fmt の不具合で意味の変わったファイルが書き込まれる。
- 経緯: 第 20 組の Fable のレビューが見つけ、親がコードで確かめた（2026-10-10）。
- 決定（2026-10-10、親）: 直す。fmt を CST に移す W3-11 で、書き込む前に `diff --ast` と同じ比べ方（§3.5）で確かめ、違えば内部エラーにする。それまでの fmt の不具合は gate の `fmt-props`・`fmt-cst` が見る範囲だけで捕まる。
- 判断: 直す（親）。`onsa fmt` が書き込む前に出力を解析し直して確かめない（`spec/tools.md` §3.5）。第 20 組の Fable のレビューで見つけた
- 反映: 実装は W3-11
