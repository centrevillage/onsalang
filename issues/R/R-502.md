# R-502 新しく解析した側と std の基を引き継いだ側で、std の関連定数を名指す定数（`pub const MIN32: I32 = I32.MIN`）の Core が違う

- 場所: `crates/onsa_sema` の std の基を引き継ぐ解析（`onsa_sema::analyze_on`、W5-19 U4）と、定数の降下（`crates/onsa_core`）の間。見張りは `crates/onsa_driver/src/base_tests.rs` の `a_continued_analysis_is_the_fresh_one`（`tests/spec` から決まった種で 40 件を抜き、二つの解析の診断と Core を比べる）。
- 内容: `tests/spec/c_runtime/c_int_modules/edge.onsa`（`pub const MIN32: I32 = I32.MIN`、`pub const MIN16: I16 = I16.MIN`）の Core が、新しく解析した側（`analyze`）では std の定数の項目を残して参照し（`const std.core.num.I32.MIN: I32 = -2147483648:I32`、`const edge.MIN32: I32 = const std.core.num.I32.MIN`）、基を引き継いだ側（`analyze_on`）では値に畳む（`const edge.MIN32: I32 = -2147483648:I32`）。値は同じで、診断も同じ。
  「引き継いだ解析は新しい解析と同じ」の約束が破れ、どちらの解析を通るか（std に診断があるときは新しい側）で Core と、それから作る C が変わりうる。
  W7-07 U1 の事例を足して `tests/spec` のファイルの一覧が変わり、抜き取りにこのファイルが入って見張りが落ちた。U1 の前のコードでも同じに落ちる（親が U1 のコードの差分を退けて確かめた）。
- 経緯: 168 回目、2026-11-19、W7-07 U1 の実装の担当（onsa-impl）が gate の `test` の失敗として報告し、親が再現して登録した。
- 判断: 見張りが落ちて W7-07 の gate を塞ぐので、見つけた W7-07 で直す（`rules/leader.md` 7.4）。抜き取りに頼らないよう、この形を見張りの決まった入力（`MADE`）にも足す。
- 反映（2026-11-19、親）: W7-07 U1b（168 回目、`ab6783c8`）で直した: 原因は W7-14 U3（`e55efe54`、R-499）が型の段の順をパッケージをまたいで「モジュールの定数 → 残り」に分けたことで、新しい解析では利用者の定数が std の関連定数より先に評価され値を読めなかった（`pub const NEG: I32 = -I32.MIN` の E0419 も新しい解析で抜けていた）。`crates/onsa_sema/src/body.rs` の `check_all` を、依存の順のパッケージごとに「モジュールの定数 → 残り」にした。見張り `crates/onsa_driver/src/base_tests.rs` の `MADE` に 2 件。普通の `onsa`（基を引き継ぐ側）の出力は変わらない（`compare.py core`・`diags` の差 0）。控え `target/notes/168/w707/r502/`。
