# R-311 新しく作った値（`Buf.zeroed(4)`、それを含むタプル）を `move` の引数に `move` 無しで渡すと E0703 で、`move` を足す候補を出す（§5.2 は `take(Buf.zeroed(4))` を正しい形とする）

- 場所: modes の引数のモードの検査（E0703、§5.2）。
- 内容: `pub fn take_buf(move buf: Buf[F32])` に `take_buf(Buf.zeroed(4))` と渡すと E0703「this parameter is `move`; write `move` before the argument」で、`move ` を足す候補を出す。
  新しく作ったタプル `pair_of_buffers((Buf.zeroed(4), 2))` も同じ。再現は横の `fresh_move_arg.onsa`（`fa`・`fb`。`let` に置いて `move t` と渡す `fc` は通る）。
  §5.2 は、場所でない値（新しく作った値、Copy のリテラル）を `move` の引数に渡すときは `move` を書かないとし、`take(Buf.zeroed(4))` を正しい形として挙げる。正しいプログラムを拒む。
  候補を当てた `take_buf(move Buf.zeroed(4))` は今は通るが、S-605 は場所でない被演算子の `move` を位置によらず E0711 とする（R-198、W4-09）ので、W4-09 の後は候補が E0703 と E0711 の間を往復する（§18.1 の候補の約束に反する）。
- 経緯: 79 回目（2026-10-28）、W4-05 U1/t（onsa-test）が範囲の外で見つけ、親が再現した。前からある。関係: R-198、S-605、S-609。
