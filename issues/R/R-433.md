# R-433 `match` の対象と、配列の配列を平面の引数に渡す形で、副作用のある添字を持つ場所の式が腕ごと・要素ごとに評価し直される

- 場所: `crates/onsa_core/src/lower/build.rs::materialize`（`as_place()` が真なら式をそのまま返すが、`Place::Index` の添字は呼び出しを含む任意の式を持てる）。その場所を何度も使う降下: `match` の対象（`lower/body/pat.rs::pat_test` を腕ごとに）と、配列の配列を `[Span[T]; N]` に渡す平面の変換（`lower/body/call.rs::coerce`）。
- 内容: `fn next(inout n: U32) -> U32 { n = n + 1  n - 1 }` の後の `match xs[next(inout n)] { 2 => …, 3 => …, _ => … }`（`xs: [U32; 3]`）は、`next` が腕の数だけ呼ばれ、選ばれる腕が変わる（`n == 1` の `assert` が落ちる）。平面の `lens(w.names[next(inout n)])`（`[[[U8; 2]; 2]; 2]`）も同じ。インタープリタと C で同じ誤った値になる（dev `073bdf60`、W5-12 U3a の前から）。§3.5 は各式を左から一度ずつ評価する形で順を定め、`match` は「取る腕だけを評価する」ので、対象を評価し直す読みは無い。呼び出しの値を対象にした `match f(inout n)` は一度だけ。
- 経緯: 140 回目（2026-11-12）、W5-12 U3a の壊す側（onsa-break）が見つけた（再現は `P/w512a/b/c4.txt` の `int_scrut_index_side`、`c9.txt` の `int_index_side_effect_array_span`）。同じ根の新しい誤り（`FixedStr` を `Span[U8]` に渡すビューが添字を二度評価する）を U3a が入れた。
- 判断: 中（正しいプログラムの値が黙って変わる。書く形としては稀）。同じ根の U3a の誤りと一緒に、場所の添字を一度だけ評価する形を一か所に作って W5-12 U3a で直す（`rules/leader.md` 7.4: 通るプログラムを変えるもの、作業が入れた後退と同じ根）。
- 反映（2026-11-12、親）: W5-12 U3a `499d8d22` で直した（`lower/build.rs::materialize` が局所・リテラル・`const` でない添字を先に一時に束縛し、場所は写さない。事例 `values/place_index_once.onsa`・`c_runtime/c_place_index_once.onsa`）。局所の添字の残りと `inout` の平面の E0200 は R-435。
