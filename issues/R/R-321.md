# R-321 長さに E0304 になった名前（二つの `impl` の同名の関連定数 `S.N`、同じモジュールの二つの `const N`）を書いた繰り返しの式 `[0.0; S.N]` に、浮動小数のリテラルの型が決まらない E0405 が連鎖して出る（§18.1 の誤りの名前を使う所には診断を出さない、に反する）

- 場所: 本体の検査の繰り返しの式（`[e; N]`）の型付けと、関数の終わりの浮動小数のリテラルの既定の判定（推測。長さが E0304 になった名前のとき、要素の型を誤りの型にしない）。
- 内容: §18.1 は、E0304 になった名前を使う所はどちらの宣言も引かず、その名前を誤りとして扱い、使う側に診断を出さないとする。`pub const K3: [F32; S.N] = [0.0; S.N]` と `pub fn f() -> [F32; S.N] { [0.0; S.N] }` は、`S.N` が二つの `impl` の同名の関連定数で E0304 のとき、E0304 に加えて `0.0` に E0405「the type of this float literal cannot be determined」が出る。
  同じモジュールの二つの `const N` の E0304 でも同じ（`issues/R/R-321/module.onsa`。W4-05 U3a の前の `fb45620` でも出る）。見つからない名前 `[0.0; Nope]` は E0302 だけで、E0405 は出ない。
  再現は `issues/R/R-321/members.onsa`（W4-05 U3a の後。U3a が E0304 のメンバを使う所を黙らせたので、関連定数の形にも届くようになった）。誤りのあるプログラムの余分な診断だけで、通るプログラムは変わらない。
- 経緯: 80 回目（2026-10-29）、W4-05 U3a の壊す側（onsa-break）の指摘 F1。親が `P80/bin/onsa-w405u3a`（U3a の変更のビルド）で再現した。関係: S-737、R-55（浮動小数のリテラルだけの比較の E0405）。
- 判断: （2026-10-29、親）直す（低）。本体の型付けの規則の作業 W5-08（定数式と E0405 の順を扱う）で直す。
