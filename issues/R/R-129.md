# R-129 prelude と標準の効果の名前が、仕様でも実装でも決まっていない

- 中・要判断・観点 1 / 3｜`crates/onsa_sema/src/sig.rs:755`、`body.rs:1763`、`std/test.onsa:11`｜§8.1、§8.2、§15.1、D-08
- 内容:
  - 仕様の prelude の一覧（§15.1）に `Alloc` が無いのに、全ての例が `use` なしで `uses {Alloc}` と書いている。レート（`Init Ctl Sig`）も一覧に無い（実装は prelude に入れている）。`Fs` は `use std.fs.{Fs}` で取り込む例があるが、`Random` などがどのモジュールにあるかは書いていない。
  - 実装は効果の名前を解決せず、`"Alloc"` の文字列と比べるだけである。存在しない名前（`uses {Nope}`）も「この版では未対応」の E0200 になり、名前の誤り（E0302）にならない（S-67 に反する。2026-10-04 に確かめた）。
  - std の `std/test.onsa` は、`use` なしで `uses {Random}` と書いている。
- 判断（R-129）: 標準の効果を std の `effect` 宣言にして `use` で取り込むか、`Alloc` をどう扱うか。推奨は、標準の効果は std に宣言して `use` で取り込み、`Alloc` も std に宣言して prelude に入れる。効果の名前は他の名前と同じく解決する。
- 決定（2026-10-04）: 推奨どおり（利用者の指示で `Alloc` も std に宣言する）。S-74。第 1 期は、効果の宣言を std の中でだけ受け付け、`Alloc` 以外の効果を効果行に書くと、名前が解決できた上で E0200（D-08）。
  std は `Random` を宣言し（モジュールの名前は仮。第 2 期の std の設計で確定する）、`std/test.onsa` は `use` で取り込む。再現は `tests/review-phase1/parent/r129.onsa`。
- 判断: 推奨どおり。S-74: prelude は `Option Result Some None Ok Err panic Alloc`、組込み型、レート。`Alloc` は std に `pub effect Alloc {}` と宣言して prelude へ。標準の効果は std の `effect` 宣言で `use` で取り込む。効果行の名前も解決し、見つからなければ E0302。
  第 1 期は std の中でだけ効果の宣言を受け付け、`Alloc` 以外は E0200（D-08）。再現は `tests/review-phase1/parent/r129.onsa`
- 反映: 仕様 §8.1 / §8.2 / §15.1 に反映済み（2026-10-04）。実装は W4-03
- 反映（2026-10-26、親）: S-659（2026-10-26）で、第 1 期の std の宣言の形（六つの標準の効果を操作の無い形で、`Alloc`・`Block` は `std.core`、`Option`・`Result`・trait は (c2) の仮の引き）を決めた。`r129.onsa` の期待はそのまま。実装は W4-03 の U5。
- 反映（2026-10-26、親）: W4-03 U5b（72 回目）で直した。効果行の名前を他の名前と同じく引き（署名・関数型・閉包とも `sig.rs::read_effects`）、`Alloc` は lang item の `DefId` で見分ける。
  std は六つの標準の効果（`std.fs`・`std.io`・`std.time`・`std.random`・`std.log`）と `std.core` の `Alloc`・`Block` を操作の無い形で宣言し、`std/test.onsa` は `use random.{Random}` で取り込む。`r129.onsa` の期待は `tests/spec/effects/names_r129.onsa` に移した（元の入力は W4-03 を終えた区切りで消す）。
