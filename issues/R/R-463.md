# R-463 利用者の `effect` の宣言を、失敗した名前が指しえた効果（S-691）に入れず、失敗した名前だけが原因の単位に E0601 を出す

- 場所: `crates/onsa_sema/src/sig/heading.rs::meant`（失敗した名前が指しえた効果を集める述語が `DefKind::Effect` だけを見る）。利用者の `effect` の宣言は `DefKind::Unsupported(Declared::Effect)`（`names/collect.rs`）。「効果の宣言か」の述語は `resolve.rs`・`manifest/table.rs` が二つの種類を、`meant`・`names/lookup.rs::std_effect_use`・`lib.rs::effect_written` が `DefKind::Effect` だけを見る。
- 内容: §18.1 は「指しえた効果は、その経路の最後の名前と同じ名前の効果」とし、S-1054 (1) はこの版で書けない効果（E0200 の要素）も行の効果に数える。利用者の `pub effect Tick {}` を行に持つ `g` を、取り込みに失敗した `Tick` を行に書いた `f` が呼ぶと、`f` に E0601（「this calls `g`: that needs `Tick`」）が出る。同じ形で std の `Random` なら `f` に E0601 は出ない。パッケージには E0200・E0302 が別にあるので、通るプログラムは変わらない（失敗した名前だけが原因の偽の連鎖）。
  再現: `issues/R/R-463/cases.txt`（`compare.py probe`。`user_effect_meant` が `main.onsa:3:26` の E0601、対照の `std_effect_meant` は無し）。
  直し方の見当: 「効果の宣言か」の述語を一つにして `meant` が読む。`meant` と `std_effect_use` の索引（W6-04 の持ち越し）と同じ所。
- 経緯: 153 回目（2026-11-15）、W6-04 の前の洗い出しの領域 E（onsa-advisor、報告 `target/notes/153/w604_survey/E_report.md` の E3）が見つけ、親が固定のバイナリ `onsa-e0b47f0` で再現し、対照を std の効果に替えた。
- 判断:
- 反映（2026-11-16、親）: W6-04 U7（`e08909c2`）で直した。名前 → 効果の宣言の索引（`Analysis::effects_named`）と述語を一つにし、利用者の `effect`（`DefKind::Unsupported(Declared::Effect)`）も失敗した名前が指しえた効果に数える。`meant`・`std_effect_use` はこの索引を読み、全宣言をなめない。事例 `tests/spec/effects/meant_user_effect*`（6 件）、`meant_path_needs_use`。
