# R-91 flow の降下の計画を、sema が一つの表で渡していない

- 中・直す・観点 2｜`crates/onsa_sema/src/flow.rs:1369-1438`（`mark`）、`:1441`、`:877`、`crates/onsa_core/src/lower/flow.rs:384`、`:461-531`（`ReadWalk`）、`:534`、`crates/onsa_driver/src/graph.rs:139`
- 状態に入れる判断が半分ずつ:
  - `let` を状態に入れる判断は sema の `mark` が、入力を状態に入れる判断は core の `ReadWalk` が行う。`ReadWalk` のコメントには「mirrors the checker」とある。
  - 降下は両方の論理和を取るので、両者が食い違っても気付けない。
- 子の列挙: AST の子を列挙する関数 `children()` が 3 か所にある。
- 名前と所属:
  - ノードのフィールド名（`format!("{name}.buf")` など）を 6 か所で組み立てている。
  - `let` に属するノードを、スパンの包含関係で求めている。
- 不動点の反復: 上限の 6 に根拠が無く、収束しなくても黙って進む。
- 影響: T4-10 や新しい式の種類を足すと、3 か所を同時に直すことになる。
- 直し方: sema が「段ごとの評価の計画、状態のフィールドの一覧、ノードの所属」を一つの表で渡し、core、graph、interface はそれを読むだけにする。M5 の前に行う。
- 範囲（2026-10-05 に追加で確かめた）: 不動点の反復の注記は「`let y` より前の `prev(y, 0.0)` は `y` のレートを後で知る」とする。しかし仕様では、前方の参照は遅延の第 1 引数の中の `^名前` だけで（§11.2、S-44）、その引数は `Sig` でなければならない（E0813）ので、遅延の出力は常に `Sig` で、帰還を除いた依存は `let` の順で閉路を持たない。反復は要らない。
- 決定（2026-10-05）:
  - (1) sema が flow ごとに「flow の計画」を一つ作って記録する（ノード、レートと段、状態のフィールドの一覧と名前、ノードの所属、依存と帰還の辺）。`let` と入力を状態に入れる判断は計画を作るときに一度だけ行い、Core・graph・interface は計画を読む（計画 §3.5 の追記、D-15）。フィールド名を作る処理と子の列挙は一つの関数にする。所属は木の構造で決める。
  - (2) レートの不動点の反復をやめ、`let` の順の一度の走査で決め、`^` の参照が `Sig` であること（E0813）は後で検査する。クロックやマルチレート（§19.1）を入れるときは見直す。
  - (3) 時期はレビューの後に決める。T4-10（R-90）と R-81 の Core の変更と同じ回に揃える候補。
- 判断: 直す。(1) sema が flow の計画（ノード、レートと段、状態のフィールドと名前、所属、依存と帰還）を一つ作り、Core・graph・interface はそれを読む。(2) レートの不動点の反復をやめ、`let` の順の一度の走査と `^` の事後の検査にする（§11.2、S-44、E0813 から閉路が無い）。(3) 時期はレビューの後（T4-10、R-81 と同じ回の候補）
- 反映: 計画 §3.5 に追記（2026-10-05）。実装は W7-02、W7-03、W7-08
