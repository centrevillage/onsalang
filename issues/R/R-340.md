# R-340 flow の本体の `!` の呼び出し（`q.put!(x)`、`Some!(x)`、`p.get!()`）が誤りなしで通る（§11.2 は E0806。fn の本体では E0714 か E0701 が出る）

- 場所: sema（flow の本体の式の閉じた一覧の判定、`flow/check.rs`。flow の本体は modes の段の `!` の判定にも届かない見込みで、コードは確かめていない）。
- 内容: §11.2 は flow の本体に書ける式を閉じた一覧にし、`!` の呼び出しを一覧の外（E0806）とする。flow の本体の `let q = P.new(x)` の後の `q.put!(x)`（`let` の束縛の `inout self` のメソッド）、`Some!(x)`、`p.get!()` は、誤りなしで通る。
  同じ形は fn の本体では E0714（構築子と `self` のメソッドの `!`）か E0701（変更できない束縛のレシーバ）になる。入力は `issues/R/R-340/`（dev `cf526898` で終了コード 0）。flow の本体の `!(` の E0806 を確かめる事例と実装待ちの項目は無い。
  `!` の無い `q.put(x)`（`issues/R/R-340/q_put_noband_flow.onsa`）も flow の本体で通る（fn の本体では E0701。第 76 組の段 1 が見つけた）。
- 経緯: 93 回目（2026-10-31）、第 76 組の下書き（onsa-gap）が見つけ、親が再現した。
- 判断: 直す（中。誤りのあるプログラムが通る）。E0806 を名前の段で出す W7-04 で、`!` の呼び出しも閉じた一覧の外として報告する。flow・遅延の `!(`（`lp!(x)`）は第 76 組（S-813）で決め、W4-12 の U2 が入れる。flow の本体の `q.put(x)` の E0713 は、候補「`!` を足す」が前の段の E0806 を作るので候補なし（S-811）。
