# R-350 要素が数でない列の `add_from!`（`[Bool; 2]`・`[[F32; 2]; 2]`）が検査を通り、`onsa test` で内部エラー（arithmetic on Bool）になる

- 場所: 組込みの表（`crates/onsa_sema/src/builtin.rs` の `Recv::Seq`）が `add_from!` を全ての列の受け手に置き、要素の型を見ない。インタプリタの `onsa_interp/src/numeric.rs` の 67 行が数でない値で内部エラーにする
- 内容: `var xs: [Bool; 2] = [true, false]` の後の `xs.add_from!(ys)` が `check` を通り、`onsa test` で「internal error: arithmetic on Bool」（終了コード 101）。`[[F32; 2]; 2]` も同じく検査を通る。再現は 105 回目の scratchpad の `g78/probe/addfrom/r1_bool.onsa`・`r2_nested.onsa`
- 経緯: 105 回目（2026-11-03）、第 78 組の下書き（onsa-gap）が見つけ、親が `1bb94a0` で再現した。前からある
- 判断: 直す（内部エラー）。要素の要求は S-855 で決め、W5-02 で列のメソッドを std に宣言するときに直す
- 判断（2026-11-03、親）: S-855 の決定（2026-11-03、(a)）で、`add_from!` の要素は `AnyNum` に限り、`[Bool; 2]` などは呼び出しの位置の E0416 になる。W5-02 で直す（`AnyNum` の境界の対応が要る）
