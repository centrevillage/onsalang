# R-141 export の入出力の重なりの検査が、型の違う組を誤って測る

- 中・直す・観点 1｜`crates/onsa_backend_c/src/export.rs:249-272`｜§14.2
- 内容: `process` の入出力の重なりの検査が、組の一方の要素の大きさで両方の範囲を測る（`Bool` の出力を `F32` の大きさで測る）。実際より大きい範囲になり、偽の重なりで `process` が 2 を返す。また、要素の型を引数の名前の前方一致（`a.starts_with(&p.name)`）で探すので、`x` と `xs` のような名前で違う引数の型を拾う。
- 経緯: W1-06 の gcc の検査で見つけた（2026-10-07）。gcc の配列の置き方では重なり、clang では偶然重ならない。再現は `tests/conformance/boundary.onsa` の `boundary.split`（gate の `c-gcc` の実装待ち）。
- 決定（2026-10-07、親）: 直す。生成したコードが黙って誤る実行時の誤りで、判断は要らない。W2-08 で、各範囲をその引数の要素の大きさで測り、引数は名前の前方一致でなく構造で引く。
- 補い（2026-10-07、W1-06/b）: 逆の向きもある。出力の要素が入力より大きい型（F32 の入力と F64 の出力）では、出力の範囲を小さく測るので、部分的な重なりを検出せずに処理する（§14.2「部分的な重なりは検出して 2 を返す」に反する）。偽の検出と偽の不検出の両方を同じ直しで消す。
- 判断: 直す（親）。export の入出力の重なりの検査は、各範囲をその引数の要素の大きさで測り、引数を構造で引く。W1-06 で見つけた
- 反映: 実装は W2-08
