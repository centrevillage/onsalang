# R-246 E0200 にした extern のブロックのメンバが名前解決に見えず、使う所に偽の E0302 が出る

- 場所: `crates/onsa_sema/src/sig/collect.rs` の `ItemKind::Extern`（E0200 にしたブロックの名前 `<extern>` だけを登録し、メンバを登録しない。trait・effect・handler は E0200 にしても名前を登録する）
- 内容: `lib` を書いた正しい `extern "C" lib "m" { fn c_abs(x: I32) -> I32 }` と、別の関数の `c_abs(1)` は、ブロックの E0200 と、使う所の E0302「cannot find `c_abs` in this scope」を出す。
  §18.1 は「誤りのある宣言も、名前まで読めれば名前解決に見せる…正しい宣言に偽の連鎖エラーを出さないためである」とする。E0200 のブロックのメンバも名前まで読めているので、使う所の E0302 は偽の連鎖である。修復のループが使う所を直しに行きうる。
- 経緯: 第 38 組の下書き（onsa-gap、2026-10-23、55 回目）が S-477 の確かめで見つけた（族の外）。dev `8427cf2` の release の `check` で親が再現した。直しは `sig/collect.rs` を作り直す W4-03。
- 判断:
- 補い（2026-10-24、親）: 63 回目（2026-10-24、W4-14 U3 の壊す側）: `naming::check` は extern のブロックの中の名前（関数と型）を見ない。今はブロックが E0200 で見える誤りは無いが、extern のブロックを実装するときに §2.3 の名前の規則を当てる。
- 判断（2026-10-25、親）: 69 回目（W4-03 U3b2 の壊す側の F5、利用者が了承）: E0200 にした extern のブロックは一つの単位でメンバを検査しないので（§18.1）、メンバの側に付く E0304（項目の後のメンバ、ブロックの中の二つのメンバ、二つのブロックの同じ名前）はブロックの E0200 に隠れる。項目の側に付く E0304（メンバの後の項目）は出る。直さない。
