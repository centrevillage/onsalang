# R-260 E0320 の修正候補が元の名前と同じになる（`struct Self_`、効果行変数の `inout_`）: release は何も変えない候補を出し、debug は内部エラー

- 場所: `crates/onsa_syntax/src/naming.rs`（E0320 の候補を作る `convert` と、S-243 の予約語の `_`）、`crates/onsa_driver/src/lib.rs` の `debug_contract`｜§2.3（E0320 の候補）、§18.1（候補を当てた後の約束）
- 内容: 規則に揃えた名前が予約語のとき末尾に `_` を足す S-243 の規則が、`_` を受けない形に当たると、候補が元の名前に戻る。
  `struct Self_ { x: I32 }` は型の名前の候補が `Self`（キーワード）で、`_` を足すと `Self_` に戻る。効果行変数の `[T, inout_]` は `snake_case` 1 語の候補が `inout`（キーワード）で、`_` を足すと `inout_` に戻る（`[T, in_out]` の候補 `inout_` もまだ E0320）。
  release のバイナリ（dev `471d076`）は「replace `Self_` with `Self_`」の何も変えない候補を出す。debug のバイナリ（dev `fdc4fa5`）は `debug_contract` で終了コード 101 の内部エラー「`rename by the naming rule` does not change the source」になる。
  §18.1 は約束を満たす候補を作れなければ出さないとするので、候補を出さないのが仕様の形である。再現は `issues/R/R-260/self_type.onsa`・`inout_effect_var.onsa`（`onsa check`）。
- 経緯: 62 回目（2026-10-24）、S-642 の下書き（onsa-gap、第 52 組）が見つけ、親が両方のバイナリで再現した。gate の fuzz と事例は拾っていない（`rules/leader.md` 4.9。直す往復で、この形を E0320 の事例に足す）。
  効果行変数の形は S-642 の決め方で変わる（「1 語」を外せば `inout_` は `snake_case` で通る）。`Self_` の形はどの案でも残る。
- 判断:
- 判断（2026-10-24、親）: 補い（2026-10-24、63 回目、S-650・S-642 の決定）: 反映後の §2.3 では末尾の `_` を全ての形に書け、「1 語」も無いので、`struct Self_` と効果行変数の `inout_` は E0320 にならず通る。W4-14 U3 で通る事例に足し、候補が元の名前と同じなら出さない守りは一般の安全として残す。
- 反映（2026-10-24、親）: W4-14 U3（63 回目）で直した: `Self_`・`inout_` は通り、候補が元の名前と同じなら出さない守りを `Shape::candidate` に置いた。事例 `tests/spec/types/naming_shapes_fine.onsa`・`naming_type_params_fine.onsa`
