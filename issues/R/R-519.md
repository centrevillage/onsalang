# R-519 イベントを持つ flow の `match` の腕のガードがその腕の束縛を読むと、`check` がスタック溢れで終わる（四つの所の探索 `Mix::of_name` の無限再帰）

- 場所: `crates/onsa_sema/src/flow/clocks/mix.rs` の `Mix::of_name`（W7-11 U1b が足した）。
- 内容: 腕の束縛のイベントの値を、対象と、その腕までのガードから探す。自分の腕のガードがその束縛を読む（`match o { Some(v) if v > 3.0 => v, … }`）と、`events` と `of_name` が終わらない（`chosen` に入るのは探した後）。イベントを持つ flow（見出しのイベントの入力か出力、またはイベントの出力の呼び出し）の `match`・`match~` だけで、`let` の初期化式か四つの所から探すときに起きる。書き手が普通に書く形である。`check` が SIGABRT で終わる。
- 経緯: 185 回目（2026-11-25）、W7-11 U2g の実装（onsa-impl）が、通る事例の flow の本体にイベントの使う所を一つ足す掃引（`inject.py`、`target/notes/185/w711/u2g/i/`）で見つけた。U1b の事例は、イベントの flow のガードが自分の束縛を読む形を持っていなかった。
- 判断: 直した（W7-11 U2g のコミット）。探す前に `chosen` に `None` を置く（自分の束縛は、対象と前のガードが足すものの他に足さない。対象にイベントの値があれば先に見つかる）。事例 `tests/spec/flow_clock/event_guard_reads_its_binding_r519.onsa`。掃引の方法を gate に入れるのは W7-11 の `持ち越し`（U3 で、候補の文脈の格子と一緒に見る）。
