# R-334 生成型 `Out` のフィールドの型が `Buf[T]` で、§11.6 の `Span[T]` と違う（`Buf[F32]` の引数に `o.l` を渡す形が E0401 にならず通り、`inout o: g.Out` の `let l = o.l` が E0710 でなく部分移動の E0711）

- 場所: `crates/onsa_sema/src/sig/generated.rs::fill_by_output`（397 行の近く。出力の struct の各フィールドを `Buf[e]`、配列なら `[Buf[e]; N]` で生成する）。
- 内容: §11.6 は、生成型 `Out` のフィールドを「各フィールドは `Span[T]` か `[Span[T]; N]`」とする（`In` も同じ）。実装は `Buf[T]` で生成するので、型の段が `o.l` を `Buf[F32]` と見る。
  再現は横の `out_field.onsa`（dev `9804880`）。
  - `pub fn to_buf(o: pair.Out) -> U32 { tb(o.l) }`（`tb(b: Buf[F32])`）が通る。同じ形の `Span[F32]` の値は E0401「expected `Buf[F32]`, found `Span[F32]`」。
  - `o.l.push(1.0)` の診断が「`Buf[F32]` has no method `push`」と `Buf` を名指す。
  - `inout o: pair.Out` の `let l = o.l` が、部分移動の E0711 になる。S-788 は `inout` 引数からの束縛を E0710 とする（`Span` なら第二級の述語で E0710 になる）。借用の `o` からの `let l = o.l` は通るが、`l` は第二級にならない（`var p = (l, 1)` が E0710 でなく E0711）。
- 経緯: 87 回目（2026-10-30）、W4-07 U2b/i（onsa-impl）が S-788 の `inout` の形を実装して気付いた。親が dev のバイナリで再現した。前からある。
- 判断: 直す（中。型の誤りを通す）。W7-03 の生成項目 `In`・`Out`・`Rendered` の Onsa の側で、フィールドの型を §11.6 に合わせる（Core と後端の表し方が変わるかは W7-03 の設計で見る）。W4-07 の S-788 の `inout` の事例は、この R の直しまで実装待ちにする。
