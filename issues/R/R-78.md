# R-78 「一通りの書き方」に反する別の形を受理し、fmt も正規化しない

- 中・直す + 要判断・観点 1｜`crates/onsa_syntax/src/parser.rs:457`、`:945-962`、`fmt.rs:750-757`｜§6.1「`()` のときは `->` を省略（唯一の書き方）」「末尾の `return` は fmt が除去」、§8.1「効果行が空なら `uses` を書かない」
- 再現:
  - `fn f() -> () {}` と `fn f() -> I32 uses {} { 1 }` が通り、fmt もそのまま残す。
  - 値の無い末尾の `return` と、無名関数の末尾の `return v` が除かれない。
- 直し方: fmt で除く。
- 判断（R-78）: `check` でもエラーにするか。
  - (a) E0020 にし、修正候補を付ける。
  - (b) fmt だけで正規化する。
  - 推奨は (a)。書き方が一つであることを、検査で保証する。
- 関連: R-69（S-56）で、fmt が AST を変える書き換えを閉じた一覧にした。(a) なら末尾の `return` は E0020 になるので一覧から外れる（構文の診断のあるファイルは fmt が書き換えない）。(b) なら `-> ()` と `uses {}` の除去が一覧に加わる。
- 関連: R-73（S-62）で、トークンの綴り（数値リテラルの文字の大小、`_` の位置）に限り、受理して fmt で揃えると決めた。
- 範囲（2026-10-04 に追加で確かめた）: 関数の型の `fn(F32) -> ()` と、末尾の位置の `if` / `match` の分岐の中の `return` も残る。今の fmt が外すのは、名前付き関数の本体の最後の文の `return v` だけである。
- 決定（2026-10-04）: (b) fmt で取り除き、`check` ではエラーにしない（元の推奨 (a) を改めた）。利用者の整理: これらは一意性の違反のうち「余分な情報」で、冗長な括弧を外すのと同じ。一意性の違反で重要なのは、構文規則の違反と、同じことをする機能が複数あることで、それは言語の設計の問題である。
  S-68: 末尾の位置（本体の最後と、そこにある `if` / `match` の各分岐の最後を再帰的に）の `return` を外す（値の無いものを含む）。`-> ()` と空の `uses {}` は全ての位置で外す。S-56 の一覧に加え、P2 の帰結をこの線引きで書き直した。再現は `tests/review-phase1/parent/r78.onsa`。
- 判断: (b) fmt で取り除く（元の推奨 (a) を改めた）。S-68: `-> ()`、空の `uses {}`、末尾の位置の `return`（本体の最後と、そこにある `if` / `match` の分岐の最後を再帰的に。値の無いものを含む）は意味を変えない余分な情報で、冗長な括弧と同じく受理して fmt が取り除く（利用者の整理）。S-56 の書き換えの一覧に加えた。
  P2 の帰結を「同じことをする機能や構文が複数あるのは設計で避け、規則に合わない書き方は検査で落とす。余分な情報は fmt が取り除く。解釈の分かれる書き方は検査で落とす」に書き直した。再現は `tests/review-phase1/parent/r78.onsa`
