# R-104 固有 impl を書ける場所と、組込み型への impl

- 中・要判断・観点 1 / 3｜`crates/onsa_sema/src/sig.rs:565-620`、`resolve.rs:126`、`body.rs:2146`｜§6.3（孤児規則）、§11.6（「同じモジュールに `impl voice.State` を書ける」）、§6.6 `impl F32 { const PI }`
- 定義と別のモジュール: 型の定義と別のモジュールで、`impl Point` を書ける。
- 組込み型への impl:
  - 利用者のコードで `impl F32 { const HALF; fn make(); fn double(self) }` と `impl Option[F32]` を書ける。
  - `F32.HALF` と `F32.make()` は使えるが、`x.double()` は E0413 になる。
  - 組込み型への impl は、全てのパッケージに効く追加になる。
- 仕組みの重複: `F32.PI` は `builtin.rs` の直書きで、別の仕組みである。
- 判断（R-104）:
  - (a) 固有 impl も型を定義したモジュールに限る。組込み型への impl は std だけに許す（§11.6 と整合する）。
  - (b) 他のモジュールでの impl も許し、仕様に書く。
  - 推奨は (a)。どちらの場合も、仕組みは一本化する。
- 決定（2026-10-04）: (a)。R-79 と一緒に決めた。S-70: 固有の `impl Ty` は `Ty` を定義したモジュールにだけ書け、違反は E0307（新設。trait の impl の違反も同じ）。組込み型は std で定義されたものとして扱い（§11.6 と同じ扱い）、組込み型のメソッド・関連関数・関連定数と標準 trait の実装を書けるのは std だけ。
  利用者が組込み型に足せるのは、自分で定義した trait の実装だけ。仕組みは R-79 の決定で一本化する（`F32.PI` も std の `impl F32` に宣言する）。§6.6 の例を `impl Point` に改めた。再現は `tests/review-phase1/types/orphan/`（期待値は `main.onsa` の先頭のコメント）。
- 判断: (a)。S-70: 固有の `impl Ty` も `Ty` を定義したモジュールにだけ書ける（違反は E0307、trait の impl も同じ）。組込み型は std で定義されたものとして扱い、組込み型のメソッド・関連関数・関連定数と標準 trait の実装は std だけが書ける。§6.6 の例を `impl Point` に改めた。再現は `tests/review-phase1/types/orphan/`
- 反映: 仕様 §6.3 / §6.6 に反映済み（2026-10-04）。検査の実装は W5-04、組込みの宣言の移行は W5-02
