# R-61 配列の長さに使う定数の扱いが不揃い

- 中・直す・観点 1｜`crates/onsa_sema/src/sig.rs:1137`、`:236`｜§4.5、§4.1
- 修飾付きの名前: `[F32; cfg.N]` は E0200 になるが、`Ring[F32, cfg.N]` は通る。
- 型の検査: `const N: I64 = 4` を長さに使っても、シグネチャは通る。
- 古い文面: E0200 の文面が、M3 の完了後も「evaluated in M3」のままである。
- 範囲（2026-10-04 に追加で確かめた）: 計算で決まる定数（`const N2: U32 = N * 2`）を長さに使うと、この E0200 になる。§6.6 のコンパイル時定数なのに使えない。`Ring[F32, M]`（`M: I64`）も通る。DSP では他の定数から長さを導くことが多いので、重さを低から中に上げた。
- 決定（2026-10-04）: 直す。配列の長さと const 引数は定数式（整数のリテラル、定数を指す名前、算術の演算子と括弧。型は `U32`）。const の型パラメータを含む式は E0417。S-50。
- 判断: 直す（重さを中に）。S-50: 配列の長さと const 引数は定数式（整数のリテラル、定数を指す名前、`+ - * / %`、括弧。型は `U32`）。計算で決まる定数も使える。修飾した名前はどちらの位置でも使える。const の型パラメータを含む式は E0417
- 反映: 仕様 §4.1 / §4.5 / §11.4 / §11.5 に反映済み（2026-10-04）。実装は W5-08、W9-03
