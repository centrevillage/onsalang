# R-233 呼び出しの形の候補の入れ子の確かめが、上限に近い単位ごとにファイルの全体を読む

- 低・直さない・観点 2｜syntax（`foreign/calls.rs` からの `groups::nests_too_deep`、`Within::file`）｜§18.1、§2.5（入れ子の上限）
- 内容: 呼び出しの形の誤り（`g(a)(a)` など）の候補が入れ子の上限を超えるかの確かめは、構文解析の途中で単位の表がまだ無いので、その単位が上限に近いとき（254 段など）ファイルの全体を読む。そうした単位が N 個並ぶと費用は二乗になる（800 単位・452 KB で約 93 秒、debug）。W3-13 の前後で時間は同じ。
  実際の書き手が 255 段に近い入れ子の単位を数百並べることは考えにくく、ファズの入れ子の変異体の形である。
- 経緯: W3-13/b の直しの再確認が見つけた（再現は 31 回目の scratchpad の `w313b3/dd3/call254_*.onsa`、2026-10-16）。前からある。
- 決定（2026-10-16、親）: 直さない（記録だけ）。直すなら、構文解析器がその単位の範囲を渡し、単位の文字で確かめる。
- 判断: 直さない（実害が低い）。呼び出しの形の候補の入れ子の確かめが、上限に近い単位ごとにファイルの全体を読み二乗になる（W3-13/b の再確認が見つけた、前からある）
