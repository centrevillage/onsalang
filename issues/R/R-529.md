# R-529 降ろせない型（`Str`・Shared を含む型）の引数・結果・局所変数が、診断なしに `()` の型で Core に降りる（§18.1 の「黙って誤った結果にせず」）

- 場所: `crates/onsa_core/src/lower/body/mod.rs` の `FnCx::new` の `placeholder_ty`（引数・結果・局所変数の型の降下が失敗すると `()` を置く）と、`lower/body/expr.rs` の穴の局所変数 `__unsupported`。
- 内容: 第 1 期は `Str` と Shared を含む型を降ろせない（E0200、`tasks/phase2.md`）。値を作る所は E0200 になるが、読まない引数・struct の引数（`pub fn unused_param(s: Str) -> U32 { 1 }`、`Str` のフィールドを持つ `Mm` の引数）は、診断なしに `fn …(s: ()) -> U32` に降り、`dump --core` と `test` が通る（`R-529/silent_unit.onsa`）。Core と C の署名が誤る。
  その引数を別の関数へ渡すと、検証器が「type mismatch `()` vs `…Mm`」で拒み、内部エラー（101）になる（`R-529/verifier_101.onsa`）。実行の値が誤る道は見つかっていない。同じ形の事例は 7 件（`wellformed_shared_elements_fine.onsa` の `a: ()` など）。R-332・R-335 と根は近い（降ろせない型が仮の形で残る）が、出る所が違う。
