# R-105 型別名の使い道

- 低・要判断・観点 3｜`crates/onsa_sema/src/sig.rs:642`、`:1060` 付近
- 再現: `type P = Point` に対して、`P.new()` は「not a value」、`P { x: 1.0 }` は「not a struct」になる。
- 診断コードの流用:
  - 別名の循環に、E0310（循環 import）を使っている。
  - アリティの誤り、「型でない」、未知の属性、impl の対象の誤りを、すべて E0302（未解決）にしている。
- 判断（R-105）: 別名を、名前空間と struct リテラルに使えるか。
  - 推奨は、Rust と同じく使えること。
  - 診断コードの表は、`explain` を書く前に整理する（`impl-review` T-8 と合わせる）。
- 範囲（2026-10-05 に追加で確かめた）:
  - 型の位置は通る。関連関数 `P.new()`（E0401）、関連定数 `Sample.PI`（E0302）、struct リテラル `P { x }`（E0401）、パターン（E0401）、列挙子 `S.Circle`（E0401 / E0302）は通らない。
  - 別名を通した `impl` が孤児規則をすり抜ける: 別のモジュールの型の別名（`type Q = geo.Point` の `impl Q`）と、組込み型の別名（`type B = Buf[F32]` の `impl B`）が通る。
  - 総称の別名 `type V[T] = (T, T)` は、理由を示さない E0002。循環は E0310、型引数の数の誤りは E0302 を流用している。
  - flow は型パラメータを持てない（`flow g[T: Float]` は E0002）。
  - 再現は `tests/review-phase1/parent/r105/`（`alias.onsa`、`generic.onsa`、`cycle.onsa` は `onsa check`、`impl/` はパッケージ）。
- 決定（2026-10-05）: S-91。
  - 別名を残すか（利用者の問い。P2 に触れそうなので利点を確かめた）: 残す。flow は型パラメータを持たないので、flow の精度を一か所で切り替える手段（`type Sample = F32`）は別名だけである。定数で長さの決まる型の名前（`type Frame = [Sample; CHANNELS]`）にも使う。
    P2 が禁じるのは同じことをする機能が複数あることで、型に名前を付ける手段は別名だけ（値に名前を付ける `const` と対）。単位の区別（`type Hz = F32`）は安全だと誤解させるので、struct を使うよう §4.4 に書いた。
  - (1) 型の名前を書ける全ての位置で、別名を元の型と同じに使える（推奨の理由は「Rust と同じ」から、書き手の予想と名前の段での一度の解決、精度の切り替えに関連定数が要ることに改めた）。
  - (2) `impl` と `impl Tr for` の対象に別名は書けない（E0307、修正候補は元の名前）。型のメソッドが宣言の名前で見つかり、孤児規則を避けられない。
  - (3) 型別名は型パラメータを持たない（E0002 の文面で示す）。総称の別名は §19.1。
  - (4) 別名の循環は E0311。他の流用（型引数の数、「型でない」、未知の属性、`impl` の対象が E0302）は、`explain` を書く前の診断コードの表の整理（`impl-review` T-8）で決める。
- 判断: S-91: 別名を残す（flow の精度の切り替えの唯一の手段。利点を確かめてから決めた）。型の名前を書ける全ての位置で元の型と同じに使える。`impl` の対象に別名は書けない（E0307。今は孤児規則をすり抜けていた）。型パラメータは持たない（総称の別名は §19.1）。循環は E0311。他の診断コードの流用は T-8 で。再現は `tests/review-phase1/parent/r105/`
