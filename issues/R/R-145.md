# R-145 生成した C が、`Option` の `match` と `narrow_*` の範囲の検査で `-Werror` の警告に落ちる

- 低・直す・観点 1｜`crates/onsa_backend_c/`（`match` と `narrow_*` の出力）｜§13.4、§14.2
- 内容: テストベクトルの fixture（`tests/vectors/fixture/scalar`）の生成した C が、W1-06 の C の検査（`-Wall -Wextra -Werror -pedantic`）を通らない。三種類ある。
  (1) 網羅した `match` を `if … else if (tag == 0)` と最後の腕まで条件付きで出し、clang の `-Wsometimes-uninitialized` になる（140 件）。(2) `narrow_*` の範囲の検査が符号の違う整数どうしを比べ、clang と gcc の `-Wsign-compare` になる（28 件）。
  (3) 同じ検査が常に真の比較を含み、clang の `-Wtautological-constant-out-of-range-compare` になる（gcc の `-Wtype-limits` と同じ種類）。値の誤りではない（`onsa build` は通り、`-Werror` を外せばコンパイルできる）。
- 経緯: W2-01 のテストベクトルの fixture で見つけた（2026-10-08）。今までの事例は、`Option` の `match` と `narrow_*` を export するビルドに含んでいなかった。
- 決定（2026-10-08、親）: 直す。生成した C を警告なしにする W2-09 で、`match` の最後の腕を条件なしの `else` にし、`narrow_*` の範囲の検査を型の範囲に合わせて符号の揃った比較だけで出す（`-Wtype-limits` に当たる検査を生成しない、と同じ回）。
- 判断: 直す（親）。生成した C の `match` の最後の腕を条件なしにし、`narrow_*` の範囲の検査を符号の揃った比較だけで出す（`-Werror` の警告を出さない）。W2-01 で見つけた
- 反映: 実装は W2-09
