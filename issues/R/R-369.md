# R-369 while の条件の中の `break`・`continue` が、C では内側のループのものになる

- 場所:
- 内容: 条件に文が要る `while` の C は `for (;;) { 条件の文; if (!c) break; 本体 }` なので、条件の中の `break`・`continue` は C ではこの `for` を指し、外のループに届かなかった。検査の段とインタープリタは外のループのものとして扱うので、同じプログラムの結果が C でだけ違う。
  `while n < 3 { n = n + 1; while ({ if c { break } … false }) {} … n = n + 10 }` の `c = true` は、インタープリタが 1、C が 11。外が `while true` なら C は止まらない。`for` の反復元と範囲の端はループの前に評価するので当たらない。
- 経緯: S-892 の了承の後に、読みを実行で確かめて見つけた。`tools/run_cases.py` と `onsa_cases --c` は C の手順（`[[test.host]]`）を回さず、回すのは `cargo test -p onsa_tests --test cases` だけである。
- 判断:
- 反映（2026-11-05、親）: W5-08 の S-892 の直し。条件の中の `break`・`continue` は、外のループのラベルへの `goto` にした（`onsa_backend_c` の `leave_loop`）。事例は `tests/spec/c_runtime/c_break_in_loop_head.onsa`。
