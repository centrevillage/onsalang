# R-157 `let o = None` の後の `match o { Some(3) => 1, _ => 0 }` が内部エラーになる

- 中・直す・観点 1｜型の段（推論）｜§4.7
- 内容: パターンの `3` が `T` を整数リテラルの型変数に結ぶが、関数の終わりに既定の `I32` が当たらず、`onsa test` で内部エラー「unresolved type」になる。同じ `o` を後で `Option[F32]` に結ぶと、E0401 の文面が「a literal cannot have type」になる。S-226 で、パターンの中のリテラルと列挙子は対象の型引数と単一化し、関数の終わりに `I32` になると決めた。
- 経緯: S-226 の仕様の空白 S-207〜S-228 の下書き（[`spec-gaps-w2-w3.md`](spec-gaps-w2-w3.md) の付録 A）で見つけた（2026-10-08）。
- 決定（2026-10-08、親）: 直す。W2-06 で S-226 と同じ回に直す。
- 判断: 直す（親、S-226 で決めた）。パターンの中のリテラルを対象の型引数と単一化し、関数の終わりに既定を当てる。S-226 の下書きで見つけた
- 反映: 実装は W2-06
