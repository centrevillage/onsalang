# R-263 export する頭が `_` の関数の C の名前が `t_onsa_g` になり、§14.2 の「`prefix` と名前の最後の要素をつなげたもの」（`t__g`）と違う

- 場所: C のバックエンドの export の名前（`prefix` と名前の最後の要素をつなぐ所）｜§14.2
- 内容: `[export] prefix = "t_"` のパッケージで頭が `_` の関数 `pub fn _g` を出すと、C の名前は `t_onsa_g` になる（dev `fdc4fa5`、`onsa build --target host`。再現は `issues/R/R-263/`）。§14.2 の「C の名前は `prefix` と名前の最後の要素をつなげたもの」なら `t__g`。
- 経緯: 62 回目（2026-10-24）、族「§2.3 の名前の形」（S-650、第 52 組）の下書き（onsa-gap）が見つけ、親が再現した。頭の `_` を書けなくすれば形は無くなる（S-650 の決め方による）。直す作業は S-650 を決めたときに決める（C の名前は W10-02）。
- 判断:
- 補い（2026-10-24、親）: 62 回目（2026-10-24）: `t_onsa_g` は `crates/onsa_backend_c/src/names.rs` の `ident` が `_` で始まる名前の頭に `onsa` を足すため（C が `_` と大文字で始まる名前と `__` で始まる名前を予約するのを避ける、意図した変換）。§14.2 の文はこの変換を書いていない。
- 判断（2026-10-24、親）: S-650 の決定（2026-10-24、62 回目。頭の `_` はどの形でも書けない）で、この形は書けなくなる。W4-14 U3 の事例で E0320 になることを確かめて閉じる。§11.6 の理由の文は「識別子は `__` を含まず `_` で始まらないので重ならない」に改める（仕様の反映）。
- 反映（2026-10-24、親）: 仕様は 63 回目に §2.3（頭の `_` は書けない）と §11.6 に反映した（`7c4ba06`）。W4-14 U3 の事例で E0320 を確かめて閉じる
