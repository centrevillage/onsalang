# R-417 型引数の並びの中の `Rg::[F32, [F32; Rg::[…].len]]` を重ねると、`parse_type_arg` の試し読みが型と式の両方で内側を読み直し、`onsa check` の時間が段の数の指数になる（n=20 で約 0.8 秒、n=60 で 10 秒超。§2.5 の 256 段の内）

- 場所: `crates/onsa_syntax/src/parser/types.rs` の `parse_type_arg`（型引数の並びの要素を型と式のどちらで読むかの試し読み）。
- 内容: `pub struct Rg[T, const N: U32] { d: [T; N] }` に続けて、`Rg::[F32, [F32; Rg::[F32, [F32; … I32 …].len]].len]` を n 段重ねた `pub fn f(r: …) -> U32 { 0 }` の `onsa check` の時間が、n=16 で 0.06 秒、n=18 で 0.21 秒、n=20 で 0.8 秒、n=60 で 10 秒を超える（n が 2 増えるごとにほぼ 4 倍）。診断は最初の `::` の E0020 で、n=60 でも §2.5 の 256 段の内（1 段で 3〜4 段使う）。見立て（推測）: 試し読みで、型としての読みと式としての読みの両方が内側を全部読み直す。
- 経緯: W5-16 U1d の壊す側が見つけた（2026-11-09、129 回目、`target/notes/129/w516u1d/b_report.md` の指摘 3）。`b45edc4`・U1d の前・U1d の後の三つで同じで、前からある。
