# R-126 組込みのメソッドの一覧が、仕様で閉じていない

- 中・要判断・観点 1 / 3｜`crates/onsa_sema/src/builtin.rs:33-130`｜§3.1（`:198` の例）、§3.3、§3.4、§5.3、[`api-candidates.md`](api-candidates.md) A-04
- 内容: R-79 で組込みの知識を一か所にまとめるには、その元になる仕様の一覧が閉じている必要がある。次の点が閉じていないか、実装と合わない（1〜4 は 2026-10-04 に `onsa check` で確かめた）。
  1. 整数の `x.abs()`、`x.min(y)`、`x.max(y)` が通る。仕様に無く、`std.math` の `abs` / `min` / `max`（`Num` で総称）と二重になる。A-04 は浮動小数のメソッドだけを扱った。§3.1 の結合の強さの例 `-x.abs()` も、メソッドの形を使っている。
  2. `F32` の `x.round_f64()` が通り、`x as F64` と二重になる。`F32` の `x.round_f32()` は何もしない変換になる。整数でも、`as` で書ける拡大（`I8` の `round_f64()`）をメソッドでも書ける。§3.3 は「`as` で書けない変換をメソッドで書く」と読める。
  3. 列（`Span`、`Buf`、`[T; N]`）の `is_empty` が通る。§5.3 の一覧に無い（`Str` には §4.2 にある）。R-96 で挙げたが、決定には入っていない。
  4. §3.4 は「`checked_*` のメソッド」と開いた形で書き、`checked_rem` / `checked_rem_euclid` に触れている。実装は `checked_add` / `sub` / `mul` / `div` だけで、`checked_rem` は E0413 になる。
  5. §3.3 の変換のメソッド（`narrow_*`、`trunc_*` / `trunc_*_sat`、`round_f32` / `round_f64`、`to_bits` / `from_bits`）は例でだけ示されていて、どの型からどの型へあるかの一覧が無い。
  6. A-04 で浮動小数の `is_nan` / `is_finite` のメソッドを不採用にしたが、代わりになる `std.math` の関数が無い。今は `x != x` でしか書けない。
- 判断（R-126）: 各点について、仕様の一覧に入れるか外すかを個別に決める。R-79 で組込みを一か所にまとめる前に決める。
- 経緯: R-79 の議論で見つけた（2026-10-04）。
- 範囲（2026-10-05 に追加で確かめた）:
  - 1〜4 は 2026-10-04 のとおり。ほかに、`I32` の `narrow_i64()`（拡大なので常に `Some`）と `narrow_i32()`（同じ型）、`I8` の `round_f64()`（`as F64` と同じ）も通る。
  - `as` で書けない組の E0411 は修正候補を一つだけ出す。`F32 as I32` は `trunc_i32()` だけで、Rust の `as` の読みの `trunc_i32_sat()` は出ない。`I64 as U8` は `narrow_u8()` で、`Option[U8]` を返すので `U8` を期待する位置では型が合わない。
  - `checked_neg` も E0413。浮動小数の `x.is_nan()` は、A-04 で不採用にした後も実装が消していないので通る。
  - 切り捨ての整数の変換（Rust / C の `x as u8`）は Onsa に無く、`(x & 0xFF).narrow_u8().unwrap()` と回り道になる。
  - E0411 と E0413 は仕様の本文に無かった（計画 §5 の表にだけある）。
  - 再現は `tests/review-phase1/parent/r126.onsa`。
- 決定（2026-10-05）: S-98。
  - (1) 整数の `abs` / `min` / `max` のメソッドを外し、`std.math` の関数に統一する（A-04 と同じ。E0413、修正候補は関数の形）。整数と浮動小数のメソッドは、変換と床除算と検査付きで全て（§3.4）。§3.1 の例を `-xs[i]` に改めた。
  - (2) 数の型の間の変換を §3.3 の表で閉じ、メソッドは `as` で書けない組にだけ置く（書ける組では E0413、修正候補は `as`）。E0411 の修正候補は読みごとに並べる（浮動小数から整数は `trunc_<型>_sat()` と `trunc_<型>()`。整数の縮小は Rust / C の `as` と意味が違うので候補を出さず、note で `narrow_<型>()`）。
    A-09（総称の整数の変換）は、この規則を壊さない形を選ぶ（`api-candidates.md` に書き添えた）。
  - (3) (a)。長さを持つ型は `len()` だけを持ち、`is_empty` は無い（`Str` の `is_empty` も外した。R-96 は `Str` の検索と切り出しを議論し、`is_empty` は議論していなかった）。E0413、修正候補は `len() == 0`。第 2 期の `Array` `Map` `Set` も同じ。
  - (4) 検査付きは「panic しうる整数の演算子とメソッドの全て」の規則で閉じる: `checked_add` `sub` `mul` `div` `rem` `neg`（符号付き） `shl` `shr` `div_euclid` `rem_euclid`。
  - (5) `std.math` に `is_nan` と `is_finite`（`[T: Float](x: T) -> Bool`）を足す。`is_infinite` は置かない。
  - (6) 切り捨ての整数の変換は今は置かない。利用者の見立て: バイト列・ビット列の trait は将来必要になるが、今は要らない。`api-candidates.md` に A-12 として挙げた。
- 判断: S-98: 整数の `abs` / `min` / `max` のメソッドを外して `std.math` の関数に統一。数の変換は §3.3 の表で閉じ、メソッドは `as` で書けない組だけ（E0413 / E0411 の修正候補は読みごと）。長さを持つ型は `len()` だけで `is_empty` は無い（`Str` も）。
  検査付きは panic しうる整数の演算子とメソッドの全て。`std.math` に `is_nan` / `is_finite`。切り捨ての変換とバイト列・ビット列の trait は A-12（将来）。再現は `tests/review-phase1/parent/r126.onsa`
