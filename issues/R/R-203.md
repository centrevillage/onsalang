# R-203 括弧の外の `g(x) (y)` が検査を通り、fmt が `g(x)(y)`（E0020）に書き換える

- 中・直す・観点 1｜syntax（`parser.rs` の `parse_postfix`）、fmt｜§2.5、§6.1、§18.2（fmt はプログラムの意味を変えない）
- 内容: `parse_postfix` は、`(` の前に空白があると `callee_expression` の判定を飛ばして呼び出しとして読む。そのため括弧の外の `let v = g(x) (y)`（`g` は関数値を返す）は診断なしで検査を通る。fmt はこれを `g(x)(y)` と書き、その形は `callee_expression` の E0020 になる。
  検査を通るファイルを、fmt が構文の誤りのあるファイルに変える。並びの中の `[(1, 2) (3, 4)]` も fmt が `[(1, 2)(3, 4)]` にする。
- 経緯: 第 20 組の下書きが見つけ、親が dev（`892cbe5`）で再現した（2026-10-10）。
- 決定（2026-10-10、親）: 直す。W3-06 で S-89 の空白の E0020（と S-399）が入ると、元の形が先に誤りになり、この分かれは無くなる。W3-06 の否定例に、fmt の出力が構文の段を通ることを確かめる事例を一件入れる。
- 判断: 直す（親）。括弧の外の `g(x) (y)` が検査を通り、fmt が `g(x)(y)`（`callee_expression` の E0020）に書き換える。第 20 組の下書きで見つけた
- 反映: 実装は W3-06（S-89 の空白の E0020 と S-399 で解ける。fmt の出力を確かめる事例を一件）
