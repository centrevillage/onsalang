# R-144 `sample` の入力と struct の出力のフィールドが同じ名前だと、生成した C がコンパイルできない

- 中・直す・観点 1｜`crates/onsa_backend_c/src/export.rs`（`process_io`）｜§11.6、§14.2
- 内容: 今の `<p>_process` は `sample` の入力と出力を一つずつの引数に並べ、引数名に Onsa の名前（入力の名前、struct の出力のフィールド名）を使う。入力と出力のフィールドが同じ名前だと、C の引数名が重なる。
  仕様 §11.6 の例 `swap(l: F32 at sample, r: F32 at sample) -> Stereo at sample` そのものが当たる。
  再現: `pub flow swap(l: Sig[F32], r: Sig[F32]) -> Sig[Stereo] { Stereo { l: r, r: l } }` を export してビルドすると `onsa_swap.h: error: redefinition of parameter 'l'`。Core の `process` も入出力を名前で引いている。
- 経緯: W1-11 の実装の担当が、手順の器の自己テストで見つけた（2026-10-07）。
- 決定（2026-10-07、親）: 直す。仕様は明確で、判断は要らない。§11.6 の `In` / `Out` の構造体（W10-03）で入力と出力が別の名前空間になる。そのとき、Core の `process` が入出力を名前でなく位置と役割で引くことも確かめる。
- 判断: 直す（親、仕様が明確）。`sample` の入力と struct の出力のフィールドが同じ名前でも、生成した C がコンパイルできるようにする（§11.6 の `In` / `Out`）。W1-11 で見つけた
- 反映: 実装は W10-03
