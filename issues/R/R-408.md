# R-408 名前の直後に隙間なしで書いた閉じない `[`（`let y = g[1,`）を並べると、検査の時間が二乗に近く増える（4000 個で 0.25 秒、16000 個で 3.38 秒）

- 場所: `parser/expressions.rs::parse_postfix` → `foreign/paths.rs::type_list_ahead` → `scan::bracket_contents`（`bracket_with_comma`）。名前か値の直後に隙間なしで書いた `[` ごとに、読みの途中で走る（誤りの無いファイルでも）。
- 内容: `fn f{i}() -> I32 {` / `  let y = g[1,` を N 個並べたファイルで、`check` が N=4000・8000・16000 で 0.25・0.93・3.38 秒（dev `bfe34c17`、debug）。閉じない `[` からファイルの終わりまで数えるので、N 個の `[` で二乗。`sample` では 1461 標本が `bracket_contents`。
  R-401（`[1,` の次の行頭の語）と R-403（離れた `g [1,`）と同じ走査で、呼び手だけが違う。入力は `target/notes/125/w511u10c/probe/`（`attached4000.onsa`、`attached16000.sample`）、台本は `target/notes/125/w511u10c/tools/measure.py`（`attached` の形）。
- 経緯: 125 回目（2026-11-08）、W5-11 U10c/i（onsa-impl）がコードを書く前の見積もりで見つけ、親が固定のバイナリで閉じない `[` の報告を確かめた。
- 判断: 直す（親）。W5-11 U10c で、パーサの側も括弧の表を引く形（実装の担当の案 (a)）。
- 反映（2026-11-08、親）: W5-11 U10c（`f09a9d77`）: `type_list_ahead` も表を引く（誤りの無いファイルでも、隙間なしの `[` があれば表を一度作る）。`attached` の 16000 個が 3.38 秒から 0.18 秒
