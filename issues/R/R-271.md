# R-271 誤りの型と単一化した型変数が残り、別名や切れた def のメンバの署名の誤りの型から、返り値の `None`・`[]` に E0406、誤りの型の値の呼び出しに E0401「`_` is not a function」が出る

- 場所: 型の推論の単一化（`crates/onsa_sema/src/infer.rs` の `unify`）と呼び出しの検査（`body/calls.rs`）。
- 内容: §18.1 は読めなかった部分を誤りの型とし、それを使う側に診断を出さないとするが、誤りの型と単一化した型変数が決まらずに残り、使う側に診断が出る。
  別名 `type A = Gone`（`Gone` は失敗した `use` の名前）の後の `fn f() -> A { None }` と `fn g() -> A { [] }` に E0406（型が決まらない）、`fn h(o: A) -> I32 { o() }` に E0401「`_` is not a function and cannot be called」が出る（`R-271/alias`）。
  S-260 の切れた def のメンバを署名に書いた `fn f() -> E.Zed { None }` も同じ E0406（`R-271/cut_member`）。U3b1 の前（`c77f3f3`）から同じで、W4-03 U3b1 の直しの後（`842450a`）も同じ。
- 経緯: 第 61 組（族「§18.1 の失敗した名前の後の検査」）の下書き（onsa-gap、2026-10-25、68 回目）が、族の形の表の 9 として見つけた。前からの誤り。S-692 で型の位置の後も本体を検査する形になると当たる所が増えるので、その実装と同じ W4-03 で直す（下書きの見当は約 +10〜15 行）。
- 判断:
- 補い（2026-10-25、親）: 第 61 組の独立のレビュー（onsa-advisor の段 1、68 回目）が同じ根の形を二つ見つけた（前から、親が四つのバイナリで再現）: 別名 `type A = Gone` の受け手 `x: A` の `match x { Some(v) => v, None => 0 }` に E0501（網羅性。`exhaust.rs` が誤りの型にも `_` を求める）、`let s = A { a: 1 }` に E0401「`A` is not a struct」（struct リテラルの経路）。
  直す所は別だが、どれも誤りの型に頼る判定が黙らない形で、同じ W4-03 で直す。再現は `R-271/alias` の `m`・`s`。
- 補い（2026-10-25、親）: W4-03 U3c のテストの票（onsa-test、68 回目）が同じ根の形をもう一つ見つけた（親が再現）: 誤りの型の値へのタプルのパターン `match x { (p, q) => p }` に E0302「cannot find `p`」（パターンの変数が束縛されない）。再現は `R-271/alias` の `t`。U3c で一緒に直す。
