# R-346 診断のテキストの表示が引用する原文の行に、ソースの制御文字（ESC など）を生のまま出す

- 場所: 診断のテキストの表示（`onsa check` などの `--json` でない出力）で、文面の下に引用する原文の行。
- 内容: 文面に埋め込む値は W4-02 U2b2 から escape する（`shown()`）が、引用する原文の行はソースの字をそのまま出す。`onsa.toml` が `name = "a<ESC>[31mb"`（生の 0x1B）なら E1101 の下の行に生の ESC が出て、端末の色や表示を変えうる。`.onsa` の E0001 の行も同じで、診断の描画に共通の前からの形（U2b2 の前の `P98/bin/onsa-632f980` と後の `onsa-w402u2b2` で同じ）。
  `--json` は JSON の文字列の escape で崩れない。生の制御文字を書くのは壊れたか悪意のあるファイルで、実害は端末の表示だけ。
- 経緯: 98 回目（2026-11-01）、W4-02 U2b2 の壊す側（低 3、`P98/w402u2b2/b/hand2.py` の `e1101_raw`）。親が両方のバイナリで再現した。
- 判断: 直す時期と形（引用の行の制御文字を見える形にするか、列の数え方を保つか）は段の終わりの見直しで決める（R-345 と同じ描画の所）。§18.1 は引用の行の字の扱いを決めていない。
- 補い（2026-11-01、親）: 直す時期と形を決める「段の終わりの見直し」は W4 の見直しの W4-18（99 回目の文書の点検の 3-G）。
- 判断（2026-11-01、親）: 100 回目（2026-11-01、W4-18 の前の洗い出しの B5、利用者が了承）: テキストの引用行は、範囲の周りの一定の幅（約 120 字）だけを出して切った端に `...` を付け、`^` の位置も切り出しに合わせる。制御文字は見える一字の絵（ESC → `␛`、Unicode の制御文字の絵）に置き換え、一字を一字にして `^` の位置を保つ。候補の行の文字列にも同じ置き換えを当てる。仕様（`spec/tools.md` §4）は引用行の形を約束しないので仕様は変えない。参考: rustc 1.94.1 が同じ形（長い行の `...` と `␛`）。W4-18 で直す。
