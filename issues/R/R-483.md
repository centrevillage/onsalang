# R-483 ビューの基に置いた一時（`take(idb(move a).slice(0, 1))`）を、modes の一時の待ち（`drops.rs::temps`）が部分ビューを外さずに数え、一時の破棄を `slice` の呼び出しの終わりに置く（`take` はその後に読む）

- 場所: `crates/onsa_sema/src/modes/drops.rs::temps`（末尾と経路の根をたどって一時の破棄を待たせるが、部分ビューの基 `view_base` を外さない）。
- 内容: `take(idb(move a).slice(0, 1))` の一時 `idb(move a)`（Affine）は、`slice` の呼び出しの終わりで破棄され、`take` はその後にビューを読む（`calls.rs::call` の `ran`）。E0601 は一時の破棄の位置を出さないので、位置はコードの読みによる（推測を含む）。Core はまだ破棄を降ろさないので今は表に出ず、W8-04 で解放後の使用になる。
  再現は `target/notes/161/w712/u2c/audit/advisor/`（`in/p5.txt` の `rt_temp_view_direct`）。
  同じ根の形（161 回目、W7-12 U2c の設計メモの改め `target/notes/161/w712/u2c/memo2/memo.md` の 2.6・7 章）: 添字の基の一時（`len_of(mk()[0])`）も添字の終わりで破棄され、呼び出しはその後に読む。平面のリテラルの要素と生成型のリテラルのフィールドに置いた一時（`planes([idb(move a), y])`、`useit(pair.In { l: idb(move a), r: y })`）は破棄点が無く（`Alloc` の無い関数と `rt fn` で E0601 が出ない）、W8-04 で漏れになる（`memo2/m2.txt`・`m4.txt`）。
- 経緯: 161 回目（2026-11-17）、W7-12 U2c の想定漏れの監査（onsa-advisor、段 1）が見つけた（「値がその位置で指す場所」の族の四つ目の歩き）。
- 判断: 直す（中）。W7-12 U2c1 の共通の構造で、作った値（一時）の葉を `temps` が読み、部分ビューの呼び出しと添字は外の位置が待つときに基の一時を自分で待たせない（メモの改めの 2.6）。直すと平面・生成型のリテラルの要素の一時に E0601 が出る（正しい側、直に書いた `take(idb(move a))` と同じ）。
