# R-39 E0310（循環 import）を経路の書き方で回避できる

- 中・直す + 要判断・観点 1 / 2｜`crates/onsa_sema/src/resolve.rs:289`、`:164`｜§15.1
- 再現:
  - `a.onsa` に `b.g()`、`b.onsa` に `a.f()` と書く。`use` を書かない相互参照は、エラーにならない。
  - `use pkg.b.{g}` と `use pkg.a.{f}` のように、自分のパッケージ名で相互に取り込むと、エラーにならない。
  - 自分のパッケージ名を前置した `pub use pkg.b.{g}` の再公開の連鎖が、解決順の誤りで E0302 になる。
- 直し方: 依存の辺を、`resolve_path` と同じ規則で作る。
- 判断（R-39）: 本体の中の経路（`b.g()`）を依存に数えるか。
  - (a) 数える。依存はモジュールの間の参照全てとする。
  - (b) モジュールを参照するには `use` を必須にする。
  - 推奨は (a)。書き手の負担が増えず、E0310 の意味もはっきりする。
- 決定（2026-10-03）: (B) `use` を必須にする。実装の暗黙の参照（ルート直下のモジュールとパッケージ名を `use` 無しで引ける。Rust 2018 の extern prelude に近い）は仕様に無い規則だったので外す。依存は `use` だけで決まり、E0310 の検査は `use` の一覧で閉じる。宣言していないパッケージを名前で引ける問題（R-88）も同じ規則で無くなる。
- 判断: (B) `use` を必須にする。実装の暗黙の参照（ルート直下のモジュールとパッケージ名を `use` 無しで引ける。Rust 2018 の extern prelude に近い）は仕様に無い規則だったので外す。依存は `use` だけで決まり、E0310 の検査は `use` の一覧で閉じる。宣言していないパッケージを名前で引ける問題（R-88）も同じ規則で無くなる
