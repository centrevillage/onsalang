# R-462 E0903 を互いに辿り合う関数の集まりごとでなく閉路ごとに出し、一つの集まりに閉路が二つあると宣言の順で数が変わる

- 場所: `crates/onsa_sema/src/rt.rs` の `check_all` の中の手書きの DFS（閉路ごとに節の集合を `reported` に控えて一つ出し、並びは `(s.file, s.start)`）。E0310・E0311・E0312・E0817 と Core の E0903（`crates/onsa_core/src/rt_cycles.rs`）は `names/cycles.rs::cyclic`（強連結成分）と `file_key`（S-313 の並び）を読む。
- 内容: §18.1 と S-778 は、呼び先が名前で決まる `rt` の関数の再帰の E0903 を「互いに辿り合う宣言の集まりごとに一つ」とする。一つの集まりに閉路が二つある形（`a` が `b` と `c` を呼び、`b`・`c` が `a` を呼ぶ）は、`c`・`b`・`a` の順に書くと E0903 が二つ（1:17 と 2:17）、`a` を先に書くと一つ（2:3）になる。どちらの形も誤りのあるプログラムなので、通るプログラムは変わらない（余分な診断と、宣言の順で数が変わること）。
  性能: `reported.contains(&cycle)` が閉路の数の二乗（自分を呼ぶ `rt fn` を 16000 個並べた形で `rt` の段が約 1.2 秒）。
  再現: `issues/R/R-462/cases.txt`（`compare.py probe`。`two_cycles_share` と `figure8_mid` が二つ、`two_cycles_share_a_first` が一つ）。
  直し方の見当: 辺から隣接表を作って `names::cyclic` を呼び、成分ごとに集まりの関数を呼ぶ呼び出しのうち最初のものに出す。循環の道は Core の `rt_cycles.rs::way_back` を共有する。
