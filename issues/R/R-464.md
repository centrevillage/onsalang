# R-464 署名の段が宣言の順にフィールドを誤りの型に変え、要約の覚えも古いまま読むので、連鎖の E0416 が宣言の順で出たり出なかったりする

- 場所: `crates/onsa_sema/src/sig/wellformed.rs`（宣言の順に回り、誤りのあるフィールドをその場で誤りの型に変える）と、`walk::Known::summaries`（宣言ごとの要約を最初に問われたときに覚え、フィールドを変えても消さない）。`sig.rs` の `wellformed` の前後の注釈は「読んだのは変える前のフィールド」と書く。
- 内容: §18.1 は読めなかった部分（フィールドなど）を誤りの型として扱い、それを使う側には診断を出さないとする。`S3[T1: ?Dup] { a: I32, w: Array[T1] }` のフィールドの E0416 の後、`H { h: OC[S3[F32]] }`（`OC[T: Copy]`）は、`S3` を先に書くと診断なし、`H` を先に書くと `H` にも E0416 が出る。`S3` の前に `S3[F32]` を問う関数があると、`S3` の後に書いた `H` にも E0416 が出る（古い要約を読む）。同じプログラムで、宣言の順で連鎖の E0416 の有無が変わる。誤りのあるプログラムだけで、通るプログラムは変わらない。
  再現: `issues/R/R-464/cases.txt`（`compare.py probe`。`s3_first` は `S3` の E0416 だけ、`h_first`・`g_first_then_s3_then_h` は連鎖の E0416 が付く）。W5-23 U1 の壊す側（121 回目、`target/notes/121/w523/u1b` の `m4`・`m5`・`m19`）が見つけ、W6-04 の持ち越しにあった「宣言の順で変わる診断」の仕組み。
  直し方の見当: 型の宣言を依存の順で先に検査し、フィールドを誤りの型に変えたらその宣言の要約を消す。R-449（要約を型ごとに覚える）は同じ所を触るので、この直しを先にする。
