# R-32 破棄の解析が経路を見ず、一時値・上書き・総称の `T` を見落とす

- 高・直す・観点 1｜`crates/onsa_sema/src/rt.rs:212-258`、`:302`、`effects.rs:86-118`、`modes.rs:58`｜§10 規則 1、§12.2、§6.3（`T: Copy` で無い限り破棄は `Alloc` を要する）
- 再現: 次のどれも通る。
  - `rt fn drop_t[T](move x: T) {}`
  - `rt fn g(move b: Buf[F32]) -> U32 { pass(move b).len() }`（一時値の破棄）
  - `var x = move a; x = move c`（上書きによる破棄）
  - `rt fn pick(move a: Buf[F32], move b: Buf[F32], c: Bool) -> Buf[F32] { if c { a } else { b } }`（片方の分岐で破棄）
- 原因:
  - `MovedLocals` が「どこかで移動されたか」を表す集合にすぎない。
  - `needs_alloc_drop` が `Ty::Param` を偽にする。
- 影響: 第 1 期の `Buf` はインタプリタでしか使えないので、実害は小さい。ただし、言語の保証には穴がある。
- 直し方: modes で、経路を見た破棄点（スコープの出口、一時値、代入による上書き）を列挙し、rt と effects はそれを共有する。
- 決定（2026-10-03）: 直す（経路を見た破棄点を modes で列挙し、rt と effects が共有する。`Copy` の無い `T` の破棄は `Alloc` を要する）。
- 判断: 直す（経路を見た破棄点を modes で列挙し、rt と effects が共有する。`Copy` の無い `T` の破棄は `Alloc` を要する）
- 反映: 実装（W6-02。R-83 と同じ回）
- 判断（2026-10-31、親）: W4-09 U2 の壊す側（91 回目）: 片方の道で移した値を、もう片方の道で全体として破棄する `Alloc` を数えない形は、S-85 の取り出し（`if c { Some(move h.buf) } else { None }`）にも届く。`var` に入れ直す形（`let x = move h.buf` の後の `h = move h1`）も同じ。
  事例 `tests/spec/negative/drop_on_the_other_path.onsa` を `until = "W6-02"` で置いた
- 補い（2026-11-06、親）: W5-22 U1 の壊す側（118 回目）: `move` の分解で `_` と最後の `_` が残すフィールドの破棄も見落とす。`pub struct H { buf: Buf[I32], n: I32 }` の `fn b(move h: H) -> I32 { let H { n: q, buf: _ } = move h \n q }` と `let H { n: q, _ } = move h` は E0601 にならず（`rt fn` でも誤りにならない）、Core にも破棄が出ない。
  §5.2 の「取り出したフィールド以外はその場で破棄され」「意味は分解の `let Holder { buf: b, gain: _ } = move s` と同じ」から、`fn a(move h: H) -> I32 { 0 }` と同じく E0601 のはずである。`_` は `buf: _` と同じ結果で、U1 の前から同じである。W6-02 の破棄点の列挙にこの形を入れる。
  Core の破棄は W8-04（S-85 の持ち越し）である。
