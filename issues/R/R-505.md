# R-505 C の生成で、リテラルの二重の否定（`-(-3.0)`・`-(-4)`）が `--3.0f` になり、C として通らない

- 場所: C の後端の式の出力（`crates/onsa_backend_c/src/emit/`）。単項の否定の被演算子が負のリテラルのとき、間を空けずに `-` を重ねる。
- 内容: 横の `R-505/`（`onsa.toml` と `src/main.onsa`、`x * (-(-3.0)) + …`）を `onsa build --target host` で C にすると `(float)(--3.0f)` が出て、clang が "expression is not assignable" で落ちる（`--` が減算の演算子として読まれる）。`check` と `build` は通る。`-(-n)`・`-(-x)` は `-(float)(-x)` で通り、リテラルの二重の否定だけが落ちる。W7-05 U3 の前のバイナリ（`72410fd`）でも同じで、W7-05 の後退ではない。
  直すときは、否定を重ねる所に空白か括弧を置き、単項の否定を入れ子にした式（リテラル・変数・括弧）を `onsa build` と `clang -fsyntax-only` に通す少数の事例（`[[test.host]]` か `tests/golden/c/`）を gate に入れる（`rules/leader.md` 4.9）。
- 経緯: 169 回目、2026-11-19、W7-05 U3 の壊す側（onsa-break）が、生成した `par~` の flow を C に落とす掃引で見つけ、親が今の dev のバイナリで再現して登録した（報告 `target/notes/169/w705/u3/b_report.md` の中-1）。
