# R-530 読む `Span` の位置（単一と平面の引数）に置いた `const` の配列が、呼び出しのたびに局所の一時へ丸ごと写る（`take(BIG)` の `__arr`、`two_pl(BIG2)` の `__planar`）

- 場所: `crates/onsa_core/src/lower/body/call.rs` の `coerce`（`span_of` の一時 `__arr` と、平面の枝の `materialize` の一時 `__planar`）。場所でない値を一時に束縛し、`const` も場所でない値に数える。
- 内容: `const BIG: [F32; 4096]` を `take(s: Span[F32])` に渡すと、生成した C は `onsa_arr_f32_4096 onsa__arr = src__main__BIG;` で定数（C では `static const`）の全体を呼び出しのたびにスタックへ写してから `Span` を作る。平面の `two_pl(BIG2)`（`[[F32; 4096]; 2]`、32 KB）も W8-15 で E0200 が外れて同じ形になった（`onsa__planar = src__main__BIG2`）。値は正しい。波形表のような大きな定数を読むだけの呼び出しで、スタックの小さい組込みの対象では溢れうる（利用者の条件: 組込みがあるのでメモリを落とさない）。再現 `R-530/const_view_copy.onsa`（`onsa build --target host` の C を読む）。
  読むだけのモード（`inout` でない）の `Span` は定数の記憶域を直に指せる見込みだが、C の `Span` の型が `const` でない指し先を持つので、指し先の `const` の扱い（キャストか、読む `Span` の型）を決める必要がある。
- 経緯: 192 回目（2026-11-27）、W8-15 の壊す側（onsa-break）が低として挙げた。単一の `Span` の `__arr` は前からの形で、W8-15 の後退ではない。写しを減らすのは移動・コピーを扱う W8-04 の見込み（親）。
