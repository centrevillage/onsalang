# R-88 パッケージのモデルが、std 以外の依存に耐えない

- 中・直す・観点 2｜`crates/onsa_driver/src/lib.rs:56`、`:67`、`crates/onsa_sema/src/resolve.rs:176`、`sig.rs:1596`
- 内容:
  - 依存を所有するツリーで持ち、重複を除かずに平らにしている。菱形の依存では std を 2 回解析し、別の DefId になる。
  - パッケージ名を大域で検索するので、宣言していないパッケージも名前で引ける。
  - std の判定に、`is_std` と名前 `"std"` の比較が混在している。
- 直し方: パッケージ ID と依存の表を持ち、見える名前を宣言した依存に限る。
- 範囲（2026-10-05 に追加で確かめた）: driver は `[dependencies]` を読むだけで、依存として常に埋め込みの std だけを読み込む（`deps: vec![std]`）。そのため菱形の依存と大域の名前の検索は、今はまだ表に出ていない。
  std の特権（`target` 宣言、未実装の効果の名前）は印 `is_std` で、`sig.rs:1596` は名前 `"std"` との比較で見分けている。`std = "x.y.z"` の版は確かめていない（再現は `tests/review-phase1/parent/r88/`）。
  仕様は、std が埋め込みなのに `std = "0.2.0"` が何を意味するか、std 以外の依存の取得元、版の解決、`onsa.lock` の形を決めていない。
- 決定（2026-10-05）:
  - (1) パッケージのモデルを、今の構造の変更（第 4 段）で直す（計画 §3.3）。パッケージ ID と、パッケージごとの見える依存の表を持ち、同じパッケージは一度だけ解析する。見える名前は宣言した依存と暗黙の `std` だけ。std は役割で見分け、std の特権は全てそれを読む。依存の図は driver が一度だけ作る（D-15）。構造の変更は早いうちに行う方針（R-86）に沿う。
  - (2) `std` はどのパッケージにも暗黙の依存（S-83）。`std = "x.y.z"` は版の固定で、埋め込みの std の版と一致しなければマニフェストの誤り。
  - (3) std 以外の依存の取得元、版の解決、`onsa.lock` の形は第 2 期に決める（§19.1、計画 §5 の持ち越し）。R-122（パッケージの `tests/`）もそこで一緒に決める。
- 判断: 直す。(1) パッケージ ID と依存の表、同じパッケージは一度だけ解析、見える名前は宣言した依存と暗黙の `std`、std は役割で見分ける（第 4 段）。(2) `std` は暗黙の依存で、`std = "x.y.z"` は埋め込みの版と比べる（S-83）。(3) std 以外の依存の取得元・版の解決・`onsa.lock` は第 2 期（§19.1、計画 §5。R-122 も一緒に）。再現は `tests/review-phase1/parent/r88/`
- 反映: 仕様 §15.1 / §15.3 / §19.1 に反映済み、計画 §3.3 / §5 に追記（2026-10-05）。実装は W4-01
