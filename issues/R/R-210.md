# R-210 複合代入の候補の編集が、演算子と右辺の間のコメントを含んで消す

- 低・直す・観点 1｜syntax（`foreign/assign.rs` の `compound_assignment` の候補）｜§18.1（編集は変えるトークンだけを置き換える最小の編集で、間のトークンとコメントを範囲に含めない、S-251）
- 内容: `x += // c` 改行 `1` の E0020 の候補「write the assignment out」は、`=` の終わりから右辺の最初のトークンまで（` // c` と改行）を ` x + ` に置き換え、書き手のコメントを消す。親が dev の `8f08fe8` のリリースのビルドと RF の単位 2 で確かめた（どちらも同じ）。RF の単位 2 で同じ種類の `&` と `mut` の間のコメント（`reference`）は直した。
- 経緯: RF/i（`foreign.rs` の深いリファクタリングの単位 2）が範囲の外で気付き、親が再現した（2026-10-11）。
- 決定（2026-10-11、親）: 直す。編集をトークンごとに分け、間のコメントを残す。時期は `foreign.rs` の深いリファクタリングで後に回した項目（`docs/carryovers.md` の「W3 の終わり」の行の (5)）と同じ回。
- 判断: 直す（親）。複合代入の候補の編集が、演算子と右辺の間のコメントを含んで消す（`x += // c` 改行 `1`、S-251）。RF/i が気付いた。前からある
- 反映: 実装は W3 の終わりの RF-5〜RF-8 と同じ回
- 判断（2026-10-19、利用者）: X-6 の手順 1（44 回目）: `=` と右辺の間に改行かコメントがあるときだけ、`=` の直後に差し込んで間のものを残す。空白だけなら今の置き換えのまま（常に差し込むと `x +=1` が `x = x +1` になり、非対称な空白の新しい誤りを作る）。S-251 の「間のトークン」に改行を含め、隣の空白は変える部分と読む。X-6 の出力を変える組で直す
- 反映（2026-10-20、親）: X-6 V（`81f9f6b`）で直した。`=` と右辺の間に改行かコメントがあるときだけ差し込み、間のものを残す。ブロックコメントを残すと、当てた後にそのコメントの E0020 が表に出る（S-251 と §2 のブロックコメントの規則の組み合わせで、設計どおり）。
- 判断（2026-10-23、親）: S-553 から。消すトークンに挟まれたコメントは消してよいと決めたが、残すトークンとの間のコメントは範囲に含めない規則のままなので、X-6 V で直した形は正しい。
