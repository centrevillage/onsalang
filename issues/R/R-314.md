# R-314 §18.1 は「候補を作れないとき、後の段で見つける形は E0020 のまま候補を出さない」とするが、登録簿（`codes.rs` の `FixRule::Required`）と候補の約束の検査（`onsa_diag::contract`）は E0020 に常に候補を求め、`without_fixes` は E0002 に落とす

- 場所: `spec/18-diagnostics.md` の 120 行と、`crates/onsa_diag/src/codes.rs` の `FixRule`（99〜116 行）・`crates/onsa_diag/src/lib.rs::contract`（390 行）。
- 内容: §18.1 は、他の言語と旧版の書き方を見つけて候補を作れないとき、構文の段の形は E0002、後の段の形は「E0020 のまま候補を出さない」とする。登録簿は E0020 を `Required`（常に候補がある）とし、候補の約束の検査は候補の無い E0020 を誤りとして数え、`without_fixes` は E0002 に落とす。
  今は後の段で候補の無い E0020 を出す所が無く（`without_fixes` を呼ぶのは構文の段の `foreign.rs`・`operands.rs` だけ）、出力に現れない。後の段で候補を作れない E0020 を初めて出す作業で、仕様の文と登録簿が食い違う。
- 経緯: 79 回目（2026-10-28）、第 71 組の独立のレビュー（onsa-advisor）が組の外の気付きとして挙げ、親が文とコードを確かめた。前からある。
- 判断（2026-10-28、親）: 直す。後の段で候補の無い E0020 を出す最初の作業で、仕様の文と登録簿のどちらに揃えるかを決める（今は実害が無いので、直す作業は決めない）。
