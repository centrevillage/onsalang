# R-400 次の項目の始まりで見つけて単位の最後へ移した誤りの文面が、次の単位のトークンを名指す（「found `fn`」、次の行の他の言語の属性の文が二つ並ぶ）

- 場所: `crates/onsa_syntax/src/parser/file.rs` の `skip_unit`（S-276 で次の項目の始まりで見つけた誤りを単位の最後の空の範囲へ移す所。`found` は消すが文面は変えない）。
- 内容: 次の項目の始まりのトークンで見つけた誤りは、§18.1 のとおり単位の最後の位置に出るが、文面は見つけたトークンを名指したまま残る。`const K: I32 = 1 +` / `fn z()` は「expected an expression (a function is declared at the top level), found `fn`」が 1 行目の末尾に出る（`type Op =` / `fn z()` の型の読みも同じ）。
  `pub type Op =` / `  #[x]` / `  fn(I32) -> I32` は、他の言語の属性の文「attributes are written `@name(...)`, …」が 1 行目の末尾（型の読みが `#` で止まった誤り）と 2 行目の `#[x]` の単位の二つに並ぶ。文面は約束でないが、切れた行の誤りを次の行の形の誤りと読ませる。
  入力は `target/notes/124/w511u9/probe/` の `b01_const_fn`・`b02_type_fn`・`v19_hash_cont`。W5-11 U9 の前から `b01` の形はあり、U9 で型の読みと `v19` の形が増えた。
- 経緯: 124 回目（2026-11-08）、第 93 組の段 1 の助言の担当が `b01` の形と `v19` の見込みを挙げ、W5-11 U9/i（onsa-impl）が実装で `v19` の二つの文面を確かめた。親が U9 の後のバイナリで再現した。
- 判断: 直す（親）。W5-11 の U10。移した誤りは「〜の後に…が要る」の形の文面（S-276 の決定の言い方）にする見込み。
