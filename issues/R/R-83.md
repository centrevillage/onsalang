# R-83 効果の集計が `Alloc` 専用で、rt と effects に重複している

- 高・直す・観点 2｜`crates/onsa_sema/src/rt.rs:150-258`、`effects.rs:44-119`、`ty.rs:203`、`builtin.rs:9-15`｜§8.1、§10、§12.2
- 重複: 呼び出し、補間、ローカルの破棄、式文の破棄を集める処理が、2 つのファイルにほぼ逐語で重複している。
- 表現の不足:
  - `EffectSet` は `alloc: bool` に `other: Vec<String>` を足した形で、関数型の単一化は効果の完全一致を要求する。
  - `MethodSig` には `rt`、効果、引数のモードが無いので、将来の `push!(move x)` などを表せない。
- 影響: 第 2 期の効果行の整合、handler、Str、Map / Set の前提を妨げる。
- 直し方:
  - 本体とクロージャごとに「使う効果の集合と、その位置」を一度だけ計算する集計器にまとめる。E0601、E0901、E0902〜E0905 は、その上の判定にする。
  - 破棄の点は modes が経路を見て列挙したもの（R-32）を使う。
  - `MethodSig` に `rt`、効果、モードを持たせる。
- 範囲（2026-10-05 に追加で確かめた）:
  - `rt.rs`（E0901）と `effects.rs`（E0601）が、同じ 6 種類の使用（呼び出し、関数値の呼び出し、名前で判定する `Buf.zeroed`、補間、所有するローカルの破棄、式文の破棄）を別々に集めている。
  - 仕様 §10 の規則 1 は「`rt` の関数の効果行は `Alloc` を含まない（E0902）。したがって生成も破棄もできない」で、本体での確保は効果行の規則の帰結だが、実装は `rt` の関数の中の確保・補間・破棄を E0901（`rt` でない関数を呼んだ）で報告する。
  - E0601 は S-23 で決めたが、仕様に書かれていない。仕様 §6.3 は、破棄に `Alloc` が要る場合を E0611 としているが、E0611 は実装に無い。
  - 報告は S-59 どおり、1 つの関数につき最初の 1 件。再現は `tests/review-phase1/parent/r83.onsa`。
  - `MethodSig` の不足は S-69（組込みのメソッドを std に宣言する）で、関数型の互換の完全一致は R-27 (2) で片付く。
- 決定（2026-10-05）:
  - (1) 効果行に無い効果の使用は、`rt` かどうかによらず E0601 にそろえる（S-77）。暗黙の確保（補間など）と破棄を含み、E0611 は E0601 にまとめる。`rt` の関数では修正候補を出さず、最初の使用の位置に置いて、§10 の規則 1 を note で示す。E0901 は `rt` でない関数と関数値の呼び出しだけ。効果の判定を全ての関数で同じにし、`rt` は効果行の制限と呼び出しの規則を足すだけの層の構造にする。
  - (2) 集計は一つの段にする（D-15）。型付けと modes の後に、本体ごとの「使用の記録」を作り、E0601、E0901、E0903 などはそれを読む判定にする。無名関数、`test`、定数の初期化式の扱いは仕様どおり。効果行は「効果の宣言の ID の集合 + 効果行の変数」で表し、`Alloc` は lang item にする（計画 §3.3）。
  - (3) 報告は S-59 どおり 1 つの関数につき最初の 1 件。`rt` でない関数の E0601 は署名に置き、効果行への追加を修正候補にし、同じ効果の他の使用を note に並べる。
- 判断: 直す。(1) 効果行に無い効果の使用は `rt` かどうかによらず E0601（暗黙の確保と破棄を含む。E0611 は E0601 にまとめる。`rt` の関数では修正候補を出さない）。E0901 は `rt` でない関数と関数値の呼び出しだけ（S-77）。(2) 集計は型付けと modes の後の一つの段（使用の記録）で、判定はそれを読む（D-15）。効果行は効果の宣言の ID の集合。
  (3) 報告は S-59 どおり最初の 1 件で、E0601 は署名に置いて同じ効果の他の使用を note に並べる。再現は `tests/review-phase1/parent/r83.onsa`
- 反映: 仕様 §6.3 / §8.1 / §10 に反映済み、計画 §3.3 に追記（2026-10-05）。実装は W6-03（R-32 の W6-02 の後）
