# R-30 種の分からない型を「Affine でない」とみなし、Affine の値を複製できる

- 高・直す・観点 1 / 2｜`crates/onsa_sema/src/kind.rs:58`、`layout.rs:65`（`subst`）、`modes.rs:615`、`rt.rs:286`、`body.rs:795`、`:831`｜§4.5、§4.6、§5.2｜再現（親）
- 原因: `kind_of` が `None` のとき、modes は「Affine でない」、境界の検査は「検査しない」として扱う。`None` になるのは、次の 2 つの場合である。
  - **`?Dup` の型パラメータ**: `fn dup2[T: ?Dup](move x: T) -> (T, T) { (move x, move x) }` に `Buf` を渡すと、`onsa test` まで通る。`fn dup3[T: ?Dup](x: T) -> T { x }` も通る。
  - **総称の型の実体化**: `layout::subst` は、置換後の型が intern 済みでなければ、置換前の型を返す近似になっている。
    - `struct Holder[T: ?Dup] { items: (T, U32) }` で、`Holder[Buf[F32]]` を 2 回 `move` できる。
    - 結果は、プログラムの別の場所で `(Buf[F32], U32)` が使われたかどうかで変わる。
- 直し方:
  - `subst` を、intern する版の一つにまとめる。
  - 種が分からないときは、保守的に Affine として扱う。`?Dup` のパラメータは Affine とする。
- 決定（2026-10-03）: 直す（`subst` を intern する版に一本化し、種が分からないときは Affine として扱う。`?Dup` のパラメータは Affine）。
- 判断: 直す（`subst` を intern する版に一本化し、種が分からないときは Affine として扱う。`?Dup` のパラメータは Affine）
- 反映: 実装（W4-05、W4-16）
- 判断（2026-10-23、親、X-8）: `subst` の一本化は W4-05（型の表現と intern の形を変える作業）、種の分からない型を Affine にするのは W4-16（X-8 の第二弾で W4-07 から分けた）。
- 補い（2026-10-28、親）: 前半（`subst` の一本化と、種・配置・破棄を型引数の環境で読む形）は W4-05 U1（`2296e83`）で済んだ。`Holder[Buf[F32]]` の二度目の `move` は E0704（`tests/spec/types/affine_generic_holder_used_after.onsa`）。後半（分からない種を Affine にする）は W4-16。
- 判断（2026-10-29、親）: 84 回目、W4-16 の設計メモから（利用者が了承、A6）: 分からない種を Affine にするのは modes の問い（複製してよいか。消費の種と捕捉の E0712）だけにする（W4-16 の U3）。破棄に `Alloc` が要るかの答えなし（`rt.rs::needs_alloc_drop`）は W6-02 の総称の `T` の破棄と一緒に直す（W6-02 の `持ち越し`）。
- 反映（2026-10-30、親）: W4-16 U3（`0fec18fd`、85 回目）: `kind::kind_in_body` を modes の消費の種と捕捉の E0712 が使う。型パラメータは境界で決め（宣言の奥も同じ）、種の答えが歩数の上限で出ないときだけ Affine にする（誤りの型・失敗した宣言・輪は §18.1 で黙る）。
  破棄の要否の答えなし（`rt.rs::needs_alloc_drop`）は W6-02 の `持ち越し`（A6）。歩数の上限に当たる正しいプログラムの E0711 は S-782。
