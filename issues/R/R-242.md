# R-242 定数の率の let を使う相を、読まれた最大の率の相だけで決め、check を通る flow の降下が内部エラーになる

- 場所: `crates/onsa_core/src/lower/flow.rs` の `lower_flow`（定数の `let` の相 `Phase::of` を `read_at` の最大の率から組む所）、`crates/onsa_sema/src/flow/reads.rs`（`read_at` は読まれた率の最大だけを持つ）
- 内容: 定数の率の `let` を使う相を、読まれた最大の率の相だけで決めるので、二つ以上の相で読まれる定数の `let`、定数の `let` から作る `let` の連鎖で、使う相に定義が無い Core を作る。`onsa check` は通り（終了 0）、`onsa dump --core` と `onsa interface` が内部エラー（終了 101、`the Core verifier rejected the output of lowering: … local … read before definition`）になる。
  - 再現（横のディレクトリ `R-242/`）: `c2.onsa`（`c1` が block と sample の両方で読まれ、最大の sample の相にだけ定義される。`c2.f.ctl` で `c1` が未定義）、`cc.onsa`（`const K` を読む `let a = K; let b = a; x * b`。`b` を tick で組むのに `a` は init の相にだけ定義される）。
  - 直すには、`read_at` を読まれた相の集合を持つ形にするか、計画の表（R-91 (1)）が相ごとの定義を持つ形にする。
- 経緯: X-6 の M2a（RF-8 (B)）の壊す側（2026-10-19、44 回目）が見つけた。基のバイナリ（`0c22312`、RF-8 (B) の前）でも同じで、差分では入っていない。R-03（`par` の中の振り返り）とは別の原因。
- 判断（2026-10-19、親）: 直す。flow の計画の表を作る W7-03 で、状態と相の定義を一度だけ決める形にして直す（R-91 (1)）。再現の入力は W7-03 で期待値付きの事例に移す。
