# R-427 関数の並びとメソッドの並びで、種類の次に数を見る順と宣言の型パラメータの並べ方が二か所にあり、要素の形の分類 `const_form` が名前の種類の判定を一部なぞる

- 場所: `crates/onsa_sema/src/` の、関数自身の並びを下ろす `sig/types.rs::own_args` とメソッド自身の並びを判定する `body/named.rs::Checker::method_args`、要素の形の分類 `names/body/type_args.rs::const_form`。
- 内容: 「数の内の要素の種類が先、次に数」の順が、関数の側（名前の段）とメソッドの側（型の段）に別々に書いてあり、宣言の型パラメータを `` `T`, `U` `` の形に並べる所も二か所にある（文面そのものは `count_error`・`arg_kind_error` の一つずつ）。順を変える決定が入ると二か所を直す。`const_form`（メソッドの並びの要素が型か定数式かを、宣言を知らずに形で決める）は、`path_end`・`is_value`・見出しの名前の判定を一部なぞり、`T.N` と組込みの名前を定数式とする判断を持つ。関連の型がこの版に無いから成り立つ分類である。
  出力の違いは見つかっていない（壊す側の、メソッドと関数の差分の掃引 約 1200 件で、違いは S-981 の E0302 が先に出る形だけ）。保守の費用の指摘である。
- 経緯: 135 回目（2026-11-10）、W5-10 U2b の壊す側（onsa-break）がコードを読んで報告した。関係: R-426。
- 判断: 低。関数の並びは名前の段が宣言を知り、メソッドの並びは型の段でしか分からないので、二つの段に分かれること自体は S-977・S-981 の帰結である。順を一つの関数にまとめられるかは、段の終わりの作業（W5-13）で、R-426 の残り（`Graph::chain` と `constarg::path_of`）と一緒に見る。関連の型を入れる作業は、`const_form` を見直す。
- 反映（2026-11-12、親）: W5-13 U6a で、自身の型引数の種類の並びを `own_kinds`、数の誤りと `` `T`, `U` `` の並びを `own_count_error` に一つにした。「種類 → 数」の順は名前の段（関数）と型の段（メソッド）の二つの呼び手に残し、`own_kinds` の注釈に書いた。`const_form` には関連の型が無いから成り立つという前提を注釈に書いた。
