# R-297 属性の行の次の行が二項演算子で始まる形（`@p()` の次の `/(`）に、E0020 の「前の行の終わりへ移す」候補を出し、当てると前の行が属性と演算子になって E0002 が残る

- 場所: 構文の段の行頭の二項演算子の E0020 と、その候補（演算子を前の行の末尾へ移す、§2.5）。前の行が式で終わるかを見ない。
- 内容: `@p()` の次の行の `/(`、`@inline` の次の行の `/ f(1)` は E0020「a line does not start with an operator that goes on with the line before」で、候補は前の行の末尾に ` /` を挿す。当てると前の行が属性と演算子になり、E0002「expected a declaration, found `/`」が残る。
  §18.1 は、当てた後に同じ段以前の診断を残す候補を出さないとする。前の行が属性（や見出し）なら、演算子が続く式が無い。通るプログラムは変わらない。
  再現は横のディレクトリの `after_attribute.onsa`（dev `42e2f5c` も同じ）と、ファズの入力 `tests/fuzz/6c441628.onsa`（種 `tests/spec/fixes/e0004_doc_after_attribute.onsa` の変異。基の `e741747` でも出る）。ファズが作った形で、書き手が書く形とは考えにくい。
- 経緯: 77 回目（2026-10-27）、`2575c47` の網羅の検査のファズが見つけた（`fix|E0020|move it to the end of the line before|E0002`）。W4-04 U5 で事例を足してコーパスが変わり、前からの形が表に出た。
- 判断: 直す（低）。字句・構文の残りを扱う W5-11 で、前の行が式で終わるときだけ候補を出す（R-296 と同じ類の、並びと行の区切りの候補の条件）。それまで入力は `tests/pending.toml` の `fuzz-input` に載せる。
