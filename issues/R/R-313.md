# R-313 種・配置・破棄の要否を辿る処理（`kind_in`・`layout_in`・`needs_alloc_drop`）が宣言をそのつど辿り、一段ごとに同じ struct を二つ持つ鎖（`struct A_k { x: A_{k-1}, y: A_{k-1} }`）で時間が段の数の指数になる

- 場所: `crates/onsa_sema/src/kind.rs`（`kind_in`）、`layout.rs`（`layout_in`）、`rt.rs`（`needs_alloc_drop`）。宣言の種と配置をメモせず、使うたびに宣言を辿る。
- 内容: 一段ごとに前の struct を二つのフィールドに持つ鎖（`struct A_k { x: A_{k-1}, y: A_{k-1} }`）を 24 段にした横の `double.onsa` は、`check` に W4-05 U1 の前で約 25 秒、後で約 4 秒かかる（終了コードは 0）。時間は段の数の指数で、30 段なら数分になる見込み。
  §4.4 の型の大きさの上限は宣言した struct を葉と数えるので、この形は正しいプログラムである。ブラウザの IDE でも同じ時間がかかる。
- 経緯: 79 回目（2026-10-28）、W4-05 U1/i（onsa-impl）が範囲の外で見つけ、親が再現した（U1 の後で 4.2 秒）。前からある。W4-05 の設計メモの審査の表 9（種を `TyId` ごとにキャッシュする、`design/03-types.md`）に当たる実例。
- 判断（2026-10-28、親）: 直す。W4-05 で、型引数を含まない宣言の種・配置・破棄の要否を一度だけ求めて `Analysis` に置く（段の出力、D-15）。U2 の宣言の順（依存を先に下ろす）の上で求めるのが近い。
- 補い（2026-10-28、親）: 79 回目（W4-05 U1/i2、`2296e83`）: 宣言を辿る歩きに一つの問いの歩数の予算（`walk.rs::STEPS = 1 << 20`）を置いたので、時間は有界になった（24 段の `double.onsa` は答えなしで速く止まる）。代わりに、展開が 100 万節を超える正しい型の種・配置・破棄は答えなし（`None`）になる。
  W4-16 で `None` を Affine にする前に、型引数を含まない宣言の答えを一度だけ求める形で直す（W4-05 の U2b）。
- 反映（2026-10-28、親）: W4-05 U2b（`fb45620`）: 種・配置・破棄の要否の歩きは、閉じた引数で使う宣言（`(DefId, 引数)`）の答えを、宣言を下ろし終えた後に一度だけ、その鍵だけの歩数の予算と深さで求めて覚える（`walk.rs::Walk::remember`）。`double.onsa` の `interface` は `A24` まで答えを出し、`check` は 0.15 秒から 0.00 秒。
  型パラメータが入れ子の奥にある引数は鍵にならない（R-317、W4-16）。降下の後の配置は別（R-316）。
