# R-03 検査を通り、後段の内部エラーになる入力

- 高・直す・観点 1｜各項目に記す｜—
- 共通: debug ビルドでは Core の検証器が panic する。release では検証器が動かないので、誤ったコードになるか、`E0200 internal ...` になる（R-82）。いずれも sema で拒否するか、正しく降下する。
- 入力ごとの原因と直し方:
  - **総称の `-x` を `U32` で使う**: `fn neg[T: Num](x: T) -> T { -x }` と `neg(u)`。`'-' on a non-signed type` で落ちる（`onsa_sema/src/body.rs:1354`）。どう直すかは R-94 で判断する。再現（親）。
  - **リテラルパターンの範囲外**:
    - `x: U8` に対する `300 =>` と、`x: U32` に対する `-1 =>` が `literal 300 out of range` で落ちる（`body.rs:2504-2535`）。再現（親）。
    - 補間を含む文字列パターン `"a{x}b" =>` は、補間を黙って捨てて `"ab"` と照合する。
    - 直し方: パターンのリテラルも範囲を検査する。補間を含む文字列パターンはエラーにする。
  - **`-(I32.MIN)` の畳み込み**: 被演算子がリテラルに降下したものなら、符号を畳む（`onsa_core/src/lower/body.rs:840-846`）。
    - debug では、検証器が `literal 2147483648 out of range` で落ちる。
    - release では、インタプリタが値を折り返して `I32.MIN` を返す。期待は実行時の panic。
    - 直し方: 畳むのは、ソースの数値リテラルに直接付いた `-` だけにする。
  - **未解決の型変数**: `let x = None` と `let b = Buf.zeroed(4); b.len()` は `check` を通る。`test` で `internal lowering error: unresolved type` になる（`body.rs:506-645` の `finish`）。
    - 直し方: リテラル以外の型変数が残ったら、E0406 か E0420 にする。
    - 仕様へ: §4.7 が定める「未解決の報告」は、リテラルの分しかない。
  - **flow の入力名**: `s`、`cfg`、`params`、`sample_rate` や、`let poisoned` で落ちる。R-15 と R-48 で直す。
  - **`par` の中の look-back**: `let a = par i in 0..2 { prev(y, 0.0) }; let y = x` が `local y read before definition` で落ちる（`onsa_core/src/lower/flow.rs:1107-1123`）。R-13 の二相化と一緒に直す。
  - **自分をインスタンスにする flow**: 相互再帰も含め、`check` を通る。その後 `E0200 this version does not lower ...` になり、将来は対応するかのような文面になっている（`lower/flow.rs:165`）。
    - 仕様 §11.5 は「flow 本体の中に再帰は無い」と定める。sema で閉路を検出し、専用の E08xx を仕様に足す。
  - **巨大な `delay`**: `delay(x, 1073741824, 0.0)` は、`interface` で `multiply with overflow` になる（`onsa_core/src/layout.rs:41`）。R-100 で扱う。
  - **`Bool` の `@param`**: `Ctl[Bool]` に `@param(default: 1.0)` を付けると、`internal lowering error` になる（`lower/flow.rs:571`）。R-99 で扱う。
