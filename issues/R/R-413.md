# R-413 候補の編集の間を空ける `apart` が、別の編集の削除でつながるトークンを見て、隣の空白の削除を空白への置き換えに戻す（`@ export(name: "f")pub`）

- 場所: `crates/onsa_syntax/src/edits.rs::apart`（候補の編集を全て当てた後のトークンで、つながる所を見て削除を空白に置き換える）。
- 内容: `@ export(name: "f")pub fn f(m: U32) -> U32 {` の E0005 の候補（S-959。`@` の後の空白の除去と引数の除去）は、引数の削除で `export` と `pub` がつながるので引数を空白に置き換える。
  そのとき隣の `@` の後の空白の削除も「つながる」と見て空白への置き換え（` ` を ` `）に戻すので、候補を当てた後に空白の E0020 が残る（§18.1 の、候補を当てた後に同じ段の誤りが残らない約束の破れ。`--fix-loop` は二手で収束する）。
  `)` と次の語が接する形だけで、`@ export(name: "f") pub` は一手で誤り 0。再現は `issues/R/R-413/export_args_touching.onsa`。
- 経緯: 127 回目（2026-11-09）、W5-11 U10d2/i3（onsa-impl）が壊す側の台本 `soup.py`（seed 2）で見つけた（W5-11 U10d2/b の M1 の残り）。直し方の案は、(a) `apart` で空白にした編集ごとに、それだけを戻してもつながらないかを確かめ直す（全ての候補に当たる一か所の判断を変える）、(b) 属性の候補の側（`foreign/spaces.rs::with_mark`）で避ける。
- 判断:
- 判断（2026-11-09、利用者）: 直す（127 回目、親の推奨の (a) を利用者が了承）。`edits.rs::apart` で空白に戻した編集ごとに、それだけを戻してもつながらないかを確かめ直す（全ての候補に当たる一か所の判断を直す）。W5-11 U10h。`@` 改行 `export(name: "f")pub` は同じ原因で候補が無い（挿入の右のトークンがつながると見て `apart` が `None` を返す）ので、同じ直しで見る。
- 反映（2026-11-09、親）: W5-11 U10h（`b72565c8`）で直した。`edits.rs::apart` は、つながる編集が二つ以上のとき、つながる編集ごとにその編集だけを元に戻して読み直し、他の編集を通してだけつながるなら元の形を残す。`@ export(name: "f")pub` の候補は一手で誤り 0、`@` 改行 `export(name: "f")pub` にも候補が出る。
