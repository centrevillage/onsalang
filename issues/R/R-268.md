# R-268 `use` の無い本体の経路に `use` を足す修正候補が経路の残りを確かめず、`std.serde.decode(1)` に付く候補 `use std` を当てると名前の段の E0302 が残る

- 場所: `crates/onsa_sema/src/names/lookup.rs` の `not_in_body`（頭が `heads` にあり、経路が二要素以上で、`closes_cycle` が偽なら `use <頭>` を足す。経路の残りは見ない）。
- 内容: §18.1 の修正候補の約束（当てて検査し直したとき、触れた単位に同じ段かそれより前の段の診断を残さない）に反する。`use` の無い `std.serde.decode(1)` に候補 `use std` が付き、当てると同じ単位に名前の段の E0302「cannot find `serde`」が残る（`target/notes/66/g58/probe/std_rest` → `std_rest_applied`、dev `30b09c5`）。
  `util.nosuch()`・`util.hidden()`（`priv`）は今は型の段の E0401（R-254）なので約束は保たれているが、W4-04 で名前の段の E0302・E0303 になると同じ違反になる。
- 経緯: 66 回目（2026-10-25）、第 58 組（S-673）の空白の下書き（onsa-gap）が見つけ、独立のレビュー（onsa-advisor）が R にする方を推した。利用者が S-673 の細部（`use` を足す候補と頭を外す候補は、当てた後の経路が名前の段で最後まで解決するときだけ出す）を了承した。
- 判断: S-673 の細部のとおり、`use` を足す候補と頭を外す候補は、当てた後の経路が名前の段で最後まで解決する（E0302 も E0303 も残らない）ときだけ出す。直しは W4-03 の U3a2。
- 反映（2026-10-26、親）: W4-03 U3a2 で直した。W4-03 を終えるときに、親が今のバイナリ（`bbf69ce`）で `std.serde.decode(1)` に候補 `use std` が付かないことを確かめた。
