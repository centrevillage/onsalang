# R-392 `/=` の候補が、直後の `//` とつながって `///` を作る（`x/=//` 改行 `r`）

- 場所: `crates/onsa_syntax/src/foreign/assign.rs` の複合代入の候補（`=` の直後に ` x /` を入れる枝）と、`edits::joining` が隣のコメントを字句のつながりに数えないこと。
- 内容: 入力 `tests/fuzz/dffd5993.onsa`（`fn g()->U{x/=//` 改行 `r`）。候補を当てると `x= x ///` になり、`//` のコメントが `///` に変わる。前の版（`d7c35101`、`655a5faf`）でも同じ候補が出る。事例を足して変異が変わり、見えるようになった。
  実害は低い。`/=` の直後に空白なしで `//` が来る形だけで、ファイルの意味を黙って変えない（残るのは書き手が読める誤りである）。入力は `tests/fuzz/allowed.toml` に載せた。
- 経緯: 122 回目（2026-11-07）、W5-23 U2 と X-24 の後の網羅の検査の fuzz で出た。W5-11 U1 の `edits::apart` と同じ族なので、W5-11 の後の単位で一緒に見る。
- 判断:
- 補い（2026-11-07、親）: U3b（2026-11-07）で入力 `dffd5993` の項目は `tests/fuzz/allowed.toml` から外れた（閉じない括弧が先に報告される）。同じ類の入力は `tests/fuzz/6cc24ed3.onsa` に差し替えた。
- 反映（2026-11-08、親）: W5-11 U10b（`c662074d`）: `edits::around` が行コメントも隣に数え、複合代入の `=` の後の挿入を `insert_apart` で作るので、`apart` が演算子とコメントの間に空白を置いて候補を残す（§18.1 の作れるときは E0020。設計メモの「落とす」形は採らなかった）。
  閉じた形 `x/=// c` は E0002 から E0020 と候補になった（事例 `fix_compound_assign_before_comment`、U1 の `fix_stays_compound_doc` の期待を改めた）。`tests/fuzz/allowed.toml` の `6cc24ed3` の項目を外した
