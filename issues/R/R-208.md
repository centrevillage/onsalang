# R-208 事例の器の修正候補の約束の検査が、候補の数に対して指数的に遅くなる

- 中・直す・観点 2｜テストの器（`crates/onsa_tests/src/fix_contract.rs`、`onsa_cases --run`）｜§18.1（S-236 の約束の検査）
- 内容: 一つの事例に、候補を当てた後に別の段の誤り（E0401 など）が残る単位が N 個あると、`onsa_cases --run` の時間が N に対して指数的に増える。
  `pub fn uK(x: I32) -> I32 {` 改行 `"a"(x)    //~ E0020` 改行 `}` を N 個並べ、`.fix1` に `"a".(x)` を並べた事例で、N=5 が 0.08 秒、6 が 0.30 秒、7 が 2.36 秒（親が dev の `8f08fe8` で確かめた）。RF/t の報告では N=8 が 22 秒、9 は 40 秒でも終わらない。
  同じファイルの `onsa check` は 0.02 秒。テストの担当は事例を 6 件以下に分けて避けている。今の事例で当たるものは無いが、事例を足すと gate の `test` の段が止まりうる。
- 経緯: RF/t（`foreign.rs` の深いリファクタリングのテストの票）が見つけた（2026-10-10）。原因は読んでいない（候補の組み合わせを試しているか、単位の照合を組み合わせで行っている見込み）。
- 決定（2026-10-10、親）: 直す。原因を調べ、単位ごとに独立に確かめる形にする（約束は候補一つを当てた前後で判定する、§18.1）。時期は W3 の終わりの器の改善（`docs/carryovers.md` の「W3 の終わり」の行）か、それより前に事例が 7 件を超えて要る作業が出たとき。
- 判断: 直す（親）。事例の器の修正候補の約束の検査が、候補を当てた後に別の段の誤りが残る単位の数に対して指数的に遅くなる（N=7 で 2.4 秒、8 で 22 秒）。RF/t が見つけた
- 判断（2026-10-23、親、X-8）: 引き金（候補を当てた後に別の段の誤りが残る単位を 7 件を超えて要る事例）を残す。W4 のテストの票に引き金を書き、当たった時点で器の単位を差し込む。
- 反映: 実装は W3 の終わりの器の改善か、それより前に要るとき（`crates/onsa_tests/src/fix_contract.rs`）
- 判断（2026-10-24、親、58 回目、利用者が見立てを了承）: 器は R-208 の後に改められた（`651f98e`・`3cf57f9`・`67897ec`）ので、今も起きるかを次のセッションで確かめる。残っていれば W4-03 の前に直す（W4-03・W4-04 の名前の段の候補は、当てた後に型の誤りが残りやすい）。器だけを触るので W4-01・W4-14・W4-17 と並べられる。
