# R-397 構文の段のガードの形の候補が、当てると入れ子の上限 256 を超える形でも出る（`1..<3 if ((…254 段…(b)…)) =>`）

- 場所: `crates/onsa_syntax/src/foreign/guard.rs` の構文の段の `guard_pattern` → `Arm::candidates` と、その候補を通す `operands::completed`。
- 内容: 構文の段のガードの形（範囲・浮動小数・補間の文字列など）の候補は、ガードの前に `v == L &&` などを書き足して段を足す（§2.5 は二項の連鎖も段に数える）が、その段を数える所が無い。`completed` は括弧を足すとき（`touched` が空でない）しか入れ子を見ない。
  そのため `1..<3 if ((…254 段の括弧…(b)…)) => 1,` の E0020 に候補が付き、当てると E0006 が出る（§18.1: 上限を超える候補は出さない）。`b && b …` が 254 個の形と、浮動小数の組 `(0.5, 0.5, …)` が 261 個の形も同じ。
  型の段の同じガード（`L if (…254…)`）は、W5-11 U8 の `nesting::Limit::exceeded`（書く字の数を足す段の上限として渡す）で候補なしと note `TOO_DEEP` になる。同じ候補を作る構文の段にこの判断が無い（D-15）。
  入力は `target/notes/124/w511u8/b/y_paren_254.onsa`、確かめは同じ所の `applyfix.py`（候補を当てて `check` を回す）。W5-11 U8 の前のバイナリ（`58598795`）でも同じ。
- 経緯: 124 回目（2026-11-07）、W5-11 U8/b（onsa-break）が入れ子の上限の前後の走査で見つけ、親が前と後のバイナリで再現した。U8 の前からある。
- 判断: 直す（親）。構文の段の呼び手にも同じ `Limit::exceeded` を通す形が見込み。gate の項目に入れる（`rules/leader.md` 4.9。`fixes = 0` の事例）。
- 反映（2026-11-08、親）: W5-11 U10b（`c662074d`）: `operands::deep` が候補を当てた単位の読みの E0006（`nesting::over_limit`）で候補を落とし、`complete` が note（括弧を足さない候補は `WRITTEN_TOO_DEEP`、足す候補は `TOO_DEEP_RULE`）を付ける。コードは E0002。
  型の段の `limit.exceeded` と `guard.rs::TOO_DEEP` は消した。単位に前からある超過（隠れた E0006）がある形でも候補を落とす（元の入力は誤りが二つで約束の外。親の読み）。事例 `nesting_boundary_guard_candidate`
