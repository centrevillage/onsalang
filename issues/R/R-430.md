# R-430 失敗した `use` の名前を繰り返しの配列の長さに書いた値（`[10.0; Point.N]`）に flow の外で `at` を付けると、名前の段が止まらず本体の検査が内部エラー（「flow syntax the names stage did not stop at」）になる

- 場所: `crates/onsa_sema` の本体の検査（`body/expressions.rs` の `at` の枝が「名前の段が止めたはずの flow の構文」として内部エラーを出す所）と、名前の段が flow の外の `at`（E0821、§11.1）を見つけて単位を止める所。
- 内容: 取り込む先の無い `use util.{Point}` の後の関数の本体の `let b = [10.0; Point.N] at sample` で、`onsa check` が内部エラー（終了コード 101）になる。
  期待は、失敗した名前 `Point` の E0302（`use` の位置）と、使う所は黙ること（§18.1）、flow の外の `at` は E0821（§11.1）で、どちらを出すかは §18.1 の段と位置の順。失敗した名前の無い `[10.0; Nope.N] at sample` は E0302、長さの無い `Point.N at sample` は E0302、flow の中の同じ形は E0302 で、どれも内部エラーにならない。失敗した名前が繰り返しの配列の長さ（定数式）にあると、名前の段がその単位を止めずに E0821 も出さないまま本体の検査へ渡ると見られる（原因は直す担当が読む）。再現は横の `main.onsa`（dev `c63b9c0f` と W5-24 U7a の後で同じ）。
- 経緯: 138 回目（2026-11-11）、W5-24 U7a の壊す側（onsa-break）が、通る事例 `tests/spec/packages/assoc_const_in_lengths_modules_kept/main.onsa` の一行を `at` 付きに変えた掃引で見つけ、親が前のバイナリで再現して最小の形にした。前からの挙動。
- 判断（2026-11-11、親）: 直す。内部エラーなので、見つけた作業の W5-24 で直す（`rules/leader.md` 7.4）。名前の段の失敗した名前と `use` の扱いを触る U7b（S-696）の票に入れる。
