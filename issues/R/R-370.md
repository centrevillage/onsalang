# R-370 型パラメータの後の `.` で見つからない名前の E0302 の文面が「cannot find `T`」になる

- 場所: 名前の段の経路の引き。同じ形の `F32.f()` の文面は「cannot find `f`」。§15.1
- 内容: `fn g[T: Show](x: T) -> U32 { T.f() }` と `T.NOPE` が E0302「cannot find `T`」になる。`T` は見つかっていて、見つからないのはメンバの `f` である。コードは E0302 のままでよく、文面だけが読み手を誤らせる。文面は仕様の約束の外。再現は `target/notes/115/w504/probe/t/`（`db59c807`）。
- 経緯: 115 回目（2026-11-05）、組 86 の独立のレビュー（onsa-advisor）が見つけ、親が固定のバイナリで再現した。
- 判断:
- 反映（2026-11-05、親）: W5-04 U2（2026-11-05、115 回目）: 式の位置の `T.f()`・`T.NOPE` の文面と位置を `f` を指す形にした。型の位置の `-> T.K`、配列の長さ `[F32; T.N]`、境界 `U: T.x`、パターン `T.K =>`、効果行 `uses {T.e}` は同じ文面のまま残る（再現は `target/notes/115/w504/u2/r370.onsa`）。文面だけなので W5-11 へ送る
- 反映（2026-11-08、親）: W5-11 U10a（`27c1cb8b`）: 型の位置・境界・効果行の型パラメータの後の `.` で、境界が読めてメンバを与えないときはメンバの名前の E0302（`sig/heading.rs::missing_member`）。式の位置は W5-04 U2 で直っていた。境界が与えるメンバと const パラメータの形は R-404。テストは `crates/onsa_cli/tests/cli/type_param_members.rs`
