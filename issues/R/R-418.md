# R-418 名前の後の `,` を含む `[…]` の要素が型でも定数式でもないとき（`Rg[F32, 1 as U32 as U32].CAP`、`if c { 1 } else { 2 } as U32`）、E0020 の `::` を挿す候補を当てると隠れていた構文の誤り（E0011・E0013）が同じ範囲に残る（値の位置は前から、配列の型の長さは W5-16 U1d から）

- 場所: `crates/onsa_syntax/src/foreign/paths.rs` の `TypeArgsSquareComma` の行（`type_args_square_comma`）の候補の作り手（値の位置と、W5-16 U1d からは型の引数の外の配列の型の長さ）。
- 内容: `pub fn f(r: [F32; Rg[F32, 1 as U32 as U32].CAP]) -> U32 { 0 }` は E0020 で `::` を挿す候補が付き、当てると E0011（`as` の連鎖）が同じ範囲に残る。`if c { 1 } else { 2 } as U32` の要素では E0013 が残る。値の位置の `let a = Rg[F32, 1 as U32 as U32].CAP` は dev `f5eced1d` でも同じ。候補が新しい誤りを作るのではなく、先に止まっていた構文の誤りが見える。乱数の文法 6.5 万件で、破れのあるファイルは dev 34 件、U1d の後 80 件（増えた分は全てこの 2 種）。§4.5（S-333）は、中身が型引数として読めない並び（型でも定数式でもない要素を含む）の候補を `xs["s"][2]` の形だけとするが、今の実装は全ての並びに `::` の候補を一つ出す。
- 経緯: W5-16 U1d の壊す側の再確認が見つけた（2026-11-10、130 回目）。入力と台本は scratchpad の `w516u1d2/b2/`（`it3/`・`valpos/`・`el/`）。
- 判断: 低。後ろに隠れた構文の誤りが見えるだけで、書き手が書く形としても稀。利用者が W5-24 U6 で S-333 の候補の作り分けと一緒に直すことを選んだ（2026-11-10。U1d で直すと U6 が作り直す）。gate のファズが `fix|E0020|…|E0011`（`E0013`）の類を拾ったら、この R を理由に許可の一覧に載せる。
- 反映（2026-11-11、親）: W5-24 U6b `274430d0`: `foreign/square.rs` の要素の分類で、型でも §4.5 の定数式でもない要素を含む並びは読めない並びとし、候補は添字の形の一つ（`::` を出さない）。`Rg[F32, 1 as U32 as U32].CAP` などは添字の形を当てると隠れていた E0011・E0013 が残る（元から誤りが二つ、事例の `leaves`）。
