# R-455 名前付きの関数の E0601 の修正候補 ` uses {Alloc}` が、返り値の型が関数型で終わる署名では返り値の関数型に付く（`pub fn mk() -> fn(I32) -> I32 { … }`）

- 場所: 効果の段の E0601 の修正候補（`crates/onsa_sema/src/effects.rs` の署名への挿入の位置）
- 内容: `pub fn bump(y: I32) -> I32 uses {Alloc} { y }`、`pub fn k(y: I32) -> I32 { y }` の下で、`pub fn mk() -> fn(I32) -> I32 { let _ = bump(1)` 改行 `k }` の E0601（3:8）の候補は返り値の型の後（本体の `{` の前）に ` uses {Alloc}` を挿入し、当てた形は返り値の関数型 `fn(I32) -> I32 uses {Alloc}` を作るだけで同じ E0601 が残る（S-364: `uses` は返り値の関数型に付く）。`onsa_cases --fix-contract` が「after it, the units its edits touch hold 3:8 E0601 of its stage or an earlier one; expected none」を出す（§18.1 の約束の違反）。`--fix-loop` は二手で止まるが、返り値の型を黙って変えた後である。正しい候補は返り値の型を括弧で囲む形（`-> (fn(I32) -> I32) uses {Alloc}`、通る）。再現は `target/notes/146/g99/advisor/probe/a2.txt` の `named_ret_fn_e0601`・`_fixed`・`named_ret_fn_paren`。
- 経緯: 146 回目（2026-11-13）、第 99 組（S-1032）の独立のレビューの段 1（onsa-advisor）が見つけ、親が固定のバイナリ `onsa-702a461` と `onsa_cases --fix-contract` で再現した。直すのは E0601 の候補を作り直す W6-03。
