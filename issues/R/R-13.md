# R-13 flow: look-back の引数の中のノードが、保存した後の値を読む

- 高・直す + 仕様へ・観点 1｜`crates/onsa_core/src/lower/flow.rs:1033`、`:1060`｜§11.2、§11.4｜再現（親）
- 原因: 保存は tick の末尾で、引数をその場で降下し直して行う。そのため、外側の `prev` の引数の中にある内側のノードは、自分の保存と前進を済ませた後に読まれる。
- 再現:
  - 最も素朴な形 `prev(prev(x, 0.0), 0.0)` が、x[n-2] ではなく x[n-1] を返す。同じ意味を `let x1 = prev(x, 0.0); let x2 = prev(x1, 0.0)` と書くと正しい（保存の段で、計算済みのローカルを読むため）。再現（親）。
  - `let a = prev(prev(y, 0.0) + y, 0.0); let y = x` に impulse を入れる。期待は `out[1] = 1`、`out[2] = 1`。実際は 2 と 0。
  - `prev(delay(x, 2, 0.0), 0.0)` は、期待が x[n-3]、実際は x[n-2]。
- 資料の誤り: `impl-review` C-9 の「保存順は逆だが結果は同じ」は、一般には成り立たない（§4）。
- 直し方: 保存を二相にする。全てのノードの保存値を一時変数に計算してから、まとめて書く。§11.4 に一文を足す。
