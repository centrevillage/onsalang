# R-348 `check` を通る `const B: Bool = !true` が `build --target c` で E0200 になる（駆動部の `is_static_init` は `Unary` を全て静的と見て評価せず、後端の `const_init` は `Neg` のリテラルしか書けない）

- 場所: `onsa_driver/src/consts.rs::is_static_init`（C の静的初期化子として書ける形の一覧。`Unary(_, x)` を全て静的と見る）と、後端の `onsa_backend_c/src/emit/consts.rs::const_init`（`Unary` は `Neg` のリテラルだけを書き、他は E0200 `ConstInitializer`）。
- 内容: `const B: Bool = !true` を `@export` の fn が読むパッケージは、`onsa check` が終了コード 0、`onsa build --target c` が `error[E0200]: the C backend does not support this \`const\` initializer (evaluated at build time) in this version`（位置は `!true`）で止まる。§6.6 では `Bool` の `const` は静的に置ける型で、E0200 にする形（Shared を含む型など）に当たらない。
  駆動部が `!` の式を静的と見て評価に回さず、後端がそれを書けない。`const A: U32 = !0`、`const F: [Bool; 2] = [!false, true]` も同じ。`!(1 < 2)` は通る（比べは静的と見ないので評価される）。`-A`・`-(-3)` は Core の畳み込みで通る。
  同じ一覧の食い違いの他の二つ（駆動部だけが `Zeroed`、後端だけが `Cast`）は、今は当たらない（`Zeroed` はブロックの中だけに現れ、ブロックは静的と見ない。`Cast` は駆動部が評価してリテラルにする）。今の `tests/`・`examples/`・std に当たる入力は無い。前からの形。
  再現はこのディレクトリの `main.onsa` と `onsa.toml`（`onsa build --target c .`）。
- 経緯: 101 回目（2026-11-02）、W4-18 U6a の実装の担当が、洗い出しの K5（二つの一覧の食い違い）を調べて見つけた。親が dev `cb276e32` のバイナリで再現した。
- 判断: 直す（低）。二つの一覧を一か所（後端が書ける形の述語を駆動部が読む）にすれば消える。W9-03 が定数の評価を Core の一つの段に作り直すので、そのときに一つにする（洗い出しの K5）。
