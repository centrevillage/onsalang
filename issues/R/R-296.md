# R-296 `match` の腕の値の後に演算子の無い式が続く形（`_ => s 0.0`）に、構文の段が「要素の間に `,` を書く」候補を出し、当てると次の腕のパターンの E0002（浮動小数のリテラルはパターンにできない）が同じ位置に残る

- 場所: 構文の段の並びの区切りの抜けの候補（「write the `,` between the elements」）。`match` の腕の並びでは、`,` の後は次の腕のパターンである。
- 内容: `match s { _ => s 0.0 }` は E0002「expected `,` or `}`, found float literal」で、候補は `s` の後に `,` を挿す。当てた `_ => s, 0.0` では `0.0` が次の腕のパターンになり、E0002「float literals cannot be patterns; compare in a guard」が同じ位置に残る。
  §18.1 は、当てた後に同じ段以前の診断を残す候補を出さないとする。書き手の意図も一つに決まらない（`s * 0.0` などの演算子の書き忘れでありうる）。通るプログラムは変わらない。
  再現は横のディレクトリの `arm_value.onsa`（dev `42e2f5c` も同じ）と、ファズの入力 `tests/fuzz/7e25b3d2.onsa`（W4-04 U5 の事例 `enum_variant_spelling.onsa` を種にした変異で、基の `e741747` でも出る）。
- 経緯: 77 回目（2026-10-27）、W4-04 U5/i の gate のファズが見つけ（`fix|E0002|write the `…` between the elements|E0002`）、親が整った形で再現した。前からの形。
- 判断: 直す。字句・構文の残りを扱う W5-11 で、`,` を挿した後の字句が次の要素の始まりになれるとき（`match` の腕ならパターンの始まり）だけ候補を出す。それまで入力は `tests/pending.toml` の `fuzz-input` に載せる。
