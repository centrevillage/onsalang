# R-390 `match` と `let` の分解の `_` に捨てた `Buf` のフィールドの破棄が、`rt` の E0901 と効果の E0601 にならない（`Str` なら出る）

- 場所: `crates/onsa_sema/src/rt.rs` の `rest_drops` の周り。部分を動かした値の残りの破棄の読み手で、`_` に捨てたフィールド。
- 内容: 横の `buf_rest.onsa`。`pub struct HBuf { g: G0[F32], b: Buf[F32] }` の `rt fn m_buf(move h: HBuf)` で `match move h { HBuf { g: gg, b: _ } => use_it(gg) }` と書くと、E0901 も E0601 も出ない。§5.2 は「取り出したフィールド以外はその場で破棄され」、§12.2 は `Buf` の破棄に `Alloc` が要ると書く。同じ形の `Str` のフィールドは E0901 になり、`h.g` で取り出す形は `Buf` でも E0601 になる。段数と関係しない。`rt` の保証が黙って外れる。
- 経緯: 121 回目（2026-11-07）、W5-23 U1/t（onsa-test）が見つけ、親が固定のバイナリ `3ded131` で再現した。前からの形である。
- 判断: （2026-11-07、親）直す。破棄の検査の作業 W6-02 で直す。原因は読んでいない（`drops_alloc` は `Buf` を真と読むので、残りを求める経路の前で落ちている見込み）。
