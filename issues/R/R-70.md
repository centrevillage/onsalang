# R-70 fmt がコメントを別の場所・別の宣言へ移す

- 高・直す + 要判断・観点 1 / 2｜`crates/onsa_syntax/src/fmt.rs:151-190`、`:666` 以降、`parser.rs:314`｜§2.1、§18.2、`impl-review` F-4
- 再現: 次のどれも、fmt が冪等で `--check` も通る状態で起きる。
  - **フィールドの `///`**: 次の `pub fn` の doc として解析される。AST が変わり、`diff --ast` が報告する。
  - **引数の行末のコメント**: 関数の本体の先頭へ移る。
  - **空の本体のコメント**: `fn empty() {\n  // todo\n}` が `fn empty() {} // todo` になる。
  - **match の腕と配列の要素（係数表）の行末のコメント**: 全て閉じ括弧の後ろに積まれ、どの要素の注釈か分からなくなる。
- 資料の誤り: `impl-review` F-4 の記述（「式の途中のコメントは文の後ろへ移る」）より、影響が大きい（§4）。
- 構造上の原因: fmt はコメントなどの trivia を AST に持たず、位置を推測して付け直す（R-86）。
- 判断（R-70）: フィールド・列挙子・引数に doc を付けられるようにするか。
  - (a) 付けられるようにする（Rust と同じ。`onsa interface` にも出す）。
  - (b) 付けられないことにし、そこに書いた `///` をエラーにする。
  - 推奨は (a)。`@param` の説明などに要る。
  - F-4 の判断は、この項目に統合する。
- 範囲（2026-10-04 に追加で確かめた）: 並び（`list()`）がコメントを全く扱わず、残ったコメントを囲みの後ろにまとめて出す。そのため、列挙子の `///`、flow の入力の `///`（本体の先頭へ）、フィールド・列挙子・呼び出しの引数・構造体リテラルの行末のコメント、並びの中の単独の行のコメントも移る。
  `{ // note` は次の行へ、`if` の条件の途中のコメントは本体の先頭へ移る。17 の形を `tests/review-phase1/parent/r70/` に置いた。コメントの並び順は変わらないので、S-56 の安全装置では捕まらない（doc が別の宣言に付く形を除く）。
- 決定（2026-10-04）: 直す。doc の付く場所は R-63（S-51）で決着した（フィールド・列挙子・flow の入力には付く。fn の引数には付けず、E0004）。S-58: fmt はコメントを書かれた行に残す（行末は同じ要素の後ろ、単独の行は次の要素の前か閉じ括弧の前。コメントを含む囲みは 1 行にまとめない）。F-4 もこれで決まる。R-86 のうち、コメントを要素に結び付ける部分を前倒しし、R-63 と同じ回（第 2 段）に直す。
- 判断: 直す。doc の付く場所は R-63（S-51）で決着（フィールド・列挙子・flow の入力には付き、fn の引数には付けない）。S-58: fmt はコメントを書かれた行に残す。行末は同じ要素の後ろ（補った `,` の後ろ）、単独の行は次の要素の前か閉じ括弧の前。並びの中でも式の途中でも同じで、コメントを含む囲みは 1 行にまとめない（F-4 もこれで決まる）。
  R-86 のうちコメントを要素に結び付ける部分（前に付く・後ろに付く・空の囲みの中）を前倒しし、R-63 と同じ回に直す。性質テストに、各コメントが同じ要素の行に残ることを加える（R-113）。再現は `tests/review-phase1/parent/r70/`（17 の形）
- 反映: 仕様 §18.2 に反映済み（2026-10-04）。実装は W3-11。補い（2026-10-07、W1-07 の性質テスト）: r70 の 17 の形に無い症状として、ブロックの先頭のコメントの後の空行が消えない（§18.2）、引数の並びの単独の行のコメントが本体へ移って空行が入る、呼び出しの引数のコメントが閉じ括弧の後へ移って空行が入る。gate の `fmt-comments`（W3-11 の実装待ち）が追う
