# R-410 閉じない `match` の腕のパターン（`A(1, [2 => 3,`）を持つ関数を並べると、読み直しのパーサが残りのトークンを毎回作り直して二乗になる（4000 個で 4.9 秒、8000 個で 18 秒）

- 場所: 読み直しのパーサ（`code_tokens`・`pattern_alternative`・`Parser::new`。`sample` の上位）。読み直すたびに残りのトークンを作り直す見込み（未確認）。
- 内容: `fn f{i}() -> I32 {` / `  match x {` / `    A(1, [2 => 3,` を N 個並べると、N=2000・4000・8000 が 1.25・4.9・18 秒（debug、前後とも）。ガードの形（`n @ [1, 2 => xs[0],`）も N=400・800・1600 で 0.12・0.28・1.07 秒。台本は `target/notes/125/w511u10c/break/scale_forms.py`（`match` の形）。
- 経緯: 125 回目（2026-11-08）、W5-11 U10c/b（onsa-break）が見つけた。前（dev `bfe34c17`）と後（U10c）で同じ時間で、U10c の範囲の外。
- 判断:
- 判断（2026-11-08、親）: 直す（利用者が了承、125 回目）。W5-11 の U10g（U10f の後。U10c と同じ構文の段の性能の族）
- 反映（2026-11-08、親）: W5-11 U10g（`a9045c1b`）で直した。括弧の表の `Brackets::scan_end`（種類を見ない対で閉じない開き括弧の次か、ファイルの終わり）で、ガードの形の読み（`form_at`・`Arm::read_tokens`）、誤りのあるファイルの `parse_pattern_alt`、先頭の `|`（`leading_vert`）、`arm_ahead` の走査を止める。`match` の 4000 個は 4.48 → 0.06 秒。同じ族のガード・浮動小数・範囲・`@`・`let`・`for`・先頭の `|`・腕の間の `,` が無い形も線形になった。出力は変えない。範囲の形の主の範囲がファイルの終わりまで延びるのは R-412。
