# R-255 rt の関数で `move` の引数に受けた Shared 値をそのまま返すか `move` で渡すと E0901 になる

- 場所: rt の関数の破棄の検査（破棄点の列挙。W6-02 の範囲）
- 内容: 再現は横の `move_return.onsa`。`rt fn hs(move s: Str) -> Str { s }` が E0901「`s` owns a `Str`, whose destruction needs `Alloc`」になる（`return s` と `[Str; 2]` も同じ）。`rt fn pass(move s: Str) -> Str { hs(s) }`（S-609 で Shared の値は `move` 無しで `move` の引数に渡す）は今は E0703 で、W4-09 の後も E0901 にならないことを確かめる。`Buf[F32]` の同じ形（`hb`）は通る。
  §12.2 は「受け取った Shared 値を、そのまま返す・`move` の引数に渡す」に `Alloc` が要らないとする。返り値や `move` の引数へ出た Dup の値を移動として記録せず、本体の終わりで破棄すると数えている見込み（推測）。正しいプログラムを拒む誤りで、見落としの集まりの R-32 と症状が違う。
  同じ根の見込みの形（第 45 組の後のまとめの onsa-gap が見つけた。推測を含む）: ローカルの所有の束縛を返す `rt fn f(v: F32) -> Param { var p = Param { name: "gain", value: 0.0 }; p.value = v; p }`（横の `v9_var_return.onsa`）と `let p = mk(v); p`（`v10_let_call_return.onsa` の `f`）も E0901 になる。
  返すのは破棄でない（§12.7）。
  `v10` の `g`（`let p = Param { name: "gain", value: v }; p`）は S-613 で借用の束縛になり、W4-16 で直る。W6-02 で両方の形を確かめる。
- 経緯: 第 44 組の二回目（S-610）の下書き（onsa-gap、2026-10-23、58 回目）の付録が見つけ、独立のレビューの段 1・段 2 が新しい R にすると決め、利用者が了承した（C5）。親が dev `2ebd664` の release の `check` で再現した。直しは W6-02（破棄点の列挙）。
