# R-38 impl のメンバの可視性が呼び方で違う。フィールドの `pub` に意味が無い

- 高・直す + 要判断・観点 1 / 3｜`crates/onsa_sema/src/body.rs:2146`、`resolve.rs:241`｜§15.1「無指定はモジュール内のみ」
- メソッドの可視性:
  - 他のモジュールから `p.private_method()` を呼ぶと、エラーなしで通る。
  - `Point.private_assoc()` は E0401「`Point` is not a value」になる。本来は E0303 で、文面も誤っている。
- フィールドの可視性:
  - フィールドの `pub` は構文として受理するが、仕様に定義が無く、検査もしない。
  - 他のモジュールから `p.x = 3.0` も struct リテラルも通る。
- 直し方: メソッドの可視性は直す。
- 判断（R-38）: フィールドの可視性をどうするか。
  - (a) 仕様に入れて検査する（Rust と同じ）。
  - (b) 構文から外し、フィールドは型と同じ可視性とする。
  - 推奨は (a)。不変条件を持つ型（`Ring` など）を作るには、フィールドを隠す手段が要る。
- 決定（2026-10-03）: メソッドの可視性は直す（呼び方によらず検査し、`Point.private_assoc()` の文面も E0303 にする）。フィールドの可視性は S-35: struct の可視性を継ぎ、狭めるときだけ `priv`（`pub(pkg)` は S-36 で外した）。必要以上に可視性を狭めず、利用側の回り道を避けるという方針（OOP 的なカプセル化は好まない）。
- 判断: メソッドの可視性は直す（呼び方によらず検査し、`Point.private_assoc()` の文面も E0303 にする）。フィールドの可視性は S-35: struct の可視性を継ぎ、狭めるときだけ `priv`（`pub(pkg)` は S-36 で外した）。必要以上に可視性を狭めず、利用側の回り道を避けるという方針（OOP 的なカプセル化は好まない）
- 反映: 仕様 §2.2 / §15.1 に反映済み（2026-10-03）。実装は W4-03（メソッドとフィールド）
