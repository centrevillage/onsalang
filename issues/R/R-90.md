# R-90 T4-10（入れ子の bulk）の受け皿が無い

- 中・要判断・観点 2 / 3｜`crates/onsa_core/src/layout.rs:152-172`、`lower/flow.rs`（`node_fields`、`init_nodes`）、`crates/onsa_backend_c/src/emit.rs:256-285`、`:840-849`、`:1063-1086`、`export.rs`、`onsa_driver/src/interface.rs`｜§12.4、S-26、S-28
- 現状の作り:
  - Core には bulk の概念が無い。State は一つの値で、`flow_layout_for` が最上位のフィールドだけを分ける。
  - C バックエンドは、export された状態についてだけ、フィールド名の照合で bulk の struct を作る。
  - ポインタを保つのは、init の sret の中（文字列 `target == "(*out)"` との一致）だけである。
- 入れ子の bulk に要るもの:
  - 状態の型ごとの再帰的な配置（子の bulk 部分のオフセット、`par` の複製の間隔）
  - 親の init が子のポインタを設定する手段
  - 「bulk を持つ状態のコピー」の禁止の見直し
- 規模の見積もり: 計画の M より大きく、M〜L である。
- 仕様の穴（判断が要る）:
  - **(i) bulk をどこで表すか**
    - (a) bulk のポインタと領域の分割を、Core の型と init の文として明示する。インタプリタでも検証できる。
    - (b) バックエンドごとに合成する。
    - 推奨は (a)。R-81 と同じ回で行う。
  - **(ii) bulk を持つ State を、通常の値（§17.6 の `voices: [voice.State; 8]`）に入れる場合**: S-28 は flow の中の flow しか扱っていない。`impl-review` B-13 の「S-28 で解消」は誤りである（§4）。
    - (a) Onsa の中の値としての State は、bulk を分けない（C の型が 2 つになる）。
    - (b) bulk を持つ State を値に入れることを、エラーにする。§17.6 は閾値の無いターゲットに限ると明記する。
    - (c) 所有者の型にも bulk を連鎖させる。
    - 推奨は (b)。第 1 期の範囲で最も単純で、マイコンでポリフォニーを書くときは `par` を使う。
  - **(iii) `SIZE` がポインタ幅に依存する**: bulk があると、先頭のポインタのせいで `SIZE` がポインタ幅に依存する。S-26 の「SIZE は全ターゲットで同じ」と矛盾し、`--backends all` では Core をターゲットごとに作り直す必要がある。
    - 推奨は、S-26 の文言を「libc に依存しない」に直すこと。bulk 領域の整列（`BULK_ALIGN`）も仕様に足す。
- 決定（2026-10-02）:
  - (i) bulk のポインタと領域の分割を、Core の型と `init` の文として明示する。
  - (ii) bulk を持つ State を普通の値に置くことは、`memory.bulk = true` のターゲットで E0819。ポリフォニーは `par` で書く（注釈の方式なら、ボイスに `@bulk` があるときだけ掛かる）。S-31。
  - (iii) 保証を「`memory.bulk` とポインタの幅だけで決まり、libc・C コンパイラに依存しない。同じターゲットでは単独の export と埋め込みで同じ」に改める。`voice.SIZE` / `BULK_SIZE` は Onsa の名前空間から外す。ポインタの幅への依存はそのまま（オフセットの案は §19.1）。Core は分割の構造だけを持つ。S-32。
- 整合（2026-10-05）: (i)〜(iii) は決定済み（S-31、S-32）。その後の R-80（ターゲットの pass）、R-81、R-82、R-89 の決定と次のように整合を取った（新しい判断は無い）。
  - (1) bulk の分割は、ターゲットの pass で行う。(i) の「Core の型と `init` の文として明示する」は、`memory.bulk = true` のターゲットでの pass の出力として実現する。`false` では分けずに通す。計画の T4-10 の記述（「降下で分ける」）を改めた。
  - (2) 分割の正しさは、検証器の V-15 と、インタプリタで分割した Core と分割しない Core の出力を比べる差分テストで確かめる（(i) の「インタプリタでも検証できる」を具体化した。インタプリタは bulk の領域とポインタを含む Core を実行できるようにする）。
  - (3) E0818 は sema、E0819 と E0820 はターゲットの pass で出す（ビルドと `onsa interface --target`。`check` では出ない。報告は S-67）。
  - (4) T4-10 は M〜L で、R-81 と同じ回に、R-06 の進め方で行う。時期はレビューの後に決める。
