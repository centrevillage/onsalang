# R-198 引数の `move` の被演算子が場所でない形が通る

- 中・直す・観点 1｜modes｜§5.2
- 内容: `eat(move if c { x } else { y })`（`eat` は `move` の引数）は検査を通り、腕の `x`・`y` を `move` 無しで消費する（`eat(move { x })` も通る）。`let z = move if c { x } else { y }` は E0711 になる。
  §5.2 は `move` の被演算子を後置式（名前と、それに続くフィールド・添字・呼び出し）とし、消費する位置に置いたブロックの各腕を `let y = <腕の値>` と同じに扱う（S-100）ので、どちらの読みでも誤りの形である。W3-20 の前から（dev のバイナリでも同じ）。
- 経緯: W3-20/b が見つけた（2026-10-09）。
- 決定（2026-10-09、親）: 直す。`move` の検査を作り直す W4-09 で行う。コードと段（被演算子を名前で始まる後置式に限る構文の段の E0002 か、腕を消費の位置として読む modes の段の E0711）は W4-09 の作業票で決める。
- 判断: 直す（親、仕様が明確）。引数の `move` の被演算子が場所でない形（`eat(move if c { x } else { y })`）を誤りにする（今は腕を `move` 無しで消費して通る。`let` の位置は E0711）。W3-20/b で見つけた
- 反映: 実装は W4-09
- 判断（2026-10-23、親）: S-605（2026-10-23）: 場所でない被演算子の `move` は位置によらず modes の E0711（段とコードを決めた）。
  同じ根の今の誤りもこの直しで直す: `move` の引数に新しい値を渡す `take(Buf.zeroed(4))`・`tk(1)` が E0703 で、`take(move Buf.zeroed(4))`・`tk(move 1)` が通る逆転、`for z in move mk2()`・`for z in move KA`・`for z in move if c { xs } else { ys }` が通る形（第 42 組の `m2x/x01`〜`x03`・`x13`・`x14`、`m2/for_move_*`）。
- 判断（2026-10-23、親）: S-609（2026-10-23）: リテラルの要素の位置の場所でない `move`（`Some(move 1)`）も今は通る（`let y = move 1` は E0711）。S-605 の E0711 の直し（W4-09）に入る。
- 判断（2026-10-30、親）: 場所でない被演算子の `move` を位置によらず E0711 にする一様な形を W4-07（U2）で直す。利用者が了承した（86 回目、W4-07 の設計メモの審査の A1）。候補（ブロックと `if` の末尾へ `move` を移す形など）は W4-09 のまま。
