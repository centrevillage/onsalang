# R-424 struct リテラルの型引数の付け先の分類が `goes_to` と別にあり、見出しの切れた型への並び（`Cut::[3] { v: 1 }`）で鎖の形（無診断）と食い違う（E0308・E0302 が出る）

- 場所: `crates/onsa_sema/src/names/body/paths.rs` の `struct_lit`（struct リテラルの頭の型引数の付け先を自前に決める）と、`names/body/type_args.rs` の `goes_to`（鎖の並びの付け先の一つの分類）。
- 内容: 見出しに構文の誤りのある総称の型（`pub struct Cut[T: ] { v: T }`）への並びで、鎖の形 `Cut::[3].x`・`Cut::[Nope].x` は何も出さない（`goes_to` が、宣言の解けない項目に何も記録しない）のに、struct リテラルの `Cut::[3] { v: 1 }` は E0308、`Cut::[Nope] { v: 1 }` は E0302 を出す。
  付け先の判断が二か所にある（D-15）。型の位置の `Cut[3]`・`Cut[Nope]` は W5-10 の前から同じ診断を出すので、struct リテラルは型の位置と揃っている。再現は横の `cut.onsa`。
- 経緯: 133 回目（2026-11-10）、W5-10 U1a の壊す側（onsa-break）が報告し、親が U1a のバイナリで再現した。U1a で入った食い違い。
- 判断: 低（見出しに誤りのある型を使う所の、二つ目以降の診断）。struct リテラルの分類を `goes_to` に通す直しは、`goes_to` の枝を実装に替える W5-10 U2a で行う。見出しの切れた型への並びを無診断にするか、型の位置に揃えて診断するかは S-984（型の読めない宣言を使う所の診断）と同じ問いなので、そこで決まるまでは鎖の側（無診断）に揃える。
- 反映（2026-11-10、親）: W5-10 U2a（`10a0b8f9`）で、struct リテラルの並びの付け先を `goes_to` に通した（`type_args.rs::struct_args`）。見出しの切れた型への並びは鎖の側と同じ無診断。事例は `tests/spec/types/type_args_struct_lit_cut_heading.onsa`。
