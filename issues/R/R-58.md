# R-58 行末の `->` が継続にならない。`type A =` の後の改行も通らない

- 中・直す + 仕様へ・観点 1｜`crates/onsa_syntax/src/parser.rs:457`、`:1022`、`:1571`、`:572-580`｜§2.5「行末のトークンが二項演算子、`=`、`->` の場合は継続」
- 再現: `fn f(x: I32) ->\n  I32 {` と `type Alias =\n  I32` が E0002 になる。一方、`const X: U32 =\n 1` は通る。
- 仕様へ: トップレベルにも同じ規則を適用するか。
- 決定（2026-10-03）: 直す。トップレベルにも同じ規則を適用し、次の行が `uses` で始まる場合も継続にする。ブロックの `{` は宣言や見出しと同じ行に書く（E0003）。S-47。
- 判断: 直す。S-47: 継続の規則をトップレベルにも適用し、次の行が `uses` で始まる場合も継続する。ブロックの `{` は宣言や見出しと同じ行に書く（E0003）。エラー回復は、前の行が継続のトークンで終わる行を項目の始まりとみなさない
- 反映: 仕様 §2.5 に反映済み（2026-10-03）。実装は W3-06。
  補い（2026-10-07、W1-07/b）: 構文解析器が §2.5 の継続を読めない形として、trait / extern のメンバの次の行頭の `uses`（`fn g(self)` の次の行の `uses {Alloc}`）、行末の `->`（`fn f(self) ->` の次の行の型）、型の別名の `type B =` の次の行の型がある（どれも E0002）。
  W3-06 で直し、fmt の性質テストの `continue` の摂動をこれらの位置に広げる
