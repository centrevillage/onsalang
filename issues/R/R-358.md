# R-358 C の生成が、関数の中の最初の E0200 でその関数を止め、同じ関数の他の E0200 を出さない（照らしに当たった関数は生成ごと飛ばす）

- 場所: `crates/onsa_backend_c/src/emit/fns.rs`（関数の生成が最初の `unsupported` の `Err` で止まる。77 行の引数の `Buf` など）、`crates/onsa_backend_c/src/prims.rs::check` と `emit/unit.rs` の `lacking_fns`（照らしに当たった関数の生成を飛ばす）
- 内容: §18.1 は、降下とビルドの診断を単位で絞らず全て報告するとする。C の後端は、一つの関数の生成を最初の E0200 で止めるので、同じ関数の他の E0200 が出ない。
  再現 `issues/R/R-358/`（`onsa build --target host`）: 関数 `h` は引数の `Buf[F32]` と `assert_near` の使用を持つ。
  W5-02 U3a の前（`ba995f61`）は `h` の見出しの `Buf` の E0200（2:1）だけが出て `assert_near` が出ず、U3a の後は `assert_near`（3:3）だけが出て `Buf` の 2:1 が出ない（件数は同じで、隠れる方が入れ替わる。1:1 の `Buf` は R-138）。
  直すときは、照らしの E0200 を出した関数も生成を続けて他の診断を集める。そうすると関数ごとの集まりが要らなくなり、`prims::check` は `onsa_core::Reach::walk`（インタプリタの照らしが使う一つの走査）で書ける（壊す側の D-15 の指摘）
- 経緯: 107 回目（2026-11-03）、W5-02 U3a の壊す側（onsa-break）が見つけた（低）。実装の担当も範囲の外として挙げていた。前からある形（関数ごとに最初の誤りで止める）で、U3a は件数を変えない
- 判断: 直す（親）。C の後端の診断の位置を直す R-138 と同じ作業（W10-01）で、関数の生成の誤りの集め方と一緒に直す
