# R-504 長さ 0 の配列を状態に持つ flow（`[F32; 0]` を値型にする遅延）の C が、状態の配置の静的な表明（大きさと `onsa_poisoned` の位置）で落ちる: Core の配置は長さ 0 の配列を大きさ 0 と数え、C は `a[1]` で 1 要素分を取る

- 場所: `crates/onsa_core/src/layout.rs` の `size_align_for` の `Ty::Array`（大きさを `要素 × N` で数え、`N = 0` は 0）と、C の後端の配列の型（`typedef struct onsa_arr_f32_0 { float a[1]; }`、`crates/onsa_backend_c/src/emit/consts.rs` の注「array of none has one element」）。
- 内容: 横の `R-504/`（`onsa.toml` と `empty_array_state.onsa`、`init` を書いた `prev~(z, [])`、`z: [F32; 0]`）を `onsa build --target host` で C にすると、`clang -c` が `sizeof(struct ea_empty_array) == 4`・`offsetof(…, onsa_poisoned) == 0` などの §12.4 の静的な表明で落ちる。W7-07 U2 の前のバイナリ（`7792da8`）でも同じ。`check` は通る。
  W7-07 U2 の壊す側の写しを `tests/conformance/default_init_values.onsa` に足したとき、gate の `c-clang`・`c-gcc`・`c-sanitize`・`c-x86` が落ちて見つかった（`run_cases.py --hosts` はこの表明を見ない）。その写しの `empty_array` の flow は `@export` を外した。
- 経緯: 168 回目、2026-11-19、親が W7-07 U2 の壊す側の事例を足して gate で見つけ、U2 の前のバイナリで再現して登録した。
- 判断: 有効なプログラムの C がコンパイルできない（内部エラーの類）ので、見つけた W7-07 で直す（`rules/leader.md` 7.4）。
- 反映（2026-11-19、親）: W7-07 U2b（168 回目）で直した: Core（`crates/onsa_core/src/layout.rs` の `size_align_for`）と sema（`crates/onsa_sema/src/layout.rs`、`onsa interface` の型の大きさ）の配置を C の表現に揃え、長さ 0 の配列は要素一つ分、`()` とフィールドの無いタプルと struct は 1 バイトにした（S-1156 の仮の (2)）。`()` と空の struct も同じ類だった（R-377）。事例 `tests/conformance/state_no_bytes.onsa`、`tests/conformance/default_init_values.onsa` の `empty_array`（U2 で外した `@export` を戻した）。横の再現は事例が持つので消した。
