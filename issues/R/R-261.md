# R-261 C の名前の `.` → `__` が、経路の要素の頭か末尾の `_` で重なる（`voice._f` と `voice_.f` がどちらも `voice___f`）: `onsa build` が C のコンパイラに拒まれて内部エラー

- 場所: C のバックエンドの名前の写し方（経路の区切りの `.` を `__` に写す所）、`onsa build` が C のコンパイラの失敗を内部エラーにする所｜§11.6（「識別子に `__` は書けないので（§2.3）、利用者の名前と重ならない」）、§14.2、§2.3
- 内容: 経路の要素が頭か末尾に `_` を持つと、区切りの `__` と続いて C の名前が重なる（`a_` と `.` と `f`、`a` と `.` と `_f` がどちらも `a___f`）。
  パッケージに `voice.onsa`（`pub fn _f`）と `voice_.onsa`（`pub fn f`）を置くと、`onsa build --target host` は「the C compiler rejected the generated C … redefinition of 'voice___f'」の内部エラーで終了コード 101（dev `fdc4fa5`。再現は `issues/R/R-261/`）。
  §11.6 の約束は、今の §2.3 の読み（`snake_case` が頭と末尾の `_` を受ける）では成り立たない。
- 経緯: 62 回目（2026-10-24）、族「§2.3 の名前の形」（S-650、第 52 組）の下書き（onsa-gap）が見つけ、親が再現した。直し方は S-650 の決め方で変わる（頭の `_` を書けなくすれば名前の規則で無くなり、書けるなら C の名前の写し方を改める）。直す作業は S-650 を決めたときに決める。
- 判断:
- 補い（2026-10-24、親）: 62 回目（2026-10-24）、S-650 の下書き（追記 2）: 最初の要素の頭の `_` でも重なる。
  C のバックエンド（`crates/onsa_backend_c/src/names.rs` の `ident`・`qualified`）は `_` で始まる名前の頭に `onsa` を足すので、`_util.onsa` と `onsa_util.onsa` の `pub fn f` がどちらも `onsa_util__f` になり、`onsa build --target host` は内部エラー（終了コード 101。再現は `issues/R/R-261/lead/`、親が dev `fdc4fa5` で再現した）。
  重なりは、ある経路の要素の末尾の `_` と別の経路の要素の頭の `_` を両方とも書ける規則か、頭の `_` を書ける規則で起きる。
- 判断（2026-10-24、親）: S-650 の決定（2026-10-24、62 回目。頭の `_` はどの形でも書けない）で、この形は書けなくなる。W4-14 U3 の事例で E0320 になることを確かめて閉じる。§11.6 の理由の文は「識別子は `__` を含まず `_` で始まらないので重ならない」に改める（仕様の反映）。
- 反映（2026-10-24、親）: 仕様は 63 回目に §2.3（頭の `_` は書けない）と §11.6 の理由の文に反映した（`7c4ba06`）。W4-14 U3 の事例で E0320 を確かめて閉じる
- 反映（2026-10-24、親）: W4-14 U3（63 回目）で直した: 頭の `_` の名前（`_f`、`_util.onsa`）が E0320 になり、`build` は C の名前を作る前に止まる。事例 `tests/spec/packages/naming_underscore_paths`、`naming_shapes.rs` の `build_stops_at_the_names_that_would_have_made_one_c_name`
