# R-86 fmt が trivia を AST に持たず、往復の検査も無い

- 中・直す・観点 2｜`crates/onsa_syntax/src/fmt.rs:87-91`、`:151-190`
- 作り:
  - コメントの位置を推測で付け直している。
  - 区切り文字を、生のテキストから探している。
- 影響: R-69、R-70、R-43 は、どれも「fmt の前後で AST が変わらない」ことを検査していれば捕まった。
- 直し方:
  - トークンの trivia を、要素（並びの各要素、引数、腕）に付けて保持する。
  - 性質テスト（§5）を入れる。再解析による安全装置は、R-69（S-56）で第 2 段に入れる。コメントを要素に結び付ける部分は、R-70（S-58）で第 2 段に前倒しした。
- 範囲（2026-10-05 に追加で確かめた）: 字句解析器はコメントと改行をトークンとして出しているが、構文解析器が読み飛ばし、AST には残らない。fmt は区切り文字を生のテキストから探し（`find_char`。途中のコメントに同じ文字があると別の位置を拾う）、空行を生のテキストの改行の数で決めている。
  R-70 の 17 の形（どれも正規形で、fmt で変わらないのが期待）のうち 15 を、今の fmt は書き換える。計画 D-02 には「AST はトークン列への索引を持つ」と書かれていたが、実装されていなかった。
- 決定（2026-10-05）:
  - (1) 段を「字句解析 → CST → AST → sema」にする（計画 D-02 の改定）。CST は全てのトークンを持つ損失の無い構文木で、誤りの回復もこの木の上で行う。AST は CST から一つの段で作り、sema は今の AST を使う。fmt は CST を読み、S-56 の書き換えも CST の上で行う。
    修正候補の範囲（R-87）と LSP の位置は CST のトークンの範囲で表す。CST は自前の簡単な作り（D-09）。元の推奨は「トークン列を残し、AST の範囲からトークンを引く」だったが、利用者の問い「修正コスト以外で (b) が優れている部分はあるか」を受けて比べ直し、改めた。
    (b) の利点（構造が少ない、軽い）はこの規模では決定的でなく、(a) は trivia の位置を構造で保証し、誤りを含むコードにも木があり、第 2 期以降の IDE の機能の土台になる。
  - (2) R-113 の性質テストに、CST の往復（CST を出力すると元のソースと一致する）を足す。
  - (3) S-58（コメントの結び付け）は CST の上で作る。CST は S-58 より先か同じ回に入れる（時期はレビューの後に決める）。
  - 利用者の方針: 構造に対する変更は、今のうちに行う方が最終的な管理コストが少ない。
- 実装（2026-10-08、W3-01）: (1) と (2) を実装した。形は計画 D-02 の「実装（W3-01）」の段落。設計メモを Fable が独立に審査し、`validate()` を常に回すことと、失敗した項目の孤児を作らないこと（S-59 の向き）を採った。(3) は W3-11。
- 判断: 直す。(1) 段を「字句解析 → CST → AST → sema」にし、fmt は CST を読む（計画 D-02 の改定。元の推奨のトークン列の索引を、比べ直して改めた）。(2) R-113 の性質テストに CST の往復を足す。(3) S-58 は CST の上で作る（CST が先か同じ回）。方針: 構造に対する変更は今のうちに行う方が最終的な管理コストが少ない
- 反映: 計画 D-02 / §3.2 に反映（2026-10-05）。時期はレビューの後に決める
