# R-412 閉じない括弧を端に持つ範囲のパターン（`1..<f(2 => 3,`）の E0002 の主の範囲が、ファイルの終わりまで延びて後の項目を含み、関数を並べると出力の字とメモリが二乗になる

- 場所: `foreign/guard.rs` の `form_at`（範囲の形の最後のトークン）と、診断ごとに範囲の字を写す `foreign::diagnostic`（`found`）。
- 内容: `fn f{i}() -> I32 {` / `  match x {` / `    1..<f(2 => 3,` を並べると、最初の関数の E0002（ranges cannot be patterns）の主の範囲（JSON の `span` と `found`）が、閉じない `(` の中をファイルの終わりまで延び、後の関数を全て含む（再現は `issues/R/R-412/range_open_2.onsa` の 2 関数で、3:5 から 6:18 まで）。
  各関数の範囲がそれぞれ終わりまで延びるので、出力の字の合計とメモリが関数の数の二乗になる（W5-11 U10g の後のバイナリで 8000 個が 0.31 秒、16000 個で 4 GB を超えた）。
  §18.1 は E0020 の主の範囲を「形を作る最初のトークンから最後のトークンまで」とし、閉じない括弧を含む形の最後のトークンは書かれていない（§2.4 の字句の並びは「閉じないリテラルや区切りで終わるときは、その開きの区切りまで」）。直すと出力が変わる。
- 経緯: 126 回目（2026-11-08）、W5-11 U10g/i（onsa-impl）が範囲の外で見つけた。前（`e67e8dcb`）から同じ範囲で、U10g は出力を変えない単位なので直していない。
- 判断:
- 補い（2026-11-08、親）: W5-11 U10g/b（onsa-break）から: 前の腕が `A(1,) => 2,` の形だと、出力の字の二乗が早く限度に着く（U10g の後のバイナリで N=2000 が 433 MB・1.80 秒、N=3000 が 4.46 秒、N=6000 で 4 GB を超えた。前のバイナリの N=2000 は 567 MB・4.95 秒）。U10g の `form_at` は、範囲が呑む形が閉じない開き括弧で終わるとき、最後のトークンをファイルの最後の記号に戻して前の主の範囲を保つ（`cut` の節）。この節を出力で固定する事例は無いので、R-412 で主の範囲を直すときに `1..<f(2 => 3,` と `n @ 1..<f(2 => 3,` の範囲の終わりを事例に置き、節を外すか改める。
