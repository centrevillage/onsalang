# R-503 同じパッケージの中で、後に書いた定数を読む定数の初期化式が畳まれず、E0419 が書いた順で出たり出なかったりする（`const B: I32 = -A` を `const A: I32 = I32.MIN` の前に書くと通る）

- 場所: `crates/onsa_sema/src/body.rs` の `check_all` の定数の型付けの順と、`crates/onsa_sema/src/consteval.rs` の `eval`（`Path` の枝が `const_values` を読む）。値の無い定数は `crates/onsa_core/src/lower/mod.rs` の `const_id` が初期化式を降下する。
- 内容: 同じパッケージのモジュールの定数は書いた順に型付けと評価をするので、後に書いた定数を読む初期化式は、読む定数の値がまだ無く畳まれない。`const_overflow` は `eval` の値を読むので、`pub const B: I32 = -A` を `pub const A: I32 = I32.MIN` の前に書くと E0419 が出ずに `check` を通る（横の `R-503/forward.onsa`、終了コード 0）。順を入れ替えると E0419（`R-503/backward.onsa`）。`A` を `-2147483647 - 1` と書いても同じ。
  診断が書いた順で変わり（§6.6 の定数の評価はコンパイル時で、順によらない）、通ってしまう形では Core が初期化式を実行時の式として降下する。新しい解析と基を引き継ぐ解析で同じなので、R-502 の外。
- 経緯: 168 回目、2026-11-19、W7-07 U1b（R-502 の直し）の実装の担当（onsa-impl）が範囲の外として報告し、親が固定のバイナリ `c56f3c7` で再現して登録した。
- 判断: 定数の評価を一つの段にし、項目の単位の依存の順を設計する W9-03 で直す（今の順の手当ては W9-03 が作り直す）。利用者もリリースもまだ無い。
