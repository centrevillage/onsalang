# R-332 `onsa test` で、`Str` のフィールドを持つ struct のリテラル（`Mm { name: "b", n: 2 }`）のフィールドを読むと、Shared の型の E0200 でなく内部エラー「no field」（終了コード 101）になる

- 場所: Core への降下（`crates/onsa_core/src/lower/`）。型の降下は `Str` を `Feature::SharedTypes` の E0200 にするが、`Str` のフィールドを持つ struct のフィールドの読みがその前に別の形を受ける（推測。R-293 の構築子のパターンと同じ類）。
- 内容: 横の `struct_str.onsa`（`pub struct Mm { name: Str, n: U32 }` と、`test` の `let m = Mm { name: "b", n: 2 }; assert m.n == 2`）を `onsa test` に渡すと、`internal lowering error: no field` で止まる（終了コード 101、dev `5caf188` のコードと W4-16 U1a の後で同じ）。`onsa check` は通る。
  §18.1 は、この版で扱えない形（Shared の型の `Str`）を E0200 にし、内部エラーにしないとする。
- 経緯: 84 回目（2026-10-29）、W4-16 U1a の壊す側（onsa-break）が範囲の外で見つけ、親が再現した。前からの形。関係: R-293、R-170。
- 判断: 直す（内部エラーは残さない）。R-293・R-170 と同じく、`Str` の降下の E0200 を先に返す。担う作業は W8-01 の設計メモで決める一覧に入れる。
