# R-142 `if` の条件の比較が二重の括弧で出て、clang の `-Werror` で落ちる

- 低・直す・観点 1｜`crates/onsa_backend_c/src/emit.rs`｜§13.4
- 内容: `if c == d { … }` から生成される C が `if ((c == d))` になり、clang の `-Wparentheses-equality` が `-Werror` で落ちる（gcc は通る）。flow でも関数でも同じ。
- 経緯: W1-06 の C の検査で見つけた（2026-10-07）。再現は `tests/pipeline/if_compare.onsa`（gate の `c-clang`、`c-sanitize`、`c-x86` の実装待ち）。
- 決定（2026-10-07、親）: 直す。生成した C の警告の誤りで、判断は要らない。同じ種類の誤り（`-Wtype-limits` に当たる検査を生成しない）を扱う W2-09 で、`if` の条件に余分な括弧を付けない。
- 判断: 直す（親）。生成する C の `if` の条件に余分な括弧を付けない（clang の `-Wparentheses-equality`）。W1-06 で見つけた
