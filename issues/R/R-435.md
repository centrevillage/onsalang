# R-435 局所の添字の場所を `match` の対象や `for` の列にして、ガードや本体がその局所を変えると、場所が評価し直されて値が変わる（`inout` の平面の引数で添字に束縛が要る形は E0200）

- 場所: `crates/onsa_core/src/lower/build.rs::materialize`（W5-12 U3a の直しの後も、局所・リテラル・`const` の添字は束縛せずに場所のまま使う）と、それを何度も読む降下（`match` の腕ごとの `pat_test`、`for` の列）。
- 内容: `for x in xs[i] { i = 1 … }`（`xs: [[U8; 2]; 2]`）は本体が `i` を変えた後の要素を読み、`match xs[i] { v if bump(inout i) => …, v => r = v }` はガードが `i` を変えた後の腕で別の要素を読む（`assert` が落ちる）。dev `073bdf60` と U3a の後で同じ（前から）。§3.5 は各式を一度ずつ評価する形で順を決めるので、対象を一度だけ評価する読みが一つ。
  同じ根の残り: `inout` の平面の引数の要素で、添字に束縛が要る形（`clear(inout ws[next(inout i)])`）は、文を前に置けないので U3a の直しで E0200（PlanarTemporary）にした（前は値を誤って通っていた）。
- 経緯: 140 回目（2026-11-12）、W5-12 U3a の直し（R-433）の実装の担当（onsa-impl）が範囲の外で見つけ、親が前後のバイナリで再現した（入力は `P/w512a/i/f1/loc.txt`・`inoutp.txt`）。
- 判断: 低（書く形が稀で、ガードや本体が対象の添字を変える形）。局所の添字も先に写すと Core の出力が広く変わる（整数の一時が一つ増える）ので、評価順の作業 W8-03 で、`inout` の平面の E0200 を開くのと一緒に直す（`rules/leader.md` 7.4）。
