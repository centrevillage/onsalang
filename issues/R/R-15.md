# R-15 flow: 生成 API の引数名が利用者の名前と衝突し、誤った `process` ができる

- 高・直す + 仕様へ・観点 1 / 3｜`crates/onsa_sema/src/sig.rs:1518`、`crates/onsa_core/src/lower/flow.rs:707`、`:1234`｜§11.6
- 原因: 引数を名前で HashMap に入れて引いている。
- 再現:
  - `flow swap(l: Sig[F32], r: Sig[F32]) -> Sig[Stereo]`（`Stereo` は `l` と `r` を持つ）は検査を通る。`process` は出力の span から入力を読み、出力は全て 0 になる。
  - 入力名が `s` なら、検証器で落ちる。`sample_rate` なら `internal: length of a non-span` になる（再現（親））。
  - `out`、`params`、`cfg`、`frames` も同じ種類の衝突である。
  - C のラッパでは、入力名 `p` / `q` / `frames` が引数や局所変数と衝突し、cc がエラーになる。
- 直し方: sema で検査する。降下では、引数を位置で扱う。
- 仕様へ: 生成 API が予約する名前の一覧と、衝突したときの扱い（エラーにするか、出力名に接頭辞を付けるか）。
- 決定（2026-10-02）: 名前空間を分ける。入出力の引数は数で形が決まり（`input` / `output`、2 つ以上は `voice.In` / `voice.Out`）、`render` の結果は `voice.Rendered`。S-30。
- 判断（2026-10-02）: 名前空間を分ける。入出力の引数は数で形が決まり（`input` / `output`、2 つ以上は `voice.In` / `voice.Out`）、`render` の結果は `voice.Rendered`
- 反映: S-30。仕様 §5.3 / §11.6 / §14.2 に反映済み。実装は W7-03（Onsa の側）と W10-03（C の側）
