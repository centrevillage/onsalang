# R-153 `const` の鎖が長く、各初期化式が深く再帰すると、安全網の内部エラーで止まり、合否が読む順で変わる

- 中・直す・観点 1｜インタプリタ（`const` の評価）｜§12.5、§6.6
- 内容: `const` を読むのは呼び出しに数えない（S-222）ので、鎖の長さに上限は無い。W2-04 の実装は、`const` が `const` を読む鎖を Rust の再帰で評価し、スタックの安全網（内部エラー、終了コード 101）で止める。
  600 個の鎖で各初期化式が 120 段再帰する形は、debug の `onsa test` で内部エラーになり、先に途中の `const` を読むテストを置くと通り、`onsa build` は添字の昇順に評価して通る。仕様の振る舞いでなく、合否が読む順で変わる。内部エラーの文が上限の不足と読める点は W2-04 で直した。
- 経緯: W2-04/b2 で見つけた（2026-10-08）。再現は `tests/review-phase1/core/const_chain_cold.onsa`。浅い鎖（`id(C)` の形）は 2000 個でも通る。
- 決定（2026-10-08、親）: 直す。W2-04 の安全網は W9-03 までのつなぎで、W9-03 が依存の順の評価で鎖の再帰を無くす（全ての環境で上限 128 に届く評価器の形と同じ回）。
- 判断: 直す（親、仕様が明確）。`const` の鎖を依存の順に評価し、鎖の長さと読む順で合否が変わらないようにする。W2-04/b2 で見つけた
- 反映: 実装は W9-03
