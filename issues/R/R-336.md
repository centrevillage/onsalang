# R-336 `Span` を推論した型引数として総称の `T` に入れる形（`id(xs)`、`xs: Span[F32]`）が通る（第二級の型は種を持たない）

- 場所: 型の段の総称の呼び出しの型引数の推論と種の判定（`crates/onsa_sema/src/` の型の段。S-766・S-771 の型引数を書いた形の検査の隣）。
- 内容: `fn id[T](x: T) -> T { x }` に `Span[F32]` の引数を渡す `id(xs).len()` が何も出さない。§4.6 は第二級の型（§5.3）は種を持たずどの種にも当たらないとし、`T` は暗黙の `Dup`（§4.5）を要るので、推論した型引数が `Span` なら型引数を書いた形（S-766・S-771、W4-05）と同じく誤りになるはずである。再現は横の `span_inferred_t.onsa`（dev `6de1620d`）。
- 経緯: 92 回目（2026-10-31）、W4-11 の設計メモ（onsa-impl）が範囲の外で気付いたこととして報告した。親が dev のバイナリで再現した。
- 判断: 直す（低。第二級の値が総称の本体を通して写される）。どのコードと位置にするか（S-766・S-771 の形に揃えるか）と担う作業は、親が区切りで決める（型の段）。
- 補い（2026-10-31、親）: S-809 の段 1 の担当の確かめ: 型引数を書いた `idn::[Span[F32]](xs)` は今 E0200 で、E0200 が外れれば E0710 になるので、書いた形と推論した形で結果が変わる。結果を保存・返却すれば型で E0710 になるので、値は漏れない
