# R-319 長い宣言の鎖（1 万段の struct の鎖 `S_i { a: S_{i+1} }`）で、`onsa interface` などの降下に進む命令がスタックを使い尽くし、内部エラー（終了コード 101）でなく SIGABRT で終わる（`check` は落ちない）

- 場所: Core への降下か Core の配置の計算の再帰（スタックの安全網が無い）。どこで溢れるかは未確認（溢れる入力を回し直さない）。
- 内容: `pub struct S_i { a: S_{i+1} }` の 1 万段（3 万・5 万・7 万・10 万段も）と、`E_i { A(E_{i+1}), B }` の 1 万・3 万段は、`onsa interface` が SIGABRT（終了コード -6）で終わる。`check` は落ちない（sema の歩きはスタックの安全網で内部エラー 101 になる）。入力は置かず台本で作る（R-298 と同じ）。
  W4-05 U2b の後、列挙型の 5 万段以上は sema の安全網が先に当たって 101 になる（U2b で歩きの一段の大きさが増えた）。宣言の 1 万段の鎖は書き手の書く形ではないが、この機械ではクラッシュの報告のダイアログが出る（`rules/common.md` 3.1）。
- 経緯: 80 回目（2026-10-28）、W4-05 U2b の壊す側の再確認が、長い鎖を `interface` に渡して見つけた（手順の誤りで、クラッシュの報告を 17 件作った）。W4-05 U2b の前（`728ebb7`）も同じ。
- 判断: （2026-10-28、親）直す（異常終了でなく内部エラーにする）。降下の再帰の安全網は Core の全体の設計（W8-01）で決め、W8 の作業で入れる。
