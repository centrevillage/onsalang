# R-14 flow: 分岐の中のインスタンスが、分岐を取ったときしか進まない

- 高・直す + 要判断・観点 1 / 3｜`crates/onsa_core/src/lower/body.rs:811`、`lower/flow.rs:1060`｜§11.5「全ての分岐・腕の flow インスタンスは常に進む」｜再現（親）
- 再現: `let c: F32 = prev(c, 0.0) + 1.0; if c > 2.0 { counter~(x) } else { 0.0 }`。期待は `out[2] = 3`、実際は 1。
  - `c && (counter~(x) > 2.0)` の短絡評価でも、同じことが起きる。
  - 分岐の中の `par` では、ループの中で保存する `prev` も止まる。
- 直し方: ノードの評価を、条件の文脈より前に出す。
- 判断（R-14）: 取られない側の引数を評価すると panic しうる場合（`if i < n { lp~(xs[i]) }`）の扱い。
  - (a) 常に評価し、panic も起きる（FAUST と同じ）。
  - (b) `&&` / `||` の右辺と分岐の中にインスタンスを書くことを禁止する。
  - 推奨は (a)。§11.5 の文言どおりで、点ごとの選択という意味とも合う。
