# R-167 poison の export の wrapper が gcc の `-Wclobbered` を出す

- 中・直す・観点 1｜C の生成｜§13.4、§9.2
- 内容: `panic = "poison"` の export の wrapper は `setjmp` をする。
  関数の本体が wrapper に inline され、ループの変数や引数が wrapper のレジスタに載ると、gcc-15 の `-O2 -Wall -Wextra` が `variable 'x' might be clobbered by 'longjmp'` を出し、`-Werror` で落ちる（§13.4 の警告を出さない約束に反する）。
  `longjmp` の後で読まれない変数でも出る誤検出だが、`setjmp` の後に変更して `longjmp` の後に読む変数があれば、値が壊れうる（C11 §7.13.2.1）。
- 経緯: W2-05/t が `c_if_equality` の事例で見つけ、W2-05/i が `c_shift.onsa` の `csh_shr_loop_i16` で再現した（2026-10-08）。I8 / I16 の `>>` の誤った古い式が、たまたまこの警告を隠していた。
- 決定（2026-10-08、親）: 直す。wrapper の形を改める（本体を `noinline` の関数を通して呼ぶ、`setjmp` の後に触る変数を `volatile` にする、など）。gcc の警告を扱う W2-09 で行う。
- 判断: 直す（親、仕様が明確）。poison の export の wrapper の `-Wclobbered`（gcc）を、wrapper の形で無くす。W2-05 で見つけた
- 反映: 実装は W2-09
