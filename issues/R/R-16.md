# R-16 flow: `par` の複製の配列が丸ごと bulk に入る

- 高・直す・観点 1 / 2｜`crates/onsa_core/src/layout.rs:152-164`｜§12.4「fast: スカラと小さな配列」、S-28
- 原因: bulk の候補を「最上位の配列で、閾値以上」と判定している。
- 再現: `bulk_threshold = 64` で `par i in 0..16 { saw~(f0) }` とする。fast は `{ bulk, poisoned, initialized }` だけになり、16 個の状態のスカラは全て bulk（外部 SDRAM）に入る。
- 資料の誤り: `impl-review` B-4 の記述より、問題が大きい（§4）。
- 直し方: bulk の候補を、要素がスカラの配列に限る。T4-10 と同じ回で直す。
- 決定（2026-10-02）: bulk への配置を大きさで決めるのをやめ、注釈 `@bulk`（値が `delay` / `vdelay` の `let` に付ける）で決める。`memory.bulk = true` で有効、ホストなどでは無視。`par` の複製も各自の注釈に従うので、この指摘は解消する。S-31。
- 判断: bulk への配置を大きさで決めるのをやめ、注釈 `@bulk`（値が `delay` / `vdelay` の `let` に付ける）で決める。`memory.bulk = true` で有効、ホストなどでは無視。`par` の複製も各自の注釈に従うので、この指摘は解消する（注釈は S-43 で `@mem(bulk)` に改めた）
- 反映: S-31。仕様 §6.5 / §12.4 / §14.2 / §15.3 / §17.4 / §17.6 に反映済み。実装は T4-10（W9-05）
