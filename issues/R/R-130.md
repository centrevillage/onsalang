# R-130 マニフェストの未知のキーを、黙って無視する

- 中・要判断・観点 1 / 3｜`crates/onsa_driver/src/lib.rs:41-95`（`Manifest` の構造体に `deny_unknown_fields` が無い）｜§15.3
- 内容: `onsa.toml` の誤記したキーや、実装がまだ読まないキーは、エラーにならずに既定値になる。`[package]` の `colour`、ターゲットの `panik`（`panic` の誤記）と `fp` を書いても、`onsa build` は成功する（2026-10-04 に確かめた）。
  S-57 で改めた `fp` と、S-43 の `memory.bulk` も、今は黙って無視される（実装は `numeric` と `memory.bulk_threshold` を読む）。仕様は未知のキーの扱いを書いていない。R-80 (5) で、テストの事例の設定もマニフェストと同じ構造体で読むので、断片の誤記も黙って通る。
- 判断（R-130）: (a) 未知のキーはエラーにする（仕様 §15.3 に書く）。(b) 警告にする。(c) 今のまま。推奨は (a)。黙って既定値になると、ターゲットの設定（panic の方式、`provides`、bulk）の誤りが生成物にだけ現れ、気付けない。将来の版で足すキーは、その版で一覧に加える。
- 経緯: R-80 の議論で見つけた（2026-10-04）。再現は `tests/review-phase1/parent/r130/`。
- 範囲（2026-10-05 に追加で確かめた）:
  - 未知のキーをエラーにすることは、R-47（2026-10-03）で決まっていた（実装は第 2 段）。ただし仕様にキーの一覧が無く、「未知」を定義できなかった。R-121 の `prefix` の誤りと S-83 の std の版の不一致は「マニフェストの誤り」とだけ書き、出し方をここに送っていた。
  - `main_frame` は読むだけで使われない。誤りはコードの無い文面を標準エラーに出し、終了コード 2。`--json` でも標準出力には何も出ない。TOML の構文の誤り、値の型の誤り（`panic = 3`）、必須のキーの欠けは、どれも「TOML parse error」の同じ文面。閉じた一覧に無い値（`panic = "poisen"`）は `onsa check` を通り、`onsa build` で初めて誤りになる。
  - キーの一覧を閉じると、`edition` の値と省略の可否、`main_frame` の値と既定、`provides` の既定、`platform` が要るターゲットが仕様に無かった。
- 決定（2026-10-05）: S-99。
  - (1) §15.3 に、表ごとのキー・値・既定を閉じた表で書いた。一覧に無い表とキーは E1102、仕様にあってこの版が未対応のものは E0200。キーは仕様の版で一覧に加えるときだけ増える。
    `edition` は必須で `"2026"` だけ、`main_frame` は `"stack"`（既定）と `"static"`、`provides` の既定は空、`platform` は C かネイティブのコードを出すターゲットで必須（そのターゲットのビルドで検査）、パッケージ名は `snake_case` の識別子で `std` は書けない（R-47 の「パッケージ名の検査」の中身）。
  - (2) (a)。マニフェストの誤りは §18.1 の診断の形で、新しい範囲 E11xx（E1101 TOML として読めない、E1102 未知の表・キー、E1103 値の型や形、E1104 必須のキーの欠け）。`span` は `onsa.toml` の中の位置、修正候補は綴りの近いキーや値と必須のキーの挿入、`--json` にも出す。
    マニフェストを読む全てのコマンドと LSP が、ソースを読む前にマニフェスト全体を検査し、誤りがあれば終了コード 2（ソースの誤りでないことを修復ループに伝える）。ターゲットに依る検査はそのターゲットのビルド。`--target` に無い名前は使い方の誤りで、コードは付かない。R-121 の `prefix`（E1104 / E1103）と S-83 の std の版（E1103）もこの形にした。
- 判断: S-99: 未知のキーをエラーにするのは R-47 で決定済み。
  §15.3 にキー・値・既定の閉じた表を書き（`edition` は必須で `"2026"`、`main_frame` は `"stack"` / `"static"`、`provides` の既定は空、`platform` は C かネイティブのコードを出すターゲットで必須）、一覧に無いものは E1102、仕様にあって未対応のものは E0200。
  マニフェストの誤りは §18.1 の診断の形で E11xx（E1101〜E1104）、`span` は `onsa.toml` の中、終了コード 2。R-121 と S-83 の「マニフェストの誤り」もこの形。再現は `tests/review-phase1/parent/r130/`
- 反映: 仕様 §14.2 / §15.3 / §18.1 / §18.2 に反映済み、計画 §5 の表に E1101〜E1104（2026-10-05）。実装は W4-02
