# R-256 rt の関数の誤りの文面に、総称の型の引数が内部の添字で `(Str, <0>)` と出る

- 場所: rt の関数の破棄の検査の文面（E0901。S-77 で E0601 に直すのは W6-03）
- 内容: 再現は横の `generic_name.onsa`。`pub rt fn f[T](move v: T, s: Str) -> U32 { let p = (s, v); p.0.len() }` の誤りが「`p` owns a `(Str, <0>)`, whose destruction needs `Alloc`」で、型の引数 `T` を内部の添字 `<0>` のまま表示する。
  `p` は借用の `Str` の要素を持つので所有の行で、誤りそのものは正しい（S-610、S-613）。直すのは表示だけで、書いた名前 `T` で出す。R-27 の効果行の `uses {<0>}` と見た目は同じだが、R-27 は効果行の変数の照合の誤りで仕組みが別である。
- 経緯: 第 45 組（S-613）の下書き（onsa-gap、2026-10-23、58 回目）の付録が見つけ（`target/notes/58/grp45/probe/x/x3_generic.onsa`、`T: Copy` の形）、独立のレビューの段 1・段 2 が新しい R（低、W6-02）にするとし、利用者が了承した（D8、2026-10-24）。E0601 の文面を作るのは S-77 の W6-03 なので、親が直しの作業を W6-03 にした。
  `T: Copy` の形は S-613 で借用になり誤りでなくなるので、親が誤りの残る形（借用の `Str` の要素）で dev `2ebd664` の release の `check` で再現した。直しは W6-03（E0601 の文面の書き直し、S-77）。
