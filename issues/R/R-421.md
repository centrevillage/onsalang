# R-421 構文の誤りのある関数の後の、どの項目にも入らない余分なトークン（`0o19`、`foo bar`）が報告されない（§18.1 は、ひと続きごとに一つの単位）

- 場所: 構文の段の項目の境の回復と単位の切り方（`crates/onsa_syntax` の項目の並びの読み。原因は未確認）。
- 内容: 本体に構文の誤りのある関数（`pub fn g(x: I32) -> I32 {` 改行 `x as 0o19` 改行 `}`、または `x as F32 F32`）の後の行に、どの項目にも入らないトークン（`0o19`、`foo bar`）を置くと、関数の誤りだけが出て、後ろのトークンは報告されない。
  誤りの無い関数の後なら、後ろの `0o19` は E0001、`foo bar` は E0002 で報告される。§18.1 は「どの項目にも入らない余分なトークンは、ひと続きごとに一つの単位とする。ひと続きは次の項目の始まりまで」とし、関数の単位は閉じた括弧で終わる。
  再現は横の `item2.onsa`・`item4.onsa`・`item5.onsa`（黙る）と `item3.onsa`（報告される）。dev `cdc74d99` と W5-24 U1a の後で同じ。
- 経緯: 131 回目（2026-11-10）、W5-24 U1a/i（onsa-impl）が範囲の外として報告し、親が dev のバイナリで再現した。前からある。
- 判断: 低（誤りのあるプログラムで、二つ目の誤りが出ないだけ。一つ目を直した次の検査で報告される）。項目の境を触る W5-24 U2b（項目の頭と次の見出しの読み）で原因を読み、直す（`rules/leader.md` 7.4）。
