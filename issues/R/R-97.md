# R-97 flow の巻き上げの単位が `let` で、仕様の「型から保証」と合わない

- 中・要判断・観点 1 / 3｜`crates/onsa_core/src/lower/flow.rs:758`（`FlowInfo.expr_rates` は降下で使われていない）｜§11.3「各 let を…巻き上げる。係数計算がサンプルループの外に出ることが、型から保証される」
- 現状: §11.7 の `x * db_to_amp(level)` は、tick で毎サンプル `db_to_amp` を計算する。
- 資料の誤り: `impl-review` FL-2 の「定数だけの rt 呼び出しは init で評価」は、`let` 全体がその呼び出しのときだけ成り立つ（§4）。
- 判断（R-97）:
  - (a) 仕様どおり `let` の単位とし、「型から保証」の文言を「`let` に分ければ保証される」に弱める。
  - (b) 部分式の単位で巻き上げる。R-17 も解消するが、一時値が状態に入るので、S-05 の順と S-06 の命名を決める必要がある。
  - 推奨は (b)。§11.7 の例そのものが部分式で書かれており、書き手に `let` の分割を強いるのは P2 に反する。
- 決定（2026-10-02）: (b) 部分式の単位で巻き上げる。`let` に分けるかどうかで評価の段が変わると、書き手が同じだと期待するものが違う挙動になり（「違うものが同じ形に見える」の類型）、`let` が名前を付ける以上の意味を持つため。部分式の巻き上げはコンパイラの最適化と同じ挙動で、意外でない。隠れたフィールドは `hoist_<番号>`。S-33。
- 判断: (b) 部分式の単位で巻き上げる。`let` に分けるかどうかで評価の段が変わると、書き手が同じだと期待するものが違う挙動になり（「違うものが同じ形に見える」の類型）、`let` が名前を付ける以上の意味を持つため。部分式の巻き上げはコンパイラの最適化と同じ挙動で、意外でない。隠れたフィールドは `hoist_<番号>`
- 反映: S-33。仕様 §11.3 / §11.5 / §11.6 / §12.4 に反映済み。実装は R-17 と同じ回（W7-05）
