# R-362 E0416 の「the type became … here as an argument of `f`」の note が、受け手が呼び出しのメソッド呼び出しで、受け手の呼び先の名前を書く（`submit(move b).map_err(full)?` の `full` を「an argument of `submit`」）

- 場所: `crates/onsa_sema/src/body/calls.rs` の `check_args`（367 行の前後）。呼び先の名前を、呼び出しの範囲のソースを最初の `(` で切った字で作る。
- 内容: `submit(move b).map_err(full)?` の `F` の E0416 の note が「the type became `Wrap` here as an argument of `submit`」になる（正しくは `map_err`、受け手が局所の変数なら「an argument of `r.map_err`」）。
  受け手が呼び出しのメソッド呼び出し（`mk().map_err(full)` も「an argument of `mk`」）で、範囲の頭が受け手の呼び先だからである。
  再現は `issues/R/R-362/note_callee.onsa`（`127b4537` のバイナリ、`a`・`c`・`d`。`?` が無く返り値の型から決まる形は「as the result of the function」で当たらない）。診断のコードと位置は変わらず、note の名前だけが違う。S-872 の (F2) で `map_err` の E0416 は出なくなるが、同じ道を通る総称のメソッドで残る。
- 経緯: 110 回目（2026-11-04）、親が第 80 組の S-872（F）の説明の入力（Affine のエラー型への `map_err`）で見つけた。
- 判断: 直す（低）。呼び先の名前は、呼び出しの呼び先の式（メソッドなら受け手の後の名前）から作る。W5-03 は `map_err`・`unwrap` の宣言を扱うので、そこで数行で直す。
