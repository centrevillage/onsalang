# R-272 並びの要素が予約語かキーワードの `use kp.{clock}`・`use std.{test}` を構文の段が並びの途中で切れた形として読み、モジュールの見つからない名前を全て黙らせる

- 場所: `crates/onsa_syntax/src/parser/items.rs` の `parse_use`（並びの要素がキーワードなら `fail_noting` で `Err`、予約語は `parse_ident` が失敗して並びを切る）と、名前の段の `cut_use`（`unread_use` を立てる）。
- 内容: §18.1 の「取り込む名前を全部は読めなかった `use`」のモジュール単位の黙らせ方は、名前まで読めた並びの要素の予約語・キーワードに当たらない（S-462 の 69 回目の補い、利用者が了承）。
  今は `use kp.{clock}` の後の同じモジュールの `zzz()` の E0302 が黙る（並びの無い `use kp.clock` は出る）。`use std.{test}` も同じ。事例は W4-03 U3b2 の `tests/spec/packages/use_reserved_list_member`（対照は `use_reserved_last_member`）。
- 経緯: 69 回目（2026-10-25）、W4-03 U3b2 の壊す側（onsa-break）の空白 G2 から（前からの挙動）。直しの担当（onsa-impl）の見積もりは約 25〜30 行（構文の段で誤りを記録して語を進め並びを読み続ける約 8、下ろしでキーワードの語を並びの名前に入れる約 6、AST に「並びは全部読めた」の印と `cut_use` の分岐 約 8〜12。CST の形が変わるので fmt-cst と fmt-props も確かめる）。
- 判断（2026-10-25、親）: 直す（69 回目、利用者が了承）。S-462 の 69 回目の補いのとおり、並びの要素の予約語・キーワードの後も並びを読み続け、その名前だけを失敗した名前にする。W4-03 の U3d で直す。
