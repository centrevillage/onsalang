# R-19 インタプリタの数値の端

- 中・直す・観点 1｜`crates/onsa_interp/src/lib.rs:1057`、`:1091`｜§3.3、§3.4、§13.4
- 64 ビットの `trunc_*` で、上限を f64 にすると丸められる。
  - `9223372036854775808.0.trunc_i64()` が `I64.MIN` を、`18446744073709551616.0.trunc_u64()` が 0 を返す。
  - C は panic するので、食い違う。
- `I32.MIN.rem_euclid(-1)` は、インタプリタだけが 0 を返す。Rust と C は panic する。
- `%` の溢れのメッセージが `/` と表示される。
- 直し方: 2 の冪の「上限 + 1」と `>=` で比べる。
- 決定（2026-10-03）: (1) 64 ビットの `trunc_*` は、上限を 2 の冪で持ち `>=` で比べるように直す。(2) `MIN` を `-1` で割った剰余は 0 を返す（panic は数学的な結果が型に収まらないときだけ。Rust の panic はハードウェアの事情によるもので、WASM / JS は元から 0）。
  インタプリタと `onsa.h` の両方を直し、`%` の溢れのメッセージの `/` の表示も直す。`trunc_*` は §3.3 の型の変換で、`std.math.trunc`（浮動小数のまま）とは別物なので残す。
- 判断: (1) 64 ビットの `trunc_*` は、上限を 2 の冪で持ち `>=` で比べるように直す。(2) `MIN` を `-1` で割った剰余は 0 を返す（panic は数学的な結果が型に収まらないときだけ。Rust の panic はハードウェアの事情によるもので、WASM / JS は元から 0）。
  インタプリタと `onsa.h` の両方を直し、`%` の溢れのメッセージの `/` の表示も直す。`trunc_*` は §3.3 の型の変換で、`std.math.trunc`（浮動小数のまま）とは別物なので残す
- 反映: 仕様 §3.4 / §9.2 に反映済み（2026-10-03）。実装は W2-03、W2-05
