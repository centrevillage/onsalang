# R-10 C: `onsa.h` の整数ヘルパに未定義動作と誤りがある

- 高・直す・観点 1｜`runtime/c/onsa.h:198`、`:293`、`:298`、`:404`｜§3.4、§3.3、§9.2｜コードで確認（親）
- **U32 の検査付き乗算**: `(int64_t)a * (int64_t)b` が int64 を超える（未定義動作）。gcc-15 の -O2 では検査が消え、`4294967295 * 4294967295` が panic せずに 1 を返す。既定の `*` がこのヘルパを使うので、影響が広い。
- **I8 / I16 の負数の右シフト**: `(T)~((~(UT)a) >> n)` は `~` の前に int へ昇格する。`-128i8 >> 1` が 64 に、`-32768i16 >> 1` が 16384 になる。どのコンパイラ、どの最適化でも同じ結果になる。
- **u16 / i16 のラップ乗算**: int に昇格して、符号付きのオーバーフローになる（UBSan が報告した）。
- **I64 / U64 の飽和変換**: `(T)(MAXP1 - 1.0)` が範囲外の変換になる。`1e30.trunc_i64_sat()` の結果が、clang -O2 では 6671500168 になる。
- 直し方:
  - u32 は `uint64_t` で掛けるか、`__builtin_mul_overflow` を使う。
  - シフトは各段で `UT` に戻す。
  - 16 ビット以下の乗算は `unsigned` で掛ける。
  - 飽和の上端は定数 `MAX` を返す。

検査付きの演算については組み込み関数で正確に検査できれば良いと思います。
ただし組み込み環境をターゲットにする場合は検査を消して効率化する仕組みが必要に思います。
仕様にあるか分かりませんが、コンパイル/トランスパイル時に検査レベルを指定できる仕組みがあるとなお良い。
