# R-439 `onsa_core` の `walk::has_return` が値の位置のブロックの入れ子ごとに子を歩き直し、集約を返す関数の `onsa build` が入れ子の深さ d に対し 2^d で伸びる（d = 26 で約 1.3 秒、28 で約 5 秒）

- 場所: `crates/onsa_core/src/walk.rs` の `has_return`（呼び手は `crates/onsa_backend_c/src/emit/fns.rs` の集約を返す関数の結果の置き場所の判定だけ）。
- 内容: `expr` が `walk_expr` で全ての子を歩き、会った `Block`・`IfExpr`・`Switch` ごとに `stmt` から `expr` を呼び直すので、値の位置のブロックの入れ子 d に対し 2^d になる。タプルを返す関数に `let v0: I32 = { let v1: I32 = { … } }` を d 段書くと、`onsa build` が d = 22・26 で約 0.14・1.3 秒（親の測り）、d = 28 で約 5 秒（advisor の測り）。返り値が `I32` の同じ形は d = 28 で 0.10 秒で、`check` は一定。入れ子の上限は 256（§2.5）なので、40 段で数時間の見込み。結果は誤らない。`Assign(_, e)` が代入先の添字の中を見ない点もある（害は未確認）。入力の台本は `target/notes/140/w513_survey/K/gen_nest.py`・`time_nest.py`。
- 経緯: 140 回目（2026-11-12）、W5-13 の前の洗い出しの領域 3（onsa-advisor）が見つけ、親が二つの深さで測り直した。
- 判断: 中（`build` が止まらない形。出力は変わらない）。呼び手は W8-05（結果の置き場所を Core の一か所で）で消えるが、それまで残るので、W5-13 で一度の歩きに直す（`walk.rs` +12 −18 の見当）。確かめは `[[test.host]]` の事例と時間の前後。gate に入れるなら段を 24 以下にして時間の上限で見る（X-24）。
