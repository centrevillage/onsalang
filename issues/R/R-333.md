# R-333 前置の `~` の直後が `=` の形（`{~=`）に、E0020 の「`!` を書く」候補を出し、当てると `!=` の一語に読まれて E0002 が残る

- 場所: `crates/onsa_syntax/src/foreign/faust.rs` の `bit_not`（表の行 `faust_bit_not`）。前置の `~` が次のトークンに接していれば、そのトークンが何かを見ずに `~` を `!` に置き換える候補を出す。
- 内容: 式の始まりの `~` の直後が `=` の形（`test "h" {` 改行 `~=`、`let b = ~= a`）は E0020「bits are negated with the prefix `!`」で、候補は `~` を `!` にする。当てると `!=` が一つのトークンに読まれ、編集の外の `=` の読みが変わり（S-302 の約束に反する）、同じ位置に E0002 が残る（候補は無いので、当て続けると止まる）。
  二項の位置の `a ~= b`（Lua の不等号）は流れの呼び出しの印の E0002 で、この行に来ない。通るプログラムは変わらない。
  再現はファズの入力 `tests/fuzz/938b63f9.onsa`（`test"h"{~=`。種 `tests/spec/packages/body_path_other_module_ok/main.onsa` の変異）。書き手が書く形とは考えにくい。
- 経緯: 85 回目（2026-10-30）、`3434a10` の後の親の `gate.py --only fuzz` が見つけた（`fix|E0020|write `…`|reading` と `fix|E0020|write `…`|E0002`）。基の `39c07d0` と `6b3e711` のコードも同じで、前からある。
- 判断: 直す（低）。字句・構文の残りを扱う W5-11 で、`~` の次が `=` か `==` なら候補を出さない（R-297 と同じ扱い）。一つの入力が二つの類を出すので許可の一覧（一つの入力に一つの類）に載せられない。それまで入力は `tests/pending.toml` の `fuzz-input` に載せる。
