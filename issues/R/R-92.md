# R-92 インタプリタが、型の合わない値を黙って 0 として扱う。`Zeroed` の意味が文書に無い

- 低・直す + 仕様へ・観点 2 / 3｜`crates/onsa_interp/src/lib.rs:511`、`:1005-1091`、`:1120-1138`、`crates/onsa_core/src/ir.rs:321`、`onsa_interp/src/value.rs:236-262`
- 黙って 0 として扱う:
  - Prim の引数の型が合わないとき、`to_i128().unwrap_or(0)` などで 0 にする。
  - `assert_near` に F32 が渡ると、0 と 0 を比べて常に成功する。
  - 検証器が Prim の型を見ない（R-82）ので、降下の誤りが隠れる。
- `Zeroed` の意味: 任意の型のゼロ値の意味は、インタプリタの実装にしか書かれていない。
  - 実装: enum は tag 0、関数値は番兵、`Buf` / `Span` は空。
  - 「読む前に必ず上書きされる」という不変条件も書かれていない。
- 直し方:
  - 型が合わないときは、内部エラーの panic にする。
  - `Zeroed` の意味を Core の文書（計画）に書く。または `from_fn` を、未初期化の宣言と全要素の代入で表す。
- 範囲（2026-10-05 に追加で確かめた）: `Zeroed` を作るのは 3 か所で、役割が 2 つに分かれる。役割 1（後で全てを書く仮の値）は `array.from_fn` の配列（`lower/body.rs`）と `par` の複製の結果の配列（`lower/flow.rs:1110`）。
  役割 2（状態の初期値）は flow の `init`（`lower/flow.rs:803`）で、状態を `Zeroed` で作り、遅延と `prev` には初期値を明示的に入れるが、`Sig` から読まれる `Ctl` の `let`、巻き上げた部分式、`vdelay` の書き込みの位置、`poisoned` は 0 のまま残す（前の二つは読む前に `ctl` が書き、後の二つは 0 が意味のある初期値）。
  `Zeroed` は、組込みの数では `T.ZERO` や `T.default()` と同じ値になるが、一般には一致しない（手書きの `impl Default` の enum の既定値は先頭の列挙子とは限らない）。R-81 の所有の規則（V-11）では、Affine の要素の仮の値の上書きが合わない。
- 決定（2026-10-05）:
  - (1) インタプリタは、型の合わない値を黙って 0 にせず、内部エラーにする。検証器の V-02 をすり抜けたときの備え。
  - (2) Core から `Zeroed` を無くし、役割ごとに明示の形にする（計画 §3.4 / §3.5 の追記）。役割 1 は「添字で配列を作る式」（各要素を宛先に一度だけ作る。R-81 と合う）。
    役割 2 は、`init` が全てのフィールドを意味のある値（初期値、`T.default()`、0、`false`、引数）で設定し、段の順で読む前に必ず書かれるフィールドは flow の計画に記録して「設定しない」と明示する。「既定値が全て 0 のビットか」を Core の型の情報として一度だけ決め、バックエンドは `memset` にまとめてよい。
    初期値の基準は `T.default()`（S-29）で、`T.ZERO`（`Num` の単位元）ではない（利用者の問いに答えた: `T.ZERO` は `Num` の型にしか無く、別の概念）。検証器に V-17（`init` が全てのフィールドを設定する）を足した。
  - (3) 言語の仕様には書かない（`Zeroed` を無くすので書く意味が無く、「設定しない」フィールドの `init` の直後の値は言語から観測できない）。
- 判断: 直す。(1) インタプリタは型の合わない値を内部エラーに。(2) Core から `Zeroed` を無くし、後で全てを書く配列は「添字で配列を作る式」、状態の初期値は `init` が全てのフィールドを意味のある値（`T.default()` など。`T.ZERO` ではない）で設定し、読む前に必ず書かれるフィールドは flow の計画に記録して「設定しない」と明示する。検証器に V-17。(3) 言語の仕様には書かない
- 反映: 計画 §3.4 / §3.5 に追記（2026-10-05）。実装は (1) W2-03、(2) W8-07
