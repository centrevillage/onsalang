# R-458 flow の遅延（`prev~`・`delay~`）の値型が Copy でなくても、`let` に置かなければ受け付け、状態に `Str` などが入る

- 場所: flow の本体の遅延（§11.4）の値型の検査。
- 内容: 横の `prev_value_type.onsa`。`prev~(if x > 0.0 { "a" } else { "bb" }, "z").len()` と `prev~(mk(x), "z").len()`（`mk` は `Str` を返す `rt fn`）は通り、同じ遅延を `let s = prev~(…)` に置くと E0810「the value type of a signal must be Copy; `Str` is Shared」。§12.4 は「flow の状態の大きさは、コンパイル時に決まる（遅延線の長さはコンパイル時定数、値型は Copy、ヒープを使わない）」とするので、名前を付けない遅延の値型も Copy でなければならない。`delay~(…, 4, None)`（`Option[Str]`）も同じ（段 1 の `a1.txt`）。
- 経緯: 第 104 組（S-1043）の独立のレビューの段 1（onsa-advisor）が挙げ、親が固定のバイナリ `onsa-bf474a4` で再現した（149 回目、2026-11-14）。材料は `target/notes/149/gap/g104/advisor/` と段 1 の報告 `target/notes/149/gap/g104/onsa-advisor-aa36969ddf6da6add-001.md`。 関係: S-1043、S-1046（巻き上げで状態に Copy でない値）、E0810、S-616。
