# R-64 仕様の例のマニフェスト（§14.2 / §15.3）でビルドできない

- 高・直す + 仕様へ・観点 1｜`crates/onsa_backend_c/src/emit.rs:344`、`names.rs:15-29`、`export.rs:476`｜§15.3「prefix + 名前の最後の要素」、§14.2
- 再現: パッケージ `voice`、flow `dsp.voice`、`fns = ["util.onsa_version"]` の組み合わせで、次の 2 つが起きる。
  - 関数用のヘッダ `onsa_voice.h` が、flow のヘッダ `onsa_voice.h` を上書きし、cc が失敗する。
  - export の名前が `onsa_onsa_version_` になる（R-48）。
- 仕様へ: 関数用のヘッダの名前の規則（例: `<prefix><package>_fns.h`）。
- 決定（2026-10-04）: 直す。S-52: ヘッダはパッケージに 1 つ（`<prefix><package>.h`）で、全ての flow と関数を宣言する。例の関数を `version` に改める（C の名前は `onsa_version`）。C の名前の重なりは、flow の生成する名前と関数の名前を含めてビルドで E1011。C の API の名前空間・版・panic の通知は R-121 に分けた。
- 判断: 直す。S-52: ヘッダは `<prefix><package>.h` の 1 つ。C の名前は `prefix` + 名前の最後の要素で、例の関数を `version` に改めた。重なりは E1011（flow の生成する名前を含む）。名前空間・版・panic の通知は R-121 へ
