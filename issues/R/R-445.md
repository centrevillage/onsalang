# R-445 構文の段のつなぐ・動かす候補の判定（R-443 の `joins_cleanly`・`chain_from`）が、`as fn(I32) -> I32` の型の `->` で走査を止め、`- b`・`* b` の候補が E0011 を残す。止まったときの既定が「候補を出す」側で、`foreign/operators.rs::compares`（S-236）と逆

- 場所: `crates/onsa_syntax/src/foreign/lines.rs` の `joins_cleanly`・`chain_from`（W5-13 U7c の R-443 の直し）。
- 内容: `a as fn(I32) -> I32` 改行 `- b`（と `* b`）で、後ろ向きの走査が型の `->` で止まり、`as` に届かないので被演算子を Plain と読み、つなぐ候補と動かす候補が出て、当てると E0011 が残る（`onsa_cases --fix-contract`）。前のバイナリでも候補は出ていた（R-443 の直しが取りこぼした形）。壊す側の 50 件の探りで 10 件。括弧付きの型（`as (fn(I32) -> I32)`）、`as Foo::Bar`・`as Self`・`as ()`・`as [I32; 4]` は通る。根は、走査の停止規則が「知らない印で止まる」で、止まったときの既定が「候補を出す」側であること。同じ「つないだ字面が読めるか」の判定の `foreign/operators.rs::compares`（S-236）は止まると候補を出さない側で、既定が逆（D-15）。前置か二項かの判定（`ends_operand(前のトークン)`）も `layout::continues`・`Cursor::head_symbol_after_operand`・`operators.rs` の `after_operand`・`lines.rs::after_operand` に分かれ、つなぐ候補の組み立ても `lines.rs` と `spaces.rs` の二か所にある。再現は `issues/R/R-445/`。
- 経緯: 142 回目（2026-11-12）、W5-13 U7c/b（onsa-break）が見つけ、親が再現した。
- 判断（2026-11-12、親）: W5-13 の次の単位（U7d）で、止まったときの既定を候補を出さない側に揃え、`compares` と読み手を一つに寄せられるかを見る。
- 反映（2026-11-12、親）: W5-13 U7d（143 回目）で、つないだ字面の連鎖を `chain_start`（後ろ向きに始まりまで）と `read_chain`（前向きに記号の行の被演算子の終わりまで）で一度だけ読み、知らない印で止まったら候補を出さない側にした（`compares` と同じ向き）。`a as fn(I32) -> I32` 改行 `- b` は `remove the space` だけ、`* b` は E0002。再現の `issues/R/R-445/` は事例 `tests/spec/fixes/e0020_leading_minus_join_unknown_chain.onsa`・`e0020_leading_operator_unknown_chain.onsa` へ移して消した。前置か二項かの判定は `operators.rs::after_operand` が `lines.rs::after_operand` を呼ぶ形で一つにした。`compares` と `read_chain` の二つの読み手と、つなぐ候補の組み立ての `lines.rs`・`spaces.rs` の二か所は、止まる線で寄せなかった（見当は `target/notes/143/w513u7d/r445.md`。`compares` を寄せると `a === b % c - d` の候補が消え出力が変わる）。壊す側の低: 見出しの中の構造体リテラルの後に `as` が続く形（`if a` 改行 `- P { x: b }.x as I32 {`）は候補が出て当てると E0002 が残るが、入力に誤りが二つ（見出しで構造体のリテラルを読まない S-08 と行頭の演算子）で約束の前提の外（S-384）。
