# リファクタリング（RF）

（仮。目的の一段落は親が書き、利用者が了承する。）

## 頭の欄

| キー | 形 | 値 | 要る | 意味 |
|---|---|---|---|---|
| `status` | 閉じた値 | `OPEN` / `WONTFIX` / `DONE` | はい | 状態 |
| `severity` | 閉じた値 | `高` / `中〜高` / `中` / `低〜中` / `低` | いいえ | 重さ |
| `spec` | 節の並び | — | いいえ | 仕様の節 |
| `decisions` | ID の並び（S） | — | いいえ | 決定 |
| `fix` | ID の並び（W） | — | いいえ | 直す作業 |
| `found_by` | 文字列 | — | いいえ | 見つけた票 |

## 本文のラベル

- `場所`: 直す所。
- `内容`: 何を直すか。
- `経緯`: 見つけた票、日付、材料。
- `判断`: 決めたこと（日付、誰）。

## 目的と条件

全ての RF に共通する（2026-10-10、12 回目、利用者）。

- 第一の目標は管理しやすい状態にすること（同じ判断を一か所に、依存の向き、名前が役割を表す）で、行数の削減を目的にしない（大きさの基準は膨らみすぎの見張りとしてだけ使う）。
- 実行の性能を落とさない（dev と新しいバイナリで、`tests/`・`std`・`examples` の全体の `onsa check`・`onsa fmt --check`、長い入力の組（12 回目の scratchpad の `w306b2/speed/`）、gate の主な段の時間を同じ条件で測り、報告に並べる。誤差を超えて遅くなる直しは採らない）。

## 持ち越しから移した RF

RF-1〜RF-16 は、持ち越し（`docs/carryovers.md`）の箇条から移した（2026-10-17）。
箇条の頭の字は題と、括弧の中の出所（`経緯`）か決定（`判断`）に分け、下の箇条は字を変えずに、ラベルの下に置いた。
