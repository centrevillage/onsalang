# 共有のファイルと文書

テストと実装の担当が、実装待ちの一覧、テストの ignore、文書を編集する前に読む。文書の点検と移行の担当は、作業を始める前に読む。

## 5. 共有のファイルと文書（t、i、docs）

5.1 `tests/pending.toml` の項目（`[[pending]]` の表）は、テストの担当は編集しない。実装の担当も、並行の作業があるときは編集しない。載せる項目は報告に並べ、親が足す（4 章の、仮に入れて回し、回した後に戻す確かめは除く）。

5.2 テストの ignore の付け外しと理由の改めは `tools/ignores.py`（`list`・`passing`・`remove`・`set`）で、実装待ちの一覧の項目の付け外しは `tools/pending.py` の `list`・`remove`・`add` で行い、使い捨ての置換を書かない。
  通るようになった ignore は `ignores.py passing -p <crate> --reason <理由>` で探す。
  ignore の理由は、そのテストを通すことになる作業の ID で始める（`W3-11 U3c: …`）。gate の `ignores` が、済んだ作業か表に無い ID の ignore を落とす。

5.3 文書（`docs/`、`rules/`、仕様）を編集するとき（i、docs）:
  - 先に `docs/`・`rules/` とリポジトリの直下に、vim のスワップファイル（`.<name>.swp`）が無いことを確かめる。確かめは、編集と別のコマンドで行う（利用者が vim で開いて回答を書いていることがある）。
  - Python の一意一致置換で編集する。
  - 表を編集したら列の数を確かめる（セルの中の `||` は `\|\|`）。

### 文書の点検と移行（docs）

5.4 文書の点検と移行の担当は、親の作業票で呼ばれる（時機は `rules/process.md` 8.6）。

5.5 書く字は、リポジトリに既にある字（移す・写す）、親の作業票か親が書いたファイルの字（そのまま）、道具の出力（`docs.py` の `fmt`・`set`・`amend`・`new`・`path`、作業票が指す移行の道具）のどれかに限る。
  「そのまま」は、改行・字下げ・句読点・空白の差を許し、語の差は許さない。消す字は、正本に同じ字で残るものか、親が作業票で名指ししたものに限る。字を起こさない。
  本文の記述から頭の欄を補う、ラベルを置き換える、持ち越しを振り分ける、状態を合わせる、は親が作業票に規則か対応表を書いたときだけ行い、無ければ案を報告する。

5.6 出所が親でも書かない場所: 仕様・規則・README の規範の文（移す・経路の直し・整形は除く）、担当の定義、道具が読む README の欄の表、コード・テスト・`tests/pending.toml`・SPEC-GAP の印。

5.7 移す・分ける・整形は、往復の確かめと `docs.py check` が通ったものだけを置く。通らなければ戻して報告する。

5.8 点検の範囲は作業票の一覧と、そこから一段だけ辿った先。一覧が決定 30・作業 15・その他の文書 10 を超えるときは、親に票を分けるよう報告する。矛盾の疑いを確かめる二段目は 10 ファイルまで。読みながら一覧を広げない。

5.9 見つけたことは両側の引用と辿った経路と推奨を付けて報告する。決めるのは親（規則と仕様は利用者）。

5.10 点検の直しは作業ツリーで行い、WIP のコミットにする（`rules/common.md` 2 章）。移行の段は、担当が動いていない区切りに主のツリーで行う。
