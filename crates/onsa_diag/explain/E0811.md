# E0811: a flow call or a `par` that holds state needs `~`, and nothing with state stands where it is not evaluated every sample

Inside a flow body, `name~(args)` creates a stateful instance of the
flow `name`, while `name(args)` applies a stateless function point by
point (spec §2.6, §11.5). Calling a flow without `~` is an error so that
the two kinds of call never look the same.

```onsa
let f1 = resonator(src, vowel_f1, 80.0)     // E0811
let f1 = resonator~(src, vowel_f1, 80.0)    // OK
```

A replication whose body holds state (an instance or a built-in delay,
in a replication in it too) is written `par~` for the same reason (spec §2.6,
§11.5): inside a flow body, a `par` whose body holds state is E0811,
with the candidate that adds the `~`. Whether the body holds state is
decided by what it calls, not by the `~` written. A `par~` whose body
holds none is E0812, with the candidate that takes the `~` off.

```onsa
let saws = par i in 0 ..< 4 { saw~(f0) }     // E0811
let saws = par~ i in 0 ..< 4 { saw~(f0) }    // OK
let gains = par i in 0 ..< 4 { x * g[i] }    // OK: no state
```

A thing with state (an instance, a built-in delay, a `par~`) is not
written where it is evaluated on some samples only (spec §11.5): a branch
of `if` / `match`, a guard of a `match` and a condition of an `if` chain
after the first are E0811, and the right of `&&` / `||` is E0806. The
candidates are the `if~` / `match~` of a branch, which evaluates every
branch, and a new `let` before the statement that holds the thing, which
evaluates it on every sample.

```onsa
let y = if gate { lp~(x) } else { 0.0 }      // E0811
let s = lp~(x)
let y = if gate { s } else { 0.0 }           // OK
```
