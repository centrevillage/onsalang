# W7-17 L5/e のイベントの値の腕の束縛を根にするフィールドの読みの値の表（§11.3、S-1247 (1)、S-1197、§11.10）

値は仕様の字（§11.3 の巻き上げの項の「腕の束縛（`match~` のガードの中の束縛も）を根にする読みは、外の条件によらず、その腕のパターンが合う刻みに読む」「初めの値はその型の既定」、§11.10 の「刻みで書いて速い段が読むフィールド … は `T.default()` に戻る」）から手で出した。
書き方は `par_arm_values.md` と同じ。各事例は共通の部品の次に `flow top(x: U32 at sample, y: U32 at sample, c: U32 at sample) -> U32 at sample { … }` の中身として置かれ、入力の列は位置 0 からの値で、書いていない入力は全て 0。
`V.default()` は `V.B(Pd { vel: 50, on: true })`。イベントは `y` から作る（1〜100 は `V.B(Pd { vel: y, on: y != 4 })`、101 以上は `V.A`、0 は無し）。
通常の `match` のガードは、この版では降下しない（E0200）ので、この表は評価器だけで走らせる（`case/` の事例には置かない）。

## 共通の部品

```onsa
struct Pd { vel: U32, on: Bool }
enum V { A, B(Pd) }
impl Default for V { rt fn default() -> V { V.B(Pd { vel: 50, on: true }) } }
flow src(y: U32 at sample) -> V at event {
  if y > 100 { Some(V.A) } else if y > 0 { Some(V.B(Pd { vel: y, on: y != 4 })) } else { None }
}
flow garm(v: V at event, x: U32 at sample) -> U32 at sample {
  match v { V.B(q) if q.on => x + q.vel, V.B(_) => x + 1, V.A => x }
}
// 事例の本体は flow top(x: U32 at sample, y: U32 at sample, c: U32 at sample) -> U32 at sample { … } の中身
```

### G1（前の腕が取られる刻みにも、後の腕の束縛の読みは書く）

```onsa
let v = src~(y)
match v { V.B(q) if q.on && c != 0 => x + q.vel, V.B(r) => x + r.vel, V.A => x }
```

- 入力: x = 1000 1000 1000 1000、y = 0 0 3 0、c = 1 1 1 0
- 手で出した期待: `1000 1000 1003 1003`
- 根拠: イベントはフレーム 2 の `V.B(Pd { vel: 3, on: true })`。`q.on`・`q.vel`・`r.vel` は `V.B` のパターンが合うイベントの刻みに書く。最初のイベントの前は `q.on` が `Bool.default()` で偽、`r.vel` が `U32.default()`（`V.default()` の 50 と true ではない）なので、フレーム 0・1 は後の腕の `x + 0`。フレーム 2 は前の腕（ガード `q.on && c != 0` が真）が取られ `x + 3`。フレーム 3 は `c` が 0 で後の腕に落ち、`r.vel` はフレーム 2 で前の腕が取られた刻みにも書いてあるので 3。

### G2（外の条件が偽の刻みにイベントが来る）

```onsa
let v = src~(y)
if c != 0 { match v { V.B(q) if q.on => x + q.vel, V.B(_) => x + 1, V.A => x } } else { x }
```

- 入力: x = 1000 1000 1000 1000、y = 0 0 3 0、c = 1 1 0 1
- 手で出した期待: `1001 1001 1000 1003`
- 根拠: フレーム 2 のイベントは `c` が 0 の刻みで来るが、`q.on`・`q.vel` は外の条件で守らずに書く。フレーム 3 で `c` が 1 に戻ると、ガードは真、`x + 3`。最初のイベントの前はガードの `q.on` が偽で `x + 1`。

### G3（ガードの読みと、イベントの種類が変わる）

```onsa
let v = src~(y)
if c != 0 { match v { V.B(q) if q.on => x + q.vel, V.B(r) => x + r.vel + 10, V.A => x } } else { x }
```

- 入力: x = 1000 1000 1000 1000 1000、y = 0 3 4 101 0、c = 1 1 1 1 1
- 手で出した期待: `1010 1003 1014 1000 1000`
- 根拠: フレーム 0 は最初のイベントの前で `q.on` が偽、`r.vel` が 0 で `x + 0 + 10`。フレーム 1 は `on` が真の `V.B(3)` で `x + 3`。フレーム 2 は `y = 4` の `V.B(Pd { vel: 4, on: false })` でガードが偽になり `r.vel` の 4 を読んで `x + 4 + 10`。フレーム 3 は `V.A` で `x`。フレーム 4 も `V.A` のまま。

### G4（`par` の複製の中の読み）

```onsa
let v = src~(y)
let s = par i in 0 ..< 2 { if c != 0 { match v { V.B(q) => x + q.vel + i, V.A => x } } else { x } }
s[0] * 10000 + s[1]
```

- 入力: x = 1000 1000 1000 1000、y = 0 0 3 0、c = 1 1 0 1
- 手で出した期待: `10001001 10001001 10001000 10031004`
- 根拠: `q.vel` は複製によらない読みで、複製ごとに欄がある。フレーム 0・1 は `q.vel` が 0 で `s[0] = 1000`、`s[1] = 1001`。フレーム 2 は `c` が 0 で両方 `x`、イベントは来ている。フレーム 3 は `q.vel = 3` で `1003`、`1004`。

### G5（`reset_if~` の後は読みの型の既定）

```onsa
garm~(src~(y), x).reset_if~(c != 0)
```

- 入力: x = 1000 1000 1000 1000 1000、y = 0 0 3 0 0、c = 0 0 0 1 0
- 手で出した期待: `1001 1001 1003 1001 1001`
- 根拠: フレーム 2 のイベントで `q.on`・`q.vel` が書かれ、フレーム 3 の `reset_if~` の後は `v` が `V.default()` に戻るが、`q.on` は `Bool.default()` の偽に戻り（`V.default()` の `on` の真ではない）、後の腕の `x + 1`。フレーム 4 も同じ（イベントは来ない）。

### G6（腕の中の `par` の複製が、腕の束縛の読みを読む）

```onsa
let v = src~(y)
let s = if c != 0 { match v { V.B(q) => par i in 0 ..< 2 { x + q.vel + i }, V.A => par i in 0 ..< 2 { x } } } else { par i in 0 ..< 2 { x } }
s[0] * 10000 + s[1]
```

- 入力: x = 1000 1000 1000 1000、y = 0 0 3 0、c = 1 1 0 1
- 手で出した期待: `10001001 10001001 10001000 10031004`
- 根拠: G4 と同じ値。`q` は `par` の外の腕の束縛で、`q.vel` は複製ごとに欄を持ち、最初のイベントの前は 0（`V.default()` の 50 ではない）。
